  ### Modification du comportement des événements DM

  Aujourd’hui, nous avons modifié le comportement des événements DM de X API v2. <Update label="Aug 3, 2022" description="X API v2">
  ### Ajout d’alias pour les opérateurs de filtrage

  Des « alias » d’opérateurs de filtrage/de requête ont été ajoutés aux endpoints de recherche et de flux filtré, pour les offres entreprise, premium et v2. Dans de nombreux cas, l’opérateur se réfère aux Publications plutôt qu’aux statuts, par exemple « in&#95;reply&#95;to&#95;tweet&#95;id » comme alias de « in&#95;reply&#95;to&#95;status&#95;id ». Dans d’autres cas, le nouvel alias d’opérateur apporte plus de clarté au filtrage effectué. Par exemple, étant donné que les Publications ne peuvent avoir qu’une seule pièce jointe vidéo, un nouvel alias « has:video&#95;link » est fourni pour « has:videos ». Consultez le [tableau des opérateurs du flux filtré v2](https://developer.x.com/en/docs/twitter-api/tweets/filtered-stream/integrate/build-a-rule#list) pour voir d’autres exemples.
</Update>

<Update label="14 déc. 2021" description="X API v2 : Authentification">
  ### Prise en charge de l’authentification OAuth 2.0

  À partir d’aujourd’hui, tous les développeurs peuvent s’authentifier avec OAuth 2.0 en sélectionnant OAuth 2.0 comme méthode d’authentification dans la Console de Développement. Nous avons ajouté la prise en charge des clients confidentiels et publics, ainsi que de tous les points de terminaison v2 pertinents pour utiliser cette méthode d’authentification dans le cadre de cette version.

  OAuth 2.0 est un protocole d’autorisation standard du secteur qui offre aux développeurs un meilleur contrôle sur les étendues (scopes) d’une application et améliore les flux d’autorisation sur plusieurs appareils. En d’autres termes, les développeurs qui créent des applications pour les personnes sur X auront plus de contrôle sur les informations que leur application demande à leurs utilisateurs, afin que vous n’ayez à demander à vos utilisateurs finaux que les données et informations dont vous avez besoin.

  Ce protocole d’autorisation moderne vous permettra de proposer à vos utilisateurs finaux un flux de consentement plus simple pour autoriser votre application, qui n’affiche que les étendues spécifiques que vous avez demandées.

  Pour en savoir plus sur ce lancement, consultez notre annonce sur le forum.
</Update>

<Update label="15 nov. 2021" description="X API v2 : Accès anticipé">
  ### Mises à jour majeures de la plateforme pour X API v2

  **Mises à jour majeures de la plateforme : X API v2 est désormais la version principale, nouveaux niveaux d’accès Essential et Elevated, et modifications des règles**

  Aujourd’hui, nous annonçons que X API v2 est désormais la version principale de X API. Nous avons lancé suffisamment de points de terminaison et de fonctionnalités dans X API v2 pour répondre aux besoins de 90 % de toutes les applications existantes construites sur X API.

  Nous lançons aujourd’hui les modifications suivantes pour améliorer encore l’expérience développeur avec X API v2 :

  * Accès Essential rapide et gratuit à l’API, et accès Elevated gratuit pour les développeurs dont les cas d’usage ont été approuvés. Nous fournissons beaucoup plus de détails sur ces niveaux d’accès sur notre page À propos de X API.

  * Nous supprimons des formulations dans notre Politique Développeur qui limitaient la manière dont vous développez avec les fonctionnalités essentielles de X et restreignaient le nombre d’utilisateurs que vous pouvez prendre en charge via votre application.

    * Nous ouvrons notre plateforme pour vous encourager à créer des outils et des produits qui rendent X meilleur, plus sain, et qui étendent la conversation publique. [Consultez une liste de solutions que nous aimerions vous voir créer](https://developer.x.com/en/docs/twitter-api/what-to-build).

    * Plus précisément, nous avons supprimé des termes qui limitaient la réplication de l’expérience X, y compris les fonctionnalités essentielles de X, ainsi que des termes qui exigeaient une autorisation pour disposer d’un nombre élevé de jetons d’utilisateur.

    * Nous savons que créer des solutions qui aident les personnes sur X signifie souvent qu’un développeur doit créer (ou reproduire) certains éléments disponibles sur X. Ces modifications de notre Politique Développeur visent à apporter de la clarté à l’écosystème des développeurs et à proposer une plateforme API ouverte qui facilite la création, l’innovation et l’impact des développeurs sur la conversation publique.

  Nous détaillons bien davantage ce lancement et les lancements X API qui ont conduit à ce moment dans notre [publication sur le forum](https://devcommunity.x.com/t/ushering-in-a-new-era-for-the-twitter-developer-platform-with-the-twitter-api-v2/162087).

  En plus d’explorer les entrées précédentes du journal des modifications, nous avons rassemblé quelques ressources clés que vous pouvez consulter pour comprendre tout ce qui a été lancé dans X API v2 à ce jour :

  * [Carte des points de terminaison X API](/fr/x-api/migrate/x-api-endpoint-map)

  * [À propos de X API](/fr/x-api/getting-started/about-x-api)
</Update>

<Update label="Dec 18, 2020" description="Champ de réglages des réponses pour les publications dans X API v2">
  ### Ajout du champ de réglages des réponses

  Aujourd’hui, nous lançons un nouveau champ dans l’objet publication, appelé `reply_settings`. Ce champ est disponible sur tous les endpoints X API v2 qui renvoient des publications, notamment post lookup, hide replies, recent search, sampled stream, filtered stream, follows lookup, user post timeline et user mention timeline, ou en [étendant](/fr/x-api/fundamentals/expansions) l’objet publication dans n’importe quel endpoint.

  Ce champ indique comment l’auteur de la publication autorise les autres à répondre à ses publications : tout le monde, uniquement les personnes mentionnées dans la publication, ou uniquement les comptes qu’il suit. Les valeurs renvoyées par le champ `reply_settings` incluent `everyone`, `mentionedUsers` et `following`. Si aucun contrôle de conversation n’est défini pour la publication, ce champ sera tout de même présent dans l’objet publication avec la valeur `everyone`.
</Update>

<Update label="May 10, 2018" description="X API: Standard v1.1">

  Aujourd’hui, nous ajoutons une modification de la manière dont les URL sont restituées dans la charge utile de la citation.

Cela signifie que l’objet &quot;quoted&#95;status&#95;permalink&quot; sera réservé au lien t.co renvoyant vers la Publication citée, tandis que le tableau &quot;entities.urls&quot; pourra être utilisé pour identifier tous les liens partagés dans la Publication originale ou la citation.

  Le paramètre optionnel `enable_dm_commands` de statuses/update permet aux applications de supprimer plus tôt la prise en charge des commandes de DM, avant la fin de la période de transition. La valeur par défaut est *false*.
