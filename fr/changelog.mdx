  ### Modification du comportement des événements de DM

  Aujourd’hui, nous avons modifié le comportement des événements de DM de X API v2. <Update label="Aug 3, 2022" description="X API v2">
  ### Ajout d’alias d’opérateurs de filtrage

  Des « alias » d’opérateurs de filtrage/requête ont été ajoutés aux endpoints search et filtered stream, sur les offres enterprise, premium et v2. Dans de nombreux cas, l’opérateur fait référence aux publications plutôt qu’aux statuts, par exemple « in&#95;reply&#95;to&#95;tweet&#95;id » comme alias de « in&#95;reply&#95;to&#95;status&#95;id ». Dans d’autres cas, le nouvel alias d’opérateur apporte davantage de clarté sur la correspondance effectuée. Par exemple, puisque les publications ne peuvent avoir qu’une seule pièce jointe vidéo, un nouvel alias « has:video&#95;link » est fourni pour « has:videos ». Consultez le [tableau des opérateurs du flux filtré v2](https://developer.x.com/en/docs/twitter-api/tweets/filtered-stream/integrate/build-a-rule#list) pour voir d’autres exemples.
</Update>

<Update label="14 déc. 2021" description="X API v2 : Authentification">
  ### Prise en charge de l’authentification OAuth 2.0

  À partir d’aujourd’hui, tous les développeurs peuvent s’authentifier avec OAuth 2.0 en sélectionnant OAuth 2.0 comme méthode d’authentification dans la Developer Console. Nous avons ajouté la prise en charge des clients confidentiels et publics, ainsi que de tous les points de terminaison v2 pertinents, afin d’utiliser cette méthode d’authentification dans le cadre de cette version.

  OAuth 2.0 est un protocole d’autorisation standard du secteur qui offre aux développeurs un meilleur contrôle sur les périmètres d’autorisation (« scopes ») d’une application et améliore les flux d’autorisation sur plusieurs appareils. En d’autres termes, les développeurs qui créent des applications pour les personnes sur X auront davantage de contrôle sur les informations que leur application demande à ses utilisateurs, afin que vous n’ayez à demander à vos utilisateurs finaux que les données et informations dont vous avez besoin.

  Ce protocole d’autorisation moderne vous permettra de proposer à vos utilisateurs finaux un flux de consentement plus fluide pour autoriser votre application, qui n’affiche que les périmètres spécifiques que vous avez demandés.

  Pour en savoir plus sur ce lancement, veuillez consulter l’annonce publiée sur notre forum.
</Update>

<Update label="15 nov. 2021" description="X API v2 : Accès anticipé">
  ### Mises à jour majeures de la plateforme pour X API v2

  **Mises à jour majeures de la plateforme : X API v2 est désormais la version principale, nouveaux niveaux d’accès Essential et Elevated, et modifications de la politique**

  Aujourd’hui, nous annonçons que X API v2 est désormais la version principale de X API. Nous avons lancé suffisamment de points de terminaison et de fonctionnalités dans X API v2 pour répondre aux besoins de 90 % de toutes les applications existantes construites sur X API.

  Nous lançons aujourd’hui les changements suivants afin d’améliorer encore l’expérience des développeurs avec X API v2 :

  * Un accès Essential rapide et gratuit à l’API, et un accès Elevated gratuit pour les développeurs dont les cas d’usage ont été approuvés. Nous fournissons beaucoup plus de détails sur ces niveaux d’accès sur notre page About the X API.

  * Nous supprimons dans notre Developer Policy la formulation qui limitait la manière dont vous utilisez les fonctionnalités essentielles de X et limitait le nombre d’utilisateurs que vous pouvez prendre en charge via votre application.

    * Nous ouvrons notre plateforme pour vous encourager à créer des outils et des produits qui rendent X meilleur, plus sain, et qui étendent la conversation publique. [Consultez une liste de solutions que nous aimerions vous voir créer](https://developer.x.com/en/docs/twitter-api/what-to-build).

    * Plus précisément, nous avons supprimé les termes qui limitaient la réplication de l’expérience X, y compris les fonctionnalités essentielles de X, ainsi que les termes qui exigeaient une autorisation pour disposer d’un grand nombre de jetons utilisateur.

    * Nous savons que créer des solutions qui aident les personnes sur X signifie souvent qu’un développeur doit créer (ou reproduire) certains des éléments disponibles sur X. Ces modifications de notre Developer Policy visent à offrir davantage de clarté à l’écosystème des développeurs et à fournir une plateforme API ouverte qui facilite la création, l’innovation et l’impact sur la conversation publique.

  Nous donnons beaucoup plus de détails sur ce lancement et sur les lancements X API qui ont conduit à ce moment dans notre [publication sur le forum](https://devcommunity.x.com/t/ushering-in-a-new-era-for-the-twitter-developer-platform-with-the-twitter-api-v2/162087).

  En plus d’explorer les entrées antérieures du journal des modifications, nous avons rassemblé des ressources clés que vous pouvez consulter pour comprendre tout ce qui a été lancé dans X API v2 à ce jour :

  * [X API endpoint map](/fr/x-api/migrate/x-api-endpoint-map)

  * [About the X API](/fr/x-api/getting-started/about-x-api)
</Update>

<Update label="10 mai 2018" description="X API : Standard v1.1">
  ### Modifications du rendu de la charge utile de citation

  Aujourd’hui, nous modifions la façon dont les URL sont restituées dans la charge utile de citation.

  Nous ajoutons une nouvelle entité appelée &quot;quoted&#95;status&#95;permalink&quot; afin de garantir que la publication citée puisse être référencée et nous supprimerons le lien t.co du champ &quot;text&quot; de la publication citée.

  Avec le nouveau format, le lien t.co n’est plus ajouté à la fin du champ &quot;text&quot; de la publication citée dans l’objet &quot;quoted&#95;status&quot;.

  De plus, nous n’ajouterons plus l’URL t.co, ainsi que les champs expanded&#95;url et display&#95;url de la publication citée dans l’entité ‘urls’. À la place, ceux‑ci seront ajoutés à un nouvel objet &quot;quoted&#95;status&#95;permalink&quot; avec les attributs d’URL &quot;url&quot;, &quot;expanded&quot; et &quot;display&quot;. Cela signifie que l’objet &quot;quoted&#95;status&#95;permalink&quot; sera réservé au lien t.co renvoyant vers la publication citée, tandis que le tableau &quot;entities.urls&quot; pourra être utilisé pour identifier tous les liens partagés dans la publication originale ou la citation.

  Veuillez lire notre [publication sur le forum](https://devcommunity.x.com/t/updating-how-urls-are-rendered-in-the-quote-tweet-payload/105473) et notre [documentation mise à jour](https://devcommunity.x.com/t/upcoming-changes-to-the-developer-platform/104603) pour plus de détails.

  Ces nouvelles API s’appuient sur la qualité et la stabilité de notre plateforme de données Enterprise et la rendent plus largement accessible via un modèle de tarification par paliers. Pour la première fois, vous pouvez commencer à effectuer des recherches sur 30 jours de publications (au lieu des 7 jours de données limités sur l’endpoint standard) et, en option, vous pouvez également accéder à nos enrichissements Premium pour la géolocalisation de profil, l’expansion d’URL et les données de sondage. Voici un aperçu de certaines des nouvelles fonctionnalités :

  * Un langage de requête bien plus riche permettant des requêtes plus complexes (Sandbox + Premium)

  * Un endpoint de comptage qui renvoie des séries temporelles du nombre de publications (Premium)

  * Des enrichissements de métadonnées, tels que les URL étendues et la géolocalisation de profil (Premium)

  Pour en savoir plus sur ce lancement, consultez cet article [sur notre blog](https://blog.x.com/developer/en_us/topics/tools/2017/introducing-twitter-premium-apis.html).

  ### Paramètres facultatifs pour les commandes de DM

  Le paramètre facultatif `enable_dm_commands` de statuses/update permet aux applications de supprimer la prise en charge des commandes de DM plus tôt, avant la fin de la période de transition. La valeur par défaut est *true* (c’est-à-dire le comportement hérité actuel), mais elle peut être définie sur *false* pour obtenir le nouveau comportement après le 1er novembre. Le paramètre facultatif `fail_dm_commands` de statuses/update fera renvoyer un code HTTP 403 (code d’erreur 151) par l’API pour les commandes de DM lorsqu’il est défini sur *true*. La valeur par défaut est *false*. Pour en savoir plus sur cette mise à jour, consultez ce contenu [sur notre forum](https://devcommunity.x.com/t/retiring-legacy-dm-commands-on-the-standard-tweet-api/86653).
