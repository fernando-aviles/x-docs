<div id="overview">
  ## Overview
</div>

Les éléments créatifs sont toutes les entités pouvant être promues dans une campagne. Les publications peuvent inclure du texte, des images, des GIF, des vidéos ou des cartes. Les cartes peuvent inclure des images ou des vidéos.

Les éléments créatifs image, GIF ou vidéo sont téléversés à l’aide soit de l’endpoint [POST media/upload](/fr/x-api/media/upload-media#post-media-upload) — un endpoint de téléversement simple qui ne prend en charge que les images — soit des endpoints POST media/upload (chunked). Ces éléments peuvent être ajoutés aux

cartes :

* POST accounts/:account&#95;id/cards
  Tweets :
* POST accounts/:account&#95;id/tweets - Pour ajouter des cartes aux Tweets, utilisez le paramètre card&#95;uri.
  Tweets programmés :
* POST accounts/:account&#95;id/scheduled&#95;tweets

Pour plus de détails sur les cartes, consultez la page Cards. La page Promoted Video fournit des détails sur l’association de vidéos avec des cartes ou des Tweets.

### Cards

L’API Ads prend en charge plusieurs types de cards pouvant être utilisés dans des Tweets, qui peuvent ensuite être promus dans des campagnes. **Remarque** : une fois qu’une card est utilisée dans un Tweet, ses détails sont visibles publiquement. Cela peut inclure des informations sur l’utilisateur qui possède la card.

<div id="image">
  #### Image
</div>

Les spécifications d’image suivantes s’appliquent aux éléments utilisés dans les [Cards](/fr/x-ads-api/creatives#cards-2). Les images doivent avoir une taille maximale de 3 Mo et une largeur d’au moins 800 px. De plus, nous prenons en charge les rapports largeur:hauteur suivants.

* Site web : 1:1 et 1,91:1
* Image App Download : 1:1 et 1,91:1
* Sondage : 1,91:1
* Image Conversation : 1,91:1
* Image Direct Message : 1,91:1

Nous prenons en charge les formats d’image suivants : .bmp, .jpeg et .png.

<div id="video">
  #### Vidéo
</div>

Les spécifications vidéo suivantes s’appliquent aux ressources utilisées dans les [Cards](/fr/x-ads-api/creatives#cards-2). Nous prenons en charge les rapports largeur/hauteur suivants.

* Vidéo de site web : 16:9 et 1:1
* Vidéo de téléchargement d’application : 16:9 et 1:1
* Sondage : 16:9
* Vidéo de conversation : 16:9
* Vidéo de message direct : 16:9

<div id="promoted-video">
  ### Vidéo sponsorisée
</div>

Ce document fournit un bref aperçu du processus de mise en ligne et de promotion de vidéos via l’Ads API.

L’Ads API prend en charge la vidéo sponsorisée dans les [Tweets](/fr/x-ads-api/creatives#tweets-2) et dans les cartes suivantes :

* [Vidéo de site Web](https://devcommunity.x.com/t/ads-api-version-11/168814)
* [Vidéo de téléchargement d’app](https://devcommunity.x.com/t/ads-api-version-11/168814)
* [Vidéo de conversation](/fr/x-ads-api/creatives#video-conversation-cards)

Commencez par mettre en ligne la vidéo à l’aide de l’endpoint [POST media/upload (chunked)](https://developer.x.com/en/docs/media/upload-media/api-reference/post-media-upload-init.html). À l’aide du `media_id`, associez la vidéo à un compte publicitaire en utilisant l’endpoint POST accounts/:account&#95;id/videos. L’`id` de la vidéo, parfois appelé `media_key`, sera utilisé dans les requêtes suivantes. Il s’agit d’une chaîne de caractères qui commence par un int, est suivie d’un underscore, et se termine par une valeur de type long. Par exemple : `13_875943225764098048`.

<div id="promoted-video-in-tweets">
  #### Vidéo sponsorisée dans les Tweets
</div>

Pour créer un Tweet, utilisez l’endpoint [POST accounts/:account&#95;id/tweet](/fr/x-ads-api/creatives#get-accounts-account-id-tweets) avec l’`id` de la vidéo. À cette étape, vous pouvez également fournir un titre pour la vidéo, une description et un call-to-action (CTA, appel à l’action). Ces valeurs sont visibles par les utilisateurs.

<div id="promoted-video-in-cards">
  #### Vidéo sponsorisée dans les Cards
</div>

Les Video App Download et Video Conversation cards prennent en charge l&#39;ajout d’images d’affiche (poster). Téléversez une image à utiliser dans ces cards à l’aide de l’endpoint [POST media/upload](https://developer.x.com/en/docs/media/upload-media/api-reference/post-media-upload.html).

Créez la card à l’aide de l’un des endpoints suivants :

* [POST accounts/:account&#95;id/cards/video&#95;website](https://devcommunity.x.com/t/ads-api-version-11/168814)
* [POST accounts/:account&#95;id/cards/video&#95;app&#95;download](https://devcommunity.x.com/t/ads-api-version-11/168814)
* [POST accounts/:account&#95;id/cards/video&#95;conversation](https://devcommunity.x.com/t/ads-api-version-11/168814)

en utilisant l’`id` de la vidéo et, éventuellement, le `media_id` de l’image (pour l’image d’affiche).

Enfin, créez le Tweet à l’aide de l’endpoint POST accounts/:account&#95;id/tweet. Les cards sont associées aux Tweets à l’aide du paramètre `card_uri`.

<div id="general-information">
  #### Informations générales
</div>

Pour des conseils détaillés sur le téléversement de vidéos via l’API, consultez le [guide de téléversement de vidéos](https://developer.x.com/en/docs/media/upload-media/uploading-media.html).

Les vidéos peuvent également être promues en tant qu’actifs pre-roll. Consultez le [guide sur l’objectif Vues de vidéo pre-roll](/fr/x-ads-api/campaign-management#video-views-preroll-objective) pour une explication détaillée.

* (À compter du 22/10/2015) Lors du téléversement de vidéos destinées à être utilisées dans du contenu promu, le paramètre `media_category` doit avoir la valeur `amplify_video` pour toutes les requêtes de commande `INIT` vers le point de terminaison [POST media/upload (chunked)](https://developer.x.com/en/docs/media/upload-media/api-reference/post-media-upload-init.html). L’utilisation de ce nouveau paramètre garantit que la vidéo est prétraitée de manière asynchrone et préparée pour une utilisation dans du contenu promu. La commande `STATUS` peut être utilisée pour vérifier la fin du traitement asynchrone après le téléversement de la vidéo.
* La durée maximale actuellement autorisée pour une vidéo promue est de 10 minutes, avec une taille de fichier de 500 Mo ou moins.
* La vidéo téléversée doit être au format mp4 ou mov.
* La vidéo téléversée est généralement traitée rapidement, mais les temps de traitement peuvent varier en fonction de la durée de la vidéo et de la taille du fichier.
* Les images d’affiche (poster) téléversées doivent être au format png ou jpg. Il n’y a aucune contrainte de rapport hauteur/largeur ou de taille, mais l’image d’affiche sera ajustée pour s’adapter au lecteur vidéo.

<div id="scheduled-tweets">
  ### Tweets programmés
</div>

<div id="introduction">
  #### Introduction
</div>

Les Tweets programmés permettent à un annonceur ou à un utilisateur de créer un Tweet et d’en programmer la publication à une date ultérieure. En plus de pouvoir créer et gérer ces Tweets, l’API permet d’associer ces Tweets à un line item, afin qu’ils soient promus une fois le Tweet publié. Cela permet aux annonceurs de préparer des Tweets natifs et de planifier à l’avance les éléments créatifs de leurs campagnes avant toute initiative clé. Par exemple, préparer un Tweet créatif pour qu’il soit publié immédiatement lors de l’annonce d’un nouveau produit.

L’ensemble des fonctionnalités fournies par les endpoints de l’API Scheduled Tweets est listé ci-dessous :

* Créer, modifier et afficher de nouveaux Tweets programmés
* Associer un Tweet programmé à un line item
* Interroger et gérer les Tweets programmés existants
* Une fois qu’un Tweet programmé est publié, récupérer l’`id` du Tweet publié

  #### Points de terminaison de l’API

  #### Affichage d’un Scheduled Tweet
</div>

* [GET accounts/:account&#95;id/scheduled&#95;tweets/preview/:scheduled&#95;tweet&#95;id](/fr/x-ads-api/creatives#scheduled-tweets-2) (afficher un Scheduled Tweet existant)

Du fait que les Scheduled Tweets sont des entités distinctes des Tweets « live », deux ensembles de contrôles de validation sont exécutés pour toute création ou modification de ces Tweets. Le premier ensemble de règles de validation est appliqué à l’étape de création du Scheduled Tweet, à savoir :

<div id="scheduled-tweet-create">
  #### Création de Tweet programmé :
</div>

* Vérifiez que l’utilisateur authentifié a les droits nécessaires pour créer des Tweets organiques pour un @handle donné. Les privilèges de création de Tweets Promoted-Only exigent que l’utilisateur authentifié soit un utilisateur du compte disposant des [Tweet composer permissions](https://developer.x.com/content/developer-twitter/en/docs/ads/campaign-management/api-reference/authenticated-user-access#get-accounts-account-id-authenticated-user-access).
* Vérifiez qu’il n’y a pas plus de 30 Tweets programmés à créer dans une fenêtre de 15 minutes autour de l’heure `scheduled_at`. Un message d’erreur SCHEDULED&#95;TWEET&#95;LIMIT&#95;EXCEEDED indique que trop de Tweets programmés ont été définis dans le même intervalle futur de 15 minutes. Les annonceurs devront supprimer un Tweet programmé existant ou déplacer l’heure `scheduled_at` plus tôt ou plus tard.

<div id="scheduled-tweet-goes-live">
  #### Le Tweet programmé est mis en ligne :
</div>

* Ces règles de validation sont exécutées à l’instant scheduled&#95;at et sont identiques à celles appliquées lors de la création d’un Tweet classique via l’API. Par exemple, un Tweet programmé ne sera pas mis en ligne et le scheduled&#95;status sera défini sur FAILED si le Tweet programmé contient à la fois une image et un GIF.

<div id="workflow">
  #### Workflow
</div>

**Créer un nouveau Tweet programmé**

Un nouveau Tweet programmé peut être créé à l’aide de l’endpoint [POST accounts/:account&#95;id/scheduled&#95;tweets](https://developer.x.com/content/developer-twitter/en/docs/ads/creatives/api-reference/scheduled-tweets#post-accounts-account-id-scheduled-tweets). Cet endpoint comporte les paramètres obligatoires suivants : l’heure `scheduled_at`, ainsi que le `text` du Tweet si aucune entité média n’est incluse dans le Tweet. De plus, cet endpoint fournit quelques options supplémentaires qui vous permettent de créer un Tweet programmé pour le compte d’un autre @handle via le paramètre `as_user_id`, ainsi que la possibilité d’ajouter une carte (`card_uri`) et des médias (`media_ids`). À noter qu’un Tweet ne peut contenir que des entités du même type, c’est‑à‑dire soit Video, Gif ou Image. Le paramètre `nullcast` contrôle si le Tweet est un Tweet &quot;Promoted-Only&quot; ou non. Tous les nouveaux Tweets programmés créés sont &quot;Promoted-Only&quot; (`nullcast=true`) par défaut. Si `nullcast=false`, alors un Tweet programmé organique est créé.

Une fois qu’un Tweet programmé est créé avec succès, la Réponse contient un champ `id`, qui fait référence à l’identifiant unique du Tweet programmé lui‑même. En plus de ce champ, un autre champ appelé `tweet_id` est également renvoyé. Ce champ est initialement `null`, mais une fois que le Tweet est publié, ce champ est renseigné avec l’ID du Tweet « live ».

```
twurl -H 'ads-api.x.com' -X POST "/6/accounts/:account_id/scheduled_tweets" -d 'scheduled_at=2017-12-24T23:59:00Z&text=Happy Holidays!'
```

Cette action créera le Tweet programmé suivant :

```json
{
  "request": {
    "params": {
      "text": "Joyeuses fêtes !",
      "scheduled_at": "2017-12-24T23:59:00Z"
    }
  },
  "data": {
    "completed_at": null,
    "id_str": "917507899668099072",
    "text": "Joyeuses fêtes !",
    "user_id": "3271358660",
    "scheduled_status": "SCHEDULED",
    "id": 917507899668099100,
    "nullcast": true,
    "created_at": "2017-10-09T21:51:44Z",

```

Une fois que ce Scheduled Tweet sera mis en ligne, le champ `tweet_id` sera renseigné avec l’ID du Tweet « en direct ».

**Associer un Tweet programmé à un élément de campagne**

Bien que les Tweets programmés puissent être utilisés pour créer des Tweets organiques, nous permettons également aux partenaires de créer un Tweet « Promoted-Only » (`nullcast=true`), qui peuvent l’un comme l’autre être associés à un élément de campagne. Pour cela, nous mettons également à disposition l’endpoint [POST accounts/:account&#95;id/scheduled&#95;promoted&#95;tweets](https://developer.x.com/content/developer-twitter/en/docs/ads/campaign-management/api-reference/scheduled-promoted-tweets#post-accounts-account-id-scheduled-promoted-tweets). Cet endpoint permet uniquement d’associer un seul Tweet programmé sponsorisé à un élément de campagne dans un seul appel d’API. Pour associer plusieurs Tweets programmés au même élément de campagne, plusieurs appels d’API sont nécessaires.

Veuillez noter qu’il n’est pas possible de modifier un Tweet programmé sponsorisé existant.

```
twurl -H 'ads-api.x.com' -X POST "/6/accounts/:account_id/scheduled_promoted_tweets" -d 'line_item_id=a44qc&scheduled_tweet_id=917507899668099072'
```

```json
{
  "data": {
    "line_item_id": "a44qc",
    "id": "26576",
    "created_at": "2017-10-09T22:24:16Z",
    "updated_at": "2017-10-09T22:24:16Z",
    "scheduled_tweet_id": "917507899668099072",
    "tweet_id": null,
    "deleted": false
  },
  "request": {
    "params": {
      "line_item_id": "a44qc",
      "scheduled_tweet_id": 917507899668099100,
      "account_id": "aaaaa"
    }
  }
}
```

Cet endpoint crée uniquement une association entre un Tweet programmé donné et un élément de campagne. Une fois que les dates de diffusion de la campagne/de l’élément de campagne sont en vigueur, l’élément de campagne commencera automatiquement à diffuser le Tweet « live » correspondant. Bien que nous vérifiions à cette étape que le Tweet programmé est dans l’état `SCHEDULED` et que le Tweet programmé donné est valide pour l’objectif concerné, aucune autre validation n’est effectuée. Toutes les règles de validation restantes qui s’appliquent à l’élément de campagne et au Tweet programmé sont exécutées lorsque le Tweet passe en mode « live ».

Afin de s’assurer qu’il n’y a aucun problème de diffusion de la campagne, il est recommandé que le Tweet programmé ait un champ `scheduled_at` défini à un moment antérieur aux dates de diffusion de la campagne/de l’élément de campagne.

Par exemple, si le Tweet programmé est configuré pour passer en « live » après la date de début de la campagne (et qu’il n’y a qu’un seul Tweet associé à un seul élément de campagne), alors la campagne sera `ACTIVE`, mais étant donné que le Tweet programmé n’est pas encore « live », il n’y aura aucune création disponible pour la diffusion.

**Gestion des Tweets programmés**

Les autres endpoints permettent aux utilisateurs de l’API de gérer tous leurs Tweets programmés et Tweets promus programmés. Ces API peuvent être utilisées soit pour renvoyer une liste de tous les Tweets programmés, éventuellement filtrée par un état donné, soit pour rechercher un Tweet programmé donné par son `id`.

<div id="what-happens-when-a-scheduled-tweet-goes-live">
  #### Que se passe-t-il lorsqu’un Tweet programmé est mis en ligne ?
</div>

Lorsqu’un Tweet programmé est sur le point d’être mis en ligne, ou en d’autres termes à l’heure `scheduled_at`, les mises à jour suivantes sont effectuées :

* Le Tweet « en ligne » est créé, mais cela peut prendre jusqu’à 1 seconde
* Le `tweet_id` est ajouté aux entités suivantes :
* Tweet programmé
* Tweet programmé promu
* Une nouvelle entité de Tweet promu est créée

<div id="best-practices">
  #### Bonnes pratiques
</div>

Les bonnes pratiques suivantes sont recommandées lors de la création ou de la promotion de Tweets programmés :

* Assurez-vous que le Tweet est valide lors de la création du Tweet programmé (par exemple, un Tweet ne peut contenir qu’une image, une vidéo ou un GIF, et non une combinaison des trois)
* Assurez-vous que les dates de diffusion de la campagne (c’est-à-dire `start_time` et `end_time`) sont alignées avec l’heure `scheduled_at` du Tweet programmé
* Les Tweets programmés ne doivent pas être définis à plus d’un an dans le futur (365 jours)
* L’aperçu de Tweet n’est actuellement pas pris en charge pour les Tweets programmés (il s’agit de la possibilité de prévisualiser les Tweets programmés avant leur création)

### Médiathèque

<div id="introduction">
  #### Introduction
</div>

Les endpoints de Media Library permettent de gérer les images, GIFs et vidéos pour les comptes X Ads. Les ressources média de la bibliothèque peuvent être utilisées dans des Tweets et pour créer des cards. Elles peuvent également être réutilisées dans plusieurs [creatives](https://developer.x.com/content/developer-twitter/en/docs/ads/creatives/overview), ce qui évite d’avoir à téléverser plusieurs fois le même élément média.

<div id="api-endpoints">
  #### Points de terminaison de l’API
</div>

* [POST media/upload](https://developer.x.com/content/developer-twitter/en/docs/media/upload-media/api-reference/post-media-upload#post-media-upload) ou [POST media/upload (chunked)](https://developer.x.com/content/developer-twitter/en/docs/media/upload-media/api-reference/post-media-upload-init#post-media-upload-init) (téléverser des médias)
* [POST accounts/:account&#95;id/media&#95;library](https://developer.x.com/x-ads-api/creatives#get-accounts-account-id-media-library#post-accounts-account-id-media-library) (ajouter des médias à la Media Library)

<div id="adding-to-the-library">
  #### Ajout à la bibliothèque
</div>

L’ajout de médias à la bibliothèque se fait en deux étapes. Tout d’abord, téléversez la ressource à l’aide de l’endpoint [POST media/upload](https://developer.x.com/content/developer-twitter/en/docs/media/upload-media/api-reference/post-media-upload#post-media-upload) ou de l’ensemble d’endpoints [POST media/upload (chunked)](https://developer.x.com/content/developer-twitter/en/docs/media/upload-media/api-reference/post-media-upload-init#post-media-upload-init). (Consultez le guide [Chunked media upload](https://developer.x.com/content/developer-twitter/en/docs/media/upload-media/uploading-media/chunked-media-upload) pour plus de détails sur notre processus de téléversement en plusieurs parties.)

<div id="request-parameters">
  #### Paramètres de la requête
</div>

Toutes les requêtes POST de Media Library nécessitent un identifiant de média. Cette valeur est renvoyée lors de l’étape de téléversement. Lorsque vous utilisez le media&#95;id, comme dans l’exemple ci-dessus, une media&#95;category doit également être spécifiée. Il existe quatre valeurs de catégorie possibles : AMPLIFY&#95;VIDEO, TWEET&#95;GIF, TWEET&#95;IMAGE et TWEET&#95;VIDEO.

En option, les valeurs name et file&#95;name peuvent être définies pour les objets dans Media Library. Ces attributs aident les utilisateurs à distinguer les variantes de médias dans la bibliothèque.

Pour les vidéos, il est également possible de définir un titre et une description. Ces valeurs sont destinées à être transmises en tant que paramètres de requête video&#95;title et video&#95;description avec le point de terminaison [POST accounts/:account&#95;id/tweet](https://developer.x.com/content/developer-twitter/en/docs/ads/creatives/api-reference/tweets#post-accounts-account-id-tweet). Dans le Tweet, ce texte apparaît sous la vidéo.

<div id="attributes">
  #### Attributs
</div>

La Media Library introduit formellement le concept de `media_key`. Il s’agit de l’identifiant unique des objets de la bibliothèque. Les media keys sont des valeurs de type chaîne de caractères au format suivant : 13&#95;875943225764098048. Elles sont entièrement prises en charge sur tous nos endpoints de carte.

De plus, la réponse de la Media Library comprend le `media_id`, représenté sous forme de chaîne de caractères. Celui-ci est inclus pour les ressources qui n’acceptent pas encore de media key : [Tweets](https://developer.x.com/content/developer-twitter/en/docs/ads/creatives/api-reference/tweets#post-accounts-account-id-tweet)*, [Tweet preview](https://developer.x.com/content/developer-twitter/en/docs/ads/creatives/api-reference/tweets#get-accounts-account-id-tweet-preview)* et [Scheduled Tweets](https://developer.x.com/content/developer-twitter/en/docs/ads/creatives/api-reference/scheduled-tweets#post-accounts-account-id-scheduled-tweets). Nous travaillons à la prise en charge des media keys partout.

L’attribut `aspect_ratio` est renvoyé pour les GIF et les vidéos. Il peut être utilisé pour filtrer les médias à utiliser dans les cartes qui n’acceptent que certains ratios d’image.

*Ces endpoints prennent en charge le paramètre `video_id`, qui est une media key.

<div id="identifying-cards">
  ### Identifier les Cards
</div>

<div id="introduction">
  #### Introduction
</div>

Les Cards sont des formats publicitaires personnalisables qui utilisent des médias et peuvent être associées à un site web, une application ou à des appels à l’action afin de générer certaines interactions des utilisateurs, comme l’ouverture d’un Direct Message. Elles peuvent être ajoutées aux Tweets, aux Scheduled Tweets ou aux Draft Tweets.

Les Cards peuvent être référencées dans les objets Tweet de deux façons : par le `card_uri` de la Card ou par son `preview_url`. Des exemples de valeurs pour chacun sont présentés ci-dessous.

| card&#95;uri | preview&#95;url |
| :--- | :--- |
| card://1043282691834048513 | https://cards.x.com/cards/18ce54d4x5t/68w3s |

**Note** : À partir de la version 3 de l’Ads API, seule la `card_uri` est générée et renvoyée dans la réponse `cards` pour les Cards nouvellement créées.

**Note** : À partir de la version 5 de l’Ads API, la `preview_url` dans la réponse `cards` n’est plus renvoyée.

Le type de référence dans la réponse de l’objet Tweet dépend de la manière dont le Tweet a été créé. En d’autres termes, si le Tweet a été créé à l’aide du paramètre de requête `card_uri`, la valeur de l’URI de la Card apparaîtra dans la réponse. Si la `preview_url` a été incluse dans le texte du Tweet, en revanche, l’URL d’aperçu apparaîtra dans la réponse.

<div id="identifying-media">
  ### Identifier les médias
</div>

<div id="introduction">
  #### Introduction
</div>

Les médias — images, GIFs et vidéos — peuvent être ajoutés aux Tweets et aux cartes. De plus, les vidéos peuvent être utilisées comme ressources de pré‑roll et les images peuvent être promues sur la [X Audience Platform](https://developer.x.com/en/docs/ads/measurement/overview/twitter-audience-platform). Cette section décrit comment trouver les références de médias dans ces différentes entités.

Il existe deux types d&#39;identifiants de média : des ID et des clés. Vous trouverez ci‑dessous des exemples de valeurs pour chacun.

| **ID du média** | **Clé de média** |
| :--- | :--- |
| 1029825579531807971 | 13&#95;1029825579531807971 |

La clé de média est l&#39;ID précédé d&#39;un préfixe numérique et d&#39;un trait de soulignement.

<div id="images">
  #### Images
</div>

Le tableau suivant indique les types d’identifiants actuellement disponibles dans la réponse de chaque ressource relative aux images, ainsi que le ou les noms d’attributs correspondants.

| **Ressource** | **Identifiant** | **Attribut(s)** |
| :--- | :--- | :--- |
| Cartes d’image | Aucun |  |
| Tweet | Les deux | `entities["media"]["id_str"]`  `entities["media"]["media_key"]` |
| Tweet programmé | Les deux | `media_ids` et `media_keys` |
| Tweet brouillon | Les deux | `media_ids` et `media_keys` |
| Médias du compte | Aucun |  |
| Bibliothèque de médias | Les deux | `media_id` et `media_key` |

Les cartes d’image et les images des Médias du compte n’incluent aucune référence à un identifiant de média. Les Tweets incluent uniquement des id de média. Les Tweets programmés et les Tweets brouillon incluent à la fois l’id de média et la clé de média. La Bibliothèque de médias renvoie également les deux.

Pour les Tweets, les champs id et id&#95;str de l’objet dans le tableau entities[&quot;media&quot;] correspondent à l’id de média. Lorsqu’un Tweet inclut plusieurs images, les références à chaque entité média ne peuvent être trouvées que dans extended&#95;entities[&quot;media&quot;].

En plus des références aux identifiants, il est souvent important d’avoir accès à l’URL de l’image.

| **Ressource** | **Attribut(s)** | **Format** |
| :--- | :--- | :--- |
| Cartes d’image | `image` | .jpg |
| Tweet* | `entities["media"][0]["media_url"]` ou `extended_entities["media"][i]["media_url"]` | .jpg |
| Tweet programmé | Aucun |  |
| Tweet brouillon | Aucun |  |
| Médias du compte | `media_url` | .jpg |
| Bibliothèque de médias | `media_url` | .jpg |

* L’emplacement de cette URL dépend du fait que le Tweet contienne une seule image ou plusieurs images.

Toutes les cartes d’image incluent un attribut de réponse image qui contient l’URL de l’image X. (Pour les cartes de téléchargement d’applications avec image, le nom est wide&#95;app&#95;image.)

Pour les Tweets, l’emplacement de l’URL du média dépend à la fois du type de média et du point de terminaison (endpoint) utilisé. Pour les Tweets contenant une seule image, l’URL se trouve dans entities[&quot;media&quot;][0][&quot;media&#95;url&quot;]. Cela vaut à la fois pour l’Ads API et l’API Standard. Lorsque les Tweets contiennent plusieurs images, cependant, les URL ne peuvent être trouvées que dans extended&#95;entities[&quot;media&quot;][i][&quot;media&#95;url&quot;]. Cela n’est disponible que dans l’API Standard.

<div id="videos">
  #### Vidéos
</div>

Le tableau suivant indique les types d’identifiants actuellement disponibles dans la réponse de chaque ressource liée aux vidéos, ainsi que le ou les noms d’attributs correspondants.

| **Ressource** | **Identifiant** | **Attribut(s)** |
| :--- | :--- | :--- |
| Cartes vidéo | Peut être l’un ou l’autre | `video_content_id` |
| Cartes de sondage vidéo | Aucun |  |
| Tweet | Les deux | `entities["media"]["id_str"]`  `entities["media"]["media_key"]` |
| Tweet programmé | Les deux | `media_ids` et `media_keys` |
| Tweet brouillon | Les deux | `media_ids` et `media_keys` |
| Médias du compte | Clé de média | `video_id` |
| Médiathèque | Les deux | `media_id` et `media_key` |

Bien que les cartes vidéo (à l’exception des cartes de sondage avec vidéo) incluent un attribut de réponse `video_content_id`, le type de valeur renvoyée n’est pas cohérent. Dans certains cas, il s’agit d’un ID de média ; dans d’autres, d’une clé de média.

Les informations expliquant comment accéder à l’URL de la vidéo sont indiquées ci-dessous.

| **Ressource** | **Attribut(s)** | **Format** |
| :--- | :--- | :--- |
| Cartes vidéo | `video_url` et `video_hls_url` | .vmap  .m3u8 |
| Tweet avec vidéo | `extended_entities["media"][i]["video_info"]["variants"][j]["url"]` | .mp4 |
| Tweet programmé | Aucun |  |
| Tweet brouillon | Aucun |  |
| Médias du compte | Aucun |  |
| Médiathèque | `media_url` | .mp4 |

Les cartes vidéo incluent les attributs de réponse `video_url` et `video_hls_url` avec, respectivement, des URL .vmap et .m3u8.

#### Media Library

Il est parfois nécessaire de récupérer des informations supplémentaires sur une ressource média. Un cas d’utilisation, pour les cartes vidéo, consiste à récupérer l’URL mp4 au lieu de celle en vmap. Ces informations sont disponibles dans la Media Library. Pour plus de détails sur les informations disponibles, consultez notre [Media Library Guide](https://developer.x.com/content/developer-twitter/en/docs/ads/creatives/guides/media-library). La plupart des ressources appartenant à l’utilisateur FULL promotable du compte publicitaire peuvent être consultées dans la Media Library. Il existe cependant quelques exceptions.

**Récupération des médias**

Comme indiqué ci-dessus, les cartes image ne contiennent pas de références ni à des ID de média ni à des clés de média. Par conséquent, il n’est pas possible de récupérer leurs ressources via la Media Library. Cela s’applique également aux images [Account Media](https://developer.x.com/content/developer-twitter/en/docs/ads/creatives/api-reference/account-media#account-media).

Les cartes vidéo exigent que la ressource vidéo fasse partie de la Media Library (ou de la ressource Videos auparavant) avant leur création. En conséquence, ces ressources seront toujours récupérables dans la Media Library. Cela s’applique également aux ressources Account Media PREROLL.

Enfin, les médias présents dans les Tweets sont toujours garantis comme étant dans la Media Library.

Le tableau suivant résume quelles ressources sont récupérables dans la Media Library, en tenant compte du fait que la réponse de la ressource inclut ou non un identifiant à utiliser pour la recherche.

| **Resource** | **In the Media Library** |
| :--- | :--- |
| Image cards | No |
| Video cards | Yes* |
| Tweets (any media)** | Yes |
| Scheduled Tweets | Yes |
| Draft Tweets | Yes |
| Account media images | No |
| Account media videos (`PREROLL`) | Yes |

* Pour les cartes où `video_content_id` est une clé de média. Lorsque la valeur est un ID de média, la ressource existe toujours dans la Media Library, mais sa récupération implique l’ajout d’un préfixe numérique et d’un caractère de soulignement (*).
** Les Tweets ne renvoient que des ID de média. Bien que la ressource soit garantie comme existant dans la Media Library, sa récupération implique l’ajout d’un préfixe numérique et d’un caractère de soulignement (*).

**Interactions avec Account Media**

Il existe deux cas où les ressources média ajoutées à la Media Library sont automatiquement ajoutées à la ressource Account Media.

* Lorsqu’une ressource AMPLIFY&#95;VIDEO est ajoutée à la Media Library, elle est automatiquement ajoutée comme ressource Account Media avec un type de création publicitaire PREROLL.
* Lorsque des images ayant des dimensions spécifiques (voir « Creative Types » sur notre [page des énumérations](https://developer.x.com/content/developer-twitter/en/docs/ads/general/overview/enums)) sont ajoutées à la Media Library, elles sont automatiquement ajoutées comme ressources Account Media. Le type de création publicitaire (par exemple, INTERSTITIAL) dépend des dimensions de l’image.

<div id="tweets">
  ### Tweets
</div>

<div id="introduction">
  #### Introduction
</div>

L&#39;API X Ads prend en charge trois types de Tweets : publiés, planifiés et brouillons.

<div id="nullcasted-tweets">
  #### Tweets en nullcast
</div>

Les Tweets peuvent être soit en nullcast (également appelés « Promoted-only »), soit organiques. Les Tweets en nullcast, une fois publiés, n&#39;apparaissent pas dans la timeline publique de l&#39;utilisateur, même s&#39;ils restent publics. Les Tweets organiques, en revanche, sont diffusés aux abonnés de l&#39;utilisateur et apparaissent dans la timeline publique de celui-ci.

**Création de Tweets**

Chacun des trois endpoints de création de Tweet accepte un paramètre booléen nullcast qui donne à l&#39;utilisateur de l&#39;API la possibilité de créer des Tweets en nullcast ou organiques. Les Tweets en nullcast peuvent être créés par l&#39;utilisateur ou par toute personne disposant de l&#39;autorisation de créer des Tweets pour le compte de l&#39;utilisateur. Les Tweets organiques peuvent uniquement être créés par le [full promotable user](https://developer.x.com/content/developer-twitter/en/docs/tutorials/ads-api-hierarchy-terminology#promotable-users).

**Mise à jour des Tweets**

Il est possible de mettre à jour la propriété nullcast pour les Tweets programmés et les Tweets en brouillon. Pour les Tweets programmés, les modifications peuvent être effectuées jusqu&#39;à l&#39;heure scheduled&#95;at du Tweet. Les Tweets en brouillon peuvent être modifiés indéfiniment. Une fois publiés, toutefois, il n&#39;est pas possible de changer un Tweet de nullcast en organique, ou inversement.

<div id="promoting-tweets">
  #### Promotion de Tweets
</div>

Seuls les Tweets publiés ou programmés peuvent être promus. Ils peuvent être nullcastés ou organiques ; il n&#39;y a aucune restriction à ce niveau. Un annonceur peut promouvoir ses propres Tweets ou les Tweets d&#39;un autre utilisateur, à condition d&#39;avoir obtenu l&#39;autorisation de le faire. (Voir : [Promoting another user&#39;s Tweets](https://developer.x.com/content/developer-twitter/en/docs/tutorials/promoting-another-users-content) pour plus d&#39;informations.)

Plusieurs Tweets peuvent être promus dans une seule campagne. De même, un seul Tweet peut être promu dans une ou plusieurs campagnes.

Pour promouvoir des Tweets publiés, utilisez l&#39;endpoint [POST accounts/:account&#95;id/promoted&#95;tweets](https://developer.x.com/content/developer-twitter/en/docs/ads/campaign-management/api-reference/promoted-tweets#post-accounts-account-id-promoted-tweets). Cela associe des Tweets publiés à un line item. Pour promouvoir des Tweets programmés, utilisez l&#39;endpoint [POST accounts/:account&#95;id/scheduled&#95;promoted&#95;tweets](https://developer.x.com/content/developer-twitter/en/docs/ads/campaign-management/api-reference/scheduled-promoted-tweets#post-accounts-account-id-scheduled-promoted-tweets).

<div id="tweet-ids">
  #### Identifiants de Tweet
</div>

Les identifiants de Tweet publiés, programmés ou en brouillon sont [numériques](https://developer.x.com/content/developer-twitter/en/docs/basics/twitter-ids) : ce sont des entiers non signés de 64 bits. Par exemple, l&#39;identifiant du Tweet publié suivant est 1166476031668015104.

<div id="carousels">
  ### Carrousels
</div>

<div id="introduction">
  #### Introduction
</div>

L&#39;API X Ads prend en charge la création et la consultation de carrousels vidéo et de carrousels d&#39;images. Le carrousel est un type de carte qui peut contenir entre 2 et 6 éléments média. La carte carrousel peut diriger un utilisateur vers un site Web ou l&#39;inciter à installer une application mobile. Pour plus d&#39;informations sur les carrousels, leurs avantages, les bonnes pratiques et la FAQ, consultez notre page [Carousel Ads on X](https://business.x.com/en/advertising/carousels.html).

Un carrousel, comme tout autre type de carte, peut être utilisé dans des Publications et ces Publications peuvent ensuite être promues. Le flux de travail est le même que celui auquel vous êtes déjà habitué :

1. Télécharger les médias
2. Créer la carte
3. Créer la Publication
4. Promouvoir la Publication

La seule différence concerne la façon dont la carte est créée. Alors que les autres requêtes de création de carte acceptent des paramètres de requête, les requêtes de création de cartes carrousel n&#39;acceptent qu&#39;un corps JSON dans une requête POST.

<div id="endpoints">
  #### Points de terminaison
</div>

L’API Ads permet de créer et de consulter des carrousels.

Pour créer un carrousel — quel qu’il soit — utilisez le point de terminaison [POST accounts/:account&#95;id/cards](https://developer.x.com/en/docs/twitter-ads-api/creatives/api-reference/cards#post-accounts-account-id-cards). Pour consulter des carrousels, utilisez le point de terminaison [GET accounts/:account&#95;id/cards](https://developer.x.com/en/docs/twitter-ads-api/creatives/api-reference/cards#get-accounts-account-id-cards).

<div id="json-post-body">
  #### Corps de la requête POST JSON
</div>

Les carrousels sont créés à l&#39;aide de deux composants. Le premier spécifie les ressources multimédias qui seront utilisées. Le second spécifie des informations concernant soit le site Web, soit l&#39;application.

Plus précisément, une carte de carrousel est créée en utilisant les composants suivants, dans cet ordre :

* Un composant `SWIPEABLE_MEDIA`, qui accepte un tableau de clés média
* *Un* des éléments suivants :
* Un composant `DETAILS` pour spécifier les informations du site Web
* Un composant `BUTTON` pour spécifier les informations de l&#39;application

Le composant `SWIPEABLE_MEDIA` doit inclure un tableau `media_keys` dans lequel vous pouvez spécifier entre 2 et 6 images ou vidéos. L&#39;ordre dans lequel les clés média sont fournies détermine l&#39;ordre dans lequel elles seront rendues.

```
{
  "type": "SWIPEABLE_MEDIA",
  "media_keys": [
    "13_1089771253848666112",
    "13_1191948012077092867"
  ]
}
```

Pour rappel, vous pouvez obtenir des clés média en envoyant une requête à l’endpoint [GET accounts/:account&#95;id/media&#95;library](https://developer.x.com/en/docs/twitter-ads-api/creatives/api-reference/media-library#get-accounts-account-id-media-library).

La composition du deuxième objet de composant dépend du fait que vous souhaitiez rediriger un utilisateur vers un site web ou l’encourager à installer une application. Le tableau ci-dessous résume les deux options. (**Remarque** : toutes les clés répertoriées sont obligatoires.)

|                            | **Site web**                                                       | **Application**                                   |
| :------------------------- | :----------------------------------------------------------------- | :------------------------------------------------ |
| Specify the component type | `"type": "DETAILS"`                                                | `"type": "BUTTON"`                                |
| Title/Label                | `"title": "X"`                                                     | `"label": { "type": "ENUM", "value": "INSTALL" }` |
| Destination                | `"destination": { "type": "WEBSITE", "url": "https://www.x.com" }` | `"destination": { "type": "APP", ... }`           |

En combinant ces éléments, un exemple de corps de requête POST JSON pour un carrousel de site web est présenté ci-dessous.

```
{
  "name": "website carousel",
  "components": [
    {
      "type": "SWIPEABLE_MEDIA",
      "media_keys": [
        "13_1089771253848666112",
        "13_1191948012077092867"
      ]
    },
    {
      "type": "DETAILS",
      "title": "X",
      "destination": {
        "type": "WEBSITE",
        "url": "https://www.x.com"
      }
    }
  ]
}
```

Les objets de destination d&#39;application au sein des composants `BUTTON` nécessitent un code de pays et au moins un identifiant d&#39;application. Ils peuvent également accepter des liens profonds (deep links). Pour une description de ces champs, consultez la [documentation de référence](https://developer.x.com/en/docs/twitter-ads-api/creatives/api-reference/cards#app-destination).

En réunissant ces éléments, un exemple de corps de requête POST JSON pour un carrousel d&#39;applications est présenté ci-dessous.

```
{
  "name": "app carousel",
  "components": [
    {
      "type": "SWIPEABLE_MEDIA",
      "media_keys": [
        "13_1089771253848666112",
        "13_1191948012077092867"
      ]
    },
    {
      "type": "BUTTON",
      "label": {
        "type": "ENUM",
        "value": "INSTALL"
      },
      "destination": {
        "type": "APP",
        "country_code": "US",
        "googleplay_app_id": "com.twitter.android",
        "iphone_app_id": "333903271"
      }
    }
  ]
}
```

<div id="creative-metadata-tagging">
  ### marquage des métadonnées des créations
</div>

<div id="introduction">
  #### Introduction
</div>

Ce guide s’adresse aux partenaires créatifs, aux agences et aux développeurs créatifs, afin de taguer les ressources utilisées dans les campagnes X pour mieux comprendre la valeur et les performances de chaque ressource.

**Remarque :** Les ressources média ne doivent être taguées que par le partenaire ou le développeur qui crée la ressource média. Si l’utilisateur de la ressource média n’est pas celui qui l’a créée, n’implémentez pas le marquage de métadonnées.

Le marquage des métadonnées créatives permet d’attribuer les images et les vidéos aux partenaires créatifs qui les ont créées, quel que soit l’endroit où la ressource est téléversée sur X ou quelle que soit l’entité qui téléverse la ressource. Pour établir le lien entre la ressource créative et le partenaire créatif, la norme [XMP](https://exiftool.org/TagNames/XMP.html) est utilisée.

<div id="tagging-creative-assets">
  #### Balisage des éléments créatifs
</div>

Le tableau suivant présente les types d&#39;identifiants actuellement disponibles dans la Réponse de chaque ressource liée aux images, ainsi que le ou les noms d&#39;attributs correspondants. Un outil de balisage est nécessaire pour baliser les éléments créatifs. [ExifTool](https://exiftool.org/), une bibliothèque Perl multiplateforme ainsi qu&#39;une [application en ligne de commande](https://exiftool.org/exiftool_pod.html) pour lire, écrire et modifier les métadonnées, est recommandé. Consultez tous les [types de fichiers](https://exiftool.org/#supported) pris en charge.

Suivez les [instructions d&#39;installation d&#39;ExifTool](https://exiftool.org/install.html) fournies. Il existe également des paquets logiciels proposés par [Homebrew](https://formulae.brew.sh/) pour simplifier davantage l&#39;installation en fournissant la [commande d&#39;installation exiftool](https://formulae.brew.sh/formula/exiftool) pour macOS et Linux. Vérifiez que votre outil est correctement installé en saisissant la commande exiftool -ver dans la ligne de commande afin d&#39;afficher le numéro de version de l&#39;outil. Pour en savoir plus sur les paramètres de commande ExifTool, consultez la [documentation ExifTool](https://exiftool.org/).

Les partenaires créatifs peuvent attribuer des balises de métadonnées à de nouveaux éléments créatifs ou à des éléments existants en renseignant leur X app&#95;id dans la balise XMP contributor et la balise date. Les éléments créatifs respecteront les restrictions de taille existantes lors du [Téléversement de médias](https://developer.x.com/en/docs/twitter-api/v1/media/upload-media/overview). 

**Remarque :** l&#39;utilisation par X de la balise XMP contributor garantit que les métadonnées ne capturent que des valeurs pour les campagnes sur X exclusivement.

`exiftool -contributor="<YOUR APP ID>" -creative_file.jpg`

`exiftool -date="<date>" -creative_file.jpg`

L&#39;app&#95;id peut être trouvé dans la [Developer Console](https://developer.x.com/en/portal/dashboard) sous Projects &amp; Apps. Exemple : 16489123

L&#39;exemple suivant ajoute app&#95;id en tant que balise contributor et date en tant que balise date pour une image :

```
app_id:858382169
```

```
date:2022-03-13
```

```
creative_file: eiffel_tower.jpg
```

```
exiftool -contributor=858382169 eiffel_tower.jpg
```

```

```

```
exiftool -date=2022-03-13 eiffel_tower.jpg
```

```

```

`exiftool -xmp:all -G1 <filename>`

Les requêtes de création de carte acceptent uniquement un corps de requête POST JSON. Le `Content-Type` doit être défini à `application/json`.

Consultez notre [Guide des carrousels](https://developer.x.com/en/docs/twitter-ads-api/creatives/guides/carousels) pour un exemple d’utilisation détaillé.

</div>

`https://ads-api.x.com/12/accounts/:account_id/cards`

#### Paramètres

Le corps de la requête POST au format JSON doit inclure un champ `name` pour la carte et un tableau de `components`. Les composants sont représentés sous forme d’objets et décrivent les attributs de la carte visibles par l’annonceur.

L’exemple suivant montre la structure générale de la charge utile (mais contient des informations non valides).

```
{
  "name": "some name",
  "components": [
    {
      "type": "TYPE_ENUM",
      "key": "value"
    }
  ]
}
```

Informations supplémentaires sur les composants ci-dessous.

| Nom                                | Description                                                                                                                                                                                                                                                                                                                                                                                                             |
| :--------------------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| account&#95;id   *Obligatoire*     | Identifiant du compte utilisé. Apparaît dans le chemin de la ressource et est généralement un paramètre obligatoire pour toutes les requêtes de l’Advertiser API, à l’exception de [GET accounts](https://developer.x.com/en/docs/ads/campaign-management/api-reference/accounts#get-accounts). Le compte spécifié doit être associé à l’utilisateur authentifié.  Type : chaîne de caractères  Exemple : `18ce54d4x5t` |
| name   *Obligatoire*               | Nom de la carte. Longueur maximale : 80 caractères.  Type : chaîne de caractères  Exemple : `component based card`                                                                                                                                                                                                                                                                                                      |
| components   *Parfois obligatoire* | Décrit les composants à utiliser pour créer la carte. Informations supplémentaires ci-dessous.  Ne peut pas être spécifié avec `slides`.  **Remarque** : l’ordre des composants est important.  Type : tableau d’objets                                                                                                                                                                                                 |
| slides   *Parfois obligatoire*     | Utilisez ce tableau de tableaux pour créer des carrousels à destinations multiples.  Décrit chaque carte comme un groupe de composants. <div id="components">
  #### Composants
</div>

Chaque composant doit inclure un champ `type` qui détermine le schéma de l&#39;objet. L’API Ads prend en charge les types de composants suivants, regroupés en composants basés sur les médias et sur la description.

* Média :
* `MEDIA` : une seule vidéo ou image
* `SWIPEABLE_MEDIA` : entre 2 et 6 vidéos ou images
* Description :
* `DETAILS`
* `BUTTON`

Chaque composant possède un ensemble de champs obligatoires (en plus de la clé `type`). Ceux-ci sont répertoriés dans le tableau suivant.

| Component `type`  | Champ                   | Type de valeur                   |
| :---------------- | :---------------------- | :------------------------------- |
| `MEDIA`           | `media_key`             | chaîne de caractères             |
| `SWIPEABLE_MEDIA` | `media_keys`            | tableau de chaînes de caractères |
| `DETAILS`         | `title`   `destination` | chaîne de caractères   objet     |
| `BUTTON`          | `label`   `destination` | objet   objet                    |

Voici un exemple de composant `BUTTON` dans le contexte du tableau `components` (en omettant intentionnellement la clé `name`). Les ellipses indiquent les endroits où des informations supplémentaires doivent être spécifiées.

```
{
  "components": [
    {
      "type": "BUTTON",
      "label": {
        ...
      },
      "destination": {
        ...
      }
    }
  ]
}
```

L&#39;ordre dans lequel les objets composant sont spécifiés détermine l&#39;ordre d&#39;affichage, de haut en bas. Les Cards doivent être créées à l&#39;aide d&#39;un composant média et d&#39;un composant `DETAILS` ou `BUTTON`. Les composants basés sur une description sont rendus sous le média et ont des destinations associées, soit des URL, soit des applications mobiles.

**Label**

Les libellés définissent le texte affiché sur les boutons et, par conséquent, ne s&#39;appliquent qu&#39;au composant `BUTTON`. Les objets de type `label` ont deux clés obligatoires : `type` et `value`. Le `type` doit avoir la valeur `ENUM` et la `value` peut être l&#39;une des valeurs suivantes : `BOOK`, `CONNECT`, `INSTALL`, `OPEN`, `ORDER`, `PLAY` ou `SHOP`.

En reprenant l&#39;exemple précédent, l&#39;exemple suivant montre l&#39;objet `label` au sein du composant `BUTTON`.

```
{
  "components": [
    {
      "type": "BUTTON",
      "label": {
        "type": "ENUM",
        "value": "INSTALL"
      },
      "destination": {
        ...
      }
    }
  ]
}
```

**Destination**

Les destinations correspondent à l’endroit où les annonceurs souhaitent amener les utilisateurs. Elles sont toujours obligatoires dans les composants `DETAILS` ou `BUTTON`. Il existe deux types de destination : `WEBSITE` ou `APP`.

**Remarque** : Les destinations de type site web ne peuvent être utilisées qu’avec les composants `DETAILS` et les destinations de type application ne peuvent être utilisées qu’avec les composants `BUTTON`.

**Destination de site web**

| Nom                  | Description                                                                                                                                   |
| :------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------- |
| type   *Obligatoire* | Le type de destination, qui détermine son schéma.  Type : enum  Valeurs possibles : `WEBSITE`                                                 |
| url   *Obligatoire*  | L’URL du site web vers lequel rediriger un utilisateur.  Type : chaîne de caractères  Exemple : `https://devcommunity.x.com/c/advertiser-api` |

**Destination d’application**

| Nom                                                          | Description                                                                                                                                                                                                                            |
| :----------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| type   *Obligatoire*                                         | Le type de destination, qui détermine son schéma.  Type : enum  Valeurs possibles : `APP`                                                                                                                                              |

<div id="post-accountsaccount_idtweet">
  #### POST accounts/:account_id/tweet
</div>

Créez une Publication pour l’utilisateur promouvable complet du compte (par défaut) ou pour l’utilisateur spécifié dans le paramètre `as_user_id`. La création de Publications nullcastées (par défaut) et organiques est prise en charge. Les Publications nullcastées n’apparaissent pas dans la timeline publique et ne sont pas diffusées aux abonnés. Les deux types peuvent être utilisés dans des campagnes.

Si l’utilisateur authentifié n’est pas l’utilisateur promouvable `FULL` sur ce compte, vérifiez s’il a l’autorisation de créer des Publications en son nom en effectuant une requête vers le point de terminaison [GET accounts/:account&#95;id/authenticated&#95;user&#95;access](https://developer.x.com/en/docs/ads/campaign-management/api-reference/authenticated-user-access#get-accounts-account-id-authenticated-user-access). Une permission `TWEET_COMPOSER` indique que l’utilisateur peut utiliser ce point de terminaison pour créer des Publications nullcastées au nom de l’[utilisateur promouvable](https://developer.x.com/en/docs/ads/campaign-management/api-reference/promotable-users#get-accounts-account-id-promotable-users) `FULL`.

Lorsque vous utilisez le [point de terminaison upload.x.com](https://developer.x.com/rest/reference/post/media/upload) pour les médias, transmettez la même valeur `user_id` pour le paramètre `additional_owners` que la valeur `as_user_id` que vous transmettez à ce point de terminaison.
