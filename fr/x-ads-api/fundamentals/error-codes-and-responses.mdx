<div id="typical-response-structure">
  ## Structure type d&#39;une réponse
</div>

Les réponses réussies sont indiquées par un code HTTP de la série 200 et un corps JSON contenant le ou les objets demandés, créés, modifiés ou supprimés, ainsi qu&#39;une indication de la façon dont le serveur a interprété votre requête.

Si vous envoyez une requête réussie, vous recevez dans votre réponse un nœud `request` qui reprend votre requête.

*Exemple :* [GET accounts/abcdefg/campaigns?with&#95;deleted=true](/fr/x-ads-api/campaign-management#campaigns)

```json
{
  /* les données de votre réponse... */,
  "request": {
    "params": {
      "account_id": "abcdefg",
      "with_deleted": "true"
    }
  }
}
```

Le champ `data` dans les réponses JSON contiendra les objets spécifiques associés à la ressource concernée. Le format du nœud `data` sera un tableau JSON lorsque la réponse peut contenir un ou plusieurs résultats. Il sera renvoyé sous forme de hash JSON lorsqu’un seul résultat est possible dans la réponse. Dans de rares cas, vous pouvez voir une réponse qui inclurait normalement une collection, mais qui utilise à la place une hashmap. Dans ce cas, considérez que la hashmap unique est un objet du même type que celui indiqué dans le champ `type`.

<div id="error-response-structure">
  ## Structure de la Réponse d’erreur
</div>

Les réponses d’erreur sont renvoyées avec un code HTTP en dehors de la série 200. En général, une réponse JSON y est associée, mais certaines erreurs renverront d’autres types de contenu. Dans ces situations où la structure de la réponse ne peut pas être analysée, considérez que la signification principale du code HTTP prévaut. Par exemple, vous pouvez parfois voir un code HTTP 404 accompagné d’une réponse HTML. Dans ce cas, il est raisonnable de supposer que le contenu est introuvable (HTTP 404 signifie « Not Found »).

Les réponses d’erreur typiques suivent une structure similaire à celle des réponses réussies. La nature de l’erreur est communiquée dans un nœud `errors` de la réponse. Le nœud `errors/code` indiquera un code d’erreur constant en MAJUSCULES&#95;AVEC&#95;UNDERSCORES que vous pouvez exploiter par programme pour prendre des décisions de résolution. Le nœud `errors/message` indiquera une description (généralement) lisible par un humain de l’erreur, en anglais. Des champs supplémentaires peuvent être associés pour indiquer des détails plus précis sur l’erreur.

```json
{
  "errors": [
    {
      "parameter": "start_time",
      "details": "invalid date",
      "code": "INVALID_PARAMETER",
      "value": "",
      "message": "Heure attendue, \"\" reçu pour start_time"
    }
  ],
  "request": {
    "params": {
      "account_id": "hkk5"
    }
  }
}
```

Dans l’exemple ci-dessus, une requête a été envoyée à un endpoint d’analytics avec une valeur invalide pour le paramètre `start_time`. Le `errors/code` associé aux requêtes comportant des paramètres invalides est `INVALID_PARAMETER`.
