<div id="user-accounts-vs-ad-accounts">
  # Comptes utilisateur vs comptes publicitaires
</div>

Deux types de comptes différents interviennent dans l’utilisation de l’Ads API : les comptes publicitaires et les comptes utilisateur X. Dans l’ensemble de la documentation de l’Ads API, le terme « compte » fait généralement référence au compte publicitaire.

* Les comptes publicitaires sont enregistrés sur **business.x.com** et identifiés dans l’API par account&#95;id. Les comptes publicitaires sont directement liés à des sources de financement et utilisent le contenu d’un ou plusieurs comptes utilisateur X en tant que « promotable users ». Chaque compte publicitaire peut accorder des autorisations à un ou plusieurs comptes utilisateur X. Le compte publicitaire, ou « compte actuel », est représenté dans presque toutes les URL exécutées sous la forme d’un paramètre en ligne :account&#95;id.
* Les comptes utilisateur X (comme @AdsAPI) sont identifiés par user&#95;id dans l’Ads API. Un ou plusieurs de ces comptes peuvent être associés à un compte publicitaire. Le compte utilisateur X authentifié qui effectue des requêtes sur l’API est appelé « utilisateur actuel ». La liste des comptes publicitaires auxquels l’utilisateur actuel a accès est disponible via [GET accounts](/fr/x-ads-api/campaign-management#accounts). Les « promotable users » sont des handles X qui peuvent être promus par un compte publicitaire spécifique. Pour plus de détails à ce sujet, consultez [Obtaining Ads Account Access](/fr/x-ads-api/introduction).

<div id="methods-for-ad-account-access">
  ## Méthodes d’accès aux comptes publicitaires
</div>

Il existe deux méthodes que vous pouvez utiliser pour effectuer des requêtes vers l’API Ads pour le compte d’un annonceur :

1. Effectuer des requêtes au nom d’un annonceur (**recommandé**)
2. Effectuer des requêtes en utilisant votre propre compte, auquel a été accordé l’accès au compte d’un annonceur, par exemple une [agence](https://business.x.com/en/blog/agencies-manage-multiple-Twitter-Ads-accounts.html) gérant plusieurs comptes.

Ce document propose un bref aperçu des différences entre ces options et doit être utilisé conjointement avec nos autres ressources, telles que la [FAQ sur la connexion multi-utilisateurs](https://business.x.com/en/help/troubleshooting/multi-user-login-faq.html). 

Comme décrit dans [Authorizing a request](/fr/resources/fundamentals/authentication#authorizing-a-request#authorizing-a-request), toutes les requêtes vers l’API Ads nécessitent des en-têtes d’autorisation utilisant [OAuth 1.0a](/fr/resources/fundamentals/authentication) avec un jeton d’accès obtenu via un flux [3-legged](/fr/resources/fundamentals/authentication#obtaining-access-tokens-using-3-legged-oauth-flow) [OAuth](/fr/resources/fundamentals/authentication#obtaining-access-tokens-using-3-legged-oauth-flow). Votre application devra implémenter un flux OAuth basé sur le Web pour [obtenir des jetons d’accès](/fr/resources/fundamentals/authentication#oauth-1-0a-2). Les développeurs de l’API Ads ne doivent jamais demander à nos annonceurs X de partager leurs identifiants de connexion.

Par défaut, chaque [application développeur X](/fr/resources/fundamentals/developer-apps) contient un **jeton d’accès** statique qui peut être utilisé pour effectuer des requêtes vers l’API Ads pour le compte qui possède l’application. Ces identifiants sont idéaux pour les cas d’usage à compte unique, sans nécessiter de flux OAuth 3-legged ou [basé sur un code PIN](/fr/resources/fundamentals/authentication#pin-based-authorization). Si vous n’accédez pas à un autre compte X Ads, utilisez ces identifiants [single-user](/fr/resources/fundamentals/authentication#oauth-1-0a-2) plutôt que les étapes suivantes.

<div id="levels-of-access">
  ## Niveaux d’accès
</div>

<div id="app-level-permissions">
  ### Autorisations au niveau de l’App
</div>

Chaque utilisateur disposera d’un niveau d’accès correspondant à ce qui a été demandé lors de la [demande d’accès à l’Ads API](/fr/x-ads-api/getting-started/step-by-step-guide) :

* **Conversions uniquement** : L’utilisateur dispose d’un accès aux endpoints [Mobile](/fr/x-ads-api/measurement/mobile-conversions) et [Web Conversion](/fr/x-ads-api/measurement/web-conversions) avec des autorisations de [lecture et écriture](/fr/resources/fundamentals/developer-apps).
* **Accès standard** : L’utilisateur dispose d’un accès aux endpoints [Analytics](/fr/x-ads-api/analytics), [Gestion des campagnes](https://developer.x.com/en/docs/twitter-ads-api/campaign-management/overview), [Creatives](https://developer.x.com/en/docs/twitter-ads-api/creatives/overview), [Audiences personnalisées](https://developer.x.com/en/docs/twitter-ads-api/audiences/overview) et [Conversion](/fr/x-ads-api/measurement/web-conversions) avec des autorisations de [lecture et écriture](/fr/resources/fundamentals/developer-apps).

**Remarque :** Les développeurs Ads API qui ont demandé l’accès avant juillet 2023 peuvent disposer de niveaux d’accès et d’autorisations différents et peuvent être limités à cinq jetons OAuth. Consultez notre guide sur l’[augmentation de l’accès](/fr/x-ads-api/getting-started/increasing-access) pour obtenir un accès à des endpoints supplémentaires ou lever les limites de jetons pour les Apps existantes.

<div id="ad-account-level-permissions">
  ### Autorisations au niveau du compte publicitaire
</div>

Chaque utilisateur qui a accès à un compte publicitaire disposera d&#39;une autorisation spécifique au niveau du compte : **Administrateur de compte**, **Gestionnaire de publicités**, **Analyste de campagnes**, **Analyste organique** et **Gestionnaire de créations** ; consultez **business.x.com** pour la documentation la plus récente concernant les autorisations au niveau du compte. Les applications doivent récupérer les autorisations pour l&#39;utilisateur actuellement authentifié via le point de terminaison d&#39;API [Authenticated User Access](/fr/x-ads-api/campaign-management#authenticated-user-access) afin de déterminer à quels points de terminaison d&#39;API et à quelles fonctionnalités publicitaires elles peuvent accéder.

**Remarque :** Tous les jetons utilisateur utilisés avec la [Conversion API](/fr/x-ads-api/measurement/web-conversions) doivent appartenir à des utilisateurs disposant d&#39;autorisations au niveau du compte **Administrateur de compte** ou **Gestionnaire de publicités**.                                                                                                                                              

<div id="methods-of-obtaining-access-tokens">
  ## Méthodes pour obtenir des jetons d’accès
</div>

<div id="1-obtain-an-advertisers-user-access-token">
  ### 1. Obtenir le jeton d&#39;accès (Utilisateur) d&#39;un annonceur
</div>

Il existe deux méthodes pour obtenir le **jeton d&#39;accès** d’un annonceur. La méthode la plus courante consiste à utiliser un [flux OAuth à 3 volets](/fr/resources/fundamentals/authentication#obtaining-access-tokens-using-3-legged-oauth-flow) directement depuis votre interface web. Les applications qui n’ont pas d’interface publique accessible aux annonceurs peuvent implémenter un processus OAuth [basé sur un code PIN](/fr/resources/fundamentals/authentication#pin-based-authorization). Une fois que l’utilisateur a terminé le flux à 3 volets, votre application disposera des identifiants lui permettant d’effectuer des requêtes pour son compte publicitaire via l’API.

L’obtention d’identifiants utilisateur via un flux OAuth est la méthode que nous **recommandons fortement** à la majorité des développeurs de l’API Ads pour obtenir l’accès à un compte annonceur. Elle vous permet d’appeler l’API au nom d’un utilisateur et d’effectuer des actions en tant que cet utilisateur. Ces jetons n’expirent pas mais peuvent être révoqués par l’utilisateur à tout moment.

<div id="2-obtain-your-developer-access-token">
  ### 2. Obtenir votre jeton d’accès (développeur)
</div>

Cette option nécessite que l’annonceur [accorde à votre @username](https://business.x.com/en/help/troubleshooting/multi-user-login-faq.html) (ou à vos @usernames) l’accès à son compte X Ads via l’interface X sur business.x.com. Les **jetons d’accès** obtenus via le flux OAuth à trois volets pour votre compte pourront accéder au compte X Ads de l’annonceur.

Cela vous permet d’appeler l’API en utilisant les jetons OAuth de votre propre @username plutôt que les jetons OAuth de l’annonceur. La principale différence avec cette option est que vous ne pourrez créer des Publications uniquement promues que si l’autorisation de délégation/de création de Publications a été accordée à votre @username.

Pour obtenir l’accès à la création de Publications uniquement promues pour le compte de l’utilisateur promouvable `FULL` associé au compte, vous devez également recevoir l’autorisation de créer des Publications dans ce flux. Cela vous donnera accès via la permission `TWEET_COMPOSER` sur l’endpoint [GET accounts/:account&#95;id/authenticated&#95;user&#95;access](/fr/x-ads-api/campaign-management#accounts).

<div id="differences-between-these-methods">
  ## Différences entre ces méthodes
</div>

|     |     |     |
| :--- | :--- | :--- |
|     | Jeton OAuth annonceur (utilisateur) | Jeton OAuth (développeur)  <br /> (@username ajouté à un compte distinct) |
| Accéder au compte X Ads | ✔   | ✔   |
| Créer des Publications pour le compte de l’utilisateur | ✔   | ✔*  |
| Gérer les campagnes | ✔   | ✔   |
| Accéder aux statistiques | ✔   | ✔   |
| Créer des Cards pour le compte de l’utilisateur | ✔   | ✔   |
| Possibilité pour le développeur d’accéder  <br />via l’interface X Ads |     | ✔   |
| [Limites de taux](/fr/x-api/enterprise-gnip-2.0/fundamentals/rate-limits) | Distinct pour chaque annonceur | Distinct pour chaque compte annonceur |
