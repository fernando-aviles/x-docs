<div id="user-accounts-vs-ad-accounts">
  # Comptes utilisateur vs comptes publicitaires
</div>

Deux types de comptes différents entrent en jeu lors de l’utilisation de l’Ads API : les comptes publicitaires et les comptes utilisateur X. Dans l’ensemble de la documentation de l’Ads API, le terme « compte » fait généralement référence au compte publicitaire.

* Les comptes publicitaires sont enregistrés sur **business.x.com** et identifiés dans l’API par account&#95;id. Les comptes publicitaires sont directement liés aux sources de financement et utilisent le contenu d’un ou plusieurs comptes utilisateur X en tant qu’« utilisateurs promouvables ». Chaque compte publicitaire peut accorder une autorisation à un ou plusieurs comptes utilisateur X. Le compte publicitaire, ou « compte actuel », est représenté dans presque toutes les URL exécutées sous la forme d’un paramètre en ligne :account&#95;id.
* Les comptes utilisateur X (comme @AdsAPI) sont identifiés par user&#95;id dans l’Ads API. Un ou plusieurs de ces comptes peuvent être associés à un compte publicitaire. Le compte utilisateur X authentifié qui effectue des requêtes vers l’API est appelé « utilisateur actuel ». Une liste des comptes publicitaires auxquels l’utilisateur actuel a accès est disponible avec [GET accounts](/fr/x-ads-api/campaign-management#accounts). Les « utilisateurs promouvables » sont des identifiants (handles) X qui peuvent être promus par un compte publicitaire spécifique. Pour plus de détails à ce sujet, voir [Obtaining Ads Account Access](/fr/x-ads-api/introduction).

<div id="methods-for-ad-account-access">
  ## Méthodes d’accès aux comptes publicitaires
</div>

Il existe deux méthodes que vous pouvez utiliser pour effectuer des requêtes à l’Ads API pour le compte d’un annonceur :

1. Effectuer des requêtes pour le compte d’un annonceur (**recommandé**)
2. Effectuer des requêtes en utilisant votre propre compte qui a obtenu l’accès au compte d’un annonceur, par exemple une [agence](https://business.x.com/en/blog/agencies-manage-multiple-Twitter-Ads-accounts.html) qui gère plusieurs comptes.

Ce document propose un bref aperçu des différences entre ces options et doit être utilisé conjointement avec nos autres ressources, comme la [FAQ sur la connexion multi-utilisateur](https://business.x.com/en/help/troubleshooting/multi-user-login-faq.html). 

Comme décrit dans [Authorizing a request](/fr/resources/fundamentals/authentication#authorizing-a-request#authorizing-a-request), toutes les requêtes vers l’Ads API nécessitent des en-têtes Authorization utilisant [OAuth 1.0a](/fr/resources/fundamentals/authentication) avec un jeton d’accès obtenu via un flux OAuth en [3 étapes](/fr/resources/fundamentals/authentication#obtaining-access-tokens-using-3-legged-oauth-flow) [OAuth](/fr/resources/fundamentals/authentication#obtaining-access-tokens-using-3-legged-oauth-flow). Votre application devra implémenter un flux OAuth basé sur le Web pour [obtenir des jetons d’accès](/fr/resources/fundamentals/authentication#oauth-1-0a-2). Les développeurs de l’Ads API ne doivent jamais demander à nos annonceurs X de partager leurs identifiants de connexion.

Par défaut, chaque [App développeur X](/fr/resources/fundamentals/developer-apps) contient un **jeton d’accès** statique qui peut être utilisé pour effectuer des requêtes à l’Ads API pour le compte propriétaire de l’application. Ces identifiants sont idéaux pour les cas d’usage à compte unique, sans nécessiter de flux OAuth en 3 étapes ou basé sur un [code PIN](/fr/resources/fundamentals/authentication#pin-based-authorization). Si vous n’accédez pas à un autre compte X Ads, utilisez plutôt ces identifiants [single-user](/fr/resources/fundamentals/authentication#oauth-1-0a-2) que les étapes suivantes.

<div id="levels-of-access">
  ## Niveaux d’accès
</div>

<div id="app-level-permissions">
  ### Autorisations au niveau de l’application
</div>

Chaque utilisateur disposera d’un niveau d’accès tel que demandé lors de la [demande d’accès à l’Ads API](/fr/x-ads-api/getting-started/step-by-step-guide) :

* **Conversion uniquement** : l’utilisateur a accès aux endpoints [Mobile](/fr/x-ads-api/measurement/mobile-conversions) et [Web Conversion](/fr/x-ads-api/measurement/web-conversions) avec des droits de [lecture et écriture](/fr/resources/fundamentals/developer-apps).
* **Accès standard** : l’utilisateur a accès aux endpoints [Analytics](/fr/x-ads-api/analytics), [Campaign Management](https://developer.x.com/en/docs/twitter-ads-api/campaign-management/overview), [Creatives](https://developer.x.com/en/docs/twitter-ads-api/creatives/overview), [Custom Audiences](https://developer.x.com/en/docs/twitter-ads-api/audiences/overview) et [Conversion](/fr/x-ads-api/measurement/web-conversions) avec des droits de [lecture et écriture](/fr/resources/fundamentals/developer-apps).

**Remarque :** les développeurs Ads API qui ont demandé l’accès avant juillet 2023 peuvent disposer de niveaux d’accès et d’autorisations différents, et peuvent être limités à cinq jetons OAuth. Consultez notre guide consacré à l’[augmentation de l’accès](/fr/x-ads-api/getting-started/increasing-access) pour obtenir l’accès à des endpoints supplémentaires ou faire lever les limites de jetons pour les applications existantes.

<div id="ad-account-level-permissions">
  ### Autorisations au niveau du compte publicitaire
</div>

Chaque utilisateur qui a accès à un compte publicitaire disposera d’une autorisation spécifique au niveau du compte : **Administrateur de compte**, **Responsable publicitaire**, **Analyste de campagne**, **Analyste organique** et **Responsable création** ; consultez **business.x.com** pour la documentation la plus récente concernant les autorisations au niveau du compte. Les applications doivent récupérer les autorisations de l’utilisateur actuellement authentifié via le point de terminaison d’API [Authenticated User Access](/fr/x-ads-api/campaign-management#authenticated-user-access) afin de déterminer à quels points de terminaison d’API et à quelles fonctionnalités publicitaires elles peuvent accéder.

**Remarque :** Tous les jetons utilisateur utilisés avec la [Conversion API](/fr/x-ads-api/measurement/web-conversions) doivent appartenir à des utilisateurs disposant des autorisations au niveau du compte **Administrateur de compte** ou **Responsable publicitaire**.                                                                                                                                              

<div id="methods-of-obtaining-access-tokens">
  ## Méthodes pour obtenir des jetons d&#39;accès
</div>

<div id="1-obtain-an-advertisers-user-access-token">
  ### 1. Obtenir le jeton d&#39;accès (utilisateur) d&#39;un annonceur
</div>

Il existe deux méthodes pour obtenir le **jeton d&#39;accès** d’un annonceur. La méthode la plus courante consiste à utiliser un [flux OAuth à 3 volets](/fr/resources/fundamentals/authentication#obtaining-access-tokens-using-3-legged-oauth-flow) directement depuis votre interface web. Les applications qui n&#39;ont pas d&#39;interface utilisateur publiquement accessible pour les annonceurs peuvent implémenter un processus OAuth [basé sur un code PIN](/fr/resources/fundamentals/authentication#pin-based-authorization). Une fois que l’utilisateur a terminé le flux à 3 volets, votre application disposera des identifiants nécessaires pour effectuer des requêtes sur son compte publicitaire via l’API.

Obtenir les identifiants utilisateur via un flux OAuth est la méthode que nous **recommandons vivement** à la majorité des développeurs de l’Ads API pour obtenir l’accès à un compte annonceur. Cela vous permet d’appeler l’API au nom d’un utilisateur et d’effectuer des actions en son nom. Ces jetons n’expirent pas, mais peuvent être révoqués par l’utilisateur à tout moment.

<div id="2-obtain-your-developer-access-token">
  ### 2. Obtenir votre jeton d&#39;accès (Developer)
</div>

Cette option nécessite que l&#39;annonceur [accorde à votre @username](https://business.x.com/en/help/troubleshooting/multi-user-login-faq.html) (ou à vos @usernames) l&#39;accès à son compte X Ads via l&#39;interface X sur business.x.com. Les **jetons d&#39;accès** obtenus via le flux OAuth à 3 volets (3-legged OAuth) pour votre compte pourront accéder au compte X Ads de l&#39;annonceur.

Cela vous permet d&#39;appeler l&#39;API en utilisant les jetons OAuth de votre propre @username plutôt que les jetons OAuth de l&#39;annonceur. La principale différence avec cette option est que vous ne pouvez créer de Publications promotionnelles uniquement que si l&#39;autorisation de délégation/de composition de Publication a été accordée à votre @username.

Pour pouvoir créer des Publications promotionnelles uniquement au nom de l&#39;utilisateur promouvable `FULL` du compte, vous devez également vous voir accorder l&#39;accès pour créer des Publications dans ce flux. Cela activera l&#39;accès via l&#39;autorisation `TWEET_COMPOSER` sur l&#39;endpoint [GET accounts/:account&#95;id/authenticated&#95;user&#95;access](/fr/x-ads-api/campaign-management#accounts).

<div id="differences-between-these-methods">
  ## Différences entre ces méthodes
</div>

|     |     |     |
| :--- | :--- | :--- |
|     | Jeton OAuth pour l’annonceur (utilisateur) | Jeton OAuth (développeur)  <br /> (@username ajouté pour distinguer le compte) |
| Accéder au compte publicitaire | ✔   | ✔   |
| Créer des Publications au nom de l’utilisateur | ✔   | ✔*  |
| Gérer les campagnes | ✔   | ✔   |
| Accéder aux analyses | ✔   | ✔   |
| Créer des Cards au nom de l’utilisateur | ✔   | ✔   |
| Possibilité pour le développeur d’accéder  <br />via l’interface utilisateur X Ads |     | ✔   |
| [Limites de débit](/fr/x-api/enterprise-gnip-2.0/fundamentals/rate-limits) | Distinctes pour chaque annonceur | Distinctes pour chaque compte annonceur |
