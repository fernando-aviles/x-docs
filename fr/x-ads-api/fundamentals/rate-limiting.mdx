L&#39;Advertiser API est soumise à une limitation de débit similaire à celle de l’API REST v1.1, comme indiqué ici : [REST API Rate Limiting in v1.1](https://developer.x.com/content/developer-twitter/en/docs/basics/rate-limits). Contrairement à l’API REST v1.1, il n&#39;existe pas d&#39;index des limites par endpoint accessible par programmation. Les limites de débit par endpoint et leurs fenêtres de réinitialisation sont communiquées via les en-têtes de Réponse HTTP. Toutes les limitations de débit de l&#39;Ads API reposent sur OAuth 1.0a.

<div id="user-level-and-ad-account-level-limits">
  ## Limites au niveau utilisateur et au niveau compte publicitaire
</div>

Il existe deux types de limites de débit : au niveau du jeton utilisateur et au niveau du compte publicitaire. Un sous-ensemble d’endpoints est configuré pour utiliser les limites de débit au niveau du compte publicitaire. Un jeton utilisateur est le [jeton d’accès OAuth](/fr/resources/fundamentals/authentication#obtaining-access-tokens-using-3-legged-oauth-flow) que vous utilisez pour vous authentifier et appeler l’Ads API. Chaque jeton utilisateur peut avoir accès à un ou plusieurs comptes publicitaires.

Les développeurs doivent utiliser la limite de débit au niveau du compte publicitaire lorsqu’elle est renvoyée dans les en-têtes de réponse, et n’utiliser la limite au niveau utilisateur que lorsque la limite de compte publicitaire n’est pas disponible.

Les limites de débit au niveau utilisateur sont exprimées via ces en-têtes : **x-rate-limit-limit**, **x-rate-limit-remaining** et **x-rate-limit-reset**

Pour les endpoints avec la limitation de débit au niveau du compte publicitaire activée, les limites de débit sont exprimées via ces en-têtes : **x-account-rate-limit-limit**, **x-account-rate-limit-remaining** et **x-account-rate-limit-reset**.

Les limites de débit au niveau du compte publicitaire sont fournies uniquement pour les endpoints GET afin de permettre aux applications de synchroniser les données d’entités (telles que les objets de campagne ou de line item) à partir d’un seul jeton utilisateur accédant à plusieurs comptes publicitaires. Les actions d’écriture ne sont pas garanties d’utiliser les mêmes limites de débit au niveau du compte publicitaire.

Pour les endpoints limités en débit au niveau du compte publicitaire, la limite de débit au niveau utilisateur est définie sur une valeur élevée représentant un quota global pour l’ensemble de votre application. Lorsqu’elle est disponible, la limite de débit au niveau du compte publicitaire doit prévaloir pour contrôler votre volume de requêtes.

<div id="best-practices">
  ## Bonnes pratiques
</div>

1. Enregistrez dans votre base de données un horodatage correspondant à la dernière synchronisation et, lorsque c’est applicable, demandez les données avec l’option `sort_by=updated_at-desc` afin de pouvoir arrêter votre processus de synchronisation dès que vous atteignez des données plus anciennes que votre dernier horodatage de synchronisation. Cela permet d’éviter de synchroniser plusieurs fois les mêmes données.

2. Demandez plusieurs entités dans une seule requête : certains endpoints vous permettent de spécifier une liste de valeurs séparées par des virgules afin de récupérer plusieurs ensembles de données similaires. Cela peut réduire le nombre total d’appels effectués et ainsi utiliser plus efficacement la limite de débit.

3. Demandez la valeur maximale de « count » dans vos requêtes : pour certains endpoints comme [GET accounts/:account&#95;id/targeting&#95;criteria](/fr/x-ads-api/campaign-management#targeting-criteria), il est fortement recommandé de les appeler avec la valeur maximale de count afin de renvoyer 1000 objets au lieu de la valeur par défaut de 200.

<div id="faqs">
  ## FAQ
</div>

*Est-il possible d’augmenter les limites de débit pour un compte publicitaire particulier ou pour notre application ?*

De manière générale, nous ne pouvons pas augmenter les limites de débit, qui sont définies pour prendre en charge les plus grands comptes publicitaires. Veuillez mettre en œuvre les bonnes pratiques répertoriées dans ce document dans un premier temps et, si les limites de débit continuent d’affecter votre capacité à faire évoluer vos intégrations ou à atteindre vos objectifs commerciaux, contactez vos interlocuteurs X Ads API en leur fournissant tous les détails sur le cas d’usage et les requêtes associées.
