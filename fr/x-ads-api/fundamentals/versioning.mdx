<div id="overview">
  ## Vue d’ensemble
</div>

Chaque mois, nous apportons des modifications et déployons plusieurs nouvelles fonctionnalités sur l’API X Ads. Ces changements sont presque toujours rétrocompatibles, mais nous introduisons tout de même chaque année un certain nombre de changements majeurs. Nous avons reçu des retours de la part de développeurs sur les difficultés que la fréquence élevée des changements dans l’API Ads peut poser à leurs cycles de développement, notamment pour la mise en œuvre de nouvelles fonctionnalités, la gestion des dépréciations et les tests. Nous souhaitons améliorer l’expérience des développeurs utilisant notre plateforme Ads, c’est pourquoi nous avons introduit le concept de versionnement de nos endpoints.

Voici quelques définitions de certains des concepts que nous abordons :

**Version** : fait référence au numéro de version figurant dans le chemin d’URL de toute requête Ads API, par exemple : GET /{version_number}/accounts. Ce style de versionnement est connu sous le nom de versionnement URI.

**Changements majeurs (Breaking Changes)** : les changements majeurs sont toutes les modifications qui nécessitent des ressources de développement pour maintenir la fonctionnalité existante. Cela inclut les ressources utilisées pour l’analyse des changements à effectuer, l’identification des fonctionnalités/endpoints qui doivent être dépréciés et la mise en œuvre finale de l’ensemble de ces changements. Une liste de changements majeurs comprend notamment :

* Suppression d’un paramètre de la requête/réponse de l’API

* Modification du nom de tout paramètre ou endpoint

* Changement dans la représentation des valeurs (preview&#95;url → card&#95;uri)

* Changement dans le comportement des endpoints (par exemple, statistiques async vs sync)

* Ajout ou modification de paramètres optionnels ou obligatoires (par exemple, rendre nom un champ Obligatoire dans la requête)

**Dépréciation** : les versions ou produits dépréciés ne seront plus pris en charge et il est recommandé aux développeurs de cesser d’utiliser ces API.

**Sunset** : une fois qu’un produit ou une API est « sunset », l’ensemble des endpoints correspondants ne sera plus accessible via l’API.

<div id="versioning-strategy">
  ## Stratégie de gestion des versions
</div>

Les principaux principes de la stratégie sont :

1. Toutes les modifications non rétrocompatibles seront regroupées dans une nouvelle version

2. Lorsqu’une nouvelle version est annoncée, les versions existantes disposent d’une période de dépréciation de 6 mois

3. À tout moment, l’API acceptera des requêtes provenant de deux versions simultanément ; toutefois, la plus ancienne des deux ne sera pas prise en charge

4. Afin de permettre une adoption plus rapide des nouveaux produits, ceux-ci seront publiés de manière continue (en dehors de la cadence de versionnage)

5. Toutes les réponses d’API contiendront un en-tête `x-current-api-version` défini sur la version actuelle de l’API, ainsi qu’un en-tête `x-api-warn` lors de l’appel de tout endpoint d’API déprécié.

S’il devait y avoir des changements fondamentaux des exigences produit nécessitant une modification non rétrocompatible de l’API (par exemple, la dépréciation de plusieurs tranches d’âge de ciblage), nous enverrons un préavis de 90 jours pour annoncer cette modification non rétrocompatible et, au moins 90 jours après la publication de ce préavis, la modification non rétrocompatible sera déployée

<div id="v5">
  ### v5
</div>

Aujourd’hui, le 28 février 2019, X introduit Ads API v5, avec des mises à jour axées sur la mise à l’échelle et l’efficacité.

Cette version inclut un nouvel endpoint pour déterminer quelles entités étaient actives sur une période donnée, des statistiques pour les Media Creatives (c’est-à-dire les vidéos In-stream et les images sur X Audience Platform), la possibilité de récupérer *plusieurs* cartes par URI de carte, ainsi qu’une plus grande flexibilité pour récupérer les critères de ciblage et d’autres entités. De plus, nous avons corrigé certains bogues et mis à jour des noms de paramètres et des attributs de Réponse. Enfin, les cartes d’applications non média et l’endpoint POST `accounts/:account_id/account_media` ont été dépréciés.

Comme pour les versions précédentes, il y aura une période de transition de 6 mois pour migrer vers la v5. Le **28 août 2019**, la version 4 de l’Ads API ne sera plus disponible. Nous encourageons tous les partenaires à migrer vers la dernière version de l’API dès que possible afin d’éviter toute interruption de service. *La version 3 de l’Ads API est arrivée en fin de vie et n’est plus disponible.*

<div id="new">
  #### Nouveau
</div>

**Déterminer quelles entités étaient actives**

L’endpoint [Active Entities](/fr/x-ads-api/analytics#active-entities-2) indique si les métriques d’analytics pour les entités publicitaires ont changé. Conçu pour être utilisé conjointement avec les endpoints d’analytics, Active Entities fonctionne en spécifiant un type d’entité et une plage de dates (sur une période maximale de 90 jours), puis renvoie un tableau d’ID d’entités pour lesquelles votre plateforme doit demander des analytics. Les ID autres que ceux renvoyés ne doivent pas être interrogés dans les requêtes d’analytics suivantes.

Cet endpoint prend en charge les types d’entités suivants : `CAMPAIGN`, `FUNDING_INSTRUMENT`, `LINE_ITEM`, `MEDIA_CREATIVE` et `PROMOTED_TWEET`.

**Statistiques `MEDIA_CREATIVE`**

Les endpoints d’analytics de l’Ads API fournissent désormais des métriques pour les entités Media Creative. Les Media Creatives sont le mécanisme permettant de promouvoir les publicités in-stream ou les images sur la X Audience Platform. L’interface X Ads affiche les métriques Media Creative sous les onglets « In-stream videos » et « Display creatives ». Les endpoints d’analytics [synchrone](/fr/x-ads-api/analytics#get-stats-accounts-account-id) et [asynchrone](/fr/x-ads-api/analytics#asynchronous-analytics) prennent désormais en charge l’énumération d’entité `MEDIA_CREATIVE`.

**Récupérer plusieurs cartes**

En améliorant la [version v3](https://devcommunity.x.com/t/ads-api-version-3/100732) de l’endpoint conçu pour récupérer une seule carte à partir de la valeur de son URI de carte, il est désormais possible de récupérer *plusieurs* cartes à l’aide de l’endpoint [GET accounts/:account&#95;id/cards/all](/fr/x-ads-api/creatives#cards-fetch). Désormais, au lieu d’effectuer une requête pour chaque carte, vous pouvez récupérer jusqu’à 200 cartes en une seule requête.

Deux points à noter :

1. Le chemin d’URL est désormais `accounts/:account_id/cards/all`. (L’ancien chemin n’est plus disponible.) Cela nous permet d’être cohérents avec [l’endpoint](/fr/x-ads-api/creatives#cards-fetch) conçu pour récupérer une carte par ID.
2. Le paramètre de requête Obligatoire se nomme désormais card&#95;uris (au pluriel).

**Souplesse de récupération**

L’endpoint [GET accounts/:account&#95;id/targeting&#95;criteria](/fr/x-ads-api/campaign-management#get-accounts-account-id-targeting-criteria) prend désormais en charge plusieurs ID de line item. Le paramètre line&#95;item&#95;ids, qui accepte jusqu’à 200 ID, est Obligatoire. Auparavant, un seul line item était accepté, ce qui rendait la synchronisation difficile. Avec ce changement, il est désormais possible de récupérer davantage de ciblage en moins de temps.

Les endpoints suivants prennent également désormais en charge plusieurs ID de line item, bien que le paramètre line&#95;item&#95;ids soit facultatif pour ceux-ci.

* [GET accounts/:account&#95;id/line&#95;item&#95;apps](https://developer.x.com/en/docs/x-ads-api/campaign-management/api-reference/line-item-apps#get-accounts-account-id-line-item-apps)
* [GET accounts/:account&#95;id/media&#95;creatives](/fr/x-ads-api/campaign-management#get-accounts-account-id-media-creatives)
* [GET accounts/:account&#95;id/promoted&#95;accounts](/fr/x-ads-api/campaign-management#get-accounts-account-id-promoted-accounts)
* [GET accounts/:account&#95;id/preroll&#95;call&#95;to&#95;actions](/fr/x-ads-api/creatives#preroll-call-to-actions)

<div id="changed">
  #### Modifications
</div>

**Récupération des campagnes et des line items brouillons**

La manière dont les campagnes et les line items brouillons sont récupérés a été mise à jour. Désormais, le paramètre with&#95;draft(boolean), lorsqu’il est défini sur true, renvoie *à la fois* les entités brouillon et non brouillon. Cela est cohérent avec la manière dont les entités supprimées sont récupérées (c’est‑à‑dire en utilisant with&#95;deleted). Auparavant, récupérer à la fois les entités brouillon et non brouillon nécessitait au minimum deux requêtes. Désormais, cela peut être fait en un seul appel à l’API.

| **v4** | **v5** |
| :--- | :--- | :--- |
| `draft_only` | `with_draft` |     |

**Ciblage de la durée d’activation du réseau**

L’Ads API a résolu un problème d’affichage où, après avoir ajouté un ciblage Network Activation Duration, le type de ciblage dans la Réponse incluait un suffixe &#95;IN&#95;SEC. La référence aux secondes prêtait à confusion, car Network Activation Duration est toujours représenté en mois. Cette correction rend la représentation cohérente et réduit la confusion.

| **v4** | **v5** |
| :--- | :--- | :--- |
| `NETWORK_ACTIVATION_DURATION_IN_SEC` | `NETWORK_ACTIVATION_DURATION` |     |

**Totaux et curseurs**

Dans v5, with&#95;total&#95;count et cursor sont mutuellement exclusifs. Spécifier les deux dans une requête renverra le code d’erreur EXCLUSIVE&#95;PARAMETERS. Avant v5, with&#95;total&#95;count était ignoré lorsque cursor était spécifié. Ce changement explicite cette relation.

<div id="removed">
  #### Supprimé
</div>

Trois champs sont supprimés des réponses Ads API : preview&#95;url, account&#95;id et parent&#95;ids. L’effort d’ingénierie requis pour ces trois éléments est minime.

* Dans v4, il a été annoncé que le paramètre de réponse preview&#95;url pour les cards était toujours null. L’étape finale de cette migration consiste à supprimer preview&#95;url de toutes les réponses de cards.
* L’attribut de réponse account&#95;id est supprimé pour les ressources suivantes, étant donné que l’ID du compte publicitaire est déjà présent dans l’URL ainsi que dans request.params. (Il est intentionnel d’exclure les instruments de financement de cette liste, car les ID parents doivent être présents dans les objets de réponse, lorsque c’est possible, et les ID de compte sont des entités parentes des instruments de financement.)
  * Médias de compte
  * Fournisseurs d’événements d’application
  * Tags d’événements d’application
  * Campagnes
  * Cards
  * Line items
  * Utilisateurs promouvables
  * Critères de ciblage
* Pour les requêtes [GET accounts/:account&#95;id/targeting&#95;criteria](/fr/x-ads-api/campaign-management#get-accounts-account-id-targeting-criteria), nous ne renvoyons plus le champ parent&#95;ids, car il était toujours un tableau vide.

**App cards sans média**

Dans v5, les app cards sans média ne sont plus prises en charge. [Auparavant](https://devcommunity.x.com/t/deprecation-announcement-app-download-cards/87807), la possibilité de créer ou de modifier des app cards sans média avait été supprimée. À présent, les derniers endpoints pour cette ressource sont dépréciés.

* Remarque : cela **n’**affecte pas les app download cards image et vidéo.

**Création de médias de compte**

L’endpoint POST accounts/:account&#95;id/account&#95;media n’est plus disponible dans v5. Les autres endpoints pour cette ressource ne sont *pas* affectés. La raison de ce changement est que, lors de l’ajout de médias à la [Media Library](/fr/x-ads-api/creatives#media-library), certains cas font que ces ressources sont *automatiquement* ajoutées comme entités Account Media, et tenter d’ajouter une ressource déjà existante à la ressource Account Media entraîne une erreur. Cela se produit dans les cas suivants.

* Les ressources `AMPLIFY_VIDEO` ajoutées à la Media Library sont automatiquement ajoutées comme ressources Account Media avec le type créatif `PREROLL`.
* Les images avec des dimensions spécifiques ajoutées à la Media Library sont automatiquement ajoutées comme ressources Account Media. Le type créatif (par exemple, `INTERSTITIAL`) dépend des dimensions de l’image. (Pour les dimensions, consultez notre page [Enumerations](/fr/x-ads-api/introduction).)

***Audiences API***

La nouvelle Audiences API est basée sur notre nouveau backend de traitement des audiences, qui offre une robustesse et une fiabilité accrues. Ce nouvel endpoint permettra aux partenaires de fournir plusieurs types d’identifiants pour un même utilisateur, ce qui signifie que nous pouvons utiliser des signaux supplémentaires pour la mise en correspondance. La documentation de référence pour le nouvel endpoint Audience est disponible [ici](/fr/x-ads-api/audiences). Nous prévoyons de continuer à publier des mises à jour et des améliorations de ce produit tout au long du reste de l’année.

Les endpoints suivants ne seront plus disponibles en v4 en raison de fonctionnalités redondantes (ils continueront de fonctionner en v3 et seront entièrement **retirés** lorsque la v3 ne sera plus disponible) :

* TON Upload :
  * GET accounts/:account&#95;id/tailored&#95;audience&#95;changes
  * GET accounts/:account&#95;id/tailored&#95;audience&#95;changes/:tailored&#95;audience&#95;change&#95;id
  * POST accounts/:account&#95;id/tailored&#95;audience&#95;changes
  * PUT accounts/:accounti&#95;d/tailored&#95;audiences/global&#95;opt&#95;out
* Real Time Audiences :
  * POST tailored&#95;audience&#95;memberships

Enfin, le paramètre `list_type` sera supprimé de la requête et de la réponse pour *tous* les [endpoints Tailored Audiences](/fr/x-ads-api/audiences) dans la version 4.

***Endpoints de paramètres***

Nous permettons désormais aux administrateurs de compte de définir et de mettre à jour les paramètres utilisateur, de compte et fiscaux. Les [paramètres utilisateur](/fr/x-ads-api/campaign-management#get-accounts-account-id-user-settings-user-id) correspondent aux préférences de contact propres à l’utilisateur pour un compte publicitaire donné. En utilisant l’endpoint [PUT accounts/:account&#95;id](/fr/x-ads-api/campaign-management#put-accounts-account-id), les annonceurs peuvent désormais mettre à jour le nom de leur compte et le type d’industrie. Enfin, les endpoints [tax settings](/fr/x-ads-api/campaign-management#get-accounts-account-id-tax-settings) permettent aux annonceurs dans les pays où une taxe sur la valeur ajoutée (TVA) est prélevée de mettre à jour des informations telles que le nom de l’entreprise, l’adresse, le numéro de TVA et d’indiquer si le compte appartient à l’annonceur ou à une agence faisant de la publicité pour le compte d’un annonceur.

<div id="removed">
  #### Supprimé
</div>

**Points de terminaison vidéo**

Les points de terminaison accounts/:account&#95;id/videos ne seront plus disponibles en v4. Ce point de terminaison a été rendu obsolète par l’introduction des points de terminaison [Media Library](/fr/x-ads-api/creatives#get-accounts-account-id-media-library). Voir la comparaison d’utilisation ci-dessous.

* Point de terminaison v3 videos : `twurl -H ads-api.x.com "/3/accounts/18ce54d4x5t/videos"`

* Point de terminaison v4 Media Library pour les vidéos : `twurl -H ads-api.x.com "/4/accounts/18ce54d4x5t/media_library?media_type=VIDEO"`

Les points de terminaison Media Library sont totalement équivalents aux points de terminaison videos et prennent également en charge des fonctionnalités supplémentaires, comme la possibilité de gérer les images et les GIF. Il est demandé aux partenaires d’utiliser exclusivement Media Library pour toute gestion de médias.

**`as_user_id` dans Tweet View**

Le paramètre `as_user_id` disponible sur le point de terminaison [GET accounts/:account&#95;id/tweet/preview/:tweet&#95;id](/fr/x-ads-api/creatives#get-accounts-account-id-tweets) ne sera plus accepté. L’aperçu sera toujours généré du point de vue de l’auteur du Tweet.

<div id="v3">
  ### v3
</div>

La version 3 de l’Ads API a été [lancée](https://devcommunity.x.com/t/ads-api-version-3/100732) le 1er février 2018. La version 2 de l’Ads API atteindra sa fin de vie le 1er août 2018.

Cette version inclut notre nouveau produit Audience Intelligence, l’accès à la Media Library et des flux de travail améliorés pour les cartes. Nous annonçons également l’obsolescence de l’endpoint [PUT accounts/:account&#95;id/targeting&#95;criteria](/fr/x-ads-api/campaign-management#get-accounts-account-id-targeting-criteria). Enfin, la version 3 inclut quelques modifications mineures des paramètres et des Réponses ainsi qu’une limite de taille de lot plus faible.

Comme pour la [version 2](https://devcommunity.x.com/t/ads-api-version-2/90360), nous donnons aux partenaires **6 mois** pour effectuer la transition. Le **2018-08-01**, la v2 de l’Ads API sera désactivée. Nous encourageons tous les partenaires et développeurs à migrer vers la v3 dès que possible.

**Audience Intelligence**

Audience Intelligence fournit des informations en temps réel sur les principaux hashtags, @handles et événements les plus pertinents pour une audience X donnée. Par exemple, saisissez Homme 18-34 aux États-Unis et vous verrez #nintendoswitch, #cardinal et @ricegum en tendance au sein de cette audience.

Les [endpoints](/fr/x-ads-api/audiences) d’Audience Intelligence offrent les fonctionnalités suivantes :

* À partir d’une audience en entrée, récupérer les hashtags, @handles et événements les plus pertinents.
* À partir d’une audience en entrée, récupérer les principales informations démographiques (telles que l’âge, le sexe et le revenu du foyer).
* À partir d’un mot-clé, récupérer la série chronologique du volume de Tweets.

**Media Library**

La [Media Library](/fr/x-ads-api/creatives#get-accounts-account-id-media-library) permet de gérer les images, GIF et vidéos pour les comptes publicitaires. Ces objets média peuvent être utilisés dans des Tweets et pour créer des cartes. Ils peuvent également être réutilisés dans plusieurs créations publicitaires, ce qui élimine la nécessité de téléverser plusieurs fois la même ressource.

Les objets de la bibliothèque sont identifiés par un media&#95;key. Les media keys sont des valeurs de type chaîne de caractères au format suivant : 13&#95;875943225764098048, par exemple. Dans l’Ads API, nous évoluons vers l’utilisation de media keys pour tous les médias.

**Flux de travail amélioré pour les cartes**

L’ensemble de nos endpoints de cartes prennent désormais en charge les media keys. Cela permet d’utiliser les objets de la Media Library pour créer ou mettre à jour des cartes.

De plus, nous introduisons deux nouveaux endpoints pour [récupérer les détails d’une carte](/fr/x-ads-api/creatives#fetching-cards). Ces endpoints peuvent être utilisés pour rechercher les cartes utilisées dans des Tweets ou des Tweets programmés, par exemple, en spécifiant soit le card&#95;uri, soit l’id. Auparavant, cela n’était pas possible.

En plus de ces nouvelles fonctionnalités, nous apportons les changements suivants dans la version 3.

**Nouveau**

* La réponse de l’endpoint [GET insights/keywords/search](/fr/x-ads-api/audiences) inclut désormais un attribut related&#95;keywords avec 30 termes liés aux mots-clés fournis en entrée.

**Modifié**

* Les attributs de réponse card&#95;uri et preview&#95;url sont désormais mutuellement exclusifs. Lorsqu’une carte possède un card&#95;uri, preview&#95;url sera null. Lorsqu’une carte ne possède pas de card&#95;uri, seul preview&#95;url sera renvoyé.

  * D’ici la version 4, toutes les cartes existantes posséderont un card&#95;uri.
* Il n’est plus possible de *créer* des cartes avec des images au format 5:2. Bien que les cartes *existantes* basées sur des images 5:2 continuent de fonctionner, nous encourageons les partenaires à passer aux formats d’image 1,91:1 ou 1:1, plus performants (là où ils sont pris en charge).

**Supprimé**

* L’endpoint [PUT accounts/:account&#95;id/targeting&#95;criteria](/fr/x-ads-api/campaign-management#get-accounts-account-id-targeting-criteria) n’est plus disponible. Nous avons décidé d’apporter ce changement, car le comportement de remplacement de cet endpoint prêtait à confusion pour les annonceurs et n’était pas cohérent avec nos autres endpoints PUT qui mettent à jour une seule ressource à la fois. À la place, consultez l’attribut de réponse entity&#95;status pour déterminer si un instrument de financement est ou non en pause. De plus, étant donné que paused et cancelled correspondent à la même valeur, cancelled n’est plus renvoyé non plus dans la réponse.
* Nous avons supprimé le paramètre card&#95;id de l’endpoint [GET accounts/:account&#95;id/tweet/preview](/fr/x-ads-api/creatives#get-accounts-account-id-tweets).
* Comme il n’est pas possible de récupérer des Tweets programmés supprimés, le paramètre with&#95;deleted n’est plus pris en charge.
* Le paramètre draft&#95;only a été supprimé des endpoints suivants, car ces entités ne peuvent jamais être dans un état de brouillon :
  * [GET accounts/:account&#95;id/targeting&#95;criteria](/fr/x-ads-api/campaign-management#get-accounts-account-id-targeting-criteria)
  * [GET accounts/:account&#95;id/promoted&#95;tweets](/fr/x-ads-api/campaign-management#get-accounts-account-id-promoted-tweets)
  * [GET accounts/:account&#95;id/promoted&#95;accounts](/fr/x-ads-api/campaign-management#get-accounts-account-id-promoted-accounts)
  * [GET accounts/:account&#95;id/media&#95;creatives](/fr/x-ads-api/campaign-management#get-accounts-account-id-media-creatives)
  * [GET accounts/:account&#95;id/preroll&#95;call&#95;to&#95;actions](/fr/x-ads-api/creatives#get-accounts-account-id-preroll-call-to-actions)

**Remarque**

Les Video Website Cards et les Tweets programmés ne sont plus en bêta.   * Interrogez jusqu’à **90 jours** de données sur jusqu’à **20 entités** dans une seule tâche.
* Consultez notre guide de migration vers Analytics v1, qui comprend un tableau de correspondance entre les métriques v0 et les métriques v1
