<div id="how-to-get-access-to-the-ads-api">
  ## Comment obtenir l'accès à l'API Ads
</div>

1. Inscrivez-vous pour obtenir un [compte développeur](https://developer.x.com/en/apply-for-access).
2. Créez une [App développeur](https://developer.x.com/app) et sécurisez votre jeton.
3. Accédez à [ads.x.com/help](https://ads.x.com/help) pour soumettre une demande d'accès à l'API Ads pour chacune de vos App développeur.

<Note>**Remarque :** Si vous utilisez déjà la plateforme développeur X et que vous avez un compte développeur, passez à l'étape trois.</Note>

<div id="step-one-signup-for-a-developer-account">
  ### Étape 1 : Créer un compte développeur
</div>

Pour envoyer des requêtes à n'importe quel produit d'API de X, vous devez d'abord créer un compte développeur. Dans la Developer Console, créez une App et une App développeur. Cela vous fournira un ensemble d'identifiants que vous utiliserez pour authentifier toutes vos requêtes auprès de l'API.

<Button href="https://developer.x.com/en/apply-for-access">
  Créer un compte développeur
</Button>

<div id="step-two-save-your-apps-key-and-tokens-and-keep-them-secure">
  ### Étape deux : Enregistrez les clés et les jetons de votre App et gardez-les en sécurité
</div>

Dans votre App développeur, un ensemble de clés d’API (également appelées Consumer Keys) vous sera fourni. Vous aurez également la possibilité de générer un ensemble de jetons d’accès pouvant être utilisés pour effectuer des requêtes au nom de votre compte X personnel, ainsi qu’un Bearer Token qui peut être utilisé pour authentifier les endpoints nécessitant OAuth 2.0 Bearer Token. Comme ces clés et jetons n’expirent pas, à moins que vous ne les régénériez, nous vous recommandons de créer des variables d’environnement ou d’utiliser un gestionnaire de mots de passe sécurisé.

Veuillez également noter votre App ID, qui se trouve dans l’URL de la page de détails de votre App. Cela facilitera votre demande d’accès à l’Ads API à l’étape suivante.

<Note>
**Remarque :** Vos clés et jetons ne s’affichent qu’une seule fois dans la Developer Console, il est donc important de stocker ces informations d’identification dans votre système de gestion de mots de passe dès que vous les générez.

Si vous égarez ou oubliez les clés et jetons, vous devrez les régénérer, ce qui crée de nouvelles clés et de nouveaux jetons et invalide les anciens. Cela signifie que vous devrez mettre à jour toutes les intégrations que vous avez pu configurer avec vos informations d’identification précédentes.

Pour en savoir plus, consultez nos [meilleures pratiques d’authentification](https://developer.x.com/en/docs/authentication/guides/authentication-best-practices).
</Note>

<div id="step-three-apply-for-access-to-the-ads-api">
  ### Troisième étape : demander l’accès à l’Ads API
</div>

À ce stade, vous disposerez d’[un accès de base à la X API](https://developer.x.com/en/docs/twitter-api/v1), mais pas des fonctionnalités spécifiques de la X Ads API. Ensuite, vous devrez demander et obtenir l’approbation pour l’accès à l’Ads API. Rendez-vous sur [ads.x.com/help](https://ads.x.com/help) pour soumettre une demande d’accès à l’Ads API pour chacune de vos Apps développeur.

<div id="access-tiers">
  ### Niveaux d'accès
</div>

Dans le cadre du processus de demande d'accès, vous devrez préciser le niveau d'accès dont vous avez besoin. Pour en savoir plus, consultez les [autorisations au niveau de l'application et au niveau du compte publicitaire](https://developer.x.com/en/docs/twitter-ads-api/obtaining-ads-account-access#levels-of-access).

<div id="conversion-only">
  #### Conversions uniquement
</div>

Accès aux endpoints de conversions sur mobile et sur le web avec accès en lecture et en écriture.

<div id="standard-access">
  #### Accès standard
</div>

Accès aux endpoints Analytics, Campaign Management, Creatives, Custom Audiences et Conversion avec autorisations de lecture et d’écriture.

<Note>**Remarque :** Une fois que votre application est approuvée pour l’accès à l’Ads API, vous devrez [régénérer tous les jetons d’accès utilisateur](https://developer.x.com/resources/fundamentals/authentication/obtaining-user-access-tokens) afin d’effectuer correctement des [requêtes Ads API authentifiées](https://developer.x.com/en/docs/twitter-ads-api/making-authenticated-requests).</Note>

<Note>**Remarque :** Les développeurs Ads API qui ont demandé l’accès avant juillet 2023 peuvent disposer de niveaux d’accès et d’autorisations différents, et peuvent être limités à cinq jetons OAuth. Consultez notre guide sur [l’augmentation de l’accès](https://developer.x.com/en/docs/twitter-ads-api/increasing-access) pour obtenir l’accès à des endpoints supplémentaires ou lever les limites de jetons pour les applications existantes.</Note>

<div id="make-your-first-request">
  ## Effectuer votre première requête
</div>

Pour tester votre accès à l’Ads API, effectuez une requête vers l’endpoint [GET accounts](https://developer.x.com/en/docs/twitter-ads-api/campaign-management/api-reference/accounts). Cet endpoint renverra les comptes publicitaires auxquels l’utilisateur actuellement autorisé a accès. Utilisez les identifiants de comptes publicitaires de cette requête dans les requêtes API suivantes pour lire et écrire des données relatives à un compte publicitaire spécifique. En utilisant [Twurl](https://developer.x.com/en/docs/tutorials/using-twurl) en ligne de commande, la requête ressemblera à ce qui suit.

**Exemple de requête**

```bash
twurl -H ads-api.x.com "/11/accounts"
```

**Exemple de réponse**

```json

  },
```
