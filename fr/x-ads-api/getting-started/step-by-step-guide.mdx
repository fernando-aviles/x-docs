<div id="how-to-get-access-to-the-ads-api">
  ## Comment obtenir l’accès à l’API Ads
</div>

1. Inscrivez-vous pour obtenir un [compte développeur](https://developer.x.com/en/apply-for-access).
2. Créez une [App développeur](https://developer.x.com/app) et protégez votre jeton.
3. Accédez à [ads.x.com/help](https://ads.x.com/help) pour soumettre une demande d’accès à l’API Ads pour chacune de vos Apps développeur.

<Note>**Remarque :** Si vous utilisez déjà la plateforme développeur X et que vous avez un compte développeur, passez à l’étape trois.</Note>

<div id="step-one-signup-for-a-developer-account">
  ### Première étape : créez un compte développeur
</div>

Pour envoyer une requête à n'importe quel produit d'API X, vous devez d'abord créer un compte développeur. Dans la Console de Développement, créez une App et une App développeur. Vous obtiendrez ainsi un ensemble d'identifiants que vous utiliserez pour authentifier toutes vos requêtes à l'API.

<Button href="https://developer.x.com/en/apply-for-access">
  Créez un compte développeur
</Button>

<div id="step-two-save-your-apps-key-and-tokens-and-keep-them-secure">
  ### Étape deux : Enregistrez la clé et les tokens de votre App et gardez-les en sécurité
</div>

Dans votre App développeur, un ensemble de clés d’API (également appelées Consumer Keys) vous sera fourni. Vous aurez également la possibilité de générer un ensemble de tokens d’accès qui peuvent être utilisés pour envoyer des requêtes pour le compte de votre compte X personnel, ainsi qu’un Bearer Token qui peut être utilisé pour authentifier les endpoints nécessitant OAuth 2.0 Bearer Token. Comme ces clés et tokens n’expirent pas tant qu’ils ne sont pas régénérés, nous vous recommandons de créer des variables d’environnement ou d’utiliser un gestionnaire de mots de passe sécurisé.

Notez également l’ID de votre App, qui se trouve dans l’URL de la page de détails de votre App. Cela facilitera la demande d’accès à l’Ads API à l’étape suivante.

<Note>
**Remarque :** Vos clés et tokens ne s’afficheront qu’une seule fois dans la Console de Développement, il est donc important de stocker ces identifiants dans votre système de gestion de mots de passe dès leur génération.

Si vous égarez ou oubliez les clés et tokens, vous devrez les régénérer, ce qui crée de nouvelles clés et de nouveaux tokens et invalide les anciens. Cela signifie que vous devrez mettre à jour toutes les intégrations que vous avez pu configurer avec vos précédents identifiants.

Pour en savoir plus, consultez nos [bonnes pratiques d’authentification](https://developer.x.com/en/docs/authentication/guides/authentication-best-practices).
</Note>

<div id="step-three-apply-for-access-to-the-ads-api">
  ### Étape trois : demander l’accès à l’Ads API
</div>

À ce stade, vous aurez [un accès de base à la X API](https://developer.x.com/en/docs/twitter-api/v1), mais pas aux fonctionnalités spécifiques de l’Ads API de X. Ensuite, vous devrez demander et obtenir l’accès à l’Ads API. Rendez-vous sur [ads.x.com/help](https://ads.x.com/help) pour soumettre une demande d’accès à l’Ads API pour chacune de vos Apps développeur.

<div id="access-tiers">
  ### Niveaux d'accès
</div>

Dans le cadre du processus de demande d'accès, vous devrez indiquer le niveau d'accès dont vous avez besoin. Pour en savoir plus, consultez la section [Autorisations au niveau de l'application et au niveau du compte publicitaire](https://developer.x.com/en/docs/twitter-ads-api/obtaining-ads-account-access#levels-of-access).

<div id="conversion-only">
  #### Conversion uniquement
</div>

Accès aux points de terminaison de conversion mobile et web avec droits de lecture et d’écriture.

<div id="standard-access">
  #### Accès standard
</div>

Accès aux endpoints Analytics, Campaign Management, Creatives, Custom Audiences et Conversion avec des droits de lecture et d’écriture.

<Note>**Remarque :** Une fois que votre application est approuvée pour l’accès à l’Ads API, vous devrez [régénérer vos jetons d’accès utilisateur existants](https://developer.x.com/resources/fundamentals/authentication/obtaining-user-access-tokens) afin d’effectuer correctement des [requêtes authentifiées à l’Ads API](https://developer.x.com/en/docs/twitter-ads-api/making-authenticated-requests).</Note>

<Note>**Remarque :** Les développeurs Ads API qui ont demandé l’accès avant juillet 2023 peuvent disposer de différents niveaux d’accès et d’autorisations, et peuvent être limités à cinq jetons OAuth. Consultez notre guide sur [l’extension de l’accès](https://developer.x.com/en/docs/twitter-ads-api/increasing-access) pour obtenir l’accès à des endpoints supplémentaires ou lever les limites de jetons pour les applications existantes.</Note>

<div id="make-your-first-request">
  ## Effectuer votre première requête
</div>

Pour tester votre accès à l’Ads API, envoyez une requête à l’endpoint [GET accounts](https://developer.x.com/en/docs/twitter-ads-api/campaign-management/api-reference/accounts). Cet endpoint renverra les comptes publicitaires auxquels l’utilisateur actuellement authentifié a accès. Utilisez les identifiants de comptes publicitaires renvoyés par cette requête dans vos requêtes API suivantes afin de lire et d’écrire des données pour un compte publicitaire spécifique. En utilisant [Twurl](https://developer.x.com/en/docs/tutorials/using-twurl) en ligne de commande, la requête serait la suivante.

**Exemple de requête**

```bash
twurl -H ads-api.x.com "/11/accounts"
```

**Exemple de réponse**

```json
{

    "params": {}
  },
  "data": [

    "business_name": null,
    "timezone": "America/Los_Angeles",
```
