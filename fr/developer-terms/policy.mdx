<div id="x-developers">
  ## X + développeurs
</div>

X aime les développeurs. Nous sommes ravis et impressionnés par les outils et services que cette communauté crée en exploitant la puissance des données de X. Dans le cadre de notre engagement envers cette communauté, notre objectif est de fournir un accès aux données qui soit ouvert et équitable pour les développeurs, sûr pour les personnes utilisant X et bénéfique pour la plateforme X dans son ensemble. Pour atteindre ces objectifs, nous avons élaboré la Politique développeur comme guide pour aider chacun à comprendre nos règles et attentes concernant l’utilisation appropriée de l’X API et du contenu X.

Cette Politique développeur (« **Politique** ») fournit des règles et des directives pour les développeurs qui interagissent avec l’écosystème d’applications, de services, de site Web, de pages Web et de contenu de X. Elle fait partie de votre contrat avec X régissant l’accès et l’utilisation de l’X API et du contenu X (soit dans le cadre du Contrat développeur, soit dans le cadre d’un autre accord écrit avec X). Tout manquement à la Politique est considéré comme une violation de votre accord. Cette Politique peut être modifiée de temps à autre sans préavis. Les termes commençant par une majuscule utilisés dans cette Politique, qui ne sont pas définis dans cette Politique, auront les significations respectives qui leur sont attribuées dans le [Contrat développeur](/fr/developer-terms/agreement) ou le Contrat-cadre de licence.

<div id="using-this-policy">
  ## Utiliser cette politique
</div>

Nous avons structuré cette politique de manière à la rendre aussi facile à suivre que possible. Veuillez garder les informations des sections suivantes de la présente politique à l’esprit lorsque vous utilisez la X API et le X Content :

1. **Mettez toutes les chances de votre côté** - Vous êtes responsable du respect de l’ensemble des politiques de X. Il est important que vous examiniez et compreniez cette politique, ainsi que les politiques auxquelles nous renvoyons dans ce document, avant d’accéder à la X API et au X Content. Le temps passé à consulter nos politiques peut vous éviter des heures de travail de reprise par la suite.

2. **La confidentialité et le contrôle sont essentiels** - La protection et la défense de la confidentialité des personnes sur X sont au cœur de l’ADN de notre entreprise. À ce titre, nous interdisons toute utilisation des données de X qui serait incompatible avec les attentes raisonnables des personnes en matière de vie privée. En développant sur la X API ou en accédant au X Content, vous jouez un rôle particulier dans la protection de cet engagement, notamment en respectant la vie privée des personnes et en leur offrant transparence et contrôle sur la façon dont leurs données sont utilisées.

3. **Respectez les règles d’utilisation de la plateforme** - Obtenir l’autorisation d’accéder à la X API et au X Content n’est que la première étape. Nos règles d’utilisation de la plateforme doivent être votre premier point de référence chaque fois que vous avez des questions sur la manière de garantir la conformité aux politiques pour votre utilisation prévue de la plateforme X.

Nous fournissons ci-dessous davantage de détails sur ce que signifie chacune de ces trois sections clés. Veuillez les lire attentivement pour vous assurer que votre utilisation de la X API et du X Content est conforme à nos politiques.

Si nous estimons que vous enfreignez cette politique (ou toute autre politique de X), nous pouvons suspendre ou révoquer définitivement votre accès à la X API et au X Content.

Enfin, veuillez noter que X peut surveiller votre utilisation de la X API afin d’améliorer les X Applications, d’examiner tout usage commercial et de garantir votre conformité à votre cas d’utilisation approuvé et à cette politique.

Merci de votre lecture, et merci de développer avec nous ! Nous avons hâte de voir ce que vous allez créer !

<div id="set-yourself-up-for-success">
  ## Mettez toutes les chances de votre côté
</div>

Vous pouvez éviter de nombreux pièges potentiels lors de l’utilisation de la X API en veillant à ce que votre service soit conçu correctement dès le premier jour. Cette section de la Politique pour les développeurs contient des règles que tous les développeurs doivent suivre avant d’utiliser la X API ou le Contenu X.

Les offres Free, Basic et Pro (telles que décrites sur [developer.x.com/en](http://developer.x.com/en)) sont conçues pour les projets de loisir, le prototypage commercial, les intégrations de produits X à un stade précoce, et pour prendre en charge des applications avec un nombre limité d’utilisateurs finaux. Si vous utilisez la X API et le Contenu X au‑delà de ce périmètre, vous devez alors souscrire (ou être déjà abonné) à une offre Enterprise (telle que décrite sur [developer.x.com/en](http://developer.x.com/en)).

**Nous examinons tous les usages proposés de la plateforme développeur de X afin de vérifier la conformité aux politiques — vous êtes donc tenu de déclarer (et de mettre à jour, le cas échéant) votre utilisation prévue de la X API et du Contenu X pour obtenir et conserver votre accès.** Tous les nouveaux développeurs doivent [demander un compte développeur](https://developer.x.com/portal/petition/essential/basic-info) pour accéder à la X API. Les développeurs actuels qui n’ont pas de compte développeur approuvé doivent en demander un lorsque X le leur indique. Dans le cadre de ce processus, vous devrez nous fournir une description écrite de vos utilisations prévues de la X API et du Contenu X.

La description de votre cas d’usage vous engage, et toute déviation substantielle par rapport à celle‑ci peut constituer une violation de nos règles et entraîner des mesures d’application. Vous devez nous informer de toute modification substantielle de votre cas d’usage et recevoir notre approbation avant de commencer à utiliser le Contenu X à cette nouvelle fin. Le non‑respect de cette obligation peut entraîner la suspension et la résiliation de votre accès à l’API et aux données.

**En développant sur la X API ou en accédant au Contenu X, vous devez respecter TOUTES les politiques de X.** Celles‑ci incluent la présente [Politique pour les développeurs](/fr/developer-terms/policy), les [Règles d’automatisation](https://help.x.com/rules-and-policies/x-automation), les [Exigences d’affichage](https://developer.x.com/developer-terms/display-requirements.html), les [Règles relatives aux usages restreints de l’API](/fr/developer-terms/restricted-use-cases), les [Règles X](https://help.x.com/rules-and-policies/x-rules), et les [Ressources de marque X](https://about.x.com/who-we-are/brand-toolkit), ainsi que tout autre accord que vous concluez avec X concernant votre utilisation de la X API ou du Contenu X, y compris, sans s’y limiter, le [Contrat développeur](/fr/developer-terms/agreement) ou un « Master Licensing Agreement » ou « Order » (selon le cas). Vous devez également respecter toute modification de ces politiques et toute nouvelle politique mise en place par X. Il vous incombe de surveiller l’utilisation de votre service et de concevoir votre service de manière à prévenir les violations des politiques de X par les personnes qui l’utilisent. Le non‑respect de cette obligation peut entraîner la suspension ou la résiliation de votre accès à l’API et au Contenu X.

**Vous ne pouvez pas enregistrer plusieurs applications pour un seul cas d’usage ou pour des cas d’usage substantiellement similaires ou se recoupant.** Dans ce contexte, un « cas d’usage » est un ensemble cohérent d’analyses, d’affichages ou d’actions effectués via une application. Les versions en « marque blanche » d’un outil ou d’un service ne sont pas autorisées. Si vous envisagez de proposer des versions en « marque blanche » de votre application, vous devez nous en informer et obtenir une approbation distincte de notre part.

*À titre de seule exception à ces règles,* vous pouvez créer et utiliser au maximum 3 applications pour les environnements de développement, de préproduction (staging) et de production d’un même service. Ces applications doivent être enregistrées sur un seul compte, et doivent être clairement identifiées (dans le nom et la description) comme des instances dev, staging et prod d’un même service. **Vous ne pouvez pas utiliser des applications de développement ou de préproduction à des fins de production.**

**Vous devez garder toutes les clés d’API et autres identifiants d’accès privés.** Vous ne pouvez pas utiliser, ni encourager ou faciliter l’utilisation par d’autres personnes, de clés d’API ou d’autres identifiants d’accès appartenant à des tiers.

**Votre contrat de licence avec X limite votre utilisation de la X API et du Contenu X. Entre autres choses, la X API applique des limites de débit (rate limits) qui contribuent à garantir une utilisation équitable des données et à lutter contre le spam sur la plateforme.** Vous ne pouvez pas dépasser ni contourner les limites de débit, ni aucune autre limitation ou restriction décrite dans cette Politique ou dans votre contrat avec X, indiquée sur le [site développeur](https://developer.x.com/) ou communiquée par X.

**Vous ne pouvez pas supprimer ni modifier les mentions propriétaires ou marques figurant sur le Contenu X reçu via la X API.** Cela permet de s’assurer que les personnes savent d’où provient le Contenu X et à qui il appartient.

**Pour des raisons d’intégrité des données et de bon fonctionnement de la plateforme, vous ne pouvez pas interférer avec, intercepter, perturber ou désactiver les fonctionnalités de la X API ou du service X.** En d’autres termes, utilisez les API comme prévu et tel que documenté sur [developer.x.com](https://developer.x.com/). Reportez‑vous à nos [directives HackerOne](https://hackerone.com/x) pour plus de détails sur l’utilisation acceptable.

<div id="privacy-and-control-are-essential">
  ## Le respect de la vie privée et du contrôle est essentiel
</div>

X accorde une grande importance à la vie privée, et nous attendons de toute personne utilisant X Content et la X API qu’elle fasse de même. Toute utilisation de la plateforme développeur X, de la X API ou de X Content d’une manière incompatible avec les attentes raisonnables des personnes en matière de vie privée peut faire l’objet de mesures d’application, pouvant inclure la suspension et la résiliation de l’accès à l’API et à X Content.

Votre engagement en matière de respect de la vie privée et de contrôle doit s’étendre à tous les usages de X Content et à tous les aspects du service que vous créez à l’aide de notre API. À cette fin, les personnes utilisant votre service doivent comprendre et accepter la façon dont vous utilisez leurs données, ainsi que la manière dont vous accédez à X en leur nom. Cela peut être accompli en fournissant aux utilisateurs une politique de confidentialité claire, complète et transparente, ainsi qu’en veillant à obtenir le consentement explicite et éclairé de chaque personne utilisant votre service avant de prendre toute mesure en son nom. **Veuillez noter qu’une personne qui s’authentifie auprès de votre service ne constitue pas, en soi, un consentement.**

<div id="consent-permissions">
  ## Consentement et autorisations
</div>

**En particulier, vous devez obtenir le consentement exprès et éclairé des personnes avant de faire l’une des choses suivantes :**

* Prendre *toute* mesure en leur nom. Cela inclut (sans s’y limiter) :
  * Publier du contenu sur X
  * Suivre/ne plus suivre des comptes
  * Modifier les informations de profil ou de compte
  * Ajouter des hashtags ou tout autre contenu aux Publications

* Republier du contenu auquel vous accédez par des moyens autres que via la X API ou d’autres outils X

* Utiliser le contenu X de quelqu’un pour promouvoir un produit ou un service

* Stocker du contenu non public, comme les Messages privés (DM), ou toute autre information privée ou confidentielle

* Partager ou publier du contenu protégé, ou toute autre information privée ou confidentielle

**Si votre service permet aux personnes de publier du contenu sur X, vous devez effectuer les opérations suivantes avant la publication :**

* Afficher exactement ce qui sera publié
* Indiquer clairement aux personnes utilisant votre service quelles informations de géolocalisation (le cas échéant) seront ajoutées au contenu

**Si votre service permet aux personnes de publier du contenu à la fois sur votre service et sur X, vous devez effectuer les opérations suivantes avant la publication :**

* Obtenir l’autorisation de publier le contenu
* Expliquer où vous publierez le contenu

**Vous devez respecter le statut protégé et bloqué de tout contenu X. Vous ne pouvez pas diffuser du contenu obtenu à l’aide du jeton d’authentification d’une personne à une autre personne qui n’est pas autorisée à voir ce contenu.**

* **Comptes protégés :** le contenu d’un [compte protégé](https://help.x.com/safety-and-security/public-and-protected-posts) n’est disponible que pour les personnes qui ont été approuvées par le propriétaire pour suivre ce compte. Ainsi, si vous exploitez un service qui accède à des comptes protégés, vous ne pouvez le faire que pour diffuser ce contenu aux personnes spécifiques disposant de l’autorisation de voir ce contenu.
* **Comptes bloqués :** les personnes sur X peuvent [bloquer](https://help.x.com/using-x/blocking-and-unblocking-accounts) l’accès à leurs comptes pour toute raison de leur choix. Le fait de mélanger des informations obtenues à partir de jetons (ou de toute autre action utilisant l’API) afin de contourner ce choix n’est pas autorisé.

**Étant donné que les Messages privés (DM) sont par nature non publics, les services qui fournissent des fonctionnalités de DM doivent prendre des mesures supplémentaires pour protéger la vie privée. Vous ne pouvez pas diffuser le contenu de DM à des personnes qui ne sont pas autorisées à voir ce contenu. Si votre service fournit des fonctionnalités de DM, vous devez également :**

* Informer les personnes si vous envoyez des événements de confirmation de lecture pour les DM. Vous pouvez le faire en fournissant un avis directement dans votre service ou en affichant les confirmations de lecture des autres participants à une conversation.
* Obtenir le consentement avant de configurer un média envoyé dans un DM comme « partagé » (c’est‑à‑dire réutilisable dans plusieurs DM). Si vous autorisez un média dans un DM à être « partagé », vous devez fournir un avis clair indiquant que ce contenu sera accessible à toute personne disposant de l’URL du média.

<div id="content-compliance">
  ## Conformité du contenu
</div>

**Si vous stockez du Contenu X hors ligne, vous devez le maintenir à jour pour qu’il reflète l’état actuel de ce contenu sur X.** Plus précisément, vous devez supprimer ou modifier tout contenu en votre possession s’il est supprimé ou modifié sur X. Cela doit être fait dès que raisonnablement possible, ou dans les 24 heures suivant la réception d’une demande en ce sens de la part de X ou du propriétaire du compte X concerné, ou selon ce qui est autrement prévu par votre contrat avec X ou par la loi applicable. Cela doit être fait sauf lorsque la loi l’interdit, et uniquement dans ce cas avec l’autorisation écrite expresse de X.

Le contenu modifié peut prendre différentes formes. Cela comprend (sans s’y limiter) :

* Contenu qui a été rendu privé ou a acquis un statut protégé
* Contenu qui a été suspendu de la plateforme
* Contenu dont les balises de géolocalisation ont été supprimées
* Contenu qui a été bloqué ou supprimé de X

<div id="off-x-matching">
  ## Correspondance hors de X
</div>

**Nous limitons les circonstances dans lesquelles vous pouvez faire correspondre une personne sur X avec des informations obtenues ou stockées hors de X.** La correspondance hors de X consiste à associer du Contenu X, y compris un @handle X ou un identifiant utilisateur, à une personne, un foyer, un appareil, un navigateur ou un autre identifiant hors de X. Vous ne pouvez le faire que si vous disposez du consentement explicite et préalable de la personne avant de procéder à cette association, ou comme décrit ci-dessous.

Dans les situations où vous ne disposez pas du consentement explicite et préalable d’une personne pour lier son identité X à un identifiant hors de X, nous exigeons que tout lien que vous établissez soit fondé uniquement sur des informations dont on peut raisonnablement s’attendre à ce qu’elles soient utilisées à cette fin. De plus, en l’absence du consentement explicite et préalable d’une personne, vous ne pouvez tenter de faire correspondre les informations que vous détenez sur quelqu’un à une identité X qu’en vous basant sur :

* **Les informations fournies directement par la personne.** Notez que les informations relatives à des personnes avec lesquelles vous n’avez aucune relation préalable, y compris les données sur des personnes obtenues auprès de tiers, ne satisfont pas à cette exigence ; et/ou
* **Les données publiques.** « Données publiques » dans ce contexte désigne :
  * Les informations concernant une personne que vous avez obtenues à partir d’une ressource publique et généralement accessible (comme un annuaire des membres d’une association professionnelle)
  * Les informations sur X concernant une personne qui sont publiquement disponibles, notamment :
    * Publications
    * Informations de profil, y compris la biographie du compte et la localisation affichée publiquement
    * Nom d’affichage et @handle

<div id="your-privacy-policy">
  ## Votre politique de confidentialité
</div>

**Vous devez présenter la politique de confidentialité de votre service aux personnes avant qu’elles ne soient autorisées à télécharger, installer ou s’inscrire à votre service.** Elle doit indiquer au minimum les informations suivantes :

* Les informations que vous collectez auprès des personnes qui utilisent votre service
* La manière dont vous utilisez et partagez ces informations (y compris avec X)
* La manière dont les personnes peuvent vous contacter pour toute question ou demande concernant les informations les concernant

Votre politique de confidentialité doit être conforme à toutes les lois applicables et offrir aux personnes un niveau de protection au moins équivalent à celui de la [Politique de confidentialité de X](https://x.com/privacy) et de la [politique de confidentialité de nos autres services et sociétés affiliées](https://help.x.com/rules-and-policies/x-services-and-corporate-affiliates). Vous devez cesser votre accès à X API et l’utilisation de tout contenu X si vous n’êtes pas en mesure de respecter votre politique de confidentialité et/ou celle de X.

<div id="using-geo-data">
  ## Utilisation des données géographiques
</div>

**L’utilisation de données géographiques est soumise à des restrictions supplémentaires en raison de la nature sensible de ces informations.** Si votre service ajoute des informations de localisation aux Publications, vous devez informer les utilisateurs :

* Quand vous ajoutez des informations de localisation
* Si vous ajoutez des informations de localisation sous forme de géotag ou de données d’annotation
* Si vos informations de localisation sont indiquées comme un lieu ou sous forme de coordonnées géographiques

Si votre application permet aux utilisateurs de publier avec leur localisation, vous devez respecter intégralement les [règles relatives aux données géographiques](/fr/developer-terms/geo-guidelines) de X.

**Toute utilisation de données de localisation ou d’informations géographiques de façon isolée est interdite.** Vous ne pouvez pas (et ne pouvez pas autoriser d’autres à) stocker, agréger ou mettre en cache des données de localisation et autres informations géographiques contenues dans le Contenu X, sauf dans le cadre d’une Publication. Par exemple, vous ne pouvez pas dissocier les données de localisation ou les informations géographiques des Publications pour montrer où des personnes se sont trouvées au fil du temps. Les cartes de chaleur et les outils associés qui affichent une activité géographique agrégée (par exemple, le nombre de personnes dans une ville utilisant un hashtag) sont autorisés.

<div id="x-passwords">
  ## Mots de passe X
</div>

**Vous ne pouvez pas conserver de mots de passe X, ni demander directement aux personnes de vous communiquer leur mot de passe X, leurs identifiants de compte ou les informations de leur App développeur (y compris la consumer key).** Nous vous suggérons d’utiliser [Sign-in with X](/fr/fundamentals/authentication/guides/log-in-with-x) comme outil d’authentification pour relier votre service aux personnes sur X.

<div id="platform-usage-guidelines">
  ## Directives d’utilisation de la plateforme
</div>

Avez-vous pris soin d’examiner attentivement les politiques de X et de configurer correctement votre accès à l’API ? Votre service respecte-t-il les règles de confidentialité et de contrôle de X ? Si vous pouvez répondre oui à ces deux questions, vous êtes prêt à commencer à utiliser X API et le Contenu X. Les directives d’utilisation de la plateforme de X fournissent l’aide nécessaire pour veiller à ce que votre utilisation du Contenu X soit conforme dès le premier jour et tout au long du cycle de vie de votre service. Nous vous recommandons de revoir régulièrement ces règles afin de vous assurer que votre intégration fonctionne de manière sécurisée et bénéfique pour les personnes sur X et pour la plateforme X dans son ensemble.

<div id="spam-bots-and-automation">
  ## Spam, bots et automatisation
</div>

**L’utilisation de X API et des produits pour développeurs afin de créer du spam ou de se livrer à toute forme de manipulation de la plateforme est interdite.** Vous devez consulter les règles de X relatives à la [manipulation de la plateforme et au spam](https://help.x.com/rules-and-policies/platform-manipulation) et veiller à ce que votre service ne viole pas nos règles et ne permette pas à des personnes de le faire.

**Les services qui effectuent des actions d’écriture, y compris la publication de Publications, le suivi de comptes ou l’envoi de Messages privés, doivent respecter les [règles d’automatisation](https://help.x.com/rules-and-policies/x-automation).** En particulier, vous devez :

* Toujours obtenir le consentement explicite des personnes avant d’envoyer des [réponses ou Messages privés automatisés](https://twittercommunity.com/t/policy-clarification-automated-replies-and-mentions/94444)
* Respecter immédiatement les demandes de désinscription de toute prise de contact de votre part
* Ne jamais effectuer d’actions massives, agressives ou de type spam, y compris le [suivi en masse](https://twittercommunity.com/t/policy-clarification-aggressive-following-and-inorganic-following-behavior/92769)
* Ne jamais publier de contenu identique ou sensiblement similaire sur [plusieurs comptes](https://blog.twitter.com/developer/en_us/topics/tips/2018/automation-and-the-use-of-multiple-accounts.html)

**Si vous exploitez un compte bot basé sur l’API, vous devez indiquer clairement de quel type de compte il s’agit et qui en est responsable.** Vous ne devez jamais tromper ni induire les personnes en erreur quant au fait que votre compte est ou n’est pas un bot. Un bon moyen de le faire est d’inclure dans la biographie du profil une mention indiquant que le compte est un bot.

<div id="x-performance-benchmarking">
  ## Benchmarking des performances de X
</div>

**Vous ne pouvez pas utiliser l&#39;API X pour mesurer la disponibilité, les performances, les fonctionnalités ou l&#39;utilisation de X à des fins de benchmarking, de concurrence ou à des fins commerciales.** Par exemple, vous ne devez jamais utiliser l&#39;API X pour :

* Calculer des métriques agrégées pour X, telles que le nombre total d&#39;utilisateurs mensuels actifs (MAs) ou d&#39;utilisateurs quotidiens actifs (DAs)
* Calculer des métriques agrégées relatives aux Publications sur X, telles que le nombre total de Publications par jour ou le nombre d&#39;interactions avec les comptes
* Mesurer ou analyser la réactivité de X
* Mesurer ou analyser le spam ou la sécurité sur X, sauf si cela est autorisé ci-dessous

**Nous soutenons la recherche qui contribue à améliorer la santé des conversations sur X.** Vous ne pouvez pas divulguer publiquement de recherches ou de résultats concernant, ni développer, créer ou proposer des services utilisant, l&#39;API X ou le contenu X qui mesurent, analysent ou tentent d&#39;identifier des comportements ou contenus qui enfreignent les règles de X sans l&#39;autorisation écrite expresse de X.

**Chercheurs DSA :** Si vous devez contacter X concernant l&#39;accès au titre de l&#39;art. 40 du Digital Services Act, veuillez contacter [**EU-Questions@X.com**](mailto:EU-Questions@X.com). Si vous souhaitez demander un accès en tant que chercheur, veuillez soumettre une [demande](https://forms.gle/btDwenPF7M3hgSvw7).

<div id="public-display-of-posts">
  ## Affichage public des Publications
</div>

**Vous devez respecter l’intégrité de tout contenu X que vous affichez publiquement ou aux personnes qui utilisent votre service.** Si vous n’utilisez pas [X for Websites](https://developer.x.com/docs/twitter-for-websites/overview) pour afficher du contenu, vous devez alors utiliser l’X API pour récupérer la version la plus récente disponible à l’affichage. Si le contenu affiché n’est plus disponible via l’X API, vous devez le retirer de votre service dès que raisonnablement possible, ou dans les 24 heures suivant la réception d’une demande de retrait émanant de X, du titulaire du compte X concerné, ou conformément à toute autre exigence du droit applicable.

**Il existe des règles spécifiques que vous devez respecter si vous affichez du contenu X hors ligne.** Suivez les [directives](https://developer.x.com/developer-terms/display-requirements) relatives à l’utilisation des Publications dans les diffusions si vous affichez des Publications hors ligne.

**Si vous intégrez ou affichez des Publications, vous devez nous contacter au sujet de votre accès à l’X API si votre site dépasse 10 millions d’impressions quotidiennes.** X se réserve le droit d’exiger des conditions supplémentaires comme condition de votre utilisation de l’X API. Des restrictions supplémentaires relatives à l’utilisation de X for Websites par les développeurs incluent :

* **Publications intégrées et/ou chronologies intégrées**
