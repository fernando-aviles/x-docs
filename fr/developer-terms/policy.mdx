<div id="x-developers">
  ## X + Developers
</div>

X aime les développeurs. Nous sommes ravis et impressionnés par les outils et services que cette communauté crée en tirant parti de la puissance des données X. Dans le cadre de notre engagement envers cette communauté, nous visons à fournir un accès aux données qui soit ouvert et équitable pour les développeurs, sûr pour les personnes sur X, et bénéfique pour la plateforme X dans son ensemble. Pour soutenir ces objectifs, nous avons élaboré la Developer Policy comme guide pour aider chacun à comprendre nos règles et nos attentes concernant l’utilisation appropriée de X API et de X Content.

Cette Developer Policy (la « **Policy** ») fournit des règles et des lignes directrices pour les développeurs qui interagissent avec l’écosystème d’applications, de services, de site web, de pages web et de contenus de X. Elle fait partie de votre contrat avec X, qui régit l’accès à X API et à X Content, ainsi que leur utilisation (dans le cadre du Developer Agreement ou de tout autre accord écrit avec X). Tout manquement à la Policy est considéré comme une violation de votre accord. Cette Policy peut être modifiée de temps à autre sans préavis. Les termes commençant par une majuscule utilisés dans cette Policy, qui ne sont pas définis dans cette Policy, auront le sens qui leur est attribué dans le [Developer Agreement](/fr/developer-terms/agreement) ou le Master License Agreement.

<div id="using-this-policy">
  ## Utiliser cette politique
</div>

Nous avons structuré cette politique de manière à ce qu’elle soit aussi facile à suivre que possible. Veuillez garder à l’esprit les informations provenant des sections suivantes de la politique lorsque vous utilisez l’X API et l’X Content :

1. **Mettez toutes les chances de votre côté** - Vous êtes responsable du respect de l’ensemble des politiques de X. Il est important que vous examiniez et compreniez la présente Politique, ainsi que les politiques auxquelles nous renvoyons dans ce document, avant d’accéder à l’X API et à l’X Content. Le temps consacré à l’examen de nos politiques peut vous éviter des heures de travail de mise en conformité par la suite.

2. **La confidentialité et le contrôle sont essentiels** - La protection et la défense de la vie privée des personnes sur X font partie de l’ADN même de notre entreprise. À ce titre, nous interdisons l’utilisation des données de X de toute manière incompatible avec les attentes raisonnables des personnes en matière de confidentialité. En développant sur l’X API ou en accédant à l’X Content, vous jouez un rôle particulier dans la protection de cet engagement, principalement en respectant la vie privée des personnes et en leur offrant transparence et contrôle sur la manière dont leurs données sont utilisées.

3. **Suivez les directives d’utilisation de la plateforme** - L’obtention de l’autorisation d’accéder à l’X API et à l’X Content n’est que la première étape. Nos directives d’utilisation de la plateforme doivent être votre première référence dès que vous avez des questions sur la manière de garantir la conformité aux règles pour l’utilisation prévue de la plateforme X.

Nous fournissons ci‑dessous davantage de détails sur ce que signifie chacune de ces trois sections clés. Veuillez les examiner attentivement pour vous assurer que votre utilisation de l’X API et de l’X Content est conforme à nos politiques.

Si nous pensons que vous enfreignez la présente Politique (ou toute autre politique de X), nous pouvons suspendre ou révoquer définitivement votre accès à l’X API et à l’X Content.

Enfin, veuillez noter que X peut surveiller votre utilisation de l’X API afin d’améliorer les applications X, d’examiner toute utilisation commerciale et de garantir votre conformité avec votre cas d’utilisation approuvé et avec cette Politique.

Merci de votre attention, et merci de développer avec nous ! Nous avons hâte de voir ce que vous allez créer !

<div id="set-yourself-up-for-success">
  ## Donnez-vous les moyens de réussir
</div>

Vous pouvez éviter de nombreux écueils potentiels lors de l’utilisation de X API en veillant à ce que votre service soit correctement conçu dès le premier jour. Cette section de la Developer Policy contient des règles que tous les développeurs doivent suivre avant d&#39;utiliser X API ou X Content.

Les offres Free, Basic et Pro (telles que décrites sur [developer.x.com/en](http://developer.x.com/en)) sont conçues pour les passionnés, le prototypage commercial, les intégrations de produits X en phase initiale et les applications avec un nombre limité d’utilisateurs finaux. Si vous utilisez X API et X Content au-delà de ce cadre, vous devez alors demander (ou déjà souscrire) une offre Enterprise (telle que décrite sur [developer.x.com/en](http://developer.x.com/en)).

**Nous examinons toutes les utilisations proposées de la plateforme développeur X afin de vérifier la conformité aux règles — vous êtes donc tenu de nous communiquer (et de mettre à jour, le cas échéant) votre utilisation prévue de X API et de X Content pour obtenir et conserver l&#39;accès.** Tous les nouveaux développeurs doivent [demander un compte développeur](https://developer.x.com/portal/petition/essential/basic-info) pour accéder à X API. Les développeurs actuels qui ne disposent pas d’un compte développeur approuvé doivent en demander un, comme X le leur indiquera. Dans le cadre de ce processus, vous devrez nous fournir une description écrite de vos utilisations prévues de X API et de X Content.

La description de votre cas d’usage vous engage et toute déviation substantielle par rapport à celle-ci peut constituer une violation de nos règles et entraîner des mesures d’application. Vous devez nous informer de toute modification substantielle de votre cas d’usage et obtenir notre approbation avant de commencer à utiliser X Content à cette nouvelle fin. Le non-respect de cette obligation peut entraîner la suspension et la résiliation de votre accès à l’API et aux données.

**En développant sur X API ou en accédant à X Content, vous devez respecter TOUTES les règles de X.** Celles-ci comprennent la présente [Developer Policy](/fr/developer-terms/policy), les [Automation Rules](https://help.x.com/rules-and-policies/x-automation), les [Display Requirements](https://developer.x.com/developer-terms/display-requirements.html), les [API Restricted Uses Rules](/fr/developer-terms/restricted-use-cases), les [X Rules](https://help.x.com/rules-and-policies/x-rules) et les [X Brand Resources](https://about.x.com/who-we-are/brand-toolkit), ainsi que tout autre accord que vous concluez avec X relatif à votre utilisation de X API ou de X Content, y compris, sans s’y limiter, le [Developer Agreement](/fr/developer-terms/agreement) ou un Master Licensing Agreement ou Order (le cas échéant). Vous devez également respecter toute modification de ces règles et toute nouvelle règle mise en place par X. Il vous incombe de surveiller l’utilisation de votre service et de concevoir votre service de manière à empêcher les violations des règles de X par les personnes qui l’utilisent. Le non-respect de cette obligation peut entraîner la suspension ou la résiliation de votre accès à l’API et à X Content.

**Vous ne pouvez pas enregistrer plusieurs applications pour un seul cas d’usage ou pour des cas d’usage substantiellement similaires ou se recoupant.** Dans ce contexte, un « cas d’usage » est un ensemble cohérent d’analyses, d’affichages ou d’actions effectués via une application. Les versions « white label » d’un outil ou d’un service ne sont pas autorisées. Si vous prévoyez de proposer des versions « white label » de votre application, vous devez nous en informer et obtenir une approbation distincte de notre part.

*À titre de seule exception à ces règles,* vous pouvez créer et utiliser au maximum 3 applications pour les environnements de développement, de préproduction (staging) et de production d’un même service. Ces applications doivent être enregistrées sur un seul compte et doivent être clairement identifiées (dans le nom et la description) comme des instances dev, staging et prod d’un même service. **Vous ne pouvez pas utiliser des applications de développement ou de préproduction à des fins de production.**

**Vous devez garder toutes les clés d’API et autres identifiants d’accès confidentiels.** Vous ne pouvez pas utiliser, ni encourager ou faciliter l’utilisation par des tiers, de clés d’API ou d’autres identifiants d’accès appartenant à d’autres personnes.

**Votre accord de licence avec X limite votre utilisation de X API et de X Content. Entre autres choses, X API applique des limites de débit qui permettent de garantir une utilisation équitable des données et de lutter contre le spam sur la plateforme.** Vous ne pouvez pas dépasser ni contourner les limites de débit, ni aucune autre limitation ou restriction décrite dans la présente politique ou dans votre accord avec X, répertoriées sur le [Developer Site](https://developer.x.com/) ou qui vous sont communiquées par X.

**Vous ne pouvez pas supprimer ni modifier les mentions de propriété ou les marques figurant sur X Content reçu via X API.** Cela permet de s’assurer que les personnes savent d’où provient X Content et à qui il appartient.

**Pour des raisons d’intégrité des données et de santé de la plateforme, vous ne pouvez pas interférer avec, intercepter, perturber ni désactiver des fonctionnalités de X API ou du service X.** En d’autres termes, utilisez les API comme prévu et tel que documenté sur [developer.x.com](https://developer.x.com/). Consultez nos [directives HackerOne](https://hackerone.com/x) pour plus de détails sur l’utilisation acceptable.

<div id="privacy-and-control-are-essential">
  ## Le respect de la vie privée et le contrôle sont essentiels
</div>

X accorde une grande importance à la vie privée et nous attendons de toute personne utilisant le Contenu X et le X API qu’elle fasse de même. Toute utilisation de la plateforme de développement X, du X API ou du Contenu X d’une manière incompatible avec les attentes raisonnables des personnes en matière de vie privée peut faire l’objet de mesures d’application, pouvant inclure la suspension et la résiliation de l’accès à l’API et au Contenu X.

Votre engagement envers la vie privée et le contrôle doit s’étendre à toutes les utilisations du Contenu X et à tous les aspects du service que vous créez à l’aide de notre API. À cette fin, les personnes utilisant votre service doivent comprendre et accepter la manière dont vous utilisez leurs données, ainsi que la manière dont vous accédez à X en leur nom. Cela peut être réalisé en fournissant aux personnes une politique de confidentialité claire, complète et transparente, et en veillant à obtenir un consentement exprès et éclairé de chaque personne utilisant votre service avant d’entreprendre toute action en son nom. **Veuillez noter que le fait pour une personne de s’authentifier dans votre service ne constitue pas, en soi, un consentement.**

<div id="consent-permissions">
  ## Consentement et autorisations
</div>

**En particulier, vous devez obtenir le consentement exprès et éclairé des personnes avant de faire l’une des choses suivantes :**

* Effectuer *toute* action en leur nom. Cela inclut (sans s’y limiter) :
  * Publier du contenu sur X
  * Suivre / ne plus suivre des comptes
  * Modifier les informations de profil ou de compte
  * Ajouter des hashtags ou tout autre contenu aux Publications

* Republier du contenu auquel vous avez accédé par des moyens autres que via X API ou d’autres outils X

* Utiliser le contenu X de quelqu’un pour promouvoir un produit ou un service

* Stocker du contenu non public tel que des messages privés (DM), ou toute autre information privée ou confidentielle

* Partager ou publier du contenu protégé, ou toute autre information privée ou confidentielle

**Si votre service permet aux personnes de publier du contenu sur X, vous devez faire ce qui suit avant la publication :**

* Afficher exactement ce qui sera publié
* Indiquer clairement aux personnes qui utilisent votre service quelles informations de géolocalisation (le cas échéant) seront ajoutées au contenu

**Si votre service permet aux personnes de publier du contenu à la fois sur votre service et sur X, vous devez faire ce qui suit avant la publication :**

* Obtenir l’autorisation de publier le contenu
* Expliquer où vous publierez le contenu

**Vous devez respecter le statut protégé et bloqué de tout contenu X. Vous ne pouvez pas diffuser du contenu obtenu en utilisant le jeton d’authentification d’une personne à une autre personne qui n’est pas autorisée à consulter ce contenu.**

* **Comptes protégés :** Le contenu d’un [compte protégé](https://help.x.com/safety-and-security/public-and-protected-posts) n’est disponible que pour les personnes qui ont été approuvées par le propriétaire pour suivre ce compte. Ainsi, si vous exploitez un service qui accède à des comptes protégés, vous ne pouvez le faire que pour diffuser ce contenu aux personnes spécifiques qui ont l’autorisation de le consulter.
* **Comptes bloqués :** Les personnes sur X peuvent [bloquer](https://help.x.com/using-x/blocking-and-unblocking-accounts) l’accès à leurs comptes pour toute raison de leur choix. Le fait de combiner des informations obtenues à partir de jetons (ou toute autre action basée sur l’API) afin de contourner ce choix n’est pas autorisé.

**Étant donné que les messages privés (DM) sont de nature non publique, les services qui fournissent des fonctionnalités de DM doivent prendre des mesures supplémentaires pour protéger la vie privée des personnes. Vous ne pouvez pas diffuser du contenu de DM à des personnes qui ne sont pas autorisées à consulter ce contenu. Si votre service fournit des fonctionnalités de DM, vous devez également :**

* Informer les personnes si vous envoyez des accusés de lecture pour les DM. Vous pouvez le faire en affichant un message directement dans votre service, ou en affichant les accusés de lecture des autres participants à une conversation.
* Obtenir le consentement avant de configurer des médias envoyés dans un DM comme « partagés » (c’est-à-dire réutilisables dans plusieurs DM). Si vous autorisez des médias dans un DM à être « partagés », vous devez fournir un avis clair indiquant que ce contenu sera accessible à toute personne disposant de l’URL du média.

<div id="content-compliance">
  ## Conformité du contenu
</div>

**Si vous stockez du contenu X hors ligne, vous devez le maintenir à jour par rapport à l’état actuel de ce contenu sur X.** Plus précisément, vous devez supprimer ou modifier tout contenu en votre possession s’il est supprimé ou modifié sur X. Cette opération doit être effectuée dès que raisonnablement possible, ou dans les 24 heures suivant la réception d’une demande en ce sens de la part de X ou du propriétaire du compte X concerné, ou selon ce qui est autrement requis par votre accord avec X ou par la loi applicable. Cette obligation s’applique sauf si la loi l’interdit, et, dans ce cas, uniquement avec l’autorisation écrite expresse de X.

Le contenu modifié peut prendre différentes formes. Cela inclut (sans s’y limiter) :

* Contenu qui a été rendu privé ou bénéficie désormais d’un statut protégé
* Contenu qui a été suspendu de la plateforme
* Contenu dont les géotags ont été supprimés
* Contenu qui a été bloqué ou supprimé sur X

<div id="off-x-matching">
  ## Correspondance hors de X
</div>

**Nous limitons les circonstances dans lesquelles vous pouvez faire correspondre une personne sur X avec des informations obtenues ou stockées en dehors de X.** La correspondance hors de X consiste à associer du contenu X, y compris un @handle X ou un user ID, à une personne, un foyer, un appareil, un navigateur ou un autre identifiant hors de X. Vous ne pouvez le faire que si vous avez obtenu le consentement explicite (opt‑in) de la personne avant de procéder à cette association, ou comme décrit ci‑dessous.

Dans les situations où vous ne disposez pas du consentement explicite (opt‑in) d’une personne pour lier son identité X à un identifiant hors de X, nous exigeons que tout lien que vous établissez soit fondé uniquement sur des informations dont on peut raisonnablement s’attendre à ce qu’elles soient utilisées à cette fin. De plus, en l’absence de consentement explicite (opt‑in) de la personne, vous ne pouvez tenter de faire correspondre vos enregistrements concernant cette personne à une identité X qu’en vous basant sur :

* **Les informations qui vous sont fournies directement par la personne.** Notez que les enregistrements concernant des personnes avec lesquelles vous n’avez aucune relation préalable, y compris les données concernant des personnes obtenues auprès de tiers, ne répondent pas à cette exigence ; et/ou
* **Les données publiques.** « Données publiques », dans ce contexte, désigne :
  * Les informations concernant une personne que vous avez obtenues à partir d’une ressource publique et généralement accessible (telle qu’un annuaire des membres d’une association professionnelle)
  * Les informations sur X concernant une personne qui sont publiquement accessibles, y compris :
    * Publications
    * Informations de profil, y compris la bio du compte et la localisation indiquée publiquement
    * Nom d’affichage et @handle

<div id="your-privacy-policy">
  ## Votre politique de confidentialité
</div>

**Vous devez présenter la politique de confidentialité de votre service aux personnes avant qu’elles ne soient autorisées à télécharger, installer ou s’inscrire à votre service.** Elle doit présenter au minimum les informations suivantes :

* Les informations que vous collectez auprès des personnes qui utilisent votre service
* La façon dont vous utilisez et partagez ces informations (y compris avec X)
* Comment les personnes peuvent vous contacter pour toute question et demande concernant leurs informations

Votre politique de confidentialité doit être conforme à toutes les lois applicables et offrir un niveau de protection au moins équivalent à celui de la [politique de confidentialité de X](https://x.com/privacy) et de la [politique de confidentialité de nos autres services et sociétés affiliées](https://help.x.com/rules-and-policies/x-services-and-corporate-affiliates). Vous devez cesser votre accès à X API et toute utilisation de X Content si vous n’êtes pas en mesure de respecter votre propre politique de confidentialité et/ou celle de X.

<div id="using-geo-data">
  ## Utilisation des données de géolocalisation
</div>

**L’utilisation de données de géolocalisation est soumise à des restrictions supplémentaires en raison de la nature sensible de ces informations.** Si votre service ajoute des informations de localisation aux Publications, vous devez informer les personnes :

* Quand vous ajoutez des informations de localisation
* Si vous ajoutez des informations de localisation sous forme de geotag ou de données d’annotation
* Si vos informations de localisation sont présentées comme un lieu ou sous forme de coordonnées géographiques

Si votre application permet aux personnes de publier avec leur localisation, vous devez respecter intégralement les [directives de géolocalisation](/fr/developer-terms/geo-guidelines) de X.

**Toute utilisation de données de localisation ou d’informations géographiques de manière isolée est interdite.** Vous ne pouvez pas (et ne pouvez pas autoriser d’autres personnes à) stocker, agréger ou mettre en cache des données de localisation et d’autres informations géographiques contenues dans le Contenu X, sauf dans le cadre d’une Publication. Par exemple, vous ne pouvez pas dissocier les données de localisation ou les informations géographiques des Publications pour montrer où des personnes se sont trouvées au fil du temps. Les cartes de chaleur et outils similaires qui affichent une activité géographique agrégée (par exemple, le nombre de personnes dans une ville utilisant un hashtag) sont autorisés.

<div id="platform-usage-guidelines">
  ## Directives d’utilisation de la plateforme
</div>

Avez-vous pris le temps d’examiner les politiques de X et de configurer correctement votre accès à l’X API ? Votre service respecte-t-il les règles de confidentialité et de contrôle de X ? Si vous pouvez répondre oui à ces deux questions, vous êtes prêt à commencer à utiliser l’X API et X Content. Les directives d’utilisation de la plateforme de X fournissent l’assistance nécessaire pour garantir que votre utilisation de X Content est conforme dès le premier jour et tout au long du cycle de vie de votre service. Nous vous recommandons de passer régulièrement en revue ces règles afin de vous assurer que votre intégration fonctionne de manière sûre et bénéfique pour les personnes sur X et pour la plateforme X dans son ensemble.

<div id="spam-bots-and-automation">
  ## Spam, bots et automatisation
</div>

**L’utilisation de X API et des produits pour développeurs afin de créer du spam ou de se livrer à toute forme de manipulation de la plateforme est interdite.** Vous devez consulter les Règles de X relatives à la [manipulation de la plateforme et au spam](https://help.x.com/rules-and-policies/platform-manipulation) et vous assurer que votre service ne viole pas nos règles et ne permet pas à des personnes de les violer.

**Les services qui effectuent des actions d’écriture, notamment la publication de Publications, le suivi de comptes ou l’envoi de Messages privés, doivent respecter les [Règles d’automatisation](https://help.x.com/rules-and-policies/x-automation).** En particulier, vous devez :

* Toujours obtenir un consentement explicite avant d’envoyer des [réponses automatisées ou des Messages privés](https://twittercommunity.com/t/policy-clarification-automated-replies-and-mentions/94444)
* Respecter immédiatement les demandes de ne plus être contacté par vous
* Ne jamais effectuer d’actions massives, agressives ou assimilables à du spam, y compris le [suivi en masse](https://twittercommunity.com/t/policy-clarification-aggressive-following-and-inorganic-following-behavior/92769)
* Ne jamais publier de contenu identique ou sensiblement similaire sur [plusieurs comptes](https://blog.twitter.com/developer/en_us/topics/tips/2018/automation-and-the-use-of-multiple-accounts.html)

**Si vous exploitez un compte bot basé sur l’API, vous devez indiquer clairement de quel type de compte il s’agit et qui en est responsable.** Vous ne devez jamais tromper ou induire les personnes en erreur quant au fait que votre compte est ou n’est pas un bot. Une bonne façon de le faire consiste à inclure dans la biographie du profil une mention indiquant que le compte est un bot.

<div id="x-performance-benchmarking">
  ## Évaluation des performances de X
</div>

**Vous ne pouvez pas utiliser X API pour mesurer la disponibilité, les performances, les fonctionnalités ou l’utilisation de X à des fins d’évaluation comparative, concurrentielles ou commerciales.** Par exemple, vous ne devez jamais utiliser X API pour :

* Calculer des métriques X agrégées, comme le nombre total d’utilisateurs actifs mensuels (MAs) ou d’utilisateurs actifs quotidiens (DAs)
* Calculer des métriques agrégées de Publications X, comme le nombre total de Publications publiées par jour ou le nombre d’engagements de comptes
* Mesurer ou analyser la réactivité de X
* Mesurer ou analyser le spam ou la sécurité sur X, sauf dans les cas autorisés ci-dessous

**Nous soutenons la recherche qui contribue à améliorer la santé des conversations sur X.** Vous ne pouvez pas divulguer publiquement de recherches ou de conclusions concernant X API ou X Content, ni développer, créer ou proposer des services utilisant X API ou X Content qui mesurent, analysent ou tentent d’identifier des comportements ou des contenus qui enfreignent les règles de X, sans l’autorisation écrite expresse de X.

**Chercheurs DSA :** Si vous devez contacter X au sujet d’un accès au titre de l’article 40 du Digital Services Act, veuillez écrire à [**EU-Questions@X.com**](mailto:EU-Questions@X.com). Si vous souhaitez demander un accès pour les chercheurs, veuillez soumettre une [candidature](https://forms.gle/btDwenPF7M3hgSvw7).

<div id="public-display-of-posts">
  ## Affichage public des Publications
</div>

**Vous devez maintenir l’intégrité de tout Contenu X que vous affichez publiquement ou aux personnes qui utilisent votre service.** Si vous n’utilisez pas [X for Websites](https://developer.x.com/docs/twitter-for-websites/overview) pour afficher du contenu, vous devez alors utiliser X API pour récupérer la version la plus récente disponible à l’affichage. Si le contenu affiché cesse d’être disponible via X API, vous devez le retirer de votre service dès que raisonnablement possible, ou dans les 24 heures suivant la réception d’une demande de retrait de la part de X, du propriétaire du compte X concerné, ou tel qu’autrement requis par la loi applicable.

**Il existe des règles spécifiques que vous devez respecter si vous affichez du Contenu X hors ligne.** Suivez les [directives](https://developer.x.com/developer-terms/display-requirements) relatives à l’utilisation des Publications en diffusion si vous affichez des Publications hors ligne.

**Si vous intégrez ou affichez des Publications, vous devez nous contacter au sujet de votre accès à X API si votre site dépasse 10 millions d’impressions quotidiennes.** X se réserve le droit d’exiger des conditions supplémentaires comme prérequis à votre utilisation de X API. Des restrictions supplémentaires relatives à l’utilisation de X for Websites par les développeurs incluent :

* **Publications intégrées et/ou fils intégrés**
  * Vous devez fournir aux personnes un avis juridiquement suffisant qui divulgue pleinement la collecte et l’utilisation par X des données concernant les activités de navigation sur votre site web, y compris à des fins de publicité fondée sur les centres d’intérêt et de personnalisation. Vous devez également obtenir un consentement juridiquement suffisant des personnes pour une telle collecte et utilisation
