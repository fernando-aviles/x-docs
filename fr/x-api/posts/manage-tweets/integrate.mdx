Cette page présente les outils et concepts clés pour intégrer les endpoints de gestion des publications à votre système.

<div id="helpful-tools">
  ## Outils pratiques
</div>

Avant d’aborder certains concepts clés qui vous aideront à intégrer cet endpoint, nous vous recommandons de vous familiariser avec les éléments suivants :

<div id="postman">
  ### Postman
</div>

Postman est un excellent outil que vous pouvez utiliser pour tester un endpoint. Chaque requête Postman comprend tous les paramètres de chemin et de corps de requête afin de vous aider à comprendre rapidement ce qui est disponible. Pour en savoir plus sur nos collections Postman, veuillez consulter notre page « [Utiliser Postman](/fr/tutorials/postman-getting-started) ».

  ## Concepts essentiels

<div id="authentication">
  ### Authentification
</div>

Tous les endpoints de X API v2 exigent que vous authentifiiez vos requêtes à l’aide d’un ensemble d’identifiants, également appelés clés et jetons.

Ces endpoints spécifiques nécessitent l’utilisation de [OAuth 1.0a User Context](/fr/resources/fundamentals/authentication), ce qui signifie que vous devez utiliser un ensemble de clés API et de jetons d’accès utilisateur pour effectuer une requête avec succès. Les jetons d’accès doivent être associés à l’utilisateur pour le compte duquel vous effectuez la requête. Si vous souhaitez générer un ensemble de jetons d’accès pour un autre utilisateur, celui-ci doit autoriser ou authentifier votre App en utilisant le [flux OAuth à 3 volets (3-legged OAuth flow)](/fr/resources/fundamentals/authentication#obtaining-access-tokens-using-3-legged-oauth-flow).

Notez qu’OAuth 1.0a peut être difficile à utiliser. Si vous n’êtes pas familiarisé avec cette méthode d’authentification, nous vous recommandons d’utiliser une [bibliothèque](/fr/x-api/tools-and-libraries/overview), un outil comme Postman, ou OAuth 2.0 pour authentifier vos requêtes.

[OAuth 2.0 Authorization Code with PKCE](/fr/resources/fundamentals/authentication#oauth-2-0-authorization-code-flow-with-pkce-2) permet un contrôle accru sur le périmètre d’autorisation d’une application, et des flux d’autorisation sur plusieurs appareils. OAuth 2.0 vous permet de choisir des périmètres d’autorisation précis et granulaires qui vous donnent des autorisations spécifiques pour le compte d’un utilisateur.

Pour activer OAuth 2.0 dans votre App, vous devez l’activer dans les paramètres d’authentification de votre App, qui se trouvent dans la section des paramètres de l’App de la Console de Développement.

<div id="developer-console-projects-and-developer-apps">
  ### Console de Développement, Projets et Apps développeur
</div>

Pour obtenir un ensemble d’identifiants d’authentification qui fonctionneront avec les endpoints de X API v2, vous devez disposer d’un [compte développeur]/resources/fundamentals/developer-portal), configurer un [Projet](/fr/resources/fundamentals/developer-apps) dans ce compte, puis créer une [App développeur](/fr/resources/fundamentals/developer-apps) au sein de ce Projet. Vous pourrez ensuite trouver vos clés et jetons dans votre App développeur.

<div id="rate-limits">
  ### Limites de taux
</div>

Chaque jour, plusieurs milliers de développeurs envoient des requêtes vers X API. Pour aider à gérer le volume de ces requêtes, des [limites de taux](https://developer.x.com/x-api/fundamentals/rate-limits) sont appliquées à chaque endpoint afin de limiter le nombre de requêtes que vous pouvez effectuer pour le compte de votre application ou pour le compte d’un utilisateur authentifié.

Ces endpoints sont soumis à des limites de taux au niveau utilisateur, ce qui signifie que l’utilisateur authentifié pour le compte duquel vous effectuez la requête ne peut appeler l’endpoint qu’un certain nombre de fois, quel que soit l’App développeur utilisée. Il existe une limite de taux utilisateur de 200 requêtes par période de 15 minutes pour la méthode POST. La méthode DELETE a une limite de taux de 50 requêtes par période de 15 minutes. De plus, il existe une limite de [300 requêtes par période de 3 heures](https://blog.x.com/developer/en_us/topics/tools/2018/new-developer-requirements-to-protect-our-platform), y compris les Publications créées avec les autorisations manage Posts ou manage Retweets.

<div id="source-labels">
  ### Libellés de source
</div>

Le nom de votre application et l’URL de votre site web seront affichés en tant que [libellé de source](https://help.x.com/en/using-twitter/how-to-tweet#source-labels) dans les métadonnées de toute Publication créée par programmation par votre application. Si vous modifiez le cas d’usage d’une application X, veillez à mettre à jour le cas d’usage dans ces paramètres afin de garantir que vous respectez les [Conditions d’utilisation du développeur](https://developer.x.com/content/developer-twitter/en/developer-terms/agreement-and-policy).

<div id="profile-settings">
  ### Paramètres de profil
</div>

Vous ne pouvez ajouter une localisation aux Publications que si vous avez activé la géolocalisation dans les paramètres de votre profil. Si vous n&#39;avez pas la géolocalisation activée, vous pouvez malgré tout ajouter un paramètre de localisation dans le corps de votre requête, mais il ne sera pas associé à votre Publication. Il en va de même pour l&#39;identification des utilisateurs dans les images. Si l&#39;utilisateur que vous identifiez n&#39;a pas activé l&#39;identification sur les photos, son nom n&#39;apparaîtra pas dans la liste des utilisateurs identifiés, même si la Publication est créée avec succès.

<div id="adding-media-to-a-post">
  ### Ajout de médias à une Publication
</div>

Actuellement, il n’existe pas de moyen d’effectuer un téléversement complet de médias en utilisant la v2 de la X API. En revanche, vous pouvez joindre à une Publication des médias déjà téléversés. Vous pouvez utiliser des id de média qui ont déjà été [téléversés à l’aide de l’endpoint média v1](https://developer.x.com/en/docs/twitter-api/v1/media/upload-media/api-reference/post-media-upload) ou de [X Media Studio](https://media.x.com/en/articles/products/2018/media-studio). Ces id de média doivent vous appartenir ou appartenir à l’utilisateur authentifié.

<div id="create-a-post">
  ### Créer une Publication
</div>

<CodeGroup dropdown>
  ```bash cURL
  curl -X POST "https://api.x.com/2/tweets" \
    -H "Authorization: OAuth ..." \
    -H "Content-Type: application/json" \
    -d '{"text": "Hello world!"}'
  ```

  ```python SDK Python
  from xdk import Client
  from xdk.oauth1_auth import OAuth1

  oauth1 = OAuth1(
      api_key="YOUR_API_KEY",
      api_secret="YOUR_API_SECRET",
      access_token="YOUR_ACCESS_TOKEN",
      access_token_secret="YOUR_ACCESS_TOKEN_SECRET"
  )

  client = Client(auth=oauth1)

  # Créer une Publication
  response = client.posts.create(text="Hello world!")
  print(f"Publication créée : {response.data.id}")
  ```

  ```javascript SDK JavaScript
  import { Client, OAuth1 } from "@xdevplatform/xdk";

  const oauth1 = new OAuth1({
    apiKey: "YOUR_API_KEY",
    apiSecret: "YOUR_API_SECRET",
    accessToken: "YOUR_ACCESS_TOKEN",
    accessTokenSecret: "YOUR_ACCESS_TOKEN_SECRET",
  });

  const client = new Client({ oauth1 });

  // Créer une Publication
  const response = await client.posts.create({ text: "Hello world!" });
  console.log(`Publication créée : ${response.data?.id}`);
  ```
</CodeGroup>
