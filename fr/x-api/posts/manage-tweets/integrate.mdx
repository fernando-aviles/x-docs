Cette page présente les outils et concepts clés pour intégrer les endpoints de gestion des Publications à votre système.

***

<div id="helpful-tools">
  ## Outils utiles
</div>

Avant d’aborder certains concepts clés qui vous aideront à intégrer cet endpoint, nous vous recommandons de vous familiariser avec ce qui suit :

<div id="postman">
  ### Postman
</div>

Postman est un excellent outil que vous pouvez utiliser pour tester un endpoint. Chaque requête Postman inclut tous les paramètres de chemin d’accès et de corps de requête afin de vous aider à comprendre rapidement ce qui est à votre disposition. Pour en savoir plus sur nos collections Postman, consultez notre page [&quot;Utiliser Postman&quot;](/fr/tutorials/postman-getting-started).

<div id="code-samples">
  ### Exemples de code
</div>

Vous souhaitez configurer cet endpoint à l’aide de code dans votre langage de programmation préféré ? Nous mettons à votre disposition plusieurs exemples de code sur notre [page GitHub](https://github.com/xdevplatform/Twitter-API-v2-sample-code), que vous pouvez utiliser comme point de départ.

  ## Concepts clés
</div>

<div id="authentication">
  ### Authentification
</div>

Tous les endpoints de X API v2 nécessitent que vous authentifiiez vos requêtes avec un ensemble d&#39;identifiants, également appelés clés et jetons.

Ces endpoints spécifiques requièrent l&#39;utilisation de [OAuth 1.0a User Context](/fr/resources/fundamentals/authentication), ce qui signifie que vous devez utiliser un ensemble de clés d&#39;API et de jetons d&#39;accès utilisateur pour effectuer une requête avec succès. Les jetons d&#39;accès doivent être associés à l&#39;utilisateur pour le compte duquel vous effectuez la requête. Si vous souhaitez générer un ensemble de jetons d&#39;accès pour un autre utilisateur, celui-ci doit autoriser ou authentifier votre App à l&#39;aide du [flux OAuth en 3 étapes (3-legged OAuth flow)](/fr/resources/fundamentals/authentication#obtaining-access-tokens-using-3-legged-oauth-flow).

Veuillez noter qu&#39;OAuth 1.0a peut être difficile à utiliser. Si vous n&#39;êtes pas à l&#39;aise avec cette méthode d&#39;authentification, nous vous recommandons d&#39;utiliser une [bibliothèque](/fr/x-api/tools-and-libraries/overview), un outil comme Postman, ou OAuth 2.0 pour authentifier vos requêtes.

[OAuth 2.0 Authorization Code with PKCE](/fr/resources/fundamentals/authentication#oauth-2-0-authorization-code-flow-with-pkce-2) permet un contrôle plus précis sur le périmètre (scope) d&#39;une application et sur les flux d&#39;autorisation entre plusieurs appareils. OAuth 2.0 vous permet de choisir des scopes précis et granulaires qui vous donnent des autorisations spécifiques au nom d&#39;un utilisateur.

Pour activer OAuth 2.0 dans votre App, vous devez l&#39;activer dans les paramètres d&#39;authentification de votre App, disponibles dans la section des paramètres de l&#39;App du Developer Console.

<div id="developer-console-projects-and-developer-apps">
  ### Developer Console, Projets et Apps développeur
</div>

Pour obtenir un ensemble d’identifiants d’authentification qui fonctionneront avec les endpoints de X API v2, vous devez disposer d’un [compte développeur]/resources/fundamentals/developer-portal), configurer un [Projet](/fr/resources/fundamentals/developer-apps) dans ce compte et créer une [App développeur](/fr/resources/fundamentals/developer-apps) dans ce Projet. Vous pourrez ensuite trouver vos clés et jetons dans votre App développeur.

<div id="rate-limits">
  ### Limites de fréquence
</div>

Chaque jour, plusieurs milliers de développeurs envoient des requêtes vers l&#39;X API. Pour aider à gérer l&#39;important volume de ces requêtes, des [limites de fréquence](https://developer.x.com/x-api/fundamentals/rate-limits) sont appliquées à chaque endpoint, ce qui limite le nombre de requêtes que vous pouvez effectuer au nom de votre application ou d&#39;un utilisateur authentifié.

Ces endpoints sont limités au niveau de l&#39;utilisateur, ce qui signifie que l&#39;utilisateur authentifié pour lequel vous effectuez la requête ne peut appeler l&#39;endpoint qu&#39;un certain nombre de fois, quel que soit l&#39;App développeur utilisée. Il existe une limite de fréquence utilisateur de 200 requêtes par période de 15 minutes pour la méthode POST. La méthode DELETE a une limite de fréquence de 50 requêtes par période de 15 minutes. De plus, il existe une limite de [300 requêtes toutes les 3 heures](https://blog.x.com/developer/en_us/topics/tools/2018/new-developer-requirements-to-protect-our-platform), y compris les Publications créées avec les autorisations manage Posts ou manage Retweets.

<div id="source-labels">
  ### Libellés de source
</div>

Le nom de votre App et l’URL de votre site web seront affichés comme [libellé de source](https://help.x.com/en/using-twitter/how-to-tweet#source-labels) dans les métadonnées de toute Publication créée par programmation via votre application. Si vous modifiez le cas d’utilisation d’une App X, veillez à mettre à jour ces paramètres en conséquence afin de rester en conformité avec les [Developer Terms](https://developer.x.com/content/developer-twitter/en/developer-terms/agreement-and-policy).

<div id="profile-settings">
  ### Paramètres du profil
</div>

Vous ne pouvez ajouter un lieu à des Publications que si vous avez activé la géolocalisation dans les paramètres de votre profil. Si la géolocalisation n&#39;est pas activée, vous pouvez toujours ajouter un paramètre de lieu dans le corps de votre requête, mais il ne sera pas associé à votre Publication. Il en va de même pour l&#39;identification d&#39;utilisateurs sur les images. Si l&#39;utilisateur que vous identifiez n&#39;a pas activé l&#39;identification sur les photos, leur nom n&#39;apparaîtra pas dans la liste des utilisateurs identifiés, même si la Publication est créée avec succès.

<div id="adding-media-to-a-post">
  ### Ajout de médias à une Publication
</div>

Actuellement, il n’existe pas de méthode permettant de téléverser des médias de bout en bout en utilisant la v2 de la X API. Cependant, vous pouvez joindre à une Publication des médias téléversés précédemment. Vous pouvez utiliser des id de média qui ont déjà été [téléversés à l’aide du point de terminaison media v1](https://developer.x.com/en/docs/twitter-api/v1/media/upload-media/api-reference/post-media-upload) ou de [X Media Studio](https://media.x.com/en/articles/products/2018/media-studio). Ces id de média doivent être les vôtres ou ceux d’un utilisateur authentifié.

<div id="create-a-post">
  ### Créer une publication
</div>

<CodeGroup dropdown>
  ```bash cURL
  curl -X POST "https://api.x.com/2/tweets" \
    -H "Authorization: OAuth ..." \
    -H "Content-Type: application/json" \
    -d '{"text": "Hello world!"}'
  ```

  ```python Python SDK
  from xdk import Client
  from xdk.oauth1_auth import OAuth1

  oauth1 = OAuth1(
      api_key="YOUR_API_KEY",
      api_secret="YOUR_API_SECRET",
      access_token="YOUR_ACCESS_TOKEN",
      access_token_secret="YOUR_ACCESS_TOKEN_SECRET"
  )

  client = Client(auth=oauth1)

  # Créer une publication
  response = client.posts.create(text="Hello world!")
  print(f"Publication créée : {response.data.id}")
  ```

  ```javascript JavaScript SDK
  import { Client, OAuth1 } from "@xdevplatform/xdk";

  const oauth1 = new OAuth1({
    apiKey: "YOUR_API_KEY",
    apiSecret: "YOUR_API_SECRET",
    accessToken: "YOUR_ACCESS_TOKEN",
    accessTokenSecret: "YOUR_ACCESS_TOKEN_SECRET",
  });

  const client = new Client({ oauth1 });

  // Créer une publication
  const response = await client.posts.create({ text: "Hello world!" });
  console.log(`Publication créée : ${response.data?.id}`);
  ```
</CodeGroup>
