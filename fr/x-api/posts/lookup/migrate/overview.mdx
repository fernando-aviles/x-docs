<div id="comparing-x-apis-posts-lookup-endpoints">
  ## Comparaison des endpoints de consultation de Publications de X API
</div>

Les endpoints v2 de consultation de Publications remplacent les endpoints standard v1.1 [GET statuses/lookup](https://developer.x.com/en/docs/twitter-api/v1/tweets/post-and-engage/api-reference/get-statuses-lookup) et [GET statuses/show](https://developer.x.com/en/docs/twitter-api/v1/tweets/post-and-engage/api-reference/get-statuses-show-id). Ce guide s’adresse aux développeurs qui migrent de ces anciennes versions vers X API v2.

***

<div id="endpoint-comparison-table">
  ## Tableau comparatif des endpoints
</div>

| Description | Standard v1.1 | X API v2 |
|:-------------|:---------------|:----------|
| **Méthodes HTTP prises en charge** | `GET` | `GET` |
| **Domaine hôte** | `https://api.x.com` | `https://api.x.com` |
| **Chemin d’endpoint** | `/1.1/statuses/show.json`, `/1.1/statuses/lookup.json` | `/2/tweets` |
| **[Authentification](resources/fundamentals/authentication)** | OAuth 1.0a User Context | OAuth 1.0a User Context, OAuth 2.0 App-Only, OAuth 2.0 Authorization Code with PKCE |
| **[Format JSON](/fr/x-api/fundamentals/data-dictionary) de la Publication** | Format standard v1.1 | [Format X API v2](/fr/x-api/fundamentals/data-dictionary), déterminé par les paramètres `fields` et `expansions` (non rétrocompatible avec v1.1) |
| **Prend en charge la sélection de [champs](/fr/x-api/fundamentals/data-dictionary) spécifiques** |  | ✔ |
| **Prend en charge les champs d’[annotations](/fr/x-api/fundamentals/post-annotations)** |  | ✔ |
| **Prend en charge les nouveaux champs de [métriques](/fr/x-api/fundamentals/metrics)** |  | ✔ |
| **Prend en charge le champ `conversation_id`** |  | ✔ |
| **Fournit l’historique des modifications de la Publication** | ✔ | ✔ |
| **Nécessite des identifiants issus d’une [App développeur](/fr/resources/fundamentals/developer-apps) associée à un [Projet](resources/fundamentals/projects)** |  | ✔ |

***

<div id="standard-v11-compared-to-x-api-v2">
  ## v1.1 standard comparé à X API v2
</div>

Si vous avez utilisé les endpoints standard v1.1 GET statuses/show et GET statuses/lookup, ce guide vous aidera à comprendre les similitudes et les différences entre les endpoints de recherche de Publications de la version standard et de X API v2.

Vous pouvez également consulter notre [outil visuel de migration de format de données](/fr/x-api/migrate/data-format-migration), qui vous aide à voir rapidement les différences entre le [format de données X API v1.1](/fr/x-api/fundamentals/data-dictionary) et le [format X API v2](/fr/x-api/fundamentals/data-dictionary).

* **Similarités**
  * OAuth 1.0a User Context
  * Limites du nombre de Publications par requête
  * Prise en charge de l’historique des modifications de Publication et des métadonnées

* **Différences**
  * URL des endpoints
  * Exigences pour les Applications et les Projets
  * Format des données de la réponse
  * Paramètres de la requête

<div id="similarities">
  ### Points communs
</div>

<div id="oauth-10a-user-context-authentication-method">
  #### Méthode d’authentification OAuth 1.0a User Context
</div>

L’endpoint standard prend en charge [OAuth 1.0a User Context](/fr/resources/fundamentals/authentication), tandis que le nouvel endpoint X API v2 de recherche de Publications prend en charge à la fois OAuth 1.0a User Context et [OAuth 2.0 App-Only](/fr/resources/fundamentals/authentication). Par conséquent, si vous utilisiez auparavant l’un des endpoints standard v1.1 de recherche de Publications, vous pouvez continuer à utiliser la même méthode d’authentification si vous migrez vers la version de X API v2.

L’authentification App-Only est probablement la manière la plus simple de commencer. Pour savoir comment générer un App Access Token, consultez [ce guide OAuth 2.0 App-only](/fr/resources/fundamentals/authentication).

<div id="posts-per-request-limits">
  #### Limites de Publications par requête
</div>

Le point de terminaison v1.1 [GET statuses/lookup](https://developer.x.com/en/docs/twitter-api/v1/tweets/post-and-engage/api-reference/get-statuses-lookup) vous permet d’indiquer jusqu’à 100 Publications par requête. Cela s’applique également au point de terminaison GET /tweets. Pour spécifier un total de 100 Publications, utilisez le paramètre `ids` comme paramètre de requête avec une liste séparée par des virgules d’[ID de Publication](/fr/resources/fundamentals/x-ids).

**Prise en charge de l’historique des modifications et des métadonnées des Publications**

Les deux versions fournissent des métadonnées qui décrivent l’historique de toute modification. Consultez les Références de l’API de recherche de Publications et la [page de principes fondamentaux sur la modification des Publications](/fr/x-api/fundamentals/edit-posts) pour plus de détails.

<div id="differences">
  ### Principales différences
</div>

<div id="endpoint-urls">
  #### URL des endpoints
</div>

* **Endpoints standard v1.1 :**
  * `https://api.x.com/1.1/statuses/show`
  * `https://api.x.com/1.1/statuses/lookup`

* **Endpoint X API v2 :**
  * `https://api.x.com/2/tweets`
  * `https://api.x.com/2/tweets/:id`

<div id="app-and-project-requirements">
  #### Conditions requises pour les Apps et les Projets
</div>

Les endpoints X API v2 nécessitent des identifiants provenant d’une [App développeur](/fr/resources/fundamentals/developer-apps) associée à un [Projet](/fr/resources/fundamentals/developer-apps) pour l’authentification. Les endpoints X API v1.1 peuvent utiliser des identifiants provenant d’Apps ou d’Apps associées à une App.

<div id="response-data-format">
  #### Format des données de la réponse
</div>

Une différence significative entre les versions d&#39;endpoints standard v1.1 et X API v2 est la manière dont les champs sont sélectionnés dans la charge utile.

Pour les endpoints standard, de nombreux champs de réponse sont inclus par défaut, avec la possibilité d&#39;utiliser des paramètres pour spécifier des champs supplémentaires.

X API v2 ne fournit cependant que les champs `id` et `text` de la publication par défaut. Les champs et objets supplémentaires nécessitent l&#39;utilisation des paramètres [fields](/fr/x-api/fundamentals/fields) et [expansions](/fr/x-api/fundamentals/expansions). Les champs étendus sont renvoyés dans un objet `includes` au sein de la réponse, qui peut être mis en correspondance avec l&#39;objet publication principal en faisant correspondre les ID.

Pour plus d&#39;informations sur l&#39;utilisation des champs et des expansions, consultez le [guide sur l&#39;utilisation des champs et des expansions](/fr/x-api/fundamentals/data-dictionary). Un [guide de migration de format de données](/fr/x-api/fundamentals/fields) établit également la correspondance entre les champs standard v1.1 et les nouveaux champs v2.

De plus, X API v2 introduit de nouveaux modèles JSON pour les objets, y compris les objets publication et [user](/fr/x-api/fundamentals/fields) :

* Les endpoints standard renvoient des objets publication dans un tableau `statuses`, tandis que X API v2 utilise un tableau `data`.
* Les Tweets retweetés et cités (Quoted Tweets) dans X API v2 remplacent la terminologie « statuses ».
* Une nouvelle terminologie telle que `like` remplace des termes comme `favorites` et `favourites`.
* Les attributs sans valeur (par exemple, `null`) ne sont pas inclus dans les charges utiles de X API v2.

L&#39;objet publication dans X API v2 inclut de nouveaux champs tels que :

* `conversation_id`
* Deux nouveaux champs [annotations](/fr/x-api/fundamentals/post-annotations) (`context` et `entities`)
* De nouveaux champs [metrics](/fr/x-api/fundamentals/metrics)
* Le champ `reply_setting`, indiquant qui peut répondre à une publication donnée

<div id="request-parameters">
  #### Paramètres de requête
</div>

Les paramètres de requête standard de la v1.1 suivants ont des équivalents dans X API v2 :

| Standard | X API v2 |
|:----------|:----------|
| `id`     | `ids`    |

Certains paramètres standard de la v1.1 **ne sont pas** pris en charge dans X API v2 :

| Standard            | Comment                                                                                                                      |
|:---------------------|:------------------------------------------------------------------------------------------------------------------------------|
| `tweet_mode`        | Remplacé par la fonctionnalité des champs et des expansions.                                                                 |
| `trim_user`         | Remplacé par les champs et les expansions. Utilisez l’expansion `author_id` et `user.fields` pour les données utilisateur.   |
| `include_my_retweet`| Fournit l’ID de la Publication source pour les Publications retweetées par l’utilisateur authentifié.                        |
| `include_entities`  | Utilisez les champs et les expansions pour contrôler les entités dans le payload.                                            |
| `include_ext_alt_text` | Ajoute le champ `ext_alt_text` dans l’entité média si un texte alternatif est présent.                                     |
| `include_card_uri`  | Ajoute `card_uri` lorsqu’une carte publicitaire (ads card) est jointe.                                                       |
| `map`               | Retourne l’ID de la Publication et le message d’erreur pour les Publications non disponibles dans X API v2, contrairement aux champs mis à `null` dans la v1.1. |

<div id="curl-requests">
  ### Requêtes cURL
</div>

Les requêtes cURL suivantes présentent les endpoints standard de la v1.1 et leurs équivalents en v2. Remplacez `ACCESS_TOKEN` dans l’en-tête par le jeton d’accès de votre application. Pour les endpoints v2, le jeton doit appartenir à une [App développeur](/fr/resources/fundamentals/developer-apps/overview) au sein d’un [Projet](/fr/resources/fundamentals/developer-apps).

Les charges utiles de réponse de la v1.1 diffèrent de celles de la v2. Avec la v2, vous pouvez demander différents champs avec les paramètres [fields](/fr/x-api/fundamentals/fields) et [expansions](/fr/x-api/fundamentals/expansions).

**Points de terminaison standard v1.1 `GET statuses/lookup` et v2 `GET /tweets`**

```bash
curl --request GET \
  --url 'https://api.x.com/1.1/statuses/lookup.json?id=1460323737035677698%2C1460323743339741184' \
  --header 'Authorization: Bearer $ACCESS_TOKEN'
```

```
  curl --request GET \
  --url 'https://api.x.com/2/tweets?ids=1460323737035677698%2C1460323743339741184&tweet.fields=created_at&expansions=author_id&user.fields=created_at' \
  --header 'Authorization: Bearer $ACCESS_TOKEN'
```

**Points de terminaison standard de la v1.1 `GET statuses/show/:id` et de la v2 `GET /tweets/:id`**

```
curl --request GET \
  --url 'https://api.x.com/1.1/statuses/show.json?id=1460323737035677698' \
  --header 'Authorization: Bearer $ACCESS_TOKEN'
```

```
curl --request GET \
  --url 'https://api.x.com/2/tweets/1460323737035677698?tweet.fields=created_at&expansions=author_id&user.fields=created_at' \
  --header 'Authorization: Bearer $ACCESS_TOKEN'
```
