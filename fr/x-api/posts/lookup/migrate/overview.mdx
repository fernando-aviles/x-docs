<div id="comparing-x-apis-posts-lookup-endpoints">
  ## Comparaison des endpoints de recherche de Publications de X API
</div>

Les endpoints de recherche de Publications de X API v2 remplacent les endpoints standard v1.1 [GET statuses/lookup](https://developer.x.com/en/docs/twitter-api/v1/tweets/post-and-engage/api-reference/get-statuses-lookup) et [GET statuses/show](https://developer.x.com/en/docs/twitter-api/v1/tweets/post-and-engage/api-reference/get-statuses-show-id). Ce guide s’adresse aux développeurs qui migrent de ces anciens endpoints vers X API v2.

***

<div id="endpoint-comparison-table">
  ## Tableau comparatif des endpoints
</div>

| Description | Standard v1.1 | X API v2 |
|:-------------|:---------------|:----------|
| **Méthodes HTTP prises en charge** | `GET` | `GET` |
| **Domaine hôte** | `https://api.x.com` | `https://api.x.com` |
| **Chemin de l’endpoint** | `/1.1/statuses/show.json`, `/1.1/statuses/lookup.json` | `/2/tweets` |
| **[Authentification](resources/fundamentals/authentication)** | OAuth 1.0a User Context | OAuth 1.0a User Context, OAuth 2.0 App-Only, OAuth 2.0 Authorization Code with PKCE |
| **Format [JSON](/fr/x-api/fundamentals/data-dictionary) de la Publication** | Format standard v1.1 | [Format X API v2](/fr/x-api/fundamentals/data-dictionary), déterminé par les paramètres `fields` et `expansions` (non rétrocompatible avec v1.1) |
| **Permet de sélectionner des [champs](/fr/x-api/fundamentals/data-dictionary) spécifiques** |  | ✔ |
| **Prend en charge les champs [annotations](/fr/x-api/fundamentals/post-annotations)** |  | ✔ |
| **Prend en charge les nouveaux champs de [métriques](/fr/x-api/fundamentals/metrics)** |  | ✔ |
| **Prend en charge le champ `conversation_id`** |  | ✔ |
| **Fournit l’historique des modifications de la Publication** | ✔ | ✔ |
| **Requiert des identifiants provenant d’une [App développeur](/fr/resources/fundamentals/developer-apps) associée à un [Projet](resources/fundamentals/projects)** |  | ✔ |

<div id="standard-v11-compared-to-x-api-v2">
  ## Standard v1.1 comparé à X API v2
</div>

Si vous avez utilisé les endpoints standard v1.1 GET statuses/show et GET statuses/lookup, ce guide vous aidera à comprendre les similitudes et les différences entre les endpoints standard et X API v2 de récupération de Publications.

Vous serez peut-être également intéressé par notre [outil visuel de migration de format de données](/fr/x-api/migrate/data-format-migration), qui vous aide à voir rapidement les différences entre le [format de données X API v1.1](/fr/x-api/fundamentals/data-dictionary) et le [format X API v2](/fr/x-api/fundamentals/data-dictionary).

* **Similarités**
  * OAuth 1.0a User Context
  * Limites du nombre de Publications par requête
  * Prise en charge de l’historique des modifications d’une Publication et des métadonnées

* **Différences**
  * URL des endpoints
  * Exigences relatives aux Apps et aux Projets
  * Format des données de la réponse
  * Paramètres de requête

<div id="similarities">
  ### Similarités
</div>

<div id="oauth-10a-user-context-authentication-method">
  #### Méthode d’authentification OAuth 1.0a User Context
</div>

L’endpoint standard prend en charge [OAuth 1.0a User Context](/fr/resources/fundamentals/authentication), tandis que le nouvel endpoint de recherche de Publication de X API v2 prend en charge à la fois OAuth 1.0a User Context et [OAuth 2.0 App-Only](/fr/resources/fundamentals/authentication). Par conséquent, si vous utilisiez auparavant l’un des endpoints standard de recherche de Publication v1.1, vous pouvez continuer à utiliser la même méthode d’authentification si vous migrez vers la version X API v2.

L’authentification App-Only est probablement le moyen le plus simple pour débuter. Pour savoir comment générer un App Access Token, consultez [ce guide OAuth 2.0 App-Only](/fr/resources/fundamentals/authentication).

<div id="posts-per-request-limits">
  #### Limites de publications par requête
</div>

Le point de terminaison v1.1 [GET statuses/lookup](https://developer.x.com/en/docs/twitter-api/v1/tweets/post-and-engage/api-reference/get-statuses-lookup) vous permet de spécifier jusqu’à 100 publications par requête. Cela s’applique également au point de terminaison GET /tweets. Pour spécifier un total de 100 publications, utilisez le paramètre `ids` comme paramètre de requête avec une liste d’[identifiants de publication](/fr/resources/fundamentals/x-ids) séparés par des virgules.

**Prise en charge de l’historique des modifications des publications et des métadonnées**

Les deux versions fournissent des métadonnées qui décrivent l’historique des modifications. Consultez les Références de l’API de recherche de publications et la [page principale sur l’édition de publications](/fr/x-api/fundamentals/edit-posts) pour plus de détails.

<div id="differences">
  ### Différences
</div>

<div id="endpoint-urls">
  #### URL des endpoints
</div>

* **Endpoints standard v1.1 :**
  * `https://api.x.com/1.1/statuses/show`
  * `https://api.x.com/1.1/statuses/lookup`

* **Endpoint de X API v2 :**
  * `https://api.x.com/2/tweets`
  * `https://api.x.com/2/tweets/:id`

<div id="app-and-project-requirements">
  #### Conditions requises pour les Apps et les Projets
</div>

Les endpoints de X API v2 nécessitent, pour l’authentification, des identifiants provenant d’une [App développeur](/fr/resources/fundamentals/developer-apps) associée à un [Projet](/fr/resources/fundamentals/developer-apps). Les endpoints de X API v1.1 peuvent utiliser des identifiants issus d’Apps ou d’Apps associées à une App.

<div id="response-data-format">
  #### Format des données de réponse
</div>

Une différence significative entre les versions d’endpoints standard v1.1 et X API v2 est la façon dont les champs sont sélectionnés dans la charge utile.

Pour les endpoints standard, de nombreux champs de réponse sont inclus par défaut, avec la possibilité d’utiliser des paramètres pour spécifier des champs supplémentaires.

X API v2, en revanche, ne renvoie par défaut que les champs `id` et `text` de la Publication. Les champs et objets supplémentaires nécessitent l’utilisation des paramètres [fields](/fr/x-api/fundamentals/fields) et [expansions](/fr/x-api/fundamentals/expansions). Les champs étendus sont renvoyés dans un objet `includes` au sein de la réponse, qui peut être associé à l’objet Publication principal en faisant correspondre les ID.

Pour plus d’informations sur l’utilisation des champs et des expansions, consultez le [guide sur l’utilisation des champs et des expansions](/fr/x-api/fundamentals/data-dictionary). Un [guide de migration de format de données](/fr/x-api/fundamentals/fields) fait également correspondre les champs standard v1.1 aux nouveaux champs de la v2.

En outre, X API v2 introduit de nouvelles structures JSON pour les objets, y compris l’objet Publication et les objets [user](/fr/x-api/fundamentals/fields) :

* Les endpoints standard renvoient les objets Publication dans un tableau `statuses`, tandis que X API v2 utilise un tableau `data`.
* Les Tweets retweetés et cités (Retweeted et Quoted Tweets) dans X API v2 remplacent la terminologie « statuses ».
* Une nouvelle terminologie comme `like` remplace des termes tels que `favorites` et `favourites`.
* Les attributs sans valeur (par exemple, `null`) ne sont pas inclus dans les charges utiles de X API v2.

L’objet Publication dans X API v2 inclut de nouveaux champs tels que :

* `conversation_id`
* Deux nouveaux champs [annotations](/fr/x-api/fundamentals/post-annotations) (`context` et `entities`)
* De nouveaux champs [metrics](/fr/x-api/fundamentals/metrics)
* Le champ `reply_setting` indiquant qui peut répondre à une publication donnée

<div id="request-parameters">
  #### Paramètres de requête
</div>

Les paramètres de requête standard v1.1 suivants ont des équivalents dans X API v2 :

| Standard | X API v2 |
|:----------|:----------|
| `id`     | `ids`    |

Certains paramètres standard v1.1 ne sont **pas** pris en charge dans X API v2 :

| Standard            | Comment                                                                                                                      |
|:---------------------|:------------------------------------------------------------------------------------------------------------------------------|
| `tweet_mode`        | Remplacé par la fonctionnalité des champs et des expansions.                                                                 |
| `trim_user`         | Remplacé par l’utilisation des champs et des expansions. Utilisez l’expansion `author_id` et `user.fields` pour les données utilisateur. |
| `include_my_retweet`| Fournit l’ID de la Publication source pour les Publications retweetées par l’utilisateur authentifié.                        |
| `include_entities`  | Utilisez les champs et les expansions pour contrôler les entités dans la charge utile.                                       |
| `include_ext_alt_text` | Ajoute le champ `ext_alt_text` dans l’entité média si un texte alternatif est présent.                                    |
| `include_card_uri`  | Ajoute `card_uri` lorsqu’une carte publicitaire est jointe.                                                                   |
| `map`               | Retourne l’ID de la Publication et le message d’erreur pour les Publications indisponibles dans X API v2, plutôt que des champs mis à null dans v1.1. |

<div id="curl-requests">
  ### Requêtes cURL
</div>

Les requêtes cURL suivantes présentent les endpoints standard v1.1 et leurs équivalents v2. Remplacez `ACCESS_TOKEN` dans l’en-tête de requête par le jeton d’accès de votre application. Pour les endpoints v2, ce jeton doit appartenir à une [App développeur](/fr/resources/fundamentals/developer-apps/overview) au sein d’un [Projet](/fr/resources/fundamentals/developer-apps).

Les charges utiles des réponses de la v1.1 diffèrent de celles de la v2. Avec la v2, vous pouvez demander différents champs à l’aide des paramètres [fields](/fr/x-api/fundamentals/fields) et [expansions](/fr/x-api/fundamentals/expansions).

**Endpoints standard v1.1 `GET statuses/lookup` et v2 `GET /tweets`**

```bash
curl --request GET \
  --url 'https://api.x.com/1.1/statuses/lookup.json?id=1460323737035677698%2C1460323743339741184' \
  --header 'Authorization: Bearer $ACCESS_TOKEN'
```

```
  curl --request GET \
  --url 'https://api.x.com/2/tweets?ids=1460323737035677698%2C1460323743339741184&tweet.fields=created_at&expansions=author_id&user.fields=created_at' \
  --header 'Authorization: Bearer $ACCESS_TOKEN'
```

**Points de terminaison standard v1.1 `GET statuses/show/:id` et v2 `GET /tweets/:id`**

```
curl --request GET \
  --url 'https://api.x.com/1.1/statuses/show.json?id=1460323737035677698' \
  --header 'Authorization: Bearer $ACCESS_TOKEN'
```

```
curl --request GET \
  --url 'https://api.x.com/2/tweets/1460323737035677698?tweet.fields=created_at&expansions=author_id&user.fields=created_at' \
  --header 'Authorization: Bearer $ACCESS_TOKEN'
```
