Ce guide présente les concepts clés nécessaires pour intégrer les endpoints de consultation de publications à votre application.

***

<div id="authentication">
  ## Authentification
</div>

Tous les endpoints de X API v2 nécessitent une authentification. Choisissez la méthode qui correspond à votre cas d&#39;usage :

| Méthode | Idéale pour | Peut accéder aux métriques privées ? |
|:-------|:---------|:---------------------------|
| [OAuth 2.0 App-Only](/fr/resources/fundamentals/authentication#oauth-2-0) | Communication serveur à serveur, données publiques | Non |
| [OAuth 2.0 Authorization Code with PKCE](/fr/resources/fundamentals/authentication#oauth-2-0-authorization-code-flow-with-pkce-2) | Applications orientées utilisateur | Oui (pour les Publications de l&#39;utilisateur autorisé) |
| [OAuth 1.0a User Context](/fr/resources/fundamentals/authentication) | Anciennes intégrations | Oui (pour les Publications de l&#39;utilisateur autorisé) |

<div id="app-only-authentication">
  ### Authentification App-only
</div>

Pour les données publiques des Publications, utilisez un Bearer Token :

<CodeGroup dropdown>
  ```bash cURL
  curl "https://api.x.com/2/tweets/1234567890" \
    -H "Authorization: Bearer $BEARER_TOKEN"
  ```

  ```python Python SDK
  from xdk import Client

  client = Client(bearer_token="YOUR_BEARER_TOKEN")

  # Récupérer une Publication par ID
  response = client.posts.get("1234567890")
  print(response.data)
  ```

  ```javascript JavaScript SDK
  import { Client } from "@xdevplatform/xdk";

  const client = new Client({ bearerToken: "YOUR_BEARER_TOKEN" });

  const response = await client.posts.get("1234567890");
  console.log(response.data);
  ```
</CodeGroup>

<div id="user-context-authentication">
  ### Authentification dans le contexte utilisateur
</div>

Pour accéder aux métriques privées, authentifiez-vous pour le compte de l’auteur de la Publication :

<Warning>
  Les champs suivants nécessitent une authentification dans le contexte utilisateur :

  * `tweet.fields.non_public_metrics`
  * `tweet.fields.promoted_metrics`
  * `tweet.fields.organic_metrics`
  * `media.fields.non_public_metrics`
  * `media.fields.promoted_metrics`
  * `media.fields.organic_metrics`
</Warning>

<div id="fields-and-expansions">
  ## Champs et expansions
</div>

X API v2 renvoie par défaut un minimum de données. Utilisez les paramètres `fields` et `expansions` pour demander précisément ce dont vous avez besoin.

<div id="default-response">
  ### Réponse par défaut
</div>

```json
{
  "data": {
    "id": "1234567890",
    "text": "Hello world!",
    "edit_history_tweet_ids": ["1234567890"]
  }
}
```

<div id="available-fields">
  ### Champs disponibles
</div>

<Accordion title="tweet.fields">
  | Champ | Description |
  |:------|:------------|
  | `created_at` | Horodatage de création de la publication |
  | `author_id` | ID utilisateur de l’auteur |
  | `public_metrics` | Nombre de J’aime, de Retweets, de réponses et de citations |
  | `entities` | Hashtags, mentions, URL, cashtags |
  | `attachments` | Clés média, ID de sondage |
  | `conversation_id` | Identifiant du fil de discussion |
  | `context_annotations` | Classifications de sujets/entités |
  | `in_reply_to_user_id` | Utilisateur auquel on répond |
  | `lang` | Langue détectée |
  | `source` | Client utilisé pour publier |
  | `possibly_sensitive` | Indicateur de contenu sensible |
  | `reply_settings` | Qui peut répondre |
</Accordion>

<Accordion title="user.fields (requiert l’extension author_id)">
  | Champ | Description |
  |:------|:------------|
  | `username` | @handle (nom d’utilisateur) |
  | `name` | Nom d’affichage |
  | `profile_image_url` | URL de l’avatar |
  | `verified` | Statut de vérification |
  | `description` | Bio |
  | `public_metrics` | Nombre d’abonnés/abonnements |
  | `created_at` | Date de création du compte |
</Accordion>

<Accordion title="media.fields (requiert l’extension attachments.media_keys)">
  | Champ | Description |
  |:------|:------------|
  | `url` | URL du média |
  | `preview_image_url` | URL de la vignette |
  | `type` | photo, video, animated&#95;gif |
  | `duration_ms` | Durée de la vidéo |
  | `height`, `width` | Dimensions |
  | `alt_text` | Texte d’accessibilité |
</Accordion>

<div id="example-with-fields">
  ### Exemple avec des champs
</div>

<CodeGroup dropdown>
  ```bash cURL
  curl "https://api.x.com/2/tweets/1234567890?\
  tweet.fields=created_at,public_metrics,entities&\
  expansions=author_id,attachments.media_keys&\
  user.fields=username,verified&\
  media.fields=url,type" \
    -H "Authorization: Bearer $BEARER_TOKEN"
  ```

  ```python Python SDK
  from xdk import Client

  client = Client(bearer_token="YOUR_BEARER_TOKEN")

  # Récupérer une Publication avec des champs supplémentaires et des expansions
  response = client.posts.get(
      "1234567890",
      tweet_fields=["created_at", "public_metrics", "entities"],
      expansions=["author_id", "attachments.media_keys"],
      user_fields=["username", "verified"],
      media_fields=["url", "type"]
  )

  print(response.data)
  print(response.includes)  # Contient des objets utilisateur et média développés
  ```

  ```javascript JavaScript SDK
  import { Client } from "@xdevplatform/xdk";

  const client = new Client({ bearerToken: "YOUR_BEARER_TOKEN" });

  const response = await client.posts.get("1234567890", {
    tweetFields: ["created_at", "public_metrics", "entities"],
    expansions: ["author_id", "attachments.media_keys"],
    userFields: ["username", "verified"],
    mediaFields: ["url", "type"],
  });

  console.log(response.data);
  console.log(response.includes); // Contient des objets utilisateur et média développés
  ```
</CodeGroup>

<div id="post-edits">
  ## Modification des publications
</div>

Les publications peuvent être modifiées jusqu&#39;à 5 fois dans les 30 minutes qui suivent leur création.

<div id="how-it-works">
  ### Fonctionnement
</div>

* Chaque modification crée un nouvel identifiant de Publication
* `edit_history_tweet_ids` contient toutes les versions (de la plus ancienne à la plus récente)
* Cet endpoint renvoie toujours la version la plus récente

<div id="example-response">
  ### Exemple de réponse
</div>

```json
{
  "data": {
    "id": "1234567893",
    "text": "Hello world! (edited twice)",
    "edit_history_tweet_ids": [
      "1234567890",
      "1234567891",
      "1234567893"
    ]
  }
}
```

<Tip>
  Les Publications obtenues après l’expiration de leur délai de modification de 30 minutes représentent la version finale. Pour les cas d’utilisation en temps réel, gardez à l’esprit que les Publications récemment publiées peuvent encore être modifiées.
</Tip>

<div id="error-handling">
  ## Gestion des erreurs
</div>

<div id="common-errors">
  ### Erreurs courantes
</div>

| Statut | Erreur | Solution |
|:-------|:------|:---------|
| 400 | Requête invalide | Vérifiez le format des paramètres |
| 401 | Non autorisé | Vérifiez les informations d’authentification |
| 403 | Accès interdit | Vérifiez les autorisations de l’application |
| 404 | Introuvable | Publication supprimée ou inexistante |
| 429 | Trop de requêtes | Attendez et réessayez (voir les limites de taux) |

<div id="deleted-or-protected-posts">
  ### Publications supprimées ou protégées
</div>

Si une Publication est supprimée ou provient d’un compte protégé que vous ne suivez pas :

* La recherche d’une seule Publication renvoie `404`
* La recherche de plusieurs Publications exclut la Publication des résultats et renvoie un tableau `errors`

```json
{
  "data": [
    { "id": "1234567890", "text": "Available post" }
  ],
  "errors": [
    {
      "resource_id": "1234567891",
      "resource_type": "tweet",
      "title": "Not Found Error",
      "detail": "Could not find tweet with id: [1234567891]."
    }
  ]
}
```
