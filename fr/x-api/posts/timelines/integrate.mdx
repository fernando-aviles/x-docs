Ce guide présente les principaux concepts dont vous avez besoin pour intégrer les endpoints Timelines à votre application.

***

<div id="authentication">
  ## Authentification
</div>

<div id="endpoint-requirements">
  ### Conditions requises pour les endpoints
</div>

| Endpoint | Application uniquement | Contexte utilisateur |
|:---------|:---------|:-------------|
| Timeline des publications de l’utilisateur | ✓ | ✓ |
| Timeline des mentions de l’utilisateur | ✓ | ✓ |
| Timeline d’accueil | — | ✓ (obligatoire) |

### Métriques privées

Pour accéder aux métriques privées, vous devez vous authentifier pour le compte de l’auteur de la Publication :

<Warning>
  Ces champs nécessitent une authentification dans un contexte utilisateur :

  * `tweet.fields.non_public_metrics`
  * `tweet.fields.promoted_metrics`
  * `tweet.fields.organic_metrics`
  * `media.fields.non_public_metrics`
  * `media.fields.promoted_metrics`
  * `media.fields.organic_metrics`
</Warning>

***

<div id="fields-and-expansions">
  ## Champs et expansions
</div>

Par défaut, les réponses incluent uniquement `id`, `text` et `edit_history_tweet_ids`. Pour obtenir des données supplémentaires :

<div id="example-request">
  ### Exemple de requête
</div>

<CodeGroup dropdown>
  ```bash cURL
  curl "https://api.x.com/2/users/123/tweets?\
  tweet.fields=created_at,public_metrics,author_id&\
  expansions=author_id,attachments.media_keys&\
  user.fields=username,verified&\
  media.fields=url,type" \
    -H "Authorization: Bearer $BEARER_TOKEN"
  ```

  ```python Python SDK
  from xdk import Client

  client = Client(bearer_token="YOUR_BEARER_TOKEN")

  # Récupérer la timeline des publications de l'utilisateur
  for page in client.posts.get_user_posts(
      user_id="123",
      tweet_fields=["created_at", "public_metrics", "author_id"],
      expansions=["author_id", "attachments.media_keys"],
      user_fields=["username", "verified"],
      media_fields=["url", "type"],
      max_results=100
  ):
      for post in page.data:
          print(f"{post.text} - {post.public_metrics}")
  ```

  ```javascript JavaScript SDK
  import { Client } from "@xdevplatform/xdk";

  const client = new Client({ bearerToken: "YOUR_BEARER_TOKEN" });

  // Récupérer la timeline des publications de l'utilisateur avec pagination
  const paginator = client.posts.getUserPosts("123", {
    tweetFields: ["created_at", "public_metrics", "author_id"],
    expansions: ["author_id", "attachments.media_keys"],
    userFields: ["username", "verified"],
    mediaFields: ["url", "type"],
    maxResults: 100,
  });

  for await (const page of paginator) {
    page.data?.forEach((post) => {
      console.log(`${post.text} - ${JSON.stringify(post.public_metrics)}`);
    });
  }
  ```
</CodeGroup>

<div id="key-fields">
  ### Champs clés
</div>

| Champ | Description |
|:------|:------------|
| `created_at` | Horodatage de création de la publication |
| `public_metrics` | Nombre d’engagements |
| `conversation_id` | Identifiant de conversation |
| `context_annotations` | Classifications de sujets |
| `entities` | Hashtags, mentions et URL |

<div id="pagination">
  ## Pagination
</div>

Les fils renvoient jusqu’à 100 Publications par requête. Utilisez la pagination pour des ensembles de résultats plus importants.

<div id="how-it-works">
  ### Fonctionnement
</div>

1. Envoyez une première requête avec `max_results`
2. Récupérez `next_token` à partir de l’objet `meta`
3. Incluez `pagination_token` dans la requête suivante
4. Répétez jusqu’à ce qu’aucun `next_token` ne soit renvoyé

<div id="example">
  ### Exemple
</div>

<CodeGroup dropdown>
  ```bash cURL
  # Première requête
  curl "https://api.x.com/2/users/123/tweets?max_results=100" \
    -H "Authorization: Bearer $BEARER_TOKEN"

  # Requête suivante avec jeton de pagination
  curl "https://api.x.com/2/users/123/tweets?max_results=100&pagination_token=NEXT_TOKEN" \
    -H "Authorization: Bearer $BEARER_TOKEN"
  ```

  ```python Python SDK
  from xdk import Client

  client = Client(bearer_token="YOUR_BEARER_TOKEN")

  # Le SDK gère automatiquement la pagination
  all_posts = []

  for page in client.posts.get_user_posts(user_id="123", max_results=100):
      if page.data:
          all_posts.extend(page.data)

  print(f"{len(all_posts)} publications trouvées")
  ```

  ```javascript JavaScript SDK
  import { Client } from "@xdevplatform/xdk";

  const client = new Client({ bearerToken: "YOUR_BEARER_TOKEN" });

  async function getAllTimelinePosts(userId) {
    const allPosts = [];

    // Le SDK gère automatiquement la pagination avec une itération asynchrone
    const paginator = client.posts.getUserPosts(userId, { maxResults: 100 });

    for await (const page of paginator) {
      if (page.data) {
        allPosts.push(...page.data);
      }
    }

    return allPosts;
  }

  // Utilisation
  const posts = await getAllTimelinePosts("123");
  console.log(`Nombre de publications trouvées : ${posts.length}`);
  ```
</CodeGroup>

<div id="filtering-results">
  ## Filtrer les résultats
</div>

<div id="time-based-filtering">
  ### Filtrage temporel
</div>

| Paramètre | Description |
|:----------|:------------|
| `start_time` | Horodatage de la Publication la plus ancienne (ISO 8601) |
| `end_time` | Horodatage de la Publication la plus récente (ISO 8601) |
| `since_id` | Renvoie les Publications postérieures à cet ID |
| `until_id` | Renvoie les Publications antérieures à cet ID |

<div id="exclude-parameter">
  ### Paramètre d’exclusion
</div>

Supprimez certains types de Publications des résultats :

<CodeGroup dropdown>
  ```bash cURL
  curl "https://api.x.com/2/users/123/tweets?exclude=retweets,replies" \
    -H "Authorization: Bearer $BEARER_TOKEN"
  ```

  ```python Python SDK
  from xdk import Client

  client = Client(bearer_token="YOUR_BEARER_TOKEN")

  # Exclure les retweets et les réponses
  for page in client.posts.get_user_posts(
      user_id="123",
      exclude=["retweets", "replies"]
  ):
      for post in page.data:
          print(post.text)
  ```

  ```javascript JavaScript SDK
  import { Client } from "@xdevplatform/xdk";

  const client = new Client({ bearerToken: "YOUR_BEARER_TOKEN" });

  // Exclure les retweets et les réponses
  const paginator = client.posts.getUserPosts("123", {
    exclude: ["retweets", "replies"],
  });

  for await (const page of paginator) {
    page.data?.forEach((post) => console.log(post.text));
  }
  ```
</CodeGroup>

| Valeur | Effet |
|:------|:-------|
| `retweets` | Exclure les retweets |
| `replies` | Exclure les réponses |

<div id="volume-limits">
  ## Limites de volume
</div>

Chaque timeline a des limites maximales de récupération :

| Endpoint | Nombre maximal de publications |
|:---------|:------------------------------|
| Timeline des publications de l’utilisateur | 3 200 les plus récentes |
| Publications de l’utilisateur (exclude=replies) | 800 les plus récentes |
| Timeline des mentions de l’utilisateur | 800 les plus récentes |
| Timeline d’accueil | 3 200 ou 7 jours |

<Note>
  Les demandes de publications au-delà de ces limites renvoient une réponse réussie sans data.
</Note>

<div id="post-edits">
  ## Modifications de publications
</div>

Les publications peuvent être modifiées jusqu&#39;à 5 fois sur une période de 30 minutes. Les endpoints de timeline renvoient toujours la version la plus récente.

<div id="considerations">
  ### Considérations
</div>

* Les publications âgées de plus de 30 minutes correspondent à leur version finale
* Les cas d’utilisation en quasi temps réel doivent tenir compte d’éventuelles modifications
* Utilisez la recherche de publications pour vérifier l’état final si nécessaire

<div id="post-metrics">
  ## Métriques des publications
</div>

<div id="public-metrics">
  ### Métriques publiques
</div>

Disponibles pour toutes les Publications avec une authentification de type App-only ou User context :

```json
{
  "public_metrics": {
    "retweet_count": 156,
    "reply_count": 23,
    "like_count": 892,
    "quote_count": 12
  }
}
```

<div id="private-metrics">
  ### Statistiques privées
</div>

Nécessite une authentification en contexte utilisateur de la part de l&#39;auteur de la Publication :

* Uniquement disponible pour les Publications des 30 derniers jours
* Uniquement renvoyé pour les Publications créées par l&#39;utilisateur authentifié
* Génère une erreur pour les Publications d&#39;autres utilisateurs

***

<div id="edge-cases">
  ## Cas particuliers
</div>

<Accordion title="Métriques non publiques et pagination">
  Lorsque vous demandez des métriques non publiques pour des Publications âgées de plus de 30 jours, vous pouvez recevoir un `next_token` avec `result_count: 0`. Pour éviter cela :

  * Limitez les requêtes aux 30 derniers jours
  * Utilisez un `max_results` d’au moins 10
</Accordion>

<Accordion title="Métriques promues pour des Publications non promues">
  Lorsque vous demandez des métriques promues pour des Publications qui n’ont pas été promues, la Réponse renvoyée est vide. Il s’agit d’un problème connu.
</Accordion>

<Accordion title="Texte de Retweet tronqué">
  Pour les Retweets dont le texte compte plus de 140 caractères, le champ `text` est tronqué. Utilisez l’expansion `referenced_tweets.id` pour obtenir le texte complet.
</Accordion>
