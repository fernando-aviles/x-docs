<div id="standard-v11-timelines-to-x-api-v2-timelines">
  ## Timelines standard v1.1 vers timelines X API v2
</div>

Si vous avez travaillé avec les endpoints de timelines v1.1 (statuses/user&#95;timeline et statuses/mentions&#95;timeline), l’objectif de ce guide est de vous aider à comprendre les similitudes et les différences entre les endpoints de timelines standard et ceux de X API v2 afin que vous puissiez migrer votre intégration actuelle vers la nouvelle version.

* **Similarités :**
  * Authentification :
    * OAuth 1.0a User Context (timeline d’accueil antichronologique, timeline des Publications d’un utilisateur et timeline des mentions d’un utilisateur)
    * OAuth 2.0 App-Only (timeline des Publications d’un utilisateur)
  * Limite d’accès historique : la timeline utilisateur (timeline des Publications d’un utilisateur) donne accès aux 3 200 Publications les plus récentes ; la timeline des mentions (timeline des mentions d’un utilisateur) donne accès aux 800 mentions les plus récentes.
  * Prise en charge de l’historique de modification des Publications et des métadonnées
  * Limites de débit (timeline des Publications d’un utilisateur)
  * Rafraîchissement par interrogation (polling) : possibilité de récupérer de nouveaux résultats depuis le since&#95;id
  * Parcours des timelines par identifiants de Publication
  * Spécifications des résultats :
    * Ordre des résultats : résultats renvoyés par ordre antichronologique
    * Possibilité d’exclure les réponses (timeline des Publications d’un utilisateur uniquement)
    * Possibilité d’exclure les Retweets (timeline des Publications d’un utilisateur uniquement)
* **Différences**
  * Nouvelle fonctionnalité d’authentification :
    * OAuth 2.0 App-Only (timeline des mentions d’un utilisateur)
    * OAuth 2.0 Authorization Code Flow with PKCE (timeline d’accueil antichronologique, timeline des Publications d’un utilisateur et timeline des mentions d’un utilisateur)
  * Exigences d’accès : exigences relatives aux Apps et Projets X API v2
  * Limites de débit (timeline des mentions d’un utilisateur et timeline d’accueil antichronologique)
  * Méthode de pagination supplémentaire
    * max&#95;results (count) différent par réponse
  * Format des données de la réponse
  * Paramètres de requête
    * Format des données personnalisé en fonction des paramètres de requête, y compris les champs v2 et expansions
    * Données supplémentaires disponibles : métriques, annotations de Publication, sondages

<div id="similarities">
  ### Similarités
</div>

**Authentification**

Les points de terminaison v1.1 statuses/user&#95;timeline et X API v2 user Post timeline prennent tous deux en charge [OAuth 1.0a User Context](/fr/resources/fundamentals/authentication) et [OAuth 2.0 App-Only](/fr/resources/fundamentals/authentication#bearer-token-also-known-as-app-only). Par conséquent, vous pouvez continuer à utiliser la même méthode d’authentification et les mêmes jetons d’autorisation si vous migrez vers la version X API v2.

**Accès à l’historique**

Les points de terminaison v1.1 statuses/user&#95;timeline et X API v2 user Post timeline renvoient tous deux les 3 200 Publications les plus récentes, y compris les Retweets.

Les points de terminaison v1.1 statuses/mentions&#95;timeline et X API v2 user mention timeline peuvent renvoyer les 800 Publications les plus récentes.

**Prise en charge de l’historique de modification des Publications et des métadonnées**

Les deux versions fournissent des métadonnées décrivant tout historique de modification. Consultez les [Références de l’API filtered stream](/fr/x-api/posts/filtered-stream#api-reference-index) et la page [Notions de base sur la modification des Publications](/fr/x-api/fundamentals/edit-posts) pour plus de détails.

**Limites de débit**

|     |     |
| :--- | :--- |
| **Standard v1.1** | **X API v2** |
| user&#95;timeline :<br /><br />900 requêtes par fenêtre de 15 minutes avec OAuth 1.0a User Context<br /><br />1 500 requêtes par fenêtre de 15 minutes avec OAuth 2.0 App-Only | User Posts timeline :<br /><br />900 requêtes par fenêtre de 15 minutes avec OAuth 1.0a User Context<br /><br />1 500 requêtes par fenêtre de 15 minutes avec OAuth 2.0 App-Only |

**Actualisation par polling avec since&#95;id**

Les deux versions permettent d’interroger périodiquement les résultats récents à l’aide de since&#95;id.

**Parcourir les chronologies par ID de Publication**

Les deux points de terminaison peuvent parcourir les chronologies à l’aide de « horodatages » d’ID de Publication, en fonction de la manière dont les ID de Publication sont construits. La fonctionnalité est globalement identique, à l’exception de ce qui suit :

|     |     |
| :--- | :--- |
| **Standard timelines v1.1** | **timelines v2** |
| since&#95;id (exclusif)<br /><br />max&#95;id (inclusif) | since&#95;id (exclusif)<br /><br />until&#95;id (également exclusif, contrairement à max&#95;id qui était inclusif) |

**Paramètres de filtrage de la Réponse**

|     |     |
| :--- | :--- |
| **Standard timelines v1.1** | **timelines v2** |
| Paramètres de filtrage de la Réponse :<br /><br />* include&#95;rts<br />* exclude&#95;replies | Paramètres de filtrage de la Réponse :<br /><br />* exclude=retweets,replies |
| Exemple<br /><br />https://api.x.com/1.1/statuses/user&#95;timeline.json?user&#95;id=2244994945&amp;include&#95;rts=0&amp;&amp;exclude&#95;replies=1 | Exemple :<br /><br />https://api.x.com/2/users/2244994945/tweets?max&#95;results=100&amp;exclude=retweets,replies |
| Notes :<br /><br />Pour user&#95;timeline :<br /><br />* L’utilisation de include&#95;rts=0 ne modifie pas la limite historique possible des 3 200 Publications les plus récentes | Notes :<br /><br />Pour user Posts timeline :<br /><br />* L’utilisation de exclude=retweets ne modifie pas la limite historique possible des 3 200 Publications les plus récentes<br />* L’utilisation de exclude=replies réduit la limite historique possible aux 800 réponses les plus récentes |

<div id="differences">
  ### Différences
</div>

**Authentification**

**L’endpoint v1.1 statuses/mentions&#95;timeline ne prend en charge que [OAuth 1.0a User Context](https://developer-staging.x.com/resources/fundamentals/authentication). L’endpoint X API v2 user mention timeline prend en charge [OAuth 1.0a User Context](/fr/resources/fundamentals/authentication), [OAuth 2.0 App-Only](/fr/resources/fundamentals/authentication#bearer-token-also-known-as-app-only) et [OAuth 2.0 Authorization Code with PKCE](/fr/resources/fundamentals/authenticationoauth-2-0/authorization-code "Cette méthode permet à une App autorisée d’agir au nom de l’utilisateur, en tant qu’utilisateur. Elle est généralement utilisée pour accéder à ou publier des informations publiques pour un utilisateur spécifique, et elle est utile lorsque votre App doit connaître la relation entre un utilisateur et ce que cet endpoint renvoie. Cliquez pour en savoir plus sur l’authentification avec OAuth 2.0 Authorization Code with PKCE.") **

Si vous souhaitez profiter de la possibilité d’accéder à des métriques privées ou sponsorisées à l’aide de l’endpoint X API v2 user Post timeline, vous devrez utiliser OAuth 1.0a User Context ou OAuth 2.0 Authorization Code with PKCE, et transmettre les jetons d’accès utilisateur associés à l’utilisateur qui a publié la Publication pour laquelle vous souhaitez accéder aux métriques.

**URL des endpoints**

Notez que les endpoints X API v2 timelines nécessitent un paramètre de chemin :id pour l’id utilisateur.

* Endpoints v1.1 standard :
  * https://api.x.com/1.1/statuses/home&#95;timeline
  * https://api.x.com/1.1/statuses/user&#95;timeline
  * https://api.x.com/1.1/statuses/mention&#95;timeline
* Endpoint X API v2 :
  * https://api.x.com/2/users/:id/timelines/reverse&#95;chronological
  * https://api.x.com/2/users/:id/tweets
  * https://api.x.com/2/users/:id/mentions

**Exigences relatives aux Apps et aux Projets**

Les endpoints X API v2 exigent que vous utilisiez des identifiants provenant d’une [App développeur](/fr/resources/fundamentals/developer-apps) associée à un [Projet](/fr/resources/fundamentals/developer-apps) pour authentifier vos requêtes. Tous les endpoints X API v1.1 peuvent utiliser des identifiants provenant d’Apps ou d’Apps associées à un Projet.

**Limites de débit**

|     |     |
| :--- | :--- |
| **mentions&#95;timeline :**<br /><br />75 requêtes par tranche de 15 minutes avec OAuth 1.0a User Context | **user mention timeline: **<br /><br />180 requêtes par fenêtre de 15 minutes avec OAuth 1.0a User Context  <br />450 requêtes par fenêtre de 15 minutes avec OAuth 2.0 Bearer Token |
| **home&#95;timelime :**<br /><br />15 requêtes par 15 minutes  <br /><br />Jusqu’à 800 Publications peuvent être obtenues sur la home timeline | **reverse chronological home timeline :**<br /><br />180 requêtes par 15 minutes<br /><br />Vous pouvez renvoyer chaque Publication créée sur une timeline au cours des 7 derniers jours ainsi que les 800 plus récentes, quelle que soit leur date de création. |

**Paramètres de requête**

|     |     |
| :--- | :--- |
| **Standard timelines v1.1** | **timelines v2** |
| Obligatoire : user&#95;id ou screen&#95;name | Obligatoire : l’ID utilisateur spécifique est spécifié dans le paramètre de chemin |
| Facultatif :<br /><br />count - définit le nombre maximal de résultats renvoyés par requête<br /><br />exclude&#95;replies - supprime les réponses des résultats<br /><br />Include&#95;rts - lorsqu’il est défini sur 0, supprime les Retweets des résultats<br /><br />trim&#95;user - supprime des résultats les objets utilisateur réhydratés<br /><br />tweet&#95;mode - définit le format de données renvoyé pour les résultats, à définir sur extended pour les Publications de plus de 140 caractères<br /><br />since&#95;id - définit l’ID de Publication le plus ancien dans le résultat (exclusif)<br /><br />max&#95;id - définit l’ID de Publication le plus récent dans le résultat (inclusif) | Facultatif :<br /><br />max&#95;results - définit le nombre maximal de résultats renvoyés par requête<br /><br />exclude=retweets,replies - supprime les Retweets ou les réponses des résultats<br /><br />tweet.fields - définit les champs de l’objet Publication à renvoyer<br /><br />user.fields - définit les champs de l’objet utilisateur à renvoyer<br /><br />place.fields - définit les champs de l’objet place à renvoyer<br /><br />media.fields - définit les champs de l’objet media à renvoyer<br /><br />poll.fields - définit les champs de l’objet poll à renvoyer<br /><br />expansions - définit les champs étendus et les data à renvoyer<br /><br />start&#95;time - définit la date/heure created&#95;at la plus ancienne pour les résultats<br /><br />end&#95;time - définit la date/heure created&#95;at la plus récente pour les résultats<br /><br />since&#95;id - définit l’ID de Publication le plus ancien pour les résultats (exclusif)<br /><br />until&#95;id - définit l’ID de Publication le plus récent dans le résultat (exclusif) |

**Format de données de la Réponse**

|     |     |
| :--- | :--- |
| **Standard search v1.1** | **Search Posts v2** |
| [<br />    tweet object,<br />    tweet object<br />  ] | <br />  &quot;data&quot;: [id,text,id,text],<br />  &quot;meta&quot;: <br />    &quot;oldest&#95;id&quot;: &quot;1337085692623646724&quot;,<br />    &quot;newest&#95;id&quot;: &quot;1334183616172019713&quot;,<br />    &quot;previous&#95;token&quot;: &quot;77qpymm88g5h9vqkluldpw91lr0qzfz1sqydh841iz48k&quot;,<br />    &quot;result&#95;count&quot;: 10,<br />    &quot;next&#95;token&quot;: &quot;7140dibdnow9c7btw3w29gqolns6a1ipl3kzeae41vsxk&quot;<br />  <br /> |

**Format JSON X API v2**

X API v2 introduit de nouveaux modèles JSON pour les objets renvoyés par les API, y compris les objets [Post](/fr/x-api/fundamentals/data-dictionary#tweet) et [user](/fr/x-api/fundamentals/data-dictionary#user). Vous pouvez en savoir plus sur le format X API v2, ainsi que sur la façon d’utiliser les champs et les expansions en consultant notre [guide](/fr/x-api/fundamentals/data-dictionary#how-to-use-fields-and-expansions), puis en parcourant notre [dictionnaire de données](/fr/x-api/fundamentals/data-dictionary) plus complet.

* Au niveau racine du JSON, les endpoints standard renvoient les objets Publication dans un tableau statuses, tandis que X API v2 renvoie un tableau data.
* Au lieu de faire référence à des &quot;statuses&quot; Retweeted et Quoted, le JSON X API v2 fait référence à des Tweets Retweeted et Quoted. De nombreux champs hérités et obsolètes, tels que contributors et user.translator&#95;type, sont supprimés.
* Au lieu d’utiliser favorites (dans l’objet Publication) et favorites (dans l’objet user), X API v2 utilise le terme like.
* X adopte la convention selon laquelle les valeurs JSON sans valeur (par exemple, null) ne sont pas incluses dans la charge utile. Les attributs de Publication et de user ne sont inclus que s’ils ont une valeur non nulle.

L’une des plus grandes différences entre les versions d’endpoints standard v1.1 et X API v2 concerne la façon dont vous sélectionnez les champs renvoyés dans votre charge utile. Pour les endpoints standard, il existe plusieurs paramètres que vous pouvez utiliser pour identifier quels champs ou ensembles de champs seront renvoyés dans la charge utile, tandis que la version X API v2 simplifie ces différents paramètres en [champs](/fr/x-api/fundamentals/fields) et [expansions](/fr/x-api/fundamentals/expansions).

* fields : les endpoints X API v2 vous permettent de sélectionner quels champs sont fournis dans votre payload. Par exemple, les objets Publication, user, Media, Place et Poll disposent tous d’une liste de champs qui peuvent être renvoyés (ou non).

* expansions : permet d’inclure les objets complémentaires référencés dans les payloads JSON de Publication. Par exemple, tous les Retweets et les réponses font référence à d’autres Publications. En définissant expansions=referenced&#95;tweets.id, ces autres objets Publication sont inclus conformément au paramètre tweet.fields. D’autres objets comme les users, polls et media peuvent être inclus.

* conversation&#95;id

* Deux nouveaux champs [annotations](/fr/x-api/fundamentals/post-annotations), dont context et entities

* Plusieurs nouveaux champs [metrics](/fr/x-api/fundamentals/metrics)

Nous avons élaboré un [guide de migration du format de données](/fr/x-api/migrate/data-format-migration#migrating-from-standard-v1-1s-data-format-to-v2) qui peut vous aider à faire correspondre les champs standard de la v1.1 aux champs de la v2 plus récente. Ce guide vous fournira également les paramètres d’expansion et de champ spécifiques que vous devrez inclure avec votre requête v2 pour renvoyer des champs précis.

<div id="user-posts-timeline-v2">
  ### Chronologie des publications de l’utilisateur (v2)
</div>

<CodeGroup dropdown>
  ```bash cURL
  curl "https://api.x.com/2/users/2244994945/tweets?max_results=100&tweet.fields=created_at,public_metrics&exclude=retweets,replies" \
    -H "Authorization: Bearer $BEARER_TOKEN"
  ```

  ```python Python SDK
  from xdk import Client

  client = Client(bearer_token="YOUR_BEARER_TOKEN")

  # Obtenir la chronologie des publications de l’utilisateur
  for page in client.posts.get_user_posts(
      "2244994945",
      tweet_fields=["created_at", "public_metrics"],
      exclude=["retweets", "replies"],
      max_results=100
  ):
      for post in page.data:
          print(f"{post.created_at}: {post.text[:50]}...")
  ```

  ```javascript JavaScript SDK
  import { Client } from "@xdevplatform/xdk";

  const client = new Client({ bearerToken: "YOUR_BEARER_TOKEN" });

  // Obtenir la chronologie des publications de l’utilisateur
  const paginator = client.posts.getUserPosts("2244994945", {
    tweetFields: ["created_at", "public_metrics"],
    exclude: ["retweets", "replies"],
    maxResults: 100,
  });

  for await (const page of paginator) {
    page.data?.forEach((post) => {
      console.log(`${post.created_at}: ${post.text?.slice(0, 50)}...`);
    });
  }
  ```
</CodeGroup>

<div id="user-mentions-timeline-v2">
  ### Fil des mentions d’un utilisateur (v2)
</div>

<CodeGroup dropdown>
  ```bash cURL
  curl "https://api.x.com/2/users/2244994945/mentions?max_results=100&tweet.fields=created_at,author_id" \
    -H "Authorization: Bearer $BEARER_TOKEN"
  ```

  ```python Python SDK
  from xdk import Client

  client = Client(bearer_token="YOUR_BEARER_TOKEN")

  # Récupérer les mentions de l'utilisateur
  for page in client.posts.get_user_mentions(
      "2244994945",
      tweet_fields=["created_at", "author_id"],
      max_results=100
  ):
      for post in page.data:
          print(f"Mentionné par {post.author_id} : {post.text[:50]}...")
  ```

  ```javascript JavaScript SDK
  import { Client } from "@xdevplatform/xdk";

  const client = new Client({ bearerToken: "YOUR_BEARER_TOKEN" });

  // Récupérer les mentions de l'utilisateur
  const paginator = client.posts.getUserMentions("2244994945", {
    tweetFields: ["created_at", "author_id"],
    maxResults: 100,
  });

  for await (const page of paginator) {
    page.data?.forEach((post) => {
      console.log(`Mentionné par ${post.author_id} : ${post.text?.slice(0, 50)}...`);
    });
  }
  ```
