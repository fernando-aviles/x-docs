<div id="standard-v11-timelines-to-x-api-v2-timelines">
  ## Chronologies standard v1.1 vers chronologies X API v2
</div>

Si vous avez travaillé avec les endpoints de chronologies v1.1 (statuses/user&#95;timeline et statuses/mentions&#95;timeline), l’objectif de ce guide est de vous aider à comprendre les similitudes et les différences entre les endpoints de chronologies standard et ceux de X API v2, afin que vous puissiez migrer votre intégration actuelle vers la nouvelle version.

* **Similitudes :**
  * Authentification :
    * OAuth 1.0a User Context (chronologie d’accueil antéchronologique, chronologie des Publications d’utilisateur et chronologie des mentions d’utilisateur)
    * OAuth 2.0 App-Only (chronologie des Publications d’utilisateur)
  * Limite d’accès historique : la chronologie d’utilisateur (chronologie des Publications d’utilisateur) donne accès aux 3 200 Publications les plus récentes ; la chronologie des mentions (chronologie des mentions d’utilisateur) donne accès aux 800 mentions les plus récentes.
  * Prise en charge de l’historique des modifications des Publications et des métadonnées
  * Limites de débit (chronologie des Publications d’utilisateur)
  * Actualisation par polling : possibilité de récupérer de nouveaux résultats à partir de since&#95;id
  * Parcours des chronologies par identifiants de Publication
  * Spécifications des résultats :
    * Ordre des résultats : résultats renvoyés dans l’ordre antéchronologique
    * Possibilité d’exclure les réponses (chronologie des Publications d’utilisateur uniquement)
    * Possibilité d’exclure les Retweets (chronologie des Publications d’utilisateur uniquement)
* **Différences**
  * Nouvelle fonctionnalité d’authentification :
    * OAuth 2.0 App-Only (chronologie des mentions d’utilisateur)
    * OAuth 2.0 Authorization Code Flow with PKCE (chronologie d’accueil antéchronologique, chronologie des Publications d’utilisateur et chronologie des mentions d’utilisateur)
  * Conditions d’accès : exigences relatives aux Apps et Projets X API v2
  * Limites de débit (chronologie des mentions d’utilisateur et chronologie d’accueil antéchronologique)
  * Méthode de pagination supplémentaire
    * max&#95;results (count) différent par réponse
  * Format des données de la réponse
  * Paramètres de requête
    * Format de données personnalisé en fonction des paramètres de requête, y compris les champs v2 et les expansions
    * Données supplémentaires disponibles : métriques, annotations de Publication, sondages

<div id="similarities">
  ### Similarités
</div>

**Authentification**

Les endpoints v1.1 `statuses/user_timeline` et l’endpoint X API v2 de chronologie des Publications d’un utilisateur prennent en charge à la fois [OAuth 1.0a User Context](/fr/resources/fundamentals/authentication) et [OAuth 2.0 App-Only](/fr/resources/fundamentals/authentication#bearer-token-also-known-as-app-only). Par conséquent, vous pouvez continuer à utiliser la même méthode d’authentification et les mêmes jetons d’autorisation si vous migrez vers la version X API v2.

**Accès à l’historique**

Les endpoints v1.1 `statuses/user_timeline` et X API v2 de chronologie des Publications d’un utilisateur renvoient tous deux les 3 200 Publications les plus récentes, y compris les Retweets.

Les endpoints v1.1 `statuses/mentions_timeline` et X API v2 de chronologie des mentions d’un utilisateur peuvent renvoyer les 800 Publications les plus récentes.

**Prise en charge de l’historique de modification des Publications et des métadonnées**

Les deux versions fournissent des métadonnées décrivant tout historique de modification. Consultez les [Références de l’API de flux filtré](/fr/x-api/posts/filtered-stream#api-reference-index) et la page des [principes de base sur la modification des Publications](/fr/x-api/fundamentals/edit-posts) pour plus de détails.

**Limites de débit**

|     |     |
| :--- | :--- |
| **Standard v1.1** | **X API v2** |
| user&#95;timeline :<br /><br />900 requêtes par 15 min avec OAuth 1.0a User Context<br /><br />1500 requêtes par 15 min avec OAuth 2.0 App-Only | Chronologie des Publications d’utilisateur :<br /><br />900 requêtes par fenêtre de 15 minutes avec OAuth 1.0a User Context<br /><br />1500 requêtes par fenêtre de 15 minutes avec OAuth 2.0 App-Only |

**Actualisation par interrogation avec since&#95;id**

Les deux versions permettent d’obtenir les résultats les plus récents à l’aide de `since_id`.

**Parcours des chronologies par ID de Publication**

Les deux endpoints peuvent parcourir les chronologies en utilisant les « horodatages » d’ID de Publication, en fonction de la façon dont les ID de Publication sont construits. La fonctionnalité est globalement la même, à l’exception de ce qui suit :

|     |     |
| :--- | :--- |
| **Chronologies standard v1.1** | **Chronologies v2** |
| since&#95;id (exclusif)<br /><br />max&#95;id (inclusif) | since&#95;id (exclusif)<br /><br />until&#95;id (également exclusif, contrairement à max&#95;id qui était inclusif) |

**Paramètres de filtrage de la réponse**

|     |     |
| :--- | :--- |
| **Chronologies standard v1.1** | **Chronologies v2** |
| Paramètres de filtrage de la réponse :<br /><br />* include&#95;rts<br />* exclude&#95;replies | Paramètres de filtrage de la réponse :<br /><br />* exclude=retweets,replies |
| Exemple :<br /><br />https://api.x.com/1.1/statuses/user&#95;timeline.json?user&#95;id=2244994945&amp;include&#95;rts=0&amp;&amp;exclude&#95;replies=1 | Exemple :<br /><br />https://api.x.com/2/users/2244994945/tweets?max&#95;results=100&amp;exclude=retweets,replies |
| Remarques :<br /><br />Pour user&#95;timeline :<br /><br />* L’utilisation de include&#95;rts=0 ne modifie pas la limite historique potentielle des 3 200 Publications les plus récentes | Remarques :<br /><br />Pour la chronologie des Publications d’utilisateur :<br /><br />* L’utilisation de exclude=retweets ne modifie pas la limite historique potentielle des 3 200 Publications les plus récentes<br />* L’utilisation de exclude=replies réduit la limite historique potentielle aux 800 réponses les plus récentes |

<div id="differences">
  ### Différences
</div>

**Authentification**

**L&#39;endpoint v1.1 statuses/mentions&#95;timeline prend uniquement en charge [OAuth 1.0a User Context](https://developer-staging.x.com/resources/fundamentals/authentication). L&#39;endpoint de chronologie des mentions utilisateur de X API v2 prend en charge [OAuth 1.0a User Context](/fr/resources/fundamentals/authentication), [OAuth 2.0 App-Only](/fr/resources/fundamentals/authentication#bearer-token-also-known-as-app-only) et [OAuth 2.0 Authorization Code with PKCE](/fr/resources/fundamentals/authenticationoauth-2-0/authorization-code "Cette méthode permet à une app autorisée d'agir au nom de l'utilisateur, en tant qu'utilisateur. Elle est généralement utilisée pour accéder à des informations publiques ou en publier pour un utilisateur spécifique, et elle est utile lorsque votre app doit connaître la relation entre un utilisateur et ce que cet endpoint renvoie. Cliquez pour savoir comment vous authentifier avec OAuth 2.0 Authorization Code with PKCE.") **

Si vous souhaitez tirer parti de la possibilité d&#39;accéder à des métriques privées ou sponsorisées à l&#39;aide de l&#39;endpoint de chronologie des Publications utilisateur de X API v2, vous devrez utiliser OAuth 1.0a User Context ou OAuth 2.0 Authorization Code with PKCE, et transmettre les jetons d&#39;accès utilisateur associés à l&#39;utilisateur qui a publié la Publication pour laquelle vous souhaitez accéder aux métriques.

**URL des endpoints**

Notez que les endpoints de chronologie de X API v2 nécessitent un paramètre de chemin :id pour l’id utilisateur.

* Endpoints v1.1 standard :
  * https://api.x.com/1.1/statuses/home&#95;timeline
  * https://api.x.com/1.1/statuses/user&#95;timeline
  * https://api.x.com/1.1/statuses/mention&#95;timeline
* Endpoint X API v2 :
  * https://api.x.com/2/users/:id/timelines/reverse&#95;chronological
  * https://api.x.com/2/users/:id/tweets
  * https://api.x.com/2/users/:id/mentions

**Exigences pour les Apps et les Project**

Les endpoints X API v2 exigent que vous utilisiez des identifiants issus d&#39;une [developer App](/fr/resources/fundamentals/developer-apps) associée à un [Project](/fr/resources/fundamentals/developer-apps) lors de l&#39;authentification de vos requêtes. Tous les endpoints X API v1.1 peuvent utiliser des identifiants provenant d&#39;Apps ou d&#39;Apps associées à un Project.

**Limites de débit**

|     |     |
| :--- | :--- |
| **mentions&#95;timeline :**<br /><br />75 requêtes par tranche de 15 minutes avec OAuth 1.0a User Context | **user mention timeline :**<br /><br />180 requêtes par tranche de 15 minutes avec OAuth 1.0a User Context  <br />450 requêtes par tranche de 15 minutes avec OAuth 2.0 Bearer Token |
| **home&#95;timelime :**<br /><br />15 requêtes par tranche de 15 minutes  <br /><br />Jusqu&#39;à 800 Publications peuvent être obtenues sur la chronologie d&#39;accueil | **reverse chronological home timeline :**<br /><br />180 requêtes par tranche de 15 minutes<br /><br />Vous pouvez renvoyer chaque Publication créée sur une chronologie au cours des 7 derniers jours, ainsi que les 800 plus récentes, quelle que soit leur date de création. |

**Paramètres de requête**

|     |     |
| :--- | :--- |
| **Standard timelines v1.1** | **timelines v2** |
| Obligatoire : user&#95;id ou screen&#95;name | Obligatoire : l’ID de l’utilisateur spécifique est spécifié dans le paramètre de chemin |
| Facultatif :<br /><br />count - définit le nombre maximal de résultats renvoyés par requête<br /><br />exclude&#95;replies - supprime les réponses des résultats<br /><br />Include&#95;rts - lorsqu’il est défini sur 0, supprime les Retweets des résultats<br /><br />trim&#95;user - supprime des résultats les objets utilisateur réhydratés<br /><br />tweet&#95;mode - définit le format de données renvoyé pour les résultats, à définir sur extended pour les Publications de plus de 140 caractères<br /><br />since&#95;id - définit l’ID de Publication la plus ancienne dans le résultat (exclusif)<br /><br />max&#95;id - définit l’ID de Publication la plus récente dans le résultat (inclusif) | Facultatif :<br /><br />max&#95;results - définit le nombre maximal de résultats renvoyés par requête<br /><br />exclude=retweets,replies - supprime les Retweets ou les réponses des résultats<br /><br />tweet.fields - définit les champs de l’objet Publication à renvoyer<br /><br />user.fields - définit les champs de l’objet User à renvoyer<br /><br />place.fields - définit les champs de l’objet place à renvoyer<br /><br />media.fields - définit les champs de l’objet media à renvoyer<br /><br />poll.fields - définit les champs de l’objet poll à renvoyer<br /><br />expansions - définit les champs étendus et les données à renvoyer<br /><br />start&#95;time - définit l’heure created&#95;at la plus ancienne pour les résultats<br /><br />end&#95;time - définit l’heure created&#95;at la plus récente pour les résultats<br /><br />since&#95;id - définit l’ID de Publication la plus ancienne pour les résultats (exclusif)<br /><br />until&#95;id - définit l’ID de Publication la plus récente dans le résultat (exclusif) |

**Format des données de réponse**

|     |     |
| :--- | :--- |
| **Standard search v1.1** | **Search Posts v2** |
| [<br />    tweet object,<br />    tweet object<br />  ] | <br />  &quot;data&quot;: [id,text,id,text],<br />  &quot;meta&quot;: <br />    &quot;oldest&#95;id&quot;: &quot;1337085692623646724&quot;,<br />    &quot;newest&#95;id&quot;: &quot;1334183616172019713&quot;,<br />    &quot;previous&#95;token&quot;: &quot;77qpymm88g5h9vqkluldpw91lr0qzfz1sqydh841iz48k&quot;,<br />    &quot;result&#95;count&quot;: 10,<br />    &quot;next&#95;token&quot;: &quot;7140dibdnow9c7btw3w29gqolns6a1ipl3kzeae41vsxk&quot;<br />  <br /> |

**Format JSON de X API v2**

X API v2 introduit de nouveaux modèles JSON pour les objets renvoyés par les API, y compris les objets [Post](/fr/x-api/fundamentals/data-dictionary#tweet) et [user](/fr/x-api/fundamentals/data-dictionary#user). Vous pouvez en savoir plus sur le format X API v2, sur la façon d’utiliser les champs et les expansions en consultant notre [guide](/fr/x-api/fundamentals/data-dictionary#how-to-use-fields-and-expansions), ainsi qu’en parcourant notre [dictionnaire de données](/fr/x-api/fundamentals/data-dictionary) plus complet.

* Au niveau racine du JSON, les endpoints standard renvoient des objets Publication dans un tableau statuses, tandis que X API v2 renvoie un tableau data.
* Au lieu de faire référence aux &quot;statuses&quot; Retweeted et Quoted, le JSON de X API v2 fait référence aux Tweets Retweeted et Quoted. De nombreux champs hérités et obsolètes, tels que contributors et user.translator&#95;type, sont supprimés.
* Au lieu d’utiliser favorites (dans l’objet Publication) et favorites (dans l’objet user), X API v2 utilise le terme like.
* X adopte la convention selon laquelle les valeurs JSON sans valeur (par exemple, null) ne sont pas écrites dans le payload. Les attributs de Publication et de user ne sont inclus que s’ils ont une valeur non nulle.

L’une des plus grandes différences entre les versions d’endpoints standard v1.1 et X API v2 est la manière dont vous sélectionnez les champs renvoyés dans votre payload. Pour les endpoints standard, il existe plusieurs paramètres que vous pouvez utiliser pour identifier quels champs ou jeux de champs seront renvoyés dans le payload, tandis que la version X API v2 simplifie ces différents paramètres en [fields](/fr/x-api/fundamentals/fields) et [expansions](/fr/x-api/fundamentals/expansions).

* champs : les endpoints X API v2 vous permettent de choisir quels champs sont fournis dans votre payload. Par exemple, les objets Publication, user, Media, Place et Poll disposent tous d’une liste de champs qui peuvent être renvoyés (ou non).

* expansions : sert à inclure les objets complémentaires référencés dans les payloads JSON de Publication. Par exemple, tous les Retweets et les réponses font référence à d’autres Publications. En définissant expansions=referenced&#95;tweets.id, ces autres objets Publication sont inclus conformément au paramètre tweet.fields. D’autres objets comme les utilisateurs, les sondages et les médias peuvent être inclus.

* conversation&#95;id

* Deux nouveaux champs [annotations](/fr/x-api/fundamentals/post-annotations), notamment context et entities

* Plusieurs nouveaux champs de [metrics](/fr/x-api/fundamentals/metrics)

Nous avons élaboré un [guide de migration du format de données](/fr/x-api/migrate/data-format-migration#migrating-from-standard-v1-1s-data-format-to-v2) qui peut vous aider à faire correspondre les champs standard v1.1 aux champs v2 plus récents. Ce guide vous fournira également les paramètres expansions et fields spécifiques que vous devrez transmettre avec votre requête v2 pour renvoyer des champs spécifiques.

<div id="user-posts-timeline-v2">
  ### Fil des publications de l’utilisateur (v2)
</div>

<CodeGroup dropdown>
  ```bash cURL
  curl "https://api.x.com/2/users/2244994945/tweets?max_results=100&tweet.fields=created_at,public_metrics&exclude=retweets,replies" \
    -H "Authorization: Bearer $BEARER_TOKEN"
  ```

  ```python Python SDK
  from xdk import Client

  client = Client(bearer_token="YOUR_BEARER_TOKEN")

  # Récupérer le fil des publications de l'utilisateur
  for page in client.posts.get_user_posts(
      "2244994945",
      tweet_fields=["created_at", "public_metrics"],
      exclude=["retweets", "replies"],
      max_results=100
  ):
      for post in page.data:
          print(f"{post.created_at}: {post.text[:50]}...")
  ```

  ```javascript JavaScript SDK
  import { Client } from "@xdevplatform/xdk";

  const client = new Client({ bearerToken: "YOUR_BEARER_TOKEN" });

  // Récupérer le fil des publications de l'utilisateur
  const paginator = client.posts.getUserPosts("2244994945", {
    tweetFields: ["created_at", "public_metrics"],
    exclude: ["retweets", "replies"],
    maxResults: 100,
  });

  for await (const page of paginator) {
    page.data?.forEach((post) => {
      console.log(`${post.created_at}: ${post.text?.slice(0, 50)}...`);
    });
  }
  ```
</CodeGroup>

<div id="user-mentions-timeline-v2">
  ### Chronologie des mentions de l’utilisateur (v2)
</div>

<CodeGroup dropdown>
  ```bash cURL
  curl "https://api.x.com/2/users/2244994945/mentions?max_results=100&tweet.fields=created_at,author_id" \
    -H "Authorization: Bearer $BEARER_TOKEN"
  ```

  ```python Python SDK
  from xdk import Client

  client = Client(bearer_token="YOUR_BEARER_TOKEN")

  # Récupérer les mentions de l’utilisateur
  for page in client.posts.get_user_mentions(
      "2244994945",
      tweet_fields=["created_at", "author_id"],
      max_results=100
  ):
      for post in page.data:
          print(f"Mentionné par {post.author_id} : {post.text[:50]}...")
  ```

  ```javascript JavaScript SDK
  import { Client } from "@xdevplatform/xdk";

  const client = new Client({ bearerToken: "YOUR_BEARER_TOKEN" });

  // Récupérer les mentions de l’utilisateur
  const paginator = client.posts.getUserMentions("2244994945", {
    tweetFields: ["created_at", "author_id"],
    maxResults: 100,
  });

  for await (const page of paginator) {
    page.data?.forEach((post) => {
      console.log(`Mentionné par ${post.author_id} : ${post.text?.slice(0, 50)}...`);
    });
  }
  ```
