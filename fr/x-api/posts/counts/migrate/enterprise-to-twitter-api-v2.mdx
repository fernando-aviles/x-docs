<div id="enterprise-compared-to-x-api-v2">
  ### Enterprise par rapport à X API v2
</div>

**Points communs**

* Granularité
* Pagination
* Fuseau horaire

**Différences**

* URL des endpoints
* Exigence relative à l’App et au Projet
* Périodes disponibles
* Format des données de réponse
* Méthodes HTTP
* Formats d’horodatage des requêtes
* Paramètres de requête
* Opérateurs de filtrage

<div id="similarities">
  #### Similarities
</div>

**Granularity**

Bien que le paramètre pour sélectionner la granularité des données renvoyées soit différent (`bucket` pour la version Enterprise, `granularity` pour la version v2), les valeurs que vous pouvez passer à ce paramètre sont les mêmes, tout comme le comportement par défaut :

* `day`
* `hour` (par défaut)
* `minute`

**Pagination**

Bien que v2 dispose de fonctionnalités de pagination supplémentaires (de nouveaux paramètres de pagination qui vous permettent de naviguer à l’aide d’ID de Publication avec `since_id` et `until_id`), les versions Enterprise et v2 vous permettent toutes deux de paginer en utilisant le temps (`fromDate` et `toDate` avec Enterprise, et `start_time` et `end_time` pour v2).

Si vous utilisez la version Enterprise, vous utiliserez le paramètre `next` pour paginer, le champ du jeton suivant sera appelé `next`, et il sera situé à la racine dans la réponse.

Si vous utilisez v2, vous pouvez utiliser soit le paramètre `next_token`, soit le paramètre `pagination_token` pour paginer, et votre jeton suivant sera situé à `meta.next_token` dans la réponse.
 

**Fuseau horaire**

Comme indiqué dans la section sur la pagination, vous pouvez parcourir différentes pages de données en utilisant le temps, pour les versions Enterprise et v2. Dans les deux cas, vous utiliserez l’UTC comme fuseau horaire lorsque vous utilisez ces paramètres.

<div id="differences">
  #### Différences
</div>

**URL d’endpoint**

* Endpoints Enterprise :
  * 30 jours - `http://gnip-api.x.com/search/30day/accounts/:account_name/:label/counts.json`
  * Archive complète - `http://gnip-api.x.com/search/fullarchive/accounts/:account_name/:label/counts.json`
* Endpoints X API v2
  * Récent (7 jours) - `https://api.x.com/2/tweets/counts/recent`
  * Archive complète - `https://api.x.com/2/tweets/counts/all`

**Exigence en matière d’App et de Projet**

Les endpoints X API v2 exigent que vous utilisiez des identifiants issus d’une [App développeur](/fr/resources/fundamentals/developer-apps) qui est associée à un [Projet](/fr/resources/fundamentals/developer-apps) lors de l’authentification de vos requêtes. Tous les endpoints X API v1.1 peuvent utiliser des identifiants provenant d’Apps ou d’Apps associées à un Projet.
 

**Périodes disponibles**

L’API Enterprise et X API v2 offrent toutes deux des endpoints qui vous permettent de récupérer des données de volume de Publications pour l’archive complète de Publications.

Cependant, X API v2 ne propose pas d’endpoint de période de 30 jours comme le fait l’API Enterprise. Au lieu de cela, elle propose l’archive complète mentionnée ci-dessus, ou une période de 7 jours, qui est alignée sur les [endpoints v2 Search Posts](/fr/x-api/posts/search/introduction).
 

**Format des données de réponse**

Il existe quelques légères différences dans le format des données que vous recevrez via Enterprise et X API v2 :

* Les données de comptage Enterprise sont situées dans un objet `results`, tandis que les données de comptage v2 se trouvent dans un objet `data`.
* Les champs de comptage Enterprise sont appelés `timePeriod` (heure de début) et `count`, tandis que v2 scinde la période en un champ `start` et un champ `end` (qui utilisent un format de date/heure différent de celui d’Enterprise, expliqué dans les formats temporels de requête) et renomme le champ de comptage en `tweet_count`.
* Les métadonnées Enterprise incluent `totalCount`, `next` et l’objet `requestParameters` au niveau racine. En revanche, v2 n’inclut pas l’objet `requestParameters` et déplace/renomme les éléments suivants dans un objet `meta` qui se trouve au niveau racine : `total_tweet_count` et `next_token`.
   

**Méthodes HTTP**

La version Enterprise de l’API vous permet d’envoyer la requête soit en tant que méthode HTTP POST avec un corps JSON, soit en tant que méthode HTTP GET avec une chaîne de requête.

La v2 vous permet uniquement d’utiliser la méthode HTTP GET avec une chaîne de requête.
 

**Formats temporels de requête**

La version Enterprise de cet endpoint utilise le format de date/heure suivant dans les paramètres de pagination et dans le champ de réponse `timePeriod` : `YYYYMMDDHHmm`

L’endpoint v2 utilise le format de date/heure ISO 8601/RFC 3339 dans les paramètres de pagination et dans les champs de réponse `start` et `end` : `YYYY-MM-DDTHH:mm:ssZ`

**Paramètres de requête**

Ci-dessous se trouve un tableau des paramètres de requête pour Enterprise et X API v2 :

| Enterprise | Search Posts v2 |
| :--- | :--- |
| query | query |
| bucket | granularity |
| fromDate (YYMMDDHHmm) | start&#95;time (YYYY-MM-DDTHH:mm:ssZ) |
| toDate (YYMMDDHHmm) | end&#95;time (YYYY-MM-DDTHH:mm:ssZ) |
|     | since&#95;id |
|     | until&#95;id |
| next | next&#95;token and pagination&#95;token |

**Opérateurs de filtrage**

Bien que les opérateurs soient pour l’essentiel les mêmes entre Enterprise et X API v2, il existe quelques différences en termes de disponibilité des opérateurs, ainsi que de nouveaux opérateurs qui ont été introduits uniquement dans la version X API v2.

Pour consulter un tableau complet des opérateurs disponibles pour X API v2, Enterprise et même Premium, veuillez visiter la [page de destination de migration des comptages de Publications](/fr/x-api/posts/counts/migrate/overview).
