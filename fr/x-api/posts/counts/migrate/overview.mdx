<div id="comparing-x-apis-post-counts-endpoints">
  ## Comparaison des endpoints de comptage de Publications de X API
</div>

L’endpoint v2 de comptage de Publications finira par remplacer l’[endpoint de comptage de l’enterprise Search API](/fr/x-api/enterprise-gnip-2.0/fundamentals/search-api#counts-requests-post-count). Si vous avez du code, des applications ou des outils qui utilisent une version plus ancienne d’un endpoint de comptage de Publications et que vous envisagez de migrer vers les nouveaux endpoints de X API v2, ce guide est fait pour vous.

***

<div id="recent-post-counts-comparison">
  ## Comparaison des décomptes de Publications récentes
</div>

La version Enterprise des endpoints de comptage de Publications vous permet de récupérer des décomptes soit sur 30 jours, soit sur l’archive complète. Par conséquent, l’endpoint v2 de comptage de Publications récentes, qui examine une période de 7 jours, n’est pas un remplacement direct de l’un ou l’autre des endpoints mentionnés ci-dessus.

Cependant, pour faciliter les comparaisons, nous allons examiner comment l’endpoint v2 de comptage de Publications récentes se compare à l’endpoint Enterprise sur 30 jours.

Le tableau suivant compare les différents types d’endpoints de décompte de Publications récentes :

| **Description** | **Enterprise** | **X API v2** |
| :--- | :--- | :--- |
| Domaine d’hébergement | https://gnip-api.x.com | https://api.x.com |
| Chemin d’endpoint | /search/30day/accounts/:account&#95;name/:label/counts.json | /2/tweets/counts/recent |
| [Authentication](/fr/resources/fundamentals/authentication) | Authentification de base | OAuth 2.0 Bearer Token |
| Format de l’horodatage | YYYYMMDDhhmm | YYYY-MM-DDTHH:mm:ssZ  <br />[ISO 8601 / RFC 3339](https://tools.ietf.org/html/rfc3339#section-5.6) |
| Renvoie des décomptes de Publications âgées d’au maximum | 31 jours | 7 jours |
| Méthodes HTTP prises en charge | GET | GET |
| Limites de débit de requêtes par défaut | 20 requêtes par seconde, agrégées entre les requêtes de recherche de données et de comptage  <br />La limite de débit par minute varie selon le partenaire, comme spécifié dans votre contrat. | 180 requêtes par 15 min et par utilisateur  <br />450 requêtes par 15 min et par App |
| Prend en charge le filtrage à l’aide des [annotations](/fr/x-api/fundamentals/post-annotations) |     | ✔   |
| Prend en charge le filtrage à l’aide de [conversation&#95;id](/fr/x-api/fundamentals/conversation-id) |     | ✔   |
| Nom de la clé JSON pour le tableau de données de Publications | results | data |
| Granularité temporelle | Jour, heure ou minute | Jour, heure ou minute |
| Fuseau horaire | UTC | UTC |
| Paramètres de requête pour sélectionner la période | fromDate  <br />toDate | start&#95;time  <br />end&#95;time |
| Paramètres de requête pour naviguer par ID de Publication |     | since&#95;id  <br />until&#95;id |
| Nécessite l’utilisation d’identifiants provenant d’une [App développeur](/fr/resources/fundamentals/developer-apps) associée à un [projet](/fr/resources/fundamentals/developer-apps) |     | ✔   |

<div id="filtering-operator-comparison">
  ### Comparaison des opérateurs de filtrage
</div>

Les deux versions différentes (Enterprise et v2) des comptes de Publications diffèrent par les opérateurs disponibles et présentent également différents niveaux de disponibilité des opérateurs au sein de chaque version, comme expliqué ci-dessous.

Enterprise

* Il n’existe pas de sous-niveaux d’opérateurs pour Enterprise. Tous les opérateurs Enterprise sont disponibles pour tous les utilisateurs Enterprise.

X API v2

* **Core :** Ces opérateurs sont disponibles pour tout utilisateur v2.
* **Advanced :** Ces opérateurs ne sont disponibles que pour les utilisateurs ayant été approuvés pour l’accès à Academic Research.

Vous pouvez en savoir plus sur chacun de ces ensembles d’opérateurs dans leurs guides respectifs :

* [Opérateurs Enterprise](/fr/x-api/enterprise-gnip-2.0/fundamentals/search-api#building-search-queries)
* [Opérateurs X API v2](/fr/x-api/posts/search/integrate/build-a-query)
