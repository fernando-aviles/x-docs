<div id="likes-lookup-standard-v11-compared-to-x-api-v2">
  ### Recherche de mentions J’aime : standard v1.1 comparé à X API v2
</div>

Si vous utilisez le point de terminaison standard v1.1 [GET favorites/list](https://developer.x.com/en/docs/x-api/v1/tweets/post-and-engage/api-reference/get-favorites-list), l’objectif de ce guide est de vous aider à comprendre les similitudes et les différences entre les points de terminaison de recherche de mentions J’aime du standard v1.1 et de X API v2.

Avec v2, nous avons également introduit un nouveau point de terminaison des utilisateurs ayant aimé, qui vous permet d’obtenir des informations sur les utilisateurs qui ont aimé une Publication.

* **Similarités**
  * Authentification
  * Limites de débit
* **Différences**
  * URL des points de terminaison

  * Limitations des requêtes

  * Exigences en matière d’app et de Projet

  * Paramètres de requête

  * Nouveau format JSON

<div id="similarities">
  #### Points communs
</div>

**Authentification**

Les endpoints Likes lookup de la version standard v1.1 et de X API v2 utilisent tous deux [OAuth 1.0a User Context](/fr/resources/fundamentals/authentication#oauth-1-0a-2) ou [OAuth 2.0 Bearer Token](/fr/resources/fundamentals/authentication#bearer-token-also-known-as-app-only). Par conséquent, si vous utilisiez auparavant les endpoints standard v1.1 [GET favorites/list](https://developer.x.com/en/docs/x-api/v1/tweets/post-and-engage/api-reference/get-favorites-list), vous pouvez continuer à utiliser la même méthode d’authentification lors de votre migration vers la version X API v2, si vous le souhaitez. 

Selon la bibliothèque ou le package d’authentification que vous choisissez, l’authentification par Bearer Token est probablement la façon la plus simple de démarrer et peut être configurée avec un simple en-tête de requête. Pour savoir comment générer un Bearer Token, consultez [ce guide OAuth 2.0 Bearer Token](/fr/resources/fundamentals/authentication#bearer-token-also-known-as-app-only). 
 

**Limites de débit**

L’endpoint standard v1.1 GET favorites/list a une limite de débit de 75 requêtes par tranche de 15 minutes et par utilisateur. L’endpoint correspondant pour les Publications aimées dans la v2 est soumis à la même limite de débit. Cependant, cet endpoint v2 a aussi une limite de débit supplémentaire de 75 requêtes par tranche de 15 minutes et par application.

<div id="differences">
  #### Différences
</div>

**URL de points de terminaison**

* Points de terminaison standard v1.1 :
  * GET https://api.x.com/1.1/favorites/list.json
    (liste des Publications de l’utilisateur spécifié)
  * Il n’existe aucun équivalent v1.1 au point de terminaison v2 liking users
* Point de terminaison X API v2 :
  * GET https://api.x.com/2/users/:id/liked&#95;tweets
    (liste des Publications aimées par l’ID utilisateur spécifié)
  * GET https://api.x.com/2/tweets/:id/liking&#95;users
    (liste des utilisateurs qui ont aimé la Publication dont l’ID est spécifié)

**Limitations des requêtes**

Le point de terminaison v2 liked Posts vous permet de demander de 5 à 100 Publications par requête, mais vous pouvez récupérer tous les likes d’une Publication en utilisant des jetons de pagination. Le point de terminaison v1.1 GET favorites/list vous permet également de récupérer tous les likes des Publications, mais vous pouvez en récupérer de 20 à 200 par requête.

Pour le point de terminaison v2 liking users, vous êtes limité à 100 utilisateurs ayant aimé une Publication. 
 

**Exigences relatives aux Apps et aux Projets**

Les points de terminaison X API v2 exigent que vous utilisiez des identifiants provenant d’une [App développeur](/fr/resources/fundamentals/developer-apps) associée à un [Projet](/fr/resources/fundamentals/developer-apps) lors de l’authentification de vos requêtes. Tous les points de terminaison X API v1.1 peuvent utiliser des identifiants provenant d’Apps ou d’Apps associées à un projet.

**Paramètres de requête**

Les paramètres de requête standard v1.1 suivants acceptaient deux paramètres de requête (user&#95;id ou screen&#95;name). X API v2 n’accepte que l’ID utilisateur numérique, qui doit être transmis dans le chemin du point de terminaison.

L’une des plus grandes différences entre les versions de points de terminaison standard v1.1 et X API v2 est la façon dont vous sélectionnez les champs renvoyés dans votre payload. Pour les points de terminaison standard, plusieurs paramètres pouvaient être utilisés pour identifier quels champs ou ensembles de champs seraient renvoyés dans le payload, tandis que la version X API v2 simplifie ces différents paramètres en [champs](/fr/x-api/fundamentals/fields) et [expansions](/fr/x-api/fundamentals/expansions). 
 

**Nouveau format JSON**

X API v2 introduit de nouveaux modèles JSON pour les objets renvoyés par les API, y compris les objets [Post](/fr/x-api/fundamentals/data-dictionary#tweet) et [user](/fr/x-api/fundamentals/data-dictionary#user).

* Au niveau racine JSON, les points de terminaison standard renvoient des objets user dans un tableau statuses, tandis que X API v2 renvoie un tableau data. 
* Au lieu de faire référence aux &quot;statuses&quot; Retweeted et Quoted, le JSON de X API v2 fait référence aux Tweets retweetés et cités. De nombreux champs hérités et obsolètes, tels que contributors et user.translator&#95;type, sont supprimés. 
* Au lieu d’utiliser à la fois favorites (dans l’objet Post) et favourites (dans l’objet user), X API v2 utilise le terme like. 
* X adopte la convention selon laquelle les propriétés JSON sans valeur (par exemple null) ne sont pas écrites dans le payload. Les attributs des objets Post et user ne sont inclus que s’ils ont des valeurs non nulles.
   

En plus des changements apportés à notre nouveau format JSON, nous avons également introduit un nouvel ensemble de champs dans l’objet Post, notamment :

* [conversation&#95;id](/fr/x-api/fundamentals/conversation-id)
* Deux nouveaux champs [Post annotations](/fr/x-api/fundamentals/post-annotations), notamment context et entities
* Plusieurs nouveaux champs [metrics](/fr/x-api/fundamentals/metrics)

<div id="get-liked-posts-v2">
  ### Récupérer les Publications aimées (v2)
</div>

<CodeGroup dropdown>
  ```bash cURL
  curl "https://api.x.com/2/users/2244994945/liked_tweets?tweet.fields=created_at,public_metrics&max_results=100" \
    -H "Authorization: Bearer $BEARER_TOKEN"
  ```

  ```python Python
  import requests

  bearer_token = "YOUR_BEARER_TOKEN"
  url = "https://api.x.com/2/users/2244994945/liked_tweets"

  params = {
      "tweet.fields": "created_at,public_metrics",
      "max_results": 100
  }

  headers = {"Authorization": f"Bearer {bearer_token}"}
  response = requests.get(url, headers=headers, params=params)

  print(response.json())
  ```

  ```python Python SDK
  from xdk import Client

  client = Client(bearer_token="YOUR_BEARER_TOKEN")

  # Récupérer les Publications aimées de l'utilisateur
  for page in client.posts.get_liked_posts(
      "2244994945",
      tweet_fields=["created_at", "public_metrics"],
      max_results=100
  ):
      for post in page.data:
          print(f"{post.text[:50]}... - J'aime : {post.public_metrics.like_count}")
  ```

  ```javascript JavaScript SDK
  import { Client } from "@xdevplatform/xdk";

  const client = new Client({ bearerToken: "YOUR_BEARER_TOKEN" });

  // Récupérer les Publications aimées de l'utilisateur
  const paginator = client.posts.getLikedPosts("2244994945", {
    tweetFields: ["created_at", "public_metrics"],
    maxResults: 100,
  });

  for await (const page of paginator) {
    page.data?.forEach((post) => {
      console.log(`${post.text?.slice(0, 50)}... - J'aime : ${post.public_metrics?.like_count}`);
    });
  }
  ```
</CodeGroup>

<div id="get-liking-users-v2">
  ### Récupérer les utilisateurs qui ont aimé une Publication (v2)
</div>

<CodeGroup dropdown>
  ```bash cURL
  curl "https://api.x.com/2/tweets/1234567890/liking_users?user.fields=username,verified" \
    -H "Authorization: Bearer $BEARER_TOKEN"
  ```

  ```python Python
  import requests

  bearer_token = "YOUR_BEARER_TOKEN"
  url = "https://api.x.com/2/tweets/1234567890/liking_users"

  params = {"user.fields": "username,verified"}

  headers = {"Authorization": f"Bearer {bearer_token}"}
  response = requests.get(url, headers=headers, params=params)

  print(response.json())
  ```

  ```python Python SDK
  from xdk import Client

  client = Client(bearer_token="YOUR_BEARER_TOKEN")

  # Récupérer les utilisateurs qui ont aimé une Publication
  response = client.posts.get_liking_users(
      "1234567890",
      user_fields=["username", "verified"]
  )
  for user in response.data:
      print(f"{user.username} - Verified: {user.verified}")
  ```

  ```javascript JavaScript SDK
  import { Client } from "@xdevplatform/xdk";

  const client = new Client({ bearerToken: "YOUR_BEARER_TOKEN" });

  // Récupérer les utilisateurs qui ont aimé une Publication
  const response = await client.posts.getLikingUsers("1234567890", {
    userFields: ["username", "verified"],
  });

  response.data?.forEach((user) => {
    console.log(`${user.username} - Verified: ${user.verified}`);
  });
  ```
</CodeGroup>
