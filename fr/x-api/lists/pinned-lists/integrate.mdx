<div id="authentication">
  ### Authentification
</div>

Tous les endpoints de X API v2 exigent que vous authentifiiez vos requêtes à l&#39;aide d&#39;un ensemble d&#39;identifiants, également appelés clés et jetons. Vous pouvez utiliser OAuth 1.0a User Context pour authentifier vos requêtes vers cet endpoint.

[OAuth 1.0a User Context](/fr/resources/fundamentals/authentication), ce qui signifie que vous devez utiliser un ensemble de clés d&#39;API et de jetons d&#39;accès utilisateur pour effectuer une requête avec succès. Les jetons d&#39;accès doivent être associés à l&#39;utilisateur pour lequel vous effectuez la requête. Si vous souhaitez générer un ensemble de jetons d&#39;accès pour un autre utilisateur, celui-ci doit autoriser votre application en utilisant le [flux OAuth à 3 volets](https://developer.x.com/resources/fundamentals/authentication/obtaining-user-access-tokens).

Veuillez noter qu&#39;OAuth 1.0a peut être difficile à utiliser. Si vous n&#39;êtes pas familier avec cette méthode d&#39;authentification, nous vous recommandons d&#39;utiliser une [bibliothèque](/fr/x-api/tools-and-libraries/overview) ou un outil comme Postman.

<div id="developer-console-projects-and-developer-apps">
  ### Developer Console, Projects, and developer Apps
</div>

Pour obtenir un ensemble d’identifiants d’authentification qui fonctionnent avec les points de terminaison de X API v2, vous devez [créer un compte développeur](https://developer.x.com/en/portal/petition/essential/basic-info), configurer un [Projet](/fr/resources/fundamentals/developer-apps) dans ce compte, puis créer une [App développeur](/fr/resources/fundamentals/developer-apps) au sein de ce Projet. Vous pourrez ensuite trouver vos clés et jetons dans votre App développeur.

<div id="rate-limits">
  ### Limites de fréquence
</div>

Chaque jour, plusieurs milliers de développeurs envoient des requêtes vers X API. Pour aider à gérer l’important volume de ces requêtes, des [limites de fréquence](/fr/x-api/fundamentals/rate-limits) sont appliquées à chaque endpoint, ce qui limite le nombre de requêtes que vous pouvez effectuer pour le compte de votre App développeur ou pour le compte d’un utilisateur authentifié.

Ces endpoints sont soumis à des limites de fréquence au niveau de l’utilisateur, ce qui signifie que l’utilisateur authentifié pour lequel vous effectuez la requête ne peut appeler l’endpoint qu’un certain nombre de fois, toutes App développeur confondues.

Le tableau ci-dessous présente les limites de fréquence pour chaque endpoint.

| Endpoint | Méthode HTTP | Limite de fréquence |
| :--- | :--- | :--- |
| /2/users/:id/pinned&#95;lists | POST | 50 requêtes par tranche de 15 minutes |
| /2/users/:id/pinned&#95;lists/:list&#95;id | DELETE | 50 requêtes par tranche de 15 minutes |
| /2/users/:id/pinned&#95;lists | GET | 15 requêtes par tranche de 15 minutes |

<div id="fields-and-expansions">
  ### Champs et expansions
</div>

L&#39;endpoint GET de X API v2 permet aux utilisateurs de sélectionner précisément quelles données ils souhaitent obtenir de l&#39;API en utilisant un ensemble d&#39;outils appelés `fields` et `expansions`. Le paramètre `expansions` vous permet d’étendre les objets référencés dans le payload. Par exemple, la consultation de listes épinglées vous permet de récupérer les [expansions](/fr/x-api/fundamentals/expansions) suivantes :

* `owner_id`

Le paramètre `fields` vous permet de sélectionner exactement quels [champs](/fr/x-api/fundamentals/fields) au sein des différents objets de données vous souhaitez recevoir. Cet endpoint renvoie principalement des objets utilisateur. Par défaut, l&#39;objet List renvoie les champs `id` et `name`. Pour recevoir des champs supplémentaires tels que `list.created_at` ou `list.description`, vous devrez les demander explicitement à l&#39;aide d&#39;un paramètre `fields`.

Nous avons ajouté à notre [dictionnaire de données X API v2](/fr/x-api/fundamentals/data-dictionary) un guide sur l&#39;utilisation conjointe des [champs et expansions](/fr/x-api/fundamentals/data-dictionary#how-to-use-fields-and-expansions).

Le tableau ci-dessous présente les champs et expansions disponibles pour l&#39;endpoint de recherche :

| Endpoint | Champs | Expansions |
| :--- | :--- | :--- |
| /2/users/:id/pinned&#95;lists | `list.fields`, `user.fields` | `owner_id` |
