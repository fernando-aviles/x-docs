<div id="authentication">
  ### Authentification
</div>

Tous les endpoints de X API v2 exigent que vous authentifiiez vos requêtes avec un ensemble d’identifiants, également appelés clés et jetons. Vous pouvez utiliser OAuth 1.0a User Context pour authentifier vos requêtes adressées à cet endpoint.

Avec [OAuth 1.0a User Context](/fr/resources/fundamentals/authentication), vous devez utiliser un ensemble de clés d’API et de jetons d’accès utilisateur pour qu’une requête aboutisse. Les jetons d’accès doivent être associés à l’utilisateur pour le compte duquel vous effectuez la requête. Si vous souhaitez générer un ensemble de jetons d’accès pour un autre utilisateur, celui-ci doit autoriser votre application à l’aide du [flux OAuth en 3 étapes](https://developer.x.com/resources/fundamentals/authentication/obtaining-user-access-tokens).

Veuillez noter qu’OAuth 1.0a peut être difficile à utiliser. Si vous ne connaissez pas bien cette méthode d’authentification, nous vous recommandons d’utiliser une [bibliothèque](/fr/x-api/tools-and-libraries/overview) ou un outil comme Postman.

<div id="developer-console-projects-and-developer-apps">
  ### Console de Développement, Projets et Apps développeur
</div>

Pour obtenir des identifiants d’authentification qui fonctionneront avec les endpoints de X API v2, vous devez vous [inscrire pour obtenir un compte développeur](https://developer.x.com/en/portal/petition/essential/basic-info), configurer un [Project](/fr/resources/fundamentals/developer-apps) dans ce compte, puis créer une [developer App](/fr/resources/fundamentals/developer-apps) dans ce Project. Vous pourrez ensuite trouver vos clés et jetons au sein de votre App développeur.

<div id="rate-limits">
  ### Limites de débit
</div>

Chaque jour, plusieurs milliers de développeurs envoient des requêtes à la X API. Pour aider à gérer le volume de ces requêtes, des [limites de débit](/fr/x-api/fundamentals/rate-limits) sont appliquées à chaque point de terminaison, ce qui limite le nombre de requêtes que vous pouvez effectuer pour le compte de votre App développeur ou pour le compte d’un utilisateur authentifié.

Ces points de terminaison sont soumis à des limites de débit au niveau de l’utilisateur, ce qui signifie que l’utilisateur authentifié pour le compte duquel vous effectuez la requête ne peut appeler le point de terminaison qu’un certain nombre de fois, quel que soit l’App développeur utilisée.

Le tableau ci-dessous présente les limites de débit pour chaque point de terminaison.

| Point de terminaison | Méthode HTTP | Limite de débit |
| :--- | :--- | :--- |
| /2/users/:id/pinned&#95;lists | POST | 50 requêtes par tranche de 15 minutes |
| /2/users/:id/pinned&#95;lists/:list&#95;id | DELETE | 50 requêtes par tranche de 15 minutes |
| /2/users/:id/pinned&#95;lists | GET | 15 requêtes par tranche de 15 minutes |

<div id="fields-and-expansions">
  ### Champs et expansions
</div>

L’endpoint GET de X API v2 permet aux utilisateurs de sélectionner exactement quelles données ils souhaitent récupérer à partir de l’API à l’aide d’un ensemble de paramètres appelés `fields` et `expansions`. Le paramètre `expansions` vous permet d’inclure les objets référencés dans le payload. Par exemple, la recherche des Lists épinglées vous permet de récupérer les [expansions](/fr/x-api/fundamentals/expansions) suivantes :

* `owner_id`

Le paramètre `fields` vous permet de sélectionner exactement quels [champs](/fr/x-api/fundamentals/fields), au sein des différents objets de données, vous souhaitez recevoir. Cet endpoint renvoie principalement des objets utilisateur. Par défaut, l’objet List renvoie les champs `id` et `name`. Pour recevoir des champs supplémentaires comme `list.created_at` ou `list.description`, vous devrez les demander explicitement en utilisant un paramètre `fields`.

Nous avons ajouté à notre [dictionnaire de données X API v2](/fr/x-api/fundamentals/data-dictionary) un guide sur l’utilisation conjointe des [fields et expansions](/fr/x-api/fundamentals/data-dictionary#how-to-use-fields-and-expansions).

Le tableau ci-dessous présente les champs et expansions disponibles pour l’endpoint de lookup :

| Endpoint | Champs | Expansions |
| :--- | :--- | :--- |
| /2/users/:id/pinned&#95;lists | `list.fields`, `user.fields` | `owner_id` |
