<div id="manage-list-members-standard-v11-compared-to-x-api-v2">
  ### Gérer les membres de liste : Standard v1.1 par rapport à X API v2
</div>

Si vous avez travaillé avec les endpoints standard v1.1 [POST lists/members/create](https://developer.x.com/en/docs/twitter-api/v1/accounts-and-users/create-manage-lists/api-reference/post-lists-members-create) et [POST lists/members/destroy](https://developer.x.com/en/docs/twitter-api/v1/accounts-and-users/create-manage-lists/api-reference/post-lists-members-destroy), ce guide a pour objectif de vous aider à comprendre les similitudes et les différences entre les endpoints standard v1.1 et X API v2 pour la gestion des membres de liste.

* **Similarités**
  * Authentification
* **Différences**
  * URL des endpoints
  * Exigences relatives aux Apps et aux Projets
  * Méthodes HTTP
  * Limites de taux
  * Paramètres de requête

<div id="similarities">
  #### Points communs
</div>

**Authentification**

Les deux versions de l’endpoint prennent en charge [OAuth 1.0a User Context](https://developer.x.com/content/developer-twitter/resources/fundamentals/authentication). Par conséquent, si vous utilisiez auparavant l’un des endpoints standard v1.1 pour la gestion des membres de listes, vous pouvez continuer à utiliser la même méthode d’authentification lors de votre migration vers la version X API v2.

<div id="differences">
  #### Différences
</div>

**URL des endpoints**

* Endpoints standard v1.1 :
  * POST https://api.x.com/1.1/lists/members/create.json
    (Ajoute un membre à une Liste spécifiée)
  * POST https://api.x.com/1.1/lists/members/destroy.json
    (Supprime un membre d’une Liste spécifiée)
* Endpoint X API v2 :
  * POST https://api.x.com/2/lists/:id/members
    (Ajoute un membre à une Liste spécifiée)

  * DELETE https://api.x.com/2/lists/:id/members/:user&#95;id
    (Supprime un membre d’une Liste spécifiée)

**Limites de taux**

| **Standard v1.1** | **X API v2** |
| :--- | :--- |
| /1.1/lists/members/create.json<br /><br />aucune | /2/lists/:id/members<br /><br />300 requêtes par fenêtre de 15 minutes avec OAuth 1.0a en contexte utilisateur<br /><br />300 requêtes par fenêtre de 15 minutes avec OAuth 2.0 Authorization Code with PKCE |
| /1.1/lists/members/destroy.json<br /><br />aucune | /2/lists/:id/members/:user&#95;id<br /><br />300 requêtes par fenêtre de 15 minutes avec OAuth 1.0a en contexte utilisateur<br /><br />300 requêtes par fenêtre de 15 minutes avec OAuth 2.0 Authorization Code with PKCE |

**Conditions requises pour les App et Project**

Les endpoints X API v2 requièrent que vous utilisiez des identifiants provenant d’une [developer App](/fr/resources/fundamentals/developer-apps) qui est associée à un [Project](/fr/resources/fundamentals/developer-apps) lors de l’authentification de vos requêtes. Tous les endpoints X API v1.1 peuvent utiliser des identifiants provenant d’App ou d’App associées à un Project.

**Paramètres de requête**

Les paramètres de requête standard v1.1 suivants ont des équivalents dans X API v2 :

| **Standard v1.1** | **X API v2** |
| :--- | :--- |
| list&#95;id | id  |
| slug | Aucun équivalent |
| screen&#95;name | Aucun équivalent |
| owner&#95;screen&#95;name | Aucun équivalent |
| owner&#95;id | Aucun équivalent |
