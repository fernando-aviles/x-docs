<div id="manage-list-members-standard-v11-compared-to-x-api-v2">
  ### Gérer les membres d’une Liste : Standard v1.1 par rapport à X API v2
</div>

Si vous avez utilisé les endpoints standard v1.1 [POST lists/members/create](https://developer.x.com/en/docs/twitter-api/v1/accounts-and-users/create-manage-lists/api-reference/post-lists-members-create) et [POST lists/members/destroy](https://developer.x.com/en/docs/twitter-api/v1/accounts-and-users/create-manage-lists/api-reference/post-lists-members-destroy), ce guide a pour objectif de vous aider à comprendre les points communs et les différences entre les endpoints standard v1.1 et ceux de X API v2 pour la gestion des membres d’une Liste.

* **Points communs**
  * Authentification
* **Différences**
  * URL des endpoints
  * Exigences pour les Apps et les Projets
  * Méthodes HTTP
  * Limites de débit
  * Paramètres de requête

<div id="similarities">
  #### Similarités
</div>

**Authentification**

Les deux versions de ces endpoints prennent en charge [OAuth 1.0a User Context](https://developer.x.com/content/developer-twitter/resources/fundamentals/authentication). Par conséquent, si vous utilisiez auparavant l’un des endpoints standard v1.1 pour gérer les membres d’une liste, vous pouvez continuer à utiliser la même méthode d’authentification si vous migrez vers la version X API v2.

<div id="differences">
  #### Différences
</div>

**URL des endpoints**

* Endpoints standard v1.1 :
  * POST https://api.x.com/1.1/lists/members/create.json
    (Ajoute un membre à une liste spécifiée)
  * POST https://api.x.com/1.1/lists/members/destroy.json
    (Supprime un membre d’une liste spécifiée)
* Endpoint X API v2 :
  * POST https://api.x.com/2/lists/:id/members
    (Ajoute un membre à une liste spécifiée)

  * DELETE https://api.x.com/2/lists/:id/members/:user&#95;id
    (Supprime un membre d’une liste spécifiée)

**Limites de débit**

| **Standard v1.1** | **X API v2** |
| :--- | :--- |
| /1.1/lists/members/create.json<br /><br />Aucune | /2/lists/:id/members<br /><br />300 requêtes par fenêtre de 15 minutes avec OAuth 1.0a User Context<br /><br />300 requêtes par fenêtre de 15 minutes avec OAuth 2.0 Authorization Code with PKCE |
| /1.1/lists/members/destroy.json<br /><br />Aucune | /2/lists/:id/members/:user&#95;id<br /><br />300 requêtes par fenêtre de 15 minutes avec OAuth 1.0a User Context<br /><br />300 requêtes par fenêtre de 15 minutes avec OAuth 2.0 Authorization Code with PKCE |

**Exigences pour les App et les Projets**

Les endpoints X API v2 requièrent que vous utilisiez des identifiants issus d’une [developer App](/fr/resources/fundamentals/developer-apps) qui est associée à un [Project](/fr/resources/fundamentals/developer-apps) lors de l’authentification de vos requêtes. Tous les endpoints X API v1.1 peuvent utiliser des identifiants provenant d’App ou d’App associées à un Project.

**Paramètres de requête**

Les paramètres de requête standard v1.1 suivants ont des équivalents dans X API v2 :

| **Standard v1.1** | **X API v2** |
| :--- | :--- |
| list&#95;id | id  |
| slug | Aucun équivalent |
| screen&#95;name | Aucun équivalent |
| owner&#95;screen&#95;name | Aucun équivalent |
| owner&#95;id | Aucun équivalent |
