Postman est un excellent outil que vous pouvez utiliser pour tester un endpoint. Chaque requête Postman inclut tous les paramètres de chemin et de corps de la requête afin de vous aider à comprendre rapidement ce qui est à votre disposition. Pour en savoir plus sur nos collections Postman, veuillez consulter notre page [&quot;Utilisation de Postman&quot;](/fr/tutorials/postman-getting-started).

  ## Concepts clés

<div id="authentication">
  ### Authentification
</div>

Tous les endpoints de X API v2 exigent que vous authentifiiez vos requêtes à l’aide d’un ensemble d’identifiants, également appelés clés et jetons. Vous pouvez utiliser soit OAuth 1.0a User Context, OAuth 2.0 Authorization Code avec PKCE, soit App only pour authentifier vos requêtes vers les endpoints de **consultation** des Lists. En revanche, vous devez vous authentifier avec OAuth 1.0a User Context ou OAuth 2.0 pour les endpoints de **gestion** des Lists.

[OAuth 1.0a User Context](/fr/resources/fundamentals/authentication), ce qui signifie que vous devez utiliser un ensemble de clés d’API et de jetons d’accès utilisateur pour effectuer une requête avec succès. Les jetons d’accès doivent être associés à l’utilisateur pour le compte duquel vous effectuez la requête. Si vous souhaitez générer un ensemble de jetons d’accès pour un autre utilisateur, celui-ci doit autoriser votre App en utilisant le [flux OAuth en 3 étapes](/fr/resources/fundamentals/authentication#obtaining-access-tokens-using-3-legged-oauth-flow).

Veuillez noter qu’OAuth 1.0a peut être difficile à utiliser. Si vous n’êtes pas à l’aise avec cette méthode d’authentification, nous vous recommandons d’utiliser une [bibliothèque](/fr/x-api/tools-and-libraries/overview), un outil comme Postman, ou d’utiliser OAuth 2.0 ou App only pour authentifier vos requêtes.

[OAuth 2.0 Authorization Code avec PKCE](/fr/resources/fundamentals/authentication#oauth-2-0-authorization-code-flow-with-pkce-2) permet un meilleur contrôle de la portée (scope) d’une application et des flux d’autorisation sur plusieurs appareils. OAuth 2.0 vous permet de choisir des scopes précis et granulaires qui vous accordent des autorisations spécifiques pour le compte d’un utilisateur.

Pour activer OAuth 2.0 dans votre App, vous devez l’activer dans les paramètres d’authentification de votre App situés dans la section App settings de la Console de Développement.

[App only](/fr/resources/fundamentals/authentication#oauth-2-0) nécessite simplement que vous transmettiez un [jeton d’accès App only](/fr/resources/fundamentals/authentication#bearer-token-also-known-as-app-only) avec votre requête. Vous pouvez soit générer un jeton d’accès App only directement dans une App développeur, soit en générer un à l’aide de l’endpoint [POST oauth2/token](/fr/resources/fundamentals/authentication#post-oauth2-token).

<div id="developer-console-projects-and-developer-apps">
  ### Console de Développement, Projets et Apps développeur
</div>

Pour obtenir un ensemble d’identifiants d’authentification qui fonctionneront avec les endpoints de X API v2, vous devez [vous inscrire pour obtenir un compte développeur](https://developer.x.com/en/portal/petition/essential/basic-info), configurer un [Projet](/fr/resources/fundamentals/developer-apps) au sein de ce compte, puis créer une [App développeur](/fr/resources/fundamentals/developer-apps) dans ce Projet. Vous pourrez ensuite trouver vos clés et vos jetons dans votre App développeur.

<div id="rate-limits">
  ### Limites de débit
</div>

Chaque jour, des milliers de développeurs envoient des requêtes vers l’X API. Pour aider à gérer l’important volume de ces requêtes, des [limites de débit](/fr/x-api/fundamentals/rate-limits) sont appliquées à chaque point de terminaison, ce qui limite le nombre de requêtes que vous pouvez effectuer au nom de votre app ou au nom d’un utilisateur authentifié.

Les points de terminaison de consultation (GET) sont soumis à des limites de débit à la fois au niveau de l’App et au niveau de l’utilisateur, tandis que les points de terminaison de gestion (POST/DELETE) sont limités au niveau de l’utilisateur. La limite de débit au niveau de l’App signifie que vous, en tant que développeur, ne pouvez effectuer qu’un certain nombre de requêtes vers ce point de terminaison sur une période donnée à partir d’une App donnée (en utilisant soit l’API Key et l’API Secret Key, soit l’App only Access Token). La limite de débit au niveau de l’utilisateur signifie que l’utilisateur authentifié au nom duquel vous effectuez la requête ne peut effectuer une consultation de liste qu’un certain nombre de fois, toutes les Apps développeur confondues.

Le tableau ci-dessous présente les limites de débit pour chaque point de terminaison.

| Point de terminaison | Méthode HTTP | Limite de débit |
| :--- | :--- | :--- |
| /2/lists/:id/members | GET | 900 requêtes par tranche de 15 minutes |
| /2/users/:id/list&#95;memberships | GET | 75 requêtes par tranche de 15 minutes |
| /2/lists/:id/members | POST | 300 requêtes par tranche de 15 minutes |
| /2/lists/:id/members/:user&#95;id | DELETE | 300 requêtes par tranche de 15 minutes |

<div id="fields-and-expansions">
  ### Champs et expansions
</div>

L’endpoint GET de X API v2 permet aux utilisateurs de sélectionner précisément quelles données ils souhaitent récupérer à partir de l’API au moyen d’un ensemble de paramètres appelés `fields` et `expansions`. Le paramètre `expansions` vous permet d’inclure les objets référencés dans le payload. Par exemple, la recherche des membres d’une List vous permet de récupérer les [expansions](/fr/x-api/fundamentals/expansions) suivantes :

* `pinned_tweet_id`

Le paramètre `fields` vous permet de sélectionner précisément quels [champs](/fr/x-api/fundamentals/fields), au sein des différents objets de données, vous souhaitez recevoir. La recherche des membres d’une List renvoie principalement des objets utilisateur. Par défaut, l’objet utilisateur renvoie les champs `id`, `name` et `username`. Pour recevoir des champs supplémentaires comme `user.created_at` ou `user.description`, vous devez les demander explicitement en utilisant le paramètre `user.fields`.

Nous avons ajouté un guide sur l’utilisation des [champs et expansions](/fr/x-api/fundamentals/data-dictionary#how-to-use-fields-and-expansions).

Le tableau ci-dessous présente les champs et expansions disponibles pour chaque endpoint de recherche :

| Endpoint | Champs | Expansions |
| :--- | :--- | :--- |
| /2/lists/:id/members | `user.fields`, `tweet.fields` | `pinned_tweet_id` |
| /2/users/:id/list&#95;memberships | `list.fields`, `user.fields` | `owner_id` |

<div id="pagination">
  ### Pagination
</div>

La consultation de l’appartenance ou des membres peut renvoyer un grand volume de données. Pour garantir que nous renvoyons des résultats cohérents et performants à tout moment, nous utilisons la pagination. La pagination est une fonctionnalité des endpoints de X API v2 qui renvoient plus de résultats qu’il n’est possible d’en inclure dans une seule réponse. Lorsque cela se produit, les données sont renvoyées sous forme de « pages » successives. Pour en savoir plus, consultez la [pagination des résultats.](/fr/x-api/fundamentals/pagination)
