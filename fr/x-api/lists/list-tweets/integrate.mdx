  ## Concepts clés

<div id="authentication">
  ### Authentication
</div>

Tous les endpoints de X API v2 nécessitent que vous authentifiiez vos requêtes à l’aide d’un ensemble d’identifiants, également appelés clés et jetons. Vous pouvez utiliser OAuth 1.0a User Context, App only ou OAuth 2.0 Authorization Code with PKCE pour authentifier vos requêtes vers cet endpoint.

Avec [OAuth 1.0a User Context](/fr/resources/fundamentals/authentication#oauth-1-0a-2), vous devez utiliser un ensemble de clés d’API et de jetons d’accès utilisateur pour effectuer une requête avec succès. Les jetons d’accès doivent être associés à l’utilisateur pour le compte duquel vous effectuez la requête. Si vous souhaitez générer un ensemble de jetons d’accès pour un autre utilisateur, celui-ci doit autoriser votre App en utilisant le [flux OAuth en 3 étapes](/fr/resources/fundamentals/authentication#obtaining-access-tokens-using-3-legged-oauth-flow).

Veuillez noter qu’OAuth 1.0a peut être difficile à utiliser. Si vous ne maîtrisez pas bien cette méthode d’authentification, nous vous recommandons d’utiliser une [bibliothèque](/fr/x-api/tools-and-libraries/overview), un outil comme Postman, ou d’utiliser OAuth 2.0 ou App only pour authentifier vos requêtes.

[OAuth 2.0 Authorization Code with PKCE](/fr/resources/fundamentals/authentication#oauth-2-0-authorization-code-flow-with-pkce-2) permet un meilleur contrôle sur la portée (scope) d’une application et sur les flux d’autorisation entre plusieurs appareils. OAuth 2.0 vous permet de choisir des scopes précis et granulaires qui vous confèrent des autorisations spécifiques au nom d’un utilisateur.

Pour activer OAuth 2.0 dans votre App, vous devez l’activer dans les paramètres d’authentification de votre App, disponibles dans la section App settings de la Console de Développement.

[App only](/fr/resources/fundamentals/authentication#app-only-authentication-and-oauth-2-0-bearer-token) exige seulement que vous transmettiez un [App only Access Token](/fr/resources/fundamentals/authentication#app-only-authentication-and-oauth-2-0-bearer-token) avec votre requête. Vous pouvez soit générer un App only Access Token directement au sein d’une App développeur, soit en générer un en utilisant l’endpoint [POST oauth2/token](/fr/resources/fundamentals/authentication#post-oauth2-token).

<div id="developer-console-projects-and-developer-apps">
  ### Console de Développement, Projets et Apps développeur
</div>

Pour obtenir un ensemble d&#39;identifiants d&#39;authentification compatibles avec les endpoints de X API v2, vous devez d&#39;abord [créer un compte développeur](https://developer.x.com/en/portal/petition/essential/basic-info), configurer un [Projet](/fr/resources/fundamentals/developer-apps) dans ce compte, puis créer une [App développeur](/fr/resources/fundamentals/developer-apps) dans ce Projet. Vous pourrez ensuite trouver vos clés et jetons dans votre App développeur.

<div id="rate-limits">
  ### Limites de débit
</div>

Chaque jour, plusieurs milliers de développeurs envoient des requêtes vers X API. Pour aider à gérer l’important volume de ces requêtes, des [limites de débit](https://developer.x.com/x-api/fundamentals/rate-limits) sont appliquées à chaque endpoint, ce qui limite le nombre de requêtes que vous pouvez effectuer pour le compte de votre application ou pour le compte d’un utilisateur authentifié.

Cet endpoint est soumis à des limites de débit à la fois au niveau de l’App et au niveau de l’utilisateur. La limite de débit au niveau de l’App signifie que vous, en tant que développeur, ne pouvez effectuer qu’un certain nombre de requêtes vers cet endpoint au cours d’une période donnée depuis une App donnée (en utilisant soit l’API Key et l’API Secret Key, soit le Bearer Token). La limite de débit au niveau de l’utilisateur signifie que l’utilisateur authentifié pour lequel vous effectuez la requête ne peut effectuer une recherche de Publications de liste qu’un certain nombre de fois, toutes les Apps développeur confondues.

Le tableau ci-dessous présente les limites de débit pour chaque endpoint.

| Endpoint | Méthode HTTP | Limite de débit |
| :--- | :--- | :--- |
| /2/lists/:id/tweets | GET | 900 requêtes par tranche de 15 minutes |

<div id="fields-and-expansions">
  ### Champs et expansions
</div>

L&#39;endpoint GET de X API v2 permet aux utilisateurs de sélectionner précisément quelles données ils souhaitent recevoir depuis l&#39;API à l&#39;aide d&#39;un ensemble d&#39;outils appelés `fields` et `expansions`. Le paramètre `expansions` vous permet de développer les objets référencés dans le payload. Par exemple, la consultation des Publications d&#39;une Liste vous permet de récupérer les [expansions](/fr/x-api/fundamentals/expansions) suivantes :

* `author_id`

Le paramètre `fields` vous permet de sélectionner précisément quels [fields](/fr/x-api/fundamentals/fields) au sein des différents objets de données vous souhaitez recevoir. Cet endpoint renvoie principalement des objets Publication. Par défaut, l&#39;objet Publication renvoie les champs `id` et `text`. Pour recevoir des champs supplémentaires tels que `tweet.created_at` ou `tweet.lang`, vous devrez les demander explicitement en utilisant un paramètre `fields`.

Nous avons ajouté à notre [dictionnaire de données X API v2](/fr/x-api/fundamentals/data-dictionary) un guide sur l&#39;utilisation conjointe des [champs et expansions](/fr/x-api/fundamentals/data-dictionary#how-to-use-fields-and-expansions).

Le tableau ci-dessous présente les champs et expansions disponibles pour l&#39;endpoint de recherche :

| Endpoint | Champs | Expansions |
| :--- | :--- | :--- |
| /2/lists/:id/tweets | `tweet.fields`, `user.fields` | `author_id` |

<div id="pagination">
  ### Pagination
</div>

La recherche de Publications d’une Liste peut renvoyer un grand volume de données. Pour garantir que nous renvoyons des résultats cohérents et performants à tout moment, nous utilisons la pagination. La pagination est une fonctionnalité des endpoints de X API v2 qui renvoient plus de résultats qu&#39;une seule réponse ne peut en contenir. Lorsque cela se produit, les données sont renvoyées sous la forme d&#39;une série de « pages ». En savoir plus sur la façon de [paginer les résultats.](/fr/x-api/fundamentals/pagination)
