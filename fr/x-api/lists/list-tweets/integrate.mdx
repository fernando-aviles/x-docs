  ## Concepts clés

<div id="authentication">
  ### Authentification
</div>

Tous les endpoints de X API v2 exigent que vous authentifiiez vos requêtes avec un ensemble d&#39;identifiants, également appelés clés et jetons. Vous pouvez utiliser OAuth 1.0a User Context, App only ou OAuth 2.0 Authorization Code avec PKCE pour authentifier vos requêtes vers cet endpoint.

[OAuth 1.0a User Context](/fr/resources/fundamentals/authentication#oauth-1-0a-2), ce qui signifie que vous devez utiliser un ensemble de clés d&#39;API et de jetons d&#39;accès utilisateur pour effectuer une requête avec succès. Les jetons d&#39;accès doivent être associés à l&#39;utilisateur pour le compte duquel vous effectuez la requête. Si vous souhaitez générer un ensemble de jetons d&#39;accès pour un autre utilisateur, celui-ci doit autoriser votre App en utilisant le [flux OAuth à 3 volets](/fr/resources/fundamentals/authentication#obtaining-access-tokens-using-3-legged-oauth-flow).

Veuillez noter qu&#39;OAuth 1.0a peut être difficile à utiliser. Si vous ne maîtrisez pas bien cette méthode d&#39;authentification, nous vous recommandons d&#39;utiliser une [bibliothèque](/fr/x-api/tools-and-libraries/overview), un outil comme Postman, ou d&#39;utiliser OAuth 2.0 ou App only pour authentifier vos requêtes.

[OAuth 2.0 Authorization Code with PKCE](/fr/resources/fundamentals/authentication#oauth-2-0-authorization-code-flow-with-pkce-2) permet un contrôle accru sur le périmètre d&#39;autorisation (scope) d&#39;une application, ainsi que sur les flux d&#39;autorisation entre plusieurs appareils. OAuth 2.0 vous permet de choisir des scopes précis et granulaires qui vous donnent des permissions spécifiques au nom d&#39;un utilisateur.

Pour activer OAuth 2.0 dans votre App, vous devez l&#39;activer dans les paramètres d&#39;authentification de votre App, accessibles dans la section App settings du Developer Console.

[App only](/fr/resources/fundamentals/authentication#app-only-authentication-and-oauth-2-0-bearer-token) exige simplement que vous transmettiez un [App only Access Token](/fr/resources/fundamentals/authentication#app-only-authentication-and-oauth-2-0-bearer-token) avec votre requête. Vous pouvez soit générer un App only Access Token directement au sein d&#39;une App développeur, soit en générer un en utilisant l&#39;endpoint [POST oauth2/token](/fr/resources/fundamentals/authentication#post-oauth2-token).

<div id="developer-console-projects-and-developer-apps">
  ### Developer Console, Projets et Apps développeur
</div>

Pour obtenir un ensemble d&#39;identifiants d&#39;authentification compatibles avec les endpoints de X API v2, vous devez [créer un compte développeur](https://developer.x.com/en/portal/petition/essential/basic-info), configurer un [Projet](/fr/resources/fundamentals/developer-apps) dans ce compte, puis créer une [App développeur](/fr/resources/fundamentals/developer-apps) dans ce Projet. Vous pourrez ensuite trouver vos clés et jetons dans votre App développeur.

<div id="rate-limits">
  ### Limites de débit
</div>

Chaque jour, des dizaines de milliers de développeurs envoient des requêtes vers l’X API. Pour aider à gérer le volume considérable de ces requêtes, des [limites de débit](https://developer.x.com/x-api/fundamentals/rate-limits) sont appliquées à chaque endpoint, ce qui limite le nombre de requêtes que vous pouvez effectuer pour le compte de votre application ou pour le compte d’un utilisateur authentifié.

Cet endpoint est soumis à des limites de débit à la fois au niveau de l’App et au niveau de l’utilisateur. La limite de débit au niveau de l’App signifie que vous, en tant que développeur, ne pouvez effectuer qu’un certain nombre de requêtes vers cet endpoint sur une période donnée depuis une App donnée (en utilisant soit l’API Key et l’API Secret Key, soit le Bearer Token). La limite de débit au niveau de l’utilisateur signifie que l’utilisateur authentifié pour le compte duquel vous effectuez la requête ne peut effectuer une opération de recherche de publications de liste qu’un certain nombre de fois, toutes Apps développeur confondues.

Le tableau ci-dessous présente les limites de débit pour chaque endpoint.

| Endpoint | Méthode HTTP | Limite de débit |
| :--- | :--- | :--- |
| /2/lists/:id/tweets | GET | 900 requêtes par tranche de 15 minutes |

<div id="fields-and-expansions">
  ### Champs et expansions
</div>

L’endpoint GET de X API v2 permet aux utilisateurs de sélectionner précisément quelles données ils souhaitent récupérer depuis l’API à l’aide d’un ensemble d’outils appelés `fields` et `expansions`. Le paramètre `expansions` vous permet d’étendre les objets référencés dans le payload. Par exemple, la consultation des Publications d’une Liste vous permet de récupérer les [expansions](/fr/x-api/fundamentals/expansions) suivantes :

* `author_id`

Le paramètre `fields` vous permet de sélectionner précisément quels [champs](/fr/x-api/fundamentals/fields) au sein des différents objets de données vous souhaitez recevoir. Cet endpoint renvoie principalement des objets de type Publication. Par défaut, l’objet Publication renvoie les champs `id` et `text`. Pour recevoir des champs supplémentaires tels que `tweet.created_at` ou `tweet.lang`, vous devrez les demander explicitement à l’aide du paramètre `fields`.

Nous avons ajouté à notre [dictionnaire de données X API v2](/fr/x-api/fundamentals/data-dictionary) un guide sur l’utilisation conjointe des [champs et expansions](/fr/x-api/fundamentals/data-dictionary#how-to-use-fields-and-expansions).

Le tableau ci-dessous présente les champs et expansions disponibles pour l’endpoint de recherche :

| Endpoint | Champs | Expansions |
| :--- | :--- | :--- |
| /2/lists/:id/tweets | `tweet.fields`, `user.fields` | `author_id` |

<div id="pagination">
  ### Pagination
</div>

La recherche de Publications d’une Liste peut renvoyer beaucoup de données. Pour garantir des résultats cohérents et performants à tout moment, nous utilisons la pagination. La pagination est une fonctionnalité des endpoints X API v2 qui renvoient plus de résultats qu&#39;il n&#39;est possible d&#39;en inclure dans une seule réponse. Lorsque cela se produit, les données sont renvoyées sous la forme d&#39;une série de « pages ». Pour en savoir plus sur la manière de [parcourir les résultats grâce à la pagination.](/fr/x-api/fundamentals/pagination)
