Ce guide vous aide à migrer de l’ancienne Enterprise Account Activity API vers Account Activity API v2. Les fonctionnalités principales restent les mêmes, mais la structure des endpoints et les méthodes d’authentification ont été mises à jour afin d’être cohérentes avec X API v2.

<div id="summary-of-changes">
  ### Résumé des modifications
</div>

* **Format d’API** : les endpoints utilisent le chemin de base /2/account\_activity/ au lieu de /1.1/account\_activity/.  
* **Gestion des webhooks** : la création, le listing, la validation (CRC) et la suppression des webhooks sont gérées par la [V2 Webhooks API](https://github.com/m-rosinsky/XWebhookTest/blob/main/app.py).  
* **Authentification** : les endpoints V2 requièrent soit :  
  * **OAuthUser** (OAuth à 3 étapes) pour les actions spécifiques à un utilisateur (par exemple, abonner un utilisateur).  
  * **OAuth2 App Only** (Bearer Token) pour les actions au niveau de l’application (par exemple, lister/supprimer des abonnements).  
  * V1.1 utilisait des exigences variables, souvent OAuth 1.0a.  
* **Correspondance des endpoints** :

| Endpoint V1.1 | Équivalent / action V2 | Notes |
| ----- | ----- | ----- |
| POST /1.1/account\_activity/webhooks.json?url=\<URL\> | POST /2/webhooks | [Docs](https://docs.x.com/x-api/webhooks/introduction). Nécessite OAuth2AppOnly. |
| GET /1.1/account\_activity/webhooks.json | GET /2/webhooks | [Docs](https://docs.x.com/x-api/webhooks/introduction). Nécessite OAuth2AppOnly. |
| PUT /1.1/account\_activity/webhooks/:webhook\_id.json | PUT /2/webhooks/:webhook\_id | Déclenche un CRC. [Docs](https://docs.x.com/x-api/webhooks/introduction). Nécessite OAuth2AppOnly. |
| DELETE /1.1/account\_activity/webhooks/:webhook\_id.json | DELETE /2/webhooks/:webhook\_id | [Docs](https://docs.x.com/x-api/webhooks/introduction). Nécessite OAuth2AppOnly. |
| POST /1.1/account\_activity/webhooks/:webhook\_id/subscriptions/all.json | POST /2/account\_activity/webhooks/:webhook\_id/subscriptions/all | Nécessite OAuthUser. |
| GET /1.1/account\_activity/subscriptions/count.json | GET /2/account\_activity/subscriptions/count | Nécessite OAuth2AppOnly. |
| GET /1.1/account\_activity/webhooks/:webhook\_id/subscriptions/all.json | GET /2/account\_activity/webhooks/:webhook\_id/subscriptions/all | Nécessite OAuthUser. |
| GET /1.1/account\_activity/webhooks/:webhook\_id/subscriptions/all/list.json | GET /2/account\_activity/webhooks/:webhook\_id/subscriptions/all/list | Nécessite OAuth2AppOnly. |
| DELETE /1.1/account\_activity/webhooks/:webhook\_id/subscriptions/:user\_id/all | DELETE /2/account\_activity/webhooks/:webhook\_id/subscriptions/:user\_id/all | Nécessite OAuth2AppOnly. |
| DELETE /1.1/account\_activity/webhooks/:webhook\_id/subscriptions/all | Obsolète / pas d’équivalent direct | Utilisez des suppressions individuelles ou supprimez le webhook via DELETE /2/webhooks/:webhook\_id. |

* **Formats de réponse** : examinez les structures de réponse de réussite et d’erreur dans la documentation AAAPI.

Lors de la migration, mettez à jour votre code pour utiliser les nouveaux chemins de base, ajustez les flux d’authentification et gérez les webhooks à l’aide de la [V2 Webhooks API](https://docs.x.com/x-api/webhooks/introduction).

<div id="how-to-migrate">
  ### Comment migrer
</div>

* **Choisir un forfait**:  
  * Choisissez le forfait Enterprise ou Self-serve pour l'accès à l'API Account Activity, en tenant compte des éléments suivants :  
    * Nombre de webhooks nécessaires.  
    * Abonnements ou utilisateurs autorisés actuels/prévus.  
    * Nombre d'applications X clientes.  
    * Niveau d'assistance souhaité (forum vs. support Enterprise dédié en 1:1).  
    * Détails de tarification (contactez l’équipe commerciale pour Enterprise).  
* **Mettre à jour votre authentification vers OAuth 2.0**:  
  * Assurez-vous que votre application X dispose des autorisations « Read, Write, and Access Direct Messages ».  
  * Passez à OAuth 2.0 pour les endpoints v2. Réautorisez les utilisateurs si les scopes d’autorisation ont changé.  
  * Utilisez la Console de Développement pour gérer :  
    * OAuth 2.0 Access Token.  
    * Client ID et Client Secret.  
* **Vérifier ou reconfigurer votre webhook**:  
  * Utilisez votre URL de webhook existante ou configurez-en une nouvelle (par exemple, https://your\_domain.com/webhook/twitter).  
  * Suivez la [documentation de l'API Webhooks v2](https://docs.x.com/x-api/webhooks/introduction) pour enregistrer et gérer votre webhook.  
* **Exemples d'applications :**  
  * [Simple webhook server](https://github.com/m-rosinsky/XWebhookTest/blob/main/app.py)  
    * Un simple script Python qui montre comment répondre à la vérification CRC et accepter les événements POST.  
  * [Account Activity API sample dashboard](https://github.com/xdevplatform/account-activity-dashboard-enterprise/tree/master)  
    * Une application web écrite avec [bun.sh](http://bun.sh) qui vous permet de gérer les webhooks, les abonnements et de recevoir des événements en direct directement dans l'application.
