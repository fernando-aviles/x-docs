<div id="overview">
  ## Vue d’ensemble
</div>

[`Enterprise`](https://developer.x.com/en/products/x-api/enterprise)

*Ceci est une API Enterprise disponible uniquement dans le cadre de nos niveaux d’accès gérés. Pour utiliser cette API, vous devez d’abord créer un compte avec notre équipe commerciale Enterprise. [En savoir plus](/fr/x-api/enterprise-gnip-2.0/enterprise-gnip)*

L’Engagement API fournit un accès aux indicateurs d’impressions et d’engagement sur les Publications. Alors que la plupart des indicateurs et des endpoints exigent une authentification via [OAuth 1.0a User Context](/fr/resources/fundamentals/authentication), vous pouvez accéder aux indicateurs publics de favoris, Retweets, réponses et vues vidéo à l’aide d’[OAuth 2.0 Bearer Token](/fr/resources/fundamentals/authentication#oauth-2-0) et de l’endpoint /totals.  

**Remarque :** Vous pouvez observer des différences entre les données affichées sur certains tableaux de bord Web de X et les données renvoyées par l’Engagement API. Ces différences se produisent parce que les tableaux de bord Web affichent généralement uniquement les engagements et/ou les impressions qui ont eu lieu dans l’intervalle de temps sélectionné. Par exemple, un tableau de bord Web peut afficher l’engagement sur des Publications sur la durée d’un mois calendaire, tandis que l’Engagement API peut afficher des engagements qui dépassent la durée de ce mois, mais restent dans l’intervalle de temps demandé. Dans ces cas, l’Engagement API doit être considérée comme la source de référence faisant foi.
 

<div id="request-endpoints">
  ### Points de terminaison des requêtes
</div>

L’API Engagement comporte trois points de terminaison :

<div id="current-totals-totals">
  #### Totaux actuels : [/totals]
</div>

* Les requêtes renvoient un total pour les impressions et un total pour les engagements pour les Publications demandées
* Limité aux métriques suivantes : Impressions, Engagements, Favoris, Réponses, Retweets, Tweets cités et Vues vidéo
* Prend en charge la récupération des métriques **Impressions** et **Engagements** pour les Publications créées **au cours des 90 derniers jours** en utilisant OAuth 1.0a User Context
* Prend en charge la récupération des métriques **Favoris, Retweets, Tweets cités, Réponses** et **Vues vidéo** pour **n’importe quelle Publication** en utilisant OAuth 2.0 Bearer Token
* Les résultats sont basés sur le total actuel d’impressions et d’engagements au moment où la requête est effectuée
* Idéal pour alimenter un tableau de bord et pour calculer les taux d’engagement sur une variété de @handles
* Prend en charge la récupération de métriques pour jusqu’à 250 Publications par requête
   

<div id="last-28-hours-28hr">
  #### 28 dernières heures : [/28hr]
</div>

* Les requêtes peuvent renvoyer une métrique totale pour les impressions, une métrique totale pour les interactions, ainsi qu’une ventilation des métriques d’interaction individuelles qui se sont produites au cours des 28 dernières heures
* Les data peuvent être regroupées par ID de Publication et, sous forme de séries chronologiques agrégées, par jour ou par heure
* Idéal pour le suivi des performances du contenu récemment créé
* Prend en charge toutes les métriques disponibles
* Permet de demander des métriques pour jusqu’à 25 Publications par requête
   

<div id="historical-historical">
  #### Historique : [/historical]
</div>

* Les requêtes peuvent renvoyer les impressions, les engagements et une répartition des métriques d’engagement individuelles pour la dernière année écoulée, en fonction du moment de l’engagement (et non de la date de création de la Publication).
* Les requêtes prennent en charge des paramètres de date de début et de date de fin, offrant la flexibilité de cibler une plage temporelle spécifique d’une durée allant jusqu’à 4 semaines.
* Les données d’engagement des Publications sont limitées aux 365 derniers jours.
* Les données peuvent être regroupées par identifiant de Publication et, dans des séries temporelles agrégées, par jour ou par heure.
* Idéal pour évaluer les performances récentes par rapport à une référence historique ou développer une vue historique des performances d’un @handle.
* Prend en charge toutes les métriques disponibles.
* Permet de demander les métriques pour jusqu’à 25 Publications par requête.

<div id="engagement-groupings">
  ### Regroupements d’engagement
</div>

Les regroupements permettent d’organiser de manière personnalisée les métriques d’engagement renvoyées. Vous pouvez inclure au maximum 3 regroupements par requête. Vous pouvez choisir de regrouper les métriques selon une ou plusieurs des valeurs suivantes :

*Les trois endpoints prennent en charge :*

* tweet.id
* engagement.type
   

*Les endpoints `/28hr` et `/historical` peuvent fournir des métriques sous forme de séries temporelles et prennent donc en charge :*

* engagement.day
* engagement.hour

Pour en savoir plus sur les regroupements, consultez la page [Engagement API Grouping](/fr/x-api/enterprise-gnip-2.0/fundamentals/engagement-api#engagement-api-groupings) dans la section Guides.

<div id="introduction">
  #### Introduction
</div>

L’objectif de cette documentation est de présenter aux développeurs les principes de base de l’intégration à l’API Engagement. Nous commencerons par expliquer les « pourquoi » de l’intégration, puis nous approfondirons les aspects techniques du « comment ».

<div id="what-does-the-engagement-api-provide">
  ##### **Que fournit l’API Engagement ?**
</div>

* L’API Engagement fournit des données d’impressions et d’engagement pour les Publications appartenant à n’importe quel compte X au cours des 90 derniers jours, à condition que ce compte ait autorisé votre application à demander des métriques en son nom à l’aide de [3-legged OAuth](/fr/resources/fundamentals/authentication#obtaining-access-tokens-using-3-legged-oauth-flow). Cette solution puissante, mais facile à implémenter, donne un accès immédiat aux impressions et aux engagements détaillés, tels que les clics sur des URL, les clics sur des #hashtags, et bien d’autres encore.
* L’API Engagement fournit des métriques agrégées totales pour les favoris, les Retweets, les Tweets cités, les réponses et les vues de vidéos pour toute Publication. C’est un moyen efficace d’obtenir des données d’engagement de base sur n’importe quelle Publication ou collection de Publications.
* L’API Engagement apporte une nouvelle valeur aux plateformes d’écoute des réseaux sociaux, de marketing et de publication de contenu en permettant aux clients de mesurer le ROI sur X en mesurant efficacement les performances du contenu à l’aide de plus de 15 métriques de performance.
* L’API Engagement est une API de type requête/réponse qui permet aux développeurs d’applications d’envoyer des requêtes avec des Post IDs, les métriques souhaitées et une période donnée, pour lesquelles l’API renvoie immédiatement des données.
   

<div id="why-integrate-example-use-cases">
  ##### **Pourquoi intégrer ? Exemples de cas d’usage**
</div>

* Comprendre la portée totale de votre contenu pour voir combien de personnes le consultent. Voir combien de personnes regardent les vidéos, cliquent sur les liens, cliquent sur les hashtags ou installent vos applications.
* Générer à la fois des métriques d’engagement globales et des séries temporelles.
* Comprendre les métriques d’engagement de base (favoris, Retweets, Tweets cités, réponses) pour n’importe quelle Publication publique.
* Utiliser ces métriques pour déterminer quels types de Publications fonctionnent, afin de pouvoir les publier plus souvent et d’obtenir plus d’impressions et plus d’engagements pour votre contenu.
* Automatiser certains comportements marketing (comme Retweeter du contenu depuis un autre compte que vous possédez) chaque fois qu’une de vos Publications atteint 100 Likes, ou un autre seuil.
* Établir des benchmarks et comparer vos campagnes entre elles comme outil de tests A/B.
* Analyser quel type de contenu trouve le plus d’écho auprès de vos clients pour votre service client, afin de déterminer comment et quand répondre.
* Afficher des analyses pour le contenu publié depuis votre plateforme.
   

L’[Engagement API a été lancée en 2016](https://blog.x.com/official/en_us/a/2016/gnip-s-engagement-api-is-now-generally-available.html) et a été la première X API à fournir ces métriques d’engagement approfondies à grande échelle. <div id="integrating-the-engagement-api">
  #### Intégrer l’API Engagement
</div>

<div id="introduction-to-api">
  ##### **Introduction à l’API**
</div>

L’Engagement API est une API RESTful simple qui reçoit des requêtes encodées en JSON et renvoie des métriques d’engagement encodées en JSON. Les requêtes se composent de trois parties principales (suivez les liens pour plus de documentation) :

* Tableau d’***identifiants de Publications***.
* Tableau spécifiant les [types de métriques](https://developer.x.com/en/docs/x-api/v1/metrics/get-tweet-engagement/overview#EngagementTypes) qui vous intéressent. Les types incluent des éléments tels que « impressions », « retweets », « hashtag&#95;clicks » et « user&#95;follows ».
* [Engagement groupings](/fr/x-api/enterprise-gnip-2.0/fundamentals/engagement-api#engagement-api-groupings), qui est une structure JSON indiquant comment vous souhaitez organiser les données d’engagement dans la réponse de l’API.

Dans de nombreux cas, les Engagement Types et Groupings restent relativement constants d’une requête à l’autre, seuls les identifiants de Publications étant mis à jour.

L’Engagement API propose [trois endpoints](https://developer.x.com/en/docs/x-api/v1/metrics/get-tweet-engagement/overview#RequestEndpoints) :

* **Totals** - Fournit les totaux globaux des engagements pour les Publications. Certaines métriques sont disponibles pour toutes les Publications, tandis que d’autres ne sont disponibles que pour les 90 derniers jours.
* **28 hour** - Fournit des métriques d’engagement en séries temporelles pour les 28 dernières heures.
* **Historical** - Fournit des métriques d’engagement en séries temporelles pour une durée allant jusqu’à quatre semaines consécutives pour les Publications publiées depuis le 1er septembre 2014.

L’endpoint **/totals** prend en charge des requêtes de métriques pour jusqu’à **250 Publications par requête**. Les endpoints **/28hour** et **/historical** prennent en charge jusqu’à **25 Publications par requête**.

Après avoir expliqué comment accéder à l’Engagement API, nous passerons en revue la création d’une requête d’API, fournirons une présentation générale d’OAuth, ainsi que des liens vers d’autres ressources techniques.

La première étape consiste à construire la requête API en JSON, composée des identifiants de ces deux Publications placés dans un tableau, d’un tableau de types d’engagement qui nous intéressent et d’un objet JSON « groupings » nommé de manière personnalisée, qui indique comment nous voulons que les métriques soient organisées dans la réponse. Voici à quoi ressemble notre requête :

```json
{
  "tweet_ids": [
    1260294888811347969, 850006245121695744
  ],
  "engagement_types": [
    "retweets", "quote_tweets", "favorites", "replies"
  ],
  "groupings": {
    "engagement-types-by-id": {
      "group_by": [
        "Tweet.id", "engagement.type"
      ]
    }
  }
}
```

Pour récupérer ces métriques totales, nous envoyons une requête POST au format JSON à l’endpoint https://data-api.x.com/insights/engagement/totals.

Nous incluons les en-têtes suivants pour indiquer que notre requête est encodée en JSON et qu’elle est compressée avec gzip (les corps de requête peuvent devenir volumineux) :

* Content-Type: application/json
* Accept-Encoding: gzip
   

Lorsque nous effectuons des requêtes, nous nous authentifions à l’aide d’OAuth, que nous aborderons plus en détail dans la section suivante.

L’API renvoie la réponse suivante :

```json
{
  "grouping name": {
    "1260294888811347969": {
      "favorites": "17111",
      "quote_tweets": "3254",
      "replies": "1828",
      "retweets": "5218"
    },
    "850006245121695744": {
      "favorites": "492",
      "quote_tweets": "66",
      "replies": "42",
      "retweets": "324"
    }
  }
}
```

Notez que la réponse contient les métriques demandées dans la structure décrite par les définitions de « groupings », avec les métriques répertoriées d’abord par ID de Publication, puis par type d’engagement au niveau suivant.

C’était assez simple. Si vous débutez avec l’authentification via OAuth, consultez la section suivante.

<div id="authenticating-with-oauth">
  #### Authentification avec OAuth
</div>

OAuth est un standard d’authentification très répandu dans le secteur technologique. Si vous utilisez déjà OAuth (peut-être avec d’autres X API), vous utilisez probablement une bibliothèque OAuth spécifique à un langage qui masque tous les détails complexes. Si vous découvrez OAuth, consultez notre page [Oauth with the X API](/fr/resources/fundamentals/authentication) ou rendez-vous directement sur [https://oauth.net](https://oauth.net/) pour en savoir plus. Nous vous recommandons ensuite de trouver une bibliothèque OAuth pour le langage d’intégration de votre choix et de commencer ainsi. Avec ces bibliothèques, le processus d’authentification consiste généralement à configurer vos clés et jetons, à créer un objet HTTP, puis à effectuer des requêtes avec cet objet.

Par exemple, dans l’écosystème Ruby, le pseudo-code suivant illustre une procédure pour créer une application compatible OAuth à l’aide du gem Ruby « oauth » et effectuer une requête POST :

```js
require 'oauth'

#Assemble JSON request (as above).
request = make_json_request()

#Build an app consumer object with my app consumer key and secret.
consumer = OAuth::Consumer.new(keys['consumer_key'], keys['consumer_secret'], {:site => ‘https://data-api.x.com’})
#Construire un jeton utilisateur avec les jetons fournis par le compte accordant la permission. Si vous effectuez une #requête application uniquement (vérification de Tweets ne nécessitant pas de permission avec le point de terminaison /totals), cette étape peut être #ignorée.
token = {:oauth_token => keys['access_token'], :oauth_token_secret => keys['access_token_secret']}

#Create oauth-enabled app object.
app = OAuth::AccessToken.from_hash(consumer, token)
#Make POST request.
result = app.post(“/insights/engagement/totals", request, {"content-type" => "application/json", "Accept-Encoding" => "gzip"})
```

L’API Engagement prend en charge à la fois l’authentification applicative uniquement et l’authentification avec contexte utilisateur. Si vous collectez des métriques d’engagement pour des Publications publiques qui ne vous appartiennent pas avec le point de terminaison /totals, aucune autorisation utilisateur n’est requise et vous pouvez utiliser l’authentification applicative uniquement. Dans ce cas, vous utiliserez uniquement la clé et le secret de votre application pour vous authentifier.

OAuth permet également à une application d’effectuer une requête d’API « au nom d’un autre utilisateur », à l’aide de jetons liés à cet utilisateur. Si vous générez des métriques d’engagement pour des Publications qui vous appartiennent, c’est-à-dire des Publications publiées par un utilisateur pour lequel vous disposez de jetons utilisateur, vous effectuerez des requêtes avec un contexte utilisateur, ce qui signifie une authentification à la fois avec les clés de votre application et avec des jetons d’accès spécifiques à l’utilisateur. Ces jetons d’accès utilisateur sont généralement fournis via le processus [Se connecter avec X](/fr/resources/fundamentals/authentication#log-in-with-x) ou obtenus directement auprès de l’utilisateur (veuillez noter que vous devez utiliser [twurl](https://github.com/xdevplatform/xurl) si vous obtenez les jetons directement auprès de l’utilisateur). Une fois que l’utilisateur vous a fourni ses jetons, ceux-ci n’expirent pas et peuvent être utilisés avec l’API Engagement pour effectuer des requêtes en son nom, tant que l’utilisateur ne réinitialise pas ses jetons et ne change pas son mot de passe. Dans ce cas, il devra vous fournir de nouveaux jetons.

Vous pouvez consulter quelles métriques nécessitent quel type d’authentification via [ce tableau](/fr/x-api/enterprise-gnip-2.0/fundamentals/engagement-api#engagement-api-groupings).

<div id="selecting-an-engagement-api-endpoint">
  ### Sélection d’un endpoint de l’Engagement API
</div>

L’Engagement API propose trois endpoints distincts :

* **[Totals](/fr/x-api/enterprise-gnip-2.0/fundamentals/engagement-api#post-insights-engagement)** - fournit des totaux globaux pour un ensemble de métriques sélectionnées issues de Publications « owned » ou « unowned ». Certaines métriques sont disponibles pour toutes les Publications, tandis que d’autres ne sont disponibles que pour les Publications publiées au cours des 90 derniers jours. Prend en charge 250 Publications par requête.
* **[28 hour](/fr/x-api/enterprise-gnip-2.0/fundamentals/engagement-api#post-insights-engagement)** - fournit des métriques d’engagement en séries temporelles pour les Publications « owned » des 28 dernières heures. Prend en charge 25 Publications par requête.
* **[Historical](/fr/x-api/enterprise-gnip-2.0/fundamentals/engagement-api#post-insights-engagement-historical)** - fournit des métriques d’engagement en séries temporelles sur une période allant jusqu’à quatre semaines consécutives pour des Publications « owned » publiées depuis le 1er septembre 2014. Prend en charge 25 Publications par requête.
   

Chaque endpoint possède ses propres caractéristiques. Que vous envisagiez d’utiliser les trois ou que vous essayiez de déterminer lequel correspond le mieux à votre cas d’usage, il est important de comprendre les différences entre eux.

Ci‑dessous, nous présentons quelques concepts clés, explorons plus en détail les trois endpoints, puis proposons des exemples de cas d’usage qui se rattachent généralement à un endpoint spécifique. Nous espérons que ces informations vous aideront à intégrer plus efficacement les trois endpoints, ou à décider quel endpoint unique correspond le mieux à votre objectif.
 

<div id="key-concepts">
  #### Concepts clés
</div>

Plusieurs concepts clés permettent d’illustrer les différentes fonctionnalités des trois endpoints de l’Engagement API, ainsi que les données qu’ils fournissent.
 

<div id="impressions-and-engagement-metrics">
  ##### Impressions et indicateurs d’engagement
</div>

Les impressions représentent le nombre de fois qu’une Publication donnée a été vue sur la plateforme X dans un contexte organique. Les impressions générées à partir de Publications vues dans un contexte promu ou payant ne sont pas incluses. Avant l’Engagement API, les impressions de Publication ne représentaient qu’une mesure des vues potentielles. Elles étaient basées sur le comptage des abonnés du compte de l’auteur et de ceux de tout compte qui retweetait le contenu. Elles ne prenaient pas en compte la situation courante où un utilisateur donné ne voit en réalité pas la Publication.

Les indicateurs d’impressions générés par l’Engagement API sont une mesure réelle du nombre de fois qu’une Publication a été effectivement affichée. Si un abonné à votre compte passe à côté de votre Publication, cela ne compte pas comme une impression.

L’Engagement API fournit des indicateurs sur 14 [types d’indicateurs](/fr/x-api/enterprise-gnip-2.0/fundamentals/engagement-api#available-metrics) d’engagement distincts, chacun représentant une action précise qu’un utilisateur peut effectuer lorsqu’une Publication lui est présentée. Cela inclut le fait de retweeter, d’aimer, de répondre, de cliquer sur des entités comme les #hashtags, les liens et les médias, de s’abonner à l’auteur et de consulter le profil de l’auteur. L’ensemble de ces actions individuelles est agrégé dans un indicateur unique nommé Engagements.

<div id="owned-and-unowned-x-content">
  ##### Contenu X propriétaire et non propriétaire
</div>

L’API Engagement établit une distinction claire entre les Publications propriétaires et non propriétaires. Les Publications propriétaires sont des Publications publiées depuis votre compte ou des Publications pour lesquelles vous avez obtenu l’autorisation de demander des données d’engagement. Comme pour les autres API X, vous obtenez cette autorisation lorsque d’autres utilisateurs/comptes X partagent des jetons d’accès qui vous permettent d’effectuer des requêtes API en leur nom. Un moyen courant d’obtenir ces jetons consiste à utiliser le [processus « Sign in with X »](/fr/resources/fundamentals/authentication#log-in-with-x).

L’endpoint /totals fournit des données d’engagement pour les Publications propriétaires et non propriétaires. Pour les Publications non propriétaires, vous pouvez demander les métriques d’engagement qui sont disponibles publiquement dans l’affichage d’une Publication : Favorite, Retweet et Reply. Pour ces métriques, la valeur ajoutée de l’API Engagement est de permettre de récupérer ces métriques à grande échelle de manière automatisée. Pour les Publications propriétaires, l’endpoint /totals fournit également les métriques Impression et Engagement (total).

Les endpoints /28hr et /historical fournissent des métriques uniquement pour les Publications propriétaires, ce qui signifie que vous devez transmettre un contexte utilisateur lorsque vous effectuez une requête vers ces endpoints.

<div id="total-and-time-series-engagement-data">
  ##### Données d’engagement totales et en séries temporelles
</div>

L’endpoint /totals fournit, comme son nom l’indique, uniquement des totaux globaux pour ses types d’engagement. Ses chiffres représentent les totaux actualisés depuis la mise en ligne de la Publication. Si une Publication vient d’être publiée et que vous demandez ses métriques à plusieurs reprises, ces totaux changeront généralement à chaque requête.

Les endpoints /28hr et /historical peuvent fournir à la fois des totaux globaux et des données sous forme de séries temporelles. Lorsque vous demandez des données en séries temporelles, les métriques d’engagement peuvent être agrégées sous forme de données quotidiennes ou horaires.   

Consultez notre documentation sur les [regroupements d’engagement](/fr/x-api/enterprise-gnip-2.0/fundamentals/engagement-api#engagement-api-groupings) pour savoir comment demander des données en séries temporelles avec les endpoints /28hr et /historical.

<div id="endpoints-and-example-use-cases">
  #### Points de terminaison et exemples de cas d’usage
</div>

Compte tenu des caractéristiques et des différences évoquées ci-dessus, chaque point de terminaison correspond généralement à différents types de cas d’usage. Pour vous aider à déterminer quel point de terminaison convient le mieux à votre cas d’usage particulier, vous trouverez ci-dessous quelques exemples de demandes utilisateur et le point de terminaison qui y répond le mieux.

<div id="totals">
  ##### **/totals**
</div>

* J’ai seulement besoin d’accéder à certains types de métriques (Impressions, Engagements, Favoris, Retweets, Quote Tweets, Réponses et vues vidéo).
* J’ai besoin d’accéder à des données d’engagement de base pour n’importe quelle Publication, pas seulement les Publications qui m’appartiennent.
* Je veux comparer les performances avec celles d’un concurrent.
* Je veux suivre des statistiques d’engagement de base pour un hashtag ou une campagne qui inclut des Publications qui ne m’appartiennent pas.
* Je n’ai pas besoin de données ventilées par jour ou par heure, j’ai seulement besoin du total actuel au moment où j’effectue une requête.
* J’ai besoin d’une seule métrique à afficher dans un rapport ou un tableau de bord et je ne veux pas stocker de données.
* Je veux afficher les données au chargement de la page, et j’ai seulement besoin d’effectuer une requête et d’obtenir une Réponse.
* J’ai besoin d’accéder aux données pour des centaines de milliers ou des millions de Publications par jour.
   

<div id="28hr">
  ##### **/28hr**
</div>

* J&#39;ai besoin d&#39;accéder aux 17 types de métriques.
* Je veux afficher des données pour les Publications très récentes publiées au cours des 28 dernières heures.
* J&#39;ai une tâche qui s&#39;exécute une fois par jour pour obtenir les données qui m&#39;intéressent et je n&#39;ai besoin d&#39;obtenir des données que pour le dernier jour.
* J&#39;ai besoin que les métriques soient ventilées par jour ou par heure.
* Je veux afficher, dans un tableau de bord, des séries temporelles d&#39;activité ventilées par heure.
* J&#39;ai besoin d&#39;un niveau d&#39;accès élevé pour des centaines de milliers de Publications par jour.
* Je dispose de capacités de stockage et je peux actualiser les données une fois par jour et conserver un cumul permanent.
   

<div id="historical">
  ##### **/historical**
</div>

* J’ai besoin d’accéder aux 17 types de métriques.
* J’ai besoin d’obtenir des données historiques pour des Publications créées remontant jusqu’en septembre 2014.
* Je veux afficher une analyse historique détaillée qui compare les campagnes.
* J’ai besoin que les métriques soient détaillées par jour ou par heure.
* Je n’ai pas besoin d’un niveau d’accès élevé à l’Engagement API et j’ai seulement besoin d’obtenir des données pour quelques centaines ou milliers de Publications par jour.

<div id="engagement-api-key-characteristics">
  ### Caractéristiques clés de l&#39;API Engagement
</div>

* **API RESTful** fournissant des données JSON, prenant en charge les requêtes POST avec des corps de données JSON.
* **Types de requêtes :** les applications clientes peuvent effectuer les types de requêtes suivants :
  * **Engagements totaux** -- requête HTTP POST vers l&#39;endpoint /totals
  * **Engagements sur les 28 dernières heures** -- requête HTTP POST vers l&#39;endpoint /28hr
  * **Engagements historiques** -- requête HTTP POST vers l&#39;endpoint /historical
* **Authentification OAuth :**
  * [OAuth 1.0 User Context](/fr/resources/fundamentals/authentication) : toutes les métriques disponibles sont accessibles pour les Publications appartenant à un utilisateur qui a autorisé votre application à l&#39;aide de [3-legged OAuth](https://developer.x.com/resources/fundamentals/authentication/obtaining-user-access-tokens). Vous devez utiliser les jetons d&#39;accès de cet utilisateur lors de l&#39;envoi de votre requête.[](/fr/resources/fundamentals/authentication)
  * [OAuth 2.0 Bearer Token](/fr/resources/fundamentals/authentication#oauth-2-0) : certaines métriques (retweets, quote tweets, réponses, favoris et vues vidéo) sont disponibles pour toute Publication publique. 
* **Métadonnées et structure de la requête** : les données de la requête constituent un objet JSON composé d&#39;un tableau d&#39;ID de Publication, d&#39;un tableau de types d&#39;engagement et d&#39;une structure de regroupement d&#39;engagement.
* **Publications par requête :**
  * endpoint /totals : 250 ID de Publication
  * endpoint /28hr : 25 ID de Publication
  * endpoint /historical : 25 ID de Publication
* **Disponibilité des métriques d&#39;engagement :**
  * **/totals** -- totaux des métriques depuis la mise en ligne de la Publication. Les impressions et engagements sont disponibles pour les Publications publiées au cours des 90 derniers jours, tandis que les retweets, quote tweets, réponses, favoris et vues vidéo sont disponibles pour toutes les Publications.
  * **/28hr** -- 28 dernières heures à partir du moment de la requête.
  * **/historical** -- toute période de 28 jours commençant le 1er septembre 2014.
* **Types de métriques** : chaque requête inclut un tableau de [Types de métriques](http://support.gnip.com/apis/engagement_api/overview.html#EngagementTypes). Leur disponibilité dépend de l&#39;endpoint et, dans le cas d&#39;une requête vers l&#39;endpoint /totals, du fait que les Publications soient ou non autorisées par l&#39;utilisateur.
  * endpoint /totals :
    * Toutes les Publications : favoris, retweets, quote tweets, réponses et vues vidéo
    * Nécessite OAuth 1.0a User Context : impressions, engagements, favoris, réponses et retweets
  * endpoints /28hr et /historical (nécessite OAuth 1.0a User Context avec le jeton d&#39;accès du propriétaire de la Publication) : impressions, engagements, favoris, réponses, retweets, clics sur URL, clics sur hashtag, clic sur le détail, clics sur lien permanent, clics sur média, tentatives d&#39;installation d&#39;application, ouvertures d&#39;application, e-mails de Publication, vues vidéo et vues de média
* **Regroupements d&#39;engagement** : chaque requête inclut un tableau de [Regroupements d&#39;engagement](/fr/x-api/enterprise-gnip-2.0/fundamentals/engagement-api#engagement-api-groupings). Avec ces regroupements, vous pouvez personnaliser la façon dont les métriques renvoyées sont organisées. Jusqu&#39;à trois regroupements peuvent être inclus dans chaque requête. Les métriques peuvent être organisées selon les valeurs suivantes :
  * Tous les endpoints : ID de Publication, type d&#39;engagement
  * endpoints /28hr et /historical : ces endpoints fournissent des séries temporelles si ces regroupements supplémentaires sont spécifiés : jour d&#39;engagement, heure d&#39;engagement
* **Attentes en matière d&#39;intégration :** votre équipe sera responsable de ce qui suit.
  * Créer et maintenir une application cliente capable d&#39;envoyer des requêtes HTTP à l&#39;API Engagement qui renvoient des métriques d&#39;engagement pour chaque ID de Publication inclus dans la requête.
* **Limites**
* Les vues vidéo ne sont disponibles que pour les Publications âgées de 1 800 jours ou moins.

<div id="authenticating-with-the-engagement-api">
  ### Authentification avec l’Engagement API
</div>

> **Veuillez noter** : 
>
> X doit activer l’accès à l’Engagement API pour votre App développeur avant que vous puissiez commencer à utiliser l’API. Pour cela, assurez-vous de communiquer l’ID de l’App que vous prévoyez d’utiliser pour l’authentification à votre account manager ou à votre équipe de support technique.

Deux méthodes d’authentification sont disponibles avec l’Engagement API : [OAuth 1.0a](/fr/resources/fundamentals/authentication#oauth-1-0a-2) et [OAuth 2.0 Bearer Token](/fr/resources/fundamentals/authentication#bearer-token-also-known-as-app-only). 

**OAuth 2.0 Bearer Token** (également appelé « application-only ») vous permet d’accéder aux métriques d’engagement disponibles publiquement. Cette méthode d’authentification peut être utilisée pour obtenir les totaux pour les Favorites (alias Likes), Retweets, Quote Tweets, Replies et vues vidéo pour toute Publication publique lors de requêtes vers le [/totals endpoint](/fr/x-api/enterprise-gnip-2.0/fundamentals/engagement-api#post-insights-engagement-totals). 

**OAuth 1.0a** (également appelé « user context ») vous permet d’effectuer des requêtes au nom d’un utilisateur et d’accéder aux métriques d’engagement privées qui appartiennent à l’utilisateur concerné. 

Cette méthode d’authentification est obligatoire pour :

* Toutes les requêtes envoyées vers le [/28hr endpoint](/fr/x-api/enterprise-gnip-2.0/fundamentals/engagement-api#post-insights-engagement-28hr) et le [/historical endpoint](/fr/x-api/enterprise-gnip-2.0/fundamentals/engagement-api#post-insights-engagement-historical)
* L’accès à l’une des métriques privées suivantes : Impressions, Engagements, Media Views, Media Engagements, URL Clicks, Hashtag Clicks, Detail Expands, Permalink Clicks, App Install Attempts, App Opens, Email Post, User Follows et User Profile Clicks

Lorsque vous envoyez une requête avec OAuth 1.0a, vous devez inclure les tokens d’accès (Access Token et Secret) de l’utilisateur qui possède la Publication ou la ressource protégée qui vous intéresse. Si vous ne fournissez pas les bons tokens d’accès utilisateur lors de la demande de données utilisateur protégées, l’Engagement API renverra une erreur `403 Forbidden`.

L’Engagement API ne vous permettra pas de récupérer les données d’engagement pour les [Publications protégées](https://help.x.com/en/safety-and-security/public-and-protected-tweets), même si vous vous authentifiez au nom de l’utilisateur qui possède ces Publications. Toute tentative en ce sens renverra une erreur `400 Bad Request`, avec le message `"Tweet ID(s) are unavailable"`.

Si vous envoyez une requête au nom de votre propre compte X (autrement dit, le compte qui possède l’App développeur), vous pouvez générer les tokens d’accès requis directement depuis la [Developer Console](https://developer.x.com/en/portal/projects-and-apps), sous l’onglet « Keys and tokens » de l’App développeur.

Si vous effectuez une requête au nom de tout autre utilisateur, vous devrez utiliser le flux OAuth en 3 étapes (3-legged OAuth) pour obtenir les tokens d’accès requis. La documentation suivante contient plus d’informations sur la façon de procéder : [OAuth 1.0a: how to obtain a user’s access tokens](/fr/resources/fundamentals/authentication#oauth-1-0a-2).

Pour des exemples supplémentaires, notamment sur la façon de vous authentifier à l’aide d’OAuth 1.0a, consultez le [code Python d’exemple XDevelopers pour l’Engagement API](https://github.com/xdevplatform/enterprise-scripts-python/tree/master/Engagement-API).

<div id="interpreting-the-metrics">
  ### Interpreting the metrics
</div>

**Remarque :** Vous pouvez constater des différences entre les données affichées sur certains tableaux de bord Web de X et les données fournies par l’Engagement API. Ces différences surviennent parce que les tableaux de bord Web n’affichent généralement que les engagements et/ou impressions survenus pendant la période de temps sélectionnée. Par exemple, un tableau de bord Web peut afficher l’engagement sur des Publications au cours d’un mois calendaire, tandis que l’Engagement API peut inclure des engagements qui dépassent la durée de ce mois, mais restent dans la plage de temps demandée. Dans ces cas, l’Engagement API doit être considérée comme la source de référence.
 

<div id="impressions-and-engagement-data">
  #### Données d’impressions et d’engagement
</div>

L’Engagement API fournit des données d’impressions et d’engagement **organiques**.

Les impressions représentent le nombre de fois qu’une Publication donnée a été vue sur la plateforme X dans un contexte organique. Les impressions générées par des Publications vues dans un contexte sponsorisé ou payant ne sont **pas** incluses.

Les engagements représentent le nombre de fois qu’une Publication donnée a fait l’objet d’une interaction de la part d’un visiteur, dans un contexte à la fois **organique** et **sponsorisé**. Les engagements incluent, sans s’y limiter, les Retweets, ajouts aux favoris, réponses, clics sur des URL, clics sur des hashtags, clics sur des mentions et vues de médias. Pour la liste complète des actions d’engagement incluses, veuillez consulter la section Engagement Data. 

Pour calculer un taux d’engagement de référence, utilisez le nombre total d’engagements divisé par le nombre total d’impressions pour une Publication donnée sur la période que vous analysez.

Les données d’impressions et d’engagement ne peuvent être récupérées que pour les Publications provenant de @handles que vous possédez, ou de @handles qui ont autorisé votre application à afficher les détails concernant leurs Publications.  En interne, l’Engagement API suit le nombre de @handles uniques qui ont été demandés par rapport à la limite contractuelle de @handles.  Il est également recommandé de suivre l’utilisation des requêtes @handle côté client tout au long du mois.  

<div id="video-metrics">
  #### Mesures vidéo
</div>

Il existe plusieurs mesures différentes qui représentent les impressions de médias au sein de X. La première est notre mesure de vues vidéo, qui repose sur le standard MRC de 50 % de la vidéo visible pendant au moins deux secondes. La seconde est Media Views, qui inclut toutes les vues (lecture automatique et clic) de vos médias, comptabilisées pour les vidéos, vines, GIF et images.

La mesure de vues vidéo est disponible pour vos propres Publications via les endpoints /28hour et /historical, ainsi que pour toutes les Publications qui ne vous appartiennent pas via l’endpoint /totals. 

Bien que la mesure de vues vidéo au sein de l’interface utilisateur de X utilise le même standard MRC, notez que vous pouvez constater un écart entre la mesure de vues vidéo affichée sur les plateformes détenues et exploitées par X (application mobile et site web) et le nombre que vous recevez via les différents endpoints de l’Engagement API.

* Les vues vidéo fournies par l’endpoint /totals et l’interface utilisateur de X afficheront le nombre de vues vidéo agrégé sur l’ensemble des Publications dans lesquelles la vidéo en question a été publiée. Cela signifie que la mesure fournie via /totals et affichée dans l’interface de X inclut les vues combinées de toute instance où la vidéo a été Retweetée ou republiée dans des Publications distinctes.
* Les vues vidéo fournies par les endpoints /28hour et /historical de l’Engagement API n’incluront que les vues générées par la Publication spécifique pour laquelle vous récupérez les mesures.

<div id="engagement-api-groupings">
  ### Regroupements de l’API Engagement
</div>

Les regroupements permettent d’organiser de manière personnalisée les métriques d’engagement renvoyées. Vous pouvez inclure au maximum 3 regroupements par requête. Vous pouvez choisir de regrouper les métriques par une ou plusieurs des valeurs suivantes :

*Les trois points de terminaison prennent en charge :*

* tweet.id
* engagement.type
   

*Les points de terminaison `/28hr` et `/historical` peuvent fournir des métriques sous forme de séries temporelles et, de ce fait, prennent en charge :*

* engagement.day
* engagement.hour

Les regroupements sont appliqués en série, ce qui vous permet de modifier le format de résultat souhaité en changeant l’ordre de vos valeurs `group_by`. Les regroupements qui contiennent quatre valeurs `group_by` ne seront pris en charge que dans l’un des deux formats suivants :

```bash
"group_by": [
    "tweet.id",
    "engagement.type",
    "engagement.day",
    "engagement.hour"
  ]
```

OU

```bash
"group_by": [
    "engagement.type",
    "tweet.id",
    "engagement.day",
    "engagement.hour"
]
```

Par exemple, si vous souhaitez générer des totaux globaux par type de métrique, incluez la spécification « groupings » suivante dans le cadre de votre requête (et consultez la page de [Référence de l’API](/fr/x-api/enterprise-gnip-2.0/fundamentals/engagement-api#post-insights-engagement) pour plus d’informations sur la composition des requêtes) :

```json
{
  "engagement_types": [
    "favorites",
    "replies",
    "retweets"
  ],
  "groupings": {
    "Grand Totals": {
      "group_by": [
        "engagement.type"
      ]
    }
  }
}
```

Avec ce regroupement, la réponse JSON de l’Engagement API inclura un attribut `"Grand Totals"` de niveau racine qui contient les totaux globaux par type de métrique :

```json
{
  "Grand Totals": {
    "favorites": "12",
    "replies": "2",
    "retweets": "2"
  }
}
```

Pour générer une série temporelle de 4 heures d’indicateurs pour une seule Publication, regroupée par identifiants de Publication, la spécification de regroupement suivante ferait partie de la requête :

```json
{
  "start": "2016-02-10T17:00:00Z",
  "end": "2016-02-10T21:00:00Z",
  "tweet_ids": [
    "697506383516729344"
  ],
  "engagement_types": [
    "impressions",
    "engagements"
  ],
  "groupings": {
    "Tweets_MetricType_TimeSeries": {
      "group_by": [
        "tweet.id",
        "engagement.type",
        "engagement.hour"
      ]
    }
  }
}
```

Avec ce regroupement, la réponse JSON de l’Engagement API inclura un attribut de niveau racine `"Tweets_MetricType_TimeSeries"` qui contient les métriques ventilées par ID de Publication, puis par type de métrique, ainsi que la série chronologique horaire correspondante :

```json
{
  "Tweets_MetricType_TimeSeries": {
    "697506383516729344": {
      "impressions": {
        "2016-02-10": {
          "17": "551",
          "18": "412",

        }
      },
      "engagements": {
```

    **Le champ de métadonnées `engagements` renvoyé dans la charge utile n’est pas égal à la somme de tous les différents totaux de métriques d’engagement. Pourquoi est-ce le cas ?**

    C’est le comportement attendu. Le champ de métadonnées `engagements` peut ne pas toujours correspondre à la somme de toutes les métriques d’engagement individuelles renvoyées par l’API. Cela est dû au fait que le champ de métadonnées `engagements` peut inclure des engagements supplémentaires qui n’ont pas de métriques spécifiques détaillées dans la charge utile. Autrement dit, l’addition de tous les différents totaux de métriques d’engagement peut ne pas être égale à la valeur que vous voyez dans le champ de métrique `engagements` qui vous est renvoyé dans la charge utile.

    Vous pouvez considérer le champ de métadonnées `engagements` comme tout clic ou interaction effectué sur la Publication.
     

    **Le champ `url_clicks` dans la réponse de la charge utile renvoie un nombre, alors que la Publication ne contient pas d’URL. Comment est-ce possible ?**

    Cela peut s’expliquer par le fait qu’une Publication contenant, par exemple, un hashtag (qui crée un lien vers une autre page) sera comptabilisée comme un clic sur une URL si un utilisateur clique dessus.
     
  </Accordion>

  <Accordion title="Pourquoi ne puis-je pas recevoir de données d’engagement pour une Publication spécifique ?">
    Il existe différentes raisons pour lesquelles vous ne pouvez pas récupérer de données d’engagement pour une Publication spécifique, notamment :

    * L’ID ou les ID de Publication que vous avez demandés ne sont pas disponibles en fonction du jeton d’authentification que vous utilisez pour récupérer des données au nom d’un tiers.

<div id="authentication">
  #### **Authentification**
</div>

L’Engagement API nécessite l’utilisation de HTTPS et prend en charge à la fois le Contexte utilisateur (User Context) et l’OAuth applicatif (Application-Only OAuth). La plupart des requêtes vers l’Engagement API nécessitent l’utilisation d’OAuth à 3 volets (une version spécifique du Contexte utilisateur), ce qui signifie que vous utilisez la clé et le secret consommateur de l’application qui a été enregistrée et approuvée pour l’accès à l’Engagement API par votre responsable de compte Twitter, ainsi que le jeton d’accès et le secret de jeton d’accès des propriétaires des Tweets pour appeler l’endpoint. Les requêtes suivantes nécessitent ce type d’OAuth :

* Toute requête vers /totals pour obtenir les types de métriques Impressions et Engagements, qui sont limitées aux Tweets dont vous êtes propriétaire
* Toute requête vers /28hr
* Toute requête vers /historical

Certaines requêtes vers l’Engagement API peuvent être effectuées en utilisant l’OAuth applicatif (Application-Only OAuth), ce qui signifie que vous devez simplement fournir votre clé et votre secret consommateur, ou un Bearer Token. La requête suivante peut être effectuée avec ce type d’OAuth :

* Toute requête vers /totals pour obtenir les types de métriques Favorites, Replies, Retweets ou Video Views, qui peuvent être récupérées pour n’importe quel Tweet

Pour toute requête, vous devrez configurer une application Twitter et la clé API correspondante à l’aide de la console de gestion d’applications disponible sur [developer.x.com](https://developer.x.com/en/portal/dashboard).

Veuillez noter : vous pouvez afficher et modifier vos [applications Twitter](/fr/resources/fundamentals/developer-apps) existantes via le [tableau de bord des applications Twitter](https://developer.x.com/en/apps) si vous êtes connecté à votre compte Twitter sur developer.x.com.

Une fois que vous avez configuré votre application, l’identifiant de l’application (app ID) devra être approuvé par votre représentant de compte afin que votre application puisse effectuer des requêtes vers l’Engagement API. Les jetons d’accès doivent être utilisés pour représenter « l’utilisateur actuel » et les requêtes effectuées au nom d’un autre utilisateur doivent être signées avec un jeton valide. Assurez-vous de [coder correctement les caractères réservés](https://tools.ietf.org/html/rfc3986) dans les URL et les corps des requêtes POST avant de préparer les chaînes de base de signature OAuth.

Pour plus d’informations sur la façon de débuter avec OAuth, veuillez consulter les liens suivants :

* [Présentation d’OAuth](/fr/resources/fundamentals/authentication)
* [Utilisation d’OAuth à 3 volets, également appelé User Context](/fr/resources/fundamentals/authentication#obtaining-access-tokens-using-3-legged-oauth-flow)
* [Utilisation de l’OAuth applicatif (Application-Only OAuth)](/fr/resources/fundamentals/authentication#bearer-token-also-known-as-app-only)

<div id="error-messages">
  #### **Messages d’erreur**
</div>

Dans divers scénarios, l’API Engagement renverra des messages d’erreur spécifiques à la situation, que votre application doit être en mesure de gérer. Le tableau ci-dessous présente des exemples courants de ces messages d’erreur et la manière dont vous devez les interpréter. Veuillez noter que, dans de nombreux cas, l’API Engagement renverra des résultats partiels pour les données disponibles, accompagnés de messages d’erreur spécifiques, dans le cadre d’une réponse 200 OK fournissant des informations supplémentaires.

| Message d’erreur | Description |
| :--- | :--- |
| `"errors":["Your account could not be authenticated. Reason: Access token not found"]` | Une erreur dans le composant d’authentification de la requête. Le champ &quot;Reason&quot; doit fournir des informations utiles pour résoudre le problème. Si vous ne parvenez pas à le résoudre, veuillez envoyer l’erreur complète, y compris la valeur de &quot;Reason&quot;, à notre équipe d’assistance. |
| `"errors":["1 Tweet ID(s) are unavailable"],"unavailable_tweet_ids": ["TWEET_IDS"]` | Le ou les Tweet ID que vous avez demandés ne sont plus disponibles, ce qui indique généralement qu’ils ont été supprimés ou ne sont plus accessibles publiquement pour une autre raison. |
| `"errors":["Impressions & engagements for tweets older than 90 days (*TIME_PERIOD*) are not supported"],"unsupported_for_impressions_engagements_tweet_ids":[*TWEET_IDS*]` | Le ou les Tweet ID que vous avez demandés, spécifiquement pour l’endpoint /totals, ne datent pas de 90 jours ou moins et ne sont donc pas éligibles au renvoi des métriques d’impressions ou d’engagements. |
| `"errors":["Forbidden to access tweets: *TWEET_IDS*"]` | Le ou les Tweet ID que vous avez demandés ne sont pas disponibles en fonction du jeton d’authentification que vous utilisez pour récupérer des données pour le compte d’un tiers. |
