## Introduction

`Enterprise`

Les enrichissements Enterprise sont des métadonnées supplémentaires incluses dans le corps de la réponse de certaines API de données. Ils sont disponibles uniquement dans le cadre d’abonnements payants.

Le tableau ci-dessous propose une brève description de chaque enrichissement :

| Enrichment: | Description: |
| :--- | :--- |
| Expanded and Enhanced URLs | Développe automatiquement les URL raccourcies (par exemple, bitly) qui sont incluses dans le corps d’une Publication et fournit les métadonnées de titre et de description HTML de la page de destination. |
| Matching rules object | Indique quelle ou quelles règles correspondent aux Publications reçues. L’objet retourne l’étiquette de règle et l’identifiant de règle dans l’objet de réponse. |
| Poll metadata | Indique la présence d’un sondage dans une Publication, inclut la liste des choix du sondage, ainsi que la durée du sondage et son heure d’expiration. |
| Profile geo | Données de localisation de profil utilisateur dérivées, y compris les coordonnées [longitude, latitude] (lorsque cela est possible) et les métadonnées associées au lieu. |

<div id="expanded-and-enhanced-urls">
  ### URL développées et enrichies
</div>

L’enrichissement des URL développées et enrichies développe automatiquement les URL raccourcies qui sont incluses dans le corps d’une Publication et ajoute l’URL obtenue comme métadonnée au sein de la charge utile. En outre, cet enrichissement fournit également les métadonnées de la page HTML à partir du `title` et de la `description` de la page de destination.

**Détails importants :**

* Pour résoudre un lien raccourci, notre système envoie des requêtes HTTP HEAD à l’URL fournie et suit toutes les redirections jusqu’à ce qu’il atteigne l’URL finale. Cette URL finale (ET NON le contenu de la page elle-même) est ensuite incluse dans la charge utile de la Réponse.

* L’enrichissement d’URL ajoute entre 5 et 10 secondes de latence aux flux en temps réel.

* Pour les requêtes envoyées à l’API Full Archive Search, les données d’enrichissement d’URL développées ne sont disponibles que pour les Publications âgées de 13 mois ou moins.

* L’enrichissement d’URL n’est pas disponible pour les liens de Publication (y compris les Tweets cités), les liens Moments et les liens de profil qui figurent dans une Publication. 
   

<div id="post-payload">
  #### Charge utile de la Publication
</div>

L’enrichissement d’URL étendue et améliorée se trouve dans l’objet `entities` de la charge utile de la Publication – plus précisément dans l’objet `entitites.urls.unwound`. Il fournit les champs de métadonnées suivants :

* URL étendue - `unwound.url`
* Statut HTTP de l’URL étendue - `unwound.status`
* Titre HTML de l’URL étendue - limite de 300 caractères - `unwound.title`
* Description HTML de l’URL étendue - limite de 1000 caractères - `unwound.description`

**Voici un exemple d’[objet entities](/fr/x-api/enterprise-gnip-2.0/fundamentals/data-dictionary#x-entities) avec l’enrichissement d’URL :**

```
"entities": {
    "hashtags": [

    ],
    "urls": [
      {
        "url": "https:\/\/t.co\/HkTkwFq8UT",
        "expanded_url": "http:\/\/bit.ly\/2wYTb9y",
        "display_url": "bit.ly\/2wYTb9y",
        "unwound": {
          "url": "https:\/\/www.forbes.com\/sites\/laurencebradford\/2016\/12\/08\/11-websites-to-learn-to-code-for-free-in-2017\/",
          "status": 200,
          "title": "11 Websites To Learn To Code For Free In 2017",
          "description": "It\u2019s totally possible to learn to code for free...but what are the best resources to achieve that? Here are 11 websites where you can get started."
        },
        "indices": [
          10,
          33
        ]
      }
    ],
    "user_mentions": [

    ],
    "symbols": [

    ]
  },
```

**Voici un exemple d’objet entities contenant un lien de publication non enrichi :**

```
"entities": {
  "urls": [{
    "url": "https://t.co/SywNbZdDmb",
    "expanded_url": "https://x.com/XDevelopers/status/1050118621198921728",
    "display_url": "x.com/XDevelopers/s…",
     "indices": [
        142,
        165
     ]
   }
  ]
}
```

<div id="filtering-operators">
  #### Opérateurs de filtrage
</div>

Les opérateurs suivants appliquent un filtre et effectuent une correspondance tokenisée sur les champs associés aux métadonnées d’URL :

**url :**

* Exemple : “url:tennis”
* Correspondance tokenisée sur toute URL développée (Expanded URL) qui inclut le mot tennis
* Peut également être utilisé comme filtre pour inclure ou exclure des liens provenant d’un site web spécifique, en utilisant par exemple “url:npr.org”

**url&#95;title :**

* Exemple : “url&#95;title:tennis”
* Correspondance tokenisée sur tout titre HTML d’URL développée qui inclut le mot tennis
* Correspond aux données de titre HTML incluses dans le payload, limitées à 300 caractères.

**url&#95;description :**

* Exemple : “url&#95;description:tennis”
* Correspondance tokenisée sur toute description HTML d’URL développée qui inclut le mot tennis
* Correspond à la description HTML incluse dans le payload, limitée à 1000 caractères.
   

<div id="http-status-codes">
  #### Codes d&#39;état HTTP
</div>

L&#39;enrichissement d&#39;URL développées fournit également le code d&#39;état HTTP pour l&#39;URL finale que nous tentons de développer. Dans les cas normaux, il s&#39;agit d&#39;un code 200. Les autres codes de la série 400 indiquent des problèmes lors de la résolution de l&#39;URL.

Divers codes d&#39;état peuvent être renvoyés lors de la tentative de développement d&#39;une URL. Pendant le processus de développement d&#39;une URL, si nous obtenons une redirection, nous la suivrons indéfiniment jusqu&#39;à ce que nous :

* Atteignions un code de la série 200 (succès)
* Atteignions un code d&#39;une série autre que les redirections (échec)
* Expirions parce que l&#39;URL finale n&#39;a pas pu être résolue dans un délai raisonnable (renvoie un 408 - délai dépassé)
* Rencontrions une exception quelconque
   

Si une exception est rencontrée, nous utilisons la correspondance suivante entre les raisons et les codes d&#39;état renvoyés :

| Raison | Code d&#39;état renvoyé |
| :--- | :--- |
| Exceptions SSL | 403 (Interdit) |
| Développement non autorisé par l&#39;URL | 405 |
| Délai d&#39;attente de socket | 408 (Délai dépassé) |
| Exception d&#39;hôte inconnu | 404 (Introuvable) |
| Opération non prise en charge | 404 (Introuvable) |
| Exception de connexion | 404 (Introuvable) |
| Argument non valide | 400 (Requête incorrecte) |
| Tout le reste | 400 (Requête incorrecte) |

<div id="matching-rules">
  ### Règles de correspondance
</div>

L’enrichissement des règles de correspondance est un objet de métadonnées qui indique quelle ou quelles règles correspondent aux Publications reçues. Il est le plus souvent utilisé avec le flux PowerTrack.

La correspondance est effectuée par mise en correspondance exacte des termes contenus dans une règle, en analysant le contenu de l’activité avec et sans ponctuation. La correspondance n’est pas sensible à la casse. Lorsque le contenu est jugé contenir tous les termes définis dans la règle, un objet matching&#95;rules au niveau racine indique la ou les règles ayant conduit à la correspondance.

**PowerTrack**

Les Publications livrées via PowerTrack (temps réel, Replay et Historical) contiendront l’objet matching&#95;rules comme suit :

```
"matching_rules": [{
        "tag": null,
        "id": 907728589029646336,
        "id_str": "907728589029646336"
    }]
```

Dans PowerTrack, l&#39;objet `matching_rules` représente *toutes* les règles qui correspondent au résultat donné. En d&#39;autres termes, si plusieurs règles correspondent à une même Publication, elle n&#39;est renvoyée qu&#39;une seule fois, mais l&#39;élément `matching_rules` contient toutes les règles qui ont correspondu.

<div id="poll-metadata">
  ### Métadonnées de sondage
</div>

Les métadonnées de sondage sont un enrichissement gratuit disponible dans tous les produits (API en temps réel et historiques) dans les payloads enrichis au format natif. Les métadonnées indiquent la présence du sondage dans une Publication, incluent la liste des choix du sondage et comprennent à la fois la durée du sondage et son heure d’expiration. Cet enrichissement facilite la prise en compte de la présence d’un sondage et permet un rendu correct d’une Publication de sondage pour l’affichage.

<div id="important-details">
  ##### Détails importants :
</div>

* Disponible dans toutes les API Enterprise (PowerTrack, Replay, Search, Historical PowerTrack)
  * *Remarque :* Pour Replay et Historical PowerTrack, ces métadonnées ont été rendues disponibles pour la première fois le 22/02/17.
* N’inclut pas les informations de vote ni les résultats de sondage
* Ne dispose actuellement d’aucune prise en charge des filtres/opérateurs
* Disponible uniquement en **format natif enrichi**
  * Le format natif enrichi est un paramètre contrôlé par l’utilisateur qui peut être modifié à tout moment via la Console : *Select a Product (PowerTrack, Replay, Search) &gt; Settings tab &gt; Output Format (Leave data in its original format)*

<div id="post-payload">
  #### Charge utile de la Publication
</div>

La Publication contenant un sondage contiendra les métadonnées suivantes dans l’objet « entities.polls » de la charge utile :

* Un tableau « options » avec jusqu’à quatre options, incluant la position (1-4) et le texte de l’option
* Date d’expiration du sondage
* Durée du sondage

Voir l’exemple de charge utile ci-dessous pour référence.

<div id="profile-geo">
  ### Géolocalisation du profil
</div>

<div id="introduction">
  #### Introduction
</div>

De nombreux profils d’utilisateurs X incluent des informations de localisation publiques fournies par l’utilisateur. Ces données sont renvoyées sous forme de chaîne de caractères classique dans `user.location` (voir le [dictionnaire de données de l’objet User](/fr/x-api/enterprise-gnip-2.0/fundamentals/data-dictionary#native-enriched-user-object)). L’enrichissement Profile Geo ajoute des géodonnées structurées pertinentes pour la valeur `user.location` en géocodant et en normalisant les chaînes de localisation lorsque cela est possible. Les coordonnées de latitude/longitude ainsi que les métadonnées de lieu associées sont ajoutées à `user.derived.locations` *uniquement* lorsqu’elles sont incluses dans la charge utile de la Publication dans les produits d’API pour entreprises. Ces données sont disponibles lors de l’utilisation du [format natif enrichi](/fr/x-api/enterprise-gnip-2.0/fundamentals/data-dictionary) et peuvent être filtrées avec une combinaison de [règles PowerTrack](/fr/x-api/enterprise-gnip-2.0/fundamentals/rules-filtering#enterprise-operators).

<Note>
  **Note :** Certaines des géodonnées utilisées pour créer l’enrichissement Profile Geo proviennent de GeoNames.org et sont utilisées par X sous la [licence Creative Commons Attribution 3.0](https://creativecommons.org/licenses/by/3.0/us/legalcode).
</Note>

Les données Profile Geo seront incluses dans les API PowerTrack, Replay, Volume Stream, Search et Historical PowerTrack de X.

<div id="profile-geo-data">
  #### Données de géolocalisation de profil
</div>

| Enriched native field name | Example value | Description |
| :--- | :--- | :--- |
| user.derived.locations.country | United States | Le pays d’origine de l’utilisateur qui a créé la Publication. |
| user.derived.locations.country&#95;code | US  | Un code pays ISO-3166 à deux lettres correspondant au pays d’origine de l’utilisateur qui a créé la Publication. |
| user.derived.locations.locality | Birmingham | La localité (généralement la ville) d’où est originaire l’utilisateur qui a créé la Publication. |
| user.derived.locations.region | Alabama | La région (généralement l’État ou la province) d’où est originaire l’utilisateur qui a créé la Publication. |
| user.derived.locations.sub&#95;region | Jefferson County | La sous-région (généralement le comté) d’où est originaire l’utilisateur qui a créé la Publication. |
| user.derived.locations.full&#95;name | Birmingham, Alabama, United States | Le nom complet (hors sous-région) du lieu d’origine de l’utilisateur qui a créé la Publication. |
| User.derived.locations.geo | See Below | Un tableau qui inclut une valeur de latitude/longitude pour une coordonnée correspondant au lieu avec le plus faible niveau de granularité d’où est originaire l’utilisateur qui a créé la Publication. |

Les API Historical PowerTrack, Search et PowerTrack prennent en charge le filtrage basé sur les données Profile Geo. Consultez la documentation produit appropriée pour plus de détails sur les opérateurs disponibles pour le filtrage des données Profile Geo.

<div id="sample-payload">
  #### Exemple de payload
</div>

```
{
    "user": {
        "derived": {
            "locations": \[
                {
                    "country": "United States",
                    "country_code": "US",
                    "locality": "Birmingham",
                    "region": "Alabama",
                    "sub_region": "Jefferson County",
                    "full_name": "Birmingham, Alabama, United States",
                    "geo": {
                        "coordinates": \[
                            -86.80249,
                            33.52066
                        \],
                        "type": "point"
                    }
                }
            \]
        }
    }
}
```

<div id="limitations">
  #### Limitations
</div>

* L’enrichissement Profile Geo tente de déterminer le meilleur choix pour le lieu géographique décrit dans la chaîne de localisation du profil. Le résultat peut ne pas être exact dans tous les cas, en raison de facteurs tels que l’existence de plusieurs lieux aux noms similaires ou de noms ambigus.
* Si aucune valeur n’est fournie dans le champ de localisation du profil d’un utilisateur (actor.location), nous ne tenterons pas d’établir de classification.
* Niveau de précision : si un enrichissement Profile Geo ne peut être établi avec un niveau de confiance suffisant qu’au niveau du pays ou de la région, les zones géographiques de niveau inférieur telles que subRegion et locality seront omises de la charge utile.
* L’enrichissement Profile Geo fournit des coordonnées lat/long (un point unique) qui correspondent au niveau de précision des résultats de l’enrichissement. Ces coordonnées représentent le centre géographique des résultats de localisation de l’enrichissement. Par exemple, si le niveau de précision est au niveau du pays, ces coordonnées sont alors définies sur le centre géographique du pays concerné.
* Les opérateurs PowerTrack fournis pour les propriétés d’adresse (locality/region/country/country code) sont volontairement granulaires afin de permettre de nombreuses combinaisons de règles. Lorsque vous tentez de cibler un emplacement spécifique qui partage un nom avec un autre emplacement, envisagez de combiner des règles d’adresse. Par exemple, ce qui suit permettrait d’éviter les correspondances pour « San Francisco, Philippines » : profile&#95;locality:&quot;San Francisco&quot; profile&#95;region:California. Lorsque vous créez des règles qui ciblent des champs Profile Geo individuels, gardez à l’esprit que chaque niveau de granularité supplémentaire limitera les résultats que vous voyez. Dans certains cas, lorsque vous tentez d’examiner des données provenant d’une ville, vous pouvez choisir de ne vous appuyer que sur une règle de région lorsque cette région présente un chevauchement significatif avec la ville ; par exemple, la ville de Zurich, en Suisse, peut être efficacement ciblée, ainsi que les zones environnantes, avec profile&#95;region:&quot;Zurich&quot;.
* Utilisation avec des Publications à géolocalisation native : l’enrichissement Profile Geo fournit un type de géographie alternatif pour une Publication, différent de la valeur geo native dans la charge utile. Ces deux types de géographie peuvent être combinés pour capturer l’ensemble des Publications possibles liées à une zone donnée (en fonction des géodonnées disponibles), même s’ils ne sont pas conceptuellement équivalents.
