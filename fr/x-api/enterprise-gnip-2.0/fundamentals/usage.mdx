<div id="usage-api-twitter-api">
  ## Usage API | Twitter API
</div>

<div id="overview">
  ### Présentation
</div>

`Enterprise`

C’est l’outil le plus important et le *meilleur* pour vous aider à surveiller et gérer l’utilisation des différentes API associées à votre compte.

**Avertissement important :**

Les volumes d’utilisation renvoyés par l’API Usage peuvent ne pas correspondre à ceux figurant sur une facture, en raison des périodes d’essai et d’autres ajustements de facturation. Toutes les valeurs sont basées sur des activités consommées au cours d’une journée donnée (en UTC), après déduplication.

<div id="features">
  #### Fonctionnalités
</div>

* Récupération par programmation des données d’utilisation disponibles dans l’interface utilisateur console.gnip.com
* Données d’utilisation au niveau du flux (stream) : fournit des données d’utilisation au niveau du flux (par exemple, dev et prod) en plus du niveau produit
* Données granulaires et descriptives : les requêtes de recherche (« requests ») sont ventilées par produits Full-Archive et 30-Day Search
* « Jours » et « jobs » Historical PowerTrack 

<div id="supported-apis">
  ### APIs prises en charge
</div>

Vous trouverez ci-dessous une liste des API actuellement prises en charge par l’API Usage :

* PowerTrack API `enterprise`
* 30-Day Search API `enterprise`
* Full-Archive Search API `enterprise`
* Historical PowerTrack `enterprise`

<div id="limitations">
  ### Limitations
</div>

* The Usage API vous permet d&#39;accéder aux données d&#39;utilisation depuis le 1er mai 2018. À partir du 1er juillet 2019, Usage API vous permet d&#39;accéder aux données d&#39;utilisation pour les **13 derniers mois civils**

* Vous pouvez accéder aux données d&#39;utilisation par **intervalles de trois mois** définis avec un fromDate et un toDate

```bash
curl -u<username>:<password> \
"https://gnip-api.x.com/metrics/usage/accounts/<account-name>.json?bucket=month"
```

<div id="api-reference">
  ## Référence de l’API
</div>

<div id="get-usage">
  ### get-usage
</div>

<div id="methods">
  #### **Méthodes**
</div>

| Méthode | Description |
| :--- | :--- |
| [GET /metrics/usage/accounts/{ACCOUNT_NAME}.json](#GETData) | Récupérer les données d&#39;utilisation |

Où :

* :account&#95;name est le nom respectant la casse associé à votre compte, tel qu&#39;il apparaît sur console.gnip.com

<div id="authentication-and-rate-limit">
  #### **Authentification et limites de débit**
</div>

<div id="authentication">
  ##### **Authentification**
</div>

Toutes les requêtes adressées à l’API Usage nécessitent une authentification HTTP Basic, en utilisant l’un des couples e‑mail/mot de passe activés sur votre compte pour vous connecter à votre compte sur console.gnip.com ou à n’importe quel flux Gnip.

<div id="rate-limit">
  ##### **Limite de débit**
</div>

L’API Usage applique une limite de 2 requêtes par minute.

<div id="best-practices-limitations">
  #### **Bonnes pratiques et limites**
</div>

<div id="data-availability">
  ##### **Disponibilité des données**
</div>

Les données d’usage sont basées sur des activités dédupliquées, prises en compte jusqu’à la dernière période complète (UTC) pour laquelle les données ont été traitées. Les données sont généralement traitées et mises à jour à la minute près, sauf lorsque Gnip est en train de déployer des systèmes.

* L’API Usage vous permet d’accéder aux données d’usage depuis le 1er mai 2018. Après le 1er juillet 2019, l’API Usage vous permet d’accéder aux données d’usage pour les **13 derniers mois civils**. 

* Vous avez la possibilité d’accéder aux données d’usage par **intervalles de trois mois** définis à l’aide de fromDate et toDate

<div id="requesting-and-receiving-data">
  #### **Demande et réception des données**
</div>

L’API Usage fonctionne en envoyant une requête HTTP GET avec des identifiants d’authentification HTTP Basic (BASIC-AUTH) vers le point de terminaison de l’API associé à votre compte.

<div id="get-request">
  ##### Requête GET :
</div>

Effectuez une requête GET vers l&#39;endpoint suivant avec vos identifiants utilisateur et le nom de votre compte :

https://gnip-api.x.com/metrics/usage/accounts/:account&#95;name.json

**Paramètres supplémentaires**

|     |     |
| :--- | :--- |
| bucket | Facultatif. L&#39;unité de temps pour laquelle les données d&#39;utilisation seront fournies. Les données d&#39;utilisation peuvent être renvoyées avec une granularité quotidienne ou mensuelle.  <br />  <br />Les requêtes effectuées sans `bucket` spécifié renverront une granularité mensuelle.  <br />  <br />Options : &#39;month&#39; ou &#39;day&#39; |
| fromDate (YYYYMMDDHHMM) | Facultatif. Les données d&#39;utilisation ne sont disponibles qu&#39;à partir du 1er mai 2018. Il s&#39;agit de l&#39;horodatage UTC le plus ancien à partir duquel les données d&#39;utilisation seront fournies. L&#39;horodatage a une granularité au jour et est inclusif (c.-à-d. 201805010000 inclut la journée du 1er mai, « 05/01 »). Les requêtes qui contiennent des valeurs autres que &#39;0000&#39; pour l&#39;heure et les minutes seront ramenées par défaut à &#39;0000&#39;.  <br />  <br />Les requêtes effectuées sans `fromDate` ni `toDate` renverront des données d&#39;utilisation par mois pour le mois en cours et incluront une référence historique pour les deux mois précédents.  <br />  <br />**Remarque :** à partir du 1er juin 2019, vous pouvez accéder aux données d&#39;utilisation des 13 derniers mois civils. Par exemple, si nous sommes le 10 octobre, vous pouvez accéder aux données d&#39;utilisation remontant au 1er septembre de l&#39;année précédente.  <br />**Exemple :** 201810010000 renverra les données à partir du 1er octobre 2018 inclus. |
| toDate (YYYYMMDDHHMM) | Facultatif. Le dernier horodatage UTC jusqu&#39;auquel les données d&#39;utilisation seront fournies. L&#39;horodatage a une granularité au jour et n&#39;est pas inclusif (c.-à-d. 201703020000 n&#39;inclut pas les données pour la journée du 03/02). Lorsqu&#39;un `toDate` est spécifié pour le jour en cours ou un jour futur, les données d&#39;utilisation seront renvoyées jusqu&#39;au dernier jour complet (UTC). Les requêtes qui contiennent des valeurs autres que &#39;0000&#39; pour l&#39;heure et les minutes seront ramenées par défaut à &#39;0000&#39;.  <br />  <br />Une requête sans `toDate` prendra par défaut le bucket suivant (demain pour bucket=day et le mois suivant pour bucket=month). Une requête effectuée sans `fromDate` ni `toDate` prendra par défaut bucket=month et affichera les données pour le mois en cours plus les deux mois immédiatement précédents.  <br />  <br />**Exemple :** 201703050000 renverra les données jusqu&#39;au 5 mars 2017, sans inclure aucune donnée du 5 mars. |

**Exemple de requête GET**

Cette requête renverra les données avec une granularité mensuelle du 1er mars 2017 au 5 mars 2017, sans inclure aucune donnée du 5 mars 2017.

curl -u &quot;https://gnip-api.x.com/metrics/usage/accounts/:account&#95;name.json?bucket=month&amp;fromdate=201403010000&amp;toDate=201403150000&quot;

<div id="data-format">
  #### **Format des données**
</div>

Les tableaux suivants décrivent les structures de données à la racine pour les données d&#39;utilisation renvoyées par l&#39;API Usage. Pour les champs comportant plusieurs niveaux de sous-champs, cliquez sur les liens fournis pour afficher les détails concernant les sous-champs.

Si vous souhaitez voir un exemple de payload complet de l&#39;API Usage, veuillez consulter [cette page](/fr/x-api/usage/introduction).

|     |     |
| :--- | :--- |
| **account** | Un objet représentant le compte pour lequel les données d&#39;utilisation ont été demandées. |
| **bucket** | L&#39;unité de temps pour laquelle les données d&#39;utilisation sont fournies. Peut être « day » ou « month ». |
| **fromDate** | Le premier horodatage UTC pour lequel vous souhaitez récupérer les données d&#39;utilisation (inclus). |
| **toDate** | Le dernier horodatage UTC pour lequel vous souhaitez récupérer les données d&#39;utilisation (exclu). |
| **publishers** | Contient trois objets principaux : Used, projected et products. |
