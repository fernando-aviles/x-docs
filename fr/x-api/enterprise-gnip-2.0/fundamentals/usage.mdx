<div id="usage-api-twitter-api">
  ## Usage API | Twitter API
</div>

<div id="overview">
  ### Vue d’ensemble
</div>

`Enterprise`

Il s’agit de l’outil le plus important, et du *meilleur*, pour vous aider à surveiller et à gérer l’utilisation des différentes API associées à votre compte.

**Avertissement important :**

Les volumes d’utilisation renvoyés par l’API Usage peuvent ne pas correspondre à ceux figurant sur une facture en raison des périodes d’essai et d’autres ajustements de facturation. Tous les chiffres sont basés sur des activités dédupliquées consommées au cours d’une journée donnée (en UTC).

<div id="features">
  #### Fonctionnalités
</div>

* Récupération programmatique des données d’utilisation disponibles dans l’interface de console.gnip.com
* Données d’utilisation au niveau du flux - fournit des données d’utilisation au niveau du flux (par exemple dev et prod) en plus du niveau produit
* Données granulaires et descriptives - les requêtes de recherche sont ventilées par produits Full-Archive et 30-Day Search
* Jours et jobs Historical PowerTrack 

<div id="supported-apis">
  ### API prises en charge
</div>

Vous trouverez ci-dessous la liste des API que l’API Usage prend actuellement en charge :

* PowerTrack API `enterprise`
* 30-Day Search API `enterprise`
* Full-Archive Search API `enterprise`
* Historical PowerTrack `enterprise`

<div id="limitations">
  ### Limitations
</div>

* L’API Usage vous permet d’accéder aux données d’utilisation depuis le 1er mai 2018. À partir du 1er juillet 2019, l’API Usage vous permet d’accéder aux données d’utilisation sur les **13 derniers mois calendaires**

* Vous avez la possibilité d’accéder aux données d’utilisation par **intervalles de trois mois** définis avec un fromDate et un toDate


  ## Référence de l’API
</div>

<div id="get-usage">
  ### get-usage
</div>

<div id="methods">
  #### **Methods**
</div>

| Method | Description |
| :--- | :--- |
| [GET /metrics/usage/accounts/{ACCOUNT_NAME}.json](#GETData) | Récupérer les données d&#39;utilisation |

Where:

* :account&#95;name est le nom (sensible à la casse) associé à votre compte, tel qu&#39;affiché sur console.gnip.com

<div id="authentication-and-rate-limit">
  #### **Authentification et limites de débit**
</div>

<div id="authentication">
  ##### **Authentification**
</div>

Toutes les requêtes adressées à l&#39;API Usage nécessitent une authentification HTTP Basic, en utilisant l&#39;une des paires adresse e-mail/mot de passe activées sur votre compte, que vous utilisez pour vous connecter à console.gnip.com ou à n&#39;importe quel flux Gnip.

<div id="rate-limit">
  ##### **Limite de débit**
</div>

L’API Usage applique une limite de débit de deux requêtes par minute.

<div id="best-practices-limitations">
  #### **Bonnes pratiques et limites**
</div>

<div id="data-availability">
  ##### **Disponibilité des données**
</div>

Les données d&#39;utilisation sont basées sur des activités dédupliquées recueillies jusqu&#39;à la dernière période complète (UTC) au cours de laquelle les données ont été traitées. Les données sont généralement traitées et mises à jour à la minute près, sauf lorsque Gnip déploie des systèmes.

* L’API Usage vous permet d’accéder aux données d&#39;utilisation depuis le 1er mai 2018. Après le 1er juillet 2019, l’API Usage vous permet d’accéder aux données d&#39;utilisation pour les **13 derniers mois civils**.

* Vous avez la possibilité d’accéder aux données d&#39;utilisation par **intervalles de trois mois** définis avec un fromDate et un toDate

<div id="requesting-and-receiving-data">
  #### **Demande et réception de données**
</div>

L’API Usage fonctionne en adressant une requête HTTP GET avec des identifiants d’authentification HTTP Basic à l’endpoint d’API de votre compte.

<div id="get-request">
  ##### Requête GET :
</div>

Effectuez une requête GET vers l’endpoint suivant avec vos identifiants utilisateur et le nom de votre compte :

https://gnip-api.x.com/metrics/usage/accounts/:account&#95;name.json

**Paramètres supplémentaires**

|     |     |
| :--- | :--- |
| bucket | Facultatif. L’unité de temps pour laquelle les données d’utilisation seront fournies. Les données d’utilisation peuvent être renvoyées avec une granularité quotidienne ou mensuelle.  <br />  <br />Les requêtes effectuées sans bucket spécifié renverront une granularité mensuelle.  <br />  <br />Options : &#39;month&#39; ou &#39;day&#39; |
| fromDate (YYYYMMDDHHMM) | Facultatif. Les données d’utilisation ne sont disponibles qu’à partir du 1er mai 2018. Il s’agit du plus ancien horodatage UTC à partir duquel les données d’utilisation seront fournies. L’horodatage possède une granularité au jour et est inclusif (c’est‑à‑dire que 201805010000 inclut la journée du 01/05). Les requêtes qui contiennent des valeurs autres que &#39;0000&#39; pour les champs d’heure et de minute auront ces valeurs définies par défaut à &#39;0000&#39;.  <br />  <br />Les requêtes faites sans fromDate ni toDate renverront les données d’utilisation par mois pour le mois en cours et incluront une référence historique pour les deux mois précédents.  <br />  <br />**Remarque :** à partir du 1er juin 2019, vous pouvez accéder aux données d’utilisation des 13 derniers mois calendaires. Par exemple, si nous sommes le 10 octobre, vous pouvez accéder aux données d’utilisation jusqu’au 1er septembre de l’année précédente.  <br />**Exemple :** 201810010000 renverra les données à partir du 1er octobre 2018 inclus. |
| toDate (YYYYMMDDHHMM) | Facultatif. Le dernier horodatage UTC jusqu’auquel les données d’utilisation seront fournies. L’horodatage possède une granularité au jour et n’est pas inclusif (c’est‑à‑dire que 201703020000 n’inclut pas les données pour la journée du 02/03). Lorsqu’un toDate est spécifié pour le jour courant ou un jour futur, les données d’utilisation seront renvoyées jusqu’au dernier jour complet (UTC). Les requêtes qui contiennent des valeurs autres que &#39;0000&#39; pour les champs d’heure et de minute auront ces valeurs définies par défaut à &#39;0000&#39;.  <br />  <br />Une requête sans toDate prendra par défaut le bucket suivant (demain pour bucket=day et le mois suivant pour bucket=month). Une requête faite sans fromDate ni toDate prendra par défaut bucket=month et affichera les données pour le mois en cours plus les deux mois immédiatement précédents.  <br />  <br />**Exemple :** 201703050000 renverra les données jusqu’au 5 mars 2017, sans inclure de données du 5 mars. |

**Exemple de requête GET**

Cette requête renverra les données avec une granularité mensuelle du 1er mars 2017 au 5 mars 2017, sans inclure aucune donnée du 5 mars 2017.

curl -u &quot;https://gnip-api.x.com/metrics/usage/accounts/:account&#95;name.json?bucket=month&amp;fromdate=201403010000&amp;toDate=201403150000&quot;

<div id="data-format">
  #### **Format des données**
</div>

Les tableaux suivants décrivent les structures de données racine pour les données d&#39;utilisation renvoyées par l&#39;API Usage. Pour les champs comportant plusieurs niveaux de sous-champs, cliquez sur les liens fournis pour afficher les détails concernant les sous-champs.

Si vous souhaitez voir un exemple complet de charge utile de l&#39;API Usage, veuillez consulter [cette page](/fr/x-api/usage/introduction).

|     |     |
| :--- | :--- |
| **account** | Objet représentant le compte pour lequel les données d&#39;utilisation ont été demandées. |
| **bucket** | Unité de temps pour laquelle les données d&#39;utilisation sont fournies. Peut être soit &#39;day&#39; soit &#39;month&#39;. |
| **fromDate** | Premier horodatage UTC à partir duquel vous souhaitez récupérer les données d&#39;utilisation (inclus). |
| **toDate** | Dernier horodatage UTC jusqu&#39;auquel vous souhaitez récupérer les données d&#39;utilisation (exclu). |
| **publishers** | Comprend trois objets principaux : Used, projected et products. |
