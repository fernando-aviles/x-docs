Commencez avec X API en trois étapes : inscrivez-vous, créez une application et enregistrez vos identifiants.

<Button href="https://console.x.com">Inscrivez-vous maintenant</Button>

***

<div id="step-1-create-a-developer-account">
  ## Étape 1 : Créer un compte développeur
</div>

<Steps>
  <Step title="Accédez à la Console de Développement">
    Rendez-vous sur [console.x.com](https://console.x.com) et connectez-vous avec votre compte X.
  </Step>

  <Step title="Acceptez le Contrat Développeur">
    Consultez et acceptez le Contrat Développeur et la Politique.
  </Step>

  <Step title="Complétez votre profil">
    Renseignez des informations de base sur la façon dont vous comptez utiliser l&#39;API.
  </Step>
</Steps>

***

<div id="step-2-create-an-app">
  ## Étape 2 : Créer une application
</div>

Après votre inscription, créez une application pour obtenir vos identifiants d’API :

<Steps>
  <Step title="Cliquez sur « New App »">
    Depuis le tableau de bord de la Console de Développement, créez une nouvelle application.
  </Step>

  <Step title="Renseignez les détails de l’application">
    Indiquez un nom, une description et un cas d’utilisation pour votre application.
  </Step>

  <Step title="Générez les identifiants">
    La console générera vos clés et jetons d’API.
  </Step>
</Steps>

***

<div id="step-3-save-your-credentials">
  ## Étape 3 : Enregistrez vos identifiants
</div>

Vous recevrez plusieurs identifiants en fonction de vos besoins d’authentification :

| Identifiant | Objectif |
|:-----------|:---------|
| **Clé API et secret** | Identifier votre application. Utilisés pour générer des jetons et signer les requêtes OAuth 1.0a. |
| **Bearer Token** | Authentification en mode application uniquement pour lire les données publiques. |
| **Jeton d’accès et secret** | Effectuer des requêtes pour le compte de votre propre compte (OAuth 1.0a). |
| **Client ID et secret** | Authentification OAuth 2.0 pour les requêtes en contexte utilisateur. |

<Warning>
  **Enregistrez-les immédiatement.** Les identifiants ne sont affichés qu’une seule fois. Stockez-les dans un gestionnaire de mots de passe ou un coffre-fort sécurisé. Si vous les perdez, vous devrez les régénérer (ce qui invalide les anciens).
</Warning>

***

<div id="which-credentials-do-you-need">
  ## De quels identifiants avez-vous besoin ?
</div>

<Tabs>
  <Tab title="Lire les données publiques">
    Utilisez le **Bearer Token** pour un accès simple, en lecture seule, aux données publiques.

    ```bash
    curl "https://api.x.com/2/users/by/username/xdevelopers" \
      -H "Authorization: Bearer $BEARER_TOKEN"
    ```

    Idéal pour : rechercher des publications, consulter des comptes, lire les tendances.
  </Tab>

  <Tab title="Agir en tant qu’utilisateur">
    Utilisez **OAuth 2.0** (recommandé) ou **OAuth 1.0a** pour agir au nom des utilisateurs.

    OAuth 2.0 propose des autorisations très granulaires : demandez uniquement les permissions dont vous avez besoin.

    Idéal pour : publier, aimer, suivre, accéder aux messages privés (DM).

    [Guide OAuth 2.0 →](/fr/resources/fundamentals/authentication/oauth-2-0/overview)
  </Tab>

  <Tab title="Agir en tant que vous-même">
    Utilisez votre **Access Token &amp; Secret** pour effectuer des requêtes avec votre propre compte.

    Ces jetons représentent le compte propriétaire de l’application.

    Idéal pour : les tests, les bots personnels, vos propres automatisations.
  </Tab>
</Tabs>

<div id="credential-security-best-practices">
  ## Bonnes pratiques de sécurité des identifiants
</div>

<CardGroup cols={2}>
  <Card title="Utilisez des variables d'environnement" icon="terminal">
    Ne codez jamais en dur vos identifiants dans votre code source.
  </Card>

  <Card title="Ne validez pas dans Git" icon="code-branch">
    Ajoutez les fichiers contenant des identifiants à `.gitignore`.
  </Card>

  <Card title="Renouvelez-les régulièrement" icon="arrows-rotate">
    Renouvelez périodiquement vos identifiants comme mesure de sécurité.
  </Card>

  <Card title="Utilisez des scopes minimaux" icon="shield-check">
    Demandez uniquement les autorisations OAuth dont votre application a besoin.
  </Card>
</CardGroup>
