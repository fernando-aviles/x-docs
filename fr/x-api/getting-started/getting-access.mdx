Commencez à utiliser X API en trois étapes : inscrivez-vous, créez une application et enregistrez vos identifiants.

<Button href="https://console.x.com">Inscrivez-vous maintenant</Button>

***

<div id="step-1-create-a-developer-account">
  ## Étape 1 : Créer un compte développeur
</div>

<Steps>
  <Step title="Accéder à la Console de développement">
    Rendez-vous sur [console.x.com](https://console.x.com) et connectez-vous avec votre compte X.
  </Step>

  <Step title="Accepter le contrat développeur">
    Consultez et acceptez le contrat développeur et la politique développeur.
  </Step>

  <Step title="Complétez votre profil">
    Fournissez des informations de base sur la façon dont vous utiliserez l&#39;API.
  </Step>
</Steps>

***

<div id="step-2-create-an-app">
  ## Étape 2 : Créer une application
</div>

Après vous être inscrit, créez une application pour obtenir vos identifiants d’API :

<Steps>
  <Step title="Cliquez sur « New App »">
    Depuis le tableau de bord de la Console de développement, créez une nouvelle application.
  </Step>

  <Step title="Saisissez les détails de l’application">
    Indiquez un nom, une description et un cas d’utilisation pour votre application.
  </Step>

  <Step title="Générez les identifiants">
    La console génère vos clés et jetons d’API.
  </Step>
</Steps>

***

<div id="step-3-save-your-credentials">
  ## Étape 3 : Enregistrez vos identifiants
</div>

Vous recevrez plusieurs identifiants selon vos besoins d&#39;authentification :

| Identifiant | Utilisation |
|:-----------|:------------|
| **API Key &amp; Secret** | Identifier votre application. Utilisés pour générer des jetons et signer les requêtes OAuth 1.0a. |
| **Jeton Bearer** | Authentification App-only pour lire des données publiques. |
| **Access Token &amp; Secret** | Effectuer des requêtes au nom de votre propre compte (OAuth 1.0a). |
| **Client ID &amp; Secret** | Authentification OAuth 2.0 pour les requêtes en contexte utilisateur. |

<Warning>
  **Enregistrez-les immédiatement.** Les identifiants ne sont affichés qu&#39;une seule fois. Stockez-les dans un gestionnaire de mots de passe ou un coffre-fort sécurisé. Si vous les perdez, vous devrez les régénérer (ce qui invalide les anciens).
</Warning>

***

<div id="which-credentials-do-you-need">
  ## De quels identifiants avez-vous besoin ?
</div>

<Tabs>
  <Tab title="Lecture de données publiques">
    Utilisez le **Jeton Bearer** pour un accès simple, en lecture seule, aux données publiques.

    ```bash
    curl "https://api.x.com/2/users/by/username/xdevelopers" \
      -H "Authorization: Bearer $BEARER_TOKEN"
    ```

    Idéal pour : rechercher des Publications, consulter des informations sur des utilisateurs, lire les tendances.
  </Tab>

  <Tab title="Agir en tant qu’utilisateur">
    Utilisez **OAuth 2.0** (recommandé) ou **OAuth 1.0a** pour agir au nom des utilisateurs.

    OAuth 2.0 offre des périmètres d’autorisation granulaires : demandez uniquement les autorisations dont vous avez besoin.

    Idéal pour : publier, aimer, suivre, accéder aux messages privés (DM).

    [Guide OAuth 2.0 →](/fr/resources/fundamentals/authentication/oauth-2-0/overview)
  </Tab>

  <Tab title="Agir en votre nom">
    Utilisez votre **Access Token &amp; Secret** pour effectuer des requêtes à partir de votre propre compte.

    Ces jetons représentent le compte propriétaire de l’App.

    Idéal pour : les tests, les bots personnels, vos propres automatisations.
  </Tab>
</Tabs>

<div id="credential-security-best-practices">
  ## Meilleures pratiques de sécurité pour les identifiants
</div>

<CardGroup cols={2}>
  <Card title="Utiliser des variables d'environnement" icon="terminal">
    Ne codez jamais vos identifiants en dur dans votre code source.
  </Card>

  <Card title="Ne pas valider dans Git" icon="code-branch">
    Ajoutez les fichiers d’identifiants à `.gitignore`.
  </Card>

  <Card title="Renouveler régulièrement" icon="arrows-rotate">
    Renouvelez régulièrement vos identifiants à titre de mesure de sécurité.
  </Card>

  <Card title="Utiliser des scopes minimaux" icon="shield-check">
    Ne demandez que les autorisations OAuth strictement nécessaires à votre App.
  </Card>
</CardGroup>
