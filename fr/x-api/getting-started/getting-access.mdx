Pour commencer avec X API, suivez trois étapes : inscrivez-vous, créez une application et enregistrez vos identifiants.

<Button href="https://console.x.com">Inscrivez-vous maintenant</Button>

***

<div id="step-1-create-a-developer-account">
  ## Étape 1 : Créer un compte développeur
</div>

<Steps>
  <Step title="Accéder à la Developer Console">
    Accédez à [console.x.com](https://console.x.com) et connectez-vous avec votre compte X.
  </Step>

  <Step title="Accepter le Contrat développeur">
    Lisez puis acceptez le Contrat développeur et la Politique développeur.
  </Step>

  <Step title="Compléter votre profil">
    Renseignez des informations de base sur votre utilisation de l’API.
  </Step>
</Steps>

***

<div id="step-2-create-an-app">
  ## Étape 2 : Créer une application
</div>

Après votre inscription, créez une application pour obtenir vos identifiants d’API :

<Steps>
  <Step title="Cliquez sur « New App »">
    Depuis le tableau de bord de la Developer Console, créez une nouvelle application.
  </Step>

  <Step title="Renseignez les détails de l’application">
    Indiquez un nom, une description et un cas d’usage pour votre application.
  </Step>

  <Step title="Générez les identifiants">
    La console générera vos clés et jetons d’API.
  </Step>
</Steps>

***

<div id="step-3-save-your-credentials">
  ## Étape 3 : Enregistrez vos identifiants
</div>

Vous recevrez plusieurs identifiants en fonction de vos besoins d’authentification :

| Identifiant | Objectif |
|:-----------|:---------|
| **API Key &amp; Secret** | Identifier votre application. Utilisés pour générer des jetons et signer les requêtes OAuth 1.0a. |
| **Bearer Token** | Authentification en mode application seule pour la lecture de données publiques. |
| **Access Token &amp; Secret** | Effectuer des requêtes en votre nom (OAuth 1.0a). |
| **Client ID &amp; Secret** | Authentification OAuth 2.0 pour des requêtes avec contexte utilisateur. |

<Warning>
  **Enregistrez-les immédiatement.** Les identifiants ne sont affichés qu’une seule fois. Stockez-les dans un gestionnaire de mots de passe ou un coffre-fort sécurisé. Si vous les perdez, vous devrez les régénérer (ce qui invalide les anciens).
</Warning>

***

<div id="which-credentials-do-you-need">
  ## De quels identifiants avez-vous besoin ?
</div>

<Tabs>
  <Tab title="Lecture des données publiques">
    Utilisez le **Bearer Token** pour un accès simple, en lecture seule, aux données publiques.

    ```bash
    curl "https://api.x.com/2/users/by/username/xdevelopers" \
      -H "Authorization: Bearer $BEARER_TOKEN"
    ```

    Idéal pour : rechercher des publications, consulter des utilisateurs, suivre les tendances.
  </Tab>

  <Tab title="Agir en tant qu’utilisateur">
    Utilisez **OAuth 2.0** (recommandé) ou **OAuth 1.0a** pour agir au nom des utilisateurs.

    OAuth 2.0 offre des périmètres d’autorisation précis : demandez uniquement les autorisations dont vous avez besoin.

    Idéal pour : publier, aimer, suivre, accéder aux DM.

    [Guide OAuth 2.0 →](/fr/resources/fundamentals/authentication/oauth-2-0/overview)
  </Tab>

  <Tab title="Agir en votre nom">
    Utilisez votre **Access Token &amp; Secret** pour effectuer des requêtes avec votre propre compte.

    Ces jetons représentent le compte propriétaire de l’application.

    Idéal pour : les tests, les bots personnels, votre propre automatisation.
  </Tab>
</Tabs>

<div id="credential-security-best-practices">
  ## Bonnes pratiques de sécurité pour les identifiants
</div>

<CardGroup cols={2}>
  <Card title="Utiliser des variables d'environnement" icon="terminal">
    Ne codez jamais en dur vos identifiants dans votre code source.
  </Card>

  <Card title="Ne pas valider dans Git" icon="code-branch">
    Ajoutez les fichiers d&#39;identifiants à `.gitignore`.
  </Card>

  <Card title="Renouveler régulièrement" icon="arrows-rotate">
    Régénérez périodiquement les identifiants comme mesure de sécurité.
  </Card>

  <Card title="Utiliser des scopes minimaux" icon="shield-check">
    Demandez uniquement les autorisations OAuth dont votre application a besoin.
  </Card>
</CardGroup>
