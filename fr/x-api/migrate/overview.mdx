<div id="what-is-the-x-api-v2">
  ## Qu’est-ce que la X API v2 ?
</div>

La X API v2 est désormais la X API principale, et c’est là que se concentrent les investissements produit et l’innovation. Nous avons collaboré avec des développeurs pour créer la nouvelle génération de la X API afin de mieux répondre aux besoins de notre communauté de développeurs, très diversifiée. Sur la base des retours des développeurs, nous avons reconstruit l’API pour mieux couvrir un éventail plus large de besoins, introduit de nouvelles fonctionnalités et de nouveaux endpoints, et amélioré l’expérience des développeurs.

La X API v2 est désormais la X API principale, et c’est là que se concentrent les investissements produit et l’innovation. Au cours des dernières années, nous avons collaboré avec des développeurs et reconstruit l’API pour mieux couvrir un éventail plus large de besoins, introduire de nouvelles fonctionnalités et de nouveaux endpoints, et améliorer l’expérience des développeurs. Nous nous engageons à continuer de construire une plateforme ouverte pour les développeurs et nous avons hâte de voir ce que vous créerez avec la X API v2.

<div id="why-migrate">
  ## Pourquoi migrer ?
</div>

X API v2 repose sur une base moderne et plus pérenne et propose à la fois des endpoints de remplacement améliorés pour la v1.1 standard et les produits Enterprise, mais aussi des fonctionnalités entièrement nouvelles. Nous recommandons vivement aux utilisateurs des API héritées (v1.1 et Enterprise) de commencer à migrer vers v2, car nous avons l’intention de les déprécier à terme. Utilisez X API pour écouter et analyser la conversation publique, interagir avec les personnes sur X et innover.

Dans cette section, nous allons examiner les endpoints et les fonctionnalités.

<div id="discover-new-and-updated-response-objects">
  ### Découvrir de nouveaux objets de réponse et des objets mis à jour
</div>

Les six objets de données suivants sont disponibles avec les endpoints v2 :

| Objet | Description |
|:--------|:-------------|
| [Tweet](/fr/x-api/fundamentals/data-dictionary#tweet) | L’objet Tweet comporte une longue liste de champs au niveau racine, tels que `id`, `text` et `created_at`. Les objets Tweet sont également l’objet parent de plusieurs objets enfants, notamment `user`, `media`, `poll` et `place`. |
| [User](/fr/x-api/fundamentals/data-dictionary#user) | L’objet User contient les métadonnées du compte utilisateur X décrivant l’utilisateur référencé. |
| [Spaces](/fr/x-api/fundamentals/data-dictionary#space) | L’objet Space se compose de champs tels que `state`, `host_id`, `is_ticketed` et même `lang`. |
| [Lists](/fr/x-api/fundamentals/data-dictionary#list) | L’objet List contient des informations de base sur la liste demandée, notamment `description`, `member_count` et `owner_id`. |
| [Media](/fr/x-api/fundamentals/data-dictionary#media) | Si un Tweet contient des médias (comme des images), l’objet Media peut alors être demandé à l’aide du paramètre `media.fields` et inclut des champs tels que `media_key`, `type`, `url`, `preview_image_url` et plus encore. |
| [Poll](/fr/x-api/fundamentals/data-dictionary#poll) | Un sondage inclus dans un Tweet n’est pas un objet principal sur un endpoint, mais peut être trouvé et étendu dans l’objet Tweet. |
| [Place](/fr/x-api/fundamentals/data-dictionary#place) | L’objet Place se compose de champs tels que `place_id`, l’objet `geo`, `country_code` et plus encore. Ces informations peuvent être utilisées pour identifier des Tweets et analyser des Tweets en fonction de leur localisation. |

En savoir plus sur [comment utiliser les champs et les expansions](/fr/x-api/fundamentals/data-dictionary#how-to-use-fields-and-expansions).

<div id="flexibility-to-choose-which-objects-and-fields-you-receive">
  ### Flexibilité dans le choix des objets et des champs que vous recevez
</div>

Lorsque vous envoyez une requête à un endpoint GET, vous recevez l’objet de données principal associé à cet endpoint, qui inclut un ensemble de champs par défaut. Par exemple, l’objet Tweet fournit les champs `id` et `text` par défaut.

Si vous souhaitez récupérer des champs supplémentaires avec votre requête, vous devrez utiliser les paramètres [fields](/fr/x-api/fundamentals/fields) et [expansions](/fr/x-api/fundamentals/expansions). Le paramètre expansions vous permet de récupérer des objets de données associés, comme le Tweet épinglé d’un utilisateur ou un objet média, tandis que les paramètres de champs vous permettent de demander des champs spécifiques au sein des objets retournés, au‑delà des valeurs par défaut.

Voici la liste complète des expansions que vous pouvez demander avec les différents endpoints de X API v2 :

| Objet / Ressource | Expansions disponibles |
|:-------------------|:----------------------|
| Tweets            | `author_id`, `edit_history_tweet_ids`, `entities.mentions.username`, `in_reply_to_user_id`, `referenced_tweets.id`, `referenced_tweets.id.author_id`, `attachments.poll_ids`, `attachments.media_keys`, `geo.place_id` |
| Users             | `pinned_tweet_id` |
| Spaces            | `invited_user_ids`, `speaker_ids`, `creator_id`, `host_ids`, `topic_ids` |

Pour en savoir plus, consultez [comment utiliser les champs et les expansions](/fr/x-api/fundamentals/data-dictionary#how-to-use-fields-and-expansions).

<div id="edit-tweets">
  ## Modifier les Tweets
</div>

Les endpoints de X API v2 fournissent des métadonnées sur les Tweets modifiés. La fonctionnalité *Edit Tweet* a d&#39;abord été introduite pour des tests auprès des employés de X le 1er septembre 2022. À partir de cette date, les Tweets éligibles peuvent être modifiés pendant 30 minutes et jusqu&#39;à 5 fois. Pour en savoir plus, consultez [Modifier les Tweets](/fr/x-api/fundamentals/edit-posts).
En utilisant X API v2, un développeur peut déterminer :

* Si un Tweet était éligible à la modification au moment de sa création. Certains Tweets, comme ceux contenant des sondages ou les Tweets programmés, ne peuvent pas être modifiés.
* Que les Tweets sont modifiables pendant 30 minutes et peuvent être modifiés jusqu&#39;à 5 fois. Pour les Tweets modifiables, vous pouvez voir s&#39;il reste du temps pour les modifier et combien de modifications supplémentaires sont possibles.
* Si vous consultez une version modifiée d&#39;un Tweet (dans la plupart des cas, l&#39;API renverra la version la plus récente d&#39;un Tweet, à moins qu&#39;une version antérieure spécifique ne soit demandée par identifiant de Tweet).
* L&#39;historique complet des modifications du Tweet.
* Les interactions attribuées à chaque version du Tweet.

<div id="track-threaded-conversations">
  ## Suivre les fils de conversation
</div>

Un nouveau champ Tweet permet d’identifier à quel fil de conversation un Tweet appartient. Un conversation ID est le Tweet ID du Tweet qui a démarré la conversation. Pour en savoir plus, voir [suivi des conversations](/fr/x-api/fundamentals/conversation-id).

<div id="ready-to-migrate">
  ## Prêt à migrer
</div>

Pour utiliser les endpoints v2, vous aurez besoin des éléments suivants :

* [Un compte développeur](https://developer.x.com/en/portal/petition/essential/basic-info)
* [Une App développeur](https://developer.x.com/en/apps) créée au sein d’un [Projet](resources/fundamentals/projects)
* [Des clés et des jetons](resources/fundamentals/authentication) provenant de l’App développeur de ce Projet

Il est important d’utiliser les clés et les jetons d’une App au sein d’un Projet. Si vous utilisez les clés et les jetons d’une App en dehors d’un Projet, vous ne pourrez pas envoyer de requêtes vers les endpoints v2.

Une fois que vous disposez d’un compte développeur, vous pouvez configurer l’ensemble des éléments ci-dessus dans la [Console de Développement](https://developer.x.com/en/portal/petition/essential/basic-info).

<div id="authentication">
  ### Authentification
</div>

Avec la nouvelle API Twitter, vous utiliserez deux mécanismes d’authentification différents, OAuth 1.0a User Context et OAuth 2.0 Bearer Token, pour accéder à différents endpoints. Chacun remplit un rôle différent lorsque vous effectuez des requêtes vers ces endpoints :

OAuth 1.0a User Context est Obligatoire lorsque vous effectuez une requête pour le compte d’un utilisateur Twitter.
OAuth 2.0 Bearer Token est Obligatoire pour effectuer des requêtes pour le compte de votre App développeur.

<div id="migrating-to-the-new-data-format">
  ## Migration vers le nouveau format de données
</div>

Lorsque vous passez de la v1.1 ou d’Enterprise à la v2, il est important de comprendre que le format dans lequel les données sont renvoyées a considérablement changé. Nous avons ajouté de nouveaux champs, modifié l’ordre des champs et, dans certains cas, supprimé des éléments.

Pour en savoir plus sur ces changements, nous développons une série de guides qui vous aideront à établir la correspondance entre les champs du format de données pré-v2 et les nouveaux champs, et expliqueront comment demander ces nouveaux champs.

Vous pouvez en apprendre davantage en consultant la section [migration des formats de données](/fr/x-api/migrate/data-format-migration) de ce centre de migration, ou en visitant nos guides spécifiques sur les formats de données :

* [Format natif vers X API v2 (v1.1 standard)](/fr/x-api/migrate/data-format-migration#migrating-from-standard-v1-1s-data-format-to-v2)
* [Native Enriched vers X API v2 (Enterprise)](/fr/x-api/migrate/data-format-migration#migrating-from-native-enriched-data-format-to-v2)
