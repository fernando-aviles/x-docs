<div id="what-is-the-x-api-v2">
  ## Qu’est-ce que la X API v2 ?
</div>

La X API v2 est désormais la X API principale, et c’est là que se concentrent les investissements produits et l’innovation. Nous avons collaboré avec des développeurs pour créer la nouvelle génération de la X API afin de mieux répondre aux besoins de notre communauté de développeurs, très diversifiée. Sur la base des retours des développeurs, nous avons refondu l’API pour couvrir un éventail plus large de besoins, introduit de nouvelles fonctionnalités et de nouveaux endpoints, et amélioré l’expérience développeur.

Au cours des dernières années, nous avons collaboré avec des développeurs et refondu l’API pour couvrir un éventail plus large de besoins, introduire de nouvelles fonctionnalités et de nouveaux endpoints, et améliorer l’expérience développeur. Nous nous engageons à continuer de construire une plateforme de développement ouverte, et nous sommes impatients de voir ce que vous allez créer avec la X API v2.

<div id="why-migrate">
  ## Pourquoi migrer ?
</div>

L’API X v2 est construite sur une base moderne et plus durable et comprend à la fois des endpoints de remplacement améliorés pour la version standard v1.1 et les produits Enterprise, mais aussi des fonctionnalités entièrement nouvelles. Nous encourageons fortement les clients des API héritées (v1.1 et Enterprise) à commencer à migrer vers v2, car nous avons l’intention de les supprimer progressivement. Utilisez l’API X pour écouter et analyser la conversation publique, interagir avec les personnes sur X et innover.

Dans cette section, nous aborderons les endpoints et les fonctionnalités.

<div id="discover-new-and-updated-response-objects">
  ### Découvrez les nouveaux objets de réponse et les objets mis à jour
</div>

Les six objets de données suivants sont disponibles via les endpoints v2 :

| Objet | Description |
|:--------|:-------------|
| [Tweet](/fr/x-api/fundamentals/data-dictionary#tweet) | L&#39;objet Tweet possède une longue liste de champs au niveau racine, tels que `id`, `text` et `created_at`. Les objets Tweet sont également l&#39;objet parent de plusieurs objets enfants, notamment `user`, `media`, `poll` et `place`. |
| [User](/fr/x-api/fundamentals/data-dictionary#user) | L&#39;objet User contient les métadonnées du compte utilisateur X décrivant l&#39;utilisateur référencé. |
| [Spaces](/fr/x-api/fundamentals/data-dictionary#space) | L&#39;objet Space se compose de champs tels que `state`, `host_id`, `is_ticketed` et même `lang`. |
| [Lists](/fr/x-api/fundamentals/data-dictionary#list) | L&#39;objet List contient des informations de base sur la liste demandée, notamment `description`, `member_count` et `owner_id`. |
| [Media](/fr/x-api/fundamentals/data-dictionary#media) | Si un Tweet contient des médias (tels que des images), l&#39;objet media peut être récupéré à l&#39;aide du paramètre `media.fields` et inclut des champs tels que `media_key`, `type`, `url`, `preview_image_url` et plus encore. |
| [Poll](/fr/x-api/fundamentals/data-dictionary#poll) | Un sondage inclus dans un Tweet n&#39;est pas un objet principal sur un endpoint, mais peut être trouvé et développé dans l&#39;objet Tweet. |
| [Place](/fr/x-api/fundamentals/data-dictionary#place) | L&#39;objet Place se compose de champs tels que `place_id`, l&#39;objet `geo`, `country_code` et plus encore. Ces informations peuvent être utilisées pour identifier des Tweets et analyser des Tweets par lieu. |

En savoir plus sur [comment utiliser les champs et les expansions](/fr/x-api/fundamentals/data-dictionary#how-to-use-fields-and-expansions).

<div id="flexibility-to-choose-which-objects-and-fields-you-receive">
  ### Flexibilité dans le choix des objets et des champs que vous recevez
</div>

Lorsque vous effectuez une requête vers un endpoint GET, vous recevez l’objet de données principal associé à cet endpoint, qui inclut un ensemble de champs par défaut. Par exemple, l’objet Tweet fournit les champs `id` et `text` par défaut.

Si vous souhaitez récupérer des champs supplémentaires avec votre requête, vous devez utiliser les paramètres [fields](/fr/x-api/fundamentals/fields) et [expansions](/fr/x-api/fundamentals/expansions). Le paramètre expansions vous permet de récupérer des objets de données associés, comme le Tweet épinglé d’un utilisateur ou un objet média, tandis que les paramètres fields vous permettent de demander des champs spécifiques dans les objets retournés, au-delà des champs par défaut.

Voici la liste complète des expansions que vous pouvez demander avec les différents endpoints de X API v2 :

| Objet / Ressource | Expansions disponibles |
|:-------------------|:----------------------|
| Tweets            | `author_id`, `edit_history_tweet_ids`, `entities.mentions.username`, `in_reply_to_user_id`, `referenced_tweets.id`, `referenced_tweets.id.author_id`, `attachments.poll_ids`, `attachments.media_keys`, `geo.place_id` |
| Users             | `pinned_tweet_id` |
| Spaces            | `invited_user_ids`, `speaker_ids`, `creator_id`, `host_ids`, `topic_ids` |

En savoir plus sur [la façon d’utiliser fields et expansions](/fr/x-api/fundamentals/data-dictionary#how-to-use-fields-and-expansions).

<div id="edit-tweets">
  ## Modifier des Tweets
</div>

Les endpoints de X API v2 fournissent des métadonnées sur les Tweets modifiés. La fonctionnalité *Edit Tweet* a d’abord été introduite pour des tests auprès des employés de X le 1er septembre 2022. À partir de cette date, les Tweets éligibles sont modifiables pendant 30 minutes et jusqu’à 5 fois. En savoir plus sur [Edit Tweets](/fr/x-api/fundamentals/edit-posts).
Avec X API v2, un développeur peut déterminer :

* Si un Tweet était éligible à la modification au moment de sa création. Certains Tweets, comme ceux avec des sondages ou les Tweets programmés, ne peuvent pas être modifiés.
* Les Tweets sont modifiables pendant 30 minutes et peuvent être modifiés jusqu’à 5 fois. Pour les Tweets modifiables, vous pouvez voir s’il reste du temps pour les modifier et combien de modifications supplémentaires sont possibles.
* Si vous consultez une version modifiée d’un Tweet (dans la plupart des cas, l’API renverra la version la plus récente d’un Tweet, sauf si une version antérieure spécifique est demandée par Tweet ID).
* L’historique complet des modifications du Tweet.
* L’engagement attribué à chaque version du Tweet.

</div>

Un nouveau champ Tweet permet d’identifier à quel fil de conversation un Tweet appartient. L’identifiant de conversation est l’identifiant du Tweet qui a lancé la conversation. En savoir plus sur le [suivi des conversations](/fr/x-api/fundamentals/conversation-id).

<div id="ready-to-migrate">
  ## Prêt à migrer
</div>

Afin d’utiliser les endpoints v2, vous devez disposer des éléments suivants :

* [Un compte développeur](https://developer.x.com/en/portal/petition/essential/basic-info)
* [Une App développeur](https://developer.x.com/en/apps) créée au sein d’un [Projet](resources/fundamentals/projects)
* [Des clés et des tokens](resources/fundamentals/authentication) provenant de l’App développeur de ce Projet

Veuillez noter l’importance d’utiliser les clés et les tokens d’une App au sein d’un Projet. Si vous utilisez les clés et les tokens d’une App en dehors d’un Projet, vous ne pourrez pas effectuer de requête vers les endpoints v2.

Une fois que vous disposez d’un compte développeur, vous pouvez configurer tous les éléments ci-dessus dans la [Developer Console](https://developer.x.com/en/portal/petition/essential/basic-info).

<div id="authentication">
  ### Authentication
</div>

Avec la nouvelle API Twitter, vous utiliserez deux modèles d’authentification différents, OAuth 1.0a User Context et OAuth 2.0 Bearer Token, pour accéder à différents endpoints. Chacun remplit un objectif différent lors de l’envoi de requêtes vers ces endpoints :

OAuth 1.0a User Context est obligatoire lorsque vous effectuez une requête pour le compte d’un utilisateur Twitter.
OAuth 2.0 Bearer Token est obligatoire pour effectuer des requêtes pour le compte de votre App développeur.

<div id="migrating-to-the-new-data-format">
  ## Migration vers le nouveau format de données
</div>

Lorsque vous passez de la v1.1 ou de l’offre enterprise à la v2, il est important de comprendre que le format dans lequel les données sont livrées a considérablement changé. Nous avons ajouté de nouveaux champs, modifié l’ordre des champs et, dans certains cas, supprimé des éléments.

Pour en savoir plus sur ces changements, nous préparons une série de guides qui vous aideront à faire correspondre les champs du format de données pré‑v2 aux nouveaux champs, et à expliquer comment demander ces nouveaux champs.

Vous pouvez en apprendre davantage en visitant la section [migration des formats de données](/fr/x-api/migrate/data-format-migration) de ce hub de migration, ou en consultant nos guides spécifiques sur les formats de données :
