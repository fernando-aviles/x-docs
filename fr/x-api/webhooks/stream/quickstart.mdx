<div id="getting-started-with-the-filtered-stream-webhooks-api">
  ## Premiers pas avec l’API de webhooks de flux filtré
</div>

L’API de webhooks de flux filtré v2 est similaire au [point de terminaison de flux filtré v2](/fr/x-api/posts/filtered-stream/introduction) en ce qui concerne la configuration des règles de filtrage. La différence réside dans le mécanisme d’acheminement des Publications qui correspondent à vos règles.

* Dans le cas du point de terminaison de flux filtré v2, vous devez établir une connexion persistante et écouter les Publications qui correspondent à vos règles.
* Dans le cas de ce point de terminaison de webhook de flux filtré, vous enregistrez votre webhook et X envoie les Publications correspondant à vos règles à votre webhook.

Ce guide explique comment filtrer et recevoir des Publications à l’aide des points de terminaison de webhooks de flux filtré. Il y a 3 étapes :

1. Configurer vos règles de flux filtré
2. Créer votre webhook
3. Lier votre instance de flux filtré à votre webhook

Une fois que vous avez lié votre instance de flux filtré à votre webhook, X enverra les Publications qui correspondent à vos règles à votre webhook.

<div id="setting-up-your-filtered-stream-rules">
  ### Configuration de vos règles de flux filtré
</div>

Les règles de flux filtré sont constituées d’un ou de plusieurs opérateurs combinés à l’aide de logique booléenne et de parenthèses afin de déterminer quelles Publications seront envoyées à vos webhooks. L’API de webhooks de flux filtré utilise le même ensemble de endpoints que l’[endpoint de flux filtré v2](/fr/x-api/posts/filtered-stream/introduction) pour créer et gérer des règles. Consultez [ce guide détaillé](/fr/x-api/posts/filtered-stream/integrate/build-a-rule) qui explique comment créer des filtres.

<div id="creating-your-webhook">
  ### Création de votre webhook
</div>

Créez un webhook pour recevoir des événements en enregistrant une URL HTTPS publiquement accessible auprès de X API. Les webhooks doivent gérer les requêtes GET pour la validation CRC et les requêtes POST pour les charges utiles d’événements. Suivez la [documentation d’introduction aux webhooks](/fr/x-api/webhooks/introduction) pour des étapes détaillées sur la création et la gestion des webhooks.

**Remarque :** Si vous utilisez déjà des webhooks pour l’[Account Activity API (AAA)](/fr/x-api/account-activity/introduction), les webhooks configurés pour celle-ci sont exactement les mêmes ici. En fait, vous pouvez utiliser le même endpoint de webhook que celui que vous utilisez pour AAA pour cette API, si vous avez la capacité nécessaire et pouvez distinguer les événements.

<div id="linking-your-filtered-stream-instance-to-your-webhook">
  ### Lier votre instance Filtered Stream à votre webhook
</div>

Une fois vos règles définies et le webhook créé, liez le webhook à votre instance Filtered Stream. Cela achemine les événements de Publication correspondants vers l’URL de votre webhook.

Utilisez l’endpoint : `POST /2/tweets/search/webhooks/:webhook_id `

Vous pouvez inclure des paramètres de requête identiques à ceux utilisés dans l’endpoint de streaming `/2/tweets/search/stream`, tels que expansions, champs et options de média. Cela personnalise les données incluses dans les charges utiles d’événements.

**Exemple :**

```bash
curl --request POST \ 
  --url 
'https://api.x.com/2/tweets/search/webhooks/123456789012345678?ex
pansions=author_id&user.fields=username,name,id' \ 
  --header 'Authorization: Bearer $BEARER_TOKEN' 
```

Exemple de réponse réussie :

```json
{ 
  "data": { 
    "provisioned": true 
  } 
}
```

**Conseil :** Vous pouvez associer plusieurs webhooks à un même flux pour assurer la redondance ou pour recevoir différents ensembles de champs. Chaque liaison peut spécifier des paramètres uniques.

Une fois que vous avez associé votre instance de Filtered Stream à votre webhook, vous commencerez à recevoir des Publications correspondant à vos règles, comme illustré ci-dessous :

```json
{
    "data": {
        "id": "1346889436626259968",
        "text": "Apprenez à utiliser les points de terminaison de chronologie des publications utilisateur et de mentions utilisateur dans l'API X v2 pour explorer les publications… https://t.co/56a0vZUx7i",
        "created_at": "2021-01-06T18:40:40.000Z",
        "author_id": "2244994945"
    },
    "includes": {
        "users": [
            {
                "id": "2244994945",
                "name": "Developers",
                "username": "Xdevelopers",
                "created_at": "2013-12-14T04:35:55Z",
                "protected": false
            }
        ]
    },
    "matching_rules": [
        {
            "id": "120897978112909812",
            "tag": "api-posts"
        }
    ]
}
```

<div id="retrieving-webhooks-linked-to-filtered-stream">
  ### Récupération des webhooks associés au flux filtré
</div>

Récupérez la liste de tous les webhooks actuellement associés à votre flux filtré :

```bash
GET /2/tweets/search/stream/webhooks 
```

Exemple de réponse :

```json
{
    "data": {
        "links": [
            {
                "application_id": "29893711",
                "business_user_id": "1877374016438091776",
                "fields": [
                    "user.fields=username",
                    "name",
                    "id",
                    "expansions=author_id"
                ],
                "instance_id": "1877375130462289920",
                "webhook_id": "1952390923729424384"
            }
        ]
    }
}
```

<div id="unlinking-your-webhook-from-filtered-stream">
  ### Dissocier votre webhook de Filtered Stream
</div>

Pour cesser de recevoir des événements sur un webhook spécifique, dissociez‑le en utilisant :

```bash
DELETE /2/tweets/search/webhooks/:webhook_id
```

La réponse sera la suivante :

```json
{
    "data": {
        "deleted": true
    }
}
```
