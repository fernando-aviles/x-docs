Les webhooks permettent d’acheminer des données en temps réel vers votre serveur. Plutôt que de sonder périodiquement pour détecter des mises à jour, vous recevez les données à mesure que les événements se produisent.

<div id="how-webhooks-work">
  ## Fonctionnement des webhooks
</div>

```
┌──────────┐      ┌──────────┐      ┌──────────┐
│ X Event  │  →   │ X Server │  →   │ Your     │
│ Occurs   │      │          │      │ Webhook  │
└──────────┘      └──────────┘      └──────────┘
```

1. **Événement déclenché** — Un utilisateur publie, envoie un DM, etc.
2. **X envoie une requête** — Requête POST vers l’URL de votre webhook
3. **Vous traitez l’événement** — Votre serveur gère l’événement
4. **Répondre avec 200** — Renvoyer un 200 OK pour accuser réception

<div id="webhook-requirements">
  ## Exigences pour les webhooks
</div>

| Exigence | Description |
|:------------|:------------|
| **HTTPS** | L’URL du webhook doit utiliser HTTPS |
| **Public** | L’URL doit être accessible publiquement |
| **Réponse rapide** | Répondre dans un délai de 10 secondes |
| **200 OK** | Renvoyer un statut 200 pour accuser réception |

<div id="challenge-response-check-crc">
  ### Vérification Challenge-Response (CRC)
</div>

X vérifie votre webhook en envoyant une requête CRC. Répondez en renvoyant un hachage HMAC-SHA256 :

```python
import hmac
import hashlib
import base64

def handle_crc(crc_token, consumer_secret):
    sha256_hash = hmac.new(
        consumer_secret.encode(),
        crc_token.encode(),
        hashlib.sha256
    ).digest()
    
    return {
        "response_token": "sha256=" + base64.b64encode(sha256_hash).decode()
    }
```

<div id="signature-verification">
  ### Vérification de la signature
</div>

Vérifiez l’authenticité du webhook à l’aide de l’en-tête `x-twitter-webhooks-signature`.
