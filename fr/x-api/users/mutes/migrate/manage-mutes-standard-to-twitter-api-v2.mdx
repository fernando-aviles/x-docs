<div id="manage-mutes-standard-v11-compared-to-x-api-v2">
  ### Gérer les mises en sourdine : version standard v1.1 par rapport à X API v2
</div>

Si vous avez utilisé les endpoints standard de la v1.1 [POST mutes/users/create](https://developer.x.com/en/docs/twitter-api/v1/accounts-and-users/mute-block-report-users/api-reference/post-mutes-users-create) et [POST mutes/users/destroy](https://developer.x.com/en/docs/twitter-api/v1/accounts-and-users/mute-block-report-users/api-reference/post-mutes-users-destroy), l’objectif de ce guide est de vous aider à comprendre les similitudes et les différences entre les endpoints de gestion des mises en sourdine de la version standard v1.1 et de X API v2.

* **Similarités**
  * OAuth 1.0a User Context
* **Différences**
  * URL des endpoints
  * Exigences relatives aux applications et aux Projets
  * Méthodes HTTP
  * Paramètres de requête

<div id="similarities">
  #### Similarités
</div>

**Méthode d’authentification OAuth 1.0a User Context**

Les deux versions de cet endpoint prennent en charge [OAuth 1.0a User Context](https://developer.x.com/content/developer-twitter/resources/fundamentals/authentication). Par conséquent, si vous utilisiez auparavant l’un des endpoints standard v1.1 de gestion des mises en sourdine, vous pouvez continuer à utiliser la même méthode d’authentification si vous migrez vers la version X API v2.

<div id="differences">
  #### Différences
</div>

**URL des endpoints**

* Endpoints standard v1.1 :
  * POST https://api.x.com/1.1/mutes/users/create.json
    (mettre un utilisateur en sourdine)
  * POST https://api.x.com/1.1/mutes/users/destroy.json
    (réactiver le son pour un utilisateur)
* Endpoints X API v2 :
  * POST https://api.x.com/2/users/:id/muting
    (mettre un utilisateur en sourdine)
  * DELETE https://api.x.com/2/users/:source&#95;user&#95;id/muting/:target&#95;user&#95;id
    (réactiver le son pour un utilisateur)

**Exigences relatives à l’App et au Projet**

Les endpoints X API v2 requièrent l’utilisation d’identifiants provenant d’une [App développeur](/fr/resources/fundamentals/developer-apps) associée à un [Projet](/fr/resources/fundamentals/developer-apps) lors de l’authentification de vos requêtes. Tous les endpoints X API v1.1 peuvent utiliser des identifiants provenant d’Apps ou d’Apps associées à un Projet.

**Paramètres de requête**

Les paramètres de requête standard v1.1 suivants ont des équivalents dans X API v2 :

| Standard v1.1 | X API v2 |
| :--- | :--- |
| user&#95;id | target&#95;user&#95;id |
| screen&#95;name | Aucun équivalent |

Veuillez noter que les paramètres standard v1.1 sont transmis en tant que paramètres de requête, tandis que les paramètres X API v2 sont transmis en tant que paramètres du corps de la requête (pour le endpoint POST) ou paramètres de chemin (pour le endpoint DELETE).

De plus, un id de l’utilisateur qui met en sourdine un utilisateur cible n’est pas obligatoire lors de l’utilisation des endpoints standard v1.1, car les jetons d’accès transmis avec [OAuth 1.0a User Context](/fr/resources/fundamentals/authentication) permettaient de déduire quel utilisateur initiait la mise ou la levée de la sourdine.

<div id="mute-a-user-v2">
  ### Mettre un utilisateur en sourdine (v2)
</div>

<CodeGroup dropdown>
  ```bash cURL
  curl -X POST "https://api.x.com/2/users/123456789/muting" \
    -H "Authorization: OAuth ..." \
    -H "Content-Type: application/json" \
    -d '{"target_user_id": "2244994945"}'
  ```

  ```python Python
  # Nécessite l'authentification OAuth 1.0a User Context
  import requests
  from requests_oauthlib import OAuth1

  auth = OAuth1(
      "API_KEY", "API_SECRET",
      "ACCESS_TOKEN", "ACCESS_TOKEN_SECRET"
  )

  url = "https://api.x.com/2/users/123456789/muting"
  response = requests.post(url, auth=auth, json={"target_user_id": "2244994945"})
  print(response.json())
  ```

  ```python Python SDK
  from xdk import Client
  from xdk.oauth1_auth import OAuth1

  oauth1 = OAuth1(
      api_key="YOUR_API_KEY",
      api_secret="YOUR_API_SECRET",
      access_token="YOUR_ACCESS_TOKEN",
      access_token_secret="YOUR_ACCESS_TOKEN_SECRET"
  )

  client = Client(auth=oauth1)

  # Mettre un utilisateur en sourdine
  response = client.users.mute(
      source_user_id="123456789",
      target_user_id="2244994945"
  )
  print(f"Mise en sourdine : {response.data.muting}")
  ```

  ```javascript JavaScript SDK
  import { Client, OAuth1 } from "@xdevplatform/xdk";

  const oauth1 = new OAuth1({
    apiKey: "YOUR_API_KEY",
    apiSecret: "YOUR_API_SECRET",
    accessToken: "YOUR_ACCESS_TOKEN",
    accessTokenSecret: "YOUR_ACCESS_TOKEN_SECRET",
  });

  const client = new Client({ oauth1 });

  // Mettre un utilisateur en sourdine
  const response = await client.users.mute("123456789", {
    targetUserId: "2244994945",
  });
  console.log(`Mise en sourdine : ${response.data?.muting}`);
  ```
</CodeGroup>
