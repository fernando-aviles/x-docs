Ce guide présente les principaux concepts nécessaires pour intégrer les endpoints de recherche d’utilisateurs dans votre application.

***

<div id="authentication">
  ## Authentification
</div>

Tous les endpoints X API v2 requièrent une authentification. Choisissez la méthode qui correspond à votre cas d’usage :

| Méthode | Idéale pour | Peut accéder aux métriques privées ? |
|:-------|:---------|:---------------------------|
| [OAuth 2.0 App-Only](/fr/resources/fundamentals/authentication#oauth-2-0) | Serveur à serveur, données publiques | Non |
| [OAuth 2.0 Authorization Code with PKCE](/fr/resources/fundamentals/authentication#oauth-2-0-authorization-code-flow-with-pkce-2) | Applications destinées aux utilisateurs | Oui (pour les données de l’utilisateur autorisé) |
| [OAuth 1.0a User Context](/fr/resources/fundamentals/authentication) | Anciennes intégrations | Oui (pour les données de l’utilisateur autorisé) |

<div id="app-only-authentication">
  ### Authentification App-only
</div>

Pour les données publiques d’utilisateurs, utilisez un Bearer Token :

<CodeGroup dropdown>
  ```bash cURL
  curl "https://api.x.com/2/users/by/username/XDevelopers" \
    -H "Authorization: Bearer $BEARER_TOKEN"
  ```

  ```python SDK Python
  from xdk import Client

  client = Client(bearer_token="YOUR_BEARER_TOKEN")

  # Récupérer un utilisateur à partir de son nom d’utilisateur
  response = client.users.get_by_username("XDevelopers")
  print(response.data)
  ```

  ```javascript SDK JavaScript
  import { Client } from "@xdevplatform/xdk";

  const client = new Client({ bearerToken: "YOUR_BEARER_TOKEN" });

  const response = await client.users.getByUsername("XDevelopers");
  console.log(response.data);
  ```
</CodeGroup>

<div id="user-context-authentication">
  ### Authentification en contexte utilisateur
</div>

Obligatoire pour l’endpoint de l’utilisateur authentifié (`/2/users/me`) :

<CodeGroup dropdown>
  ```bash cURL
  curl "https://api.x.com/2/users/me" \
    -H "Authorization: Bearer $USER_ACCESS_TOKEN"
  ```

  ```python Python SDK
  from xdk import Client

  # Utilisation d’un jeton d’accès utilisateur OAuth 2.0
  client = Client(bearer_token="YOUR_USER_ACCESS_TOKEN")

  # Récupère le profil de l’utilisateur authentifié
  response = client.users.get_me()
  print(response.data)
  ```

  ```javascript JavaScript SDK
  import { Client } from "@xdevplatform/xdk";

  // Utilisation d’un jeton d’accès utilisateur OAuth 2.0
  const client = new Client({ accessToken: "YOUR_USER_ACCESS_TOKEN" });

  const response = await client.users.getMe();
  console.log(response.data);
  ```
</CodeGroup>

<Warning>
  L’endpoint `/2/users/me` fonctionne uniquement avec une authentification en contexte utilisateur. Les jetons App-only renverront une erreur.
</Warning>

<div id="fields-and-expansions">
  ## Champs et expansions
</div>

X API v2 renvoie par défaut un minimum de données. Utilisez `fields` et `expansions` pour demander exactement ce dont vous avez besoin.

<div id="default-response">
  ### Réponse par défaut
</div>

```json
{
  "data": {
    "id": "2244994945",
    "name": "X Developers",
    "username": "XDevelopers"
  }
}
```

<div id="available-fields">
  ### Champs disponibles
</div>

<Accordion title="user.fields">
  | Champ | Description |
  |:------|:------------|
  | `created_at` | Horodatage de la création du compte |
  | `description` | Biographie de l’utilisateur |
  | `entities` | URL analysées dans la biographie |
  | `location` | Localisation définie par l’utilisateur |
  | `pinned_tweet_id` | ID de la publication épinglée |
  | `profile_image_url` | URL de l’avatar |
  | `protected` | Indique si le compte est protégé |
  | `public_metrics` | Compteurs d’abonnés/abonnements |
  | `url` | URL du site Web |
  | `verified` | Statut de vérification |
  | `withheld` | Informations de retenue |
</Accordion>

<Accordion title="tweet.fields (requires pinned_tweet_id expansion)">
  | Champ | Description |
  |:------|:------------|
  | `created_at` | Horodatage de la création de la publication |
  | `text` | Contenu de la publication |
  | `public_metrics` | Compteurs d’engagement |
  | `entities` | Hashtags, mentions, URL |
</Accordion>

<div id="example-with-fields">
  ### Exemple avec des champs
</div>

<CodeGroup dropdown>
  ```bash cURL
  curl "https://api.x.com/2/users/by/username/XDevelopers?\
  user.fields=created_at,description,public_metrics,verified&\
  expansions=pinned_tweet_id&\
  tweet.fields=created_at,public_metrics" \
    -H "Authorization: Bearer $BEARER_TOKEN"
  ```

  ```python SDK Python
  from xdk import Client

  client = Client(bearer_token="YOUR_BEARER_TOKEN")

  # Récupérer un utilisateur avec des champs supplémentaires et des expansions
  response = client.users.get_by_username(
      "XDevelopers",
      user_fields=["created_at", "description", "public_metrics", "verified"],
      expansions=["pinned_tweet_id"],
      tweet_fields=["created_at", "public_metrics"]
  )

  print(response.data)
  print(response.includes)  # Contient le Tweet épinglé étendu
  ```

  ```javascript SDK JavaScript
  import { Client } from "@xdevplatform/xdk";

  const client = new Client({ bearerToken: "YOUR_BEARER_TOKEN" });

  const response = await client.users.getByUsername("XDevelopers", {
    userFields: ["created_at", "description", "public_metrics", "verified"],
    expansions: ["pinned_tweet_id"],
    tweetFields: ["created_at", "public_metrics"],
  });

  console.log(response.data);
  console.log(response.includes); // Contient le Tweet épinglé étendu
  ```
</CodeGroup>

<div id="batch-lookups">
  ## Recherches groupées
</div>

Recherchez plusieurs utilisateurs en une seule requête :

<CodeGroup dropdown>
  ```bash cURL (par ID)
  curl "https://api.x.com/2/users?ids=2244994945,783214,6253282&\
  user.fields=username,verified" \
    -H "Authorization: Bearer $BEARER_TOKEN"
  ```

  ```bash cURL (par noms d’utilisateur)
  curl "https://api.x.com/2/users/by?usernames=XDevelopers,X,XAPI&\
  user.fields=username,verified" \
    -H "Authorization: Bearer $BEARER_TOKEN"
  ```

  ```python Python SDK
  from xdk import Client

  client = Client(bearer_token="YOUR_BEARER_TOKEN")

  # Récupérer plusieurs utilisateurs par ID
  response = client.users.get_users(
      ids=["2244994945", "783214", "6253282"],
      user_fields=["username", "verified"]
  )
  for user in response.data:
      print(f"{user.username}: {user.verified}")

  # Récupérer plusieurs utilisateurs par noms d’utilisateur
  response = client.users.get_users_by_usernames(
      usernames=["XDevelopers", "X", "XAPI"],
      user_fields=["username", "verified"]
  )
  for user in response.data:
      print(f"{user.username}: {user.verified}")
  ```

  ```javascript JavaScript SDK
  import { Client } from "@xdevplatform/xdk";

  const client = new Client({ bearerToken: "YOUR_BEARER_TOKEN" });

  // Récupérer plusieurs utilisateurs par ID
  const byIds = await client.users.getUsers({
    ids: ["2244994945", "783214", "6253282"],
    userFields: ["username", "verified"],
  });
  byIds.data.forEach((user) => {
    console.log(`${user.username}: ${user.verified}`);
  });

  // Récupérer plusieurs utilisateurs par noms d’utilisateur
  const byUsernames = await client.users.getUsersByUsernames({
    usernames: ["XDevelopers", "X", "XAPI"],
    userFields: ["username", "verified"],
  });
  byUsernames.data.forEach((user) => {
    console.log(`${user.username}: ${user.verified}`);
  });
  ```
</CodeGroup>

<Tip>
  Les requêtes groupées sont limitées à 100 utilisateurs. Utilisez plusieurs requêtes pour des jeux de données plus volumineux.
</Tip>

<div id="error-handling">
  ## Gestion des erreurs
</div>

<div id="common-errors">
  ### Erreurs courantes
</div>

| Statut | Erreur | Solution |
|:-------|:------|:---------|
| 400 | Requête invalide | Vérifiez le format des paramètres |
| 401 | Non autorisé | Vérifiez les informations d’authentification |
| 403 | Accès interdit | Vérifiez les autorisations de l’application |
| 404 | Introuvable | L’utilisateur n’existe pas ou a été suspendu |
| 429 | Trop de requêtes | Attendez puis réessayez (voir les limites de débit) |

<div id="suspended-or-deleted-users">
  ### Utilisateurs suspendus ou supprimés
</div>

Si un utilisateur est suspendu ou supprimé :

* La recherche d’un seul utilisateur renvoie `404`
* La recherche de plusieurs utilisateurs exclut l’utilisateur des résultats avec un tableau `errors`

```json
{
  "data": [
    { "id": "2244994945", "username": "XDevelopers" }
  ],
  "errors": [
    {
      "resource_id": "1234567890",
      "resource_type": "user",
      "title": "Not Found Error",
      "detail": "Could not find user with id: [1234567890]."
    }
  ]
}
```

<div id="protected-users">
  ### Utilisateurs protégés
</div>

Pour les comptes protégés que vous ne suivez pas :

* Les informations de base (id, name, username) sont accessibles
* Le contenu protégé (Publication épinglée) peut être restreint
* `protected: true` indique le statut du compte
