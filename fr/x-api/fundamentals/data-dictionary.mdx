L&#39;API X renvoie des objets JSON structurés représentant des publications, des utilisateurs, des médias et bien plus encore. Cette référence documente chaque champ disponible pour chaque type d&#39;objet.

<div id="post-tweet">
  ## Publication (Tweet)
</div>

Les publications constituent l’unité de contenu principale sur X. Chaque objet Publication inclut du texte, des métadonnées et des références à des objets associés comme les auteurs, les médias et les sondages.

**Champs par défaut :** `id`, `text`, `edit_history_tweet_ids`

Utilisez `tweet.fields` pour demander des champs supplémentaires et `expansions` pour inclure des objets associés.

**Récupération d’un objet Tweet**

**Exemple de requête**

Dans la requête suivante, nous demandons des champs pour le Tweet en utilisant le point de terminaison [Tweets lookup](/fr/resources/fundamentals/rate-limits). Veillez à remplacer `$BEARER_TOKEN` par votre propre [Bearer Token](/fr/resources/fundamentals/authentication) que vous avez généré.

```bash
curl --request GET 'https://api.x.com/2/tweets?ids=1212092628029698048&tweet.fields=attachments,author_id,context_annotations,created_at,entities,geo,id,in_reply_to_user_id,lang,possibly_sensitive,public_metrics,referenced_tweets,text,withheld&expansions=referenced_tweets.id' --header 'Authorization: Bearer $BEARER_TOKEN'
```

<div id="user">
  ### User
</div>

L&#39;objet user contient les métadonnées du compte utilisateur Twitter décrivant l&#39;utilisateur référencé. L&#39;objet user est l&#39;objet principal renvoyé par l&#39;endpoint [users lookup](/fr/x-api/users/lookup/introduction). Lorsque vous demandez des champs utilisateur supplémentaires pour cet endpoint, utilisez simplement le paramètre de champs `user.fields`.

L&#39;objet user peut également apparaître comme objet enfant et être étendu dans l&#39;objet Tweet. L&#39;objet est disponible via `?expansions=author_id` ou `?expansions=in_reply_to_user_id` afin d&#39;obtenir l&#39;objet condensé avec uniquement les champs par défaut. Utilisez cette expansion avec le paramètre de champs `user.fields` lorsque vous demandez des champs supplémentaires pour compléter l&#39;objet.

<div id="space">
  ### Space
</div>

Les Spaces permettent l’expression et l’interaction via des conversations audio en direct. Le dictionnaire de données Space contient les métadonnées pertinentes à propos d’un Space ; tous les détails sont mis à jour en temps réel.

Les objets User peuvent être trouvés et étendus dans la ressource user. Ces objets peuvent être étendus en ajoutant au moins l’un de `host_ids`, `creator_id`, `speaker_ids`, `mentioned_user_ids` au paramètre de requête `expansions`.

Contrairement aux Tweets, les Spaces sont éphémères et deviennent indisponibles une fois qu’ils se terminent ou lorsqu’ils sont annulés par leur créateur. Lorsque votre application traite des données de Spaces, vous êtes responsable de renvoyer les informations les plus récentes et devez supprimer les données qui ne sont plus disponibles sur la plateforme. Les [endpoints de recherche de Spaces](/fr/x-api/spaces/lookup/introduction) peuvent vous aider à vous assurer que vous respectez les attentes et l’intention des utilisateurs.

<div id="list">
  ### List
</div>

L’objet List contient les métadonnées des [Twitter Lists](https://help.x.com/en/using-twitter/twitter-lists) décrivant la List référencée. L’objet List est l’objet principal renvoyé par le point de terminaison de recherche de List. Pour demander des champs supplémentaires de List à partir de ce point de terminaison, utilisez simplement le paramètre de champs `list.fields`.

L’objet List ne se trouve pas en tant qu’enfant d’autres objets data. Cependant, des objets User peuvent être renvoyés et développés dans la ressource user. Ces objets sont disponibles pour une expansion en ajoutant `owner_id` au paramètre de requête `expansions`. Utilisez cette expansion avec le paramètre de champ `list.fields` lorsque vous demandez des champs supplémentaires pour compléter l’objet List principal, et `user.fields` pour compléter l’objet développé.

<div id="direct-message-events">
  ### Événements de messages privés
</div>

Les conversations de messages privés (DM) sont composées d&#39;événements. La X API v2 prend actuellement en charge trois types d&#39;événements : MessageCreate, ParticipantsJoin et ParticipantsLeave.

Les objets d&#39;événement de DM sont renvoyés par les endpoints [Direct Message lookup](/fr/x-api/direct-messages/lookup/introduction), et un événement MessageCreate est créé lorsque des messages privés sont créés avec succès via les endpoints [Manage Direct Messages](/fr/x-api/direct-messages/lookup/introduction).

Lorsque vous interrogez des événements de DM, trois attributs d&#39;objet d&#39;événement par défaut, ou champs, sont inclus : id, event&#95;type et text. Pour recevoir des champs d&#39;événement supplémentaires, utilisez le paramètre [fields](/fr/x-api/fundamentals/fields) dm&#95;event.fields pour en sélectionner d&#39;autres. Les autres champs d&#39;événement disponibles incluent les suivants : dm&#95;conversation&#95;id, created&#95;at, sender&#95;id, attachments, participant&#95;ids et referenced&#95;tweets.

Plusieurs de ces champs fournissent les identifiants d&#39;autres objets X liés à l&#39;événement de message privé :

* sender&#95;id - L&#39;identifiant du compte qui a envoyé le message ou qui a invité un participant à une conversation de groupe
* partricipants&#95;ids - Un tableau d&#39;identifiants de compte. Pour les événements ParticipantsJoin et ParticipantsLeave, ce tableau contient un seul identifiant, celui du compte qui a créé l&#39;événement
* attachments - Fournit les identifiants de média pour le contenu qui a été téléversé sur Twitter par l&#39;expéditeur
* referenced&#95;tweets - Si une URL de Tweet est trouvée dans le champ text, l&#39;identifiant de ce Tweet est inclus dans la Réponse

Les [expansions](/fr/x-api/fundamentals/expansions) sender&#95;id, participant&#95;ids, referenced&#95;tweets.id et attachments.media&#95;keys sont disponibles pour développer ces identifiants d&#39;objets Twitter.

<div id="community">
  ### Communauté
</div>

Les communautés sont des espaces dédiés où les utilisateurs de X peuvent se connecter, partager et se rapprocher des discussions qui les intéressent le plus.

Les publications dans les communautés peuvent être vues par n’importe qui sur X, mais seuls les autres membres de la communauté peuvent interagir et participer à la discussion.

L’objet Community contient des métadonnées pertinentes sur une communauté.

| Field value      | Type            | Description                                                           |    |
| :--------------- | :-------------- | :-------------------------------------------------------------------- | :- |
| created&#95;at   | date (ISO 8601) | Date et heure de création de la communauté.                           |    |
| id               | string          | L’identifiant unique de la communauté.                                |    |
| name             | string          | Le nom de la communauté.                                              |    |
| description      | string          | Le texte de la description de la communauté, si elle est fournie.     |    |
| access           | string          | Le niveau d’accès de la communauté. <br /><br /> Peut être l’un de :  |    |
|                  |                 | - `Public`                                                            |    |
|                  |                 | - `Closed`                                                            |    |
| join&#95;policy  | string          | La règle d’adhésion à la communauté. <br /><br /> Peut être l’un de : |    |
|                  |                 | - `Open`                                                              |    |
|                  |                 | - `RestrictedJoinRequestsDisabled`                                    |    |
|                  |                 | - `RestrictedJoinRequestsRequireAdminApproval`                        |    |
|                  |                 | - `RestrictedJoinRequestsRequireModeratorApproval`                    |    |

<div id="how-to-use-fields-and-expansions">
  ## Comment utiliser les champs et les expansions
</div>

Par défaut, les objets de données de X API v2 incluent un petit nombre de champs par défaut lorsque vous effectuez une requête sans utiliser les paramètres de requête [fields](/fr/x-api/fundamentals/fields) ou [expansions](/fr/x-api/fundamentals/expansions). Ce guide vous montrera comment utiliser les paramètres de requête `fields` et `expansions` dans votre requête pour recevoir des objets et des champs supplémentaires dans votre Réponse.

Dans ce guide, nous demanderons plusieurs champs pour le Tweet présenté dans la capture d’écran suivante.
 

![Cette image inclut une capture d’écran d’un Tweet publié par @X. Vous pouvez voir le texte du Tweet, le nom d’utilisateur, la date et l’heure de publication, la source et les métriques publiques. Elle inclut également une vidéo.](https://cdn.cms-twdigitalassets.com/content/dam/developer-twitter/ScreenShotDataDictionaryGuide.png.twimg.1920.png)

Comme vous pouvez le voir dans la capture d’écran, plusieurs informations visibles sont liées au Tweet, notamment l’auteur du Tweet, les métriques du Tweet, l’horodatage de création, la vidéo et le nombre de vues de la vidéo. Il existe également plusieurs éléments de données qui ne sont pas visibles dans la capture d’écran, mais qui peuvent tout de même être demandés.

Lorsque vous effectuez une requête vers l’API, la Réponse par défaut est simple et ne contient que les champs de Tweet par défaut (id et text). Vous ne recevrez également que l’objet principal renvoyé par le point de terminaison que vous utilisez, et non les objets de données associés qui peuvent être liés à l’objet principal.

Cette simplicité, associée aux paramètres fields et expansions, vous permet de demander uniquement les champs dont vous avez besoin, en fonction de votre cas d’usage. 
 

<div id="requesting-additional-fields-and-objects">
  #### Demande de champs et d&#39;objets supplémentaires.
</div>

Tout d&#39;abord, nous allons récupérer un [objet Tweet](/fr/x-api/fundamentals/data-dictionary#tweet) en utilisant un ID de Tweet et le [point de terminaison GET /tweets](/fr/x-api/posts/lookup/introduction).

Requête :

```bash
curl --request GET --url 'https://api.x.com/2/tweets?ids=1260294888811347969' \
  --header 'Authorization: Bearer $BEARER_TOKEN'
```

Réponse :

```
{
    "data": [
        {
            "id": "1260294888811347969",
            "text": "Ne manquez pas les Tweets concernant votre Tweet. \n\nMaintenant sur iOS, vous pouvez voir tous les Retweets avec commentaires au même endroit. https://t.co/oanjZfzC6y"
        }
    ]
}
```

Le guide étape par étape suivant vous montrera comment récupérer les données supplémentaires visibles dans la capture d&#39;écran.

1. Identifiez les champs supplémentaires que vous souhaitez récupérer en utilisant notre [modèle d’objet](/fr/x-api/fundamentals/data-dictionary#tweet), ou en consultant, dans la Référence de l’API, la liste des champs des différents points de terminaison.

   Dans ce cas, nous allons demander les champs supplémentaires suivants :
   attachments, author&#95;id, created&#95;at, public&#95;metrics.

2. Créez le paramètre de requête `tweet.fields` en définissant sa valeur comme une liste séparée par des virgules des champs ci-dessus :
   `?tweet.fields=attachments,author_id,created_at,public_metrics`

3. Ajoutez le paramètre de requête à l’appel GET /tweets que vous avez effectué précédemment.

Requête :

`curl --request GET --url 'https://api.x.com/2/tweets?ids=1260294888811347969&tweet.fields=attachments,author_id,created_at,public_metrics' \   --header 'Authorization: Bearer $BEARER_TOKEN'`

Réponse :


?expansions=attachments.media&#95;keys

Requête :

?media.fields=public&#95;metrics,duration&#95;ms

Requête :
 

`curl --request GET --url 'https://api.x.com/2/tweets?ids=1260294888811347969&tweet.fields=attachments,author_id,created_at,public_metrics&expansions=attachments.media_keys&media.fields=duration_ms,public_metrics' --header 'Authorization: Bearer $BEARER_TOKEN'`
