<div id="post-tweet">
  ## Publication (Tweet)
</div>

La publication est l’unité de contenu fondamentale sur X. Chaque objet Publication comprend du texte, des métadonnées et des références à des objets associés comme les auteurs, les médias et les sondages.

**Champs par défaut :** `id`, `text`, `edit_history_tweet_ids`

Utilisez `tweet.fields` pour demander des champs supplémentaires et `expansions` pour inclure des objets associés.

**Récupération d’un objet Tweet**

**Exemple de requête**

Dans la requête suivante, nous demandons des champs pour le Tweet via le point de terminaison [Tweets lookup](/fr/resources/fundamentals/rate-limits). Assurez-vous de remplacer `$BEARER_TOKEN` par votre propre [Bearer Token](/fr/resources/fundamentals/authentication) que vous avez généré.

```bash
curl --request GET 'https://api.x.com/2/tweets?ids=1212092628029698048&tweet.fields=attachments,author_id,context_annotations,created_at,entities,geo,id,in_reply_to_user_id,lang,possibly_sensitive,public_metrics,referenced_tweets,text,withheld&expansions=referenced_tweets.id' --header 'Authorization: Bearer $BEARER_TOKEN'
```

<div id="user">
  ### Utilisateur
</div>

L&#39;objet utilisateur contient les métadonnées du compte d’un utilisateur Twitter décrivant l&#39;utilisateur référencé. L&#39;objet utilisateur est l&#39;objet principal renvoyé par l&#39;endpoint [users lookup](/fr/x-api/users/lookup/introduction). Lorsque vous demandez des champs utilisateur supplémentaires pour cet endpoint, utilisez simplement le paramètre `user.fields`.

L&#39;objet utilisateur peut également apparaître comme objet enfant et être étendu dans l&#39;objet Tweet. Il est disponible via le paramètre d’expansion `?expansions=author_id` ou `?expansions=in_reply_to_user_id` afin d&#39;obtenir une version condensée de l&#39;objet ne contenant que les champs par défaut. Utilisez ce paramètre d’expansion avec le paramètre de champs `user.fields` lorsque vous demandez des champs supplémentaires pour compléter l&#39;objet.

<div id="space">
  ### Space
</div>

Les Spaces permettent l’expression et l’interaction via des conversations audio en direct. Le dictionnaire de données Space contient des métadonnées pertinentes sur un Space ; tous les détails sont mis à jour en temps réel.

Les objets User peuvent être trouvés et étendus dans la ressource user. Ces objets peuvent être inclus via `expansions` en ajoutant au moins un des éléments suivants au paramètre de requête `expansions` : `host_ids`, `creator_id`, `speaker_ids`, `mentioned_user_ids`.

Contrairement aux Tweets, les Spaces sont éphémères et deviennent indisponibles une fois terminés ou lorsqu’ils sont annulés par leur créateur. Lorsque votre application gère des données de Spaces, vous êtes responsable de renvoyer les informations les plus récentes et devez supprimer les données qui ne sont plus disponibles sur la plateforme. Les [endpoints de recherche de Spaces](/fr/x-api/spaces/lookup/introduction) peuvent vous aider à respecter les attentes et l’intention des utilisateurs.

Utilisez cette expansion avec le paramètre de champ `list.fields` lorsque vous demandez des champs supplémentaires pour compléter l&#39;objet List principal, et `user.fields` pour compléter l&#39;objet d&#39;expansion.

<div id="direct-message-events">
  ### Événements de messages privés
</div>

Les conversations de messages privés (DM) sont composées d&#39;événements. X API v2 prend actuellement en charge trois types d&#39;événements : MessageCreate, ParticipantsJoin et ParticipantsLeave.

Les objets d&#39;événement de DM sont renvoyés par les endpoints de [recherche de messages privés](/fr/x-api/direct-messages/lookup/introduction), et un événement MessageCreate est créé lorsque des messages privés sont créés avec succès via les endpoints [Gérer les messages privés](/fr/x-api/direct-messages/lookup/introduction).

Lorsque vous demandez des événements de DM, trois attributs d&#39;objet d&#39;événement, ou champs, sont inclus par défaut : id, event&#95;type et text. Pour recevoir des champs d&#39;événement supplémentaires, utilisez le paramètre [fields](/fr/x-api/fundamentals/fields) dm&#95;event.fields pour en sélectionner d&#39;autres. Les autres champs d&#39;événement disponibles incluent notamment : dm&#95;conversation&#95;id, created&#95;at, sender&#95;id, attachments, participant&#95;ids et referenced&#95;tweets.

Plusieurs de ces champs fournissent les ID d&#39;autres objets X associés à l&#39;événement de message privé :

* sender&#95;id - L&#39;ID du compte qui a envoyé le message ou qui a invité un participant à une conversation de groupe
* partricipants&#95;ids - Un tableau d&#39;ID de comptes. Pour les événements ParticipantsJoin et ParticipantsLeave, ce tableau contiendra un seul ID correspondant au compte qui a créé l&#39;événement
* attachments - Fournit les ID de médias pour le contenu qui a été téléversé sur Twitter par l&#39;expéditeur
* referenced&#95;tweets - Si une URL de Tweet est trouvée dans le champ text, l&#39;ID de ce Tweet est inclus dans la réponse

Les expansions [sender&#95;id, participant&#95;ids, referenced&#95;tweets.id et attachments.media&#95;keys](/fr/x-api/fundamentals/expansions) sont disponibles pour développer ces ID d&#39;objets Twitter.

<div id="community">
  ### Communauté
</div>

Les communautés sont des espaces dédiés où les utilisateurs de X peuvent se connecter, partager et se rapprocher des discussions qui les intéressent le plus.

Les publications dans les communautés peuvent être vues par toute personne sur X, mais seuls les autres membres au sein de la communauté elle-même peuvent interagir et participer à la discussion.

L’objet Community contient les métadonnées pertinentes d’une communauté.

| Valeur du champ  | Type            | Description                                                                            |    |
| :--------------- | :-------------- | :------------------------------------------------------------------------------------- | :- |
| created&#95;at   | date (ISO 8601) | Date et heure de création de la communauté.                                            |    |
| id               | string          | L’identifiant unique de la communauté.                                                 |    |
| name             | string          | Le nom de la communauté.                                                               |    |
| description      | string          | Le texte de la description de la communauté, si fourni.                                |    |
| access           | string          | Le niveau d’accès de la communauté. <br /><br /> Peut être l’un des suivants :         |    |
|                  |                 | - `Public`                                                                             |    |
|                  |                 | - `Closed`                                                                             |    |
| join&#95;policy  | string          | La politique d’adhésion de la communauté. <br /><br /> Peut être l’une des suivantes : |    |
|                  |                 | - `Open`                                                                               |    |
|                  |                 | - `RestrictedJoinRequestsDisabled`                                                     |    |
|                  |                 | - `RestrictedJoinRequestsRequireAdminApproval`                                         |    |
|                  |                 | - `RestrictedJoinRequestsRequireModeratorApproval`                                     |    |
|                  |                 | - `SuperFollowRequired`                                                                |    |
| member&#95;count | integer         | Le nombre de membres ayant rejoint la communauté.                                      |    |

```bash
curl --location 'https://api.x.com/2/communities/search?query=anime&amp;community.fields=access,created_at,description,id,join_policy,member_count,name' --header 'Authorization: $BEARER_TOKEN'
```

<div id="how-to-use-fields-and-expansions">
  ## Comment utiliser les champs et les expansions
</div>

Par défaut, les objets de données de X API v2 incluent un petit ensemble de champs par défaut lorsque vous effectuez une requête sans utiliser les paramètres [fields](/fr/x-api/fundamentals/fields) ou [expansions](/fr/x-api/fundamentals/expansions). Ce guide vous montrera comment utiliser les paramètres de requête `fields` et `expansions` dans votre requête afin de recevoir des objets et des champs supplémentaires dans votre réponse.

Dans ce guide, nous allons demander plusieurs champs en nous basant sur la capture d’écran du Tweet suivant.
 

![Cette image inclut une capture d’écran d’un Tweet publié par @X. Vous pouvez voir le texte du Tweet, le nom d’utilisateur, la date et l’heure de publication, la source et les métriques publiques. Elle inclut également une vidéo.](https://cdn.cms-twdigitalassets.com/content/dam/developer-twitter/ScreenShotDataDictionaryGuide.png.twimg.1920.png)

Comme vous pouvez le voir sur la capture d’écran, plusieurs éléments d’information visibles sont liés au Tweet, notamment l’auteur du Tweet, les métriques du Tweet, l’horodatage de création, la vidéo et le nombre de vues de la vidéo. Il existe également plusieurs éléments de données qui ne sont pas visibles dans la capture d’écran, mais qui restent disponibles via une requête. 

Lors de l’envoi d’une requête à l’API, la réponse par défaut est simple et ne contient que les champs de Tweet par défaut (id et text). Vous ne recevrez également que l’objet principal renvoyé par l’endpoint que vous utilisez, et non les objets de données associés qui peuvent être liés à l’objet principal.

Cette simplicité, associée aux paramètres `fields` et `expansions`, vous permet de demander uniquement les champs dont vous avez besoin, en fonction de votre cas d’usage. 
 

<div id="requesting-additional-fields-and-objects">
  #### Demande de champs et d&#39;objets supplémentaires.
</div>

Tout d&#39;abord, nous allons récupérer un [objet Tweet](/fr/x-api/fundamentals/data-dictionary#tweet) en utilisant un ID de Tweet et le [point de terminaison GET /tweets](/fr/x-api/posts/lookup/introduction).

Requête :

```bash
curl --request GET --url 'https://api.x.com/2/tweets?ids=1260294888811347969' \
  --header 'Authorization: Bearer $BEARER_TOKEN'
```

Réponse :

```
{
    "data": [
        {
            "id": "1260294888811347969",
            "text": "Ne manquez pas les Tweets concernant votre Tweet. \n\nMaintenant sur iOS, vous pouvez voir tous les Retweets avec commentaires au même endroit. https://t.co/oanjZfzC6y"
        }
    ]
}
```

Le guide étape par étape suivant vous montrera comment récupérer les données supplémentaires visibles dans la capture d&#39;écran.

1. Identifiez les champs supplémentaires que vous souhaitez récupérer en utilisant notre [modèle d’objet](/fr/x-api/fundamentals/data-dictionary#tweet), ou en consultant la liste des champs dans les pages de Référence de l’API des différents endpoints.

   Dans ce cas, nous allons demander les champs supplémentaires suivants :
   attachments, author&#95;id, created&#95;at, public&#95;metrics.

2. Créez le paramètre de requête `tweet.fields` avec les champs ci-dessus comme valeur, en utilisant une liste de valeurs séparées par des virgules :
   `?tweet.fields=attachments,author_id,created_at,public_metrics`

3. Ajoutez le paramètre de requête à l’appel GET /tweets que vous avez effectué précédemment.

Requête :

`curl --request GET --url 'https://api.x.com/2/tweets?ids=1260294888811347969&tweet.fields=attachments,author_id,created_at,public_metrics' \   --header 'Authorization: Bearer $BEARER_TOKEN'`

Réponse :

```
{
    "data": [
        {
            "id": "1260294888811347969",
            "text": "Ne manquez pas les Tweets à propos de votre Tweet. \n\nMaintenant sur iOS, vous pouvez voir les Retweets avec commentaires au même endroit. https://t.co/oanjZfzC6y",
            "author_id": "783214",

                "retweet_count": 5219,
```

?expansions=attachments.media&#95;keys

Requête :

```bash
curl --request GET --url 'https://api.x.com/2/tweets?ids=1260294888811347969&tweet.fields=attachments,author_id,created_at,public_metrics&expansions=attachments.media_keys' \

```

```
                "type": "video"
            }
        ]

```

5. Enfin, nous allons demander le nombre de vues et la durée de la vidéo. Ces champs ne sont pas renvoyés par défaut, nous devons donc les demander explicitement. Utilisez le paramètre `media.fields` avec les valeurs séparées par des virgules `public_metrics` et `duration_ms` dans votre requête.

?media.fields=public&#95;metrics,duration&#95;ms

Requête :
 

`curl --request GET --url 'https://api.x.com/2/tweets?ids=1260294888811347969&tweet.fields=attachments,author_id,created_at,public_metrics&expansions=attachments.media_keys&media.fields=duration_ms,public_metrics' --header 'Authorization: Bearer $BEARER_TOKEN'`

Au total, nous avons inclus les paramètres suivants pour cet exemple :

* ids=1260294888811347969
* tweet.fields=attachments,author&#95;id,created&#95;at,public&#95;metrics
* expansions=attachments.media&#95;keys
* media.fields=public&#95;metrics,duration&#95;ms
   

Lorsqu’on les combine, voici à quoi ressemble la chaîne de requête complète :

```
?ids=1260294888811347969&tweet.fields=attachments,author\_id,created\_at,public\_metrics&expansions=attachments.media\_keys&media.fields=public\_metrics,duration\_ms
```
