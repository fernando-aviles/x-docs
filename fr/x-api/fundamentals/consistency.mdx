X API v2 est conçue avec des schémas cohérents sur tous les endpoints. Une fois que vous avez compris comment fonctionne un endpoint, ces mêmes schémas s&#39;appliquent partout.

***

<div id="consistent-patterns">
  ## Modèles cohérents
</div>

<div id="url-structure">
  ### Structure des URL
</div>

Tous les endpoints v2 suivent une structure prévisible :

```
/version/resource/{id}?parameters
/version/resource/verb?parameters
```

Exemples :

```
/2/tweets/1234567890                    # Get a specific post
/2/tweets/search/recent                 # Search recent posts
/2/users/by/username/xdevelopers        # Obtenir un utilisateur par nom d'utilisateur
/2/users/1234/followers                 # Get user's followers
```

<div id="response-structure">
  ### Structure de la réponse
</div>

Toutes les réponses utilisent la même structure de haut niveau :

```json
{
  "data": { ... },       // Objet(s) principal(aux)
  "includes": { ... },   // Objets développés
  "meta": { ... },       // Pagination, décomptes
  "errors": [ ... ]      // Erreurs partielles (le cas échéant)
}
```

<div id="id-format">
  ### Format des ID
</div>

Tous les ID sont renvoyés sous forme de chaînes de caractères afin de garantir la compatibilité entre les différents langages de programmation :

```json
{
  "id": "1234567890123456789",
  "author_id": "2244994945"
}
```

***

<div id="fields-and-expansions">
  ## Champs et expansions
</div>

Les mêmes paramètres [fields](/fr/x-api/fundamentals/fields) et [expansions](/fr/x-api/fundamentals/expansions) fonctionnent de manière cohérente :

| Objet | Paramètre de champs | S’applique à |
|:-------|:--------------------|:-------------|
| Publication | `tweet.fields` | Tous les points de terminaison renvoyant des publications |
| Utilisateur | `user.fields` | Tous les points de terminaison renvoyant des utilisateurs |
| Média | `media.fields` | Tous les points de terminaison avec des expansions de médias |
| Sondage | `poll.fields` | Tous les points de terminaison avec des expansions de sondages |
| Lieu | `place.fields` | Tous les points de terminaison avec des expansions de lieux |

***

<div id="object-schemas">
  ## Schémas d&#39;objets
</div>

Le même type d&#39;objet présente les mêmes champs, quel que soit l&#39;endpoint qui le renvoie :

* Une Publication issue de search présente les mêmes champs qu&#39;une Publication issue de lookup
* Un Utilisateur issu de followers présente les mêmes champs qu&#39;un Utilisateur issu de search
* Les objets étendus correspondent à leurs équivalents autonomes

***

<div id="authentication">
  ## Authentification
</div>

Tous les endpoints utilisent les mêmes méthodes d’authentification :

| Méthode | Format de l’en-tête |
|:-------|:--------------|
| Bearer Token | `Authorization: Bearer {token}` |
| OAuth 1.0a | `Authorization: OAuth {parameters}` |
| OAuth 2.0 | `Authorization: Bearer {user_token}` |

***

<div id="error-handling">
  ## Gestion des erreurs
</div>

Les erreurs respectent un format cohérent :

```json
{
  "title": "Requête non valide",
  "detail": "Le paramètre de requête est manquant",
  "type": "https://api.x.com/2/problems/invalid-request"
}
```

[Voir tous les types d’erreurs →](/fr/x-api/fundamentals/response-codes-and-errors)

***

<div id="pagination">
  ## Pagination
</div>

Tous les endpoints avec pagination utilisent le même système de jetons :

| Paramètre | Description |
|:----------|:------------|
| `max_results` | Résultats par page |
| `pagination_token` | Jeton provenant de `next_token` ou `previous_token` |

[En savoir plus sur la pagination →](/fr/x-api/fundamentals/pagination)

***

<div id="naming-conventions">
  ## Conventions de nommage
</div>

* Orthographe en anglais américain (`favorites` et non `favourites`)
* snake&#95;case pour les noms de champs (`author_id`, `created_at`)
* Terminologie cohérente (`retweet_count`, et non `repost_count` dans les champs)

***

<div id="empty-values">
  ## Valeurs vides
</div>

Les champs sans valeur sont omis plutôt que renvoyés en tant que `null` :

```json
// User without a bio
{
  "id": "1234",
  "name": "Example User",
  "username": "example"
  // « description » est omis, pas null
}
```

***

<div id="entity-consistency">
  ## Cohérence des entités
</div>

L&#39;objet `entities` ne contient que les entités extraites du texte :

* `urls`
* `hashtags`
* `mentions`
* `cashtags`

Les médias et les sondages sont dans `attachments`, pas dans `entities`.
