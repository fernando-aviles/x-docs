X API utilise les codes d&#39;état HTTP standard. Les requêtes réussies renvoient des codes 2xx ; les erreurs renvoient des codes 4xx ou 5xx avec des détails dans le corps de la Réponse.

***

<div id="http-status-codes">
  ## Codes de statut HTTP
</div>

<div id="success-codes">
  ### Codes de réussite
</div>

| Code | Signification | Description |
|:-----|:--------|:------------|
| **200** | OK | Requête réussie |
| **201** | Créé | Ressource créée (requêtes POST) |
| **204** | Aucun contenu | Réussite sans corps de réponse (requêtes DELETE) |

<div id="client-error-codes">
  ### Codes d&#39;erreur côté client
</div>

| Code | Signification | Causes courantes |
|:-----|:--------|:--------------|
| **400** | Requête incorrecte | JSON invalide, requête mal formée, paramètres obligatoires manquants |
| **401** | Non autorisé | Identifiants d’authentification invalides ou manquants |
| **403** | Interdit | Authentification valide mais aucune autorisation pour cette ressource ou cette action |
| **404** | Introuvable | La ressource n’existe pas ou a été supprimée |
| **409** | Conflit | Le flux n’a aucune règle (flux filtré uniquement) |
| **429** | Trop de requêtes | Limite de débit ou quota d’utilisation dépassé |

<div id="server-error-codes">
  ### Codes d’erreur du serveur
</div>

| Code | Signification | Que faire |
|:-----|:--------------|:----------|
| **500** | Internal Server Error | Attendez puis réessayez ; consultez la [page d’état](/fr/status) |
| **502** | Bad Gateway | Attendez puis réessayez |
| **503** | Service Unavailable | X est surchargé ; attendez puis réessayez |
| **504** | Gateway Timeout | Attendez puis réessayez |

***

<div id="error-response-format">
  ## Format de réponse d’erreur
</div>

Les réponses d’erreur incluent des détails structurés :

```json
{
  "title": "Invalid Request",
  "detail": "The 'query' parameter is required.",
  "type": "https://api.x.com/2/problems/invalid-request"
}
```

| Champ    | Description                            |
| :------- | :------------------------------------- |
| `type`   | URI identifiant le type d&#39;erreur   |
| `title`  | Courte description de l&#39;erreur     |
| `detail` | Explication spécifique de cette erreur |

Des champs supplémentaires peuvent être présents en fonction du type d&#39;erreur.

***

<div id="error-types">
  ## Types d’erreur
</div>

| Type | Description |
|:-----|:------------|
| `about:blank` | Erreur générique (voir le code d’état HTTP) |
| `.../invalid-request` | Requête mal formée ou paramètres invalides |
| `.../resource-not-found` | Publication, utilisateur ou autre ressource inexistante |
| `.../not-authorized-for-resource` | Aucun accès au contenu privé/protégé |
| `.../client-forbidden` | Application non inscrite ou ne disposant pas des accès requis |
| `.../usage-capped` | Plafond d’utilisation dépassé |
| `.../rate-limit-exceeded` | Limite de débit dépassée |
| `.../streaming-connection` | Problème de connexion au flux |
| `.../rule-cap` | Trop de règles de flux filtré |
| `.../invalid-rules` | Erreur de syntaxe de règle |
| `.../duplicate-rules` | La règle existe déjà |

<div id="partial-errors">
  ## Erreurs partielles
</div>

Certaines requêtes peuvent réussir partiellement. Une réponse 200 peut inclure à la fois `data` et `errors` :

```json
{
  "data": [
    {"id": "123", "text": "Hello"}
  ],
  "errors": [
    {
      "resource_id": "456",
      "resource_type": "tweet",
      "title": "Not Found Error",
      "detail": "Could not find tweet with id: [456].",
      "type": "https://api.x.com/2/problems/resource-not-found"
    }
  ]
}
```

Cela se produit lorsque vous effectuez une requête pour plusieurs ressources et que certaines ne sont pas disponibles.

<div id="troubleshooting-common-errors">
  ## Dépannage des erreurs courantes
</div>

<Accordion title="401 Unauthorized">
  **Vérifiez votre authentification :**

  * Vérifiez que vous utilisez la bonne méthode d’authentification pour l’endpoint
  * Assurez-vous que les identifiants n’ont pas été régénérés
  * Vérifiez le format de l’en-tête `Authorization`
  * Pour OAuth 1.0a, vérifiez le calcul de la signature

  [Guide d’authentification →](/fr/resources/fundamentals/authentication/overview)
</Accordion>

<Accordion title="403 Forbidden">
  **Vérifiez vos droits d’accès :**

  * Vérifiez que votre application a accès à cet endpoint
  * Certains endpoints nécessitent une inscription ou une approbation spécifique
  * Les endpoints en contexte utilisateur nécessitent des scopes OAuth appropriés
  * La ressource peut être privée ou protégée
</Accordion>

<Accordion title="429 Too Many Requests">
  **Limite de débit atteinte :**

  * Vérifiez l’en-tête `x-rate-limit-reset` pour savoir quand réessayer
  * Mettez en œuvre un backoff exponentiel
  * Envisagez de mettre les Réponses en cache
  * Répartissez les requêtes sur la fenêtre temporelle

  [Guide sur les limites de débit →](/fr/x-api/fundamentals/rate-limits)
</Accordion>

<Accordion title="400 Bad Request">
  **Corrigez votre requête :**

  * Validez la syntaxe JSON
  * Vérifiez l’absence de paramètres Obligatoire manquants
  * Vérifiez les types de paramètres (chaînes de caractères vs. nombres)
  * Échappez les caractères spéciaux dans les requêtes
</Accordion>

<Accordion title="Missing expected posts">
  **Vérifiez les éléments suivants :**

  * Les publications des comptes protégés ne sont visibles qu’avec autorisation
  * Les publications supprimées renvoient un code 404
  * Certaines publications sont restreintes dans certaines régions
  * Vérifiez que la syntaxe de la requête de recherche est correcte
</Accordion>

<Accordion title="Stream disconnections">
  **Gérez la reconnexion :**

  * Implémentez une reconnexion automatique avec backoff
  * Utilisez les fonctionnalités de récupération pour les données manquantes
  * Vérifiez les déconnexions dues à un buffer saturé (client ne consommant pas assez vite)
  * Vérifiez qu’au moins une règle de flux existe

  [Guide sur le streaming →](/fr/x-api/posts/filtered-stream/integrate/handling-disconnections)
</Accordion>

<div id="rate-limit-headers">
  ## En-têtes de limitation de débit
</div>

Chaque réponse contient des informations de limitation de débit :

```
x-rate-limit-limit: 900
x-rate-limit-remaining: 847
x-rate-limit-reset: 1705420800
```

| En-tête                  | Description                                               |
| :----------------------- | :-------------------------------------------------------- |
| `x-rate-limit-limit`     | Nombre maximal de requêtes dans la fenêtre actuelle       |
| `x-rate-limit-remaining` | Requêtes restantes                                        |
| `x-rate-limit-reset`     | Horodatage Unix du moment où la fenêtre est réinitialisée |
