X API utilise les codes d’état HTTP standards. Les requêtes réussies renvoient des codes 2xx ; les erreurs renvoient des codes 4xx ou 5xx avec des détails dans le corps de la réponse.

***

<div id="http-status-codes">
  ## Codes d&#39;état HTTP
</div>

<div id="success-codes">
  ### Codes de succès
</div>

| Code | Signification | Description |
|:-----|:--------------|:------------|
| **200** | OK | Requête réussie |
| **201** | Created | Ressource créée (requêtes POST) |
| **204** | No Content | Réussite sans corps de réponse (requêtes DELETE) |

<div id="client-error-codes">
  ### Codes d’erreur client
</div>

| Code | Signification | Causes courantes |
|:-----|:--------------|:-----------------|
| **400** | Requête incorrecte | JSON non valide, requête mal formée, paramètres obligatoires manquants |
| **401** | Non autorisé | Informations d’authentification non valides ou manquantes |
| **403** | Interdit | Authentification valide, mais aucune autorisation pour cette ressource ou cette action |
| **404** | Introuvable | La ressource n’existe pas ou a été supprimée |
| **409** | Conflit | Le flux n’a aucune règle définie (flux filtré uniquement) |
| **429** | Trop de requêtes | Limite de débit ou plafond d’utilisation dépassé |

<div id="server-error-codes">
  ### Codes d’erreur du serveur
</div>

| Code | Signification | Que faire |
|:-----|:--------------|:----------|
| **500** | Erreur interne du serveur | Attendez et réessayez ; consultez la [page d’état](/fr/status) |
| **502** | Mauvaise passerelle | Attendez et réessayez |
| **503** | Service indisponible | X est surchargé ; attendez et réessayez |
| **504** | Délai d’attente de la passerelle dépassé | Attendez et réessayez |

***

<div id="error-response-format">
  ## Format des réponses d’erreur
</div>

Les réponses d’erreur contiennent des informations structurées :

```json
{
  "title": "Invalid Request",
  "detail": "The 'query' parameter is required.",
  "type": "https://api.x.com/2/problems/invalid-request"
}
```

| Champ    | Description                            |
| :------- | :------------------------------------- |
| `type`   | URI qui identifie le type d’erreur     |
| `title`  | Brève description de l’erreur          |
| `detail` | Explication spécifique de cette erreur |

Des champs supplémentaires peuvent être présents en fonction du type d’erreur.

***

<div id="error-types">
  ## Types d’erreurs
</div>

| Type | Description |
|:-----|:------------|
| `about:blank` | Erreur générique (voir le code de statut HTTP) |
| `.../invalid-request` | Requête mal formée ou paramètres invalides |
| `.../resource-not-found` | Publication, utilisateur ou autre ressource inexistante |
| `.../not-authorized-for-resource` | Aucun accès au contenu privé/protégé |
| `.../client-forbidden` | Application non inscrite ou ne disposant pas des accès requis |
| `.../usage-capped` | Plafond d’utilisation dépassé |
| `.../rate-limit-exceeded` | Limite de débit dépassée |
| `.../streaming-connection` | Problème de connexion de streaming |
| `.../rule-cap` | Trop de règles de flux filtré |
| `.../invalid-rules` | Erreur de syntaxe dans la règle |
| `.../duplicate-rules` | Règle déjà définie |

<div id="partial-errors">
  ## Erreurs partielles
</div>

Certaines requêtes peuvent réussir partiellement. Une réponse 200 peut inclure à la fois `data` et `errors` :

```json
{
  "data": [
    {"id": "123", "text": "Hello"}
  ],
  "errors": [
    {
      "resource_id": "456",
      "resource_type": "tweet",
      "title": "Not Found Error",
      "detail": "Could not find tweet with id: [456].",
      "type": "https://api.x.com/2/problems/resource-not-found"
    }
  ]
}
```

Cela se produit lorsque vous effectuez une requête portant sur plusieurs ressources et que certaines ne sont pas disponibles.

<div id="troubleshooting-common-errors">
  ## Dépannage des erreurs courantes
</div>

<Accordion title="401 Non autorisé">
  **Vérifiez votre authentification :**

  * Vérifiez que vous utilisez la bonne méthode d&#39;authentification pour l&#39;endpoint
  * Assurez-vous que les identifiants n&#39;ont pas été régénérés
  * Vérifiez le format de l&#39;en-tête `Authorization`
  * Pour OAuth 1.0a, vérifiez le calcul de la signature

  [Guide d’authentification →](/fr/resources/fundamentals/authentication/overview)
</Accordion>

<Accordion title="403 Interdit">
  **Vérifiez vos droits d’accès :**

  * Vérifiez que votre application a accès à cet endpoint
  * Certains endpoints nécessitent une inscription ou une approbation spécifique
  * Les endpoints en contexte utilisateur nécessitent des scopes OAuth appropriés
  * La ressource peut être privée ou protégée
</Accordion>

<Accordion title="429 Trop de requêtes">
  **Limite de débit atteinte :**

  * Vérifiez l&#39;en-tête `x-rate-limit-reset` pour savoir quand réessayer
  * Mettez en œuvre un backoff exponentiel
  * Envisagez de mettre les réponses en cache
  * Répartissez les requêtes sur la fenêtre temporelle

  [Guide des limites de débit →](/fr/x-api/fundamentals/rate-limits)
</Accordion>

<Accordion title="400 Mauvaise requête">
  **Corrigez votre requête :**

  * Validez la syntaxe JSON
  * Vérifiez qu’aucun paramètre obligatoire ne manque
  * Vérifiez les types de paramètres (chaînes de caractères vs nombres)
  * Échappez les caractères spéciaux dans les requêtes
</Accordion>

<Accordion title="Publications attendues manquantes">
  **Vérifiez ces facteurs :**

  * Les publications des comptes protégés ne sont visibles qu’avec l’autorisation adéquate
  * Les publications supprimées renvoient 404
  * Certaines publications ne sont pas disponibles dans certaines régions
  * Vérifiez que la syntaxe de la requête de recherche est correcte
</Accordion>

<Accordion title="Déconnexions de flux">
  **Gérez la reconnexion :**

  * Implémentez une reconnexion automatique avec backoff
  * Utilisez les fonctionnalités de récupération pour les données manquées
  * Vérifiez les déconnexions dues à un tampon plein (client ne consommant pas assez vite)
  * Vérifiez qu’au moins une règle de flux existe

  [Guide de streaming →](/fr/x-api/posts/filtered-stream/integrate/handling-disconnections)
</Accordion>

<div id="rate-limit-headers">
  ## En-têtes de limitation de débit
</div>

Chaque réponse contient des informations relatives à la limitation de débit :

```
x-rate-limit-limit: 900
x-rate-limit-remaining: 847
x-rate-limit-reset: 1705420800
```

| Header                   | Description                                                         |
| :----------------------- | :------------------------------------------------------------------ |
| `x-rate-limit-limit`     | Nombre maximal de requêtes dans la fenêtre en cours                 |
| `x-rate-limit-remaining` | Requêtes restantes                                                  |
| `x-rate-limit-reset`     | Horodatage Unix indiquant le moment où la fenêtre est réinitialisée |
