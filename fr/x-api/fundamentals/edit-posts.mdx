Les publications sur X peuvent être modifiées dans les 30 minutes suivant leur publication, jusqu&#39;à 5 fois. X API fournit un accès complet à l&#39;historique des modifications et aux métadonnées.

***

<div id="edit-rules">
  ## Règles de modification
</div>

| Règle | Détails |
|:-----|:--------|
| **Fenêtre de modification** | 30 minutes à compter de la publication d’origine |
| **Limite de modifications** | 5 modifications maximum |
| **Comportement de l’identifiant** | Chaque modification crée un nouvel identifiant de publication |
| **Suppression** | La suppression de n’importe quelle version supprime toute la chaîne |

***

<div id="what-cant-be-edited">
  ## Ce qui ne peut pas être modifié
</div>

Certains types de publications ne sont pas modifiables :

* Publications sponsorisées (publicités)
* Publications avec un sondage
* Réponses à d&#39;autres personnes (en dehors de vos propres fils)
* Reposts (les publications citées *peuvent* être modifiées)
* Publications dans une communauté
* Publications collaboratives
* Publications programmées

***

<div id="edit-data-in-responses">
  ## Modifier les données dans les réponses
</div>

<div id="default-fields">
  ### Champs par défaut
</div>

Toutes les réponses de Publication incluent `edit_history_tweet_ids` par défaut :

```json
{
  "data": {
    "id": "1234567891",
    "text": "Updated text (edited)",
    "edit_history_tweet_ids": ["1234567890", "1234567891"]
  }
}
```

* Un seul id = jamais modifié
* Plusieurs id = historique des modifications (de la plus ancienne à la plus récente)

<div id="edit-controls">
  ### Contrôles de modification
</div>

Demandez le champ `edit_controls` pour obtenir le statut de modification :

```bash
curl "https://api.x.com/2/tweets/1234567891?tweet.fields=edit_controls" \
  -H "Authorization: Bearer $TOKEN"
```

```json
{
  "data": {
    "id": "1234567891",
    "text": "Updated text (edited)",
    "edit_history_tweet_ids": ["1234567890", "1234567891"],
    "edit_controls": {
      "is_edit_eligible": true,
      "editable_until": "2024-01-15T12:30:00.000Z",
      "edits_remaining": 3
    }
  }
}
```

| Field              | Description                                   |
| :----------------- | :-------------------------------------------- |
| `is_edit_eligible` | Indique si la publication peut être modifiée  |
| `editable_until`   | Moment où la fenêtre de modification se ferme |
| `edits_remaining`  | Nombre de modifications restantes (0-5)       |

***

<div id="getting-edit-history">
  ## Récupérer l’historique des modifications
</div>

Utilisez l’expansion `edit_history_tweet_ids` pour obtenir des objets de type Publication complets pour toutes les versions :

```bash
curl "https://api.x.com/2/tweets/1234567891?\
tweet.fields=edit_controls&\
expansions=edit_history_tweet_ids" \
  -H "Authorization: Bearer $TOKEN"
```

```json
{
  "data": {
    "id": "1234567891",
    "text": "Updated text (edited)",
    "edit_history_tweet_ids": ["1234567890", "1234567891"],
    "edit_controls": {
      "is_edit_eligible": true,
      "editable_until": "2024-01-15T12:30:00.000Z",
      "edits_remaining": 3
    }
  },
  "includes": {
    "tweets": [{
      "id": "1234567890",
      "text": "Original text (with typo)",
      "edit_history_tweet_ids": ["1234567890", "1234567891"],
      "edit_controls": {
        "is_edit_eligible": true,
        "editable_until": "2024-01-15T12:30:00.000Z",
        "edits_remaining": 3
      }
    }]
  }
}
```

***

<div id="which-version-is-returned">
  ## Quelle version est renvoyée ?
</div>

Par défaut, l’API renvoie la **version la plus récente** d’une publication modifiée.

Pour obtenir une version spécifique, demandez-la directement via son identifiant de publication :

```bash
# Obtenir la version originale
curl "https://api.x.com/2/tweets/1234567890" -H "Authorization: Bearer $TOKEN"

# Get edited version  
curl "https://api.x.com/2/tweets/1234567891" -H "Authorization: Bearer $TOKEN"
```

***

<div id="metrics-for-edited-posts">
  ## Statistiques pour les publications modifiées
</div>

Chaque version d’une publication modifiée possède ses propres statistiques d’engagement. Les statistiques sont attribuées à la version qui était visible au moment où l’engagement a eu lieu.

***

<div id="availability">
  ## Disponibilité
</div>

Les métadonnées d’édition sont disponibles :

* Pour toutes les publications créées depuis le 29 septembre 2022
* Sur tous les endpoints v2 qui renvoient des publications
* Y compris la recherche, les fils, les flux en continu et les opérations de lookup

Les publications créées avant cette date ne contiennent pas de métadonnées d’édition.

***

<div id="use-cases">
  ## Cas d’usage
</div>

<Tabs>
  <Tab title="Suivre les modifications">
    Surveillez les publications pour détecter les modifications et consigner les différences :

    ```python
    def check_for_edits(post):
        history = post.get("edit_history_tweet_ids", [])
        if len(history) > 1:
            print(f"Post {post['id']} has been edited {len(history) - 1} times")
    ```
  </Tab>

  <Tab title="Afficher un indicateur de modification">
    Affichez un badge « modifié » dans votre interface utilisateur :

    ```javascript
    const isEdited = post.edit_history_tweet_ids?.length > 1;
    if (isEdited) {
      showEditedBadge();
    }
    ```
  </Tab>

  <Tab title="Récupérer le contenu d’origine">
    Récupérez la version d’origine d’une publication modifiée :

    ```python
    original_id = post["edit_history_tweet_ids"][0]
    original = api.get_tweet(original_id)
    ```
  </Tab>
</Tabs>
