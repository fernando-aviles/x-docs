Les limites de débit déterminent le nombre de requêtes que vous pouvez effectuer sur chaque endpoint. Si vous dépassez ces limites, vous recevrez une erreur 429 jusqu’à ce que la fenêtre soit réinitialisée.

***

<div id="how-rate-limits-work">
  ## Fonctionnement des limites de débit
</div>

| Concept | Description |
|:--------|:------------|
| **Fenêtre temporelle** | Généralement 15 minutes ou 24 heures |
| **Limites par utilisateur** | S&#39;appliquent avec OAuth 1.0a ou des jetons utilisateur OAuth 2.0 |
| **Limites par application** | S&#39;appliquent avec Bearer Token (application uniquement) |
| **Limites par endpoint** | Chaque endpoint a ses propres limites |

***

<div id="checking-your-limits">
  ## Vérifier vos limites
</div>

Les en-têtes de réponse indiquent l’état actuel de vos limites de débit :

```
x-rate-limit-limit: 900
x-rate-limit-remaining: 847
x-rate-limit-reset: 1705420800
```

| En-tête                  | Description                                               |
| :----------------------- | :-------------------------------------------------------- |
| `x-rate-limit-limit`     | Nombre maximal de requêtes autorisées                     |
| `x-rate-limit-remaining` | Nombre de requêtes restantes dans la fenêtre              |
| `x-rate-limit-reset`     | Horodatage Unix du moment où la fenêtre est réinitialisée |

<div id="handling-rate-limits">
  ## Gestion des limites de débit
</div>

Lorsque vous atteignez une limite de débit, vous recevrez une réponse 429 :

```json
{
  "errors": [{
    "code": 88,
    "message": "Rate limit exceeded"
  }]
}
```

<div id="recovery-strategy">
  ### Stratégie de reprise
</div>

1. Vérifiez `x-rate-limit-reset` pour savoir quand la fenêtre sera réinitialisée
2. Patientez jusqu&#39;à ce moment avant de réessayer
3. Utilisez un backoff exponentiel si nécessaire

```python
import time

def make_request_with_backoff(url, headers):
    response = requests.get(url, headers=headers)
    
    if response.status_code == 429:
        reset_time = int(response.headers.get('x-rate-limit-reset', 0))
        wait_time = max(reset_time - time.time(), 60)
        time.sleep(wait_time)
        return make_request_with_backoff(url, headers)
    
    return response
```

<div id="rate-limits-vs-billing">
  ## Limites de débit vs. facturation
</div>

Les limites de débit et la facturation sont distinctes :

| Concept | Objectif |
|:--------|:--------|
| **Limites de débit** | Contrôler la fréquence des requêtes pour la stabilité du système |
| **Facturation à l&#39;usage** | Facturer les données récupérées (paiement à l&#39;usage) |

Vous pouvez respecter les limites de débit tout en générant des coûts d&#39;utilisation, ou atteindre les limites de débit sans coût supplémentaire.
