Les limites de débit déterminent le nombre de requêtes que vous pouvez envoyer à chaque endpoint. Le dépassement de ces limites entraîne une erreur 429 jusqu’à ce que la fenêtre soit réinitialisée.

***

<div id="how-rate-limits-work">
  ## Fonctionnement des limites de débit
</div>

| Concept | Description |
|:--------|:------------|
| **Fenêtre de temps** | Généralement 15 minutes ou 24 heures |
| **Limites par utilisateur** | S&#39;appliquent avec OAuth 1.0a ou des jetons utilisateur OAuth 2.0 |
| **Limites par application** | S&#39;appliquent avec un Bearer Token (application uniquement) |
| **Par point de terminaison** | Chaque point de terminaison a ses propres limites |

***

<div id="checking-your-limits">
  ## Vérifier vos limites
</div>

Les en-têtes de réponse indiquent vos limites de débit actuelles :

```
x-rate-limit-limit: 900
x-rate-limit-remaining: 847
x-rate-limit-reset: 1705420800
```

| En-tête                  | Description                                         |
| :----------------------- | :-------------------------------------------------- |
| `x-rate-limit-limit`     | Nombre maximal de requêtes autorisées               |
| `x-rate-limit-remaining` | Nombre de requêtes restantes dans la fenêtre        |
| `x-rate-limit-reset`     | Horodatage Unix auquel la fenêtre est réinitialisée |

<div id="handling-rate-limits">
  ## Gestion des limites de débit
</div>

Lorsque vous atteignez une limite de débit, vous recevrez une réponse 429 :

```json
{
  "errors": [{
    "code": 88,
    "message": "Rate limit exceeded"
  }]
}
```

<div id="recovery-strategy">
  ### Stratégie de reprise
</div>

1. Vérifiez `x-rate-limit-reset` pour connaître l’heure de réinitialisation de la fenêtre
2. Attendez jusqu’à ce moment avant de réessayer
3. Utilisez une temporisation exponentielle si nécessaire

```python
import time

def make_request_with_backoff(url, headers):
    response = requests.get(url, headers=headers)
    
    if response.status_code == 429:
        reset_time = int(response.headers.get('x-rate-limit-reset', 0))
        wait_time = max(reset_time - time.time(), 60)
        time.sleep(wait_time)
        return make_request_with_backoff(url, headers)
    
    return response
```

<div id="rate-limits-vs-billing">
  ## Limites de débit et facturation
</div>

Les limites de débit et la facturation sont distinctes :

| Concept | Objectif |
|:--------|:--------|
| **Limites de débit** | Contrôler la fréquence des requêtes pour la stabilité du système |
| **Facturation à l’usage** | Facturer les données récupérées (paiement à l’usage) |

Vous pouvez respecter les limites de débit tout en générant des coûts d’utilisation, ou atteindre les limites de débit sans coût supplémentaire.
