X API utilise des numéros de version dans les chemins d’URL de ses endpoints pour garantir la stabilité tout en permettant l’évolution. Comprendre notre stratégie de versionnage vous aide à planifier vos intégrations et à rester à jour.

***

<div id="current-versions">
  ## Versions actuelles
</div>

| Version | Statut | Description |
|:--------|:-------|:------------|
| **v2** | Actuelle | Endpoints modernes, tarification flexible, toutes les nouvelles fonctionnalités |
| **v1.1** | Ancienne | Support limité, mises à jour minimales |
| **Enterprise** | Disponible | Accès à haut volume avec prise en charge dédiée |

<Tip>
  Utilisez **X API v2** pour tous les nouveaux projets. C’est là que toutes les nouvelles fonctionnalités sont déployées.
</Tip>

***

<div id="version-in-urls">
  ## Version dans les URL
</div>

Le numéro de version apparaît dans le chemin de l’URL de l’endpoint :

```
https://api.x.com/2/tweets
                   ^
                   version
```

<div id="breaking-vs-non-breaking-changes">
  ## Modifications rétro-incompatibles vs rétro-compatibles
</div>

<div id="breaking-changes-require-code-updates">
  ### Modifications majeures (nécessitent des mises à jour de code)
</div>

Ces changements ne se produisent que lors de mises à niveau majeures de version :

* Suppression d’un endpoint
* Suppression d’un champ de Réponse
* Suppression d’un paramètre de requête
* Ajout d’un nouveau paramètre Obligatoire
* Modification du type de données d’un champ
* Renommage d’un champ ou d’une ressource
* Modification des codes de Réponse ou des types d’erreur
* Modification des scopes d’autorisation

<div id="non-breaking-changes-additive">
  ### Modifications rétrocompatibles (additives)
</div>

Celles-ci peuvent se produire à tout moment sans changement de version :

* Ajout d’un nouvel endpoint
* Ajout d’un nouveau paramètre facultatif
* Ajout d’un nouveau champ de réponse
* Ajout de nouveaux scopes OAuth
* Modification du texte des messages d’erreur
* Définition de champs à null pour des raisons de confidentialité/de sécurité

<div id="deprecation-policy">
  ## Politique de dépréciation
</div>

Lorsque nous publions une nouvelle version majeure :

1. **Dépréciation** : la version précédente est marquée comme dépréciée
2. **Période de prise en charge** : la version dépréciée continue de fonctionner pendant une période déterminée
3. **Retrait** : la version dépréciée est supprimée

<div id="definitions">
  ### Définitions
</div>

| Statut | Description |
|:-------|:--------|
| **Actif** | Entièrement pris en charge, avec de nouvelles fonctionnalités et des correctifs |
| **Obsolète** | Aucune nouvelle fonctionnalité ; correction des bogues critiques uniquement ; utilisation déconseillée |
| **Retiré** | N’est plus accessible |
