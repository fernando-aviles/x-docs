X API utilise des numéros de version dans les chemins d’URL des endpoints afin de garantir la stabilité tout en permettant l’évolution. Comprendre notre stratégie de versionnage vous aide à planifier vos intégrations et à rester à jour.

***

<div id="current-versions">
  ## Versions actuelles
</div>

| Version | Statut | Description |
|:--------|:-------|:------------|
| **v2** | Actuelle | Endpoints modernes, tarification flexible, toutes les nouvelles fonctionnalités |
| **v1.1** | Ancienne | Prise en charge limitée, mises à jour minimales |
| **Enterprise** | Disponible | Accès à haut volume avec support dédié |

<Tip>
  Utilisez **X API v2** pour tous les nouveaux projets. C&#39;est là que toutes les nouvelles fonctionnalités sont déployées.
</Tip>

***

<div id="version-in-urls">
  ## Version dans les URL
</div>

Le numéro de version apparaît dans le chemin de l’endpoint :

```
https://api.x.com/2/tweets
                   ^
                   version
```

<div id="breaking-vs-non-breaking-changes">
  ## Modifications avec ou sans rupture de compatibilité
</div>

<div id="breaking-changes-require-code-updates">
  ### Modifications avec rupture de compatibilité (nécessitent des mises à jour du code)
</div>

Ces changements ne se produisent que lors du passage à une nouvelle version majeure :

* Suppression d&#39;un endpoint
* Suppression d&#39;un champ de réponse
* Suppression d&#39;un paramètre de requête
* Ajout d&#39;un nouveau paramètre obligatoire
* Modification du type de données d&#39;un champ
* Changement de nom d&#39;un champ ou d&#39;une ressource
* Modification des codes de réponse ou des types d&#39;erreur
* Modification des scopes d&#39;autorisation

<div id="non-breaking-changes-additive">
  ### Modifications rétrocompatibles (additives)
</div>

Celles-ci peuvent intervenir à tout moment sans changement de version :

* Ajout d’un nouvel endpoint
* Ajout d’un nouveau paramètre optionnel
* Ajout d’un nouveau champ de réponse
* Ajout de nouveaux scopes OAuth
* Modification du texte des messages d’erreur
* Mise de champs à `null` pour des raisons de confidentialité/sécurité

<div id="deprecation-policy">
  ## Politique d’obsolescence
</div>

Lorsque nous publions une nouvelle version majeure :

1. **Mise en obsolescence** : la version précédente est marquée comme obsolète
2. **Période de support** : la version obsolète continue de fonctionner pendant une période définie
3. **Retrait** : la version obsolète est supprimée

<div id="definitions">
  ### Définitions
</div>

| Statut | Description |
|:-------|:--------|
| **Actif** | Entièrement pris en charge, avec de nouvelles fonctionnalités et des correctifs |
| **Obsolète** | Aucune nouvelle fonctionnalité ; corrections uniquement pour les bogues critiques ; utilisation déconseillée |
| **Retiré** | N’est plus accessible |
