<div id="introduction">
  ## Introduction
</div>

Les [endpoints Search Posts](/fr/x-api/posts/search/introduction)
dans l’environnement v2 vous permettent de recevoir des Publications liées à des sujets d’intérêt,
en fonction d’une requête de recherche que vous définissez. Nous proposons deux endpoints
différents avec v2 Search Posts : la recherche récente, qui est disponible pour tous les
développeurs disposant d’un compte approuvé et peut rechercher des Publications jusqu’à sept jours
en arrière, et la recherche dans l’archive complète, qui est uniquement disponible
pour les chercheurs approuvés pour la
[filière de produit Academic Research](https://developer.x.com/en/products/x-api/early-access/guide#na_2),
et peut rechercher dans l’intégralité de l’archive de Publications remontant à mars 2006.

Vous pouvez consulter l’ensemble de notre offre de recherche sur notre
[page de présentation de la recherche](/fr/x-api/posts/search/introduction).

Ces endpoints Search Posts répondent à l’un des cas d’usage les plus courants des
chercheurs universitaires, qui peuvent les utiliser pour des études longitudinales
ou pour analyser un sujet ou un événement passé.

Ce tutoriel fournit un guide pas à pas pour les chercheurs qui souhaitent utiliser
l’endpoint de recherche dans l’archive complète afin de rechercher dans l’historique complet
des données publiques de X. Il montrera également différentes manières de constituer un jeu
de données, par exemple en récupérant des Publications géolocalisées, et comment parcourir
les Publications disponibles pour une requête donnée.

<div id="connecting-to-the-full-archive-search-endpoint">
  ### Connexion à l’endpoint de recherche de l’archive complète
</div>

La commande cURL ci-dessous montre comment obtenir des Publications historiques du compte @XDevelopers.
Remplacez $BEARER&#95;TOKEN par votre propre Bearer Token, collez la requête complète dans votre terminal, puis appuyez sur « Entrée ».

```bash
curl --request GET 'https://api.x.com/2/tweets/search/all?query=from:xdevelopers' --header 'Authorization: Bearer $BEARER_TOKEN'
```

Vous verrez le JSON de la Réponse.

Par défaut, seules les 10 Publications les plus récentes seront renvoyées. Si vous souhaitez plus
de 10 Publications par requête, vous pouvez utiliser le paramètre max&#95;results et le définir à
une valeur maximale de 500 Publications par requête, comme illustré ci-dessous :

```bash
curl --request GET 'https://api.x.com/2/tweets/search/all?query=from:xdevelopers&max_results=500' --header 'Authorization: Bearer $BEARER_TOKEN'
```

###

Création de requêtes

Comme vous pouvez le voir dans les exemples d’appels ci-dessus, en utilisant le paramètre query, vous pouvez
spécifier les données que vous souhaitez rechercher. Par exemple, si vous voulez
récupérer toutes les Publications qui contiennent le mot *covid* ou le mot *coronavirus*, vous pouvez
utiliser l’opérateur OR entre parenthèses, et votre requête peut être
`(covid OR coronavirus)` et ainsi votre appel d’API aura la forme suivante :

```bash
curl --request GET 'https://api.x.com/2/tweets/search/all?query=(covid%20OR%20coronavirus)&max_results=500' --header 'Authorization: Bearer $BEARER_TOKEN'
```

De même, si vous voulez toutes les Publications qui contiennent le terme *covid19* et qui ne sont pas
des reposts, vous pouvez utiliser l’opérateur is:retweet avec l’opérateur logique NOT (représenté
par -), de sorte que votre requête soit covid19 -is:retweet et votre appel d’API sera :

```bash
curl --request GET 'https://api.x.com/2/tweets/search/all?query=covid19%20-is:retweet&max_results=500' --header 'Authorization: Bearer $BEARER_TOKEN'
```

Consultez
[ce guide pour la liste complète des opérateurs](/fr/x-api/posts/search/integrate/build-a-query)
pris en charge par le point de terminaison de recherche sur l’archive complète.

<div id="using-the-start_time-and-end_time-parameters-to-get-historical-posts">
  ### Utiliser les paramètres start_time et end_time pour obtenir des Publications historiques
</div>

Lorsque vous utilisez l&#39;endpoint de recherche sur l&#39;ensemble des archives, par défaut les Publications des 30 derniers jours sont renvoyées. Si vous souhaitez obtenir des Publications datant de plus de 30 jours, vous pouvez utiliser les paramètres start&#95;time et end&#95;time dans votre appel d&#39;API. Ces paramètres doivent être dans un format de date et d&#39;heure RFC3339 valide, par exemple
2020-12-21T13:00:00.00Z. Ainsi, si vous voulez obtenir toutes les Publications du compte XDevelopers pour le mois de décembre 2020, votre appel d&#39;API sera :

```bash
curl --request GET 'https://api.x.com/2/tweets/search/all?query=from:XDevelopers&start_time=2020-12-01T00:00:00.00Z&end_time=2021-01-01T00:00:00.00Z' --header 'Authorization: Bearer $BEARER_TOKEN'
```

###

Récupérer des Publications historiques géolocalisées

Les Publications géolocalisées sont des Publications qui contiennent des informations géographiques associées, telles qu’une ville, une région, un pays, etc.

<div id="using-hasgeo-operator">
  #### Utilisation de l’opérateur has:geo
</div>

Si vous souhaitez obtenir des Publications contenant des données de géolocalisation, vous pouvez utiliser l’opérateur has:geo.
Par exemple, la requête cURL suivante récupérera uniquement les Publications du compte
@XDevelopers avec des données de géolocalisation :

```
curl --request GET
'https://api.x.com/2/tweets/search/all?query=from:xdevelopers%20has:geo' --header
'Authorization: Bearer $BEARER_TOKEN'
```

<div id="using-place_country-operator">
  #### Utilisation de l’opérateur place_country
</div>

De la même manière, vous pouvez limiter les Publications comportant des données de géolocalisation à un pays spécifique en utilisant l’opérateur place&#95;country. La commande cURL ci-dessous récupérera toutes les Publications du compte @XDevelopers provenant des États-Unis :

```
curl --request GET
'https://api.x.com/2/tweets/search/all?query=from:xdevelopers%20place_country:US'
--hbasheader 'Authorization: Bearer XXXXX'
```

Le pays est indiqué ci-dessus à l&#39;aide du code pays ISO alpha-2. Les codes ISO valides sont disponibles [ici](http://en.wikipedia.org/wiki/ISO_3166-1_alpha-2).

<div id="getting-more-than-500-historical-posts-using-the-next_token">
  ### Obtenir plus de 500 Publications historiques en utilisant le next_token
</div>

Comme mentionné ci-dessus, par défaut vous ne pouvez obtenir qu’au maximum 500 Publications par requête pour
une requête vers l’endpoint de recherche dans l’ensemble des archives. S’il y a plus de 500 Publications
disponibles pour votre requête, votre réponse JSON inclura un next&#95;token que vous
pourrez ajouter à votre appel d’API afin d’obtenir les Publications suivantes pour cette
requête. Ce next&#95;token est disponible dans l’objet meta de votre réponse JSON,
qui ressemble à ceci :

```
{ "newest_id": "12345678...", "oldest_id": "12345678...", "result_count": 500,
"nebashxt_token": "XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX" }
```

Ainsi, pour obtenir les prochaines Publications disponibles, utilisez la valeur `next_token` de cet objet `meta` et utilisez cette valeur comme valeur du paramètre `next_token` dans votre appel d’API au endpoint de recherche dans l’archive complète, comme illustré ci‑dessous (vous utiliserez votre propre Bearer Token et la valeur que vous obtiendrez pour `next_token` lors de votre appel d’API précédent).

```
curl --request GET
'https://api.x.com/2/tweets/search/all?max_results=500&query=covid&next_token=XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX'
--header 'Authorization: Bearer $BEARER_TOKEN'
```

De cette façon, vous pouvez continuer à vérifier si un next&#95;token est disponible et, si vous n’avez pas encore atteint le nombre souhaité de Publications à collecter, vous pouvez continuer à appeler l’endpoint full-archive avec le nouveau next&#95;token pour chaque requête.
