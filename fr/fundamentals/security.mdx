Créer des applications sécurisées protège à la fois vos utilisateurs et la plateforme X. Ce guide couvre les pratiques de sécurité essentielles pour les développeurs utilisant la X API.

***

<div id="core-requirements">
  ## Exigences principales
</div>

<CardGroup cols={2}>
  <Card title="TLS obligatoire" icon="lock">
    Toutes les requêtes d’API doivent utiliser HTTPS. Les requêtes HTTP non chiffrées sont refusées.
  </Card>

  <Card title="Sécurité des identifiants" icon="key">
    Ne divulguez jamais de clés d’API ni de jetons dans le code côté client, les journaux ou les dépôts.
  </Card>
</CardGroup>

***

<div id="protecting-credentials">
  ## Protection des identifiants
</div>

Vos clés et jetons d’API sont les clés de votre application. Gardez-les en lieu sûr :

<Steps>
  <Step title="Utilisez des variables d’environnement">
    Stockez les identifiants dans des variables d’environnement, pas dans le code.

    ```bash
    export X_API_KEY="your-api-key"
    export X_API_SECRET="your-api-secret"
    ```
  </Step>

  <Step title="Ne validez jamais de secrets">
    Ajoutez les fichiers d’identifiants à `.gitignore`. Utilisez des outils comme `git-secrets` pour éviter les commits accidentels.
  </Step>

  <Step title="Renouvelez-les régulièrement">
    Régénérez les clés périodiquement et immédiatement si vous suspectez une compromission.
  </Step>

  <Step title="Utilisez des permissions minimales">
    Demandez uniquement les scopes OAuth dont votre application a réellement besoin.
  </Step>
</Steps>

<div id="if-credentials-are-compromised">
  ### En cas de compromission des identifiants
</div>

1. **Régénérez-les immédiatement** dans la [Console de Développement](https://console.x.com)
2. **Révoquez les anciens jetons d’accès** — la régénération invalide automatiquement les anciens identifiants
3. **Contrôlez l’utilisation** — recherchez toute activité API non autorisée
4. **Mettez à jour votre application** — déployez les nouveaux identifiants dans tous les environnements

<div id="application-security">
  ## Sécurité applicative
</div>

<div id="input-validation">
  ### Validation des entrées
</div>

Ne faites jamais confiance aux données fournies par l’utilisateur. Validez et assainissez toutes les données avant de les utiliser :

```python
# Mauvais - vulnérable à l'injection
query = f"from:{user_input}"

# Good - validate input first
import re
if re.match(r'^[a-zA-Z0-9_]{1,15}$', user_input):
    query = f"from:{user_input}"
```

<div id="output-encoding">
  ### Encodage de sortie
</div>

Appliquez un échappement aux données renvoyées par la X API avant de les afficher en HTML afin de prévenir les attaques XSS :

```javascript
// Mauvais - vulnérable au XSS
element.innerHTML = tweet.text;

// Bon - échapper le HTML
element.textContent = tweet.text;
```

<div id="common-vulnerabilities-to-prevent">
  ### Vulnérabilités courantes à prévenir
</div>

| Vulnérabilité | Prévention |
|:--------------|:-----------|
| **XSS** | Échappez tout le contenu généré par les utilisateurs avant l’affichage |
| **CSRF** | Utilisez des jetons anti-CSRF dans les formulaires ; vérifiez le paramètre `state` OAuth |
| **Injection SQL** | Utilisez des requêtes paramétrées, ne concaténez jamais les données fournies par les utilisateurs |
| **Redirections ouvertes** | Validez les URL de rappel par rapport à une liste d’autorisation définie |

<div id="oauth-security">
  ## Sécurité OAuth
</div>

<div id="state-parameter">
  ### Paramètre state
</div>

Utilisez toujours le paramètre `state` dans les flux OAuth pour prévenir les attaques CSRF :

```python
import secrets

# Generate state before authorization
state = secrets.token_urlsafe(32)
session['oauth_state'] = state

# Verify state after callback
if request.args.get('state') != session.get('oauth_state'):
    abort(403)  # Non-concordance de l'état - CSRF possible
```

<div id="token-storage">
  ### Stockage des jetons
</div>

| Type de jeton | Recommandations de stockage |
|:--------------|:---------------------------|
| **Access tokens** | Base de données chiffrée ou coffre-fort sécurisé |
| **Refresh tokens** | Base de données chiffrée avec contrôles d’accès renforcés |
| **Bearer tokens** | Variables d’environnement ou configuration sécurisée |

<div id="compliance-checklist">
  ## Liste de contrôle de conformité
</div>

<Accordion title="Exigences de sécurité pour les développeurs utilisant X API">
  * [ ] Toutes les requêtes à l’API utilisent TLS/HTTPS
  * [ ] Identifiants stockés de manière sécurisée (pas dans le code ni les journaux)
  * [ ] Jetons utilisateur chiffrés au repos
  * [ ] Validation des entrées sur toutes les données fournies par l’utilisateur
  * [ ] Encodage des sorties pour empêcher les attaques XSS
  * [ ] Protection CSRF sur les flux OAuth
  * [ ] Journalisation de sécurité activée (sans données sensibles)
  * [ ] Plan de réponse aux incidents documenté
  * [ ] Dépendances mises à jour régulièrement
  * [ ] Portées OAuth minimales nécessaires demandées
</Accordion>
