<div id="bearer-token-also-known-as-app-only">
  ### Bearer Token (également appelé app-only)
</div>

OAuth 2.0 Bearer Token authentifie les requêtes pour le compte de votre [App développeur](/fr/resources/fundamentals/developer-apps). Comme cette méthode est propre à l’App, elle n’implique aucun utilisateur. Elle est généralement utilisée par les développeurs qui ont besoin d’un accès en lecture seule aux informations publiques. 

Cette méthode d’authentification requiert que vous envoyiez un Bearer Token avec votre requête, que vous pouvez générer dans la section Keys and tokens de vos Apps développeur. Voici un exemple de requête utilisant un Bearer Token fictif :

```json
  curl "https://api.x.com/2/tweets?ids=1261326399320715264,1278347468690915330" \
  -H "Authorization: Bearer AAAAAAAAAAAAAAAAAAAAAFnz2wAAAAAAxTmQbp%2BIHDtAhTBbyNJon%2BA72K4%3DeIaigY0QBrv6Rp8KZQQLOTpo9ubw5Jt?WRE8avbi"
```

Les appels à l’API utilisant uniquement l’authentification applicative sont [soumis à des limites de débit](/fr/resources/fundamentals/rate-limits) par endpoint, au niveau de l’App.

Pour utiliser cette méthode, vous aurez besoin d’un Bearer Token, que vous pouvez générer en transmettant votre clé API et votre secret via l’endpoint [POST oauth2/token](/fr/resources/fundamentals/authentication/api-reference#post-oauth2-token), ou en le générant dans la section « keys and token » des paramètres de votre App dans la [Console de Développement](/fr/resources/fundamentals/developer-portal).

Si vous souhaitez révoquer un Bearer Token, vous pouvez utiliser l’endpoint [POST oauth2/invalidate&#95;token](/fr/resources/fundamentals/authentication/api-reference#post-oauth2-invalidate-token), ou cliquer sur « revoke » à côté du Bearer Token dans la section « keys and tokens » des paramètres de votre App.

<div id="oauth-20-authorization-code-flow-with-pkce">
  ### Flux d’autorisation par code OAuth 2.0 avec PKCE
</div>

Le flux d’autorisation par code OAuth 2.0 avec PKCE vous permet d’authentifier des actions au nom d’un autre utilisateur tout en ayant un contrôle plus fin sur les scopes d’une application, et il améliore les flux d’autorisation sur plusieurs appareils. En d’autres termes, les développeurs qui créent des applications pour les personnes sur X disposent d’un meilleur contrôle sur les informations que leur application demande à leurs utilisateurs, de sorte que vous ne devez demander à vos utilisateurs finaux que les données et informations dont vous avez réellement besoin.

Ce protocole d’autorisation moderne vous permet de proposer à vos utilisateurs finaux un flux de consentement plus simple pour l’autorisation de votre application, qui n’affiche que les scopes précis que vous avez demandés. Non seulement cela réduit le volume de données que vous traitez, mais cela peut également renforcer la confiance de vos utilisateurs finaux.
