Les connexions TLS sont obligatoires pour pouvoir accéder aux points de terminaison X API. La communication via TLS préserve la confidentialité et la sécurité des utilisateurs en protégeant les informations échangées entre l’utilisateur et X API lorsqu’elles transitent sur l’Internet public. Les connexions à X API requièrent la version 1.2 du protocole TLS.


<div id="verification">
  ## Vérification
</div>

<div id="use-an-up-to-date-root-store">
  ### Utiliser un magasin de certificats racine à jour
</div>

Il est important que votre application ou bibliothèque utilise un magasin de certificats racine fiable et à jour lors de la vérification du certificat X. Lorsque c’est possible, utiliser le magasin de certificats racine fourni par votre système d’exploitation peut s’avérer l’approche la plus simple. À défaut, le [magasin de racines Mozilla (NSS)](https://www.mozilla.org/en-US/about/governance/policies/security-group/certs/) est maintenu de façon publique et transparente. cURL fournit également [une version de ce magasin au format PEM](https://curl.haxx.se/docs/caextract.html).

X émet actuellement la majorité de nos certificats à partir de la [DigiCert High Assurance EV Root CA](https://www.digicert.com/digicert-root-certificates.htm), mais ce n’est pas le cas pour 100 % des certificats liés à X et cela peut changer à l’avenir. Par conséquent, faire confiance uniquement aux racines DigiCert actuellement utilisées peut entraîner des problèmes avec votre application à l’avenir.

<div id="check-crls-and-the-ocsp-status">
  ### Vérifier les CRL et le statut OCSP[](#check-crls-and-the-ocsp-status "Permalink to this headline")
</div>

De nombreuses applications ne vérifient pas la liste de révocation de certificats (CRL) pour les certificats retournés ou se reposent sur le système d’exploitation pour le faire. Assurez-vous que votre application ou votre bibliothèque TLS est configurée de manière à exiger la vérification des CRL et d’OCSP (Online Certificate Status Protocol) avant d’accepter le certificat émis par X.

<div id="cdns">
  ### CDNs[](#cdns "Permalien vers ce titre")
</div>

Lors de l’affichage de Tweets contenant des médias, utilisez l’attribut `media_url_https` pour les URL HTTPS à utiliser pour l’affichage des images. À l’avenir, toutes les URL servies par les endpoints de l’API fourniront des chemins HTTPS.

<div id="provide-an-indication-of-security-status">
  ## Indiquer l’état de sécurité
</div>

Si possible, vous devriez afficher une indication de l’état de sécurité actuel entre votre application et X. Certains navigateurs l’indiquent à l’aide d’une icône en forme de cadenas, tandis que d’autres signalent l’état actuel de la connexion au moyen d’un message descriptif.
