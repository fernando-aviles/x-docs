<div id="oauth-echo">
  ### OAuth Echo
</div>

OAuth Echo est un moyen de déléguer en toute sécurité une autorisation OAuth à un tiers lors de l’interaction avec une API.

Quatre parties interviennent dans cette interaction :

* **l’Utilisateur** qui utilise X via une application X particulière et autorisée
* **le Consumer**, c’est‑à‑dire l’application X qui tente d’interagir avec le fournisseur de médias tiers (par exemple le site de partage de photos)
* **le Delegator**, c’est‑à‑dire le fournisseur de médias tiers
* **le Service Provider**, également appelé X lui‑même
     

Concrètement, préparez une requête que le Delegator enverra à l’X API au nom d’une application et d’un utilisateur. Ajoutez ce qui serait normalement une requête OAuth signée dans un en‑tête HTTP et demandez au Delegator d’envoyer cette requête à X après avoir terminé l’opération intermédiaire.

Voici un exemple : l’Utilisateur souhaite téléverser une photo. Le Consumer va appeler la méthode d’upload sur le Delegator avec une requête POST. Le POST doit contenir l’image, mais il doit également contenir deux éléments supplémentaires sous forme d’en‑têtes HTTP :

* `x-auth-service-provider` — en pratique, il s’agit du domaine vers lequel la délégation d’identité doit être envoyée — dans le cas de X, définissez‑le sur https://api.x.com/1.1/account/verify_credentials.json. Les intégrations X basées sur iOS5 ajouteront un paramètre supplémentaire application_id à cette URL, qui sera également utilisé pour calculer la oauth_signature utilisée dans x-verify-credentials-authorization.
* `x-verify-credentials-authorization` — le Consumer doit créer tous les paramètres OAuth nécessaires pour pouvoir appeler https://api.x.com/1.1/account/verify_credentials.json en utilisant OAuth dans l’en‑tête HTTP (par exemple, cela devrait ressembler à OAuth oauth\_consumer\_key=”...”, oauth\_token=”...”, oauth\_signature\_method=”...”, oauth\_signature=”...”, oauth\_timestamp=”...”, oauth\_nonce=”...”, oauth_version=”...” ).
     

Gardez à l’esprit que l’ensemble de la transaction doit se dérouler dans un laps de temps pendant lequel le `oauth_timestamp` est toujours valide.

Autrement, au lieu d’envoyer ces deux paramètres dans l’en‑tête, ils peuvent être envoyés dans le POST sous les noms x\_auth\_service_provider et x\_verify\_credentials_authorization — dans ce cas, n’oubliez pas d’échapper les paramètres et de les inclure dans la chaîne de base de la signature OAuth, comme pour l’encodage des paramètres dans n’importe quelle requête. Il est préférable d’utiliser des en‑têtes HTTP afin de garder les opérations aussi distinctes que possible.

L’objectif du Delegator, à ce stade, est de vérifier que l’Utilisateur est bien celui qu’il prétend être avant d’enregistrer le média. Une fois que le Delegator a reçu toutes les données ci‑dessus via sa méthode d’upload, il doit stocker temporairement l’image, puis construire un appel au point de terminaison spécifié dans l’en‑tête x-auth-service-provider — dans ce cas, https://api.x.com/1.1/account/verify_credentials.json, en utilisant le même en‑tête d’authentification OAuth fourni par le Consumer dans l’en‑tête x-verify-credentials-authorization.
 

<div id="oauth-echo-best-practices">
  #### Bonnes pratiques OAuth Echo
</div>

Utilisez l’URL fournie par `x-auth-service-provider` pour effectuer la requête, et _non_ une valeur codée en dur. Apple iOS, par exemple, ajoute un paramètre supplémentaire application_id à toutes les requêtes OAuth, et son existence doit être préservée à chaque étape d’OAuth Echo.

Pour la partie autorisation OAuth, prenez la valeur de l’en-tête x-verify-credentials-authorization, et placez-la dans son propre en-tête Authorization pour son appel au fournisseur de services. Par précaution, confirmez que la valeur dans `x-auth-service-provider` est bien celle attendue.

* Si le fournisseur de services renvoie un HTTP 200, alors c’est correct. Le Delegator doit stocker définitivement l’image, générer une URL et la renvoyer.
* Si le fournisseur de services ne renvoie pas un HTTP 200, supprimez l’image, puis renvoyez une erreur au Consumer.
