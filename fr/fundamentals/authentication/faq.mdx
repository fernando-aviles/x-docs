<div id="general">
  ## Généralités
</div>

<AccordionGroup>
  <Accordion title="Qu’est-ce qu’OAuth ?">
    OAuth est un protocole d’authentification qui permet aux utilisateurs d’autoriser une application à agir en leur nom sans partager leur mot de passe. Vous trouverez plus d’informations sur [oauth.net](http://oauth.net/).
  </Accordion>

  <Accordion title="Comment générer des jetons d’accès ?">
    Vous devez avoir une [application X](/fr/resources/fundamentals/developer-apps) pour générer des jetons d’accès. Pour en savoir plus sur les jetons d’accès, consultez [cette page](/fr/resources/fundamentals/authentication#oauth-1-0a-2). 
  </Accordion>

  <Accordion title="Comment créer une application X ?">
    Vous devez avoir un [compte développeur](/fr/resources/fundamentals/developer-portal) pour créer une [application X](/fr/resources/fundamentals/developer-apps). Vous pouvez vous inscrire [ici](https://developer.x.com/en/portal/petition/essential/basic-info).
  </Accordion>

  <Accordion title="Si je dispose déjà d’une application X, comment puis-je afficher et modifier cette application ?">
    Vous pouvez afficher et modifier votre application depuis le [tableau de bord des applications X](https://developer.x.com/content/developer-twitter/en/apps) si vous êtes connecté à votre compte X sur developer.x.com.
  </Accordion>
</AccordionGroup>

<div id="technical">
  ## Technique
</div>

<AccordionGroup>
  <Accordion title="Pendant combien de temps un jeton d’accès reste-t-il valide ?">
    Les jetons d’accès n’expirent pas explicitement. Un jeton d’accès sera invalidé si un utilisateur révoque explicitement une application dans les paramètres de son compte X, ou si X suspend une application. Si une application est suspendue, un message s’affichera dans le tableau de bord de l’[application X](/fr/resources/fundamentals/developer-apps) indiquant qu’elle a été suspendue.
  </Accordion>

  <Accordion title="Que se passe-t-il si un jeton d’accès devient invalide ?">
    Considérez que le jeton d’accès d’un utilisateur *peut* devenir invalide à tout moment. Si cela se produit, invitez l’utilisateur à autoriser à nouveau l’application. Il est important de gérer cette situation de manière fluide pour offrir une bonne expérience utilisateur.
  </Accordion>

  <Accordion title="La page d’inscription de l’application demande un accès lecture/écriture. Qu’est-ce qui constitue une écriture ?">
    De nombreux utilisateurs font confiance à une application pour lire leurs informations, mais pas nécessairement pour modifier les informations de leur profil utilisateur ou publier de nouvelles publications. La mise à jour d’informations via X API – qu’il s’agisse du nom, de la localisation ou de l’ajout d’une nouvelle publication – nécessite une requête HTTP POST. Toute méthode d’API qui nécessite une requête HTTP POST est considérée comme une méthode d’écriture et requiert un accès en lecture et écriture.
  </Accordion>
</AccordionGroup>
