<div id="post-oauthrequest_token">
  ### POST oauth/request_token
</div>

Permet à une application consommatrice d’obtenir un OAuth Request Token pour demander l’autorisation de l’utilisateur. Cette méthode satisfait à la [section 6.1](https://oauth.net/core/1.0/#auth_step1) du [flux d’authentification OAuth 1.0](http://oauth.net/core/1.0/#anchor9).

**Nous exigeons que vous utilisiez HTTPS pour toutes les étapes d’autorisation OAuth.**

**Remarque d’utilisation :** seules les valeurs ASCII sont acceptées pour le `oauth_nonce`.

**URL de ressource[](#resource-url "Permalien vers ce titre")**

`https://api.x.com/oauth/request_token`

**Informations sur la ressource[](#resource-information "Permalien vers ce titre")**

|     |     |
| :--- | :--- |
| Formats de réponse | JSON |
| Nécessite une authentification ? | Non  |
| Soumise à une limitation de débit ? | Oui |

**Paramètres[](#parameters "Permalien vers ce titre")**

| Nom | Obligatoire | Description | Exemple |
| :--- | :--- | :--- | :--- |
| oauth&#95;callback | Obligatoire | Pour être conforme à OAuth 1.0a, ce paramètre est **obligatoire**. La valeur que vous indiquez ici sera utilisée comme URL vers laquelle un utilisateur est redirigé s’il approuve l’accès de votre application à son compte. Définissez cette valeur sur `oob` pour le mode code PIN hors bande. C’est également ainsi que vous indiquez des callbacks personnalisés à utiliser dans des applications de bureau/mobile. Envoyez toujours un `oauth_callback` à cette étape, qu’un callback soit pré‑enregistré ou non.<br /><br />Nous exigeons que toute URL de callback utilisée avec ce point de terminaison doive être configurée dans les paramètres de l’App sur developer.x.com* | `http://themattharris.local/auth.php` `twitterclient://callback` |
| x&#95;auth&#95;access&#95;type | Facultatif | Remplace le niveau d’accès qu’une application demande au compte d’un utilisateur. Les valeurs prises en charge sont `read` ou `write`. Ce paramètre permet à un développeur d’enregistrer une application lecture/écriture tout en demandant un accès en lecture seule lorsque c’est approprié. |     |

Pour en savoir plus sur l’approbation de vos URL de callback, consultez [cette page](/fr/resources/fundamentals/developer-apps#callback-urls).

**Veuillez noter :** vous pouvez afficher et modifier vos [applications X](/fr/resources/fundamentals/developer-apps) existantes via le [tableau de bord des applications X](https://developer.x.com/en/apps) si vous êtes connecté à votre compte X sur developer.x.com.

**Exemple de requête[](#example-request "Permalien vers ce titre")**

URL de la requête : `POST https://api.x.com/oauth/request_token`

Corps de la requête POST : *N/A*

En-tête Authorization : `OAuth oauth_nonce="K7ny27JTpKVsTgdyLdDfmQQWVLERj2zAK5BslRsqyw", oauth_callback="http%3A%2F%2Fmyapp.com%3A3005%2Ftwitter%2Fprocess_callback", oauth_signature_method="HMAC-SHA1", oauth_timestamp="1300228849", oauth_consumer_key="OqEqJeafRSF11jBMStrZz", oauth_signature="Pc%2BMLdv028fxCErFyi8KXFM%2BddU%3D", oauth_version="1.0"`

Réponse : `oauth_token=Z6eEdO8MOmk394WozF5oKyuAv855l4Mlqo7hhlSLik&oauth_token_secret=Kd75W4OQfb2oJTV0vzGzeXftVAwgMnEK9MumzYcM&oauth_callback_confirmed=true`

<div id="get-oauthauthorize">
  ### GET oauth/authorize
</div>

Permet à une application cliente d’utiliser un OAuth Request Token pour demander l’autorisation d’un utilisateur. Cette méthode couvre la [Section 6.2](http://oauth.net/core/1.0/#auth_step2) du [flux d’authentification OAuth 1.0](http://oauth.net/core/1.0/#anchor9). Les applications de bureau doivent utiliser cette méthode (et ne peuvent pas utiliser [GET oauth / authenticate](/fr/resources/fundamentals/authentication/api-reference#get-oauth-authenticate)).

**Remarque d’utilisation :** Un `oauth_callback` n’est jamais envoyé à cette méthode ; fournissez-le plutôt à [POST oauth / request&#95;token](/fr/resources/fundamentals/authentication/api-reference#post-oauth-request-token).

**Resource URL[](#resource-url "Permalink to this headline")**

`https://api.x.com/oauth/authorize`

**Resource Information[](#resource-information "Permalink to this headline")**

|     |     |
| :--- | :--- |
| Formats de réponse | JSON |
| Authentification requise ? | Oui |
| Soumis à une limitation de débit ? | Oui |

**Parameters[](#parameters "Permalink to this headline")**

|     |     |     |     |     |
| :--- | :--- | :--- | :--- | :--- |
| Name | Required | Description | Default Value | Example |
| force&#95;login | facultatif | Oblige l’utilisateur à saisir ses identifiants pour garantir que le bon compte utilisateur est autorisé. |     |     |
| screen&#95;name | facultatif | Préremplit le champ de saisie du nom d’utilisateur de l’écran de connexion OAuth avec la valeur fournie. |     |     |

**Example request[](#example-request "Permalink to this headline")**

Envoyez l’utilisateur à l’étape `oauth/authorize` dans un navigateur web, en incluant un paramètre `oauth_token` :\
`https://api.x.com/oauth/authorize?oauth_token=Z6eEdO8MOmk394WozF5oKyuAv855l4Mlqo7hhlSLik`

<div id="get-oauthauthenticate">
  ### GET oauth/authenticate
</div>

Permet à une application cliente d’utiliser un `request_token` OAuth pour demander l’autorisation d’un utilisateur.

Cette méthode remplace la [Section 6.2](http://oauth.net/core/1.0/#auth_step2) du [flux d’authentification OAuth 1.0](http://oauth.net/core/1.0/#anchor9) pour les applications qui utilisent le flux d’authentification avec callback. La méthode utilisera l’utilisateur actuellement connecté comme compte à autoriser pour l’accès, sauf si le paramètre `force_login` est défini sur `true`.

Cette méthode diffère de [GET oauth / authorize](/fr/resources/fundamentals/authentication/api-reference#get-oauth-authorize) en ce que, si l’utilisateur a déjà accordé l’autorisation à l’application, la redirection aura lieu sans que l’utilisateur ait à approuver à nouveau l’application. Pour obtenir ce comportement, vous devez activer le paramètre *Use Sign in with X* dans la [fiche de votre application](https://developer.x.com/apps).

**URL de ressource[](#resource-url "Permalien vers ce titre")**

`https://api.x.com/oauth/authenticate`

**Informations sur la ressource[](#resource-information "Permalien vers ce titre")**

|     |     |
| :--- | :--- |
| Formats de réponse | JSON |
| Authentification requise ? | Oui |
| Soumis à la limitation de débit ? | Oui |

**Paramètres[](#parameters "Permalien vers ce titre")**

|     |     |     |     |     |
| :--- | :--- | :--- | :--- | :--- |
| Nom | Obligatoire | Description | Valeur par défaut | Exemple |
| force&#95;login | optionnel | Oblige l’utilisateur à saisir ses identifiants afin de garantir que le compte du bon utilisateur est autorisé. |     | *true* |
| screen&#95;name | optionnel | Préremplit le champ de saisie du nom d’utilisateur sur l’écran de connexion OAuth avec la valeur indiquée. |     |     |

**Exemple de requête[](#example-request "Permalien vers ce titre")**

Envoyez l’utilisateur vers l’étape `oauth/authenticate` dans un navigateur web, en incluant un paramètre oauth&#95;token :
`https://api.x.com/oauth/authenticate?oauth_token=Z6eEdO8MOmk394WozF5oKyuAv855l4Mlqo7hhlSLik`

<div id="post-oauthaccess_token">
  ### POST oauth/access_token
</div>

Permet à une application cliente d’échanger le jeton de requête OAuth (OAuth Request Token) contre un jeton d’accès OAuth (OAuth Access Token). Cette méthode correspond à la [Section 6.3](http://oauth.net/core/1.0/#auth_step3) du [flux d’authentification OAuth 1.0](http://oauth.net/core/1.0/#anchor9).

**Resource URL[](#resource-url "Permalink to this headline")**

`https://api.x.com/oauth/access_token`

**Resource Information[](#resource-information "Permalink to this headline")**

|     |     |
| :--- | :--- |
| Formats de réponse | JSON |
| Authentification requise ? | Oui |
| Soumis à une limite de débit ? | Oui |

**Parameters[](#parameters "Permalink to this headline")**

|     |     |     |     |     |
| :--- | :--- | :--- | :--- | :--- |
| Nom | Obligatoire | Description | Valeur par défaut | Exemple |
| oauth&#95;token | Obligatoire | Le `oauth_token` ici doit être identique au `oauth_token` renvoyé lors de l’étape `request_token`. |     |     |
| oauth&#95;verifier | Obligatoire | Si vous utilisez le flux Web OAuth, définissez ce paramètre sur la valeur de `_oauth_verifier_` renvoyée dans l’URL de rappel (callback URL). Si vous utilisez OAuth hors bande (out-of-band), définissez cette valeur sur le code PIN. Pour respecter OAuth 1.0a, ce paramètre est **obligatoire**. OAuth 1.0a est strictement appliqué et les applications qui n’utilisent pas `_oauth_verifier_` échoueront à terminer le flux OAuth. |     |     |

**Example request[](#example-request "Permalink to this headline")**

`POST https://api.x.com/oauth/access_token?oauth_token=qLBVyoAAAAAAx72QAAATZxQWU6P&oauth_verifier=ghLM8lYmAxDbaqL912RZSRjCCEXKDIzx`

Depuis un flux basé sur un code PIN : `POST https://api.x.com/oauth/access_token?oauth_token=9Npq8AAAAAAAx72QBRABZ4DAfY9&oauth_verifier=4868795`

**Example response[](#example-response "Permalink to this headline")**

`oauth_token=6253282-eWudHldSbIaelX7swmsiHImEL4KinwaGloHANdrY&oauth_token_secret=2EEfA6BG5ly3sR3XjE0IBSnlQu4ZrUzPiYTmrkVU&user_id=6253282&screen_name=xapi`

<div id="post-oauthinvalidate_token">
  ### POST oauth/invalidate_token
</div>

Permet à une application enregistrée de révoquer un access&#95;token OAuth émis en présentant ses identifiants de client. Une fois qu’un access&#95;token a été invalidé, toute nouvelle tentative d’obtention renverra un autre jeton d’accès et l’utilisation du jeton invalidé ne sera plus autorisée.

**URL de la ressource[](#resource-url "Lien permanent vers ce titre")**

`https://api.x.com/1.1/oauth/invalidate_token`

**Informations sur la ressource[](#resource-information "Lien permanent vers ce titre")**

|                                    |                                                                                 |
| :--------------------------------- | :------------------------------------------------------------------------------ |
| Formats de réponse                 | JSON                                                                            |
| Authentification requise ?         | Oui - contexte utilisateur avec les jetons d’accès que vous souhaitez invalider |
| Soumis à une limitation de débit ? | Oui                                                                             |

**Exemple de requête[](#example-request "Lien permanent vers ce titre")**

```bash
        curl --request POST
          --url 'https://api.x.com/1.1/oauth/invalidate_token.json'
          --header 'authorization: OAuth oauth_consumer_key="CLIENT_KEY",
         oauth_nonce="AUTO_GENERATED_NONCE", oauth_signature="AUTO_GENERATED_SIGNATURE",
         oauth_signature_method="HMAC-SHA1", oauth_timestamp="AUTO_GENERATED_TIMESTAMP",
         oauth_token="ACCESS_TOKEN", oauth_version="1.0"'
```

**Exemple de réponse[](#example-response "Lien permanent vers ce titre")**

```bash
        HTTP/1.1 200 OK
        Content-Type: application/json; charset=utf-8
        Content-Length: 127
        ...

        {"access_token":"ACCESS_TOKEN"}
```

**Exemple de réponse d’erreur après l’invalidation du jeton[](#example-error-response-after-token-has-been-invalidated "Permalink to this headline")**

```bash
        HTTP/1.1 401 Authorization Required
        ...

        {"errors": [{
          "code": 89,
          "message": "Invalid or expired token."}
        ]}
```

<div id="post-oauth2token">
  ### POST oauth2/token
</div>

Permet à une application enregistrée d’obtenir un Bearer Token OAuth 2, qui peut être utilisé pour effectuer des requêtes d’API pour le compte de l’application elle-même, sans contexte utilisateur. On parle alors d’[authentification Application-only](/fr/resources/fundamentals/authentication/oauth-2-0/application-only).

Un Bearer Token peut être invalidé à l’aide de oauth2/invalidate&#95;token. Une fois qu’un Bearer Token a été invalidé, toute nouvelle tentative de création produira un Bearer Token différent et l’utilisation du jeton précédent ne sera plus autorisée.

Un seul Bearer Token peut être actif pour une application, et des requêtes répétées vers cette méthode renverront le même jeton déjà existant jusqu’à ce qu’il ait été invalidé.

Les réponses réussies incluent une structure JSON décrivant le Bearer Token accordé.

Les jetons reçus par cette méthode doivent être mis en cache. En cas de tentatives trop fréquentes, les requêtes seront rejetées avec un code HTTP 403 et le code 99.

**Resource URL[](#resource-url "Permalink to this headline")**

`https://api.x.com/oauth2/token`

**Resource Information[](#resource-information "Permalink to this headline")**

|                                 |                                                                                                                              |
| :------------------------------ | :--------------------------------------------------------------------------------------------------------------------------- |
| Formats de réponse              | JSON                                                                                                                         |
| Authentification requise ?      | Oui - authentification Basic avec votre clé d’API comme nom d’utilisateur et le secret de votre clé d’API comme mot de passe |
| Soumis à des limites de débit ? | Oui                                                                                                                          |

**Parameters[](#parameters "Permalink to this headline")**

|                |             |                                                                                                                                                                                                                                                        |                   |                          |
| :------------- | :---------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :---------------- | :----------------------- |
| Nom            | Obligatoire | Description                                                                                                                                                                                                                                            | Valeur par défaut | Exemple                  |
| grant&#95;type | Obligatoire | Spécifie le type de grant demandé par l’application. Pour le moment, seul *client&#95;credentials* est autorisé. Voir [authentification Application-only](/fr/resources/fundamentals/authentication/oauth-2-0/application-only) pour plus d’informations. |                   | *client&#95;credentials* |

**Example request[](#example-request "Permalink to this headline")**

```bash
    POST /oauth2/token HTTP/1.1
    Host: api.x.com
    User-Agent: My X App v1.0.23
    Authorization: Basic eHZ6MWV2R ... o4OERSZHlPZw==
    Content-Type: application/x-www-form-urlencoded;charset=UTF-8
    Content-Length: 29
    Accept-Encoding: gzip

    grant_type=client_credentials
```

**Exemple de réponse :**

```bash
    HTTP/1.1 200 OK
    Status: 200 OK
    Content-Type: application/json; charset=utf-8
    ...
    Content-Encoding: gzip
    Content-Length: 140

    {"token_type":"bearer","access_token":"AAAA%2FAAA%3DAAAAAAAA"}
```

<div id="post-oauth2invalidate_token">
  ### POST oauth2/invalidate_token
</div>

Permet à une application enregistrée de révoquer un Bearer Token OAuth 2.0 émis en présentant ses identifiants client. Une fois qu&#39;un Bearer Token a été invalidé, toute nouvelle tentative de création produira un Bearer Token différent et l&#39;utilisation du jeton invalidé ne sera plus autorisée.

Les réponses réussies renvoient une structure JSON décrivant le Bearer Token révoqué.

**Resource URL[](#resource-url "Permalien vers ce titre")**

`https://api.x.com/oauth2/invalidate_token`

**Resource Information[](#resource-information "Permalien vers ce titre")**

|                          |                                                                                                                                                                                                                             |
| :----------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Response formats         | JSON                                                                                                                                                                                                                        |
| Requires authentication? | Oui - [OAuth 1.0a](/fr/resources/fundamentals/authentication/oauth-1-0a) avec les clés API consommateur de l&#39;application et le jeton d&#39;accès &amp; le secret de jeton d&#39;accès du propriétaire de l&#39;application |
| Rate limited?            | Oui                                                                                                                                                                                                                         |

**Parameters[](#parameters "Permalien vers ce titre")**

| Name             | Obligatoire | Description                                         |
| :--------------- | :---------- | :-------------------------------------------------- |
| access&#95;token | Obligatoire | Valeur du Bearer Token que vous souhaitez invalider |

**Example request[](#example-request "Permalien vers ce titre")**

```
        curl --request POST
          --url 'https://api.x.com/oauth2/invalidate_token?access_token=AAAA%2FAAA%3DAAAAAAAA'
          --header 'authorization: OAuth oauth_consumer_key="CLIENT_KEY",
         oauth_nonce="AUTO_GENERATED_NONCE", oauth_signature="AUTO_GENERATED_SIGNATURE",
         oauth_signature_method="HMAC-SHA1", oauth_timestamp="AUTO_GENERATED_TIMESTAMP",
         oauth_token="ACCESS_TOKEN", oauth_version="1.0"'
```

**Exemple de réponse[](#example-response "Lien permanent vers ce titre")**

```
         Status: 200 OK
         Content-Type: application/json; charset=utf-8
         Content-Length: 135
         ...
       {
        "access_token": "AAAA%2FAAA%3DAAAAAAAA"
        }
```
