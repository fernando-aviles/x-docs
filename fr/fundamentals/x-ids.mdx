Chaque objet de l&#39;API X — publications, utilisateurs, listes, DMs, Spaces — possède un identifiant unique. Comprendre comment fonctionnent ces identifiants vous aidera à créer des intégrations fiables.

***

<div id="id-format">
  ## Format d’ID
</div>

Les ID X sont des **entiers non signés sur 64 bits** générés à l’aide d’un système appelé « Snowflake ». Chaque ID encode :

* **Horodatage** — Moment où l’objet a été créé
* **Numéro de worker** — Serveur qui a généré l’ID
* **Numéro de séquence** — Ordre au sein de cette milliseconde

Cela signifie que les ID sont approximativement ordonnés dans le temps : les ID les plus élevés représentent généralement les objets les plus récents.

<Tip>
  Les ID sont uniques à l’échelle de l’ensemble de X, et pas seulement au sein d’un seul type d’objet.
</Tip>

***

<div id="string-vs-integer-representation">
  ## Représentation en chaîne de caractères vs représentation en entier
</div>

<Warning>
  **Utilisez toujours des id sous forme de chaîne de caractères dans votre code.** Certains langages de programmation (comme JavaScript) ne peuvent pas représenter avec précision des entiers sur 64 bits.
</Warning>

En JavaScript, les entiers sont limités à 53 bits. Cela entraîne une perte de précision avec des id de grande valeur :

```javascript
// Cela entraîne une perte de précision !
const id = 10765432100123456789;
console.log(id.toString()); // "10765432100123458000" — incorrect !

// Utilisez plutôt des chaînes de caractères
const id = "10765432100123456789";
console.log(id); // "10765432100123456789" — correct !
```

<div id="api-versions">
  ### Versions de l&#39;API
</div>

| Version | Format d&#39;ID |
|:--------|:------------|
| **X API v2** | Les ID sont renvoyés au format chaîne de caractères par défaut |
| **X API v1.1** | Retourne à la fois `id` (entier) et `id_str` (chaîne de caractères) — utilisez toujours `id_str` |

<div id="working-with-ids">
  ## Utilisation des identifiants
</div>

<div id="storing-ids">
  ### Stockage des identifiants
</div>

Stockez les identifiants sous forme de chaînes de caractères ou d&#39;entiers 64 bits dans votre base de données :

| Base de données | Type recommandé |
|:---------|:-----------------|
| PostgreSQL | `BIGINT` ou `TEXT` |
| MySQL | `BIGINT UNSIGNED` ou `VARCHAR(20)` |
| MongoDB | Chaîne de caractères |
| SQLite | `TEXT` (les entiers SQLite sont limités à 63 bits) |

<div id="comparing-ids">
  ### Comparer des identifiants
</div>

Lors de la comparaison des id pour l’ordonnancement chronologique :

```python
# Python - safe for 64-bit integers
if int(id1) > int(id2):
    print("id1 is newer")

# JavaScript - comparer en tant que chaînes de caractères (fonctionne lexicographiquement pour les id de même longueur)
# Ou utiliser BigInt
if (BigInt(id1) > BigInt(id2)) {
    console.log("id1 is newer");
}
```
