L’X API utilise la pagination pour les endpoints qui renvoient plusieurs pages de résultats (par exemple les fils, la recherche, etc.). Chaque réponse d’API inclut un objet `meta` avec `result_count`, `previous_token` et `next_token`. Le xdk se charge d’effectuer plusieurs appels d’API en utilisant le `next_token`, de sorte que les développeurs peuvent simplement spécifier la quantité de données souhaitée sans avoir à effectuer plusieurs appels.
Le SDK simplifie cela avec&nbsp;:

- **Itérateurs intégrés**&nbsp;: utilisez des fonctions génératrices pour récupérer de façon transparente plusieurs pages.
- **Gestion explicite des jetons**&nbsp;: pour un contrôle manuel flexible en passant `pagination_token` lorsque nécessaire.
- **Respect du nombre maximal de résultats**&nbsp;: respecte `max_results` par appel (dans les limites de l’API, par exemple 100 pour la recherche).

<div id="automatic-pagination-recommended">
  ## Pagination automatique (recommandée)
</div>

Utilisez la méthode `iterate()` sur les réponses paginées pour récupérer progressivement tous les résultats.
**Exemple : recherche paginée**

```python
from xdk import Client
client = Client(bearer_token="your_bearer_token")
# Recherche avec pagination automatique
all_posts = []
for page in client.posts.search_recent(
    query="python",
    max_results=100,  # Par page
    tweet_fields=["created_at", "author_id"]  # Expansions facultatives
):
    all_posts.extend(page.data)
    print(f"Fetched {len(page.data)} Posts (total: {len(all_posts)})")
print(f"Total tweets: {len(all_posts)}")
```

* L&#39;itérateur gère automatiquement le `next_token`.
* S&#39;arrête lorsqu&#39;aucun `next_token` n&#39;est renvoyé.
* Gère la temporisation en cas de limite de débit afin d&#39;éviter les erreurs 429.


<div id="manual-pagination">
  ## Pagination manuelle
</div>

Si vous avez besoin d’un contrôle précis sur les résultats pour une logique personnalisée (par exemple un traitement page par page), vous pouvez continuer à utiliser le `next_token` et effectuer la pagination manuellement comme indiqué ci-dessous :

```python
# Obtenir la première page - search_recent renvoie un Iterator
first_page = next(client.posts.search_recent(
    query="xdk python sdk",
    max_results=100,
    pagination_token=None  # Première page
))
print(f"Première page : {len(first_page.data) if first_page.data else 0} Publications")
# Extraire next_token de meta
next_token = None
if hasattr(first_page, 'meta') and first_page.meta:
    if hasattr(first_page.meta, 'next_token'):
        next_token = first_page.meta.next_token
    elif isinstance(first_page.meta, dict):
        next_token = first_page.meta.get('next_token')
if next_token:
    second_page = next(client.posts.search_recent(
        query="xdk python sdk",
        max_results=100,
        pagination_token=next_token
    ))
    print(f"Second page: {len(second_page.data) if second_page.data else 0} Posts")
```

**Conseils** :

* Indiquez toujours `max_results` pour optimiser (la valeur par défaut varie selon l&#39;endpoint).
* Surveillez `meta.result_count` pour le débogage.
* Pour des requêtes très volumineuses, envisagez une itération asynchrone afin d&#39;éviter de bloquer l&#39;exécution.
