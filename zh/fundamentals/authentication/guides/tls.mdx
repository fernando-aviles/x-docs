要访问 X API 端点，必须使用 TLS 连接。通过 TLS 进行通信，可以保护在公共互联网中于用户与 X API 之间传输的信息，从而维护用户隐私和安全。与 X API 的连接必须使用 TLS 1.2 版本。


<div id="verification">
  ## 验证
</div>

<div id="use-an-up-to-date-root-store">
  ### 使用最新的根证书存储
</div>

在验证 X 证书时，确保你的应用或库使用可信且最新的根证书存储非常重要。在可能的情况下，使用操作系统提供的根证书存储通常是最简单的做法。或者，[Mozilla（NSS）根证书存储](https://www.mozilla.org/en-US/about/governance/policies/security-group/certs/)也由社区以公开透明的方式进行良好维护。Curl 还提供了[该证书存储的 PEM 格式版本](https://curl.haxx.se/docs/caextract.html)。

X 目前绝大部分证书由 [DigiCert High Assurance EV Root CA](https://www.digicert.com/digicert-root-certificates.htm) 签发，但这并不适用于 100% 与 X 相关的证书，未来情况也可能发生变化，因此如果只信任当前使用的 DigiCert 根证书，将来可能会给你的 App 带来问题。

<div id="check-crls-and-the-ocsp-status">
  ### 检查 CRL 和 OCSP 状态[](#check-crls-and-the-ocsp-status "Permalink to this headline")
</div>

许多应用程序不会为返回的证书检查证书撤销列表（CRL），或者依赖操作系统来执行该操作。请确保你的应用程序或 TLS 库被配置为在接受 X 的证书之前，强制执行 CRL 和 OCSP（Online Certificate Status Protocol，在线证书状态协议）验证。

<div id="cdns">
  ### CDNs[](#cdns "此标题的永久链接")
</div>

当展示包含媒体的推文时，请使用 `media_url_https` 属性提供的 HTTPS URL 来显示图片。未来，通过 API 端点提供的所有 URL 都将支持 HTTPS 路径。

<div id="provide-an-indication-of-security-status">
  ## 提供安全状态提示
</div>

如果可能，你应当展示你的应用与 X 之间当前安全状态的提示。一些浏览器通过显示锁形图标来表示这一点，而其他浏览器则通过描述性消息来指示当前连接状态。
