使用 Log in with X（也称为 Sign in with X）功能，你可以在自己的网站或应用中添加一个按钮，让 X 用户只需一次点击即可享受注册用户账户的各项权益。此功能适用于网站、iOS、移动应用和桌面应用程序。

<div id="features">
  ## 功能
</div>

* 易于使用 - 你的网站新访客只需点击两个按钮即可完成首次登录。
* X 集成 - “使用 X 登录”流程可以授予代表你的用户调用 X API 的权限。
* 基于 OAuth - 众多客户端库和示例代码都兼容“使用 X 登录”API。

<div id="available-for">
  ## 适用范围
</div>

* 浏览器 - 如果用户可以访问浏览器，即可集成 Log in with X。了解浏览器登录流程。
* 移动设备 - 任何可联网的移动设备都可以使用 Log in with X。了解移动端登录流程。

<div id="implementing-log-in-with-x">
  ## 实现 Log in with X
</div>

浏览器和移动端网页对 Log in with X 的实现是基于 OAuth 的。本页面演示在登录流程中获取 access token 所需的请求。

要使用 “Log in with X” 流程，请前往你的 [X app 设置](/zh/resources/fundamentals/developer-apps)，并确保已启用 *&quot;Allow this app to be used to Sign in with X?*” 选项。

本页面假定读者已经了解如何使用 OAuth 1.0a 协议对请求进行签名。如果你想了解如何对请求进行签名，请阅读 [Authorizing a request](/zh/resources/fundamentals/authentication/oauth-1-0a/authorizing-a-request) 页面。

如果你想验证本页中请求签名是否正确，所使用的 consumer secret 为：L8qq9PZyRg6ieKGEKhZolGC0vJWLw8iEJ88DRdyOg。该值仅供测试用途，不能用于真实请求。

通过获取 request token、重定向用户以及将 request token 转换为 access token 来实现 Log in with X 的三个步骤如下所示。

<Tabs>
  <Tab title="第 1 步">
    ### 步骤 1：获取请求令牌

    要启动登录流程，你的 [X 应用](/zh/resources/fundamentals/developer-apps) 必须通过向 [POST oauth/request&#95;token](/zh/resources/fundamentals/authentication/api-reference#post-oauth-request-token) 发送一条已签名消息来获取请求令牌。此请求中唯一的特有参数是 oauth&#95;callback，它必须是你希望用户在完成步骤 2 后被重定向到的 URL 的 URL 编码版本。其余参数由 OAuth 签名流程添加。

    <Note>
      **注意：** 你在 [POST oauth/request&#95;token](/zh/resources/fundamentals/authentication/api-reference#post-oauth-request-token) 端点中使用的任何 [回调 URL](/zh/resources/fundamentals/developer-apps#callback-urls) 都必须先在 [开发者控制台](/zh/resources/fundamentals/developer-portal) 的 [X 应用设置](/zh/resources/fundamentals/developer-apps) 中注册。
    </Note>

    <Frame>
      <img src="/images/auth-4.png.twimg.1920.png" alt="" />
    </Frame>

    **示例请求（Authorization 头部已换行展示）：**

    ```
    POST /oauth/request_token HTTP/1.1
    User-Agent: themattharris' HTTP Client
    Host: api.x.com
    Accept: */*
    Authorization:
            OAuth oauth_callback="http%3A%2F%2Flocalhost%2Fsign-in-with-twitter%2F",
                  oauth_consumer_key="cChZNFj6T5R0TigYB9yd1w",
                  oauth_nonce="ea9ec8429b68d6b77cd5600adbbb0456",
                  oauth_signature="F1Li3tvehgcraF8DMJ7OyxO4w9Y%3D",
                  oauth_signature_method="HMAC-SHA1",
                  oauth_timestamp="1318467427",
                  oauth_version="1.0"
    ```

    你的应用应检查该响应的 HTTP 状态码。任何不为 200 的值都表示失败。响应正文将包含 `oauth&#95;token`、`oauth&#95;token&#95;secret` 和 `oauth&#95;callback&#95;confirmed` 参数。你的应用应验证 `oauth&#95;callback&#95;confirmed` 是否为 `true`，并将另外两个值保存起来以用于后续步骤。

    **示例响应（响应正文已换行显示）：**

    ```
    HTTP/1.1 200 OK
    Date: Thu, 13 Oct 2011 00:57:06 GMT
    Status: 200 OK
    Content-Type: text/html; charset=utf-8
    Content-Length: 146
    Pragma: no-cache
    Expires: Tue, 31 Mar 1981 05:00:00 GMT
    Cache-Control: no-cache, no-store, must-revalidate, pre-check=0, post-check=0
    Vary: Accept-Encoding
    Server: tfe

    oauth_token=NPcudxy0yU5T3tBzho7iCotZ3cnetKwcTIRlX0iwRl0&
    oauth_token_secret=veNRnAWe6inFuo8o2u8SLLZLjolYDmDP7SzL0YfYI&
    oauth_callback_confirmed=true

    ```

  <Tab title="步骤 2">
    ### 步骤 2：重定向用户

    下一步是将用户重定向到 X，以便他们可以完成合适的流程，具体如下文“浏览器登录流程”中所述。将用户重定向到 [GET oauth/authenticate](/zh/resources/fundamentals/authentication/api-reference#get-oauth-authenticate)，并将第 1 步中获取的请求令牌作为 `oauth&#95;token` 参数传递。

    网站实现这一点最顺畅的方式，是在对原始“登录”请求的响应中返回一个 HTTP 302 重定向。移动端和桌面应用应打开一个新的浏览器窗口，或通过内嵌 Web 视图跳转到该 URL。

    **用于重定向的示例 URL：**

    https://api.x.com/oauth/authenticate?oauth&#95;token=NPcudxy0yU5T3tBzho7iCotZ3cnetKwcTIRlX0iwRl0

    登录端点会根据用户状态以以下三种方式之一工作：

    1. **已登录且已授权**：如果用户已在 x.com 登录，并且已经授权调用的应用程序，将立即完成身份验证，并携带一个有效的 OAuth 请求令牌返回到回调 URL。跳转到 x.com 的过程对用户来说并不明显。
    2. **已登录但未授权**：如果用户已在 x.com 登录，但尚未授权调用的应用程序，则会显示一个请求，要求与调用应用程序共享访问权限。在接受授权请求后，用户将被重定向到回调 URL，并携带一个有效的 OAuth 请求令牌。
    3. **未登录**：如果用户未在 x.com 登录，他们会在同一屏幕上被提示输入其凭据，并授予应用访问其信息的权限。登录完成后，用户会携带一个有效的 OAuth 请求令牌返回到回调 URL。

    在成功完成身份验证后，您的 `callback&#95;url` 将会收到一个请求，其中包含 `oauth&#95;token` 和 `oauth&#95;verifier` 参数。您的应用程序应验证该令牌是否与第 1 步中收到的请求令牌匹配。

    **来自客户端重定向的请求（查询字符串参数已换行显示）：**

    ```
    GET /sign-in-with-twitter/?
            oauth_token=NPcudxy0yU5T3tBzho7iCotZ3cnetKwcTIRlX0iwRl0&
            oauth_verifier=uw7NjWHT6OJ1MpJOXsHfNxoAhPKpgI8BlYDhxEjIBY HTTP/1.1
    Host: localhost
    User-Agent: Mozilla/5.0 (Macintosh; Intel Mac OS X 10_6_8) AppleWebKit/535.5 (KHTML, like Gecko) Chrome/16.0.891.1 Safari/535.5
    Accept: text/html,application/xhtml+xml,application/xml;q=0.9,*/*;q=0.8
    Referer: http://localhost/sign-in-with-twitter/
    Accept-Encoding: gzip,deflate,sdch
    Accept-Language: en-US,en;q=0.8
    Accept-Charset: ISO-8859-1,utf-8;q=0.7,*;q=0.3
    ```

  <Tab title="步骤 3">
    ### 步骤 3：将请求令牌转换为访问令牌

    要将请求令牌转换为可用的访问令牌，你的应用程序必须向 [POST oauth/access&#95;token](/zh/resources/fundamentals/authentication/api-reference#post-oauth-access-token) 端点发起请求，请求中应包含在步骤 2 中获取的 oauth&#95;verifier 值。请求令牌也会通过请求头中的 oauth&#95;token 字段传递，但这部分会由签名流程自动添加。

    **示例请求（Authorization 请求头已换行显示）：**

    ```
    POST /oauth/access_token HTTP/1.1
    User-Agent: themattharris' HTTP Client
    Host: api.x.com
    Accept: */*
    Authorization: OAuth oauth_consumer_key="cChZNFj6T5R0TigYB9yd1w",
                          oauth_nonce="a9900fe68e2573b27a37f10fbad6a755",
                          oauth_signature="39cipBtIOHEEnybAR4sATQTpl2I%3D",
                          oauth_signature_method="HMAC-SHA1",
                          oauth_timestamp="1318467427",
                          oauth_token="NPcudxy0yU5T3tBzho7iCotZ3cnetKwcTIRlX0iwRl0",
                          oauth_version="1.0"
    Content-Length: 57
    Content-Type: application/x-www-form-urlencoded

    oauth_verifier=uw7NjWHT6OJ1MpJOXsHfNxoAhPKpgI8BlYDhxEjIBY
    ```

    成功的响应包含 oauth&#95;token 和 oauth&#95;token&#95;secret 参数。应当将该 token 和 token secret 存储起来，并在之后向 X API 发起已认证请求时使用。要确定用户身份，请使用 [GET account/verify&#95;credentials](https://dev.x.com/rest/reference/get/account/verify_credentials)。

    **示例响应（响应正文已进行换行处理）：**

    ```
    HTTP/1.1 200 OK
    Date: Thu, 13 Oct 2011 00:57:08 GMT
    Status: 200 OK
    Content-Type: text/html; charset=utf-8
    Content-Length: 157
    Pragma: no-cache
    Expires: Tue, 31 Mar 1981 05:00:00 GMT
    Cache-Control: no-cache, no-store, must-revalidate, pre-check=0, post-check=0
    Vary: Accept-Encoding
    Server: tfe

    oauth_token=7588892-kagSNqWge8gB1WwE3plnFsJHAZVfxWD7Vb57p0b4&
    ```

  <Tab title="浏览器登录流程">
    浏览器登录流程适用于能够打开或嵌入 Web 浏览器的网站和应用。大致流程如下：

    * 应用显示一个 “Sign in with X” 链接或按钮。
    * 用户点击登录按钮。
    * 当前 Web 浏览器被重定向到 X（或打开一个新的浏览器并导航到 X）。
    * 如有需要，用户在 X 上完成登录和授权步骤。
    * X 重定向回应用控制下的某个 URL，并传递用户的授权信息。

    X 会跟踪授权记录，因此对于已经登录 X.com 且已授权该应用的用户，不会显示任何界面，而是会自动重定向回应用。
