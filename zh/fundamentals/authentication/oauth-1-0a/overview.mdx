<div id="oauth-10a">
  ## OAuth 1.0a
</div>

X 开发者平台上的许多端点使用 OAuth 1.0a 方式代表某个 X 账号执行操作或发起 API 请求。比如，如果你有一个 X 开发者 App，只要某个用户完成对你的 App 的授权，你就可以代表该 X 账号发起 API 请求。

请注意：如果你不熟悉 HMAC-SHA1 和百分号编码（percent encoding）等概念，建议先查看下方的“实用工具”部分，其中列出了一些可以大大简化认证流程的 API 客户端。

<div id="key-concepts">
  ### 核心概念
</div>

<div id="signing-a-request-with-keys-and-tokens">
  #### 使用密钥和令牌对请求进行签名
</div>

你必须在 Authorization 头中传递若干生成的密钥和令牌，对每个 API 请求进行签名。首先，你可以在 [X developer app 的](/zh/resources/fundamentals/developer-apps) 详情页面生成多个密钥和令牌，包括以下内容：

|     |     |
| :--- | :--- |
| API key 和 secret：<br /><br />`oauth_consumer_key`<br /><br />`oauth_consumer_secret` | 可以将它们视为在发起 API 请求时代表你的 X developer app 的用户名和密码。 |
| Access token 和 secret：<br /><br />`oauth_token`<br /><br />`oauth_token_secret` | Access token 和 access token secret 是针对用户的凭证，用于对 OAuth 1.0a API 请求进行身份验证。它们指定了请求代表的是哪个 X 账号。<br /><br />如果你希望你的 App 代表与你的开发者账号关联的同一个 X 账号发起请求，你可以在 [X developer app 的](/zh/resources/fundamentals/developer-apps) 详情页面生成你自己的 access token 和 token secret。<br /><br />如果你想为其他用户生成 access token，请参阅下文的 “Making requests on behalf of users”。 |

<div id="making-requests-on-behalf-of-users">
  #### 代表用户发起请求
</div>

在创建签名时，你需要一组访问令牌，用于标识你将代表其发起请求的用户身份。

你可以在 [App 的详情页面](https://developer.x.com/content/developer-twitter/en/apps) 生成一组访问令牌，它代表拥有该 X 开发者 App 的 X 账号。但如果你希望代表另一个 X 账号发起请求，则该账号的所有者必须在 [3-legged OAuth 流程](/zh/resources/fundamentals/authentication#obtaining-access-tokens-using-3-legged-oauth-flow)中，通过登录其账号的方式向你授予访问权限。该流程的结果是一组访问令牌（oauth&#95;token 和 oauth&#95;token&#95;secret），可以用来发起 OAuth 1.0a 请求。

一旦你拥有这些密钥和令牌，你可以[从头开始创建签名](/zh/resources/fundamentals/authentication#creating-a-signature)。除非你非常了解自己在做什么，或者你正在使用下面提到的某个工具向需要 OAuth 1.0a 的端点发起请求，否则我们不建议这样做。

作为参考，下面是一个带签名的 cURL 请求示例，所有生成的令牌都通过 Authorization 头部传入：

```bash
curl --request POST \
  --url 'https://api.x.com/1.1/statuses/update.json?status=Hello%20world' \
  --header 'authorization: OAuth oauth_consumer_key="CONSUMER_API_KEY", oauth_nonce="OAUTH_NONCE", oauth_signature="OAUTH_SIGNATURE", oauth_signature_method="HMAC-SHA1", oauth_timestamp="OAUTH_TIMESTAMP", oauth_token="ACCESS_TOKEN", oauth_version="1.0"' \
```

<Note>
  **注意：** 用户访问令牌属于敏感信息，必须妥善保管。一旦生成访问令牌，被其代表的用户就是在信任你的应用能确保这些令牌的安全。如果 API 密钥和用户访问令牌同时遭到泄露或攻破，你的应用就有可能暴露对私密信息和账户功能的访问。我们鼓励你进一步了解[如何保护密钥和访问令牌](/zh/resources/fundamentals/developer-apps)。
</Note>

<div id="useful-tools">
  ### 实用工具
</div>

对[请求进行签名](/zh/resources/fundamentals/authentication#creating-a-signature) 的过程较为复杂。我们建议你使用可以自动生成大部分身份验证令牌的 API 客户端库：

|     |     |
| :--- | :--- |
| [Postman](https://www.getpostman.com/) | 一款 API 客户端，允许你构建并发送 REST API 请求。阅读我们的“[Postman 入门](/zh/tutorials/postman-getting-started)”教程以进一步了解该工具。 |
| [Insomnia](https://insomnia.rest/) | Insomnia 是一款 REST API 客户端，提供 Cookie 管理、环境变量、代码生成以及身份验证等功能，支持 Mac、Windows 和 Linux。 |
