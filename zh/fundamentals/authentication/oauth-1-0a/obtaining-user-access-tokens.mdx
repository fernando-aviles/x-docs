<div id="obtaining-access-tokens-using-3-legged-oauth-flow">
  ### 使用三方 OAuth 流程获取访问令牌
</div>

要代表其他用户执行操作，你需要获取他们的访问令牌。访问令牌指定了请求代表哪个 X 账号发起，因此在你获取这些令牌之前，他们需要先授予你访问权限。这些令牌不会过期，但用户可以随时撤销。

X 允许你通过三方 OAuth 流程获取用户访问令牌。该流程会通过将用户重定向到 X 并让他们授权你的应用，从而为你的应用获取一个**访问令牌**和访问令牌密钥（access token secret）。此流程与[实现使用 X 登录](/zh/resources/fundamentals/authentication/guides/log-in-with-x)中描述的流程几乎相同，但有两点区别：

* 使用 [GET oauth/authorize](/zh/resources/fundamentals/authentication/api-reference#get-oauth-authorize) 端点，而不是 [GET oauth/authenticate](/zh/resources/fundamentals/authentication/api-reference#get-oauth-authenticate)。
* 即使先前已经授予访问权限，系统也会**始终**提示用户再次授权你的应用访问。

在开始之前，你需要检查[应用](/zh/resources/fundamentals/developer-apps)的权限，并了解 consumer key（消费者密钥）和回调 URL。如果你没有回调 URL 或公网可访问的 UI，可以考虑使用 [基于 PIN 的授权](/zh/resources/fundamentals/authentication/oauth-1-0a/pin-based-oauth)，它适用于那些在授权后无法访问或嵌入浏览器以重定向用户的应用。

<div id="overview-of-the-process">
  #### 流程概览
</div>

从整体上看，3-legged OAuth 流程将会：

1. 创建一个请求，以便消费者应用获取请求 token。
2. 让用户完成认证，并将请求 token 发送给消费者应用。
3. 将该请求 token 转换为可用的用户访问 token。

**术语说明**

在下面的指南中，你可能会看到不同的术语指代同一件事。

**客户端凭证：**

* App Key === API Key === Consumer API Key === Consumer Key === Customer Key === `oauth_consumer_key`
* App Key Secret === API Secret Key === Consumer Secret === Consumer Key === Customer Key === `oauth_consumer_secret`
* Callback URL === `oauth_callback`
   

**临时凭证：**

* Request Token === `oauth_token`
* Request Token Secret === `oauth_token_secret`
* oauth&#95;verifier
   

**令牌凭证：**

* Access token === Token === 生成的 `oauth_token`
* Access token secret === Token Secret === 生成的 `oauth_token_secret`

<div id="walkthrough-steps">
  #### 演练步骤
</div>

**步骤 1： [POST oauth/request&#95;token](/zh/resources/fundamentals/authentication/api-reference#post-oauth-request-token)**

让消费者应用发起一个请求，以获取 request token。

此请求中唯一特有的参数是 oauth&#95;callback，它必须是你希望用户在完成步骤 2 后被重定向到的 URL 的[URL 编码](/zh/resources/fundamentals/authentication/oauth-1-0a/percent-encoding-parameters)版本。其余参数由 OAuth 签名流程添加。

请注意：你在 [POST oauth/request&#95;token](/zh/resources/fundamentals/authentication/api-reference#post-oauth-request-token) 端点中使用的任何回调 URL，都必须先在开发者控制台中开发者 App 详情页的[开发者 App](/zh/resources/fundamentals/developer-apps)设置里进行配置。
 

**请求包含：**

`oauth_callback="https%3A%2F%2FyourCallbackUrl.com"`

`oauth_consumer_key="cChZNFj6T5R0TigYB9yd1w" `

你的应用应检查响应的 HTTP 状态码。任何不是 200 的值都表示失败。响应体将包含 `oauth_token`、`oauth_token_secret` 和 `oauth_callback_confirmed` 参数。你的应用应验证 `oauth_callback_confirmed` 是否为 true，并将另外两个值存储起来用于后续步骤。
 

**响应包含**

`oauth_token=NPcudxy0yU5T3tBzho7iCotZ3cnetKwcTIRlX0iwRl0`

`oauth_token_secret=veNRnAWe6inFuo8o2u8SLLZLjolYDmDP7SzL0YfYI`

`oauth_callback_confirmed=true`

**步骤 2： [GET oauth/authorize](/zh/resources/fundamentals/authentication/api-reference#get-oauth-authorize)**

让用户完成认证，并将 request token 发送给消费者应用。
 

**用于重定向用户的示例 URL：**

`https://api.x.com/oauth/authorize?oauth_token=NPcudxy0yU5T3tBzho7iCotZ3cnetKwcTIRlX0iwRl0`

认证成功后，你的 `callback_url` 会收到一个包含 `oauth_token` 和 `oauth_verifier` 参数的请求。你的应用应验证该 token 是否与步骤 1 中收到的 request token 相匹配。
 

**来自客户端重定向的请求：**

`https://yourCallbackUrl.com?oauth_token=NPcudxy0yU5T3tBzho7iCotZ3cnetKwcTIRlX0iwRl0&oauth_verifier=uw7NjWHT6OJ1MpJOXsHfNxoAhPKpgI8BlYDhxEjIBY`

**步骤 3： [POST oauth/access&#95;token](/zh/resources/fundamentals/authentication/api-reference#post-oauth-access-token)**

将 request token 转换为可用的 access token。

要将 request token 转换为可用的 access token，你的应用必须向 [POST oauth/access&#95;token](/zh/resources/fundamentals/authentication/api-reference#post-oauth-access-token) 端点发起请求，其中包含在步骤 2 中获取的 `oauth_verifier` 值。request token 也会通过头部中的 `oauth_token` 字段传递，但这会由签名流程自动添加。
 

**请求包含：**

`POST /oauth/access_token`

`oauth_consumer_key=cChZNFj6T5R0TigYB9yd1w`

`oauth_token=NPcudxy0yU5T3tBzho7iCotZ3cnetKwcTIRlX0iwRl0`

`oauth_verifier=uw7NjWHT6OJ1MpJOXsHfNxoAhPKpgI8BlYDhxEjIBY`

成功的响应将包含 `oauth_token` 和 `oauth_token_secret` 参数。应将该 token 和 token secret 存储起来，并在后续对 X API 的已认证请求中使用。要确定用户身份，请使用 [GET account/verify&#95;credentials](/zh/resources/fundamentals/authentication/api-reference)。
 

**响应包含：**

`oauth_token=7588892-kagSNqWge8gB1WwE3plnFsJHAZVfxWD7Vb57p0b4`

`oauth_token_secret=PbKfYqSryyeKDWz4ebtY3o5ogNLG11WJuZBc9fQrQo`

**在需要使用 OAuth 1.0a（应用-用户）的请求中使用这些凭证**

现在你已经获取了用户访问令牌，可以使用它们调用某些 API，例如 [POST statuses/update](/zh/x-api/posts/manage-tweets/introduction) 来代表用户创建推文。
 

**请求内容包括：**

`POST statuses/update.json`

`oauth_consumer_key=cChZNFj6T5R0TigYB9yd1w`

`oauth_token=7588892-kagSNqWge8gB1WwE3plnFsJHAZVfxWD7Vb57p0b4`
