<div id="bearer-token-also-known-as-app-only">
  ### Bearer Token（也称为仅应用（app-only））
</div>

OAuth 2.0 Bearer Token 用于代表你的[开发者 App](/zh/resources/fundamentals/developer-apps)对请求进行身份验证。由于此方法特定于该 App，因此不涉及任何用户。此方法通常适用于只需要以只读方式访问公开信息的开发者。 

此身份验证方法要求你在请求中携带一个 Bearer Token，你可以在开发者 App 的“Keys and tokens”部分生成该 Token。下面是一个带有虚构 Bearer Token 的请求示例：

```json
  curl "https://api.x.com/2/tweets?ids=1261326399320715264,1278347468690915330" \
  -H "Authorization: Bearer AAAAAAAAAAAAAAAAAAAAAFnz2wAAAAAAxTmQbp%2BIHDtAhTBbyNJon%2BA72K4%3DeIaigY0QBrv6Rp8KZQQLOTpo9ubw5Jt?WRE8avbi"
```

使用仅应用身份验证进行的 API 调用，会在 App 级别按端点[受到速率限制](/zh/resources/fundamentals/rate-limits)。

要使用此方法，你需要一个 Bearer Token。你可以通过将 API Key 和 Secret 传递给 [POST oauth2/token](/zh/resources/fundamentals/authentication/api-reference#post-oauth2-token) 端点来生成它，或者在 [Developer Console](/zh/resources/fundamentals/developer-portal) 中的 App 设置里 &quot;keys and token&quot; 部分生成它。

如果你想吊销 Bearer Token，可以使用 [POST oauth2/invalidate&#95;token](/zh/resources/fundamentals/authentication/api-reference#post-oauth2-invalidate-token) 端点，或者在 App 设置的 &quot;keys and tokens&quot; 部分中，点击 Bearer Token 旁边的 &quot;revoke&quot;。

<div id="oauth-20-authorization-code-flow-with-pkce">
  ### 使用 PKCE 的 OAuth 2.0 授权码流程
</div>

使用 PKCE 的 OAuth 2.0 授权码流程允许你代表其他用户完成身份验证，同时对应用的权限范围拥有更精细的控制，并改进跨多设备的授权流程。换句话说，为 X 用户构建应用的开发者将能更好地控制其应用向用户请求哪些信息，因此你只需要向终端用户请求真正需要的数据和信息。

这一现代授权协议使你能够为终端用户呈现更简化、更加顺畅的授权同意流程来为你的应用授予权限，其中只会显示你向他们请求的特定权限范围。这不仅减少了你处理数据的负担，也有助于提升终端用户对你的信任。
