<div id="bearer-token-also-known-as-app-only">
  ### Bearer Token（也称为仅限 App）
</div>

OAuth 2.0 Bearer Token 用于代表你的 [developer App](/zh/resources/fundamentals/developer-apps) 对请求进行身份验证。由于这种方式仅针对 App，不涉及任何用户。此方法通常适用于只需要对公开信息进行只读访问的开发者。 

此身份验证方法要求你在请求中携带 Bearer Token，你可以在开发者 App 的 Keys and tokens 部分生成该令牌。下面是一个带有虚构 Bearer Token 的请求示例：

```json
  curl "https://api.x.com/2/tweets?ids=1261326399320715264,1278347468690915330" \
  -H "Authorization: Bearer AAAAAAAAAAAAAAAAAAAAAFnz2wAAAAAAxTmQbp%2BIHDtAhTBbyNJon%2BA72K4%3DeIaigY0QBrv6Rp8KZQQLOTpo9ubw5Jt?WRE8avbi"
```

使用仅应用（App-only）身份验证进行的 API 调用，会在应用级别对每个端点分别实施[速率限制](/zh/resources/fundamentals/rate-limits)。

要使用此方法，你需要一个 Bearer Token。你可以通过将你的 API Key 和 Secret 传递给 [POST oauth2/token](/zh/resources/fundamentals/authentication/api-reference#post-oauth2-token) 端点来生成，或者在 [Developer Console](/zh/resources/fundamentals/developer-portal) 中的 App 设置里，“keys and token” 部分生成。

如果你想撤销 Bearer Token，可以使用 [POST oauth2/invalidate&#95;token](/zh/resources/fundamentals/authentication/api-reference#post-oauth2-invalidate-token) 端点，或者在 App 设置中 “keys and tokens” 部分里，在 Bearer Token 旁边点击 “revoke”。

<div id="oauth-20-authorization-code-flow-with-pkce">
  ### 使用 PKCE 的 OAuth 2.0 授权码流程
</div>

使用 PKCE 的 OAuth 2.0 授权码流程，允许你代表其他用户进行身份验证，同时对应用的 scope 拥有更多控制，并改进跨多设备的授权流程。换句话说，为 X 用户构建应用的开发者，将能更好地控制其 App 向用户请求的信息，因此你只需要向终端用户请求你真正所需的数据和信息。

这种现代的授权协议将使你能够为终端用户提供更加简化的授权同意流程，用于为你的应用授予权限，而且该流程只会展示你向他们请求的特定 scope。这样不仅减少了你的数据处理负担，还有可能提升终端用户对你的信任度。
