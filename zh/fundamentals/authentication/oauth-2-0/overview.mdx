<div id="bearer-token-also-known-as-app-only">
  ### Bearer 令牌（也称为仅 App）
</div>

OAuth 2.0 Bearer 令牌用于代表你的[开发者 App](/zh/resources/fundamentals/developer-apps)对请求进行身份验证。由于这种方式是特定于 App 的，因此不涉及任何用户。此方式通常适用于只需要对公开信息进行只读访问的开发者。 

这种认证方式要求你在请求中携带一个 Bearer 令牌，你可以在开发者 App 的 “Keys and tokens” 部分生成该令牌。下面是一个带有虚构 Bearer 令牌的请求示例：

```json
  curl "https://api.x.com/2/tweets?ids=1261326399320715264,1278347468690915330" \
  -H "Authorization: Bearer AAAAAAAAAAAAAAAAAAAAAFnz2wAAAAAAxTmQbp%2BIHDtAhTBbyNJon%2BA72K4%3DeIaigY0QBrv6Rp8KZQQLOTpo9ubw5Jt?WRE8avbi"
```

使用仅 App 身份验证的 API 调用，会在 App 级别按端点进行[速率限制](/zh/resources/fundamentals/rate-limits)。

要使用此方法，你需要一个 Bearer 令牌。你可以通过将 API Key 和 Secret 传递给 [POST oauth2/token](/zh/resources/fundamentals/authentication/api-reference#post-oauth2-token) 端点来生成该令牌，或者在 [开发者控制台](/zh/resources/fundamentals/developer-portal) 中的 App 设置里 “keys and token” 部分生成它。

如果你想撤销一个 Bearer 令牌，可以使用 [POST oauth2/invalidate&#95;token](/zh/resources/fundamentals/authentication/api-reference#post-oauth2-invalidate-token) 端点，或者在 App 设置中 “keys and tokens” 部分里，点击 Bearer 令牌旁边标有 “revoke” 的位置进行撤销。

<div id="oauth-20-authorization-code-flow-with-pkce">
  ### 使用 PKCE 的 OAuth 2.0 授权码流程
</div>

使用 PKCE 的 OAuth 2.0 授权码流程允许你代表其他用户进行身份验证，更精细地控制应用的权限范围（scopes），并改进跨多设备的授权流程。换句话说，为 X 上的用户构建应用的开发者将能更好地控制其 App 向用户请求的信息，这样你只需向终端用户请求你真正需要的数据和信息。

这一现代授权协议将使你能够向终端用户呈现更精简的同意授权流程来为你的应用授予权限，该流程只显示你向他们请求的特定权限范围（scopes）。这样不仅可以减轻你的数据处理负担，还可能提升终端用户对你的信任度。
