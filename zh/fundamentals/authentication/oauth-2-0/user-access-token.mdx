<div id="how-to-connect-to-endpoints-using-oauth-20-authorization-code-flow-with-pkce">
  ### 如何使用 OAuth 2.0 带 PKCE 的授权码流程连接到 API 端点
</div>

<div id="how-to-connect-to-the-endpoints">
  #### 如何连接这些端点
</div>

为了对你的用户进行身份验证，你的 App 需要实现一个授权流程。通过该授权流程，你可以将用户引导到 X 上的授权对话框。在那里，X 的主体验会显示授权对话框，并代表你的 App 处理授权。你的用户可以选择授权你的 App，或拒绝授权。用户做出选择后，X 会将用户重定向回你的 App，此时你可以将授权码交换为访问令牌（如果用户授权了你的 App），或者处理授权被拒的情况（如果用户未授权你的 App）。

<div id="working-with-confidential-clients">
  #### 使用机密客户端
</div>

如果你在使用机密客户端，你需要使用一种[基本身份验证](https://datatracker.ietf.org/doc/html/rfc2617#section-2)方案，在向令牌端点发起请求时，通过 base64 编码生成带有 Authorization 头的请求。

在凭证中，`userid` 和 `password` 之间使用一个冒号（&quot;:&quot;）字符分隔，并组合为一个 base64 编码字符串。

一个示例如下所示：

`-header 'Authorization: Basic V1ROclFTMTRiVWhwTWw4M2FVNWFkVGQyTldNNk1UcGphUTotUm9LeDN4NThKQThTbTlKSXQyZm1BanEzcTVHWC1icVozdmpKeFNlR3NkbUd0WEViUA=='`

如果用户代理希望发送 Client ID &quot;Aladdin&quot; 和密码 &quot;open sesame&quot;，则会使用以下请求头字段：

`Authorization: Basic QWxhZGRpbjpvcGVuIHNlc2FtZQ==`

要创建 Basic 授权头部，你需要对 Client ID 和 Client Secret 进行 base64 编码，这两个值可以从你的 App 在[开发者控制台](https://developer.x.com/en/portal/dashboard)中的 “Keys and Tokens” 页面获取。

<div id="steps-to-connect-using-oauth-20">
  #### 使用 OAuth 2.0 进行连接的步骤
</div>

**步骤 1：构造 Authorize URL**

你的 App 需要构建一个指向 X 的 authorize URL，用于指定你的 App 需要授权的 scope。比如，如果你的 App 需要查询推文、用户以及管理关注关系，则应请求以下 scope：

`tweet.read%20users.read%20follows.read%20follows.write`

该 URL 还将包含 `code_challenge` 和 state 参数，以及其他必需参数。在生产环境中，你应为 `code_challenge` 使用随机字符串。

**步骤 2：GET oauth2/authorize**

让用户进行身份验证，并向你的应用返回一个授权码。如果你已经为你的 App 启用了 OAuth 2.0，可以在 App 的 “Keys and Tokens” 页面中找到你的 Client ID。

一个可用于重定向用户的示例 URL 如下：

```
https://x.com/i/oauth2/authorize?response_type=code&client_id=M1M5R3BMVy13QmpScXkzTUt5OE46MTpjaQ&redirect_uri=https://www.example.com&scope=tweet.read%20users.read%20follows.read%20follows.write&state=state&code_challenge=challenge&code_challenge_method=plain
```

包含 offline&#95;access 的示例 URL 如下：

```
https://x.com/i/oauth2/authorize?response_type=code&client_id=M1M5R3BMVy13QmpScXkzTUt5OE46MTpjaQ&redirect_uri=https://www.example.com&scope=tweet.read%20users.read%20follows.read%20offline.access&state=state&code_challenge=challenge&code_challenge_method=plain
```

在成功完成认证后，你会在 `redirect_uri` 上收到一个包含 `auth_code` 参数的请求。你的应用程序应当验证 `state` 参数。

来自客户端重定向的示例请求如下所示：

```
https://www.example.com/?state=state&code=VGNibzFWSWREZm01bjN1N3dicWlNUG1oa2xRRVNNdmVHelJGY2hPWGxNd2dxOjE2MjIxNjA4MjU4MjU6MToxOmFjOjE
```

**步骤 3：POST oauth2/token - 访问令牌**

在这一步，你可以使用授权码来创建访问令牌和刷新令牌（仅当请求了 `offline.access` 作用域时）。你可以向以下端点发送 POST 请求：

```
https://api.x.com/2/oauth2/token
```

你需要通过请求头传入 `Content-Type` 为 `application/x-www-form-urlencoded`。此外，你的请求中应包含以下参数：`code`、`grant_type`、`client_id`、`redirect_uri`，以及 `code_verifier`。

下面是一个公共客户端的示例令牌请求：

```json
curl --location --request POST 'https://api.x.com/2/oauth2/token' \
--header 'Content-Type: application/x-www-form-urlencoded' \
--data-urlencode 'code=VGNibzFWSWREZm01bjN1N3dicWlNUG1oa2xRRVNNdmVHelJGY2hPWGxNd2dxOjE2MjIxNjA4MjU4MjU6MToxOmFjOjE' \
--data-urlencode 'grant_type=authorization_code' \
--data-urlencode 'client_id=rG9n6402A3dbUJKzXTNX4oWHJ' \
--data-urlencode 'redirect_uri=https://www.example.com' \
--data-urlencode 'code_verifier=challenge'
```

下面是一个使用机密客户端的示例：

```json
curl --location --request POST 'https://api.x.com/2/oauth2/token' \
--header 'Content-Type: application/x-www-form-urlencoded' \
--header 'Authorization: Basic V1ROclFTMTRiVWhwTWw4M2FVNWFkVGQyTldNNk1UcGphUTotUm9LeDN4NThKQThTbTlKSXQyZm1BanEzcTVHWC1icVozdmpKeFNlR3NkbUd0WEViUA=='\
--data-urlencode 'code=VGNibzFWSWREZm01bjN1N3dicWlNUG1oa2xRRVNNdmVHelJGY2hPWGxNd2dxOjE2MjIxNjA4MjU4MjU6MToxOmFjOjE' \
--data-urlencode 'grant_type=authorization_code' \
--data-urlencode 'redirect_uri=https://www.example.com' \
--data-urlencode 'code_verifier=challenge'
```

**步骤 4：连接到 API**

现在你可以使用 OAuth 2.0 连接到这些端点了。为此，你将像使用 [Bearer Token 身份验证](/zh/resources/fundamentals/authentication/oauth-2-0/application-only) 那样向 API 发起请求。但这一次无需传递 Bearer Token，而是应当使用你在上一步中生成的 access token。作为响应，你应该会看到与你所请求的端点相对应的有效负载。此请求对于公共和机密客户端是相同的。 

你要发起的请求示例如下：

```json
curl --location --request GET 'https://api.x.com/2/tweets?ids=1261326399320715264,1278347468690915330' \
--header 'Authorization: Bearer Q0Mzb0VhZ0V5dmNXSTEyNER2MFNfVW50RzdXdTN6STFxQlVkTGhTc1lCdlBiOjE2MjIxNDc3NDM5MTQ6MToxOmF0OjE'
```

**步骤 5：POST oauth2/token - refresh token（刷新令牌）**

`refresh token`（刷新令牌）允许应用在无需再次提示用户授权的情况下获取新的访问令牌。你可以通过向以下端点发送一个 POST 请求来创建 `refresh token`：https://api.x.com/2/oauth2/token。你需要在请求头中加入 `Content-Type`，其值为 `application/x-www-form-urlencoded`。此外，你还需要传入你的 `refresh_token`，将 `grant_type` 设置为 `refresh_token`，并指定你的 `client_id`。

此请求适用于公共客户端（public clients）：

```json
POST 'https://api.x.com/2/oauth2/token' \
--header 'Content-Type: application/x-www-form-urlencoded' \
--data-urlencode 'refresh_token=bWRWa3gzdnk3WHRGU1o0bmRRcTJ5VUxWX1lZTDdJSUtmaWcxbTVxdEFXcW5tOjE2MjIxNDc3NDM5MTQ6MToxOnJ0OjE' \
--data-urlencode 'grant_type=refresh_token' \
--data-urlencode 'client_id=rG9n6402A3dbUJKzXTNX4oWHJ'
```

以下是一个机密客户端的示例：

```json
POST 'https://api.x.com/2/oauth2/token' \
--header 'Content-Type: application/x-www-form-urlencoded' \
--header 'Authorization: Basic V1ROclFTMTRiVWhwTWw4M2FVNWFkVGQyTldNNk1UcGphUTotUm9LeDN4NThKQThTbTlKSXQyZm1BanEzcTVHWC1icVozdmpKeFNlR3NkbUd0WEViUA=='\
--data-urlencode 'refresh_token=bWRWa3gzdnk3WHRGU1o0bmRRcTJ5VUxWX1lZTDdJSUtmaWcxbTVxdEFXcW5tOjE2MjIxNDc3NDM5MTQ6MToxOnJ0OjE'\
--data-urlencode 'grant_type=refresh_token'
```

**步骤 6：POST oauth2/revoke - 撤销令牌**

撤销令牌会使访问令牌或刷新令牌失效。它用于在客户端中启用“注销”功能，使你能够清理与授权流程相关、可能不再需要的任何安全凭据。撤销令牌是供 App 撤销令牌使用的，而不是供用户直接使用的。如果 App 希望以编程方式撤销授予它的访问权限，你可以通过向以下 URL 发送 POST 请求来创建撤销令牌请求：

```
https://api.x.com/2/oauth2/revoke
```

你需要在请求头中传入 `Content-Type` 为 `application/x-www-form-urlencoded`，以及你的令牌和 `client_id`。

在某些情况下，用户可能希望撤销此前授予某个 App 的访问权限，可以前往[已连接的 App 页面](https://x.com/settings/connected_apps)来撤销该权限。

```bash
curl --location --request POST 'https://api.x.com/2/oauth2/revoke' \
--header 'Content-Type: application/x-www-form-urlencoded' \
--data-urlencode 'token=Q0Mzb0VhZ0V5dmNXSTEyNER2MFNfVW50RzdXdTN6STFxQlVkTGhTc1lCdlBiOjE2MjIxNDc3NDM5MTQ6MToxOmF0OjE' \
--data-urlencode 'client_id=rG9n6402A3dbUJKzXTNX4oWHJ'
```

此请求适用于机密客户端：

```bash
curl --location --request POST 'https://api.x.com/2/oauth2/revoke' \
--header 'Content-Type: application/x-www-form-urlencoded' \
--header 'Authorization: Basic V1ROclFTMTRiVWhwTWw4M2FVNWFkVGQyTldNNk1UcGphUTotUm9LeDN4NThKQThTbTlKSXQyZm1BanEzcTVHWC1icVozdmpKeFNlR3NkbUd0WEViUA=='\
--data-urlencode 'token=Q0Mzb0VhZ0V5dmNXSTEyNER2MFNfVW50RzdXdTN6STFxQlVkTGhTc1lCdlBiOjE2MjIxNDc3NDM5MTQ6MToxOmF0OjE'
```
