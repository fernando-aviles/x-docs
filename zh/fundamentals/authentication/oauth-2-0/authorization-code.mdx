<div id="oauth-20-authorization-code-flow-with-pkce">
  ### 使用 PKCE 的 OAuth 2.0 授权码模式
</div>

<div id="introduction">
  #### 简介
</div>

OAuth 2.0 是一种业界标准的授权协议，可让你对应用的权限范围（scope）以及跨多设备的授权流程进行更精细的控制。OAuth 2.0 允许你选择粒度更细的 scope，从而代表用户获取相应的权限。 

要在你的 App 中启用 OAuth 2.0，你必须先在开发者控制台中打开 App 设置，并在其中的身份验证设置里启用它。

<div id="how-long-will-my-credentials-stay-valid">
  #### 我的凭证能有效多久？
</div>

默认情况下，通过带有 PKCE 的 Authorization Code Flow 创建的访问令牌只在两个小时内有效，除非你使用了 `offline.access` 权限范围。

<div id="refresh-tokens">
  #### 刷新令牌
</div>

刷新令牌允许应用程序在不再次提示用户的情况下，通过刷新令牌流程获取新的访问令牌。

如果应用请求了 `offline.access` scope，将会签发一个 OAuth 2.0 刷新令牌。利用这个刷新令牌，可以获取一个访问令牌。如果未传入该 scope，我们将不会生成刷新令牌。

使用刷新令牌获取新的访问令牌的示例请求如下：

```bash
POST 'https://api.x.com/2/oauth2/token' \
--header 'Content-Type: application/x-www-form-urlencoded' \
--data-urlencode 'refresh_token=bWRWa3gzdnk3WHRGU1o0bmRRcTJ5VUxWX1lZTDdJSUtmaWcxbTVxdEFXcW5tOjE2MjIxNDc3NDM5MTQ6MToxOnJ0OjE' \
--data-urlencode 'grant_type=refresh_token' \
--data-urlencode 'client_id=rG9n6402A3dbUJKzXTNX4oWHJ
```

<div id="app-settings">
  #### App 设置
</div>

你可以将 App 的身份验证设置配置为 OAuth 1.0a 或 OAuth 2.0。你也可以让一个 App 同时使用 OAuth 1.0a 和 OAuth 2.0。

OAuth 2.0 只能与 X API v2 搭配使用。如果你选择了 OAuth 2.0，就可以在 App 的 Keys and Tokens 部分看到一个 Client ID。 

<div id="confidential-clients">
  #### 机密客户端（Confidential Clients）
</div>

[机密客户端](https://datatracker.ietf.org/doc/html/rfc6749#section-2.1) 可以安全地保存凭证而不将其暴露给未授权方，并能够安全地与授权服务器进行身份验证，从而保证你的 client secret 处于受保护状态。公共客户端通常在浏览器或移动设备上运行，无法使用你的 client secrets。如果你选择的 App 类型是机密客户端，你将会获得一个 client secret。 

如果你在开发者控制台中选择的客户端类型是机密客户端，你同样可以看到一个 Client Secret。可选项包括 Native App、Single page App、Web App、Automated App 或 bot。Native App 和 Single page App 属于公共客户端，而 Web App、Automated App 或 bot 属于机密客户端。

对于具有有效 Authorization Header 的机密客户端，你不需要提供 client id。对于使用公共客户端发起的请求，仍然需要在请求体中包含 Client Id。 

<div id="scopes">
  #### 作用域（Scopes）
</div>

作用域允许你为 App 配置精细的访问权限，使你的 App 仅拥有其所需的权限。要了解不同作用域对应哪些端点，请查看我们的[认证映射指南](/zh/resources/fundamentals/authentication/guides/v2-authentication-mapping)。

|     |     |
| :--- | :--- |
| **Scope（作用域）** | **Description（说明）** |
| tweet.read | 你可以查看的所有推文，包括受保护账号的推文。 |
| tweet.write | 代你发布推文和转推。 |
| tweet.moderate.write | 隐藏和取消隐藏对你推文的回复。 |
| users.email | 来自已认证用户的电子邮件地址。 |
| users.read | 你可以查看的任何账号，包括受保护账号。 |
| follows.read | 关注你的人以及你关注的人。 |
| follows.write | 代你关注和取消关注他人。 |
| offline.access | 保持与你账号的连接，直到你撤销访问权限。 |
| space.read | 你可以查看的所有 Space。 |
| mute.read | 你已静音的账号。 |
| mute.write | 代你静音和取消静音账号。 |
| like.read | 你点赞过的推文以及你可以查看的点赞。 |
| like.write | 代你点赞和取消点赞推文。 |
| list.read | 你创建或加入的列表（包括私密列表）的列表信息、成员和关注者。 |
| list.write | 代你创建和管理列表。 |
| block.read | 你已屏蔽的账号。 |
| block.write | 代你屏蔽和取消屏蔽账号。 |
| bookmark.read | 获取已认证用户已加书签的推文。 |
| bookmark.write | 为推文添加书签并移除书签。 |
| media.write | 上传媒体。 |

<div id="rate-limits">
  #### 速率限制
</div>

在大多数情况下，使用 OAuth 2.0 时的速率限制与使用 OAuth 1.0a 进行认证时相同，推文查询和用户查询除外。对于使用 OAuth 2.0 执行推文查询和用户查询的场景，我们会将每个 App 的限制从每 15 分钟 300 次请求提高到 900 次请求。要了解更多信息，请务必查看我们的[速率限制文档](/zh/resources/fundamentals/rate-limits)。

<div id="grant-types">
  #### 授权类型（grant types）
</div>

在本次初始发布中，我们仅提供带有 [PKCE](https://oauth.net/2/pkce/) 的 [authorization code](https://oauth.net/2/grant-types/authorization-code/) 以及 [refresh token](https://oauth.net/2/grant-types/refresh-token/) 这两种 [grant types](https://oauth.net/2/grant-types/)。未来我们可能会提供更多授权类型。

<div id="oauth-20-flow">
  #### OAuth 2.0 流程
</div>

OAuth 2.0 的授权流程与我们当前使用的 OAuth 1.0a 流程类似。你可以在我们的[相关文档](/zh/resources/fundamentals/authentication/oauth-1-0a/obtaining-user-access-tokens)中查看流程图和详细说明。 

<div id="glossary">
  #### 术语表
</div>

|     |     |
| :--- | :--- |
| **术语** | **说明** |
| Grant types | OAuth 框架为不同用例定义了多种授权类型（grant type），并提供了创建新授权类型的机制。例如 authorization code、client credentials、device code 和 refresh token。 |
| Confidential client | 这类客户端是能够与授权服务器进行安全认证的应用程序，例如能够安全保存其注册的 client secret。 |
| Public client | 这类客户端无法使用注册的 client secret，例如在浏览器或移动设备中运行的应用程序。 |
| Authorization code flow | 由 confidential client 和 public client 共用，用于将 authorization code 交换为 access token 的流程。 |
| PKCE | 对 authorization code flow 的一种扩展，用于防范多种攻击，并使 public client 能够安全地执行 OAuth 令牌交换。 |
| Client ID | 可以在开发者控制台中 “keys and tokens” 部分、标题为 “Client ID” 的位置找到。如果没有看到，请直接联系我们的团队。生成 authorize URL 时需要用到 Client ID。 |
| Redirect URI | 你的回调 URL。你需要满足[精确匹配校验](https://datatracker.ietf.org/doc/html/rfc6749#section-10.6)的要求。 |
| Authorization code | 允许应用代表用户调用 API。通常称为 auth&#95;code。App 拥有者从用户处获得获批的 auth&#95;code 后，其有效期为 30 秒。你必须在 30 秒内将其交换为 access token，否则 auth&#95;code 将过期。 |
| Access token | Access token 是应用代表用户发起 API 请求时所使用的令牌。 |
| Refresh token | 允许应用通过 refresh token flow 在不再次提示用户的情况下获取新的 access token。 |
| Client Secret | 如果你选择的 App 类型是 confidential client，将在 App 的 “keys and tokens” 部分的 “Client ID” 下方获得一个 “Client Secret”。 |

<div id="parameters">
  #### 参数
</div>

要构造 OAuth 2.0 授权 URL，你需要在授权 URL 中包含以下参数。 

|     |     |
| :--- | :--- |
| **参数** | **说明** |
| response&#95;type | 你需要使用字符串“code”来指定这是一个授权码。 |
| client&#95;id | 可以在开发者控制台中标题为“Client ID”的位置找到。 |
| redirect&#95;uri | 你的回调 URL。该值必须与在 App 设置中定义的某个 Callback URL 完全一致。对于 OAuth 2.0，你需要对回调 URL 启用[精确匹配校验](https://datatracker.ietf.org/doc/html/rfc6749#section-10.6)。 |
| state | 你提供的随机字符串，用于防范[CSRF 攻击](https://auth0.com/docs/protocols/state-parameters)。该字符串的长度最多可为 500 个字符。 |
| code&#95;challenge | 一个 [PKCE](https://www.oauth.com/oauth2-servers/pkce/authorization-request/) 参数，即你每次发起请求时使用的随机密钥。 |
| code&#95;challenge&#95;method | 指定你用于生成 code&#95;challenge 并发起请求的方法（S256 或 plain）。 |

<div id="authorize-url">
  #### 授权 URL
</div>

使用 OAuth 2.0 时，你需要创建一个授权 URL，用于让用户通过认证流程完成身份验证，类似于使用 X 的“登录”功能。 

你要创建的 URL 示例如下：

```
https://x.com/i/oauth2/authorize?response_type=code&client_id=M1M5R3BMVy13QmpScXkzTUt5OE46MTpjaQ&redirect_uri=https://www.example.com&scope=tweet.read%20users.read%20account.follows.read%20account.follows.write&state=state&code_challenge=challenge&code_challenge_method=plain
```

要让该 URL 正常工作，你需要使用正确的编码。请务必查阅我们关于[百分号编码](/zh/resources/fundamentals/authentication/oauth-1-0a/percent-encoding-parameters)的文档。
