<div id="oauth-20-authorization-code-flow-with-pkce">
  ### 使用 PKCE 的 OAuth 2.0 授权码模式
</div>

<div id="introduction">
  #### 简介
</div>

OAuth 2.0 是一种行业标准的授权协议，它可以让你对应用的权限范围进行更精细的控制，并支持在多设备间执行授权流程。OAuth 2.0 允许你选择特定的细粒度权限范围，从而代表用户获得相应的权限。 

要在你的 App 中启用 OAuth 2.0，你必须在开发者控制台的 App 设置部分中，进入该 App 的身份验证设置里将其启用。

<div id="how-long-will-my-credentials-stay-valid">
  #### 我的凭证会保持有效多长时间？
</div>

默认情况下，通过带 PKCE 的 Authorization Code Flow 创建的 access token 仅在两小时内有效，除非你使用了 `offline.access` scope。

<div id="refresh-tokens">
  #### 刷新令牌
</div>

刷新令牌允许应用在不再次提示用户的情况下，通过刷新令牌流程获取新的访问令牌。

如果应用了 `offline.access` scope，将签发一个 OAuth 2.0 刷新令牌。使用该刷新令牌，你可以获取新的访问令牌。如果未传递该 scope，我们将不会生成刷新令牌。

使用刷新令牌获取新访问令牌的请求示例如下：

```bash
POST 'https://api.x.com/2/oauth2/token' \
--header 'Content-Type: application/x-www-form-urlencoded' \
--data-urlencode 'refresh_token=bWRWa3gzdnk3WHRGU1o0bmRRcTJ5VUxWX1lZTDdJSUtmaWcxbTVxdEFXcW5tOjE2MjIxNDc3NDM5MTQ6MToxOnJ0OjE' \
--data-urlencode 'grant_type=refresh_token' \
--data-urlencode 'client_id=rG9n6402A3dbUJKzXTNX4oWHJ
```

<div id="app-settings">
  #### 应用设置
</div>

您可以将应用的身份验证方式设置为 OAuth 1.0a 或 OAuth 2.0。您也可以启用应用同时使用 OAuth 1.0a 和 OAuth 2.0。

OAuth 2.0 只能与 X API v2 搭配使用。如果您选择了 OAuth 2.0，您会在应用的 Keys and Tokens 部分看到一个 Client ID。 

<div id="confidential-clients">
  #### 机密客户端
</div>

[机密客户端](https://datatracker.ietf.org/doc/html/rfc6749#section-2.1) 可以以安全的方式保存凭据，不会将其暴露给未授权方，并且可以与授权服务器进行安全认证，从而确保你的客户端密钥安全。公共客户端通常运行在浏览器或移动设备上，无法使用你的客户端密钥。如果你选择的 App 类型是机密客户端，将会获得一个客户端密钥（client secret）。 

如果你在开发者控制台中选择的客户端类型是机密客户端，你也可以看到一个客户端密钥（Client Secret）。可选类型包括 Native App、Single page App、Web App、Automated App 或 bot。Native App 和 Single page App 属于公共客户端，而 Web App 和 Automated App 或 bot 属于机密客户端。

对于具有有效 Authorization Header 的机密客户端，你不需要提供客户端 id。对于使用公共客户端发起的请求，仍然必须在请求体中包含 Client Id。 

<div id="scopes">
  #### 作用域
</div>

作用域允许你为 App 设置更细粒度的访问控制，使 App 只拥有所需的权限。要了解各个作用域与哪些端点相对应，请查看我们的[认证映射指南](/zh/resources/fundamentals/authentication/guides/v2-authentication-mapping)。

| :--- | :--- |
| **Scope** | **Description** |
| tweet.read | 所有你可以查看的推文，包括受保护账号的推文。 |
| tweet.write | 为你发布推文和转推。 |
| tweet.moderate.write | 隐藏和取消隐藏对你推文的回复。 |
| users.email | 已通过身份验证用户的电子邮件地址。 |
| users.read | 任何你可以查看的账号，包括受保护账号。 |
| follows.read | 关注你的人以及你关注的人。 |

| offline.access | 保持对你账号的访问，直到你撤销授权。 |
| space.read | 所有你可以查看的 Spaces。 |
| mute.read | 你已静音的账号。 |
| mute.write | 为你静音和取消静音账号。 |

<div id="rate-limits">
  #### 速率限制
</div>

在大多数情况下，使用 OAuth 2.0 进行身份验证时的速率限制与使用 OAuth 1.0a 时相同，推文查询和用户查询除外。对于使用 OAuth 2.0 的推文查询和用户查询，我们将每个 App 的限额从每 15 分钟 300 次请求提高到 900 次请求。要了解更多信息，请务必查看我们的[速率限制文档](/zh/resources/fundamentals/rate-limits)。

<div id="grant-types">
  #### 授权类型
</div>

在本次初始发布中，我们仅支持带有 [PKCE](https://oauth.net/2/pkce/) 的[授权码](https://oauth.net/2/grant-types/authorization-code/)和[刷新令牌](https://oauth.net/2/grant-types/refresh-token/)这两种[授权类型](https://oauth.net/2/grant-types/)。未来我们可能会提供更多授权类型。

<div id="oauth-20-flow">
  #### OAuth 2.0 流程
</div>

OAuth 2.0 使用的流程与我们目前使用的 OAuth 1.0a 流程相似。你可以在我们的[相关文档](/zh/resources/fundamentals/authentication/oauth-1-0a/obtaining-user-access-tokens)中查看流程图和详细说明。 

<div id="glossary">
  #### 术语表
</div>

|     |     |
| :--- | :--- |
| **术语** | **说明** |
| 授权类型（Grant types） | OAuth 框架为不同的使用场景定义了多种授权类型，并提供了创建新授权类型的框架。例如 authorization code、client credentials、device code 和 refresh token。 |
| 机密客户端（Confidential client） | 机密客户端是可以与授权服务器安全进行身份验证的应用程序，例如能够安全保存其注册的 client secret。 |
| 公共客户端（Public client） | 公共客户端无法使用已注册的 client secret，例如在浏览器或移动设备中运行的应用程序。 |
| Authorization code flow（授权码流程） | 由机密客户端和公共客户端使用，以授权码换取访问令牌（access token）。 |
| PKCE | 对授权码流程的扩展，用于防止多种攻击，并使公共客户端能够安全地执行 OAuth 授权交换。 |
| Client ID | 可以在开发者控制台的密钥和令牌部分，在标题为 &quot;Client ID&quot; 的位置找到。如果你没有看到这一项，请直接联系我们的团队。生成 authorize URL 时需要使用 Client ID。 |
| Redirect URI | 你的回调 URL。你需要进行[精确匹配校验](https://datatracker.ietf.org/doc/html/rfc6749#section-10.6)。 |
| Authorization code（授权码） | 允许应用代表用户调用 API。也称为 auth&#95;code。一旦 App 所有者从用户那里收到经批准的 auth&#95;code，其有效期为 30 秒。你必须在 30 秒内将其交换为访问令牌，否则该 auth&#95;code 将过期。 |
| Access token（访问令牌） | 访问令牌是应用代表用户发起 API 请求时使用的令牌。 |
| Refresh token（刷新令牌） | 允许应用通过刷新令牌流程在不打扰用户的情况下获取新的访问令牌。 |
| Client Secret | 如果你选择的 App 类型是机密客户端，会在 App 的密钥和令牌部分的 “Client ID” 下方获得一个 “Client Secret”。 |

<div id="parameters">
  #### 参数
</div>

要构造一个 OAuth 2.0 授权 URL，你需要确保在授权 URL 中包含以下参数。 

|     |     |
| :--- | :--- |
| **Parameter** | **Description** |
| response&#95;type | 你需要使用字符串 `code` 指定这是授权码类型。 |
| client&#95;id | 可以在开发者控制台中 &quot;Client ID&quot; 标题下找到。 |
| redirect&#95;uri | 你的回调 URL。该值必须与在你的 App 设置中定义的某个 Callback URL 精确对应。对于 OAuth 2.0，你需要为回调 URL 启用[精确匹配验证](https://datatracker.ietf.org/doc/html/rfc6749#section-10.6)。 |
| state | 你提供的用于防范 [CSRF 攻击](https://auth0.com/docs/protocols/state-parameters) 的随机字符串。该字符串的长度最多可以为 500 个字符。 |
| code&#95;challenge | 一个 [PKCE](https://www.oauth.com/oauth2-servers/pkce/authorization-request/) 参数，即你每次发起请求时生成的随机机密值。 |
| code&#95;challenge&#95;method | 指定你用于发起请求的方法（S256 或 plain）。 |

<div id="authorize-url">
  #### 授权 URL
</div>

使用 OAuth 2.0 时，你需要创建一个授权 URL，允许用户通过认证流程进行身份验证，其体验类似于“使用 X 登录”。 

你要创建的 URL 示例如下所示：

```
https://x.com/i/oauth2/authorize?response_type=code&client_id=M1M5R3BMVy13QmpScXkzTUt5OE46MTpjaQ&redirect_uri=https://www.example.com&scope=tweet.read%20users.read%20account.follows.read%20account.follows.write&state=state&code_challenge=challenge&code_challenge_method=plain
```

要使此 URL 正常工作，需要使用正确的编码。请务必查阅我们关于[百分号编码](/zh/resources/fundamentals/authentication/oauth-1-0a/percent-encoding-parameters)的文档。
