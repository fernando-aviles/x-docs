X API 处理着海量数据。我们通过身份验证来确保这些数据对开发者和用户而言都是安全的。下面列出了几种身份验证方法。

大多数开发者无需处理与身份验证相关的各种复杂性，因为客户端库会自动帮你处理这些问题。

你可以在我们的[工具和库](/zh/resources/tools-and-libraries)页面找到可用客户端库列表。

<div id="authentication-methods">
  ## 身份验证方法
</div>

<CardGroup cols={2}>
  <Card title="OAuth 1.0a 用户上下文" href="/zh/resources/fundamentals/authentication/oauth-1-0a/api-key-and-secret">
    OAuth 1.0a 允许经过授权的 X 开发者 App 访问私有账号信息，或代表某个 X 账号在 X 上执行操作。

    <br />

    [**了解更多**](/zh/resources/fundamentals/authentication/oauth-1-0a/api-key-and-secret)
  </Card>

  <Card title="仅限 App" href="/zh/resources/fundamentals/authentication/oauth-2-0/overview">
    仅限 App 的 Access Token 允许 X 开发者 App 访问 X 上公开可见的信息。

    <br />

    [**了解更多**](/zh/resources/fundamentals/authentication/oauth-2-0/overview)
  </Card>

  <Card title="基本身份验证" href="/zh/resources/fundamentals/authentication/basic-auth">
    许多 X 的企业级 API 需要使用 HTTP 基本身份验证。

    <br />

    [**了解更多**](/zh/resources/fundamentals/authentication/basic-auth)
  </Card>

  <Card title="带 PKCE 的 OAuth 2.0 授权码流程" href="/zh/resources/fundamentals/authentication/oauth-2-0/authorization-code">
    OAuth 2.0 用户上下文允许你代表另一账号进行身份验证，并对应用的访问范围进行更精细的控制，同时支持跨多设备的授权流程。

    <br />

    [**了解更多**](/zh/resources/fundamentals/authentication/oauth-2-0/authorization-code)
  </Card>
</CardGroup>

<Note>
  **注意：**
  你的 App 的 API Keys 和仅限 App 的 Access Token，以及你的个人 Access Token 和 Access Token Secret，可以在[开发者控制台](/zh/resources/fundamentals/developer-portal)中的 [X developer Apps](/zh/resources/fundamentals/developer-apps) 部分获取。

  **如果你希望代表其他用户发起请求**，需要使用 [3-legged OAuth 流程](https://developer.x.com/resources/fundamentals/authentication/obtaining-user-access-tokens)为该用户生成一套单独的 Access Token，并在你使用 OAuth 1.0a 用户上下文或 OAuth 2.0 用户上下文发起的请求中携带该用户的令牌。
</Note>
