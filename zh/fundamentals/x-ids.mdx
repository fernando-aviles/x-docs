X API 中的每个对象——帖子、用户、列表、私信、Spaces——都有一个唯一的 ID。了解这些 ID 的工作原理有助于你构建可靠的集成方案。

***

<div id="id-format">
  ## ID 格式
</div>

X 的 ID 是使用名为 &quot;Snowflake&quot; 的系统生成的 **64 位无符号整数**。每个 ID 包含：

* **时间戳** — 对象创建的时间
* **工作节点编号** — 生成该 ID 的服务器
* **序列号** — 该毫秒内的顺序

这意味着 ID 大致按时间排序：较大的 ID 通常表示较新的对象。

<Tip>
  ID 在整个 X 中都是全局唯一的，而不仅仅是在某一种对象类型内部唯一。
</Tip>

***

<div id="string-vs-integer-representation">
  ## 字符串与整数表示方式
</div>

<Warning>
  **在代码中务必始终使用字符串形式的 ID。** 某些编程语言（例如 JavaScript）无法精确表示 64 位整数。
</Warning>

在 JavaScript 中，整数被限制为 53 位。这会导致在处理较大 ID 值时出现精度损失：

```javascript
// 这会丢失精度!
const id = 10765432100123456789;
console.log(id.toString()); // "10765432100123458000" — 错误!

// 改用字符串
const id = "10765432100123456789";
console.log(id); // "10765432100123456789" — 正确!
```

<div id="api-versions">
  ### API 版本
</div>

| 版本 | ID 格式 |
|:--------|:----------|
| **X API v2** | 默认返回字符串形式的 ID |
| **X API v1.1** | 同时返回 `id`（整数）和 `id_str`（字符串）——始终使用 `id_str` |

<div id="working-with-ids">
  ## 处理 ID
</div>

<div id="storing-ids">
  ### 存储 ID
</div>

在数据库中将 ID 存储为字符串或 64 位整数：

| Database | 推荐类型 |
|:---------|:-----------------|
| PostgreSQL | `BIGINT` 或 `TEXT` |
| MySQL | `BIGINT UNSIGNED` 或 `VARCHAR(20)` |
| MongoDB | `String` |
| SQLite | `TEXT`（SQLite 的整数最多为 63 位） |

<div id="comparing-ids">
  ### 比较 id
</div>

在按照时间顺序比较 id 时：

```python
# Python - safe for 64-bit integers
if int(id1) > int(id2):
    print("id1 is newer")

# JavaScript - 作为字符串比较(字典序适用于相同长度的 ID)
# 或使用 BigInt
if (BigInt(id1) > BigInt(id2)) {
    console.log("id1 is newer");
}
```

  ## 常见 ID 类型

| 列表 | `1234567890` | |

| 私信事件 | `1234567890123456789` | |
