X API 中的每个对象——帖子、用户、列表、私信和 Space——都有一个唯一的 ID。了解这些 ID 的工作方式有助于你构建可靠的集成。

***

<div id="id-format">
  ## ID 格式
</div>

X 的 ID 是使用名为 &quot;Snowflake&quot; 的系统生成的 **64 位无符号整数**。每个 ID 编码了：

* **时间戳** — 对象创建的时间
* **工作节点编号** — 哪台服务器生成了该 ID
* **序列号** — 该毫秒内的生成顺序

这意味着 ID 大致按时间顺序递增：较大的 ID 通常表示较新的对象。

<Tip>
  ID 在整个 X 平台范围内都是全局唯一的，而不仅仅是在单一对象类型内唯一。
</Tip>

***

<div id="string-vs-integer-representation">
  ## 字符串与整数表示
</div>

<Warning>
  **在代码中始终使用字符串形式的 id。** 某些编程语言（例如 JavaScript）无法准确表示 64 位整数。
</Warning>

在 JavaScript 中，整数被限制为 53 位。这会在处理较大的 id 时导致精度丢失：

```javascript
// This loses precision!
const id = 10765432100123456789;
console.log(id.toString()); // "10765432100123458000" — 错误!

// Use strings instead
const id = "10765432100123456789";
console.log(id); // "10765432100123456789" — correct!
```

<div id="api-versions">
  ### API 版本
</div>

| 版本 | ID 格式 |
|:--------|:----------|
| **X API v2** | 默认将 ID 作为字符串返回 |
| **X API v1.1** | 同时返回 `id`（整数）和 `id_str`（字符串）——应始终使用 `id_str` |

<div id="working-with-ids">
  ## 使用 id
</div>

<div id="storing-ids">
  ### 存储 ID
</div>

在数据库中将 ID 存储为字符串或 64 位整数：

| 数据库 | 推荐类型 |
|:---------|:-----------------|
| PostgreSQL | `BIGINT` 或 `TEXT` |
| MySQL | `BIGINT UNSIGNED` 或 `VARCHAR(20)` |
| MongoDB | `String` |
| SQLite | `TEXT`（SQLite 整数最多为 63 位） |

<div id="comparing-ids">
  ### 比较 ID
</div>

在按时间顺序比较 ID 时：

```python
# Python - safe for 64-bit integers
if int(id1) > int(id2):
    print("id1 is newer")

# JavaScript - 作为字符串比较(字典序适用于相同长度的 ID)
# 或使用 BigInt
if (BigInt(id1) > BigInt(id2)) {
    console.log("id1 is newer");
}
```

<div id="common-id-types">
  ## 常见 ID 类型
</div>

| 对象 | 示例 ID | 备注 |
|:-------|:-----------|:------|
| 帖子（推文） | `1234567890123456789` | 也称为 Tweet ID |
| 用户 | `2244994945` | 较早创建的账号通常具有更短的 ID |
| 列表 | `1234567890` | |
| Space | `1YqGodQbNXDxv` | 字母数字组合，而非 Snowflake 格式 |
| 私信事件 | `1234567890123456789` | |
