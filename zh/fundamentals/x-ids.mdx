X API 中的每个对象（帖子、用户、列表、私信、Space）都有一个唯一的 ID。了解这些 ID 的工作原理有助于你构建可靠的集成。

***

<div id="id-format">
  ## ID 格式
</div>

X 的 ID 是使用名为 &quot;Snowflake&quot; 的系统生成的 **64 位无符号整数**。每个 ID 包含：

* **时间戳（Timestamp）** — 对象创建的时间
* **工作节点编号（Worker number）** — 生成该 ID 的服务器
* **序列号（Sequence number）** — 该毫秒内的顺序

这意味着 ID 大致按时间排序：数值更大的 ID 通常代表更新的对象。

<Tip>
  ID 在整个 X 范围内都是全局唯一的，而不仅仅是在单一对象类型内唯一。
</Tip>

***

<div id="string-vs-integer-representation">
  ## 字符串与整数表示
</div>

<Warning>
  **在代码中请始终使用字符串类型的 ID。** 某些编程语言（如 JavaScript）无法精确表示 64 位整数。
</Warning>

在 JavaScript 中，整数的精度最多为 53 位。这会在处理较大的 ID 时导致精度丢失：

```javascript
// 这会丢失精度!
const id = 10765432100123456789;
console.log(id.toString()); // "10765432100123458000" — 错误!

// 改用字符串
const id = "10765432100123456789";
console.log(id); // "10765432100123456789" — 正确!
```

<div id="api-versions">
  ### API 版本
</div>

| 版本 | ID 格式 |
|:--------|:----------|
| **X API v2** | 默认将 ID 作为字符串返回 |
| **X API v1.1** | 同时返回 `id`（整数）和 `id_str`（字符串）— 始终使用 `id_str` |

<div id="working-with-ids">
  ## 使用 id
</div>

<div id="storing-ids">
  ### 存储 ID
</div>

建议在数据库中将 ID 存储为字符串或 64 位整数：

| 数据库 | 推荐类型 |
|:---------|:-----------------|
| PostgreSQL | `BIGINT` 或 `TEXT` |
| MySQL | `BIGINT UNSIGNED` 或 `VARCHAR(20)` |
| MongoDB | 字符串 |
| SQLite | `TEXT`（SQLite 整数最多支持 63 位） |

<div id="comparing-ids">
  ### 比较 ID
</div>

在比较 ID 以确定时间顺序时：

```python
# Python - safe for 64-bit integers
if int(id1) > int(id2):
    print("id1 is newer")

# JavaScript - 作为字符串比较(字典序适用于相同长度的 ID)
# 或使用 BigInt
if (BigInt(id1) > BigInt(id2)) {
    console.log("id1 is newer");
}
```

  ## 常见 ID 类型
</div>

| 对象 | 示例 ID | 说明 |
|:-------|:-----------|:------|
| 帖子（推文） | `1234567890123456789` | 也称为推文 ID |
| 用户 | `2244994945` | 较早创建的账号通常具有更短的 ID |
| 列表 | `1234567890` | |
| Space | `1YqGodQbNXDxv` | 字母数字组合，而非 Snowflake 格式 |
| DM Event | `1234567890123456789` | |
