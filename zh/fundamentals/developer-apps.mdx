应用是你的 API 凭证的容器。每个应用都有自己独立的密钥、令牌和设置。

---

<div id="app-credentials">
  ## 应用凭证
</div>

创建应用时，你可以生成以下凭证：

| 凭证 | 用途 |
|:-----------|:---------|
| **API Key & Secret** | 使用 OAuth 1.0a 进行身份验证。用于签名请求或生成用户令牌。 |
| **Access Token & Secret** | 代表你自己的帐户发起请求（OAuth 1.0a）。 |
| **Client ID & Secret** | 使用 OAuth 2.0 进行身份验证。用于授权码流程。 |
| **Bearer Token** | 用于访问公共数据端点的仅应用身份验证。 |

<Tip>
对于新项目，请选择 **OAuth 2.0**。它提供更细粒度的权限范围（scopes），并且是 X API v2 用户上下文端点的必需条件。
</Tip>

<div id="creating-an-app">
  ## 创建应用
</div>

<Steps>
  <Step title="打开 Developer Console">
    前往 [console.x.com](https://console.x.com) 并登录。
  </Step>
  <Step title="点击 Create App">
    为你的应用输入名称、描述和用例。
  </Step>
  <Step title="生成凭证">
    创建完成后，生成所需的密钥和令牌。
  </Step>
  <Step title="安全存储">
    立即保存凭证——它们只会显示一次。
  </Step>
</Steps>

<div id="app-permissions-oauth-10a">
  ## 应用权限（OAuth 1.0a）
</div>

OAuth 1.0a 应用具有三个权限级别：

<Tabs>
  <Tab title="只读">
    - 查看帖子、用户以及公开数据
    - 无法发布、点赞或修改任何内容
    - 无法访问私信
  </Tab>
  <Tab title="读写">
    - 所有只读权限
    - 发布和删除帖子
    - 关注/取消关注用户
    - 点赞和转发
    - 无法访问私信
  </Tab>
  <Tab title="读写和私信">
    - 所有读写权限
    - 发送和读取私信
  </Tab>
</Tabs>

<Note>
更改权限需要用户重新授权你的应用，以获取权限范围已更新的新 token。
</Note>

<div id="oauth-20-app-types">
  ## OAuth 2.0 应用类型
</div>

在配置 OAuth 2.0 时，选择你的应用类型：

| 类型 | 客户端 | 使用场景 |
|:-----|:-------|:---------|
| **Web App** | 机密 | 能够安全存储密钥的服务端应用程序 |
| **Automated App / Bot** | 机密 | 运行在服务器上的机器人和自动化服务 |
| **Native App** | 公共 | 无法安全存储密钥的移动或桌面应用程序 |
| **Single Page App** | 公共 | 基于浏览器的 JavaScript 应用程序 |

**机密客户端（Confidential clients）** 会获得一个客户端密钥（Client Secret）。**公共客户端（Public clients）** 仅使用 PKCE。

<div id="callback-urls">
  ## 回调 URL
</div>

回调 URL（重定向 URI）在 OAuth 流程中是必需的。在用户授权你的应用后，他们会被重定向到你的回调 URL，并附带授权码。

<div id="requirements">
  ### 要求
</div>

- 在 Developer Console 中将回调 URL 添加到你应用的允许列表中
- URL 必须完全一致（包括末尾的斜杠）
- 每个应用最多支持 **10 个回调 URL**
- 在生产环境中使用 `https://`
- 本地开发时使用 `http://127.0.0.1`（不要使用 `localhost`）

<div id="disallowed-protocols">
  ### 不允许使用的协议
</div>

禁止使用以下协议：`javascript`、`data`、`file`、`ftp`、`mailto`、`telnet`，以及其他非标准 URL 方案（scheme）。

<Accordion title="不允许使用的协议完整列表">
`vbscript`、`javascript`、`vbs`、`data`、`mocha`、`keyword`、`livescript`、`ftp`、`file`、`gopher`、`acrobat`、`callto`、`daap`、`itpc`、`itms`、`firefoxurl`、`hcp`、`ldap`、`mailto`、`mmst`、`mmsu`、`msbd`、`rtsp`、`mso-offdap`、`snews`、`news`、`nntp`、`outlook`、`stssync`、`rlogin`、`telnet`、`tn3270`、`shell`、`sip`
</Accordion>

<div id="automated-account-labels">
  ## 自动化账号标签
</div>

如果你的应用运行的是机器人账号，你可以将其标记为自动化账号：

1. 打开你的机器人账号，进入 **Settings（设置）**
2. 选择 **Your account（你的账号）** → **Automation（自动化）**
3. 关联你的管理账号

这有助于建立用户信任，并将你的机器人账号与垃圾信息区分开来。

<div id="troubleshooting">
  ## 疑难解答
</div>

<Accordion title="Callback URL 未获批准错误">
请确认你的回调 URL 与在 Developer Console 中注册的值完全相同，包括协议和任何结尾的斜杠。在将其作为查询参数传递时，请对该 URL 进行 HTTP 编码。

```json
{
  "errors": [{
    "code": 415,
    "message": "Callback URL not approved for this client application."
  }]
}
```
</Accordion>

<Accordion title="应用被暂停">
如果你的应用显示为已暂停，请检查邮箱中是否有来自 X 平台团队的通知。使用 [Platform Help Form](https://help.x.com/forms/platform) 提交申诉。
</Accordion>
