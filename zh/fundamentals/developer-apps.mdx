应用是用于保存你 API 凭证的容器。每个应用都有自己独立的密钥、令牌和设置。

---

<div id="app-credentials">
  ## 应用凭证
</div>

创建应用时，你可以生成以下凭证：

| 凭证 | 使用场景 |
|:-----------|:---------|
| **API Key 和 Secret** | 使用 OAuth 1.0a 进行身份验证。用于签名请求或生成用户令牌。 |
| **Access Token 和 Secret** | 以你自己的账号身份发起请求（OAuth 1.0a）。 |
| **Client ID 和 Secret** | 使用 OAuth 2.0 进行身份验证。用于授权码流程。 |
| **Bearer Token** | 针对公共数据端点的仅限应用身份验证（App-only）。 |

<Tip>
对于新项目，请选择 **OAuth 2.0**。它提供细粒度的权限范围控制，并且是 X API v2 用户上下文端点所必需的。
</Tip>

<div id="creating-an-app">
  ## 创建应用
</div>

<Steps>
  <Step title="打开开发者控制台">
    前往 [console.x.com](https://console.x.com) 并登录。
  </Step>
  <Step title="点击 Create App">
    输入应用的名称、描述和使用场景。
  </Step>
  <Step title="生成凭证">
    创建完成后，生成所需的密钥和令牌。
  </Step>
  <Step title="安全存储">
    立即保存凭证——它们只会显示一次。
  </Step>
</Steps>

<div id="app-permissions-oauth-10a">
  ## 应用权限（OAuth 1.0a）
</div>

OAuth 1.0a 应用具有三个权限级别：

<Tabs>
  <Tab title="仅读取">
    - 查看帖子、用户和公共 data
    - 无法发布、点赞或修改任何内容
    - 无法访问私信（Direct Messages）
  </Tab>
  <Tab title="读取和写入">
    - 所有读取权限
    - 发布和删除帖子
    - 关注/取消关注用户
    - 点赞和转发帖子
    - 无法访问私信（Direct Messages）
  </Tab>
  <Tab title="读取、写入和私信">
    - 所有读取和写入权限
    - 发送和阅读私信（Direct Messages）
  </Tab>
</Tabs>

<Note>
更改权限时，用户需要重新授权你的应用，以获取具有更新访问范围的新令牌。
</Note>

<div id="oauth-20-app-types">
  ## OAuth 2.0 应用类型
</div>

配置 OAuth 2.0 时，请选择应用类型：

| 类型 | 客户端 | 使用场景 |
|:-----|:-------|:---------|
| **Web App** | 机密 | 能安全存储密钥的服务端应用 |
| **Automated App / Bot** | 机密 | 运行在服务器上的机器人和自动化服务 |
| **Native App** | 公共 | 无法安全保存密钥的移动或桌面应用 |
| **Single Page App** | 公共 | 基于浏览器的 JavaScript 单页应用 |

**机密客户端（Confidential clients）** 会获授一个 Client Secret。**公共客户端（Public clients）** 只能使用 PKCE。

<div id="callback-urls">
  ## 回调 URL
</div>

在 OAuth 授权流程中，回调 URL（重定向 URI）是必需的。用户授权你的应用后，他们会被重定向到你的回调 URL，并携带授权代码。

<div id="requirements">
  ### 要求
</div>

- 在开发者控制台中将回调 URL 添加到你的应用的允许列表中
- URL 必须完全匹配（包括末尾的斜杠）
- 每个应用最多 **10 个回调 URL**
- 在生产环境中使用 `https://`
- 本地开发时使用 `http://127.0.0.1`（不要使用 `localhost`）

<div id="disallowed-protocols">
  ### 不允许使用的协议
</div>

禁止使用以下协议：`javascript`、`data`、`file`、`ftp`、`mailto`、`telnet`，以及其他非标准 URL 协议。

<Accordion title="不允许使用的协议完整列表">
`vbscript`、`javascript`、`vbs`、`data`、`mocha`、`keyword`、`livescript`、`ftp`、`file`、`gopher`、`acrobat`、`callto`、`daap`、`itpc`、`itms`、`firefoxurl`、`hcp`、`ldap`、`mailto`、`mmst`、`mmsu`、`msbd`、`rtsp`、`mso-offdap`、`snews`、`news`、`nntp`、`outlook`、`stssync`、`rlogin`、`telnet`、`tn3270`、`shell`、`sip`
</Accordion>

<div id="automated-account-labels">
  ## 自动化账号标签
</div>

如果你的应用使用机器人账号，你可以为其添加自动化标签：

1. 前往你的机器人账号的 **Settings（设置）**
2. 选择 **Your account（你的账号）** → **Automation（自动化）**
3. 关联你的管理账号

这样有助于提升用户信任度，并将你的机器人账号与垃圾账号区分开来。

<div id="troubleshooting">
  ## 疑难解答
</div>

<Accordion title="Callback URL not approved error">
请确保你的回调 URL 与在开发者控制台中注册的地址完全一致，包括协议以及任何结尾的斜杠。在将该 URL 作为查询参数传递时，请对其进行 HTTP 编码。

```json
{
  "errors": [{
    "code": 415,
    "message": "Callback URL not approved for this client application."
  }]
}
```
</Accordion>

<Accordion title="App suspended">
如果你的应用显示为已暂停，请检查你的电子邮箱中是否有来自 X 平台团队的通知。使用 [Platform Help Form](https://help.x.com/forms/platform) 提交申诉。
</Accordion>
