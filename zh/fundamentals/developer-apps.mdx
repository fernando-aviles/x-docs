应用是用于存放你 API 凭证的容器。每个应用都有各自独立的密钥、令牌和设置。

---

<div id="app-credentials">
  ## App 凭证
</div>

当你创建 App 时，可以生成以下凭证：

| Credential | 用途 |
|:-----------|:-----|
| **API Key & Secret** | 使用 OAuth 1.0a 进行身份验证。用于对请求进行签名或生成用户令牌。 |
| **Access Token & Secret** | 代表你自己的账号发起请求（OAuth 1.0a）。 |
| **Client ID & Secret** | 使用 OAuth 2.0 进行身份验证。用于授权码流程。 |
| **Bearer Token** | 用于访问公共数据端点的 App 级（仅 App）身份验证。 |

<Tip>
新项目请选择 **OAuth 2.0**。它提供更细粒度的权限范围，并且是 X API v2 用户上下文端点的必需条件。
</Tip>

<div id="creating-an-app">
  ## 创建 App
</div>

<Steps>
  <Step title="打开开发者控制台">
    前往 [console.x.com](https://console.x.com) 并登录。
  </Step>
  <Step title="点击 Create App">
    为你的 App 输入名称、描述和使用场景。
  </Step>
  <Step title="生成凭证">
    创建完成后，生成所需的密钥和令牌。
  </Step>
  <Step title="安全存储">
    立即保存凭证——这些信息只会显示一次。
  </Step>
</Steps>

<div id="app-permissions-oauth-10a">
  ## App 权限（OAuth 1.0a）
</div>

使用 OAuth 1.0a 的 App 有三个权限级别：

<Tabs>
  <Tab title="仅限读取">
    - 查看帖子、用户和公开数据
    - 无法发布、点赞或修改任何内容
    - 无法访问私信（Direct Messages）
  </Tab>
  <Tab title="读写">
    - 所有读取权限
    - 发布和删除帖子
    - 关注/取消关注用户
    - 点赞和转发
    - 无法访问私信
  </Tab>
  <Tab title="读写和私信">
    - 所有读写权限
    - 发送和阅读私信
  </Tab>
</Tabs>

<Note>
更改权限需要用户重新授权你的 App，以获取带有更新后作用域的新令牌。
</Note>

<div id="oauth-20-app-types">
  ## OAuth 2.0 App 类型
</div>

在配置 OAuth 2.0 时，选择你的 App 类型：

| 类型 | Client | 使用场景 |
|:-----|:-------|:---------|
| **Web App** | 机密 | 可以安全存储密钥的服务端应用 |
| **Automated App / Bot** | 机密 | 在服务器上运行的机器人和自动化服务 |
| **Native App** | 公共 | 无法安全存储密钥的移动或桌面应用 |
| **Single Page App** | 公共 | 浏览器端的 JavaScript 应用 |

**机密 Client** 会分配一个 Client Secret。**公共 Client** 仅使用 PKCE。

<div id="callback-urls">
  ## 回调 URL
</div>

回调 URL（重定向 URI）是 OAuth 流程中必需的。用户授权你的 App 之后，会被重定向到你的回调 URL，并在其中附带一个授权码。

<div id="requirements">
  ### 要求
</div>

- 在开发者控制台中将回调 URL 添加到你的 App 的允许列表中
- URL 必须完全一致（包括末尾的斜杠）
- 每个 App 最多可配置 **10 个回调 URL**
- 在生产环境中使用 `https://`
- 本地开发时使用 `http://127.0.0.1`（不要使用 `localhost`）

<div id="disallowed-protocols">
  ### 禁止使用的协议
</div>

以下协议禁止使用：`javascript`、`data`、`file`、`ftp`、`mailto`、`telnet`，以及其他非标准协议方案。

<Accordion title="禁止使用的协议完整列表">
`vbscript`、`javascript`、`vbs`、`data`、`mocha`、`keyword`、`livescript`、`ftp`、`file`、`gopher`、`acrobat`、`callto`、`daap`、`itpc`、`itms`、`firefoxurl`、`hcp`、`ldap`、`mailto`、`mmst`、`mmsu`、`msbd`、`rtsp`、`mso-offdap`、`snews`、`news`、`nntp`、`outlook`、`stssync`、`rlogin`、`telnet`、`tn3270`、`shell`、`sip`
</Accordion>

<div id="automated-account-labels">
  ## 自动化账号标签
</div>

如果你的 App 运行的是机器人账号，可以将其标记为自动化账号：

1. 前往你的机器人账号的 **Settings（设置）**
2. 选择 **Your account（你的账号）** → **Automation（自动化）**
3. 关联你的管理账号

这样可以增强用户信任，并将你的机器人账号与垃圾账号区分开来。

<div id="troubleshooting">
  ## 故障排查
</div>

<Accordion title="回调 URL 未获批准错误">
请确保你的回调 URL 与在开发者控制台中注册的配置完全一致，包括协议和任何结尾的斜杠。在将 URL 作为查询参数传递时，请对其进行 HTTP 编码。

```json
{
  "errors": [{
    "code": 415,
    "message": "Callback URL not approved for this client application."
  }]
}
```
</Accordion>

<Accordion title="App 已被暂停">
如果你的 App 显示为已暂停，请检查你的电子邮件，查看是否有来自 X 平台团队的通知。请使用 [Platform Help Form](https://help.x.com/forms/platform) 提交申诉。
</Accordion>
