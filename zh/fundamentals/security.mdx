构建安全的应用程序有助于同时保护你的用户和 X 平台。本指南介绍了 X API 开发者必须掌握的关键安全实践。

***

<div id="core-requirements">
  ## 核心要求
</div>

<CardGroup cols={2}>
  <Card title="必须使用 TLS" icon="lock">
    所有 API 请求都必须使用 HTTPS，纯文本 HTTP 请求会被拒绝。
  </Card>

  <Card title="凭证安全" icon="key">
    切勿在客户端代码、日志或代码仓库中暴露 API 密钥或访问令牌。
  </Card>
</CardGroup>

***

<div id="protecting-credentials">
  ## 保护凭证
</div>

你的 API 密钥和令牌就是你 App 的钥匙。务必保证其安全：

<Steps>
  <Step title="使用环境变量">
    将凭证存储在环境变量中，而不是代码里。

    ```bash
    export X_API_KEY="your-api-key"
    export X_API_SECRET="your-api-secret"
    ```
  </Step>

  <Step title="切勿将密钥提交到代码仓库">
    将凭证文件加入 `.gitignore`。使用 `git-secrets` 等工具防止意外提交。
  </Step>

  <Step title="定期轮换">
    定期重新生成密钥，一旦怀疑发生泄露要立即更换。
  </Step>

  <Step title="使用最小权限">
    只请求你的 App 实际需要的 OAuth 权限范围（scope）。
  </Step>
</Steps>

<div id="if-credentials-are-compromised">
  ### 如果凭证遭到泄露
</div>

1. 在[开发者控制台](https://console.x.com)中**立即重新生成**
2. **吊销旧令牌** —— 重新生成会自动使旧凭证失效
3. **审计使用情况** —— 检查是否存在未经授权的 API 活动
4. **更新你的应用** —— 在所有环境中部署新的凭证

<div id="application-security">
  ## 应用安全
</div>

<div id="input-validation">
  ### 输入验证
</div>

永远不要信任用户输入。在使用任何数据之前，都要先进行验证和清洗：

```python
# Bad - vulnerable to injection
query = f"from:{user_input}"

# Good - validate input first
import re
if re.match(r'^[a-zA-Z0-9_]{1,15}$', user_input):
    query = f"from:{user_input}"
```

<div id="output-encoding">
  ### 输出编码
</div>

在将 X API 数据输出到 HTML 之前进行转义，以防止 XSS 攻击：

```javascript
// Bad - vulnerable to XSS
element.innerHTML = tweet.text;

// Good - escape HTML
element.textContent = tweet.text;
```

<div id="common-vulnerabilities-to-prevent">
  ### 需要预防的常见漏洞
</div>

| 漏洞 | 预防措施 |
|:--------------|:-----------|
| **XSS** | 在渲染前对所有用户生成的内容进行转义 |
| **CSRF** | 在表单中使用防 CSRF 令牌；验证 OAuth state 参数 |
| **SQL Injection** | 使用参数化查询，切勿拼接用户输入 |
| **Open redirects** | 根据白名单验证回调 URL |

<div id="oauth-security">
  ## OAuth 安全
</div>

<div id="state-parameter">
  ### state 参数
</div>

在 OAuth 授权流程中始终使用 `state` 参数来防止 CSRF：

```python
import secrets

# 授权前生成 state
state = secrets.token_urlsafe(32)
session['oauth_state'] = state

# 回调后验证 state
if request.args.get('state') != session.get('oauth_state'):
    abort(403)  # State 不匹配 - 可能的 CSRF 攻击
```

<div id="token-storage">
  ### 令牌存储
</div>

| 令牌类型 | 存储建议 |
|:-----------|:-----------------------|
| **访问令牌** | 加密数据库或安全保管库 |
| **刷新令牌** | 具有额外访问控制的加密数据库 |
| **Bearer 令牌** | 环境变量或安全配置 |

  ## 安全开发实践
</div>

<div id="compliance-checklist">
  ## 合规检查清单
</div>

<Accordion title="面向 X API 开发者的安全要求">
  * [ ] 所有 API 请求都使用 TLS/HTTPS
  * [ ] 凭证安全存储（不写入代码或日志）
  * [ ] 对静态存储的用户令牌进行加密
  * [ ] 对所有用户提供的数据进行输入验证
  * [ ] 对输出进行编码以防止 XSS
  * [ ] 在 OAuth 流程中启用 CSRF 防护
  * [ ] 启用安全日志记录（不包含敏感数据）
  * [ ] 编写并保存安全事件响应预案
  * [ ] 定期更新依赖项
  * [ ] 仅请求最小必要的 OAuth 权限范围
</Accordion>
