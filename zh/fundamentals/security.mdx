构建安全的应用程序既能保护你的用户，也能保护 X 平台。本指南涵盖了 X API 开发者必备的关键安全实践。

***

<div id="core-requirements">
  ## 核心要求
</div>

<CardGroup cols={2}>
  <Card title="必须使用 TLS" icon="lock">
    所有 API 请求必须使用 HTTPS。纯 HTTP 请求会被拒绝。
  </Card>

  <Card title="凭证安全" icon="key">
    切勿在客户端代码、日志或代码仓库中暴露 API key 或 token。
  </Card>
</CardGroup>

<div id="protecting-credentials">
  ## 保护凭证
</div>

你的 API 密钥和令牌就是你应用的钥匙。务必妥善保管：

<Steps>
  <Step title="使用环境变量">
    将凭证存储在环境变量中，而不是写入代码。

    ```bash
    export X_API_KEY="your-api-key"
    export X_API_SECRET="your-api-secret"
    ```
  </Step>

  <Step title="切勿提交机密信息">
    将凭证文件添加到 `.gitignore` 中。使用 `git-secrets` 等工具防止意外提交。
  </Step>

  <Step title="定期轮换">
    定期重新生成密钥，一旦怀疑发生泄露，应立即更换。
  </Step>

  <Step title="使用最小权限">
    只请求你的应用实际需要的 OAuth 作用域。
  </Step>
</Steps>

<div id="if-credentials-are-compromised">
  ### 如果凭证遭到泄露
</div>

1. 在 [Developer Console](https://console.x.com) 中**立即重新生成**
2. **撤销旧 token** —— 重新生成会自动使旧凭证失效
3. **审查使用情况** —— 检查是否存在任何未授权的 API 活动
4. **更新你的应用** —— 将新凭证部署到所有环境

<div id="application-security">
  ## 应用程序安全
</div>

<div id="input-validation">
  ### 输入验证
</div>

切勿信任用户输入。在使用之前，应对所有数据进行验证和净化：

```python
# 不当做法 - 易受注入攻击
query = f"from:{user_input}"

# 正确做法 - 先验证输入
import re
if re.match(r'^[a-zA-Z0-9_]{1,15}$', user_input):
    query = f"from:{user_input}"
```

<div id="output-encoding">
  ### 输出编码
</div>

在将 X API data 显示到 HTML 之前，对其进行转义以防止 XSS 攻击：

```javascript
// 不当做法 - 易受 XSS 攻击
element.innerHTML = tweet.text;

// 正确做法 - 转义 HTML
element.textContent = tweet.text;
```

<div id="common-vulnerabilities-to-prevent">
  ### 需要防范的常见漏洞
</div>

| 漏洞类型 | 防范措施 |
|:--------------|:-----------|
| **XSS** | 在渲染前转义所有用户生成的内容 |
| **CSRF** | 在表单中使用防 CSRF 令牌；校验 OAuth state 参数 |
| **SQL Injection** | 使用参数化查询，切勿拼接用户输入 |
| **Open redirects** | 验证回调 URL 是否在允许列表中 |

<div id="oauth-security">
  ## OAuth 安全
</div>

<div id="state-parameter">
  ### state 参数
</div>

在 OAuth 流程中始终使用 `state` 参数来防止 CSRF 攻击：

```python
import secrets

# Generate state before authorization
state = secrets.token_urlsafe(32)
session['oauth_state'] = state

# Verify state after callback
if request.args.get('state') != session.get('oauth_state'):
    abort(403)  # State 不匹配 - 可能的 CSRF 攻击
```

<div id="token-storage">
  ### 令牌存储
</div>

| 令牌类型 | 存储建议 |
|:-----------|:-----------------------|
| **访问令牌** | 加密数据库或安全保险库 |
| **刷新令牌** | 具备额外访问控制措施的加密数据库 |
| **Bearer tokens** | 环境变量或安全配置 |

<div id="compliance-checklist">
  ## 合规检查清单
</div>

<Accordion title="X API 开发者安全要求">
  * [ ] 所有 API 请求均使用 TLS/HTTPS
  * [ ] 凭证安全存储（不得写入代码或日志）
  * [ ] 用户令牌在静态存储时加密
  * [ ] 对所有用户提供的数据进行输入验证
  * [ ] 对输出进行编码以防止 XSS 攻击
  * [ ] 在 OAuth 流程中启用 CSRF 防护
  * [ ] 启用安全日志记录（不包含敏感数据）
  * [ ] 制定并文档化安全事件响应计划
  * [ ] 定期更新依赖项
  * [ ] 仅请求最小必要的 OAuth 权限范围
</Accordion>
