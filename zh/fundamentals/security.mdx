构建安全的应用程序既能保护你的用户，也能保护 X 平台。本指南概述了 X API 开发者需要了解的关键安全实践。

***

<div id="core-requirements">
  ## 核心要求
</div>

<CardGroup cols={2}>
  <Card title="必须使用 TLS" icon="lock">
    所有 API 请求都必须使用 HTTPS；使用明文 HTTP 的请求会被拒绝。
  </Card>

  <Card title="凭证安全" icon="key">
    切勿在客户端代码、日志或代码仓库中暴露 API 密钥或令牌。
  </Card>
</CardGroup>

***

<div id="protecting-credentials">
  ## 保护凭证
</div>

你的 API 密钥和令牌就是你应用的钥匙。务必确保它们安全：

<Steps>
  <Step title="使用环境变量">
    将凭证存储在环境变量中，而不是写入代码。

    ```bash
    export X_API_KEY="your-api-key"
    export X_API_SECRET="your-api-secret"
    ```
  </Step>

  <Step title="切勿提交机密信息">
    将凭证文件添加到 `.gitignore`。使用 `git-secrets` 等工具防止意外提交。
  </Step>

  <Step title="定期轮换">
    定期重新生成密钥，一旦怀疑泄露要立即更换。
  </Step>

  <Step title="使用最小权限">
    只请求你的应用实际需要的 OAuth 权限范围。
  </Step>
</Steps>

<div id="if-credentials-are-compromised">
  ### 如果凭据遭到泄露
</div>

1. 在[开发者控制台](https://console.x.com)中**立即重新生成**
2. **撤销旧令牌** —— 重新生成会自动使旧凭据失效
3. **审查使用情况** —— 检查是否存在未经授权的 API 调用
4. **更新你的应用程序** —— 将新凭据部署到所有环境中

<div id="application-security">
  ## 应用程序安全
</div>

<div id="input-validation">
  ### 输入验证
</div>

切勿轻信用户输入。在使用之前，必须对所有数据进行验证和清理：

```python
# 错误 - 易受注入攻击
query = f"from:{user_input}"

# 正确 - 先验证输入
import re
if re.match(r'^[a-zA-Z0-9_]{1,15}$', user_input):
    query = f"from:{user_input}"
```

<div id="output-encoding">
  ### 输出编码
</div>

在 HTML 中显示之前，对来自 X API 的 data 进行转义，以防止 XSS 攻击：

```javascript
// 不当做法 - 易受 XSS 攻击
element.innerHTML = tweet.text;

// 正确做法 - 转义 HTML
element.textContent = tweet.text;
```

<div id="common-vulnerabilities-to-prevent">
  ### 需要防范的常见漏洞
</div>

| 漏洞 | 防范措施 |
|:--------------|:-----------|
| **XSS** | 在渲染前转义所有用户生成的内容 |
| **CSRF** | 在表单中使用防 CSRF 令牌；验证 OAuth state 参数 |
| **SQL 注入** | 使用参数化查询，切勿拼接用户输入 |
| **开放重定向** | 根据允许列表验证回调 URL 是否合法 |

<div id="oauth-security">
  ## OAuth 安全
</div>

<div id="state-parameter">
  ### state 参数
</div>

在 OAuth 流程中务必使用 `state` 参数以防范 CSRF 攻击：

```python
import secrets

# Generate state before authorization
state = secrets.token_urlsafe(32)
session['oauth_state'] = state

# Verify state after callback
if request.args.get('state') != session.get('oauth_state'):
    abort(403)  # State 不匹配 - 可能是 CSRF 攻击
```

<div id="token-storage">
  ### 令牌存储
</div>

| 令牌类型 | 存储建议 |
|:-----------|:-----------------------|
| **Access tokens** | 加密数据库或安全保管库 |
| **Refresh tokens** | 具有额外访问控制的加密数据库 |
| **Bearer tokens** | 环境变量或安全配置 |

<div id="resources">
  ## 合规清单
</div>

<Accordion title="X API 开发者的安全要求">
  * [ ] 所有 API 请求都使用 TLS/HTTPS
  * [ ] 凭证安全存储（不硬编码在代码中，也不写入日志）
  * [ ] 对静态存储的用户令牌进行加密
  * [ ] 对所有用户提供的数据进行输入验证
  * [ ] 对输出进行编码以防止 XSS
  * [ ] 在 OAuth 流程中启用 CSRF 防护
  * [ ] 启用安全日志记录（不包含敏感数据）
  * [ ] 制定并文档化安全事件响应预案
  * [ ] 定期更新依赖项
  * [ ] 仅请求最小必要的 OAuth 权限范围
</Accordion>
