速率限制用于控制你在给定时间段内可以发出的 API 请求次数，以确保整个平台的公平使用和系统稳定性。

***

<div id="how-rate-limits-work">
  ## 速率限制的工作方式
</div>

| 概念 | 说明 |
|:--------|:------------|
| **时间窗口** | 大多数限制每 15 分钟重置一次 |
| **用户级限制** | 在使用 OAuth 1.0a 或 OAuth 2.0 用户令牌时适用 |
| **应用级限制** | 在使用 Bearer Token（仅应用）身份验证时适用 |
| **端点级限制** | 每个端点都有各自的限制 |

***

<div id="checking-your-limits">
  ## 检查你的速率限制
</div>

每个 API 响应的响应头中都会包含显示你当前速率限制状态的字段：

```
x-rate-limit-limit: 900
x-rate-limit-remaining: 847
x-rate-limit-reset: 1705420800
```

| Header                   | 说明             |
| :----------------------- | :------------- |
| `x-rate-limit-limit`     | 当前窗口内允许的最大请求数  |
| `x-rate-limit-remaining` | 当前窗口内剩余的请求数    |
| `x-rate-limit-reset`     | 限制重置的 Unix 时间戳 |

***

<div id="rate-limit-errors">
  ## 速率限制错误
</div>

当你超过速率限制时，将收到 **429 Too Many Requests** 响应：

```json
{
  "errors": [{
    "code": 88,
    "message": "Rate limit exceeded"
  }]
}
```

<div id="best-practices">
  ## 最佳实践
</div>

<CardGroup cols={2}>
  <Card title="缓存响应" icon="database">
    在本地缓存 API 响应，以减少对相同数据的重复请求。
  </Card>

  <Card title="使用指数退避" icon="clock-rotate-left">
    当触发速率限制时，重试前先等待，并在每次重试时将等待时间加倍。
  </Card>

  <Card title="检查头信息" icon="list-check">
    监控速率限制相关的 HTTP 头，以主动避免触及限制。
  </Card>

  <Card title="使用流式接口" icon="signal-stream">
    对于实时数据，使用筛选流（filtered stream）而不是轮询搜索端点。
  </Card>
</CardGroup>
