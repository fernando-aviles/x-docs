速率限制用于控制你在特定时间段内可以发起的 API 请求数量，从而确保整个平台的公平使用和系统稳定性。

***

<div id="how-rate-limits-work">
  ## 速率限制的工作原理
</div>

| 概念 | 说明 |
|:--------|:------------|
| **时间窗口** | 大多数限制会每 15 分钟重置一次 |
| **按用户限制** | 在使用 OAuth 1.0a 或 OAuth 2.0 用户令牌时适用 |
| **按 App 限制** | 在使用 Bearer 令牌（仅 App）身份验证时适用 |
| **按端点限制** | 每个端点都有其各自的限制 |

***

<div id="checking-your-limits">
  ## 检查你的速率限制配额
</div>

每个 API 响应都会包含响应头，用于指示你当前的速率限制状态：

```
x-rate-limit-limit: 900
x-rate-limit-remaining: 847
x-rate-limit-reset: 1705420800
```

| Header                   | Description       |
| :----------------------- | :---------------- |
| `x-rate-limit-limit`     | 当前时间窗口内允许的最大请求数   |
| `x-rate-limit-remaining` | 当前时间窗口内剩余的请求数     |
| `x-rate-limit-reset`     | 限制重置时对应的 Unix 时间戳 |

***

<div id="rate-limit-errors">
  ## 速率限制错误
</div>

当你超过速率限制时，会收到 **429 Too Many Requests** 响应：

```json
{
  "errors": [{
    "code": 88,
    "message": "Rate limit exceeded"
  }]
}
```

<div id="best-practices">
  ## 最佳实践
</div>

<CardGroup cols={2}>
  <Card title="缓存响应" icon="database">
    在本地存储 API 响应，以减少对相同数据的重复请求。
  </Card>

  <Card title="使用指数退避" icon="clock-rotate-left">
    当遇到速率限制时，在重试前等待，并在每次重试时将等待时间加倍。
  </Card>

  <Card title="检查响应头" icon="list-check">
    监控速率限制相关的响应头，主动避免触及上限。
  </Card>

  <Card title="使用流式传输" icon="signal-stream">
    对于实时数据，请使用过滤流，而不是轮询搜索端点。
  </Card>
</CardGroup>
