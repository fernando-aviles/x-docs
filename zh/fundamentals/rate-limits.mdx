速率限制控制在一定时间段内可以发起的 API 请求数量，从而确保整个平台的公平使用和系统稳定性。

<div id="how-rate-limits-work">
  ## 速率限制的工作原理
</div>

| 概念 | 描述 |
|:--------|:------------|
| **时间窗口** | 大多数限制每 15 分钟重置一次 |
| **每用户限制** | 在使用 OAuth 1.0a 或 OAuth 2.0 用户令牌时适用 |
| **每应用限制** | 在使用 Bearer Token（仅应用身份验证）时适用 |
| **端点粒度** | 每个端点都有自己的限制 |
--------------------------

<div id="rate-limit-errors">
  ## 检查你的速率限制
</div>

每个 API 响应的响应头中都会包含用于显示你当前速率限制状态的信息：

```
x-rate-limit-limit: 900
x-rate-limit-remaining: 847
x-rate-limit-reset: 1705420800
```

| Header                   | Description    |
| :----------------------- | :------------- |
| `x-rate-limit-limit`     | 当前窗口允许的最大请求数   |
| `x-rate-limit-remaining` | 当前窗口内剩余可用的请求数  |
| `x-rate-limit-reset`     | 限额重置的 Unix 时间戳 |

***

<div id="best-practices">
  ## 速率限制错误
</div>

当你超出速率限制时，你将收到 **429 Too Many Requests** 响应：

```json
{
  "errors": [{
    "code": 88,
    "message": "Rate limit exceeded"
  }]
}
```
