为了支持更多广告活动的最大数量，并高效检索与账户关联的所有实体，Advertiser API 现在在许多 GET 端点上提供了分页功能。该分页机制易于使用，并且与 REST API 中的基于游标的分页机制非常相似，详见[使用游标遍历集合](https://developer.x.com/en/docs/x-api/v1/pagination)。

<div id="getting-started">
  ## 入门
</div>

对于特定的 GET 请求，我们现已支持 `cursor` 和 `count` 查询参数，它们都是可选的。如果某个响应包含的实体数量超过 `count`，这些端点将返回前 `count` 个实体，并在响应 JSON 中包含一个 `next_cursor` 字段。

`GET https://ads-api.x.com/5/accounts/abc1/campaigns?count=50`

```json
{
  "data": \[...\],
  "next_cursor": "c-3yvu1pzhd3i7",
  "request": {...}
}
```

若要获取下一批响应，请在查询参数中添加 `cursor`：

`GET https://ads-api.x.com/5/accounts/abc1/campaigns?cursor=c-3yvu1pzhd3i7&count=50`

```json
{
  "data": \[...\],
  "next_cursor": "c-3w3zdyg8ywan",
  "request": {...}
}
```


<div id="going-deeper">
  ## 深入了解
</div>

对于大多数端点，`count` 的最大值为 **1,000**，最小值为 **1**，默认值为 **200**。

`next_cursor` 提供的值始终是字符串，应视为不透明值；其实现方式可能会发生变化。如果当前结果页返回的实体少于 `count`，则 `next_cursor` 的值将为 `null`。

**注意：**analytics 端点不支持这种分页方式。stats 端点的分页是通过指定时间段来实现的。有关更多信息，请参阅各个端点的文档。
