为了支持更高的广告系列数量上限，并高效检索与账户关联的所有实体，Advertiser API 现在在许多 GET 端点上支持分页。该分页机制易于使用，并且与 REST API 的基于游标的分页方式非常相似，具体说明参见[使用游标浏览集合](https://developer.x.com/en/docs/x-api/v1/pagination)。

<div id="getting-started">
  ## 入门
</div>

对于特定的 GET 请求，我们现在支持 `cursor` 和 `count` 查询参数，这两个参数都是可选的。如果某个响应包含的实体数量多于 `count`，这些端点将返回前 `count` 个实体，并在响应 JSON 中包含一个 `next_cursor` 字段。

`GET https://ads-api.x.com/5/accounts/abc1/campaigns?count=50`

```json
{
  "data": \[...\],
  "next_cursor": "c-3yvu1pzhd3i7",
  "request": {...}
}
```

要获取下一批响应，你需要在查询参数中添加 `cursor`：

`GET https://ads-api.x.com/5/accounts/abc1/campaigns?cursor=c-3yvu1pzhd3i7&count=50`

```json
{
  "data": \[...\],
  "next_cursor": "c-3w3zdyg8ywan",
  "request": {...}
}
```


<div id="going-deeper">
  ## 深入了解
</div>

对于大多数端点，`count` 的最大值为 **1,000**，最小值为 **1**，默认值为 **200**。

`next_cursor` 提供的值始终是一个字符串，应视为不透明值；其具体实现可能会发生变化。如果当前结果集页面中返回的实体数量少于 `count`，则 `next_cursor` 的值将为 `null`。

**注意：**analytics 端点不支持这种分页方式。stats 端点的分页通过指定时间区间来实现。有关更多信息，请参阅这些各自端点的文档。
