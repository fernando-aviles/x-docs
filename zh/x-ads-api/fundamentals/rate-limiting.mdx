Advertiser API 的速率限制方式与 REST API v1.1 类似，详见文档：[REST API v1.1 中的速率限制](https://developer.x.com/content/developer-twitter/en/docs/basics/rate-limits)。与 REST API v1.1 不同的是，没有提供按 endpoint 列出的可编程限额索引。各 endpoint 的速率限制和重置时间窗口通过 HTTP 响应头传达。Ads API 中的所有速率限制均基于 OAuth 1.0a 实现。

<div id="user-level-and-ad-account-level-limits">
  ## 用户级别和广告账户级别限制
</div>

速率限制有两种类型：用户令牌级别和广告账户级别。一部分端点启用了广告账户级别的速率限制。用户令牌是你用来进行身份验证并调用 Ads API 的 [OAuth 访问令牌](/zh/resources/fundamentals/authentication#obtaining-access-tokens-using-3-legged-oauth-flow)。每个用户令牌可以访问一个或多个广告账户。

当响应头中返回广告账户级别速率限制时，开发者应优先使用广告账户级别速率限制；仅在找不到广告账户级别限制时才使用用户级别限制。

用户级别速率限制通过以下响应头体现：**x-rate-limit-limit**、**x-rate-limit-remaining** 和 **x-rate-limit-reset**。

对于启用了广告账户级别速率限制的端点，其速率限制通过以下响应头体现：**x-account-rate-limit-limit**、**x-account-rate-limit-remaining** 和 **x-account-rate-limit-reset**。

广告账户级别的速率限制仅适用于 GET 端点，用于帮助应用在单个用户令牌访问多个广告账户时同步实体数据（例如广告系列或投放单对象）。写入操作不保证使用相同的广告账户级别速率限制。

对于启用广告账户级别速率限制的端点，用户级别的速率限制会被设置为一个较高的值，代表整个应用的全局配额。在可用的情况下，应优先使用广告账户级别的速率限制来控制你的请求量。

<div id="best-practices">
  ## 最佳实践
</div>

1. 在你的数据库中保存上次同步的时间戳，并且在适用的情况下，请求数据时使用 `sort_by=updated_at-desc` 选项，这样当你同步到早于上次同步时间戳的数据时，就可以停止同步过程，从而避免对相同数据进行重复同步。

2. 在单个请求中请求多个实体：某些端点允许你指定一个逗号分隔的取值列表，以检索多条类似的数据。这可以减少你发起的总体调用次数，从而更高效地利用速率限制配额。

3. 在请求中使用最大的 `count` 值：强烈建议对某些端点（例如 [GET accounts/:account&#95;id/targeting&#95;criteria](/zh/x-ads-api/campaign-management#targeting-criteria)）使用最大可用的 `count` 值进行调用，以返回 1000 个对象，而不是默认值 200 个。

<div id="faqs">
  ## 常见问题
</div>

*是否可以为特定广告账号或我们的应用提高速率限制？*

我们通常无法提高速率限制，这些限制的设定足以支持规模最大的广告账号。请首先落实本文档中列出的最佳实践；如果速率限制仍然影响你扩展或实现业务目标的能力，请联系你的 X Ads API 对接人员，并提供关于相关用例和请求的完整详细信息。

  ## 速率限制范围
</div>

<div id="scopes-for-this-doc">
  ### 本文档中的范围
</div>

* Category：属于指定类别的所有端点在每个时间窗口内共享同一分配的速率限制。
* Endpoint：每个端点在每个时间窗口内都有各自独立分配的速率限制。
