要访问 X Ads API 的各个端点，你的应用程序必须通过 TLS 安全地向 https://ads-api.x.com 发送已通过身份验证的 web 请求。

下文将概述如何发起已通过身份验证的 API 请求、如何配置 [Twurl](https://github.com/twitter/twurl#getting-started) 与 API 交互，以及如何扩展你的应用程序以支持 OAuth 1.0a，并向你的 Ads 账户发起请求。

<div id="requirements">
  ## 要求
</div>

在向 X Ads API 发起认证请求之前，你需要：

* 一个[已获批准的开发者账号](/zh/resources/fundamentals/developer-portal)
* 一个已获准访问 [Ads API](/zh/x-ads-api/introduction) 的应用
* 通过 [App 管理界面](/zh/resources/fundamentals/developer-apps) 获取的 API key 和 secret，以及
* 具备 X Ads 账号访问权限的用户的[访问令牌](/zh/resources/fundamentals/authentication#obtaining-access-tokens-using-3-legged-oauth-flow)

<div id="using-the-api">
  ## 使用 API
</div>

Advertising API 可通过 https://ads-api.x.com 访问。[标准 REST API](https://developer.x.com/en/docs/x-api/v1/tweets/post-and-engage/overview) 和 Advertising API 可以在同一个客户端应用中一起使用。Advertising API 强制使用 HTTPS，因此尝试通过 HTTP 访问任何端点都会返回错误信息。

Ads API 输出 JSON。所有标识符都是字符串，且所有字符串均为 UTF-8。Advertising API 支持[版本控制](/zh/x-ads-api/fundamentals/versioning)，版本号作为任何资源 URL 的第一个路径元素进行指定。

`https://ads-api.x.com/&lt;version&gt;/accounts`

<div id="http-verbs-typical-response-codes">
  ## HTTP 动词和典型响应代码
</div>

Ads API 使用四种 HTTP 动词：

* **GET** 用于获取数据 
* **POST** 用于创建新数据，例如广告系列（campaign）
* **PUT** 用于更新现有数据，例如广告单元（line item）
* **DELETE** 用于删除数据。

虽然删除是永久性的，但在大多数基于 GET 的方法中，仍然可以通过在请求资源时显式包含参数 `with_deleted=true` 来查看已删除的数据。否则，对已删除记录的请求将返回 HTTP 404。

成功的请求在创建、删除或更新资源时，会返回一个 HTTP 200 系列的响应，以及一个表示该对象的 JSON 响应。

使用 HTTP PUT 更新数据时，只有指定的字段会被更新。可以通过将参数设置为空字符串来清除一个可选值。例如，下面这一组参数会清除任何已经设置的 `end_time`：`&end_time=&paused=false`。

有关错误响应的更多详细信息，请参阅 [Error Codes &amp; Responses](/zh/x-ads-api/fundamentals/error-codes-and-responses)。

<div id="in-line-parameters">
  ## 内联参数
</div>

大多数资源 URL 都包含一个或多个内联参数。许多 URL 还会在查询字符串中接收显式声明的参数，或者在 POST 或 PUT 请求中放在请求体中。

在每个资源的 **Resource Path** 部分中，内联参数以前置冒号（“:”）表示。例如，如果你正在处理的账户被标识为 `"abc1"`，并且你正在[检索与某个账户关联的广告系列（campaigns）](/zh/x-ads-api/campaign-management#campaigns)，你可以通过使用 URL `https://ads-api.x.com/6/accounts/abc1/campaigns` 来访问该列表。通过在资源 URL（`https://ads-api.x.com/6/accounts/:account_id/campaigns`）中指定所描述的内联 `account_id` 参数，你就将请求限定为仅与该账户关联的对象。

<div id="using-access-tokens">
  ## 使用访问令牌
</div>

X Ads API 使用已签名的 HTTPS 请求来验证应用的身份，并获取终端用户授予该应用代表其发起 API 请求的权限，这些权限由用户的访问令牌表示。对 Ads API 的所有 HTTP 调用都必须在 HTTPS 协议之上包含一个 Authorization 请求头（使用 OAuth 1.0a）。

你需要在你的应用中添加对生成 OAuth 1.0a Authorization 请求头的支持，以便集成 X Ads API。由于生成签名请求较为复杂，我们强烈建议合作伙伴使用现有的库，这些库要么已经支持 X API，要么实现了 OAuth 1.0a 请求处理——这里列出了一些[推荐的 OAuth 库](/zh/resources/fundamentals/authentication#oauth-1-0a-2)以及[认证示例代码](/zh/resources/fundamentals/authentication#oauth-1-0a-2)。

请注意，当合作伙伴在使用已知库时遇到身份验证错误，我们可以提供协助，但无法为自定义的 OAuth 实现提供支持。

<div id="http-oauth">
  ## HTTP 与 OAuth
</div>

与 X REST API v1.1 类似，Advertising API 要求同时使用 [OAuth 1.0a](/zh/resources/fundamentals/authentication) 和 HTTPS。可以通过 [App 管理控制台](/zh/resources/fundamentals/developer-apps) 获取 API 密钥。还必须使用访问令牌（access token）来表示“当前用户”。当前用户是具备投放广告功能的 X 账号。

我们强烈建议合作伙伴使用 OAuth 库，而不是自行编写实现。当你使用常见的库时，我们可以提供调试支持，但如果你自行实现 OAuth，则无法提供支持。请参阅你可以使用的 [库](/zh/resources/fundamentals/authentication#oauth-1-0a-2)。

该 API 对 HTTP 1.1 和 OAuth 有严格要求。请确保在准备 OAuth 签名基字符串之前，已在 URL 和 POST 正文中正确[编码保留字符](https://tools.ietf.org/html/rfc3986#section-2.2)。Advertising API 尤其会在指定时间时使用“:”字符，在提供一组选项时使用“,”字符。这两个字符都属于以下保留字符集合：

| 符号 | URL 编码 |
| :--- | :--- |
| !   | %21 |
| #   | %23 |
| $   | %24 |
| &amp;   | %26 |
| &#39;   | %27 |
| (   | %28 |
| )   | %29 |
| *   | %2A |
| +   | %2B |
| ,   | %2C |
| /   | %2F |
| :   | %3A |
| ;   | %3B |
| =   | %3D |
| ?   | %3F |
| @   | %40 |
| [   | %5B |
| ]   | %5D |

<div id="making-your-first-api-request-with-twurl">
  ## 使用 Twurl 发起你的第一个 API 请求
</div>

X 参与维护一个命令行工具 [Twurl](https://developer.x.com/en/docs/tutorials/using-twurl)，它支持 OAuth 1.0a 授权请求头，可作为 [cURL](https://en.wikipedia.org/wiki/CURL) 的替代方案。Twurl 提供了一种简单方式，让你在将身份验证集成到应用之前，就可以发起带身份验证的 API 请求并探索 Ads API。

在[安装并授权 Twurl](https://github.com/twitter/twurl#getting-started) 之后，你可以快速生成访问令牌，并向 Ads API 发起带身份验证的请求。

```bash
twurl -H "ads-api.x.com" "/5/accounts/"
```

花点时间，通过这个讲解如何通过 API 创建广告系列的[分步](/zh/x-ads-api/campaign-management#creating-a-campaign-step-by-step)教程来熟悉 Twurl 和该 API。

<div id="extending-your-application-to-make-authenticated-requests">
  ### 扩展你的应用以发起经身份验证的请求
</div>

在熟悉了使用 Twurl 向 Ads API 发起请求之后，就可以开始在你的应用中加入对创建 OAuth 1.0a 身份验证头的支持。

[OAuth 1.0a](/zh/resources/fundamentals/authentication) 身份验证头包含用于验证应用和用户身份的信息，并可防止请求被篡改。你的应用需要为每个 API 请求创建一个新的 `Authorization` 头。许多编程语言都有开源库，可以帮助你创建这个身份验证头，从而向 X 发起 API 请求。

下面是一些使用 C#、PHP、Ruby 和 Python 的示例——[代码示例](/zh/resources/fundamentals/authentication#oauth-1-0a-2)。

<div id="custom-implementation">
  ## 自定义实现
</div>

在某些场景下，你需要在没有开源库支持的情况下实现 OAuth 1.0a 认证。[授权请求](/zh/resources/fundamentals/authentication#authorizing-a-request) 提供了关于如何实现用于创建 Authorization 头部的支持的详细说明。我们强烈建议使用由社区支持的库。

总体步骤概览：

1. 为头部收集 7 个以 oauth&#95; 开头的键/值对
2. 使用这些键/值对生成一个 [OAuth 1.0a HMAC-SHA1 签名](/zh/resources/fundamentals/authentication#creating-a-signature)
3. 使用上述值构建 [Authorization 头部](/zh/resources/fundamentals/authentication#authorizing-a-request)
