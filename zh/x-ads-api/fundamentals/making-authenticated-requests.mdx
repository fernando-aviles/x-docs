访问 X Ads API 端点时，要求你的应用通过 TLS，安全地向 https://ads-api.x.com 发送经过认证的网络请求。

下文各部分将概述如何发起认证的 API 请求、如何设置 [Twurl](https://github.com/twitter/twurl#getting-started) 与 API 交互，以及如何扩展你的应用以支持 OAuth 1.0a，并向你的 Ads 账号发起请求。

<div id="requirements">
  ## 前提条件
</div>

在向 X Ads API 发送经过身份验证的请求之前，你需要：

* 一个[已获批准的开发者账号](/zh/resources/fundamentals/developer-portal)
* 一个已[获批 Ads API 访问权限](/zh/x-ads-api/introduction) 的应用
* 通过 [应用管理 UI](/zh/resources/fundamentals/developer-apps) 获取的 API key 和 secret
* 一个拥有 X Ads 账号访问权限的用户的[访问令牌](/zh/resources/fundamentals/authentication#obtaining-access-tokens-using-3-legged-oauth-flow)

<div id="using-the-api">
  ## 使用 API
</div>

Advertising API 可通过 https://ads-api.x.com 访问。[标准 REST API](https://developer.x.com/en/docs/x-api/v1/tweets/post-and-engage/overview) 和 Advertising API 可以在同一个客户端应用中配合使用。Advertising API 要求使用 HTTPS，因此尝试通过 HTTP 访问端点将会返回错误。

Ads API 返回 JSON。所有标识符都是字符串，且所有字符串均为 UTF-8 编码。Advertising API 支持[版本控制](/zh/x-ads-api/fundamentals/versioning)，版本号作为任意资源 URL 的第一个路径元素指定。

`https://ads-api.x.com/<version>/accounts`

<div id="http-verbs-typical-response-codes">
  ## HTTP 动词和典型响应代码
</div>

Ads API 中使用了四种 HTTP 动词：

* **GET** 用于检索数据
* **POST** 用于创建新的数据，例如广告活动（campaigns）
* **PUT** 用于更新现有数据，如广告项目（line items）
* **DELETE** 用于删除数据。

虽然删除操作是永久性的，但在通过大多数基于 GET 的方法请求资源时，如果显式包含 `with_deleted=true` 参数，仍然可以查看已删除的数据。否则，被删除的记录会返回 HTTP 404 状态码。

在创建、删除或更新资源时，请求成功会返回 2xx 范围内的 HTTP 响应状态码，并附带表示该对象的 JSON 响应。

使用 HTTP PUT 更新数据时，只有指定的字段会被更新。你可以通过将参数指定为空字符串来取消设置一个可选值。比如，下面这组参数会取消任何已经设置的 `end_time`：`&end_time=&paused=false`。

有关错误响应的更多详细信息，请参阅 [错误代码和响应](/zh/x-ads-api/fundamentals/error-codes-and-responses)。

<div id="in-line-parameters">
  ## 内联参数
</div>

大多数资源 URL 都包含一个或多个内联参数。许多 URL 还会在查询字符串中显式接受参数，或者在 POST 或 PUT 请求时接受包含在请求 body 中的参数。

内联参数会在每个资源的 **Resource Path** 部分以前置冒号（“:”）标记。例如，如果你正在操作的账号被标识为 `"abc1"`，并且你在[检索与某个账号关联的推广活动](/zh/x-ads-api/campaign-management#campaigns)，你可以通过使用 URL `https://ads-api.x.com/6/accounts/abc1/campaigns` 来访问该列表。通过在资源 URL（`https://ads-api.x.com/6/accounts/:account_id/campaigns`）中指定内联的 `account_id` 参数，你就将该请求限定为只返回与该账号关联的对象。

<div id="using-access-tokens">
  ## 使用访问令牌
</div>

X Ads API 使用签名的 HTTPS 请求来验证应用的身份，并获取应用代表终端用户发起 API 请求时，该终端用户授予的权限，这些权限由用户的访问令牌表示。所有对 Ads API 的 HTTP 调用都必须通过 HTTPS 协议进行，并在请求中包含 Authorization 请求头（使用 OAuth 1.0a）。

你需要在应用中添加对生成 OAuth 1.0a Authorization 请求头的支持，才能与 X Ads API 集成。不过，由于生成签名请求的过程较为复杂，我们强烈建议合作方使用现有的库，这些库要么已经支持 X API，要么实现了 OAuth 1.0a 请求处理——这里提供了一份[推荐的 OAuth 库](/zh/resources/fundamentals/authentication#oauth-1-0a-2)和[身份验证代码示例](/zh/resources/fundamentals/authentication#oauth-1-0a-2)列表。

请注意，当合作方在使用已知库时遇到身份验证错误，我们可以提供协助，但无法为自定义的 OAuth 实现提供支持。

<div id="http-oauth">
  ## HTTP 与 OAuth
</div>

与 X REST API v1.1 类似，Advertising API 需要同时使用 [OAuth 1.0a](/zh/resources/fundamentals/authentication) 和 HTTPS。可以通过 [应用管理控制台](/zh/resources/fundamentals/developer-apps) 获取 API 密钥。还必须使用访问令牌来表示“当前用户”。当前用户是具有投放广告能力的 X 账号。

强烈建议合作伙伴使用 OAuth 库，而不是自行编写实现。当你使用常见库时，我们可以协助调试；如果你自行实现 OAuth，则无法提供这类支持。请参阅可使用的 [库](/zh/resources/fundamentals/authentication#oauth-1-0a-2)。

API 对 HTTP 1.1 和 OAuth 有严格要求。请确保在准备 OAuth 签名基础字符串之前，已在 URL 和 POST 请求正文中正确 [对保留字符进行编码](https://tools.ietf.org/html/rfc3986#section-2.2)。Advertising API 在指定时间时特别使用 “:” 字符，在提供一组选项时使用 “,” 字符。这两个字符都属于下列保留字符集：

| 符号 | URL 编码 |
| :--- | :--- |
| !   | %21 |
| #   | %23 |
| $   | %24 |
| &amp;   | %26 |
| &#39;   | %27 |
| (   | %28 |
| )   | %29 |
| *   | %2A |
| +   | %2B |
| ,   | %2C |
| /   | %2F |
| :   | %3A |
| ;   | %3B |
| =   | %3D |
| ?   | %3F |
| @   | %40 |
| [   | %5B |
| ]   | %5D |

<div id="making-your-first-api-request-with-twurl">
  ## 使用 Twurl 发起你的第一个 API 请求
</div>

X 帮助维护了一个命令行工具 [Twurl](https://developer.x.com/en/docs/tutorials/using-twurl)，它支持使用 OAuth 1.0a 授权请求头，作为 [cURL](https://en.wikipedia.org/wiki/CURL) 的替代方案。Twurl 提供了一种简单的方法，用于发起带认证信息的 API 请求，并在将认证集成到你的应用之前先探索 Ads API。

在[安装并授权 Twurl](https://github.com/twitter/twurl#getting-started) 之后，你可以快速生成访问令牌，并向 Ads API 发起带认证信息的请求。

```bash
twurl -H "ads-api.x.com" "/5/accounts/"
```

花点时间通过这个[分步](/zh/x-ads-api/campaign-management#creating-a-campaign-step-by-step)教程（演示如何通过 API 创建广告活动）来熟悉 Twurl 和 API。

<div id="extending-your-application-to-make-authenticated-requests">
  ### 扩展你的应用以发起经过认证的请求
</div>

在通过 Twurl 熟悉了向 Ads API 发起请求之后，就可以在你的应用中添加对生成 OAuth 1.0a 认证头的支持了。

[OAuth 1.0a](/zh/resources/fundamentals/authentication) 认证头包含用于验证应用程序和用户身份的信息，同时还能防止请求被篡改。你的应用需要为每个 API 请求创建一个新的 `Authorization` 头。许多编程语言都有支持创建此授权头、用于向 X 发起 API 请求的开源库。

以下是一些使用 C#、PHP、Ruby 和 Python 的示例：[代码示例](/zh/resources/fundamentals/authentication#oauth-1-0a-2)。

<div id="custom-implementation">
  ## 自定义实现
</div>

在某些场景下，你需要在没有开源库支持的情况下实现 OAuth 1.0a 认证。[为请求授权](/zh/resources/fundamentals/authentication#authorizing-a-request) 中提供了关于如何实现对 `Authorization` 头的支持（即如何创建该头）的详细说明。我们强烈建议你使用由社区维护的库。

总体步骤概览：

1. 为头收集 7 个以 `oauth_` 开头的键值对
2. 使用这些键值对生成一个 [OAuth 1.0a HMAC-SHA1 签名](/zh/resources/fundamentals/authentication#creating-a-signature)
3. 使用上述值构建 [Authorization 头](/zh/resources/fundamentals/authentication#authorizing-a-request)
