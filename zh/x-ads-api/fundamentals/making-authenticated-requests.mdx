访问 X Ads API 端点时，你的应用程序必须通过 TLS 向 https://ads-api.x.com 安全地发送经身份验证的 Web 请求。

以下部分将概述如何发起已认证的 API 请求、如何设置 [Twurl](https://github.com/twitter/twurl#getting-started) 与 API 交互，以及如何扩展你的应用程序以支持 OAuth 1.0a，并向你的 Ads 账户发起请求。

<div id="requirements">
  ## 要求
</div>

在向 X Ads API 发起已认证请求之前，你需要：

* 一个[已获批准的开发者账号](/zh/resources/fundamentals/developer-portal)
* 一个已获 Ads API 访问批准的应用，参见[介绍](/zh/x-ads-api/introduction)
* 通过[应用管理 UI](/zh/resources/fundamentals/developer-apps) 获取的 API key 和 secret
* 拥有 X Ads 账号访问权限的用户的[访问令牌](/zh/resources/fundamentals/authentication#obtaining-access-tokens-using-3-legged-oauth-flow)

<div id="using-the-api">
  ## 使用 API
</div>

Advertising API 可通过 https://ads-api.x.com 访问。[标准 REST API](https://developer.x.com/en/docs/x-api/v1/tweets/post-and-engage/overview) 和 Advertising API 可以在同一个客户端应用中同时使用。Advertising API 强制使用 HTTPS，因此尝试通过 HTTP 访问任何端点都会返回错误信息。

Ads API 输出 JSON 格式。所有标识符都是字符串，并且所有字符串均为 UTF-8 编码。Advertising API 采用[版本控制](/zh/x-ads-api/fundamentals/versioning)，版本号作为任意资源 URL 的第一个路径元素指定。

`https://ads-api.x.com/<version>/accounts`

<div id="http-verbs-typical-response-codes">
  ## HTTP 动词和典型响应代码
</div>

Ads API 中使用了四种 HTTP 动词：

* **GET** 用于检索数据
* **POST** 用于创建新的数据，例如广告系列（campaigns）
* **PUT** 用于更新已有的数据，例如广告单元（line items）
* **DELETE** 用于删除数据。

尽管删除是永久性的，但在大多数基于 GET 的方法中，如果在请求资源时显式包含参数 `with_deleted=true`，仍然可以查看被删除的数据。否则，被删除的记录将返回 HTTP 404。

成功的请求在创建、删除或更新资源时，会返回一个 200 段的 HTTP 响应状态码，以及表示该对象的 JSON 响应。

使用 HTTP PUT 更新数据时，只有指定的字段会被更新。你可以通过将参数设置为空字符串来清空一个可选值。例如，下面这组参数将会清除任何已设置的 `end_time`：`&end_time=&paused=false`。

有关错误响应的更多详细信息，请参阅 [Error Codes &amp; Responses](/zh/x-ads-api/fundamentals/error-codes-and-responses)。

<div id="in-line-parameters">
  ## 内联参数
</div>

大多数资源 URL 都包含一个或多个内联参数。许多 URL 还会在查询字符串中显式声明参数，或者在 POST 或 PUT 请求中通过请求体传入参数。

内联参数在每个资源的 **Resource Path** 部分中以前置冒号（“:”）表示。例如，如果你正在操作的账户标识为 `"abc1"`，并且正在[检索与某个账户关联的推广活动](/zh/x-ads-api/campaign-management#campaigns)，你会通过使用 URL `https://ads-api.x.com/6/accounts/abc1/campaigns` 来访问该列表。通过在资源 URL（`https://ads-api.x.com/6/accounts/:account_id/campaigns`）中指定所述内联 `account_id` 参数，你已将请求限定为仅与该账户关联的对象。

<div id="using-access-tokens">
  ## 使用访问令牌
</div>

X Ads API 使用签名的 HTTPS 请求来验证应用的身份，并获取授予终端用户的权限（应用代表该用户发起 API 请求），这些权限由用户的访问令牌表示。所有对 Ads API 的 HTTP 调用都必须通过 HTTPS 协议发送，并在其中包含一个 Authorization 请求头（使用 OAuth 1.0a）。

你需要在应用中添加生成 OAuth 1.0a Authorization 请求头的功能，才能与 X Ads API 集成。不过，由于生成签名请求的过程较为复杂，我们强烈建议合作伙伴使用现有的库，这些库要么已经支持 X API，要么实现了 OAuth 1.0a 请求处理——这里提供了一些[推荐的 OAuth 库](/zh/resources/fundamentals/authentication#oauth-1-0a-2)和[身份验证代码示例](/zh/resources/fundamentals/authentication#oauth-1-0a-2)。

请注意，当合作伙伴在使用已知库时遇到身份验证错误，我们可以提供协助，但无法支持自定义的 OAuth 实现。

<div id="http-oauth">
  ## HTTP 与 OAuth
</div>

与 X REST API v1.1 相同，Advertising API 需要同时使用 [OAuth 1.0A](/zh/resources/fundamentals/authentication) 和 HTTPS。可以通过 [应用管理控制台](/zh/resources/fundamentals/developer-apps) 获取 API 密钥。还必须使用访问令牌来表示“当前用户”。当前用户是具有广告投放能力的 X 账号。

强烈建议合作伙伴使用 OAuth 库，而不是自行实现。使用已知库时，我们可以协助调试，但如果你自行实现 OAuth，我们将无法提供支持。请参阅可使用的 [库](/zh/resources/fundamentals/authentication#oauth-1-0a-2)。

该 API 对 HTTP 1.1 和 OAuth 的要求非常严格。请确保在构造 OAuth 签名基字符串之前，已经在 URL 和 POST 请求体中正确[对保留字符进行编码](https://tools.ietf.org/html/rfc3986#section-2.2)。特别是，Advertising API 在指定时间时使用“:”字符，在提供一组选项时使用“,”字符。这两个字符都属于以下保留字符集：

| 符号 | URL 编码 |
| :--- | :--- |
| !   | %21 |
| #   | %23 |
| $   | %24 |
| &amp;   | %26 |
| &#39;   | %27 |
| (   | %28 |
| )   | %29 |
| *   | %2A |
| +   | %2B |
| ,   | %2C |
| /   | %2F |
| :   | %3A |
| ;   | %3B |
| =   | %3D |
| ?   | %3F |
| @   | %40 |
| [   | %5B |
| ]   | %5D |

<div id="making-your-first-api-request-with-twurl">
  ## 使用 Twurl 发起你的第一个 API 请求
</div>

X 提供并维护了一个命令行工具 [Twurl](https://developer.x.com/en/docs/tutorials/using-twurl)，它支持使用 OAuth 1.0a 授权头，作为 [cURL](https://en.wikipedia.org/wiki/CURL) 的替代方案。Twurl 提供了一种简单方式，让你在将授权集成到应用之前，就能发起已授权的 API 请求并探索 Ads API。

在 [安装并授权 Twurl](https://github.com/twitter/twurl#getting-started) 之后，你可以快速生成访问令牌，并向 Ads API 发起已授权的请求。

```bash
twurl -H "ads-api.x.com" "/5/accounts/"
```

花点时间通过这个用于通过 API 创建广告系列的[分步](/zh/x-ads-api/campaign-management#creating-a-campaign-step-by-step)教程来熟悉 Twurl 和 API。

<div id="extending-your-application-to-make-authenticated-requests">
  ### 扩展你的应用以发起已认证请求
</div>

在熟悉了使用 Twurl 向 Ads API 发起请求之后，就可以开始在你的应用中添加对创建 OAuth 1.0a 认证请求头的支持。

[OAuth 1.0a](/zh/resources/fundamentals/authentication) 认证请求头包含用于验证应用和用户身份的信息，并能防止请求被篡改。你的应用需要为每个 API 请求创建一个新的 `Authorization` 请求头。许多编程语言都有开源库，可以用来创建此授权请求头，从而向 X 发起 API 请求。

下面是使用 C#、PHP、Ruby 和 Python 的一些示例——[代码示例](/zh/resources/fundamentals/authentication#oauth-1-0a-2)。

<div id="custom-implementation">
  ## 自定义实现
</div>

在某些场景下，你需要在没有开源库支持的情况下实现 OAuth 1.0a 认证。[授权请求](/zh/resources/fundamentals/authentication#authorizing-a-request) 一节详细说明了如何实现对创建 Authorization 头部的支持。我们强烈建议使用社区维护的库。

总体步骤概述：

1. 为头部收集 7 个以 oauth&#95; 开头的键/值对
2. 使用这些键/值对生成一个 [OAuth 1.0a HMAC-SHA1 签名](/zh/resources/fundamentals/authentication#creating-a-signature)
3. 使用上述值构建 [Authorization 头部](/zh/resources/fundamentals/authentication#authorizing-a-request)
