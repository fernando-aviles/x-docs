<div id="timezones-accounts-and-billing">
  ## 时区、账户和计费
</div>

Datetime 值始终以 UTC 时间返回（由 datetime 值末尾的 Z 表示）。在使用 POST 或 PUT 命令时，可以使用任何时区来指定 datetime，时区格式需符合 ISO 8601 标准。时间采用 [ISO-8601](http://en.wikipedia.org/wiki/ISO_8601) 的一个子集表示。更具体地说，我们的日期格式对应的 strptime 字符串是 `%Y-%m-%dT%l:%M:%S%z`。广告主账户的时区决定了官方计费数据锁定的实际时间点。

在账户级别查询 API（[GET accounts](/zh/x-ads-api/campaign-management#accounts)）时，你会获得类似如下的时区信息：

```json
    {
      "request": {
        "params": {
          "account_id": "18ce54d4x5t"
        }
      },
      "data": {
        "name": "API McTestface",
        "business_name": null,
        "timezone": "America/Los_Angeles",
        "timezone_switch_at": "2016-07-21T07:00:00Z",
        "id": "18ce54d4x5t",
        "created_at": "2016-07-21T22:42:09Z",
        "salt": "54cb7b5a34183f77d82dd6d0f4329691",
        "updated_at": "2017-09-09T06:42:14Z",
        "business_id": null,
        "approval_status": "ACCEPTED",
        "deleted": false
      }
    }
```

这包括两个时区值：`timezone`（概览请参见 [维基百科中的时区条目](https://en.wikipedia.org/wiki/Tz_database#Names_of_time_zones)）和 `timezone_switch_at`。请注意，`timezone_switch_at` 使用 UTC 时区（+00:00）表示，但它始终表示所给定时区中的本地午夜时间。

广告主的时区不支持通过 API 修改。此属性由广告主在 X 的客户经理在合同/计费层面进行设置。

在创建报表并查询我们的分析端点时，请留意 `timezone_switch_at` 的取值，因为在账户从 America/Los&#95;Angeles 时区切换到新的本地值的那一天，会出现一个时间间隔（数据空档）。

<div id="specifying-datetime-values-with-timezone">
  ### 使用时区指定日期时间值
</div>

日期时间值始终以 UTC 时间返回（由日期时间值末尾的 `Z` 表示）。在 POST 或 PUT 命令中，可以使用任意时区来指定日期时间，时区格式需符合 [ISO 8601 标准](http://en.wikipedia.org/wiki/ISO_8601)。例如，`2017-07-10T08:00:00-0800` 是一个可接受的输入值，并会自动转换为 UTC 值 `2017-07-10T16:00:00Z`。

在使用 `granularity` 为 `DAY` 或 `TOTAL` 的 analytics 端点时，`start_time` 值必须指定为账户持有人本地时区中目标日期的午夜时间。应使用的时区偏移量为当前日期的偏移量，而不是目标日期的偏移量。例如，对于位于 America/Los&#95;Angeles、处于太平洋夏令时（Pacific Daylight Time）的广告账户，UTC 偏移量为 -0700。因此，在 analytics 请求中，时间应指定为：`start_time=2017-05-21T07:00:00Z` 或 `start_time=2017-05-21T00:00:00-0700`。如果广告账户位于 Asia/Tokyo（此处偏移量始终为 +09:00），则应指定为：`start_time=2017-05-20T15:00:00Z` 或 `start_time=2017-05-21T00:00:00+0900`。

<div id="accepted-utc-offset-formats">
  ### 可接受的 UTC 偏移量格式
</div>

参见 [ISO 8601 时区标识符](http://en.wikipedia.org/wiki/ISO_8601#Time_zone_designators)。

支持以下格式：`Z`, `-HHMM`, `+HHMM`, `-HH:MM`, `+HH:MM`, `-HH`, `+HH`
