<div id="user-accounts-vs-ad-accounts">
  # 用户账户与广告账户
</div>

在使用 Ads API 时会涉及两种不同类型的账户：广告账户和 X 用户账户。在整个 Ads API 文档中，“account”（账户）一词通常指广告账户。

* 广告账户在 **business.x.com** 上注册，并在 API 中通过 `account_id` 标识。广告账户直接关联资金来源，并利用一个或多个 X 用户账户的内容作为“可推广用户”。每个广告账户都可以向一个或多个 X 用户账户授予权限。广告账户（或称“当前账户”）在几乎每个执行的 URL 中都以内联的 `:account_id` 参数形式出现。
* X 用户账户（例如 @AdsAPI）在 Ads API 中通过 `user_id` 标识。这些账户中的一个或多个可以与一个广告账户关联。向 API 发起请求的已认证 X 用户账户被称为“当前用户”。当前用户可访问的广告账户列表可通过 [GET accounts](/zh/x-ads-api/campaign-management#accounts) 获取。“可推广用户”是指可以由某个特定广告账户进行推广的 X 账号（handle）。有关更多详细信息，请参阅[获取广告账户访问权限](/zh/x-ads-api/introduction)。

<div id="methods-for-ad-account-access">
  ## 获取广告帐户访问权限的方法
</div>

你可以通过两种方式向广告主的帐户发起 Ads API 请求：

1. 代表某个广告主发起请求（**推荐**）
2. 使用你自己的帐户（该帐户已被授予访问某广告主帐户的权限）发起请求，例如，一个为多个帐户提供支持的[代理商](https://business.x.com/en/blog/agencies-manage-multiple-Twitter-Ads-accounts.html)。

本文档简要概述了这两种方式之间的差异，应与我们的其他资源配合使用，例如[多用户登录常见问题](https://business.x.com/en/help/troubleshooting/multi-user-login-faq.html)。 

如[授权请求](/zh/resources/fundamentals/authentication#authorizing-a-request#authorizing-a-request)中所述，对 Ads API 的所有请求都需要在 Authorization 头部中使用通过[3-legged](/zh/resources/fundamentals/authentication#obtaining-access-tokens-using-3-legged-oauth-flow)[OAuth](/zh/resources/fundamentals/authentication#obtaining-access-tokens-using-3-legged-oauth-flow) 流程获取的访问令牌，并采用 [OAuth 1.0a](/zh/resources/fundamentals/authentication) 协议。你的应用需要实现基于 Web 的 OAuth 流程来[获取访问令牌](/zh/resources/fundamentals/authentication#oauth-1-0a-2)。Ads API 开发者绝不应要求我们的 X 广告主分享其登录凭证。

默认情况下，每个 [X 开发者应用](/zh/resources/fundamentals/developer-apps)都包含一个静态的**访问令牌**，可用于为拥有该应用的帐户发起 Ads API 请求。对于无需 3-legged 或[基于 PIN 的 OAuth](/zh/resources/fundamentals/authentication#pin-based-authorization) 流程的单帐户用例，这些凭证非常适合。如果你不需要访问其他 X Ads 帐户，请使用这些[单用户](/zh/resources/fundamentals/authentication#oauth-1-0a-2)凭证，而不是下面的步骤。

<div id="levels-of-access">
  ## 访问权限级别
</div>

<div id="app-level-permissions">
  ### App 级别权限
</div>

每个用户都会在[申请 Ads API](/zh/x-ads-api/getting-started/step-by-step-guide)时获得相应级别的访问权限：

* **仅转化（Conversion Only）**：用户具备[读写](/zh/resources/fundamentals/developer-apps)访问权限，可访问 [Mobile](/zh/x-ads-api/measurement/mobile-conversions) 和 [Web Conversion](/zh/x-ads-api/measurement/web-conversions) 端点。
* **标准访问（Standard Access）**：用户具备[读写](/zh/resources/fundamentals/developer-apps)访问权限，可访问 [Analytics](/zh/x-ads-api/analytics)、[Campaign Management](https://developer.x.com/en/docs/twitter-ads-api/campaign-management/overview)、[Creatives](https://developer.x.com/en/docs/twitter-ads-api/creatives/overview)、[Custom Audiences](https://developer.x.com/en/docs/twitter-ads-api/audiences/overview) 和 [Conversion](/zh/x-ads-api/measurement/web-conversions) 端点。

**注意：** 在 2023 年 7 月之前申请访问权限的 Ads API 开发者，可能拥有不同级别的访问权限和权限配置，并且可能被限制为最多五个 OAuth 令牌。请参阅我们的[提升访问级别](/zh/x-ads-api/getting-started/increasing-access)指南，以获得更多端点的访问权限，或为现有应用取消令牌数量限制。

<div id="ad-account-level-permissions">
  ### 广告账户级别权限
</div>

每个有权访问某个 Ads Account 的用户都会被分配一种特定的账户级别权限：**Account administrator**、**Ad manager**、**Campaign analyst**、**Organic analyst** 和 **Creative Manager**。请参阅 **business.x.com** 上关于账户级别权限的最新文档。应用应通过 [Authenticated User Access](/zh/x-ads-api/campaign-management#authenticated-user-access) API endpoint 获取当前已认证用户的权限，以确定他们可以访问哪些 API endpoint 和 Ads 功能。

**注意：** 任何用于 [Conversion API](/zh/x-ads-api/measurement/web-conversions) 的用户 access token，必须属于具备 **Account administrator** 或 **Ad manager** 账户级别权限的用户。                                                                                                                                              

<div id="methods-of-obtaining-access-tokens">
  ## 获取访问令牌的方式
</div>

<div id="1-obtain-an-advertisers-user-access-token">
  ### 1. 获取广告主（用户）访问令牌
</div>

有两种方法可以获取广告主的 **access token（访问令牌）**。最常见的方法是在你的 Web 界面中直接发起 [三方 OAuth 授权流程（3-legged OAuth flow）](/zh/resources/fundamentals/authentication#obtaining-access-tokens-using-3-legged-oauth-flow)。对于没有向广告主提供可公开访问界面的应用，可以实现 [基于 PIN 的](/zh/resources/fundamentals/authentication#pin-based-authorization) OAuth 授权流程。用户完成三方流程后，你的应用就会拥有凭证，可以通过 API 为他们的 Ads 账户发起请求。

通过 OAuth 流程获取用户凭证是我们 **强烈推荐** 的、适用于大多数 Ads API 开发者用于访问广告主账户的方法。它允许你代表某个用户调用 API，并以该用户的身份执行操作。这些令牌不会过期，但用户可以随时撤销它们。

<div id="2-obtain-your-developer-access-token">
  ### 2. 获取你的（开发者）访问令牌
</div>

此选项要求广告主通过 business.x.com 上的 X UI，[授予你的 @username](https://business.x.com/en/help/troubleshooting/multi-user-login-faq.html)（或多个 @username）访问其 X Ads 账户的权限。通过你账户的三方（3-legged）OAuth 授权流程获得的**访问令牌**将能够访问该广告主的 X Ads 账户。

这样，你可以使用自己 @username 的 OAuth 令牌来调用 API，而不是使用广告主的 OAuth 令牌。此选项的关键区别在于，仅当你的 @username 被授予帖子委托/创作权限（Post delegation/composer permission）时，你才可以创建仅推广帖子（Promoted-Only Posts）。

若要代表账户上的 `FULL` 可推广用户创建仅推广帖子（Promoted-Only Posts），你还必须在此流程中被授予创建帖子（Posts）的权限。这样即可通过 [GET accounts/:account&#95;id/authenticated&#95;user&#95;access](/zh/x-ads-api/campaign-management#accounts) 端点上的 `TWEET_COMPOSER` 权限获得访问能力。

  ## 这些方法之间的区别
</div>

|     | 广告主（用户）OAuth 令牌 | （开发者）OAuth 令牌  <br /> (@username added to separate account) |

| 代表用户创建帖子 | ✔   | ✔*  |
