<div id="user-accounts-vs-ad-accounts">
  # 用户账号与广告账号
</div>

在使用 Ads API 时会涉及两种不同类型的账号：广告账号和 X 用户账号。在整套 Ads API 文档中，“account” 一词通常指的是广告账号。

* 广告账号在 **business.x.com** 上注册，并在 API 中通过 `account_id` 标识。广告账号直接关联资金来源，并使用一个或多个 X 用户账号的内容作为“可推广用户”（promotable users）。每个广告账号都可以向一个或多个 X 用户账号授予权限。广告账号（或称为“当前账号”）几乎在每个执行的 URL 中都会以内联 `:account_id` 参数的形式出现。
* X 用户账号（例如 @AdsAPI）在 Ads API 中通过 `user_id` 标识。一个或多个此类账号可以与一个广告账号关联。通过 API 发起请求的已认证 X 用户账号被称为“当前用户”。当前用户可访问的广告账号列表可以通过 [GET accounts](/zh/x-ads-api/campaign-management#accounts) 获取。“可推广用户”（promotable users）是指可由特定广告账号进行推广的 X 用户名（X handle）。有关这方面的更多详情，请参阅 [Obtaining Ads Account Access](/zh/x-ads-api/introduction)。

<div id="methods-for-ad-account-access">
  ## 获取广告账户访问权限的方法
</div>

你可以通过两种方式为某个广告主的账户发起 Ads API 请求：

1. 代表某个广告主发起请求（**推荐**）
2. 使用你自己的账户（该账户已被授予访问某个广告主账户的权限）发起请求，例如，一个为多个账户提供支持的[代理商](https://business.x.com/en/blog/agencies-manage-multiple-Twitter-Ads-accounts.html)。

本文档简要概述了这两种方式之间的差异，并应配合同我们的其他资源一起使用，例如[多用户登录常见问题](https://business.x.com/en/help/troubleshooting/multi-user-login-faq.html)。

如 [Authorizing a request](/zh/resources/fundamentals/authentication#authorizing-a-request#authorizing-a-request) 中所述，对 Ads API 的所有请求都需要在 Authorization 请求头中使用 [OAuth 1.0a](/zh/resources/fundamentals/authentication)，并使用通过[三方](/zh/resources/fundamentals/authentication#obtaining-access-tokens-using-3-legged-oauth-flow)[OAuth](/zh/resources/fundamentals/authentication#obtaining-access-tokens-using-3-legged-oauth-flow) 流程获取的访问令牌。你的应用需要实现基于 Web 的 OAuth 流程来[获取访问令牌](/zh/resources/fundamentals/authentication#oauth-1-0a-2)。Ads API 开发者绝不应要求我们的 X 广告主分享他们的登录凭证。

默认情况下，每个 [X developer application](/zh/resources/fundamentals/developer-apps) 都包含一个静态的 **access token**，可用于为拥有该应用的账户发起 Ads API 请求。对于不需要使用三方或[基于 PIN 的 OAuth](/zh/resources/fundamentals/authentication#pin-based-authorization) 流程的单账户用例，这些凭证是理想选择。如果你不需要访问其他 X Ads Account，请使用这些[单用户](/zh/resources/fundamentals/authentication#oauth-1-0a-2)凭证，而不是以下步骤。

<div id="levels-of-access">
  ## 访问权限级别
</div>

<div id="app-level-permissions">
  ### 应用级权限
</div>

每个用户都会根据在[申请 Ads API](/zh/x-ads-api/getting-started/step-by-step-guide)时提出的需求，被授予相应的访问级别：

* **仅转化（Conversion Only）**：用户可以以[读写](/zh/resources/fundamentals/developer-apps)访问权限调用 [Mobile](/zh/x-ads-api/measurement/mobile-conversions) 和 [Web Conversion](/zh/x-ads-api/measurement/web-conversions) 端点。
* **标准访问（Standard Access）**：用户可以以[读写](/zh/resources/fundamentals/developer-apps)访问权限调用 [Analytics](/zh/x-ads-api/analytics)、[Campaign Management](https://developer.x.com/en/docs/twitter-ads-api/campaign-management/overview)、[Creatives](https://developer.x.com/en/docs/twitter-ads-api/creatives/overview)、[Custom Audiences](https://developer.x.com/en/docs/twitter-ads-api/audiences/overview) 和 [Conversion](/zh/x-ads-api/measurement/web-conversions) 端点。

**注意：** 2023 年 7 月之前申请访问的 Ads API 开发者，其访问级别和权限可能有所不同，并且可能被限制为最多五个 OAuth 令牌。请参阅我们的[提升访问级别](/zh/x-ads-api/getting-started/increasing-access)指南，以获取更多端点的访问权限，或为现有应用解除令牌数量限制。

<div id="ad-account-level-permissions">
  ### 广告账户级权限
</div>

每个有权访问某个广告账户的用户都会拥有一个特定的账户级权限：**Account administrator**、**Ad manager**、**Campaign analyst**、**Organic analyst** 和 **Creative Manager**。有关账户级权限的最新文档，请参阅 **business.x.com**。应用应通过 [Authenticated User Access](/zh/x-ads-api/campaign-management#authenticated-user-access) API 端点获取当前已认证用户的权限，以确定他们可以访问哪些 API 端点和 Ads 功能。

**注意：** 任何用于 [Conversion API](/zh/x-ads-api/measurement/web-conversions) 的用户令牌都必须属于具有 **Account administrator** 或 **Ad manager** 账户级权限的用户。                                                                                                                                              

<div id="methods-of-obtaining-access-tokens">
  ## 获取访问令牌的方式
</div>

<div id="1-obtain-an-advertisers-user-access-token">
  ### 1. 获取广告主（用户）的访问令牌
</div>

获取广告主**访问令牌**有两种方法。最常见的方法是通过你的 Web 界面直接发起 [三方（3-legged）OAuth 授权流程](/zh/resources/fundamentals/authentication#obtaining-access-tokens-using-3-legged-oauth-flow)。对于没有向广告主公开界面的应用程序，可以实现 [基于 PIN 的](/zh/resources/fundamentals/authentication#pin-based-authorization) OAuth 授权流程。在用户完成三方流程之后，你的应用将拥有代表其 Ads 账户通过 API 发起请求的凭证。

通过 OAuth 流程获取用户凭证是我们向大多数 Ads API 开发者**强烈推荐**的获取广告主账户访问权限的方法。它允许你代表某个用户调用 API，并以该用户身份执行操作。这些令牌不会过期，但可以被用户随时撤销。

<div id="2-obtain-your-developer-access-token">
  ### 2. 获取你的（开发者）访问令牌
</div>

此选项要求广告主通过 business.x.com 上的 X 界面（X UI）[授予你的 @username](https://business.x.com/en/help/troubleshooting/multi-user-login-faq.html)（或多个 @username）访问其 X Ads 账户的权限。通过你账户的三方（3-legged）OAuth 授权流程获得的**访问令牌**将能够访问该广告主的 X Ads 账户。

这样你就可以使用自己 @username 对应的 OAuth 令牌来调用 API，而不是使用广告主的 OAuth 令牌。此选项的关键区别在于，只有在已将帖子委派/创作权限授予你的 @username 时，你才能创建仅推广帖子（Promoted-Only Posts）。

若要获得代表该账户中 `FULL` 可推广用户创建仅推广帖子的访问权限，你还必须在此流程中被授予创建帖子的权限。这样就可以通过 [GET accounts/:account&#95;id/authenticated&#95;user&#95;access](/zh/x-ads-api/campaign-management#accounts) 端点上的 `TWEET_COMPOSER` 权限进行访问。

<div id="differences-between-these-methods">
  ## 这些方法之间的区别
</div>

|     |     |     |
| :--- | :--- | :--- |
|     | 广告主（用户）OAuth 令牌 | （开发者）OAuth 令牌  <br />（@username 添加到单独账户） |
| 访问广告账户 | ✔   | ✔   |
| 代表用户创建帖子 | ✔   | ✔*  |
| 管理广告活动 | ✔   | ✔   |
| 访问分析数据 | ✔   | ✔   |
| 代表用户创建卡片 | ✔   | ✔   |
| 开发者通过 X Ads UI  <br />进行访问 |     | ✔   |
| [速率限制](/zh/x-api/enterprise-gnip-2.0/fundamentals/rate-limits) | 按广告主单独计算 | 按广告主账户单独计算 |

</Note>

<div id="advertisers-access-token-via-oauth-3-legged-web-flow">
  ### 通过 OAuth 三方 Web 流程获取广告主的访问令牌
</div>

标准流程基于 Web，并使用 [三方授权](/zh/resources/fundamentals/authentication#obtaining-access-tokens-using-3-legged-oauth-flow) OAuth 流程。这里展示的截图来自一个示例应用，你可以在此查看其源码：[https://github.com/xdevplatform/twauth-web](https://github.com/xdevplatform/twauth-web)。

在你的应用的某个环节，你需要重定向到 X，让用户为你的应用授权。

  <img src="https://cdn.cms-twdigitalassets.com/content/dam/developer-twitter/images/twauth-web-2.png" alt="image0" />
</Frame>

当你携带 request token 重定向到 X 时，系统会提示用户为你的应用授权。

在用户为你的应用授权之后，会被重定向到你在生成 request token 时提供的回调 URL。你将使用它为该用户获取永久访问令牌，并在本地存储。
