要在 Ads API 中取得良好效果，深入理解 X Ads 中各个实体之间的关系非常重要。本教程将介绍 X Ads 对象层级的基础知识。

![X Ads API 层级结构](/images/adsapi-heirarchy.png.twimg.1920.png)

<div id="ad-group-line-items">
  ## 广告组（line items）
</div>

广告组（在 Ads API 中称为 [line items](https://developer.x.com/content/developer-twitter/en/docs/tutorials/ads-api-hierarchy-terminology#line-items)）隶属于广告活动，用于针对一组 X 用户进行定向和竞价。广告主通过将帖子或媒体（例如作为 In-stream 广告推广的视频）与某个 line item 关联来进行推广。另请参阅“广告组”。

<div id="account-media">
  ## 账户媒体
</div>

上传到广告账户并作为[账户媒体](/zh/x-ads-api/creatives#account-media)保存的一组创意素材，其中可以包括推广视频的[前贴片资源](/zh/x-ads-api/campaign-management#video-views-preroll-objective)（也称为流内广告），以及可在 [X Audience Platform](https://developer.x.com/content/developer-twitter/en/docs/ads/measurement/overview/twitter-audience-platform) 上进行推广的图片。

<div id="ads-accounts">
  ## Ads 账户
</div>

在 X Ads 层级结构的最顶层是 Ads 账户。一个 Ads 账户可以由多名 X 用户管理。@Furni（我们的演示家具商店）就是一个管理 Ads 账户的用户示例。我们通过 account&#95;id 来标识 Ads 账户，它是一个 [base36](https://en.wikipedia.org/wiki/Base36) 字母数字字符串。

在每个账户之下，我们会存储若干实体类型，这些实体可以在不同广告系列之间复用，例如用于定向的 Tailored Audiences、账户媒体（视频或图片），以及 Cards（可以添加到帖子中的扩展创意素材）。

<div id="amplify-video">
  ## Amplify Video
</div>

在上传视频素材时，上传方可以为视频定义一个类别（例如，推文视频、推文 GIF、推文图片和 Amplify Video）。在尝试上传要作为流内广告进行投放的视频时，Amplify Video 类别为必需。这些视频需要特殊处理以确保可以投放，因此媒体类别必须设置为 Amplify Video。

<div id="analytics">
  ## 分析
</div>

分析指标可帮助合作伙伴和广告主了解他们在 X 上推广内容的表现。这包括展示次数、点击次数、视频观看次数以及花费等信息。此外，合作伙伴和广告主还可以获取其触达受众中各个细分群体的详细指标。

Ads API 支持两种获取广告系列详细表现指标的方式：同步和异步。

通过[同步分析](/zh/x-ads-api/analytics#synchronous-analytics)请求，所请求的指标会在响应中返回。同步端点支持较短的时间范围，非常适合查询广告系列的实时表现。

通过[异步分析](/zh/x-ads-api/analytics#asynchronous-analytics)端点，请求的指标会在关联的“作业”处理完成后，以可下载的结果文件形式提供。异步端点支持在更长时间范围内请求指标，支持返回细分数据，并适用于获取规模更大的数据——非常适合生成报表或进行历史数据回补。

<div id="campaigns">
  ## Campaigns
</div>

广告主投放的每一个广告活动（Campaign）都必须基于一个已有的资金工具（funding instrument）创建。通过 Campaign，你可以定义广告活动的名称、投放时间安排和预算等内容。继续以 Furni 为例，我们可以创建一个名为 “Furni home decor” 的 Campaign。

需要注意的是，一个广告账户（ads account）最多只能拥有 200 个处于活动状态的 Campaign；该上限可以由广告主的客户经理提高。Campaign 在到达结束时间或预算用尽之前都被视为活动状态。已暂停的 Campaign 在计算 Campaign 数量时仍然计入活动 Campaign 上限。

<div id="cards">
  ## Cards
</div>

卡片（Cards）提供了一种在视觉上扩展推文的方式，可以包含图片、视频或 UI 元素。Ads API 支持多种可用于推文的卡片类型，这些推文随后可以在广告活动中推广。

<div id="creatives">
  ## 创意素材
</div>

广告主可以在包含创意素材（例如图片、GIF 和视频）的广告活动中推广推文。这些创意素材可以与 X 卡片关联，用于在推文中附加丰富的照片、视频和其他媒体体验。创意素材也可以直接附加到推文中。例如，你可以包含文本和一段视频（或最多 3 张图片），并创建一条推广推文。

每个广告单元若要投放，必须至少关联一个创意素材。可用的创意素材选项包括：用于获取新粉丝的 Promoted Accounts、适用于 TX Audience Platform 上各类广告单元的图片或视频等 Media Creatives，以及 Promoted Posts。

<div id="funding-instruments">
  ## 资金工具（Funding Instruments）
</div>

在广告账户下还有资金工具（Funding Instruments），即广告主为使用 X Ads 而配置的不同资金来源。这些资金来源可以包括与 X 签署的投放订单（insertion orders），以及绑定到账户的信用卡等。

<div id="line-items">
  ## 广告组（Line Items）
</div>

在一个广告系列中，你可以有一个或多个广告组，在 Ads API 中也称为 line items。可以将 line item 理解为广告系列中的不同细分单元，每个单元都有自己的一套定向设置和创意素材。包含多个 line item 的广告系列通常被称为“广告组型广告系列”（ad group campaigns）。

在单个广告系列中使用多个 line item 的优势之一，是你可以创建更加多样化的定向与创意组合。

在我们的 “Furni home decor” 广告系列下，我们可能希望创建两个 line item：一个可以是 “Home buyers in San Francisco”，另一个可以是 “Home buyers in London”。

每个广告系列最多允许 100 个 line item，并且一个广告账户在所有广告系列中合计最多可以拥有 4,000 个处于运行状态的 line item。

<div id="mobile-app-promotion-map">
  ## 移动应用推广（MAP）
</div>

移动应用推广（Mobile App Promotion，简称 MAP）是一套产品组合，使广告主能够通过 X 推广移动应用，包括应用安装、转化和再互动等目标。

<div id="mobile-app-conversion-tracking-mact">
  ## 移动应用转化跟踪（MACT）
</div>

<div id="media-library">
  ## 媒体库
</div>

Media Library 端点提供了用于管理 X Ads 账户中图片、GIF 和视频的功能。媒体库中的媒体素材可用于帖子和卡片创建，并且可以在多个创意中重复使用，从而无需多次上传相同的素材。

<div id="promoted-accounts">
  ## 推广帐号
</div>

推广帐号（粉丝广告系列）是“可能感兴趣的人”功能的一部分，它会向用户推荐目前尚未关注但可能感兴趣的帐号。推广帐号有助于向用户介绍更多类型丰富、他们可能会喜欢的帐号。

推广帐号使广告主可以推广自己的帐号，并在 X 上扩大受众。粉丝广告系列会在 X 平台上的多个位置展示——包括首页时间线、“可能感兴趣的人”和搜索结果——这些推荐会带有“推广”标签，以便与其他推荐帐号区分开来。

<div id="promotable-users">
  ## 可推广用户
</div>

每个 X Ads 广告账户都可以拥有一个或多个可推广用户，即我们可以通过该广告账户进行投放推广的用户。Furni 的 @Furni 账号就是 Furni 广告账户下 FULL 级别可推广用户的一个示例，这意味着我们可以为 @Furni 及其推文投放所有类型的广告活动。一个广告账户中只能有一个 FULL 级别的可推广用户。

请注意，一个广告账户下还可以配置其他类型的可推广用户。例如，如果我们想推广 @Jack 发布的关于 Furni 产品的推文，他将在该账户下成为仅限转推的可推广用户，这在系统中以 RETWEETS&#95;ONLY 标识。广告主应联系各自的 X 客户经理，了解将仅转推用户添加到其广告账户的相关信息。

<div id="promoted-video">
  ## 推广视频
</div>

推广视频是指包含在推广推文中的、由广告主付费投放的视频。它们会出现在主页时间线、X 上搜索结果的顶部，以及平台内的其他位置，并且会被清晰地标记为“推广”。

<div id="scheduled-tweets">
  ## 定时推文
</div>

定时推文使广告主或用户可以创建一条推文，并安排其在未来的某个时间发布。除了能够创建和管理这些推文之外，API 还允许将这些推文关联到某个广告单元（line item），以便在推文发布后进行推广。这样一来，广告主可以预先创建原生推文，并在任何关键活动开始之前提前规划其广告创意。例如，将某条推文创意预先排期为在新产品发布公告的那一刻立即上线。

<div id="segmentation">
  ## 细分
</div>

细分使合作伙伴和广告主能够按特定定向值（例如年龄、设备或语言）拆分并获取对应的指标，该功能仅可通过我们的异步分析端点使用。要请求细分后的指标，请使用 `segmentation_type` 请求参数。有关细分选项的更多信息，请参阅 Metrics and Segmentation。

<div id="tailored-audience-list">
  ## 定向受众 - 列表
</div>

基于列表的定向受众是三种“定向受众”类型之一，通过上传包含你自有用户和客户数据的文件创建。你的列表会与 X 上的用户进行匹配，从而使你可以在广告系列中直接定向触达这些用户。请务必查看这些限制条件。

<div id="tailored-audience-web">
  ## 定向受众 - 网站
</div>

网站定向受众是三种定向受众类型之一，由访问过你网站的 X 用户组成。要使用网站定向受众，你必须在自己的网站上安装我们的 X 像素，或使用我们支持的标签管理器合作伙伴之一。请查看相关限制条件。

<div id="targeting-criteria">
  ## 定向条件
</div>

如前所述，定向条件是与广告子项目（line item）关联的。你可以使用多种不同的定向方式，从位置、关键词、性别到更细粒度的属性，例如用户行为和兴趣。对于“Home Buyers in San Francisco”这个广告子项目，我们可能会同时将“home buying”行为和“San Francisco”位置作为定向条件。

有关不同定向类型的更多信息，请访问我们开发者网站上的 Targeting Overview 页面。

<div id="twitter-object-nest-ton">
  ## Twitter Object Nest (TON)
</div>

Twitter Object Nest (TON) 用于存储通过 Media Upload 端点上传的媒体和各种资源，以用作 Creatives。
