<div id="overview">
  ## 概述
</div>

每个月，我们都会对 X Ads API 进行变更并推出若干新功能。这些变更几乎始终保持向后兼容，但每年通常仍会有少量破坏性变更。我们从开发者那里收到反馈，认为 Ads API 快速迭代在实现新功能、处理弃用以及测试变更时，会给其开发周期带来挑战。为了提升在使用我们 Ads 平台时的开发者体验，我们引入了端点版本化这一概念。

下面是我们将会提到的一些概念的定义：

**版本（Version）**：指的是在任意 Ads API 请求的 URL 路径中出现的版本号，例如：GET /{version_number}/accounts。这种版本控制方式称为 URI 版本化。

**破坏性变更（Breaking Changes）**：破坏性变更是指任何需要开发者投入资源才能维持现有功能的变更。这包括用于调查需要进行哪些变更、确定将被弃用的功能/端点，以及最终落实现有变更所需的资源。破坏性变更的示例包括：

* 从 API 请求/响应中移除某个参数

* 修改任意参数或端点的名称

* 更改值的表示方式（preview&#95;url → card&#95;uri）

* 更改端点行为（例如，将统计从同步改为异步）

* 添加/更改可选或必需参数（例如，将名称设为必需字段）

**弃用（Deprecation）**：被弃用的版本或产品将不再受支持，建议开发者停止使用这些 API。

**下线（Sunset）**：一旦某个产品或 API 被下线，与之对应的一组端点将无法再通过 API 访问。

<div id="versioning-strategy">
  ## 版本管理策略
</div>

该策略的主要原则如下：

1. 所有不兼容变更都会被打包到一个新版本中

2. 每当新版本发布时，现有版本的弃用期为 6 个月

3. 在任意时间点，API 将同时允许来自两个版本的请求，但其中较旧的那个版本将不再受支持

4. 为了加快新产品的采用，这些产品将以持续滚动发布的方式推出（不受版本节奏限制）

5. 所有 API 响应都将包含一个 `x-current-api-version`，其值为当前 API 版本；在调用任何已弃用的 API 端点时，还会额外包含一个 `x-api-warn` 头

如果出现任何需要进行 API 不兼容变更的基础产品需求变更（例如弃用多个年龄区间定向），我们将提前 90 天发出通知来宣布此不兼容变更，并且在通知发布至少 90 天之后，才会部署该不兼容变更

</div>

<div id="v5">
  ### v5
</div>

今天（2019 年 2 月 28 日），X 推出了 Ads API v5，本次更新重点在于提升扩展性和效率。

此版本包含一个新端点，用于确定在给定时间范围内处于活跃状态的实体，为 Media Creatives（即 X Audience Platform 上的流内视频和图片）提供统计数据，支持通过卡片 URI 获取&#95;多个&#95;卡片，并在检索定向条件和其他实体方面提供了更高的灵活性。此外，我们修复了一些问题，并更新了参数名称和响应属性。最后，非媒体应用卡片以及 POST `accounts/:account_id/account_media` 端点已被弃用。

与之前的版本一样，将有 6 个月的过渡期用于迁移到 v5。自 **2019-08-28** 起，Ads API 的第 4 版将不再可用。我们鼓励所有合作伙伴尽快迁移到最新版本的 API，以避免任何服务中断。*Ads API 的第 3 版已结束生命周期，现已不再提供使用。*

<div id="new">
  #### 新增
</div>

**确定哪些实体处于活跃状态**

[Active Entities](/zh/x-ads-api/analytics#active-entities-2) 端点用于指示广告实体的分析指标是否发生了变化。该端点设计为与分析端点配合使用，Active Entities 通过指定实体类型和日期范围（最长 90 天）来工作，并返回一个实体 ID 数组，你的平台应为这些实体请求分析数据。未在返回结果中的 ID 不应在后续分析请求中查询。

此端点支持以下实体类型：`CAMPAIGN`、`FUNDING_INSTRUMENT`、`LINE_ITEM`、`MEDIA_CREATIVE` 和 `PROMOTED_TWEET`。

**`MEDIA_CREATIVE` 统计数据**

Ads API 的分析端点现在为 Media Creative 实体提供指标。Media Creative 是在 X Audience Platform 上推广贴片广告或图片的方式。X Ads UI 会在“In-stream videos”和“Display creatives”标签页下显示 Media Creative 指标。[同步](/zh/x-ads-api/analytics#get-stats-accounts-account-id) 和 [异步](/zh/x-ads-api/analytics#asynchronous-analytics) 分析端点现在都支持 `MEDIA_CREATIVE` 实体枚举。

**获取多个 card**

在用于按 card URI 值检索单个 card 的端点的 [v3 版本发布](https://devcommunity.x.com/t/ads-api-version-3/100732) 基础上进行了改进，现在可以使用 [GET accounts/:account&#95;id/cards/all](/zh/x-ads-api/creatives#cards-fetch) 端点获取 *多个* card。现在，你无需为每个 card 发起一次请求，而是可以在单个请求中最多检索 200 个 card。

需要注意两点：

1. URL 路径现为 `accounts/:account_id/cards/all`。（之前的路径已不再可用。）这是为了与[按 ID 检索 card 的端点](/zh/x-ads-api/creatives#cards-fetch)保持一致。
2. 必需的请求参数现在命名为 card&#95;uris（复数）。

**在检索方面的灵活性**

[GET accounts/:account&#95;id/targeting&#95;criteria](/zh/x-ads-api/campaign-management#get-accounts-account-id-targeting-criteria) 端点现在支持多个 line item 的 ID。line&#95;item&#95;ids 参数最多可接收 200 个 ID，是必需参数。此前只接受单个 line item，这会使同步变得困难。通过这一改动，现在可以在更短时间内检索更多定向信息。

以下端点现在也支持多个 line item ID，不过对这些端点来说，line&#95;item&#95;ids 参数是可选的。

* [GET accounts/:account&#95;id/line&#95;item&#95;apps](https://developer.x.com/en/docs/x-ads-api/campaign-management/api-reference/line-item-apps#get-accounts-account-id-line-item-apps)
* [GET accounts/:account&#95;id/media&#95;creatives](/zh/x-ads-api/campaign-management#get-accounts-account-id-media-creatives)
* [GET accounts/:account&#95;id/promoted&#95;accounts](/zh/x-ads-api/campaign-management#get-accounts-account-id-promoted-accounts)
* [GET accounts/:account&#95;id/preroll&#95;call&#95;to&#95;actions](/zh/x-ads-api/creatives#preroll-call-to-actions)

<div id="changed">
  #### 已更改
</div>

**检索草稿广告活动和广告项目**

检索草稿广告活动和广告项目的方式已更新。现在，当将 with&#95;draft(boolean) 参数设置为 true 时，会同时返回草稿和非草稿实体。此行为与检索已删除实体的方式保持一致（即使用 with&#95;deleted）。此前，要同时获取草稿和非草稿实体至少需要两次请求。现在，只需一次 API 调用即可完成。

| **v4** | **v5** |
| :--- | :--- | :--- |
| `draft_only` | `with_draft` |     |

**Network activation duration 定向**

Ads API 已解决一个显示问题：在添加 Network Activation Duration 定向后，响应中的定向类型包含 `_IN_SEC` 后缀。由于 Network Activation Duration 始终以月为单位表示，引用秒数会造成混淆。此修复确保表示方式一致并减少混淆。

| **v4** | **v5** |
| :--- | :--- | :--- |
| `NETWORK_ACTIVATION_DURATION_IN_SEC` | `NETWORK_ACTIVATION_DURATION` |     |

**总数和游标**

在 v5 中，with&#95;total&#95;count 和 cursor 是互斥的参数。在请求中同时指定这两个参数将返回 EXCLUSIVE&#95;PARAMETERS 错误代码。在 v5 之前，如果指定了 cursor，则会忽略 with&#95;total&#95;count。此更改明确了它们之间的关系。

<div id="removed">
  #### 已移除
</div>

有三个字段将从 Ads API 响应中移除：preview&#95;url、account&#95;id 和 parent&#95;ids。为这三项进行的工程改动工作量很小。

* 在 v4 中，我们已宣布 cards 的 preview&#95;url 响应参数始终为 null。本次迁移的最后一步是从所有 cards 响应中移除 preview&#95;url。
* 对于以下资源，将移除 account&#95;id 响应属性，因为广告账户 ID 已经同时存在于 URL 和 request.params 中。（在此列表中有意不包含资金工具，因为在可能的情况下，父 ID 应该出现在响应对象中，而账户 ID 是资金工具的父实体。）
  * 账户媒体（Account media）
  * 应用事件提供方（App event providers）
  * 应用事件标签（App event tags）
  * 广告系列（Campaigns）
  * Cards
  * Line items
  * 可推广用户（Promotable users）
  * 定向条件（Targeting criteria）
* 对于 [GET accounts/:account&#95;id/targeting&#95;criteria](/zh/x-ads-api/campaign-management#get-accounts-account-id-targeting-criteria) 请求，我们将不再返回 parent&#95;ids 字段，因为它始终是空数组。

**非媒体应用卡片**

在 v5 中，不再支持非媒体应用卡片。[此前](https://devcommunity.x.com/t/deprecation-announcement-app-download-cards/87807)，已移除创建或编辑非媒体应用卡片的能力。现在，该资源剩余的端点也将被弃用。

* 注意：这 **不** 影响图片和视频应用下载卡片。

**账户媒体创建**

在 v5 中，不再提供 POST accounts/:account&#95;id/account&#95;media 端点。该资源的其他端点 *不* 受影响。做出这一变更的原因是：在向 [Media Library](/zh/x-ads-api/creatives#media-library) 添加媒体时，在某些情况下，这些素材会**自动**作为 Account Media 实体添加，如果尝试将已存在的素材再次添加到 Account Media 资源，就会导致错误。这会在以下情况发生：

* 添加到 Media Library 的 `AMPLIFY_VIDEO` 素材会自动作为具有 `PREROLL` 创意类型的 Account Media 素材添加。
* 具有特定尺寸的图片添加到 Media Library 时会自动作为 Account Media 素材添加。创意类型（例如 `INTERSTITIAL`）取决于图片尺寸。（关于尺寸，请参见我们的 [Enumerations](/zh/x-ads-api/introduction) 页面。）

<div id="v4">
  ### v4
</div>

Ads API 第 4 版将于今天（2018 年 8 月 28 日）正式发布。

本次发布对我们的 [Audiences](/zh/x-ads-api/audiences) 产品进行了改进，包括一个由更强大的受众处理后端驱动的新 API 接口。第 4 版还包含一组用于管理用户、账户和税务设置的端点。此外，accounts/:account&#95;id/videos 端点将被弃用。本次发布还包括一些参数和响应名称的小幅变更。

与第 3 版一样，我们提供 6 个月的过渡期。自 **2019-02-28** 起，第 3 版 Ads API 将不再可用。我们鼓励所有合作伙伴尽快迁移到最新版本的 API，以避免任何服务中断。请参阅我们的 [Versions](/zh/x-ads-api/introduction) 页面了解版本策略的详细信息。

<div id="new">
  #### 新增
</div>

***Audience API***

全新的 Audiences API 构建在我们新的受众处理后端之上，能够提供更高的健壮性和可靠性。这个新端点允许合作伙伴为同一位用户提供多种用户标识符类型，这意味着我们可以利用更多信号进行匹配。新 Audience 端点的参考文档可在[此处](/zh/x-ads-api/audiences)找到。我们计划在今年剩余时间内持续发布该产品的更新和改进。

以下端点由于功能冗余，在 v4 中将不再可用（它们在 v3 中仍可使用，并会在 v3 不再可用时完全**停用**）：

* TON Upload:
  * GET accounts/:account&#95;id/tailored&#95;audience&#95;changes
  * GET accounts/:account&#95;id/tailored&#95;audience&#95;changes/:tailored&#95;audience&#95;change&#95;id
  * POST accounts/:account&#95;id/tailored&#95;audience&#95;changes
  * PUT accounts/:accounti&#95;d/tailored&#95;audiences/global&#95;opt&#95;out
* Real Time Audiences:
  * POST tailored&#95;audience&#95;memberships

最后，`list_type` 参数将在 v4 中从*所有* [Tailored Audiences 端点](/zh/x-ads-api/audiences)的请求和响应中移除。

***Settings Endpoints***

我们现在为账户管理员提供设置和更新用户、账户以及税务设置的功能。[User settings](/zh/x-ads-api/campaign-management#get-accounts-account-id-user-settings-user-id) 对应于给定广告账户下用户的联系人偏好设置。通过使用 [PUT accounts/:account&#95;id](/zh/x-ads-api/campaign-management#put-accounts-account-id) 端点，广告主现在可以更新其账户名称和行业类型。最后，[tax settings](/zh/x-ads-api/campaign-management#get-accounts-account-id-tax-settings) 端点允许在征收增值税（VAT）的国家/地区的广告主更新公司名称、地址、VAT ID，以及该账户是由广告主本人所有还是由代表广告主投放广告的代理机构所有等信息。

再次提醒，请使用卡片的 `card_uri` 值将卡片与推文关联。请参阅以下示例请求。

$ twurl -X POST -H ads-api.x.com &quot;/4/accounts/18ce54d4x5t/tweet?text=Version 4&amp;card&#95;uri=card://958225772740714496&quot;

</div>

**视频端点**

`accounts/:account_id/videos` 端点在 v4 中将不再可用。该端点已因引入 [Media Library](/zh/x-ads-api/creatives#get-accounts-account-id-media-library) 端点而被废弃。请参阅以下用法对比。

* v3 videos 端点：`twurl -H ads-api.x.com "/3/accounts/18ce54d4x5t/videos"`

* v4 media library 视频端点：`twurl -H ads-api.x.com "/4/accounts/18ce54d4x5t/media_library?media_type=VIDEO"`

Media Library 端点与 videos 端点在功能上完全对等，并且还支持其他功能，例如处理图片和 GIF。请合作伙伴在所有媒体管理场景中统一使用 Media Library。

**Tweet 视图中的 `as_user_id`**

[GET accounts/:account&#95;id/tweet/preview/:tweet&#95;id](/zh/x-ads-api/creatives#get-accounts-account-id-tweets) 端点上提供的 `as_user_id` 参数将不再被接受。预览将始终以推文作者的身份进行渲染。

<div id="v3">
  ### v3
</div>

Ads API 的第 3 版于 2018 年 2 月 1 日[发布](https://devcommunity.x.com/t/ads-api-version-3/100732)。Ads API 的第 2 版将于 2018 年 8 月 1 日终止服务。

此版本包含我们全新的 Audience Intelligence 产品、对 Media Library 的访问权限，以及改进的卡片工作流。我们还在此宣布弃用 [PUT accounts/:account&#95;id/targeting&#95;criteria](/zh/x-ads-api/campaign-management#get-accounts-account-id-targeting-criteria) 端点。最后，第 3 版还包括一些次要的参数和响应变更，以及更低的批处理大小上限。

与 [第 2 版](https://devcommunity.x.com/t/ads-api-version-2/90360) 一样，我们为合作伙伴提供 **6 个月** 的迁移时间。到 **2018-08-01**，Ads API 的 v2 将被关闭。我们鼓励所有合作伙伴和开发者尽快迁移到 v3。

**Audience Intelligence**

Audience Intelligence 提供实时洞察，展示与指定 X 受众最相关的热门标签（hashtags）、@handles 和事件。例如，输入“男性 18-34 岁、位于美国”，即可看到在该受众中热度较高的 #nintendoswitch、#cardinal 和 @ricegum 等趋势。

Audience Intelligence 的 [端点](/zh/x-ads-api/audiences) 将提供以下功能：

* 对给定的输入受众，检索最相关的热门标签（hashtags）、@handles 和事件。
* 对给定的输入受众，检索关键人口统计信息（例如年龄、性别和家庭收入）。
* 对给定关键字，检索推文量的时间序列。

**Media Library**

[Media Library](/zh/x-ads-api/creatives#get-accounts-account-id-media-library) 提供管理广告账户图像、GIF 和视频的能力。这些媒体对象可以用于推文以及创建卡片。它们也可以在多个创意中重复使用，从而无需多次上传相同素材。

库中的对象通过 media&#95;key 进行标识。media&#95;key 是具有以下格式的字符串值，例如：13&#95;875943225764098048。在 Ads API 中，我们正逐步将所有媒体统一为使用 media&#95;key。

**改进的卡片工作流**

我们所有的卡片端点现在都支持 media&#95;key。这样，Media Library 中的对象即可用于创建或更新卡片。

此外，我们引入了两个用于 [检索卡片详情](/zh/x-ads-api/creatives#fetching-cards) 的新端点。通过指定 card&#95;uri 或 id，这些端点可用于查询用于推文或定时推文中的卡片等内容。此前，这是无法实现的。

<div id="other-changes">
  #### 其他变更
</div>

除了这些新功能之外，我们还在第 3 版中加入了以下变更。

**新增**

* [GET insights/keywords/search](/zh/x-ads-api/audiences) 端点的响应现在包含一个 `related_keywords` 属性，其中含有 30 个与输入关键词相关的术语。

**更改**

* 定向条件批量的最大数量现在为 500。
* `card_uri` 和 `preview_url` 响应属性现在互斥。当卡片具有 `card_uri` 时，`preview_url` 将为 `null`。当卡片没有 `card_uri` 时，只会返回 `preview_url`。
  * 自 2018-01-29 起创建的所有卡片都将具有 `card_uri`。
  * 到第 4 版时，所有现有卡片都将具有 `card_uri`。
* 不再允许 *创建* 使用 5:2 图片的卡片。尽管 *现有的* 基于 5:2 图片的卡片仍然可以使用，我们鼓励合作伙伴改为使用表现更好的 1.91:1 或 1:1 纵横比（在支持的情况下）。

**移除**

* [PUT accounts/:account&#95;id/targeting&#95;criteria](/zh/x-ads-api/campaign-management#get-accounts-account-id-targeting-criteria) 端点已不再可用。我们之所以进行此更改，是因为该端点的替换行为会让广告主感到困惑，并且与我们其他一次只更新单个资源的 PUT 端点不一致。取而代之的是，合作伙伴应使用 [POST batch/accounts/:account&#95;id/targeting&#95;criteria](/zh/x-ads-api/campaign-management#post-batch-accounts-account-id-targeting-criteria) 端点，它提供了更大的灵活性，包括能够在单个请求中同时添加和移除定向条件。
* `paused` 响应属性不再针对资金工具返回。相反，应查看 `entity_status` 响应属性来判断资金工具是否已暂停。此外，因为 `paused` 和 `cancelled` 对应相同的值，`cancelled` 也不再在响应中返回。
* 我们已从 [GET accounts/:account&#95;id/tweet/preview](/zh/x-ads-api/creatives#get-accounts-account-id-tweets) 端点中移除了 `card_id` 参数。
* 由于无法检索已删除的预定推文（Scheduled Tweets），`with_deleted` 参数不再受支持。
* 以下端点中已移除 `draft_only` 参数，因为这些实体永远不会处于草稿状态：
  * [GET accounts/:account&#95;id/targeting&#95;criteria](/zh/x-ads-api/campaign-management#get-accounts-account-id-targeting-criteria)
  * [GET accounts/:account&#95;id/promoted&#95;tweets](/zh/x-ads-api/campaign-management#get-accounts-account-id-promoted-tweets)
  * [GET accounts/:account&#95;id/promoted&#95;accounts](/zh/x-ads-api/campaign-management#get-accounts-account-id-promoted-accounts)
  * [GET accounts/:account&#95;id/media&#95;creatives](/zh/x-ads-api/campaign-management#get-accounts-account-id-media-creatives)
  * [GET accounts/:account&#95;id/preroll&#95;call&#95;to&#95;actions](/zh/x-ads-api/creatives#get-accounts-account-id-preroll-call-to-actions)

**注意**

视频网站卡片（Video Website Cards）和预定推文（Scheduled Tweets）现在均已正式脱离测试阶段。有关自发布以来我们对预定推文所做变更，请参阅[此主题](https://devcommunity.x.com/t/announcement-update-to-scheduled-tweets/94869)。其中包括为预定推文生成 HTML [预览](https://devcommunity.x.com/t/announcement-tweet-preview-improvements/96577) 的功能。

**版本 1 的变更：[¶](#changes-in-version-1 "Permalink to this headline")**

* [触达预估变更](https://developer.x.com/en/docs/ads/campaign-management/api-reference/reach-estimate.html#get-accounts-account-id-reach-estimate):
* 为了提供更准确的触达预估结果，该 endpoint 现在会考虑预算因素。以下参数现在为必需：
  * [新增] `campaign_daily_budget_amount_local_micro`
  * `currency`
  * `bid`
  * `objective`

* `infinite_count` 已重命名为 `infinite_bid_count`，以避免对其用途产生歧义

  * `impressions`
  * `engagements`
  * `estimated_daily_spend_local_micro`
* 定向受众数据类型变更
* 在我们所有的响应中，Tailored Audiences 的 `data_type` 已从 `tailored_audiences` 更改为 `tailored_audience`。
* 共享定制受众现已以 *仅限 API* 的测试版形式提供。共享定制受众允许在多个广告账号之间复用同一个受众。使用 [POST accounts/:account&#95;id/tailored&#95;audiences/:tailored&#95;audience&#95;id/permissions](/zh/x-ads-api/audiences)（及相关端点）来管理你希望在多个广告账号之间共享的该定制受众的权限。
* 在收集广告主账户绩效[分析](/zh/x-ads-api/analytics)数据的方式上进行了重大改进：
* 为遵循我们的[最佳实践](/zh/x-ads-api/analytics#best-practices)，我们现在只允许通过[同步统计信息端点](/zh/x-ads-api/analytics#get-stats-accounts-account-id)拉取最近最多 **7 天** 的数据。
* 为了简化指标获取，我们用新的 `metric_groups` 参数替换了 `metrics` 参数。开发者只需在相应请求中指定希望返回的指标分组即可。
  * 任何针对给定实体不适用的指标的请求都会从响应中排除，并以 `null` 值表示。*这些指标不会计入你的分析费用上限。*
* 该响应已经**大幅简化**，现在将与我们的 UI 中指标的呈现方式更加一致。
  * 之前，我们针对每个投放位置分别提供了独立的指标（搜索中的 Promoted Tweets、时间线中的 Promoted Tweets、个人资料和推文详情中的 Promoted Tweets、X Audience Platform）。现在，我们会为每个位置返回一组标准化的指标（不再使用 `promoted_tweet_timeline_impressions`、`promoted_tweet_search_impressions`、`promoted_tweets_profile_impressions`、`promoted_tweets_tpn_impressions`）。当你在以下任一类别中请求时，这些指标将作为单一指标 `impressions` 提供（适用于所有指标）：
  * `ALL_ON_TWITTER`
  * `PUBLISHER_NETWORK`
  * 当你发起请求时，你只会获得一个 `impressions` 指标，从而更容易与我们 UI 中的数值进行对齐。
  * 你必须发起两次查询才能分别获取 `ALL_ON_TWITTER` 和 `PUBLISHER_NETWORK` 的 data，因为它们不能被合并。
* 根据开发者反馈，[异步统计数据端点](/zh/x-ads-api/analytics#asynchronous-analytics) 现已开放使用！
  * 一组新的端点，用于*异步*请求统计数据，适用于你不需要立即获取的数据或历史数据拉取。
  * 使用一个新的单个端点将统计任务加入队列。我们会在资源允许的情况下获取你所请求的数据。
  * 你可以查询任务状态端点，以确定数据是否可用。
  * 一旦数据可用，我们会提供一个提取 ID，供你下载 JSON 响应，其结构将与同步端点的响应保持一致。
  * 在单个任务中最多查询 **90 天** 的数据，覆盖最多 **20 个实体**。
* 请参阅我们的 analytics v1 迁移指南，其中提供了从 v0 指标到 v1 指标的映射关系
* 沙盒改进 * 您现在可以在沙盒环境中[创建多个测试广告账户](/zh/x-ads-api/campaign-management#post-accounts)。* 您现在可以仅在沙盒环境中为一个测试广告账户创建多个资金工具（funding instruments）。这使您能够测试我们所有的资金工具类型。此前仅提供 `CREDIT_CARD` 资金来源用于测试。* 想要测试 Beta 功能？您现在可以在沙盒环境中为某个账户启用或停用功能，以满足您的测试需求。
