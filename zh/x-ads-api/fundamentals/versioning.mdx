<div id="overview">
  ## 概览
</div>

每个月，我们都会对 X Ads API 进行修改并推出若干新功能。这些更改几乎总是向后兼容的，但我们每年通常也会有少量破坏性变更。我们从开发者那里收到反馈，指出 Ads API 快速迭代节奏在实现新功能、处理弃用以及测试变更时，对他们的开发周期带来了挑战。我们希望改进开发者在我们的 Ads 平台上的使用体验，这也是我们引入对端点进行版本化这一概念的原因。

以下是我们在此讨论的一些概念的定义：

**版本（Version）**：指的是任何 Ads API 请求的 URL 路径中出现的版本号，例如：GET /{version_number}/accounts。这种版本控制方式称为 URI 版本控制。

**破坏性变更（Breaking Changes）**：破坏性变更是指任何需要投入开发资源来维持现有功能的更改。这包括用于调查需要进行哪些更改的资源、确定将被弃用的功能/端点的资源，以及最终实施所有这些更改的资源。破坏性变更的示例如下：

* 从 API 请求/响应中移除某个参数

* 修改任意参数或端点的名称

* 更改值的表示方式（preview&#95;url → card&#95;uri）

* 更改端点的行为（例如，异步统计改为同步统计）

* 添加/更改可选或必填参数（例如，将 name 字段设为请求中的必填字段）

**弃用（Deprecation）**：被弃用的版本或产品将不再受到支持，建议开发者停止使用这些 API。

**下线（Sunset）**：一旦某个产品或 API 被下线，相应的一组端点将无法再通过 API 访问。

<div id="versioning-strategy">
  ## 版本管理策略
</div>

该策略的主要原则如下：

1. 所有破坏性变更都会被打包进一个新版本中

2. 每当新版本发布时，现有版本的弃用周期为 6 个月

3. 在任意时间点，API 会同时允许两个版本的请求，但其中较旧的那个版本将不再受支持

4. 为了加快新产品的采用，这些产品将以持续滚动的方式发布（不受版本节奏限制）

5. 所有 API 响应都会包含一个 `x-current-api-version`，其值为当前 API 版本；另外，在调用任何已被弃用的 API 端点时，还会包含一个 `x-api-warn` 头。

如果出现任何需要进行 API 破坏性变更的基础产品需求变动（例如弃用多个年龄区间定向），我们将提前发送 90 天通知来公告该破坏性变更，并且在通知发布至少 90 天之后再部署该破坏性变更。

<div id="v5">
  ### v5
</div>

今天（2019 年 2 月 28 日），X 推出 Ads API v5，本次更新重点在于提升扩展性和效率。

本次发布新增了一个用于确定在给定时间范围内哪些实体处于活动状态的 endpoint，为媒体创意（即 X Audience Platform 上的流内视频和图片）提供统计数据，支持按卡片 URI 获取&#95;多个&#95;卡片，并在检索定向条件和其他实体方面提供了更高的灵活性。此外，我们修复了一些缺陷，并更新了参数名称和响应属性。最后，非媒体 App 卡片以及 POST `accounts/:account_id/account_media` endpoint 已被弃用。

与先前版本一样，将提供 6 个月的过渡期以迁移到 v5。自 **2019-08-28** 起，Ads API 的第 4 版将不再可用。我们鼓励所有合作伙伴尽快迁移到最新版本的 API，以避免任何服务中断。*Ads API 第 3 版的生命周期已结束，不再可用。*

<div id="new">
  #### 新增
</div>

**确定哪些实体处于活跃状态**

[Active Entities](/zh/x-ads-api/analytics#active-entities-2) 端点用于指示广告实体的分析指标是否发生变化。该端点设计为与各类 analytics 端点配合使用，你可以通过指定实体类型和日期范围（最长 90 天）来调用，端点会返回一个实体 ID 数组，你的平台应基于这些 ID 来请求分析数据。未包含在响应结果中的 ID 不应在后续的分析请求中被查询。

此端点支持以下实体类型：`CAMPAIGN`、`FUNDING_INSTRUMENT`、`LINE_ITEM`、`MEDIA_CREATIVE` 和 `PROMOTED_TWEET`。

**`MEDIA_CREATIVE` 统计数据**

Ads API 的 analytics 端点现在为 Media Creative 实体提供指标数据。Media Creative 是在 X Audience Platform 上推广视频流内广告或图片的方式。X Ads UI 会在“In-stream videos”和“Display creatives”选项卡下显示 Media Creative 指标。同步的[同步](/zh/x-ads-api/analytics#get-stats-accounts-account-id)和[异步](/zh/x-ads-api/analytics#asynchronous-analytics) analytics 端点现在都支持 `MEDIA_CREATIVE` 实体枚举。

**获取多个 card**

在之前用于通过 card URI 值检索单个 card 的[第 v3 版发布](https://devcommunity.x.com/t/ads-api-version-3/100732)端点基础上进行了改进，现在可以使用 [GET accounts/:account&#95;id/cards/all](/zh/x-ads-api/creatives#cards-fetch) 端点获取 *多个* card。你无需再为每个 card 单独发起请求，而是可以在一次请求中最多检索 200 个 card。

需要注意两点：

1. URL 路径现在为 `accounts/:account_id/cards/all`。（之前的路径已不再可用。）这样可以与[用于按 ID 检索 card 的端点](/zh/x-ads-api/creatives#cards-fetch)保持一致。
2. 必需的请求参数现在命名为 card&#95;uris（复数形式）。

**在检索方面的灵活性**

[GET accounts/:account&#95;id/targeting&#95;criteria](/zh/x-ads-api/campaign-management#get-accounts-account-id-targeting-criteria) 端点现在支持多个 line item ID。必需的 line&#95;item&#95;ids 参数最多可接收 200 个 ID。此前仅接受单个 line item，这使得同步较为困难。通过此更改，现在可以在更短时间内检索到更多定向信息。

下列端点现在同样支持多个 line item ID，但对这些端点而言，line&#95;item&#95;ids 参数是可选的。

* [GET accounts/:account&#95;id/line&#95;item&#95;apps](https://developer.x.com/en/docs/x-ads-api/campaign-management/api-reference/line-item-apps#get-accounts-account-id-line-item-apps)
* [GET accounts/:account&#95;id/media&#95;creatives](/zh/x-ads-api/campaign-management#get-accounts-account-id-media-creatives)
* [GET accounts/:account&#95;id/promoted&#95;accounts](/zh/x-ads-api/campaign-management#get-accounts-account-id-promoted-accounts)
* [GET accounts/:account&#95;id/preroll&#95;call&#95;to&#95;actions](/zh/x-ads-api/creatives#preroll-call-to-actions)

<div id="changed">
  #### 已更改
</div>

**检索草稿广告系列和推广线项**

检索草稿广告系列和推广线项的方式已更新。现在，当将 with&#95;draft(boolean) 参数设置为 true 时，会同时返回草稿和非草稿实体（*both*）。这与检索已删除实体的方式保持一致（即使用 with&#95;deleted）。此前，要同时获取草稿和非草稿实体至少需要两次请求。现在，可以通过一次 API 调用完成。

| **v4** | **v5** |
| :--- | :--- | :--- |
| `draft_only` | `with_draft` |     |

**Network activation duration targeting（网络激活时长定向）**

Ads API 已修复一个显示问题：在添加 Network Activation Duration 定向后，响应中的定向 type 带有 &#95;IN&#95;SEC 后缀。由于 Network Activation Duration 始终以“月”为单位表示，引用“秒”会造成混淆。此次修复从而统一了表示方式，并减少了混淆。

| **v4** | **v5** |
| :--- | :--- | :--- |
| `NETWORK_ACTIVATION_DURATION_IN_SEC` | `NETWORK_ACTIVATION_DURATION` |     |

**总数统计和游标**

在 v5 中，with&#95;total&#95;count 和 cursor 是互斥的。在同一个请求中同时指定这两个参数将返回 EXCLUSIVE&#95;PARAMETERS 错误代码。在 v5 之前，当指定了 cursor 时，with&#95;total&#95;count 会被忽略。这一变更使两者之间的关系更加明确。

<div id="removed">
  #### 已移除
</div>

有三个字段将从 Ads API 响应中移除：preview&#95;url、account&#95;id 和 parent&#95;ids。针对这三项所需的工程改动很小。

* 在 v4 中，我们已宣布 cards 的 preview&#95;url 响应参数始终为 null。本次迁移的最后一步是从所有 cards 响应中移除 preview&#95;url。
* 将从以下资源中移除 account&#95;id 响应属性，因为广告账户 ID 已经同时存在于 URL 以及 request.params 中。（特意将资金工具排除在此列表之外，因为在可能的情况下，父级 ID 应当出现在响应对象中，而账户 ID 是资金工具的父级实体。）
  * 账户媒体（Account media）
  * App 事件提供方（App event providers）
  * App 事件标签（App event tags）
  * 广告系列（Campaigns）
  * Cards
  * Line items
  * 可推广用户（Promotable users）
  * 定向条件（Targeting criteria）
* 对于 [GET accounts/:account&#95;id/targeting&#95;criteria](/zh/x-ads-api/campaign-management#get-accounts-account-id-targeting-criteria) 请求，我们不再返回 parent&#95;ids 字段，因为它始终是一个空数组。

**非媒体 App 卡片**

在 v5 中，不再支持非媒体 App 卡片。[此前](https://devcommunity.x.com/t/deprecation-announcement-app-download-cards/87807)，创建或编辑非媒体 App 卡片的能力已经被移除。现在，此资源剩余的端点也将被弃用。

* 注意：这 **不会** 影响图片和视频 App 下载卡片。

**创建账户媒体**

在 v5 中，POST accounts/:account&#95;id/account&#95;media 端点不再可用。此资源的其他端点 **不** 受影响。进行此更改的原因是：在将媒体添加到 [Media Library](/zh/x-ads-api/creatives#media-library) 时，在某些情况下这些素材会被**自动**添加为 Account Media 实体，而尝试将已存在的素材再次添加到 Account Media 资源会导致错误。在以下情况下会发生此问题。

* 添加到 Media Library 的 `AMPLIFY_VIDEO` 素材会自动作为 Account Media 素材添加，并使用 `PREROLL` 创意类型。
* 具有特定尺寸的图片添加到 Media Library 时会自动作为 Account Media 素材添加。创意类型（例如 `INTERSTITIAL`）取决于图片尺寸。（有关尺寸，请参阅我们的 [Enumerations](/zh/x-ads-api/introduction) 页面。）

<div id="v4">
  ### v4
</div>

Ads API 第 4 版已于 2018 年 8 月 28 日正式发布。

本次发布对我们的 [Audiences](/zh/x-ads-api/audiences) 产品进行了改进，包括提供由更健壮的受众处理后端驱动的全新 API 接口。第 4 版还新增了一组用于管理用户、账户和税务设置的端点。此外，accounts/:account&#95;id/videos 端点将被弃用。本次发布还包含少量参数和响应名称的更改。

与第 3 版一样，我们提供 6 个月的过渡期。自 **2019-02-28** 起，第 3 版 Ads API 将不再可用。我们鼓励所有合作伙伴尽快迁移到最新版本的 API，以避免任何服务中断。有关我们的版本策略的详细信息，请参阅 [Versions](/zh/x-ads-api/introduction) 页面。

<div id="new">
  #### 新增
</div>

***Audience API***

全新的 Audiences API 构建在我们新一代的受众处理后端之上，具备更高的健壮性和可靠性。这个新端点允许合作伙伴为单个用户提供多种用户标识符类型，这意味着我们可以利用更多信号进行匹配。新 Audience 端点的参考文档可在[此处](/zh/x-ads-api/audiences)查阅。我们计划在今年剩余时间内持续发布该产品的更新和改进。

由于功能重复，以下端点在 v4 中将不再可用（它们在 v3 中仍可使用，并会在 v3 不再可用时完全**下线**）：

* TON Upload：
  * GET accounts/:account&#95;id/tailored&#95;audience&#95;changes
  * GET accounts/:account&#95;id/tailored&#95;audience&#95;changes/:tailored&#95;audience&#95;change&#95;id
  * POST accounts/:account&#95;id/tailored&#95;audience&#95;changes
  * PUT accounts/:accounti&#95;d/tailored&#95;audiences/global&#95;opt&#95;out
* Real Time Audiences：
  * POST tailored&#95;audience&#95;memberships

最后，在第 4 版中，`list_type` 参数将从&#95;所有&#95; [Tailored Audiences 端点](/zh/x-ads-api/audiences)的请求和响应中移除。

***Settings Endpoints***

我们现在为账户管理员提供设置和更新用户、账户及税务设置的功能。[User settings](/zh/x-ads-api/campaign-management#get-accounts-account-id-user-settings-user-id) 对应于给定广告账户的、特定于用户的联系偏好设置。通过 [PUT accounts/:account&#95;id](/zh/x-ads-api/campaign-management#put-accounts-account-id) 端点，广告主现在可以更新其账户名称和所属行业。最后，[tax settings](/zh/x-ads-api/campaign-management#get-accounts-account-id-tax-settings) 端点允许在征收增值税（VAT）的国家/地区的广告主更新信息，例如公司名称、地址、VAT ID，以及该账户是由广告主直接所有，还是由代表广告主投放广告的代理机构所有。

**在所有地方使用 `country_code`**

* [POST accounts/:account&#95;id/cards/video&#95;app&#95;download](https://developer.x.com/content/developer-twitter/en/docs/ads/creatives/api-reference/video-app-download#post-accounts-account-id-cards-video-app-download)
* [PUT accounts/:account&#95;id/cards/video&#95;app&#95;download/:card&#95;id](https://developer.x.com/content/developer-twitter/en/docs/ads/creatives/api-reference/video-app-download#put-accounts-account-id-cards-video-app-download-card-id)

这不会影响这些参数的行为或可接受的取值，仅是名称上的更改。

**`preview_url` 始终为 null**

正如在 v3 公告中所承诺的，现在所有现有卡片都有一个 `card_uri`。因此，`preview_url` 的值将始终为 `null`。

提醒一下，请使用卡片的 `card_uri` 值将其与推文关联。请参见以下示例请求。

$ twurl -X POST -H ads-api.x.com &quot;/4/accounts/18ce54d4x5t/tweet?text=Version 4&amp;card&#95;uri=card://958225772740714496&quot;

<div id="removed">
  #### 已移除
</div>

**视频端点**

`accounts/:account_id/videos` 端点在 v4 中将不再可用。该端点已被引入的 [Media Library](/zh/x-ads-api/creatives#get-accounts-account-id-media-library) 端点所取代。请参见以下用法对比。

* v3 视频端点：`twurl -H ads-api.x.com "/3/accounts/18ce54d4x5t/videos"`

* v4 视频的 Media Library 端点：`twurl -H ads-api.x.com "/4/accounts/18ce54d4x5t/media_library?media_type=VIDEO"`

Media Library 端点与视频端点功能完全一致，并且还支持其他功能，例如处理图片和 GIF。请合作伙伴在所有媒体管理场景中仅使用 Media Library。

**推文视图中的 `as_user_id`**

[GET accounts/:account&#95;id/tweet/preview/:tweet&#95;id](/zh/x-ads-api/creatives#get-accounts-account-id-tweets) 端点上可用的 `as_user_id` 参数将不再支持。预览将始终以推文作者的身份渲染。

<div id="v3">
  ### v3
</div>

Ads API 的第 3 版于 2018 年 2 月 1 日[发布](https://devcommunity.x.com/t/ads-api-version-3/100732)。Ads API 的第 2 版将于 2018 年 8 月 1 日终止服务。

此版本包含我们全新的 Audience Intelligence 产品、对 Media Library 的访问能力以及改进的卡片工作流程。我们也在此宣布弃用 [PUT accounts/:account&#95;id/targeting&#95;criteria](/zh/x-ads-api/campaign-management#get-accounts-account-id-targeting-criteria) 端点。最后，第 3 版还包含少量参数和响应变更，并降低了批量大小上限。

与[第 2 版](https://devcommunity.x.com/t/ads-api-version-2/90360)一样，我们为合作伙伴提供 **6 个月** 的迁移时间。自 **2018-08-01** 起，Ads API 的 v2 将被关闭。我们鼓励所有合作伙伴和开发者尽快迁移到 v3。

**Audience Intelligence**

Audience Intelligence 提供与特定 X 受众最相关的热门话题标签、@handles 和事件的实时洞察。例如，输入“美国 18–34 岁男性”，你会看到 #nintendoswitch、#cardinal 和 @ricegum 在该受众中非常流行。

Audience Intelligence 的[端点](/zh/x-ads-api/audiences)将提供以下功能：

* 根据输入受众，获取最相关的话题标签、@handles 和事件。
* 根据输入受众，获取关键人口统计信息（例如年龄、性别和家庭收入）。
* 根据关键词，获取推文量时间序列。

**Media Library**

[Media Library](/zh/x-ads-api/creatives#get-accounts-account-id-media-library) 提供管理广告账户图片、GIF 和视频的能力。这些媒体对象可以用于推文以及创建卡片。它们还可以在多个创意中重复使用，从而无需多次上传相同素材。

库中的对象由 media&#95;key 标识。Media key 是字符串值，例如格式为 13&#95;875943225764098048。在 Ads API 中，我们正逐步在所有媒体中统一使用 media key。

**改进的卡片工作流程**

我们所有的卡片端点现在都支持 media key。这使得 Media Library 中的对象可以用于创建或更新卡片。

此外，我们还引入了两个用于[检索卡片详情](/zh/x-ads-api/creatives#fetching-cards)的新端点。通过指定 card&#95;uri 或 id，这些端点可用于查询用于推文或预定推文中的卡片，而此前这是无法实现的。

<div id="other-changes">
  #### 其他更改
</div>

除了这些新特性之外，我们还在版本 3 中加入了以下更改。

**新增**

* 现在，[GET insights/keywords/search](/zh/x-ads-api/audiences) 端点的响应中包含一个 related&#95;keywords 属性，其中包含与输入关键词相关的 30 个词语。

**更改**

* 目标定向条件批处理的最大条目数现在为 500。
* 响应属性 card&#95;uri 和 preview&#95;url 现在是互斥的。当一个 card 拥有 card&#95;uri 时，preview&#95;url 将为 null。当一个 card 没有 card&#95;uri 时，只会返回 preview&#95;url。
  * 自 2018-01-29 起创建的所有 card 都将拥有 card&#95;uri。
  * 到版本 4 时，所有现有 card 都将拥有 card&#95;uri。
* 不再支持 *创建* 使用 5:2 图片的 card。虽然 *现有* 的基于 5:2 图片的 card 仍然可以使用，但我们鼓励合作伙伴改用表现更好的 1.91:1 或 1:1 纵横比（在支持的情况下）。

**移除**

* [PUT accounts/:account&#95;id/targeting&#95;criteria](/zh/x-ads-api/campaign-management#get-accounts-account-id-targeting-criteria) 端点已不再可用。我们决定做出此更改，是因为该端点的替换行为会让广告主感到困惑，并且与我们其他一次仅更新单个资源的 PUT 端点不一致。合作伙伴应改用 [POST batch/accounts/:account&#95;id/targeting&#95;criteria](/zh/x-ads-api/campaign-management#post-batch-accounts-account-id-targeting-criteria) 端点，它提供了更大的灵活性，包括能够在单个请求中同时添加和移除定向条件。
* funding instrument 的响应中不再返回 paused 属性。取而代之的是，请查看 entity&#95;status 响应属性以确定某个 funding instrument 是否已暂停。此外，由于 paused 和 cancelled 对应相同的值，响应中也不再返回 cancelled。
* 我们已从 [GET accounts/:account&#95;id/tweet/preview](/zh/x-ads-api/creatives#get-accounts-account-id-tweets) 端点中移除了 card&#95;id 参数。
* 由于无法检索已删除的 Scheduled Tweets（计划推文），因此不再支持 with&#95;deleted 参数。
* 以下端点已移除 draft&#95;only 参数，因为这些实体永远不会处于草稿状态：
  * [GET accounts/:account&#95;id/targeting&#95;criteria](/zh/x-ads-api/campaign-management#get-accounts-account-id-targeting-criteria)
  * [GET accounts/:account&#95;id/promoted&#95;tweets](/zh/x-ads-api/campaign-management#get-accounts-account-id-promoted-tweets)
  * [GET accounts/:account&#95;id/promoted&#95;accounts](/zh/x-ads-api/campaign-management#get-accounts-account-id-promoted-accounts)
  * [GET accounts/:account&#95;id/media&#95;creatives](/zh/x-ads-api/campaign-management#get-accounts-account-id-media-creatives)
  * [GET accounts/:account&#95;id/preroll&#95;call&#95;to&#95;actions](/zh/x-ads-api/creatives#get-accounts-account-id-preroll-call-to-actions)

**注意**

Video Website Cards 和 Scheduled Tweets（计划推文）现在都已退出测试版。有关自 Scheduled Tweets 上线以来我们所做更改的说明，请参见 [此讨论帖](https://devcommunity.x.com/t/announcement-update-to-scheduled-tweets/94869)。其中包括为 Scheduled Tweets 生成 HTML [预览](https://devcommunity.x.com/t/announcement-tweet-preview-improvements/96577) 的功能。

**重大变更/弃用[¶](#breaking-changes-deprecations "Permalink to this headline")**

* `total_count` 现在是一个可选的响应属性。只有在将 `with_total_count` 设为 `true` 时才会返回该属性

* PUT accounts/:account&#95;id/promoted&#95;tweets 端点上的 `display_properties`。该值也将不再作为响应的一部分返回

* 由于上一点所述的更改，将无法再更新（PUT）promoted&#95;tweets 实体

* [GET accounts/:account&#95;id/promoted&#95;tweets](/zh/x-ads-api/campaign-management#get-accounts-account-id-promoted-tweets) 端点上的 `line_item_id` 参数已被移除

**第 1 版的更改：[¶](#changes-in-version-1 "此标题的永久链接")**

  * [新增] `campaign_daily_budget_amount_local_micro`

  * `impressions`
  * `engagements`
  * `estimated_daily_spend_local_micro`

* 在我们的所有响应中，Tailored Audiences 的 `data_type` 已从 `tailored_audiences` 更改为 `tailored_audience`。
* 共享型 Tailored Audiences 现已作为*仅限通过 API 使用*的测试版提供。共享型 Tailored Audiences 允许在多个广告账号之间复用同一个受众。使用 [POST accounts/:account&#95;id/tailored&#95;audiences/:tailored&#95;audience&#95;id/permissions](/zh/x-ads-api/audiences)（及相关端点）来管理你希望在多个广告账号之间共享的 Tailored Audience 的权限。

* 为与我们的[最佳实践](/zh/x-ads-api/analytics#best-practices)保持一致，我们现在仅允许通过[同步统计端点](/zh/x-ads-api/analytics#get-stats-accounts-account-id)最多获取 **7 天** 的数据。
* 为了简化拉取指标数据，我们用新的 `metric_groups` 参数替换了 `metrics` 参数。开发者只需在每个请求中指定希望返回的指标分组即可。
  * 任何针对特定实体不适用的指标请求，都会在响应中被排除，并以 `null` 值表示。*这些指标不会计入你的分析费用上限。*
* 响应已被**大幅简化**，现在与我们在 UI 中展示指标的方式更加一致。
  * 之前，我们针对每个投放位置分别提供了单独的指标（搜索中的 Promoted Tweets、时间线中的 Promoted Tweets、个人资料与推文详情中的 Promoted Tweets、X Audience Platform）。现在，我们会为每个位置返回一组标准化的指标（不再使用 `promoted_tweet_timeline_impressions`、`promoted_tweet_search_impressions`、`promoted_tweets_profile_impressions`、`promoted_tweets_tpn_impressions`），当你在以下任一类别中请求时，这些都会作为单一的 `impressions` 指标提供（这适用于所有指标）：
  * `ALL_ON_TWITTER`
  * `PUBLISHER_NETWORK`
  * 当你发起请求时，你只会获得一个 `impressions` 指标，以便更容易与我们 UI 中显示的数值进行匹配。
  * 你必须发起两次查询才能分别获取 `ALL_ON_TWITTER` 和 `PUBLISHER_NETWORK` 数据，因为这两类数据无法合并。
* 根据开发者的反馈，我们现已提供 [异步统计端点](/zh/x-ads-api/analytics#asynchronous-analytics)！
  * 一组新的端点，用于 *异步* 请求统计数据，适用于你不需要立即获取的数据或历史数据拉取。
  * 使用一个新的统一端点将统计任务加入队列。我们会在资源允许的情况下拉取你请求的数据。
  * 你可以查询任务状态端点以确定数据是否可用。
  * 一旦数据可用，我们会提供一个用于取回的 ID，供你下载 JSON 响应，该响应将与同步端点的响应保持一致。
  * 在单个任务中最多可查询 **90 天** 的数据以及最多 **20 个实体**。
* 请参阅我们的 Analytics v1 迁移指南，其中包含从 v0 指标到 v1 指标的映射关系。
* Sandbox 改进 * 您现在可以在 Sandbox 环境中[创建多个测试广告账户](/zh/x-ads-api/campaign-management#post-accounts)。 * 您现在只能在 Sandbox 环境中为测试广告账户创建多个资金工具（funding instruments）。这使您可以测试我们所有类型的资金工具。之前只能使用 `CREDIT_CARD` 作为资金来源进行测试。 * 想要测试某个 Beta 功能？现在您可以在 Sandbox 环境中为某个账户开启或关闭功能，以满足您的测试需求。
