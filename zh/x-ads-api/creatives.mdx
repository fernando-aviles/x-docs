<div id="overview">
  ## 概览
</div>

创意（Creatives）是指在广告活动中可以被推广的任何实体。帖子可以包含文本、图片、GIF、视频或卡片。卡片可以包含图片或视频。

图片、GIF 或视频类创意需通过 [POST media/upload](/zh/x-api/media/upload-media#post-media-upload) 上传——这是一个仅支持图片的简单上传端点——或通过 POST media/upload（分块上传）端点上传。这些创意可以添加到：

卡片：

* POST accounts/:account&#95;id/cards
  推文：
* POST accounts/:account&#95;id/tweets - 若要将卡片添加到推文中，请使用 card&#95;uri 参数。
  预定推文：
* POST accounts/:account&#95;id/scheduled&#95;tweets

有关卡片的更多详细信息，请参阅 Cards 页面。Promoted Video 页面提供了将视频与卡片或推文关联的详细信息。

### 卡片

Ads API 支持多种可用于推文中的卡片类型，这些卡片随后可以在广告活动中推广。**注意**：一旦作为推文发布，卡片详情将对公众可见。这可能包括关于拥有该卡片的用户的信息。

<div id="image">
  #### 图片
</div>

以下图片规范适用于 [Cards](/zh/x-ads-api/creatives#cards-2) 中使用的素材。图片大小必须不超过 3MB，且宽度至少为 800px。此外，我们支持以下宽高比。

* Website：1:1 和 1.91:1
* Image App Download：1:1 和 1.91:1
* Poll：1.91:1
* Image Conversation：1.91:1
* Image Direct Message：1.91:1

我们支持以下图片格式：.bmp、.jpeg 和 .png。

<div id="video">
  #### 视频
</div>

以下视频规格适用于在 [Cards](/zh/x-ads-api/creatives#cards-2) 中使用的素材。我们支持以下宽高比（宽:高）。

* 视频网站卡片：16:9 和 1:1
* 视频应用下载卡片：16:9 和 1:1
* 投票：16:9
* 视频会话：16:9
* 视频私信：16:9

<div id="promoted-video">
  ### 推广视频
</div>

本文档简要概述了通过 Ads API 上传和投放视频广告的流程。

Ads API 支持在[推文](/zh/x-ads-api/creatives#tweets-2)以及以下卡片中使用推广视频：

* [视频网站卡片](https://devcommunity.x.com/t/ads-api-version-11/168814)
* [视频应用下载卡片](https://devcommunity.x.com/t/ads-api-version-11/168814)
* [视频会话卡片](/zh/x-ads-api/creatives#video-conversation-cards)

首先，使用 [POST media/upload (chunked)](https://developer.x.com/en/docs/media/upload-media/api-reference/post-media-upload-init.html) 端点上传视频。然后使用 `media_id`，通过 POST accounts/:account&#95;id/videos 端点将该视频与广告账户关联。该视频的 `id`（有时也称为 `media_key`）将在后续请求中使用。它是一个字符串，以整数开头，后跟一个下划线，最后以一个 long 类型数值结尾。例如：`13_875943225764098048`。

<div id="promoted-video-in-tweets">
  #### 推文中的推广视频
</div>

要创建推文，请使用 [POST accounts/:account&#95;id/tweet](/zh/x-ads-api/creatives#get-accounts-account-id-tweets) 端点，并提供视频的 `id`。在此步骤中，你还可以提供视频标题、描述和行动号召（CTA）。这些值是用户可见的。

<div id="promoted-video-in-cards">
  #### 卡片中的推广视频
</div>

视频应用下载卡片和视频会话卡片支持添加海报图片。使用 [POST media/upload](https://developer.x.com/en/docs/media/upload-media/api-reference/post-media-upload.html) 端点上传要在这些卡片中使用的图片。

使用以下任一端点创建卡片：

* [POST accounts/:account&#95;id/cards/video&#95;website](https://devcommunity.x.com/t/ads-api-version-11/168814)
* [POST accounts/:account&#95;id/cards/video&#95;app&#95;download](https://devcommunity.x.com/t/ads-api-version-11/168814)
* [POST accounts/:account&#95;id/cards/video&#95;conversation](https://devcommunity.x.com/t/ads-api-version-11/168814)

使用视频的 `id`，以及可选的图片 `media_id`（作为海报图片）。

最后，使用 POST accounts/:account&#95;id/tweet 端点创建推文。卡片通过 `card_uri` 参数附加到推文上。

<div id="general-information">
  #### 常规信息
</div>

有关通过 API 上传视频的详细指南，请参阅 [视频上传指南](https://developer.x.com/en/docs/media/upload-media/uploading-media.html)。

视频也可以作为前贴片素材进行投放。请参阅 [Video Views Pre-roll Objective 指南](/zh/x-ads-api/campaign-management#video-views-preroll-objective) 以获取详细说明。

* （自 2015-10-22 起）在上传用于推广内容的视频时，所有对 [POST media/upload (chunked)](https://developer.x.com/en/docs/media/upload-media/api-reference/post-media-upload-init.html) 端点的 `INIT` 命令请求，其 `media_category` 参数必须设置为 `amplify_video`。使用这一新参数可确保视频以异步方式进行预处理，并为在推广内容中使用做好准备。视频上传完成后，可以使用 `STATUS` 命令检查异步处理是否完成。
* 当前允许的推广视频最长为 10 分钟，文件大小需不超过 500MB。
* 上传的视频应为 mp4 或 mov 格式。
* 上传的视频通常会被快速处理，但处理时间会因视频长度和文件大小而有所不同。
* 上传的封面图像应为 png 或 jpg 格式。对纵横比或尺寸没有要求，但封面图像会被调整以适配视频播放器。

<div id="scheduled-tweets">
  ### 定时发送推文
</div>

<div id="introduction">
  #### 介绍
</div>

预定推文（Scheduled Tweets）允许广告主或用户创建一条推文，并安排在未来某个时间发布。除了能够创建和管理这些推文之外，API 还支持将这些推文关联到某个 line item（广告项目），以便在推文发布后进行推广。这样可以让广告主预先准备原生推文，并在任意关键活动开始前提前规划他们的广告活动创意素材。例如，预先安排一条推文创意，使其在新产品发布公告发出的瞬间立即上线。

Scheduled Tweets API 端点提供的完整功能集如下所示：

* 创建、修改和查看新创建的预定推文
* 将一条预定推文与某个 line item 关联
* 查询和管理现有的预定推文
* 一旦预定推文上线，检索该已上线推文的 `id`

  #### API 端点

* [PUT accounts/:account&#95;id/scheduled&#95;tweets/:scheduled&#95;tweet&#95;id](/zh/x-ads-api/creatives#example-request-39)（修改现有的定时推文）
* [DELETE accounts/:account&#95;id/scheduled&#95;tweets/:scheduled&#95;tweet&#95;id](/zh/x-ads-api/creatives#example-request-40)（使用其 `id` 删除定时推文）
* [GET accounts/:account&#95;id/scheduled&#95;tweets/preview/:scheduled&#95;tweet&#95;id](/zh/x-ads-api/creatives#scheduled-tweets-2)（预览现有的定时推文）

  #### 排期推广推文
</div>

* [GET accounts/:account&#95;id/scheduled&#95;promoted&#95;tweets](/zh/x-ads-api/campaign-management#get-accounts-account-id-scheduled-promoted-tweets)（获取所有排期推广推文的列表）
* [GET accounts/:account&#95;id/scheduled&#95;promoted&#95;tweets/:scheduled&#95;promoted&#95;tweet&#95;id](/zh/x-ads-api/campaign-management#get-accounts-account-id-scheduled-promoted-tweets-scheduled-promoted-tweet-id)（根据其 `id` 查询排期推广推文）
* [POST accounts/:account&#95;id/scheduled&#95;promoted&#95;tweets](/zh/x-ads-api/campaign-management#post-accounts-account-id-scheduled-promoted-tweets)（创建新的排期推广推文）
* [DELETE accounts/:account&#95;id/scheduled&#95;promoted&#95;tweets/:scheduled&#95;promoted&#95;tweet&#95;id](/zh/x-ads-api/campaign-management#delete-accounts-account-id-scheduled-promoted-tweets-scheduled-promoted-tweet-id)（根据其 `id` 删除现有的排期推广推文）

  #### 预定推文查看
</div>

* [GET accounts/:account&#95;id/scheduled&#95;tweets/preview/:scheduled&#95;tweet&#95;id](/zh/x-ads-api/creatives#scheduled-tweets-2)（查看现有的预定推文）

由于预定推文与“实时”推文在性质上是彼此独立的实体，在对这些推文进行任何创建或编辑操作时，都会运行两套不同的验证。第一套验证规则会在创建预定推文的步骤中执行，具体包括：

<div id="scheduled-tweet-create">
  #### 创建计划推文：
</div>

* 验证已认证用户是否有权限为指定的 @handle 创建自然推文。要创建仅推广推文，已认证用户必须是具有 [Tweet composer permissions](https://developer.x.com/content/developer-twitter/en/docs/ads/campaign-management/api-reference/authenticated-user-access#get-accounts-account-id-authenticated-user-access) 的账户用户。
* 验证在距离 `scheduled_at` 时间前后 15 分钟的时间窗口内，计划创建的推文不超过 30 条。`SCHEDULED_TWEET_LIMIT_EXCEEDED` 错误消息表示在同一个未来 15 分钟时间段内安排了过多计划推文。广告主需要删除一条现有的计划推文，或者将 `scheduled_at` 时间适当前移或后移。

<div id="scheduled-tweet-goes-live">
  #### 定时推文发布时：
</div>

* 这些验证规则会在 `scheduled_at` 时间点运行，并且与通过 API 创建普通推文时应用的规则完全相同。例如，如果定时推文同时包含图片和 GIF，则该定时推文不会发布，其 `scheduled_status` 将被设为 `FAILED`。

<div id="workflow">
  #### 工作流
</div>

**创建新的预定推文**

可以使用 [POST accounts/:account&#95;id/scheduled&#95;tweets](https://developer.x.com/content/developer-twitter/en/docs/ads/creatives/api-reference/scheduled-tweets#post-accounts-account-id-scheduled-tweets) 端点来创建新的预定推文。此端点具有以下必需参数：`scheduled_at` 时间；如果推文中未包含任何媒体实体，则还必须提供推文 `text`。此外，此端点还提供了一些附加选项，允许你通过 `as_user_id` 参数代表另一个 @handle 创建预定推文，并可添加卡片（`card_uri`）和任意媒体（`media_ids`）。注意，一条推文只能包含同一类型的实体，即只能是 Video、Gif 或 Image 之一。`nullcast` 参数控制该推文是否为“仅推广”推文。所有新创建的预定推文默认均为“仅推广”（`nullcast=true`）。如果 `nullcast=false`，则会创建一条自然预定推文。

成功创建预定推文后，响应中会包含一个 `id` 字段，它表示该预定推文本身的唯一标识符。除了此字段外，还会返回一个名为 `tweet_id` 的字段。该字段最初为 `null`，但一旦推文上线，此字段就会被填充为该“上线”推文的 ID。

```
twurl -H 'ads-api.x.com' -X POST "/6/accounts/:account_id/scheduled_tweets" -d 'scheduled_at=2017-12-24T23:59:00Z&text=Happy Holidays!'
```

这将创建以下预定推文：

```json
{
  "request": {
    "params": {
      "text": "Happy Holidays!",

  },
  "data": {
    "completed_at": null,
    "id_str": "917507899668099072",
    "text": "Happy Holidays!",
    "user_id": "3271358660",

    "tweet_id": null,

```

一旦这条预定推文发布，`tweet_id` 字段就会被填充为这条已发布推文的 ID。

**将预定推文关联到广告单元**

虽然预定推文可用于创建自然推文，我们也允许合作伙伴创建“仅推广”（`nullcast=true`）推文，这两种推文都可以与广告单元关联。为此，我们还提供了一个 [POST accounts/:account&#95;id/scheduled&#95;promoted&#95;tweets](https://developer.x.com/content/developer-twitter/en/docs/ads/campaign-management/api-reference/scheduled-promoted-tweets#post-accounts-account-id-scheduled-promoted-tweets) 端点。该端点在一次 API 调用中只允许将一条预定推广推文关联到一个广告单元。若要将多条预定推文关联到同一个广告单元，则需要进行多次 API 调用。

请注意，无法修改已有的预定推广推文。

```
twurl -H 'ads-api.x.com' -X POST "/6/accounts/:account_id/scheduled_promoted_tweets" -d 'line_item_id=a44qc&scheduled_tweet_id=917507899668099072'
```

```json
{
  "data": {
    "line_item_id": "a44qc",
    "id": "26576",
    "created_at": "2017-10-09T22:24:16Z",
    "updated_at": "2017-10-09T22:24:16Z",
    "scheduled_tweet_id": "917507899668099072",
    "tweet_id": null,
    "deleted": false
  },
  "request": {
    "params": {
      "line_item_id": "a44qc",
      "scheduled_tweet_id": 917507899668099100,
      "account_id": "aaaaa"
    }
  }
}
```

此端点只会在给定的预定推文与某个 line item 之间创建关联。一旦广告系列 / line item 的投放日期进入生效期，该 line item 将会自动开始投放对应的已上线推文。虽然我们会在这一步验证预定推文是否处于 `SCHEDULED` 状态，以及该预定推文是否适用于指定的 objective，但不会执行其他验证。任何适用于该 line item 和预定推文的其余验证规则会在推文上线时执行。

为确保广告系列投放不会出现问题，建议将预定推文的 `scheduled_at` 时间设置在广告系列 / line item 投放日期开始之前。

例如，假设预定推文被设置为在广告系列开始日期之后上线（且仅有一条推文与一个 line item 关联），那么广告系列将处于 `ACTIVE` 状态，但由于预定推文尚未上线，将没有可用于投放的创意。

**预定推文管理**

其余一组端点允许 API 使用者管理其所有预定推文和预定推广推文。这些 API 可用于返回所有预定推文的列表（可按给定状态进行可选过滤），以及通过 `id` 查询指定的预定推文。

<div id="what-happens-when-a-scheduled-tweet-goes-live">
  #### 已排程推文发布时会发生什么情况？
</div>

当某条已排程推文即将发布时，换句话说，在 `scheduled_at` 时间点，会发生以下更新：

* 会创建一条“正式发布”的推文，但可能会有最长 1 秒的延迟
* `tweet_id` 会被添加到以下实体：
* 已排程推文
* 已排程推广推文
* 会创建一个新的推广推文实体

<div id="best-practices">
  #### 最佳实践
</div>

在创建或推广预定推文时，建议遵循以下最佳实践：

* 在创建预定推文时，确保推文本身是有效的（例如，一条推文只能包含图片、视频或 Gif 其中一种，而不能同时包含多种类型）
* 确保广告活动投放日期（即 `start_time` 和 `end_time`）与该预定推文的 `scheduled_at` 时间相匹配
* 预定推文的发布时间不应设置为超过未来一年（365 天）之后的时间
* 目前尚不支持预览预定推文的功能（即在创建前预览预定推文）

### 媒体库

#### 简介

Media Library 端点用于管理 X Ads 广告账户中的图片、GIF 和视频。媒体库中的素材可以用于推文和创建卡片，也可以在多个[创意](https://developer.x.com/content/developer-twitter/en/docs/ads/creatives/overview)中复用，从而避免重复上传相同的素材。

<div id="api-endpoints">
  #### API 端点
</div>

* [POST media/upload](https://developer.x.com/content/developer-twitter/en/docs/media/upload-media/api-reference/post-media-upload#post-media-upload)（上传媒体）
* [POST media/upload (chunked)](https://developer.x.com/content/developer-twitter/en/docs/media/upload-media/api-reference/post-media-upload-init#post-media-upload-init)（上传媒体（分块））
* [POST accounts/:account&#95;id/media&#95;library](https://developer.x.com/x-ads-api/creatives#get-accounts-account-id-media-library#post-accounts-account-id-media-library)（将媒体添加到媒体库）

<div id="adding-to-the-library">
  #### 添加到媒体库
</div>

将媒体添加到媒体库是一个由两步组成的流程。首先，使用 [POST media/upload](https://developer.x.com/content/developer-twitter/en/docs/media/upload-media/api-reference/post-media-upload#post-media-upload) 端点或 [POST media/upload (chunked)](https://developer.x.com/content/developer-twitter/en/docs/media/upload-media/api-reference/post-media-upload-init#post-media-upload-init) 这一组端点上传媒体资源。（有关我们的分段上传流程的详细信息，请参阅 [Chunked media upload](https://developer.x.com/content/developer-twitter/en/docs/media/upload-media/uploading-media/chunked-media-upload) 指南。）

```
twurl -X POST -H upload.x.com "/1.1/media/upload.json?additional_owners=756201191646691328" --file latte.jpeg --file-field "media"
```

```json
{
   "media_id":966947208837742592,
   "media_id_string":"966947208837742592",
   "size":74194,
   "expires_after_secs":86400,
   "image":{
      "image_type":"image/jpeg",
      "w":800,
      "h":418
   }
}
```

接下来，使用媒体 ID，通过 [POST accounts/:account&#95;id/media&#95;library](https://developer.x.com/x-ads-api/creatives#get-accounts-account-id-media-library#post-accounts-account-id-media-library) 端点将该媒体添加到广告账户的媒体库中。

```

```

<div id="request-parameters">
  #### 请求参数
</div>

所有发往 Media Library 的 POST 请求都需要一个媒体标识符。该值会在上传步骤中返回。使用 media&#95;id（如上例所示）时，还必须指定 media&#95;category。共有四种可能的类别值：AMPLIFY&#95;VIDEO、TWEET&#95;GIF、TWEET&#95;IMAGE 和 TWEET&#95;VIDEO。

可以为 Media Library 中的对象选择性地设置 name 和 file&#95;name 值。这些属性可帮助用户在媒体库中区分不同的媒体变体。

对于视频，还可以设置标题和描述。这些值用于在调用 [POST accounts/:account&#95;id/tweet](https://developer.x.com/content/developer-twitter/en/docs/ads/creatives/api-reference/tweets#post-accounts-account-id-tweet) 端点时，作为 video&#95;title 和 video&#95;description 请求参数传入。在推文中，这些文本显示在视频下方。

<div id="attributes">
  #### 属性
</div>

Media Library 正式引入了 `media_key` 的概念。它是媒体库中对象的唯一标识符。Media key 是形如 13&#95;875943225764098048 的字符串值。我们的所有 card 相关端点都完全支持它。

此外，Media Library 响应中还包含 `media_id`，以字符串形式表示。对于当前尚不接受 media key 的资源，响应中会包含该字段：[推文](https://developer.x.com/content/developer-twitter/en/docs/ads/creatives/api-reference/tweets#post-accounts-account-id-tweet)*、[推文预览](https://developer.x.com/content/developer-twitter/en/docs/ads/creatives/api-reference/tweets#get-accounts-account-id-tweet-preview)* 和 [计划推文](https://developer.x.com/content/developer-twitter/en/docs/ads/creatives/api-reference/scheduled-tweets#post-accounts-account-id-scheduled-tweets)。我们正致力于在所有端点中支持 media key。

`aspect_ratio` 属性会在 GIF 和视频中返回。它可用于筛选仅接受特定纵横比的 card 所使用的媒体。

*这些端点支持 `video_id` 参数，该参数是一个 media key。

<div id="identifying-cards">
  ### 识别卡片
</div>

#### 简介

Card 是一种可自定义的媒体广告格式，可以与网站、应用或号召性用语关联，用于推动特定的用户互动，例如发起私信。它们可以附加到推文、预定发送的推文或推文草稿中。

在 Tweet 对象中，可以通过以下两种方式之一引用 Card：通过 Card 的 `card_uri`，或通过其 `preview_url`。下面给出了每种方式的示例值。

| card&#95;uri | preview&#95;url |
| :--- | :--- |
| card://1043282691834048513 | https://cards.x.com/cards/18ce54d4x5t/68w3s |

**注意**：从 Ads API 版本 3 起，对于新创建的 Card，在 cards 响应中只会生成并返回 `card_uri`。

**注意**：从 Ads API 版本 5 起，在 cards 响应中将不再返回 `preview_url`。

Tweet 对象响应中的引用类型取决于创建该推文的方式。换句话说，如果推文是使用 `card_uri` 请求参数创建的，那么响应中将包含该 card URI 值。另一方面，如果 `preview_url` 被包含为推文文本的一部分，那么响应中将包含该预览 URL。

<div id="identifying-media">
  ### 标识媒体
</div>

#### 简介

媒体（图片、GIF 和视频）可以添加到推文和卡片中。此外，视频可以用作前贴片素材，图片可以在 [X Audience Platform](https://developer.x.com/en/docs/ads/measurement/overview/twitter-audience-platform) 上进行推广。本节介绍如何在这些实体中查找媒体引用。

有两种媒体标识：ID 和 key。下面给出了每种标识的示例值。

| **媒体 ID** | **媒体 key** |
| :--- | :--- |
| 1029825579531807971 | 13&#95;1029825579531807971 |

媒体 key 由 ID 加上一个数字前缀和一个下划线组成。

<div id="images">
  #### Images
</div>

下表展示了当前每个与图片相关的资源在其响应中可用的标识符类型，以及对应的属性名称。

| **Resource** | **Identifier** | **Attribute(s)** |
| :--- | :--- | :--- |
| Image cards | None |  |
| Tweet | Both | `entities["media"]["id_str"]`  `entities["media"]["media_key"]` |
| Scheduled Tweet | Both | `media_ids` and `media_keys` |
| Draft Tweet | Both | `media_ids` and `media_keys` |
| Account Media | None |  |
| Media Library | Both | `media_id` and `media_key` |

Image cards 和 Account Media 资源中的图片不包含对任何媒体标识符的引用。Tweet 仅包含媒体 ID。Scheduled Tweet 和 Draft Tweet 同时包含媒体 ID 和 media key。Media Library 也会同时返回这两者。

对于 Tweet，`entities["media"]` 数组中对象里的 `id` 和 `id_str` 字段对应媒体 ID。当一条 Tweet 包含多张图片时，对每个媒体实体的引用只能在 `extended_entities["media"]` 中找到。

除了对标识符的引用之外，通常还需要能够访问图片的 URL。

| **Resource** | **Attribute(s)** | **Format** |
| :--- | :--- | :--- |
| Image cards | `image` | .jpg |
| Tweet* | `entities["media"][0]["media_url"]` or `extended_entities["media"][i]["media_url"]` | .jpg |
| Scheduled Tweet | None |  |
| Draft Tweet | None |  |
| Account Media | `media_url` | .jpg |
| Media Library | `media_url` | .jpg |

* 此 URL 的位置取决于 Tweet 是包含单张图片还是多张图片。

所有 Image cards 都包含一个 image 响应属性，其中包含 X 图片 URL。（对于 image app download cards，该属性名称为 `wide_app_image`。）

对于 Tweet，media URL 的位置取决于媒体类型以及所使用的 endpoint。对于仅包含一张图片的 Tweet，URL 可以在 `entities["media"][0]["media_url"]` 中找到，这对 Ads API 和 Standard API 都适用。然而，当 Tweet 包含多张图片时，这些 URL 只能在 `extended_entities["media"][i]["media_url"]` 中找到，而这仅在 Standard API 中可用。

<div id="video">
  #### 视频
</div>

下表显示了当前在各个与视频相关的资源的响应中可用的标识符类型，以及相应的属性名称。

| **资源** | **标识符** | **属性** |
| :--- | :--- | :--- |
| 视频卡片 | 可能为任一类型 | `video_content_id` |
| 视频投票卡片 | 无 |  |
| 推文 | 两者都有 | `entities["media"]["id_str"]`  `entities["media"]["media_key"]` |
| 预排推文 | 两者都有 | `media_ids` 和 `media_keys` |
| 草稿推文 | 两者都有 | `media_ids` 和 `media_keys` |
| 账户媒体 | 媒体 key | `video_id` |
| 媒体库 | 两者都有 | `media_id` 和 `media_key` |

虽然视频卡片（带视频的投票卡片除外）包含 `video_content_id` 响应属性，但返回值的类型并不一致。在某些情况下，它是媒体 ID；在另一些情况下，它是媒体 key。

关于如何访问视频 URL 的信息如下所示。

| **资源** | **属性** | **格式** |
| :--- | :--- | :--- |
| 视频卡片 | `video_url` 和 `video_hls_url` | .vmap  .m3u8 |
| 带视频的推文 | `extended_entities["media"][i]["video_info"]["variants"][j]["url"]` | .mp4 |
| 预排推文 | 无 |  |
| 草稿推文 | 无 |  |
| 账户媒体 | 无 |  |
| 媒体库 | `media_url` | .mp4 |

视频卡片包含 `video_url` 和 `video_hls_url` 响应属性，分别对应 .vmap 和 .m3u8 URL。

<div id="media-library">
  #### 媒体库
</div>

在某些情况下，需要获取媒体资产的更多信息。比如在处理视频卡片时，你可能需要获取 mp4 URL 而不是 vmap URL。这些信息可以在媒体库中获取。有关可用信息的详细说明，请参阅我们的[媒体库指南](https://developer.x.com/content/developer-twitter/en/docs/ads/creatives/guides/media-library)。大多数属于该广告账号 FULL promotable 用户的资产都可以在媒体库中找到，不过也有一些例外。

**获取媒体**

如上所述，图片卡片不包含对 media ID 或 media key 的引用。因此，无法通过媒体库来获取它们的资产。[Account Media](https://developer.x.com/content/developer-twitter/en/docs/ads/creatives/api-reference/account-media#account-media) 中的图片也是如此。

在创建视频卡片之前，视频资产必须已经是媒体库（或其前身 Videos 资源）的一部分。因此，这些资产始终可以在媒体库中被检索到。Account Media 中的 PREROLL 资产情况也是如此。

最后，推文中的媒体始终保证存在于媒体库中。

在考虑资源响应是否包含可用于查询的标识符的前提下，下表总结了哪些资产可以在媒体库中被检索到。

| **资源** | **是否在媒体库中** |
| :--- | :--- |
| 图片卡片 | 否 |
| 视频卡片 | 是* |
| 推文（任意媒体）** | 是 |
| 预定推文 | 是 |
| 草稿推文 | 是 |
| Account Media 图片 | 否 |
| Account Media 视频（`PREROLL`） | 是 |

* 适用于 `video_content_id` 为 media key 的卡片。当该值为 media ID 时，资产依然存在于媒体库中，但要检索它，需要在其前面追加一个数字前缀和下划线。\
** 推文仅返回 media ID。尽管资产保证存在于媒体库中，但要获取它，同样需要在其前面追加一个数字前缀和下划线。

**与 Account Media 的交互**

有两种情况会使添加到媒体库的媒体资产自动添加到 Account Media 资源中。

* 当将 AMPLIFY&#95;VIDEO 资产添加到媒体库时，它会自动作为 Account Media 资产添加，创意类型为 PREROLL。
* 当将具有特定尺寸的图片（参见我们[枚举页面](https://developer.x.com/content/developer-twitter/en/docs/ads/general/overview/enums)中的 “Creative Types”）添加到媒体库时，它们会自动作为 Account Media 资产添加。创意类型（例如 INTERSTITIAL）取决于图片的尺寸。

<div id="tweets">
  ### 推文
</div>

#### 简介

X Ads API 支持三种类型的推文：已发布、已计划发布和草稿。

<div id="nullcasted-tweets">
  #### 仅推广（nullcasted）推文
</div>

推文可以是仅推广（nullcasted，亦称“仅用于推广”）或自然推文。仅推广推文在发布后不会出现在用户的公共时间线上，但仍然是公开可见的。相反，自然推文会展示给用户的关注者，并出现在用户的公共时间线上。

**创建推文**

三个用于创建 Tweet 的端点（endpoint）中，每一个都支持一个布尔值类型的 `nullcast` 参数，API 用户可以通过该参数选择创建仅推广推文或自然推文。仅推广推文既可以由用户自己创建，也可以由任何被授权代表该用户创建推文的人创建。自然推文只能由[完全可推广用户](https://developer.x.com/content/developer-twitter/en/docs/tutorials/ads-api-hierarchy-terminology#promotable-users)创建。

**更新推文**

对于已计划发送和草稿状态的推文，可以更新其 `nullcast` 属性。对于计划发送的推文，可以在该推文的 `scheduled_at` 时间之前进行编辑。草稿推文可以无限期编辑。但一旦发布，就无法再在仅推广推文与自然推文之间进行转换。

<div id="promoting-tweets">
  #### 推广推文
</div>

只有已发布和已排期的推文才可以推广。这些推文可以是 nullcasted 推文或自然推文，类型不限。广告主既可以推广自己的推文，也可以在获得许可的前提下推广其他用户的推文。（参见：[Promoting another user&#39;s Tweets](https://developer.x.com/content/developer-twitter/en/docs/tutorials/promoting-another-users-content) 了解更多信息。）

在单个广告系列中可以推广多条推文。同样，单条推文也可以在一个或多个广告系列中推广。

要推广已发布的推文，请使用 [POST accounts/:account&#95;id/promoted&#95;tweets 端点](https://developer.x.com/content/developer-twitter/en/docs/ads/campaign-management/api-reference/promoted-tweets#post-accounts-account-id-promoted-tweets)。这会将已发布的推文关联到一个广告单元（line item）。要推广已排期的推文，请使用 [POST accounts/:account&#95;id/scheduled&#95;promoted&#95;tweets](https://developer.x.com/content/developer-twitter/en/docs/ads/campaign-management/api-reference/scheduled-promoted-tweets#post-accounts-account-id-scheduled-promoted-tweets) 端点。

<div id="tweet-ids">
  #### 推文 ID
</div>

已发布、已排期和草稿推文的 ID 均为[数值型](https://developer.x.com/content/developer-twitter/en/docs/basics/twitter-ids)——它们是 64 位无符号整数。例如，下列已发布推文的 ID 为 1166476031668015104。

  },

      "line_item_id": "6c62d",

<div id="carousels">
  ### 轮播广告
</div>

<div id="introduction">
  #### 介绍
</div>

X Ads API 支持创建和检索视频轮播和图片轮播。轮播是一种卡片类型，可以包含 2 到 6 个媒体资源。轮播卡片可以将用户引导至某个网站，或鼓励他们安装移动应用程序。有关轮播广告的优势、最佳实践和常见问题的更多信息，请参阅我们的 [Carousel Ads on X](https://business.x.com/en/advertising/carousels.html) 页面。

与其他卡片类型一样，轮播可以用于推文，这些推文随后可以被推广。整个流程与你已经熟悉的步骤相同：

1. 上传媒体
2. 创建卡片
3. 创建推文
4. 推广推文

唯一的区别在于卡片的创建方式。虽然其他卡片创建请求接受查询参数，但轮播卡片创建请求只接受 JSON 格式的 POST 请求体。

<div id="endpoints">
  #### 端点
</div>

Ads API 支持创建和获取轮播卡片。

要创建任何类型的轮播卡片，请使用 [POST accounts/:account&#95;id/cards](https://developer.x.com/en/docs/twitter-ads-api/creatives/api-reference/cards#post-accounts-account-id-cards) 端点。要获取轮播卡片，请使用 [GET accounts/:account&#95;id/cards](https://developer.x.com/en/docs/twitter-ads-api/creatives/api-reference/cards#get-accounts-account-id-cards) 端点。

<div id="json-post-body">
  #### JSON POST Body
</div>

轮播由两个组件创建。第一个组件指定要使用的媒体素材。第二个组件指定与网站或应用相关的信息。

具体来说，轮播卡片是按以下顺序组合这些组件创建的：

* 一个 `SWIPEABLE_MEDIA` 组件，用于接收一个媒体键（media keys）数组
* *以下组件中的一个*：
* 一个 `DETAILS` 组件，用于指定网站信息
* 一个 `BUTTON` 组件，用于指定应用信息

`SWIPEABLE_MEDIA` 组件必须包含一个 `media_keys` 数组，你可以在其中指定 2 到 6 个图片或视频。传入这些媒体键的顺序将决定它们被渲染时的顺序。

```
{
  "type": "SWIPEABLE_MEDIA",
  "media_keys": [
    "13_1089771253848666112",
    "13_1191948012077092867"
  ]
}
```

提醒一下，你可以通过向 [GET accounts/:account&#95;id/media&#95;library](https://developer.x.com/en/docs/twitter-ads-api/creatives/api-reference/media-library#get-accounts-account-id-media-library) 端点发出请求来获取媒体 key。

第二个组件对象的结构取决于你是希望将用户引导到网站，还是鼓励他们安装应用。下表总结了这两种选项。（**注意**：表中列出的所有键都是必需的。）

|                            | **Website**                                                        | **App**                                           |
| :------------------------- | :----------------------------------------------------------------- | :------------------------------------------------ |
| Specify the component type | `"type": "DETAILS"`                                                | `"type": "BUTTON"`                                |
| Title/Label                | `"title": "X"`                                                     | `"label": { "type": "ENUM", "value": "INSTALL" }` |
| Destination                | `"destination": { "type": "WEBSITE", "url": "https://www.x.com" }` | `"destination": { "type": "APP", ... }`           |

综合以上内容，下面展示了一个网站轮播组件的 JSON POST 请求体示例。

```
{
  "name": "website carousel",
  "components": [
    {
      "type": "SWIPEABLE_MEDIA",
      "media_keys": [
        "13_1089771253848666112",
        "13_1191948012077092867"
      ]
    },
    {
      "type": "DETAILS",
      "title": "X",
      "destination": {
        "type": "WEBSITE",
        "url": "https://www.x.com"
      }
    }
  ]
}
```

`BUTTON` 组件中的应用目标对象需要提供国家代码以及至少一个应用标识符，还可以（可选）包含深度链接。有关这些字段的说明，请参阅[参考文档](https://developer.x.com/en/docs/twitter-ads-api/creatives/api-reference/cards#app-destination)。

综合以上内容，下面展示了一个应用轮播卡片的 JSON POST 请求体示例。

```
{
  "name": "app carousel",
  "components": [
    {
      "type": "SWIPEABLE_MEDIA",
      "media_keys": [
        "13_1089771253848666112",
        "13_1191948012077092867"
      ]
    },
    {
      "type": "BUTTON",
      "label": {
        "type": "ENUM",
        "value": "INSTALL"
      },
      "destination": {
        "type": "APP",
        "country_code": "US",
        "googleplay_app_id": "com.twitter.android",
        "iphone_app_id": "333903271"
      }
    }
  ]
}
```

<div id="creative-metadata-tagging">
  ### 创意元数据标记
</div>

<div id="introduction">
  #### 介绍
</div>

本指南面向创意合作伙伴、代理商和创意开发者，用于为在 X 活动中使用的素材添加标签，以更好地了解单个素材的价值和表现。

**注意：** 媒体素材只能由创建该媒体素材的合作伙伴或开发者进行标记。如果媒体素材的使用者并未创建该媒体素材，请勿为其添加元数据标签。

Creative Metadata Tagging 功能可对由创意合作伙伴（Creative Partners）创建的图片和视频进行归因，无论该素材在 X 上由谁上传、从何处上传。为在创意素材与创意合作伙伴之间建立关联，本功能采用 [XMP](https://exiftool.org/TagNames/XMP.html) 标准。

<div id="tagging-creative-assets">
  #### 标记创意素材
</div>

下表展示了当前在每个与图片相关的资源的响应中可用的标识符类型，以及对应的属性名称。标记创意素材需要使用标记工具。推荐使用 [ExifTool](https://exiftool.org/)，这是一个跨平台的 Perl 库以及一个用于读取、写入和编辑元数据信息的[命令行应用程序](https://exiftool.org/exiftool_pod.html)。请参阅其支持的所有[文件类型](https://exiftool.org/#supported)。

请按照提供的[ExifTool 安装说明](https://exiftool.org/install.html)进行安装。[Homebrew](https://formulae.brew.sh/) 也提供了软件包，通过提供适用于 macOS 和 Linux 的 [exiftool 安装命令](https://formulae.brew.sh/formula/exiftool)进一步简化安装过程。通过在命令行中输入 exiftool -ver 并查看返回的工具版本号，确认你的工具已正确安装。你可以在 [ExifTool 文档](https://exiftool.org/)中了解更多 ExifTool 命令参数的信息。

创意合作伙伴可以在新的或现有的创意素材上，将其 X app&#95;id 写入 contributor XMP 标签和 date 标签的元数据中。创意素材在[上传媒体](https://developer.x.com/en/docs/twitter-api/v1/media/upload-media/overview)时将遵循现有的大小限制。 

**注意：** X 对 contributor XMP 标签的使用，确保元数据仅用于记录 X 上广告活动的取值。

`exiftool -contributor="<YOUR APP ID>" -creative_file.jpg`

  #### POST accounts/:account_id/cards
</div>

创建一个与指定账户关联的新卡片。

卡片创建请求只接受 JSON 格式的 POST 请求体。`Content-Type` 必须设置为 `application/json`。

有关详细的使用示例，请参阅我们的 [轮播卡片指南](https://developer.x.com/en/docs/twitter-ads-api/creatives/guides/carousels)。

<div id="resource-url">
  #### 资源 URL
</div>

`https://ads-api.x.com/12/accounts/:account_id/cards`

#### 参数

JSON POST 请求体必须包含卡片的 `name` 字段和一个由 `components` 组成的数组。组件以对象的形式表示，用于描述该卡片面向广告主的属性。

下面的示例展示了有效负载的一般结构（但其中的信息并非实际可用）。

```
{
  "name": "some name",
  "components": [
    {
      "type": "TYPE_ENUM",
      "key": "value"
    }
  ]
}
```

组件的更多信息见下文。

| Name                              | Description                                                                                                                                                                                                      |
| :-------------------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| account&#95;id   *required*       | 所使用广告账户的标识符。出现在资源路径中，除 [GET accounts](https://developer.x.com/en/docs/ads/campaign-management/api-reference/accounts#get-accounts) 之外，一般是所有 Advertiser API 请求的必需参数。指定的账户必须与已通过身份验证的用户关联。 类型：字符串 示例：`18ce54d4x5t` |
| name   *required*                 | 卡片的名称。最大长度：80 个字符。 类型：字符串 示例：`component based card`                                                                                                                                                              |
| components   *sometimes required* | 描述用于创建卡片的组件。更多信息见下文。不能与 `slides` 同时指定。**注意**：组件的顺序很重要。 类型：对象数组                                                                                                                                                   |
| slides   *sometimes required*     | 使用这个数组的数组来创建多目标轮播（Multi-Destination Carousels）。将每张卡片描述为一组组件。每个 slide 都应是对一张卡片的完整表示。不能与 `components` 同时指定。**注意**：每个 slide 的顺序很重要。 类型：数组的数组                                                                        |

<div id="components">
  #### 组件
</div>

每个组件都必须包含一个 `type` 字段，用于确定对象的 schema。Ads API 支持以下组件类型，分为媒体类组件和描述类组件。

* 媒体：
* `MEDIA`：单个视频或图像
* `SWIPEABLE_MEDIA`：2–6 个视频或图像
* 描述：
* `DETAILS`
* `BUTTON`

每个组件都有一组必需字段（除了 `type` 键之外）。这些字段列在下表中。

| Component `type`  | Field                   | Value type       |
| :---------------- | :---------------------- | :--------------- |
| `MEDIA`           | `media_key`             | string           |
| `SWIPEABLE_MEDIA` | `media_keys`            | array of strings |
| `DETAILS`         | `title`   `destination` | string   object  |
| `BUTTON`          | `label`   `destination` | object   object  |

下面是在 `components` 数组中作为一项时的 `BUTTON` 组件示例（刻意省略 `name` 键）。（省略号表示在这些位置还需要提供更多信息。）

```
{
  "components": [
    {
      "type": "BUTTON",
      "label": {
        ...
      },
      "destination": {
        ...
      }
    }
  ]
}
```

指定组件对象的顺序决定了它们自上而下的渲染顺序。Cards 必须使用一个基于媒体的组件，并搭配一个 `DETAILS` 或 `BUTTON` 组件来创建。基于描述的组件会渲染在媒体组件下方，并具有关联的目标地址，可以是 URL 或移动应用。

**Label**

Labels 定义按钮上显示的文本，因此只适用于 `BUTTON` 组件。Label 对象包含两个必需的键：`type` 和 `value`。`type` 必须设置为 `ENUM`，而 `value` 可以是以下之一：`BOOK`、`CONNECT`、`INSTALL`、`OPEN`、`ORDER`、`PLAY` 或 `SHOP`。

在前一个示例的基础上，下面展示了 `BUTTON` 组件中的 `label` 对象。

```
{
  "components": [
    {
      "type": "BUTTON",
      "label": {
        "type": "ENUM",
        "value": "INSTALL"
      },
      "destination": {
        ...
      }
    }
  ]
}
```

**目标位置**

目标位置是广告主希望引导用户前往的位置。在 `DETAILS` 或 `BUTTON` 组件中始终为必需字段。目标位置有两种类型：`WEBSITE` 或 `APP`。

**注意**：网站目标位置只能与 `DETAILS` 组件一起使用，而应用目标位置只能与 `BUTTON` 组件一起使用。

**网站目标位置**

| 名称                | 描述                                                                         |
| :---------------- | :------------------------------------------------------------------------- |
| type   *required* | 目标位置的类型，用于决定其架构（schema）。 类型：枚举  可能的取值：`WEBSITE`                            |

<div id="get-accountsaccount_idtweets">
  #### GET accounts/:account_id/tweets
</div>

获取该账户的完整可投放用户（默认）或通过 `user_id` 参数指定用户的推文详情。该用户可以是此账户下的任意一个[可投放用户](https://developer.x.com/en/docs/ads/campaign-management/api-reference/promotable-users)。

<div id="resource-url">
  #### 资源 URL
</div>

`https://ads-api.x.com/12/accounts/:account_id/tweets`

#### 参数

| 名称 | 描述 |
| :--- | :--- |
| account&#95;id   *必需* | leveraged account（杠杆账户）的标识符。出现在资源路径中，一般是除 [GET accounts](https://developer.x.com/en/docs/ads/campaign-management/api-reference/accounts#get-accounts) 之外所有 Advertiser API 请求的必需参数。指定的账户必须与已通过身份验证的用户关联。 类型：字符串 示例：`18ce54d4x5t` |
| tweet&#95;type   *必需* | 指定 `tweet_ids` 的推文类型。 类型：enum 可能的取值：`DRAFT`、`PUBLISHED`、`SCHEDULED` |
| count   *可选* | 指定每个请求尝试检索的记录数。 类型：int 默认值：`200` 最小值与最大值：`1`、`1000` |
| cursor   *可选* | 指定用于获取下一页结果的游标。更多信息参见 [Pagination](https://developer.x.com/x-ads-api/introduction)。 类型：字符串 示例：`AAAAAFhLRpQLNF-sGBSgAA` |
| include&#95;mentions&#95;and&#95;replies   *可选* | 是否从可用推文列表中过滤掉提及和回复。 类型：boolean 默认值：`false` 可能的取值：`true`、`false` |
| name   *可选* | 用于按 `name` 限定推文范围的可选查询参数。省略此参数以检索全部推文。最大长度：80 个字符。 **注意**：采用不区分大小写的前缀匹配。 类型：字符串 示例：`dtc` |
| timeline&#95;type   *可选* | 指定是否返回 nullcast（又称“Promoted-only”）推文、自然推文，或两者皆返回。 类型：enum 默认值：`NULLCAST` 可能的取值：`ALL`、`NULLCAST`、`ORGANIC` |
| trim&#95;user   *可选* | 是否在推文响应中排除用户对象。启用后，返回的用户对象中仅包含该推文作者的用户 id。 类型：boolean 默认值：`false` 可能的取值：`true`、`false` |
| tweet&#95;ids   *可选* | 以逗号分隔的标识符列表。最多可提供 200 个 id。 **注意**：这些 id 应与指定的 `tweet_type` 相对应。例如，如果传入的是计划推文（Scheduled Tweet）的 id，则 `tweet_type` **必须** 为 `SCHEDULED`，该推文才会在响应中返回。 类型：long 示例：`1122911801354510336,1102836745790316550` |
| user&#95;id   *可选* | 指定用于限定推文所属用户的参数。如果未设置，则默认为该账户上的 `FULL` 级别可推广用户。 类型：long 示例：`756201191646691328` |

<div id="post-accountsaccount_idtweet">
  #### POST accounts/:account_id/tweet
</div>

为该账户的完整可推广用户（默认）或通过 `as_user_id` 参数指定的用户创建一条推文。支持创建不投放（nullcasted，默认）和自然推文。不投放推文不会出现在公开时间线中，也不会投放给关注者。这两种类型都可以用于广告系列。

如果已认证用户不是此账户的 `FULL` 可推广用户，请通过调用 [GET accounts/:account&#95;id/authenticated&#95;user&#95;access](https://developer.x.com/en/docs/ads/campaign-management/api-reference/authenticated-user-access#get-accounts-account-id-authenticated-user-access) 端点来确定其是否有权以该用户身份创建推文。权限为 `TWEET_COMPOSER` 表示该用户可以使用此端点代表 `FULL` [可推广用户](https://developer.x.com/en/docs/ads/campaign-management/api-reference/promotable-users#get-accounts-account-id-promotable-users) 创建不投放推文。

在通过 [upload.x.com 端点](https://developer.x.com/rest/reference/post/media/upload) 上传媒体时，请将 `additional_owners` 参数中的 `user_id` 值设置为与调用此端点时传入的 `as_user_id` 值相同。
