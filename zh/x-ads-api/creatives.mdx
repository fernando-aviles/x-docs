<div id="overview">
  ## 概览
</div>

创意素材是可以在广告系列中推广的任何实体。帖子可以包含文本、图片、GIF、视频或卡片。卡片可以包含图片或视频。

图片、GIF 或视频创意素材通过 [POST media/upload](/zh/x-api/media/upload-media#post-media-upload) 上传 —— 这是一个仅支持图片的简单上传端点 —— 或者通过 POST media/upload（分片上传）端点上传。这些可以添加到

卡片：

* POST accounts/:account&#95;id/cards
  推文：
* POST accounts/:account&#95;id/tweets - 要将卡片添加到推文，请使用 card&#95;uri 参数。
  预定推文：
* POST accounts/:account&#95;id/scheduled&#95;tweets

有关卡片的更多详细信息，请参阅 Cards 页面。Promoted Video 页面提供了将视频与卡片或推文关联的详细信息。

### 卡片

Ads API 支持多种卡片类型，可在推文中使用，并可在广告活动中推广。**注意**：一旦推文发布，卡片的详细信息将对所有人可见。这可能包括拥有该卡片的用户的相关信息。

<div id="image">
  #### 图片
</div>

以下图片规范适用于 [Cards](/zh/x-ads-api/creatives#cards-2) 所使用的素材。图片大小必须不超过 3MB，且宽度至少为 800px。此外，我们支持以下宽高比：

* Website：1:1 和 1.91:1
* Image App Download：1:1 和 1.91:1
* Poll：1.91:1
* Image Conversation：1.91:1
* Image Direct Message：1.91:1

我们支持以下图片格式：.bmp、.jpeg 和 .png。

<div id="video">
  #### 视频
</div>

以下视频规范适用于 [Cards](/zh/x-ads-api/creatives#cards-2) 中使用的素材。我们支持以下宽高比：

* 视频网站卡片：16:9 和 1:1
* 视频 App 下载卡片：16:9 和 1:1
* 投票卡片：16:9
* 视频会话卡片：16:9
* 视频私信卡片：16:9

<div id="promoted-video">
  ### 推广视频
</div>

本文档对通过 Ads API 上传和推广视频的流程进行简要概述。

Ads API 支持在 [推文](/zh/x-ads-api/creatives#tweets-2) 中以及以下卡片中使用推广视频：

* [视频网站](https://devcommunity.x.com/t/ads-api-version-11/168814)
* [视频 App 下载](https://devcommunity.x.com/t/ads-api-version-11/168814)
* [视频对话](/zh/x-ads-api/creatives#video-conversation-cards)

首先，使用 [POST media/upload (chunked)](https://developer.x.com/en/docs/media/upload-media/api-reference/post-media-upload-init.html) 端点上传视频。使用 `media_id`，通过 POST accounts/:account&#95;id/videos 端点将视频关联到广告账户。该视频的 `id`（有时也称为 `media_key`）将在后续请求中使用。它是一个字符串，以一个整数开头，后跟下划线，最后是一个长整型值。例如：`13_875943225764098048`。

<div id="promoted-video-in-tweets">
  #### 推文中的推广视频
</div>

要创建一条推文，请使用 [POST accounts/:account&#95;id/tweet](/zh/x-ads-api/creatives#get-accounts-account-id-tweets) 这个 endpoint，并提供视频的 `id`。在此步骤中，你还可以提供视频标题、描述以及行动号召（CTA）。这些字段将直接展示给用户。

<div id="promoted-video-in-cards">
  #### 卡片中的推广视频
</div>

Video App Download 卡片和 Video Conversation 卡片支持添加封面图片。使用 [POST media/upload](https://developer.x.com/en/docs/media/upload-media/api-reference/post-media-upload.html) 端点上传一张要在这些卡片中使用的图片。

使用以下任一端点创建卡片：

* [POST accounts/:account&#95;id/cards/video&#95;website](https://devcommunity.x.com/t/ads-api-version-11/168814)
* [POST accounts/:account&#95;id/cards/video&#95;app&#95;download](https://devcommunity.x.com/t/ads-api-version-11/168814)
* [POST accounts/:account&#95;id/cards/video&#95;conversation](https://devcommunity.x.com/t/ads-api-version-11/168814)

使用视频的 `id`，以及可选的图片 `media_id`（作为封面图片）。

最后，使用 POST accounts/:account&#95;id/tweet 端点创建推文。通过 `card_uri` 参数将卡片附加到推文上。

<div id="general-information">
  #### 一般信息
</div>

有关通过 API 上传视频的详细指南，请参阅 [视频上传指南](https://developer.x.com/en/docs/media/upload-media/uploading-media.html)。

视频也可以作为前贴片素材进行投放。有关详细说明，请参阅 [Video Views Pre-roll 目标指南](/zh/x-ads-api/campaign-management#video-views-preroll-objective)。

* （截至 2015-10-22）在上传用于推广内容的视频时，对于所有向 [POST media/upload (chunked)](https://developer.x.com/en/docs/media/upload-media/api-reference/post-media-upload-init.html) 端点发出的 `INIT` 命令请求，必须将 `media_category` 参数设置为 `amplify_video`。使用此参数可确保视频被异步预处理，并为在推广内容中的使用做好准备。上传视频后，可以使用 `STATUS` 命令检查异步处理是否完成。
* 目前允许的推广视频的最长时长为 10 分钟，文件大小不超过 500MB。
* 上传的视频应为 mp4 或 mov 格式。
* 上传视频通常会被快速处理，但处理时间会因视频长度和文件大小而有所不同。
* 上传的封面图片应为 png 或 jpg 格式。没有纵横比或尺寸要求，但封面图片会被调整以适配视频播放器。

<div id="scheduled-tweets">
  ### 定时发布推文
</div>

<div id="introduction">
  #### 介绍
</div>

定时推文允许广告主或用户创建一条可以在未来指定时间发布的推文。除了可以创建和管理这些推文外，API 还支持将这些推文关联到某个 line item，以便在推文上线后进行推广。这样可以让广告主提前创建原生推文，并在任何关键活动开始前规划他们的营销素材。例如，预先创建一条推文创意，使其能在新品发布公告发布的同一时间立即上线。

Scheduled Tweets API 端点所提供的全部功能如下所示：

* 创建、修改并查看新建的定时推文
* 将一条定时推文关联到一个 line item
* 查询和管理已有的定时推文
* 当一条定时推文上线后，获取上线推文的 `id`

<div id="api-endpoints">
  #### API 端点
</div>

所有与上述功能相关的端点如下：

<div id="scheduled-tweet-management">
  #### 定时推文管理
</div>

* [GET accounts/:account&#95;id/scheduled&#95;tweets](/zh/x-ads-api/creatives#get-accounts-account-id-scheduled-tweets)（检索所有定时推文）
* [GET accounts/:account&#95;id/scheduled&#95;tweets/:scheduled&#95;tweet&#95;id](/zh/x-ads-api/creatives#get-accounts-account-id-scheduled-tweets)（使用其 `id` 查询特定定时推文）
* [POST accounts/:account&#95;id/scheduled&#95;tweets](/zh/x-ads-api/creatives#post-accounts-account-id-scheduled-tweets)（创建新的定时推文）
* [PUT accounts/:account&#95;id/scheduled&#95;tweets/:scheduled&#95;tweet&#95;id](/zh/x-ads-api/creatives#example-request-39)（修改现有的定时推文）
* [DELETE accounts/:account&#95;id/scheduled&#95;tweets/:scheduled&#95;tweet&#95;id](/zh/x-ads-api/creatives#example-request-40)（使用其 `id` 删除定时推文）
* [GET accounts/:account&#95;id/scheduled&#95;tweets/preview/:scheduled&#95;tweet&#95;id](/zh/x-ads-api/creatives#scheduled-tweets-2)（预览现有的定时推文）

<div id="scheduled-promoted-tweets">
  #### 预定推广推文
</div>

* [GET accounts/:account&#95;id/scheduled&#95;promoted&#95;tweets](/zh/x-ads-api/campaign-management#get-accounts-account-id-scheduled-promoted-tweets)（获取所有预定推广推文的列表）
* [GET accounts/:account&#95;id/scheduled&#95;promoted&#95;tweets/:scheduled&#95;promoted&#95;tweet&#95;id](/zh/x-ads-api/campaign-management#get-accounts-account-id-scheduled-promoted-tweets-scheduled-promoted-tweet-id)（根据其 `id` 查询预定推广推文）
* [POST accounts/:account&#95;id/scheduled&#95;promoted&#95;tweets](/zh/x-ads-api/campaign-management#post-accounts-account-id-scheduled-promoted-tweets)（创建新的预定推广推文）
* [DELETE accounts/:account&#95;id/scheduled&#95;promoted&#95;tweets/:scheduled&#95;promoted&#95;tweet&#95;id](/zh/x-ads-api/campaign-management#delete-accounts-account-id-scheduled-promoted-tweets-scheduled-promoted-tweet-id)（根据其 `id` 删除现有的预定推广推文）

<div id="scheduled-tweet-view">
  #### 预定推文视图
</div>

* [GET accounts/:account&#95;id/scheduled&#95;tweets/preview/:scheduled&#95;tweet&#95;id](/zh/x-ads-api/creatives#scheduled-tweets-2)（查看现有预定推文）

由于预定推文作为与“实时”推文相互独立的实体存在，对这些推文进行创建或编辑时会执行两套不同的校验规则。第一套校验规则会在创建预定推文的步骤中执行，具体包括：

<div id="scheduled-tweet-create">
  #### 计划推文创建：
</div>

* 验证已认证用户是否有权限为指定的 @handle 创建自然（organic）推文。仅推广推文（Promoted-Only Tweet）的创建权限要求已认证用户是具有 [Tweet composer permissions](https://developer.x.com/content/developer-twitter/en/docs/ads/campaign-management/api-reference/authenticated-user-access#get-accounts-account-id-authenticated-user-access) 的账号用户。
* 验证在距离 scheduled&#95;at 时间前后 15 分钟的时间窗口内，计划创建的推文数量不超过 30 条。SCHEDULED&#95;TWEET&#95;LIMIT&#95;EXCEEDED 错误消息表明在同一未来 15 分钟时间段内计划的推文过多。广告主需要删除一条现有的计划推文，或将 scheduled&#95;at 时间向前或向后调整。

<div id="scheduled-tweet-goes-live">
  #### 预定推文“发布”：
</div>

* 这些验证规则会在 scheduled&#95;at 指定的时间执行，并且与通过 API 创建普通推文时所应用的规则完全相同。举例来说，如果预定推文同时包含图片和 GIF，则该预定推文将不会被发布，并且 scheduled&#95;status 会被设置为 FAILED。

<div id="workflow">
  #### 工作流程
</div>

**创建新的定时推文**

可以使用 [POST accounts/:account&#95;id/scheduled&#95;tweets](https://developer.x.com/content/developer-twitter/en/docs/ads/creatives/api-reference/scheduled-tweets#post-accounts-account-id-scheduled-tweets) 端点来创建新的定时推文。该端点有以下必需参数：`scheduled_at` 时间，以及当推文中不包含媒体实体时的推文 `text`。此外，该端点还提供了一些额外选项，允许你通过 `as_user_id` 参数代表另一个 @handle 创建定时推文，并可以添加卡片（`card_uri`）以及媒体（`media_ids`）。注意，一条推文只能包含相同 type 的实体，即 Video、Gif 或 Image 其中一种。`nullcast` 参数用于控制该推文是否为 “Promoted-Only” 推文。所有新创建的定时推文默认都是 “Promoted-Only”（`nullcast=true`）。如果 `nullcast=false`，则会创建一条自然定时推文（Organic Scheduled Tweet）。

一旦定时推文创建成功，响应中会包含一个 `id` 字段，它表示该定时推文本身的唯一标识符。除了这个字段，响应中还会返回另一个名为 `tweet_id` 的字段。该字段在初始时为 `null`，但当推文正式发布上线后，这个字段会被填充为该“已上线”推文的 ID。

```
twurl -H 'ads-api.x.com' -X POST "/6/accounts/:account_id/scheduled_tweets" -d 'scheduled_at=2017-12-24T23:59:00Z&text=Happy Holidays!'
```

这将创建以下计划推文：

```json
{

  },
```

一旦这条预定推文发布，`tweet_id` 字段就会被填入这条“正式”推文的 ID。

**将预定推文关联到明细项（line item）**

虽然预定推文可用于创建自然推文（Organic Tweets），我们也允许合作伙伴创建“仅推广”（Promoted-Only，`nullcast=true`）推文，这两类推文都可以与明细项（line item）关联。为此，我们还提供了一个 [POST accounts/:account&#95;id/scheduled&#95;promoted&#95;tweets](https://developer.x.com/content/developer-twitter/en/docs/ads/campaign-management/api-reference/scheduled-promoted-tweets#post-accounts-account-id-scheduled-promoted-tweets) 端点。该端点在一次 API 调用中只允许将单个推广预定推文（Promoted Scheduled Tweet）关联到一个明细项。若要将多个预定推文关联到同一个明细项，就需要进行多次 API 调用。

请注意，无法修改现有的推广预定推文（Scheduled Promoted Tweet）。

```
twurl -H 'ads-api.x.com' -X POST "/6/accounts/:account_id/scheduled_promoted_tweets" -d 'line_item_id=a44qc&scheduled_tweet_id=917507899668099072'
```

```json
{
  "data": {
    "line_item_id": "a44qc",
    "id": "26576",
    "created_at": "2017-10-09T22:24:16Z",
    "updated_at": "2017-10-09T22:24:16Z",
    "scheduled_tweet_id": "917507899668099072",
    "tweet_id": null,
    "deleted": false
  },
  "request": {
    "params": {
      "line_item_id": "a44qc",
      "scheduled_tweet_id": 917507899668099100,
      "account_id": "aaaaa"
    }
  }
}
```

此 endpoint 仅在指定的 Scheduled Tweet 和某个 line item 之间创建关联。一旦 campaign/line item 的投放期进入当前时间窗口，该 line item 将会自动开始投放对应已“上线”的 Tweet。尽管在此步骤中我们会验证 Scheduled Tweet 是否处于 `SCHEDULED` 状态，以及该 Scheduled Tweet 是否对给定的 objective 有效，但不会执行其他校验。任何其余适用于 line item 和 Scheduled Tweet 的验证规则，都会在 Tweet 实际“上线”时才运行。

为确保 campaign 投放过程中不会出现问题，建议将 Scheduled Tweet 的 `scheduled_at` 时间设置在 campaign/line item 投放日期开始之前。

例如，假设 Scheduled Tweet 被设置为在 campaign 开始日期之后才上线（并且只有一个 Tweet 与一个 line item 关联），那么 campaign 状态将会是 `ACTIVE`，但是由于 Scheduled Tweet 尚未上线，将没有可用于投放的创意。

**Scheduled Tweet 管理**

其余这一组 endpoints 允许 API 使用方管理其所有的 Scheduled Tweets 和 Scheduled Promoted Tweets。这些 API 可用于返回所有 Scheduled Tweets 的列表（可选地按给定状态进行过滤），以及根据 `id` 查询指定的 Scheduled Tweet。

<div id="what-happens-when-a-scheduled-tweet-goes-live">
  #### 预定推文发布时会发生什么情况？
</div>

当某条预定推文即将发布（也就是说，在 `scheduled_at` 指定的时间）时，会进行以下更新：

* 系统会创建“已发布”的推文，但创建过程可能会有最长 1 秒的延迟
* `tweet_id` 会被添加到以下实体中：
* 预定推文
* 预定的推广推文
* 会创建一个新的推广推文实体

<div id="best-practices">
  #### 最佳实践
</div>

在创建或推广预定推文时，建议遵循以下最佳实践：

* 在创建预定推文时，确保推文本身有效（例如，一条推文中只能包含图片、视频或 GIF 动图中的一种，不能同时包含多种）
* 确保广告投放周期日期（即 `start_time` 和 `end_time`）与预定推文的 `scheduled_at` 时间保持一致
* 预定推文的发布时间不应设置在未来超过一年（365 天）
* 目前不支持预定推文的预览功能（即在创建前预览预定推文）

### 媒体库

<div id="introduction">
  #### 介绍
</div>

Media Library 端点支持为 X Ads 帐户管理图片、GIF 和视频等媒体素材。库中的媒体素材可以用于推文以及创建卡片。它们也可以在多个[广告创意](https://developer.x.com/content/developer-twitter/en/docs/ads/creatives/overview)中重复使用，从而无需多次上传相同的素材。

<div id="api-endpoints">
  #### API 端点
</div>

* [POST media/upload](https://developer.x.com/content/developer-twitter/en/docs/media/upload-media/api-reference/post-media-upload#post-media-upload) 或 [POST media/upload (chunked)](https://developer.x.com/content/developer-twitter/en/docs/media/upload-media/api-reference/post-media-upload-init#post-media-upload-init)（上传媒体）
* [POST accounts/:account&#95;id/media&#95;library](https://developer.x.com/x-ads-api/creatives#get-accounts-account-id-media-library#post-accounts-account-id-media-library)（将媒体添加到媒体库）

<div id="adding-to-the-library">
  #### 添加到媒体库
</div>

将媒体添加到媒体库是一个包含两步的流程。首先，使用 [POST media/upload](https://developer.x.com/content/developer-twitter/en/docs/media/upload-media/api-reference/post-media-upload#post-media-upload) 端点或一组 [POST media/upload（分块）](https://developer.x.com/content/developer-twitter/en/docs/media/upload-media/api-reference/post-media-upload-init#post-media-upload-init) 端点上传素材。（有关我们的分块上传流程的详细信息，请参阅《[分块媒体上传](https://developer.x.com/content/developer-twitter/en/docs/media/upload-media/uploading-media/chunked-media-upload)》指南。）

```
twurl -X POST -H upload.x.com "/1.1/media/upload.json?additional_owners=756201191646691328" --file latte.jpeg --file-field "media"
```

```json
{
   "media_id":966947208837742592,
   "media_id_string":"966947208837742592",
   "size":74194,
   "expires_after_secs":86400,
   "image":{
      "image_type":"image/jpeg",
      "w":800,
      "h":418
   }
}
```

<div id="request-parameters">
  #### 请求参数
</div>

所有 Media Library 的 POST 请求都需要一个媒体标识符。该值会在上传步骤中返回。使用 `media_id` 时（如上例所示），还必须指定一个 `media_category`。共有四种可能的类别值：`AMPLIFY_VIDEO`、`TWEET_GIF`、`TWEET_IMAGE` 和 `TWEET_VIDEO`。

可以为 Media Library 中的对象选择性地设置 `name` 和 `file_name` 值。这些属性可以帮助用户在库中区分不同的媒体变体。

对于视频，还可以设置 `title` 和描述（description）。这些值用于在调用 [POST accounts/:account&#95;id/tweet](https://developer.x.com/content/developer-twitter/en/docs/ads/creatives/api-reference/tweets#post-accounts-account-id-tweet) 端点时，作为 `video_title` 和 `video_description` 请求参数传递。在推文中，这些文本会显示在视频下方。

<div id="attributes">
  #### 属性
</div>

Media Library 正式引入了 media&#95;key 的概念。它是媒体库中对象的唯一标识符。media key 是如下格式的字符串值：13&#95;875943225764098048。我们的所有卡片端点（card endpoints）都完全支持它们。

此外，Media Library 的响应中还包含以字符串形式表示的 media&#95;id。对于当前尚不接受 media key 的资源，会包含该字段：[推文（Tweets）](https://developer.x.com/content/developer-twitter/en/docs/ads/creatives/api-reference/tweets#post-accounts-account-id-tweet)*、[推文预览（Tweet preview）](https://developer.x.com/content/developer-twitter/en/docs/ads/creatives/api-reference/tweets#get-accounts-account-id-tweet-preview)* 和 [预定推文（Scheduled Tweets）](https://developer.x.com/content/developer-twitter/en/docs/ads/creatives/api-reference/scheduled-tweets#post-accounts-account-id-scheduled-tweets)。我们正在推进在所有场景中支持 media key。

对于 GIF 和视频，会返回 aspect&#95;ratio 属性。它可用于筛选媒体，以便用于只接受特定宽高比的卡片（card）。

*这些端点支持 video&#95;id 参数，该参数本质上是一个 media key。

<div id="introduction">

</div>

Cards 是可自定义的广告格式，使用媒体资源，并且可以与网站、App 或号召性用语（call to action）关联，以推动特定用户互动，例如发起一条私信（Direct Message）。它们可以附加到推文、计划发送的推文或推文草稿中。

Cards 在推文对象中可以通过两种方式之一被引用：通过 card 的 `card_uri` 或 `preview_url`。下面给出了每种方式的示例值。

| :--- | :--- |
| card://1043282691834048513 | https://cards.x.com/cards/18ce54d4x5t/68w3s |

<div id="identifying-media">
  ### 识别媒体
</div>

<div id="introduction">
  #### 介绍
</div>

媒体（图片、GIF 和视频）可以添加到推文和卡片中。此外，视频可以用作贴片广告素材，图片可以在 [X Audience Platform](https://developer.x.com/en/docs/ads/measurement/overview/twitter-audience-platform) 上进行推广。本节介绍如何在这些实体中查找媒体引用。

媒体标识符有两种类型：ID 和键。下面给出了每种类型的示例值。

| **媒体 ID** | **媒体键** |
| :--- | :--- |
| 1029825579531807971 | 13&#95;1029825579531807971 |

媒体键由在 ID 前添加一个数字前缀和一个下划线组成。

<div id="images">
  #### 图像
</div>

下表显示了当前在每个与图像相关的资源响应中可用的标识符类型，以及相应的属性名称。

| **资源** | **标识符** | **属性** |
| :--- | :--- | :--- |
| 图片卡片 | 无 |  |
| 推文 | 两者都有 | `entities["media"]["id_str"]`  `entities["media"]["media_key"]` |
| 预定推文 | 两者都有 | `media_ids` 和 `media_keys` |
| 草稿推文 | 两者都有 | `media_ids` 和 `media_keys` |
| 账户媒体 | 无 |  |
| 媒体库 | 两者都有 | `media_id` 和 `media_key` |

图片卡片和账户媒体中的图像不会引用任何媒体标识符。推文只包含媒体 ID。预定推文和草稿推文同时包含媒体 ID 和媒体 key。媒体库同样会返回两者。

对于推文，对象中 `entities["media"]` 数组内的 `id` 和 `id_str` 字段对应媒体 ID。对于包含多张图片的推文，每个媒体实体的引用只能在 `extended_entities["media"]` 中找到。

除了对标识符的引用之外，通常还需要能够访问图像的 URL。

| **资源** | **属性** | **格式** |
| :--- | :--- | :--- |
| 图片卡片 | `image` | .jpg |
| 推文* | `entities["media"][0]["media_url"]` 或 `extended_entities["media"][i]["media_url"]` | .jpg |
| 预定推文 | 无 |  |
| 草稿推文 | 无 |  |
| 账户媒体 | `media_url` | .jpg |
| 媒体库 | `media_url` | .jpg |

* 该 URL 的位置取决于推文是包含单张图片还是多张图片。

所有图片卡片都包含一个 `image` 响应属性，其中包含 X 图像 URL。（对于应用下载类图片卡片，该属性名为 `wide_app_image`。）

对于推文，媒体 URL 的位置取决于媒体的类型以及所使用的端点。对于只包含一张图片的推文，URL 可以在 `entities["media"][0]["media_url"]` 中找到，这对 Ads API 和 Standard API 都成立。而当推文包含多张图片时，这些 URL 只能在 `extended_entities["media"][i]["media_url"]` 中找到，该属性仅在 Standard API 中可用。

<div id="video">
  #### 视频
</div>

下表显示了当前在各个与视频相关的资源响应中可用的标识符类型，以及相应的属性名称。

| **Resource** | **Identifier** | **Attribute(s)** |
| :--- | :--- | :--- |
| Video cards | May be either | `video_content_id` |
| Video poll cards | None |  |
| Tweet | Both | `entities["media"]["id_str"]`  `entities["media"]["media_key"]` |
| Scheduled Tweet | Both | `media_ids` and `media_keys` |
| Draft Tweet | Both | `media_ids` and `media_keys` |
| Account Media | Media key | `video_id` |
| Media Library | Both | `media_id` and `media_key` |

虽然视频卡片（带视频的投票卡片除外）包含一个 `video_content_id` 响应属性，但其返回值的类型并不一致。在某些情况下它是媒体 ID，在其他情况下则是媒体 key。

以下内容说明如何访问视频的 URL。

| **Resource** | **Attribute(s)** | **Format** |
| :--- | :--- | :--- |
| Video cards | `video_url` and `video_hls_url` | .vmap  .m3u8 |
| Tweet with video | `extended_entities["media"][i]["video_info"]["variants"][j]["url"]` | .mp4 |
| Scheduled Tweet | None |  |
| Draft Tweet | None |  |
| Account Media | None |  |
| Media Library | `media_url` | .mp4 |

视频卡片包含 `video_url` 和 `video_hls_url` 响应属性，分别对应 .vmap 和 .m3u8 URL。

<div id="media-library">
  #### 媒体库
</div>

有时需要检索媒体资产的额外信息。比如在视频卡片的用例中，可能需要获取 mp4 URL 而不是 vmap URL。这些信息可以在媒体库中获取。关于可用信息的详细说明，请参阅我们的[媒体库指南](https://developer.x.com/content/developer-twitter/en/docs/ads/creatives/guides/media-library)。大多数属于广告账户的 FULL promotable user 的资产都可以在媒体库中找到，但也有一些例外情况。

**获取媒体**

如上所述，图片卡片不包含对媒体 `id` 或媒体 key 的引用。因此，无法通过媒体库获取其资产。[Account Media](https://developer.x.com/content/developer-twitter/en/docs/ads/creatives/api-reference/account-media#account-media) 中的图片也有同样的限制。

在创建视频卡片之前，视频资产必须已经是媒体库（或其前身 Videos 资源）的一部分。因此，这些资产始终可以通过媒体库检索。Account Media 中的 PREROLL 资产同样适用这一点。

最后，推文中的媒体始终保证会出现在媒体库中。

下表在考虑资源响应中是否包含可用于查找的标识符的前提下，总结了哪些资产可以在媒体库中被检索。

| **Resource** | **In the Media Library** |
| :--- | :--- |
| Image cards | No |
| Video cards | Yes* |
| Tweets (any media)** | Yes |
| Scheduled Tweets | Yes |
| Draft Tweets | Yes |
| Account media images | No |
| Account media videos (`PREROLL`) | Yes |

* 适用于 `video_content_id` 为媒体 key 的卡片。当该值为媒体 `id` 时，资产依然存在于媒体库中，但检索它需要在其前面追加一个数字前缀和下划线。\
** 推文仅返回媒体 `id`。尽管可以保证资产存在于媒体库中，但获取它需要在其前面追加一个数字前缀和下划线。

**与 Account Media 的交互**

有两种情况，添加到媒体库的媒体资产会被自动添加到 Account Media 资源中。

* 当一个 AMPLIFY&#95;VIDEO 资产被添加到媒体库时，它会自动作为 PREROLL 创意类型的 Account Media 资产被添加。
* 当具有特定尺寸的图片（参见我们的[枚举页面](https://developer.x.com/content/developer-twitter/en/docs/ads/general/overview/enums)中的“Creative Types”）被添加到媒体库时，它们会自动作为 Account Media 资产被添加。创意类型（例如 INTERSTITIAL）取决于图片尺寸。

<div id="tweets">
  ### 推文
</div>

#### 简介

X Ads API 支持三种推文类型：已发布、预定发布和草稿。

<div id="nullcasted-tweets">
  #### 不展示推文（Nullcasted Tweets）
</div>

推文可以是不展示推文（又称“仅推广（Promoted-only）”），也可以是自然推文。已发布的不展示推文不会出现在用户的公开时间线中，但它们依然是公开可见的。另一方面，自然推文会投放给用户的关注者，并且会出现在该用户的公开时间线中。

**创建推文**

三个推文创建端点都支持一个布尔值的 `nullcast` 参数，使 API 用户可以选择创建不展示推文或自然推文。不展示推文可以由用户本人创建，也可以由任何被授权代表该用户创建推文的人创建。自然推文只能由[完全可推广用户（full promotable user）](https://developer.x.com/content/developer-twitter/en/docs/tutorials/ads-api-hierarchy-terminology#promotable-users)创建。

**更新推文**

对于预定发送和草稿推文，可以更新其 `nullcast` 属性。对于预定发送的推文，可以在该推文的 `scheduled_at` 时间之前进行编辑。草稿推文可以无限期编辑。但一旦推文发布，就无法再将其从不展示推文改为自然推文，或反之亦然。

<div id="promoting-tweets">
  #### 推广推文
</div>

只有已发布和已排期的推文可以被推广。它们可以是 nullcast（不通过自然分发展示）或自然推文（organic），对此没有限制。广告主可以推广自己的推文，也可以在获得许可的情况下推广其他用户的推文。（参见：[Promoting another user&#39;s Tweets](https://developer.x.com/content/developer-twitter/en/docs/tutorials/promoting-another-users-content) 了解更多信息。）

在单个广告活动中可以推广多条推文。同样，一条推文也可以在一个或多个广告活动中被推广。

要推广已发布的推文，请使用 [POST accounts/:account&#95;id/promoted&#95;tweets 端点](https://developer.x.com/content/developer-twitter/en/docs/ads/campaign-management/api-reference/promoted-tweets#post-accounts-account-id-promoted-tweets)。这会将已发布的推文关联到某个 line item。要推广已排期的推文，请使用 [POST accounts/:account&#95;id/scheduled&#95;promoted&#95;tweets 端点](https://developer.x.com/content/developer-twitter/en/docs/ads/campaign-management/api-reference/scheduled-promoted-tweets#post-accounts-account-id-scheduled-promoted-tweets)。

<div id="tweet-ids">
  #### 推文 ID
</div>

已发布、已排程和草稿推文的 ID 均为[数字](https://developer.x.com/content/developer-twitter/en/docs/basics/twitter-ids)，即 64 位无符号整数。例如，下面这条已发布推文的 ID 为 1166476031668015104。

<div id="carousels">
  ### 轮播图
</div>

#### 简介

X Ads API 支持创建和检索视频轮播和图片轮播。轮播是一种卡片类型，可以包含 2 到 6 个媒体资源。轮播卡片可以将用户引导至网站，或鼓励他们安装移动应用。有关轮播的更多信息，包括其优势、最佳实践和常见问题，请参阅我们的 [Carousel Ads on X](https://business.x.com/en/advertising/carousels.html) 页面。

轮播与其他任何卡片类型一样，可以用于推文，这些推文随后可以被推广。其工作流与你已经熟悉的流程相同：

1. 上传媒体
2. 创建卡片
3. 创建推文
4. 推广推文

唯一的区别在于卡片的创建方式。其他卡片创建请求接受查询参数，而轮播卡片创建请求只接受 JSON POST 正文。

<div id="endpoints">
  #### 端点
</div>

Ads API 支持创建和获取轮播卡片。

要创建任意类型的轮播卡片，请使用 [POST accounts/:account&#95;id/cards](https://developer.x.com/en/docs/twitter-ads-api/creatives/api-reference/cards#post-accounts-account-id-cards) 端点。要获取轮播卡片，请使用 [GET accounts/:account&#95;id/cards](https://developer.x.com/en/docs/twitter-ads-api/creatives/api-reference/cards#get-accounts-account-id-cards) 端点。

<div id="json-post-body">
  #### JSON POST Body
</div>

轮播是通过两个组件创建的。第一个组件用于指定将要使用的媒体素材。第二个组件用于指定网站或 App 的相关信息。

具体来说，一个轮播卡片是按如下顺序使用以下组件创建的：

* 一个 `SWIPEABLE_MEDIA` 组件，它接收一个媒体 key 数组
* *以下组件中的一个*：
* 一个 `DETAILS` 组件，用于指定网站信息
* 一个 `BUTTON` 组件，用于指定 App 信息

`SWIPEABLE_MEDIA` 组件必须包含一个 `media_keys` 数组，你可以在其中指定 2 到 6 张图片或视频。传入媒体 key 的顺序决定了它们被渲染时的顺序。

```
{
  "type": "SWIPEABLE_MEDIA",
  "media_keys": [
    "13_1089771253848666112",
    "13_1191948012077092867"
  ]
}
```

提醒一下，你可以通过向 [GET accounts/:account&#95;id/media&#95;library](https://developer.x.com/en/docs/twitter-ads-api/creatives/api-reference/media-library#get-accounts-account-id-media-library) 端点发起请求来获取媒体 key。

第二个组件对象的组成取决于你是希望将用户引导至网站，还是鼓励他们安装应用。下表对这两种选项进行了总结。（**注意**：所有列出的键都是必需的。）

|        | **网站**                                                             | **应用**                                            |
| :----- | :----------------------------------------------------------------- | :------------------------------------------------ |
| 指定组件类型 | `"type": "DETAILS"`                                                | `"type": "BUTTON"`                                |
| 标题/标签  | `"title": "X"`                                                     | `"label": { "type": "ENUM", "value": "INSTALL" }` |
| 目标     | `"destination": { "type": "WEBSITE", "url": "https://www.x.com" }` | `"destination": { "type": "APP", ... }`           |

综合以上内容，下面是一个网站轮播的 JSON POST 请求正文示例。

```
{
  "name": "website carousel",
  "components": [
    {
      "type": "SWIPEABLE_MEDIA",
      "media_keys": [
        "13_1089771253848666112",
        "13_1191948012077092867"
      ]
    },
    {
      "type": "DETAILS",
      "title": "X",
      "destination": {
        "type": "WEBSITE",
        "url": "https://www.x.com"
      }
    }
  ]
}
```

`BUTTON` 组件中的 App 目标对象需要一个国家/地区代码以及至少一个应用标识符。它们还可以选择性地支持深度链接。有关这些字段的描述，请参阅[参考文档](https://developer.x.com/en/docs/twitter-ads-api/creatives/api-reference/cards#app-destination)。

综合以上内容，下面是一个 App 轮播 JSON POST 请求体示例。

```
{
  "name": "app carousel",
  "components": [
    {
      "type": "SWIPEABLE_MEDIA",
      "media_keys": [
        "13_1089771253848666112",
        "13_1191948012077092867"
      ]
    },
    {
      "type": "BUTTON",
      "label": {
        "type": "ENUM",
        "value": "INSTALL"
      },
      "destination": {
        "type": "APP",
        "country_code": "US",
        "googleplay_app_id": "com.twitter.android",
        "iphone_app_id": "333903271"
      }
    }
  ]
}
```

<div id="creative-metadata-tagging">
  ### 创意元数据标注
</div>

#### 简介

本指南面向创意合作伙伴、代理商和创意开发者，帮助你为在 X 广告投放活动中使用的素材添加标签，从而更好地了解单个素材的价值和表现。

**注意：** 媒体素材的标签必须由创建该媒体素材的合作伙伴或开发者自行添加。如果媒体素材的使用者并非该素材的创建者，请不要实施元数据标记。

Creative Metadata Tagging 可为由 Creative Partners 创建的图片和视频提供归因，无论该素材被上传到 X 的何处，或由哪一主体上传。为了在创意素材和创意合作伙伴之间建立关联，我们使用 [XMP](https://exiftool.org/TagNames/XMP.html) 标准。

</div>

<div id="post-accountsaccount_idcards">
  #### POST accounts/:account_id/cards
</div>

创建一个与指定账户关联的新卡片。

卡片创建请求只接受 JSON 格式的 POST 请求体。`Content-Type` 必须设置为 `application/json`。

有关详细的使用示例，请参阅我们的 [轮播卡片指南](https://developer.x.com/en/docs/twitter-ads-api/creatives/guides/carousels)。

<div id="resource-url">
  #### 资源 URL
</div>

`https://ads-api.x.com/12/accounts/:account_id/cards`

#### 参数

JSON POST 请求体必须包含卡片的 `name` 和一个 `components` 数组。组件以对象的形式表示，用于描述卡片中面向广告主的属性。

下面的示例展示了请求负载的一般结构（其中包含的示例信息不可用于实际调用）。

```
{
  "name": "some name",
  "components": [
    {
      "type": "TYPE_ENUM",
      "key": "value"
    }
  ]
}
```

下面是关于组件的更多信息。

| Name                              | Description                                                                                                                                                                                                               |
| :-------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| account&#95;id   *required*       | 被操作账户的标识符。出现在资源路径中，并且通常是除 [GET accounts](https://developer.x.com/en/docs/ads/campaign-management/api-reference/accounts#get-accounts) 以外所有 Advertiser API 请求所必需的参数。指定的账户必须与已认证用户关联。  Type: string  Example: `18ce54d4x5t` |
| name   *required*                 | 卡片名称。最大长度：80 个字符。  Type: string  Example: `component based card`                                                                                                                                                          |
| components   *sometimes required* | 描述用于创建卡片的组件。更多信息见下文。不能与 `slides` 同时指定。**注意**：组件的顺序很重要。 Type: array of objects                                                                                                                                             |
| slides   *sometimes required*     | 使用这个数组的数组（二维数组）创建 Multi-Destination Carousels（多目的地轮播）。将每张卡片描述为一组组件。每个 slide 都应完整表示一张卡片。不能与 `components` 同时指定。**注意**：各个 slide 的顺序很重要。 Type: array of array                                                                 |

<div id="components">
  #### 组件
</div>

每个组件都必须包含一个 `type` 字段，用于指定该对象的 schema。Ads API 支持以下组件类型，分为媒体类组件和描述类组件。

* 媒体：
* `MEDIA`：单个视频或图片
* `SWIPEABLE_MEDIA`：2 到 6 个视频或图片
* 描述：
* `DETAILS`
* `BUTTON`

每个组件都有一组必填字段（除了 `type` 键以外）。这些字段列在下表中。

| 组件 `type`         | 字段                      | 值类型              |
| :---------------- | :---------------------- | :--------------- |
| `MEDIA`           | `media_key`             | string           |
| `SWIPEABLE_MEDIA` | `media_keys`            | array of strings |
| `DETAILS`         | `title`   `destination` | string   object  |
| `BUTTON`          | `label`   `destination` | object   object  |

下面是在 `components` 数组中一个 `BUTTON` 组件的示例（有意省略 `name` 键）。（省略号表示在这些位置还需要提供更多信息。）

```
{
  "components": [
    {
      "type": "BUTTON",
      "label": {
        ...
      },
      "destination": {
        ...
      }
    }
  ]
}
```

组件对象被指定的顺序决定了它们自上而下的渲染顺序。Card 必须由一个媒体组件和一个 `DETAILS` 或 `BUTTON` 组件创建。描述型组件会渲染在媒体组件下方，并具有关联的目标，可以是 URL 或移动 App。

**Label**

Label 用于定义显示在按钮上的文本，因此仅适用于 `BUTTON` 组件。Label 对象有两个必需的键：`type` 和 `value`。`type` 必须设置为 `ENUM`，而 `value` 可以是以下之一：`BOOK`、`CONNECT`、`INSTALL`、`OPEN`、`ORDER`、`PLAY` 或 `SHOP`。

在前面示例的基础上，下面展示了 `BUTTON` 组件中的 `label` 对象。

```
{
  "components": [
    {
      "type": "BUTTON",
      "label": {
        "type": "ENUM",
        "value": "INSTALL"
      },
      "destination": {
        ...
      }
    }
  ]
}
```

**目标页面**

目标页面是广告主希望将用户引导至的地点。在 `DETAILS` 或 `BUTTON` 组件中始终为必填字段。目标页面有两种类型：`WEBSITE` 或 `APP`。

**注意**：网站类目标页面只能与 `DETAILS` 组件一起使用，App 类目标页面只能与 `BUTTON` 组件一起使用。

**网站目标页面**

| Name              | Description                                                                         |
| :---------------- | :---------------------------------------------------------------------------------- |
| type   *required* | 目标页面的类型，用于决定其使用的 schema。Type: enum  Possible values: `WEBSITE`                      |
| url   *required*  | 将用户重定向到的网站 URL。Type: string  Example: `https://devcommunity.x.com/c/advertiser-api` |

**App 目标页面**

| Name                                                        | Description                                                                                                                         |
| :---------------------------------------------------------- | :---------------------------------------------------------------------------------------------------------------------------------- |
| type   *required*                                           | 目标页面的类型，用于决定其使用的 schema。Type: enum  Possible values: `APP`                                                                          |
| country&#95;code   *required*                               | App 销售所在国家/地区的 [ISO 3166-1 alpha-2](https://en.wikipedia.org/wiki/ISO_3166-1_alpha-2) 双字母代码。Type: string  Example: `US`             |
| googleplay&#95;app&#95;id   *sometimes required*            | Google Play 应用包名。**注意**：以下字段中至少需要提供一个：`ios_app_store_identifier` 或 `googleplay_app_id`。Type: string  Example: `com.twitter.android` |

<div id="post-accountsaccount_idtweet">
  #### POST accounts/:account_id/tweet
</div>

为账号的完整可推广用户（默认）或在 `as_user_id` 参数中指定的用户创建一条推文。支持创建空投放（nullcast，默认）和自然推文。空投放推文不会出现在公共时间线中，也不会展示给关注者。这两种类型的推文都可以用于广告活动。

如果已通过身份验证的用户不是此账号上的 `FULL` 可推广用户，请通过向 [GET accounts/:account&#95;id/authenticated&#95;user&#95;access](https://developer.x.com/en/docs/ads/campaign-management/api-reference/authenticated-user-access#get-accounts-account-id-authenticated-user-access) 端点发起请求，以确定其是否有权限代表该用户发布推文。权限值 `TWEET_COMPOSER` 表示该用户可以使用此端点代表 `FULL` [可推广用户](https://developer.x.com/en/docs/ads/campaign-management/api-reference/promotable-users#get-accounts-account-id-promotable-users) 创建空投放推文。

使用 [upload.x.com 端点](https://developer.x.com/rest/reference/post/media/upload) 上传媒体时，请将 `additional_owners` 参数中的 `user_id` 值设置为与调用此端点时传入的 `as_user_id` 值相同。
