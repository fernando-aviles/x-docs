<div id="overview">
  ## 概览
</div>

创意素材是指在广告系列中可以被推广的任何实体。帖子可以包含文本、图片、GIF、视频或卡片。卡片可以包含图片或视频。

图片、GIF 或视频创意素材可通过 [POST media/upload](/zh/x-api/media/upload-media#post-media-upload) 上传——这是一个仅支持图片的简单上传端点——或通过 POST media/upload（分片上传）端点上传。上述创意素材可以添加到：

卡片：

* POST accounts/:account&#95;id/cards
  推文：
* POST accounts/:account&#95;id/tweets - 要在推文中添加卡片，请使用 card&#95;uri 参数。
  预定推文：
* POST accounts/:account&#95;id/scheduled&#95;tweets

有关卡片的更多详情，请参阅 Cards 页面。Promoted Video 页面提供了将视频与卡片或推文关联的详细说明。

<div id="cards">
  ### 卡片
</div>

Ads API 支持多种可用于推文的卡片类型，这些卡片随后可以在广告活动中进行推广。**注意**：一旦作为推文发布，卡片的详细信息将向公众可见，其中可能包括拥有该卡片的用户相关信息。

<div id="image">
  #### 图片
</div>

以下图片规范适用于 [Cards](/zh/x-ads-api/creatives#cards-2) 中使用的素材。图片文件大小必须不超过 3MB，且宽度至少为 800px。此外，我们支持以下宽高比：

* Website：1:1 和 1.91:1
* Image App Download：1:1 和 1.91:1
* Poll：1.91:1
* Image Conversation：1.91:1
* Image Direct Message：1.91:1

我们支持以下图片格式：.bmp、.jpeg 和 .png。

<div id="video">
  #### 视频
</div>

以下视频规范适用于 [Cards](/zh/x-ads-api/creatives#cards-2) 中使用的素材。我们支持以下宽高比：

* 网站视频：16:9 和 1:1
* 应用下载视频：16:9 和 1:1
* 投票：16:9
* 视频会话：16:9
* 视频私信：16:9

<div id="promoted-video">
  ### 推广视频
</div>

本文档简要概述了通过 Ads API 上传和推广视频的流程。

Ads API 支持在[推文](/zh/x-ads-api/creatives#tweets-2)以及以下卡片中使用推广视频：

* [视频网站卡片](https://devcommunity.x.com/t/ads-api-version-11/168814)
* [视频应用下载卡片](https://devcommunity.x.com/t/ads-api-version-11/168814)
* [视频对话卡片](/zh/x-ads-api/creatives#video-conversation-cards)

首先，使用 [POST media/upload (chunked)](https://developer.x.com/en/docs/media/upload-media/api-reference/post-media-upload-init.html) 端点上传视频。使用 `media_id`，通过 POST accounts/:account&#95;id/videos 端点将该视频关联到广告账户。该视频的 `id`（有时称为 `media_key`）将在后续请求中使用。它是一个以整数开头、后接下划线并以长整型数值结尾的字符串。例如：`13_875943225764098048`。

<div id="promoted-video-in-tweets">
  #### 推文中的推广视频
</div>

要创建一条推文，请使用 [POST accounts/:account&#95;id/tweet](/zh/x-ads-api/creatives#get-accounts-account-id-tweets) 端点，并传入该视频的 `id`。在这一步中，你还可以提供视频标题、描述和号召性用语（CTA）。这些值将展示给用户。

<div id="promoted-video-in-cards">
  #### 卡片中的推广视频
</div>

Video App Download 卡片和 Video Conversation 卡片支持添加封面图片。使用 [POST media/upload](https://developer.x.com/en/docs/media/upload-media/api-reference/post-media-upload.html) 端点上传一张要在这些卡片中使用的图片。

使用以下端点之一创建卡片：

* [POST accounts/:account&#95;id/cards/video&#95;website](https://devcommunity.x.com/t/ads-api-version-11/168814)
* [POST accounts/:account&#95;id/cards/video&#95;app&#95;download](https://devcommunity.x.com/t/ads-api-version-11/168814)
* [POST accounts/:account&#95;id/cards/video&#95;conversation](https://devcommunity.x.com/t/ads-api-version-11/168814)

使用视频的 `id`，并可选地使用图片的 `media_id`（作为封面图片）。

最后，使用 POST accounts/:account&#95;id/tweet 端点创建推文。通过 `card_uri` 参数将卡片附加到推文。

<div id="general-information">
  #### 一般信息
</div>

若要获取通过 API 上传视频的详细指南，请参阅[视频上传指南](https://developer.x.com/en/docs/media/upload-media/uploading-media.html)。

视频也可以推广为前贴片广告素材。请参阅[视频观看量前贴片目标指南](/zh/x-ads-api/campaign-management#video-views-preroll-objective)以获取详细说明。

* （自 2015-10-22 起）当上传要用于推广内容的视频时，在所有发往 [POST media/upload (chunked)](https://developer.x.com/en/docs/media/upload-media/api-reference/post-media-upload-init.html) 端点的 `INIT` 命令请求中，必须将 `media_category` 参数设置为 `amplify_video`。使用此新参数可确保视频以异步方式进行预处理，并为在推广内容中使用做好准备。视频上传后，可以使用 `STATUS` 命令检查异步处理是否完成。
* 当前允许的推广视频最长时长为 10 分钟，文件大小不超过 500MB。
* 上传的视频应为 mp4 或 mov 格式。
* 上传视频一般会被快速处理，但处理时间可能会因视频时长和文件大小而有所不同。
* 上传的封面图片应为 png 或 jpg 格式。对纵横比或尺寸没有要求，但封面图片会被调整以适配视频播放器。

<div id="scheduled-tweets">
  ### 定时发布推文
</div>

<div id="introduction">
  #### 介绍
</div>

计划发布推文功能允许广告主或用户创建一条可以安排在未来某个时间发布的推文。除了能够创建和管理这些推文之外，API 还允许将这些推文与某个广告单元关联起来，以便在推文发布后进行推广。这样一来，广告主就可以提前预先创建原生推文，并在任何关键活动前规划他们的活动创意。例如，将某条推文创意设置为在新产品发布公告的同时立即上线。

Scheduled Tweets API 端点所提供的全部功能如下所示：

* 创建、修改和查看新计划发布的推文
* 将一条计划发布推文与某个广告单元关联
* 查询和管理现有的计划发布推文
* 一旦某条计划发布推文上线，检索已上线推文的 `id`

<div id="api-endpoints">
  #### API 端点
</div>

与上述功能相关的所有端点如下：

<div id="scheduled-tweet-management">
  #### 计划推文管理
</div>

* [GET accounts/:account&#95;id/scheduled&#95;tweets](/zh/x-ads-api/creatives#get-accounts-account-id-scheduled-tweets)（获取所有计划推文的列表）
* [GET accounts/:account&#95;id/scheduled&#95;tweets/:scheduled&#95;tweet&#95;id](/zh/x-ads-api/creatives#get-accounts-account-id-scheduled-tweets)（根据其 `id` 查询特定计划推文）
* [POST accounts/:account&#95;id/scheduled&#95;tweets](/zh/x-ads-api/creatives#post-accounts-account-id-scheduled-tweets)（创建新的计划推文）
* [PUT accounts/:account&#95;id/scheduled&#95;tweets/:scheduled&#95;tweet&#95;id](/zh/x-ads-api/creatives#example-request-39)（修改现有计划推文）
* [DELETE accounts/:account&#95;id/scheduled&#95;tweets/:scheduled&#95;tweet&#95;id](/zh/x-ads-api/creatives#example-request-40)（根据其 `id` 删除计划推文）
* [GET accounts/:account&#95;id/scheduled&#95;tweets/preview/:scheduled&#95;tweet&#95;id](/zh/x-ads-api/creatives#scheduled-tweets-2)（预览现有计划推文）

<div id="scheduled-promoted-tweets">
  #### 预定推广推文
</div>

* [GET accounts/:account&#95;id/scheduled&#95;promoted&#95;tweets](/zh/x-ads-api/campaign-management#get-accounts-account-id-scheduled-promoted-tweets)（获取所有预定推广推文的列表）
* [GET accounts/:account&#95;id/scheduled&#95;promoted&#95;tweets/:scheduled&#95;promoted&#95;tweet&#95;id](/zh/x-ads-api/campaign-management#get-accounts-account-id-scheduled-promoted-tweets-scheduled-promoted-tweet-id)（使用其 `id` 查询预定推广推文）
* [POST accounts/:account&#95;id/scheduled&#95;promoted&#95;tweets](/zh/x-ads-api/campaign-management#post-accounts-account-id-scheduled-promoted-tweets)（创建新的预定推广推文）
* [DELETE accounts/:account&#95;id/scheduled&#95;promoted&#95;tweets/:scheduled&#95;promoted&#95;tweet&#95;id](/zh/x-ads-api/campaign-management#delete-accounts-account-id-scheduled-promoted-tweets-scheduled-promoted-tweet-id)（使用其 `id` 删除现有的预定推广推文）

<div id="scheduled-tweet-view">
  #### 预定推文视图
</div>

* [GET accounts/:account&#95;id/scheduled&#95;tweets/preview/:scheduled&#95;tweet&#95;id](/zh/x-ads-api/creatives#scheduled-tweets-2)（查看现有的预定推文）

由于预定推文与“已发布”推文是相互独立的实体，在创建或编辑这些推文时，会运行两套不同的验证。第一套验证规则会在创建预定推文的步骤中运行，具体包括：

<div id="scheduled-tweet-create">
  #### 计划推文创建：
</div>

* 验证已认证用户是否有权限为给定的 @handle 创建自然推文。仅推广推文的创建权限要求已认证用户是具有 [Tweet composer permissions](https://developer.x.com/content/developer-twitter/en/docs/ads/campaign-management/api-reference/authenticated-user-access#get-accounts-account-id-authenticated-user-access) 的账户用户。
* 验证在距离 `scheduled_at` 时间前后 15 分钟的时间窗口内，计划创建的推文不超过 30 条。`SCHEDULED_TWEET_LIMIT_EXCEEDED` 错误消息表明在同一未来 15 分钟时间段内计划的推文数量过多。广告主需要删除现有的一条计划推文，或者将 `scheduled_at` 时间提前或推后。

<div id="scheduled-tweet-goes-live">
  #### 预定推文开始发布：
</div>

* 这些验证规则会在 scheduled&#95;at 指定的时间执行，并且与通过 API 创建普通推文时所应用的规则完全相同。例如，如果预定推文同时包含图片和 GIF 动图，则该预定推文不会发布，且 scheduled&#95;status 将被设置为 FAILED。

<div id="workflow">
  #### 工作流
</div>

**创建新的预定推文**

可以使用 [POST accounts/:account&#95;id/scheduled&#95;tweets](https://developer.x.com/content/developer-twitter/en/docs/ads/creatives/api-reference/scheduled-tweets#post-accounts-account-id-scheduled-tweets) 端点来创建新的预定推文。此端点具有以下必需参数：`scheduled_at` 时间，以及在推文中未包含媒体实体时必需提供的推文 `text`。此外，该端点还提供了一些额外选项，使你可以通过 `as_user_id` 参数代表其他 @handle 创建预定推文，并能够添加卡片（`card_uri`）和媒体（`media_ids`）。注意，一条推文只能包含同一类型的实体，即要么是 Video、GIF 或 Image。`nullcast` 参数控制该推文是否为“仅推广（Promoted-Only）”推文。所有新创建的预定推文默认均为 &quot;Promoted-Only&quot;（`nullcast=true`）。如果 `nullcast=false`，则会创建一条自然预定推文。

预定推文成功创建后，响应会包含一个 `id` 字段，它指的是该预定推文本身的唯一标识符。除了该字段外，还会返回另一个名为 `tweet_id` 的字段。该字段最初为 `null`，但一旦推文上线，此字段就会被填充为该“上线”推文的 ID。

```
twurl -H 'ads-api.x.com' -X POST "/6/accounts/:account_id/scheduled_tweets" -d 'scheduled_at=2017-12-24T23:59:00Z&text=Happy Holidays!'
```

这将创建以下定时推文：

```json
{
  "request": {
    "params": {
      "text": "Happy Holidays!",

    }
  },
  "data": {
    "completed_at": null,
    "id_str": "917507899668099072",
    "text": "Happy Holidays!",
    "user_id": "3271358660",
    "scheduled_status": "SCHEDULED",
    "id": 917507899668099100,

    "tweet_id": null,
    "media_keys": []
  }

```

一旦此计划推文发布，`tweet_id` 字段就会填入该“上线”推文的 ID。

**将预定推文关联到 line item**

虽然预定推文可用于创建自然推文，我们也允许合作伙伴创建“仅推广”（`nullcast=true`）推文，这两种推文都可以关联到某个 line item（投放项）。为此，我们还提供了一个 [POST accounts/:account&#95;id/scheduled&#95;promoted&#95;tweets](https://developer.x.com/content/developer-twitter/en/docs/ads/campaign-management/api-reference/scheduled-promoted-tweets#post-accounts-account-id-scheduled-promoted-tweets) API 端点。该端点在一次 API 调用中仅允许将单条预定推广推文关联到一个 line item。若要将多条预定推文关联到同一个 line item，需要进行多次 API 调用。

请注意，无法修改现有的预定推广推文。

```
twurl -H 'ads-api.x.com' -X POST "/6/accounts/:account_id/scheduled_promoted_tweets" -d 'line_item_id=a44qc&scheduled_tweet_id=917507899668099072'
```

```json
{
  "data": {
    "line_item_id": "a44qc",
    "id": "26576",
    "created_at": "2017-10-09T22:24:16Z",
    "updated_at": "2017-10-09T22:24:16Z",
    "scheduled_tweet_id": "917507899668099072",
    "tweet_id": null,
    "deleted": false
  },
  "request": {
    "params": {
      "line_item_id": "a44qc",
      "scheduled_tweet_id": 917507899668099100,
      "account_id": "aaaaa"
    }
  }
}
```

此端点仅在给定的预定推文（Scheduled Tweet）和广告单元（line item）之间创建关联。一旦广告活动／广告单元的投放日期进入当前时间范围，该广告单元将自动开始投放对应的“已上线”推文。虽然我们在此步骤会验证预定推文是否处于 `SCHEDULED` 状态，以及该预定推文是否适用于给定的投放目标（objective），但不会执行其他验证。任何适用于广告单元和预定推文的其余验证规则，会在推文真正“上线”时执行。

为确保广告活动投放没有问题，建议将预定推文的 `scheduled_at` 时间设置为早于广告活动／广告单元投放日期的时间点。

例如，如果预定推文被设置为在广告活动开始日期之后才上线（并且只有一条推文与一个广告单元关联），那么广告活动的状态将为 `ACTIVE`，但是由于预定推文尚未上线，将没有可供投放的创意。

**预定推文管理**

其余这些端点允许 API 使用方管理所有预定推文（Scheduled Tweets）和预定推广推文（Scheduled Promoted Tweets）。这些 API 可用于返回所有预定推文的列表（可按给定状态进行可选过滤），以及通过 `id` 查询指定的预定推文。

<div id="what-happens-when-a-scheduled-tweet-goes-live">
  #### 当计划发送的推文开始发布时会发生什么？
</div>

当某条计划发送的推文即将发布时，也就是在 `scheduled_at` 指定的时间点，会进行以下更新：

* 会创建“已发布”的推文，但这可能会有最长 1 秒的延迟
* `tweet_id` 会被添加到以下实体中：
* 计划发送的推文
* 计划发送的推广推文
* 会创建一个新的推广推文实体

<div id="best-practices">
  #### 最佳实践
</div>

在创建或推广计划推文（Scheduled Tweets）时，建议遵循以下最佳实践：

* 在创建计划推文时，确保该推文本身是有效的（例如，一条推文只能包含图片、视频或 GIF 三者之一，而不能将三者任意组合）
* 确保投放活动的投放周期（即 `start_time` 和 `end_time`）与计划推文的 `scheduled_at` 时间保持一致
* 计划推文的发布时间不应设置在距离当前时间超过一年（365 天）之后
* 目前不支持计划推文的预览功能（即在创建前预览计划推文）

### 媒体库

<div id="introduction">
  #### 介绍
</div>

Media Library 端点允许你为 X Ads 账户管理图像、GIF 和视频。媒体库中的素材可以用于推文以及创建卡片，也可以在多个[创意](https://developer.x.com/content/developer-twitter/en/docs/ads/creatives/overview)中重复使用，从而无需反复上传同一素材。

<div id="api-endpoints">
  #### API 端点
</div>

* [POST media/upload](https://developer.x.com/content/developer-twitter/en/docs/media/upload-media/api-reference/post-media-upload#post-media-upload) 或 [POST media/upload (chunked)](https://developer.x.com/content/developer-twitter/en/docs/media/upload-media/api-reference/post-media-upload-init#post-media-upload-init)（上传媒体）
* [POST accounts/:account&#95;id/media&#95;library](https://developer.x.com/x-ads-api/creatives#get-accounts-account-id-media-library#post-accounts-account-id-media-library)（将媒体添加到媒体库）

<div id="adding-to-the-library">
  #### 添加到媒体库
</div>

向媒体库添加媒体是一个由两步组成的流程。首先，使用 [POST media/upload](https://developer.x.com/content/developer-twitter/en/docs/media/upload-media/api-reference/post-media-upload#post-media-upload) 端点或 [POST media/upload (chunked)](https://developer.x.com/content/developer-twitter/en/docs/media/upload-media/api-reference/post-media-upload-init#post-media-upload-init) 这一组端点上传媒体素材。（有关我们分片上传流程的详细信息，请参阅 [分片媒体上传](https://developer.x.com/content/developer-twitter/en/docs/media/upload-media/uploading-media/chunked-media-upload) 指南。）

```
twurl -X POST -H upload.x.com "/1.1/media/upload.json?additional_owners=756201191646691328" --file latte.jpeg --file-field "media"
```

```json

   "media_id":966947208837742592,

   "expires_after_secs":86400,
   "image":{
      "image_type":"image/jpeg",
      "w":800,
      "h":418
```

<div id="request-parameters">
  #### 请求参数
</div>

所有 Media Library 的 POST 请求都需要一个媒体标识符。此值会在上传步骤中返回。使用 `media_id`（如上例所示）时，还必须指定 `media_category`。共有四种可能的类别值：`AMPLIFY_VIDEO`、`TWEET_GIF`、`TWEET_IMAGE` 和 `TWEET_VIDEO`。

可以为 Media Library 中的对象选择性地设置 `name` 和 `file_name` 值。这些属性有助于用户在库中区分不同的媒体变体。

对于视频，还可以设置 `title` 和描述。这些值旨在在调用 [POST accounts/:account&#95;id/tweet](https://developer.x.com/content/developer-twitter/en/docs/ads/creatives/api-reference/tweets#post-accounts-account-id-tweet) 端点时，作为 `video_title` 和 `video_description` 请求参数进行传递。在该推文中，这些文本会显示在视频下方。

<div id="attributes">
  #### 属性
</div>

Media Library 正式引入了 `media_key` 的概念。它是媒体库中对象的唯一标识符。Media key 的字符串值格式类似：13&#95;875943225764098048。我们的所有卡片相关端点都完全支持这种标识符。

此外，Media Library 响应中还包含以字符串形式表示的 `media_id`。对于当前尚不接受 media key 的资源，会返回该字段：[推文 (Tweets)](https://developer.x.com/content/developer-twitter/en/docs/ads/creatives/api-reference/tweets#post-accounts-account-id-tweet)*、[推文预览 (Tweet preview)](https://developer.x.com/content/developer-twitter/en/docs/ads/creatives/api-reference/tweets#get-accounts-account-id-tweet-preview)* 和 [预定推文 (Scheduled Tweets)](https://developer.x.com/content/developer-twitter/en/docs/ads/creatives/api-reference/scheduled-tweets#post-accounts-account-id-scheduled-tweets)。我们正在努力在所有场景中支持 media key。

`aspect_ratio` 属性会在 GIF 和视频上返回。它可用于筛选可用于仅接受特定宽高比的卡片中的媒体。

*这些端点支持 `video_id` 参数，其值即为 media key。

<div id="identifying-cards">

</div>

#### 简介

Card 是一种可自定义的广告格式，使用媒体内容，可以与网站、应用或带有号召性用语（call to action）的内容关联，用于推动特定用户互动，例如发起私信（Direct Message）。它可以附加到推文、定时推文或草稿推文中。

在 Tweet 对象中可以通过两种方式引用 Card：通过 Card 的 card&#95;uri 或通过它的 preview&#95;url。下面给出了每种方式的示例值。

| card&#95;uri | preview&#95;url |
| :--- | :--- |
| card://1043282691834048513 | https://cards.x.com/cards/18ce54d4x5t/68w3s |

**注意**：从 Ads API 版本 5 开始，cards 响应中不再返回 preview&#95;url。

<div id="identifying-media">
  ### 媒体识别
</div>

#### 简介

媒体（图片、GIF 和视频）可以添加到推文和卡片中。此外，视频可以用作前贴片素材，图片可以在 [X Audience Platform](https://developer.x.com/en/docs/ads/measurement/overview/twitter-audience-platform) 上进行推广。本节介绍如何在这些实体中查找媒体引用。

媒体标识符有两种类型：ID 和 key。下面展示了每种类型的示例值。

| **媒体 ID** | **媒体 key** |
| :--- | :--- |
| 1029825579531807971 | 13&#95;1029825579531807971 |

媒体 key 是在 ID 前添加数字前缀和下划线后得到的。

<div id="images">
  #### 图像
</div>

下表显示了当前每个与图像相关的资源在其响应中可用的标识符类型以及对应的属性名称。

| **Resource** | **Identifier** | **Attribute(s)** |
| :--- | :--- | :--- |
| Image cards | None |  |
| Tweet | Both | `entities["media"]["id_str"]`  `entities["media"]["media_key"]` |
| Scheduled Tweet | Both | `media_ids` and `media_keys` |
| Draft Tweet | Both | `media_ids` and `media_keys` |
| Account Media | None |  |
| Media Library | Both | `media_id` and `media_key` |

Image cards 和 Account Media 中的图像不包含对任何媒体标识符的引用。Tweet 仅包含媒体 ID。Scheduled Tweet 和 Draft Tweet 同时包含媒体 ID 和媒体 key。Media Library 也会返回这两者。

对于推文，entities[&quot;media&quot;] 数组中对象的 id 和 id&#95;str 字段对应媒体 ID。如果某条推文包含多张图片，对每个媒体实体的引用只能在 extended&#95;entities[&quot;media&quot;] 中找到。

除了对标识符的引用之外，通常还需要能够访问图像的 URL。

| **Resource** | **Attribute(s)** | **Format** |
| :--- | :--- | :--- |
| Image cards | `image` | .jpg |
| Tweet* | `entities["media"][0]["media_url"]` or `extended_entities["media"][i]["media_url"]` | .jpg |
| Scheduled Tweet | None |  |
| Draft Tweet | None |  |
| Account Media | `media_url` | .jpg |
| Media Library | `media_url` | .jpg |

* 该 URL 的位置取决于推文是包含单张图片还是多张图片。

所有 Image cards 都包含一个名为 image 的响应属性，其中包含 X 图像 URL。（对于 image app download cards，该属性名称为 wide&#95;app&#95;image。）

对于推文，media URL 的位置取决于媒体的类型以及所使用的端点。对于只包含一张图片的推文，URL 可以在 entities[&quot;media&quot;][0][&quot;media&#95;url&quot;] 中找到，这对 Ads API 和 Standard API 都适用。然而，当推文包含多张图片时，URL 只能在 extended&#95;entities[&quot;media&quot;][i][&quot;media&#95;url&quot;] 中找到。这仅在 Standard API 中可用。

<div id="video">
  #### 视频
</div>

下表显示了当前每个与视频相关的资源的响应中可用的标识符类型，以及对应的属性名称。

| **资源** | **标识符** | **属性** |
| :--- | :--- | :--- |
| Video cards | 可能为任一类型 | `video_content_id` |
| Video poll cards | 无 |  |
| Tweet | 两者都有 | `entities["media"]["id_str"]`  `entities["media"]["media_key"]` |
| Scheduled Tweet | 两者都有 | `media_ids` 和 `media_keys` |
| Draft Tweet | 两者都有 | `media_ids` 和 `media_keys` |
| Account Media | Media key | `video_id` |
| Media Library | 两者都有 | `media_id` 和 `media_key` |

虽然视频卡片（带视频的投票卡片除外）包含 `video_content_id` 响应属性，但其返回值的类型并不一致。在某些情况下，它是 media ID；在其他情况下，它是 media key。

以下是如何访问视频 URL 的相关信息。

| **资源** | **属性** | **格式** |
| :--- | :--- | :--- |
| Video cards | `video_url` 和 `video_hls_url` | .vmap  .m3u8 |
| Tweet with video | `extended_entities["media"][i]["video_info"]["variants"][j]["url"]` | .mp4 |
| Scheduled Tweet | 无 |  |
| Draft Tweet | 无 |  |
| Account Media | 无 |  |
| Media Library | `media_url` | .mp4 |

视频卡片包含 `video_url` 和 `video_hls_url` 响应属性，分别对应 .vmap 和 .m3u8 的 URL。

<div id="media-library">
  #### 媒体库
</div>

有时需要检索媒体资产的其他信息。以视频卡片为例，有时需要获取 mp4 URL，而不是 vmap URL。这些信息可以在 Media Library（媒体库）中获取。有关可用信息的详细说明，请参阅我们的[媒体库指南](https://developer.x.com/content/developer-twitter/en/docs/ads/creatives/guides/media-library)。大多数属于该广告账户 FULL 可推广用户的资产都可以在媒体库中找到，但也有一些例外。

**获取媒体**

如上所述，图片卡片不包含对 media ID 或 media key 的引用。因此，无法通过媒体库来获取它们的资产。[Account Media](https://developer.x.com/content/developer-twitter/en/docs/ads/creatives/api-reference/account-media#account-media) 图像同样如此。

在创建视频卡片之前，视频资产必须已经存在于媒体库（或其前身 Videos 资源）中。因此，这些资产始终可以在媒体库中检索。Account Media 中的 PREROLL 资产同样如此。

最后，推文中的媒体始终保证存在于媒体库中。

下表总结了在媒体库中可以检索到哪些资产，并结合资源响应中是否包含用于查找的标识符进行说明。

| **Resource** | **In the Media Library** |
| :--- | :--- |
| Image cards | No |
| Video cards | Yes* |
| Tweets (any media)** | Yes |
| Scheduled Tweets | Yes |
| Draft Tweets | Yes |
| Account media images | No |
| Account media videos (`PREROLL`) | Yes |

* 对于 `video_content_id` 为 media key 的卡片。当该值为 media ID 时，资产仍然存在于媒体库中，但检索时需要在其前面追加一个数字前缀和下划线。
** 推文仅返回 media ID。尽管可以保证资产存在于媒体库中，但获取它需要在其前面追加一个数字前缀和下划线。

**与 Account Media 的交互**

在以下两种情况下，添加到媒体库的媒体资产会自动添加到 Account Media 资源中：

* 当 AMPLIFY&#95;VIDEO 资产被添加到媒体库时，它会自动作为 PREROLL 创意类型的 Account Media 资产添加。
* 当具有特定尺寸的图像（参见我们[枚举页面](https://developer.x.com/content/developer-twitter/en/docs/ads/general/overview/enums)中的“Creative Types”）被添加到媒体库时，它们会自动作为 Account Media 资产添加。创意类型（例如 INTERSTITIAL）取决于图像的尺寸。

<div id="tweets">
  ### 推文
</div>

#### 简介

X Ads API 支持三种类型的推文：已发布推文、排期推文和草稿推文。

<div id="nullcasted-tweets">
  #### Nullcasted 推文
</div>

推文可以是 nullcasted（又称为“仅推广”）或自然推文。Nullcasted 推文在发布后不会出现在用户的公开时间线上，但它们仍然是公开的。相对地，自然推文会投放给用户的关注者，并出现在用户的公开时间线上。

**创建推文**

三个创建 Tweet 的端点都支持一个布尔值类型的 `nullcast` 参数，使 API 使用者可以选择创建 nullcasted 或自然推文。Nullcasted 推文既可以由用户本人创建，也可以由任何有权限代表该用户创建推文的人创建。自然推文只能由[完全可推广用户](https://developer.x.com/content/developer-twitter/en/docs/tutorials/ads-api-hierarchy-terminology#promotable-users)创建。

**更新推文**

可以更新计划推文和草稿推文的 `nullcast` 属性。对于计划推文，可以在该推文的 `scheduled_at` 时间点之前进行编辑。草稿推文可以无限期编辑。但是，一旦发布，就无法在 nullcasted 与自然推文之间相互转换。

<div id="promoting-tweets">
  #### 推广推文
</div>

只有已发布和已排期的推文可以被推广。它们可以是未公开投放（nullcasted）或自然投放（organic），对此没有限制。广告主可以推广自己的推文，也可以在获得许可的前提下推广其他用户的推文。（参见：[Promoting another user&#39;s Tweets](https://developer.x.com/content/developer-twitter/en/docs/tutorials/promoting-another-users-content) 了解更多信息。）

在单个广告活动中可以推广多条推文。同样，一条推文也可以在一个或多个广告活动中推广。

要推广已发布的推文，请使用 [POST accounts/:account&#95;id/promoted&#95;tweets 端点](https://developer.x.com/content/developer-twitter/en/docs/ads/campaign-management/api-reference/promoted-tweets#post-accounts-account-id-promoted-tweets)。此端点会将已发布的推文与一个广告单元（line item）关联。要推广已排期的推文，请使用 [POST accounts/:account&#95;id/scheduled&#95;promoted&#95;tweets](https://developer.x.com/content/developer-twitter/en/docs/ads/campaign-management/api-reference/scheduled-promoted-tweets#post-accounts-account-id-scheduled-promoted-tweets) 端点。

<div id="tweet-ids">
  #### 推文 ID
</div>

已发布、已排期和草稿推文的 ID 为[数值类型](https://developer.x.com/content/developer-twitter/en/docs/basics/twitter-ids)——它们是 64 位无符号整数。例如，下面这条已发布推文的 ID 为 1166476031668015104。

<div id="carousels">
  ### 轮播组件
</div>

#### 简介

X Ads API 支持创建和检索视频轮播和图片轮播。轮播是一种卡片类型，可以包含 2 到 6 个媒体资源。轮播卡片可以将用户引导到某个网站，或鼓励他们安装移动应用。有关轮播广告、其优势、最佳实践和常见问题的更多信息，请参阅我们的 [Carousel Ads on X](https://business.x.com/en/advertising/carousels.html) 页面。

与任何其他卡片类型一样，轮播可以用于推文，这些推文随后可以被推广。其工作流程与您已经熟悉的流程相同：

1. 上传媒体
2. 创建卡片
3. 创建推文
4. 推广推文

唯一的区别在于卡片的创建方式。其他卡片创建请求接受查询参数，而轮播卡片创建请求只接受 JSON POST 请求体。

<div id="endpoints">
  #### 端点
</div>

Ads API 支持创建和检索轮播广告。

要创建任意类型的轮播广告，请使用 [POST accounts/:account&#95;id/cards](https://developer.x.com/en/docs/twitter-ads-api/creatives/api-reference/cards#post-accounts-account-id-cards) 端点。要检索轮播广告，请使用 [GET accounts/:account&#95;id/cards](https://developer.x.com/en/docs/twitter-ads-api/creatives/api-reference/cards#get-accounts-account-id-cards) 端点。

<div id="json-post-body">
  #### JSON POST 正文
</div>

轮播图是通过两个组件来创建的。第一个组件用于指定要使用的媒体资源。第二个组件用于指定网站或应用的信息。

具体来说，一个轮播卡片是通过按以下顺序使用这些组件来创建的：

* 一个 `SWIPEABLE_MEDIA` 组件，它接收一个媒体键数组
* *以下组件中的一个*：
* 一个 `DETAILS` 组件，用于指定网站信息
* 一个 `BUTTON` 组件，用于指定应用信息

`SWIPEABLE_MEDIA` 组件必须包含一个 `media_keys` 数组，你可以在其中指定 2 到 6 张图片或视频。传入媒体键的顺序决定了它们被渲染的顺序。

```
{
  "type": "SWIPEABLE_MEDIA",
  "media_keys": [
    "13_1089771253848666112",
    "13_1191948012077092867"
  ]
}
```

提醒一下，你可以通过向 [GET accounts/:account&#95;id/media&#95;library](https://developer.x.com/en/docs/twitter-ads-api/creatives/api-reference/media-library#get-accounts-account-id-media-library) 端点发起请求来获取 media key。

第二个组件对象的构成取决于你是希望将用户引导到某个网站，还是鼓励他们安装应用。下表总结了这两个选项。（**注意**：列出的所有键都是必需的。）

|        | **网站**                                                             | **应用**                                            |
| :----- | :----------------------------------------------------------------- | :------------------------------------------------ |
| 指定组件类型 | `"type": "DETAILS"`                                                | `"type": "BUTTON"`                                |
| 标题/标签  | `"title": "X"`                                                     | `"label": { "type": "ENUM", "value": "INSTALL" }` |
| 目标地址   | `"destination": { "type": "WEBSITE", "url": "https://www.x.com" }` | `"destination": { "type": "APP", ... }`           |

综合以上内容，下面展示了一个网站轮播的 JSON POST 请求体示例。

```
{
  "name": "website carousel",
  "components": [
    {
      "type": "SWIPEABLE_MEDIA",
      "media_keys": [
        "13_1089771253848666112",
        "13_1191948012077092867"
      ]
    },
    {
      "type": "DETAILS",
      "title": "X",
      "destination": {
        "type": "WEBSITE",
        "url": "https://www.x.com"
      }
    }
  ]
}
```

`BUTTON` 组件中的应用目标对象需要提供国家代码和至少一个应用标识符，还可以可选地包含深度链接。有关这些字段的说明，请参阅[参考文档](https://developer.x.com/en/docs/twitter-ads-api/creatives/api-reference/cards#app-destination)。

综合以上内容，下面展示了一个应用轮播 JSON POST 请求正文示例。

```
{
  "name": "app carousel",
  "components": [
    {
      "type": "SWIPEABLE_MEDIA",
      "media_keys": [
        "13_1089771253848666112",
        "13_1191948012077092867"
      ]
    },
    {
      "type": "BUTTON",
      "label": {
        "type": "ENUM",
        "value": "INSTALL"
      },
      "destination": {
        "type": "APP",
        "country_code": "US",
        "googleplay_app_id": "com.twitter.android",
        "iphone_app_id": "333903271"
      }
    }
  ]
}
```

<div id="creative-metadata-tagging">

</div>

#### 简介

本指南面向创意合作伙伴、代理商和创意开发者，指导他们为 X 广告活动中使用的素材添加标签，以便更好地了解单个素材的价值和表现。

Creative Metadata Tagging 为由创意合作伙伴创建的图片和视频提供归因，无论该素材在 X 的何处被上传，也无论由哪个主体上传。为了在创意素材与创意合作伙伴之间建立关联，我们使用 [XMP](https://exiftool.org/TagNames/XMP.html) 标准。

<div id="post-accountsaccount_idcards">
  #### POST accounts/:account_id/cards
</div>

创建一个与指定账户关联的新卡片。

卡片创建请求仅接受 JSON 格式的 POST 请求体。`Content-Type` 必须设置为 `application/json`。

详细用法示例请参阅我们的[轮播指南](https://developer.x.com/en/docs/twitter-ads-api/creatives/guides/carousels)。

<div id="resource-url">
  #### 资源 URL
</div>

`https://ads-api.x.com/12/accounts/:account_id/cards`

#### 参数

JSON POST 请求体必须包含一个卡片的 `name` 字段和一个 `components` 数组。组件以对象形式表示，用于描述卡片面向广告主的属性。

下面的示例展示了载荷的一般结构（但其中的信息不可用）。

```
{
  "name": "some name",
  "components": [
    {
      "type": "TYPE_ENUM",
      "key": "value"
    }
  ]
}
```

下面是关于组件的补充信息。

| Name                              | Description                                                                                                                                                                                                            |
| :-------------------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| account&#95;id   *required*       | 广告账户的标识符。出现在资源路径中，并且通常是除 [GET accounts](https://developer.x.com/en/docs/ads/campaign-management/api-reference/accounts#get-accounts) 之外所有 Advertiser API 请求的必需参数。指定的账户必须与已授权用户关联。 Type: string  Example: `18ce54d4x5t` |
| name   *required*                 | 卡片的名称。最大长度：80 个字符。 Type: string  Example: `component based card`                                                                                                                                                       |
| components   *sometimes required* | 描述用于创建卡片的组件。更多信息见下文。不能与 `slides` 同时指定。**注意**：组件的顺序很重要。 Type: array of objects                                                                                                                                          |
| slides   *sometimes required*     | 使用该数组的数组来创建多目标轮播（Multi-Destination Carousels）。将每张卡片描述为组件的分组。每个 slide 都应完整呈现一张卡片。不能与 `components` 同时指定。**注意**：每个 slide 的顺序很重要。 Type: array of array                                                                     |

<div id="components">
  #### 组件
</div>

每个组件都必须包含一个 `type` 字段，用于确定对象的 schema。Ads API 支持以下组件类型，分为媒体类组件和描述类组件。

* 媒体：
* `MEDIA`：单个视频或图片
* `SWIPEABLE_MEDIA`：2–6 个视频或图片
* 描述：
* `DETAILS`
* `BUTTON`

每个组件都有一组必需字段（除了 `type` 键之外）。这些字段列在下表中。

| 组件 `type`         | 字段                      | 值类型       |
| :---------------- | :---------------------- | :-------- |
| `MEDIA`           | `media_key`             | 字符串       |
| `SWIPEABLE_MEDIA` | `media_keys`            | 字符串数组     |
| `DETAILS`         | `title`   `destination` | 字符串   对象  |
| `BUTTON`          | `label`   `destination` | 对象     对象 |

下面是在 `components` 数组中的一个 `BUTTON` 组件示例（特意省略 `name` 键）。（省略号表示在这些位置需要提供更多信息。）

```
{
  "components": [
    {
      "type": "BUTTON",
      "label": {
        ...
      },
      "destination": {
        ...
      }
    }
  ]
}
```

指定组件对象的顺序决定了它们自上而下的渲染顺序。卡片必须使用一个媒体组件以及一个 `DETAILS` 或 `BUTTON` 组件来创建。基于描述的组件会渲染在媒体下方，并且具有关联的目标，要么是 URL，要么是移动应用。

**Label**

Label 定义显示在按钮上的文本，因此只适用于 `BUTTON` 组件。Label 对象有两个必需的键：`type` 和 `value`。`type` 必须设置为 `ENUM`，`value` 可以是以下之一：`BOOK`、`CONNECT`、`INSTALL`、`OPEN`、`ORDER`、`PLAY` 或 `SHOP`。

在前一个示例的基础上，下面展示了 `BUTTON` 组件中的 `label` 对象。

```
{
  "components": [
    {
      "type": "BUTTON",
      "label": {
        "type": "ENUM",
        "value": "INSTALL"
      },
      "destination": {
        ...
      }
    }
  ]
}
```

**目标地址**

目标地址是广告主希望将用户引导到的地方。它在 `DETAILS` 或 `BUTTON` 组件中始终为必需字段。目标地址有两种类型：`WEBSITE` 或 `APP`。

**注意**：网站目标地址只能与 `DETAILS` 组件一起使用，应用目标地址只能与 `BUTTON` 组件一起使用。

**网站目标地址**

| 名称          | 描述                                                                          |
| :---------- | :-------------------------------------------------------------------------- |
| type   *必需* | 目标地址的类型，用于决定其 schema 定义。 类型: enum  可能的取值：`WEBSITE`                          |
| url   *必需*  | 用于将用户重定向到的网站 URL。 类型: 字符串  示例：`https://devcommunity.x.com/c/advertiser-api` |

**应用目标地址**

| 名称                                             | 描述                                                                                                                       |
| :--------------------------------------------- | :----------------------------------------------------------------------------------------------------------------------- |

<div id="post-accountsaccount_idtweet">
  #### POST accounts/:account_id/tweet
</div>

为账号的完整可推广用户（默认），或在 `as_user_id` 参数中指定的用户创建一条推文。支持创建 nullcast（默认）推文和自然推文。nullcast 推文不会出现在公共时间线中，也不会推送给粉丝。这两种类型都可用于广告投放活动。

如果经过身份验证的用户不是此账号上的 `FULL` 可推广用户，请通过调用 [GET accounts/:account&#95;id/authenticated&#95;user&#95;access](https://developer.x.com/en/docs/ads/campaign-management/api-reference/authenticated-user-access#get-accounts-account-id-authenticated-user-access) 端点，确定其是否具有代表该用户发布推文的权限。权限值为 `TWEET_COMPOSER` 表示该用户可以使用此端点，代表 `FULL` [可推广用户](https://developer.x.com/en/docs/ads/campaign-management/api-reference/promotable-users#get-accounts-account-id-promotable-users) 创建 nullcast 推文。

在为媒体使用 [upload.x.com endpoint](https://developer.x.com/rest/reference/post/media/upload) 时，请将与本端点中传入的 `as_user_id` 值相同的 `user_id` 值作为 `additional_owners` 参数传入。
