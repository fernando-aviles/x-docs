<div id="overview">
  ## 概览
</div>

<div id="introduction">
  ### 介绍
</div>

A/B 测试允许广告主对他们在 X 上触达的用户进行细分分组，从而了解如何最大化优化广告活动表现，并获取洞察以指导其营销策略。

这些分组——称为用户组拆分（user group splits）——是随机且互斥的。通过随机化，影响结果的各类因素会被均匀分布。换句话说，各组之间及其预期行为不存在内在差异。正因如此，当仅对某一个用户组应用某个单一变体、而对其他组不应用时，广告活动表现上的差异就可以归因于该变体。

尽管可以同时测试多个变体，我们强烈建议一次只测试一个变体。这样可以将导致广告活动表现差异的因果因素单独隔离出来。

变体是在广告活动级别设置的。举例来说，如果广告主想测试一个新创意（creative）的效果，应创建两个完全相同的广告活动，并确保唯一的差异就是该创意。未来，我们计划支持在广告单元（line item）级别设置变体。

<div id="use-cases">
  ### 使用场景
</div>

A/B 测试最常用于两类场景：（1）面向绩效客户的“优化”类场景，帮助他们了解在 X 上哪些策略效果最佳，从而优化投放投入；以及（2）面向品牌广告主的“学习”类场景，帮助他们利用测试结论来指导营销策略。 

该 API 将支持对任何广告活动变量进行 A/B 测试，包括：

* 创意 

* 定向 

* 出价类型

* 出价单位

<div id="ab-testing">
  ## A/B 测试
</div>

A/B 测试使广告主能够对他们在 X 上触达的用户进行分组，从而了解如何以最佳方式优化广告系列表现，并从中获取经验洞察，以指导他们的营销策略。

这些分组——称为用户分组拆分（user group splits）——是随机且互斥的。通过随机化，影响结果的各种因素会被均匀分配。换句话说，各组之间或它们的预期行为之间不存在内在差异。正因如此，当某个变体仅应用于一个用户组而未应用于其他用户组时，广告系列表现的差异可以归因于该变体。

虽然可以同时测试多个变体，但我们强烈建议一次只测试一个变体。这样可以将导致观察到的广告系列表现差异的因果因素单独隔离出来。

变体可以设置在广告系列层级或广告组层级。广告组通过 Ads API 中的 [line item](https://developer.x.com/en/docs/twitter-ads-api/campaign-management/api-reference/line-items) 来设置。以广告组层级的变体为例，如果广告主想测试一个新广告创意的效果，应创建一个广告系列，包含两个完全相同的广告组，二者之间唯一的差异就是广告创意本身。

<div id="use-cases">
  ### 使用场景
</div>

A/B 测试最常用于支持两类使用场景：(1) 为绩效型客户提供优化类场景，帮助他们了解在 X 上什么效果最好，从而优化其广告投放投入；以及 (2) 为品牌广告主提供学习类场景，帮助他们利用测试所得洞察来制定营销策略。 

该 API 将支持针对任何广告系列变量进行 A/B 测试，包括：

* 创意

* 定向

* 出价类型

* 出价单位

<div id="attributes">
  ### 属性
</div>

A/B 测试以嵌套结构表示。A/B 测试本身有顶层字段，以及一个用户分组对象数组，每个对象都有一组字段用于对其进行描述。

从整体上看，每个 A/B 测试都必须包含以下信息。

* 测试持续时间，由 start&#95;time 和 end&#95;time 字段表示

* 进行流量划分的级别，由 entity&#95;type 字段表示

* 至少两个（且最多 30 个）用户分组，每个分组在 user&#95;groups 数组中表示为一个对象

每个用户分组*必须*包含以下信息。

* 应该分配到该用户分组的用户占比，由 size 字段表示

* 应构成该用户分组用户池的 campaign id/line item id，由 entity&#95;ids 数组表示

可选地，你可以为 A/B 测试和用户分组设置 name 和 description 字段的值。有关验证规则和其他约束的信息可在下方找到。

其他元数据，例如 id 或创建时间，也会包含在内，但由 X 自动设置。

<div id="usage">
  ### 使用说明
</div>

以下小节介绍如何创建和更新 A/B 测试。读取和删除操作的用法与其他 Ads API 端点相同。

<div id="creating">
  #### 创建
</div>

使用 [POST accounts/:account&#95;id/ab&#95;tests](https://developer.x.com/en/docs/x-ads-api/measurement/api-reference/ab-tests) 端点创建 A/B 测试。该端点仅接受 JSON POST 请求体。`Content-Type` 必须设置为 `application/json`。

在广告主设置了两个或更多推广活动后，就可以创建 A/B 测试。如上所述，A/B 测试 *必须* 包括：测试时长、拆分层级，以及至少两个用户组。每个用户组必须声明要分配给该组的用户百分比，以及构成其用户池的推广活动 ID。下文将对这些内容分别进行更详细的说明。

测试时长：

* start&#95;time 和 end&#95;time 的值必须

  * 位于未来（相对于创建 A/B 测试的时间）

  * 与推广活动/广告单元的投放日期有重叠

* 对于非应用类推广活动，测试必须至少持续一天；对于应用类推广活动，测试必须至少持续五天

拆分层级：

* entity&#95;type 可以设置为 CAMPAIGN 或 LINE&#95;ITEM

用户组：

* 每个用户组在 user&#95;groups 数组中表示为一个对象

  * 至少需要两个用户组

  * 最多允许 30 个用户组

* 每个用户组的大小通过 1.00 到 99.00 之间数值的字符串表示形式来设置

  * **注意**：各对象的 size 数值之和 **必须** 为 100.00

* 每个用户组的推广活动 ID 应在该用户组的 entity&#95;ids 数组中指定

你也可以选择为 A/B 测试或一个或多个用户组设置 name 和 description 字段。

**针对广告单元层级进行 A/B 测试**

在广告系列层级和广告单元层级进行 A/B 测试的主要区别是 entity&#95;type。对于广告单元层级的 A/B 测试，我们需要将其设置为 ‘entity&#95;type’ = ‘LINE&#95;ITEM’。这适用于下文对已创建 A/B 测试执行的所有操作。 

要求：

1. A/B 测试广告系列中的所有广告单元必须包含在该分组测试中。
2. 在广告单元层级只允许进行均等拆分。
3. 单次分组测试中允许的用户组（广告单元）数量必须小于或等于 5 个。 
4. 每个用户组仅允许 1 个广告单元。

<div id="updating">
  ### 更新
</div>

使用 [PUT accounts/:account&#95;id/ab&#95;tests/:ab&#95;test&#95;id](https://developer.x.com/en/docs/x-ads-api/measurement/api-reference/ab-tests) 端点更新 A/B 测试。该端点要求在请求中发送一个 JSON 数据块。`Content-Type` 必须设置为 `application/json`。

与其他更新端点类似，[PUT accounts/:account&#95;id/ab&#95;tests/:ab&#95;test&#95;id](/zh/x-ads-api/measurement/ab-testing#get-accounts-account-id-ab-tests) 端点要求在 URL 中包含 A/B 测试 ID。一般来说，只有当状态为 `SCHEDULED` 时，A/B 测试才可以被更新。有一个例外：当 A/B 测试处于 `LIVE` 状态时，可以更新该 A/B 测试的 `end_time`。

此端点支持带对象 ID 的部分 JSON 更新。适用以下原则：

* 若要添加或删除对象或元素，传入整个数组（及其子结构）；这是一次**替换**操作

* 其他情况下，通过引用键名或 ID 来修改（更改、添加、删除）现有*字段*

  * 若要删除字段，将其值设置为 `null`

  * 未传入的字段不会被修改

例如，要在之前创建的 A/B 测试中添加第三个用户组，我们需要在 `user_groups` 数组中同时包含两个现有的用户组对象以及希望添加的新用户组。可以将其视为*重新创建* `user_groups` 数组；传入的数据应好像你一开始就是以这种方式创建它（不要传入用户组对象 ID）。更新请求中的 `user_groups` 数组可以如下所示。

```json
[
  {
    "entity_ids": [
      "f2qcw",
      "f2tht"
    ],
    "size": "30.0",
    "name": "first group"
  },
  {
    "entity_ids": [
      "f2rqi",
      "f2tws"
    ],
    "size": "30.0",
    "name": "second group",
    "description": "second AB test group"
  },
  {
    "entity_ids": [
      "i1vwr",
      "i1xre"
    ],
    "size": "40.0"
  }
]
```

请注意，各对象的 size 字段取值相加后仍然为 100.00。如果我们没有更新前两个对象（它们之前各为 50.00），请求就会失败。

如果我们只是想为第一个用户组添加描述，则在更新请求中，user&#95;groups 数组将表示如下。

```json
[
  {
    "id": "p1bcx",
    "description": "updated using a PUT request"
  }
]
```

我们通过其 id 引用用户组对象，并且只包含需要修改的字段。
