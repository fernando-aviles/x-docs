<div id="overview">
  ## 概览
</div>

<div id="introduction">
  ### 介绍
</div>

A/B 测试允许广告主对其在 X 上触达的用户进行分组，从而了解如何更好地优化广告系列表现，并获取经验洞察，以指导其营销策略。

这些分组——称为用户组拆分（user group splits）——是随机且互斥的。通过随机化，影响结果的各种因素会被均匀分布。换句话说，各组之间或其预期行为不存在内在差异。正因如此，当只对某一个用户组而非其他用户组应用某个单一变体时，广告系列表现上的差异就可以归因于该变体。

尽管可以同时测试多个变体，我们仍强烈建议一次仅测试一个变体。这样可以将导致观察到的广告系列表现差异的因果因素单独隔离出来。

变体是在广告系列级别设置的。比如，如果广告主想测试一个新创意的效果，他们应创建两个完全相同的广告系列，唯一的区别就是创意本身。未来，我们计划支持在投放单元（line item）级别设置变体。

<div id="use-cases">
  ### 使用场景
</div>

A/B 测试最常用于两类使用场景：（1）面向绩效广告主的优化类场景，这类客户希望了解在 X 上哪些方案表现最佳，从而优化其投放回报；以及（2）面向品牌广告主的学习类场景，这类广告主希望利用测试结果来指导其营销策略。

该 API 支持针对任意广告活动变量进行 A/B 测试，包括：

* 创意

* 定向

* 出价类型

* 出价单位

<div id="ab-testing">
  ## A/B 测试
</div>

A/B 测试允许广告主对他们在 X 上所触达的用户进行分组，从而了解如何以最佳方式优化广告系列表现，并积累经验以指导其市场营销策略。

这些分组——称为用户组拆分（user group splits）——是随机且互斥的。通过随机化，影响结果的各类因素会被均匀分布。换句话说，各组之间在本质上不存在差异，其预期行为也应相同。正因如此，当某个变体只应用于一个用户组而不应用于其他用户组时，广告系列表现的差异可以归因于该变体本身。

虽然可以同时测试多个变体，但我们强烈建议一次只测试一个变体。这样可以将导致广告系列表现差异的因果因素单独隔离出来。

变体可以设置在广告系列层级或广告组层级。广告组是通过 Ads API 中的 [line item](https://developer.x.com/en/docs/twitter-ads-api/campaign-management/api-reference/line-items) 来设置的。以广告组层级的变体为例，如果广告主想测试一个新创意的效果，他们应创建一个包含 2 个相同广告组的广告系列，并确保这两个广告组之间唯一的差异就是该创意本身。

<div id="use-cases">
  ### 使用场景
</div>

A/B 测试最常用于支持两类场景：（1）针对效果广告主的优化类用例，这类客户希望了解在 X 上哪些方案表现最佳，从而优化其投入；以及（2）针对品牌广告主的学习类用例，这类客户希望利用测试结果来指导其营销策略。 

该 API 将支持针对任何广告系列变量进行 A/B 测试，包括：

* 创意素材

* 定向

* 出价类型

* 出价单位

<div id="attributes">
  ### 属性
</div>

A/B 测试表示为嵌套结构。顶层包含 A/B 测试本身的字段，以及一个用户分组对象数组，其中每个对象都有一组字段用于描述该用户分组。

在总体层面上，每个 A/B 测试必须包含以下信息。

* 测试持续时间，由 start&#95;time 和 end&#95;time 字段表示

* 进行流量拆分的层级，由 entity&#95;type 字段表示

* 至少两个（最多 30 个）用户分组，每个用户分组在 user&#95;groups 数组中表示为一个对象

每个用户分组 *必须* 包含以下信息。

* 应分配到该用户分组的用户百分比，由 size 字段表示

* 应构成该用户分组用户池的 campaign ID/line item ID，由 entity&#95;ids 数组表示

此外，可以为 A/B 测试和用户分组设置可选的 name 和 description 值。有关验证规则和其他约束的信息见下文。

其他元数据（例如 ID 或创建时间）也会包含在内，但由 X 自动设置。

<div id="usage">
  ### 用法
</div>

以下小节介绍如何创建和更新 A/B 测试。读取和删除操作的行为与所有其他 Ads API 端点相同。

<div id="creating">
  #### 创建
</div>

使用 [POST accounts/:account&#95;id/ab&#95;tests](https://developer.x.com/en/docs/x-ads-api/measurement/api-reference/ab-tests) 端点创建一个 A/B 测试。该端点只接受 JSON 格式的 POST 请求体。`Content-Type` 必须设置为 `application/json`。

在广告主设置了两个或更多广告系列之后，就可以创建 A/B 测试。如上所述，A/B 测试&#95;必须&#95;包含：测试时长、拆分级别，以及至少两个用户组。每个用户组都必须声明应该分配给该组的用户百分比，以及构成其用户池的广告系列 ID。下面将对这些内容进行更详细的说明。

测试时长：

* `start_time` 和 `end_time` 的值必须

  * 位于将来的时间点（相对于创建 A/B 测试的时间）

  * 与广告系列/广告单元的投放日期有重叠

* 对于非基于 App 的广告系列，测试至少需要持续一天；对于基于 App 的广告系列，测试至少需要持续五天

拆分级别：

* `entity_type` 可以设置为 `CAMPAIGN` 或 `LINE_ITEM`

用户组：

* 每个用户组在 `user_groups` 数组中表示为一个对象

  * 至少需要两个用户组

  * 最多允许 30 个用户组

* 每个用户组的占比通过一个 1.00 到 99.00 之间的数值字符串来设置

  * **注意**：各对象的 size 值 **必须** 相加为 100.00

* 广告系列 ID 应在每个用户组的 `entity_ids` 数组中指定

你可以选择为 A/B 测试或一个或多个用户组设置名称和描述。

**针对 Line item 级别的 A/B 测试**

在 campaign 级别和 Line item 级别进行 A/B 测试的主要区别在于 `entity_type`。对于 Line item 级别的 A/B 测试，我们需要将其设置为 `entity_type` = `LINE_ITEM`。下面对已创建的 A/B 测试执行的所有操作都适用这一点。 

要求：

1. A/B 测试所属 campaign 中的所有 Line item 必须都包含在该拆分测试中。
2. Line item 级别只允许等比例拆分。
3. 单个拆分测试中允许的用户组 Line item 数量必须小于或等于 5。 
4. 每个用户组只允许 1 个 Line item。

<div id="updating">
  ### 更新
</div>

使用 [PUT accounts/:account&#95;id/ab&#95;tests/:ab&#95;test&#95;id](https://developer.x.com/en/docs/x-ads-api/measurement/api-reference/ab-tests) 端点更新 A/B 测试。该端点要求在请求中发送 JSON 数据块。`Content-Type` 必须设置为 `application/json`。

与其他更新端点类似，[PUT accounts/:account&#95;id/ab&#95;tests/:ab&#95;test&#95;id](/zh/x-ads-api/measurement/ab-testing#get-accounts-account-id-ab-tests) 端点要求在 URL 中包含 A/B 测试 ID。通常情况下，只有在状态为 `SCHEDULED` 时，A/B 测试才可以被更新。有一个例外：在测试处于 `LIVE` 状态时，可以更新 A/B 测试的 `end_time`。

此端点支持带有对象 ID 的部分更新 JSON。适用以下原则：

* 若要添加或移除对象或元素，请传入整个数组（及其子结构）；这是一次**替换**操作

* 其他情况下，通过引用键名或 ID 来修改（更改、添加、删除）现有*字段*

  * 若要删除某个字段，将其值设为 `null`

  * 未在请求中传入的字段不会被修改

例如，向先前创建的 A/B 测试中添加第三个用户组，需要在 `user_groups` 数组中同时传入两个现有的用户组对象以及想要新增的用户组对象。可以将其视为*重新创建* `user_groups` 数组；像一开始创建它时那样传入数据（不要传入用户组对象 ID）。更新请求中的 `user_groups` 数组可以表示为如下形式。

```json
[
  {
    "entity_ids": [
      "f2qcw",
      "f2tht"
    ],
    "size": "30.0",
    "name": "first group"
  },
  {
    "entity_ids": [
      "f2rqi",
      "f2tws"
    ],
    "size": "30.0",
    "name": "second group",
    "description": "second AB test group"
  },
  {
    "entity_ids": [
      "i1vwr",
      "i1xre"
    ],
    "size": "40.0"
  }
]
```

请注意，各对象中的 size 值相加后仍为 100.00。若我们没有更新前两个对象（之前各自设置为 50.00），该请求就会失败。

如果我们只是想为第一个用户组添加一个描述，则在更新请求中，user&#95;groups 数组将表示如下。

```json
[
  {
    "id": "p1bcx",
    "description": "updated using a PUT request"
  }
]
```

我们根据 id 引用用户组对象，并且只包含需要修改的字段。
