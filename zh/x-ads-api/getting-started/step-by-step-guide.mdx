<div id="how-to-get-access-to-the-ads-api">
  ## 如何获取 Ads API 访问权限
</div>

1. 注册一个[开发者账号](https://developer.x.com/en/apply-for-access)。
2. 创建一个[开发者 App](https://developer.x.com/app)并妥善保管你的令牌（token）。
3. 访问 [ads.x.com/help](https://ads.x.com/help)，为你的每个开发者 App 提交 Ads API 访问申请。

<Note>**注意：**如果你已经在 X Developer Platform 上进行开发并已拥有开发者账号，可以直接跳到第三步。</Note>

<div id="step-one-signup-for-a-developer-account">
  ### 第一步：注册开发者账号
</div>

要向任何 X API 产品发起请求，您必须先注册一个开发者账号。在开发者控制台中创建一个 App 和开发者 App。这样您就会获得一组凭据，用于对所有 API 请求进行身份验证。

<Button href="https://developer.x.com/en/apply-for-access">
  注册开发者账号
</Button>

<div id="step-two-save-your-apps-key-and-tokens-and-keep-them-secure">
  ### 第二步：保存你的 App 密钥和令牌并确保其安全
</div>

在你的开发者 App 中，你会获得一组 API Keys（也称为 Consumer Keys）。你还可以生成一组 Access Tokens，用于代表你的个人 X 账号发起请求，以及一个 Bearer Token，用于对需要 OAuth 2.0 Bearer 令牌的端点进行身份验证。由于这些密钥和令牌除非被重新生成否则不会过期，我们建议你通过创建环境变量或使用安全的密码管理器来保存它们。

请同时记录你的 App ID，它可以在 App 详情页面的 URL 中找到。这将使你在下一步申请 Ads API 访问权限时更为方便。

<Note>
**注意：** 你的密钥和令牌只会在开发者控制台中显示一次，因此在生成它们之后，务必立即将这些凭证存储到你的密码管理系统中。

如果你丢失或忘记了这些密钥和令牌，你需要重新生成它们，这会创建新的密钥和令牌，并使旧的失效。这意味着你必须更新任何使用旧凭证配置的集成。

详细了解我们的[身份验证最佳实践](https://developer.x.com/en/docs/authentication/guides/authentication-best-practices)。
</Note>

<div id="step-three-apply-for-access-to-the-ads-api">
  ### 步骤三：申请 Ads API 访问权限
</div>

此时，你已经拥有了 [X API 的基本访问权限](https://developer.x.com/en/docs/twitter-api/v1)，但还无法使用特定的 X Ads API 功能。接下来，你需要申请并获批 Ads API 的访问权限。前往 [ads.x.com/help](https://ads.x.com/help)，为你的每个开发者 App 提交 Ads API 访问申请。

<div id="access-tiers">
  ### 访问层级
</div>

作为申请流程的一部分，你需要说明所需的访问层级。详细了解 [App 级别和广告账号级别的权限](https://developer.x.com/en/docs/twitter-ads-api/obtaining-ads-account-access#levels-of-access)。

<div id="conversion-only">
  #### 仅转化
</div>

可对移动端和网页转化端点进行读写访问。

<div id="standard-access">
  #### 标准访问
</div>

可使用读写权限访问 Analytics、Campaign Management、Creatives、Custom Audiences 和 Conversion 端点。

<Note>**注意：**在你的 App 获得 Ads API 访问权限审批通过后，你需要[重新生成任何用户访问令牌](https://developer.x.com/resources/fundamentals/authentication/obtaining-user-access-tokens)，以便发起[符合要求的经身份验证的 Ads API 请求](https://developer.x.com/en/docs/twitter-ads-api/making-authenticated-requests)。</Note>

<Note>**注意：**在 2023 年 7 月之前申请访问权限的 Ads API 开发者，可能具有不同级别的访问和权限，并且可能被限制为最多使用五个 OAuth 令牌。请参阅我们的[提升访问级别](https://developer.x.com/en/docs/twitter-ads-api/increasing-access)指南，以获得更多端点访问权限，或为现有应用放宽令牌数量限制。</Note>

<div id="make-your-first-request">
  ## 发出你的第一个请求
</div>

要测试你对 Ads API 的访问权限，请向 [GET accounts](https://developer.x.com/en/docs/twitter-ads-api/campaign-management/api-reference/accounts) 端点发起请求。此端点会返回当前已授权用户可访问的广告账户。在后续 API 请求中，使用该请求返回的广告账户 id 来读取和写入特定广告账户的数据。使用命令行中的 [Twurl](https://developer.x.com/en/docs/tutorials/using-twurl) 时，请求将类似如下所示。

**示例请求**

```bash
twurl -H ads-api.x.com "/11/accounts"
```

**示例响应**

```json
{

    "params": {}
  },
  "data": [

    "created_at": "2016-04-07T14:40:15Z",
```
