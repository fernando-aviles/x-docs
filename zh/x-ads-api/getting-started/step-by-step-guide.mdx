<div id="how-to-get-access-to-the-ads-api">
  ## 如何申请 Ads API 访问权限
</div>

1. 注册一个[开发者账号](https://developer.x.com/en/apply-for-access)。
2. 创建一个[开发者 App](https://developer.x.com/app)，并妥善保管你的 token。
3. 访问 [ads.x.com/help](https://ads.x.com/help)，为你的每个开发者 App 提交 Ads API 访问申请。

<Note>**注意：**如果你已经在 X Developer Platform 上进行开发并且已有开发者账号，请直接跳至第三步。</Note>

<div id="step-one-signup-for-a-developer-account">
  ### 第一步：注册开发者账号
</div>

若要向任何 X 的 API 产品发起请求，你必须先注册一个开发者账号。在开发者控制台中创建一个 App 和开发者 App。这样你就会获得一组凭证，用于对所有发送到 API 的请求进行身份验证。

<Button href="https://developer.x.com/en/apply-for-access">
  注册开发者账号
</Button>

<div id="step-two-save-your-apps-key-and-tokens-and-keep-them-secure">
  ### 步骤二：保存你的 App 密钥和令牌并确保其安全
</div>

在你的开发者 App 中，你会获得一组 API Keys（也称为 Consumer Keys）。你还可以生成一组 Access Tokens，用于代表你的个人 X 账号发起请求，以及一个 Bearer Token，用于对需要 OAuth 2.0 Bearer Token 的端点进行身份验证。由于这些密钥和令牌在未重新生成的情况下不会过期，我们建议你创建环境变量，或使用安全的密码管理器进行保存。

请同时记录你的 App ID，它可以在 App 详情页的 URL 中找到。这将使你在下一步申请 Ads API 访问权限时更加方便。

<Note>
**注意：**你的密钥和令牌只会在开发者控制台中显示一次，因此在生成它们之后，务必立即将这些凭证存储到你的密码管理器中。

如果你丢失或忘记了这些密钥和令牌，你将需要重新生成它们，这会创建新的密钥和令牌，并使旧的失效。这意味着你必须更新任何使用先前凭证所设置的集成。

详细了解我们的[身份验证最佳实践](https://developer.x.com/en/docs/authentication/guides/authentication-best-practices)。
</Note>

<div id="step-three-apply-for-access-to-the-ads-api">
  ### 步骤三：申请 Ads API 访问权限
</div>

此时，你已经拥有了[对 X API 的基本访问权限](https://developer.x.com/en/docs/twitter-api/v1)，但还不能使用特定的 X Ads API 功能。接下来，你需要申请并获批 Ads API 访问权限。请访问 [ads.x.com/help](https://ads.x.com/help)，为每个开发者 App 提交 Ads API 访问申请。

<div id="access-tiers">
  ### 访问层级
</div>

作为申请流程的一部分，你需要指定所需的访问权限级别。详细了解[应用级和广告账户级权限](https://developer.x.com/en/docs/twitter-ads-api/obtaining-ads-account-access#levels-of-access)。

<div id="conversion-only">
  #### 仅转化
</div>

可使用移动端和网页转化端点，具备读写访问权限。

<div id="standard-access">
  #### 标准访问
</div>

可对 Analytics、Campaign Management、Creatives、Custom Audiences 和 Conversion 端点进行读写访问权限。

<Note>**注意：**在你的应用获批获得 Ads API 访问权限后，你需要[重新生成相关的用户访问令牌](https://developer.x.com/resources/fundamentals/authentication/obtaining-user-access-tokens)，以便发起[已正确完成身份验证的 Ads API 请求](https://developer.x.com/en/docs/twitter-ads-api/making-authenticated-requests)。</Note>

<Note>**注意：**在 2023 年 7 月之前申请访问权限的 Ads API 开发者，其访问级别和权限可能有所不同，并且可能被限制为最多五个 OAuth 令牌。请参阅我们的[提升访问级别](https://developer.x.com/en/docs/twitter-ads-api/increasing-access)指南，以获取对更多端点的访问权限，或为现有应用解除令牌数量限制。</Note>

<div id="make-your-first-request">
  ## 发起你的第一个请求
</div>

要测试你是否可以访问 Ads API，请向 [GET accounts](https://developer.x.com/en/docs/twitter-ads-api/campaign-management/api-reference/accounts) 端点发起请求。此端点会返回当前已授权用户可访问的广告账户。将该请求返回的广告账户 ID 用于后续的 API 请求，以便读取和写入特定广告账户的数据。使用命令行中的 [Twurl](https://developer.x.com/en/docs/tutorials/using-twurl) 时，请求如下所示。

**示例请求**

```bash
twurl -H ads-api.x.com "/11/accounts"
```

**示例响应**

