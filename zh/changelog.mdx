<Update label="Dec 14, 2021" description="X API v2：认证">
  ### 对 OAuth 2.0 认证的支持

  从今天起，所有开发者都可以在开发者控制台中选择 OAuth 2.0 作为认证方式来进行身份验证。作为本次发布的一部分，我们已经为机密客户端和公共客户端，以及所有相关的 v2 端点添加了对此认证方式的支持。

  OAuth 2.0 是一种行业标准的授权协议，它为开发者在应用的权限范围（scopes）上提供了更多控制，并改进了跨多设备的授权流程。换句话说，为 X 上的用户构建应用的开发者，将对其 App 向用户请求的信息拥有更多控制权，因此你只需要向终端用户请求你真正需要的 data 和相关信息。

  这种现代授权协议将允许你为终端用户提供更精简的授权同意流程来授权你的应用，该流程只会显示你向他们请求的特定权限范围。

  如需了解有关此次发布的更多信息，请访问我们的论坛公告。
</Update>

<Update label="Nov 15, 2021" description="X API v2：早期访问">
  ### X API v2 的重大平台更新

  **重大平台更新：X API v2 现在是主要版本，全新的 Essential 和 Elevated 访问级别，以及政策变更**

  今天，我们宣布 X API v2 现已成为 X API 的主要版本。我们已经在 X API v2 中发布了足够多的端点和功能，可以满足 90% 基于 X API 构建的现有 App 的需求。

  我们今天推出以下变更，以进一步提升 X API v2 的开发者体验：

  * 快速且免费的 Essential 级别 API 访问，以及对用例已获批准的开发者提供免费的 Elevated 访问。关于这些访问级别的更多详细信息，请参见我们的 “About the X API” 页面。

  * 我们正在移除开发者政策中，限制你如何基于 X 的核心功能进行构建，以及限制你的应用可支持用户数量的相关措辞。

    * 我们正在开放平台，以鼓励你构建能够让 X 变得更好、更健康，并扩展公共对话的工具和产品。[查看我们希望你构建的一系列解决方案](https://developer.x.com/en/docs/twitter-api/what-to-build)。

    * 具体来说，我们移除了限制复刻 X 体验（包括 X 的核心功能）的条款，以及要求在拥有大量用户令牌时须获得许可的条款。

    * 我们知道，构建能帮助 X 上用户的解决方案，往往意味着开发者必须构建（或复刻）一些 X 上已经提供的功能。这些对开发者政策的变更，旨在为开发者生态提供更清晰的指引，并提供一个开放的 API 平台，让开发者更容易构建、创新，并对公共对话产生影响。

  在我们的[论坛帖子](https://devcommunity.x.com/t/ushering-in-a-new-era-for-the-twitter-developer-platform-with-the-twitter-api-v2/162087)中，我们对本次发布以及此前各个 X API 发布（共同促成了这一重要时刻）进行了更为详细的说明。

  除了查看更早的更新日志条目外，我们还整理了一些关键资源，供你了解迄今为止 X API v2 已经发布的所有内容：

  * [X API 端点映射](/zh/x-api/migrate/x-api-endpoint-map)

  * [关于 X API](/zh/x-api/getting-started/about-x-api)

<Update label="Jun 29, 2021" description="v2 过滤流和样本流现在支持冗余连接和回补功能">
  ### 流式端点的可靠性功能

  今天，我们为 X API v2 的过滤流和样本流推出了两项面向流式的可靠性功能，称为回补（backfill）和冗余连接（redundant connections），现在已在 Academic Research 产品线中提供。

  冗余连接功能使你可以对同一数据流建立两条连接，这有助于在其中一条流连接中断时，最大化流式连接的可用时间。

  你可以在流式请求中添加 `backfill_minutes` 参数，并将其设置为 1 到 5 之间的整数来使用回补功能，从而请求因流中断而可能错过的数据。

  若要了解此次发布的更多信息，请访问我们的[论坛公告](https://devcommunity.x.com/t/new-reliability-and-recovery-functionality-available-for-twitter-api-v2-streaming-endpoints/156244/2)。

<Update label="2020 年 12 月 18 日" description="适用于 X API v2 的会话回复设置字段">
  ### 新增回复设置字段

  今天我们在帖子对象中推出了一个名为 `reply_settings` 的新字段。该字段在所有返回帖子的 X API v2 端点中均可用，包括帖子查询、隐藏回复、最近搜索、采样流、过滤流、关注关系查询、用户帖子时间线和用户提及时间线端点，或通过在任一端点中[扩展](/zh/x-api/fundamentals/expansions)帖子对象来获取。

  此字段表示帖子作者允许他人回复其帖子的方式：是所有人可回复，仅帖子中提到的人可回复，还是仅其关注的人可回复。`reply_settings` 字段返回的取值包括 `everyone`、`mentionedUsers` 和 `following`。如果该帖子未设置会话控制，该字段仍会出现在帖子对象中，字段取值为 `everyone`。
</Update>

  ### 对引用负载渲染方式的更改

  今天，我们对在引用负载中 URL 的渲染方式进行了更改。

  我们新增了一个名为 &quot;quoted&#95;status&#95;permalink&quot; 的实体，以确保可以引用被引用的帖子，并且将从被引用帖子 &quot;text&quot; 字段中移除 t.co 链接。

  如需了解更多详情，请阅读我们的[论坛帖子](https://devcommunity.x.com/t/updating-how-urls-are-rendered-in-the-quote-tweet-payload/105473)和[更新后的文档](https://devcommunity.x.com/t/upcoming-changes-to-the-developer-platform/104603)。

<Update label="Nov 14, 2017" description="X API: Premium v1.1">
  ### Premium API 上线

  Premium API 已上线。

  这些新的 API 构建在我们企业级数据平台的质量和稳定性之上，并通过分级定价模式向更广泛的用户提供。首次，您可以搜索长达 30 天内的帖子（而不是标准端点上受限的 7 天数据），并且还可以选择访问我们针对个人资料地理位置（Profile Geo）、URL 展开和投票数据提供的高级富化功能。以下是部分新功能示例：

  * 每个请求可获取更多帖子（Sandbox + Premium）

  * 更加丰富的查询语言，支持更复杂的查询（Sandbox + Premium）

  * 一个用于计数的端点，返回帖子的时间序列计数（Premium）

  * 元数据富化，例如展开的 URL 和个人资料地理位置（Premium）

  在我们的[博客](https://blog.x.com/developer/en_us/topics/tools/2017/introducing-twitter-premium-apis.html)上阅读更多关于此次发布的内容。
</Update>

<Update label="2017 年 8 月 7 日" description="X API：Enterprise v1.1">
  ### 30 天搜索中停止支持 url_contains 运算符

  30 天搜索和完整存档搜索（Full-Archive Search）已停止支持 `url_contains:` 运算符。此运算符的弃用已在 2016 年 8 月的 Gnip 2.0 迁移中宣布。任何使用 `url_contains:` 运算符的搜索查询都将被视为无效并被拒绝。
</Update>

<Update label="2017 年 7 月 6 日" description="X API：Enterprise v1.1">
  ### 即将移除搜索 API 中的 url_contains 运算符

  从今天起 30 天后（或在 2017 年 8 月 4 日之后），30 天搜索 API（包括 30 天和完整存档）将不再支持 `url_contains:` 运算符（实际上，对 `url_contains:` 的支持会在该日期之后的首次部署中结束）。此运算符的弃用已在 2016 年 8 月的 Gnip 2.0 迁移中宣布。当对该运算符的支持结束后，任何使用 `url_contains:` 的查询都将被视为无效并被拒绝。
</Update>

<Update label="2017 年 5 月 5 日" description="X API：Standard v1.1">
  ### DM 命令的可选参数

  `statuses/update` 的可选参数 `enable_dm_commands` 允许应用在过渡期结束前提前移除对 DM 命令的支持。默认值为 *true*（即当前旧版行为），但可以将其设置为 *false* 以获得新的、2017 年 11 月 1 日之后的行为。`statuses/update` 的可选参数 `fail_dm_commands` 在设置为 *true* 时，将使 DM 命令从 API 返回 HTTP 403（错误码 151）。默认值为 *false*。可在[我们的论坛](https://devcommunity.x.com/t/retiring-legacy-dm-commands-on-the-standard-tweet-api/86653)了解此更新的更多信息。
