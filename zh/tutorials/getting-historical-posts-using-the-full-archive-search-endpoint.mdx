<div id="introduction">
  ## 介绍
</div>

在 v2 中，[Search Posts 端点](/zh/x-api/posts/search/introduction)使你能够根据自己构建的搜索查询，获取与你感兴趣主题相关的帖子。针对 v2 Search Posts，我们提供两个不同的端点：`recent search`，对所有已获批准账户的开发者开放，可以搜索最多过去七天内的帖子；以及 `full-archive search`，仅对已获批准进入
[Academic Research 产品路径](https://developer.x.com/en/products/x-api/early-access/guide#na_2)
的研究者开放，可以搜索可追溯至 2006 年 3 月的全部帖子归档。

你可以在我们的[搜索概览页面](/zh/x-api/posts/search/introduction)查看完整的搜索功能。

这些 Search Posts 端点满足了学术研究者最常见的使用场景之一，他们可能会将其用于纵向研究，或分析过去的某个话题或事件。

本教程为希望使用 `full-archive search` 端点来搜索全部公开 X 数据历史记录的研究者提供分步指南。它还将演示构建数据集的不同方式，例如检索带地理标签的帖子，以及如何对某个查询返回的可用帖子进行分页访问。

<div id="connecting-to-the-full-archive-search-endpoint">
  ### 连接到完整存档搜索端点
</div>

下面的 cURL 命令展示了如何从 @XDevelopers 账号获取历史帖子。将 $BEARER&#95;TOKEN 替换为你自己的 Bearer Token，把完整请求粘贴到终端中，然后按下“return”键。

```bash
curl --request GET 'https://api.x.com/2/tweets/search/all?query=from:xdevelopers' --header 'Authorization: Bearer $BEARER_TOKEN'
```

你将看到响应 JSON。

默认情况下，只会返回最近的 10 条帖子。如果你希望每次请求返回超过 10 条帖子，可以使用 `max_results` 参数，并将其设置为每次请求最多返回 500 条帖子，如下所示：

```bash
curl --request GET 'https://api.x.com/2/tweets/search/all?query=from:xdevelopers&max_results=500' --header 'Authorization: Bearer $BEARER_TOKEN'
```

###

构建查询

正如你在上面的示例请求中所看到的，使用 `query` 参数可以
指定你想要搜索的内容。例如，如果你想要
获取所有包含 *covid* 或 *coronavirus* 这个词的帖子，你可以
在括号内使用 OR 运算符，你的查询可以是
`(covid OR coronavirus)`，因此你的 API 调用将如下所示：

```bash
curl --request GET 'https://api.x.com/2/tweets/search/all?query=(covid%20OR%20coronavirus)&max_results=500' --header 'Authorization: Bearer $BEARER_TOKEN'
```

同样地，如果你想获取所有包含 *covid19* 且不是转帖的帖子，可以将 is:retweet 操作符与逻辑非（用 - 表示）一起使用，因此查询可以写成 covid19 -is:retweet，对应的 API 调用如下：

```bash
curl --request GET 'https://api.x.com/2/tweets/search/all?query=covid19%20-is:retweet&max_results=500' --header 'Authorization: Bearer $BEARER_TOKEN'
```

请查看
[本指南，其中包含完整的运算符列表](/zh/x-api/posts/search/integrate/build-a-query)
这些运算符可在完整归档搜索端点中使用。

<div id="using-the-start_time-and-end_time-parameters-to-get-historical-posts">
  ### 使用 start_time 和 end_time 参数获取历史帖子
</div>

在使用完整归档搜索端点时，默认会返回最近 30 天的帖子。如果你想获取早于 30 天的帖子，可以在 API 调用中使用 start&#95;time 和 end&#95;time 参数。这些参数必须采用有效的 RFC 3339 日期时间格式，例如 2020-12-21T13:00:00.00Z。因此，如果你想获取 XDevelopers 账号在 2020 年 12 月的所有帖子，你的 API 调用将是：

```bash
curl --request GET 'https://api.x.com/2/tweets/search/all?query=from:XDevelopers&start_time=2020-12-01T00:00:00.00Z&end_time=2021-01-01T00:00:00.00Z' --header 'Authorization: Bearer $BEARER_TOKEN'
```

###

获取带地理标签的历史帖子

带地理标签的帖子是指关联了地理位置信息的帖子，例如城市、州、国家等。

<div id="using-hasgeo-operator">
  #### 使用 has:geo 运算符
</div>

如果您想获取包含地理位置信息的帖子，可以使用 has:geo 运算符。
例如，下面的 cURL 请求只会获取来自 @XDevelopers 账号且包含地理位置信息的帖子：

```
curl --request GET
'https://api.x.com/2/tweets/search/all?query=from:xdevelopers%20has:geo' --header
'Authorization: Bearer $BEARER_TOKEN'
```

<div id="using-place_country-operator">
  #### 使用 place_country 运算符
</div>

类似地，你可以使用 place&#95;country 运算符，将结果限定为具有地理数据且位于特定国家/地区的帖子。下面的 cURL 命令将获取 @XDevelopers 账号在美国发布的所有帖子：

```
curl --request GET
'https://api.x.com/2/tweets/search/all?query=from:xdevelopers%20place_country:US'
--hbasheader 'Authorization: Bearer XXXXX'
```

在上文中使用 ISO Alpha-2 两位字母代码指定国家/地区。可在[此处](http://en.wikipedia.org/wiki/ISO_3166-1_alpha-2)查阅有效的 ISO 代码。

<div id="getting-more-than-500-historical-posts-using-the-next_token">
  ### 使用 next_token 获取超过 500 条历史帖子
</div>

如上所述，默认情况下，在对完整存档搜索端点发起查询时，每个请求最多只能获取 500 条帖子。如果你的查询中可用的帖子超过 500 条，你的 JSON 响应中会包含一个 next&#95;token，你可以将其附加到 API 调用中，以获取此查询下一批可用的帖子。这个 next&#95;token 位于 JSON 响应中的 meta 对象（元数据对象）中，其结构类似于：

```
{ "newest_id": "12345678...", "oldest_id": "12345678...", "result_count": 500,
"nebashxt_token": "XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX" }
```

因此，要获取下一批可用的帖子，请从该 meta 对象中读取 next&#95;token 的值，并在对完整归档搜索端点进行 API 调用时，将该值作为 next&#95;token 参数的取值，如下所示（你将使用你自己的 Bearer Token，以及你在前一次 API 调用中获得的 next&#95;token 值）。

```
curl --request GET
'https://api.x.com/2/tweets/search/all?max_results=500&query=covid&next_token=XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX'
--header 'Authorization: Bearer $BEARER_TOKEN'
```

通过这种方式，你可以持续检查是否还有可用的 `next_token`，如果你尚未达到希望收集的帖子数量，就可以在每次请求中使用新的 `next_token` 继续调用 full-archive 端点。
