<div id="introduction">
  ## 介绍
</div>

v2 中的 [Search Posts 端点](/zh/x-api/posts/search/introduction)
使你能够根据自己构建的搜索查询，获取与你感兴趣主题相关的帖子。针对 v2 Search Posts，我们提供了两个不同的端点：recent search 端点，对所有已获批准账号的开发者开放，可搜索最多近七天内的帖子；以及 full-archive search 端点，它仅向已获批准加入
[Academic Research 产品路径](https://developer.x.com/en/products/x-api/early-access/guide#na_2)
的研究人员开放，并且可以在整个帖子存档中进行搜索，时间可一直追溯到 2006 年 3 月。

你可以在我们的
[搜索概览页面](/zh/x-api/posts/search/introduction)
查看完整的搜索功能。

这些 Search Posts 端点满足了学术研究人员最常见的一类使用场景，他们可能会将其用于纵向研究，或分析既往的主题或事件。

本教程为希望使用 full-archive search 端点来搜索 X 公共数据完整历史记录的研究人员提供分步指南。它还将演示构建数据集的多种方式，例如检索带地理标签的帖子，以及如何对某个查询返回的可用帖子进行分页获取。

<div id="connecting-to-the-full-archive-search-endpoint">
  ### 连接到全量存档搜索端点
</div>

下面的 cURL 命令演示了如何从 @XDevelopers 账号获取历史帖子。将 $BEARER&#95;TOKEN 替换为你自己的 Bearer 令牌，将完整请求粘贴到终端中，然后按下 &quot;return&quot; 键。

```bash
curl --request GET 'https://api.x.com/2/tweets/search/all?query=from:xdevelopers' --header 'Authorization: Bearer $BEARER_TOKEN'
```

你将会看到 JSON 响应。

默认情况下，只会返回最近的 10 条帖子。如果你希望每次请求返回超过 10 条帖子，可以使用 max&#95;results 参数，并将其设置为每次请求最多 500 条帖子，如下所示：

```bash
curl --request GET 'https://api.x.com/2/tweets/search/all?query=from:xdevelopers&max_results=500' --header 'Authorization: Bearer $BEARER_TOKEN'
```

###

构建查询

如前面的示例调用所示，通过使用 `query` 参数，你可以指定要搜索的数据。例如，如果你想要获取所有包含单词 *covid* 或 *coronavirus* 的帖子，可以在括号内使用 OR 运算符，你的查询可以是 `(covid OR coronavirus)`，因此你的 API 调用将如下所示：

```bash
curl --request GET 'https://api.x.com/2/tweets/search/all?query=(covid%20OR%20coronavirus)&max_results=500' --header 'Authorization: Bearer $BEARER_TOKEN'
```

同样地，如果你想获取所有包含 *covid19* 且不是转发的帖子，可以将 is:retweet 运算符与逻辑非（用 - 表示）结合使用，因此你的查询可以是 covid19 -is:retweet，而你的 API 调用将是：

```bash
curl --request GET 'https://api.x.com/2/tweets/search/all?query=covid19%20-is:retweet&max_results=500' --header 'Authorization: Bearer $BEARER_TOKEN'
```

请查看
[本指南，了解完整的运算符列表](/zh/x-api/posts/search/integrate/build-a-query)，
这些运算符都可用于完整归档搜索端点。

<div id="using-the-start_time-and-end_time-parameters-to-get-historical-posts">
  ### 使用 start_time 和 end_time 参数获取历史帖子
</div>

在使用完整存档搜索端点时，默认会返回最近 30 天的帖子。如果你想获取早于最近 30 天的帖子，可以在 API 调用中使用 start&#95;time 和 end&#95;time 参数。这些参数必须采用有效的 RFC3339 日期时间格式，例如 2020-12-21T13:00:00.00Z。因此，如果你想获取 XDevelopers 账号在 2020 年 12 月的所有帖子，你的 API 调用应如下所示：

```bash
curl --request GET 'https://api.x.com/2/tweets/search/all?query=from:XDevelopers&start_time=2020-12-01T00:00:00.00Z&end_time=2021-01-01T00:00:00.00Z' --header 'Authorization: Bearer $BEARER_TOKEN'
```

###

获取带地理标记的历史帖子

带地理标记的帖子是指包含地理位置信息（例如城市、省/州、国家等）的帖子。

<div id="using-hasgeo-operator">
  #### 使用 has:geo 运算符
</div>

如果你想获取包含地理位置信息的帖子，可以使用 has:geo 运算符。
例如，下面的 cURL 请求将仅获取来自
@XDevelopers 账号且包含地理位置信息的帖子：

```
curl --request GET
'https://api.x.com/2/tweets/search/all?query=from:xdevelopers%20has:geo' --header
'Authorization: Bearer $BEARER_TOKEN'
```

<div id="using-place_country-operator">
  #### 使用 place_country 运算符
</div>

类似地，你可以使用 place&#95;country 运算符，将带有地理位置信息的帖子限定为特定国家。下面的 cURL 命令会获取 @XDevelopers 账号在美国发布的所有帖子：

```
curl --request GET
'https://api.x.com/2/tweets/search/all?query=from:xdevelopers%20place_country:US'
--hbasheader 'Authorization: Bearer XXXXX'
```

上方指定的国家使用 ISO alpha-2 两位字母代码表示。有效的 ISO 代码可以在[此处](http://en.wikipedia.org/wiki/ISO_3166-1_alpha-2)找到。

<div id="getting-more-than-500-historical-posts-using-the-next_token">
  ### 使用 next_token 获取超过 500 条历史帖子
</div>

如上所述，默认情况下，对于完整归档搜索端点的查询，每个请求最多只能获取 500 条帖子。如果你的查询结果中可用的帖子数量超过 500 条，你的 JSON 响应会包含一个 next&#95;token，你可以将它追加到 API 调用中，以获取该查询的下一批可用帖子。这个 next&#95;token 位于 JSON 响应中的 meta 对象内，其大致结构类似于：

```
{ "newest_id": "12345678...", "oldest_id": "12345678...", "result_count": 500,
"nebashxt_token": "XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX" }
```

因此，要获取下一批可用的帖子，请从该 meta 对象中取出 next&#95;token 的值，并在随后对完整存档搜索端点发起的 API 调用中，将该值作为 next&#95;token 的值使用，如下所示（你将使用你自己的 Bearer 令牌，以及在前一次 API 调用中获得的 next&#95;token 值）。

```
curl --request GET
'https://api.x.com/2/tweets/search/all?max_results=500&query=covid&next_token=XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX'
--header 'Authorization: Bearer $BEARER_TOKEN'
```

通过这种方式，你可以持续检查是否有可用的 `next_token`，如果还未达到你希望收集的帖子数量，就可以在每次请求时携带新的 `next_token` 继续调用完整归档端点。
