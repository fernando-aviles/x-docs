<div id="introduction">
  ## 介绍
</div>

在 v2 中，[Search Posts 端点](/zh/x-api/posts/search/introduction)
让你能够根据自己构建的搜索查询，获取与你感兴趣主题相关的帖子。对于 v2 Search Posts，
我们提供两个不同的端点：recent search（最近搜索），对所有已获批准的开发者账号开放，
可以搜索追溯至 7 天前的帖子；以及 full-archive search（完整存档搜索），
仅对已获批准加入
[Academic Research product track](https://developer.x.com/en/products/x-api/early-access/guide#na_2)
的研究人员开放，可以搜索追溯到 2006 年 3 月以来的全部历史归档帖子。

你可以在我们的
[搜索概览页面](/zh/x-api/posts/search/introduction)
查看完整的搜索功能。

这些 Search Posts 端点满足了学术研究人员最常见的用例之一，
他们可能会将其用于纵向研究，或分析过去的某个话题或事件。

本教程为希望使用 full-archive search 端点搜索整个 X 公开数据历史的研究人员提供分步指南。教程还将演示构建数据集的不同方式，
例如获取带地理标签的帖子，以及如何在某个查询的可用帖子中进行分页检索。

<div id="connecting-to-the-full-archive-search-endpoint">
  ### 连接到完整归档搜索端点
</div>

下面的 cURL 命令展示了如何从 @XDevelopers 账号获取历史帖子。将 $BEARER&#95;TOKEN 替换为你自己的 Bearer Token，把完整请求粘贴到终端中，然后按下回车键。

```bash
curl --request GET 'https://api.x.com/2/tweets/search/all?query=from:xdevelopers' --header 'Authorization: Bearer $BEARER_TOKEN'
```

你会看到 JSON 响应。

默认情况下，只会返回最近的 10 条帖子。如果你希望每个请求获取超过 10 条帖子，可以使用 `max_results` 参数，并将其设置为每个请求最多 500 条帖子，如下所示：

```bash
curl --request GET 'https://api.x.com/2/tweets/search/all?query=from:xdevelopers&max_results=500' --header 'Authorization: Bearer $BEARER_TOKEN'
```

###

构建查询

如你在上面的示例调用中所见，通过使用 `query` 参数，你可以指定你想要搜索的数据。比如，如果你想获取所有包含单词 *covid* 或单词 *coronavirus* 的帖子，你可以在括号内使用 OR 运算符，你的查询可以是 `(covid OR coronavirus)`，因此你的 API 调用将如下所示：

```bash
curl --request GET 'https://api.x.com/2/tweets/search/all?query=(covid%20OR%20coronavirus)&max_results=500' --header 'Authorization: Bearer $BEARER_TOKEN'
```

类似地，如果你想获取所有包含 *covid19* 且不是转发的帖子，可以将 is:retweet 运算符与逻辑非（用 - 表示）结合使用，因此查询可以写为 covid19 -is:retweet，对应的 API 调用将是：

```bash
curl --request GET 'https://api.x.com/2/tweets/search/all?query=covid19%20-is:retweet&max_results=500' --header 'Authorization: Bearer $BEARER_TOKEN'
```

请参阅
[本指南，获取完整的运算符列表](/zh/x-api/posts/search/integrate/build-a-query)
了解全量存档搜索端点所支持的运算符。

<div id="using-the-start_time-and-end_time-parameters-to-get-historical-posts">
  ### 使用 start_time 和 end_time 参数获取历史帖子
</div>

在使用完整归档搜索端点时，默认只会返回最近 30 天内的帖子。如果你想获取早于 30 天前的帖子，可以在 API 调用中使用 start&#95;time 和 end&#95;time 参数。这些参数必须采用有效的 RFC3339 日期时间格式，例如 2020-12-21T13:00:00.00Z。因此，如果你想获取 XDevelopers 账号在 2020 年 12 月的所有帖子，你的 API 调用将是：

```bash
curl --request GET 'https://api.x.com/2/tweets/search/all?query=from:XDevelopers&start_time=2020-12-01T00:00:00.00Z&end_time=2021-01-01T00:00:00.00Z' --header 'Authorization: Bearer $BEARER_TOKEN'
```

###

获取带地理标签的历史帖子

所谓带有地理标签的帖子，是指附带城市、省/州、国家等地理位置信息的帖子。

<div id="using-hasgeo-operator">
  #### 使用 has:geo 运算符
</div>

如果你想获取包含地理数据的帖子，可以使用 has:geo 运算符。
例如，下面的 cURL 请求将仅获取 @XDevelopers 账号中带有地理数据的帖子：

```
curl --request GET
'https://api.x.com/2/tweets/search/all?query=from:xdevelopers%20has:geo' --header
'Authorization: Bearer $BEARER_TOKEN'
```

<div id="using-place_country-operator">
  #### 使用 place_country 运算符
</div>

类似地，你可以使用 place&#95;country 运算符，将包含地理信息的帖子限定为特定国家/地区。下面的 cURL 命令将获取所有来自美国、由 @XDevelopers 账号发布的帖子：

```
curl --request GET
'https://api.x.com/2/tweets/search/all?query=from:xdevelopers%20place_country:US'
--hbasheader 'Authorization: Bearer XXXXX'
```

上文中的国家使用 ISO alpha-2 两位字母代码指定。有效的 ISO 代码可以在[此处](http://en.wikipedia.org/wiki/ISO_3166-1_alpha-2)查阅。

<div id="getting-more-than-500-historical-posts-using-the-next_token">
  ### 使用 next_token 获取超过 500 条历史帖子
</div>

如上所述，在对完整归档搜索端点执行一次查询时，默认每个请求最多只能返回 500 条帖子。如果与你的查询匹配的帖子多于 500 条，你的 JSON 响应中会包含一个 next&#95;token，你可以在后续的 API 调用中将其附加到请求中，以获取此查询接下来可用的帖子。这个 next&#95;token 位于 JSON 响应中的元数据对象 meta 内，其结构大致如下所示：

```
{ "newest_id": "12345678...", "oldest_id": "12345678...", "result_count": 500,
"nebashxt_token": "XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX" }
```

因此，要获取下一批可用的帖子，请从该 meta 对象中获取 next&#95;token 的值，并在对完整归档搜索端点发起 API 调用时，将其作为 next&#95;token 的取值，如下所示（你将使用你自己的 Bearer Token，以及在上一次 API 调用中获得的 next&#95;token 值）。

```
curl --request GET
'https://api.x.com/2/tweets/search/all?max_results=500&query=covid&next_token=XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX'
--header 'Authorization: Bearer $BEARER_TOKEN'
```

通过这种方式，您可以持续检查 `next_token` 是否可用，如果尚未达到希望收集的帖子数量，就可以在每次请求中使用新的 `next_token` 持续调用完整归档搜索端点。
