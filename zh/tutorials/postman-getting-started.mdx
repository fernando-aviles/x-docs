<div id="introduction">
  ## 介绍
</div>

Postman 是一款桌面和 Web 应用，允许你通过图形用户界面对 API 发起请求。我们建议你在探索 X API、X Ads API 和 Labs 端点的功能时，以及在排查应用问题时使用 Postman。 

目前我们提供了两个 Postman 集合：

  <Card title="X Ads API 集合" icon="code" iconType="solid" href="https://app.getpostman.com/run-collection/1d12b9fc623b8e149f87" horizontal />

<div id="prerequisites">
  ### 先决条件
</div>

在开始使用 X 的 Postman 集合之前，你需要确保已经为你选择的 X 开发平台工具获取了相应的访问权限和凭证。你可以在我们的[“入门”页面](/zh/resources/platform-overview)了解如何获得访问权限。

在你已经拥有一个[开发者账号](https://developer.x.com/en/portal/petition/essential/basic-info)、完成[开发者 App](/zh/resources/fundamentals/developer-apps)的设置、获得一组[身份验证](/zh/resources/fundamentals/authentication)密钥和令牌，并且已正确配置环境以便向你计划使用的特定 API 发起请求后，就可以按照以下步骤开始使用。
 

<div id="getting-started-with-xs-postman-collections">
  ## X 的 Postman 集合入门
</div>

<div id="step-one-add-one-of-the-x-postman-collections-to-your-account">
  ### 第一步：将一个 X Postman 集合添加到你的账号中
</div>

虽然你可以在 Postman 中手动搭建想要使用的各个端点，但我们已经帮你完成了大部分繁重工作，预先为你构建了一套可直接使用的相关 API 集合。只需点击前面“Postman 集合”部分中的任意一个链接，包含所选 API 相关全部端点的集合就会被添加到你的 Postman 应用中。这些集合也可以在 [Postman API Network](https://explore.postman.com/) 中获取。每个端点都会自动包含可用参数、示例响应以及已配置好的身份验证类型，因此你只需要添加自己的凭证和参数值，就可以开始探索这些功能。

在本示例中，我们将使用 X 的 [API v2 集合](https://app.getpostman.com/run-collection/9956214-784efcda-ed4c-4491-a4c0-a26470a67400)。 
 

<div id="step-two-add-your-keys-and-tokens-as-environmental-variables">
  ### 步骤二：将你的密钥和令牌添加为环境变量
</div>

当你将集合添加到 Postman 实例时，它会自动添加一个名为 “X API v2” 的环境，你需要在其中添加你的密钥和令牌。在本步骤中，我们将引导你完成从开发者 App 中将密钥和令牌添加到 “X API v2” 环境的过程。 

若要将密钥和令牌添加到 “X API v2” 环境，请点击 Postman 右上角的 “manage environments” 按钮，或点击右上角的设置按钮。 
 

<Frame>
  <img src="/images/using-postman-1.png.twimg.1920.png" alt="此图展示了在 Postman 控制台中被高亮显示的 “manage environments” 按钮。" />
</Frame>

在环境列表中，点击 “X API v2”。 

接下来，将你通过 Apps 仪表板生成的所有不同密钥和令牌，各自作为变量添加到表格中。下方是你的表格应有的示例：

| VARIABLE | INITIAL VALUE | CURRENT VALUE |
| :--- | :--- | :--- |
| consumer&#95;key | `QAktM6W6DF6F7XXXXXX` | `QAktM6W6DF6F7XXXXXX` |
| consumer&#95;secret | `AJX560A2Omgwyjr6Mml2esedujnZLHXXXXXX` | `AJX560A2Omgwyjr6Mml2esedujnZLHXXXXXX` |
| access&#95;token | `1995XXXXX-0NGqVhk3s96IX6SgT3H2bbjOPjcyQXXXXXXX` | `1995XXXXX-0NGqVhk3s96IX6SgT3H2bbjOPjcyQXXXXXXX` |
| token&#95;secret | `rHVuh7dgDuJCOGeoe4tndtjKwWiDjBZHLaZXXXXXX` | `rHVuh7dgDuJCOGeoe4tndtjKwWiDjBZHLaZXXXXXX` |
| bearer&#95;token | `AAAAAAAAAAAAAAAAAAAAAL9v6AAAAAAA99t03huuqRYg0mpYAAFRbPR3XXXXXXX` | `AAAAAAAAAAAAAAAAAAAAAL9v6AAAAAAA99t03huuqRYg0mpYAAFRbPR3XXXXXXX` |

请注意，上述表格中使用的密钥和令牌是虚构的，如果在请求中使用，将无法生效。 

在你将凭证添加为变量，并确认已选择 X API v2 环境后，你就可以开始向 X API v2 集合发起请求。这是因为每个端点的授权（authorization）选项卡都已配置为自动继承该环境中的变量。 

若要在 Postman 中使用用户访问令牌，请跳过 XXXX，查看关于如何操作的更多详细信息。

  ### 步骤三：选择一个 endpoint
</div>

下一步是从集合中选择一个 endpoint，并开始构建你的请求。你可以从右侧导航栏中选择一个 endpoint。如下所示：

<Frame>
  <img src="/images/using-postman-2.png.twimg.1920.png" alt="此图显示在 &#x22;X API v2&#x22; 部分的 &#x22;Post Lookup&#x22; 下拉菜单中选中了 &#x22;Single Posts&#x22; 请求。" />
</Frame>

在本示例中，我们将使用 X API v2 &gt; Post Lookup &gt; Single Post endpoint。 

<div id="step-four-add-values-to-the-params-tab">
  #### 步骤四：在 Params 选项卡中添加值
</div>

接下来，前往 Params 选项卡。你应该会看到一组未启用的参数（params），每个参数都带有说明其作用的描述，以及一个列出了你可以在请求中传递的所有可用取值的列表。 

在这个示例中，我们将启用 `expansions` 和 `tweet.fields` 查询参数，并添加以下值：

|     |     |
| :--- | :--- |
| **Key** | **Value** |
| `tweet.fields` | `created_at,attachments` |
| expansions | author&#95;id |

除了添加查询参数之外，我们还需要添加必需的路径变量（Path Variable）`id`。由于此端点返回帖子（Posts），我们需要添加一个有效的帖子 ID 作为该值。

你可以通过访问 x.com，点击某条帖子，然后查看浏览器地址栏中的 URL 来找到帖子 ID。例如，以下 URL 中的帖子 ID 为 `1228393702244134912`：

`https://x.com/XDevelopers/status/1228393702244134912`

在 Params 选项卡中，向下滚动，越过所有查询参数，直到显示 “Path Variables” 部分。我们会将你想要使用的帖子 ID 作为值添加到 `id` 键中。

如果你在此步骤中输入的所有内容都正确，Params 选项卡应类似如下所示：

<div id="step-five-send-your-request-and-review-your-response">
  #### 第五步：发送请求并查看响应
</div>

如果一切设置正确，你应该会收到如下响应负载：

<div id="generating-a-user-access-token-with-postman">
  ### 使用 Postman 生成用户访问令牌：
</div>

<div id="using-oauth-10a-to-generate-a-user-access-token">
  #### 使用 OAuth 1.0a 生成用户访问令牌
</div>

查看 [OAuth 1.0a flow test collection](https://www.postman.com/xapidevelopers/workspace/twitter-s-public-workspace/collection/9956214-784efcda-ed4c-4491-a4c0-a26470a67400?ctx=documentation) 中使用的三步流程。

<div id="using-oauth-20-to-generate-a-user-access-token">
  #### 使用 OAuth 2.0 生成用户访问令牌
</div>

如果你想在 Postman 中生成 OAuth 2.0 用户访问令牌，可以将其与 X [API v2 Postman collection](https://www.postman.com/xapidevelopers/workspace/twitter-s-public-workspace/collection/9956214-784efcda-ed4c-4491-a4c0-a26470a67400?ctx=documentation) 搭配使用。 

在工作空间中点击该 collection，转到名为 “Auth” 的选项卡，并将类型选择为 “OAuth 2.0”。然后在标题为 “Configure New Token” 的部分下找到 “Configuration Options”。你可以将 “Grant Type” 更新为 “Authorization Code (With PKCE)”。

你需要将 Callback URL 更新为与你的应用程序关联的回调 URL 相匹配。此外，还需要更新以下参数：

* Auth URL -  https://x.com/i/oauth2/authorize
* Access Token URL -  https://api.x.com/2/oauth2/token
* Client ID - 来自 Dev Portal 的 OAuth 2.0 client ID
* Client Secret - 如果你使用的是机密客户端
* Update Scope - 使 scope 与要连接的端点相匹配。例如 “tweet.read users.read” 
* 你的 callback URL（也称为 redirect URL）。它必须与你在应用认证设置中配置的值完全一致。
* State - state

配置完成后，你可以点击 “Get New Access Token” 来生成访问令牌。如果你看到一个对话框提示出现错误，可能需要点击返回按钮重新登录。你需要在对话框中点击 “Authorize app” 来授权你的应用访问你的账号。

在你授权应用之后，你会被重定向回 Postman，在那里你可以看到你的令牌，并点击 “Use Token” 按钮，以代表已授权用户开始发起请求。

你现在已经可以使用该 Postman collection 了。
