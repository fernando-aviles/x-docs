<div id="introduction">
  ## 介绍
</div>

Postman 是一款桌面和 Web 应用程序，它允许你通过图形用户界面对 API 发起请求。我们建议在探索 X API、X Ads API 和 Labs 端点功能，以及排查应用程序中的问题时使用 Postman。 

我们目前提供了两个 Postman 集合：

<div id="prerequisites">
  ### 先决条件
</div>

在开始使用 X 的 Postman 集合之前，你需要确认自己已经拥有所选的 X 开发者平台工具所需的相应访问权限和凭证。你可以在我们的[“入门”页面](/zh/resources/platform-overview)了解更多获取访问权限的信息。

一旦你拥有了[开发者账号](https://developer.x.com/en/portal/petition/essential/basic-info)、完成了[开发者 App](/zh/resources/fundamentals/developer-apps)的设置，并获取了一组用于[身份验证](/zh/resources/fundamentals/authentication)的密钥和令牌，同时已正确配置好环境，以便向你计划使用的特定 API 发起请求，你就可以按照以下步骤开始操作。
 

<div id="getting-started-with-xs-postman-collections">
  ## X Postman 集合入门
</div>

<div id="step-one-add-one-of-the-x-postman-collections-to-your-account">
  ### 步骤一：将一个 X Postman 集合添加到你的账号中
</div>

虽然你可以在 Postman 中逐一配置想要使用的各个端点，但我们已经替你完成了大部分繁琐工作，并构建了一套可直接使用的相关 API 集合。只需点击前文“Postman collections”部分中的任一链接，即可将包含所选 API 相关所有端点的集合添加到你的 Postman App 中。这些集合也可以在 [Postman API network](https://explore.postman.com/) 中获取。每个端点都会自动包含可用参数、示例响应以及预设的身份验证类型，因此你只需要添加自己的凭证和参数值，就可以开始体验这些功能。

在本示例中，我们将使用 X 的 [API v2 collection](https://app.getpostman.com/run-collection/9956214-784efcda-ed4c-4491-a4c0-a26470a67400)。 
 

<div id="step-two-add-your-keys-and-tokens-as-environmental-variables">
  ### 步骤二：将密钥和令牌添加为环境变量
</div>

当你将集合添加到 Postman 实例时，它会自动添加一个名为“X API v2”的环境，你需要将你的密钥和令牌添加到该环境中。在本步骤中，我们将引导你把开发者 App 中的密钥和令牌添加到“X API v2”环境。 

要将密钥和令牌添加到“X API v2”环境，请单击 Postman 右上角的“manage environments”按钮。 
 

<Frame>
  <img src="/images/using-postman-1.png.twimg.1920.png" alt="此图展示了在 Postman 控制台中高亮显示的“manage environments”按钮。" />
</Frame>

在环境列表中，单击“X API v2”。 

接下来，在表格中为通过 Apps 控制面板生成的所有不同密钥和令牌添加变量。下面是你的表格应当呈现的示例：

| VARIABLE | INITIAL VALUE | CURRENT VALUE |
| :--- | :--- | :--- |
| consumer&#95;key | `QAktM6W6DF6F7XXXXXX` | `QAktM6W6DF6F7XXXXXX` |
| consumer&#95;secret | `AJX560A2Omgwyjr6Mml2esedujnZLHXXXXXX` | `AJX560A2Omgwyjr6Mml2esedujnZLHXXXXXX` |
| access&#95;token | `1995XXXXX-0NGqVhk3s96IX6SgT3H2bbjOPjcyQXXXXXXX` | `1995XXXXX-0NGqVhk3s96IX6SgT3H2bbjOPjcyQXXXXXXX` |
| token&#95;secret | `rHVuh7dgDuJCOGeoe4tndtjKwWiDjBZHLaZXXXXXX` | `rHVuh7dgDuJCOGeoe4tndtjKwWiDjBZHLaZXXXXXX` |
| bearer&#95;token | `AAAAAAAAAAAAAAAAAAAAAL9v6AAAAAAA99t03huuqRYg0mpYAAFRbPR3XXXXXXX` | `AAAAAAAAAAAAAAAAAAAAAL9v6AAAAAAA99t03huuqRYg0mpYAAFRbPR3XXXXXXX` |

请注意，上表中使用的密钥和令牌是虚构的，如果在请求中使用将无法生效。 

在你将凭证添加为变量并确保已选择 X API v2 环境之后，你就可以向 X API v2 集合发出请求了。这是因为每个端点的授权选项卡都已设置为自动继承该环境中的变量。 

如果要在 Postman 中使用用户访问令牌，请跳至 XXXX 部分查看有关如何操作的更多详细信息。

<div id="step-three-select-an-endpoint">
  ### 步骤三：选择端点
</div>

接下来从集合中选择一个端点，并开始构建你的请求。你可以在右侧导航栏中选择端点。如下所示：

<Frame>
  <img src="/images/using-postman-2.png.twimg.1920.png" alt="该图展示了在“X API v2”部分的“Post Lookup”下拉菜单中选中的“Single Posts”请求。" />
</Frame>

在本示例中，我们将使用 X API v2 &gt; Post Lookup &gt; Single Post 端点。 

<div id="step-four-add-values-to-the-params-tab">
  #### 步骤四：在 Params 选项卡中添加值
</div>

接下来，你需要切换到 Params 选项卡。你应该会看到一组未激活的参数，其中包含说明各参数作用的描述，以及你可以在请求中传递的所有潜在取值列表。 

在此示例中，我们将激活 `expansions` 和 `tweet.fields` 查询参数，并添加以下值：

|     |     |
| :--- | :--- |
| **Key** | **Value** |
| `tweet.fields` | `created_at,attachments` |
| expansions | author&#95;id |

除了添加查询参数之外，我们还需要添加必填的路径变量（Path Variable）`id`。由于此 endpoint 返回帖子，我们需要添加一个有效的 Post ID 作为它的值。

你可以通过访问 x.com 并点击某条帖子，然后查看 URL 来找到该 Post ID。例如，下面这个 URL 中的 Post ID 是 `1228393702244134912`：

`https://x.com/XDevelopers/status/1228393702244134912`

在 Params 选项卡中，向下滚动，越过所有查询参数，直到显示 “Path Variables” 部分。我们会将你想要使用的 Post ID 作为值，添加到键 `id` 中。

如果你已正确输入本步骤中的所有内容，Params 选项卡应类似于下图所示：

  #### 步骤五：发送请求并查看响应

如果一切配置正确，你应当会收到如下响应内容：

<div id="generating-a-user-access-token-with-postman">
  ### 使用 Postman 生成用户访问令牌：
</div>

<div id="using-oauth-10a-to-generate-a-user-access-token">
  #### 使用 OAuth 1.0a 生成用户访问令牌
</div>

回顾 [OAuth1.0a flow test collection](https://www.postman.com/xapidevelopers/workspace/twitter-s-public-workspace/collection/9956214-784efcda-ed4c-4491-a4c0-a26470a67400?ctx=documentation) 中使用的三步流程。

<div id="using-oauth-20-to-generate-a-user-access-token">
  #### 使用 OAuth 2.0 生成用户访问令牌
</div>

如果你想在 Postman 中生成 OAuth 2.0 用户访问令牌，你可以生成 OAuth 2.0 访问令牌，并配合 X 的 [API v2 Postman collection](https://www.postman.com/xapidevelopers/workspace/twitter-s-public-workspace/collection/9956214-784efcda-ed4c-4491-a4c0-a26470a67400?ctx=documentation) 一起使用。

在工作区中点击该 collection，进入名为 “Auth” 的选项卡，并将 type 选择为 “OAuth 2.0”。然后在 “Configure New Token” 标题下，找到 “Configuration Options”。你可以将 “Grant Type” 更新为 “Authorization Code (With PKCE)”。

你需要将 Callback URL 更新为与你的应用关联的 Callback URL 一致。此外，你还需要更新以下参数：

* Auth URL - https://x.com/i/oauth2/authorize
* Access Token URL - https://api.x.com/2/oauth2/token
* Client ID - 来自 Dev Portal 的 OAuth 2.0 client ID
* Client Secret - 如果你使用的是 confidential client
* Update Scope - 与要连接的端点相匹配的 scopes。例如 “tweet.read users.read”
* 你的 Callback URL（也称为 redirect URL）。它必须与你在 App 的 authentication 设置中配置的值完全一致。
* State - state

当你准备好后，可以点击 “Get New Access Token” 来生成访问令牌。如果你看到一个提示出现错误的对话框，你可能需要点击返回按钮重新登录。你需要在对话框中点击 “Authorize app”，授权你的应用访问你的账户。

在你授权应用之后，你会被重定向回 Postman，在那里你可以看到你的令牌，并点击 “Use Token” 按钮，开始代表授权用户发起请求。

现在你已经可以使用该 Postman collection 了。
