<div id="introduction">
  ## 介绍
</div>

Postman 是一款桌面端和 Web 应用程序，允许您通过图形用户界面对 API 发起请求。我们建议您在探索 X API、X Ads API 和 Labs 端点的功能，以及排查应用问题时使用 Postman。 

我们目前提供两个 Postman 集合：

<div id="prerequisites">
  ### 前提条件
</div>

在开始使用 X 的 Postman 集合之前，你需要先确认自己已具备所选 X 开发平台工具所需的正确访问权限和凭证。你可以在我们的 [“入门”页面](/zh/resources/platform-overview) 了解如何获得访问权限。

当你已经拥有一个 [开发者账号](https://developer.x.com/en/portal/petition/essential/basic-info)，完成 [开发者 App](/zh/resources/fundamentals/developer-apps) 的设置，并获取了一组用于 [认证](/zh/resources/fundamentals/authentication) 的密钥和令牌，同时已正确配置好环境以便向你计划使用的特定 API 发起请求后，就可以按照以下步骤开始操作。
 

<div id="getting-started-with-xs-postman-collections">
  ## X 的 Postman 集合入门
</div>

<div id="step-one-add-one-of-the-x-postman-collections-to-your-account">
  ### 第一步：将 X 的 Postman 集合添加到你的账户中
</div>

虽然你可以在 Postman 中自行构建想要使用的具体端点，但我们已经替你完成了大部分工作，并预先构建了一套可直接使用的相关 API 集合。只需点击前面“Postman collections”部分中的任意链接，与所选 API 相关的所有端点就会作为一个集合添加到你的 Postman 应用中。这些集合也可以在 [Postman API network](https://explore.postman.com/) 中获取。每个端点都会自动包含可用参数、示例响应和已配置好的认证类型，因此你只需要添加自己的凭证和参数值，就可以开始体验和探索这些功能。

在本示例中，我们将使用 X 的 [API v2 collection](https://app.getpostman.com/run-collection/9956214-784efcda-ed4c-4491-a4c0-a26470a67400) 进行演示。 
 

<div id="step-two-add-your-keys-and-tokens-as-environmental-variables">
  ### 步骤二：将你的密钥和令牌添加为环境变量
</div>

当你将集合添加到 Postman 实例时，它会自动添加一个名为 “X API v2” 的环境，你需要在该环境中添加你的密钥和令牌。在此步骤中，我们将引导你完成将开发者 App 中的密钥和令牌添加到 “X API v2” 环境的整个过程。 

要将你的密钥和令牌添加到 “X API v2” 环境中，点击 Postman 右上角的 “manage environments” 按钮（设置按钮）。 
 

<Frame>
  <img src="/images/using-postman-1.png.twimg.1920.png" alt="此图展示了在 Postman 控制台中被高亮显示的 “manage environments” 按钮。" />
</Frame>

在环境列表中，点击 “X API v2”。 

接下来，将你通过 Apps 仪表盘生成的所有不同密钥和令牌作为变量添加到表格中。下面是你的表格应有的示例：

| 变量 | 初始值 | 当前值 |
| :--- | :--- | :--- |
| consumer&#95;key | `QAktM6W6DF6F7XXXXXX` | `QAktM6W6DF6F7XXXXXX` |
| consumer&#95;secret | `AJX560A2Omgwyjr6Mml2esedujnZLHXXXXXX` | `AJX560A2Omgwyjr6Mml2esedujnZLHXXXXXX` |
| access&#95;token | `1995XXXXX-0NGqVhk3s96IX6SgT3H2bbjOPjcyQXXXXXXX` | `1995XXXXX-0NGqVhk3s96IX6SgT3H2bbjOPjcyQXXXXXXX` |
| token&#95;secret | `rHVuh7dgDuJCOGeoe4tndtjKwWiDjBZHLaZXXXXXX` | `rHVuh7dgDuJCOGeoe4tndtjKwWiDjBZHLaZXXXXXX` |
| bearer&#95;token | `AAAAAAAAAAAAAAAAAAAAAL9v6AAAAAAA99t03huuqRYg0mpYAAFRbPR3XXXXXXX` | `AAAAAAAAAAAAAAAAAAAAAL9v6AAAAAAA99t03huuqRYg0mpYAAFRbPR3XXXXXXX` |

请注意，上表中使用的密钥和令牌是虚构的，如果在请求中使用将无法生效。 

在你将凭证作为变量添加完毕，并确认已选择 X API v2 环境后，你就可以向 X API v2 集合发起请求了。这是因为每个端点的授权选项卡都被设置为自动继承该环境中的变量。 

如果要在 Postman 中使用 User Access Tokens，请跳转到 XXXX 查看关于如何执行此操作的更多详细信息。

</div>

在这个示例中，我们将使用 X API v2 &gt; Post Lookup &gt; Single Post 这个 endpoint。 

<div id="step-four-add-values-to-the-params-tab">
  #### 第四步：在 Params 选项卡中添加值
</div>

下一步是在 Postman 中切换到 Params 选项卡。你应该会看到一组未启用的参数，每个参数都有说明其作用的描述，以及一个列出了你在请求中可以传递的所有可用值的列表。 

在此示例中，我们将启用 `expansions` 和 `tweet.fields` 查询参数，并添加以下值：

|     |     |
| :--- | :--- |
| **Key** | **Value** |
| `tweet.fields` | `created_at,attachments` |
| expansions | author&#95;id |

除了添加查询参数之外，我们还需要添加必需的路径变量 id。由于此端点会返回帖子，因此我们需要添加一个有效的帖子 ID 作为其值。

你可以通过访问 x.com，点击某个帖子，然后在 URL 中查找帖子 ID。例如，以下 URL 的帖子 ID 为 `1228393702244134912`：

`https://x.com/XDevelopers/status/1228393702244134912`

在 Params 选项卡中，向下滚动，越过所有查询参数，直到显示 “Path Variables” 部分。我们会将你想要使用的帖子 ID 作为值填入 id 键中。

如果你正确输入了本步骤中的所有内容，Params 选项卡应类似如下所示：

<div id="generating-a-user-access-token-with-postman">
  ### 使用 Postman 生成用户访问令牌：
</div>

<div id="using-oauth-10a-to-generate-a-user-access-token">
  #### 使用 OAuth 1.0a 生成用户访问令牌
</div>

查看 [OAuth 1.0a flow test collection](https://www.postman.com/xapidevelopers/workspace/twitter-s-public-workspace/collection/9956214-784efcda-ed4c-4491-a4c0-a26470a67400?ctx=documentation) 中使用的三步流程。

<div id="using-oauth-20-to-generate-a-user-access-token">
  #### 使用 OAuth 2.0 生成用户访问令牌
</div>

如果你想在 Postman 中生成 OAuth 2.0 用户访问令牌，可以生成 OAuth 2.0 访问令牌，并将其与 X [API v2 Postman collection](https://www.postman.com/xapidevelopers/workspace/twitter-s-public-workspace/collection/9956214-784efcda-ed4c-4491-a4c0-a26470a67400?ctx=documentation) 配合使用。 

在工作区中点击该 collection，进入名为 “Auth” 的选项卡，并将类型选择为 “OAuth 2.0”。然后在 “Configure New Token” 标题下，找到 “Configuration Options” 部分。你可以将 “Grant Type” 更新为 “Authorization Code (With PKCE)”。

你需要将 Callback URL 更新为与你的应用关联的回调 URL。此外，你还需要更新以下参数：

* Auth URL -  https://x.com/i/oauth2/authorize
* Access Token URL -  https://api.x.com/2/oauth2/token
* Client ID - 来自 Dev Portal 的 OAuth 2.0 client ID
* Client Secret - 如果你使用的是 confidential client
* Update Scope - 与要访问的端点相匹配的权限范围（scopes）。例如 “tweet.read users.read” 
* 你的 Callback URL（也称为 Redirect URL）。它必须与你在应用身份验证设置中配置的值完全匹配。
* State - 状态值（state）

准备就绪后，你可以点击 “Get New Access Token” 来生成访问令牌。如果你看到一个对话框提示出现错误，你可能需要点击返回按钮重新登录。你需要在对话框中点击 “Authorize app” 来授权你的应用访问你的账户。

在你授权应用之后，你会被重定向回 Postman，在那里你可以看到你的令牌，并点击 “Use Token” 按钮，开始代表已授权用户发起请求。

现在你已经可以使用该 Postman collection 了。
