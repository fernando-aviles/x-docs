X API 在返回多页结果的端点（例如时间线、搜索等）中使用分页机制。每个 API 调用的响应都会包含一个带有 `result_count`、`previous_token` 和 `next_token` 的 `meta` 对象。XDK 会使用 `next_token` 自动完成多次 API 调用，因此开发者只需指定所需的数据量，而不必手动发起多次请求。
SDK 通过以下方式简化了这一流程：

- **内置迭代器**：使用 generator 函数无缝获取多页数据。
- **显式 Token 处理**：在需要时通过传入 `pagination_token` 以获得更灵活的手动控制。
- **最大结果数限制**：在每次调用中遵守 `max_results` 限制（受 API 上限约束，例如搜索接口的上限为 100）。

<div id="automatic-pagination-recommended">
  ## 自动分页（推荐）
</div>

对分页响应使用 `iterate()` 方法，以惰性（lazy）方式获取所有结果。
**示例：分页搜索**

```python
from xdk import Client
client = Client(bearer_token="your_bearer_token")
# 使用自动分页进行搜索
all_posts = []
for page in client.posts.search_recent(
    query="python",
    max_results=100,  # 每页
    tweet_fields=["created_at", "author_id"]  # 可选的 expansions
):
    all_posts.extend(page.data)
    print(f"Fetched {len(page.data)} Posts (total: {len(all_posts)})")
print(f"Total tweets: {len(all_posts)}")
```

* 迭代器会自动处理 `next_token`。
* 当不再返回 `next_token` 时会停止。
* 支持速率限制退避机制，以避免 429 错误。


<div id="manual-pagination">
  ## 手动分页
</div>

如果你需要出于某些自定义逻辑（例如按页处理）来控制结果，你仍然可以使用 `next_token`，并按照下面所示手动进行分页：

```python
# 获取第一页 - search_recent 返回一个迭代器
first_page = next(client.posts.search_recent(
    query="xdk python sdk",
    max_results=100,
    pagination_token=None  # 第一页
))
print(f"第一页：{len(first_page.data) if first_page.data else 0} 条帖子")
# 从 meta 中提取 next_token
next_token = None
if hasattr(first_page, 'meta') and first_page.meta:
    if hasattr(first_page.meta, 'next_token'):
        next_token = first_page.meta.next_token
    elif isinstance(first_page.meta, dict):
        next_token = first_page.meta.get('next_token')
if next_token:
    second_page = next(client.posts.search_recent(
        query="xdk python sdk",
        max_results=100,
        pagination_token=next_token
    ))
    print(f"Second page: {len(second_page.data) if second_page.data else 0} Posts")
```

**提示**：

* 始终显式指定 `max_results` 以优化效果（默认值因端点而异）。
* 关注 `meta.result_count` 以便调试。
* 对于非常大的查询，考虑使用异步迭代以避免阻塞。
