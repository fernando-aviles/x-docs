用于管理 DM 屏蔽的端点使你能够代表经过身份验证的用户屏蔽或取消屏蔽指定账号。对于这些端点，有两个可用的 POST 方法：

* **/2/users/:id/dm/block**: 允许你屏蔽一个账号
* **/2/users/:id/dm/unblock**: 允许你取消屏蔽一个账号

<div id="getting-started">
  ### 快速开始
</div>

<div id="authentication">
  ### 身份验证
</div>

由于你是代表某个用户发起请求，必须使用 [OAuth 1.0a User Context](/zh/resources/fundamentals/authentication#obtaining-access-tokens-using-3-legged-oauth-flow) 或 [OAuth 2.0 Authorization Code with PKCE](/zh/resources/fundamentals/authentication#oauth-2-0-authorization-code-flow-with-pkce-2) 来对这些端点的请求进行身份验证，并使用与你所代表用户关联的用户 Access Token。你可以通过 [3-legged OAuth flow](https://developer.x.com/resources/fundamentals/authentication/obtaining-user-access-tokens)（OAuth 1.0a）或 [Authorization Code with PKCE grant flow](/zh/resources/fundamentals/authentication#oauth-2-0-authorization-code-flow-with-pkce-2)（OAuth 2.0）来生成该用户的 Access Token。

<div id="making-a-request">
  ### 发起请求
</div>

Block

一旦用户在你的 App 中完成认证，你就可以按如下方式代表该用户调用 Block 端点：

```
      curl --request POST 'https://api.x.com/2/users/:id/dm/block' --header 'Authorization: ••••••'
```

如果请求成功，你会看到如下 JSON 响应：

```
{
   "data": {
       "blocked": true
   }
}
```

**取消屏蔽**

一旦用户通过你的 App 完成认证后，你就可以代表该用户调用 Unblock 端点，如下所示：

```
      curl --request POST 'https://api.x.com/2/users/:id/dm/unblock' --header 'Authorization: ••••••'
```

如果请求成功，你将会看到如下所示的 JSON 响应：

```
{
   "data": {
       "blocked": false
   }
}
```
