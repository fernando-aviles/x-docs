  ## 关键概念
</div>

<div id="authentication">
  ### 身份验证
</div>

所有 X API v2 端点都要求你使用一组凭证（也称为 keys 和 tokens）对请求进行身份验证。你可以使用 OAuth 1.0a User Context、仅 App（App only），或者带 PKCE 的 OAuth 2.0 授权码来对发往此端点的请求进行身份验证。

[OAuth 1.0a User Context](/zh/resources/fundamentals/authentication#oauth-1-0a-2)，这意味着你必须使用一组 API Keys 和用户 Access Tokens 才能成功发起请求。Access Tokens 必须与代表其发起请求的用户关联。如果你希望为另一位用户生成一组 Access Tokens，则该用户必须使用 [3-legged OAuth 流程](/zh/resources/fundamentals/authentication#obtaining-access-tokens-using-3-legged-oauth-flow)授权你的 App。

请注意，OAuth 1.0a 的使用可能相对复杂。如果你不熟悉这种身份验证方式，我们建议你使用一个[库](/zh/x-api/tools-and-libraries/overview)、使用 Postman 之类的工具，或者使用 OAuth 2.0 或仅 App（App only）来对你的请求进行身份验证。

[带 PKCE 的 OAuth 2.0 授权码](/zh/resources/fundamentals/authentication#oauth-2-0-authorization-code-flow-with-pkce-2)可以更好地控制应用的 scope，并支持跨多设备的授权流程。OAuth 2.0 允许你选择精细化的 scopes，从而代表用户获取特定权限。

要在你的 App 中启用 OAuth 2.0，你必须在开发者控制台的 App 设置部分中，在该 App 的身份验证设置里启用 OAuth 2.0。

[仅 App（App only）](/zh/resources/fundamentals/authentication#app-only-authentication-and-oauth-2-0-bearer-token)只要求你在请求中携带一个 [App only Access Token](/zh/resources/fundamentals/authentication#app-only-authentication-and-oauth-2-0-bearer-token)。你可以直接在开发者 App 中生成 App only Access Token，或者使用 [POST oauth2/token](/zh/resources/fundamentals/authentication#post-oauth2-token) 端点来生成。

<div id="developer-console-projects-and-developer-apps">
  ### 开发者控制台、Project 和开发者 App
</div>

要获取可用于 X API v2 端点的一组身份验证凭证，你必须先[注册一个开发者账号](https://developer.x.com/en/portal/petition/essential/basic-info)，在该账号下设置一个 [Project](/zh/resources/fundamentals/developer-apps)，并在该 Project 中创建一个[开发者 App](/zh/resources/fundamentals/developer-apps)。随后，你可以在该开发者 App 中找到你的密钥和令牌。

<div id="rate-limits">
  ### 速率限制
</div>

每天都有成千上万的开发者向 X API 发起请求。为了管理如此庞大的请求量，我们在每个端点上都设置了[速率限制](https://developer.x.com/x-api/fundamentals/rate-limits)，以限制你代表 App 或代表已认证用户所能发起的请求次数。

此端点在 App 级别和用户级别都受速率限制。App 级速率限制意味着你作为开发者，在给定时间段内，从任意 App（通过使用 API Key 与 API Secret Key，或 Bearer Token）对该端点只能发起一定数量的请求。用户级速率限制意味着，你代表其发起请求的已认证用户，在所有开发者 App 中，对列表中的帖子进行查询（List Post lookup）操作的次数也有限制。

下表显示了每个端点对应的速率限制。

| Endpoint | HTTP method | Rate limit |
| :--- | :--- | :--- |
| /2/lists/:id/tweets | GET | 每 15 分钟 900 次请求 |

<div id="fields-and-expansions">
  ### 字段和 expansions
</div>

X API v2 的 GET 端点允许用户使用一组称为 `fields` 和 `expansions` 的工具，精确选择希望从 API 返回的具体数据。`expansions` 参数用于展开请求载荷中被引用的对象。例如，在查询列表中的帖子时，你可以获取以下 [expansions](/zh/x-api/fundamentals/expansions)：

* `author_id`

`fields` 参数允许你精确选择希望在不同数据对象中接收的[字段](/zh/x-api/fundamentals/fields)。此端点主要返回 Post 对象。默认情况下，Post 对象返回 `id` 和 `text` 字段。若要接收其他字段（例如 `tweet.created_at` 或 `tweet.lang`），你必须通过 fields 参数显式请求这些字段。

我们在 [X API v2 数据字典](/zh/x-api/fundamentals/data-dictionary)中新增了一篇关于如何同时使用[字段和 expansions](/zh/x-api/fundamentals/data-dictionary#how-to-use-fields-and-expansions)的指南。

下表展示了该查找端点可用的字段和 expansions：

| Endpoint | Fields | Expansions |
| :--- | :--- | :--- |
| /2/lists/:id/tweets | `tweet.fields`, `user.fields` | `author_id` |

<div id="pagination">
  ### 分页
</div>

查询列表帖子时可能会返回大量数据。为了确保在任何时间都能返回稳定且高效的结果，我们会使用分页。分页是 X API v2 中的一项功能，适用于那些单个响应无法返回全部结果的端点。当出现这种情况时，数据会分成一系列“页面”返回。了解更多关于[如何对结果进行分页](/zh/x-api/fundamentals/pagination)。
