  ## 核心概念

<div id="authentication">
  ### 身份验证
</div>

所有 X API v2 端点都要求你使用一组凭证（也称为 keys 和 tokens）对请求进行身份验证。你可以使用 OAuth 1.0a 用户上下文、仅 App（App only），或带有 PKCE 的 OAuth 2.0 授权码方式（Authorization Code）来对发送到此端点的请求进行身份验证。

[OAuth 1.0a 用户上下文](/zh/resources/fundamentals/authentication#oauth-1-0a-2) 意味着你必须使用一组 API Keys 和用户 Access Tokens 才能成功发起请求。Access Tokens 必须与代表其发起请求的用户相关联。如果你想为另一位用户生成一组 Access Tokens，他们必须使用 [三方 OAuth 流（3-legged OAuth flow）](/zh/resources/fundamentals/authentication#obtaining-access-tokens-using-3-legged-oauth-flow) 授权你的 App。

请注意，OAuth 1.0a 使用起来可能比较困难。如果你对这种身份验证方法不熟悉，我们建议你使用一个 [library](/zh/x-api/tools-and-libraries/overview)、使用 Postman 之类的工具，或使用 OAuth 2.0 或仅 App（App only）来对你的请求进行身份验证。

[带有 PKCE 的 OAuth 2.0 授权码方式（Authorization Code with PKCE）](/zh/resources/fundamentals/authentication#oauth-2-0-authorization-code-flow-with-pkce-2) 可以让你对应用的 scope 以及跨多设备的授权流程进行更精细的控制。OAuth 2.0 允许你选择特定的细粒度 scope，从而代表用户获取特定的权限。

要在你的 App 中启用 OAuth 2.0，你必须在 Developer Console 中 App 设置部分的 App 身份验证设置里将其启用。

[仅 App（App only）](/zh/resources/fundamentals/authentication#app-only-authentication-and-oauth-2-0-bearer-token) 只要求你在请求中携带一个 [仅 App Access Token](/zh/resources/fundamentals/authentication#app-only-authentication-and-oauth-2-0-bearer-token)。你可以直接在一个开发者 App 中生成仅 App Access Token，或使用 [POST oauth2/token](/zh/resources/fundamentals/authentication#post-oauth2-token) 端点生成一个。

<div id="developer-console-projects-and-developer-apps">
  ### Developer Console、Project 和开发者 App
</div>

要获取可用于 X API v2 各端点的一组认证凭证，你必须先[注册开发者账号](https://developer.x.com/en/portal/petition/essential/basic-info)、在该账号下创建一个 [Project](/zh/resources/fundamentals/developer-apps)，并在该 Project 中创建一个[开发者 App](/zh/resources/fundamentals/developer-apps)。随后，你可以在自己的开发者 App 中找到密钥和令牌。

<div id="rate-limits">
  ### 速率限制
</div>

每天都有成千上万的开发者向 X API 发起请求。为了管理如此庞大的请求量，我们在每个端点上都设置了[速率限制](https://developer.x.com/x-api/fundamentals/rate-limits)，以限制你代表你的应用或代表经过认证的用户所能发起的请求次数。

此端点在 App 级别和用户级别都受到速率限制。App 级别的速率限制意味着，你作为开发者，在给定的时间段内，从任意给定的 App（通过使用 API Key 和 API Secret Key，或 Bearer Token 来识别）对该端点只能发起一定数量的请求。用户级别的速率限制意味着，你代表其发起请求的已认证的用户，在所有开发者 App 中，只能执行一定次数的列表帖子查询操作。

下表展示了每个端点的速率限制。

| 端点 | HTTP 方法 | 速率限制 |
| :--- | :--- | :--- |
| /2/lists/:id/tweets | GET | 每 15 分钟 900 次请求 |

<div id="fields-and-expansions">
  ### 字段与扩展
</div>

X API v2 的 GET 端点允许用户使用一组称为 `fields` 和 `expansions` 的工具，精确指定希望从 API 返回的哪些数据。`expansions` 参数允许你展开响应负载中被引用的对象。例如，在查询列表帖子（List Posts）时，你可以获取以下[扩展](/zh/x-api/fundamentals/expansions)：

* `author_id`

`fields` 参数允许你在不同的数据对象中精确选择希望接收的哪些[字段](/zh/x-api/fundamentals/fields)。此端点主要返回 Post 对象。默认情况下，Post 对象仅返回 `id` 和 `text` 字段。若要接收诸如 `tweet.created_at` 或 `tweet.lang` 等其他字段，你必须通过 `fields` 参数显式请求这些字段。

我们在 [X API v2 数据字典](/zh/x-api/fundamentals/data-dictionary)中新增了一篇关于结合使用[字段与扩展](/zh/x-api/fundamentals/data-dictionary#how-to-use-fields-and-expansions)的指南。

下表展示了该查找端点可用的字段与扩展：

| Endpoint | Fields | Expansions |
| :--- | :--- | :--- |
| /2/lists/:id/tweets | `tweet.fields`, `user.fields` | `author_id` |

<div id="pagination">
  ### 分页
</div>

查询列表中的帖子时可能会返回大量 data。为了确保在任意时间点都能返回一致且高效的结果，我们使用分页。分页是 X API v2 端点的一项功能，用于在返回结果数量超过单个响应所能包含的范围时使用。在这种情况下，data 会被拆分为一系列“页面”返回。详细了解如何[对结果进行分页](/zh/x-api/fundamentals/pagination)。
