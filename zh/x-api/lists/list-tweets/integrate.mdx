  ## 关键概念

<div id="authentication">
  ### 认证
</div>

所有 X API v2 端点都要求你使用一组凭证（也称为 key 和 token）对请求进行认证。你可以使用 OAuth 1.0a 用户上下文、仅限 App，或者带 PKCE 的 OAuth 2.0 授权码来对发往该端点的请求进行认证。

[OAuth 1.0a 用户上下文](/zh/resources/fundamentals/authentication#oauth-1-0a-2)，意味着你必须使用一组 API Key 和用户访问令牌（Access Token）才能成功发起请求。访问令牌必须与你代表其发起请求的那位用户相关联。如果你想为另一位用户生成一组访问令牌，他们必须通过 [3-legged OAuth 流程](/zh/resources/fundamentals/authentication#obtaining-access-tokens-using-3-legged-oauth-flow)授权你的 App。

请注意，OAuth 1.0a 的使用可能相对复杂。如果你对这种认证方式不熟悉，我们建议你使用一个[库](/zh/x-api/tools-and-libraries/overview)、使用 Postman 之类的工具，或者使用 OAuth 2.0 或仅限 App 的方式来对请求进行认证。

[带 PKCE 的 OAuth 2.0 授权码](/zh/resources/fundamentals/authentication#oauth-2-0-authorization-code-flow-with-pkce-2)能够让你对应用的 scope（权限范围）拥有更精细的控制，并支持跨多个设备的授权流程。OAuth 2.0 允许你选择特定的细粒度 scope，从而代表用户获得对应的权限。

要在你的 App 中启用 OAuth 2.0，你必须在开发者控制台中 App 设置部分的认证设置里启用它。

[仅限 App](/zh/resources/fundamentals/authentication#app-only-authentication-and-oauth-2-0-bearer-token) 只要求你在请求中携带一个[仅限 App 的 Access Token](/zh/resources/fundamentals/authentication#app-only-authentication-and-oauth-2-0-bearer-token)。你可以直接在对应的开发者 App 中生成一个仅限 App 的 Access Token，或者使用 [POST oauth2/token](/zh/resources/fundamentals/authentication#post-oauth2-token) 端点生成一个。

<div id="developer-console-projects-and-developer-apps">
  ### 开发者控制台、Project 和开发者 App
</div>

要获取一组可用于 X API v2 各个端点的认证凭证，你必须先[注册开发者账号](https://developer.x.com/en/portal/petition/essential/basic-info)，在该账号下创建一个 [Project](/zh/resources/fundamentals/developer-apps)，并在该 Project 中创建一个 [开发者 App](/zh/resources/fundamentals/developer-apps)。然后，你可以在自己的开发者 App 中找到对应的 keys 和 tokens。

<div id="rate-limits">
  ### 速率限制
</div>

每天都有数以千计的开发者向 X API 发出请求。为了帮助管理如此巨大的请求量，我们在每个端点上都设置了[速率限制](https://developer.x.com/x-api/fundamentals/rate-limits)，以限制你代表你的应用或代表已认证用户所能发出的请求次数。

此端点在 App 级别和用户级别都受到速率限制。App 级别的速率限制意味着你作为开发者，在给定时间段内，从任意特定的 App（即通过使用 API Key 和 API Secret Key，或 Bearer Token 所标识的 App）向该端点发出的请求次数是有限的。用户级别的速率限制意味着，你代表其发出请求的已认证用户，在所有开发者 App 中只能在一定次数内执行列表帖子查找操作。

下表显示了每个端点的速率限制。

| Endpoint | HTTP method | Rate limit |
| :--- | :--- | :--- |
| /2/lists/:id/tweets | GET | 每 15 分钟 900 个请求 |

<div id="fields-and-expansions">
  ### 字段与扩展
</div>

X API v2 的 GET 端点允许用户使用一组称为 `fields` 和 `expansions` 的工具，精确选择希望从 API 返回的哪些数据。`expansions` 参数允许你展开载荷中引用的对象。例如，查询列表中的帖子时，你可以获取以下[扩展](/zh/x-api/fundamentals/expansions)：

* `author_id`

`fields` 参数允许你在不同的数据对象中精确选择希望接收的[字段](/zh/x-api/fundamentals/fields)。此端点主要返回 Post 对象。默认情况下，Post 对象返回 `id` 和 `text` 字段。若要接收诸如 `tweet.created_at` 或 `tweet.lang` 等其他字段，你必须通过 `fields` 参数明确请求这些字段。

我们在 [X API v2 data dictionary](/zh/x-api/fundamentals/data-dictionary) 中新增了一篇关于如何结合使用[fields 和 expansions](/zh/x-api/fundamentals/data-dictionary#how-to-use-fields-and-expansions) 的指南。

下表显示了该 lookup 端点可用的字段和扩展：

| Endpoint | Fields | Expansions |
| :--- | :--- | :--- |
| /2/lists/:id/tweets | `tweet.fields`，`user.fields` | `author_id` |

<div id="pagination">
  ### 分页
</div>

在查询列表帖子时可能会返回大量数据。为了确保在任何时间点都能返回一致且高效的结果，我们会使用分页。分页是 X API v2 端点中的一项功能，当返回的结果多于单个响应所能包含的数量时就会用到。此时，这些数据会以一系列「页面」的形式返回。详细了解如何[对结果进行分页](/zh/x-api/fundamentals/pagination)。
