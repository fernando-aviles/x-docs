<div id="key-concepts">
  ## 关键概念
</div>

<div id="authentication">
  ### 认证
</div>

所有 X API v2 端点都要求你使用一组凭证（也称为 keys 和 tokens）对请求进行认证。对于 Lists 的 **lookup** 端点，你可以使用 OAuth 1.0a 用户上下文、OAuth 2.0 Authorization Code with PKCE，或仅 App 模式来对请求进行认证。但是，对于 **manage** Lists 端点，你必须使用 OAuth 1.0a 用户上下文或 OAuth 2.0 进行认证。

使用 [OAuth 1.0a 用户上下文](/zh/resources/fundamentals/authentication) 时，你必须使用一组 API Keys 和用户 Access Tokens 才能成功发起请求。Access Tokens 必须与代表其发起请求的用户关联。如果你想为另一个用户生成一组 Access Tokens，则该用户必须通过 [3-legged OAuth flow](/zh/resources/fundamentals/authentication#obtaining-access-tokens-using-3-legged-oauth-flow) 授权你的 App。

请注意，OAuth 1.0a 可能较难使用。如果你不熟悉这种认证方式，建议你使用一个 [library](/zh/x-api/tools-and-libraries/overview)、使用类似 Postman 的工具，或者使用 OAuth 2.0 或仅 App 模式来对请求进行认证。

[OAuth 2.0 Authorization Code with PKCE](/zh/resources/fundamentals/authentication#oauth-2-0-authorization-code-flow-with-pkce-2) 允许对应用的 scope 和跨多设备的授权流程进行更精细的控制。OAuth 2.0 允许你选择特定的细粒度 scopes，以便代表用户获取特定权限。

要在你的 App 中启用 OAuth 2.0，你必须在 Developer Console 中 App 设置部分的认证设置里启用它。

[仅 App](/zh/resources/fundamentals/authentication#oauth-2-0) 只要求你在请求中携带一个 [App only Access Token](/zh/resources/fundamentals/authentication#bearer-token-also-known-as-app-only)。你可以直接在一个开发者 App 中生成 App only Access Token，或者使用 [POST oauth2/token](/zh/resources/fundamentals/authentication#post-oauth2-token) 端点来生成。

<div id="developer-console-projects-and-developer-apps">
  ### Developer Console、Project 和开发者 App
</div>

要获取可用于 X API v2 端点的一组认证凭据，你必须先[注册开发者账号](https://developer.x.com/en/portal/petition/essential/basic-info)，在该账号下设置一个 [Project](/zh/resources/fundamentals/developer-apps)，然后在该 Project 中创建一个[开发者 App](/zh/resources/fundamentals/developer-apps)。之后，你可以在该开发者 App 中找到你的密钥和令牌。

<div id="rate-limits">
  ### 速率限制
</div>

每天都有成千上万的开发者向 X API 发起请求。为了帮助管理这些大量请求，[速率限制](/zh/x-api/fundamentals/rate-limits) 会应用到每个端点上，用来限制你代表你的应用或代表一个已认证用户所能发起的请求数量。

查询（GET）端点在 App 级别和用户级别都会受到速率限制，而管理类（POST/DELETE）端点只在用户级别受到限制。App 级速率限制意味着你作为开发者，在给定时间段内，从任意一个开发者 App（通过使用 API Key 和 API Secret Key，或仅使用 App Access Token）对该端点只能发起一定数量的请求。用户级速率限制意味着，你代表的已认证用户，在任意开发者 App 上只能执行一定次数的 List 查找操作。

下表展示了每个端点对应的速率限制。

| 端点 | HTTP 方法 | 速率限制 |
| :--- | :--- | :--- |
| /2/lists/:id/members | GET | 每 15 分钟 900 次请求 |
| /2/users/:id/list&#95;memberships | GET | 每 15 分钟 75 次请求 |
| /2/lists/:id/members | POST | 每 15 分钟 300 次请求 |
| /2/lists/:id/members/:user&#95;id | DELETE | 每 15 分钟 300 次请求 |

<div id="fields-and-expansions">
  ### 字段和扩展
</div>

X API v2 的 GET 端点允许用户使用一组名为 `fields` 和 `expansions` 的工具，精确选择他们希望从 API 返回的数据。`expansions` 参数允许你展开在载荷中被引用的对象。例如，在查询列表成员（List members）时，你可以获取以下[扩展](/zh/x-api/fundamentals/expansions)：

* `pinned_tweet_id`

`fields` 参数允许你精确选择希望在不同数据对象中接收的[字段](/zh/x-api/fundamentals/fields)。列表成员查询主要返回用户对象。默认情况下，用户对象会返回 id、名称和用户名字段。要接收诸如 `user.created_at` 或 `user.description` 等额外字段，你必须通过 `user.fields` 参数显式请求这些字段。

我们添加了一篇关于如何使用[字段和扩展](/zh/x-api/fundamentals/data-dictionary#how-to-use-fields-and-expansions)的指南。

下表展示了每个查询端点可用的字段和扩展：

| Endpoint | 字段 | 扩展 |
| :--- | :--- | :--- |
| /2/lists/:id/members | `user.fields`，`tweet.fields` | `pinned_tweet_id` |
| /2/users/:id/list&#95;memberships | `list.fields`，`user.fields` | `owner_id` |

<div id="pagination">
  ### 分页
</div>

查询成员身份或成员列表时，可能会返回大量 data。为了确保在任何时刻都能返回一致且高效的结果，我们会使用分页。分页是 X API v2 端点中的一项功能，用于在结果数量超过单个响应可返回的上限时，将结果分成多页返回。当出现这种情况时，data 会以一系列“页”的形式返回。进一步了解如何[对结果进行分页。](/zh/x-api/fundamentals/pagination)
