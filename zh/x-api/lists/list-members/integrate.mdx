  ## 关键概念

<div id="authentication">
  ### 身份验证
</div>

所有 X API v2 端点都要求你使用一组凭证（也称为密钥和令牌）对请求进行身份验证。对于 Lists 的 **lookup** 端点，你可以使用 OAuth 1.0a 用户上下文、OAuth 2.0 Authorization Code with PKCE，或 App only 来对请求进行身份验证。不过，对于 **manage** Lists 端点，你必须使用 OAuth 1.0a 用户上下文或 OAuth 2.0 进行身份验证。

[OAuth 1.0a 用户上下文](/zh/resources/fundamentals/authentication)，意味着你必须使用一组 API Key 和用户 Access Token 才能成功发出请求。这些 Access Token 必须与代表其发出请求的用户关联。如果你想为另一位用户生成一组 Access Token，则该用户必须使用 [3-legged OAuth flow](/zh/resources/fundamentals/authentication#obtaining-access-tokens-using-3-legged-oauth-flow) 授权你的 App。

请注意，OAuth 1.0a 使用起来可能比较复杂。如果你不熟悉这种身份验证方式，我们建议你使用[库](/zh/x-api/tools-and-libraries/overview)、使用 Postman 之类的工具，或者使用 OAuth 2.0 或 App only 来对请求进行身份验证。

[OAuth 2.0 Authorization Code with PKCE](/zh/resources/fundamentals/authentication#oauth-2-0-authorization-code-flow-with-pkce-2) 允许对应用的权限范围进行更精细的控制，并支持跨多台设备的授权流程。OAuth 2.0 允许你选择特定的细粒度权限范围（scope），从而代表用户获得相应的特定权限。

要在你的 App 中启用 OAuth 2.0，你必须先在开发者控制台中该 App 设置部分的身份验证设置里将其启用。

[App only](/zh/resources/fundamentals/authentication#oauth-2-0) 只要求你在请求中携带一个 [App only Access Token](/zh/resources/fundamentals/authentication#bearer-token-also-known-as-app-only)。你可以直接在开发者 App 中生成一个 App only Access Token，或者使用 [POST oauth2/token](/zh/resources/fundamentals/authentication#post-oauth2-token) 端点生成一个。

<div id="developer-console-projects-and-developer-apps">
  ### 开发者控制台、Project 和开发者 App
</div>

要获取一组可用于 X API v2 端点的认证凭证，你需要先[注册开发者账号](https://developer.x.com/en/portal/petition/essential/basic-info)，在该账号下创建一个 [Project](/zh/resources/fundamentals/developer-apps)，并在该 Project 中创建一个[开发者 App](/zh/resources/fundamentals/developer-apps)。随后，你可以在该开发者 App 中找到你的密钥和令牌。

<div id="rate-limits">
  ### 速率限制
</div>

每天都有成千上万的开发者向 X API 发起请求。为了帮助管理如此庞大的请求量，我们在每个端点上都设置了[速率限制](/zh/x-api/fundamentals/rate-limits)，用来限制你代表你的应用或代表已认证用户所能发起的请求数量。

查询（GET）端点在 App 级别和用户级别都会受到速率限制；而管理类（POST/DELETE）端点则仅在用户级别受到限制。App 级速率限制意味着你作为开发者，在给定的一段时间内，通过任意给定的 App（通过使用 API Key 和 API Secret Key，或仅使用 App-only Access Token）访问该端点时，只能发起一定数量的请求。用户级速率限制意味着，你代表其发起请求的已认证用户，在所有开发者 App 中只能在一定次数内执行列表查询（List lookup）。

下表展示了每个端点对应的速率限制。

| 端点 | HTTP 方法 | 速率限制 |
| :--- | :--- | :--- |
| /2/lists/:id/members | GET | 每 15 分钟 900 个请求 |
| /2/users/:id/list&#95;memberships | GET | 每 15 分钟 75 个请求 |
| /2/lists/:id/members | POST | 每 15 分钟 300 个请求 |
| /2/lists/:id/members/:user&#95;id | DELETE | 每 15 分钟 300 个请求 |

<div id="fields-and-expansions">
  ### 字段和扩展
</div>

X API v2 的 GET 端点允许用户使用一组称为 `fields` 和 `expansions` 的工具，精确选择他们希望从 API 返回的数据。`expansions` 参数允许你展开在载荷中被引用的对象。例如，查询 List 成员时，你可以获取以下[扩展](/zh/x-api/fundamentals/expansions)：

* `pinned_tweet_id`

`fields` 参数允许你在不同的数据对象中精确选择希望接收的[字段](/zh/x-api/fundamentals/fields)。List 成员查询主要返回用户对象。默认情况下，用户对象会返回 id、名称和用户名字段。要接收诸如 `user.created_at` 或 `user.description` 之类的其他字段，你必须通过 `user.fields` 参数显式请求这些字段。

我们提供了一篇关于如何使用[字段和扩展](/zh/x-api/fundamentals/data-dictionary#how-to-use-fields-and-expansions)的指南。

下表展示了每个查找端点可用的字段和扩展：

| Endpoint | Fields | Expansions |
| :--- | :--- | :--- |
| /2/lists/:id/members | `user.fields`, `tweet.fields` | `pinned_tweet_id` |
| /2/users/:id/list&#95;memberships | `list.fields`, `user.fields` | `owner_id` |

<div id="pagination">
  ### 分页
</div>

查询成员关系或成员时，可能会返回大量数据。为了确保在任何时间点都能返回一致且高效的结果，我们使用分页。分页是 X API v2 端点上的一项功能，当返回的结果数量超过单个响应所能包含时，就会使用分页。此时，data 会以一系列“页面”的形式返回。详细了解如何[对结果进行分页](/zh/x-api/fundamentals/pagination)。
