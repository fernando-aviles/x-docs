<div id="list-members-lookup-standard-v11-compared-to-x-api-v2">
  ### 列表成员查找：标准 v1.1 与 X API v2 的比较
</div>

如果你一直在使用标准 v1.1 的 [GET lists/members](https://developer.x.com/en/docs/twitter-api/v1/accounts-and-users/create-manage-lists/api-reference/get-lists-members) 和 [GET lists/memberships](https://developer.x.com/en/docs/twitter-api/v1/accounts-and-users/create-manage-lists/api-reference/get-lists-memberships) 端点，本指南旨在帮助你了解标准 v1.1 与 X API v2 列表成员端点之间的相同点和差异。

* **相似点**
  * 身份验证方式
* **差异**
  * 端点 URL
  * 速率限制
  * App 和 Project 要求
  * 每个请求的数据对象数量上限
  * 响应数据格式
  * 请求参数

<div id="similarities">
  #### 相似点
</div>

**认证**

这两个版本的 endpoint 都支持 [OAuth 1.0a 用户上下文](/zh/resources/fundamentals/authentication#oauth-1-0a-2) 和 [仅 App](/zh/resources/fundamentals/authentication#oauth-2-0) 认证。因此，如果你之前在使用标准 v1.1 的某个列表成员 endpoint，那么在迁移到 X API v2 版本时，可以继续使用相同的认证方式。

取决于你所使用的认证库或软件包，采用仅 App 认证通常是最容易上手的方式，并且只需要设置一个简单的请求头即可。要了解如何生成仅 App 的访问令牌，请参阅[本仅 App 指南](/zh/resources/fundamentals/authentication#bearer-token-also-known-as-app-only)。

<div id="differences">
  #### 差异
</div>

**Endpoint URL**

* 标准 v1.1 endpoint：
  * GET https://api.x.com/1.1/lists/members.json
    （查询指定列表的成员）
  * GET https://api.x.com/1.1/lists/memberships.json
    （查询某个用户所属的列表）
* X API v2 endpoint：
  * GET https://api.x.com/2/lists/:id/members
    （查询指定列表的成员）

  * GET https://api.x.com/2/users/:id/list&#95;memberships
    （查询某个用户所属的列表）

**速率限制**

|     |     |
| :--- | :--- |
| **标准 v1.1** | **X API v2** |
| /1.1/lists/members.json<br /><br />使用 OAuth 1.0a 用户上下文时，每个 15 分钟时间窗口内最多 900 次请求<br /><br />仅使用 App 时，每个 15 分钟时间窗口内最多 15 次请求 | /2/lists/:id/members<br /><br />使用 OAuth 1.0a 用户上下文时，每个 15 分钟时间窗口内最多 900 次请求<br /><br />使用 OAuth 2.0 Authorization Code with PKCE 时，每个 15 分钟时间窗口内最多 900 次请求<br /><br />仅使用 App 时，每个 15 分钟时间窗口内最多 900 次请求 |
| /1.1/lists/memberships.json<br /><br />使用 OAuth 1.0a 用户上下文时，每个 15 分钟时间窗口内最多 15 次请求<br /><br />仅使用 App 时，每个 15 分钟时间窗口内最多 15 次请求 | /2/users/:id/list&#95;memberships<br /><br />使用 OAuth 1.0a 用户上下文时，每个 15 分钟时间窗口内最多 15 次请求<br /><br />使用 OAuth 2.0 Authorization Code with PKCE 时，每个 15 分钟时间窗口内最多 15 次请求<br /><br />仅使用 App 时，每个 15 分钟时间窗口内最多 15 次请求 |

**App 和 Project 要求**

在对 X API v2 endpoint 进行请求认证时，你必须使用来自与某个 [Project](/zh/resources/fundamentals/developer-apps) 关联的 [developer App](/zh/resources/fundamentals/developer-apps) 的凭证。所有 X API v1.1 endpoint 都可以使用来自独立 App 或与 Project 关联的 App 的凭证。

**每次请求的数据对象数量限制**

标准 v1.1 的 /1.1/lists/members endpoint 每次请求最多可返回 5000 个用户。新的 v2 endpoint 每次请求最多可返回 100 个用户。默认情况下会返回 100 个用户对象，如需更改结果数量，你需要传入查询参数 max&#95;results=，其值为 1–100 之间的数字；随后可以在下一个请求中，将响应负载中返回的 next&#95;token 作为 pagination&#95;token 查询参数传入。

此外，/1.1/lists/memberships endpoint 每次请求最多可返回 1000 个列表。使用 v2 替代 endpoint 时，每次请求最多允许返回 100 个列表。默认会返回 100 个列表对象，请以与 /1.1/lists/members 相同的方式使用查询参数 max&#95;results= 和 pagination&#95;token 来更改结果数量。

**响应数据格式**

标准 v1.1 和 X API v2 版本 endpoint 之间最大的差异之一，是你如何选择要在响应负载中返回哪些字段。

对于标准 endpoint，你会默认收到许多响应字段，然后可以通过参数来指定哪些额外的字段或字段集合应在负载中返回。

X API v2 版本 /users/:id/list&#95;memberships 会默认返回列表的 id 和 name 字段。要请求任何额外字段或对象，你需要使用 [fields](/zh/x-api/fundamentals/fields) 和 [expansions](/zh/x-api/fundamentals/expansions) 参数。你从该 endpoint 请求的任何列表字段都会返回在主列表对象中。任何被展开的对象及其字段都会在响应中的 includes 对象中返回。你随后可以通过匹配主对象和展开对象中都存在的 ID，将任何展开对象与主列表对象关联起来。

下面是一些可能的列表字段和 expansions 示例：

* created&#95;at

* follower&#95;count

* member&#95;count

* owner&#95;id

* description

* private

|     |     |
| :--- | :--- |
| **Endpoint** | **Expansion** |
| /2/lists/:id/members | pinned&#95;tweet&#95;id |
| /2/users/:id/list&#95;memberships | owner&#95;id |

我们建议你在各自的指南中进一步了解这些新参数，或者阅读我们的[如何使用 fields 和 expansions](/zh/x-api/fundamentals/data-dictionary#how-to-use-fields-and-expansions) 指南。 

我们还整理了一份[数据格式迁移指南](/zh/x-api/migrate/data-format-migration)，可帮助你将标准 v1.1 字段映射到较新的 v2 字段。该指南还会为你提供在 v2 请求中需要传递的具体 `expansion` 和 `field` 参数，以便返回特定字段。 

除了请求某些字段的方式发生变化外，X API v2 还为 API 返回的对象引入了新的 JSON 设计，包括 [Post](/zh/x-api/fundamentals/data-dictionary#tweet) 对象和 [user](/zh/x-api/fundamentals/data-dictionary#user) 对象。

* 在 JSON 根级别，标准端点在 `statuses` 数组中返回 Post 对象，而 X API v2 则在 `data` 数组中返回 Post 对象。 

* X API v2 的 JSON 不再使用 Retweeted 和 Quoted “statuses” 这样的表述，而是使用 Retweeted 和 Quoted Tweets。许多旧版和已弃用的字段（例如 `contributors` 和 `user.translator_type`）正在被移除。 

* X API v2 不再同时使用 `favorites`（在 Post 对象中）和 `favourites`（在 user 对象中），而是统一使用术语 `like`。 

* X 采用这样的约定：没有值的 JSON 值（例如 `null`）不会写入载荷。只有当 Post 和 user 属性具有非 `null` 值时才会被包含。

**请求参数**

以下标准 v1.1 请求参数在 X API v2 中有对应项：

**列表成员查询**

|     |     |
| :--- | :--- |
| **Standard v1.1** | **X API v2** |
| list&#95;id | id  |
| slug | 无对应项 |
| owner&#95;screen&#95;name | 无对应项 |
| owner&#95;id | 无对应项 |
| count | max&#95;results |
| cursor | pagination&#95;token |
| include&#95;entities | 无对应项 |
| skip&#95;status | 无对应项 |

**列表成员资格查询**

|     |     |
| :--- | :--- |
| **Standard v1.1** | **X API v2** |
| user&#95;id | id  |
| screen&#95;name | 无对应项 |
| count | max&#95;results |
| cursor | pagination&#95;token |
