<div id="list-members-lookup-standard-v11-compared-to-x-api-v2">
  ### 列表成员查询：标准 v1.1 与 X API v2 的比较
</div>

如果你一直在使用标准 v1.1 的 [GET lists/members](https://developer.x.com/en/docs/twitter-api/v1/accounts-and-users/create-manage-lists/api-reference/get-lists-members) 和 [GET lists/memberships](https://developer.x.com/en/docs/twitter-api/v1/accounts-and-users/create-manage-lists/api-reference/get-lists-memberships) 端点，本指南旨在帮助你了解标准 v1.1 与 X API v2 列表成员端点之间的相似点和差异。

* **相似点**
  * 认证方式
* **差异**
  * 端点 URL
  * 速率限制
  * App 和 Project 要求
  * 每个请求允许的数据对象数量上限
  * 响应数据格式
  * 请求参数

<div id="similarities">
  #### 相似之处
</div>

**身份验证**

这两个版本的端点都支持 [OAuth 1.0a 用户上下文](/zh/resources/fundamentals/authentication#oauth-1-0a-2) 和 [仅应用（App only）](/zh/resources/fundamentals/authentication#oauth-2-0)。因此，如果你之前使用的是某个标准 v1.1 列表（List）成员端点，在迁移到 X API v2 版本时，可以继续使用相同的身份验证方式。

根据你选择的身份验证库或软件包，仅应用（App only）身份验证通常是最容易上手的方式，并且可以通过一个简单的请求头进行设置。要了解如何生成 App only 访问令牌，请参阅[此仅应用指南](/zh/resources/fundamentals/authentication#bearer-token-also-known-as-app-only)。

<div id="differences">
  #### 差异
</div>

**Endpoint URL**

* 标准 v1.1 endpoint：
  * GET https://api.x.com/1.1/lists/members.json
    （查找指定列表的成员）
  * GET https://api.x.com/1.1/lists/memberships.json
    （查找某个用户所属的列表）
* X API v2 endpoint：
  * GET https://api.x.com/2/lists/:id/members
    （查找指定列表的成员）

  * GET https://api.x.com/2/users/:id/list&#95;memberships
    （查找某个用户所属的列表）

**速率限制**

|     |     |
| :--- | :--- |
| **标准 v1.1** | **X API v2** |
| /1.1/lists/members.json<br /><br />使用 OAuth 1.0a 用户上下文时，每 15 分钟窗口内 900 次请求<br /><br />仅使用 App 进行访问时，每 15 分钟窗口内 15 次请求 | /2/lists/:id/members<br /><br />使用 OAuth 1.0a 用户上下文时，每 15 分钟窗口内 900 次请求<br /><br />使用 OAuth 2.0 Authorization Code with PKCE 时，每 15 分钟窗口内 900 次请求<br /><br />仅使用 App 进行访问时，每 15 分钟窗口内 900 次请求 |
| /1.1/lists/memberships.json<br /><br />使用 OAuth 1.0a 用户上下文时，每 15 分钟窗口内 15 次请求<br /><br />仅使用 App 进行访问时，每 15 分钟窗口内 15 次请求 | /2/users/:id/list&#95;memberships<br /><br />使用 OAuth 1.0a 用户上下文时，每 15 分钟窗口内 15 次请求<br /><br />使用 OAuth 2.0 Authorization Code with PKCE 时，每 15 分钟窗口内 15 次请求<br /><br />仅使用 App 进行访问时，每 15 分钟窗口内 15 次请求 |

**App 和 Project 要求**

在对请求进行认证时，X API v2 endpoint 要求你使用与某个 [developer App](/zh/resources/fundamentals/developer-apps) 关联的 [Project](/zh/resources/fundamentals/developer-apps) 提供的凭证。所有 X API v1.1 endpoint 都可以使用来自独立 App 或与 Project 关联的 App 的凭证。

**每个请求的数据对象数量限制**

标准 v1.1 的 /1.1/lists/members endpoint 每个请求最多可返回 5000 个用户。新的 v2 endpoint 每个请求最多可返回 100 个用户。默认会返回 100 个用户对象，如需更改结果数量，你需要传递查询参数 max&#95;results=，其值为 1–100 之间的数字；然后可以将响应负载中返回的 next&#95;token 传递给下一次请求中的 pagination&#95;token 查询参数，以获取下一页结果。

此外，/1.1/lists/memberships endpoint 每个请求最多可返回 1000 个列表。使用 v2 替代 endpoint 时，每个请求最多允许返回 100 个列表。默认会返回 100 个列表对象，请以与 /1.1/lists/members 相同的方式使用查询参数 max&#95;results= 和 pagination&#95;token 来更改结果数量。

**响应数据格式**

标准 v1.1 与 X API v2 版本的 endpoint 之间最大的差异之一，是如何选择在响应负载中返回哪些字段。

对于标准 endpoint，你默认会收到许多响应字段，然后可以选择使用参数来指定需要在负载中额外返回哪些字段或字段集合。

X API v2 版本的 /users/:id/list&#95;memberships 会默认返回列表的 id 和名称字段。若要请求任何其他字段或对象，你需要使用 [fields](/zh/x-api/fundamentals/fields) 和 [expansions](/zh/x-api/fundamentals/expansions) 参数。从此 endpoint 请求的任何列表字段都会返回到主列表对象中。任何扩展对象及其字段都会作为 includes 对象返回在响应中。然后，你可以通过匹配主对象和扩展对象中出现的 id，将这些扩展对象关联回主列表对象。

以下是一些可能的列表字段和扩展示例：

* created&#95;at

* follower&#95;count

* member&#95;count

* owner&#95;id

* description

* private

|     |     |
| :--- | :--- |
| **Endpoint** | **Expansion** |
| /2/lists/:id/members | pinned&#95;tweet&#95;id |
| /2/users/:id/list&#95;memberships | owner&#95;id |

我们建议你在各自的指南中进一步了解这些新参数，或者阅读我们的[如何使用 fields 和 expansions](/zh/x-api/fundamentals/data-dictionary#how-to-use-fields-and-expansions) 指南。 

我们还整理了一份[数据格式迁移指南](/zh/x-api/migrate/data-format-migration)，可帮助你将标准版 v1.1 的字段映射到新版 v2 字段。该指南还会为你提供需要随 v2 请求一起传递的特定 expansion 参数和字段参数，以便返回特定字段。 

除了你请求某些字段的方式发生变化之外，X API v2 还为 API 返回的对象（包括 [Post](/zh/x-api/fundamentals/data-dictionary#tweet) 和 [user](/zh/x-api/fundamentals/data-dictionary#user) 对象）引入了新的 JSON 设计。

* 在 JSON 根级别，标准端点在一个 statuses 数组中返回 Post 对象，而 X API v2 返回一个 data 数组。 

* X API v2 的 JSON 不再引用被转发和被引用的“statuses”，而是引用被转发和被引用的推文。许多旧版和已弃用字段（例如 contributors 和 user.translator&#95;type）正在被移除。 

* X API v2 不再在 Post 对象中使用 favorites、在 user 对象中使用 favourites，而是统一使用 like 这一术语。 

* X 采用的约定是：没有值的 JSON 字段（例如为 null）不会写入负载。仅当 Post 和 user 属性具有非空值时才会被包含。

**请求参数**

以下标准版 v1.1 请求参数在 X API v2 中有对应项：

**列表成员查询**

|     |     |
| :--- | :--- |
| **Standard v1.1** | **X API v2** |
| list&#95;id | id  |
| slug | 无对应项 |
| owner&#95;screen&#95;name | 无对应项 |
| owner&#95;id | 无对应项 |
| count | max&#95;results |
| cursor | pagination&#95;token |
| include&#95;entities | 无对应项 |
| skip&#95;status | 无对应项 |

**列表成员资格查询**

|     |     |
| :--- | :--- |
| **Standard v1.1** | **X API v2** |
| user&#95;id | id  |
| screen&#95;name | 无对应项 |
| count | max&#95;results |
| cursor | pagination&#95;token |
