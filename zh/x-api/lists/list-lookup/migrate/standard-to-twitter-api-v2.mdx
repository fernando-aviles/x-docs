<div id="list-lookup-standard-v11-compared-to-x-api-v2">
  ### 列表查询：标准 v1.1 与 X API v2 的比较
</div>

如果你一直在使用标准 v1.1 的 [GET lists/show](https://developer.x.com/en/docs/twitter-api/v1/accounts-and-users/create-manage-lists/api-reference/get-lists-show) 和 [GET lists/ownerships](https://developer.x.com/en/docs/twitter-api/v1/accounts-and-users/create-manage-lists/api-reference/get-lists-ownerships) 端点，本指南旨在帮助你理解标准 v1.1 与 X API v2 列表查询端点之间的相似点和差异。

* **相似点**
  * 认证方式
  * 速率限制
* **差异**
  * 端点 URL
  * App 和 Project 要求
  * 每个请求可返回的数据对象数量限制
  * 响应数据格式
  * 请求参数

<div id="similarities">
  #### 相似之处
</div>

**身份验证**

这两个版本的端点都支持 [OAuth 1.0a 用户上下文](/zh/resources/fundamentals/authentication#oauth-1-0a-2) 和 [仅应用](/zh/resources/fundamentals/authentication#app-only-authentication-and-oauth-2-0-bearer-token) 身份验证。因此，如果你之前使用的是某个标准 v1.1 列表查询端点，在迁移到 X API v2 版本时，可以继续使用相同的身份验证方式。

取决于你使用的身份验证库或包，**仅应用** 身份验证可能是最容易上手的方式，并且只需通过一个简单的请求头即可完成设置。要了解如何生成仅应用访问令牌，请参阅[此仅应用指南](/zh/resources/fundamentals/authentication#using-and-generating-an-app-only-bearer-token)。

**速率限制**

|     |     |
| :--- | :--- |
| **标准 v1.1** | **X API v2** |
| /1.1/lists/show.json<br /><br />使用 OAuth 1.0a 用户上下文时，每 15 分钟 75 次请求<br /><br />使用仅应用时，每 15 分钟 75 次请求 | /2/lists/:id<br /><br />使用 OAuth 1.0a 用户上下文时，每 15 分钟 75 次请求<br /><br />使用 OAuth 2.0 带 PKCE 的授权码模式时，每 15 分钟 75 次请求 |
| /1.1/lists/ownerships.json<br /><br />使用 OAuth 1.0a 用户上下文时，每 15 分钟 15 次请求<br /><br />使用仅应用时，每 15 分钟 15 次请求 | /2/users/:id/owned&#95;lists<br /><br />使用 OAuth 1.0a 用户上下文时，每 15 分钟 15 次请求<br /><br />使用 OAuth 2.0 带 PKCE 的授权码模式时，每 15 分钟 15 次请求<br /><br />使用仅应用时，每 15 分钟 15 次请求 |

<div id="differences">
  #### 差异
</div>

**Endpoint URL**

* 标准 v1.1 endpoint：
  * GET https://api.x.com/1.1/lists/show.json
    （查询指定的列表）
  * GET https://api.x.com/1.1/lists/ownerships.json
    （查询指定用户拥有的列表）
* X API v2 endpoint：
  * GET https://api.x.com/2/lists/:id
    （查询指定的列表）

  * GET https://api.x.com/2/users/:id/owned&#95;lists
    （查询指定用户拥有的列表）

**App 和 Project 要求**

在对请求进行认证时，X API v2 endpoint 要求你使用与某个 [developer App](/zh/resources/fundamentals/developer-apps) 及其所属 [Project](/zh/resources/fundamentals/developer-apps) 关联的凭证。所有 X API v1.1 endpoint 都可以使用来自 App，或来自与某个 Project 关联的 App 的凭证。

**每个请求的数据对象数量限制**

标准 v1.1 的 /lists/ownerships endpoint 允许你每个请求最多返回 1000 个列表。新的 v2 endpoint 允许你每个请求最多返回 100 个列表。默认情况下会返回 100 个用户对象，如需更改结果数量，你需要传递查询参数 max&#95;results=，其值为 1-100 之间的数字；然后你可以将响应负载中返回的 next&#95;token 作为 pagination&#95;token 查询参数传入下一次请求中。

**响应数据格式**

标准 v1.1 与 X API v2 版本的 endpoint 之间最大差异之一，是你如何选择要在负载中返回的字段。

对于标准 endpoint，你默认会接收到大量响应字段，然后可以选择使用参数来指定哪些额外字段或字段集应在负载中返回。

X API v2 版本默认只返回列表的 id 和 name 字段。若要请求任何额外字段或对象，你需要使用 [fields](/zh/x-api/fundamentals/fields) 和 [expansions](/zh/x-api/fundamentals/expansions) 参数。你从该 endpoint 请求的任何列表字段都会返回在主列表对象中。任何扩展的帖子或用户对象及其字段都会作为响应中的 includes（包含对象）对象返回。随后，你可以通过匹配用户对象和扩展的帖子对象中存在的 ID，将任何扩展对象重新关联到列表对象。

以下是可能的列表字段和 expansions 示例：

* created&#95;at

* follower&#95;count

* member&#95;count

* owner&#95;id

* description

* private

|     |     |
| :--- | :--- |
| **Endpoint** | **Expansion** |
| /2/lists/:id | owner&#95;id |
| /2/users/:id/owned&#95;lists | owner&#95;id |

我们建议你在各自的指南中详细了解这些新参数，或者阅读我们的[如何使用 fields 和 expansions](/zh/x-api/fundamentals/data-dictionary#how-to-use-fields-and-expansions) 指南。

我们还整理了一份[数据格式迁移指南](/zh/x-api/migrate/data-format-migration)，帮助你将标准 v1.1 字段映射到新版 v2 字段。该指南还将为你提供在 v2 请求中需要传递的具体 expansion 和 field 参数，以返回特定字段。

除了你请求某些字段的方式发生变化之外，X API v2 还为 API 返回的对象引入了新的 JSON 设计，包括 [Post](/zh/x-api/fundamentals/data-dictionary#tweet)（帖子）和 [user](/zh/x-api/fundamentals/data-dictionary#user) 对象。

* 在 JSON 根级别，标准 endpoint 在 statuses 数组中返回帖子对象，而 X API v2 在 data 数组中返回帖子对象。

* X API v2 JSON 不再将其称为“转发和引用的 statuses”，而是称为转发推文（Retweeted Tweets）和引用推文（Quoted Tweets）。许多旧版和已弃用字段（例如 contributors 和 user.translator&#95;type）正在被移除。

* X API v2 不再同时使用 favorites（Post 对象中）和 favourites（user 对象中），而统一使用术语 like。

* X 采用的约定是，对于没有值的 JSON 值（例如 null），不会写入到负载中。Post 和 user 属性只有在具有非空值时才会被包含。

**请求参数**

以下标准 v1.1 请求参数在 X API v2 中有对应项：

**通过 ID 查询列表**

|     |     |
| :--- | :--- |
| **Standard v1.1** | **X API v2** |
| list&#95;id | id  |
| slug | 无对应项 |
| owner&#95;screen&#95;name | 无对应项 |
| owner&#95;id | 通过 expansions/fields 参数请求 |

**查询用户拥有的列表**

|     |     |
| :--- | :--- |
| **Standard v1.1** | **X API v2** |
| user&#95;id | id  |
| screen&#95;name | 无对应字段 |
| count | max&#95;results |
| cursor | pagination&#95;token |
