<div id="introduction">
  ## 介绍
</div>

随着 X API v2 版本的推出，我们采用了一种新的数据响应格式和请求不同对象及字段的新方式，并将其统称为 X API v2 格式。 

在“总体差异”这一部分中，你可以了解一些与标准版和企业版用户相关的变化。同时，我们还为[标准版 v1.1 原生格式](https://developer.x.com/en/docs/x-api/v1/data-dictionary/overview)、企业版的 [Native Enriched 格式](/zh/x-api/enterprise-gnip-2.0/fundamentals/data-dictionary#native-enriched-tweet-object)以及企业版的 [Activity Streams 格式](/zh/x-api/enterprise-gnip-2.0/fundamentals/data-dictionary#activity-object)整理了专门的指南，这些指南有助于完成字段映射，并说明在请求新的 v2 字段时你必须使用哪些字段和 expansions。 

* [Native 格式到 X API v2（标准版 v1.1）](/zh/x-api/migrate/data-format-migration#migrating-from-standard-v1-1s-data-format-to-v2) 
* [Native Enriched 到 X API v2（企业版）](/zh/x-api/migrate/data-format-migration#migrating-from-native-enriched-data-format-to-v2)
* [Activity Streams 到 X API v2（企业版）](/zh/x-api/migrate/data-format-migration#migrating-from-activity-streams-data-format-to-v2)

你可能也会对我们的[可视化数据格式迁移工具](/zh/x-api/migrate/data-format-migration#visual-data-format-migration-tool)感兴趣，它可以帮助你快速查看 [X API v1.1 数据格式](https://developer.x.com/en/docs/x-api/v1/data-dictionary/overview)与 [X API v2 格式](/zh/x-api/introduction)之间的差异。

<div id="general-differences">
  ### 总体差异
</div>

<div id="requesting-objects-and-fields">
  #### 请求对象和字段
</div>

与 v2 之前的端点相比，最大的变化之一是：新版本默认只返回少量字段，而标准版、高级版和企业版端点默认会返回大部分字段。新版本通过名为 [fields](/zh/x-api/fundamentals/fields) 和 [expansions](/zh/x-api/fundamentals/expansions) 的参数来明确请求超出默认值的额外数据，这意味着你可以只请求自己需要的数据，而无需处理对你来说无关紧要的字段。 

你请求的、与主数据对象相关的任何字段，都会与默认值一起返回在该主数据对象中。但是，如果你使用 expansions 参数请求任何扩展对象，次级对象将会返回在一个新的 includes 对象中。你可以通过使用在两者中都会返回的 id 字段，将 includes 对象中的扩展对象匹配回主对象。

例如，如果你在使用 v2 的 [Post lookup](/zh/x-api/posts/lookup/introduction) 端点，并且在请求中包含 `expansions=author_id` 参数，你将会在主 Post 对象中收到 `author_id` 字段，同时在 includes 对象中，每个帖子对应一个 user 对象。每个 user 对象都会包含可用于将该 user 对象匹配回 Post 对象的默认 `id` 字段。下面是一个示例，展示了它的结构：

```
{
  "data": [
    {
      "author_id": "2244994945",
      "id": "1397568983931392004",
      "text": "The Twitter Developer Platform. Ooh la la! https://t.co/iGTdPXBfOv https://t.co/Ze8z8EODdg"
    }
  ],
  "includes": {
    "users": [
      {
        "id": "2244994945",
        "name": "Twitter Dev",
        "username": "TwitterDev"
      }
    ]
  }
}
```

<div id="updated-json-design">
  #### 更新后的 JSON 设计
</div>

除了更改请求特定字段的方式之外，X API v2 还为 API 返回的对象（包括 [Post](/zh/x-api/fundamentals/data-dictionary#tweet) 和 [user](/zh/x-api/fundamentals/data-dictionary#user) 对象）引入了新的 JSON 设计。

* 在 JSON 根级别，标准端点在 **statuses** 数组中返回 Post 对象，而 X API v2 则在 **data** 数组中返回 Post 对象。 
* X API v2 的 JSON 不再引用被转发和被引用的 “statuses”，而是引用被转发和被引用的推文。许多遗留和已弃用的字段（例如 **contributors** 和 **user.translator&#95;type**）会被移除。 
* X API v2 不再同时使用 **favorites**（在 Post 对象中）和 **favourites**（在 user 对象中），而是统一使用术语 like（点赞）。 
* X 采用这样的约定：当 JSON 值为空（例如为 null）时，不会写入负载。只有当 Post 和 user 属性的值为非 null 时才会被包含在内。 
   

<div id="new-v2-fields">
  #### 新的 v2 字段
</div>

我们还在 [帖子对象](/zh/x-api/fundamentals/data-dictionary#tweet) 中引入了一组新的字段，包括：

* 一个 [conversation&#95;id](/zh/x-api/fundamentals/conversation-id) 字段
* 两个新的 [annotations](/zh/x-api/fundamentals/post-annotations) 字段，包括 context 和 entities
* 若干新的 [metrics](/zh/x-api/fundamentals/metrics) 字段
* 一个新的 reply&#95;setting 字段，用于显示谁可以回复某条帖子

<div id="migrating-from-standard-v11s-data-format-to-v2">
  ### 从标准 v1.1 的数据格式迁移到 v2
</div>

如果你还没有阅读，我们建议你先查看[数据格式迁移](/zh/x-api/migrate/data-format-migration)简介。你也可能会对我们的[可视化数据格式迁移工具](/zh/x-api/migrate/data-format-migration#visual-data-format-migration-tool)感兴趣，它可以帮助你快速查看 [X API v1.1 数据格式](https://developer.x.com/en/docs/x-api/v1/data-dictionary/overview)与 [X API v2 格式](/zh/x-api/fundamentals/data-dictionary)之间的差异。

标准 v1.1 数据格式（也称为原生格式）是通过[标准 v1.1](https://developer.x.com/en/docs/twitter-api/v1) 端点返回的主要数据格式。

如果你在使用高级产品，请参考[原生富化数据迁移指南](/zh/x-api/migrate/data-format-migration#migrating-from-native-enriched-data-format-to-v2)。企业客户可能在使用原生富化格式或 activity streams，这取决于你在 Gnip 控制台中的配置方式。

<div id="migrating-from-native-enriched-data-format-to-v2">
  ### 从 Native Enriched 数据格式迁移到 v2
</div>

Native Enriched 数据格式用于我们的[企业级](/zh/x-api/enterprise-gnip-2.0/enterprise-gnip)产品。

Native Enriched 数据格式已经更新，以提供已编辑推文的元数据。要了解有关编辑推文元数据的更多信息，请查看 [Edit Tweets 基础知识](/zh/x-api/enterprise-gnip-2.0/fundamentals/edit-tweets) 页面。

如果你使用的是标准 v1.1 端点，请参考[标准 v1.1 到 v2 指南](/zh/x-api/migrate/data-format-migration#migrating-from-standard-v1-1s-data-format-to-v2)。如果你在使用带有 Activity Streams 的企业级产品，我们也为你提供了 [Activity Streams 到 v2](/zh/x-api/migrate/data-format-migration#migrating-from-activity-streams-data-format-to-v2) 指南。

X API v2 为 [Tweet](/zh/x-api/fundamentals/data-dictionary#tweet) 和 [user](/zh/x-api/fundamentals/data-dictionary#user) 对象引入了新的 JSON 设计。

* 在 JSON 根级别，Native Enriched 格式在一个 results 数组中返回 Tweet 对象，而 X API v2 在一个 data 数组中返回 Tweet 对象。
* X API v2 统一使用术语 like，而不是在 Tweet 对象中使用 favorites、在 user 对象中使用 favourites。
* X 采用了这样的约定：JSON 中值为空（例如为 null）的字段不会写入请求载荷。只有当 Tweet 和 user 属性具有非空值时才会被包含。
* v2 中所有 id 字段都将采用字符串格式
   

除了对新的 JSON 格式所做的更改之外，我们还在 Tweet 对象中引入了一组新字段，包括：

* conversation&#95;id
* reply&#95;settings
* 媒体上的 alt&#95;text
* 两个新的 [annotations](/zh/x-api/fundamentals/post-annotations) 字段，包括 context 和 entities
* 若干新的 [metrics](/zh/x-api/fundamentals/metrics) 字段
* 若干新的 [polls](/zh/x-api/fundamentals/data-dictionary#poll) 字段
   

许多旧版和已弃用的字段将被移除：

* contributors
* 某些 entities.media 和 extended&#95;entities.media 字段
* filter&#95;level
* timestamp&#95;ms
* truncated

<div id="migrating-from-activity-streams-data-format-to-v2">
  ### 从 Activity Streams 数据格式迁移到 v2
</div>

Activity Streams 数据格式适用于我们的 [enterprise](/zh/x-api/enterprise-gnip-2.0/enterprise-gnip) 产品。

Activity Streams 数据格式已更新，以提供已编辑推文的元数据。若要了解有关编辑推文元数据的更多信息，请参阅 [Edit Tweets 基础知识](/zh/x-api/enterprise-gnip-2.0/fundamentals/edit-tweets) 页面。

如果你使用的是标准版 v1.1 端点，请参考 [standard v1.1 to v2 指南](/zh/x-api/migrate/overview)。如果你使用的是高级版端点，或企业版的 Native Enriched 格式，请参考 [Native Enriched to v2 指南](/zh/x-api/migrate/data-format-migration#migrating-from-native-enriched-data-format-to-v2)。

X API v2 为 [Post](/zh/x-api/fundamentals/data-dictionary#tweet) 和 [user](/zh/x-api/fundamentals/data-dictionary#user) 对象引入了新的 JSON 设计。

* 在 JSON 根级别上，Activity Streams 格式会在 results 数组中返回 Tweet 对象，而 X API v2 会在 data 数组中返回 Tweet 对象。 
* X API v2 的 JSON 不再引用被转推和被引用的“activities”，而是引用被转推和被引用的推文。 
* X API v2 使用 like 这一术语，而不是在 Tweet 对象中使用 favorites、在 user 对象中使用 favourites 这两种写法。 
* Twitter 正在采用这样一种约定：对于没有值的 JSON 字段（例如 null），不会写入到有效负载中。只有在属性具有非 null 值时才会包含对应的 Tweet 和 user 属性。 
* v2 中所有 id 字段都将采用字符串格式。
   

除了对新的 JSON 格式所做的更改之外，我们还向 Tweet 对象中引入了一组新字段，包括：

* conversation&#95;id
* reply&#95;settings
* 媒体上的 alt&#95;text
* 两个新的 [annotations](/zh/x-api/fundamentals/post-annotations) 字段，包括 context 和 entities
* 若干新的 [metrics](/zh/x-api/fundamentals/metrics) 字段
* 若干新的 [polls](/zh/x-api/fundamentals/data-dictionary#poll) 字段
   

许多旧版和已弃用字段将被移除或替换：

* display&#95;text&#95;range
* generator
* gnip
* link
* objectType
* provider
* twitter&#95;entities.symbols 替换为 data.entities.cashtags
* 部分 twitter&#95;extended&#95;entities.media 和 twitter&#95;entities.media 字段
* twitter&#95;filter&#95;level
* twitterTimeZone
* verb
