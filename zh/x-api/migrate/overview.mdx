<div id="what-is-the-x-api-v2">
  ## 什么是 X API v2？
</div>

X API v2 现在是主要的 X API，也是我们进行产品投入和创新的重点所在。我们与开发者合作，共同打造新一代 X API，以更好地服务多元化的开发者社区。基于开发者的反馈，我们重新构建了该 API，以更好地满足更广泛的使用场景，引入新的功能和端点，并改进整体开发者体验。

X API v2 现在是主要的 X API，也是我们进行产品投入和创新的重点所在。在过去的几年中，我们与开发者合作，重新构建了该 API，以更好地满足更广泛的需求，引入新的功能和端点，并改进整体开发者体验。我们致力于持续构建一个开放的开发者平台，并期待看到你使用 X API v2 构建的成果。

<div id="why-migrate">
  ## 为什么要迁移？
</div>

X API v2 构建在更现代且更具可持续性的基础之上，既提供了对标准版 v1.1 和企业级产品的改进替代端点，也引入了全新的功能。我们强烈建议旧版 API（v1.1 和企业级）的用户开始迁移到 v2，因为我们确实计划最终弃用这些旧版接口。使用 X API 来监听和分析公共对话、在 X 上与人互动并进行创新。

在本节中，我们将介绍这些端点及其功能。

<div id="discover-new-and-updated-response-objects">
  ### 发现新的和更新的响应对象
</div>

以下六种数据对象可通过 v2 端点获取：

| Object | Description |
|:--------|:-------------|
| [Tweet](/zh/x-api/fundamentals/data-dictionary#tweet) | Tweet 对象具有大量根级字段，例如 `id`、`text` 和 `created_at`。Tweet 对象也是多个子对象（包括 `user`、`media`、`poll` 和 `place`）的父对象。 |
| [User](/zh/x-api/fundamentals/data-dictionary#user) | user 对象包含描述被引用用户的 X 用户账号元数据。 |
| [Spaces](/zh/x-api/fundamentals/data-dictionary#space) | Space 对象由诸如 `state`、`host_id`、`is_ticketed` 以及 `lang` 等字段组成。 |
| [Lists](/zh/x-api/fundamentals/data-dictionary#list) | List 对象包含所请求列表的基本信息，包括 `description`、`member_count` 和 `owner_id`。 |
| [Media](/zh/x-api/fundamentals/data-dictionary#media) | 如果一条推文包含媒体（例如图像），则可以使用 `media.fields` 参数请求 media 对象，并获取诸如 `media_key`、`type`、`url`、`preview_image_url` 等字段。 |
| [Poll](/zh/x-api/fundamentals/data-dictionary#poll) | 包含在推文中的投票不是任何端点上的主要对象，但可以在 Tweet 对象中找到并展开。 |
| [Place](/zh/x-api/fundamentals/data-dictionary#place) | place 对象由诸如 `place_id`、`geo` 对象、`country_code` 等字段组成。此信息可用于识别推文并按位置分析推文。 |

详细了解[如何使用字段和扩展](/zh/x-api/fundamentals/data-dictionary#how-to-use-fields-and-expansions)。

<div id="flexibility-to-choose-which-objects-and-fields-you-receive">
  ### 灵活选择要接收的对象和字段
</div>

当你向 GET 端点发起请求时，会收到与该端点关联的主要 data 对象，其中包含一组默认字段。例如，Tweet 对象默认返回 `id` 和 `text` 字段。

如果你想在请求中获取更多字段，则需要使用 [fields](/zh/x-api/fundamentals/fields) 和 [expansions](/zh/x-api/fundamentals/expansions) 参数。`expansions` 参数可以让你获取相关的 data 对象，例如用户置顶的推文或媒体对象，而 fields 参数可以让你在默认字段之外，请求返回对象中的特定字段。

以下是在不同 X API v2 端点中可以请求的所有 expansions 完整列表：

| Object / Resource | Available Expansions |
|:-------------------|:----------------------|
| Tweets            | `author_id`, `edit_history_tweet_ids`, `entities.mentions.username`, `in_reply_to_user_id`, `referenced_tweets.id`, `referenced_tweets.id.author_id`, `attachments.poll_ids`, `attachments.media_keys`, `geo.place_id` |
| Users             | `pinned_tweet_id` |
| Spaces            | `invited_user_ids`, `speaker_ids`, `creator_id`, `host_ids`, `topic_ids` |

进一步了解[如何使用 fields 和 expansions](/zh/x-api/fundamentals/data-dictionary#how-to-use-fields-and-expansions)。

<div id="edit-tweets">
  ## 编辑推文
</div>

X API v2 端点提供已编辑推文的元数据。“编辑推文”功能于 2022 年 9 月 1 日首次在 X 员工中开始测试。从该日期起，符合条件的推文在 30 分钟内可编辑，最多可编辑 5 次。详细了解 [编辑推文](/zh/x-api/fundamentals/edit-posts)。
使用 X API v2，开发者可以获知：

* 某条推文在创建时是否符合可编辑条件。某些推文（例如带有投票或已排程的推文）无法编辑。
* 推文在 30 分钟内可编辑，且最多可编辑 5 次。对于可编辑的推文，你可以看到剩余编辑时间以及还可以编辑的次数。
* 你是否正在查看某条推文的已编辑版本（在大多数情况下，除非通过推文 ID 请求特定的历史版本，否则 API 会返回该推文的最新版本）。
* 该推文的完整编辑历史。
* 归因到该推文各个版本的互动数据。

</div>

一个新的推文字段可帮助识别某条推文属于哪个会话串。会话 ID 是发起该会话的那条推文的推文 ID。详细了解[会话跟踪](/zh/x-api/fundamentals/conversation-id)。

<div id="ready-to-migrate">
  ## 准备迁移
</div>

要使用 v2 端点，你需要准备以下内容：

* [一个开发者账号](https://developer.x.com/en/portal/petition/essential/basic-info)
* 在一个 [Project](resources/fundamentals/projects) 中创建的 [开发者 App](https://developer.x.com/en/apps)
* 来自该 Project 的开发者 App 的 [密钥和令牌](resources/fundamentals/authentication)

请注意，务必使用属于某个 Project 的 App 的密钥和令牌。如果你使用的是在任何 Project 之外创建的 App 的密钥和令牌，将无法向 v2 端点发出请求。

一旦你拥有开发者账号，你就可以在 [开发者控制台](https://developer.x.com/en/portal/petition/essential/basic-info) 中完成上述所有设置。

<div id="authentication">
  ### 身份验证
</div>

在新的 Twitter API 中，你将使用两种不同的身份验证模式：OAuth 1.0a User Context 和 OAuth 2.0 Bearer Token，来访问不同的端点。在向端点发出请求时，每种模式都有不同的用途：

当你代表某个 Twitter 用户发出请求时，必需使用 OAuth 1.0a User Context。
当你代表你的开发者 App 发出请求时，必需使用 OAuth 2.0 Bearer Token。
