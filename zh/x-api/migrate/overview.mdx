<div id="what-is-the-x-api-v2">
  ## 什么是 X API v2？
</div>

X API v2 现在是主要的 X API，也是我们进行产品投入和创新的重点所在。我们与开发者携手构建了新一代 X API，以更好地服务多元化的开发者社区。根据开发者反馈，我们对该 API 进行了重构，以更好地满足更广泛的需求场景，推出了新的功能和端点，并全面提升了开发者体验。

X API v2 现在是主要的 X API，也是我们进行产品投入和创新的重点所在。过去几年中，我们与开发者携手，对该 API 进行了重构，以更好地满足更广泛的需求场景，引入新的功能和端点，并改进开发者体验。我们致力于持续打造一个开放的开发者平台，并期待看到你使用 X API v2 所构建的成果。

<div id="why-migrate">
  ## 为什么要迁移？
</div>

X API v2 构建在更现代且更可持续的基础之上，不仅为标准版 v1.1 API 和企业级产品提供了经过改进的替代端点，还带来了全新的功能。我们强烈建议使用旧版 API（v1.1 和企业版）的客户开始迁移到 v2，因为我们确实计划最终弃用这些旧版本。使用 X API 来监测和分析公开对话，在 X 上与用户互动，并进行创新。

在本节中，我们将介绍相关端点和功能。

虽然 X API v2 中的大多数端点是对 pre-v2 端点的替代，但我们也引入了若干全新的端点。以下是我们在 v2 中发布的一些新端点示例：

* 使用 OpenAPI 规范来构建新库并更透明地跟踪变更

<div id="discover-new-and-updated-response-objects">
  ### 发现新的和已更新的响应对象
</div>

以下六个数据对象可在 v2 端点中使用：

| Object | Description |
|:--------|:-------------|
| [Tweet](/zh/x-api/fundamentals/data-dictionary#tweet) | Tweet 对象在根级具有一长串字段，例如 `id`、`text` 和 `created_at`。Tweet 对象也是多个子对象（包括 `user`、`media`、`poll` 和 `place`）的父对象。 |
| [User](/zh/x-api/fundamentals/data-dictionary#user) | User 对象包含描述所引用用户的 X 用户账户元数据。 |
| [Spaces](/zh/x-api/fundamentals/data-dictionary#space) | Space 对象由诸如 `state`、`host_id`、`is_ticketed`，以及 `lang` 等字段组成。 |
| [Lists](/zh/x-api/fundamentals/data-dictionary#list) | List 对象包含关于所请求列表的基本信息，包括 `description`、`member_count` 和 `owner_id`。 |
| [Media](/zh/x-api/fundamentals/data-dictionary#media) | 如果某条推文包含媒体（例如图片），则可以使用 `media.fields` 参数请求 Media 对象，其中包含 `media_key`、`type`、`url`、`preview_image_url` 等字段。 |
| [Poll](/zh/x-api/fundamentals/data-dictionary#poll) | 包含在推文中的投票不是任何端点上的主要对象，但可以在 Tweet 对象中找到并展开。 |
| [Place](/zh/x-api/fundamentals/data-dictionary#place) | Place 对象由诸如 `place_id`、`geo` 对象、`country_code` 等字段组成。此信息可用于识别推文并按地理位置分析推文。 |

详细了解[如何使用字段和扩展](/zh/x-api/fundamentals/data-dictionary#how-to-use-fields-and-expansions)。

<div id="flexibility-to-choose-which-objects-and-fields-you-receive">
  ### 灵活选择要接收的对象和字段
</div>

向 GET 端点发出请求时，你会收到与该端点相关的主要 data 对象，其中包含一组默认字段。例如，Tweet 对象默认会返回 `id` 和 `text` 字段。

如果你希望在请求中获取更多字段，需要使用 [fields](/zh/x-api/fundamentals/fields) 和 [expansions](/zh/x-api/fundamentals/expansions) 参数。`expansions` 参数可以让你检索关联的 data 对象，例如某个用户置顶的推文或媒体对象，而各类 fields 参数可以让你在返回的对象中请求默认字段之外的特定字段。

下面是你可以在不同 X API v2 端点中使用的 `expansions` 参数完整列表：

| 对象 / 资源 | 可用 Expansions |
|:-------------------|:----------------------|
| 推文            | `author_id`, `edit_history_tweet_ids`, `entities.mentions.username`, `in_reply_to_user_id`, `referenced_tweets.id`, `referenced_tweets.id.author_id`, `attachments.poll_ids`, `attachments.media_keys`, `geo.place_id` |
| 用户             | `pinned_tweet_id` |
| Spaces            | `invited_user_ids`, `speaker_ids`, `creator_id`, `host_ids`, `topic_ids` |

详细了解[如何使用 fields 和 expansions](/zh/x-api/fundamentals/data-dictionary#how-to-use-fields-and-expansions)。

<div id="edit-tweets">
  ## 编辑推文
</div>

X API v2 端点提供与已编辑推文相关的元数据。*编辑推文* 功能于 2022 年 9 月 1 日首先向 X 员工开放测试。从该日期起，符合条件的推文在发布后 30 分钟内可编辑，最多可编辑 5 次。详见[编辑推文](/zh/x-api/fundamentals/edit-posts)。
使用 X API v2，开发者可以了解：

* 某条推文在创建时是否符合可编辑条件。某些推文（例如带投票的推文或预定发送的推文）无法编辑。
* 推文在 30 分钟内可编辑，且最多可编辑 5 次。对于可编辑的推文，你可以查看剩余可编辑时间以及还可以编辑多少次。
* 你当前查看的是否是推文的已编辑版本（在大多数情况下，除非通过推文 ID 明确请求过去的某个版本，否则 API 将返回该推文的最新版本）。
* 该推文的完整编辑历史。
* 归属于推文每个版本的互动量。

<div id="track-threaded-conversations">
  ## 跟踪会话串
</div>

一个新的推文字段可帮助你确定某条推文所属的会话串。会话 ID 即发起该会话的那条推文的推文 ID。请在[会话跟踪](/zh/x-api/fundamentals/conversation-id)中了解更多信息。

<div id="ready-to-migrate">
  ## 准备好进行迁移
</div>

要使用 v2 端点，你需要具备以下内容：

* [一个开发者账号](https://developer.x.com/en/portal/petition/essential/basic-info)
* 在一个 [Project](resources/fundamentals/projects) 中创建的 [一个开发者 App](https://developer.x.com/en/apps)
* 来自该 Project 中开发者 App 的 [密钥和令牌](resources/fundamentals/authentication)

请特别注意，必须使用属于某个 Project 中 App 的密钥和令牌。如果你使用的是不在任何 Project 中的 App 的密钥和令牌，将无法向 v2 端点发起请求。

在拥有开发者账号之后，你可以在 [Developer Console](https://developer.x.com/en/portal/petition/essential/basic-info) 中完成以上所有设置。

<div id="authentication">
  ### Authentication
</div>

在新的 Twitter API 中，你将使用两种不同的认证方式，OAuth 1.0a 用户上下文和 OAuth 2.0 Bearer Token，来访问不同的端点。它们在向端点发出请求时各自有不同的用途：

当代表某个 Twitter 用户发出请求时，必需使用 OAuth 1.0a 用户上下文\
当代表你的开发者 App 发出请求时，必需使用 OAuth 2.0 Bearer Token

<div id="migrating-to-the-new-data-format">
  ## 迁移到新的数据格式
</div>

在从 v1.1 或 enterprise 迁移到 v2 时，需要注意数据的交付格式已经发生了重大变化。我们新增了字段，修改了字段的顺序，并且在某些情况下完全移除了部分元素。

为了帮助你进一步了解这些变化，我们正在编写一系列指南，帮助你将 v2 之前的数据格式中的字段映射到新的字段，并说明如何请求这些新字段。

你可以访问本迁移中心中的 [data formats migration](/zh/x-api/migrate/data-format-migration) 部分了解更多内容，或者参考我们针对特定数据格式的指南：

* [Native format to X API v2 (standard v1.1)](/zh/x-api/migrate/data-format-migration#migrating-from-standard-v1-1s-data-format-to-v2)
* [Native Enriched to X API v2 (enterprise)](/zh/x-api/migrate/data-format-migration#migrating-from-native-enriched-data-format-to-v2)
* [Activity Streams to X API v2 (enterprise)](/zh/x-api/migrate/data-format-migration#migrating-from-activity-streams-data-format-to-v2)
