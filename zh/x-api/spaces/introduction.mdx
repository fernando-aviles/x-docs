以下页面介绍了 X API 中包含的 Spaces 端点。若要进一步了解 Spaces 的基础概念，请访问 [help.x.com](https://help.x.com/en/using-twitter/spaces)。

Spaces 通过实时音频对话提供表达与互动的方式。Spaces 端点提供了一系列工具，帮助你围绕 Spaces 构建新的功能。你可以使用这些端点查询正在进行或已计划的 Spaces，或构建发现体验，让你的用户能够找到他们可能感兴趣的 Spaces。

我们鼓励你发挥创意，将 Spaces 的使用场景拓展到我们最初的设计之外。通过这些端点，你可以构建体验：根据标题中包含的关键词为听众推荐 Spaces，或向用户展示由其关注的账号主持的正在进行或即将开始的 Spaces；你也可以帮助主持人更好地了解他们的 Spaces 表现，并获得更多关于受众的洞察。

<div id="understanding-the-lifecycle-of-spaces">
  #### 了解 Spaces 的生命周期
</div>

与 X Developer Platform 中的其他资源不同，Spaces 有固定的生命周期。Spaces 最多可以在计划开始日期前 14 天进行预定，并且在结束后将变为不可用。主持人还可以在 Space 开始前的任意时间取消先前已预定的 Space。

Spaces 仅在进行中时可访问；一旦结束，就不能再通过 Spaces 端点进行检索，并会返回错误消息来指示这一情况。

当你的应用处理 Spaces 数据时，你有责任返回最新的信息，并删除平台上已不再可用的数据。[Spaces lookup endpoint](/zh/x-api/spaces/lookup/introduction) 可以帮助你确保符合用户的预期和意图。
 

<div id="roles-in-spaces">
  ### Spaces 中的角色
</div>

这些端点体现了 Spaces 在 X 应用中的工作方式。在 Spaces 中，X 用户可以根据他们在某个 Space 中的参与方式被分配不同的角色。
 

<div id="creator-or-primary-host">
  ### 创建者（或主要 Host）
</div>

主要 Host 是创建 Space 的用户，同时也是该 Space 的所有者。目前，一个 Space 只能有一个 Host，因此主要 Host 也是唯一的 Host。 在 [Spaces data dictionary](/zh/x-api/fundamentals/data-dictionary#space) 中，主要 Host 信息会出现在 `creator_id` 字段中，该字段可以展开为一个 [user object](/zh/x-api/fundamentals/data-dictionary#user)。
 

<div id="hosts">
  ### 主持人
</div>

主要主持人可以将一个或多个用户设为联合主持人。在 Spaces 数据字典中，这些主持人会显示为 host&#95;ids，可以展开为一个用户对象列表。主持人角色在 Space 的整个持续期间内都可能发生变化，这些端点返回的元数据会反映请求发出时的状态。

你的应用程序可以通过检查 creator&#95;id 的值来识别主要主持人，并通过检查 host&#95;ids 的值来识别联合主持人。
 

<div id="speaker">
  ### 发言者
</div>

发言者是拥有在 Space 中发言权限的用户。任意时间点可以有零名或多名发言者，一个 Space 中最多可以有 10 名发言者（包括主持人）。在 Space 的数据字典中，发言者会通过 `speaker_ids` 列表返回，你可以将其展开为一个用户对象列表。
 

<div id="listener">
  ### Listener
</div>

Listener（听众）可以收听 Space，在任意时间使用预定义的表情进行回应，并请求成为 speaker（前提是 Host 在 Space 设置中允许这样做）。Listener 相关信息只会作为参与者（包括 Hosts）聚合总数的一部分返回，体现在 `participant_count` 字段中。
