  ## X API 关注关系端点对比
</div>

<div id="follows-lookup">
  ### 关注关系查询
</div>

v2 关注关系查询端点将取代标准 v1.1 的 [followers/ids](https://developer.x.com/en/docs/twitter-api/v1/accounts-and-users/follow-search-get-users/api-reference/get-followers-ids)、v1.1 [followers/list](https://developer.x.com/en/docs/twitter-api/v1/accounts-and-users/follow-search-get-users/api-reference/get-followers-list)、v1.1 [friends/ids](https://developer.x.com/en/docs/twitter-api/v1/accounts-and-users/follow-search-get-users/api-reference/get-friends-ids) 和 v1.1 [friends/list](https://developer.x.com/en/docs/twitter-api/v1/accounts-and-users/follow-search-get-users/api-reference/get-friends-list) 端点。

下表对比了各种类型的关注关系查询端点：

|     |     |     |
| :--- | :--- | :--- |
| **描述** | **标准 v1.1** | **X API v2** |
| 支持的 HTTP 方法 | `GET` | `GET` |
| 主机域名 | `https://api.x.com` | `https://api.x.com` |
| 端点路径 | /1.1/friends/ids.json<br /><br />/1.1/friends/list.json<br /><br />/1.1/followers/ids.json<br /><br />/1.1/followers/list.json | /2/users/:id/following<br /><br />/2/users/:id/followers |
| [身份验证](/zh/resources/fundamentals/authentication) | OAuth 1.0a 用户上下文<br /><br />仅限 App | OAuth 1.0a 用户上下文<br /><br />OAuth 2.0 Authorization Code with PKCE<br /><br />仅限 App |
| 默认请求[速率限制](/zh/resources/fundamentals/rate-limits) | 每 15 分钟 15 次请求（每个用户）<br /><br />每 15 分钟 15 次请求（每个 App） | 每 15 分钟 15 次请求（每个用户）<br /><br />每 15 分钟 15 次请求（每个 App） |
| 每个响应的最大用户数 | `GET friends/id` 和 `GET followers/id` 每页最多返回 5000 个用户 ID。<br /><br />  <br /><br />`GET friends/list` 和 `GET followers/list` 每页最多返回 200 个用户对象。 | 每页最多 1000 个用户对象 |
| 分页 | 令牌会返回在 `next_cursor` 字段中，然后可以将其作为 `cursor` 参数的值传入，以返回下一页结果。 | 令牌会返回在 `next_token` 字段中，然后可以将其作为 `token` 参数的值传入，以返回下一页结果。<br /><br />v2 响应负载还会提供一个 `previous_token` 字段，也可以与 `pagination_token` 参数一起传入，以返回上一页结果。 |
| JSON 格式 | 标准 v1.1 格式 | [X API v2 格式](/zh/x-api/fundamentals/data-dictionary)（由 `fields` 和 `expansions` 请求参数决定，与 v1.1 格式不向后兼容）<br /><br />要了解如何从标准 v1.1 格式迁移到 X API v2 格式，请参阅我们的[数据格式迁移指南](/zh/x-api/migrate/data-format-migration)。 |
| 是否支持选择哪些[字段](/zh/x-api/fundamentals/data-dictionary)在响应负载中返回 |     | ✔   |
| 是否支持 Post [annotations](/zh/x-api/fundamentals/post-annotations) 字段 |     | ✔   |
| 是否支持请求新的[metrics](/zh/x-api/fundamentals/metrics) 字段 |     | ✔   |
| 是否支持 [conversation&#95;id](/zh/x-api/fundamentals/conversation-id) 字段 |     | ✔   |
| 是否要求使用与[项目](/zh/resources/fundamentals/developer-apps)关联的[开发者 App](/zh/resources/fundamentals/developer-apps) 的凭证 |     | ✔   |

<div id="manage-follows">
  #### 管理关注
</div>

用于管理关注关系的 v2 端点将取代标准 v1.1 的 [POST friendships/create](https://developer.x.com/en/docs/twitter-api/v1/accounts-and-users/follow-search-get-users/api-reference/post-friendships-create) 和 [POST friendships/destroy](https://developer.x.com/en/docs/twitter-api/v1/accounts-and-users/follow-search-get-users/api-reference/post-friendships-destroy) 端点。

下表比较了标准 v1.1 和 X API v2 的创建关注端点：

<div id="follow-a-user">
  #### 关注用户
</div>

| 描述 | 标准 v1.1 | X API v2 |
| :--- | :--- | :--- |
| 支持的 HTTP 方法 | POST | POST |
| 主机域名 | https://api.x.com | https://api.x.com |
| 端点路径 | /1.1/friendships/create.json | /2/users/:id/following |
| [Authentication](/zh/resources/fundamentals/authentication) | OAuth 1.0a 用户上下文 | OAuth 1.0a 用户上下文<br /><br />OAuth 2.0 授权码模式（Authorization Code）并使用 PKCE |
| 默认请求[速率限制](/zh/resources/fundamentals/rate-limits) | 每 15 分钟 50 次请求 | 每 15 分钟 50 次请求 |
| 每个用户的每日最大操作数 | 400 | 400 |
| 每个 App 的每日最大操作数 | 1000 | 1000 |
| 需要使用与某个 [Project](/zh/resources/fundamentals/developer-apps) 关联的 [developer App](/zh/resources/fundamentals/developer-apps) 的凭证 |     | ✔️  |

<div id="unfollow-a-user">
  #### 取消关注用户
</div>

下表比较了标准 v1.1 和 X API v2 的取消关注端点：

| 描述 | 标准 v1.1 | X API v2 |
| :--- | :--- | :--- |
| 支持的 HTTP 方法 | POST | DELETE |
| 主机域名 | https://api.x.com | https://api.x.com |
| 端点路径 | /1.1/friendships/destroy.json | /2/users/:source&#95;user&#95;id/following/:target&#95;user&#95;id |
| [身份验证](/zh/resources/fundamentals/authentication) | OAuth 1.0a 用户上下文 | OAuth 1.0a 用户上下文<br /><br />OAuth 2.0 授权码模式（使用 PKCE） |
| 默认请求[速率限制](/zh/resources/fundamentals/rate-limits) | 每 15 分钟 15 个请求（每个用户） | 每 15 分钟 50 个请求（每个用户） |
| 每个 App 的每日最大操作数 | 无上限 | 500 |
| 是否需要使用与某个 [Project](/zh/resources/fundamentals/developer-apps) 相关联的 [开发者 App](/zh/resources/fundamentals/developer-apps) 的凭证 |     | ✔️  |
