<div id="mutes-lookup-standard-v11-compared-to-x-api-v2">
  ### 静音查询：标准 v1.1 与 X API v2 对比
</div>

如果你一直在使用标准 v1.1 的 [GET mutes/users/ids](https://developer.x.com/en/docs/twitter-api/v1/accounts-and-users/mute-block-report-users/api-reference/get-mutes-users-ids) 和 [GET mutes/users/list](https://developer.x.com/en/docs/twitter-api/v1/accounts-and-users/mute-block-report-users/api-reference/get-mutes-users-list) 端点，本指南旨在帮助你了解标准 v1.1 与 X API v2 静音查询端点之间的相似点和差异。

* **相似点**
  * 身份验证
* **差异**
  * 端点 URL

  * 每个请求的用户数量限制

  * App 和 Project 要求

  * 响应数据格式

  * 请求参数

<div id="similarities">
  #### 相似之处
</div>

**身份验证**

标准 v1.1 和 X API v2 的静音查找端点都使用 [OAuth 1.0a 用户上下文](/zh/resources/fundamentals/authentication#oauth-1-0a-2)。因此，如果你之前使用过某个标准 v1.1 的静音查找端点，那么在迁移到 X API v2 版本时，可以继续使用相同的身份验证方法。 

<div id="differences">
  #### 差异
</div>

**Endpoint URLs**

* 标准 v1.1 endpoints：
  * GET https://api.x.com/1.1/mutes/users/ids.json
    （指定用户已静音的用户 ID 列表）
  * GET https://api.x.com/1.1/mutes/users/lists.json
    （被指定用户静音的用户列表）
* X API v2 endpoint：
  * GET https://api.x.com/2/users/:id/muting
    （被指定用户 ID 静音的用户列表）
     

**每个请求的用户数限制**

标准 v1.1 endpoints 允许你在每个请求中返回最多 5000 个用户。新的 v2 endpoints 允许你在每个请求中返回最多 1000 个用户。要返回完整的 1000 个用户，你需要在查询参数中传入 max&#95;results=1000；然后可以将响应负载中返回的 next&#95;token 传给下一次请求中的 pagination&#95;token 查询参数。

 

**App 和 Project 要求**

在使用 X API v2 endpoints 进行请求认证时，你必须使用来自与某个 [Project](/zh/resources/fundamentals/developer-apps) 关联的 [developer App](/zh/resources/fundamentals/developer-apps) 的凭证。所有 X API v1.1 endpoints 都可以使用来自独立 App 或与某个 Project 关联的 App 的凭证。

**响应数据格式**

标准 v1.1 与 X API v2 版本 endpoints 之间最大差异之一，在于你如何指定在负载中返回哪些字段。

对于标准 endpoints，你会默认收到许多响应字段，然后可以选择使用参数来指定应该在负载中返回哪些字段或字段集。

X API v2 版本默认只返回用户的 id、名称（name）和用户名（username）字段。若要请求任何其他字段或对象，你需要使用 [fields](/zh/x-api/fundamentals/fields) 和 [expansions](/zh/x-api/fundamentals/expansions) 参数。从此 endpoint 请求的任何用户字段都会返回在主用户对象中。任何扩展的 Post（帖子）对象及其字段会以 includes 对象的形式返回在响应中。然后你可以通过匹配用户对象和扩展 Post 对象中出现的 ID，将这些扩展对象重新关联回用户对象。

我们建议你在各自的指南中进一步了解这些新参数，或者阅读我们的 [如何使用 fields 和 expansions](/zh/x-api/fundamentals/data-dictionary#how-to-use-fields-and-expansions) 指南。

我们还整理了一份 [数据格式迁移指南](/zh/x-api/migrate/data-format-migration#migrating-from-standard-v1-1s-data-format-to-v2)，可帮助你将标准 v1.1 字段映射到较新的 v2 字段。该指南还会向你说明，在 v2 请求中需要传入哪些特定的 expansions 和 fields 参数，才能返回特定字段。

 

除了更改你请求某些字段的方式之外，X API v2 还为 APIs 返回的对象引入了新的 JSON 结构，包括 [Post](/zh/x-api/fundamentals/data-dictionary#tweet) 和 [user](/zh/x-api/fundamentals/data-dictionary#user) 对象。

* 在 JSON 根级别，标准 endpoints 在 statuses 数组中返回 Post 对象，而 X API v2 则在 data 数组中返回 Post 对象。
* X API v2 JSON 不再使用“statuses”来表示被转发和被引用的内容，而是使用 Retweeted 和 Quoted Tweets。许多旧有和已弃用字段（例如 contributors 和 user.translator&#95;type）正在被移除。
* X API v2 不再在 Post 对象中使用 favorites、在用户对象中使用 favourites，而是统一使用术语 like。
* X 采用了这样一种约定：没有值的 JSON 值（例如 null）不会写入负载。只有在具有非 null 值时，Post 和 user 属性才会被包含在负载中。

   

我们还为 [Post 对象](/zh/x-api/fundamentals/data-dictionary#tweet) 引入了一组新字段，包括以下内容：

* 一个 [conversation&#95;id](/zh/x-api/fundamentals/conversation-id) 字段
* 两个新的 [annotations](/zh/x-api/fundamentals/post-annotations) 字段，包括 context 和 entities
* 若干新的 [metrics](/zh/x-api/fundamentals/metrics) 字段
* 一个新的 reply&#95;setting 字段，用于指示谁可以回复某条 Post

**请求参数**

以下标准 v1.1 请求参数在 X API v2 中都有对应项：

| **标准** | **X API v2** |
| :--- | :--- |
| stringify&#95;ids | 无等效项 |
| cursor | pagination&#95;token |
| skip&#95;status | 无等效项 |

在 X API v2 中，还有一组标准的 v1.1 Mutes 查找请求参数**不**受支持：

| 标准 | 说明 |
| :--- | :--- |
| include&#95;entities | 此参数用于从帖子负载中移除 entities 节点。它已被追加式的字段和扩展（expansions）功能所取代。 |

<div id="get-muted-users-v2">
  ### 获取已静音的用户（v2）
</div>

<CodeGroup dropdown>
  ```bash cURL
  curl "https://api.x.com/2/users/123456789/muting?user.fields=username,verified&max_results=100" \
    -H "Authorization: OAuth ..."
  ```

  ```python Python
  # 需要使用 OAuth 1.0a 用户上下文 进行认证
  import requests
  from requests_oauthlib import OAuth1

  auth = OAuth1(
      "API_KEY", "API_SECRET",
      "ACCESS_TOKEN", "ACCESS_TOKEN_SECRET"
  )

  url = "https://api.x.com/2/users/123456789/muting"
  params = {"user.fields": "username,verified", "max_results": 100}

  response = requests.get(url, auth=auth, params=params)
  print(response.json())
  ```

  ```python Python SDK
  from xdk import Client
  from xdk.oauth1_auth import OAuth1

  oauth1 = OAuth1(
      api_key="YOUR_API_KEY",
      api_secret="YOUR_API_SECRET",
      access_token="YOUR_ACCESS_TOKEN",
      access_token_secret="YOUR_ACCESS_TOKEN_SECRET"
  )

  client = Client(auth=oauth1)

  # 使用分页获取已静音的用户
  for page in client.users.get_muting(
      "123456789",
      user_fields=["username", "verified"],
      max_results=100
  ):
      for user in page.data:
          print(f"{user.username} - Verified: {user.verified}")
  ```

  ```javascript JavaScript SDK
  import { Client, OAuth1 } from "@xdevplatform/xdk";

  const oauth1 = new OAuth1({
    apiKey: "YOUR_API_KEY",
    apiSecret: "YOUR_API_SECRET",
    accessToken: "YOUR_ACCESS_TOKEN",
    accessTokenSecret: "YOUR_ACCESS_TOKEN_SECRET",
  });

  const client = new Client({ oauth1 });

  // 使用分页获取已静音的用户
  const paginator = client.users.getMuting("123456789", {
    userFields: ["username", "verified"],
    maxResults: 100,
  });

  for await (const page of paginator) {
    page.data?.forEach((user) => {
      console.log(`${user.username} - Verified: ${user.verified}`);
    });
  }
  ```
