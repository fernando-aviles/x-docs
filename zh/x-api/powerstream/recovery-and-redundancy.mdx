在处理流式数据时，尽可能延长连接时间并接收所有匹配的数据是一个基本目标。这意味着，充分利用冗余连接、自动检测连接中断、快速重新连接，以及制定恢复丢失数据的方案都非常重要。

在本集成指南中，我们将讨论不同的恢复与冗余功能：冗余连接、回填（backfill）以及恢复。
 

<div id="redundant-connections">
  ## 冗余连接
</div>

冗余连接是指允许你同时建立多个到同一流的连接。这样可以通过让你用两个独立的消费者连接到同一个流，并通过这两个连接接收相同的 data，从而提供冗余能力。因此，在各种情况下（例如某个流断开连接，或者你的应用主服务器发生故障），你的应用都可以进行热切换。

要使用冗余流，只需连接到与你的主连接相同的 URL。该流的 data 会通过这两个连接同时发送。

<div id="backfill">
  ## 回填
</div>

在你检测到连接中断之后，你的系统应该足够智能，能够重新连接到流。如果可能，你的系统还应该记录连接中断持续了多长时间，以便你可以使用合适的恢复功能来回填数据。 

如果你确认断线持续时间不超过五分钟，你可以使用回填参数 `backfillMinutes`。如果你在 `GET /powerstream` 请求中传入此参数，你将会收到过去一到五分钟内符合你规则的帖子。我们通常会先投递这些较早的帖子，然后再投递任何新匹配到的帖子，并且不会对帖子进行去重。这意味着，如果你断线了 90 秒，但请求了 2 分钟的回填数据，你将会收到 30 秒的重复帖子，你的系统应该能够容忍这些重复内容。下面是一个带有回填参数的请求示例：

`curl 'https://api.x.com/2/powerstream?backfillMinutes=5' -H "Authorization: Bearer $ACCESS_TOKEN"`

如果你确认断线持续时间超过五分钟，你可以使用[最近搜索端点](/zh/x-api/posts/search/introduction)或恢复功能来请求遗漏的数据。 

<div id="recovery">
  ## Recovery
</div>

如果你无法在 5 分钟回补窗口内重新连接，可以使用 Recovery 功能在过去 24 小时内补回错过的数据。

流式恢复功能允许你将回补窗口扩展至 24 小时。Recovery 使你能够“重放”错过数据的时间段。当你在连接请求中使用 `startTime` 和 `endTime` 请求参数时，将启动恢复流。连接成功后，Recovery 会重新推送指定时间段的数据，然后断开连接。  

|     |     |     |
| :--- | :--- | :--- |
| **名称** | **类型** | **说明** |
| `startTime` | date (ISO 8601) | YYYY-MM-DDTHH:mm:ssZ (ISO 8601/RFC 3339)。<br /><br />UTC 中表示恢复起始时间的日期。 |
| `endTime` | date (ISO 8601) | YYYY-MM-DDTHH:mm:ssZ (ISO 8601/RFC 3339)。<br /><br />UTC 中表示恢复结束时间的日期。 |

示例请求 URL：`https://api.x.com/2/powerstream?startTime=2022-07-12T15:10:00Z&endTime=2022-07-12T15:20:00Z`
