在消费流式数据时，尽可能延长连接时间并接收所有匹配的数据是一个基本目标。这意味着，你需要充分利用冗余连接、自动检测连接中断、快速重新连接，并制定恢复丢失数据的方案。

在本集成指南中，我们将讨论多种恢复与冗余特性：冗余连接、回填（backfill）和恢复。
 

<div id="redundant-connections">
  ## 冗余连接
</div>

冗余连接指的是允许你同时建立多个指向同一流的连接。通过让你使用两个独立的消费者连接到同一个流，并在这两个连接上接收相同的 data，这种方式提供了冗余能力。因此，在各种情况下（例如某个流被断开，或你的应用的主服务器发生故障），你的应用都可以实现热故障转移。

要使用冗余流，只需连接到与你的主连接相同的 URL。你的流的 data 将通过这两个连接发送。

<div id="backfill">
  ## 回填
</div>

在检测到断开连接之后，你的系统应该能够自动重新连接到流。如果可能，你的系统还应记录断开连接持续的时间，以便你可以使用合适的恢复功能来回填这些数据。 

如果你确认断开连接持续了五分钟或更短时间，你可以使用回填参数 `backfillMinutes`。如果你在 `GET /powerstream` 请求中携带此参数，你会收到过去一到五分钟内符合你规则的帖子。通常我们会先发送这些较旧的帖子，然后再发送任何新匹配到的帖子，并且不会对帖子进行去重。这意味着，如果你断开连接持续了 90 秒，但请求了两分钟的回填数据，你会收到 30 秒的重复帖子，你的系统应该能够容忍这些重复。下面是一个带有回填参数的请求示例：

`curl 'https://api.x.com/2/powerstream?backfillMinutes=5' -H "Authorization: Bearer $ACCESS_TOKEN"`

如果你确认断开连接时间超过五分钟，你可以使用[最近搜索端点](/zh/x-api/posts/search/introduction)或恢复功能来请求遗漏的数据。 

<div id="recovery">
  ## 恢复
</div>

如果你无法在 5 分钟回补窗口内重新连接，可以使用恢复功能在过去 24 小时内补回错过的数据。

流式恢复功能允许你将回补窗口扩展到 24 小时。通过恢复，你可以“重放”错过数据的这段时间。当你在连接请求中使用 `startTime` 和 `endTime` 请求参数时，将启动一个恢复流。连接建立后，恢复功能会重新推送指定时间段的数据，然后断开连接。  

|     |     |     |
| :--- | :--- | :--- |
| **名称** | **类型** | **描述** |
| `startTime` | 日期（ISO 8601） | YYYY-MM-DDTHH:mm:ssZ（ISO 8601/RFC 3339）。<br /><br />以 UTC 表示的起始时间，用于指定从何时开始恢复。 |
| `endTime` | 日期（ISO 8601） | YYYY-MM-DDTHH:mm:ssZ（ISO 8601/RFC 3339）。<br /><br />以 UTC 表示的结束时间，用于指定恢复到何时为止。 |

示例请求 URL：`https://api.x.com/2/powerstream?startTime=2022-07-12T15:10:00Z&endTime=2022-07-12T15:20:00Z`
