X API 会返回结构化 JSON 对象来表示帖子、用户、媒体等内容。本参考文档列出了每种对象类型可用的所有字段。

<div id="post-tweet">
  ## 帖子（推文）
</div>

帖子是 X 上的核心内容单元。每个 Post 对象都包含文本、元数据，以及对作者、媒体、投票等相关对象的引用。

**默认字段：** `id`, `text`, `edit_history_tweet_ids`

使用 `tweet.fields` 来请求附加字段，并使用 `expansions` 来包含相关对象。

<div id="all-post-fields">
  ### 所有帖子字段
</div>

| 字段名                                              | 类型           | 描述                                                                                             | 使用场景                           |
| :----------------------------------------------- | :----------- | :--------------------------------------------------------------------------------------------- | :----------------------------- |
| **id（默认）**                                       | 字符串          | 所请求推文的唯一标识符。                                                                                   | 使用此字段以编程方式检索特定推文。              |
| **text（默认）**                                     | 字符串          | 推文的实际 UTF-8 文本内容。有关有效字符的详细信息，请参阅 [twitter-text](https://github.com/twitter/twitter-text/)。     | 用于关键词抽取以及情感分析/分类。              |
| **edit&#95;history&#95;tweet&#95;ids (default)** | 对象           | 指示该推文所有版本的唯一标识符。对于没有编辑记录的推文，只会有一个 ID；对于有编辑历史的推文，会有多个 ID。                                       | 使用此信息查找某条推文的编辑历史。              |
| **article**                                      | 对象           | 包含此推文中存在的 Article 的元数据。                                                                        | 使用此字段获取 Article 的文本和实体信息。      |
| **附件**                                           | 对象           | 指定此推文中（如果有）存在的附件类型。                                                                            | 用于理解通过所请求扩展返回的对象。              |
| **author&#95;id**                                | 字符串          | 发布此推文的 User 的唯一标识符。                                                                            | 用于填充 User 对象，并在同行评审数据集中共享相关数据。 |
| **card&#95;uri**                                 | 字符串          | 此推文中存在的 Card 的 URI。                                                                            |                                |
| **community&#95;id**                             | 字符串          | 此帖子所属 Community 的唯一标识符。                                                                        |                                |
| **context&#95;annotations**                      | 数组           | 包含该推文的上下文注释。                                                                                   | 用于实体识别/抽取和主题分析。                |
| **conversation&#95;id**                          | 字符串          | 会话中原始推文的推文 ID（包括直接回复和回复的回复）。                                                                   | 使用此字段从某条推文重建整个会话。              |
| **created&#95;at**                               | 日期（ISO 8601） | 推文的创建时间。                                                                                       | 用于时间序列分析以及了解推文的创建时间。           |
| **display&#95;text&#95;range**                   | 数组           | 一个数组，包含要显示的文本部分的起始和结束位置索引。                                                                     | 用于了解在较长帖子中默认显示的是哪一部分文本。        |
| **edit&#95;controls**                            | 对象           | 指示该推文还能编辑多长时间以及剩余可编辑次数。                                                                        | 使用此字段确定一条推文是否仍可编辑。             |
| **entities**                                     | 对象           | 从推文文本中解析出的实体。请参阅 Tweet 对象中的 entities 字段。                                                       | 提供关于话题标签、URL、提及等的附加信息。         |
| **geo**                                          | 对象           | 指示带地理标签的推文的位置或地点。                                                                              | 使用此字段来确定带地理标签推文的位置。            |
| **in&#95;reply&#95;to&#95;user&#95;id**          | 字符串          | 如果所表示的推文是一条回复，此字段将包含原始推文作者的 ID。                                                                | 用于判断该推文是否是在回复另一条推文。            |
| **lang**                                         | 字符串          | 推文的语言（如果已被 X 检测到）。                                                                             | 根据使用语言对推文进行分类。                 |
| **non&#95;public&#95;metrics**                   | 对象           | 请求时刻此推文的非公开互动指标。需要用户上下文认证。                                                                     | 用于确定该推文产生的总展示量。                |
| **note&#95;tweet**                               | 对象           | 对于长文本帖子（超过 280 个字符），包含该帖子的完整文本。                                                                | 获取帖子的完整文本。                     |
| **organic&#95;metrics**                          | 对象           | 请求时刻此推文在自然（非推广）环境下跟踪到的互动指标。需要用户上下文认证。                                                          | 衡量该推文的自然互动情况。                  |
| **possibly&#95;sensitive**                       | 布尔值          | 指示内容是否可能被识别为敏感内容。                                                                              | 用于研究某些类型内容的传播情况。               |
| **promoted&#95;metrics**                         | 对象           | 请求时刻此推文在推广场景下跟踪到的互动指标。需要用户上下文认证。                                                               | 衡量该推文在被推广时的互动情况。               |
| **public&#95;metrics**                           | 对象           | 请求时刻此推文的公开互动指标。                                                                                | 衡量推文的整体互动情况。                   |
| **referenced&#95;tweets**                        | 数组           | 此推文所引用的推文列表，例如转推、引用推文或回复。                                                                      | 用于理解转推等相关的会话属性。                |
| **reply&#95;settings**                           | 字符串          | 显示谁可以回复指定推文。可选值为 &quot;everyone&quot;、&quot;mentioned&#95;users&quot; 和 &quot;followers&quot;。 | 确定该推文的会话回复设置。                  |
| **withheld**                                     | 对象           | 包含[受限内容](https://help.x.com/en/rules-and-policies/tweet-withheld-by-country)的屏蔽相关详情。           |                                |
| **scopes**                                       | 对象           | 包含该推文可见范围（scope）的详细信息。                                                                         | 指示谁可以查看该帖子。仅对推广帖子返回。           |
| **media&#95;metadata**                           | 数组           | 包含推文中媒体附件的元数据。                                                                                 | 获取更多元数据，例如推文媒体附件的 `alt_text`。  |

**检索 Tweet 对象**

**请求示例**

在以下请求中，我们通过 [Tweets lookup](/zh/resources/fundamentals/rate-limits) 端点为该推文请求字段。请务必将 `$BEARER_TOKEN` 替换为你自己生成的 [Bearer Token](/zh/resources/fundamentals/authentication)。

```bash
curl --request GET 'https://api.x.com/2/tweets?ids=1212092628029698048&tweet.fields=attachments,author_id,context_annotations,created_at,entities,geo,id,in_reply_to_user_id,lang,possibly_sensitive,public_metrics,referenced_tweets,text,withheld&expansions=referenced_tweets.id' --header 'Authorization: Bearer $BEARER_TOKEN'
```

<div id="user">
  ### User
</div>

`user` 对象包含描述所引用用户的 Twitter 用户账户元数据。`user` 对象是 [users lookup](/zh/x-api/users/lookup/introduction) 端点返回的主要对象。在该端点请求额外的用户字段时，只需使用查询参数 `user.fields`。

`user` 对象也可以作为子对象出现在 Tweet 对象中，并在其中进行扩展。该对象可通过 `?expansions=author_id` 或 `?expansions=in_reply_to_user_id` 进行扩展，以获取仅包含默认字段的精简版对象。当你需要请求额外字段以补全该对象时，请将这些扩展与字段参数 `user.fields` 一起使用。

  ### Space

<div id="direct-message-events">
  ### 私信事件
</div>

私信（Direct Message，DM）会话由一系列事件构成。X API v2 目前支持三种事件类型：MessageCreate、ParticipantsJoin 和 ParticipantsLeave。

DM 事件对象通过 [Direct Message lookup](/zh/x-api/direct-messages/lookup/introduction) 端点返回，当通过 [Manage Direct Messages](/zh/x-api/direct-messages/lookup/introduction) 端点成功创建私信时，会生成一个 MessageCreate 事件。

在请求 DM 事件时，默认会包含三个事件对象属性（或字段）：id、event&#95;type 和 text。若要获取更多事件字段，请使用 [fields](/zh/x-api/fundamentals/fields) 参数 dm&#95;event.fields 来请求其他字段。其他可用的事件字段包括：dm&#95;conversation&#95;id、created&#95;at、sender&#95;id、attachments、participant&#95;ids 和 referenced&#95;tweets。

其中有几个字段会提供与该私信事件相关的其他 X 对象的 ID：

* sender&#95;id - 发送消息的账号，或在群组会话中邀请参与者的账号的 ID
* partricipants&#95;ids - 账号 ID 数组。对于 ParticipantsJoin 和 ParticipantsLeave 事件，此数组将只包含一个创建该事件的账号 ID
* attachments - 提供由发送方上传到 X 的内容的媒体 ID
* referenced&#95;tweets - 如果在 text 字段中发现推文 URL，则会在响应中包含该推文的 ID

可以使用 sender&#95;id、participant&#95;ids、referenced&#95;tweets.id 和 attachments.media&#95;keys 的 [expansions](/zh/x-api/fundamentals/expansions) 来展开这些 X 对象 ID 所引用的对象。

| event&#95;type (default) | string | 描述事件的类型。目前支持三种类型： <br /><br />* MessageCreate<br />    <br />* ParticipantsJoin<br />    <br />* ParticipantsLeave<br />    <br /><br />&quot;event&#95;type&quot;: &quot;MessageCreate&quot; | 在检索会话历史时，用于了解消息的创建时间；对于群组会话，用于了解参与者的加入和离开时间。所有 GET 方法都支持使用 `event_type=` 查询参数来筛选特定事件类型。 |

<div id="community">
  ### Community
</div>

Community 是 X 用户专门用于互相联系、分享内容，并更贴近他们最关心讨论的空间。

发布在 Community 中的帖子可以被任何 X 用户看到，但只有该 Community 内的成员才能参与互动和讨论。

Community 对象包含关于某个 Community 的相关元数据。

| Field value      | Type            | Description                                        |    |
| :--------------- | :-------------- | :------------------------------------------------- | :- |
| created&#95;at   | date (ISO 8601) | Community 的创建时间。                                   |    |
| id               | string          | Community 的唯一标识符。                                  |    |
| name             | string          | Community 的名称。                                     |    |
| description      | string          | Community 的描述文本（如果已提供）。                            |    |
| access           | string          | Community 的访问级别。<br /><br /> 可以是以下之一：              |    |
|                  |                 | - `Public`                                         |    |
|                  |                 | - `Closed`                                         |    |
| join&#95;policy  | string          | Community 的加入策略。<br /><br /> 可以是以下之一：              |    |
|                  |                 | - `Open`                                           |    |
|                  |                 | - `RestrictedJoinRequestsDisabled`                 |    |
|                  |                 | - `RestrictedJoinRequestsRequireAdminApproval`     |    |
|                  |                 | - `RestrictedJoinRequestsRequireModeratorApproval` |    |

<div id="how-to-use-fields-and-expansions">
  ## 如何使用字段和扩展
</div>

默认情况下，当你在发起不包含 [fields](/zh/x-api/fundamentals/fields) 或 [expansions](/zh/x-api/fundamentals/expansions) 参数的请求时，X API v2 的 data 对象只包含少量默认字段。本指南将演示如何在请求中使用 `fields` 和 `expansions` 查询参数，以便在响应中获取更多对象和字段。

在本指南中，我们将基于下面这张推文截图来请求若干字段。
 

![此图片包含一条由 @X 发布的推文截图。你可以看到推文文本、用户名、发布时间和时间、来源以及公开指标。截图中还包含一个视频。](https://cdn.cms-twdigitalassets.com/content/dam/developer-twitter/ScreenShotDataDictionaryGuide.png.twimg.1920.png)

如你在截图中所见，与这条推文相关的可见信息有多项内容，包括推文作者、推文指标、创建时间戳、视频以及视频观看次数。此外，还有若干数据在截图中不可见，但仍然可以通过请求获取。 

当向 API 发起请求时，默认响应非常简单，仅包含默认推文字段（id 和 text）。你也只会接收到所使用端点返回的主要对象，而不会接收到与该主要对象相关联的任何数据对象。

这种简洁性结合 fields 和 expansions 参数，使你可以根据自己的使用场景，只请求所需的字段。 
 

<div id="requesting-additional-fields-and-objects">
  #### 请求额外的字段和对象
</div>

首先,我们将使用推文 ID 和 [GET /tweets 端点](/zh/x-api/posts/lookup/introduction)来请求一个 [Tweet 对象](/zh/x-api/fundamentals/data-dictionary#tweet)。

请求：

```bash
curl --request GET --url 'https://api.x.com/2/tweets?ids=1260294888811347969' \
  --header 'Authorization: Bearer $BEARER_TOKEN'
```

响应：

```

        }

```

以下分步指南将展示如何检索截图中显示的附加数据。

1. 使用我们的[对象模型](/zh/x-api/fundamentals/data-dictionary#tweet)，或查看各个端点 API 参考页面中的字段列表，来确定你想要请求的其他字段。

   在本例中，我们将请求以下额外字段：
   attachments、author&#95;id、created&#95;at、public&#95;metrics。

2. 使用上述字段，以逗号分隔的列表形式作为值来构建 `tweet.fields` 查询参数：
   `?tweet.fields=attachments,author_id,created_at,public_metrics`

请求：

`curl --request GET --url 'https://api.x.com/2/tweets?ids=1260294888811347969&tweet.fields=attachments,author_id,created_at,public_metrics' \   --header 'Authorization: Bearer $BEARER_TOKEN'`
