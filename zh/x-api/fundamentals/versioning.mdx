X API 在接口路径中使用版本号，在保证稳定性的同时支持持续迭代。了解我们的版本管理策略有助于你规划集成并保持最新。

***

<div id="current-versions">
  ## 当前版本
</div>

| Version | Status | Description |
|:--------|:-------|:------------|
| **v2** | 当前版本 | 现代化端点、灵活定价、涵盖所有新功能 |
| **v1.1** | 旧版 | 支持受限、仅进行少量更新 |
| **Enterprise** | 可用 | 大规模访问权限，配备专属支持 |

<Tip>
  对于所有新项目，请使用 **X API v2**。所有新功能都会优先在这里发布。
</Tip>

***

<div id="breaking-vs-non-breaking-changes">
  ## 破坏性变更与非破坏性变更
</div>

<div id="breaking-changes-require-code-updates">
  ### 破坏性更改（需要更新代码）
</div>

这些更改仅会在大版本升级时发生：

* 移除一个 endpoint
* 移除一个响应字段
* 移除一个查询参数
* 添加一个新的必需参数
* 更改字段的数据类型
* 重命名字段或资源
* 更改响应状态码或错误类型
* 修改授权范围

<div id="non-breaking-changes-additive">
  ### 向后兼容的更改（增量）
</div>

这些更改可以在任何时间进行，而无需变更版本号：

* 添加新的 endpoint
* 添加新的可选参数
* 添加新的响应字段
* 添加新的 OAuth 作用域
* 修改错误消息文本
* 出于隐私/安全原因将字段设为 null

<div id="release-schedule">
  ## 发布计划
</div>

| 类型 | 频率 | 通知 |
|:-----|:----------|:-------|
| **主要版本** | 每年至多一次 | 提供迁移指南 |
| **向后兼容变更** | 持续进行 | 更新变更日志 |
| **安全补丁** | 视需要而定 | 可应用于当前版本 |

***

<div id="deprecation-policy">
  ## 弃用策略
</div>

当我们发布新的主版本时：

1. **弃用**：将先前的版本标记为已弃用
2. **支持期**：已弃用版本在指定的时间段内继续可用
3. **退役**：在支持期结束后移除已弃用版本

<div id="definitions">
  ### 术语定义
</div>

| 状态 | 含义 |
|:-------|:--------|
| **Active** | 完全受支持，并持续提供新功能和修复 |
| **Deprecated** | 不再新增功能；仅修复严重缺陷；不建议继续使用 |
| **Retired** | 已无法访问 |
