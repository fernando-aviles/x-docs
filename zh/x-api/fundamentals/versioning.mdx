X API 在端点 URL 路径中使用版本号，在保证稳定性的同时支持演进。了解我们的版本管理策略有助于你规划集成并保持最新状态。

***

<div id="current-versions">
  ## 当前版本
</div>

| Version | Status | Description |
|:--------|:-------|:------------|
| **v2** | 当前版本 | 现代化的端点、灵活的定价、所有新功能 |
| **v1.1** | 旧版 | 支持有限，更新极少 |
| **Enterprise** | 可用 | 大规模访问，配备专属支持 |

<Tip>
  对于所有新项目，请使用 **X API v2**。所有新功能都会在这里发布。
</Tip>

***

<div id="version-in-urls">
  ## URL 中的版本号
</div>

版本号出现在端点路径中：

```
https://api.x.com/2/tweets
                   ^
                   version
```

<div id="breaking-vs-non-breaking-changes">
  ## 破坏性变更与非破坏性变更
</div>

<div id="breaking-changes-require-code-updates">
  ### 不兼容变更（需要更新代码）
</div>

这些变更只会在主版本号升级时发生：

* 移除某个端点
* 移除某个响应字段
* 移除某个查询参数
* 新增必需参数
* 更改字段的数据类型
* 重命名字段或资源
* 更改响应状态码或错误类型
* 修改授权范围

<div id="non-breaking-changes-additive">
  ### 非破坏性更改（增量式）
</div>

这些更改可以在不修改版本的情况下随时进行：

* 新增 endpoint
* 新增可选参数
* 新增响应字段
* 新增 OAuth 权限范围
* 修改错误消息文本
* 出于隐私/安全原因将字段置为 null

<div id="release-schedule">
  ## 发布节奏
</div>

| 类型 | 频率 | 通知 |
|:-----|:----------|:-------|
| **主版本** | 每年不超过一次 | 提供迁移指南 |
| **非破坏性更改** | 持续进行 | 在变更日志中记录 |
| **安全补丁** | 按需发布 | 可能会应用到当前版本 |

***

<div id="deprecation-policy">
  ## 弃用策略
</div>

当我们发布新的主版本时：

1. **弃用**：上一版本会被标记为弃用
2. **支持期**：被弃用的版本在预定义的一段时间内继续可用
3. **退役**：被弃用的版本会被移除

<div id="definitions">
  ### 定义
</div>

| 状态 | 含义 |
|:-------|:--------|
| **Active** | 完全受支持，并持续提供新功能和修复 |
| **Deprecated** | 不再添加新功能；仅修复重大缺陷；不建议使用 |
| **Retired** | 不再可用 |
