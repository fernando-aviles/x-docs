X API 在端点路径中使用版本号，在保证稳定性的同时支持功能演进。了解我们的版本管理策略有助于你规划集成并保持最新状态。

***

<div id="current-versions">
  ## 当前版本
</div>

| 版本 | 状态 | 说明 |
|:--------|:-------|:------------|
| **v2** | 当前 | 现代化的端点、灵活的定价、所有新功能 |
| **v1.1** | 旧版 | 支持受限，仅进行少量更新 |
| **Enterprise** | 可用 | 大规模访问权限，并提供专属支持 |

<Tip>
  对于所有新项目，请使用 **X API v2**。所有新功能都会在此版本中发布。
</Tip>

***


<div id="breaking-vs-non-breaking-changes">
  ## 不兼容变更与兼容变更
</div>

<div id="breaking-changes-require-code-updates">
  ### 不兼容变更（需要更新代码）
</div>

这些变更只会出现在主版本升级中：

* 删除 endpoint
* 删除响应字段
* 删除查询参数
* 新增必填参数
* 更改字段的数据类型
* 重命名字段或资源
* 更改响应状态码或错误类型
* 修改授权 scope

<div id="non-breaking-changes-additive">
  ### 非破坏性变更（增量）
</div>

这些变更可以在不更改版本的情况下随时进行：

* 添加新的端点（endpoint）
* 添加新的可选参数
* 添加新的响应字段
* 添加新的 OAuth 权限范围（scope）
* 修改错误信息文本
* 出于隐私/安全原因将字段置为 null

<div id="release-schedule">
  ## 版本发布计划
</div>

| 类型 | 频率 | 通知 |
|:-----|:----------|:-------|
| **主版本** | 最多每年一次 | 提供迁移指南 |
| **非破坏性变更** | 持续进行 | 在变更日志中更新 |
| **安全补丁** | 按需发布 | 可能会应用于当前版本 |

***

<div id="deprecation-policy">
  ## 弃用策略
</div>

当我们发布新的主版本时：

1. **弃用**：先前版本被标记为弃用
2. **支持期**：被弃用的版本在规定的时间段内继续可用
3. **退役**：被弃用的版本被移除

<div id="definitions">
  ### 术语定义
</div>

| 状态 | 含义 |
|:-------|:--------|
| **Active** | 完全受支持，并会持续提供新功能和修复 |
| **Deprecated** | 不再增加新功能；仅修复严重问题；不建议使用 |
| **Retired** | 已无法访问 |
