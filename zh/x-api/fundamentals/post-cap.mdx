X API v2 采用**按使用量付费**的定价模式。系统会在应用级别跟踪实际的 API 使用量，并据此计费。

***

<div id="how-billing-works">
  ## 计费机制说明
</div>

| 概念 | 描述 |
|:--------|:------------|
| **基于额度** | 预先购买额度，调用 API 时按使用量扣减 |
| **按请求计费** | 不同的端点收费不同 |
| **实时跟踪** | 在 Developer Console 中监控用量 |
| **无上限** | 按需使用——没有每月使用上限 |

<div id="deduplication">
  ## 去重
</div>

<Note>
  **每日去重**：如果同一条帖子在一天内通过多个查询返回，在计费时只按 1 次计费。
</Note>

这意味着：

* 在同一天多次获取同一条帖子 = 收费 1 次
* 第二天再次获取同一条帖子 = 额外收费 1 次
* 同一请求中的不同帖子 = 各自单独计费

| 指标 | 说明 |
|:-------|:------------|

| **按端点** | 按端点类型划分的用量明细 |
| **按 App** | 每个开发者 App 的用量 |
| **成本跟踪** | 实时成本计算 |
| **额度余额** | 剩余预付额度 |

<div id="pricing-details">
  ## 价格详情
</div>

要查看当前各端点和操作的最新定价，请访问 [Developer Console](https://console.x.com)。

价格可能因以下因素而有所不同：

* 端点类型（搜索 search、查找 lookup、流式 stream）
* 操作（读取 read、写入 write）
* 数据范围（近期 recent、完整归档 full-archive）

<div id="faqs">
  ## 常见问题
</div>

<Accordion title="如果我的额度用完会怎样？">
  在你购买更多额度之前，API 请求将会失败。请设置余额提醒以避免服务中断。
</Accordion>

<Accordion title="有没有每月最低消费？">
  没有。你只需为实际使用量付费。即使某些月份完全没有使用，也不会产生任何费用。
</Accordion>

<Accordion title="流式数据如何计费？">
  通过过滤流传递的每条唯一的帖子都会计入用量，并按天进行去重。
</Accordion>

<Accordion title="失败的请求也会计费吗？">
  不会。只有返回 data 的成功响应才会计费。
</Accordion>
