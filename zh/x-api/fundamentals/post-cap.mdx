X API v2 采用 **按使用量付费** 的定价模式。您的费用根据实际的 API 使用情况计算，并在 App 级别进行跟踪。

***

<div id="how-billing-works">
  ## 计费机制
</div>

| 概念 | 说明 |
|:--------|:------------|
| **额度制（Credit-based）** | 预先购买额度，在使用 API 时按量扣减 |
| **按请求计价** | 不同的接口费用不同 |
| **实时跟踪** | 在开发者控制台中监控用量 |
| **无上限** | 可按需使用——没有月度上限 |

<div id="deduplication">
  ## 去重
</div>

<Note>
  **按日去重**：如果同一条帖子在一天内通过多个查询被返回，在计费时只会被计费一次。
</Note>

这意味着：

* 在同一天多次获取同一条帖子 = 计费 1 次
* 第二天再次获取同一条帖子 = 额外计费 1 次
* 同一请求中的不同帖子 = 各自单独计费

</div>

<div id="faqs">
  ## 常见问题
</div>

<Accordion title="如果我的额度用完会发生什么？">
  在你购买更多额度之前，API 请求都会失败。请设置余额提醒，以避免服务中断。
</Accordion>

<Accordion title="有没有每月的最低消费？">
  没有。只需为你实际使用的部分付费。你可以有使用量为零、成本也为零的月份。
</Accordion>

<Accordion title="流式传输如何计费？">
  通过过滤流传递的每个唯一帖子都会计入用量，并按天进行去重计算。
</Accordion>

<Accordion title="失败的请求也会计费吗？">
  不会。只对成功返回数据的响应计费。
</Accordion>
