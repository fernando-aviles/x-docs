当 API 响应包含的结果多于一次可返回的数量时，请使用分页来检索所有页的数据。

***

<div id="how-pagination-works">
  ## 分页的工作原理
</div>

1. 使用 `max_results` 发起初始请求
2. 检查响应中的 `meta` 对象是否包含 `next_token`
3. 如果存在，使用该令牌作为 `pagination_token` 发起下一次请求
4. 重复此过程，直到不再返回 `next_token`

```bash
# 初始请求
curl "https://api.x.com/2/users/12345/tweets?max_results=100" \
  -H "Authorization: Bearer $TOKEN"

# 响应包含 next_token
# {"data": [...], "meta": {"next_token": "abc123", ...}}

# 下一页
curl "https://api.x.com/2/users/12345/tweets?max_results=100&pagination_token=abc123" \
  -H "Authorization: Bearer $TOKEN"
```

***

<div id="pagination-tokens">
  ## 分页令牌
</div>

| 令牌 | 说明 |
|:------|:------------|
| `next_token` | 位于响应的 `meta` 元数据中。用于获取下一页。 |
| `previous_token` | 位于响应的 `meta` 元数据中。用于返回上一页。 |
| `pagination_token` | 请求参数。设置为 `next_token` 或 `previous_token` 的值。 |

***

<div id="response-structure">
  ## 响应结构
</div>

```json
{
  "data": [
    {"id": "1234", "text": "..."},
    {"id": "1235", "text": "..."}
  ],
  "meta": {
    "result_count": 100,
    "next_token": "7140w9gefhslx3",
    "previous_token": "77qp89slxjd"
  }
}
```

当没有更多结果时，响应中不会包含 `next_token`：

```json
{
  "data": [...],
  "meta": {
    "result_count": 42,
    "previous_token": "77qp89abc"
  }
}
```

***

<div id="pagination-parameters">
  ## 分页参数
</div>

| 参数 | 说明 | 默认值 |
|:----------|:------------|:--------|
| `max_results` | 每页结果数 | 取决于具体端点 |
| `pagination_token` | 上一个响应中的令牌 | 无 |

请查阅各端点的 API 参考文档，了解该端点对 `max_results` 的具体限制。

***

<div id="example-paginating-through-all-results">
  ## 示例：分页获取所有结果
</div>

<Tabs>
  <Tab title="Python">
    ```python
    import requests

    def get_all_tweets(user_id, bearer_token):
        url = f"https://api.x.com/2/users/{user_id}/tweets"
        headers = {"Authorization": f"Bearer {bearer_token}"}
        params = {"max_results": 100}
        
        all_tweets = []
        
        while True:
            response = requests.get(url, headers=headers, params=params)
            data = response.json()
            
            if "data" in data:
                all_tweets.extend(data["data"])
            
            # 检查是否存在下一页
            next_token = data.get("meta", {}).get("next_token")
            if not next_token:
                break
                
            params["pagination_token"] = next_token
        
        return all_tweets
    ```
  </Tab>

  <Tab title="JavaScript">
    ```javascript
    async function getAllTweets(userId, bearerToken) {
      const url = `https://api.x.com/2/users/${userId}/tweets`;
      const headers = { Authorization: `Bearer ${bearerToken}` };
      
      let allTweets = [];
      let paginationToken = null;
      
      do {
        const params = new URLSearchParams({ max_results: 100 });
        if (paginationToken) {
          params.set("pagination_token", paginationToken);
        }
        
        const response = await fetch(`${url}?${params}`, { headers });
        const data = await response.json();
        
        if (data.data) {
          allTweets.push(...data.data);
        }
        
        paginationToken = data.meta?.next_token;
      } while (paginationToken);
      
      return allTweets;
    }
    ```
  </Tab>
</Tabs>

<div id="best-practices">
  ## 最佳实践
</div>

<CardGroup cols={2}>
  <Card title="使用最大返回数" icon="arrow-up-1-9">
    请求允许的最大 `max_results` 值，以尽量减少 API 调用次数。
  </Card>

  <Card title="处理部分页面" icon="square-check">
    最后一页的结果可能少于 `max_results`。
  </Card>

  <Card title="保存令牌" icon="database">
    如果需要稍后继续分页，请保存 `next_token`。
  </Card>

  <Card title="不要用分页轮询" icon="clock">
    对于新数据，请使用 `since_id`，而不是反复分页。
  </Card>
</CardGroup>

***

<div id="result-ordering">
  ## 结果排序
</div>

结果按时间**逆序**返回：

* 首页的第一个结果 = 最新
* 最后一页的最后一个结果 = 最早

这一规则适用于页内及跨页的结果。

***

<div id="notes">
  ## 注意事项
</div>

* 分页令牌是不透明的字符串，不要尝试解析或修改它们
* 令牌可能会在一段时间后过期
* 如果你获得的结果数量少于 `max_results`，可能仍然还有更多结果（继续请求，直到不再返回 `next_token`）
* 使用 [SDK](/zh/x-api/tools-and-libraries/sdks) 来自动处理分页
