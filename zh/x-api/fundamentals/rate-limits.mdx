速率限制控制你对每个端点可发起的请求次数。超出限制会返回 429 错误，直到时间窗口重置为止。

***

<div id="how-rate-limits-work">
  ## 速率限制的工作原理
</div>

| 概念 | 描述 |
|:--------|:------------|
| **时间窗口** | 通常为 15 分钟或 24 小时 |
| **按用户限制** | 适用于 OAuth 1.0a 或 OAuth 2.0 用户令牌 |
| **按应用限制** | 适用于 Bearer Token（仅应用） |
| **按端点限制** | 每个端点都有自己的限制 |

***

<div id="checking-your-limits">
  ## 检查你的速率限制
</div>

响应头会显示你当前的速率限制情况：

```
x-rate-limit-limit: 900
x-rate-limit-remaining: 847
x-rate-limit-reset: 1705420800
```

| Header                   | Description       |
| :----------------------- | :---------------- |
| `x-rate-limit-limit`     | 允许的最大请求数          |
| `x-rate-limit-remaining` | 当前时间窗口内剩余的请求数     |
| `x-rate-limit-reset`     | 时间窗口重置时的 Unix 时间戳 |

<div id="handling-rate-limits">
  ## 处理速率限制
</div>

当你达到速率限制时，会收到一个 429 响应：

```json
{
  "errors": [{
    "code": 88,
    "message": "Rate limit exceeded"
  }]
}
```

<div id="recovery-strategy">
  ### 恢复策略
</div>

1. 检查 `x-rate-limit-reset` 以确定窗口何时重置
2. 等待到该时间点后再重试
3. 如有需要，使用指数退避策略

```python
import time

def make_request_with_backoff(url, headers):
    response = requests.get(url, headers=headers)
    
    if response.status_code == 429:
        reset_time = int(response.headers.get('x-rate-limit-reset', 0))
        wait_time = max(reset_time - time.time(), 60)
        time.sleep(wait_time)
        return make_request_with_backoff(url, headers)
    
    return response
```

<div id="rate-limits-vs-billing">
  ## 速率限制与计费
</div>

速率限制和计费是彼此独立的：

| 概念 | 目的 |
|:--------|:--------|
| **速率限制** | 控制请求频率以保障系统稳定性 |
| **用量计费** | 按检索到的 data 收费（按使用量付费） |

你可以在速率限制范围内但仍产生用量费用，也可能达到速率限制但不产生额外费用。
