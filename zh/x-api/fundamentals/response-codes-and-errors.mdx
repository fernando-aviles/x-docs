X API 使用标准 HTTP 状态码。请求成功时返回 2xx 状态码；出错时返回 4xx 或 5xx 状态码，并在响应正文中提供错误详情。

***

<div id="http-status-codes">
  ## HTTP 状态码
</div>

<div id="success-codes">
  ### 成功状态码
</div>

| 状态码 | 含义 | 说明 |
|:-----|:--------|:------------|
| **200** | OK | 请求成功 |
| **201** | Created | 资源已创建（POST 请求） |
| **204** | No Content | 成功但无响应正文（DELETE 请求） |

<div id="client-error-codes">
  ### 客户端错误状态码
</div>

| Code | 含义 | 常见原因 |
|:-----|:--------|:--------------|
| **400** | 错误请求 | 无效的 JSON、格式错误的查询、缺少必需参数 |
| **401** | 未授权 | 身份验证凭证无效或缺失 |
| **403** | 禁止 | 认证有效但对该资源或操作没有权限 |
| **404** | 未找到 | 资源不存在或已被删除 |
| **409** | 冲突 | 流没有规则（仅适用于 Filtered Stream） |
| **429** | 请求过多 | 超出速率限制或使用上限 |

<div id="server-error-codes">
  ### 服务器错误代码
</div>

| 代码 | 含义 | 处理建议 |
|:-----|:--------|:-----------|
| **500** | 内部服务器错误 | 请稍候重试；检查 [状态页](/zh/status) |
| **502** | 错误网关 | 请稍候重试 |
| **503** | 服务不可用 | X 负载过高；请稍候重试 |
| **504** | 网关超时 | 请稍候重试 |

***

<div id="error-response-format">
  ## 错误响应格式
</div>

错误响应包含结构化的详细信息：

```json
{
  "title": "Invalid Request",
  "detail": "The 'query' parameter is required.",
  "type": "https://api.x.com/2/problems/invalid-request"
}
```

| 字段       | 描述            |
| :------- | :------------ |
| `type`   | 用于标识错误类型的 URI |
| `title`  | 简要的错误描述       |
| `detail` | 关于此错误的具体说明    |

视错误类型而定，可能还会包含其他字段。

***

<div id="error-types">
  ## 错误类型
</div>

| 类型 | 描述 |
|:-----|:------------|
| `about:blank` | 通用错误（参见 HTTP 状态码） |
| `.../invalid-request` | 请求格式错误或参数无效 |
| `.../resource-not-found` | 帖子、用户或其他资源不存在 |
| `.../not-authorized-for-resource` | 无权访问私有/受保护内容 |
| `.../client-forbidden` | 应用未注册或缺少必需访问权限 |
| `.../usage-capped` | 超出使用上限 |
| `.../rate-limit-exceeded` | 超出速率限制 |
| `.../streaming-connection` | 流式连接问题 |
| `.../rule-cap` | 过滤流规则数量超限 |
| `.../invalid-rules` | 规则语法错误 |
| `.../duplicate-rules` | 规则已存在 |

<div id="partial-errors">
  ## 部分错误
</div>

某些请求可能会部分成功。200 响应可能同时包含 `data` 和 `errors`：

```json
{
  "data": [
    {"id": "123", "text": "Hello"}
  ],
  "errors": [
    {
      "resource_id": "456",
      "resource_type": "tweet",
      "title": "Not Found Error",
      "detail": "Could not find tweet with id: [456].",
      "type": "https://api.x.com/2/problems/resource-not-found"
    }
  ]
}
```

在请求多个资源且其中部分资源不可用时，会发生这种情况。

<div id="troubleshooting-common-errors">
  ## 排查常见错误
</div>

<Accordion title="401 未授权">
  **检查你的身份验证：**

  * 确认你为该端点使用了正确的身份验证方式
  * 确认凭证没有被重新生成
  * 检查 `Authorization` 请求头的格式
  * 对于 OAuth 1.0a，核对签名计算是否正确

  [身份验证指南 →](/zh/resources/fundamentals/authentication/overview)
</Accordion>

<Accordion title="403 禁止访问">
  **检查你的访问权限：**

  * 确认你的应用对该端点具有访问权限
  * 某些端点需要特定的注册或审批
  * 需要用户上下文的端点需要合适的 OAuth 范围（scope）
  * 资源可能是私有或受保护的

  [访问控制指南 →](/zh/resources/fundamentals/authentication/overview)
</Accordion>

<Accordion title="429 请求过多">
  **被限速：**

  * 检查 `x-rate-limit-reset` 响应头以确定何时重试
  * 实现指数退避重试策略
  * 考虑缓存响应
  * 将请求分散到整个时间窗口中

  [Rate limits guide →](/zh/x-api/fundamentals/rate-limits)
</Accordion>

<Accordion title="400 错误请求">
  **修正你的请求：**

  * 验证 JSON 语法
  * 检查是否缺少必需参数
  * 核对参数类型（字符串 vs. 数字）
  * 在查询中转义特殊字符
</Accordion>

<Accordion title="缺少预期的帖子">
  **检查以下因素：**

  * 受保护账号的帖子只有在授权后才可见
  * 已删除的帖子会返回 404
  * 某些帖子在特定地区会被屏蔽
  * 确认搜索查询语法正确
</Accordion>

<Accordion title="流连接中断">
  **处理重连：**

  * 实现带退避策略的自动重连
  * 使用恢复功能获取遗漏的数据
  * 检查是否因为缓冲区已满导致断开（客户端消费速度不够快）
  * 确认至少存在一条流规则

  [流式传输指南 →](/zh/x-api/posts/filtered-stream/integrate/handling-disconnections)
</Accordion>

<div id="rate-limit-headers">
  ## 速率限制相关的响应头
</div>

每个响应都会包含速率限制相关信息：

```
x-rate-limit-limit: 900
x-rate-limit-remaining: 847
x-rate-limit-reset: 1705420800
```

| Header                   | Description         |
| :----------------------- | :------------------ |
| `x-rate-limit-limit`     | 当前时间窗口内的最大请求数       |
| `x-rate-limit-remaining` | 剩余可用请求数             |
| `x-rate-limit-reset`     | 时间窗口重置时间点的 Unix 时间戳 |
