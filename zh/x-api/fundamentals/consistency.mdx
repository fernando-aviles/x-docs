X API v2 在所有端点中采用了一致的设计模式。一旦你了解了某个端点的工作方式，同样的模式就适用于所有端点。

***

<div id="consistent-patterns">
  ## 统一的模式
</div>

<div id="url-structure">
  ### URL 结构
</div>

所有 v2 端点都遵循一个可预期的模式：

```
/version/resource/{id}?parameters
/version/resource/verb?parameters
```

示例：

```
/2/tweets/1234567890                    # Get a specific post
/2/tweets/search/recent                 # Search recent posts
/2/users/by/username/xdevelopers        # 根据用户名获取用户
/2/users/1234/followers                 # Get user's followers
```

<div id="response-structure">
  ### 响应结构
</div>

所有响应都采用相同的顶级结构：

```json
{
  "data": { ... },       // 主要对象
  "includes": { ... },   // 扩展对象
  "meta": { ... },       // 分页、计数
  "errors": [ ... ]      // 部分错误(如有)
}
```

<div id="id-format">
  ### ID 格式
</div>

所有 ID 均以字符串形式返回，以确保语言兼容性：

```json
{
  "id": "1234567890123456789",
  "author_id": "2244994945"
}
```

***

<div id="fields-and-expansions">
  ## 字段和扩展
</div>

相同的 [字段](/zh/x-api/fundamentals/fields) 和 [扩展](/zh/x-api/fundamentals/expansions) 参数在各处的用法是一致的：

| 对象 | 字段参数 | 适用范围 |
|:-------|:-----------------|:-------------|
| 帖子 | `tweet.fields` | 所有返回帖子对象的端点 |
| 用户 | `user.fields` | 所有返回用户对象的端点 |
| 媒体 | `media.fields` | 所有带有媒体扩展的端点 |
| 投票 | `poll.fields` | 所有带有投票扩展的端点 |
| 地点 | `place.fields` | 所有带有地点扩展的端点 |

***

<div id="object-schemas">
  ## 对象模式
</div>

无论由哪个端点返回，同一对象类型都具有相同的字段：

* 来自 search 的帖子和来自 lookup 的帖子具有相同的字段
* 来自 followers 的用户和来自 search 的用户具有相同的字段
* 扩展后的对象与其单独返回时的对象完全一致

***

<div id="authentication">
  ## 身份验证
</div>

所有端点都使用相同的身份验证方法：

| 方法 | Header 格式 |
|:-------|:--------------|
| Bearer Token | `Authorization: Bearer {token}` |
| OAuth 1.0a | `Authorization: OAuth {parameters}` |
| OAuth 2.0 | `Authorization: Bearer {user_token}` |

***

<div id="error-handling">
  ## 错误处理
</div>

错误采用统一的格式：

```json
{
  "title": "Invalid Request",
  "detail": "The query parameter is missing",
  "type": "https://api.x.com/2/problems/invalid-request"
}
```

[查看所有错误类型 →](/zh/x-api/fundamentals/response-codes-and-errors)

***

<div id="pagination">
  ## 分页
</div>

所有分页端点都使用相同的令牌系统：

| 参数 | 描述 |
|:----------|:------------|
| `max_results` | 每页返回的结果数 |
| `pagination_token` | 来自 `next_token` 或 `previous_token` 的令牌 |

[了解更多关于分页的信息 →](/zh/x-api/fundamentals/pagination)

***

<div id="naming-conventions">
  ## 命名约定
</div>

* 使用美式英文拼写（`favorites` 而不是 `favourites`）
* 字段名使用 snake&#95;case（`author_id`、`created_at`）
* 术语保持一致（在字段中使用 `retweet_count`，而不是 `repost_count`）

***

<div id="empty-values">
  ## 空值
</div>

没有值的字段会被省略，而不是返回 `null`：

```json
// User without a bio
{
  "id": "1234",
  "name": "Example User",
  "username": "example"
  // "description" 被省略,而非 null
}
```

***

<div id="entity-consistency">
  ## 实体一致性
</div>

`entities` 对象仅包含从文本中解析出的实体：

* `urls`
* `hashtags`
* `mentions`
* `cashtags`

媒体和投票位于 `attachments` 中，而不是 `entities` 中。
