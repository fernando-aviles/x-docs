<div id="retweets-lookup-standard-v11-compared-to-x-api-v2">
  ### 转推查询：标准版 v1.1 与 X API v2 的比较
</div>

如果你一直在使用标准版 v1.1 的 [v1.1 GET statuses/retweets/:id](https://developer.x.com/en/docs/twitter-api/v1/tweets/post-and-engage/api-reference/get-statuses-retweets-id)、[v1.1 GET statuses/retweets/:ids](https://developer.x.com/en/docs/twitter-api/v1/tweets/post-and-engage/api-reference/get-statuses-retweeters-ids)，本指南旨在帮助你理解标准版 v1.1 与 X API v2 转推查询端点之间的相似之处和差异。

* **相似之处**
  * 认证方式
  * 每个请求的用户数量限制
* **差异之处**
  * 端点 URL

  * 请求限制

  * App 和 Project 要求

  * 响应数据格式

  * 请求参数

<div id="similarities">
  #### 相似之处
</div>

**认证**

标准版 v1.1 和 X API v2 的转发查询端点（[v1.1 GET statuses/retweets/:id](https://developer.x.com/en/docs/twitter-api/v1/tweets/post-and-engage/api-reference/get-statuses-retweets-id) 和 [v1.1 GET statuses/retweeters/:ids](https://developer.x.com/en/docs/twitter-api/v1/tweets/post-and-engage/api-reference/get-statuses-retweeters-ids)）都使用 [OAuth 1.0a 用户上下文](https://developer.x.com/content/developer-twitter/resources/fundamentals/authentication) 或 OAuth 2.0 Bearer Token。

**每个请求的用户数量限制**

对于 v1.1 和 v2 的 GET 端点，转发查询端点在单次请求中最多会返回 100 个用户。对于 v2 的转发查询端点，不会传递分页令牌；默认情况下我们返回 100 个用户，也是可返回的最大数量。

<div id="differences">
  #### 差异
</div>

**Endpoint URL**

* 标准 v1.1 endpoint：
  * https://api.x.com/1.1/statuses/retweets/:id.json
    （返回由 `id` 参数指定的帖子最近 100 条转发组成的集合）
  * `https://api.x.com/1.1/statuses/retweeters/ids.json`
    （返回由 `id` 参数指定的帖子转发者中最多 100 个用户 ID 的集合）
* X API v2 endpoint：
  * https://api.x.com/2/tweets/:id/retweeted&#95;by
    （返回转发了指定帖子的账号列表）

**App 和 Project 要求**

在对请求进行认证时，X API v2 endpoint 要求你使用某个 [developer App](/zh/resources/fundamentals/developer-apps) 的凭证，并且该 App 必须隶属于某个 [Project](/zh/resources/fundamentals/developer-apps)。所有 X API v1.1 endpoint 都可以使用来自 App 的凭证，无论该 App 是否与某个 Project 关联。

**响应数据格式**

标准 v1.1 与 X API v2 版本的 endpoint 之间的最大差异之一在于，你如何选择要在负载中返回哪些字段。

对于标准 endpoint，默认会返回许多响应字段，然后你可以再选择使用参数来指定应在负载中返回哪些字段或字段集合。

X API v2 版本默认仅返回用户 id、名称和用户名字段。若要请求任何其他字段或对象，你需要使用 [fields](/zh/x-api/fundamentals/fields) 和 [expansions](/zh/x-api/fundamentals/expansions) 参数。你从该 endpoint 请求的任何用户字段都会返回在主 user 对象中。任何扩展的 Post 对象及其字段都会返回在响应中的 includes（包含对象）对象中。然后，你可以通过匹配 user 对象和扩展的 Post 对象中的 id 值，将任何扩展对象关联回 user 对象。 

我们建议你在各自的指南中进一步了解这些新参数，或者阅读我们的[如何使用 fields 和 expansions](/zh/x-api/fundamentals/data-dictionary#how-to-use-fields-and-expansions) 指南。 

我们还整理了一个 [数据格式迁移指南](/zh/x-api/migrate/data-format-migration#migrating-from-standard-v1-1s-data-format-to-v2)，可帮助你将标准 v1.1 字段映射到较新的 v2 字段。该指南还会为你提供在 v2 请求中需要传递的特定 expansions 和 fields 参数，以返回指定字段。 
 

除了你请求某些字段的方式发生变化之外，X API v2 还为 API 返回的对象引入了新的 JSON 设计，包括 [Post](/zh/x-api/fundamentals/data-dictionary#tweet) 和 [user](/zh/x-api/fundamentals/data-dictionary#user) 对象。

* 在 JSON 根级别，标准 endpoint 在 statuses 数组中返回 Post 对象，而 X API v2 在 data 数组中返回 Post 对象。 
* X API v2 JSON 不再引用被转发和被引用的“statuses”，而是引用被转发和被引用的 Tweets。许多旧版和已弃用的字段（例如 contributors 和 user.translator&#95;type）正在被移除。 
* X API v2 不再同时使用 favorites（位于 Post 对象中）和 favourites（位于 user 对象中），而是统一使用术语 like。 
* X 采用这样的约定：对于没有值的 JSON 字段（例如值为 null 的字段），不会写入到负载中。仅当 Post 和 user 属性具有非 null 值时，才会被包含。 
   

我们还为 [Post 对象](/zh/x-api/fundamentals/data-dictionary#tweet) 引入了一组新字段，包括以下内容：

* 一个 [conversation&#95;id](/zh/x-api/fundamentals/conversation-id) 字段
* 两个新的 [annotations](/zh/x-api/fundamentals/post-annotations) 字段，包括 context 和 entities
* 若干新的 [metrics](/zh/x-api/fundamentals/metrics) 字段 
* 一个新的 reply&#95;setting 字段，用于指示谁可以回复给定的帖子

**请求参数**

以下标准 v1.1 请求可以接受两个查询参数（user&#95;id 或 screen&#95;name）。X API v2 仅接受数字用户 ID，并且必须作为 endpoint 路径的一部分进行传递。

<div id="get-users-who-retweeted-a-post-v2">
  ### 获取转发某条帖子的用户 (v2)
</div>

<CodeGroup dropdown>
  ```bash cURL
  curl "https://api.x.com/2/tweets/1234567890/retweeted_by?user.fields=username,verified" \
    -H "Authorization: Bearer $BEARER_TOKEN"
  ```

  ```python Python
  import requests

  bearer_token = "YOUR_BEARER_TOKEN"
  url = "https://api.x.com/2/tweets/1234567890/retweeted_by"

  params = {"user.fields": "username,verified"}
  headers = {"Authorization": f"Bearer {bearer_token}"}

  response = requests.get(url, headers=headers, params=params)
  print(response.json())
  ```

  ```python Python SDK
  from xdk import Client

  client = Client(bearer_token="YOUR_BEARER_TOKEN")

  # 获取转发某条帖子的用户
  response = client.posts.get_retweeted_by(
      "1234567890",
      user_fields=["username", "verified"]
  )
  for user in response.data:
      print(f"{user.username} - Verified: {user.verified}")
  ```

  ```javascript JavaScript SDK
  import { Client } from "@xdevplatform/xdk";

  const client = new Client({ bearerToken: "YOUR_BEARER_TOKEN" });

  // 获取转发某条帖子的用户
  const response = await client.posts.getRetweetedBy("1234567890", {
    userFields: ["username", "verified"],
  });

  response.data?.forEach((user) => {
    console.log(`${user.username} - Verified: ${user.verified}`);
  });
  ```
