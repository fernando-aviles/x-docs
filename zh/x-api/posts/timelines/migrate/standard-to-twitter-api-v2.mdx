<div id="standard-v11-timelines-to-x-api-v2-timelines">
  ## 标准 v1.1 时间线到 X API v2 时间线
</div>

如果你一直在使用 v1.1 时间线端点（statuses/user&#95;timeline 和 statuses/mentions&#95;timeline），本指南旨在帮助你理解标准时间线端点与 X API v2 时间线端点之间的相似点和差异，从而将你当前的集成迁移到新版本。

* **相似点：**
  * 认证：
    * OAuth 1.0a 用户上下文（按逆时间顺序排序的主页时间线、用户帖子时间线和用户提及时间线）
    * OAuth 2.0 App-Only（用户帖子时间线）
  * 历史访问限制：用户时间线（用户帖子时间线）可访问最近的 3200 条帖子；提及时间线（用户提及时间线）可访问最近的 800 条提及。
  * 支持帖子编辑历史和元数据
  * 速率限制（用户帖子时间线）
  * 刷新轮询：能够从 since&#95;id 起检索新增结果
  * 按帖子 ID 遍历时间线
  * 结果规范：
    * 结果顺序：结果按逆时间顺序返回
    * 能够排除回复（仅限用户帖子时间线）
    * 能够排除转发（仅限用户帖子时间线）
* **差异：**
  * 新的认证能力：
    * OAuth 2.0 App-Only（用户提及时间线）
    * 带 PKCE 的 OAuth 2.0 授权码流程（按逆时间顺序排序的主页时间线、用户帖子时间线和用户提及时间线）
  * 访问要求：X API v2 App 和 Project 要求
  * 速率限制（用户提及时间线和按逆时间顺序排序的主页时间线）
  * 额外的分页方式
    * 每个响应可返回的 max&#95;results（数量）不同
  * 响应数据格式
  * 请求参数
    * 可根据请求参数定制的数据格式，包括 v2 字段和扩展
    * 额外可用数据：指标、帖子注解、投票

<div id="similarities">
  ### 相似之处
</div>

**认证**

v1.1 的 statuses/user&#95;timeline 和 X API v2 的用户帖子时间线端点都支持 [OAuth 1.0a 用户上下文](/zh/resources/fundamentals/authentication) 和 [OAuth 2.0 仅应用（App-Only）](/zh/resources/fundamentals/authentication#bearer-token-also-known-as-app-only)。因此，如果你迁移到 X API v2 版本，可以继续使用相同的认证方法和授权令牌。

**历史访问**

v1.1 的 statuses/user&#95;timeline 和 X API v2 的用户帖子时间线端点都会返回最新的 3200 条帖子，包括转发（Retweets）。

v1.1 的 statuses/mentions&#95;timeline 和 X API v2 的用户提及时间线端点可以返回最新的 800 条帖子。

**对帖子编辑历史和元数据的支持**

这两个版本都提供描述任何编辑历史的元数据。查看 [filtered stream API 参考](/zh/x-api/posts/filtered-stream#api-reference-index) 和 [编辑帖子基础知识页面](/zh/x-api/fundamentals/edit-posts) 了解更多详细信息。

**速率限制**

|     |     |
| :--- | :--- |
| **标准 v1.1** | **X API v2** |
| user&#95;timeline:<br /><br />使用 OAuth 1.0a 用户上下文时，每 15 分钟 900 个请求<br /><br />使用 OAuth 2.0 仅应用（App-Only）时，每 15 分钟 1500 个请求 | 用户帖子时间线：<br /><br />使用 OAuth 1.0a 用户上下文时，每 15 分钟窗口 900 个请求<br /><br />使用 OAuth 2.0 仅应用（App-Only）时，每 15 分钟窗口 1500 个请求 |

**使用 since&#95;id 进行轮询刷新**

这两个版本都允许使用 since&#95;id 轮询最新的结果。

**通过帖子 ID 遍历时间线**

这两个端点都可以基于帖子 ID 的构造方式，使用帖子 ID 的“时间戳”来遍历时间线。除以下差异外，其功能通常相同：

|     |     |
| :--- | :--- |
| **标准时间线 v1.1** | **时间线 v2** |
| since&#95;id（不包含）<br /><br />max&#95;id（包含） | since&#95;id（不包含）<br /><br />until&#95;id（同样为不包含，而 max&#95;id 为包含） |

**响应过滤参数**

|     |     |
| :--- | :--- |
| **标准时间线 v1.1** | **时间线 v2** |
| 响应过滤参数：<br /><br />* include&#95;rts<br />* exclude&#95;replies | 响应过滤参数：<br /><br />* exclude=retweets,replies |
| 示例 <br /><br />https://api.x.com/1.1/statuses/user&#95;timeline.json?user&#95;id=2244994945&amp;include&#95;rts=0&amp;&amp;exclude&#95;replies=1 | 示例：<br /><br />https://api.x.com/2/users/2244994945/tweets?max&#95;results=100&amp;exclude=retweets,replies |
| 说明：<br /><br />对于 user&#95;timeline：<br /><br />* 使用 include&#95;rts=0 不会改变最多可访问的历史帖子上限（最新 3200 条） | 说明：<br /><br />对于用户帖子时间线：<br /><br />* 使用 exclude=retweets 不会改变最多可访问的历史帖子上限（最新 3200 条）<br />* 使用 exclude=replies 会将最多可访问的历史帖子上限减少为最新的 800 条回复 |

<div id="differences">
  ### 差异
</div>

**身份验证**

**v1.1 的 `statuses/mentions_timeline` 端点仅支持 [OAuth 1.0a 用户上下文](https://developer-staging.x.com/resources/fundamentals/authentication)。X API v2 用户提及时间线端点同时支持 [OAuth 1.0a 用户上下文](/zh/resources/fundamentals/authentication)、[OAuth 2.0 App-Only](/zh/resources/fundamentals/authentication#bearer-token-also-known-as-app-only) 和 [OAuth 2.0 Authorization Code with PKCE](/zh/resources/fundamentals/authenticationoauth-2-0/authorization-code "此方法允许已获授权的应用代表用户、以用户身份执行操作。它通常用于访问或发布某个特定用户的公开信息，并且在你的应用需要了解用户与此端点返回结果之间的关系时非常有用。点击了解如何使用 OAuth 2.0 Authorization Code with PKCE 进行身份验证。") **

如果你希望通过 X API v2 用户帖子时间线端点访问私有或推广相关指标，你需要使用 OAuth 1.0a 用户上下文或 OAuth 2.0 Authorization Code with PKCE，并传递与发布该帖子（即你希望为其访问指标的帖子）的用户相关的用户访问令牌。

**端点 URL**

请注意，X API v2 时间线端点在路径中需要一个 `:id` 参数来表示用户 id。

* 标准 v1.1 端点：
  * https://api.x.com/1.1/statuses/home&#95;timeline
  * https://api.x.com/1.1/statuses/user&#95;timeline
  * https://api.x.com/1.1/statuses/mention&#95;timeline
* X API v2 端点：
  * https://api.x.com/2/users/:id/timelines/reverse&#95;chronological
  * https://api.x.com/2/users/:id/tweets
  * https://api.x.com/2/users/:id/mentions

**App 和 Project 要求**

在对请求进行身份验证时，X API v2 端点要求你使用与某个 [Project](/zh/resources/fundamentals/developer-apps) 关联的 [developer App](/zh/resources/fundamentals/developer-apps) 的凭证。所有 X API v1.1 端点都可以使用来自 App，或来自关联到某个 Project 的 App 的凭证。

**速率限制**

|     |     |
| :--- | :--- |
| **mentions&#95;timeline：**<br /><br />使用 OAuth 1.0a 用户上下文时，每 15 分钟 75 次请求 | **用户提及时间线：**<br /><br />使用 OAuth 1.0a 用户上下文时，每 15 分钟窗口 180 次请求  <br />使用 OAuth 2.0 Bearer Token 时，每 15 分钟窗口 450 次请求 |
| **home&#95;timelime：**<br /><br />每 15 分钟 15 次请求  <br /><br />在主页时间线上最多可以获取 800 条帖子 | **按时间倒序的主页时间线：**<br /><br />每 15 分钟 180 次请求<br /><br />你可以返回最近 7 天内在时间线上创建的每一条帖子，以及不论创建日期如何的最近 800 条帖子。 |

**请求参数**

|     |     |
| :--- | :--- |
| **Standard timelines v1.1** | **timelines v2** |
| 必需：user&#95;id 或 screen&#95;name | 必需：在路径参数中指定特定的用户 ID |
| 可选：<br /><br />count - 设置每次请求返回的最大结果数<br /><br />exclude&#95;replies - 从结果中移除回复<br /><br />Include&#95;rts - 设置为 0 时，从结果中移除转发<br /><br />trim&#95;user - 从结果中移除重新填充的用户对象（rehydrated user objects）<br /><br />tweet&#95;mode - 设置结果返回的数据格式，对于超过 140 字的帖子设置为 extended<br /><br />since&#95;id - 设置结果中最早的帖子 ID（不包含该 ID）<br /><br />max&#95;id - 设置结果中最新的帖子 ID（包含该 ID） | 可选：<br /><br />max&#95;results - 设置每次请求返回的最大结果数<br /><br />exclude=retweets,replies - 从结果中移除转发或回复<br /><br />tweet.fields - 设置要返回的 Post 对象字段<br /><br />user.fields - 设置要返回的 User 对象字段<br /><br />place.fields - 设置要返回的 place 对象字段<br /><br />media.fields - 设置要返回的 media 对象字段<br /><br />poll.fields - 设置要返回的 poll 对象字段<br /><br />expansions - 设置要返回的扩展字段和相关 data<br /><br />start&#95;time - 设置结果中最早的 created&#95;at 时间<br /><br />end&#95;time - 设置结果中最新的 created&#95;at 时间<br /><br />since&#95;id - 设置结果中最早的帖子 ID（不包含该 ID）<br /><br />until&#95;id - 设置结果中最新的帖子 ID（不包含该 ID） |

**响应数据格式**

|     |     |
| :--- | :--- |
| **Standard search v1.1** | **Search Posts v2** |
| [<br />    tweet object,<br />    tweet object<br />  ] | <br />  &quot;data&quot;: [id,text,id,text],<br />  &quot;meta&quot;: <br />    &quot;oldest&#95;id&quot;: &quot;1337085692623646724&quot;,<br />    &quot;newest&#95;id&quot;: &quot;1334183616172019713&quot;,<br />    &quot;previous&#95;token&quot;: &quot;77qpymm88g5h9vqkluldpw91lr0qzfz1sqydh841iz48k&quot;,<br />    &quot;result&#95;count&quot;: 10,<br />    &quot;next&#95;token&quot;: &quot;7140dibdnow9c7btw3w29gqolns6a1ipl3kzeae41vsxk&quot;<br />  <br /> |

**X API v2 JSON 格式**

X API v2 为 API 返回的对象（包括 [Post](/zh/x-api/fundamentals/data-dictionary#tweet) 和 [user](/zh/x-api/fundamentals/data-dictionary#user) 对象）引入了新的 JSON 设计。你可以通过访问我们的[指南](/zh/x-api/fundamentals/data-dictionary#how-to-use-fields-and-expansions)来进一步了解 X API v2 格式、如何使用字段和扩展，也可以阅读更全面的[数据字典](/zh/x-api/fundamentals/data-dictionary)。

* 在 JSON 根级别，标准端点在一个名为 statuses 的数组中返回 Post 对象，而 X API v2 则在一个名为 data 的数组中返回这些对象。
* X API v2 JSON 不再引用被转发和被引用的“statuses”，而是引用被转发的和被引用的推文。许多旧版和已弃用的字段，例如 contributors 和 user.translator&#95;type，将被移除。
* X API v2 不再在 Post 对象和 user 对象中都使用 favorites，而是统一使用术语 like。
* X 采用的约定是：没有取值的 JSON 字段（例如值为 null）不会写入有效负载。只有在 Post 和 user 属性具有非空值时才会被包含。

标准 v1.1 与 X API v2 端点版本之间最大的差异之一是，你如何选择在有效负载中返回哪些字段。对于标准端点，可以使用多个参数来指定有效负载中要返回哪些字段或字段集合，而 X API v2 版本则将这些不同的参数简化为 [fields](/zh/x-api/fundamentals/fields) 和 [expansions](/zh/x-api/fundamentals/expansions)。

* fields: X API v2 端点让你能够选择响应载荷中包含哪些字段。例如，帖子、用户、Media、Place 和 Poll 对象都有一组可以（或不）返回的字段。

* expansions: 用于扩展帖子 JSON 载荷中被引用的补充对象。例如，所有转发和回复都会引用其他帖子。通过设置 expansions=referenced&#95;tweets.id，这些其他帖子对象会根据 tweet.fields 的设置被展开。其他对象（例如用户、投票和媒体）也可以被展开。

* conversation&#95;id

* 两个新的 [annotations](/zh/x-api/fundamentals/post-annotations) 字段，包括 context 和 entities

* 若干新的 [metrics](/zh/x-api/fundamentals/metrics) 字段

我们整理了一份 [data format migration guide](/zh/x-api/migrate/data-format-migration#migrating-from-standard-v1-1s-data-format-to-v2)，可帮助你将标准 v1.1 字段映射到较新的 v2 字段。该指南还将告知你在 v2 请求中需要传递哪些具体的 expansions 和 fields 参数，以返回特定字段。

<div id="user-posts-timeline-v2">
  ### 用户帖子时间线（v2）
</div>

<CodeGroup dropdown>
  ```bash cURL
  curl "https://api.x.com/2/users/2244994945/tweets?max_results=100&tweet.fields=created_at,public_metrics&exclude=retweets,replies" \
    -H "Authorization: Bearer $BEARER_TOKEN"
  ```

  ```python Python SDK
  from xdk import Client

  client = Client(bearer_token="YOUR_BEARER_TOKEN")

  # 获取用户的帖子时间线
  for page in client.posts.get_user_posts(
      "2244994945",
      tweet_fields=["created_at", "public_metrics"],
      exclude=["retweets", "replies"],
      max_results=100
  ):
      for post in page.data:
          print(f"{post.created_at}: {post.text[:50]}...")
  ```

  ```javascript JavaScript SDK
  import { Client } from "@xdevplatform/xdk";

  const client = new Client({ bearerToken: "YOUR_BEARER_TOKEN" });

  // 获取用户的帖子时间线
  const paginator = client.posts.getUserPosts("2244994945", {
    tweetFields: ["created_at", "public_metrics"],
    exclude: ["retweets", "replies"],
    maxResults: 100,
  });

  for await (const page of paginator) {
    page.data?.forEach((post) => {
      console.log(`${post.created_at}: ${post.text?.slice(0, 50)}...`);
    });
  }
  ```
</CodeGroup>
