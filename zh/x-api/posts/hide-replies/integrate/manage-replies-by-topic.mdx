<div id="manage-replies-by-topic">
  ### 按话题管理回复
</div>

通过 hide replies 端点，你可以构建集成，帮助用户和品牌让他们的对话保持在指定话题上。本页展示了如何使用 hide replies 和 [recent search](/zh/x-api/posts/recent-search) 端点来管理一段对话。

Recent search 具有获取一段对话及其回复的功能，而 Post 负载会返回 [Post annotations](/zh/x-api/fundamentals/post-annotations)，帮助你理解每条帖子（Post）的上下文和主题，而不受语言限制。

应用的流程将包含用于展示和管理对话的控件：

1. 它会请求用户授权读取他们的帖子并管理其回复。

2. 它会通过一个 Post URL 获取最近的一段对话，并检查这段对话是否由正在进行认证的用户发起。

3. 它会调用 recent search 端点来展示对话中的每条帖子。请求将包含对话 ID 的搜索查询和注释扩展，以根据 X 对该帖子的理解来判断该帖子是否与体育相关。

4. 当用户选择这样做时，它会调用 hide replies 来隐藏某条回复。同时还会提供撤销此操作的方式，以便用户在需要时始终可以恢复。 

5. 对于较长的对话，它会提供控件用于[分页浏览搜索结果](/zh/x-api/posts/search/integrate/paginate)。
    

<div id="optimize-for-the-user-and-for-usage">
  #### 为用户（以及使用情况）优化
</div>

你可以将流程设计为，让用户对自己打算执行的每个操作都拥有控制权。牢记这一原则还能帮助你构建一个能够优化帖子消费体验的集成方案。

1. 由于已认证用户只能管理由自己发起的会话，当不满足这一条件时，你的流程应尽早结束。
   * 首先发起一次帖子查询请求。如果帖子 URL 无效，或该会话并非由当前认证用户发起，则应尽早终止流程。
   * 这样，当会话无法由已认证用户进行管理时，你的应用就不必再发起最近搜索请求。
2. 在同一个请求中同时请求[用户和帖子字段](/zh/x-api/fundamentals/fields)，以避免发起单独的请求。这种方式也可以提升应用的性能。
3. 在不需要时避免发起请求。此应用会在用户的浏览器中缓存回复的隐藏状态。这对于规模较大的会话非常有用，用户可能希望稍后继续他们的审核工作，同时也有助于你的应用优化用于隐藏或取消隐藏回复的请求。
