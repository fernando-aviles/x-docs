<div id="manage-replies-by-topic">
  ### 按主题管理回复
</div>

通过 hide replies 端点，你可以构建集成，帮助个人和品牌让他们的对话始终围绕正确的主题展开。此页面展示了如何使用 hide replies 和 [recent search](/zh/x-api/posts/recent-search) 端点来管理一段对话。

recent search 可以检索一段对话及其所有回复，而 Post 有效负载会返回 [Post annotations](/zh/x-api/fundamentals/post-annotations)，无论使用何种语言，都能帮助你理解每条帖子的上下文和主题。

App 的流程将包含用于展示和管理对话的控件：

1. 它会征得用户的许可，以读取他们的帖子并管理他们的回复。

2. 它会从一个 Post URL 中获取一段最近的对话，并检查该对话是否来自进行认证的用户。

3. 它会调用 recent search 端点来展示对话中的每条帖子。请求将包含 conversation ID 的搜索查询以及注释扩展，以根据 X 对帖子的理解来判断该帖子是否与体育相关。

4. 当用户选择隐藏某条回复时，它会调用 hide replies 来隐藏该回复。同时，它还会提供一种撤销此操作的方式，从而让用户始终保持控制权。 

5. 对于更长的对话，它会提供控件以[在搜索结果中进行分页](/zh/x-api/posts/search/integrate/paginate)。
    

<div id="optimize-for-the-user-and-for-usage">
  #### 针对用户进行优化（以及针对使用模式）
</div>

你可以设计一个流程，让用户始终掌控自己打算执行的任何操作。牢记这一原则还能帮助你构建能够针对帖子消费进行优化的集成方案。

1. 因为已认证用户只能管理由自己发起的会话，所以当不满足这一条件时，你的流程应尽早终止。
   * 先发起一次帖子查询请求。如果帖子 URL 无效，或该会话并非由用于认证的用户发起，则应尽早终止流程。
   * 这样一来，如果会话无法由已认证用户进行管理，你的应用就不必再发起最近搜索请求。
2. 在同一个请求中同时请求[用户和帖子字段](/zh/x-api/fundamentals/fields)，以避免发起多个独立请求。这种做法还能提升你的应用性能。
3. 在不需要时避免发起请求。此应用会在用户的浏览器中缓存回复的隐藏状态。这对较大的会话尤其有用，因为用户可能希望在之后继续进行审查工作，同时也有助于你的应用优化用于隐藏或取消隐藏回复的请求开销。
