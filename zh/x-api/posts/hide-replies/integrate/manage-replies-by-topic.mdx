<div id="manage-replies-by-topic">
  ### 按话题管理回复
</div>

通过 hide replies 端点，你可以构建集成应用，帮助个人和品牌让他们的对话始终围绕指定话题展开。本页展示了如何使用 hide replies 和 [recent search](/zh/x-api/posts/recent-search) 端点来管理一段对话。

Recent search 具备获取一段对话及其回复的功能，而 Post 负载会返回 [Post annotations](/zh/x-api/fundamentals/post-annotations)，帮助你理解每条帖子（Post）的上下文和话题，而不受语言影响。

应用的流程会包含用于展示和管理对话的控制项：

1. 它会请求用户授权读取他们的帖子并管理他们的回复。

2. 它会从一个 Post URL 中提取最近的一段对话，并检查该对话是否来自正在进行认证的用户。

3. 它会调用 recent search 端点来展示对话中的每条帖子。请求将包含一个会话 ID 搜索查询以及注解扩展，以根据 X 对该帖子的理解判断该帖子是否与体育相关。

4. 当用户选择隐藏某条回复时，它会调用 hide replies 来隐藏该回复。同时，它也会提供一种撤销此操作的方式，以确保用户始终保持控制权。 

5. 对于较长的对话，它会提供控制项以[在搜索结果中分页浏览](/zh/x-api/posts/search/integrate/paginate)。
    

<div id="optimize-for-the-user-and-for-usage">
  #### 为用户（以及使用效率）优化
</div>

你可以将流程设计为让用户掌控他们打算执行的任何操作。牢记这一原则还能帮助你构建能够优化帖子消费体验的集成。

1. 由于已认证用户只能管理他们自己发起的会话，当不满足这一条件时，你的流程应尽早终止。
   * 先发起一次初始帖子查询请求。如果帖子 URL 无效，或会话并非由已认证用户发起，则应尽早终止流程。
   * 这样一来，如果会话无法由已认证用户进行审核，你的应用就不必再发起最近搜索请求。
2. 在同一个请求中同时请求[用户和帖子字段](/zh/x-api/fundamentals/fields)，以避免发起多个独立请求。这种方式也有助于提升你的应用性能。
3. 仅在确有需要时再发起请求。此应用会在用户的浏览器中缓存回复的隐藏状态。这对规模较大的会话非常有用，用户可能希望在之后继续他们的审核工作，同时也有助于你的应用优化用于隐藏或取消隐藏回复的请求。
