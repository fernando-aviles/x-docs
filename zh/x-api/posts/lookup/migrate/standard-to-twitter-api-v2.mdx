<div id="standard-v11-compared-to-x-api-v2">
  ## 标准 v1.1 与 X API v2 的对比
</div>

如果你一直在使用标准 v1.1 的 GET statuses/show 和 GET statuses/lookup，本指南将帮助你了解标准 v1.1 与 X API v2 帖子查询端点之间的异同。

你可能也会对我们的[可视化数据格式迁移工具](/zh/x-api/migrate/data-format-migration)感兴趣，它可以帮助你快速查看 [X API v1.1 数据格式](/zh/x-api/fundamentals/data-dictionary)与 [X API v2 格式](/zh/x-api/fundamentals/data-dictionary) 之间的差异。

* **相似之处**
  * OAuth 1.0a 用户上下文
  * 单次请求的帖子数量上限
  * 对帖子编辑历史和元数据的支持

* **差异**
  * 端点 URL
  * App 和 Project 要求
  * 响应数据格式
  * 请求参数

<div id="similarities">
  ### 相似点
</div>

<div id="oauth-10a-user-context-authentication-method">
  #### OAuth 1.0a 用户上下文身份验证方法
</div>

标准端点支持 [OAuth 1.0a User Context](/zh/resources/fundamentals/authentication)，而新的 X API v2 帖子查找端点同时支持 OAuth 1.0a User Context 和 [OAuth 2.0 App-Only](/zh/resources/fundamentals/authentication)。因此，如果你之前在使用某个标准 v1.1 帖子查找端点，那么在迁移到 X API v2 版本时，可以继续使用相同的身份验证方法。

App-Only 身份验证通常是最容易上手的方式。要了解如何生成 App 访问令牌，请参阅 [这篇 OAuth 2.0 App-only 指南](/zh/resources/fundamentals/authentication)。

<div id="posts-per-request-limits">
  #### 每次请求的帖子数量限制
</div>

v1.1 的 [GET statuses/lookup](https://developer.x.com/en/docs/twitter-api/v1/tweets/post-and-engage/api-reference/get-statuses-lookup) 端点允许你在每个请求中指定最多 100 条帖子。GET /tweets 端点也适用相同限制。要在一次请求中指定完整的 100 条帖子，请将用逗号分隔的 [Post IDs](/zh/resources/fundamentals/x-ids) 列表作为查询参数传入 `ids`。

**对帖子编辑历史和元数据的支持**

这两个版本都会返回用于描述编辑历史的元数据。请参阅帖子查询 API 参考以及[编辑帖子基础知识页面](/zh/x-api/fundamentals/edit-posts)以获取更多详细信息。

<div id="differences">
  ### 差异
</div>

<div id="endpoint-urls">
  #### 端点 URL
</div>

* **标准版 v1.1 端点：**
  * `https://api.x.com/1.1/statuses/show`
  * `https://api.x.com/1.1/statuses/lookup`

* **X API v2 端点：**
  * `https://api.x.com/2/tweets`
  * `https://api.x.com/2/tweets/:id`

<div id="app-and-project-requirements">
  #### App 和 Project 要求
</div>

X API v2 端点在进行身份验证时，需要使用来自与某个 [Project](/zh/resources/fundamentals/developer-apps) 关联的 [developer App](/zh/resources/fundamentals/developer-apps) 的凭证。X API v1.1 端点可以使用来自 App 的凭证，或者来自与某个 Project 关联的 App 的凭证。

<div id="response-data-format">
  #### 响应数据格式
</div>

标准版 v1.1 与 X API v2 端点版本之间的一个显著差异，是在响应负载中如何选择字段。

对于标准端点，许多响应字段会默认返回，同时可以通过参数来指定额外的字段。

然而，在 X API v2 中，默认只返回帖子（Post）的 `id` 和 `text` 字段。额外的字段和对象需要使用 [fields](/zh/x-api/fundamentals/fields) 和 [expansions](/zh/x-api/fundamentals/expansions) 参数。扩展得到的字段会出现在响应中的 `includes` 对象内，可以通过匹配 ID 将它们与主帖子（Post）对象对应起来。

如需了解有关使用字段和 expansions 的更多信息，请参阅[如何使用字段和 expansions 的指南](/zh/x-api/fundamentals/data-dictionary)。[数据格式迁移指南](/zh/x-api/fundamentals/fields) 还将标准 v1.1 字段映射到更新的 v2 字段。

此外，X API v2 为对象引入了新的 JSON 设计，包括帖子（Post）和 [user](/zh/x-api/fundamentals/data-dictionary#user) 对象：

* 标准端点在 `statuses` 数组中返回帖子对象，而 X API v2 使用 `data` 数组。
* 在 X API v2 中，使用“转发推文（Retweeted Tweets）”和“引用推文（Quoted Tweets）”等术语来替代 “statuses” 这一术语。
* 新术语如 `like` 替代了 `favorites` 和 `favourites` 等术语。
* 在 X API v2 的负载中，不包含无值的属性（例如 `null`）。

X API v2 中的帖子（Post）对象包含如下新字段：

* `conversation_id`
* 两个新的 [annotations](/zh/x-api/fundamentals/post-annotations) 字段（`context` 和 `entities`）
* 新的 [metrics](/zh/x-api/fundamentals/metrics) 字段
* 用于表示谁可以回复某条帖子的 `reply_setting` 字段

<div id="request-parameters">
  #### 请求参数
</div>

以下标准 v1.1 请求参数在 X API v2 中有等价参数：

| Standard | X API v2 |
|:----------|:----------|
| `id`     | `ids`    |

某些标准 v1.1 参数在 X API v2 中**不**受支持：

| Standard            | Comment                                                                                                                      |
|:---------------------|:------------------------------------------------------------------------------------------------------------------------------|
| `tweet_mode`        | 已由字段和 expansions 功能取代。                                                                                              |
| `trim_user`         | 已由字段和 expansions 取代。请使用 `author_id` expansion 和 `user.fields` 获取用户数据。                                      |
| `include_my_retweet`| 为经过身份验证的用户所转发的帖子提供源帖子的 ID。                                                                             |
| `include_entities`  | 使用字段和 expansions 来控制响应载荷中的实体。                                                                                |
| `include_ext_alt_text` | 如果存在替代文本（alt text），则在媒体实体中添加 `ext_alt_text` 字段。                                                    |
| `include_card_uri`  | 在附加有广告卡片时添加 `card_uri`。                                                                                           |
| `map`               | 在 X API v2 中，对于不可用的帖子返回帖子 ID 和错误信息，而不是像 v1.1 中那样将字段设为 null。                                |

<div id="code-examples">
  ### 代码示例
</div>

以下示例展示了标准 v1.1 端点及其在 v2 中的等效端点。请将示例中的凭据替换为你的实际令牌。对于 v2 端点，令牌必须属于某个 [developer App](/zh/resources/fundamentals/developer-apps/overview) 所在的 [Project](/zh/resources/fundamentals/developer-apps/overview)。

v1.1 返回的响应数据与 v2 会有所不同。使用 v2 时，你可以通过 [fields](/zh/x-api/fundamentals/fields) 和 [expansions](/zh/x-api/fundamentals/expansions) 参数请求不同的字段。

**多条帖子查找：v1.1 `GET statuses/lookup` → v2 `GET /tweets`**

<CodeGroup dropdown>
  ```bash cURL (v1.1)
  curl --request GET \
    --url 'https://api.x.com/1.1/statuses/lookup.json?id=1460323737035677698%2C1460323743339741184' \
    --header 'Authorization: Bearer $ACCESS_TOKEN'
  ```

  ```bash cURL (v2)
  curl --request GET \
    --url 'https://api.x.com/2/tweets?ids=1460323737035677698%2C1460323743339741184&tweet.fields=created_at&expansions=author_id&user.fields=created_at' \
    --header 'Authorization: Bearer $ACCESS_TOKEN'
  ```

  ```python Python (v2)
  import requests

  bearer_token = "YOUR_BEARER_TOKEN"
  url = "https://api.x.com/2/tweets"

  params = {
      "ids": "1460323737035677698,1460323743339741184",
      "tweet.fields": "created_at",
      "expansions": "author_id",
      "user.fields": "created_at"
  }

  headers = {"Authorization": f"Bearer {bearer_token}"}
  response = requests.get(url, headers=headers, params=params)

  print(response.json())
  ```

  ```python Python SDK
  from xdk import Client

  client = Client(bearer_token="YOUR_BEARER_TOKEN")

  # 通过 ID 获取多条帖子，并指定字段和 expansions
  response = client.posts.get_posts(
      ids=["1460323737035677698", "1460323743339741184"],
      tweet_fields=["created_at"],
      expansions=["author_id"],
      user_fields=["created_at"]
  )

  for post in response.data:
      print(f"Post: {post.text}")
      print(f"Created at: {post.created_at}")
  ```

  ```javascript JavaScript SDK
  import { Client } from "@xdevplatform/xdk";

  const client = new Client({ bearerToken: "YOUR_BEARER_TOKEN" });

  // 通过 ID 获取多条帖子，并指定字段和 expansions
  const response = await client.posts.getPosts({
    ids: ["1460323737035677698", "1460323743339741184"],
    tweetFields: ["created_at"],
    expansions: ["author_id"],
    userFields: ["created_at"],
  });

  response.data?.forEach((post) => {
    console.log(`Post: ${post.text}`);
    console.log(`Created at: ${post.created_at}`);
  });
  ```
</CodeGroup>
