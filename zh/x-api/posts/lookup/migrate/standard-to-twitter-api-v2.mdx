<div id="standard-v11-compared-to-x-api-v2">
  ## 标准 v1.1 与 X API v2 的比较
</div>

如果你一直在使用标准 v1.1 的 GET statuses/show 和 GET statuses/lookup，本指南将帮助你了解标准版与 X API v2 帖子查找端点之间的相似点与差异。

你可能也会对我们的[可视化数据格式迁移工具](/zh/x-api/migrate/data-format-migration)感兴趣，它可以帮助你快速查看 [X API v1.1 数据格式](/zh/x-api/fundamentals/data-dictionary)与 [X API v2 格式](/zh/x-api/fundamentals/data-dictionary)之间的差异。

* **相似点**
  * OAuth 1.0a 用户上下文
  * 每次请求的帖子数量限制
  * 对帖子编辑历史和元数据的支持

* **差异**
  * 端点 URL
  * App 和 Project 要求
  * 响应数据格式
  * 请求参数

<div id="similarities">
  ### 相似之处
</div>

<div id="oauth-10a-user-context-authentication-method">
  #### OAuth 1.0a 用户上下文身份验证方法
</div>

标准端点支持 [OAuth 1.0a 用户上下文](/zh/resources/fundamentals/authentication)，而新的 X API v2 帖子查找端点同时支持 OAuth 1.0a 用户上下文和 [OAuth 2.0 App-Only](/zh/resources/fundamentals/authentication)。因此，如果你之前使用的是某个标准 v1.1 帖子查找端点，那么在迁移到 X API v2 版本时，可以继续使用相同的身份验证方法。

App-Only 身份验证通常是最容易上手的方式。要了解如何生成应用访问令牌，请参阅 [此 OAuth 2.0 App-Only 指南](/zh/resources/fundamentals/authentication)。

<div id="posts-per-request-limits">
  #### 每个请求的帖子数量限制
</div>

v1.1 的 [GET statuses/lookup](https://developer.x.com/en/docs/twitter-api/v1/tweets/post-and-engage/api-reference/get-statuses-lookup) 端点允许你在单个请求中最多指定 100 条帖子。`GET /tweets` 端点也遵循同样的限制。要指定完整的 100 条帖子，请将 `ids` 作为查询参数使用，并提供一个以逗号分隔的 [帖子 ID](/zh/resources/fundamentals/x-ids) 列表。

**对帖子编辑历史和元数据的支持**

两个版本都会提供描述任何编辑历史的元数据。请参阅 Post 查询 API 参考和[编辑帖子基础知识页面](/zh/x-api/fundamentals/edit-posts)以获取更多详细信息。

<div id="differences">
  ### 不同之处
</div>

<div id="endpoint-urls">
  #### 端点 URL
</div>

* **标准 v1.1 端点：**
  * `https://api.x.com/1.1/statuses/show`
  * `https://api.x.com/1.1/statuses/lookup`

* **X API v2 端点：**
  * `https://api.x.com/2/tweets`
  * `https://api.x.com/2/tweets/:id`

<div id="app-and-project-requirements">
  #### App 和 Project 要求
</div>

X API v2 端点在进行身份验证时，需要使用来自与 [Project](/zh/resources/fundamentals/developer-apps) 关联的 [开发者 App](/zh/resources/fundamentals/developer-apps) 的凭证。X API v1.1 端点可以使用来自独立 App 的凭证，或来自与某个 Project 关联的 App 的凭证。

<div id="response-data-format">
  #### 响应数据格式
</div>

标准 v1.1 与 X API v2 端点版本之间的一个重要区别在于如何在返回负载中选择字段。

对于标准端点，许多响应字段会默认返回，并可以通过参数指定其他字段。

然而，X API v2 默认只返回帖子 `id` 和 `text` 字段。额外的字段和对象需要使用 [fields](/zh/x-api/fundamentals/fields) 和 [expansions](/zh/x-api/fundamentals/expansions) 参数来请求。通过扩展返回的字段会包含在响应中的 `includes` 对象中，可以通过匹配 ID 将它们与主帖子对象进行关联。

若要了解有关使用字段和扩展的更多信息，请参阅[如何使用 fields 和 expansions 的指南](/zh/x-api/fundamentals/data-dictionary)。[数据格式迁移指南](/zh/x-api/fundamentals/fields) 还提供了标准 v1.1 字段到更新 v2 字段的映射关系。

此外，X API v2 为对象引入了新的 JSON 设计，包括帖子和 [user](/zh/x-api/fundamentals/data-dictionary#user) 对象：

* 标准端点在 `statuses` 数组中返回 Post 对象，而 X API v2 使用 `data` 数组。
* 在 X API v2 中，转推和引用的推文取代了 “statuses” 这一术语。
* 新术语（例如 `like`）取代了 `favorites` 和 `favourites` 等术语。
* 不带任何值的属性（例如 `null`）不会包含在 X API v2 的负载中。

X API v2 中的 Post 对象包含新的字段，例如：

* `conversation_id`
* 两个新的 [annotations](/zh/x-api/fundamentals/post-annotations) 字段（`context` 和 `entities`）
* 新的 [metrics](/zh/x-api/fundamentals/metrics) 字段
* `reply_setting` 字段，用于表示谁可以回复某条帖子

<div id="request-parameters">
  #### 请求参数
</div>

以下标准 v1.1 请求参数在 X API v2 中有对应项：

| Standard | X API v2 |
|:----------|:----------|
| `id`     | `ids`    |

某些标准 v1.1 参数在 X API v2 中**不**受支持：

| Standard            | Comment                                                                                                                      |
|:---------------------|:------------------------------------------------------------------------------------------------------------------------------|
| `tweet_mode`        | 已由字段和扩展功能取代。                                                                                                      |
| `trim_user`         | 已由字段和扩展取代。用户数据请使用 `author_id` 扩展和 `user.fields`。                                                        |
| `include_my_retweet`| 为已通过认证的用户返回其转推的帖子所对应的源帖子的 ID。                                                                      |
| `include_entities`  | 使用字段和扩展来控制有效负载中的实体。                                                                                       |
| `include_ext_alt_text` | 如果存在替代文本（alt text），则在媒体实体中添加 `ext_alt_text` 字段。                                                    |
| `include_card_uri`  | 当附加有广告卡片时添加 `card_uri`。                                                                                          |
| `map`               | 在 X API v2 中，对于不可用的帖子，返回帖子 ID 和错误信息，而不是像 v1.1 中那样将字段置为 null。                              |

<div id="code-examples">
  ### 代码示例
</div>

以下示例展示了标准 v1.1 端点及其在 v2 中的对应端点。请将示例中的凭证替换为你自己的令牌。对于 v2 端点，令牌必须属于某个 [developer App](/zh/resources/fundamentals/developer-apps/overview)，且该 App 位于某个 [Project](/zh/resources/fundamentals/developer-apps/overview) 中。

v1.1 的响应负载与 v2 会有所不同。在 v2 中，你可以使用 [fields](/zh/x-api/fundamentals/fields) 和 [expansions](/zh/x-api/fundamentals/expansions) 参数来请求不同的字段。

**多个帖子查找：v1.1 `GET statuses/lookup` → v2 `GET /tweets`**

<CodeGroup dropdown>
  ```bash cURL (v1.1)
  curl --request GET \
    --url 'https://api.x.com/1.1/statuses/lookup.json?id=1460323737035677698%2C1460323743339741184' \
    --header 'Authorization: Bearer $ACCESS_TOKEN'
  ```

  ```bash cURL (v2)
  curl --request GET \
    --url 'https://api.x.com/2/tweets?ids=1460323737035677698%2C1460323743339741184&tweet.fields=created_at&expansions=author_id&user.fields=created_at' \
    --header 'Authorization: Bearer $ACCESS_TOKEN'
  ```

  ```python Python (v2)
  import requests

  bearer_token = "YOUR_BEARER_TOKEN"
  url = "https://api.x.com/2/tweets"

  params = {
      "ids": "1460323737035677698,1460323743339741184",
      "tweet.fields": "created_at",
      "expansions": "author_id",
      "user.fields": "created_at"
  }

  headers = {"Authorization": f"Bearer {bearer_token}"}
  response = requests.get(url, headers=headers, params=params)

  print(response.json())
  ```

  ```python Python SDK
  from xdk import Client

  client = Client(bearer_token="YOUR_BEARER_TOKEN")

  # 使用字段和扩展，通过 ID 获取多个帖子
  response = client.posts.get_posts(
      ids=["1460323737035677698", "1460323743339741184"],
      tweet_fields=["created_at"],
      expansions=["author_id"],
      user_fields=["created_at"]
  )

  for post in response.data:
      print(f"Post: {post.text}")
      print(f"Created at: {post.created_at}")
  ```

  ```javascript JavaScript SDK
  import { Client } from "@xdevplatform/xdk";

  const client = new Client({ bearerToken: "YOUR_BEARER_TOKEN" });

  // 使用字段和扩展，通过 ID 获取多个帖子
  const response = await client.posts.getPosts({
    ids: ["1460323737035677698", "1460323743339741184"],
    tweetFields: ["created_at"],
    expansions: ["author_id"],
    userFields: ["created_at"],
  });

  response.data?.forEach((post) => {
    console.log(`Post: ${post.text}`);
    console.log(`Created at: ${post.created_at}`);
  });
  ```
</CodeGroup>
