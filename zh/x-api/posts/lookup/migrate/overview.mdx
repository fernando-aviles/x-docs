<div id="comparing-x-apis-posts-lookup-endpoints">
  ## 比较 X API 的帖子查找端点
</div>

v2 帖子查找端点替代了标准 v1.1 的 [GET statuses/lookup](https://developer.x.com/en/docs/twitter-api/v1/tweets/post-and-engage/api-reference/get-statuses-lookup) 和 [GET statuses/show](https://developer.x.com/en/docs/twitter-api/v1/tweets/post-and-engage/api-reference/get-statuses-show-id) 端点。本文适用于正从这些旧版端点迁移到 X API v2 的开发者。

***

<div id="endpoint-comparison-table">
  ## 端点对比表
</div>

| 描述 | Standard v1.1 | X API v2 |
|:-------------|:---------------|:----------|
| **支持的 HTTP 方法** | `GET` | `GET` |
| **主机域名** | `https://api.x.com` | `https://api.x.com` |
| **端点路径** | `/1.1/statuses/show.json`, `/1.1/statuses/lookup.json` | `/2/tweets` |
| **[身份验证](resources/fundamentals/authentication)** | OAuth 1.0a User Context | OAuth 1.0a User Context、OAuth 2.0 App-Only、OAuth 2.0 Authorization Code with PKCE |
| **帖子 [JSON 格式](/zh/x-api/fundamentals/data-dictionary)** | Standard v1.1 格式 | [X API v2 格式](/zh/x-api/fundamentals/data-dictionary)，由 `fields` 和 `expansions` 参数确定（与 v1.1 不向后兼容） |
| **支持选择特定的 [字段](/zh/x-api/fundamentals/data-dictionary)** |  | ✔ |
| **支持 [annotations](/zh/x-api/fundamentals/post-annotations) 字段** |  | ✔ |
| **支持新的 [metrics](/zh/x-api/fundamentals/metrics) 字段** |  | ✔ |
| **支持 `conversation_id` 字段** |  | ✔ |
| **提供帖子编辑历史记录** | ✔ | ✔ |
| **需要使用与 [Project](resources/fundamentals/projects) 关联的 [开发者 App](/zh/resources/fundamentals/developer-apps) 的凭证** |  | ✔ |

***

<div id="standard-v11-compared-to-x-api-v2">
  ## 标准版 v1.1 与 X API v2 的比较
</div>

如果你一直在使用标准版 v1.1 的 GET statuses/show 和 GET statuses/lookup，本指南将帮助你了解标准版与 X API v2 帖子查询端点之间的相似点和差异。

你可能也会对我们的[可视化数据格式迁移工具](/zh/x-api/migrate/data-format-migration)感兴趣，它可以帮助你快速查看 [X API v1.1 数据格式](/zh/x-api/fundamentals/data-dictionary)和 [X API v2 格式](/zh/x-api/fundamentals/data-dictionary)之间的差异。

* **相似之处**
  * OAuth 1.0a 用户上下文
  * 每个请求的帖子数量限制
  * 对帖子编辑历史和元数据的支持

* **差异之处**
  * 端点 URL
  * App 和 Project 要求
  * 响应数据格式
  * 请求参数

<div id="similarities">
  ### 相似之处
</div>

<div id="oauth-10a-user-context-authentication-method">
  #### OAuth 1.0a 用户上下文身份验证方法
</div>

标准端点支持 [OAuth 1.0a 用户上下文](/zh/resources/fundamentals/authentication)，而新的 X API v2 帖子查询端点同时支持 OAuth 1.0a 用户上下文和 [OAuth 2.0 App-Only](/zh/resources/fundamentals/authentication)。因此，如果你之前使用的是某个标准 v1.1 帖子查询端点，那么在迁移到 X API v2 版本时，可以继续使用相同的身份验证方法。

App-Only 身份验证通常是最容易上手的方式。要了解如何生成应用访问令牌，请参阅[这篇 OAuth 2.0 App-only 指南](/zh/resources/fundamentals/authentication)。

<div id="posts-per-request-limits">
  #### 每次请求的帖子数量限制
</div>

v1.1 的 [GET statuses/lookup](https://developer.x.com/en/docs/twitter-api/v1/tweets/post-and-engage/api-reference/get-statuses-lookup) 端点允许你在每次请求中最多指定 100 条帖子。`GET /tweets` 端点同样适用。要指定完整的 100 条帖子，请在查询参数中使用 `ids` 参数，并提供一个以逗号分隔的 [帖子 ID](/zh/resources/fundamentals/x-ids) 列表。

**对帖子编辑历史和元数据的支持**

这两个版本都提供描述任何编辑历史的元数据。查看帖子查询 API 参考以及[帖子编辑基础知识页面](/zh/x-api/fundamentals/edit-posts)以获取更多详细信息。

<div id="differences">
  ### 差异
</div>

<div id="endpoint-urls">
  #### 端点 URL
</div>

* **标准 v1.1 端点：**
  * `https://api.x.com/1.1/statuses/show`
  * `https://api.x.com/1.1/statuses/lookup`

* **X API v2 端点：**
  * `https://api.x.com/2/tweets`
  * `https://api.x.com/2/tweets/:id`

<div id="app-and-project-requirements">
  #### App 和 Project 要求
</div>

X API v2 端点要求使用与 [Project](/zh/resources/fundamentals/developer-apps) 关联的 [开发者 App](/zh/resources/fundamentals/developer-apps) 的凭证进行身份验证。X API v1.1 端点可以使用来自独立 App 的凭证，或来自隶属于某个 Project 的 App 的凭证。

<div id="response-data-format">
  #### 响应数据格式
</div>

标准版 v1.1 与 X API v2 端点版本之间的一个重要区别，是在负载中如何选择字段。

对于标准端点，许多响应字段会默认返回，并可以通过参数来指定额外的字段。

然而，在 X API v2 中，默认只返回帖子 `id` 和 `text` 字段。要请求更多字段和对象，需要使用 [字段](/zh/x-api/fundamentals/fields) 和 [扩展](/zh/x-api/fundamentals/expansions) 参数。扩展得到的字段会在响应中的 `includes` 对象中返回，并可通过匹配 ID 将其与主要的 Post 对象对应起来。

有关如何使用字段和扩展的更多信息，请参阅[如何使用字段和扩展的指南](/zh/x-api/fundamentals/data-dictionary)。[数据格式迁移指南](/zh/x-api/fundamentals/fields)还将标准版 v1.1 的字段映射到新的 v2 字段。

此外，X API v2 为对象（包括 Post 和 [user](/zh/x-api/fundamentals/fields) 对象）引入了新的 JSON 设计：

* 标准端点在 `statuses` 数组中返回 Post 对象，而 X API v2 使用 `data` 数组。
* 在 X API v2 中，使用 “Retweeted” 和 “Quoted Tweets” 等术语来取代 “statuses” 术语。
* 新术语（例如 `like`）取代了 `favorites` 和 `favourites` 等术语。
* 没有值的属性（例如为 `null`）不会包含在 X API v2 的负载中。

X API v2 中的 Post 对象包含如下新字段：

* `conversation_id`
* 两个新的 [annotations](/zh/x-api/fundamentals/post-annotations) 字段（`context` 和 `entities`）
* 新的 [metrics](/zh/x-api/fundamentals/metrics) 字段
* `reply_setting` 字段，用于表示谁可以回复指定的帖子

<div id="request-parameters">
  #### 请求参数
</div>

以下标准 v1.1 请求参数在 X API v2 中有对应项：

| 标准 v1.1 | X API v2 |
|:----------|:----------|
| `id`     | `ids`    |

某些标准 v1.1 参数在 X API v2 中**不**受支持：

| 标准 v1.1            | 说明                                                                                                                      |
|:---------------------|:------------------------------------------------------------------------------------------------------------------------------|
| `tweet_mode`        | 由字段和扩展功能取代。                                                                             |
| `trim_user`         | 由字段和扩展取代。请对用户数据使用 `author_id` 扩展和 `user.fields`。                               |
| `include_my_retweet`| 返回经身份验证用户所转发帖子的源帖子 ID。                                          |
| `include_entities`  | 使用字段和扩展来控制响应负载中的实体。                                                               |
| `include_ext_alt_text` | 如果存在替代文本，则在媒体实体中添加 `ext_alt_text` 字段。                                                         |
| `include_card_uri`  | 当附加广告卡片时添加 `card_uri`。                                                                               |
| `map`               | 对于在 X API v2 中不可用的帖子，返回帖子 ID 和错误消息，而不是像 v1.1 中那样将相关字段置为空。            |

<div id="curl-requests">
  ### cURL 请求
</div>

以下 cURL 请求展示了标准 v1.1 端点及其在 v2 中的对应端点。将请求头中的 `ACCESS_TOKEN` 替换为你的应用访问令牌。对于 v2 端点，此令牌必须属于某个 [developer App](/zh/resources/fundamentals/developer-apps/overview)，且该 App 位于某个 [Project](/zh/resources/fundamentals/developer-apps) 中。

v1.1 的响应负载会与 v2 不同。使用 v2 时，你可以通过 [fields](/zh/x-api/fundamentals/fields) 和 [expansions](/zh/x-api/fundamentals/expansions) 参数请求不同的字段。

**标准 v1.1 `GET statuses/lookup` 和 v2 `GET /tweets` 端点**

```bash
curl --request GET \
  --url 'https://api.x.com/1.1/statuses/lookup.json?id=1460323737035677698%2C1460323743339741184' \
  --header 'Authorization: Bearer $ACCESS_TOKEN'
```

```
  curl --request GET \
  --url 'https://api.x.com/2/tweets?ids=1460323737035677698%2C1460323743339741184&tweet.fields=created_at&expansions=author_id&user.fields=created_at' \
  --header 'Authorization: Bearer $ACCESS_TOKEN'
```

**标准 v1.1 `GET statuses/show/:id` 和 v2 `GET /tweets/:id` 端点**

```
curl --request GET \
  --url 'https://api.x.com/1.1/statuses/show.json?id=1460323737035677698' \
  --header 'Authorization: Bearer $ACCESS_TOKEN'
```

```
curl --request GET \
  --url 'https://api.x.com/2/tweets/1460323737035677698?tweet.fields=created_at&expansions=author_id&user.fields=created_at' \
  --header 'Authorization: Bearer $ACCESS_TOKEN'
```
