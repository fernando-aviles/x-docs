<div id="enterprise-compared-to-x-api-v2">
  ### Enterprise 与 X API v2 的比较
</div>

**相似之处**

* 粒度
* 分页
* 时区

**差异**

* 端点 URL
* 应用和 Project 的要求
* 可用时间范围
* 响应数据格式
* HTTP 方法
* 请求中的时间格式
* 请求参数
* 过滤运算符

<div id="similarities">
  #### 相似点
</div>

**粒度**

虽然用于选择返回 data 粒度的参数不同（企业版使用 `bucket`，v2 版本使用 `granularity`），但该参数可接受的取值相同，默认行为也一致：

* `day`
* `hour`（默认）
* `minute`

**分页**

虽然 v2 具有额外的分页功能（新增了分页参数，允许你使用带有 `since_id` 和 `until_id` 的帖子 ID 进行导航），但企业版和 v2 都允许你按时间分页（企业版使用 `fromDate` 和 `toDate`，v2 使用 `start_time` 和 `end_time`）。

如果你使用的是企业版，将使用 `next` 参数进行分页，下一页的 token 字段名为 `next`，并位于响应的根级。

如果你使用的是 v2，可以使用 `next_token` 或 `pagination_token` 参数进行分页，下一页的 token 将位于响应中的 `meta.next_token`。

**时区**

如分页部分所述，你可以在企业版和 v2 中使用时间在不同 data 页之间进行跳转。在这两种情况下，使用这些参数时，你都将使用 UTC 作为时区。

<div id="differences">
  #### 差异
</div>

**Endpoint URL**

* 企业级 endpoint：
  * 30 天 - `http://gnip-api.x.com/search/30day/accounts/:account_name/:label/counts.json`
  * 全量归档 - `http://gnip-api.x.com/search/fullarchive/accounts/:account_name/:label/counts.json`
* X API v2 endpoint
  * 最近（7 天）- `https://api.x.com/2/tweets/counts/recent`
  * 全量归档 - `https://api.x.com/2/tweets/counts/all`

**App 和 Project 要求**

X API v2 endpoint 要求你在对请求进行认证时，使用与某个 [developer App](/zh/resources/fundamentals/developer-apps) 关联的 [Project](/zh/resources/fundamentals/developer-apps) 中的凭证。所有 X API v1.1 endpoint 都可以使用来自 App，或与 Project 关联的 App 的凭证。
 

**可用时间区间**

企业级 API 和 X API v2 都提供了 endpoint，可用于检索全量归档中的帖子数量数据。

但是，X API v2 不像企业级 API 那样提供 30 天时间区间的 endpoint。取而代之的是，它提供前文提到的全量归档端点，或 7 天时间区间端点，这与 [v2 Search Posts endpoint](/zh/x-api/posts/search/introduction) 保持一致。
 

**响应数据格式**

通过企业级 API 和 X API v2 返回的数据格式存在一些细微差异：

* 企业级的计数数据位于 `results` 对象中，而 v2 的计数数据位于 `data` 对象中。
* 企业级的计数字段名称为 `timePeriod`（开始时间）和 `count`，而 v2 将时间区间拆分为 `start` 和 `end` 字段（使用与企业级不同的日期/时间格式，详见请求时间格式），并将 `count` 字段重命名为 `tweet_count`。
* 企业级的元数据在根级别包含 `totalCount`、`next` 和 `requestParameters` 对象。而 v2 不再包含 `requestParameters` 对象，并将如下字段移动/重命名到位于根级别的 `meta` 对象中：`total_tweet_count` 和 `next_token`。
   

**HTTP 方法**

企业级版本的 API 允许你通过两种方式发送请求：使用带 JSON body 的 POST HTTP 方法，或使用带查询字符串的 GET HTTP 方法。

v2 只允许你使用带查询字符串的 GET HTTP 方法。
 

**请求时间格式**

该 endpoint 的企业级版本在分页参数以及 `timePeriod` 响应字段中使用如下日期/时间格式：`YYYYMMDDHHmm`

v2 endpoint 在分页参数以及 `start` 和 `end` 响应字段中使用 ISO 8601/RFC 3339 日期/时间格式：`YYYY-MM-DDTHH:mm:ssZ`

**请求参数**

下表列出了企业级和 X API v2 的请求参数：

| 企业级 | Search Posts v2 |
| :--- | :--- |
| query | query |
| bucket | granularity |
| fromDate (YYMMDDHHmm) | start&#95;time (YYYY-MM-DDTHH:mm:ssZ) |
| toDate (YYMMDDHHmm) | end&#95;time (YYYY-MM-DDTHH:mm:ssZ) |
|     | since&#95;id |
|     | until&#95;id |
| next | next&#95;token 和 pagination&#95;token |

**过滤运算符**

虽然企业级和 X API v2 之间的大多数运算符是相同的，但在运算符可用性方面存在一些差异，并且有一些仅在 X API v2 版本中引入的新运算符。

要查看适用于 X API v2、企业级，甚至 premium 的完整运算符表，请访问 [Post counts 迁移概览页面](/zh/x-api/posts/counts/migrate/overview)。
