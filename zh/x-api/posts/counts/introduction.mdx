Post 计数端点会按时间返回与查询匹配的帖子总量，但不会返回帖子本身。使用这些端点来分析趋势、了解讨论规模，并在搜索之前优化查询。

<div id="endpoints">
  ## 端点
</div>

| Endpoint | 描述 | 访问权限 |
|:---------|:------------|:-------|
| GET [`/2/tweets/counts/recent`](/zh/x-api/posts/get-count-of-recent-posts) | 统计最近 7 天的帖子数量 | 所有开发者 |
| GET [`/2/tweets/counts/all`](/zh/x-api/posts/get-count-of-all-posts) | 统计完整归档中的帖子数量 | 按使用量计费，企业版 |

***

<div id="granularity-options">
  ## 粒度选项
</div>

使用 `granularity` 参数指定计数的分组方式：

| Granularity | 说明 | 使用场景 |
|:------------|:------------|:---------|
| `minute` | 按分钟计数 | 实时监控 |
| `hour` | 按小时计数（默认） | 每日分析 |
| `day` | 按天计数 | 长期趋势 |

***

<div id="recent-counts">
  ## 近期计数
</div>

统计**最近 7 天**内的帖子数量。对所有开发者开放。

<div id="features">
  ### 功能
</div>

* 按分钟、小时或天粒度统计计数
* 与最近搜索相同的查询运算符
* 查询字符串最长 512 个字符

<div id="example-response">
  ### 响应示例
</div>

```json
{
  "data": [
    { "start": "2024-01-15T00:00:00.000Z", "end": "2024-01-15T01:00:00.000Z", "tweet_count": 1523 },
    { "start": "2024-01-15T01:00:00.000Z", "end": "2024-01-15T02:00:00.000Z", "tweet_count": 1247 },
    { "start": "2024-01-15T02:00:00.000Z", "end": "2024-01-15T03:00:00.000Z", "tweet_count": 892 }
  ],
  "meta": {
    "total_tweet_count": 3662
  }
}
```

<div id="full-archive-counts">
  ## 全量归档计数
</div>

从**全量归档**中统计自 2006 年起的帖子数量。

<Note>
  全量归档计数功能适用于按次付费和企业级客户。
</Note>

<div id="features">
  ### 功能
</div>

* 统计任意时间范围内的历史帖子数量
* 支持所有查询运算符
* 查询长度上限为 1,024 个字符（Enterprise 版为 4,096 个字符）

<div id="pagination">
  ### 分页
</div>

结果按每个响应覆盖 31 天的时间范围进行分页：

* **按天粒度**：每页 31 天
* **按小时粒度**：每页 744 小时（31 天）
* **按分钟粒度**：每页 44,640 分钟（31 天）

<div id="important-notes">
  ## 重要说明
</div>

<Note>
  **计数结果与搜索结果的差异**

  计数结果可能与搜索结果不完全一致。搜索端点会应用额外的合规性过滤，而计数端点不会执行这些过滤。
</Note>
