<div id="comparing-x-apis-manage-posts-endpoints">
  ## 比较 X API 的帖子管理端点
</div>

v2 帖子管理端点将取代标准 v1.1 的 [POST statuses/update](https://developer.x.com/en/docs/twitter-api/v1/tweets/post-and-engage/api-reference/post-statuses-update) 和 [POST statuses/destroy/:id](https://developer.x.com/en/docs/twitter-api/v1/tweets/post-and-engage/api-reference/post-statuses-destroy-id) 端点。如果你有使用 v1.1 帖子管理端点的代码、App 或工具，并且正在考虑迁移到较新的 X API v2 端点，那么这一系列指南就是为你准备的。

下表比较了标准 v1.1 和 X API v2 的帖子管理端点：

<div id="create-a-post">
  ### 创建帖子
</div>

| 描述 | 标准 v1.1 | X API v2 |
| :--- | :--- | :--- |
| 支持的 HTTP 方法 | POST | POST |
| 主机域名 | https://api.x.com | https://api.x.com |
| 端点路径 | /1.1/statuses/update.json | /2/tweets |
| [Authentication](/zh/resources/fundamentals/authentication) | OAuth 1.0a 用户上下文 | OAuth 1.0a 用户上下文<br /><br />OAuth 2.0 授权码（Authorization Code）配合 PKCE |
| 默认请求[速率限制](/zh/x-api/fundamentals/rate-limits) | 无<br /><br />每位用户在每个 App 中每 3 小时内最多 300 次请求。与 v1.1 的 POST Retweets 端点共享。 | 每位用户每 15 分钟最多 200 次请求<br /><br />每位用户在每个 App 中每 3 小时内最多 300 次请求。与 v2 的 POST Retweets 端点共享。 |
| 是否需要使用与某个 [Project](/zh/resources/fundamentals/developer-apps) 关联的 [developer App](/zh/resources/fundamentals/developer-apps) 的凭证 |     | ✔   |

<div id="delete-a-post">
  ### 删除帖子
</div>

| 描述 | 标准 v1.1 | X API v2 |
| :--- | :--- | :--- |
| 支持的 HTTP 方法 | POST | DELETE |
| 主机域名 | https://api.x.com | https://api.x.com |
| 端点路径 | /1.1/statuses/destroy/:id.json | /2/tweets/:id |
| [认证](/zh/resources/fundamentals/authentication) | OAuth 1.0a 用户上下文 | OAuth 1.0a 用户上下文<br /><br />OAuth 2.0 使用 PKCE 的授权码授权 |
| 默认请求[速率限制](/zh/x-api/fundamentals/rate-limits) | 无 | 每位用户每 15 分钟 50 次请求 |
| 需要使用与某个[项目](/zh/resources/fundamentals/developer-apps)关联的[开发者 App](/zh/resources/fundamentals/developer-apps)的凭证 |     | ✔   |
