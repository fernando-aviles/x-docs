<div id="enterprise-compared-to-x-api-v2">
  ### Enterprise 与 X API v2 的对比
</div>

**相似之处**

* 分页
* 时区
* 对帖子编辑历史和元数据的支持

**差异**

* 端点 URL
* 对 App 和 Project 的要求
* 可用时间范围
* 响应数据格式
* HTTP 方法
* 请求中的时间格式
* 请求参数
* 过滤运算符

<div id="similarities">
  #### 相似之处
</div>

**分页**

虽然 v2 具有额外的分页功能（新的分页参数允许你使用帖子 ID 通过 `since_id` 和 `until_id` 进行导航），但 Enterprise 和 v2 都允许你使用时间进行分页（Enterprise 使用 `fromDate` 和 `toDate`，v2 使用 `start_time` 和 `end_time`）。

**时区**

如分页部分所述，你可以在 Enterprise 和 v2 中都使用时间来浏览不同的数据页。在这两种情况下，使用这些参数时，你将使用 UTC 作为时区。

**对帖子编辑历史和元数据的支持**

这两个版本都提供描述任何编辑历史的元数据。请参阅 [搜索 API 参考](/zh/x-api/posts/recent-search) 和 [帖子编辑基础页面](/zh/x-api/fundamentals/edit-posts) 以了解更多详细信息。 

<div id="differences">
  #### 差异
</div>

**Endpoint URLs**

* 企业版 endpoints：
  * 30 天 - `http://gnip-api.x.com/search/30day/accounts/:account_name/:label.json`
  * 全量归档（Full-archive）- `http://gnip-api.x.com/search/fullarchive/accounts/:account_name/:label.json`
* X API v2 endpoints
  * 最近（7 天）- `https://api.x.com/2/tweets/search/recent`
  * 全量归档（Full-archive）- `https://api.x.com/2/tweets/search/all`

**App 和 Project 要求**

X API v2 的 endpoints 要求你在请求认证时使用来自某个 Project 的凭证。所有 X API v1.1 的 endpoints 可以使用来自 Apps 或与 App 关联的 Apps 的凭证。
 

**可用时间范围**

企业版 API 和 X API v2 都提供了 endpoints，让你可以为完整归档（full-archive）的帖子获取经过过滤的帖子 data。

但是，X API v2 并不像企业版 API 那样提供 30 天时间范围的 endpoint。它提供的是前面提到的全量归档，或者 7 天时间范围，这与 Native Enriched 到 v2 以及 [Activity Streams 到 v2](/zh/x-api/migrate/data-format-migration#migrating-from-activity-streams-data-format-to-v2) 的迁移方案相一致，可以帮助你将企业版字段映射到较新的 v2 字段。本指南还将为你提供在 v2 请求中需要传递的具体扩展和字段参数，以返回特定字段。
 

**响应数据格式**

[企业版响应格式](https://developer.x.com/x-api/enterprise-gnip-2.0/fundamentals/data-dictionary)和 [X API v2 的格式](/zh/x-api/fundamentals/data-dictionary) 之间最大的差异之一，是你如何选择在负载中返回哪些字段。

对于企业版 Search API，你默认会收到许多响应字段，然后可以选择使用参数来指定哪些字段或字段集应在负载中返回。

X API v2 版本默认只返回帖子 `id` 和 `text` 字段。若要请求任何额外字段或对象，你需要使用 [fields](/zh/x-api/fundamentals/fields) 和 [expansions](/zh/x-api/fundamentals/expansions) 参数。从这些 endpoints 请求的任何帖子字段都会返回在主帖子对象中。任何展开的用户、媒体、投票或地点对象及其字段则会返回在响应中的 `includes` 对象内。然后你可以通过匹配帖子对象和展开对象中出现的 ID，将这些展开对象重新关联回帖子对象。

我们建议你在各自的指南中进一步了解这些新参数，或者阅读我们的[如何使用 fields 和 expansions](/zh/x-api/fundamentals/data-dictionary#how-to-use-fields-and-expansions) 指南。

除了更改如何请求某些字段之外，X API v2 还为 API 返回的对象（包括 [Post](/zh/x-api/fundamentals/data-dictionary#tweet) 和 [user](/zh/x-api/fundamentals/data-dictionary#user) 对象）引入了新的 JSON 设计。

* 在 JSON 根级别，标准 endpoints 在 `statuses` 数组中返回 Post 对象，而 X API v2 返回的是 `data` 数组。
* X API v2 的 JSON 不再引用被转发（Retweeted）和被引用（Quoted）的“statuses”，而是引用被转发和被引用的 Tweets。许多旧的和已弃用字段（例如 `contributors` 和 `user.translator_type`）正在被移除。
* X API v2 不再在帖子对象中使用 `favorites`，在用户对象中使用 `favourites`，而是统一使用 like 这一术语。
* X 采用的约定是，对于没有取值的 JSON 值（例如 `null`），不会写入到负载中。Post 和 user 属性只有在具有非 null 值时才会被包含。
   

我们还在 Post 对象中引入了一组新字段，包括以下内容：

* 一个 [conversation&#95;id](/zh/x-api/fundamentals/conversation-id) 字段
* 两个新的 [annotations](/zh/x-api/fundamentals/post-annotations) 字段，包括 context 和 entities
* 若干新的 [metrics](/zh/x-api/fundamentals/metrics) 字段
* 一个新的 `reply_setting` 字段，用于指示谁可以回复特定帖子

最后还有一点说明。高级版响应在根级别包含一个 `requestParameters` 对象，其中包含你在请求中所包含的参数。v2 版本则在根级别包含一个 `meta` 对象，其中包含 `newest_id`、`oldest_id`、`result_count`，以及在存在额外结果页时的 `next_token`。

**HTTP methods**

企业版 API 允许你通过两种方式发起请求：使用带 JSON 请求体的 HTTP POST 方法，或使用带查询字符串的 HTTP GET 方法。

v2 仅允许你使用带查询字符串的 HTTP GET 方法。
 

**请求时间格式**

此端点的企业版在分页参数和 `timePeriod` 响应字段中都使用以下日期/时间格式：`YYYYMMDDHHmm`

v2 端点在分页参数以及 `start` 和 `end` 响应字段中使用 ISO 8601/RFC 3339 日期/时间格式：`YYYY-MM-DDTHH:mm:ssZ
 `

**请求参数**

下表列出了企业版和 X API v2 的请求参数：

| Enterprise | Search Posts v2 |
| :--- | :--- |
| query | query |
| maxResults | max&#95;results |
| fromDate (YYMMDDHHmm) | start&#95;time (YYYY-MM-DDTHH:mm:ssZ) |
| toDate (YYMMDDHHmm) | end&#95;time (YYYY-MM-DDTHH:mm:ssZ) |
|     | since&#95;id |
|     | until&#95;id |
| next | next&#95;token or pagination&#95;token |

**过滤运算符**

虽然企业版与 X API v2 之间的大多数运算符相同，但在运算符可用性方面存在一些差异，并且在 X API v2 版本中还引入了一些新的运算符。

若要查看适用于 X API v2、企业版，以及高级版和标准版的完整运算符列表，请访问 [Search Posts 迁移概览页面](/zh/x-api/posts/search/migrate/overview)。
