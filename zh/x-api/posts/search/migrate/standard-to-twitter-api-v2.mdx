<div id="standard-v11-compared-to-x-api-v2">
  ### 标准 v1.1 与 X API v2 的比较
</div>

如果你一直在使用 v1.1 的 [search/posts](/zh/x-api/posts/search/introduction)，本指南的目标是帮助你了解标准版与 X API v2 搜索帖子端点之间的相似点和差异。

* **相似点**
  * OAuth 1.0a 用户上下文 和 OAuth 2.0 仅应用模式（App-only）
  * 支持帖子编辑历史和元数据。 
* **差异**
  * 端点 URL

  * 应用和 Project 的要求

  * 响应数据格式

  * 请求参数

  * 新的查询运算符

  * AND / OR 运算符的优先级 

<div id="similarities">
  #### 相似之处
</div>

**OAuth 1.0a 用户上下文和 OAuth 2.0 仅应用程序身份验证**

v1.1 的 search/posts 端点和 X API v2 的 recent search 端点都支持 [OAuth 1.0a 用户上下文](/zh/resources/fundamentals/authentication) 和 [OAuth 2.0 仅应用程序](/zh/resources/fundamentals/authentication#oauth-2-0) 身份验证。 

因此，如果你之前使用的是标准的 v1.1 search 端点，在迁移到 X API v2 版本时，可以继续使用相同的身份验证方式。 

根据你选择的身份验证库/包，仅应用程序身份验证通常是最容易上手的方式，并且只需要通过一个简单的请求头就可以设置。要了解如何生成应用访问令牌，请参阅 [OAuth 2.0 仅应用程序指南](/zh/resources/fundamentals/authentication#bearer-token-also-known-as-app-only)。 

如果你希望利用 X API v2 端点来获取私有或广告指标，则需要使用 OAuth 1.0a 用户上下文，并传递与发布该帖子（即你希望获取其指标的帖子）的用户相关联的用户访问令牌。 

**对帖子编辑历史和元数据的支持**

这两个版本都提供描述任何编辑历史的元数据。请查看 [搜索 API 参考](/zh/x-api/posts/recent-search) 和 [帖子编辑基础知识页面](/zh/x-api/fundamentals/edit-posts) 以了解更多详情。 

<div id="differences">
  #### 差异
</div>

**Endpoint URLs（端点 URL）**

* 标准 v1.1 端点：
  * https://api.x.com/1.1/search/tweets

* X API v2 端点：
  * https://api.x.com/2/tweets/search/recent
     

**App 和 Project 要求**

在对请求进行认证时，X API v2 端点要求你使用与某个 [Project](/zh/resources/fundamentals/developer-apps) 关联的 [开发者 App](/zh/resources/fundamentals/developer-apps) 的凭证。所有 X API v1.1 端点都可以使用来自 App 的凭证，或来自与某个 App 关联的 App 的凭证。 

**响应数据格式**

标准 v1.1 与 X API v2 端点版本之间最大的差异之一，是你如何选择在负载中返回哪些字段。

对于标准端点，你会默认收到许多响应字段，然后可以选择使用参数来指定哪些字段或字段集应在负载中返回。

X API v2 版本默认只返回帖子 id 和 text 字段。要请求任何其他字段或对象，你需要使用 [fields](/zh/x-api/fundamentals/fields) 和 [expansions](/zh/x-api/fundamentals/expansions) 参数。你从这些端点请求的任何帖子字段都会在主 Post 对象中返回。任何扩展的用户、媒体、投票或地点对象及其字段都会在响应中的 includes 对象中返回。然后，你可以通过匹配帖子对象和扩展对象中出现的 ID，将任何扩展对象重新关联回帖子对象。 

我们建议你在各自的指南中进一步了解这些新参数，或者查看我们的[如何使用 fields 和 expansions](/zh/x-api/fundamentals/data-dictionary#how-to-use-fields-and-expansions) 指南。 

我们还编写了一个[数据格式迁移指南](/zh/x-api/migrate/data-format-migration#migrating-from-standard-v1-1s-data-format-to-v2)，可以帮助你将标准 v1.1 字段映射到较新的 v2 字段。该指南还会为你提供在 v2 请求中需要携带的具体扩展和字段参数，以返回特定字段。 
 

除了你请求某些字段的方式发生变化之外，X API v2 还为 API 返回的对象引入了新的 JSON 设计，包括 [Post](/zh/x-api/fundamentals/data-dictionary#tweet) 和 [user](/zh/x-api/fundamentals/data-dictionary#user) 对象。

* 在 JSON 根级别，标准端点在 statuses 数组中返回 Post 对象，而 X API v2 则在 data 数组中返回 Post 对象。 
* X API v2 JSON 不再引用“转发（Retweeted）和引用（Quoted）状态（statuses）”，而是引用转发和引用推文（Retweeted and Quoted Tweets）。许多旧版和已弃用的字段（例如 contributors 和 user.translator&#95;type）将被移除。 
* X API v2 不再在 Post 对象中使用 favorites、在 user 对象中使用 favourites，而是统一使用术语 like。 
* X 采用这样的约定：没有值的 JSON 字段（例如 null）不会写入负载。Post 和 user 属性只有在其值非 null 时才会被包含。 
   

我们还在 [Post 对象](/zh/x-api/fundamentals/data-dictionary#tweet) 中引入了一组新的字段，包括：

* 一个 [conversation&#95;id](/zh/x-api/fundamentals/conversation-id) 字段
* 两个新的 [annotations](/zh/x-api/fundamentals/post-annotations) 字段，包括 context 和 entities
* 若干新的 [metrics](/zh/x-api/fundamentals/metrics) 字段 
* 一个新的 reply&#95;setting 字段，用于指示谁可以回复某条帖子

<div id="request-parameters">
  #### 请求参数
</div>

以下标准版 v1.1 的请求参数在 X API v2 中有对应项：

| 标准搜索 v1.1 | 搜索帖子 v2 |
| :--- | :--- |
| q   | query |
|     | start&#95;time (YYYY-MM-DDTHH:mm:ssZ) |
| until (YYYY-MM-DD) | end&#95;time (YYYY-MM-DDTHH:mm:ssZ) |
| since&#95;id | since&#95;id |
| max&#95;id | until&#95;id |
| count | max&#95;results |
| 响应中提供 search&#95;metadata.next&#95;results | next&#95;token |

还有一组标准搜索帖子的请求参数在 X API v2 中**不**受支持：

| **标准 v1.1 参数** | **详细信息** |
| :--- | :--- |
| geocode | 搜索帖子支持用于基于位置查询的地理运算符。 |
| locale | 在标准搜索中，该参数用于指定查询的语言，但从未完全实现。 |
| lang | 搜索帖子端点提供 lang 查询运算符，用于匹配感兴趣的语言。 |
| include&#95;entities | 帖子实体始终会被包含。 |
| result&#95;type | 搜索帖子端点会返回所有匹配的帖子，而不考虑互动程度。 |
| extended | X API v2 自底层起即构建为支持最多 280 字符的帖子。在 v2 中，不再存在“extended”帖子这一概念。 |

下面是一个示例请求，用于展示标准请求与搜索帖子请求之间的差异：

|     |     |
| :--- | :--- |
| **标准 v1.1** | **X API v2** |
| https://api.x.com/1.1/search/tweets.json?q=snow&amp;count=50 | https://api.x.com/2/tweets/search/recent?query=snow&amp;max&#95;results=50 |

这两个请求都会返回包含关键字 snow 的最新 50 条帖子。v2 请求会返回匹配帖子默认的 id 和 text 字段。下面是一个示例，展示如何指定额外的帖子和用户字段以包含在 JSON 负载中：

|     |
| :--- |
| **X API v2** |
| https://api.x.com/2/tweets/search/recent?query=snow&amp;max&#95;results=50&amp;tweet.fields=id,created&#95;at,author&#95;id,text,source,entities,attachments&amp;user.fields=id,name,username,description |

**新的查询运算符**

搜索帖子引入了新的运算符，以支持两个新的 X API v2 功能： 

* **[Conversation IDs](/zh/x-api/fundamentals/conversation-id)** - 随着对话在 X 上展开，会话 ID 可用于标记属于该对话的帖子。对话中的所有帖子其 conversation&#95;id 都会被设置为开启该对话的帖子 ID。 
  * `conversation_id:`
* **[X Annotations](/zh/x-api/fundamentals/post-annotations)** 为帖子提供上下文信息，包括实体和上下文注解。实体由人物、地点、产品和组织构成。上下文是领域或主题，被识别出的实体属于这些领域或主题。例如，在一条帖子中提到的人，可能具有一个上下文，用于指示他们是运动员、演员还是政治人物。  
  * context: 匹配已用感兴趣上下文进行注解的帖子。 
  * entity: 匹配已用感兴趣实体进行注解的帖子。 

     

<div id="and-or-operator-precedence">
  #### AND / OR 运算符优先级
</div>

构建搜索查询的基本方式是使用 OR 和 AND 进行逻辑组合。标准搜索 API 会先应用 OR 再应用 AND，而 Search Posts 端点（以及高级版和企业版）则是先应用 AND 再应用 OR。在这两者之间转换查询时，这一差异至关重要。 

例如，在标准搜索中，如果你想匹配包含关键词“storm”且提到单词“colorado”或 #COwx 标签的帖子，可以使用如下搜索查询：

storm #COwx OR colorado

在 Search Posts 的运算符优先级中，会先应用 AND，再应用 OR。因此，上述查询等价于： 

(storm #COwx) OR colorado

然而，上述规则会匹配任何提到“Colorado”的帖子，而不管该帖子是否同时提到“storm”或 #COwx 标签。此外，它也会匹配同时提到关键词“storm”和 #COwx 标签的帖子。 

要让查询按照最初预期的方式工作，需要将 OR 子句分组。原始标准查询在转换为 Search Posts 时应为：

storm (#COwx OR colorado)

这两个规则的匹配行为截然不同。以 2019 年 10 月为例，原始规则匹配到超过 1,175,000 条帖子，而正确转换后的规则大约只匹配到 5,600 条帖子。请务必留意 AND 与 OR 的使用，并在需要时使用括号。 

<div id="curl-requests">
  #### cURL 请求
</div>

**本节展示了标准 v1.1 端点及其在 v2 中对应端点的 cURL 请求。**

这些请求使用 [OAuth 2.0 App-Only](https://developer.x.com(/resources/fundamentals/authentication#app-only-authentication-and-oauth-2-0-bearer-token) 进行调用。要运行下面的 cURL 请求，您需要将授权头中的 ACCESS&#95;TOKEN 替换为您的应用访问令牌。对于 v2 端点，您的应用访问令牌必须属于某个 [developer App](/zh/resources/fundamentals/developer-apps/overview)，并且该 App 必须位于某个 [Project](/zh/resources/fundamentals/developer-apps/overview) 中。 

v1.1 端点返回的响应载荷将与 v2 端点返回的响应载荷不同。在 v2 中，响应会包含默认字段，以及通过 [fields](/zh/x-api/fundamentals/fields) 和 [expansions](/zh/x-api/fundamentals/expansions) 参数请求的其他字段。您可以使用这些参数来请求返回不同的字段集合。

**标准 v1.1 `GET search/tweets` → v2 `GET tweets/search/recent`**

<CodeGroup dropdown>
  ```bash cURL (v1.1)
  curl --request GET \
    --url 'https://api.x.com/1.1/search/tweets.json?q=from%3AXDevelopers%20-is%3Aretweet&count=100' \
    --header 'Authorization: Bearer $ACCESS_TOKEN'
  ```

  ```bash cURL (v2)
  curl --request GET \
    --url 'https://api.x.com/2/tweets/search/recent?query=from%3AXDevelopers%20-is%3Aretweet&tweet.fields=created_at%2Cconversation_id%2Centities&max_results=100' \
    --header 'Authorization: Bearer $ACCESS_TOKEN'
  ```

  ```python Python (v2)
  import requests

  bearer_token = "YOUR_BEARER_TOKEN"
  url = "https://api.x.com/2/tweets/search/recent"

  params = {
      "query": "from:XDevelopers -is:retweet",
      "tweet.fields": "created_at,conversation_id,entities",
      "max_results": 100
  }

  headers = {"Authorization": f"Bearer {bearer_token}"}
  response = requests.get(url, headers=headers, params=params)

  for post in response.json()["data"]:
      print(f"{post['created_at']}: {post['text'][:50]}...")
  ```

  ```python Python SDK
  from xdk import Client

  client = Client(bearer_token="YOUR_BEARER_TOKEN")

  # 搜索最新帖子 - SDK 会自动处理分页
  for page in client.posts.search_recent(
      query="from:XDevelopers -is:retweet",
      tweet_fields=["created_at", "conversation_id", "entities"],
      max_results=100
  ):
      for post in page.data:
          print(f"{post.created_at}: {post.text[:50]}...")
  ```

  ```javascript JavaScript SDK
  import { Client } from "@xdevplatform/xdk";

  const client = new Client({ bearerToken: "YOUR_BEARER_TOKEN" });

  // 搜索最新帖子 - SDK 会自动处理分页
  const paginator = client.posts.searchRecent("from:XDevelopers -is:retweet", {
    tweetFields: ["created_at", "conversation_id", "entities"],
    maxResults: 100,
  });

  for await (const page of paginator) {
    page.data?.forEach((post) => {
      console.log(`${post.created_at}: ${post.text?.slice(0, 50)}...`);
    });
  }
  ```
