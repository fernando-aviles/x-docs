<div id="standard-v11-compared-to-x-api-v2">
  ### 标准版 v1.1 与 X API v2 对比
</div>

如果你之前一直在使用 v1.1 的 [statuses/filter](https://developer.x.com/en/docs/x-api/v1/tweets/filter-realtime/api-reference/post-statuses-filter) 端点，本指南可以帮助你理解标准版端点与 X API v2 过滤流端点之间的相似点和差异。

* **相似点**
  * 请求参数和运算符
  * 对帖子编辑历史和元数据的支持
* **差异**
  * 端点 URL
  * App 和 Project 要求
  * 身份验证方式
  * 规则数量和持久化流
  * 响应数据格式
  * 请求参数
  * 恢复和冗余功能的可用性
  * 查询运算符

<div id="similarities">
  #### 相似点
</div>

**请求参数与运算符**

标准 v1.1 的 `statuses/filter` 端点提供了一些可以随请求一起传递的参数，用于过滤流。在 v2 过滤流中，则改为使用一组可以通过布尔逻辑连接在一起的[运算符](/zh/x-api/posts/filtered-stream#building-rules-for-filtered-stream)，以筛选所需的帖子。可用的运算符中，有一些是对现有标准 v1.1 参数的直接替代。 

以下标准 v1.1 请求参数在 X API v2 中有等效的运算符：
 

| **Standard** | **X API v2** |
| :--- | :--- |
| follow - 逗号分隔的用户 id 列表，表示其帖子应在流中投递的用户。 | 多种运算符可帮助你查找与特定用户相关的帖子：<br /><br />* @<br />* from:<br />* to:<br />* 等等 |
| track - 逗号分隔的短语列表，用于确定哪些帖子会被投递到流中。 | 多种运算符可帮助你查找与特定关键词相关的帖子：<br /><br />* keyword<br />* &quot;exact phrase match&quot;<br />* #<br />* 等等 |

**对帖子编辑历史和元数据的支持**

这两个版本都提供描述任何编辑历史记录的元数据。请参阅 [filtered stream API 参考](/zh/x-api/posts/filtered-stream#api-reference-index) 和 [Post edits 基础知识页面](/zh/x-api/fundamentals/edit-posts)了解更多详情。 

<div id="differences">
  #### 差异
</div>

**Endpoint URL**

* 标准 v1.1 端点：
  * https://stream.x.com/1.1/statuses/filter.json
* X API v2 端点：
  * https://api.x.com/2/tweets/search/stream
  * https://api.x.com/2/tweets/search/stream/rule

**App 和 Project 要求**

在对请求进行认证时，X API v2 端点要求你使用与某个 [developer App](/zh/resources/fundamentals/developer-apps) 关联、并隶属于某个 [Project](/zh/resources/fundamentals/developer-apps) 的凭证。所有 X API v1.1 端点都可以使用来自 App，或来自与某个 App 关联的 App 的凭证。

**认证方式**

标准端点支持 [OAuth 1.0a User Context](/zh/resources/fundamentals/authentication)，而 X API v2 filtered stream 端点支持 [OAuth 2.0 App-Only](/zh/resources/fundamentals/authentication#oauth-2-0)（也称为 Application-only 认证）。要向 X API v2 版本发出请求，你必须使用 App Access Token 对请求进行认证。

如果你不再拥有在开发者控制台中创建 App 时提供给你的 App Access Token，可以通过在开发者控制台中进入应用的 “Keys and tokens” 页面来生成新的令牌。如果你希望通过编程方式生成 App Access Token，请参阅此 [OAuth 2.0 App-Only 指南](/zh/resources/fundamentals/authentication#app-only-authentication-and-oauth-2-0-bearer-token)。 

**规则数量和持久流**

标准 v1.1 端点仅支持使用单个规则来过滤流式连接。要更改规则，你必须先断开流，然后提交一个包含更新后过滤规则（作为参数提交）的新请求。 

X API v2 filtered stream 端点允许你对单个流应用多个规则，并在保持流连接的同时向流中添加或移除规则。 

**响应数据格式**

标准 v1.1 与 X API v2 端点版本之间最大的差异之一，是你如何选择在载荷中返回哪些字段。

对于标准端点，你会默认接收许多响应字段，然后可以选择使用参数指出哪些字段或字段集应在载荷中返回。

X API v2 版本默认只返回 Post 的 id 和 text 字段。要请求任何其他字段或对象，你需要使用 [fields](/zh/x-api/fundamentals/fields) 和 [expansions](/zh/x-api/fundamentals/expansions) 参数。你从这些端点请求的任何 Post 字段都会返回在主 Post 对象中。任何展开的 user、media、poll 或 place 对象及其字段都会返回在响应中的一个 includes 对象内。然后，你可以通过匹配 Post 和展开对象中都出现的 ID，将任何展开对象匹配回对应的 Post 对象。 

我们鼓励你在各自的指南中进一步了解这些新参数，或者查看我们的 [如何使用 fields 和 expansions](/zh/x-api/fundamentals/data-dictionary#how-to-use-fields-and-expansions) 指南。 

我们还整理了一份 [数据格式迁移指南](/zh/x-api/migrate/data-format-migration#migrating-from-standard-v1-1s-data-format-to-v2)，帮助你将标准 v1.1 字段映射到较新的 v2 字段。本指南还会为你提供在 v2 请求中需要携带的、用于返回特定字段的具体扩展和字段参数。 
 

除了更改如何请求某些字段之外，X API v2 还为 API 返回的对象（包括 Post 和 [user](/zh/x-api/fundamentals/data-dictionary#user) 对象）引入了新的 JSON 设计。

* 在 JSON 根级别，标准端点将 Post 对象返回在一个 statuses 数组中，而 X API v2 则返回在一个 data 数组中。 
* X API v2 JSON 不再引用被转发（Retweeted）和被引用（Quoted）的 “statuses”，而是引用被转发和被引用的 Tweets。许多传统和已弃用字段（例如 contributors 和 user.translator&#95;type）正在被移除。 
* X API v2 使用术语 like，替代在 Post 对象中的 favorites 和在 user 对象中的 favourites。 
* X 采用这样一种约定：没有值的 JSON 字段（例如为 null）不会写入载荷。Post 和 user 属性仅在具有非 null 值时才会被包含。 
   

我们还为 [Post 对象](/zh/x-api/fundamentals/data-dictionary#tweet) 引入了一组新的字段，包括以下内容：

* 一个 [conversation&#95;id](/zh/x-api/fundamentals/conversation-id) 字段
* 两个新的 [annotations](/zh/x-api/fundamentals/post-annotations) 字段，包括 context 和 entities
* 若干新的 [metrics](/zh/x-api/fundamentals/metrics) 字段
* 一个新的 reply&#95;setting 字段，用于显示谁可以回复指定的帖子

**请求参数**

还有一组在 X API v2 中**不**支持的标准过滤流请求参数：

| 标准 v1.1 参数 | 详情 |
| :--- | :--- |
| locations - 一个以逗号分隔的经度、纬度对列表，用于指定一组边界框，以按地理位置过滤帖子。 | 我们尚未为 X API v2 发布基于位置的运算符。 |
| Delimited | 对于 v1.1 端点，将其设置为字符串长度表示流中的状态应被分隔，这样客户端就知道在状态消息结束前需要读取多少字节。<br /><br />此功能在 X API v2 中不可用。 |
| Stall&#95;warnings | 对于 v1.1 端点，将此参数设置为 true 会在客户端有断开连接风险时周期性发送消息。<br /><br />在 X API v2 中，停滞警告会默认发送，并且会不时发送新行。 |

**恢复与冗余功能的可用性**

X API v2 版本的过滤流引入了恢复和冗余功能，可帮助你最大化流式连接的正常运行时间，并在断开连接持续五分钟或更短时间的情况下恢复可能遗漏的帖子。

冗余连接允许你最多两次连接到给定流，这有助于确保你始终保持与流的连接，即使其中一个连接失败。

backfill&#95;minutes 参数可用于恢复最多五分钟的遗漏 data。

这两项功能仅通过 [Academic Research access](/zh/x-api/getting-started/about-x-api) 提供。你可以通过我们的 [恢复与冗余功能](/zh/x-api/posts/filtered-stream#filtered-stream-recovery-and-redundancy-features) 集成指南进一步了解此功能。

**新的查询运算符**

X API v2 引入了新的运算符，以支持两项新功能：

* **[Conversation IDs](/zh/x-api/fundamentals/conversation-id)** - 随着对话在 X 上展开，将提供一个 conversation ID 来标记属于该对话的帖子。对话中的所有帖子其 conversation&#95;id 都会被设置为发起该对话的帖子 ID。
  * conversation&#95;id:
* **[X Annotations](/zh/x-api/fundamentals/post-annotations)** 提供关于帖子的上下文信息，包括实体和上下文注解。实体由人物、地点、产品和组织构成。上下文是已浮现实体所属的领域或主题。例如，帖子中提到的人物可以具有上下文，指明他们是运动员、演员还是政治人物。
  * context: - 匹配带有目标上下文注解的帖子。
  * entity: - 匹配带有目标实体注解的帖子。

<div id="add-a-rule-to-filtered-stream-v2">
  ### 向过滤流 (v2) 添加一条规则
</div>

<CodeGroup dropdown>
  ```bash cURL
  curl -X POST "https://api.x.com/2/tweets/search/stream/rules" \
    -H "Authorization: Bearer $BEARER_TOKEN" \
    -H "Content-Type: application/json" \
    -d '{"add": [{"value": "cat has:images", "tag": "cats with images"}]}'
  ```

  ```python Python
  import requests

  bearer_token = "YOUR_BEARER_TOKEN"
  url = "https://api.x.com/2/tweets/search/stream/rules"

  headers = {
      "Authorization": f"Bearer {bearer_token}",
      "Content-Type": "application/json"
  }

  data = {
      "add": [{"value": "cat has:images", "tag": "cats with images"}]
  }

  response = requests.post(url, headers=headers, json=data)
  print(response.json())
  ```

  ```python Python SDK
  from xdk import Client

  client = Client(bearer_token="YOUR_BEARER_TOKEN")

  # 向过滤流添加一条规则
  response = client.posts.add_stream_rules(
      add=[{"value": "cat has:images", "tag": "cats with images"}]
  )
  print(response.data)
  ```

  ```javascript JavaScript SDK
  import { Client } from "@xdevplatform/xdk";

  const client = new Client({ bearerToken: "YOUR_BEARER_TOKEN" });

  // 向过滤流添加一条规则
  const response = await client.posts.addStreamRules({
    add: [{ value: "cat has:images", tag: "cats with images" }],
  });
  console.log(response.data);
  ```

<div id="connect-to-filtered-stream-v2">
  ### 连接到过滤流（v2）
</div>

<CodeGroup dropdown>
  ```bash cURL
  curl "https://api.x.com/2/tweets/search/stream?tweet.fields=created_at,author_id" \
    -H "Authorization: Bearer $BEARER_TOKEN"
  ```

  ```python Python
  import requests

  bearer_token = "YOUR_BEARER_TOKEN"
  url = "https://api.x.com/2/tweets/search/stream"

  params = {"tweet.fields": "created_at,author_id"}
  headers = {"Authorization": f"Bearer {bearer_token}"}

  # 实时获取帖子流
  response = requests.get(url, headers=headers, params=params, stream=True)
  for line in response.iter_lines():
      if line:
          print(line.decode("utf-8"))
  ```

  ```python Python SDK
  from xdk import Client

  client = Client(bearer_token="YOUR_BEARER_TOKEN")

  # 连接到过滤流
  for post in client.posts.stream(
      tweet_fields=["created_at", "author_id"]
  ):
      print(f"{post.data.created_at}: {post.data.text[:50]}...")
  ```

  ```javascript JavaScript SDK
  import { Client } from "@xdevplatform/xdk";

  const client = new Client({ bearerToken: "YOUR_BEARER_TOKEN" });

  // 连接到过滤流
  const stream = client.posts.stream({
    tweetFields: ["created_at", "author_id"],
  });

  for await (const post of stream) {
    console.log(`${post.data?.created_at}: ${post.data?.text?.slice(0, 50)}...`);
  }
  ```
