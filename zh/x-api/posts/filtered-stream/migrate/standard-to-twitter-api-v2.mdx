<div id="standard-v11-compared-to-x-api-v2">
  ### 标准 v1.1 与 X API v2 的比较
</div>

如果你一直在使用 v1.1 的 [statuses/filter](https://developer.x.com/en/docs/x-api/v1/tweets/filter-realtime/api-reference/post-statuses-filter) 端点，本指南将帮助你了解标准 v1.1 与 X API v2 过滤流端点之间的相似点和差异。

* **相似点**
  * 请求参数和运算符
  * 对帖子编辑历史和元数据的支持
* **差异**
  * 端点 URL
  * App 和 Project 要求
  * 身份验证方式
  * 规则数量上限和持久流
  * 响应数据格式
  * 请求参数
  * 恢复和冗余功能的可用性
  * 查询运算符

<div id="similarities">
  #### 相似之处
</div>

**请求参数与运算符**

标准 v1.1 的 `statuses/filter` 端点提供了一些可以随请求一起传递的参数，用于过滤流。在 v2 过滤流中，则改为使用一组[运算符](/zh/x-api/posts/filtered-stream#building-rules-for-filtered-stream)，可以通过布尔逻辑将它们组合起来，以筛选所需的帖子。这些可用的运算符中，有一些是对现有标准 v1.1 参数的直接替代。 

以下标准 v1.1 请求参数在 X API v2 中有等效运算符：
 

| **Standard** | **X API v2** |
| :--- | :--- |
| follow - 以逗号分隔的用户 id 列表，表示其帖子应被推送到流中的用户。 | 多个运算符可以帮助你查找与特定用户相关的帖子：<br /><br />* @<br />* from:<br />* to:<br />* 等等 |
| track - 以逗号分隔的短语列表，将用于确定哪些帖子会被推送到流中。 | 多个运算符可以帮助你查找与特定关键词相关的帖子：<br /><br />* keyword<br />* &quot;exact phrase match&quot;<br />* #<br />* 等等 |

**对帖子编辑历史和元数据的支持**

这两个版本都提供用于描述编辑历史的相关元数据。请查看 [filtered stream API 参考](/zh/x-api/posts/filtered-stream#api-reference-index)和 [帖子编辑基础知识页面](/zh/x-api/fundamentals/edit-posts)以了解更多详情。 

<div id="differences">
  #### 差异
</div>

**Endpoint URLs（端点 URL）**

* 标准 v1.1 端点：
  * https://stream.x.com/1.1/statuses/filter.json
* X API v2 端点：
  * https://api.x.com/2/tweets/search/stream
  * https://api.x.com/2/tweets/search/stream/rule

**App 和 Project 要求**

在对请求进行认证时，X API v2 端点要求你使用与某个 [developer App](/zh/resources/fundamentals/developer-apps) 关联、并且该 App 已关联到某个 [Project](/zh/resources/fundamentals/developer-apps) 的凭证。所有 X API v1.1 端点都可以使用来自 App 的凭证，或者来自与 Project 关联的 App 的凭证。

**认证方式**

标准端点支持 [OAuth 1.0a User Context](/zh/resources/fundamentals/authentication)，而 X API v2 过滤流端点支持 [OAuth 2.0 App-Only](/zh/resources/fundamentals/authentication#oauth-2-0)（也称为 Application-only 认证）。要向 X API v2 版本发出请求，你必须使用 App Access Token 来对请求进行认证。

如果你不再拥有在 Developer Console 中创建 App 时向你展示的 App Access Token，可以通过进入 Developer Console 中你的 App 的“Keys and tokens”页面来生成一个新的。如果你希望通过编程方式生成 App Access Token，请参阅此 [OAuth 2.0 App-Only 指南](/zh/resources/fundamentals/authentication#app-only-authentication-and-oauth-2-0-bearer-token)。 

**规则数量与持久连接流**

标准 v1.1 端点仅支持使用单条规则来过滤流式连接。要更改规则，你必须断开流连接，并使用更新后的过滤规则作为参数提交新的请求。 

X API v2 过滤流端点允许你在单个流上应用多条规则，并且可以在保持流连接的同时向流添加或移除规则。 

**响应数据格式**

标准 v1.1 与 X API v2 端点版本之间最大的差异之一，是你如何选择在有效载荷中返回哪些字段。

对于标准端点，你默认会接收到许多响应字段，然后可以选择使用参数来指定应在有效载荷中返回哪些字段或字段集合。

X API v2 版本默认只返回帖子 id 和 text 字段。若要请求任何额外的字段或对象，你需要使用 [fields](/zh/x-api/fundamentals/fields) 和 [expansions](/zh/x-api/fundamentals/expansions) 参数。从这些端点请求的任何帖子字段都会在主 Post 对象中返回。任何扩展的用户、媒体、投票或地点对象及其字段都会在响应中的 includes 对象内返回。然后，你可以通过匹配帖子对象和扩展对象中出现的 id，将任何扩展对象与帖子对象对应起来。 

我们建议你在各自的指南中进一步了解这些新参数，或阅读关于 [如何使用 fields 和 expansions](/zh/x-api/fundamentals/data-dictionary#how-to-use-fields-and-expansions) 的指南。 

我们还整理了一份 [数据格式迁移指南](/zh/x-api/migrate/data-format-migration#migrating-from-standard-v1-1s-data-format-to-v2)，可帮助你将标准 v1.1 字段映射到较新的 v2 字段。该指南也会为你提供在 v2 请求中需要传入的具体扩展和字段参数，以返回特定字段。 
 

除了你请求某些字段的方式发生变化之外，X API v2 还为 API 返回的对象（包括帖子和 [user](/zh/x-api/fundamentals/data-dictionary#user) 对象）引入了新的 JSON 设计。

* 在 JSON 根级别，标准端点会在 statuses 数组中返回 Post 对象，而 X API v2 会返回一个 data 数组。 
* X API v2 JSON 不再引用被转发和被引用的“statuses”，而是引用被转发和被引用的推文。许多旧版和已弃用字段（例如 contributors 和 user.translator&#95;type）正在被移除。 
* X API v2 不再在帖子对象中使用 favorites、在用户对象中使用 favourites，而是统一使用术语 like。 
* X 采用这样的约定：在 JSON 中，没有值的字段（例如 null）不会写入到有效载荷中。只有在 Post 和 user 属性具有非 null 值时，这些属性才会被包含。 
   

我们还在 [Post object](/zh/x-api/fundamentals/data-dictionary#tweet) 中引入了一组新的字段，包括以下内容：

* 一个 [conversation&#95;id](/zh/x-api/fundamentals/conversation-id) 字段
* 两个新的 [annotations](/zh/x-api/fundamentals/post-annotations) 字段，包括 context 和 entities
* 若干新的 [metrics](/zh/x-api/fundamentals/metrics) 字段
* 一个新的 reply&#95;setting 字段，用于显示谁可以回复某条给定的帖子

**请求参数**

还有一组标准的过滤流请求参数在 X API v2 中**不**受支持：

| 标准 v1.1 参数 | 详情 |
| :--- | :--- |
| locations - 由逗号分隔的经度、纬度对列表，指定用于按边界框过滤帖子的边界框集合。 | 我们尚未为 X API v2 发布基于位置的运算符。 |
| Delimited | 对于 v1.1 端点，将其设置为字符串长度表示应在流中对状态进行分隔，以便客户端知道在状态消息结束前需要读取多少字节。<br /><br />此功能在 X API v2 中不可用。 |
| Stall&#95;warnings | 对于 v1.1 端点，将此参数设置为 true 将在客户端有断开连接风险时定期发送消息。<br /><br />在 X API v2 中，停顿警告默认发送，并会不时发送新的一行。 |

**恢复和冗余功能的可用性**

X API v2 的过滤流引入了恢复和冗余功能，可帮助你最大化流式传输的在线时间，并在断开连接持续五分钟或更短时间的情况下恢复可能遗漏的帖子。

冗余连接允许你对同一流建立最多两条并发连接，这可以帮助确保你始终保持与该流的连接，即使其中一个连接失败。

backfill&#95;minutes 参数可用于恢复最多五分钟的遗漏数据。

这两项功能仅可通过 [Academic Research access](/zh/x-api/getting-started/about-x-api) 使用。你可以通过我们的 [recovery and redundancy features](/zh/x-api/posts/filtered-stream#filtered-stream-recovery-and-redundancy-features) 集成指南了解更多相关功能。

**新的查询运算符**

X API v2 引入了新的运算符，以支持两个新功能：

* **[Conversation IDs](/zh/x-api/fundamentals/conversation-id)** - 随着对话在 X 上展开，将提供一个 conversation&#95;id 来标记属于该对话的帖子。对话中的所有帖子，其 conversation&#95;id 都将被设置为启动该对话的帖子 ID。 
  * conversation&#95;id:
* **[X Annotations](/zh/x-api/fundamentals/post-annotations)** 提供关于帖子的上下文信息，包括 entity 和 context 注解。Entities 由人物、地点、产品和组织组成。Contexts 是域或主题，已识别的实体属于这些域或主题。例如，帖子中提到的人物可能具有某个 context，指示他们是运动员、演员还是政治人物。
  * context: - 匹配已用感兴趣的 context 进行了注解的帖子。
  * entity: - 匹配已用感兴趣的 entity 进行了注解的帖子。

<div id="add-a-rule-to-filtered-stream-v2">
  ### 向过滤流（v2）添加规则
</div>

<CodeGroup dropdown>
  ```bash cURL
  curl -X POST "https://api.x.com/2/tweets/search/stream/rules" \
    -H "Authorization: Bearer $BEARER_TOKEN" \
    -H "Content-Type: application/json" \
    -d '{"add": [{"value": "cat has:images", "tag": "cats with images"}]}'
  ```

  ```python Python
  import requests

  bearer_token = "YOUR_BEARER_TOKEN"
  url = "https://api.x.com/2/tweets/search/stream/rules"

  headers = {
      "Authorization": f"Bearer {bearer_token}",
      "Content-Type": "application/json"
  }

  data = {
      "add": [{"value": "cat has:images", "tag": "cats with images"}]
  }

  response = requests.post(url, headers=headers, json=data)
  print(response.json())
  ```

  ```python Python SDK
  from xdk import Client

  client = Client(bearer_token="YOUR_BEARER_TOKEN")

  # 向过滤流添加规则
  response = client.posts.add_stream_rules(
      add=[{"value": "cat has:images", "tag": "cats with images"}]
  )
  print(response.data)
  ```

  ```javascript JavaScript SDK
  import { Client } from "@xdevplatform/xdk";

  const client = new Client({ bearerToken: "YOUR_BEARER_TOKEN" });

  // 向过滤流添加规则
  const response = await client.posts.addStreamRules({
    add: [{ value: "cat has:images", tag: "cats with images" }],
  });
  console.log(response.data);
  ```

<div id="connect-to-filtered-stream-v2">
  ### 连接到过滤流（v2）
</div>

<CodeGroup dropdown>
  ```bash cURL
  curl "https://api.x.com/2/tweets/search/stream?tweet.fields=created_at,author_id" \
    -H "Authorization: Bearer $BEARER_TOKEN"
  ```

  ```python Python
  import requests

  bearer_token = "YOUR_BEARER_TOKEN"
  url = "https://api.x.com/2/tweets/search/stream"

  params = {"tweet.fields": "created_at,author_id"}
  headers = {"Authorization": f"Bearer {bearer_token}"}

  # 实时获取帖子流
  response = requests.get(url, headers=headers, params=params, stream=True)
  for line in response.iter_lines():
      if line:
          print(line.decode("utf-8"))
  ```

  ```python Python SDK
  from xdk import Client

  client = Client(bearer_token="YOUR_BEARER_TOKEN")

  # 连接到过滤流
  for post in client.posts.stream(
      tweet_fields=["created_at", "author_id"]
  ):
      print(f"{post.data.created_at}: {post.data.text[:50]}...")
  ```

  ```javascript JavaScript SDK
  import { Client } from "@xdevplatform/xdk";

  const client = new Client({ bearerToken: "YOUR_BEARER_TOKEN" });

  // 连接到过滤流
  const stream = client.posts.stream({
    tweetFields: ["created_at", "author_id"],
  });

  for await (const post of stream) {
    console.log(`${post.data?.created_at}: ${post.data?.text?.slice(0, 50)}...`);
  }
  ```
