<div id="matching-returned-posts-to-their-associated-rule">
  ### 将返回的帖子与其关联规则进行匹配
</div>

filtered stream 端点允许你在单个连接中配置多条规则。在开始在流中接收帖子之前，你需要先创建一条规则，用来指定你感兴趣的帖子类型。 

当你基于多种属性（包括用户属性、地理位置、语言等）来指定匹配帖子的规则时，你可以为该规则附加一个标签，以便在更高层级对这条规则进行区分。标签是为规则提供上下文信息的一个好方式，尤其是在你已经配置了许多规则的情况下。过滤规则会决定哪些与帖子相关的活动会通过该连接被发送。

如果你需要添加新的过滤规则来捕获不同类型的帖子，或者移除现有规则，你的应用可以向 [POST tweets/search/stream/rules](/zh/x-api/posts/filtered-stream#post-2-tweets-search-stream-rules) 端点发送请求来实现这一点。发送该请求后，过滤规则会被自动修改，这些更改会直接在数据流中生效，无需重新连接。大多数新增规则会在大约 20 秒内生效。虽然不太常见，但根据外部因素（例如网络连接情况），在你开始接收到匹配的帖子之前可能会花费更长时间。如果你在列出规则的端点中找不到某条规则，请确认该规则创建请求已成功；你可以通过检查日志中的任何错误消息来完成这一点。

<div id="matching-rules">
  #### 匹配规则
</div>

当某个活动通过你的过滤流连接被投递时，在 matching&#95;rules 数组中会包含与所投递帖子匹配的过滤器列表。

在 Post 负载（帖子负载）中，还有额外的字符串元数据，其中包含导致特定帖子被投递的规则 id 和标签。如果多个规则匹配同一个帖子，该活动只会被投递一次，但元数据中会包含每一条匹配的规则。匹配规则为你提供了一种简单的方法，将特定帖子与特定规则关联起来，这在你拥有大量不同规则时尤其有用。由于数据会以这种方式通过单一流进行投递，因此确保每条规则都具有唯一的 id 和标签对于匹配来说至关重要。 

**下面是 Post 负载中 “matching&#95;rules” 数组的示例：**

```"matching_rules": [
    {
      "id": "1166916266197536768",
      "tag": "test-rule-tag-00000"
    },
    {
      "id": "1166916266197536769",
      "tag": "test-rule-tag-12345"
    }
  ]
```

<div id="rule-tags">
  #### 规则标签
</div>

在创建时，每条过滤规则都可以带有一个标签。规则标签本身没有特殊含义，它们只是作为与规则一起携带的不透明字符串处理。它们会包含在返回的活动中的 `matching_rules` 元数据里，目的是在更高层级上帮助你更容易地区分各条规则。 

标签提供了一种简单的方法来对过滤规则进行逻辑分组。比如，你可以为某条特定规则生成一个唯一 id 作为其标签，并让你的应用在处理活动时引用该 id，将结果与特定客户、广告活动、类别或其他相关分组关联起来。

请注意，现有规则的标签无法更新，只能在创建规则时添加。若要“更新”或“重命名”标签，你需要先删除该规则，然后再使用所需的标签重新添加。最佳做法是直接使用唯一标识符作为标签，由你的系统在自己的应用中将该标识符与其他各类数据点关联起来，而无需对规则集本身做任何修改。
