<div id="matching-returned-posts-to-their-associated-rule">
  ### 将返回的帖子与其关联的规则进行匹配
</div>

`filtered stream` 端点使你能够通过单个连接同时使用多条规则。在开始在流中接收帖子之前，你需要先创建一条规则，用于指定你感兴趣的帖子类型。 

当你根据多种属性（包括用户属性、地理位置、语言等）来指定规则以匹配帖子时，你可以附加一个标签，在更高层面区分这条规则。标签是为规则提供上下文的良好方式，尤其是在你启用了大量规则的情况下。过滤规则决定了哪些帖子相关活动会通过该连接发送。

如果你需要添加一条新的过滤规则来捕获不同类型的帖子，或者移除现有规则，你的应用可以向 [POST tweets/search/stream/rules](/zh/x-api/posts/filtered-stream#post-2-tweets-search-stream-rules) 端点发送请求来完成此操作。发送该请求后，过滤规则会自动被修改，更改会直接在数据流中生效，而无需重新连接。大多数新增规则会在大约 20 秒内生效。虽然不太常见，但根据外部因素（例如网络连接情况），在你开始接收匹配帖子之前可能会花费更长时间。如果你在列出规则的端点返回结果中找不到某条规则，请确认该规则创建请求是否成功；你可以通过检查日志中的任何错误消息来完成这一点。

<div id="matching-rules">
  #### 匹配规则
</div>

当某个活动通过你的过滤流连接被送达时，在 matching&#95;rules 数组中会包含与已送达帖子匹配的过滤器列表。

在帖子负载中，还有额外的字符串元数据，其中包含导致特定帖子被送达的规则 id 和标签。如果多个规则匹配同一个帖子，该活动只会被送达一次，并在这些元数据中包含每一条匹配规则。匹配规则为将特定帖子与特定规则关联起来提供了一种简便的方法，这在你拥有许多不同规则时尤其有用。由于数据是以这种方式通过单一流送达的，确保你拥有唯一的 id 和标签对于匹配至关重要。 

**下面是 “matching&#95;rules” 数组在帖子负载中的示例：**

```"matching_rules": [
    {
      "id": "1166916266197536768",
      "tag": "test-rule-tag-00000"
    },
    {
      "id": "1166916266197536769",
      "tag": "test-rule-tag-12345"
    }
  ]
```

<div id="rule-tags">
  #### 规则标签
</div>

在创建过滤规则时，每条规则都可以带有一个标签。规则标签在语义上没有特殊含义，只是作为与规则一起携带的不透明字符串处理。它们会包含在返回的活动中的 `matching_rules` 元数据中，用于帮助你在更高层级更容易地区分各条规则。 

标签提供了一种简单方式来对过滤规则进行逻辑分组。比如，你可以为某条特定规则生成一个唯一 ID 作为其标签，并让应用在处理活动时引用该 ID，将结果关联到特定客户、广告活动、类别或其他相关分组。

请注意，现有规则的标签无法更新，只能在创建规则时指定。若要“更新”或“重命名”标签，你需要先删除该规则，然后再使用期望的标签重新添加。最佳做法是直接使用唯一标识符作为标签，由你的系统在应用内部将其与各类其他数据点关联，而无需对规则集本身做任何改动。
