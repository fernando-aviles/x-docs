<div id="matching-returned-posts-to-their-associated-rule">
  ### 将返回的帖子与其关联的规则匹配
</div>

filtered stream 端点允许你在单个连接上配置多条规则。在你开始通过流接收帖子之前，你需要先创建一条规则，用来指定你感兴趣的帖子类型。 

当你根据多种属性（包括用户属性、地理位置、语言等）来指定匹配帖子的规则时，你可以附加一个标签，在更高层级区分这条规则。标签是为规则提供上下文的好方式，尤其是在你配置了很多规则的情况下。过滤规则会决定哪些帖子相关活动会通过该连接发送。

如果你需要新增一条过滤规则来捕获不同类型的帖子，或删除一条现有规则，你的 App 可以向 [POST tweets/search/stream/rules](/zh/x-api/posts/filtered-stream#post-2-tweets-search-stream-rules) 端点发送请求来完成这一操作。请求发送后，过滤规则会自动被修改，变更会直接在数据流中生效，无需重新连接。大多数新增规则会在大约 20 秒或更短时间内生效。虽然这种情况不太常见，但视外部因素（例如网络连接情况）而定，你可能需要更长时间才会开始接收到匹配的帖子。如果你在用于列出规则的端点中找不到某条规则，请确认该规则创建请求是否成功；你可以通过检查日志中的任何错误消息来完成这一点。

<div id="matching-rules">
  #### 匹配规则
</div>

当某个活动通过你的过滤流连接传送时，其 matching&#95;rules 数组中会包含与被传送帖子匹配的过滤器列表。

在帖子负载中还有额外的字符串元数据，其中包含导致特定帖子被传送的规则 id 和标签。如果多个规则匹配同一个帖子，该活动只会被传送一次，并且所有匹配规则都会包含在这段元数据中。匹配规则提供了一种简单的方法，将特定帖子与特定规则关联起来，这在你定义了许多不同规则时尤其有用。由于数据是以这种方式通过单个流传送的，因此确保你使用唯一的 id 和标签对于匹配来说至关重要。 

**下面是“matching&#95;rules”数组在帖子负载中的示例：**

```"matching_rules": [
    {
      "id": "1166916266197536768",
      "tag": "test-rule-tag-00000"
    },
    {
      "id": "1166916266197536769",
      "tag": "test-rule-tag-12345"
    }
  ]
```

<div id="rule-tags">
  #### 规则标签
</div>

在创建时，每条过滤规则都可以同时创建一个标签。规则标签本身没有特殊含义，只是作为与规则一起携带的不透明字符串处理。它们会包含在返回的活动数据中的 `matching_rules` 元数据里，目的是在更高层级上帮助你更容易地区分各条规则。 

标签提供了一种简便方式来对过滤规则进行逻辑分组。比如，你可以为某条特定规则生成一个唯一 ID 作为其标签，并让你的应用在处理活动时引用该 ID，以便将结果与特定客户、广告活动、类别或其他相关分组关联起来。

请注意，现有规则的标签无法更新，只能在创建规则时指定。若要“更新”或“重命名”标签，你需要先删除该规则，然后使用所需的标签重新添加该规则。最好的解决方案是直接使用一个唯一标识符作为标签，由你的系统将它与自己 App 内的各类数据点关联，而无需对规则集本身做任何修改。
