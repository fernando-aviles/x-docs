过滤流端点会推送符合应用到流上的一组规则的帖子。规则由一系列用于匹配各种帖子属性的运算符组成。

可以使用 [POST /tweets/search/stream/rules](/zh/x-api/posts/filtered-stream#post-2-tweets-search-stream-rules) 端点应用多条规则。添加规则并通过 [GET /tweets/search/stream](/zh/x-api/posts/filtered-stream#get-2-tweets-search-stream) 建立连接后，只有符合你规则的帖子才会被推送。你无需断开连接即可添加或删除规则。

***

<div id="rule-limitations">
  ## 规则限制
</div>

规则数量的上限取决于你的[访问级别](/zh/x-api/getting-started/about-x-api)。具体限制请参阅[过滤流简介](/zh/x-api/posts/filtered-stream/introduction)。

***

<div id="operator-types-standalone-and-conjunction-required">
  ## 运算符类型：独立型与需连词型
</div>

**独立运算符** 可以单独使用，也可以与任何其他运算符组合使用（包括那些必须与连词一起使用的运算符）。

例如，下面这条规则是有效的，因为 `#hashtag` 是一个独立运算符：

```
#xapiv2
```

**必须与其他条件组合使用的运算符** 不能在规则中单独使用；只有在规则中至少包含一个可独立使用的运算符时，它们才能被使用。原因是单独使用这些运算符会匹配到数量极其庞大的帖子。

例如，以下规则 **不受支持**，因为它们只包含必须与其他条件组合使用的运算符：

```
has:media
```

```
has:links OR is:retweet
```

如果我们添加一个单独的运算符，例如短语 `"X data"`，该规则就会正常工作：

```
"X data" has:mentions (has:media OR has:links)
```

***

<div id="boolean-operators-and-grouping">
  ## 布尔运算符和分组
</div>

使用以下运算符将多个条件串联在一起：

| Operator | Description | Example |
| :--- | :--- | :--- |
| **AND**（空格） | 帖子必须同时匹配这两个条件 | `snow day #NoSchool` 匹配同时包含 &quot;snow&quot;、&quot;day&quot; 和 #NoSchool 的帖子 |
| **OR** | 帖子只需匹配其中一个条件 | `grumpy OR cat OR #meme` 匹配包含 &quot;grumpy&quot; 或 &quot;cat&quot; 或 #meme 的帖子 |
| **NOT**（短横线） | 排除匹配此条件的帖子 | `cat #meme -grumpy` 匹配包含 &quot;cat&quot; 和 #meme 但不包含 &quot;grumpy&quot; 的帖子 |
| **Grouping**（括号） | 将运算符和条件分组 | `(grumpy cat) OR (#meme has:images)` 匹配任一分组 |

<Note>
  **关于取反的说明**

  * 除了 `sample:` 之外，所有运算符都可以取反
  * 运算符 `-is:nullcast` 必须始终以否定形式使用
  * 被取反的运算符不能单独使用
  * 不要对分组后的运算符整体取反。不要使用 `skiing -(snow OR day OR noschool)`，应使用 `skiing -snow -day -noschool`
</Note>

***

<div id="order-of-operations">
  ## 运算顺序
</div>

当同时使用 AND 和 OR 时：

1. 优先组合由 AND 逻辑连接的运算符
2. 然后再应用由 OR 逻辑连接的运算符

**示例：**

| Query                    | Evaluated as               |
| :----------------------- | :------------------------- |
| `apple OR iphone ipad`   | `apple OR (iphone ipad)`   |
| `ipad iphone OR android` | `(iphone ipad) OR android` |

为消除歧义，请使用括号：

```
(apple OR iphone) ipad
```

```
iphone (ipad OR android)
```

***

<div id="punctuation-diacritics-and-case-sensitivity">
  ## 标点符号、变音符号和大小写区分
</div>

**变音符号：** 带有变音符号的过滤流规则只会匹配同样包含该变音符号的帖子。例如，`diacrítica` 能匹配 *diacrítica*，但**不能**匹配 *diacritica*。

**大小写区分：** 所有运算符都不区分大小写。规则 `cat` 可以匹配 *cat*、*CAT* 和 *Cat*。

<Note>
  **搜索帖子时的行为不同**

  在[构建搜索查询](/zh/x-api/posts/search/integrate/build-a-query)时，带变音符号的关键字会匹配同时包含和不包含变音符号的帖子。例如，`Diacrítica` 同时匹配 *Diacrítica* 和 *Diacritica*。
</Note>

***

<div id="quote-tweet-matching">
  ## 引用推文匹配
</div>

在使用过滤流（filtered stream）时，运算符会同时匹配引用推文的内容**以及**被引用的原始帖子的内容。

<Note>
  [搜索帖子](/zh/x-api/posts/search/introduction) 的行为有所不同——它只匹配引用推文的内容，而不匹配原始帖子。
</Note>

***

<div id="specificity-and-efficiency">
  ## 精确性与效率
</div>

<Warning>
  不建议只使用单个关键词或话题标签这类范围很广的运算符——它会匹配到海量帖子，并迅速耗尽你的连接资源。
</Warning>

**构建有效规则的技巧：**

1. **先精确，再放宽** —— 先创建能返回高相关结果的精准规则
2. **使用多个运算符** —— 组合运算符以收窄结果范围
3. **注意字符数限制** —— 整个规则字符串都会计入限制

**示例演进：**

```
# Too broad - 200,000+ Posts per day
happy

# 更好 - 添加了语言过滤器和排除项
(happy OR happiness) lang:en -birthday -is:retweet

# Even better - 59 characters, more specific
(happy OR happiness) place_country:GB -birthday -is:retweet
```

<div id="iteratively-building-a-rule">
  ## 逐步构建规则
</div>

<div id="step-1-start-with-a-basic-rule">
  ### 第 1 步：从一个基本规则开始
</div>

```
happy OR happiness
```

<div id="step-2-test-and-narrow-based-on-results">
  ### 步骤 2：根据结果进行测试并缩小范围
</div>

我们发现帖子使用了多种语言。添加一个语言过滤器：

```
(happy OR happiness) lang:en
```

我们收到了生日祝福的推文。把这些和转推排除掉：

```
(happy OR happiness) lang:en -birthday -is:retweet
```

<div id="step-3-broaden-for-better-coverage">
  ### 步骤 3：扩大覆盖范围
</div>

我们希望捕获更多情绪信息。添加相关关键词：

```
(happy OR happiness OR excited OR elated) lang:en -birthday -is:retweet
```

<div id="step-4-adjust-for-trends">
  ### 步骤 4：根据趋势进行调整
</div>

节日相关的帖子开始出现了。将它们排除：

```
(happy OR happiness OR excited OR elated) lang:en -birthday -is:retweet -holidays
```

<div id="adding-and-removing-rules">
  ## 添加和删除规则
</div>

使用 [POST /2/tweets/search/stream/rules](/zh/x-api/posts/filtered-stream#post-2-tweets-search-stream-rules) 来添加或删除规则。

<div id="adding-rules">
  ### 添加规则
</div>

提交一个 `add` JSON 请求体，其中包含 `value`（规则）和可选的 `tag`（用于标识匹配的帖子）：

```bash
curl -X POST "https://api.x.com/2/tweets/search/stream/rules" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -d '{
    "add": [
      {"value": "cat has:media", "tag": "cats with media"},
      {"value": "cat has:media -grumpy", "tag": "happy cats with media"},
      {"value": "meme", "tag": "funny things"},
      {"value": "meme has:images"}
    ]
  }'
```

<div id="removing-rules">
  ### 删除规则
</div>

提交一个 `delete` JSON 请求体，其中包含要删除的规则 ID：

```bash
curl -X POST "https://api.x.com/2/tweets/search/stream/rules" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -d '{
    "delete": {
      "ids": [
        "1165037377523306498",
        "1165037377523306499"
      ]
    }
  }'
```

<div id="rule-examples">
  ## 规则示例
</div>

<div id="tracking-a-natural-disaster">
  ### 追踪自然灾害
</div>

匹配来自气象机构、有关飓风“哈维”的帖子：

```json
{
  "value": "-is:retweet has:geo (from:NWSNHC OR from:NHC_Atlantic OR from:NWSHouston OR from:NWSSanAntonio OR from:USGS_TexasRain OR from:USGS_TexasFlood OR from:JeffLindner1)",
  "tag": "飓风哈维 - 带有地理位置的气象机构"
}
```

<div id="sentiment-analysis-for-nowplaying">
  ### #nowplaying 的情感分析
</div>

**积极情感：**

```json
{
  "value": "#nowplaying (happy OR exciting OR excited OR favorite OR fav OR amazing OR lovely OR incredible) (place_country:US OR place_country:MX OR place_country:CA) -horrible -worst -sucks -bad -disappointing",
  "tag": "#nowplaying positive"
}
```

**负面情感：**

```json
{
  "value": "#nowplaying (horrible OR worst OR sucks OR bad OR disappointing) (place_country:US OR place_country:MX OR place_country:CA) -happy -exciting -excited -favorite -fav -amazing -lovely -incredible",
  "tag": "#nowplaying negative"
}
```

<div id="using-post-annotations">
  ### 使用帖子注解
</div>

使用 `context:` 运算符查找带图片的日语宠物（不包括猫）帖子：

首先，使用 [Post lookup](/zh/x-api/posts/lookup/introduction) 并通过 `tweet.fields=context_annotations` 来识别 domain.entity 的 ID：

* Cats：`domain` 66，`entity` 852262932607926273
* Pets：`domain` 65，`entity` 852262932607926273

```json
{
  "value": "context:65.852262932607926273 -context:66.852262932607926273 -is:retweet has:images lang:ja",
  "tag": "Japanese pets with images - no cats"
}
```
