<div id="introduction">
  #### 简介
</div>

在消费流式数据时，最大化连接时长并接收所有匹配数据是一个基本目标。这意味着，充分利用冗余连接、自动检测断线并快速重连，以及制定恢复丢失数据的方案都非常重要。

在本集成指南中，我们将讨论不同的恢复和冗余功能：冗余连接、回填（backfill）以及数据恢复。

**冗余连接**

简而言之，冗余连接就是允许你对同一个过滤流同时建立多个连接。这样可以让两个独立的消费者连接到同一个流，并在两条连接上接收到相同的数据，从而提供冗余能力。因此，你的应用在各种情况下都具备热备切换能力，例如当某条流连接断开，或者你的应用的主服务器发生故障时。

当前，过滤流仅允许具有 Enterprise 访问权限的 Project 建立最多两个冗余连接。要使用冗余流，只需使用与你的主连接相同的 URL 建立连接即可。你的流数据将通过这两条连接同时发送。

<div id="recovering-missed-data-after-a-disconnection-backfill">
  #### 断开连接后恢复遗漏数据：回填（Backfill）
</div>

在你检测到断开连接后，你的系统应该能够智能地重新连接到流。如果可能，你的系统应记录断开连接持续了多长时间，以便你可以使用合适的恢复功能来回填数据。 

如果你在使用具有 Enterprise 访问权限的 Project，并确认断开连接持续了五分钟或更短时间，你可以使用回填参数 `backfill_minutes`。如果你在 [GET /tweets/search/stream](/zh/x-api/posts/filtered-stream#get-2-tweets-search-stream) 请求中传递该参数，你将会接收到过去一到五分钟内与你的规则匹配的帖子。通常我们会优先投递这些较早的帖子，然后才是任何新的匹配帖子，而且不会对帖子进行去重。这意味着，如果你断开连接 90 秒，但请求了两分钟的回填数据，你将会收到 30 秒的重复帖子，你的系统应能够容忍这些重复。下面是带有回填参数的请求示例：

`curl 'https://api.x.com/2/tweets/search/stream?backfill_minutes=5' -H "Authorization: Bearer $ACCESS_TOKEN"`

如果你没有 Enterprise 访问权限，或者确认断开连接持续时间超过五分钟，你可以使用 [recent search endpoint](/zh/x-api/posts/search/introduction) 或恢复功能来请求遗漏的数据。但请注意，search Posts 端点不支持 sample:、bio:、bio&#95;name: 或 bio&#95;location: 操作符，并且在使用带重音符号和变音符号的关键字以及 #hashtag 操作符时，在匹配行为上存在某些差异。这些差异可能意味着，你无法完全恢复通过 filtered stream 端点本应接收到的所有帖子。 

**断开连接后恢复遗漏数据：恢复（Recovery）**

如果你在使用具有 Enterprise 访问权限的 Project，当你无法在 5 分钟的回填窗口内重新连接时，可以使用 Recovery 功能在过去 24 小时内恢复遗漏的数据。

流式恢复功能允许你拥有最长 24 小时的扩展回填窗口。Recovery 使你能够“重放”遗漏数据的时间区间。当你使用 `start_time` 和 `end_time` 请求参数发起连接请求时，将启动恢复流。一旦连接成功，Recovery 会重新推送指定时间区间内的数据，然后断开连接。  

你最多可以同时向 Recovery 发起 2 个并发请求，即“两项恢复作业”。在技术上，Recovery 与回填的工作方式相同，只是额外定义了开始时间和结束时间。一个恢复周期对应单个时间范围。

|     |     |     |
| :--- | :--- | :--- |
| **Name** | **Type** | **Description** |
| start&#95;time | date (ISO 8601) | YYYY-MM-DDTHH:mm:ssZ (ISO 8601/RFC 3339)。<br /><br />以 UTC 表示的日期时间，表示恢复的起始时间。 |
| end&#95;time | date (ISO 8601) | YYYY-MM-DDTHH:mm:ssZ (ISO 8601/RFC 3339)。<br /><br />以 UTC 表示的日期时间，表示恢复的结束时间。 |

请求 URL 示例： [https://api.x.com/2/tweets/search/stream?start&#95;time=2022-07-12T15:10:00Z&amp;end&#95;time=2022-07-12T15:20:00Z](https://api.x.com/2/tweets/search/stream?start_time=1985-04-12T23:20:50.52Z\&end_time=1985-04-13T00:20:50.52Z)
