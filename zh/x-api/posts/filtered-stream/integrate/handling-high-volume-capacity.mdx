<div id="how-to-plan-for-high-volume-social-data-events">
  ### 如何规划应对高流量社交数据事件
</div>

大型国内和全球性事件通常会伴随着社交媒体平台上用户活动的剧烈激增。有些事件是预先已知的，比如 Super Bowl、政治选举和全球各地的新年庆祝活动。还有一些则是由于突发情况引发的流量高峰，例如自然灾害、突发政治事件、流行文化热点时刻，或像 COVID-19 这样的公共卫生疫情。

这些用户活动的激增有时可能非常短暂（以秒计），也可能会持续数分钟。无论成因如何，都必须考虑它们对从 X 获取数据的应用可能产生的影响。下面是一些最佳实践，可帮助你的团队为高流量社交数据事件做好准备。

<div id="review-your-current-filtered-stream-rules">
  #### 检查你当前的 filtered stream 规则
</div>

* 在高数据量事件期间，某些关键词的使用量可能会飙升，例如品牌赞助大型体育赛事时，对该品牌的提及量。
* 注意避免任何不必要或过于宽泛的规则，以免产生不必要的数据量。
* 考虑在已知的高数据量事件发生之前与客户进行沟通，帮助他们做好相应规划。
     

<div id="stress-test-your-application">
  #### 为你的应用进行压力测试
</div>

预计突发流量可能会达到日常平均数据用量的 5–10 倍。根据你的规则集，增幅可能会远高于这一水平。

<div id="understand-delivery-caps-for-connections">
  #### 了解连接的投递上限
</div>

流和投递上限基于访问级别设定。因此，每条流可投递的结果量是一个固定值。

* **Academic**：每秒 250 条帖子
* **Enterprise**：每秒帖子数上限由访问级别决定

<div id="optimize-to-stay-connected">
  #### 优化以保持连接
</div>

对于流式连接而言，保持持续连接对避免丢失数据至关重要。你的客户端应用应能够检测到断线，并具备在断线后立即尝试重新连接的逻辑；如果重连尝试失败，应采用指数退避策略进行重试。
 

<div id="add-built-in-buffering-on-your-end">
  #### 在你的端加入内置缓冲机制
</div>

构建多线程应用程序是处理高流量数据流的关键策略。从整体上看，管理数据流的一个最佳实践是使用单独的线程/进程来建立流式连接，然后将接收到的 JSON 活动写入内存结构或带缓冲的流读取器。这个“轻量级”的流处理线程负责处理传入的数据，这些数据可以缓存在内存中，并根据需要扩展或收缩。然后由另一个线程消费该哈希表，执行对 JSON 的“繁重工作”，例如解析 JSON、准备数据库写入，或你的应用程序需要执行的任何其他操作。
 

<div id="global-events-global-time-zones">
  #### 全球事件 = 全球时区
</div>

这些事件可能发生在下班后或周末，因此请确保你的团队也已为非工作时间可能出现的流量激增做好准备。
