<div id="how-to-plan-for-high-volume-social-data-events">
  ### 如何规划应对高流量社交数据事件
</div>

重大的国家级和全球性事件，往往会伴随着社交媒体平台上用户活动的剧烈激增。有些事件是可以事先预知的，例如超级碗、政治选举，以及世界各地的新年庆祝活动。另一些情况下，流量激增则源于突发事件，比如自然灾害、突发政治事件、流行文化高光时刻，或像 COVID-19 这样的公共卫生疫情。

这些用户活动高峰有时可能非常短暂（以秒计），也可能会持续数分钟之久。无论其成因如何，都需要认真考虑它们对从 X 获取 data 的应用所产生的影响。以下是一些最佳实践，可帮助你的团队为高流量社交数据事件做好准备。

<div id="review-your-current-filtered-stream-rules">
  #### 审查您当前的过滤流（filtered stream）规则
</div>

* 在高流量事件期间，某些关键词的数量可能会激增，例如当某品牌赞助大型体育赛事时，与该品牌相关的提及会大幅增加。
* 注意避免任何不必要或过于宽泛的规则，以免产生多余的活动数据量。
* 考虑在预期的高流量事件发生前与客户进行沟通，以帮助他们做好相应规划。
     

<div id="stress-test-your-application">
  #### 对你的应用进行压力测试
</div>

预期突发流量可能会达到平均每日数据使用量的 5–10 倍。具体增幅可能会因你的规则集而远高于这一水平。

<div id="understand-delivery-caps-for-connections">
  #### 了解连接的投递上限
</div>

流式连接和投递上限基于不同的访问级别设定。这会导致流式数据具有固定的数据投递量。

* **Academic**：250 帖子/秒
* **Enterprise**：帖子/秒的上限由访问级别决定

<div id="optimize-to-stay-connected">
  #### 优化以保持连接
</div>

对于流式连接来说，保持连接对于避免丢失数据至关重要。你的客户端应用程序应能够检测到连接断开，并实现逻辑在断开后立即尝试重新连接；如果重连尝试失败，则应采用指数退避策略进行重试。
 

<div id="add-built-in-buffering-on-your-end">
  #### 在你这端添加内置缓冲机制
</div>

构建多线程应用程序是处理高吞吐量数据流的一项关键策略。从整体上看，管理数据流的最佳实践是：使用一个单独的线程/进程来建立流式连接，然后将接收到的 JSON 活动数据写入内存结构或带缓冲的流读取器中。这个“轻量级”的流处理线程负责处理传入的数据，这些数据可以在内存中进行缓冲，并根据需要动态扩展和收缩。然后由另一个线程来消费该哈希结构，完成对 JSON 的解析、准备数据库写入，或执行你的应用程序需要完成的其他繁重工作。
 

<div id="global-events-global-time-zones">
  #### 全球事件 = 全球时区
</div>

这些事件可能发生在非工作时间或周末，因此请确保你的团队已做好准备，应对在日常工作时间之外出现的流量高峰。
