<div id="deduplication">
  ## 去重
</div>

所有资源都会在一个**基于 UTC 的 24 小时时间窗口**内进行去重。如果你请求并为某个资源（例如一个帖子）付费，那么在该时间窗口内再次请求同一资源将不会产生额外收费。

这意味着：

* 在一天内多次请求同一个帖子只计为一次收费
* 去重窗口会在 UTC 午夜重置
* 这适用于所有可计费资源（帖子、用户等）

<Note>
  去重是一个**软性保证**。虽然在绝大多数情况下都会生效，但在某些特定边缘场景（例如服务中断）下，可能会出现资源未被去重的情况。
</Note>

<div id="credit-balance">
  ## 额度余额
</div>

你的额度余额会显示在 Developer Console 中。当你发出 API 请求时，额度会被实时扣减。

<Warning>
  请定期监控你的额度余额，以避免服务中断。在余额降为零之前充值额度，以确保 API 访问不中断。

  ***注意：** 账户额度余额有可能会略微变为负数。在这种情况下，在你充值以弥补负余额之前，API 请求将会被阻止。*
</Warning>

<div id="auto-recharge">
  ### 自动充值
</div>

启用自动充值功能，可在余额不足时自动为你的信用余额充值，从而避免服务中断。请在 Developer Console 中进行配置：

| Setting | Description |
|:--------|:------------|
| **Recharge amount** | 自动充值被触发时要增加的金额（例如 $25） |
| **Trigger threshold** | 当你的余额低于此金额时，将触发自动充值（例如 $5） |

<Note>
  自动充值需要有已保存并设置为默认的付款方式。你可以随时在 Developer Console 中取消，或通过联系支持团队取消。
</Note>

***

<div id="spending-limits">
  ### 支出上限
</div>

为每个计费周期设置你可支出的最高金额，以控制成本。当达到上限时，在下一个计费周期开始之前，API 请求将被阻止。

| 选项 | 说明 |
|:-------|:------------|
| **支出上限** | 设置一个具体的美元金额，作为每个计费周期的最高支出金额 |

<Tip>
  使用支出上限可以防止产生意外费用，尤其是在开发和测试阶段。
</Tip>

<div id="monitoring-usage">
  ## 监控用量
</div>

通过 [Usage 端点](/zh/x-api/usage/introduction) 以编程方式跟踪 API 使用情况：

```bash
curl "https://api.x.com/2/usage/tweets" \
  -H "Authorization: Bearer $BEARER_TOKEN"
```

这将返回每日帖子用量统计，帮助你：

* 根据你的预算跟踪用量
* 在接近配额上限时设置告警
* 识别用量较高的端点
* 生成使用情况报告
