<div id="deduplication">
  ## 去重
</div>

所有资源都会在一个**24 小时（按 UTC 计算的自然日）窗口**内进行去重。如果你请求并为某个资源（例如一个帖子）付费，那么在该窗口内再次请求相同资源将不会产生额外费用。

这意味着：

* 在同一 UTC 日内多次请求同一个帖子只计为一次收费
* 去重窗口会在 UTC 午夜重置
* 这适用于所有可计费资源（帖子、用户等）

<Note>
  去重是一种**软保证**。虽然在绝大多数情况下都会执行去重，但在某些特定边缘情况（例如服务中断）下，可能会出现资源未被成功去重的情况。
</Note>

<div id="credit-balance">
  ## 信用额度余额
</div>

您的信用额度余额会显示在开发者控制台中。每当您发起 API 请求时，系统会实时扣减相应的信用额度。

<Warning>
  请定期监控您的信用额度余额，以避免服务中断。在余额归零之前为账户充值，以确保 API 访问不中断。

  ***注意：** 账户信用额度余额有可能会出现小幅为负的情况。在您充值以弥补负余额之前，API 请求将被阻止。*
</Warning>

<div id="auto-recharge">
  ### 自动充值
</div>

启用自动充值可在余额不足时自动为你的信用余额充值，避免服务中断。请在开发者控制台中进行配置：

| Setting | Description |
|:--------|:------------|
| **充值金额** | 自动充值触发时要添加的金额（例如 $25） |
| **触发阈值** | 当你的余额低于此金额时触发自动充值（例如 $5） |

<Note>
  自动充值需要有一项已保存并设为默认的支付方式。你可以随时在开发者控制台中或通过联系支持来取消。
</Note>

<div id="spending-limits">
  ### 支出限额
</div>

为每个计费周期设置你可以支出的最高金额，以控制成本。达到限额后，API 请求将在下一个计费周期开始前被阻止。

| 选项 | 说明 |
|:-------|:------------|
| **支出限额** | 为每个计费周期设置一个具体的美元数额作为你的最高支出 |

<Tip>
  使用支出限额来防止出现意外费用，尤其是在开发和测试期间。
</Tip>

<div id="monitoring-usage">
  ## 监控使用情况
</div>

通过 [Usage endpoint](/zh/x-api/usage/introduction) 以编程方式跟踪你的 API 使用情况：

```bash
curl "https://api.x.com/2/usage/tweets" \
  -H "Authorization: Bearer $BEARER_TOKEN"
```

这将返回每日帖子用量统计，帮助您：

* 按预算跟踪用量
* 在接近上限时设置告警
* 识别高用量的端点
* 生成用量报告
