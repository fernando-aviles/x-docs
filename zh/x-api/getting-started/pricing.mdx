<div id="deduplication">
  ## 去重
</div>

所有资源都会在**按 UTC 计算的 24 小时窗口**内进行去重。如果你请求并为某个资源（例如一条帖子）付费，那么在该时间窗口内再次请求同一资源将不会产生额外费用。

这意味着：

* 在一天内多次请求同一条帖子只会计费一次
* 去重窗口会在 UTC 午夜重置
* 这适用于所有可计费资源（帖子、用户等）

<Note>
  去重是一种**软性保障**。虽然在绝大多数情况下都会生效，但在某些特定边缘情况（例如服务中断）中，可能会出现资源未被去重的情况。
</Note>

<div id="credit-balance">
  ## 信用余额
</div>

你的信用余额会显示在开发者控制台中。每当你发起 API 请求时，系统都会实时扣减相应额度。

<Warning>
  请定期查看你的信用余额，以避免服务中断。在余额归零之前及时充值，确保 API 访问不中断。

  ***注意：** 账户信用余额有可能会略微为负值。在这种情况下，在你充值补足负余额之前，API 请求将会被阻止。*
</Warning>

<div id="auto-recharge">
  ### 自动充值
</div>

启用自动充值，可在余额不足时自动为你的信用余额充值，避免服务中断。请在开发者控制台中进行配置：

| 设置 | 说明 |
|:--------|:------------|
| **Recharge amount** | 自动充值被触发时追加的金额（例如 $25） |
| **Trigger threshold** | 当你的余额低于该金额时会触发自动充值（例如 $5） |

<Note>
  自动充值需要有已保存并设为默认的支付方式。你可以随时在开发者控制台中取消，或通过联系支持进行取消。
</Note>

***

<div id="spending-limits">
  ### 支出限额
</div>

为每个计费周期设置你在该周期内可支出的最高金额，以控制成本。当达到该限额时，API 请求将被阻止，直到下一个计费周期开始。

| Option | Description |
|:-------|:------------|
| **Spending limit** | 为每个计费周期设置一个具体的美元金额作为你的最高支出 |

<Tip>
  使用支出限额来防止产生意外费用，尤其是在开发和测试期间。
</Tip>

<div id="monitoring-usage">
  ## 监控用量
</div>

使用 [Usage endpoint](/zh/x-api/usage/introduction) 以编程方式跟踪你的 API 用量：

```bash
curl "https://api.x.com/2/usage/tweets" \
  -H "Authorization: Bearer $BEARER_TOKEN"
```

这会返回每日帖子使用量统计，帮助你：

* 对照预算跟踪用量
* 在接近限制时设置警报
* 识别高消耗端点
* 生成使用报告
