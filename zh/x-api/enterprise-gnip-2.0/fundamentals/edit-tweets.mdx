企业级端点已更新，可提供帖子编辑元数据。&#95;Edit Posts&#95; 功能最初于 2022 年 9 月 1 日在 X 员工中启动测试。从该日期开始，符合条件的帖子可在 30 分钟内编辑，且最多可编辑 5 次。*自 2022 年 9 月 29 日起创建的所有帖子对象* 都包含帖子编辑元数据，即使该帖子从未被编辑。每次帖子被编辑时，都会创建一个新的帖子 ID。一个帖子的编辑历史可以通过将这些 ID 串联起来进行描述，从原始 ID 开始。此外，如果编辑链中的任意一个帖子被删除，该链中的所有帖子也都会被删除。

这些元数据会自动包含在内。无需在请求中添加任何参数即可将可用的编辑历史作为帖子对象的一部分返回。

借助这些新的元数据，开发者可以了解：

* 帖子在创建时是否具备可编辑资格。某些帖子（例如包含投票或预定发布的帖子）无法编辑。
* 帖子在 30 分钟内可编辑，且最多可编辑 5 次。对于可编辑的帖子，你可以查看是否仍有剩余编辑时间以及还可以编辑多少次。
* 你当前查看的是否为某个帖子的已编辑版本。在大多数情况下，除非通过帖子 ID 请求特定的历史版本，否则 API 将返回该帖子的最新版本。

在顶层新增了三个帖子属性：

* **edit&#95;history** - 提供与该帖子的编辑历史相关的所有帖子 ID。&quot;initial&#95;tweet&#95;id&quot; 属性表示原始帖子，而 &quot;edit&#95;tweet&#95;ids&quot; 属性是一个数组，提供与其编辑历史相关的所有 ID。如果该帖子从未被编辑，则该数组只包含一个 ID。

```
"edit_history": {
    "initial\_tweet\_id": "1283764123"
    "edit\_tweet\_ids": \["1283764123"\]
  }
```

* **edit&#95;controls** - 提供属性，用于指示 30 分钟编辑窗口的结束时间以及剩余的可编辑次数。

```
"edit_controls": {  
     "editable\_until\_ms": 1660155761384
     "edits_remaining": 3   
  }
```

* **editable** - 指示帖子在创建时是否可编辑。 

&quot;editable&quot;: true

大多数帖子都可编辑。但以下类型的帖子不可编辑： 

* 帖子是推广内容
* 帖子包含投票
* 帖子是非本人线程中的回复
* 帖子是 Retweet（注意，Quote Tweets 可以编辑）
* 帖子为 nullcast
* 社区帖子
* Superfollow 帖子
* 协作帖子

**合规支持**

[Compliance Firehose](/zh/x-api/enterprise-gnip-2.0/fundamentals/firehouse) 和 v2 的 [batch compliance endpoint](/zh/x-api/compliance/batch-compliance/introduction) 都已更新，以支持帖子编辑功能：

在 Compliance Firehose 中新增了一种名为 &quot;tweet&#95;edit&quot; 的事件类型。

```
{
  "tweet_edit": {
    "id": <tweetId>,
    "initial_tweet_id": <tweetId>,
    "edit_tweet_ids": [<tweetId1>, <tweetId2>, <tweetId3> ...],
    "timestamp_ms": "<timestampMsStr>"
  }
}
```
