<div id="usage-api-twitter-api">
  ## 使用量 API | Twitter API
</div>

<div id="overview">
  ### 概览
</div>

`Enterprise`

这是在您的账户下，用于帮助监控和管理跨不同 API 使用情况的最重要且&#95;最佳&#95;的工具。

**重要免责声明：**

由于试用期和其他计费调整，Usage API 返回的使用量统计可能与账单或发票上的数字不一致。所有数字均基于在某一日期（UTC）内去重后的消耗活动量计算得出。

<div id="features">
  #### 功能
</div>

* 以编程方式检索 console.gnip.com UI 中可用的使用数据
* 流级使用数据 - 除产品级别外，还提供流级别（例如 dev 和 prod）的使用数据
* 细粒度且具有描述性的数据 - 搜索请求（requests）按 Full-Archive 和 30-Day Search 产品拆分
* 历史 PowerTrack “days”和“jobs” 

<div id="supported-apis">
  ### 支持的 API
</div>

以下是目前由 Usage API 支持的 API 列表：

* PowerTrack API `enterprise`
* 30-Day Search API `enterprise`
* Full-Archive Search API `enterprise`
* Historical PowerTrack `enterprise`

<div id="limitations">
  ### 限制
</div>

* Usage API 允许你访问自 2018 年 5 月 1 日以来的使用数据。2019 年 7 月 1 日之后，Usage API 允许你访问**最近 13 个日历月**的使用数据。

* 你可以使用由 fromDate 和 toDate 定义的**三个月区间**来访问使用数据。

请参阅以下请求和响应：

```bash
curl -u<username>:<password> \
"https://gnip-api.x.com/metrics/usage/accounts/<account-name>.json?bucket=month"
```

<div id="methods">
  #### **Methods**
</div>

| Method | Description |
| :--- | :--- |
| [GET /metrics/usage/accounts/{ACCOUNT_NAME}.json](#GETData) | 获取使用情况数据 |

Where:

* :account&#95;name 是与您的账户关联的、区分大小写的名称，如在 console.gnip.com 中所显示

<div id="authentication-and-rate-limit">
  #### **身份验证与速率限制**
</div>

<div id="authentication">
  ##### **Authentication**
</div>

对 Usage API 的所有请求都需要使用 HTTP 基本身份验证（HTTP Basic Authentication）。请使用你账号中已启用的任一电子邮件/密码凭证，这些凭证可用于登录你在 console.gnip.com 的账户或连接任意 Gnip 数据流。

<div id="rate-limit">
  ##### **速率限制**
</div>

Usage API 的调用频率限制为每分钟最多两次请求。

<div id="best-practices-limitations">
  #### **最佳实践和限制**
</div>

<div id="data-availability">
  ##### **数据可用性**
</div>

Usage data 基于去重后的活动，这些活动来自最近一个已完整处理数据的时间段（UTC）。除非 Gnip 正在部署系统，否则数据通常会被处理并更新到分钟级。

* Usage API 允许你访问自 2018 年 5 月 1 日以来的使用量数据。从 2019 年 7 月 1 日起，Usage API 允许你访问**向前回溯 13 个日历月**的使用量数据。 

* 你可以通过使用 fromDate 和 toDate，以**三个月为一个区间**的方式访问使用量数据。

<div id="requesting-and-receiving-data">
  #### **请求与接收数据**
</div>

Usage API 的工作方式是：向与你的账户关联的 API 端点发送带有 HTTP BASIC-AUTH 身份验证凭据的 HTTP GET 请求。

<div id="get-request">
  ##### GET 请求:
</div>

使用你的用户凭证和账户名称，向以下端点发起 GET 请求：

https://gnip-api.x.com/metrics/usage/accounts/:account&#95;name.json

**其他参数**

|     |     |
| :--- | :--- |
| bucket | 可选。用于返回使用数据的时间单位。使用数据可以按每日或每月粒度返回。  <br />  <br />未指定 bucket 的请求将返回按月粒度的数据。  <br />  <br />选项：&#39;month&#39; 或 &#39;day&#39; |
| fromDate (YYYYMMDDHHMM) | 可选。使用数据仅自 2018 年 5 月 1 日起可用。用于返回使用数据的最早 UTC 时间戳。时间戳以天为粒度，并且是包含的（例如，201805010000 包含 05-01 这一天）。如果小时或分钟的值不是 &#39;0000&#39;，请求会被重置为 &#39;0000&#39;。  <br />  <br />未包含 fromDate 或 toDate 的请求将按月返回当月的使用数据，并包含前两个月的历史数据。  <br />  <br />**请注意：** 自 2019 年 6 月 1 日起，你可以访问过去 13 个日历月的使用数据。例如，如果当前日期是 10 月 10 日，你可以访问回溯到上一年 9 月 1 日的使用数据。  <br />**示例：** 201810010000 将返回从 2018 年 10 月 1 日（含 10 月 1 日）开始的数据。 |
| toDate (YYYYMMDDHHMM) | 可选。用于返回使用数据的最晚 UTC 时间戳。时间戳以天为粒度且不包含该日（例如，201703020000 不包含 03-02 这一天的数据）。当为当日或将来的某日指定 toDate 时，将返回截至最后一个完整日（UTC）的使用数据。如果小时或分钟的值不是 &#39;0000&#39;，请求会被重置为 &#39;0000&#39;。  <br />  <br />未指定 toDate 的请求将默认使用下一个 bucket（当 bucket=day 时为明天；当 bucket=month 时为下个月）。未指定 fromDate 和 toDate 的请求将默认使用 bucket=month，并显示当前月份以及紧邻的前两个月的数据。  <br />  <br />**示例：** 201703050000 将返回截至 2017 年 3 月 5 日的数据，但不包含 3 月 5 日当天的任何数据。 |

**GET 请求示例**

此请求将按月粒度返回从 2017 年 3 月 1 日到 2017 年 3 月 5 日的数据，但不包含 2017 年 3 月 5 日当天的任何数据。

curl -u &quot;https://gnip-api.x.com/metrics/usage/accounts/:account&#95;name.json?bucket=month&amp;fromdate=201403010000&amp;toDate=201403150000&quot;

<div id="data-format">
  #### **数据格式**
</div>

下表说明了 Usage API 返回的用量数据的根级别数据结构。对于具有多级子字段的字段，请点击提供的链接查看这些子字段的详细信息。

如果你想查看完整的 Usage API 负载示例，请访问[此页面](/zh/x-api/usage/introduction)。

|     |     |
| :--- | :--- |
| **account** | 表示请求用量数据所属账号的对象。 |
| **bucket** | 提供用量数据的时间单位，可以是 &#39;day&#39; 或 &#39;month&#39;。 |
| **fromDate** | 你希望提取用量数据的最早 UTC 时间戳（包含该时间点）。 |
| **toDate** | 你希望提取用量数据的最晚 UTC 时间戳（不包含该时间点）。 |
| **publishers** | 包含三个主要对象：Used、projected 和 products。 |
