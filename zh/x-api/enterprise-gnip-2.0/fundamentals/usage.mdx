<div id="usage-api-twitter-api">
  ## 用量 API | Twitter API
</div>

<div id="overview">
  ### 概览
</div>

`Enterprise`

这是你在账户下用于监控和管理各个 API 使用情况的最重要、也是&#95;最佳&#95;的工具。

**重要免责声明：**

由于试用和其他账单调整，Usage API 返回的使用量可能与发票上的数据不完全一致。所有数值均基于在特定日期（UTC）内去重后的实际活动消耗量计算得出。

<div id="features">
  #### 功能
</div>

* 以编程方式检索在 console.gnip.com 控制台界面中可用的使用数据
* 流级使用数据——在产品级别之外，还提供流级别（例如 dev 和 prod）的使用数据
* 细粒度且具描述性的使用数据——搜索请求（&quot;requests&quot;）会按 Full-Archive 和 30-Day Search 产品进行拆分
* 历史 PowerTrack “days” 和 “jobs” 数据 

<div id="supported-apis">
  ### 支持的 API
</div>

以下是 Usage API 当前支持的 API 列表：

* PowerTrack API `enterprise`
* 30-Day Search API `enterprise`
* Full-Archive Search API `enterprise`
* Historical PowerTrack `enterprise`

<div id="limitations">
  ### 限制
</div>

* Usage API 允许你访问自 2018 年 5 月 1 日以来的用量数据。自 2019 年 7 月 1 日起，Usage API 允许你访问 **过去 13 个日历月** 的用量数据

* 你可以按由 fromDate 和 toDate 定义的 **三个月区间** 访问用量数据

请参见下方的请求和响应示例：

```bash
curl -u<username>:<password> \
"https://gnip-api.x.com/metrics/usage/accounts/<account-name>.json?bucket=month"
```

<div id="methods">
  #### **Methods**
</div>

| Method | Description |
| :--- | :--- |
| [GET /metrics/usage/accounts/{ACCOUNT_NAME}.json](#GETData) | 获取使用情况数据 |

Where:

* :account&#95;name 是与您的账户关联的（区分大小写的）名称，如在 console.gnip.com 中所显示

<div id="authentication-and-rate-limit">
  #### **身份验证与速率限制**
</div>

<div id="authentication">
  ##### **Authentication**
</div>

对 Usage API 的所有请求都需要使用 HTTP 基本身份验证（HTTP Basic Authentication）。你可以使用你账户中任一已启用的邮箱/密码凭据，这些凭据可用于登录你在 console.gnip.com 的账户或连接到任何 Gnip 流。

<div id="rate-limit">
  ##### **速率限制**
</div>

Usage API 的调用频率限制为每分钟最多 2 次请求。

<div id="best-practices-limitations">
  #### **最佳实践与限制**
</div>

<div id="data-availability">
  ##### **数据可用性**
</div>

用量数据基于已去重的活动，这些活动来自最近一个已处理完成的完整时间区间（UTC）。除非 Gnip 正在部署系统，一般情况下数据会被处理并实时更新至分钟级。

* Usage API 允许你访问自 2018 年 5 月 1 日起的用量数据。自 2019 年 7 月 1 日起，Usage API 允许你访问最近 **13 个自然月** 的用量数据。 

* 你可以通过使用 fromDate 和 toDate，按定义的 **三个月时间区间** 访问用量数据

<div id="requesting-and-receiving-data">
  #### **请求与接收数据**
</div>

Usage API 的工作方式是使用 HTTP BASIC-AUTH 凭据向与你的账户对应的 API 端点发起 HTTP GET 请求。

<div id="get-request">
  ##### GET 请求：
</div>

使用你的用户凭证和账户名称，向以下端点发起 GET 请求：

https://gnip-api.x.com/metrics/usage/accounts/:account&#95;name.json

**附加参数**

|     |     |
| :--- | :--- |
| bucket | 可选。返回使用量数据所采用的时间单位。使用量数据可以按天或按月粒度返回。  <br />  <br />未指定 bucket 的请求将返回按月粒度的数据。  <br />  <br />可选值：`month` 或 `day` |
| fromDate (YYYYMMDDHHMM) | 可选。使用量数据仅从 2018 年 5 月 1 日起可用。此字段表示将要返回的使用量数据中最早的 UTC 时间戳。时间戳为按天粒度，且为包含（即 201805010000 包含 05 月 01 日当天）。在小时和分钟粒度上，包含除 `0000` 以外值的请求会被重置为 `0000`。  <br />  <br />未指定 fromDate 或 toDate 的请求，将按月返回当前月份的使用量数据，并包含前两个月的历史参考数据。  <br />  <br />**请注意：** 自 2019 年 6 月 1 日起，你可以访问过去 13 个日历月的使用量数据。例如，如果当前日期是 10 月 10 日，你可以访问到上一年 9 月 1 日起的使用量数据。  <br />**示例：** 201810010000 将返回从 2018 年 10 月 1 日起（包含 10 月 1 日）的数据。 |
| toDate (YYYYMMDDHHMM) | 可选。此字段表示将要返回的使用量数据中最新的 UTC 时间戳。时间戳为按天粒度，且为不包含（即 201703020000 不包含 03 月 02 日当天的数据）。当指定的 toDate 为当前日或未来某一日时，使用量数据会返回到最近一个完整自然日（UTC）。在小时和分钟粒度上，包含除 `0000` 以外值的请求会被重置为 `0000`。  <br />  <br />未指定 toDate 的请求，默认设置为下一个 bucket（当 bucket=day 时为明天，当 bucket=month 时为下个月）。同时未指定 fromDate 和 toDate 的请求会默认设置为 bucket=month，并显示当前月份以及之前紧邻的两个完整月份的数据。  <br />  <br />**示例：** 201703050000 将返回截至 2017 年 3 月 5 日的数据，但不包含 3 月 5 日当天的任何数据。 |

**GET 请求示例**

此请求将按月粒度返回从 2017 年 3 月 1 日到 2017 年 3 月 5 日的数据，但不包含 2017 年 3 月 5 日的任何数据。

curl -u &quot;https://gnip-api.x.com/metrics/usage/accounts/:account&#95;name.json?bucket=month&amp;fromdate=201403010000&amp;toDate=201403150000&quot;

<div id="data-format">
  #### **数据格式**
</div>

下表描述了 Usage API 返回的使用数据在根级的 data 结构。对于具有多级子字段的字段，请单击提供的链接以查看这些子字段的详细信息。

如果你想查看完整 Usage API 响应负载的示例，请访问[此页面](/zh/x-api/usage/introduction)。

|     |     |
| :--- | :--- |
| **account** | 表示请求使用数据所针对账户的对象。 |
| **bucket** | 提供使用数据的时间单位。可以是 &#39;day&#39; 或 &#39;month&#39;。 |
| **fromDate** | 希望提取使用数据的最早 UTC 时间戳（含）。 |
| **toDate** | 希望提取使用数据的最晚 UTC 时间戳（不含）。 |
| **publishers** | 包含三个主要对象：used、projected 和 products。 |
