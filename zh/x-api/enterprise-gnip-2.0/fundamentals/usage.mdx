<div id="usage-api-twitter-api">
  ## 用量 API | Twitter API
</div>

<div id="overview">
  ### 概览
</div>

`Enterprise`

这是帮助你监控和管理你帐户下各个 API 使用情况的最重要、也是&#95;最佳&#95;的工具。

**重要免责声明：**

由于试用和其他计费调整，Usage API 返回的使用量统计可能与账单发票上的数据不一致。所有数值均基于某一日（按 UTC 计算）内去重后的消耗活动数。

<div id="features">
  #### 功能
</div>

* 以编程方式获取 console.gnip.com UI 中提供的用量数据
* 流级用量数据——在产品级别之外，还提供流级别（例如开发环境 dev 和生产环境 prod）的用量数据
* 细粒度且描述性强的数据——将搜索请求按 Full-Archive 和 30-Day Search 产品拆分统计
* 历史 PowerTrack “days” 和 “jobs” 数据 

<div id="supported-apis">
  ### 支持的 API
</div>

Usage API 当前支持的 API 如下：

* PowerTrack API `enterprise`
* 30-Day Search API `enterprise`
* Full-Archive Search API `enterprise`
* Historical PowerTrack `enterprise`

<div id="limitations">
  ### 限制
</div>

* Usage API 允许你访问自 2018 年 5 月 1 日以来的使用数据。自 2019 年 7 月 1 日起，Usage API 允许你访问**最近 13 个日历月**内的使用数据

* 你可以通过指定 fromDate 和 toDate，以**三个月为一个区间**访问使用数据

请参阅下面的请求和响应示例：

```bash
curl -u<username>:<password> \
"https://gnip-api.x.com/metrics/usage/accounts/<account-name>.json?bucket=month"
```

<div id="authentication-and-rate-limit">
  #### **身份验证和速率限制**
</div>

<div id="authentication">
  ##### **身份验证**
</div>

所有对 Usage API 的请求都需要使用 HTTP 基本认证。你可以使用你账号中任一已启用的电子邮件/密码凭证，这些凭证可用于登录你在 console.gnip.com 上的账号，或连接到任何 Gnip 流。

<div id="rate-limit">
  ##### **速率限制**
</div>

Usage API 的速率限制为每分钟最多 2 次请求。

<div id="best-practices-limitations">
  #### **最佳实践和限制**
</div>

<div id="data-availability">
  ##### **数据可用性**
</div>

使用数据基于去重后的活动，这些活动来自最近一个已完成处理的数据完整时间段（UTC）。数据通常会被处理并实时更新到分钟级，除非 Gnip 正在部署系统。

* Usage API 允许你访问自 2018 年 5 月 1 日起的使用数据。自 2019 年 7 月 1 日起，Usage API 允许你访问**最近 13 个日历月**的使用数据。 

* 你可以按以 `fromDate` 和 `toDate` 定义的**连续三个月时间区间**来访问使用数据。

<div id="requesting-and-receiving-data">
  #### **请求与接收数据**
</div>

Usage API 的工作方式是向与你的账户关联的 API 端点发送携带 HTTP BASIC-AUTH 凭据的 HTTP GET 请求。

<div id="get-request">
  ##### GET Request:
</div>

使用你的用户凭证和账户名称，向以下端点发送 GET 请求：

https://gnip-api.x.com/metrics/usage/accounts/:account&#95;name.json

**Additional Parameters**

|     |     |
| :--- | :--- |
| bucket | 可选。用于提供用量数据的时间单位。用量数据可以按天或按月粒度返回。  <br />  <br />未指定 bucket 的请求将返回按月粒度的数据。  <br />  <br />选项：&#39;month&#39; 或 &#39;day&#39; |
| fromDate (YYYYMMDDHHMM) | 可选。用量数据最早可从 2018 年 5 月 1 日开始获取。该参数为提供用量数据的最早 UTC 时间戳。时间戳为按天粒度且为包含关系（即 201805010000 包含 0501 这一天）。请求中如果在小时和分钟粒度上使用了除 &#39;0000&#39; 之外的值，将默认重置为 &#39;0000&#39;。  <br />  <br />未指定 fromDate 或 toDate 的请求，将按月返回当月的用量数据，并包含最近两个月的历史数据。  <br />  <br />**请注意：** 自 2019 年 6 月 1 日起，你可以访问过去 13 个日历月的用量数据。例如，如果当前日期是 10 月 10 日，你可以访问前一年 9 月 1 日起的用量数据。  <br />**示例：**201810010000 将返回从 2018 年 10 月 1 日起（包含 10 月 1 日）的数据。 |
| toDate (YYYYMMDDHHMM) | 可选。用于提供用量数据的最新 UTC 时间戳。时间戳为按天粒度且为不包含关系（即 201703020000 不包含 0302 这一天的数据）。当为当前日或未来某日指定 toDate 时，用量数据将返回到最近一个完整日（UTC）。请求中如果在小时和分钟粒度上使用了除 &#39;0000&#39; 之外的值，将默认重置为 &#39;0000&#39;。  <br />  <br />未指定 toDate 的请求，将默认使用下一个 bucket（当 bucket=day 时为明天，当 bucket=month 时为下个月）。未指定 fromDate 和 toDate 的请求将默认 bucket=month，并显示当前月和紧邻的前两个月的数据。  <br />  <br />**示例：**201703050000 将返回截至 2017 年 3 月 5 日的数据，但不包含 3 月 5 日当天的任何数据。 |

**Example GET Request**

此请求将按月粒度返回从 2017 年 3 月 1 日到 2017 年 3 月 5 日的用量数据，但不包含 2017 年 3 月 5 日当天的任何数据。

curl -u &quot;https://gnip-api.x.com/metrics/usage/accounts/:account&#95;name.json?bucket=month&amp;fromdate=201403010000&amp;toDate=201403150000&quot;

<div id="data-format">
  #### **数据格式**
</div>

下表描述了 Usage API 返回的用量数据的根级数据结构。对于包含多级子字段的字段，请点击提供的链接以展开查看子字段的详细信息。

如果你想查看完整的 Usage API 负载示例，请访问[此页面](/zh/x-api/usage/introduction)。

|     |     |
| :--- | :--- |
| **account** | 表示请求用量数据所针对账号的对象。 |
| **bucket** | 提供用量数据所对应的时间单位，可以是 &quot;day&quot; 或 &quot;month&quot;。 |
| **fromDate** | 要获取用量数据的最早 UTC 时间戳（含该时间点）。 |
| **toDate** | 要获取用量数据的最晚 UTC 时间戳（不含该时间点）。 |
| **publishers** | 包含三个主要对象：Used、projected 和 products。 |
