<div id="getting-started-with-enterprise-rules-and-queries">
  ## 企业规则和查询入门
</div>

使用 enterprise 运算符的产品会根据你设置的过滤规则向你提供社交数据。规则由一个或多个“子句”组成，子句可以是关键字、精确短语，或众多 enterprise 运算符之一。在开始使用 enterprise 运算符构建规则之前，请务必先查看下面描述的语法，浏览可用运算符列表，并了解构建规则时的限制。你还应当在“[运算顺序](#orderofoperations)”部分理解规则在逻辑上如何求值的各种细节。

多个子句可以通过 &quot;and&quot; 和 &quot;or&quot; 逻辑进行组合。

**请注意：** &quot;And&quot; 逻辑通过子句之间的空格指定，而 &quot;or&quot; 逻辑则通过大写的 `OR` 指定。 

每条规则最长可以包含 2,048 个字符，对正向子句（你希望匹配或基于其进行过滤的内容）和负向子句（你希望排除且不匹配的内容）的数量没有限制。
 

<div id="building-rules-and-queries">
  ### 构建规则和查询
</div>

**关键词匹配**

关键词匹配类似于搜索界面中的查询。例如，下面的企业级运算符规则将匹配正文中包含 &quot;social&quot; 这一术语的活动。

`social`

**使用空格进行 AND 连接**

添加另一个关键词等同于为匹配增加一个额外条件。例如，下面的规则只会匹配文本中同时包含 &quot;social&quot; 和 &quot;media&quot; 的活动，顺序不限——*在术语之间使用空格相当于布尔 AND 逻辑*。如果在规则中显式写出 AND，则会被 rules 端点拒绝。

`social media`

**使用大写 OR 进行 OR 连接**

很多情况下实际上需要布尔 OR 逻辑。这也很容易实现。*注意 OR 运算符必须是大写，使用小写 “or” 会被当作普通关键词处理。*

`social OR data`

**术语取反**

还有一些场景可能需要排除包含某些关键词的结果（布尔 NOT 逻辑）。例如，包含 “happy” 的活动，但排除任何文本中含有 “birthday” 的结果。

`social -personality`

**使用括号进行分组**

这些逻辑类型可以通过使用括号分组进行组合，并扩展为更加复杂的查询。

`(social OR data) (academic OR research) -personality -information -university`

不过这仅仅是个开始——虽然上面的示例只是依赖于对关键词的分词匹配，企业级产品还提供了在文本上执行不同类型匹配的运算符。

**精确匹配**

`"social media research"`

**子串匹配**

`contains:info`

**邻近匹配**

`"social media research"~3`

此外，还有其他运算符允许你根据除文本以外的社交数据的独特属性进行过滤。 

**发布帖子的用户**

`from:XDeveloeprs`

**距离美国科罗拉多州博尔德市 Pearl St. 10 英里范围内的地理标记推文**

`point_radius:[-105.27346517 40.01924738 10.0mi]`

**综合运用**

你可以将它们与文本过滤器结合使用，并应用上述相同类型的逻辑。

`(social OR data) (academic OR research OR "social media research") point_radius:[-105.27346517 40.01924738 10.0mi] lang:en -personality -information -university`

<div id="boolean-syntax">
  ### 布尔语法
</div>

前一节中的示例使用了多种类型的布尔逻辑和分组。请参阅下表，了解每种语法及其要求的详细说明。

|     |     |     |
| :--- | :--- | :--- |
| **逻辑类型** | **运算符语法** | 说明 |
| AND | social data | 在两个运算符之间使用空格分隔，会在它们之间形成 AND 逻辑。  <br />  <br />匹配同时包含两个关键词（&quot;social&quot;、&quot;data&quot;）的活动。  <br />  <br />**不要在规则中显式使用 AND。只使用空格。显式写出的 AND 会被当作普通关键词处理。** |
| OR  | social OR data | 若要将两个运算符用 OR 连接，在它们之间插入被空格包围的全大写 OR。  <br />  <br />匹配包含任一关键词（&quot;social&quot; 或 &quot;data&quot;）的活动。  <br />  <br />请注意，如果你在单条规则中同时使用 OR 和 AND 功能，你需要理解“[运算顺序](#OrderOfOperations)”一节中描述的运算顺序，并考虑按照下文所述使用括号对未取反的运算符进行分组，以确保规则行为符合预期。  <br />  <br />你必须在规则中使用大写的 &quot;OR&quot;。小写的 &#39;or&#39; 会被当作普通关键词处理。 |
| NOT | social data  <br />-apple -android -phone | 在运算符或一组运算符前紧接着插入一个 `-` 字符。  <br />  <br />上面的示例规则匹配包含关键词 &quot;social&quot; 的活动，但会排除包含关键词 &quot;data&quot; 的活动。  <br />  <br />不允许使用会请求“firehose 中除取反项之外的所有内容”的取反 OR 逻辑。例如，`apple OR -ipad` 是无效的，因为它将匹配所有活动，除了那些提到 &quot;ipad&quot; 的活动。 |
| 分组 | (social OR data) -XDeveloeprs -api | 用括号将多个运算符括起来可以创建一个功能性的“组（group）”。<br /><br />组可以像单个子句一样，通过空格（AND）或 OR 与其他子句连接。不过，请注意，最佳实践是不通过在整个组前加上取反符号 - 来将多个取反项整体分组。相反，你应当对每个单独的运算符分别取反，并通过空格（AND）将它们串联起来。<br /><br />例如，不要使用 -(iphone OR imac OR macbook)，而应使用：-iphone -imac -macbook  <br />  <br />在单条规则同时包含 AND 和 OR 功能的情况下，由于规则评估时采用的运算顺序，分组尤为重要。详情见下文。 |

**请注意：** 运算符可以是正向的，也可以是负向的。

**正向运算符（Positive Operators）** 定义你希望在结果中**包含**的内容。例如，`has:hashtags` 运算符表示“我想要包含话题标签的活动”。

**负向运算符（Negative Operators）** 定义你希望从结果中**排除**的内容，通过使用上文所述的布尔 NOT 逻辑来创建。例如，`-has:hashtags` 表示“排除任何包含话题标签的活动，即使它们在其他方面符合我的规则”。

Premium 运算符产品对正向和负向子句的数量没有限制，但规则的最大长度为 2,048 个字符。
 

<div id="order-of-operations">
  #### 运算顺序
</div>

在单条规则中同时组合 AND 和 OR 逻辑时，规则将按以下运算顺序进行解析：

1. 先组合通过 AND 逻辑连接的运算符
2. 然后再应用通过 OR 逻辑连接的运算符

**示例：**

* `apple OR iphone ipad` 会被解析为 `apple OR (iphone ipad)`
* `ipad iphone OR android` 会被解析为 `(iphone ipad) OR android`

为消除不确定性并确保规则按预期方式被解析，请在合适的位置使用括号将词项分组。例如：

* `(apple OR iphone) ipad`
* `iphone (ipad OR android)`

<div id="punctuation-diacritics-and-case-sensitivity">
  #### 标点符号、变音符号和大小写敏感
</div>

如果在企业运算符中为关键词或话题标签指定带有重音或其他变音符号的规则，则该规则会匹配帖子文本中同样带有这些变音符号的内容（话题标签或关键词）。例如，包含关键词 `Diacr**í**tica` 或话题标签 `#cumplea**ñ**os` 的规则，会匹配 &quot;Diacr**í**tica&quot; 或 &quot;#cumplea**ñ**os&quot;，但不会匹配不带重音符号的 &quot;Diacritica&quot; 或 &quot;#cumpleanos&quot;（缺少重音符号 **í** 或字母 **eñe**）。

带有重音或其他变音符号的字符与普通字符一视同仁，不会被视为词边界。例如，规则 cumplea**ñ**os 只会匹配包含单词 cumpleaños 的活动，而不会匹配包含 cumplea、cumplean 或 os 的活动。

所有运算符在评估时都不区分大小写。例如，规则 `Cat` 将匹配以下所有内容：&quot;cat&quot;、&quot;CAT&quot;、&quot;Cat&quot;。

<div id="powertrack-rule-tags">
  #### PowerTrack 规则标签
</div>

如我们的 “[Matching rules](/zh/x-api/enterprise-gnip-2.0/fundamentals/data-enrichments#matching-rules)” 页面所述，每条规则在创建时都可以带有一个标签。这些标签不会影响过滤结果，但可以用于在你的应用中对规则进行逻辑分组。每条规则只能有一个标签，且标签最大长度为 255 个字符。在通过 API 创建规则时，标签会与 JSON 格式的规则一同提交，如我们的 “Matching rules” 页面所述。

<div id="putting-rules-in-json-format">
  #### 将规则转换为 JSON 格式
</div>

要通过 API 向流中添加或删除规则，这些规则必须使用 JSON 格式。基本上，这要求将每条规则写成以下结构：

`{"value":"insert_rule_here"}`

**包含双引号的规则**

如果规则中包含用于精确匹配或其他运算符的双引号字符（`“`），则必须使用反斜杠进行转义，以便将其与 JSON 结构本身区分开来。

`"social data" @XDevelopers`

对应的 JSON 格式规则如下：

`{"value":"\"social data\" @XDevelopers"}`

**包含双引号字符串字面量的规则**

要在精确匹配中包含作为字符串字面量的双引号字符，必须进行双重转义。比如，对于匹配精确短语 &quot;Toys “R” Us&quot; 的规则（包括围绕 &quot;R&quot; 的双引号），其纯文本表示形式如下：

`"Toys \"R\" Us"`

将其转换为 JSON 格式时，应使用以下结构：

`{"value":"\"Toys \\\"R\\\" Us\""}`

**带有标签的规则**

要为规则添加一个可选标签，如上所述，只需在规则中额外包含一个 `tag` 字段：

`{"value":"\"social data\" @XDevelopers","tag":"RULE-TAG-01"}`

**API 请求的格式**

通过 API 向流中添加或删除规则时，多个 JSON 格式的规则应以逗号分隔，并封装在一个 JSON `rules` 数组中，如下所示：

`{"rules":[{"value":"from:XDevelopers"},{"value":"\social data\" @XDevelopers","tag":"RULE-TAG-01"}]}`

但是，如果你使用 [Search API](/zh/x-api/enterprise-gnip-2.0/fundamentals/search-api)，这些运算符只会匹配引用推文本身的内容，而不会匹配被引用的原始帖子中的任何内容。

<div id="enterprise-operators">
  ## 企业运算符
</div>

以下是 PowerTrack 和 Historical PowerTrack 中可用的运算符。其中一部分也适用于 30-Day 和 Full-Archive 搜索 API。有关各产品可用运算符的列表，请参阅[此表](/zh/x-api/enterprise-gnip-2.0/fundamentals/rules-filtering#operators-by-product)。 

| 运算符                                    | 说明                                                                                                                                                                                                                                                                                           |
| :------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 关键词                                    | 在帖子正文或 URL 中匹配关键字。关键字必须以数字（0-9）或任意非标点符号字符开头。<br />关键字匹配采用分词方式进行匹配，即将关键字与帖子正文的分词文本进行比对。<br />对于包含标点符号的字符串（例如 &quot;coca-cola&quot;），请使用带引号的 &quot;精确短语匹配&quot;。<br />*示例*：`(social OR pizza OR wildfire) -planet`                                                                             |
| 表情符号                                   | 在帖子正文中匹配表情符号，使用基于标点符号、符号/表情符号和分隔符字符的分词匹配。<br />如果某个表情符号存在变体，请使用引号进行精确匹配。<br />*示例*: `(🍕 OR 💜 OR 🐢) -🤖`                                                                                                                                                                                   |
| 精确短语匹配                                 | 在帖子正文中匹配完全一致的短语。标点符号会被视为空白字符。<br />*示例*：`("social media" OR "developer.x.com" OR "wildfire911" OR "coca-cola") -"planet earth"`                                                                                                                                                              |
| #                                      | 匹配包含指定话题标签的任意帖子。为精确匹配，这意味着 `#2016` 只会匹配带有 `#2016` 的帖子，而不会匹配带有 `#2016election` 的帖子。<br />*示例*: `(#social OR #pizza OR #2016election) -#planet`                                                                                                                                                |
| @                                      | 匹配任何提到指定用户名的帖子。<br />*示例*：`(@XDevelopers OR @api OR @twittereng) -@jack`                                                                                                                                                                                                                     |
| &quot;keyword1 keyword2&quot;~N        | 接近度运算符，用于匹配关键词彼此之间相距不超过 N 个 token 的帖子。<br />若关键词以相反顺序出现，它们之间最多只能相隔 N-2 个 token。N 不能大于 6。<br />*示例*: `"social media"~5 OR "API"~3`                                                                                                                                                            |

| to:                                    | 匹配任何回复特定用户的帖子，可根据 X 数字账号 id 或用户名（不含 `@`）进行匹配。<br />*示例*：`(to:2244994945 OR to:api OR to:twittereng) -to:jack`                                                                                                                                                                                |
| url:                                   | 对帖子中展开后的 URL 执行基于分词（关键词/短语）的匹配。<br />*示例*: `@XDevelopers url:"developer.x.com"`                                                                                                                                                                                                              |

| url&#95;description:                   | 对展开后的页面描述元数据执行关键词/短语匹配。<br />*仅适用于 PowerTrack 和 Historical PowerTrack。*                                                                                                                                                                                                                      |
| url&#95;contains:                      | 匹配其 URL 中包含指定短语或关键词的帖子。<br />将包含标点符号的搜索词用引号括起来。<br />*示例*：`(url_contains:"developer.x.com" OR url_contains:wildfire) -url_contains:reddit`                                                                                                                                                   |
| bio:                                   | 匹配帖子中用户个人简介中的关键词或短语。这是在 [User object](/zh/x-api/enterprise-gnip-2.0/fundamentals/data-dictionary#native-enriched-user-object) 的 &#39;description&#39; 字段中进行的分词匹配。<br />*示例*: `(bio:engineer OR bio:"wordpress.com" OR bio:🚀) -bio:troll`<br />*注意：* 仅在 PowerTrack 和 Historical PowerTrack 中可用。 |

| followers&#95;count:                   | 当作者的粉丝数位于给定范围内时匹配帖子。<br />如果只指定一个数字，则会匹配所有大于或等于该数字的情况。<br />可以指定一个范围以匹配该范围内的任何数字（例如，`followers_count:1000..10000`）。<br />*注意：* 仅适用于 PowerTrack 和 Historical PowerTrack。                                                                                                                      |
| friends&#95;count:                     | 当作者的关注数（其关注的用户数量）在给定范围内时，会匹配帖子。<br />如果只指定一个数字，则会匹配任何大于或等于该数字的值。<br />可以指定一个范围以匹配该范围内的任何数字（例如：`friends_count:1000..10000`）。<br />*注意：* 仅适用于 PowerTrack 和 Historical PowerTrack。                                                                                                              |
| listed&#95;count:                      | 当作者在 X 中被加入列表的次数位于给定范围内时，将匹配这些帖子。<br />如果只指定一个数字，将匹配所有大于或等于该数字的情况。<br />可以指定一个范围，以匹配该范围内的任意数字（例如，`listed_count:10..100`）。<br />*注意：* 仅适用于 PowerTrack 和 Historical PowerTrack。                                                                                                                |
| $                                      | 匹配任何包含指定 “cashtag” 实体的帖子。<br />*示例*：`($TWTR OR $TSLA OR $BRK.A) -$F`<br />*注意：*cashtag 运算符依赖于 X 的 “symbols” 实体提取来匹配 cashtag，而不是直接从正文内容中提取。                                                                                                                                                   |
