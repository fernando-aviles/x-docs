<div id="getting-started-with-enterprise-rules-and-queries">
  ## 企业规则和查询入门
</div>

使用企业运算符的产品会根据你设置的过滤规则向你提供社交数据。规则由一个或多个“子句”组成，子句可以是关键词、精确短语，或众多企业运算符之一。在开始使用企业运算符构建规则之前，请务必先查看下面描述的语法、浏览可用运算符列表，并了解构建规则时的限制。你还应当理解规则在逻辑评估方式上的细微差别，详见“[运算顺序](#orderofoperations)”部分。

多个子句可以通过 &quot;and&quot; 和 &quot;or&quot; 逻辑组合使用。

**请注意：** &quot;and&quot; 逻辑通过子句之间的空格来指定，而 &quot;or&quot; 逻辑则通过大写的 `OR` 来指定。 

每条规则最多可包含 2,048 个字符，对正向子句（你希望匹配或进行过滤的内容）和负向子句（你希望排除且不匹配的内容）的数量没有限制。
 

<div id="building-rules-and-queries">
  ### 构建规则和查询
</div>

**关键词匹配**

关键词匹配类似于搜索界面中的查询。例如，下面的企业级运算符规则会匹配文本正文中包含词语 &quot;social&quot; 的活动。

`social`

**使用空格进行 AND 组合**

添加另一个关键词等同于为匹配结果添加另一个条件。例如，以下规则只会匹配文本中同时包含 &quot;social&quot; 和 &quot;media&quot; 的活动，顺序不限 —— *在术语之间使用空格，相当于布尔 AND 逻辑*。如果在规则中显式包含 AND，该规则会被 rules 端点拒绝。

`social media`

**使用大写 OR 进行 OR 组合**

不过，很多场景实际上需要布尔 OR 逻辑。这也很容易实现。 *请注意，OR 运算符必须为大写，小写的 “or” 会被视为普通关键词。*

`social OR data`

**对术语取反**

还有一些场景需要排除包含特定关键词的结果（布尔 NOT 逻辑）。例如，包含 “happy” 的活动，但排除任何在文本中包含 “birthday” 的活动。

`social -personality`

**使用括号进行分组**

可以使用括号对以上类型的逻辑进行组合分组，并扩展为更复杂的查询。

`(social OR data) (academic OR research) -personality -information -university`

不过这仅仅是开始 —— 上述示例只是依赖对关键词的分词匹配，而企业级产品还提供运算符来对文本执行不同类型的匹配。

**精确匹配**

`"social media research"`

**子串匹配**

`contains:info`

**邻近匹配**

`"social media research"~3`

此外，其他运算符还允许你根据社交数据的独特属性进行过滤，而不仅仅是文本本身。 

**发布帖子的用户**

`from:XDeveloeprs`

**距离美国科罗拉多州博尔德市 Pearl St. 10 英里范围内的带地理标签的推文**

`point_radius:[-105.27346517 40.01924738 10.0mi]`

**综合运用**

可以使用与上述相同类型的逻辑，将这些与文本过滤器组合在一起。

`(social OR data) (academic OR research OR "social media research") point_radius:[-105.27346517 40.01924738 10.0mi] lang:en -personality -information -university`

<div id="boolean-syntax">
  ### 布尔语法
</div>

上一节中的示例使用了多种布尔逻辑和分组方式。请参阅下表，了解每种语法及其要求的更多细节。

|     |     |     |
| :--- | :--- | :--- |
| **逻辑类型** | **运算符语法** | 说明 |
| AND | social data | 在两个运算符之间留出空格，会在它们之间产生 AND 逻辑。  <br />  <br />匹配同时包含两个关键词（&quot;social&quot;、&quot;data&quot;）的活动。  <br />  <br />**不要在规则中显式写出 AND。只使用空格。显式写出的 AND 会被当作普通关键词处理。** |
| OR  | social OR data | 要对两个运算符使用 OR 逻辑，请在它们之间插入大写的 OR，并在两侧保留空格。  <br />  <br />匹配包含任一关键词（&quot;social&quot; 或 &quot;data&quot;）的活动。  <br />  <br />请注意，如果在同一条规则中同时使用 OR 和 AND 逻辑，你应了解我们在“[运算顺序](#OrderOfOperations)”一节中介绍的运算顺序，并考虑按下面所述使用括号对未取反的运算符进行分组，以确保规则按预期运行。  <br />  <br />你必须在规则中使用大写的 &quot;OR&quot;。小写的 &#39;or&#39; 会被当作普通关键词处理。 |
| NOT | social data  <br />-apple -android -phone | 在运算符或一组运算符前面直接加上 `-` 字符。  <br />  <br />上面的示例规则会匹配包含关键词 &quot;social&quot; 的活动，但会排除那些包含关键词 &quot;data&quot; 的活动。  <br />  <br />不允许使用会导致规则请求“Firehose 中除了该否定项以外的所有内容”的被取反 OR 组合。例如，`apple OR -ipad` 是无效的，因为它会匹配所有活动，除了提到 &quot;ipad&quot; 的活动。 |
| 分组 | (social OR data) -XDeveloeprs -api | 在多个运算符外加括号会创建一个功能性“分组”。<br /><br />分组可以像单个子句一样，通过空格（AND）或 OR 与其他子句连接。不过，请注意，最佳实践是不通过在整个分组前添加取反符号 - 来整体否定该分组。相反，你应分别对每个运算符取反，并通过空格（AND）将它们串联起来。<br /><br />例如，不要使用 -(iphone OR imac OR macbook)，而应使用：-iphone -imac -macbook  <br />  <br />当一条规则同时包含 AND 和 OR 逻辑时，由于应用于规则的运算顺序，分组尤为重要。更多细节见下文。 |

**请注意：** 运算符可以是肯定的，也可以是否定的。

**正向运算符** 定义你希望在结果中**包含**的内容。例如，`has:hashtags` 运算符表示“我想要包含话题标签的活动”。

**负向运算符** 定义你希望从结果中**排除**的内容，并通过使用上文所述的布尔 NOT 逻辑来创建。例如，`-has:hashtags` 表示“排除任何包含话题标签的活动，即便它们在其他方面符合我的规则”。

Premium 运算符产品在正向和负向子句的数量上没有限制，但规则的最大长度为 2,048 个字符。
 

<div id="order-of-operations">
  #### 运算顺序
</div>

当在同一个规则中同时使用 AND 和 OR 逻辑时，以下运算顺序将决定规则的评估方式：

1. 由 AND 逻辑连接的运算符会首先组合
2. 然后再应用由 OR 逻辑连接的运算符

**示例：**

* `apple OR iphone ipad` 会被评估为 `apple OR (iphone ipad)`
* `ipad iphone OR android` 会被评估为 `(iphone ipad) OR android`

为消除不确定性并确保规则按预期被评估，请在合适的地方使用括号将词语进行分组。例如：

* `(apple OR iphone) ipad`
* `iphone (ipad OR android)`

<div id="punctuation-diacritics-and-case-sensitivity">
  #### 标点符号、变音符号与大小写敏感性
</div>

如果你在企业运算符中为关键词或话题标签规则指定了带有重音或其他变音符号的字符，则会按这些变音符号精确匹配帖子文本中的话题标签或关键词。带有关键词 `Diacr**í**tica` 或话题标签 `#cumplea**ñ**os` 的规则将匹配 &quot;Diacr**í**tica&quot; 或 &quot;#cumplea**ñ**os&quot;，但不会匹配不带这些符号的 &quot;Diacritica&quot; 或 &quot;#cumpleanos&quot;（缺少重音符号 **í** 或字母 **ñ**（eñe））。

带有重音或其他变音符号的字符与普通字符一视同仁，不会被视为词边界。例如，规则 cumplea**ñ**os 只会匹配包含单词 cumpleaños 的活动，而不会匹配只包含 cumplea、cumplean 或 os 的活动。

所有运算符的求值都不区分大小写。例如，规则 `Cat` 会匹配以下所有内容：&quot;cat&quot;、&quot;CAT&quot;、&quot;Cat&quot;。

<div id="powertrack-rule-tags">
  #### PowerTrack 规则标签
</div>

如我们在“[匹配规则](/zh/x-api/enterprise-gnip-2.0/fundamentals/data-enrichments#matching-rules)”页面中所述，每条规则在创建时都可以附带一个标签。标签不会对过滤产生任何影响，但可用于在你的应用中对规则进行逻辑分组。每条规则只能有一个标签，且标签的最大长度为 255 个字符。通过 API 创建规则时，可以在 JSON 格式的规则中一并提供标签，具体如我们的“匹配规则”页面所述。

<div id="putting-rules-in-json-format">
  #### 将规则转换为 JSON 格式
</div>

要通过 API 向流中添加或删除规则，规则必须使用 JSON 格式。基本上，这需要将每条规则放入以下结构中：

`{"value":"insert_rule_here"}`

**包含双引号的规则**

如果规则中包含与精确匹配或其他运算符相关的双引号字符（`"`），则必须使用反斜杠进行转义，以将其与 JSON 格式本身的结构区分开来。

`"social data" @XDevelopers`

该规则的 JSON 格式为：

`{"value":"\"social data\" @XDevelopers"}`

**包含双引号字符串字面量的规则**

要在精确匹配中包含一个作为字符串字面量的双引号字符，必须进行双重转义。比如，对于一条匹配精确短语 &quot;Toys &quot;R&quot; Us&quot; 的规则（包括围绕 &quot;R&quot; 的双引号），其纯文本表示如下所示：

`"Toys \"R\" Us"`

将其转换为 JSON 格式时，应使用以下结构：

`{"value":"\"Toys \\\"R\\\" Us\""}`

**带有标签的规则**

要在规则中包含一个可选标签，如上文所述，只需在规则中额外加入一个 `tag` 字段即可。

`{"value":"\"social data\" @XDevelopers","tag":"RULE-TAG-01"}`

**API 请求的格式**

当通过 API 向流中添加或删除规则时，多个 JSON 格式的规则应使用逗号分隔，并封装在一个 JSON `rules` 数组中，如下所示：

`{"rules":[{"value":"from:XDevelopers"},{"value":"\social data\" @XDevelopers","tag":"RULE-TAG-01"}]}`

但是，如果使用的是 [Search API](/zh/x-api/enterprise-gnip-2.0/fundamentals/search-api)，这些运算符将只会匹配引用推文本身的内容，而不会匹配被引用的原始帖子的任何内容。

<div id="enterprise-operators">
  ## 企业级运算符
</div>

下面列出了 PowerTrack 和 Historical PowerTrack 提供的运算符。其中一部分运算符也适用于 30-Day 和 Full-Archive 搜索 API。有关各产品可用运算符的列表，请参阅[此表](/zh/x-api/enterprise-gnip-2.0/fundamentals/rules-filtering#operators-by-product)。 

| 运算符                                    | 说明                                                                                                                                                                                                                                                                                              |
| :------------------------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 关键词                                    | 匹配帖子正文或 URL 中的关键词。关键词必须以数字（0-9）或任意非标点字符开头。<br />关键词匹配是基于分词的，即将关键词与帖子正文分词后的文本进行匹配。<br />对于包含标点符号的字符串（例如 &quot;coca-cola&quot;），请使用带引号的 &quot;精确短语匹配&quot;。<br />*示例*：`(social OR pizza OR wildfire) -planet`                                                                                     |
| 表情符号                                   | 在帖子正文中匹配表情符号，使用基于标点符号、符号/表情符号和分隔符字符的分词匹配。<br />如果某个表情符号存在变体，请使用引号括起来以进行精确匹配。<br />*示例*：`(🍕 OR 💜 OR 🐢) -🤖`                                                                                                                                                                                   |
| “完全匹配短语”                               | 在帖子正文中匹配完全相同的短语。标点符号按空白字符处理。<br />*示例*：`("social media" OR "developer.x.com" OR "wildfire911" OR "coca-cola") -"planet earth"`                                                                                                                                                                  |

| @                                      | 匹配任何提及指定用户名的帖子。<br />*示例*：`(@XDevelopers OR @api OR @twittereng) -@jack`                                                                                                                                                                                                                        |
| &quot;keyword1 keyword2&quot;~N        | 接近度运算符，用于匹配关键词之间距离不超过 N 个 token 的帖子。<br />当关键词顺序相反时，它们之间的距离不能超过 N-2 个 token。N 的最大值为 6。<br />*示例*：`"social media"~5 OR "API"~3`                                                                                                                                                                  |

| to:                                    | 匹配任何回复特定用户的帖子，可通过 X 数字账户 ID 或用户名（不包含 `@`）进行匹配。<br />*示例*：`(to:2244994945 OR to:api OR to:twittereng) -to:jack`                                                                                                                                                                                  |
| url:                                   | 对帖子的展开后 URL 执行基于分词的关键词/短语匹配。<br />*示例*：`@XDevelopers url:"developer.x.com"`                                                                                                                                                                                                                     |

| followers&#95;count:                   | 当作者的粉丝数量在给定范围内时，会匹配这些帖子。<br />如果只指定一个数字，则会匹配所有大于或等于该数值的情况。<br />可以指定一个范围来匹配该范围内的任何数值（例如，`followers_count:1000..10000`）。<br />*注意：* 仅适用于 PowerTrack 和 Historical PowerTrack。                                                                                                                     |
| friends&#95;count:                     | 当作者的关注数（其关注的用户数量）在给定范围内时，会匹配帖子。<br />如果只指定单个数字，则会匹配任何大于或等于该数字的值。<br />可以指定一个范围来匹配该范围内的任何数字（例如，`friends_count:1000..10000`）。<br />*注意：* 仅适用于 PowerTrack 和 Historical PowerTrack。                                                                                                                 |
| listed&#95;count:                      | 当作者在 X 上被加入列表的次数处于给定范围内时，匹配这些帖子。<br />如果只指定一个数字，则会匹配大于或等于该数值的任意次数。<br />可以指定一个范围来匹配该范围内的任意次数（例如，`listed_count:10..100`）。<br />*注意：* 仅适用于 PowerTrack 和 Historical PowerTrack。                                                                                                                    |
