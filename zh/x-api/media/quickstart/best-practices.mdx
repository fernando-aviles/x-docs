在使用 [`POST /2/media/upload`](/zh/x-api/media/media-upload) 端点时，有几个关键概念需要理解。使用 OAuth 上传媒体可能会有些棘手，因此我们在此列出了一些需要注意的事项，并提供了一个可运行示例来演示如何使用该端点。

<div id="keep-in-mind">
  ## 请注意
</div>

* 你在一条帖子中最多可以附加 4 张照片、1 个动态 GIF 或 1 个视频。
* 传入的图像应为图像的原始二进制数据或 base64 编码的二进制数据，只要正确设置 Content-Type（如果不确定：`application/octet-stream`），无需对内容进行其他编码或转义。
* 在发布 base64 编码图像时，请确保在消息中图像部分设置 &quot;Content-Transfer-Encoding: base64&quot;。
* 多部分消息的边界必须单独占一行，并以 CRLF 结束。
* 若要查看使用此端点进行 POST 的可运行示例，我们建议使用 [xurl](https://github.com/xdevplatform/xurl) 进行测试。同时，也可以查看可用的 [X Libraries](/zh/resources/tools-and-libraries)。
* 在 JavaScript 以及任何无法精确表示长整数的语言中，请使用 API 响应中提供的 `media_id_string`。

<div id="media-categories">
  ## 媒体类别
</div>

Media Category 参数定义了将要上传的媒体文件的使用场景，并且可能会影响媒体上传时适用的文件大小限制或其他约束。在上传媒体时使用正确的媒体类别非常重要，以避免在尝试使用该媒体时出现问题。它是在上传流程中通过 INIT 请求传递的一个可选值。如果未指定媒体类别，则会根据内容类型，假定上传的媒体是用于帖子（`tweet_image`、`tweet_video` 或 `tweet_gif`）的媒体。

最常见的媒体类别如下：

* `tweet_image`
* `tweet_video`
* `tweet_gif`
* `dm_image`
* `dm_video`
* `dm_gif`
* `subtitles`

如果你是 Ads API 合作伙伴，请参阅[这些文档](/zh/x-ads-api/creatives#promoted-video)，以了解关于推广视频推荐媒体类别的更多信息。

<div id="image-specifications-and-recommendations">
  ## 图像规范和建议
</div>

图像文件必须满足以下所有条件：

* **支持的图像媒体类型**：`JPG`、`PNG`、`GIF`、`WEBP`
* **图像大小**：`<= 5 MB`
* **动态图像 GIF 大小**：`<= 15 MB`

上述文件大小限制由媒体上传端点强制执行。此外，当使用 `media_id` 调用帖子创建（或类似）端点时，还会应用一个针对产品实体的单独文件大小限制。文件大小限制和其他约束可能会因 `media_category` 参数而有所不同。

<div id="animated-gif-recommendations">
  ## 动图 GIF 建议
</div>

即使 GIF 文件大小在限制范围内，仍可能在创建帖子时处理失败。请遵循以下约束条件以提高成功率。

* **分辨率**：`<= 1280x1080`（`width` x `height`）
* **帧数**：`<= 350`
* **像素总数**：`<= 3 亿`（`width` * `height` * `num_frames`）
* **文件大小**：`<= 15MB`

若要处理更大的 GIF，请使用带有 `media_category` 参数的[分块上传](/zh/x-api/media/quickstart/media-upload-chunked)端点。这样可以让服务器异步处理 GIF 文件，这是处理大文件的必要条件。传入 `media_category=tweet_gif`，为包含动图 GIF 的帖子启用异步上传行为。

<div id="video-specifications-and-recommendations">
  ## 视频规格和建议
</div>

进行媒体上传时，请使用异步路径（Async Path）。

<div id="recommended">
  ### 推荐设置
</div>

* **视频编解码器**: `H264 High Profile`
* **帧率**: `30 FPS`，`60 FPS`
* **视频分辨率**: `1280x720`（横屏）、`720x1280`（竖屏）、`720x720`（正方形）。已订阅用户可以上传 1080p 视频并以 1080p 播放。未订阅用户可以上传 720p 视频并以 720p 播放。
* **最低视频码率**: `5,000 kbps`
* **最低音频码率**: `128 kbps`
* **音频编解码器**: `AAC LC`
* **纵横比**: `16:9`（横屏或竖屏）、`1:1`（正方形）

<div id="advanced">
  ### 高级
</div>

* **帧率（Frame rate）**：必须不超过 `60 FPS`
* **分辨率（Dimensions）**：必须在 `32x32` 和 `1280x1024` 之间
* **文件大小（File size）**：不得超过 `512 MB`
* **时长（Duration）**：必须在 `0.5 秒` 和 `140 秒` 之间
* **纵横比（Aspect ratio）**：必须在 `1:3` 和 `3:1` 之间
* **[像素纵横比（Pixel aspect ratio）](https://en.wikipedia.org/wiki/Pixel_aspect_ratio)**：必须为 `1:1`
* **像素格式（Pixel format）**：仅支持 [YUV](https://en.wikipedia.org/wiki/YUV) 4:2:0
* 音频必须为 [`AAC` 低复杂度（Low Complexity）配置](https://en.wikipedia.org/wiki/Advanced_Audio_Coding#Modular_encoding)。（不支持高效率 `AAC`）
* 音频必须为单声道（`mono`）或立体声（`stereo`），不支持 5.1 或更多声道
* 不得使用 [`open GOP`](https://en.wikipedia.org/wiki/Group_of_pictures)
* 必须使用 [`progressive scan`](https://en.wikipedia.org/wiki/Progressive_scan)（逐行扫描）
