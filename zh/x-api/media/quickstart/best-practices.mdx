在使用 [`POST /2/media/upload`](/zh/x-api/media/media-upload) 端点时，有几个重要概念需要先理解。使用 OAuth 上传媒体可能会有些棘手，因此我们在此整理了一些需要注意的事项，并提供了一个可运行的示例，演示如何使用该端点。

<div id="keep-in-mind">
  ## 请注意
</div>

* 你最多可以在一条帖子中附加 4 张照片、1 个动画 GIF 或 1 个视频。
* 传入的图像应为图像的原始二进制数据或其 base64 编码后的二进制内容，只要正确设置了 Content-Type（如果不确定：`application/octet-stream`），就不需要对内容进行其他编码或转义。
* 在发布 base64 编码图像时，请确保在消息中图像部分设置“Content-Transfer-Encoding: base64”。
* 多部分消息的边界必须单独占一行，并以 CRLF 结尾。
* 如需了解如何使用此端点进行 POST 请求的示例，我们建议使用 [xurl](https://github.com/xdevplatform/xurl) 进行测试。同时也可以查看可用的 [X Libraries](/zh/resources/tools-and-libraries)。
* 对于 JavaScript 和任何其他无法精确表示长整型整数的语言，请使用 API 响应中提供的 `media_id_string`。

<div id="media-categories">
  ## 媒体类别
</div>

Media Category 参数定义了要上传的媒体文件的使用场景/用途，并且可能会影响媒体上传时适用的文件大小限制或其他约束。在上传媒体时使用正确的媒体类别非常重要，以避免在后续使用该媒体时出现问题。它是一个可选值，在上传流程中作为 INIT 请求的一部分传递。如果未指定媒体类别，则会根据内容类型假定上传的媒体是用于帖子（`tweet_image`、`tweet_video` 或 `tweet_gif`）的媒体。

最常见的媒体类别如下：

* `tweet_image`
* `tweet_video`
* `tweet_gif`
* `dm_image`
* `dm_video`
* `dm_gif`
* `subtitles`

如果您是 Ads API 合作伙伴，请参阅[这些文档](/zh/x-ads-api/creatives#promoted-video)，了解有关推广视频推荐媒体类别的更多信息。

<div id="image-specifications-and-recommendations">
  ## 图像规范和建议
</div>

图像文件必须满足以下所有条件：

* **支持的图像媒体类型**：`JPG`、`PNG`、`GIF`、`WEBP`
* **图像大小**：`<= 5 MB`
* **动画 GIF 大小**：`<= 15 MB`

上述文件大小限制由媒体上传端点强制执行。此外，在调用带有 `media_id` 的帖子创建（或类似）端点时，还会应用一个针对具体产品实体的单独文件大小限制。根据 `media_category` 参数的不同，文件大小限制和其他约束条件可能会有所变化。

<div id="animated-gif-recommendations">
  ## 动画 GIF 建议
</div>

即使 GIF 在文件大小限制以内，也可能在创建帖子时上传失败。请遵循以下约束条件以提高成功率。

* **分辨率**：`<= 1280x1080`（`width` x `height`）
* **帧数**：`<= 350`
* **像素数量**：`<= 3 亿`（`width` * `height` * `num_frames`）
* **文件大小**：`<= 15MB`

要处理更大的 GIF，请使用带有 `media_category` 参数的 [chunked upload](/zh/x-api/media/quickstart/media-upload-chunked) 端点。这样服务器可以异步处理 GIF 文件，这是处理较大文件的必要条件。传入 `media_category=tweet_gif`，以便为包含动画 GIF 的帖子启用异步上传行为。

<div id="video-specifications-and-recommendations">
  ## 视频规格和建议
</div>

请使用 Async Path 进行媒体上传。

<div id="recommended">
  ### 推荐配置
</div>

* **视频编码格式**: `H264 High Profile`
* **帧率**: `30 FPS`, `60 FPS`
* **视频分辨率**: `1280x720`（横屏）、`720x1280`（竖屏）、`720x720`（正方形）。订阅用户可以上传 1080p 视频并获得 1080p 播放。未订阅用户可以上传 720p 视频并获得 720p 播放。
* **最低视频码率**: `5,000 kbps`
* **最低音频码率**: `128 kbps`
* **音频编码格式**: `AAC LC`
* **纵横比**: `16:9`（横屏或竖屏）、`1:1`（正方形）

<div id="advanced">
  ### 高级
</div>

* **帧率**：必须为 `60 FPS` 或更低
* **尺寸**：必须介于 `32x32` 和 `1280x1024` 之间
* **文件大小**：不得超过 `512 MB`
* **时长**：必须在 `0.5 秒` 到 `140 秒` 之间
* **纵横比**：必须介于 `1:3` 和 `3:1` 之间
* **[像素纵横比](https://en.wikipedia.org/wiki/Pixel_aspect_ratio)**：必须为 `1:1`
* **像素格式**：仅支持 [YUV](https://en.wikipedia.org/wiki/YUV) 4:2:0
* 音频必须为 [`AAC` 低复杂度（Low Complexity）配置文件](https://en.wikipedia.org/wiki/Advanced_Audio_Coding#Modular_encoding)。（不支持高效 `AAC`（High-Efficiency AAC））
* 音频必须为 `mono`（单声道）或 `stereo`（立体声），不支持 5.1 或更多声道
* 不得使用 [`open GOP`](https://en.wikipedia.org/wiki/Group_of_pictures)
* 必须使用 [`progressive scan`](https://en.wikipedia.org/wiki/Progressive_scan)（逐行扫描）

| 纵向 | 360 | 640 | 768K | 64K |
| 纵向 | 180 | 320 | 256K | 64K |
| 正方形 | 720 | 720 | 2048K | 128K |
