本指南将引导你创建批量合规任务，用于检查帖子或用户的合规状态。

<Note>
  **先决条件**

  在开始之前，你需要：

  * 一个已有获批 App 的 [开发者账号](https://developer.x.com/en/portal/petition/essential/basic-info)
  * 你的 App 的 Bearer Token
</Note>

***

<Steps>
  <Step title="创建任务" icon="plus">
    创建一个新的合规任务，并指定类型（tweets 或 users）：

    <Tabs>
      <Tab title="cURL">
        ```bash
        curl -X POST "https://api.x.com/2/compliance/jobs" \
          -H "Authorization: Bearer $BEARER_TOKEN" \
          -H "Content-Type: application/json" \
          -d '{
            "type": "tweets",
            "name": "my-compliance-job"
          }'
        ```
      </Tab>

      <Tab title="Python">
        ```python
        import requests

        bearer_token = "YOUR_BEARER_TOKEN"

        url = "https://api.x.com/2/compliance/jobs"
        headers = {
            "Authorization": f"Bearer {bearer_token}",
            "Content-Type": "application/json"
        }
        payload = {
            "type": "tweets",
            "name": "my-compliance-job"
        }

        response = requests.post(url, headers=headers, json=payload)
        print(response.json())
        ```
      </Tab>
    </Tabs>

    **响应：**

    ```json
    {
      "data": {
        "id": "1234567890",
        "type": "tweets",
        "name": "my-compliance-job",
        "status": "created",
        "upload_url": "https://storage.googleapis.com/...",
        "download_url": "https://storage.googleapis.com/...",
        "created_at": "2024-01-15T10:00:00.000Z"
      }
    }
    ```

    保存 `upload_url` 和 `download_url`，用于后续步骤。
  </Step>

  <Step title="准备数据文件" icon="file">
    创建一个文本文件，每行一个 ID：

    ```
    1234567890
    1234567891
    1234567892
    1234567893
    ```

    保存为 `ids.txt`。
  </Step>

  <Step title="上传数据" icon="upload">
    将文件上传到提供的 `upload_url`：

    ```bash
    curl -X PUT "UPLOAD_URL_FROM_RESPONSE" \
      -H "Content-Type: text/plain" \
      --data-binary @ids.txt
    ```
  </Step>

  <Step title="检查任务状态" icon="clock">
    轮询任务状态，直到完成：

    ```bash
    curl "https://api.x.com/2/compliance/jobs/1234567890" \
      -H "Authorization: Bearer $BEARER_TOKEN"
    ```

    **任务状态：**

    | Status        | Description |
    | :------------ | :---------- |
    | `created`     | 任务已创建，等待上传  |
    | `in_progress` | 正在处理数据      |
    | `complete`    | 结果已准备好可下载   |
    | `failed`      | 任务失败        |
    | `expired`     | 任务在完成前已过期   |
  </Step>

  <Step title="下载结果" icon="download">
    当状态为 `complete` 时，从 `download_url` 下载：

    ```bash
    curl "DOWNLOAD_URL_FROM_RESPONSE" -o results.json
    ```

    **结果格式**（每行一个 JSON 对象）：

    ```json
    {"id": "1234567890", "action": "delete", "created_at": "2024-01-10T12:00:00.000Z", "redacted_at": "2024-01-12T08:30:00.000Z", "reason": "deleted"}
    {"id": "1234567891", "action": "delete", "created_at": "2024-01-10T12:00:00.000Z", "redacted_at": "2024-01-13T14:20:00.000Z", "reason": "suspended"}
    ```

    只有存在合规事件的 ID 才会出现在结果中。未出现在结果中的 ID 仍然有效。
  </Step>
</Steps>

<div id="compliance-actions">
  ## 合规操作
</div>

<AccordionGroup>
  <Accordion title="帖子合规事件">
    | 操作 | 原因 | 描述 |
    |:-------|:-------|:------------|
    | `delete` | `deleted` | 帖子已被删除 |
    | `delete` | `bounced` | 帖子未通过合规检查 |
    | `delete` | `protected` | 账号变为受保护状态 |
    | `delete` | `suspended` | 账号已被封禁 |
    | `delete` | `scrub_geo` | 地理位置信息被移除 |
  </Accordion>

  <Accordion title="用户合规事件">
    | 操作 | 原因 | 描述 |
    |:-------|:-------|:------------|
    | `delete` | `deleted` | 账号已被删除 |
    | `delete` | `suspended` | 账号已被封禁 |
    | `delete` | `protected` | 账号变为受保护状态 |
    | `delete` | `deactivated` | 账号已被停用 |
  </Accordion>
</AccordionGroup>

<div id="list-all-jobs">
  ## 列出所有任务
</div>

获取你的应用的所有合规任务：

```bash
curl "https://api.x.com/2/compliance/jobs?type=tweets" \
  -H "Authorization: Bearer $BEARER_TOKEN"
```
