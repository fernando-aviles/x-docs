`Usage` 端点可用于监控你的 API 使用情况，包括已消耗的帖子数量。你可以通过编程方式跟踪用量，以管理成本并避免超出限制。

<div id="endpoint">
  ## 端点
</div>

| 方法 | 端点 | 描述 |
|:-------|:---------|:------------|
| GET | [`/2/usage/tweets`](/zh/x-api/usage/get-usage) | 获取帖子用量数据 |

***

<div id="response-data">
  ## 响应数据
</div>

响应中包含每日帖子消费计数：

```json
{
  "data": {
    "daily_project_usage": [
      {
        "date": "2024-01-15",
        "usage": [
          {
            "app_id": "12345678",
            "tweets_consumed": 15420
          }
        ]
      }
    ],
    "project_id": "1234567890",
    "project_cap": 10000000
  }
}
```

<div id="fields">
  ### 字段
</div>

| 字段 | 描述 |
|:------|:------------|
| `daily_project_usage` | 每日使用数据的数组 |
| `date` | YYYY-MM-DD 格式的日期 |
| `app_id` | 您的 App 的 id |
| `tweets_consumed` | 当日消耗的帖子数量 |
| `project_cap` | 您的每月帖子上限 |
----------------------------

<div id="use-cases">
  ## 示例请求
</div>

```bash
curl "https://api.x.com/2/usage/tweets" \
  -H "Authorization: Bearer $BEARER_TOKEN"
```

***

<div id="getting-started">
  ## 使用场景
</div>

* **成本监控** — 跟踪你的用量与套餐限额的对比
* **告警** — 在接近限额时设置告警
* **优化** — 识别高消耗的端点
* **报告** — 生成用量报告

<Tip>
  在 24 小时的 UTC 时间窗口内会对资源进行去重，因此在该时间窗口内多次请求同一资源只会计费一次。[进一步了解定价 →](/zh/x-api/getting-started/pricing)
</Tip>
