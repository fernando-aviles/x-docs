<div id="overview">
  ## 概览
</div>

过滤流端点组使开发者能够对公共帖子流进行过滤。该端点组的功能包含多个端点，使你可以创建和管理规则，并应用这些规则来过滤帖子流，从而返回匹配的公共帖子。通过该端点组，用户可以监听特定主题和事件、监控与竞赛相关的讨论、了解趋势如何发展等。

开发者可以使用 REST [rules endpoint](/zh/x-api/posts/filtered-stream#post-2-tweets-search-stream-rules) 添加和移除规则，以过滤出符合指定条件的帖子。这些 [rules](/zh/x-api/posts/filtered-stream#building-rules-for-filtered-stream) 可以通过运算符创建，用于匹配帖子属性，例如消息关键词、话题标签和 URL。你可以将运算符和规则子句与布尔逻辑和括号组合使用，以便细化过滤器的匹配行为。 

添加完一组规则后，你可以注册你的 webhook，X 将开始以 JSON 格式向你投递[帖子对象](/zh/x-api/fundamentals/data-dictionary#tweet)。你只会在 webhook 中收到与规则匹配的内容。

此端点支持已编辑的帖子。你的 webhook 会接收匹配一个或多个过滤条件的已编辑帖子，以及其编辑历史，其中包括一个帖子 ID 数组。对于没有编辑历史的帖子，该数组只包含一个 ID。对于已被编辑过的帖子，该数组会包含多个 ID，并按升序排列，反映编辑的顺序，数组最后一个元素是最新版本。要了解更多关于帖子编辑工作方式的信息，请参阅[帖子编辑基础](/zh/x-api/fundamentals/edit-posts)页面。 

**注意：**在规则设置方面，此端点组与 [v2 filtered stream endpoint](/zh/x-api/posts/filtered-stream/introduction) 类似。唯一的区别在于匹配你规则的帖子在投递机制上的不同。

* 对于 v2 filtered stream endpoint，你需要建立一个持久连接，并监听匹配你规则的帖子。
* 对于本过滤流 webhook 端点，你需要注册你的 webhook，X 会将匹配你规则的帖子投递到你的 webhook。

这使你无需处理因客户端中断或我们的服务正常重启导致的服务器端断开带来的连接问题。由于我们很可能每秒投递数百个事件，你的 webhook 服务器必须能够处理这些同时到来的连接尝试。

该端点目前对企业级开发者开放，并支持以下配置：

* 每个 Project 支持 25,000+ 条规则
* 构建规则时可使用所有运算符
* 规则长度最多可达 2048 个字符
* 如需企业级访问，请在[此处申请](https://developer.x.com/en/products/x-api/enterprise/enterprise-api-interest-form)

通过过滤流返回的帖子将计入每月的[帖子上限](/zh/x-api/fundamentals/post-cap)。
