<div id="overview">
  ## 概览
</div>

过滤流端点组使开发者能够过滤公共帖子流。此端点组的功能包括多个端点，用于创建和管理规则，并将这些规则应用于帖子流，以返回与之匹配的公共帖子。通过此端点组，用户可以监听特定主题和事件、监控有关竞赛的讨论、了解趋势如何发展等。

开发者可以使用 REST [rules endpoint](/zh/x-api/posts/filtered-stream#post-2-tweets-search-stream-rules) 添加和移除规则，以过滤符合已定义条件的帖子。这些 [rules](/zh/x-api/posts/filtered-stream#building-rules-for-filtered-stream) 可以通过运算符基于帖子属性（例如消息关键词、话题标签和 URL）进行匹配。运算符和规则子句可以与布尔逻辑和括号组合使用，以帮助优化过滤器的匹配行为。 

添加一组规则后，您可以注册 webhook，X 将开始以 JSON 格式向其投递 [Post objects](/zh/x-api/fundamentals/data-dictionary#tweet)（Post 对象）。您只会在 webhook 上接收到与您的规则匹配的内容。

此端点支持已编辑的帖子。您的 webhook 将接收符合一个或多个过滤条件的已编辑帖子，以及其编辑历史记录，其中包括一个帖子 ID 数组。对于没有编辑历史的帖子，此数组仅包含一个 ID。对于已被编辑的帖子，此数组包含多个 ID，按升序排列，反映编辑的先后顺序，数组最后一个元素为最新版本。要了解帖子编辑的工作方式，请参阅 [Posts edits fundamentals](/zh/x-api/fundamentals/edit-posts) 页面。 

**注意：** 在规则设置方面，此端点组与 [v2 filtered stream endpoint](/zh/x-api/posts/filtered-stream/introduction) 类似。唯一的区别在于与您的规则匹配的帖子在投递机制上的不同。

* 对于 v2 filtered stream endpoint，您必须建立持久连接并监听与您的规则匹配的帖子。
* 对于此 filtered stream webhook 端点，您需要注册 webhook，X 会将与您的规则匹配的帖子投递到您的 webhook。

这消除了处理由于客户端掉线或我们服务正常重启导致的服务端断开连接的需求。由于我们可能会以每秒数百个事件的速率进行投递，因此您的 webhook 服务器必须能够处理这些并发的连接尝试。

此端点目前向企业级开发者开放，并支持以下配置：

* 每个 Project 支持 25,000+ 条规则
* 构建规则时可以使用所有运算符
* 规则长度最多可达 2048 个字符
* 申请企业级访问权限请[点击此处](https://developer.x.com/en/products/x-api/enterprise/enterprise-api-interest-form)

过滤流返回的帖子计入每月的 [Post cap](/zh/x-api/fundamentals/post-cap)。
