<div id="overview">
  ## 概览
</div>

过滤流端点组使开发者能够对公开帖子流进行过滤。该端点组包含多个端点，允许你创建和管理规则，并将这些规则应用到帖子流中，以返回匹配的公开帖子。通过该端点组，用户可以监听特定主题和事件、监控比赛相关的讨论、了解趋势如何发展等更多用例。

开发者可以使用 REST [rules endpoint](/zh/x-api/posts/filtered-stream#post-2-tweets-search-stream-rules) 添加和移除规则，以过滤出符合指定条件的帖子。这些[规则](/zh/x-api/posts/filtered-stream#building-rules-for-filtered-stream)可以使用运算符与帖子属性进行匹配，例如消息关键词、话题标签和 URL。运算符和规则子句可以结合布尔逻辑和括号使用，帮助你进一步优化过滤器的匹配行为。 

在你添加了一组规则之后，就可以注册你的 webhook，X 将开始以 JSON 格式投递 [Post objects](/zh/x-api/fundamentals/data-dictionary#tweet)。你只会在 webhook 上接收到符合你规则的内容。

该端点支持已编辑的帖子。你的 webhook 会接收到匹配你一个或多个过滤条件的已编辑帖子，以及其编辑历史，其中包括帖子 ID 的数组。对于没有编辑历史的帖子，该数组中只包含一个 ID。对于已被编辑的帖子，该数组包含多个 ID，并按升序排列，反映编辑的顺序，数组最后一个元素为最新版本。要进一步了解帖子编辑的工作方式，请参阅 [Posts edits fundamentals](/zh/x-api/fundamentals/edit-posts) 页面。 

**注意：**该端点组在规则配置方面与 [v2 filtered stream endpoint](/zh/x-api/posts/filtered-stream/introduction) 类似。唯一的差异在于匹配你规则的帖子在投递机制上的不同。

* 对于 v2 filtered stream endpoint，你必须建立一个持久连接，并监听匹配你规则的帖子。
* 对于本过滤流 webhook 端点，你只需注册你的 webhook，X 会将匹配你规则的帖子投递到你的 webhook。

这省去了你处理因客户端掉线或服务正常重启而导致的连接断开问题。由于我们很可能每秒投递数百个事件，你的 webhook 服务器必须能够处理这些同时到来的连接尝试。

该端点目前向企业开发者开放，并支持以下配置：

* 每个项目 25,000+ 条规则
* 构建规则时可使用所有运算符
* 每条规则最长可达 2048 个字符
* 要申请企业访问权限，请在[此处](https://developer.x.com/en/products/x-api/enterprise/enterprise-api-interest-form)提交申请

通过过滤流返回的帖子将计入每月的 [Post cap](/zh/x-api/fundamentals/post-cap)。
