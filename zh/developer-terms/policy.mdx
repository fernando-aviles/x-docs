<div id="x-developers">
  ## X + 开发者
</div>

X 热爱开发者。我们对这个社区利用 X data 的力量创造出的工具和服务感到由衷欣喜和惊叹。作为我们对这一社区承诺的一部分，我们致力于为开发者提供开放且公平的数据访问，同时保障 X 上用户的安全，并有利于整个 X 平台。为进一步实现这些目标，我们制定了本开发者政策，作为指南帮助人们理解我们关于适当使用 API 和 X Content 的规则和期望。

本开发者政策（“**本政策**”）为与 X 的应用、服务、网站、网页和内容构成的生态系统进行交互的开发者提供规则和指南。本政策构成你与 X 之间关于访问和使用 X API 和 X Content 的合同的一部分（无论是作为开发者协议的一部分，还是你与 X 签订的其他书面协议的一部分）。违反本政策即视为违反你的协议。本政策可能会不时修改，恕不另行通知。本政策中使用但未作定义的首字母大写术语，其各自含义应以[开发者协议](/zh/developer-terms/agreement)或主许可协议中的定义为准。

<div id="using-this-policy">
  ## 如何使用本政策
</div>

我们对本政策进行了编排设计，以便尽可能易于理解和遵循。在使用 X API 和 X Content 时，请务必牢记以下政策章节中的信息：

1. **为成功打好基础** - 你有责任遵守所有 X 政策。在访问 X API 和 X Content 之前，请务必审阅并理解本政策，以及我们在本文档中链接到的其他政策。花时间阅读我们的政策，可能会为你节省日后数小时的返工时间。

2. **隐私与控制至关重要** - 保护和捍卫 X 上人们的隐私是我们公司核心 DNA 的一部分。因此，我们禁止以任何与人们对隐私的合理预期不一致的方式使用 X 数据。通过基于 X API 构建产品或访问 X Content，你在维护这一承诺方面扮演着特殊角色，最重要的是尊重人们的隐私，并向他们提供关于其数据如何被使用的透明度和控制权。

3. **遵守平台使用指南** - 获批访问 X API 和 X Content 只是第一步。每当你对如何确保你计划使用 X 平台的方式符合政策要求有疑问时，都应首先查阅我们的平台使用指南。

下面我们对这三个关键章节的含义提供了更为详细的说明。请仔细阅读，以确保你对 X API 和 X Content 的使用与我们的政策保持一致。

如果我们认为你违反了本政策（或任何其他 X 政策），我们可能会暂停或永久撤销你对 X API 和 X Content 的访问。

最后，请注意，X 可能会监控你对 X API 的使用，以改进 X 应用、审查任何商业使用情况，并确保你遵守经批准的用例和本政策。

感谢你的阅读，也感谢你与我们共同构建！我们期待看到你创造的成果！

<div id="set-yourself-up-for-success">
  ## 为成功打好基础
</div>

在使用 X API 时，只要确保你的服务从第一天起就以正确的方式构建，就可以避免许多潜在陷阱。本《开发者政策》的本节包含所有开发者在使用 X API 或 X Content 之前必须遵守的规则。

Free、Basic 和 Pro 订阅计划（如 [developer.x.com/en](http://developer.x.com/en) 所述）专为业余爱好者、商业原型验证、早期阶段的 X 产品集成，以及面向终端用户数量有限的应用而设计。如果你对 X API 和 X Content 的使用超出了这一范围，则必须申请（或已经订阅）Enterprise 计划（如 [developer.x.com/en](http://developer.x.com/en) 所述）。

**我们会审查所有拟定的 X 开发者平台使用方式，以验证其是否符合政策要求——因此，你必须披露（并在适用时更新）你计划如何使用 X API 和 X Content，才能获得并维持访问权限。** 所有新开发者都必须[申请开发者账号](https://developer.x.com/portal/petition/essential/basic-info)才能访问 X API。当前尚未获批开发者账号的开发者，必须在 X 要求时按指示进行申请。作为此流程的一部分，你需要向我们提供一份书面说明，描述你计划如何使用 X API 和 X Content。

你的用例说明对你具有约束力，任何在实质上与之偏离的行为都可能构成对我们规则的违反，并导致我们采取执行措施。你必须将任何对用例的实质性修改告知我们，并在开始将 X Content 用于该新目的之前获得批准。否则，可能导致你的 API 和 data 访问被暂停或终止。

**在基于 X API 构建或访问 X Content 时，你必须遵守所有 X 政策。** 这些政策包括本[《开发者政策》](/zh/developer-terms/policy)、[《自动化规则》](https://help.x.com/rules-and-policies/x-automation)、[《展示要求》](https://developer.x.com/developer-terms/display-requirements.html)、[《API 限制使用规则》](/zh/developer-terms/restricted-use-cases)、[《X 规则》](https://help.x.com/rules-and-policies/x-rules)以及 [X 品牌资源](https://about.x.com/who-we-are/brand-toolkit)，以及你与 X 就使用 X API 或 X Content 所签署的任何其他协议（包括但不限于[《开发者协议》](/zh/developer-terms/agreement)或主许可协议或订单（如适用））。你还必须遵守这些政策的任何修改以及 X 推出的任何新政策。你有责任监控你的服务的使用情况，并将你的服务设计为能够防止使用者违反 X 政策。如未履行，可能导致你的 API 和 X Content 访问被暂停或终止。

**你不得针对单一用例或在实质上相似或重叠的用例注册多个应用程序。** 在此语境下，“用例”是指通过应用程序执行的一组一致的分析、展示或操作。“白标”版本的工具或服务不被允许。如果你计划提供应用程序的“白标”版本，必须事先通知我们并获得单独批准。

*作为对上述规则的唯一例外，* 你可以为同一服务的开发、预生产和生产环境创建并使用最多 3 个应用程序。这些应用必须注册在一个账号下，并在名称和描述中清晰标明其为同一服务的 dev（开发）、staging（预生产）和 prod（生产）实例。**你不得将开发或预生产应用用于生产目的。**

**你必须对所有 API 密钥或其他访问凭据保密。** 你不得使用，也不得鼓励或协助他人使用他人所拥有的 API 密钥或其他访问凭据。

**你与 X 签订的许可协议会限制你对 X API 和 X Content 的使用。除其他内容外，X API 具有速率限制，用于确保数据使用公平并打击平台上的垃圾信息。** 你不得超出或规避速率限制，或本政策或你与 X 的协议中所述、[Developer Site](https://developer.x.com/) 上列明，或由 X 通知你的任何其他限制或约束。

**你不得移除或修改通过 X API 接收的 X Content 上的任何所有权声明或标识。** 这有助于确保人们知道 X Content 的来源以及其归属。

**出于数据完整性和平台健康的原因，你不得干扰、截获、破坏或禁用 X API 或 X 服务的任何功能。** 换言之，请按照 [developer.x.com](https://developer.x.com/) 上所预期并加以文档说明的方式使用 API。请参阅我们的 [HackerOne 指南](https://hackerone.com/x)，了解有关可接受使用的更多详情。

<div id="privacy-and-control-are-essential">
  ## 隐私与控制至关重要
</div>

X 高度重视隐私，我们也期望所有使用 X Content 和 X API 的人同样重视隐私。任何以不符合人们对隐私的合理预期的方式使用 X 开发者平台、X API 或 X Content 的行为，都可能受到相应的执行措施，其中可能包括暂停或终止对 API 和 X Content 的访问。

你对隐私与控制的承诺必须涵盖对 X Content 的所有使用场景，以及你使用我们的 API 所构建服务的各个方面。为此，你的服务用户必须理解并同意你如何使用他们的 data，以及你如何代表他们访问 X。你可以通过向用户提供清晰、全面且透明的隐私政策来实现这一点，并确保在代表他们采取任何行动之前，从每一位使用你服务的用户那里获得明确且知情的同意。**请注意，用户在你的服务中完成身份验证这一行为本身并不构成同意。**

<div id="consent-permissions">
  ## 同意与权限
</div>

**特别是，在进行以下任何操作之前，您必须从相关个人那里获得明确且知情的同意：**

* 代表他们执行*任何*操作。这包括（但不限于）：
  * 在 X 上发布内容
  * 关注/取消关注账号
  * 修改个人资料或账号信息
  * 向帖子添加话题标签或任何其他内容

* 通过 X API 或其他 X 工具以外的方式访问并重新发布内容

* 使用他人的 X 内容推广某个产品或服务

* 存储非公开内容，例如私信（Direct Messages，DMs）或任何其他私人或机密信息

* 分享或发布受保护内容，或任何其他私人或机密信息

**如果您的服务允许人们向 X 发布内容，在发布之前您必须执行以下操作：**

* 显示将要发布的具体内容
* 明确向使用您服务的人说明将向内容中添加何种地理位置信息（如果有）

**如果您的服务允许人们同时向您的服务和 X 发布内容，在发布之前您必须执行以下操作：**

* 获取发布该内容的许可
* 说明您将把内容发布到哪些地方

**您必须尊重所有 X 内容的受保护状态和屏蔽状态。您不得将使用某一人的认证令牌获取的内容提供给未被授权查看该内容的其他人。**

* **受保护账号：**[受保护账号](https://help.x.com/safety-and-security/public-and-protected-posts)的内容仅对已获账号所有者批准关注该账号的人可见。因此，如果您运营的服务会访问受保护账号，您只能向具有查看该内容权限的特定人员提供此类内容。
* **被屏蔽账号：**X 上的用户可以出于其自行选择的任何理由[屏蔽](https://help.x.com/using-x/blocking-and-unblocking-accounts)对其账号的访问。混合使用从令牌（或任何其他基于 API 的操作）获取的信息以规避这一选择是不被允许的。

**由于私信（DMs）本质上是非公开的，提供 DM 功能的服务必须采取额外措施来保护个人隐私。您不得向未被授权查看该内容的人提供 DM 内容。如果您的服务提供 DM 功能，您还必须：**

* 在您发送 DM 已读回执事件时告知用户。您可以通过在您的服务中直接提供通知，或显示会话中其他参与者的已读回执来实现这一点。
* 在将要把在 DM 中发送的媒体配置为“共享”（即可在多个 DM 中重复使用）之前获得同意。如果您确实允许 DM 中的媒体被“共享”，您必须提供清晰的通知，说明任何持有该媒体 URL 的人都可以访问这类内容。

<div id="content-compliance">
  ## 内容合规
</div>

**如果你在离线环境中存储 X 内容，则必须确保其与该内容在 X 上的当前状态保持同步。** 具体而言，如果某条内容在 X 上被删除或修改，你必须相应地删除或修改你所持有的该内容的任何副本。你必须在合理可行的最短时间内完成此操作，或在收到 X 或相应 X 账号所有者提出的请求后 24 小时内完成，或按照你与 X 所签订的协议或适用法律的其他要求执行。除非法律另有禁止，且仅在获得 X 明确的书面许可的情况下，方可不执行上述要求。

被修改的内容可以呈现多种形式。这包括但不限于：

* 已被设为私密或获得受保护状态的内容
* 已在平台上被暂停的内容
* 已被移除地理标签的内容
* 已在 X 上被限制展示或移除的内容

<div id="off-x-matching">
  ## X 站外匹配
</div>

**我们会限制你在何种情况下可以将 X 上的个人与在 X 站外获得或存储的信息进行匹配。** X 站外匹配是指将 X 内容（包括 X 的 @handle 或用户 ID）与某个人、家庭、设备、浏览器或其他 X 站外标识符相关联。只有在进行关联之前已获得该个人的明确选择加入同意，或符合下文所述情形时，你才可以这样做。

在你尚未获得某人明确选择加入同意、以将其在 X 上的身份与某个 X 站外标识符关联的情况下，我们要求你建立的任何关联必须完全基于他人可以合理预期会被用于该目的的信息。此外，在未获得某人明确选择加入同意的前提下，你只能基于以下内容，尝试将你持有的关于某人的记录与其在 X 上的身份进行匹配：

* **由该个人直接提供给你的信息。** 请注意，对于与你没有任何既有关系的个人的记录（包括从第三方获取的个人数据），不符合这一标准；和/或
* **公开数据。** 在此语境下，“公开数据”是指：
  * 你从公共、普遍可获得的资源（例如某专业协会会员名录）中获得的关于某人的信息
  * 在 X 上关于某人且为公开可用的信息，包括：
    * 帖子
    * 个人资料信息，包括账号简介和公开标明的所在地
    * 显示名称和 @handle

<div id="your-privacy-policy">
  ## 您的隐私政策
</div>

**在用户被允许下载、安装或注册使用您的服务之前，您必须向他们展示您的服务隐私政策。** 该隐私政策至少必须披露以下信息：

* 您从使用您服务的用户处收集的信息
* 您如何使用和共享这些信息（包括与 X 的共享方式）
* 用户就其个人信息如何联系您进行咨询和提出请求

您的隐私政策必须符合所有适用法律，并且对用户的保护程度不得低于 [X 的隐私政策](https://x.com/privacy) 和 [我们其他服务及公司关联方的隐私政策](https://help.x.com/rules-and-policies/x-services-and-corporate-affiliates)。如果您无法遵守您自身的隐私政策和/或 X 的隐私政策，您必须停止访问 X API 并停止使用所有 X 内容。

<div id="using-geo-data">
  ## 使用地理数据
</div>

**由于此类信息的敏感性质，使用地理数据会附加额外限制。** 如果你的服务向帖子添加位置信息，你必须向用户披露：

* 你在何时添加位置信息
* 你是以地理标签（geotag）还是注释数据的形式添加位置信息
* 你的位置信息是以地点（place）的形式列出，还是以地理坐标的形式列出

如果你的应用允许用户在发布帖子时附带位置信息，你必须完全遵守 X 的[地理指南](/zh/developer-terms/geo-guidelines)。

**禁止单独使用任何位置信息或地理信息。** 你不得（也不得允许他人）存储、汇总或缓存 X Content 中所含的位置信息和其他地理信息，除非其作为帖子的一部分。例如，你不得将位置信息或地理信息从帖子中分离出来，用于显示个人在一段时间内去过哪些地方。允许使用热力图以及相关工具来展示汇总的地理活动（例如，在某个城市中使用某个话题标签的人数）。

<div id="x-passwords">
  ## X 密码
</div>

**不得存储 X 密码，也不得要求用户直接向您提供其 X 密码、账户凭证或开发者 App 信息（包括 consumer key）。** 我们建议使用 [Sign-in with X](/zh/fundamentals/authentication/guides/log-in-with-x) 作为身份验证工具，将您的服务与 X 上的用户关联起来。

<div id="platform-usage-guidelines">
  ## 平台使用指南
</div>

你是否已经认真审阅了 X 的各项政策，并且正确配置了你的 API 访问权限？你的服务是否遵守 X 的隐私和控制指南？如果你能对这两个问题都回答“是”，那么你就可以开始使用 X API 和 X 内容了。X 的平台使用指南提供必要的支持，确保你对 X 内容的使用自第一天起直至整个服务生命周期内都保持合规。我们建议你定期审阅这些规则，以确保你的集成以一种对 X 上的人以及整个 X 平台都安全且有益的方式运行。

<div id="spam-bots-and-automation">
  ## 垃圾信息、机器人与自动化
</div>

**禁止使用 X API 和开发者产品来创建垃圾信息，或从事任何形式的平台操纵行为。** 你应当查阅 X 规则中关于[平台操纵和垃圾信息](https://help.x.com/rules-and-policies/platform-manipulation)的内容，并确保你的服务本身不违反我们的政策，也不会使他人得以违反我们的政策。

**执行写操作的服务（包括发布帖子、关注账号或发送私信）必须遵守[自动化规则](https://help.x.com/rules-and-policies/x-automation)。** 特别是，你应当：

* 在向用户发送[自动回复或私信](https://twittercommunity.com/t/policy-clarification-automated-replies-and-mentions/94444)之前，始终获得其明确同意
* 在有人提出不再被你联系的请求时，立即停止联系并予以尊重
* 切勿执行批量、激进或类似垃圾信息的操作，包括[批量关注](https://twittercommunity.com/t/policy-clarification-aggressive-following-and-inorganic-following-behavior/92769)
* 切勿在[多个账号](https://blog.twitter.com/developer/en_us/topics/tips/2018/automation-and-the-use-of-multiple-accounts.html)上发布相同或实质上相似的内容

**如果你在运营一个基于 API 的机器人账号，你必须清楚表明该账号的性质以及由谁负责。** 你绝不能误导或混淆他人，让他们搞不清你的账号是否为机器人账号。一个好的做法是在账号的个人简介中加入一条声明，表明该账号是机器人账号。

<div id="x-performance-benchmarking">
  ## X 性能基准测试
</div>

**你不得使用 X API 来衡量 X 的可用性、性能、功能或使用情况，以用于基准测试、竞争或商业目的。** 例如，你绝不应使用 X API 来：

* 计算汇总性的 X 指标，例如每月活跃用户数（MA）或每日活跃用户数（DA）的总量
* 计算汇总性的 X 帖子指标，例如每天发布的帖子总数，或账号互动次数
* 衡量或分析 X 的响应能力
* 衡量或分析 X 上的垃圾信息或安全状况，但以下允许的情形除外

**我们支持有助于提升 X 上对话健康度的研究。** 未经 X 的明确书面许可，你不得公开披露任何涉及使用 X API 或 X 内容开展的研究或研究发现，或开发、创建或提供任何使用 X API 或 X 内容的服务，这些研究、发现或服务旨在衡量、分析或试图识别违反 X 政策的行为或内容。

**《数字服务法》（DSA）研究人员：** 如果你需要就《数字服务法》第 40 条项下的访问事宜联系 X，请联系 [**EU-Questions@X.com**](mailto:EU-Questions@X.com)。如果你希望申请研究人员访问权限，请提交[申请](https://forms.gle/btDwenPF7M3hgSvw7)。
