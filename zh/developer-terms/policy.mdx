<div id="x-developers">
  ## X + 开发者
</div>

X 热爱开发者。对于这个社区利用 X 数据的力量创造出的各种工具和服务，我们既欣喜又惊叹。作为我们对这一社区承诺的一部分，我们的目标是，为开发者提供开放且公平的数据访问方式，确保 X 上的用户安全，并让整个 X 平台从中受益。为实现这些目标，我们制定了本《开发者政策》，作为指南，帮助大家了解我们关于适当使用 API 和 X 内容的规则和期望。

本《开发者政策》（“**政策**”）为与 X 的应用、服务、网站、网页和内容生态系统进行交互的开发者提供规则和指南。它构成您与 X 之间合同的一部分，用于规范您访问和使用 X API 和 X 内容的行为（无论该等内容是作为《开发者协议》的一部分，还是作为您与 X 签署的其他书面协议的一部分）。违反本政策即被视为违反您的协议。我们可能会不时修改本政策，且无需另行通知。本政策中使用但未在本政策中定义的首字母大写术语，其各自含义以[《开发者协议》](/zh/developer-terms/agreement)或《主许可协议》中赋予的含义为准。

<div id="using-this-policy">
  ## 使用本政策
</div>

我们对本政策的结构进行了编排，力求尽可能易于理解和遵循。在使用 X API 和 X 内容时，请始终牢记以下政策部分中的信息：

1. **为成功打好基础** - 你有责任遵守所有 X 政策。你在访问 X API 和 X 内容之前，应当审阅并理解本政策，以及我们在本文件中提供链接的其他政策。花时间审阅我们的政策，可能会为你节省日后数小时的返工。

2. **隐私与控制至关重要** - 保护和捍卫人们在 X 上的隐私是我们公司核心基因的一部分。因此，我们禁止以任何与人们对隐私的合理预期不一致的方式使用 X 数据。通过基于 X API 构建或访问 X 内容，你在维护这一承诺中承担着特殊责任，尤其体现在尊重人们的隐私，并为他们提供关于其数据如何被使用的透明度和控制权。

3. **遵守平台使用指南** - 获准访问 X API 和 X 内容只是第一步。每当你对如何确保你计划在 X 平台上的使用符合政策有任何疑问时，我们的平台使用指南都应该是你的首选参考。

我们在下文对这三个关键部分分别提供了更加详细的说明。请仔细阅读，以确保你对 X API 和 X 内容的使用符合我们的各项政策。

如果我们认为你违反了本政策（或任何其他 X 政策），我们可能会暂停或永久撤销你对 X API 和 X 内容的访问权限。

最后，请注意，X 可能会监控你对 X API 的使用，以改进 X 应用程序、审查任何商业使用情况，并确保你遵守经批准的使用场景及本政策。

感谢阅读，也感谢你与我们一起构建！我们期待看到你创造的成果！

<div id="set-yourself-up-for-success">
  ## 为成功打好基础
</div>

通过确保你的服务从第一天起就以正确的方式构建，你可以在使用 X API 时避免许多潜在的陷阱。本《开发者政策》中的本节包含所有开发者在使用 X API 或 X 内容之前必须遵守的规则。

免费版、基础版和专业版（详见 [developer.x.com/en](http://developer.x.com/en)）面向业余爱好者、商业原型开发、早期阶段的 X 产品集成，以及终端用户数量有限的应用程序。如果你对 X API 和 X 内容的使用超出了该范围，则必须申请（或已经订阅）企业版（Enterprise）套餐（详见 [developer.x.com/en](http://developer.x.com/en)）。

**我们会审查对 X 开发者平台的所有拟议用途，以核实其是否符合政策——因此，你必须披露（并在适用时更新）你计划如何使用 X API 和 X 内容，方可获得并持续保持访问权限。** 所有新开发者必须[申请开发者账号](https://developer.x.com/portal/petition/essential/basic-info)才能访问 X API。当前尚未获批开发者账号的现有开发者，必须按照 X 的指示申请一个账号。作为此流程的一部分，你需要向我们提供一份书面说明，阐述你计划如何使用 X API 和 X 内容。

你的用例说明对你具有约束力，对其进行任何实质性偏离都可能构成对我们规则的违反，并导致执行措施。你必须就任何对用例的实质性修改通知我们，并在开始将 X 内容用于该新目的之前获得批准。如未履行该义务，可能导致你的 API 和数据访问被暂停或终止。

**一旦基于 X API 构建或访问 X 内容，你必须遵守所有 X 政策。** 这些政策包括本《[开发者政策](/zh/developer-terms/policy)》、“[自动化规则](https://help.x.com/rules-and-policies/x-automation)”、“[展示要求](https://developer.x.com/developer-terms/display-requirements.html)”、“[API 受限用途规则](/zh/developer-terms/restricted-use-cases)”、“[X 规则](https://help.x.com/rules-and-policies/x-rules)”以及“[X 品牌资源](https://about.x.com/who-we-are/brand-toolkit)”，以及你与 X 就使用 X API 或 X 内容签订的任何其他协议，包括但不限于《[开发者协议](/zh/developer-terms/agreement)》或主许可协议或订单（如适用）。你还必须遵守这些政策的任何修改以及 X 推出的任何新政策。你有责任监控你的服务的使用情况，并将你的服务设计为可防止使用者违反 X 政策。如未履行该义务，可能导致你的 API 和 X 内容访问被暂停或终止。

**你不得为单一用例或实质相似或重叠的用例注册多个应用程序。** 在此语境中，“用例”是指通过某个应用程序执行的一组一致的分析、展示或操作。不允许“白标”版本的工具或服务。如果你计划为你的应用程序提供“白标”版本，必须通知我们并获得单独批准。

*作为对这些规则的唯一例外，* 你可以为同一服务的开发（development）、预发布（staging）和生产（production）环境创建并使用最多 3 个应用程序。这些 App 必须注册在同一账号下，并应在名称和描述中明确标识为同一服务的 dev、staging 和 prod 实例。**你不得将开发或预发布应用程序用于生产目的。**

**你必须对所有 API 密钥或其他访问凭证保密。** 你不得使用，也不得鼓励或协助他人使用他人拥有的 API 密钥或其他访问凭证。

**你与 X 的许可协议会限制你对 X API 和 X 内容的使用。除其他事项外，X API 具有速率限制，用于确保数据使用的公平性并打击平台上的垃圾信息。** 你不得超出或规避速率限制，或本政策或你与 X 的协议中描述的、列于[开发者网站](https://developer.x.com/)上的，或由 X 告知你的任何其他限制或约束。

**你不得移除或更改通过 X API 接收的 X 内容上的任何专有声明或标识。** 这有助于确保人们了解 X 内容的来源及其归属。

**出于数据完整性和平台健康的原因，你不得干扰、拦截、破坏或禁用 X API 或 X 服务的任何功能。** 换句话说，请按照 [developer.x.com](https://developer.x.com/) 上预期的方式和文档说明使用 API。有关可接受使用的更多详细信息，请参阅我们的 [HackerOne 指南](https://hackerone.com/x)。

<div id="privacy-and-control-are-essential">
  ## 隐私和控制至关重要
</div>

X 非常重视隐私，我们也期望所有使用 X 内容和 X API 的人同样重视隐私。任何以与人们对隐私的合理预期不一致的方式使用 X 开发者平台、X API 或 X 内容的行为，都可能受到执法行动，包括暂停或终止对 API 和 X 内容的访问权限。

你对隐私和控制的承诺必须覆盖对 X 内容的所有使用，以及你使用我们的 API 构建的服务的各个方面。为此，使用你服务的人必须理解并同意你如何使用他们的数据，以及你如何代表他们访问 X。你可以通过向人们提供清晰、全面且透明的隐私政策来实现这一点，并确保在代表他们采取任何行动之前，事先从每一位使用你服务的人那里获得明确且知情的同意。**请注意，仅仅是一个人通过认证登录你的服务本身并不构成同意。**

<div id="consent-permissions">
  ## 同意与权限
</div>

**特别是，在执行以下任何操作之前，你必须事先获得用户明确且知情的同意：**

* 以他们的名义执行*任何*操作。这包括（但不限于）：
  * 向 X 发布内容
  * 关注/取消关注账号
  * 修改个人资料或账号信息
  * 在帖子中添加标签或任何其他内容

* 重新发布通过非 X API 或其他 X 工具获取的内容

* 使用他人的 X 内容来推广产品或服务

* 存储非公开内容，例如私信（Direct Messages，DMs），或任何其他私人或机密信息

* 分享或发布受保护内容，或任何其他私人或机密信息

**如果你的服务允许用户向 X 发布内容，你在发布前必须做到以下几点：**

* 精确展示将要发布的内容
* 清楚告知使用你服务的用户，内容中会添加哪些地理位置信息（如果有）

**如果你的服务允许用户同时向你的服务和 X 发布内容，你在发布前必须做到以下几点：**

* 获取发布该内容的许可
* 说明你将把内容发布到哪些位置/平台

**你必须尊重所有 X 内容的受保护状态和被屏蔽状态。你不得将通过某个人的认证令牌获取的内容提供给未被授权查看该内容的其他人。**

* **受保护账号：**[受保护账号](https://help.x.com/safety-and-security/public-and-protected-posts)的内容仅对已获账号所有者批准关注该账号的用户可见。因此，如果你运营的服务会访问受保护账号，你只能向被授权查看该内容的特定用户提供此类内容。
* **被屏蔽账号：**X 上的用户可以出于任何他们选择的理由[屏蔽](https://help.x.com/using-x/blocking-and-unblocking-accounts)他人访问其账号。将通过令牌（或任何其他基于 API 的操作）获得的信息合并或混用以绕过这一选择是不被允许的。

**由于私信（DMs）本质上是非公开的，提供 DM 功能的服务必须采取额外措施来保护个人隐私。你不得向未被授权查看 DM 内容的人提供该内容。如果你的服务提供 DM 功能，你还必须：**

* 在你为 DMs 发送已读回执事件时通知用户。你可以通过直接在你的服务中提供通知，或展示会话中其他参与者的已读回执来实现。
* 在将媒体配置为在 DM 中以“共享”（即可在多个 DM 中复用）的形式发送之前获得同意。如果你确实允许 DM 中的媒体被“共享”，你必须明确告知该内容将对任何拥有该媒体 URL 的人可访问。

<div id="content-compliance">
  ## 内容合规
</div>

**如果你在线下存储 X 内容，你必须确保其与该内容在 X 上的当前状态保持一致。** 具体来说，如果该内容在 X 上被删除或修改，你必须删除或修改你所持有的任何对应内容。此操作必须在合理可行的情况下尽快完成，或在收到 X 或相关 X 账号所有者请求后 24 小时内完成，或按照你与 X 的协议或适用法律的其他要求完成。除非适用法律另有禁止，并且仅在取得 X 的明确书面许可的情况下，方可不执行上述要求。

被修改的内容可以有多种形式。这包括（但不限于）：

* 已被设为私密或获得受保护状态的内容
* 已在平台上被暂停显示的内容
* 已从中移除地理标签的内容
* 已被 X 屏蔽或删除的内容

<div id="off-x-matching">
  ## 站外匹配
</div>

**我们会限制你在何种情况下可以将 X 上的个人与从 X 之外获得或存储的信息进行匹配。** 站外匹配是指将 X 内容（包括 X 的 @handle 或 user ID）与某个人、家庭、设备、浏览器或其他站外标识符关联起来。你只能在事前已获得该个人明确的主动同意（opt-in），或在下文所述情形下，才可以进行此类关联。

在你未获得某人明确主动同意以将其在 X 上的身份与站外标识符关联的情形下，我们要求，你所建立的任何关联必须完全基于人们可以合理预期会被用于该目的的信息。此外，在没有该人明确主动同意的情况下，你只能基于以下信息，尝试将你所持有的关于某人的记录与其在 X 上的身份进行匹配：

* **该人直接提供给你的信息。** 请注意，对于与你没有任何既有关系的个人的记录（包括从第三方获取的个人数据），不符合这一标准；和/或
* **公共数据。** 在此语境下，“公共数据”是指：
  * 你从公共、普遍可用的资源（例如某专业协会会员名录）中获得的关于某人的信息
  * 在 X 上公开可获得的关于某人的信息，包括：
    * 帖子
    * 个人资料信息，包括账号简介和公开声明的所在地
    * 显示名称和 @handle

<div id="your-privacy-policy">
  ## 您的隐私政策
</div>

**在用户被允许下载、安装或注册使用您的服务之前，您必须向他们展示您的服务隐私政策。** 隐私政策至少必须披露以下信息：

* 您从使用您服务的用户那里收集的信息
* 您如何使用和共享这些信息（包括与 X 共享）
* 用户如何就其信息相关的咨询和请求联系您

您的隐私政策必须符合所有适用法律，并且对个人的保护不得低于 [X 的隐私政策](https://x.com/privacy) 和[我们其他服务及关联公司的隐私政策](https://help.x.com/rules-and-policies/x-services-and-corporate-affiliates) 所提供的保护程度。如果您无法遵守您自身和/或 X 的隐私政策，您必须停止访问 X API 并停止使用所有 X 内容。

<div id="using-geo-data">
  ## 使用地理数据
</div>

**由于地理数据的敏感性，使用地理数据会附带额外限制。** 如果你的服务向帖子添加位置信息，你必须向用户披露：

* 你在何时添加位置信息
* 你是以地理标签（geotag）还是注释数据的形式添加位置信息
* 你的位置信息是以地点（place）还是以地理坐标的形式列出

如果你的应用允许用户在发布帖子时附带位置信息，你必须完全遵守 X 的[地理指南](/zh/developer-terms/geo-guidelines)。

**禁止以独立形式使用任何位置信息或地理信息。** 除非是作为帖子的一部分，否则你不得（也不得允许他人）存储、聚合或缓存 X 内容中包含的位置信息和其他地理信息。例如，你不得将位置信息或地理信息从帖子中分离出来，用于展示个人在一段时间内去过哪些地方。热力图以及展示聚合地理活动的相关工具（例如，显示在某城市中使用某个话题标签的人数）是被允许的。

<div id="x-passwords">
  ## X 密码
</div>

**你不得存储 X 密码，也不得要求用户直接向你提供他们的 X 密码、账号凭证或开发者 App 信息（包括 consumer key）。** 我们建议使用 [使用 X 登录](/zh/fundamentals/authentication/guides/log-in-with-x) 作为身份验证工具，将你的服务与 X 上的用户连接起来。

<div id="platform-usage-guidelines">
  ## 平台使用指南
</div>

你是否已经仔细审阅了 X 的各项政策，并以正确的方式配置了你的 API 访问权限？你的服务是否遵循了 X 的隐私和控制相关指南？如果你能对这两个问题都回答“是”，那么你就已经准备好开始使用 X API 和 X 内容了。X 的平台使用指南为你提供必要的指引，确保你从第一天起直至整个服务生命周期内，对 X 内容的使用始终保持合规。我们建议你定期查看这些规则，以确保你的集成始终以一种对 X 上的人以及整个 X 平台都安全且有益的方式运行。

<div id="spam-bots-and-automation">
  ## 垃圾信息、机器人与自动化
</div>

**禁止使用 X API 和开发者产品来制造垃圾信息，或从事任何形式的平台操控行为。** 你应当查阅《X 规则》中关于[平台操控和垃圾信息](https://help.x.com/rules-and-policies/platform-manipulation)的内容，确保你的服务本身不会，也不会使他人能够违反我们的政策。

**执行写入操作的服务（包括发布帖子、关注账号或发送私信）必须遵守[自动化规则](https://help.x.com/rules-and-policies/x-automation)。** 特别是，你应当：

* 在向他人发送[自动回复或私信](https://twittercommunity.com/t/policy-clarification-automated-replies-and-mentions/94444)之前，始终获得其明确同意
* 立即尊重任何要求停止与你联系的请求
* 切勿执行批量、激进或类似垃圾信息的操作，包括[批量关注](https://twittercommunity.com/t/policy-clarification-aggressive-following-and-inorganic-following-behavior/92769)
* 切勿在[多个账号](https://blog.twitter.com/developer/en_us/topics/tips/2018/automation-and-the-use-of-multiple-accounts.html)上发布完全相同或实质相似的内容

**如果你运营的是一个基于 API 的机器人账号，你必须清楚地表明该账号的性质以及由谁负责。** 你绝不能以任何方式误导或让人混淆你账号是否为机器人账号。一个好的做法是在个人简介中加入说明，表明该账号是机器人账号。

<div id="x-performance-benchmarking">
  ## X 性能基准测试
</div>

**您不得出于基准测试、竞争或商业目的，使用 X API 来衡量 X 的可用性、性能、功能或使用情况。** 例如，您绝不应使用 X API 来：

* 计算 X 的汇总指标，例如每月活跃用户数（MAs）或每日活跃用户数（DAs）的总数
* 计算 X 帖子的汇总指标，例如每天发布的帖子总数，或账号互动次数
* 测量或分析 X 的响应能力
* 测量或分析 X 上的垃圾信息或安全状况，但以下允许的情形除外

**我们支持有助于提升 X 上对话健康状况的研究。** 未经 X 事先书面许可，您不得公开披露任何涉及使用 X API 或 X 内容的研究或研究结果，亦不得开发、创建或提供利用 X API 或 X 内容来衡量、分析或试图识别违反 X 政策的行为或内容的服务。

**DSA 研究人员：** 如果您因《数字服务法》第 40 条项下的访问事宜需要联系 X，请发送邮件至 [**EU-Questions@X.com**](mailto:EU-Questions@X.com)。如果您希望申请研究人员访问权限，请提交[申请](https://forms.gle/btDwenPF7M3hgSvw7)。
