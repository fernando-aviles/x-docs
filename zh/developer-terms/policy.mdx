<div id="x-developers">
  ## X + 开发者
</div>

X 热爱开发者。我们对这个社区利用 X 数据的强大能力构建出的工具和服务感到既高兴又惊叹。作为我们对这一社区承诺的一部分，我们的目标是为开发者提供开放且公平的数据访问，同时保障 X 上用户的安全，并使整个 X 平台受益。为了实现这些目标，我们制定了《Developer Policy》，作为指南帮助大家理解我们关于适当使用 API 和 X Content 的规则和期望。

本《Developer Policy》（“**Policy**”）为与 X 的应用程序、服务、网站、网页和内容生态进行交互的开发者提供规则和准则。它构成你与 X 之间规范你访问和使用 X API 和 X Content 的合同的一部分（无论是作为《Developer Agreement》的一部分，还是你与 X 之间其他书面协议的一部分）。违反本 Policy 将被视为违反你的协议。本 Policy 可能会不时变更，恕不另行通知。本 Policy 中使用但未在本 Policy 中定义的首字母大写术语，应具有 [Developer Agreement](/zh/developer-terms/agreement) 或《Master License Agreement》中赋予它们的各自含义。

<div id="using-this-policy">
  ## 使用本政策
</div>

我们对本政策进行了结构化编排，旨在让你尽可能容易理解和遵守。在使用 X API 和 X 内容时，请务必牢记以下政策部分中的信息：

1. **为成功打好基础** - 你有责任遵守所有 X 政策。在访问 X API 和 X 内容之前，务必审阅并理解本政策，以及我们在本文件中链接到的其他政策。花时间审阅我们的政策，可能会为你节省今后数小时的返工。

2. **隐私与控制至关重要** - 保护和维护人们在 X 上的隐私已深植于我们公司的核心基因。因此，我们禁止以任何与人们对隐私的合理预期不一致的方式使用 X 数据。如果你基于 X API 构建或访问 X 内容，你在维护这一承诺方面扮演着特殊角色，其中最重要的是尊重人们的隐私，并为他们就其数据如何被使用提供透明度和控制权。

3. **遵循平台使用指南** - 获批访问 X API 和 X 内容只是第一步。每当你对如何在计划使用 X 平台时确保遵守政策有任何疑问时，平台使用指南都应是你首先查阅的内容。

我们在下文对这三个关键部分中的每一项提供了更多详细说明。请仔细阅读，以确保你对 X API 和 X 内容的使用符合我们的政策。

如果我们认为你违反了本政策（或任何其他 X 政策），我们可能会暂停或永久撤销你对 X API 和 X 内容的访问。

最后，请注意，X 可能会监控你对 X API 的使用，以改进 X 应用、评估任何商业用途，并确保你遵守已获批准的使用场景和本政策。

感谢你的阅读，也感谢你选择与我们一起构建！我们期待看到你的创意成果！

<div id="set-yourself-up-for-success">
  ## 为成功打好基础
</div>

通过确保你的服务从一开始就以正确的方式构建，你可以在使用 X API 时避免许多潜在的陷阱。本《开发者政策》的这一部分包含所有开发者在使用 X API 或 X 内容之前必须遵守的规则。

Free、Basic 和 Pro 方案（如 [developer.x.com/en](http://developer.x.com/en) 所述）专为业余爱好者、商业原型设计、早期 X 产品集成，以及面向终端用户数量有限的应用而设计。如果你对 X API 和 X 内容的使用超出了这一范围，则必须申请（或已经订阅）Enterprise 方案（如 [developer.x.com/en](http://developer.x.com/en) 所述）。

**我们会审查所有拟在 X 开发者平台上的使用方式，以验证其是否符合政策——因此，你必须披露（并在适用时更新）你计划如何使用 X API 和 X 内容，作为获得并保持访问权限的前提。** 所有新开发者都必须[申请开发者账号](https://developer.x.com/portal/petition/essential/basic-info)才能访问 X API。当前尚未获得批准开发者账号的开发者，必须按照 X 的指示提出申请。作为此流程的一部分，你需要向我们提供书面说明，描述你打算如何使用 X API 和 X 内容。

你的用例说明对你具有约束力，任何与其存在实质性偏离的行为都可能构成对我们规则的违反，并导致执行措施。你必须就用例的任何实质性修改通知我们，并在开始将 X 内容用于该新目的之前获得批准。不履行此义务可能导致你的 API 和数据访问被暂停或终止。

**在基于 X API 进行构建或访问 X 内容时，你必须遵守所有 X 政策。** 这些政策包括本[《开发者政策》](/zh/developer-terms/policy)、[《自动化规则》](https://help.x.com/rules-and-policies/x-automation)、[《展示要求》](https://developer.x.com/developer-terms/display-requirements.html)、[《API 限制使用规则》](/zh/developer-terms/restricted-use-cases)、[《X 规则》](https://help.x.com/rules-and-policies/x-rules)以及 [X 品牌资源](https://about.x.com/who-we-are/brand-toolkit)，以及你与 X 就使用 X API 或 X 内容签订的任何其他协议，包括但不限于[《开发者协议》](/zh/developer-terms/agreement)或主许可协议或订单（如适用）。你还必须遵守这些政策的任何修改以及 X 推出的任何新政策。你有责任监控你的服务的使用情况，并设计你的服务以防止使用你服务的人违反 X 政策。不履行此义务可能导致你的 API 和 X 内容访问被暂停或终止。

**你不得为单一用例或实质相似或重叠的用例注册多个应用。** 在此语境中，“用例”是指通过某个应用执行的一组一致的分析、展示或操作。不允许提供工具或服务的“白标”（white label）版本。如果你计划为你的应用提供“白标”版本，必须通知我们并单独获得我们的批准。

*作为对这些规则的唯一例外，*你可以为同一服务的开发、预发布和生产环境创建并使用最多 3 个应用。这些应用必须注册到同一个账号，并应在名称和描述中清楚标识为同一服务的开发（dev）、预发布（staging）和生产（prod）环境实例。**你不得将开发或预发布应用用于生产目的。**

**你必须对所有 API 密钥或其他访问凭证保密。** 你不得使用，也不得鼓励或协助他人使用他人拥有的 API 密钥或其他访问凭证。

**你与 X 签订的许可协议会限制你对 X API 和 X 内容的使用。除其他事项外，X API 具有速率限制，以帮助确保公平地使用数据并打击平台上的垃圾信息。** 你不得超出或规避速率限制，或本政策或你与 X 的协议中所述、列于 [Developer Site](https://developer.x.com/) 上或由 X 告知你的任何其他限制或约束。

**你不得移除或更改通过 X API 接收到的 X 内容上的任何专有声明或标识。** 这有助于确保人们知道 X 内容的来源及其归属。

**出于数据完整性和平台健康的考虑，你不得干扰、拦截、扰乱或禁用 X API 或 X 服务的任何功能。** 换句话说，应按照 [developer.x.com](https://developer.x.com/) 上所预期和记录的方式使用这些 API。有关可接受使用的更多详情，请参阅我们的 [HackerOne 指南](https://hackerone.com/x)。

<div id="privacy-and-control-are-essential">
  ## 隐私与控制至关重要
</div>

X 严肃对待隐私问题，我们也期望所有使用 X Content 和 X API 的人同样如此。任何以与人们对隐私的合理预期不一致的方式使用 X 开发者平台、X API 或 X Content 的行为，都可能会受到合规执法行动，这些行动可能包括暂停或终止对 API 和 X Content 的访问。

你对隐私和控制的承诺必须适用于对 X Content 的所有使用场景，以及你使用我们的 API 所构建服务的各个方面。为此，使用你服务的人必须理解并同意你如何使用他们的数据，以及你如何代表他们访问 X。你可以通过向人们提供清晰、全面且透明的隐私政策来实现这一点，并且在代表他们采取任何行动之前，确保从每一位使用你服务的人那里获得明确且知情的同意。**请注意，个人仅仅通过身份验证登录你的服务，并不构成同意。**

<div id="consent-permissions">
  ## 同意与权限
</div>

**特别是，在执行以下任何操作之前，你必须事先获得用户明确且知情的同意：**

* 以他们的名义采取*任何*行动。这包括（但不限于）：
  * 在 X 上发布内容
  * 关注/取消关注账号
  * 修改个人资料或账号信息
  * 在帖子中添加话题标签或任何其他内容

* 通过非 X API 或其他 X 工具的方式获取并重新发布内容

* 使用他人的 X 内容来推广某个产品或服务

* 存储非公开内容，例如私信（Direct Messages，DMs），或任何其他私人或机密信息

* 共享或发布受保护内容，或任何其他私人或机密信息

**如果你的服务允许用户在 X 上发布内容，你在发布之前必须做到以下几点：**

* 准确展示将要发布的内容
* 明确告知使用你服务的用户，将向内容中添加哪些地理信息（如果有）

**如果你的服务允许用户同时在你的服务和 X 上发布内容，你在发布之前必须做到以下几点：**

* 获得发布该内容的许可
* 说明你将把内容发布到哪些平台或渠道

**你必须尊重所有 X 内容的受保护和被屏蔽状态。你不得将使用某个人的认证令牌获取的内容提供给未被授权查看该内容的其他人。**

* **受保护账号：**[受保护账号](https://help.x.com/safety-and-security/public-and-protected-posts)的内容仅对已被账号所有者批准关注该账号的用户可见。因此，如果你运营的服务会访问受保护账号，你只能这样做以便将此类内容提供给有权查看该内容的特定用户。
* **被屏蔽账号：**X 上的用户可以基于其选择的任何理由[屏蔽](https://help.x.com/using-x/blocking-and-unblocking-accounts)他人访问其账号。将通过令牌（或任何其他基于 API 的操作）获得的信息混合使用以绕过这一选择是不被允许的。

**由于私信（DMs）本质上是非公开的，提供私信功能的服务必须采取额外措施来保护个人隐私。你不得向未被授权查看该内容的用户提供私信内容。如果你的服务提供私信功能，你还必须：**

* 在你为私信发送已读回执事件时通知用户。你可以通过在你的服务中直接提供通知，或通过展示会话中其他参与者的已读回执来实现。
* 在将要把在私信中发送的媒体配置为“共享”（即可在多个私信中重复使用）之前获得同意。如果你允许私信中的媒体被“共享”，你必须明确告知该内容将对任何拥有该媒体 URL 的人可访问。

<div id="content-compliance">
  ## 内容合规
</div>

**如果你在 X 之外存储 X 内容，你必须确保其与该内容在 X 上的当前状态保持同步。** 具体而言，如果某条内容在 X 上被删除或修改，你必须相应删除或修改你所持有的该内容。你必须在合理可行的情况下尽快完成此操作，或在接到 X 或相关 X 账号所有者的请求后 24 小时内完成，或按照你与 X 的协议或适用法律的其他要求完成。除非法律另有禁止，并且仅在获得 X 的书面明确许可的情况下，才可以不执行上述要求。

被修改的内容可以有多种形式。这包括（但不限于）：

* 已被设为私密或获得受保护状态的内容
* 已被平台暂停或封禁的内容
* 已移除地理标签的内容
* 已在 X 上被限制或移除的内容

<div id="off-x-matching">
  ## 站外匹配
</div>

**我们会限制你在何种情况下可以将 X 上的个人与在 X 之外获取或存储的信息进行匹配。** 站外匹配是指将 X 内容（包括 X 的 @handle 或用户 ID）与某个人、家庭、设备、浏览器或其他站外标识符相关联。只有在你在进行关联之前已获得该人的明确主动同意（opt-in），或符合下文所述情形时，你才可以这样做。

在你未获得某人明确主动同意以将其 X 身份链接到站外标识符的情况下，我们要求你所建立的任何关联必须仅基于某人可以合理预期会被用于该目的的信息。此外，在没有获得某人明确主动同意时，你只能基于以下内容，尝试将你关于某人的记录与一个 X 身份进行匹配：

* **该人直接提供给你的信息。** 请注意，你与之没有任何既有关系的个人记录（包括从第三方获取的个人数据）不符合此标准；和/或
* **公开数据。** 在此语境下，“公开数据”是指：
  * 你从公共、普遍可获取的资源（例如某专业协会成员名录）中获得的关于某人的信息
  * 关于某人的、在 X 上公开可获取的信息，包括：
    * 帖子
    * 个人资料信息，包括账号简介和公开标明的位置
    * 显示名称和 @handle

<div id="your-privacy-policy">
  ## 您的隐私政策
</div>

**在用户被允许下载、安装或注册使用您的服务之前，您必须向其展示您的服务隐私政策。** 该隐私政策至少必须披露以下信息：

* 您从使用您服务的用户处收集的信息
* 您如何使用和共享该信息（包括与 X 的共享方式）
* 用户如何就其信息相关的咨询和请求联系您

您的隐私政策必须符合所有适用法律，并且其对用户的保护不得低于 [X 的隐私政策](https://x.com/privacy) 以及[我们其他服务和关联公司的隐私政策](https://help.x.com/rules-and-policies/x-services-and-corporate-affiliates)的保护水平。如果您无法遵守您自身和/或 X 的隐私政策，您必须停止您对 X API 的访问以及对所有 X 内容的使用。

<div id="using-geo-data">
  ## 使用地理数据
</div>

**由于此类信息的敏感性，使用地理数据会受到额外限制。** 如果你的服务向帖子添加位置信息，你必须向用户披露：

* 你在何时添加位置信息
* 你是否以地理标签或注释 data 的形式添加位置信息
* 你的位置信息是以地点的形式呈现，还是以地理坐标的形式呈现

如果你的应用允许用户在发布内容时附带他们的位置，你必须全面遵守 X 的[地理指南](/zh/developer-terms/geo-guidelines)。

**禁止单独使用位置信息或其他地理信息。** 除非作为帖子的一部分，你不得（也不得允许他人）存储、汇总或缓存 X 内容中包含的位置信息和其他地理信息。 例如，你不得将位置信息或其他地理信息从帖子中拆分出来，用于展示个人随时间变化的行踪。允许使用热力图和相关工具来展示汇总的地理活动（例如，在某个城市使用某个标签的人数）。

<div id="x-passwords">
  ## X 密码
</div>

**不得存储 X 密码，也不得要求人们直接向你提供他们的 X 密码、账户凭证或开发者 App 信息（包括 consumer key）。** 我们建议使用 [Sign-in with X](/zh/fundamentals/authentication/guides/log-in-with-x) 作为身份验证工具，将你的服务与 X 上的用户关联起来。

<div id="platform-usage-guidelines">
  ## 平台使用指南
</div>

你是否已经仔细审阅了 X 的相关政策，并以正确的方式配置了你的 API 访问权限？你的服务是否遵循了 X 的隐私和控制指南？如果这两个问题的答案都是肯定的，那么你就已经准备好开始使用 X API 和 X Content 了。X 的平台使用指南提供了必要的指引，确保你从第一天起到整个服务生命周期中对 X Content 的使用始终合规。我们建议你定期审查这些规则，以确保你的集成始终以对 X 上的用户以及整个 X 平台安全且有益的方式运行。

<div id="spam-bots-and-automation">
  ## 垃圾信息、机器人和自动化
</div>

**禁止使用 X API 和开发者产品创建垃圾信息或从事任何形式的平台操纵行为。** 你应当查阅关于[平台操纵和垃圾信息](https://help.x.com/rules-and-policies/platform-manipulation)的《X 规则》，并确保你的服务本身不会、也不会使他人能够违反我们的政策。

**执行写入操作的服务（包括发布帖子、关注账号或发送私信）必须遵守[自动化规则](https://help.x.com/rules-and-policies/x-automation)。** 特别是，你应当：

* 在向他人发送[自动回复或私信](https://twittercommunity.com/t/policy-clarification-automated-replies-and-mentions/94444)之前，始终获得对方的明确同意
* 一旦有人要求不再被你联系，必须立即予以尊重并停止联系
* 切勿执行批量、激进或具有垃圾信息性质的操作，包括[批量关注](https://twittercommunity.com/t/policy-clarification-aggressive-following-and-inorganic-following-behavior/92769)
* 切勿在[多个账号](https://blog.twitter.com/developer/en_us/topics/tips/2018/automation-and-the-use-of-multiple-accounts.html)上发布相同或实质上相似的内容

**如果你在运营基于 API 的机器人账号，必须清楚说明该账号的性质以及由谁负责。** 你绝不应误导他人，或让他人对你的账号是否为机器人账号产生混淆。一个好的做法是在个人资料简介中加入说明，表明该账号是机器人。

<div id="x-performance-benchmarking">
  ## X 性能基准测试
</div>

**你不得使用 X API 出于基准测试、竞争或商业目的来衡量 X 的可用性、性能、功能或使用情况。** 例如，你绝不能使用 X API：

* 计算 X 的汇总指标，例如每月活跃用户总数（Monthly Actives, MAs）或每日活跃用户总数（Daily Actives, DAs）
* 计算 X 帖子的汇总指标，例如每天发布的帖子总数，或账号互动次数
* 衡量或分析 X 的响应速度
* 衡量或分析 X 上的垃圾信息或安全状况，但下文允许的情形除外

**我们支持有助于提升 X 上对话健康状况的研究。** 未经 X 明确的书面许可，你不得公开披露任何关于使用 X API 或 X Content 的研究或发现，也不得开发、创建或提供任何服务，用于衡量、分析或试图识别违反 X 政策的行为或内容。

**DSA 研究人员：** 如果你因依据《数字服务法》第 40 条申请访问而需要联系 X，请发送邮件至 [**EU-Questions@X.com**](mailto:EU-Questions@X.com)。如果你希望申请研究人员访问权限，请提交[申请](https://forms.gle/btDwenPF7M3hgSvw7)。
