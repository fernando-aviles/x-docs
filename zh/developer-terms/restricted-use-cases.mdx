要使用我们的开发者平台，您必须先阅读并同意我们的[开发者协议和政策](/zh/developer-terms/agreement)，以及相关政策，包括[展示要求](https://developer.x.com/en/developer-terms/display-requirements.html)和[自动化规则](https://help.twitter.com/en/rules-and-policies/twitter-automation)。除其他内容外，我们的协议和政策对若干受限使用场景提供了相应规范。下面我们就其中部分限制提供更多补充信息。

<div id="sensitive-information">
  ## 敏感信息
</div>

你在使用 X 数据来推导或推断 X 用户的潜在敏感特征时应当格外谨慎。不得针对任何 X 用户推导或推断以下信息，或存储此类已推导或推断的信息：

* 健康状况（包括怀孕）
* 不利的财务状况或境况
* 政治立场或信仰
* 种族或民族出身
* 宗教或哲学信仰或背景
* 性生活或性取向
* 工会会员身份
* 被指控或实际实施犯罪的情况

在不存储任何个人 data（例如用户 id、用户名及其他标识符）的前提下，对 X 内容进行汇总分析是被允许的，前提是该分析同样遵守适用法律以及《开发者协议和政策》的所有条款。

<div id="off-x-matching">
  ## 站外匹配
</div>

站外匹配是指将 X 内容（包括 X 用户名或用户 ID）与某个人、家庭、设备、浏览器或其他站外标识符进行关联。例如，将某个 X 用户名与某企业的客户记录关联起来（即在你的客户记录中，“John Doe”与 X 上的 @johndoe 匹配）。

我们希望人们在 X 上可以安心创建一个独立的身份，如果他们愿意，也可以是一个使用化名的身份。如果你打算将关于某个 X 用户的任何信息与某个站外标识符关联，我们要求你在进行关联之前，必须获得该用户的明确、主动选择加入的同意。例如，如果用户在注册你的服务时，作为注册流程的一部分，直接向你提供了他们的 X 用户名（handle），你就可以据此获得该同意。

在你没有获得用户明确、主动同意将其 X 身份与某个站外标识符关联的情况下，我们要求，你所做的任何关联只能基于用户在合理预期范围内会被用于该目的的信息。如果用户得知你正在使用他们提供的信息，将其 X 账号与 X 之外的某个身份关联而会感到意外，请不要这么做。此外，在缺乏个人明确、主动同意的情形下，你只能基于以下内容，尝试将你记录中的某人与某个 X 身份进行匹配：

* **用户直接提供给你的信息。** 对于与你没有任何既有关系的个人的记录（包括从第三方获取的个人数据），不符合此标准；和/或
* **公开数据。** 在此语境中，“公开数据”指的是：
  * 你从公开且普遍可获得的资源（例如某专业协会成员名录）中获取的关于某个用户的信息
  * 在 X 上公开可见的关于某个用户的信息，包括：
    * 帖子
    * 个人资料信息，包括用户的个人简介和公开声明的所在地
    * 显示名称和用户名

<div id="redistribution-of-x-content">
  ## 重新分发 X 内容
</div>

如果你需要与第三方共享通过 X API 获取的 X 内容，最好的方式是共享 Post ID、Direct Message ID 和/或 User ID，由内容的最终用户使用 X API 对其进行 rehydrate（即重新请求完整的帖子、用户或私信内容）。这有助于确保 X 内容的最终用户始终直接从我们这里获得最新信息。

我们允许通过非自动化方式对已 rehydrate 的 X 内容进行有限的重新分发。如果你选择以这种方式与第三方共享已 rehydrate 的 X 内容，则你每天、每位接收方最多只能共享 50,000 个已 rehydrate 的公共帖子对象（Post Object）和/或用户对象（User Object），并且不应将这些数据公开提供（例如，作为博客文章的附件或在公共 Github 代码库中）。

在重新分发 X 内容时，还有几点需要注意：

* 在 30 天内，如果未事先获得 X 的明确书面许可，你向单一实体分发的 Post ID 总量最多为 1,500,000 个。
* 代表学术机构、且仅为非商业研究目的重新分发 Post ID 和/或 User ID 的个人，可不受数量限制地重新分发 Post ID 和/或 User ID。
* 如需按上述方式共享 X 内容的许可，请使用 API Policy 支持表单进行申请。

在你被允许向第三方分发 X 内容的范围内，请注意，这些内容仍受《开发者协议》和《开发者政策》约束，并且这些第三方在接收 X 内容之前，必须同意 X 的[服务条款](https://twitter.com/en/tos)、[隐私政策](https://twitter.com/en/privacy)、[开发者协议](/zh/developer-terms/agreement)和[开发者政策](/zh/developer-terms/policy)。

<div id="multiple-applications">
  ## 多个应用
</div>

你不得为单一使用场景，或在本质上相同或重叠的使用场景，注册多个应用。要了解更多关于这些政策的信息，请参阅[此处](https://twittercommunity.com/t/policy-clarification-multiple-applications-for-the-same-use-case/92080)。

在此语境下，我们将“使用场景”定义为通过某个应用执行的一组固定的分析、展示或操作。向不同终端用户提供同一项服务或应用被视为一个使用场景；但工具或服务的“白标”版本不包括在内。如果你计划提供你的应用的“白标”版本，必须事先告知我们并单独获得批准。这些规则同时适用于你注册的应用，以及你的工具或服务的终端用户所注册的应用；如果你要求终端用户为了使用你的工具或服务而注册应用，可能会导致我们对你、你的应用、你的客户和/或你的工具或服务的终端用户采取执法措施。

此规则唯一的例外，是为同一项服务创建开发（“dev”）、预发布（“staging”）和生产（“prod”）实例。请确保这些应用被清晰标记（例如在应用名称或描述中），并且不要将开发或预发布应用用于生产目的。

<div id="automation-spam-and-auto-responses">
  ## 自动化、垃圾信息和自动回复
</div>

禁止使用 X 的 API 和开发者产品创建垃圾信息，或从事垃圾信息相关行为。你应当查阅有关垃圾信息的 [X Rules](https://t.co/rules)，并确保你的应用本身不会、也不会让用户能够违反我们的政策。

如果你的应用将被用于在 X 服务上执行写入操作，包括发布帖子、关注账号或发送私信，你应当仔细阅读 [Automation Rules](https://support.twitter.com/articles/76915)，以确保你的服务符合我们的指南。特别是，你应当：

* 在向用户发送[自动回复或消息](https://twittercommunity.com/t/policy-clarification-automated-replies-and-mentions/94444)之前，一定要获得其明确同意
* 立即尊重并执行用户要求不再被你联系的请求
* 切勿执行批量、激进或类似垃圾信息的操作，包括[批量关注](https://twittercommunity.com/t/policy-clarification-aggressive-following-and-inorganic-following-behavior/92769)
* 切勿在[多个账号](https://blog.twitter.com/developer/en_us/topics/tips/2018/automation-and-the-use-of-multiple-accounts.html)上发布完全相同或高度相似的内容

<div id="measuring-the-x-service">
  ## 衡量 X 服务
</div>

不得将 X API 用于衡量 X 的可用性、性能、功能或使用情况，以进行基准测试或竞争性分析。例如，你绝不能使用 X API 来：

* 计算 X 用户的聚合指标，例如活跃用户或账号的总数
* 计算 X 帖子的聚合指标，例如每天的帖子总数，或用户互动次数或账号互动次数
* 衡量或分析 X 上的垃圾信息或安全情况，除非 [X Rules](https://help.twitter.com/en/rules-and-policies/twitter-rules) 中另有允许

<div id="surveillance-privacy-and-user-protection">
  ## 监控、隐私与用户保护
</div>

在 X，我们将保护和捍卫用户隐私深度融入公司的核心基因之中——我们的开发者产品和数据产品也体现了这一承诺。我们相信，X 数据可以成为推动世界向善的强大力量——从在雅加达洪灾期间挽救生命，到帮助美国地质调查局（USGS）追踪地震，再到与联合国合作实现可持续发展目标。然而，我们禁止任何实体将 X 数据和 X API 用于监控目的，或以任何其他方式使用它们，从而与用户对隐私的合理预期不一致。无一例外。

我们在 [Developer Agreement](/zh/developer-terms/agreement) 中描述了对我们数据和开发者产品的禁止用途，其中包括禁止调查或追踪 X 用户或其内容，以及禁止追踪、预警或监控敏感事件（例如抗议、集会或社区组织会议）。

根据这些条款，以下其他类别的活动也被禁止（包括但不限于）：

* 调查或追踪敏感群体和组织，例如工会或维权团体
* 背景调查或任何形式的严苛审查
* 信用或保险风险分析
* 针对个人的画像或心理特征细分
* 人脸识别

这些政策适用于我们所有 API 的用户。任何将 X API 滥用于上述目的的行为，都将受到相应的执行措施约束，其中可能包括暂停或终止访问权限。

有关执法机构寻求获取 X 账号信息的更多详情，请访问 [https://t.co/le](https://t.co/le)。

此外，目前，除 [Grok](https://help.x.com/en/using-x/about-grok) 之外，X 禁止以任何方式使用 X API 和/或 X Content 来微调或训练基础模型或前沿模型。
