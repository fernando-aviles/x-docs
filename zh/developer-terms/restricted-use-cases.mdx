在使用我们的开发者平台之前，您需要审阅并同意我们的[开发者协议与政策](/zh/developer-terms/agreement)，以及相关政策，包括[展示要求](https://developer.x.com/en/developer-terms/display-requirements.html)和[自动化规则](https://help.twitter.com/en/rules-and-policies/twitter-automation)。除其他内容外，我们的协议和政策还就若干受限使用场景提供了指引。下面我们对其中部分限制提供了更多说明。

<div id="sensitive-information">
  ## 敏感信息
</div>

你在使用 X 数据来推导或推测 X 用户的潜在敏感特征时，应当格外谨慎。切勿针对某个 X 用户，从以下方面进行推导或推测，或存储任何由此推导或推测得出的信息：

* 健康状况（包括怀孕）
* 不利的财务状况或情况
* 政治立场或信仰
* 种族或民族出身
* 宗教或哲学立场或信仰
* 性生活或性取向
* 工会成员身份
* 涉嫌或实际实施的犯罪行为

在不存储任何个人数据（例如用户 id、用户名及其他标识符）的前提下，对 X 内容进行汇总分析是允许的，但同时必须遵守适用法律以及《开发者协议和政策》的所有条款。

<div id="off-x-matching">
  ## 站外匹配
</div>

站外匹配是指将 X 内容（包括 X 用户名或用户 ID）与某个人、家庭、设备、浏览器或其他站外标识符关联起来。比如，将某个 X 用户名与某企业的客户记录关联（即，将你客户记录中的 “John Doe” 与 X 上的 @johndoe 匹配）。

我们希望人们在 X 上能够安心创建一个独立的身份，并且在他们选择的情况下，可以使用化名（pseudonymous）身份。如果你打算将任何关于某个 X 用户的信息与某个站外标识符关联，我们要求你在进行关联之前，必须从该用户处取得其明确的、主动选择（opt-in）同意。例如，如果用户在注册你服务的流程中，直接向你提供了自己的 X 账号（handle），你就可以据此获取该同意。

在你没有取得用户明确、主动选择同意，将其 X 身份与某个站外标识符关联的情况下，我们要求你所作的任何关联，只能基于用户在合理预期范围内会认为可用于该目的的信息。如果用户得知你正在利用他们提供的信息，将其 X 账号与 X 站外的某个身份进行关联时会感到意外，就不要这么做。此外，在缺乏某人的明确主动选择同意时，你只能基于以下信息，尝试将你所掌握的关于某人的记录与某个 X 身份进行匹配：

* **用户直接提供给你的信息。** 对于与你没有任何既有关系的个人的记录（包括从第三方获取的有关个人的数据），不符合这一标准；和/或
* **公开数据。** 在此情境下，“公开数据”是指：
  * 你从某个公共、普遍可访问的资源（例如某专业协会成员名录）中获取的关于某个用户的信息
  * 在 X 上关于某个用户且公开可用的信息，包括：
    * 帖子
    * 个人资料信息，包括用户的简介（bio）和其公开声明的所在地
    * 显示名称和用户名

<div id="redistribution-of-x-content">
  ## X 内容的再分发
</div>

如果你需要将通过 X API 获取的 X 内容与其他方共享，最佳方式是共享 Post ID、Direct Message ID 和/或 User ID，由内容的最终用户使用 X API 对其进行“再水化”（即请求完整的帖子、用户或私信内容）。这样可以帮助确保 X 内容的最终用户始终直接从我们这里获取最新信息。

我们允许通过非自动化方式对已再水化的 X 内容进行有限再分发。如果你选择以这种方式与其他方共享已再水化的 X 内容，你每天针对每个接收方最多只能共享 50,000 个已再水化的公开 Post Object 和/或 User Object，并且不应将这些数据公开可见（例如，作为博客文章的附件或在公开的 Github 仓库中）。

在再分发 X 内容时，还有几点需要牢记：

* 在 30 天内，你最多只能向单一实体分发合计 1,500,000 个 Post ID，除非你事先获得了来自 X 的明确书面许可。
* 代表学术机构、且仅为非商业研究目的再分发 Post ID 和/或 User ID 的个人，可以无限量再分发 Post ID 和/或 User ID。
* 如需按上述方式共享 X 内容的许可，请使用 API Policy 支持表单提交请求。

在你被允许向第三方分发 X 内容的范围内，请注意，这些内容仍然受《开发者协议》和《开发者政策》的约束，并且这些第三方在接收 X 内容之前，必须同意 X 的[服务条款](https://twitter.com/en/tos)、[隐私政策](https://twitter.com/en/privacy)、[开发者协议](/zh/developer-terms/agreement)和[开发者政策](/zh/developer-terms/policy)。

<div id="multiple-applications">
  ## 多个应用程序
</div>

你不得为单一用例，或在本质上相同或相互重叠的用例，注册多个应用程序。你可以在[这里](https://twittercommunity.com/t/policy-clarification-multiple-applications-for-the-same-use-case/92080)详细了解这些政策。

在本政策中，我们将“用例”定义为通过某个应用程序执行的一组固定的分析、展示或操作。向不同终端用户提供同一项服务或同一个应用程序，被视为单一用例；但“白标”版本的工具或服务不包括在内。如果你计划提供应用程序的“白标”版本，必须事先通知我们并获得单独批准。这些规则同时适用于你注册的应用程序，以及由你的工具或服务的终端用户注册的应用程序；如果你要求终端用户为使用你的工具或服务而注册应用程序，我们可能会对你、你的应用程序、你的客户，以及/或你的工具或服务的终端用户采取执法措施。

这一规则的唯一例外，是为同一项服务创建开发（“dev”）、预发布（“staging”）和生产（“prod”）实例。请确保这些应用程序有清晰的标识（例如在应用程序名称或描述中加以说明），并且不要将开发或预发布应用程序用于生产目的。

<div id="automation-spam-and-auto-responses">
  ## 自动化、垃圾信息和自动回复
</div>

禁止使用 X 的 API 和开发者产品来创建垃圾信息，或从事垃圾信息行为。你应当查阅关于垃圾信息的 [X 规则](https://t.co/rules)，并确保你的应用本身不会违反我们的政策，也不会让用户能够违反我们的政策。

如果你的应用将用于在 X 服务上执行写入操作，包括发布帖子、关注账号或发送私信（Direct Messages），你应当仔细阅读[自动化规则](https://support.twitter.com/articles/76915)，以确保你的服务符合我们的指南。尤其是，你应当：

* 在向用户发送[自动回复或自动消息](https://twittercommunity.com/t/policy-clarification-automated-replies-and-mentions/94444)之前，务必获得用户的明确同意
* 立即尊重并执行用户提出的不再被你联系的退订请求
* 切勿执行批量、激进或带有垃圾性质的操作，包括[批量关注](https://twittercommunity.com/t/policy-clarification-aggressive-following-and-inorganic-following-behavior/92769)
* 切勿在[多个账号](https://blog.twitter.com/developer/en_us/topics/tips/2018/automation-and-the-use-of-multiple-accounts.html)上发布完全相同或实质相似的内容

<div id="measuring-the-x-service">
  ## 衡量 X 服务
</div>

不得使用 X API 来衡量 X 的可用性、性能、功能或使用情况，以用于基准测试或竞争分析。例如，你绝不应使用 X API 来：

* 计算 X 用户的聚合指标，例如活跃用户或账号的总数
* 计算 X 帖子的聚合指标，例如每天的帖子总数，或用户互动次数或账号互动次数
* 衡量或分析 X 上的垃圾信息或安全状况，除非在 [X Rules](https://help.twitter.com/en/rules-and-policies/twitter-rules) 中被允许的范围内

<div id="surveillance-privacy-and-user-protection">
  ## 监控、隐私与用户保护
</div>

在 X，保护和捍卫用户隐私已经深深融入公司的核心基因——我们的开发者和数据产品也充分体现了这一承诺。我们相信，X 数据可以成为推动世界向善的强大力量——从在雅加达洪灾期间挽救生命，到帮助美国地质调查局（USGS）追踪地震，再到与联合国合作推动实现可持续发展目标。然而，我们禁止任何实体将 X 数据和 X API 用于监控目的，或以任何其他方式使用而与用户对隐私的合理预期不相符。绝不例外。

我们在[《开发者协议》](/zh/developer-terms/agreement)中描述了对我们数据和开发者产品的禁止使用情形，其中包括禁止调查或追踪 X 用户或其内容，以及禁止对敏感事件（例如抗议、集会或社区组织会议）进行追踪、告警或监控。

在这些条款下，其他被禁止的活动类别包括但不限于：

* 调查或追踪敏感群体和组织，例如工会或行动团体
* 背景审查或任何形式的严苛审查
* 信贷或保险风险分析
* 个体画像或心理特征细分
* 人脸识别

这些政策适用于我们 API 的所有用户。任何将 X API 滥用于上述目的的行为都将面临执法措施，其中可能包括暂停或终止访问权限。

如需了解执法机构索取 X 账户信息的更多说明，请访问 [https://t.co/le](https://t.co/le)。

此外，目前 X 禁止以任何方式使用 X API 和/或 X 内容来微调或训练基础模型或前沿模型，[Grok](https://help.x.com/en/using-x/about-grok) 除外。
