要使用我们的开发者平台，您需要先审阅并同意我们的[开发者协议和政策](/zh/developer-terms/agreement)，以及相关政策，包括[展示要求](https://developer.x.com/en/developer-terms/display-requirements.html)和[自动化规则](https://help.twitter.com/en/rules-and-policies/twitter-automation)。除其他内容外，我们的协议和政策还对若干受限使用场景提供了指导。下面我们就其中一些限制提供更多信息。

<div id="sensitive-information">
  ## 敏感信息
</div>

在使用 X 数据推导或推断 X 用户可能具有的敏感特征时，你应当格外谨慎。绝不要对任何 X 用户推导或推断，或存储经推导或推断得出的以下信息：

* 健康状况（包括怀孕）
* 负面的财务状况或情况
* 政治倾向或信仰
* 种族或民族出身
* 宗教或哲学派别或信仰
* 性生活或性取向
* 工会成员身份
* 涉嫌或实际实施犯罪的情况

在不存储任何个人数据（例如，用户 ID、用户名和其他标识符）的前提下，对 X 内容进行汇总分析是允许的，但前提是该分析还必须遵守适用法律以及《开发者协议与政策》的全部条款。

<div id="off-x-matching">
  ## 站外匹配（Off-X matching）
</div>

站外匹配是指将 X 内容（包括 X 用户名或用户 ID）与某个人、家庭、设备、浏览器或其他 X 站外标识符进行关联的行为。比如，将某个 X 用户名与某家企业的客户记录关联起来（即将客户记录中的 “John Doe” 与 X 上的 @johndoe 匹配）。

我们希望人们在 X 上可以放心地创建一个独立的身份，并且在他们愿意的情况下，可以使用化名身份。如果你打算将关于某个 X 用户的任何信息与某个 X 站外标识符关联，我们要求你在进行关联之前，必须取得该用户的明确、主动（opt-in）同意。例如，如果用户在注册你的服务的过程中，主动向你提供了他们的 X 账号（handle），你就可以在此过程中取得该同意。

在你没有取得用户的明确、主动同意来将其 X 身份与某个 X 站外标识符关联的情况下，我们要求你所建立的任何关联只能基于用户在合理情况下预期会被用于该目的的信息。如果用户得知你正在使用他们提供的信息，将其 X 账号与 X 站外身份关联起来时会感到意外，那就不要这么做。此外，在缺乏某人明确、主动同意的情况下，你只能基于以下信息尝试将你持有的关于某人的记录与某个 X 身份进行匹配：

* **由用户直接提供给你的信息。** 对于与你没有任何既有关系的个人的记录（包括从第三方获取的关于个人的数据信息），并不符合这一标准；和/或
* **公开数据。** 在此语境下，“公开数据”是指：
  * 你从某个公开、普遍可获取的资源中获得的关于某个用户的信息（例如某专业协会的会员名录）
  * X 上关于某个用户的、对公众公开的信息，包括：
    * 帖子
    * 个人资料信息，包括用户的简介以及公开声明的位置
    * 显示名称和用户名

<div id="redistribution-of-x-content">
  ## X 内容的再分发
</div>

如果你需要与其他方分享你通过 X API 获取的 X 内容，最佳方式是分享帖子 ID、私信 ID 和/或用户 ID，由内容的最终用户使用 X API 对其进行还原（即请求完整的帖子、用户或私信内容）。这样有助于确保 X 内容的最终用户始终直接从我们这里获得最新信息。

我们允许通过非自动化方式对已还原的 X 内容进行有限的再分发。如果你选择以这种方式与其他方分享已还原的 X 内容，则你每天、每位接收方最多只能分享 50,000 条已还原的公开帖子对象和/或用户对象，并且不应将这些数据公开提供（例如，作为博客文章的附件或在公共 GitHub 仓库中）。

在再分发 X 内容时，还需注意以下几点：

* 除非事先获得 X 的书面明确许可，否则你在 30 天内向单个实体分发的帖子 ID 总数最多为 1,500,000 条。
* 代表学术机构且仅用于非商业研究目的而再分发帖子 ID 和/或用户 ID 的个人，可以不受限制地再分发任意数量的帖子 ID 和/或用户 ID。
* 如需按上述方式请求分享 X 内容的许可，请使用 API Policy 支持表单。

在你被允许向第三方分发 X 内容的范围内，请注意，此类内容仍受开发者协议和开发者政策约束，且这些第三方在接收 X 内容之前，必须同意 X 的[服务条款](https://twitter.com/en/tos)、[隐私政策](https://twitter.com/en/privacy)、[开发者协议](/zh/developer-terms/agreement)和[开发者政策](/zh/developer-terms/policy)。

<div id="multiple-applications">
  ## 多个应用
</div>

你不得针对单一用例，或针对在实质上相似或重叠的用例，注册多个应用。请在[此处](https://twittercommunity.com/t/policy-clarification-multiple-applications-for-the-same-use-case/92080)详细了解这些政策。

在这里，我们将“用例”定义为：通过某个应用执行的一组一致的分析、展示或操作。向不同的最终用户提供同一项服务或应用被视为单一用例；但“白标”版本的工具或服务不视为同一用例。如果你计划提供应用的“白标”版本，必须事先通知我们并获得单独批准。这些规则同时适用于你注册的应用，以及由你的工具或服务的最终用户注册的应用；如果你要求最终用户为了使用你的工具或服务而注册应用，则可能导致我们对你、你的应用、你的客户和/或你的工具或服务的最终用户采取执法措施。

此规则的唯一例外，是为同一项服务创建开发（“dev”）、预发布（“staging”）和生产（“prod”）实例。请确保这些应用被清晰标注（例如，在应用名称或描述中），并且不要将开发或预发布应用用于生产目的。

<div id="automation-spam-and-auto-responses">
  ## 自动化、垃圾信息和自动回复
</div>

禁止使用 X 的 API 和开发者产品来创建垃圾信息，或从事垃圾式行为。你应当查看关于垃圾信息的 [X 规则](https://t.co/rules)，并确保你的应用本身不违反我们的政策，也不会使用户能够违反我们的政策。

如果你的应用会被用来在 X 服务上执行写操作，包括发布帖子、关注账号或发送私信，你应当认真阅读[自动化规则](https://support.twitter.com/articles/76915)，以确保你的服务符合我们的指南。特别是，你应当：

* 在向用户发送[自动回复或消息](https://twittercommunity.com/t/policy-clarification-automated-replies-and-mentions/94444)之前，始终获得用户的明确同意
* 立即尊重用户选择不再被你联系的请求
* 切勿执行批量、激进或垃圾式操作，包括[批量关注](https://twittercommunity.com/t/policy-clarification-aggressive-following-and-inorganic-following-behavior/92769)
* 切勿在[多个账号](https://blog.twitter.com/developer/en_us/topics/tips/2018/automation-and-the-use-of-multiple-accounts.html)上发布相同或实质相似的内容

<div id="measuring-the-x-service">
  ## 衡量 X 服务
</div>

不得将 X API 用于衡量 X 的可用性、性能、功能或使用情况，以进行基准测试或竞争性分析。例如，绝不应使用 X API 来：

* 计算汇总的 X 用户指标，例如活跃用户或账号的总数
* 计算汇总的 X 帖子指标，例如每日帖子总量，或用户互动次数或账号互动次数
* 衡量或分析 X 上的垃圾信息或安全状况，除非[X 规则](https://help.twitter.com/en/rules-and-policies/twitter-rules)中另有许可

<div id="surveillance-privacy-and-user-protection">
  ## 监控、隐私与用户保护
</div>

在 X，我们将保护和捍卫用户隐私融入公司的核心 DNA——我们的开发者产品和数据产品也体现了这一承诺。我们相信，X 数据可以成为推动世界向善的强大力量——从在雅加达洪水期间拯救生命，到帮助 USGS 追踪地震，再到与联合国合作实现可持续发展目标。然而，我们禁止任何实体将 X 数据和 X API 用于监控目的，或以任何其他方式使用它们，从而违背用户对隐私的合理预期。没有例外。

我们在[开发者协议](/zh/developer-terms/agreement)中描述了对我们数据和开发者产品的禁止用途，包括禁止调查或追踪 X 用户或其内容，以及追踪、预警或监控敏感事件（如抗议、集会或社区组织会议）。

在这些条款下被禁止的其他活动类别包括（但不限于）：

* 调查或追踪敏感群体和组织，例如工会或活动人士团体
* 背景调查或任何形式的严格审查
* 信用或保险风险分析
* 个人画像或心理特征细分
* 人脸识别

这些政策适用于所有使用我们 API 的用户。任何出于上述目的对 X API 的滥用都将面临相应的执行措施，其中可能包括暂停或终止访问权限。

有关执法机构寻求 X 账号相关信息的更多内容，请访问 [https://t.co/le](https://t.co/le)。

此外，目前除 [Grok](https://help.x.com/en/using-x/about-grok) 之外，X 禁止以任何方式使用 X API 和/或 X Content 来微调或训练基础模型或前沿模型。
