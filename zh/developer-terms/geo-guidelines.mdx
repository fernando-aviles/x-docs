<div id="introduction">
  ## 引言
</div>

Posting With Location 是 X API 中的地理标记功能。该功能通过为帖子增加更多上下文信息，帮助为用户提供更有意义的体验。例如，“Fireworks!”（烟花！）如果与某个位置关联，就会更加贴切：“Fireworks!” 来自加利福尼亚州旧金山 SoMa 社区。我们期待与开发者生态中的伙伴合作，围绕此功能打造出色的产品体验！

<div id="user-privacy-and-user-control-of-their-location-information">
  ## 用户隐私以及用户对其位置信息的控制
</div>

为确保良好且安全的体验，开发者在处理用户位置信息时应格外注意用户隐私，并在“附带位置信息发布内容”的体验上提供基本的一致性。以下是一些需要牢记的关键事项，有助于保护用户隐私，并确保用户了解其操作可能带来的影响：

<div id="general-guidelines">
  ## 一般准则
</div>

* 用户必须主动选择开启“带位置的发帖”功能（将位置切换为“开启”）。
* 用户必须明确授权，才可将其精确位置随帖子一同展示。如果你客户端上的位置功能是“持续生效”的（sticky）——即一旦开启位置，之后发布的帖子都会附带位置——你可以只显示地点名称（place&#95;ids），并允许用户在每条帖子基础上，或通过某个单独的替代设置，进一步选择是否附带精确纬度和经度。
* 当你访问用户的位置数据以发布帖子时，除非获得用户的明确许可，你不应在帖子之外存储该信息。
* 必须让用户清楚了解，其帖子将会展示何种级别的位置信息（如果有的话）。你可以采用的一种方式是，在帖子发布之前，通过地图展示这些信息将如何显示。如果在客户端上，用户发布的信息中包含（或唯一包含）精确纬度和经度，则必须明确告知用户其精确坐标将被发布。
* 用户在每次撰写帖子时，都应能够开启或关闭其位置。
* 你必须遵守 X 的[开发者政策](/zh/developer-terms/policy.html)的条款——其中包括如下要求：除作为帖子的一部分外，你不得从 X API 聚合、缓存或存储位置数据和其他地理信息，也不得将此类位置数据或地理信息单独使用。

<div id="specific-examples">
  ## 具体示例
</div>

示例 1：*不添加明确的纬度和经度（这是当前 X Web 客户端 UI 的行为）*

1. 当用户撰写帖子时，显示一个“添加你的位置”的链接；
2. 在后台，调用 X 的 [reverse&#95;geocode](https://developer.x.com/en/docs/geo/places-near-location/api-reference/get-geo-reverse_geocode.html) API，并传入你获取的纬度、经度、定位精度，以及用户首选的位置粒度级别（默认是“街区”）；
3. 显示默认地点的名称（X 会尝试以合理的方式对这些地点进行排序——排序方式使得 X 客户端可以直接显示列表而无需修改）；
4. 允许用户从列表中选择不同的位置（例如从“SoMa, San Francisco”更改为“South Beach, San Francisco”）。
5. 重要提示：如果你将展示精确位置信息，务必对用户保持透明。确保用户清楚是否会显示精确位置信息。
6. 允许用户在每次撰写帖子时选择开启或关闭位置。

示例 2：*已有的地理标记实现*

许多 X 客户端应用实现了最初的地理标记功能（该功能只广播纬度/经度，而不提供 place&#95;ID）。API 的默认行为会模仿这种行为——也就是说，作为开发者，你无需对现有应用进行任何更改即可保持当前的行为。事实上，如果你只向 X 传递一组纬度/经度坐标，X 会自动对该经纬度进行反向地理编码，并在我们有可用数据的地区，将 place&#95;ID 与纬度/经度一起显示。

确保对你的用户透明，说明他们的精确坐标正在被 X 使用并显示。对于现有应用，一个最佳实践是允许用户以每条帖子为单位选择开启或关闭其位置。你也可以让用户启用默认仅共享 place&#95;ID 而非精确坐标，并将其设置为“记住此设置”的持续生效选项。

<div id="x-storage-of-user-location-data">
  ## X 对用户位置信息的存储
</div>

X 将按如下方式存储由客户端传递的数据：

* X 会保存用户选择向其关注者公开展示的所有数据。这类似于 X 存储帖子发布时间戳的方式，也就是说，如果用户在发帖时包含其精确坐标，X 将在该帖子存在期间，把这一精确位置与该帖子一起存储。用户可以按照[此处](https://support.twitter.com/articles/122236-how-to-tweet-with-your-location))所述，在“设置”页面点击“清除我的位置历史”按钮，从其帖子中清除位置信息。

<div id="summary">
  ## 摘要
</div>

从用户角度来看，在帖子中添加位置信息能够极大地丰富上下文并提升其价值。不过，在你的客户端中实现位置功能时，应当谨慎对待隐私与用户透明度，并将其作为设计以位置为核心的产品时的关键考量因素。

如果你对隐私、位置以及其他地理功能有任何问题或意见，请[联系我们](https://support.twitter.com/forms/platform)。
