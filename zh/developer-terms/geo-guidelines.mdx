<div id="introduction">
  ## 简介
</div>

Posting With Location 是 X API 中用于地理标记的功能。该功能通过让帖子更加贴合语境，为用户提供更有意义的体验。例如，将“Fireworks!”（意为“烟花！”）与位置关联后会更有意义：来自加利福尼亚州旧金山 SoMa 街区的“Fireworks!”。我们期待与开发者生态系统合作，围绕这一功能打造出色的体验！

<div id="user-privacy-and-user-control-of-their-location-information">
  ## 用户隐私以及用户对其位置信息的控制
</div>

为确保良好且安全的体验，开发者在处理用户位置信息时应高度重视用户隐私，并在“携带位置信息发帖”的体验中提供基本的一致性。以下是一些需要牢记的关键事项，有助于保护用户隐私并确保用户了解其行为所带来的影响：

<div id="general-guidelines">
  ## 一般性准则
</div>

* 用户必须主动选择使用“带位置发布”功能（将位置设置为“开启”）。
* 用户必须明确授权，才能将其精确位置与帖子一同展示。如果你的客户端中的位置功能是“粘性”的——即一旦位置开启，就会始终附加在帖子上——你可以考虑仅显示地点名称（place&#95;ids），并允许用户按每条帖子分别，或通过单独的设置项，进一步选择是否附加精确的经纬度信息。
* 当你访问用户的位置数据以发布帖子时，除非获得用户的明确许可，否则不得在帖子之外存储该信息。
* 必须让用户清楚了解，其帖子会关联展示何种级别的位置信息（如果有的话）。一种做法是在帖子发布前，通过地图展示这些信息将如何显示。如果用户在客户端上发布的信息中包含精确经纬度（或仅包含精确经纬度），则必须向用户明确说明其精确坐标将会被发布。
* 用户应当能够在每次撰写帖子时开启或关闭位置功能。
* 你必须遵守 X 的[开发者政策](/zh/developer-terms/policy.html)——包括以下要求：除作为帖子的一部分外，你不得从 X API 汇总、缓存或存储位置数据和其他地理信息，也不得将此类位置数据或地理信息作为独立数据加以使用。

<div id="specific-examples">
  ## 具体示例
</div>

示例 1：*不添加显式纬度和经度（这是当前 X Web Client 界面）*

1. 当用户撰写帖子时，显示“添加你的位置信息”的链接；
2. 在后台，使用 X 的 [reverse&#95;geocode](https://developer.x.com/en/docs/geo/places-near-location/api-reference/get-geo-reverse_geocode.html) API 调用，并传递纬度、经度、定位精度以及用户首选的粒度（默认是“neighborhood”）；
3. 显示默认地点的名称（X 会尝试以合理的方式对这些地点排序——排序方式使得 X 客户端可以直接显示该列表，而无需修改）；
4. 允许用户从列表中选择不同的位置（例如，从“SoMa, San Francisco”更改为“South Beach, San Francisco”）。
5. 重要：如果你将显示精确位置信息，请对用户保持透明。确保用户清楚知悉是否会显示精确位置信息。
6. 允许用户在每次撰写帖子时都可以选择开启或关闭位置功能。

示例 2：*已有的地理标记实现*

许多 X 客户端 App 已经实现了最初的地理标记功能（仅广播经纬度，而不提供 place&#95;ID）。API 的默认行为模拟了这种行为——也就是说，作为开发者，你无需对现有 App 做任何更改，就可以维持当前的行为。实际上，如果你仅向 X 传递一个经纬度坐标，X 将自动对该纬度和经度进行反向地理编码，并在我们有可用数据的区域中，除了经纬度外，还显示 place&#95;ID。

请确保清晰告知用户：他们的精确坐标正在被使用并在 X 上显示。对现有 App 的最佳实践是允许用户针对每条帖子开启或关闭其位置信息。你还可以让用户选择仅共享 place&#95;ID 而非精确坐标，并将其设为默认的、可持续生效的设置。

<div id="x-storage-of-user-location-data">
  ## X 对用户位置信息的存储
</div>

X 会按如下方式存储由客户端传递的数据：

* X 会保存所有用户选择公开展示给其关注者的数据。这类似于 X 存储帖子发布时间戳的方式，这意味着如果用户在发帖时附带其精确坐标，X 将在帖子存在期间，把这一精确位置与该帖子一并存储。用户可以按照[此处](https://support.twitter.com/articles/122236-how-to-tweet-with-your-location))所述，在“设置”页面点击“clear my location history”（清除我的位置记录）按钮，从其帖子中清除位置信息。

<div id="summary">
  ## 摘要
</div>

从用户角度来看，为帖子添加位置信息可以提供极其丰富的上下文和价值。不过，在你的 Client 中实现位置功能时，应格外谨慎，将隐私保护和用户知情透明作为设计以位置为重点产品时的关键考量。

如果你对隐私、位置或其他地理位置功能有任何问题或意见，请[联系我们。](https://support.twitter.com/forms/platform)
