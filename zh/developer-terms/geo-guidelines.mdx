<div id="introduction">
  ## 简介
</div>

Posting With Location 是 X API 中的地理标签功能。该功能通过为帖子提供更多上下文信息，帮助为用户带来更有意义的体验。比如，“Fireworks!”（烟花！）在与位置关联时会更加贴切：“Fireworks!” 来自加利福尼亚州旧金山 SoMa 街区。我们期待与开发者生态系统合作，围绕这一功能打造出色的体验！

<div id="user-privacy-and-user-control-of-their-location-information">
  ## 用户隐私与用户对其位置信息的控制
</div>

为确保良好、安全的使用体验，开发者在处理用户位置信息时应充分重视用户隐私，并在“附带位置发布”（Posting with Location）体验中提供基本的一致性。以下是一些需要牢记的关键事项，有助于保护用户隐私，并确保用户理解其行为所带来的影响：

<div id="general-guidelines">
  ## 一般指南
</div>

* 用户必须主动选择加入才能使用“附带位置发布”功能（将位置功能“打开”）。
* 用户必须明确授权，允许在其帖子中显示其精确位置。如果你的客户端中的位置功能具有“粘性”——即一旦位置被打开，它就会始终伴随帖子显示——你可以考虑仅显示地点名称（place&#95;id），并允许用户在每条帖子中或通过单独的设置项，进一步选择是否附加精确的纬度和经度。
* 当你访问用户的位置 data 来发布帖子时，如未经用户明确许可，你不得在帖子本身之外保存该信息。
* 必须让用户清楚了解：其帖子会关联显示何种级别的位置信息（如果有的话）。一种方式是在帖子发布前展示一张地图，说明这些信息将如何显示。如果在客户端上，精确的纬度和经度是用户发布的信息的一部分（或唯一信息），则必须让用户清楚知道其精确坐标将被公开发布。
* 用户在每次撰写帖子时，都应该可以开启或关闭位置功能。
* 你必须遵守 X 的[开发者政策](/zh/developer-terms/policy.html)——其中包括以下要求：除作为帖子的一部分外，你不得从 X API 聚合、缓存或存储位置 data 和其他地理信息，也不得将此类位置 data 或地理信息单独使用。

<div id="specific-examples">
  ## 具体示例
</div>

示例 1：*不添加明确的纬度和经度（这是当前的 X Web 客户端 UI）*

1. 当用户撰写帖子时，显示“添加位置”（Add your location）的链接；
2. 在后台，使用 X 的 [reverse&#95;geocode](https://developer.x.com/en/docs/geo/places-near-location/api-reference/get-geo-reverse_geocode.html) API 调用，并传入定位得到的纬度、经度、定位精度以及用户首选的粒度（默认是“neighborhood”）；
3. 显示默认地点的名称（X 会尝试以合理的方式对这些地点排序——排序方式使得 X 客户端可以直接显示该列表而无需修改）；
4. 允许用户从列表中选择不同的位置（例如将“SoMa, San Francisco”更改为“South Beach, San Francisco”）。
5. 重要提示：如果你将显示精确位置信息，请对用户保持透明。确保用户清楚是否会显示精确位置信息。
6. 允许用户在每次撰写帖子时选择开启或关闭位置信息。

示例 2：*现有地理标记（geotagging）实现*

许多 X 客户端应用已经实现了最初的地理标记功能（只广播纬度/经度，而不提供 place&#95;IDs）。API 的默认行为会模仿这种行为——也就是说，作为开发者，你无需对现有应用进行任何更改即可保持当前的行为。实际上，如果你仅向 X 传递一组纬度/经度坐标，X 会自动对该纬度和经度执行反向地理编码，并在我们有可用 data 的区域中，除了纬度/经度之外，还显示 place&#95;ID。

请确保对你的用户保持透明，明确告知他们的精确坐标正被使用并在 X 上展示。对现有应用而言，一个最佳实践是允许用户按帖子逐条选择开启或关闭位置信息。你也可以让用户只共享 place&#95;IDs 而非精确坐标，并将其设为默认且会被保留的设置。

<div id="x-storage-of-user-location-data">
  ## X 对用户位置数据的存储
</div>

X 将按如下方式存储由客户端传递的数据：

* X 会保存用户选择向其关注者公开展示的所有数据。这与 X 存储帖子发布时间戳的方式类似，这意味着如果用户在发帖时附带其精确坐标，X 将在帖子存在期间，一直把该精确位置与该帖子一同保存。用户可以通过点击设置页面上的“清除我的位置记录”按钮，从其帖子中清除位置信息，如[此处](https://support.twitter.com/articles/122236-how-to-tweet-with-your-location))所述。

<div id="summary">
  ## 摘要
</div>

从用户角度来看，在帖子中添加位置信息可以极大地丰富上下文并提升价值。然而，在你的客户端中实现位置功能时，应格外谨慎，在设计以位置为核心的产品时，将隐私保护和对用户的透明度视为首要考量。

如果你对隐私、位置以及其他地理功能有任何问题或意见，请[联系我们。](https://support.twitter.com/forms/platform)
