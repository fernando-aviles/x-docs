Esta guía cubre los conceptos clave que necesitas para integrar los endpoints de silenciamiento en tu aplicación.

***

<div id="authentication">
  ## Autenticación
</div>

Los endpoints de silenciamiento requieren autenticación de usuario para acceder a listas de silencio privadas:

| Método | Descripción |
|:-------|:------------|
| [OAuth 2.0 Authorization Code with PKCE](/es/resources/fundamentals/authentication#oauth-2-0-authorization-code-flow-with-pkce-2) | Recomendado para aplicaciones nuevas |
| [OAuth 1.0a User Context](/es/resources/fundamentals/authentication) | Compatibilidad heredada |

<Warning>
  La autenticación App-Only no es compatible. Debes autenticarte en nombre de un usuario.
</Warning>

<div id="required-scopes-oauth-20">
  ### Alcances obligatorios (OAuth 2.0)
</div>

| Scope | Obligatorio para |
|:------|:-------------|
| `mute.read` | Obtener cuentas silenciadas |
| `mute.write` | Silenciar y dejar de silenciar cuentas |
| `users.read` | Obligatorio con los alcances de mute |

***

<div id="endpoints-overview">
  ## Descripción general de endpoints
</div>

| Método | Endpoint | Descripción |
|:-------|:---------|:------------|
| GET | `/2/users/:id/muting` | Obtener la lista de cuentas silenciadas |
| POST | `/2/users/:id/muting` | Silenciar una cuenta |
| DELETE | `/2/users/:source_user_id/muting/:target_user_id` | Dejar de silenciar una cuenta |

<div id="example-with-fields">
  ### Ejemplo con campos
</div>

<CodeGroup dropdown>
  ```bash cURL
  curl "https://api.x.com/2/users/123456789/muting?\
  user.fields=username,verified,created_at&\
  max_results=100" \
    -H "Authorization: Bearer $USER_ACCESS_TOKEN"
  ```

  ```python Python SDK
  from xdk import Client

  client = Client(bearer_token="YOUR_USER_ACCESS_TOKEN")

  # Obtener usuarios silenciados con campos adicionales
  for page in client.users.get_muting(
      user_id="123456789",
      user_fields=["username", "verified", "created_at"],
      max_results=100
  ):
      for user in page.data:
          print(f"{user.username} - Verificado: {user.verified}")
  ```

  ```javascript JavaScript SDK
  import { Client } from "@xdevplatform/xdk";

  const client = new Client({ accessToken: "YOUR_USER_ACCESS_TOKEN" });

  const paginator = client.users.getMuting("123456789", {
    userFields: ["username", "verified", "created_at"],
    maxResults: 100,
  });

  for await (const page of paginator) {
    page.data?.forEach((user) => {
      console.log(`${user.username} - Verificado: ${user.verified}`);
    });
  }
  ```
</CodeGroup>

<div id="pagination">
  ## Paginación
</div>

Para usuarios con listas de cuentas silenciadas muy grandes, los resultados se paginan:

<CodeGroup dropdown>
  ```bash cURL
  # Primera solicitud
  curl "https://api.x.com/2/users/123/muting?max_results=100" \
    -H "Authorization: Bearer $USER_ACCESS_TOKEN"

  # Solicitud posterior con token de paginación
  curl "https://api.x.com/2/users/123/muting?max_results=100&pagination_token=NEXT_TOKEN" \
    -H "Authorization: Bearer $USER_ACCESS_TOKEN"
  ```

  ```python Python SDK
  from xdk import Client

  client = Client(bearer_token="YOUR_USER_ACCESS_TOKEN")

  # El SDK se encarga de la paginación automáticamente
  all_muted = []

  for page in client.users.get_muting(user_id="123", max_results=100):
      if page.data:
          all_muted.extend(page.data)

  print(f"Se han silenciado {len(all_muted)} usuarios")
  ```

  ```javascript JavaScript SDK
  import { Client } from "@xdevplatform/xdk";

  const client = new Client({ accessToken: "YOUR_USER_ACCESS_TOKEN" });

  async function getAllMutedUsers(userId) {
    const allMuted = [];

    // El SDK se encarga de la paginación automáticamente
    const paginator = client.users.getMuting(userId, { maxResults: 100 });

    for await (const page of paginator) {
      if (page.data) {
        allMuted.push(...page.data);
      }
    }

    return allMuted;
  }

  // Uso
  const muted = await getAllMutedUsers("123");
  console.log(`Se han silenciado ${muted.length} usuarios`);
  ```
</CodeGroup>

<div id="behavior-differences">
  ## Diferencias en el comportamiento
</div>

<div id="muting-vs-blocking">
  ### Silenciar vs bloquear
</div>

| Característica | Silenciar | Bloquear |
|:--------|:-----|:------|
| Ver sus publicaciones | No (oculto) | No |
| Pueden ver tus publicaciones | Sí | No |
| Pueden seguirte | Sí (pueden seguir) | No (se elimina) |
| Pueden enviarte MD | Sí | No |
| Notificación enviada | No | No |

<Tip>
  Silenciar es una acción privada: el usuario silenciado no recibe ninguna notificación ni puede saber que ha sido silenciado.
</Tip>

<div id="error-handling">
  ## Manejo de errores
</div>

| Status | Error | Solución |
|:-------|:------|:---------|
| 400 | Solicitud no válida | Comprueba el formato del id de usuario |
| 401 | No autorizado | Comprueba el token de acceso |
| 403 | Prohibido | Comprueba los scopes y los permisos |
| 404 | No encontrado | El usuario no existe |
| 429 | Demasiadas solicitudes | Espera y vuelve a intentarlo |
