  ## Comparación de los endpoints de seguimiento de X API
</div>

<div id="follows-lookup">
  ### Búsqueda de seguimientos
</div>

Los endpoints de búsqueda de seguimientos de v2 reemplazarán los endpoints estándar de v1.1 [followers/ids](https://developer.x.com/en/docs/twitter-api/v1/accounts-and-users/follow-search-get-users/api-reference/get-followers-ids), v1.1 [followers/list](https://developer.x.com/en/docs/twitter-api/v1/accounts-and-users/follow-search-get-users/api-reference/get-followers-list), v1.1 [friends/ids](https://developer.x.com/en/docs/twitter-api/v1/accounts-and-users/follow-search-get-users/api-reference/get-friends-ids) y v1.1 [friends/list](https://developer.x.com/en/docs/twitter-api/v1/accounts-and-users/follow-search-get-users/api-reference/get-friends-list).

La siguiente tabla compara los distintos tipos de endpoints de búsqueda de seguimientos:

|     |     |     |
| :--- | :--- | :--- |
| **Description** | **Standard v1.1** | **X API v2** |
| HTTP methods supported | `GET` | `GET` |
| Host domain | `https://api.x.com` | `https://api.x.com` |
| Endpoint path | /1.1/friends/ids.json<br /><br />/1.1/friends/list.json<br /><br />/1.1/followers/ids.json<br /><br />/1.1/followers/list.json | /2/users/:id/following<br /><br />/2/users/:id/followers |
| [Authentication](/es/resources/fundamentals/authentication) | OAuth 1.0a User Context<br /><br />Solo App | OAuth 1.0a User Context<br /><br />OAuth 2.0 Authorization Code with PKCE<br /><br />Solo App |
| Default request [rate limits](/es/resources/fundamentals/rate-limits) | 15 solicitudes por 15 min (por usuario)<br /><br />15 solicitudes por 15 min (por App) | 15 solicitudes por 15 min (por usuario)<br /><br />15 solicitudes por 15 min (por App) |
| Maximum users per response | GET friends/id y GET followers/id devuelven un máximo de 5000 IDs de usuarios por página.<br /><br />  <br /><br />GET friends/list y GET followers/list devuelven un máximo de 200 objetos de usuario por página. | 1000 objetos de usuario por página |
| Pagination | El token se devuelve en un campo next&#95;cursor, que luego se puede pasar como valor al parámetro cursor para devolver la página siguiente de resultados. | El token se devuelve en un campo next&#95;token, que luego se puede pasar como valor al parámetro token para devolver la página siguiente de resultados.<br /><br />El payload de v2 también incluye un campo previous&#95;token, que también se puede pasar con el parámetro pagination&#95;token para devolver la página anterior de resultados. |
| JSON format | Formato estándar de v1.1 | [Formato de X API v2](/es/x-api/fundamentals/data-dictionary) (determinado por los parámetros de solicitud fields y expansions, no es retrocompatible con los formatos de v1.1)<br /><br />Para obtener más información sobre cómo migrar del formato estándar de v1.1 al formato de X API v2, visita nuestra [guía de migración de formatos de datos](/es/x-api/migrate/data-format-migration). |
| Supports selecting which [fields](/es/x-api/fundamentals/data-dictionary) return in the payload |     | ✔   |
| Supports the Post [annotations](/es/x-api/fundamentals/post-annotations) fields |     | ✔   |
| Supports requesting new [metrics](/es/x-api/fundamentals/metrics) fields |     | ✔   |
| Supports the [conversation&#95;id](/es/x-api/fundamentals/conversation-id) field |     | ✔   |
| Requires the use of credentials from a [developer App](/es/resources/fundamentals/developer-apps) associated with a [project](/es/resources/fundamentals/developer-apps) |     | ✔   |

<div id="manage-follows">
  #### Administrar seguimientos
</div>

Los endpoints de la v2 para administrar seguimientos reemplazarán a los endpoints estándar de la v1.1 [POST friendships/create](https://developer.x.com/en/docs/twitter-api/v1/accounts-and-users/follow-search-get-users/api-reference/post-friendships-create) y [POST friendships/destroy](https://developer.x.com/en/docs/twitter-api/v1/accounts-and-users/follow-search-get-users/api-reference/post-friendships-destroy).

Las siguientes tablas comparan los endpoints estándar de la v1.1 y de X API v2 para crear seguimientos:

<div id="follow-a-user">
  #### Seguir a un usuario
</div>

| Descripción | v1.1 estándar | X API v2 |
| :--- | :--- | :--- |
| Métodos HTTP compatibles | POST | POST |
| Dominio del host | https://api.x.com | https://api.x.com |
| Ruta del endpoint | /1.1/friendships/create.json | /2/users/:id/following |
| [Autenticación](/es/resources/fundamentals/authentication) | OAuth 1.0a User Context | OAuth 1.0a User Context<br /><br />OAuth 2.0 Authorization Code with PKCE |
| [Límites de frecuencia de solicitudes](/es/resources/fundamentals/rate-limits) predeterminados | 50 solicitudes por 15 min | 50 solicitudes por 15 min |
| Operaciones máximas diarias por usuario | 400 | 400 |
| Operaciones máximas diarias por App | 1000 | 1000 |
| Requiere el uso de credenciales de una [App de desarrollador](/es/resources/fundamentals/developer-apps) que esté asociada con un [Project](/es/resources/fundamentals/developer-apps) |     | ✔️  |

<div id="unfollow-a-user">
  #### Dejar de seguir a un usuario
</div>

La siguiente tabla compara los endpoints de eliminación de seguimiento de Standard v1.1 y X API v2:

| Descripción | Standard v1.1 | X API v2 |
| :--- | :--- | :--- |
| Métodos HTTP admitidos | POST | DELETE |
| Dominio del host | https://api.x.com | https://api.x.com |
| Ruta del endpoint | /1.1/friendships/destroy.json | /2/users/:source&#95;user&#95;id/following/:target&#95;user&#95;id |
| [Autenticación](/es/resources/fundamentals/authentication) | OAuth 1.0a User Context | OAuth 1.0a User Context<br /><br />OAuth 2.0 Authorization Code with PKCE |
| [Límites de frecuencia](/es/resources/fundamentals/rate-limits) de solicitudes predeterminados | 15 solicitudes por 15 min (por usuario) | 50 solicitudes por 15 min (por usuario) |
| Operaciones diarias máximas por App | Ninguna | 500 |
| Requiere el uso de credenciales de una [developer App](/es/resources/fundamentals/developer-apps) que esté asociada con un [Project](/es/resources/fundamentals/developer-apps) |     | ✔️  |
