Esta guía describe los conceptos clave que necesitas para integrar en tu aplicación los endpoints de consulta de Mensajes Directos.

***

<div id="authentication">
  ## Autenticación
</div>

Los endpoints de mensajes directos requieren autenticación de usuario para acceder a conversaciones privadas:

| Method | Description |
|:-------|:------------|
| [OAuth 2.0 Authorization Code with PKCE](/es/resources/fundamentals/authentication#oauth-2-0-authorization-code-flow-with-pkce-2) | Recomendado |
| [OAuth 1.0a User Context](/es/resources/fundamentals/authentication) | Compatibilidad con versiones anteriores |

<Warning>
  La autenticación de solo aplicación (App-only) no se admite. Todos los mensajes directos son privados.
</Warning>

<div id="required-scopes-oauth-20">
  ### Scopes obligatorios (OAuth 2.0)
</div>

| Scope | Obligatorio para |
|:------|:-----------------|
| `dm.read` | Leer eventos de mensajes directos |
| `tweet.read` | Obligatorio con `dm.read` |
| `users.read` | Obligatorio con `dm.read` |

<div id="event-types">
  ## Tipos de eventos
</div>

| Evento | Descripción | Campos clave |
|:------|:------------|:-----------|
| `MessageCreate` | Se envió un mensaje | `text`, `sender_id` |
| `ParticipantsJoin` | Un usuario se unió al grupo | `participant_ids`, `sender_id` |
| `ParticipantsLeave` | Un usuario abandonó el grupo | `participant_ids` |

<div id="fields-and-expansions">
  ## Campos y expansions
</div>

<div id="default-fields">
  ### Campos predeterminados
</div>

| Tipo de evento | Campos predeterminados |
|:-----------|:---------------|
| MessageCreate | `id`, `event_type`, `text` |
| ParticipantsJoin/Leave | `id`, `event_type`, `participant_ids` |

<div id="available-fields">
  ### Campos disponibles
</div>

| Field | Description | Events |
|:------|:------------|:-------|
| `dm_conversation_id` | ID de la conversación | Todos |
| `created_at` | Marca de tiempo del evento | Todos |
| `sender_id` | Quién envió/invitó | MessageCreate, Join |
| `attachments` | Archivos multimedia adjuntos | MessageCreate |
| `referenced_tweets` | Publicaciones compartidas | MessageCreate |

<div id="available-expansions">
  ### Expansions disponibles
</div>

| Expansión | Devuelve |
|:----------|:--------|
| `sender_id` | Objeto User del remitente |
| `participant_ids` | Objetos User de los participantes |
| `attachments.media_keys` | Objetos Media |
| `referenced_tweets.id` | Objetos Post |

<div id="example-with-expansions">
  ### Ejemplo con expansions
</div>

<CodeGroup dropdown>
  ```bash cURL
  curl "https://api.x.com/2/dm_events?\
  dm_event.fields=created_at,sender_id,attachments&\
  expansions=sender_id,attachments.media_keys&\
  user.fields=username,profile_image_url&\
  media.fields=url,type" \
    -H "Authorization: Bearer $USER_ACCESS_TOKEN"
  ```

  ```python SDK de Python
  from xdk import Client

  client = Client(bearer_token="YOUR_USER_ACCESS_TOKEN")

  # Obtener eventos de MD con expansions
  for page in client.dm_events.list(
      dm_event_fields=["created_at", "sender_id", "attachments"],
      expansions=["sender_id", "attachments.media_keys"],
      user_fields=["username", "profile_image_url"],
      media_fields=["url", "type"],
      max_results=100
  ):
      for event in page.data:
          print(f"Evento: {event.event_type} - {event.text}")
  ```

  ```javascript SDK de JavaScript
  import { Client } from "@xdevplatform/xdk";

  const client = new Client({ accessToken: "YOUR_USER_ACCESS_TOKEN" });

  const paginator = client.dmEvents.list({
    dmEventFields: ["created_at", "sender_id", "attachments"],
    expansions: ["sender_id", "attachments.media_keys"],
    userFields: ["username", "profile_image_url"],
    mediaFields: ["url", "type"],
    maxResults: 100,
  });

  for await (const page of paginator) {
    page.data?.forEach((event) => {
      console.log(`Evento: ${event.event_type} - ${event.text}`);
    });
  }
  ```
</CodeGroup>

<div id="pagination">
  ## Paginación
</div>

Los eventos de MD se devuelven en orden cronológico inverso (los más recientes primero):

<CodeGroup dropdown>
  ```bash cURL
  # Primera solicitud
  curl "https://api.x.com/2/dm_events?max_results=100" \
    -H "Authorization: Bearer $USER_ACCESS_TOKEN"

  # Solicitud posterior con token de paginación
  curl "https://api.x.com/2/dm_events?max_results=100&pagination_token=NEXT_TOKEN" \
    -H "Authorization: Bearer $USER_ACCESS_TOKEN"
  ```

  ```python Python SDK
  from xdk import Client

  client = Client(bearer_token="YOUR_USER_ACCESS_TOKEN")

  # El SDK gestiona la paginación automáticamente
  all_events = []

  for page in client.dm_events.list(max_results=100):
      if page.data:
          all_events.extend(page.data)

  print(f"Se encontraron {len(all_events)} eventos de MD")
  ```

  ```javascript JavaScript SDK
  import { Client } from "@xdevplatform/xdk";

  const client = new Client({ accessToken: "YOUR_USER_ACCESS_TOKEN" });

  async function getAllDMEvents() {
    const allEvents = [];

    // El SDK gestiona la paginación automáticamente
    const paginator = client.dmEvents.list({ maxResults: 100 });

    for await (const page of paginator) {
      if (page.data) {
        allEvents.push(...page.data);
      }
    }

    return allEvents;
  }

  // Uso
  const events = await getAllDMEvents();
  console.log(`Se encontraron ${events.length} eventos de MD`);
  ```
</CodeGroup>

<Note>
  Los eventos de los últimos **30 días** están disponibles.
</Note>

<div id="id-compatibility-with-v11">
  ## Compatibilidad de id con v1.1
</div>

Los id de conversaciones y de eventos son comunes entre los extremos de v1.1 y v2. Esto significa que puedes:

* Usar v2 para obtener eventos y luego usar v1.1 para eliminar mensajes específicos
* Hacer referencia a id de conversación a partir de direcciones URL de x.com en solicitudes de API
