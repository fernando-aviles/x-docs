<div id="authentication">
  ### Autenticación
</div>

Todos los endpoints de X API v2 requieren que autentiques tus solicitudes con un conjunto de credenciales, también conocidas como claves y tokens. Puedes usar OAuth 1.0a User Context, OAuth 2.0 Authorization Code with PKCE o App only para autenticar tus solicitudes para los endpoints de **lookup** de Listas. Sin embargo, debes autenticarte con OAuth 1.0a User Context o OAuth 2.0 para los endpoints de **manage** de Listas.

[OAuth 1.0a User Context](/es/resources/fundamentals/authentication) es un método de autenticación que requiere que utilices un conjunto de API Keys y Access Tokens de usuario para realizar una solicitud correcta. Los Access Tokens deben estar asociados con el usuario en cuyo nombre estás realizando la solicitud. Si deseas generar un conjunto de Access Tokens para otro usuario, ese usuario debe autorizar tu App mediante el [flujo OAuth de 3 patas (3-legged OAuth flow)](/es/resources/fundamentals/authentication#obtaining-access-tokens-using-3-legged-oauth-flow).

Ten en cuenta que OAuth 1.0a puede ser difícil de usar. Si no estás familiarizado con este método de autenticación, te recomendamos que uses una [biblioteca](/es/x-api/tools-and-libraries/overview), utilices una herramienta como Postman o uses OAuth 2.0 o App only para autenticar tus solicitudes.

[OAuth 2.0 Authorization Code with PKCE](/es/resources/fundamentals/authentication#oauth-2-0-authorization-code-flow-with-pkce-2) permite un mayor control sobre el alcance de una aplicación y flujos de autorización entre varios dispositivos. OAuth 2.0 te permite elegir ámbitos específicos y granulares que te otorgan permisos específicos en nombre de un usuario.

Para habilitar OAuth 2.0 en tu App, debes habilitarlo en la configuración de autenticación de tu App que se encuentra en la sección App settings de la Consola de Desarrollador.

[App only](/es/resources/fundamentals/authentication#oauth-2-0) solo requiere que pases un [App only Access Token](/es/resources/fundamentals/authentication#bearer-token-also-known-as-app-only) con tu solicitud. Puedes generar un App only Access Token directamente dentro de una App de desarrollador o generar uno usando el endpoint [POST oauth2/token](/es/resources/fundamentals/authentication#post-oauth2-token).

<div id="developer-console-projects-and-developer-apps">
  ### Consola de Desarrollador, Projects y Apps de desarrollador
</div>

Para obtener un conjunto de credenciales de autenticación que funcionen con los endpoints de X API v2, debes [registrarte para obtener una cuenta de desarrollador](https://developer.x.com/en/portal/petition/essential/basic-info), configurar un [Project](/es/resources/fundamentals/developer-apps) dentro de esa cuenta y crear una [App de desarrollador](/es/resources/fundamentals/developer-apps) dentro de ese Project. Luego podrás encontrar tus claves y tokens en tu App de desarrollador.

<div id="rate-limits">
  ### Límites de frecuencia
</div>

Cada día, muchos miles de desarrolladores realizan solicitudes a la X API. Para ayudar a gestionar el enorme volumen de estas solicitudes, se aplican [límites de frecuencia](/es/x-api/fundamentals/rate-limits) en cada endpoint, que limitan la cantidad de solicitudes que puedes hacer en nombre de tu App o en nombre de un usuario autenticado.

Los endpoints de consulta (GET) tienen límites de frecuencia tanto a nivel de App como a nivel de usuario, mientras que los endpoints de gestión (POST/DELETE) están limitados solo a nivel de usuario. El límite de frecuencia de App significa que tú, como desarrollador, solo puedes realizar una cierta cantidad de solicitudes a este endpoint durante un período de tiempo determinado desde cualquier App determinada (ya sea usando la API Key y la API Secret Key, o el App only Access Token). El límite de frecuencia de usuario significa que el usuario autenticado en cuyo nombre realizas la solicitud solo puede realizar una consulta de Lista una cierta cantidad de veces a través de cualquier App de desarrollador.

La siguiente tabla muestra los límites de frecuencia para cada endpoint.

| Endpoint | Método HTTP | Límite de frecuencia |
| :--- | :--- | :--- |
| /2/lists/:id/members | GET | 900 solicitudes cada 15 minutos |
| /2/users/:id/list&#95;memberships | GET | 75 solicitudes cada 15 minutos |
| /2/lists/:id/members | POST | 300 solicitudes cada 15 minutos |
| /2/lists/:id/members/:user&#95;id | DELETE | 300 solicitudes cada 15 minutos |

<div id="fields-and-expansions">
  ### Campos y expansions
</div>

El endpoint GET de X API v2 permite a los usuarios seleccionar exactamente qué datos quieren que la API devuelva utilizando un conjunto de herramientas llamadas `fields` y `expansions`. El parámetro `expansions` te permite expandir objetos referenciados en la carga útil. Por ejemplo, al consultar miembros de una List puedes obtener las siguientes [expansions](/es/x-api/fundamentals/expansions):

* `pinned_tweet_id`

El parámetro `fields` te permite seleccionar exactamente qué [campos](/es/x-api/fundamentals/fields) dentro de los diferentes objetos de datos deseas recibir. La consulta de miembros de una List entrega principalmente objetos de usuario. De forma predeterminada, el objeto de usuario devuelve los campos id, name y username. Para recibir campos adicionales como `user.created_at` o `user.description`, tendrás que solicitarlos específicamente usando un parámetro user.fields.

Hemos añadido una guía sobre cómo usar [fields y expansions](/es/x-api/fundamentals/data-dictionary#how-to-use-fields-and-expansions).

La tabla siguiente muestra los campos y expansions disponibles para cada endpoint de consulta:

| Endpoint | Campos | Expansions |
| :--- | :--- | :--- |
| /2/lists/:id/members | `user.fields`, `tweet.fields` | `pinned_tweet_id` |
| /2/users/:id/list&#95;memberships | `list.fields`, `user.fields` | `owner_id` |

<div id="pagination">
  ### Paginación
</div>

Consultar membresías o miembros puede devolver una gran cantidad de datos. Para garantizar que devolvemos resultados coherentes y de alto rendimiento en cualquier momento dado, utilizamos paginación. La paginación es una funcionalidad de los endpoints de X API v2 que devuelven más resultados de los que se pueden incluir en una sola respuesta. Cuando eso ocurre, los datos se devuelven en una serie de «páginas». Obtén más información sobre cómo [paginar los resultados.](/es/x-api/fundamentals/pagination)
