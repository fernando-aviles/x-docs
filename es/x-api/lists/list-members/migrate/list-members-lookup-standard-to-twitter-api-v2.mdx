<div id="list-members-lookup-standard-v11-compared-to-x-api-v2">
  ### Consulta de miembros de listas: estándar v1.1 en comparación con X API v2
</div>

Si has estado trabajando con los endpoints estándar v1.1 [GET lists/members](https://developer.x.com/en/docs/twitter-api/v1/accounts-and-users/create-manage-lists/api-reference/get-lists-members) y [GET lists/memberships](https://developer.x.com/en/docs/twitter-api/v1/accounts-and-users/create-manage-lists/api-reference/get-lists-memberships), el objetivo de esta guía es ayudarte a comprender las similitudes y diferencias entre los endpoints de miembros de listas de la versión estándar v1.1 y de X API v2.

* **Similitudes**
  * Métodos de autenticación
* **Diferencias**
  * URLs de los endpoints
  * Límites de frecuencia
  * Requisitos de App y Project
  * Límites de cantidad de objetos de datos por solicitud
  * Formatos de datos de la respuesta
  * Parámetros de la solicitud

<div id="similarities">
  #### Similitudes
</div>

**Autenticación**

Ambas versiones del endpoint admiten tanto [OAuth 1.0a User Context](/es/resources/fundamentals/authentication#oauth-1-0a-2) como [solo aplicación](/es/resources/fundamentals/authentication#oauth-2-0). Por lo tanto, si antes utilizabas uno de los endpoints estándar de miembros de listas de v1.1, puedes seguir usando el mismo método de autenticación si migras a la versión de X API v2.

Según la biblioteca o el paquete de autenticación que elijas, la autenticación de solo aplicación probablemente sea la forma más fácil de empezar y se puede configurar con un encabezado de solicitud sencillo. Para aprender a generar un token de acceso de solo aplicación, consulta [esta guía de solo aplicación](/es/resources/fundamentals/authentication#bearer-token-also-known-as-app-only).

<div id="differences">
  #### Diferencias
</div>

**URL de los endpoints**

* Endpoints estándar v1.1:
  * GET https://api.x.com/1.1/lists/members.json
    (Consulta de miembros de una Lista especificada)
  * GET https://api.x.com/1.1/lists/memberships.json
    (Consulta de las Listas de las que un usuario es miembro)
* Endpoint de X API v2:
  * GET https://api.x.com/2/lists/:id/members
    (Consulta de miembros de una Lista especificada)

  * GET https://api.x.com/2/users/:id/list&#95;memberships
    (Consulta de las Listas de las que un usuario es miembro)

**Límites de frecuencia**

|     |     |
| :--- | :--- |
| **Estándar v1.1** | **X API v2** |
| /1.1/lists/members.json<br /><br />900 solicitudes por ventana de 15 minutos con OAuth 1.0a User Context<br /><br />15 solicitudes por ventana de 15 minutos con solo App | /2/lists/:id/members<br /><br />900 solicitudes por ventana de 15 minutos con OAuth 1.0a User Context<br /><br />900 solicitudes por ventana de 15 minutos con OAuth 2.0 Authorization Code with PKCE<br /><br />900 solicitudes por ventana de 15 minutos con solo App |
| /1.1/lists/memberships.json<br /><br />15 solicitudes por ventana de 15 minutos con OAuth 1.0a User Context<br /><br />15 solicitudes por ventana de 15 minutos con solo App | /2/users/:id/list&#95;memberships<br /><br />15 solicitudes por ventana de 15 minutos con OAuth 1.0a User Context<br /><br />15 solicitudes por ventana de 15 minutos con OAuth 2.0 Authorization Code with PKCE<br /><br />15 solicitudes por ventana de 15 minutos con solo App |

**Requisitos de App y Project**

Los endpoints de X API v2 requieren que utilices credenciales de una [App de desarrollador](/es/resources/fundamentals/developer-apps) que esté asociada con un [Project](/es/resources/fundamentals/developer-apps) al autenticar tus solicitudes. Todos los endpoints de X API v1.1 pueden usar credenciales de Apps o de Apps asociadas con un Project.

**Límites de objetos de datos por solicitud**

El endpoint estándar v1.1 /1.1/lists/members permite devolver hasta 5000 usuarios por solicitud. Los nuevos endpoints v2 permiten devolver hasta 100 usuarios por solicitud. De forma predeterminada, se devolverán 100 objetos de usuario; para cambiar el número de resultados deberás pasar un parámetro de consulta max&#95;results= con un número entre 1 y 100; luego puedes pasar el next&#95;token devuelto en el cuerpo de la respuesta al parámetro de consulta pagination&#95;token en tu siguiente solicitud.

Además, el endpoint /1.1/lists/memberships permite devolver hasta 1000 Listas por solicitud. Con el reemplazo en v2, el endpoint permite hasta 100 Listas por solicitud. De forma predeterminada se devuelven 100 objetos de Lista; usa los parámetros de consulta max&#95;results= y pagination&#95;token del mismo modo que en /1.1/lists/members para cambiar el número de resultados.

**Formato de los datos de la respuesta**

Una de las mayores diferencias entre las versiones de endpoints estándar v1.1 y X API v2 es cómo seleccionas qué campos se devuelven en el cuerpo de tu respuesta.

En los endpoints estándar, recibes muchos de los campos de la respuesta de forma predeterminada y luego tienes la opción de usar parámetros para identificar qué campos adicionales o conjuntos de campos se deben devolver en el cuerpo de la respuesta.

La versión de X API v2 /users/:id/list&#95;memberships entregará los campos id y nombre de la Lista de forma predeterminada. Para solicitar campos u objetos adicionales, deberás usar los parámetros [fields](/es/x-api/fundamentals/fields) y [expansions](/es/x-api/fundamentals/expansions). Cualquier campo de Lista que solicites desde este endpoint se devolverá en el objeto principal de Lista. Cualquier objeto expandido y sus campos se devolverán en un objeto includes dentro de tu respuesta. Luego puedes hacer coincidir cualquier objeto expandido con el objeto principal de Lista haciendo coincidir los id ubicados tanto en el objeto principal como en el objeto expandido. 

A continuación se muestran ejemplos de posibles campos de Lista y expansions:

* created&#95;at

* follower&#95;count

* member&#95;count

* owner&#95;id

* description

* private

|     |     |
| :--- | :--- |
| **Endpoint** | **Expansion** |
| /2/lists/:id/members | pinned&#95;tweet&#95;id |
| /2/users/:id/list&#95;memberships | owner&#95;id |

Te recomendamos leer más sobre estos nuevos parámetros en sus guías correspondientes o consultando nuestra guía sobre [cómo usar campos y expansions](/es/x-api/fundamentals/data-dictionary#how-to-use-fields-and-expansions). 

También hemos preparado una [guía de migración del formato de datos](/es/x-api/migrate/data-format-migration) que puede ayudarte a mapear los campos estándar de la v1.1 a los campos más recientes de la v2. Esta guía también te proporcionará los parámetros específicos de expansión y campos que tendrás que pasar con tu solicitud a v2 para devolver campos concretos. 

Además de los cambios en cómo solicitas ciertos campos, X API v2 también introduce nuevos diseños JSON para los objetos que devuelven las API, incluidos los objetos de [Publicación](/es/x-api/fundamentals/data-dictionary#tweet) y de [usuario](/es/x-api/fundamentals/data-dictionary#user).

* En el nivel raíz de JSON, los endpoints estándar devuelven objetos de Publicación en un array statuses, mientras que X API v2 devuelve un array data. 

* En lugar de hacer referencia a &quot;statuses&quot; de tipo Retweeted y Quoted, el JSON de X API v2 hace referencia a Tuits retuiteados y citados. Muchos campos heredados y obsoletos, como contributors y user.translator&#95;type, se están eliminando. 

* En lugar de usar tanto favorites (en el objeto de Publicación) como favourites (en el objeto de usuario), X API v2 utiliza el término like. 

* X está adoptando la convención de que los valores JSON sin valor (por ejemplo, null) no se escriben en la carga útil. Los atributos de Publicación y de usuario solo se incluyen si tienen valores no nulos.

| owner&#95;id | Sin equivalente |
| count | max&#95;results |
| cursor | pagination&#95;token |
