<div id="authentication">
  ### Autenticación
</div>

Todos los endpoints de X API v2 requieren que autentiques tus solicitudes con un conjunto de credenciales, también conocidas como claves y tokens. Puedes usar OAuth 1.0a User Context para autenticar tus solicitudes a este endpoint.

[OAuth 1.0a User Context](/es/resources/fundamentals/authentication), lo que significa que debes usar un conjunto de claves de API y tokens de acceso de usuario para realizar una solicitud exitosa. Los tokens de acceso deben estar asociados con el usuario en cuyo nombre estás realizando la solicitud. Si deseas generar un conjunto de tokens de acceso para otro usuario, ese usuario debe autorizar tu App utilizando el [flujo OAuth con 3 participantes](https://developer.x.com/resources/fundamentals/authentication/obtaining-user-access-tokens).

Ten en cuenta que OAuth 1.0a puede ser difícil de usar. Si no estás familiarizado con este método de autenticación, te recomendamos que utilices una [biblioteca](/es/x-api/tools-and-libraries/overview) o una herramienta como Postman.

<div id="developer-console-projects-and-developer-apps">
  ### Developer Console, Projects y Apps de desarrollador
</div>

Para obtener un conjunto de credenciales de autenticación que funcionen con los endpoints de X API v2, debes [registrarte para obtener una cuenta de desarrollador](https://developer.x.com/en/portal/petition/essential/basic-info), crear un [Project](/es/resources/fundamentals/developer-apps) dentro de esa cuenta y crear una [App de desarrollador](/es/resources/fundamentals/developer-apps) dentro de ese Project. Luego podrás encontrar tus claves y tokens dentro de tu App de desarrollador.

<div id="rate-limits">
  ### Límites de frecuencia
</div>

Cada día, muchos miles de desarrolladores realizan solicitudes a la X API. Para ayudar a gestionar el enorme volumen de estas solicitudes, se aplican [límites de frecuencia](/es/x-api/fundamentals/rate-limits) en cada endpoint que restringen la cantidad de solicitudes que puedes hacer en nombre de tu aplicación o en nombre de un usuario autenticado.

Estos endpoints tienen límites de frecuencia a nivel de usuario, lo que significa que el usuario autenticado en cuyo nombre realizas la solicitud solo puede invocar el endpoint un número determinado de veces desde cualquier App de desarrollador.

La siguiente tabla muestra los límites de frecuencia para cada endpoint.

| Endpoint | Método HTTP | Límite de frecuencia |
| :--- | :--- | :--- |
| /2/users/:id/pinned&#95;lists | POST | 50 solicitudes cada 15 minutos |
| /2/users/:id/pinned&#95;lists/:list&#95;id | DELETE | 50 solicitudes cada 15 minutos |
| /2/users/:id/pinned&#95;lists | GET | 15 solicitudes cada 15 minutos |

<div id="fields-and-expansions">
  ### Campos y expansiones
</div>

El endpoint GET de X API v2 permite a los usuarios seleccionar exactamente qué datos quieren que se devuelvan desde la API usando un conjunto de herramientas denominado `fields` y `expansions`. El parámetro `expansions` permite expandir los objetos referenciados en el payload. Por ejemplo, consultar listas fijadas (pinned Lists) permite obtener las siguientes [expansions](/es/x-api/fundamentals/expansions):

* `owner_id`

El parámetro `fields` permite seleccionar exactamente qué [campos](/es/x-api/fundamentals/fields) dentro de los diferentes objetos de datos se desean recibir. Este endpoint entrega principalmente objetos de usuario. De forma predeterminada, el objeto List devuelve los campos `id` y `name`. Para recibir campos adicionales como `list.created_at` o `list.description`, tendrás que solicitarlos específicamente usando un parámetro `fields`.

Hemos añadido una guía sobre cómo usar [campos y expansiones](/es/x-api/fundamentals/data-dictionary#how-to-use-fields-and-expansions) juntos en nuestro [diccionario de datos de X API v2](/es/x-api/fundamentals/data-dictionary).

La siguiente tabla muestra los campos y expansiones disponibles para el endpoint de consulta:

| Endpoint | Campos | Expansions |
| :--- | :--- | :--- |
| /2/users/:id/pinned&#95;lists | `list.fields`, `user.fields` | `owner_id` |
