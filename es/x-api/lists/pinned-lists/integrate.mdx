<div id="authentication">
  ### Autenticación
</div>

Todos los endpoints de X API v2 requieren que autentiques tus solicitudes con un conjunto de credenciales, también conocidas como claves y tokens. Puedes usar OAuth 1.0a User Context para autenticar tus solicitudes en este endpoint.

[OAuth 1.0a User Context](/es/resources/fundamentals/authentication), lo que significa que debes usar un conjunto de API Keys y tokens de acceso de usuario para realizar una solicitud correctamente. Los tokens de acceso deben estar asociados con el usuario en cuyo nombre estás realizando la solicitud. Si deseas generar un conjunto de tokens de acceso para otro usuario, este debe autorizar tu aplicación usando el [flujo OAuth de 3 patas](https://developer.x.com/resources/fundamentals/authentication/obtaining-user-access-tokens).

Ten en cuenta que OAuth 1.0a puede ser difícil de usar. Si no estás familiarizado con este método de autenticación, te recomendamos que utilices una [biblioteca](/es/x-api/tools-and-libraries/overview) o una herramienta como Postman.

<div id="developer-console-projects-and-developer-apps">
  ### Consola de Desarrollador, Projects y Apps de desarrollador
</div>

Para obtener un conjunto de credenciales de autenticación que funcionen con los endpoints de X API v2, debes [registrarte para obtener una cuenta de desarrollador](https://developer.x.com/en/portal/petition/essential/basic-info), configurar un [Project](/es/resources/fundamentals/developer-apps) dentro de esa cuenta y crear una [App de desarrollador](/es/resources/fundamentals/developer-apps) dentro de ese Project. Luego podrás encontrar tus claves y tokens dentro de tu App de desarrollador.

<div id="rate-limits">
  ### Límites de frecuencia
</div>

Todos los días, muchos miles de desarrolladores realizan solicitudes a la X API. Para ayudar a gestionar el alto volumen de estas solicitudes, se establecen [límites de frecuencia](/es/x-api/fundamentals/rate-limits) en cada endpoint que limitan la cantidad de solicitudes que puedes realizar en nombre de tu aplicación o en nombre de un usuario autenticado.

Estos endpoints tienen límites de frecuencia a nivel de usuario, lo que significa que el usuario autenticado en cuyo nombre realizas la solicitud solo puede llamar al endpoint un número determinado de veces, independientemente de la App de desarrollador.

La tabla siguiente muestra los límites de frecuencia para cada endpoint.

| Endpoint | Método HTTP | Límite de frecuencia |
| :--- | :--- | :--- |
| /2/users/:id/pinned&#95;lists | POST | 50 solicitudes cada 15 minutos |
| /2/users/:id/pinned&#95;lists/:list&#95;id | DELETE | 50 solicitudes cada 15 minutos |
| /2/users/:id/pinned&#95;lists | GET | 15 solicitudes cada 15 minutos |

<div id="fields-and-expansions">
  ### Campos y expansions
</div>

El endpoint GET de X API v2 permite a los usuarios seleccionar exactamente qué datos quieren obtener de la API utilizando un conjunto de herramientas llamadas `fields` y `expansions`. El parámetro `expansions` te permite expandir los objetos a los que se hace referencia en el payload. Por ejemplo, consultar listas fijadas te permite obtener las siguientes [expansions](/es/x-api/fundamentals/expansions):

* `owner_id`

El parámetro `fields` te permite seleccionar exactamente qué [campos](/es/x-api/fundamentals/fields) dentro de los diferentes objetos de datos deseas recibir. Este endpoint entrega principalmente objetos de usuario. De forma predeterminada, el objeto List devuelve los campos `id` y `name`. Para recibir campos adicionales como `list.created_at` o `list.description`, tendrás que solicitarlos específicamente utilizando un parámetro `fields`.

Hemos añadido a nuestro [diccionario de datos de X API v2](/es/x-api/fundamentals/data-dictionary) una guía sobre cómo usar [fields y expansions](/es/x-api/fundamentals/data-dictionary#how-to-use-fields-and-expansions) juntos.

La siguiente tabla muestra los campos y expansions disponibles para el endpoint de consulta:

| Endpoint | Campos | Expansions |
| :--- | :--- | :--- |
| /2/users/:id/pinned&#95;lists | `list.fields`, `user.fields` | `owner_id` |
