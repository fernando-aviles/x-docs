<div id="authentication">
  ### Autenticación
</div>

Todos los endpoints de X API v2 requieren que autentiques tus solicitudes con un conjunto de credenciales, también conocidas como claves y tokens. Puedes usar OAuth 1.0a User Context, App only u OAuth 2.0 Authorization Code with PKCE para autenticar tus solicitudes a este endpoint.

[OAuth 1.0a User Context](/es/resources/fundamentals/authentication#oauth-1-0a-2), lo que significa que debes usar un conjunto de API Keys y Access Tokens de usuario para realizar una solicitud correcta. Los Access Tokens deben estar asociados con el usuario en cuyo nombre estás realizando la solicitud. Si deseas generar un conjunto de Access Tokens para otro usuario, esa persona debe autorizar tu App usando el [flujo OAuth de 3 participantes](/es/resources/fundamentals/authentication#obtaining-access-tokens-using-3-legged-oauth-flow).

Ten en cuenta que OAuth 1.0a puede ser difícil de usar. Si no estás familiarizado con este método de autenticación, te recomendamos que uses una [biblioteca](/es/x-api/tools-and-libraries/overview), una herramienta como Postman o que uses OAuth 2.0 o App only para autenticar tus solicitudes.

[OAuth 2.0 Authorization Code with PKCE](/es/resources/fundamentals/authentication#oauth-2-0-authorization-code-flow-with-pkce-2) permite un mayor control sobre el alcance (scope) de una aplicación y flujos de autorización en múltiples dispositivos. OAuth 2.0 te permite elegir scopes específicos y detallados que te otorgan permisos concretos en nombre de un usuario.

Para habilitar OAuth 2.0 en tu App, debes habilitarlo en la configuración de autenticación de tu App, que se encuentra en la sección de configuración de la App en el Developer Console.

[App only](/es/resources/fundamentals/authentication#app-only-authentication-and-oauth-2-0-bearer-token) solo requiere que pases un [App only Access Token](/es/resources/fundamentals/authentication#app-only-authentication-and-oauth-2-0-bearer-token) con tu solicitud. Puedes generar un App only Access Token directamente dentro de una App de desarrollador o generar uno usando el endpoint [POST oauth2/token](/es/resources/fundamentals/authentication#post-oauth2-token).

<div id="developer-console-projects-and-developer-apps">
  ### Developer Console, Projects y Apps de desarrollador
</div>

Para obtener un conjunto de credenciales de autenticación compatibles con los endpoints de X API v2, debes [registrarte para obtener una cuenta de desarrollador](https://developer.x.com/en/portal/petition/essential/basic-info), configurar un [Project](/es/resources/fundamentals/developer-apps) dentro de esa cuenta y crear una [App de desarrollador](/es/resources/fundamentals/developer-apps) dentro de ese Project. Luego podrás encontrar tus claves y tokens dentro de tu App de desarrollador.

<div id="rate-limits">
  ### Límites de frecuencia
</div>

Cada día, muchos miles de desarrolladores realizan solicitudes a la X API. Para ayudar a gestionar el gran volumen de estas solicitudes, se establecen [límites de frecuencia](https://developer.x.com/x-api/fundamentals/rate-limits) en cada endpoint que limitan la cantidad de solicitudes que puedes hacer en nombre de tu app o en nombre de un usuario autenticado.

Este endpoint tiene límites de frecuencia tanto a nivel de App como a nivel de usuario. El límite de frecuencia de la App significa que tú, como desarrollador, solo puedes realizar un cierto número de solicitudes a este endpoint durante un período de tiempo determinado desde cualquier App determinada (suponiendo que uses la API Key y la API Secret Key, o el Bearer Token). El límite de frecuencia de usuario significa que el usuario autenticado en cuyo nombre realizas la solicitud solo puede realizar una búsqueda de publicaciones de lista un cierto número de veces a través de cualquier App de desarrollador.

La siguiente tabla muestra los límites de frecuencia para cada endpoint.

| Endpoint | Método HTTP | Límite de frecuencia |
| :--- | :--- | :--- |
| /2/lists/:id/tweets | GET | 900 solicitudes cada 15 minutos |

<div id="fields-and-expansions">
  ### Campos y expansions
</div>

El endpoint GET de X API v2 permite a los usuarios seleccionar exactamente qué datos quieren obtener de la API utilizando un conjunto de parámetros denominados `fields` y `expansions`. El parámetro `expansions` te permite expandir los objetos referenciados en el payload. Por ejemplo, al consultar Publicaciones de Lista puedes obtener las siguientes [expansions](/es/x-api/fundamentals/expansions):

* `author_id`

El parámetro `fields` te permite seleccionar exactamente qué [campos](/es/x-api/fundamentals/fields) dentro de los diferentes objetos de data deseas recibir. Este endpoint entrega principalmente objetos Post. De forma predeterminada, el objeto Post devuelve los campos `id` y `text`. Para recibir campos adicionales como `tweet.created_at` o `tweet.lang`, tendrás que solicitar específicamente esos campos utilizando un parámetro `fields`.

Hemos añadido una guía sobre cómo usar [fields y expansions](/es/x-api/fundamentals/data-dictionary#how-to-use-fields-and-expansions) juntos en nuestro [diccionario de datos de X API v2](/es/x-api/fundamentals/data-dictionary).

La siguiente tabla muestra los campos y expansions disponibles para el endpoint de búsqueda:

| Endpoint | Campos | Expansions |
| :--- | :--- | :--- |
| /2/lists/:id/tweets | `tweet.fields`, `user.fields` | `author_id` |

<div id="pagination">
  ### Paginación
</div>

La consulta de Publicaciones de listas puede devolver una gran cantidad de datos. Para garantizar que devolvemos resultados coherentes y de alto rendimiento en todo momento, usamos paginación. La paginación es una característica de los endpoints de X API v2 que devuelven más resultados de los que se pueden incluir en una sola respuesta. Cuando eso ocurre, los datos se devuelven en una serie de “páginas”. Obtén más información sobre cómo [paginar los resultados.](/es/x-api/fundamentals/pagination)
