<div id="how-webhooks-work">
  ## Cómo funcionan los Webhooks
</div>

```
┌──────────┐      ┌──────────┐      ┌──────────┐
│ X Event  │  →   │ X Server │  →   │ Your     │
│ Occurs   │      │          │      │ Webhook  │
└──────────┘      └──────────┘      └──────────┘
```

1. **Ocurre un evento** — Un usuario publica, envía un DM, etc.
2. **X envía una solicitud** — Solicitud POST a la URL de tu webhook
3. **Tú procesas** — Tu servidor gestiona el evento
4. **Responde con 200** — Devuelve 200 OK para confirmar la recepción

***

<div id="webhook-requirements">
  ## Requisitos del webhook
</div>

| Requisito | Descripción |
|:------------|:------------|
| **HTTPS** | La URL del webhook debe utilizar HTTPS |
| **Pública** | La URL debe ser de acceso público |
| **Respuesta rápida** | Envía una respuesta en un plazo máximo de 10 segundos |
| **200 OK** | Devuelve el estado 200 para confirmar la recepción |

</div>

<div id="challenge-response-check-crc">
  ### Comprobación de desafío-respuesta (CRC)
</div>

X verifica tu webhook enviando una solicitud CRC. Responde con un hash HMAC-SHA256:

```python
import hmac
import hashlib
import base64

def handle_crc(crc_token, consumer_secret):
    sha256_hash = hmac.new(
        consumer_secret.encode(),
        crc_token.encode(),
        hashlib.sha256
    ).digest()
    
    return {
        "response_token": "sha256=" + base64.b64encode(sha256_hash).decode()
    }
```

<div id="signature-verification">
  ### Verificación de la firma
</div>

Verifica la autenticidad del webhook mediante el encabezado `x-twitter-webhooks-signature`.
