<div id="matching-returned-posts-to-their-associated-rule">
  ### Hacer coincidir las Publicaciones devueltas con su regla asociada
</div>

El endpoint de stream filtrado te permite tener múltiples reglas activas a través de una única conexión. Antes de empezar a recibir Publicaciones en tu stream, deberás crear una regla que especifique qué tipos de Publicaciones te interesan. 

Cuando especificas tus reglas para hacer coincidir Publicaciones en función de una amplia variedad de atributos, incluidos atributos de usuario, geolocalización, idioma y muchos otros, puedes adjuntar una etiqueta para distinguir esa regla a un nivel superior. Las etiquetas son una buena forma de contextualizar tu regla, especialmente si tienes muchas reglas configuradas. Las reglas de filtrado determinan qué actividades de las Publicaciones se enviarán a través de la conexión.

Si necesitas añadir una nueva regla de filtrado para capturar un tipo diferente de Publicación, o eliminar una regla existente, tu aplicación puede enviar una solicitud al endpoint [POST tweets/search/stream/rules](/es/x-api/posts/filtered-stream#post-2-tweets-search-stream-rules) para hacerlo. Cuando se envía esa solicitud, las reglas de filtrado se modifican automáticamente y los cambios simplemente surten efecto en el stream de datos sin necesidad de volver a conectarse. La mayoría de las nuevas reglas surten efecto en aproximadamente 20 segundos o menos. Es poco probable, pero dependiendo de factores externos (por ejemplo, la conectividad de red), puede llevar más tiempo antes de que empieces a recibir Publicaciones que coincidan con ellas. Si no puedes encontrar una regla en el endpoint de listado de reglas, asegúrate de que la solicitud de creación de la regla se haya completado correctamente; puedes hacerlo revisando tus registros en busca de cualquier mensaje de error.

<div id="matching-rules">
  #### Reglas de coincidencia
</div>

Cuando se entrega una actividad a través de tu conexión de flujo filtrado, en un array matching&#95;rules se incluye la lista de filtros que coincidieron con la Publicación entregada.

En el payload de la Publicación hay metadatos adicionales de tipo cadena de texto que incluyen el id y la etiqueta de la regla que provocó que se entregara una Publicación específica. Si varias reglas coinciden con una sola Publicación, la actividad se entrega una sola vez con cada una de las reglas coincidentes incluidas en estos metadatos. Las reglas de coincidencia proporcionan una forma sencilla de asociar una Publicación específica con reglas específicas, lo cual es especialmente útil si tienes muchas reglas distintas. Dado que los datos se entregan a través de un único flujo de esta manera, asegurarte de tener un id y una etiqueta únicos es esencial para la coincidencia. 

**A continuación se muestra un ejemplo de cómo aparece el array ”matching&#95;rules” en el payload de la Publicación:**

```"matching_rules": [
    {
      "id": "1166916266197536768",
      "tag": "test-rule-tag-00000"
    },
    {
      "id": "1166916266197536769",
      "tag": "test-rule-tag-12345"
    }
  ]
```

<div id="rule-tags">
  #### Etiquetas de reglas
</div>

En el momento en que se crean, cada regla de filtrado puede definirse con una etiqueta. Las etiquetas de reglas no tienen un significado especial, ya que simplemente se tratan como cadenas de texto opacas asociadas a una regla. Se incluirán en los metadatos `matching_rules` de las actividades devueltas y están pensadas para facilitar la diferenciación de tus reglas a un nivel más alto. 

Las etiquetas proporcionan una forma sencilla de crear agrupaciones lógicas de reglas de filtrado. Por ejemplo, puedes generar un identificador único para una regla específica y usarlo como su etiqueta, y permitir que tu aplicación haga referencia a ese identificador dentro de las actividades que procesa para asociar un resultado con clientes, campañas, categorías u otros grupos relacionados específicos.

Ten en cuenta que las etiquetas no se pueden actualizar en una regla existente y solo se pueden incluir cuando se crea una regla. Para “actualizar” o “cambiar el nombre” de una etiqueta, primero debes eliminar la regla y luego volver a agregarla con la etiqueta deseada. La mejor solución es simplemente utilizar un identificador único como tu etiqueta, que tu sistema pueda asociar con varios otros datos dentro de tu propia aplicación, todo ello sin tener que cambiar nada en el conjunto de reglas.
