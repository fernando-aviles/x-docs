<div id="matching-returned-posts-to-their-associated-rule">
  ### Hacer coincidir las Publicaciones devueltas con su regla asociada
</div>

El endpoint de flujo filtrado te da la capacidad de tener múltiples reglas activas a través de una sola conexión. Antes de empezar a recibir Publicaciones en tu flujo, debes crear una regla que especifique qué tipos de Publicaciones te interesan. 

Cuando especificas tus reglas para hacer coincidir Publicaciones en función de una amplia variedad de atributos, incluidos atributos de usuario, geolocalización, idioma y muchos otros, puedes adjuntar una etiqueta para distinguir esta regla a un nivel superior. Las etiquetas son una buena forma de contextualizar tu regla, especialmente si tienes muchas reglas activas. Las reglas de filtrado determinan qué actividad de las Publicaciones se enviará a través de la conexión.

Si necesitas agregar una nueva regla de filtrado para capturar un tipo diferente de Publicación, o eliminar una regla existente, tu app puede enviar una solicitud al endpoint [POST tweets/search/stream/rules](/es/x-api/posts/filtered-stream#post-2-tweets-search-stream-rules) para hacerlo. Cuando se envía esa solicitud, las reglas de filtrado se modifican automáticamente y los cambios simplemente surten efecto en el flujo de datos sin necesidad de volver a conectarte. La mayoría de las nuevas reglas surten efecto en unos 20 segundos o menos. Es poco probable, pero dependiendo de factores externos (por ejemplo, la conectividad de red), puede llevar más tiempo antes de que empieces a recibir Publicaciones que coincidan con esas reglas. Si no puedes encontrar una regla en el endpoint de listado de reglas, asegúrate de que la solicitud de creación de la regla se haya realizado correctamente; esto se puede verificar revisando tus registros en busca de mensajes de error.

<div id="matching-rules">
  #### Reglas de coincidencia
</div>

Cuando una actividad se entrega a través de tu conexión de flujo filtrado, el payload incluye un array `matching&#95;rules` que indica qué lista de filtros coincidió con la Publicación entregada.

En la carga útil de la Publicación hay metadatos adicionales de tipo cadena que incluyen el id de la regla y la etiqueta que hicieron que se entregara una Publicación específica. Si varias reglas coinciden con una sola Publicación, la actividad se entrega una sola vez con cada una de las reglas coincidentes incluida en estos metadatos. Las reglas de coincidencia ofrecen una forma sencilla de asociar una Publicación específica con reglas específicas, lo que resulta especialmente útil si tienes muchas reglas distintas. Dado que los datos se entregan a través de un único flujo de esta manera, garantizar que dispongas de un id y una etiqueta únicos es esencial para la coincidencia. 

**Aquí tienes un ejemplo de cómo aparece el array `matching&#95;rules` en la carga útil de la Publicación:**

```"matching_rules": [
    {
      "id": "1166916266197536768",
      "tag": "test-rule-tag-00000"
    },
    {
      "id": "1166916266197536769",
      "tag": "test-rule-tag-12345"
    }
  ]
```

<div id="rule-tags">
  #### Etiquetas de reglas
</div>

En el momento de su creación, cada regla de filtrado puede crearse con una etiqueta. Las etiquetas de reglas no tienen un significado especial, ya que simplemente se tratan como cadenas de texto opacas asociadas a una regla. Se incluirán en los metadatos de matching&#95;rules en las actividades devueltas y están pensadas para facilitar la distinción entre tus reglas a un nivel más alto. 

Las etiquetas proporcionan una forma sencilla de crear agrupaciones lógicas de reglas de filtrado. Por ejemplo, puedes generar un ID único para una regla específica como su etiqueta y permitir que tu App haga referencia a ese ID dentro de las actividades que procesa para asociar un resultado con clientes, campañas, categorías u otros grupos relacionados específicos.

Ten en cuenta que las etiquetas no se pueden actualizar en una regla existente y solo se pueden incluir cuando se crea una regla. Para “actualizar” o “renombrar” una etiqueta, primero debes eliminar la regla y luego volver a agregarla con la etiqueta deseada. La mejor solución es simplemente usar un identificador único como tu etiqueta, que tu sistema pueda asociar con varios otros puntos de datos dentro de tu propia App, todo sin tener que cambiar nada en el conjunto de reglas.
