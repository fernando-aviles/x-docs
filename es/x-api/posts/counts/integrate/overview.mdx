<div id="key-concepts">
  ## Conceptos clave
</div>

<div id="authentication">
  ### Autenticación
</div>

Todos los endpoints de X API v2 requieren que las solicitudes estén [autenticadas](/es/resources/fundamentals/authentication) con un conjunto de credenciales, también conocidas como claves y tokens. Este endpoint específico requiere el uso de [OAuth 2.0 Bearer Token](/es/resources/fundamentals/authentication#oauth-2-0), lo que significa que debes pasar un [Bearer Token](/es/resources/fundamentals/authentication#bearer-token-also-known-as-app-only) para realizar una solicitud exitosa. Puedes generar un Bearer Token directamente en una App de desarrollador o generar uno usando el endpoint [POST oauth2/token](/es/resources/fundamentals/authentication#post-oauth2-token).

<div id="developer-console-projects-and-developer-apps">
  ### Consola de Desarrollador, Projects y Apps de desarrollador
</div>

Para trabajar con cualquier endpoint de X API v2, debes tener una [cuenta de desarrollador](/es/resources/fundamentals/developer-portal), configurar un [Project](/es/resources/fundamentals/developer-apps) dentro de esa cuenta y crear una [App de desarrollador](/es/resources/fundamentals/developer-apps) dentro de ese Project. Tus claves y tokens dentro de esa App de desarrollador funcionarán con los endpoints de conteo de Publicaciones recientes. Si deseas usar el endpoint de conteo de Publicaciones del archivo completo o utilizar los operadores avanzados y consultas más largas, deberás haber sido aprobado para acceso empresarial.

Visita nuestra sección sobre acceso empresarial para obtener más información.

<div id="rate-limits">
  ### Límites de frecuencia
</div>

Cada día, muchos miles de desarrolladores realizan solicitudes a la X API. Para ayudar a gestionar el volumen, se establecen [límites de frecuencia](/es/x-api/fundamentals/rate-limits) en cada endpoint que limitan la cantidad de solicitudes que cada desarrollador puede realizar en nombre de una app o en nombre de un usuario autenticado.

Este endpoint tiene límites de frecuencia a nivel de aplicación (App), lo que significa que tú, como desarrollador, solo puedes realizar una cierta cantidad de solicitudes a este endpoint durante un período de tiempo determinado desde cualquier App (según las credenciales que estés utilizando).

<div id="building-queries">
  ### Creación de consultas
</div>

La característica central de estos endpoints es el uso de una sola consulta para filtrar las Publicaciones en los recuentos que recibes. Estas consultas están formadas por operadores que coinciden con atributos de la Publicación y del usuario, como palabras clave del mensaje, hashtags y URL. Los operadores se pueden combinar en consultas con lógica booleana y paréntesis para ayudar a refinar el comportamiento de coincidencia de la consulta.

Puedes usar nuestra guía sobre [cómo crear una consulta](/es/x-api/posts/counts/integrate/build-a-query) para obtener más información.

<div id="pagination">
  ### Paginación
</div>

Para los recuentos recientes de Publicaciones, no se devuelve ningún next&#95;token, lo que significa que, independientemente de la granularidad, recibirás el volumen de Publicaciones de los últimos 7 días en una sola llamada a la API.

Para los recuentos de Publicaciones del archivo completo, recibirás data de los últimos 30 días. Para data de más de 30 días, recibirás un next&#95;token que luego puedes usar para paginar y obtener la data adicional.
