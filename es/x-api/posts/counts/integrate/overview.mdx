<div id="key-concepts">
  ## Conceptos clave
</div>

<div id="authentication">
  ### Autenticación
</div>

Todos los endpoints de X API v2 requieren que las solicitudes estén [autenticadas](/es/resources/fundamentals/authentication) con un conjunto de credenciales, también conocidas como claves y tokens. Este endpoint en concreto requiere el uso de [OAuth 2.0 Bearer Token](/es/resources/fundamentals/authentication#oauth-2-0), lo que significa que debes pasar un [Bearer Token](/es/resources/fundamentals/authentication#bearer-token-also-known-as-app-only) para realizar una solicitud exitosa. Puedes generar un Bearer Token directamente en una App de desarrollador o generar uno usando el endpoint [POST oauth2/token](/es/resources/fundamentals/authentication#post-oauth2-token).

<div id="developer-console-projects-and-developer-apps">
  ### Consola de desarrollador, Proyectos y Apps de desarrollador
</div>

Para trabajar con cualquier endpoint de X API v2, debes tener una [cuenta de desarrollador](/es/resources/fundamentals/developer-portal), configurar un [Proyecto](/es/resources/fundamentals/developer-apps) dentro de esa cuenta y crear una [App de desarrollador](/es/resources/fundamentals/developer-apps) dentro de ese Proyecto. Tus claves y tokens dentro de esa App de desarrollador funcionarán para los endpoints de conteo de Publicaciones recientes. Si deseas utilizar el endpoint de conteo de Publicaciones del archivo completo o aprovechar los operadores avanzados y una longitud de consulta mayor, deberás haber sido aprobado para el acceso empresarial.

Visita nuestra sección sobre acceso empresarial para obtener más información.

<div id="rate-limits">
  ### Límites de tasa
</div>

Cada día, muchos miles de desarrolladores realizan solicitudes a la X API. Para ayudar a gestionar el volumen, se aplican [límites de tasa](/es/x-api/fundamentals/rate-limits) a cada endpoint, lo que limita la cantidad de solicitudes que cada desarrollador puede hacer en nombre de una App o de un usuario autenticado.

Este endpoint está sujeto a límites de tasa a nivel de App, lo que significa que tú, como desarrollador, solo puedes hacer una cierta cantidad de solicitudes a este endpoint durante un período de tiempo determinado desde cualquier App (según las credenciales que estés utilizando).

<div id="building-queries">
  ### Creación de consultas
</div>

La característica central de estos endpoints es el uso de una sola consulta para filtrar las Publicaciones y obtener los conteos que se te devuelven. Estas consultas se componen de operadores que buscan coincidencias en atributos de la Publicación y del usuario, como palabras clave del mensaje, hashtags y URLs. Los operadores se pueden combinar en consultas con lógica booleana y paréntesis para ayudar a refinar cómo la consulta realiza las coincidencias.

Puedes consultar nuestra guía sobre [cómo crear una consulta](/es/x-api/posts/counts/integrate/build-a-query) para obtener más información.

<div id="pagination">
  ### Paginación
</div>

Para recuentos recientes de Publicaciones, no se devuelve ningún next&#95;token, lo que significa que, independientemente de la granularidad, obtendrás el volumen de Publicaciones de los últimos 7 días en una sola llamada a la API.

Para recuentos de Publicaciones de archivo completo, obtendrás datos de los últimos 30 días. Para datos anteriores a esos 30 días, obtendrás un next&#95;token que luego podrás usar para paginar y obtener los datos adicionales.
