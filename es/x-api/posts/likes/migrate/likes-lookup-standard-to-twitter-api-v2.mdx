<div id="likes-lookup-standard-v11-compared-to-x-api-v2">
  ### Búsqueda de Me gusta: v1.1 estándar en comparación con X API v2
</div>

Si has estado trabajando con el endpoint v1.1 estándar [GET favorites/list](https://developer.x.com/en/docs/x-api/v1/tweets/post-and-engage/api-reference/get-favorites-list), el objetivo de esta guía es ayudarte a comprender las similitudes y diferencias entre los endpoints de búsqueda de Me gusta de la v1.1 estándar y de X API v2.

Con v2, también hemos introducido un nuevo endpoint de usuarios a los que les gusta, que te permite obtener información sobre los usuarios a los que les ha gustado una Publicación.

* **Similitudes**
  * Autenticación
  * Límites de frecuencia (rate limits)
* **Diferencias**
  * URLs de endpoint

  * Limitaciones de las solicitudes

  * Requisitos de App y Project

  * Parámetros de las solicitudes

  * Nuevo formato JSON

<div id="similarities">
  #### Similitudes
</div>

**Autenticación**

Tanto los endpoints Likes lookup de la versión estándar v1.1 como los de X API v2 usan [OAuth 1.0a User Context](/es/resources/fundamentals/authentication#oauth-1-0a-2) o [OAuth 2.0 Bearer Token](/es/resources/fundamentals/authentication#bearer-token-also-known-as-app-only). Por lo tanto, si anteriormente estabas usando los endpoints estándar v1.1 [GET favorites/list endpoints](https://developer.x.com/en/docs/x-api/v1/tweets/post-and-engage/api-reference/get-favorites-list), puedes seguir utilizando el mismo método de autenticación si migras a la versión de X API v2, si así lo deseas. 

Según la biblioteca o paquete de autenticación que elijas, la autenticación mediante Bearer Token probablemente sea la forma más sencilla de comenzar y se puede configurar con un encabezado de solicitud sencillo. Para aprender cómo generar un Bearer Token, consulta [esta guía de OAuth 2.0 Bearer Token](/es/resources/fundamentals/authentication#bearer-token-also-known-as-app-only). 
 

**Límites de frecuencia**

El endpoint estándar v1.1 GET favorites/list tiene un límite de frecuencia de 75 solicitudes por 15 minutos por usuario. El endpoint correspondiente de publicaciones marcadas con &quot;Me gusta&quot; en v2 también tiene este mismo límite de frecuencia. Sin embargo, este endpoint de v2 también tiene un límite de frecuencia adicional de 75 solicitudes por 15 minutos por App.

<div id="differences">
  #### Diferencias
</div>

**URLs de los endpoints**

* Endpoints estándar v1.1:
  * GET https://api.x.com/1.1/favorites/list.json
    (lista de Publicaciones que son del usuario especificado)
  * No hay un equivalente en v1.1 para el endpoint de usuarios que indican Me gusta en v2
* Endpoint de X API v2:
  * GET https://api.x.com/2/users/:id/liked&#95;tweets
    (lista de Publicaciones que el ID de usuario especificado ha marcado con Me gusta)
  * GET https://api.x.com/2/tweets/:id/liking&#95;users
    (lista de usuarios que han marcado con Me gusta la Publicación con el ID especificado)

**Limitaciones de la solicitud**

El endpoint de Publicaciones con Me gusta en v2 te permite solicitar entre 5 y 100 Publicaciones por solicitud, pero puedes solicitar todos los Me gusta de una Publicación usando tokens de paginación. El endpoint v1.1 GET favorites/list también te permite extraer todos los Me gusta de Publicaciones, pero puedes extraer entre 20 y 200 Publicaciones por solicitud.

Para el endpoint de usuarios que indican Me gusta en v2, estás limitado a 100 usuarios que indican Me gusta por Publicación. 
 

**Requisitos de App y Project**

Los endpoints de X API v2 requieren que uses credenciales de una [developer App](/es/resources/fundamentals/developer-apps) que esté asociada con un [Project](/es/resources/fundamentals/developer-apps) al autenticar tus solicitudes. Todos los endpoints de X API v1.1 pueden usar credenciales de Apps o de Apps asociadas con un Project.

**Parámetros de la solicitud**

Los siguientes parámetros de solicitud estándar de v1.1 aceptaban dos parámetros de consulta (user&#95;id o screen&#95;name). X API v2 solo acepta el ID numérico de usuario, y debe pasarse como parte de la ruta del endpoint.

Una de las mayores diferencias entre las versiones de endpoints estándar v1.1 y X API v2 es cómo seleccionas qué campos se devuelven en tu carga útil. Para los endpoints estándar, había varios parámetros que podías usar para identificar qué campos o conjuntos de campos se devolverían en la carga útil, mientras que la versión de X API v2 simplifica estos distintos parámetros en [fields](/es/x-api/fundamentals/fields) y [expansions](/es/x-api/fundamentals/expansions). 
 

**Nuevo formato JSON**

X API v2 está introduciendo nuevos diseños JSON para los objetos devueltos por las API, incluidos los objetos de [Post](/es/x-api/fundamentals/data-dictionary#tweet) y de [user](/es/x-api/fundamentals/data-dictionary#user).

* En el nivel raíz de JSON, los endpoints estándar devuelven objetos de usuario en un array statuses, mientras que X API v2 devuelve un array data. 
* En lugar de hacer referencia a &quot;statuses&quot; retuiteados y citados, el JSON de X API v2 se refiere a Tuits retuiteados y citados. Muchos campos heredados y obsoletos, como contributors y user.translator&#95;type, se están eliminando. 
* En lugar de usar tanto favorites (en el objeto Post) como favourites (en el objeto user), X API v2 usa el término like. 
* X está adoptando la convención de que los valores JSON sin valor (por ejemplo, null) no se escriben en la carga útil. Los atributos de Post y user solo se incluyen si tienen valores distintos de null.
   

Además de los cambios que hicimos en nuestro nuevo formato JSON, también introdujimos un nuevo conjunto de campos en el objeto Post, incluidos los siguientes:

* [conversation&#95;id](/es/x-api/fundamentals/conversation-id)
* Dos nuevos campos de [Post annotations](/es/x-api/fundamentals/post-annotations), incluidos context y entities
* Varios nuevos campos de [metrics](/es/x-api/fundamentals/metrics)

<div id="get-liked-posts-v2">
  ### Obtener publicaciones con Me gusta (v2)
</div>

<CodeGroup dropdown>
  ```bash cURL
  curl "https://api.x.com/2/users/2244994945/liked_tweets?tweet.fields=created_at,public_metrics&max_results=100" \
    -H "Authorization: Bearer $BEARER_TOKEN"
  ```

  ```python Python
  import requests

  bearer_token = "YOUR_BEARER_TOKEN"
  url = "https://api.x.com/2/users/2244994945/liked_tweets"

  params = {
      "tweet.fields": "created_at,public_metrics",
      "max_results": 100
  }

  headers = {"Authorization": f"Bearer {bearer_token}"}
  response = requests.get(url, headers=headers, params=params)

  print(response.json())
  ```

  ```python Python SDK
  from xdk import Client

  client = Client(bearer_token="YOUR_BEARER_TOKEN")

  # Obtener las publicaciones a las que un usuario dio Me gusta
  for page in client.posts.get_liked_posts(
      "2244994945",
      tweet_fields=["created_at", "public_metrics"],
      max_results=100
  ):
      for post in page.data:
          print(f"{post.text[:50]}... - Me gusta: {post.public_metrics.like_count}")
  ```

  ```javascript JavaScript SDK
  import { Client } from "@xdevplatform/xdk";

  const client = new Client({ bearerToken: "YOUR_BEARER_TOKEN" });

  // Obtener las publicaciones a las que un usuario dio Me gusta
  const paginator = client.posts.getLikedPosts("2244994945", {
    tweetFields: ["created_at", "public_metrics"],
    maxResults: 100,
  });

  for await (const page of paginator) {
    page.data?.forEach((post) => {
      console.log(`${post.text?.slice(0, 50)}... - Me gusta: ${post.public_metrics?.like_count}`);
    });
  }
  ```
</CodeGroup>

<div id="get-liking-users-v2">
  ### Obtener usuarios que dieron Me gusta (v2)
</div>

<CodeGroup dropdown>
  ```bash cURL
  curl "https://api.x.com/2/tweets/1234567890/liking_users?user.fields=username,verified" \
    -H "Authorization: Bearer $BEARER_TOKEN"
  ```

  ```python Python
  import requests

  bearer_token = "YOUR_BEARER_TOKEN"
  url = "https://api.x.com/2/tweets/1234567890/liking_users"

  params = {"user.fields": "username,verified"}

  headers = {"Authorization": f"Bearer {bearer_token}"}
  response = requests.get(url, headers=headers, params=params)

  print(response.json())
  ```

  ```python Python SDK
  from xdk import Client

  client = Client(bearer_token="YOUR_BEARER_TOKEN")

  # Obtener usuarios que dieron Me gusta a una Publicación
  response = client.posts.get_liking_users(
      "1234567890",
      user_fields=["username", "verified"]
  )
  for user in response.data:
      print(f"{user.username} - Verified: {user.verified}")
  ```

  ```javascript JavaScript SDK
  import { Client } from "@xdevplatform/xdk";

  const client = new Client({ bearerToken: "YOUR_BEARER_TOKEN" });

  // Obtener usuarios que dieron Me gusta a una Publicación
  const response = await client.posts.getLikingUsers("1234567890", {
    userFields: ["username", "verified"],
  });

  response.data?.forEach((user) => {
    console.log(`${user.username} - Verified: ${user.verified}`);
  });
  ```
</CodeGroup>
