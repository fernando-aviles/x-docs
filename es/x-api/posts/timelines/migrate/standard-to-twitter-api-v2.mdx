<div id="standard-v11-timelines-to-x-api-v2-timelines">
  ## Cronologías estándar v1.1 a cronologías de X API v2
</div>

Si has estado trabajando con los endpoints de cronologías v1.1 (statuses/user&#95;timeline y statuses/mentions&#95;timeline), el objetivo de esta guía es ayudarte a entender las similitudes y diferencias entre los endpoints de cronologías estándar y de X API v2, de modo que puedas migrar tu integración actual a la nueva versión.

* **Similitudes:**
  * Autenticación:
    * OAuth 1.0a User Context (cronología de inicio en orden cronológico inverso, cronología de Publicaciones del usuario y cronología de menciones del usuario)
    * OAuth 2.0 App-Only (cronología de Publicaciones del usuario)
  * Límite de acceso histórico: la cronología del usuario (cronología de Publicaciones del usuario) proporciona acceso a las 3200 Publicaciones más recientes; la cronología de menciones (cronología de menciones del usuario) proporciona acceso a las 800 menciones más recientes.
  * Compatibilidad con el historial de edición de Publicaciones y metadatos
  * Límites de frecuencia (cronología de Publicaciones del usuario)
  * Sondeo de actualización: capacidad de recuperar nuevos resultados a partir de since&#95;id
  * Recorrido de cronologías por ID de Publicación
  * Especificaciones de resultados:
    * Orden de resultados: resultados devueltos en orden cronológico inverso
    * Posibilidad de excluir respuestas (solo cronología de Publicaciones del usuario)
    * Posibilidad de excluir Retuits (solo cronología de Publicaciones del usuario)
* **Diferencias**
  * Nueva capacidad de autenticación:
    * OAuth 2.0 App-Only (cronología de menciones del usuario)
    * OAuth 2.0 Authorization Code Flow with PKCE (cronología de inicio en orden cronológico inverso, cronología de Publicaciones del usuario y cronología de menciones del usuario)
  * Requisitos de acceso: requisitos de App y Project de X API v2
  * Límites de frecuencia (cronología de menciones del usuario y cronología de inicio en orden cronológico inverso)
  * Método adicional de paginación
    * Diferente valor de max&#95;results (count) por respuesta
  * Formato de datos de la respuesta
  * Parámetros de la solicitud
    * Formato de datos personalizado según los parámetros de la solicitud, incluidos los campos v2 y expansions
    * Datos adicionales disponibles: métricas, anotaciones de Publicaciones, encuestas

<div id="similarities">
  ### Similitudes
</div>

**Autenticación**

El endpoint v1.1 statuses/user&#95;timeline y el endpoint de cronología de publicaciones de usuario de X API v2 admiten tanto [OAuth 1.0a User Context](/es/resources/fundamentals/authentication) como [OAuth 2.0 App-Only](/es/resources/fundamentals/authentication#bearer-token-also-known-as-app-only). Por lo tanto, puedes seguir usando el mismo método de autenticación y los mismos tokens de autorización si migras a la versión de X API v2.

**Acceso histórico**

El endpoint v1.1 statuses/user&#95;timeline y el endpoint de cronología de publicaciones de usuario de X API v2 devuelven ambos las 3200 publicaciones más recientes, incluidos los Retweets.

El endpoint v1.1 statuses/mentions&#95;timeline y el endpoint de cronología de menciones de usuario de X API v2 pueden devolver las 800 publicaciones más recientes.

**Compatibilidad con el historial de edición de publicaciones y metadatos**

Ambas versiones proporcionan metadatos que describen cualquier historial de edición. Consulta las [Referencias de la API de flujo filtrado](/es/x-api/posts/filtered-stream#api-reference-index) y la [página de fundamentos de edición de publicaciones](/es/x-api/fundamentals/edit-posts) para más detalles.

**Límites de frecuencia**

|     |     |
| :--- | :--- |
| **Estándar v1.1** | **X API v2** |
| user&#95;timeline:<br /><br />900 solicitudes por ventana de 15 minutos con OAuth 1.0a User Context<br /><br />1500 solicitudes por ventana de 15 minutos con OAuth 2.0 App-Only | Cronología de publicaciones de usuario:<br /><br />900 solicitudes por ventana de 15 minutos con OAuth 1.0a User Context<br /><br />1500 solicitudes por ventana de 15 minutos con OAuth 2.0 App-Only |

**Sondeo de actualización usando since&#95;id**

Ambas versiones permiten hacer sondeo para obtener resultados recientes usando since&#95;id.

**Recorrido de cronologías por ID de publicación**

Ambos endpoints tienen la capacidad de recorrer cronologías usando las “marcas de tiempo” de ID de publicación, basadas en la forma en que se construyen las ID de las publicaciones. La funcionalidad es, en general, la misma salvo por lo siguiente:

|     |     |
| :--- | :--- |
| **Cronologías estándar v1.1** | **Cronologías v2** |
| since&#95;id (exclusivo)<br /><br />max&#95;id (incluido) | since&#95;id (exclusivo)<br /><br />until&#95;id (también exclusivo, frente a max&#95;id, que era incluido) |

**Parámetros de filtrado de respuesta**

|     |     |
| :--- | :--- |
| **Cronologías estándar v1.1** | **Cronologías v2** |
| Parámetros de filtrado de respuesta:<br /><br />* include&#95;rts<br />* exclude&#95;replies | Parámetros de filtrado de respuesta:<br /><br />* exclude=retweets,replies |
| Ejemplo <br /><br />https://api.x.com/1.1/statuses/user&#95;timeline.json?user&#95;id=2244994945&amp;include&#95;rts=0&amp;&amp;exclude&#95;replies=1 | Ejemplo:<br /><br />https://api.x.com/2/users/2244994945/tweets?max&#95;results=100&amp;exclude=retweets,replies |
| Notas:<br /><br />Para user&#95;timeline:<br /><br />* Usar include&#95;rts=0 no cambia el posible límite histórico de publicaciones de las 3200 más recientes | Notas:<br /><br />Para la cronología de publicaciones de usuario:<br /><br />* Usar exclude=retweets no cambia el posible límite histórico de publicaciones de las 3200 más recientes <br />* Usar exclude=replies reduce el posible límite histórico de publicaciones a las 800 respuestas más recientes |

<div id="differences">
  ### Diferencias
</div>

**Autenticación**

**El endpoint v1.1 statuses/mentions&#95;timeline solo admite [OAuth 1.0a User Context](https://developer-staging.x.com/resources/fundamentals/authentication). El endpoint de cronología de menciones de usuario de X API v2 admite [OAuth 1.0a User Context](/es/resources/fundamentals/authentication), [OAuth 2.0 App-Only](/es/resources/fundamentals/authentication#bearer-token-also-known-as-app-only) y [OAuth 2.0 Authorization Code with PKCE](/es/resources/fundamentals/authenticationoauth-2-0/authorization-code "Este método permite que una app autorizada actúe en nombre del usuario, como si fuera el usuario. Normalmente se utiliza para acceder o publicar información pública de un usuario específico, y es útil cuando tu app necesita conocer la relación entre un usuario y lo que devuelve este endpoint. Haz clic para aprender cómo autenticarte con OAuth 2.0 Authorization Code with PKCE.")**

Si deseas aprovechar la capacidad de acceder a métricas privadas o promocionadas utilizando el endpoint de cronología de Publicaciones de usuario de X API v2, deberás usar OAuth 1.0a User Context o OAuth 2.0 Authorization Code with PKCE y pasar los tokens de acceso de usuario relacionados con el usuario que publicó la Publicación para la que deseas acceder a las métricas.

**URLs de endpoints**

Ten en cuenta que los endpoints de cronologías de X API v2 requieren un parámetro de ruta :id correspondiente al id de usuario.

* Endpoints estándar v1.1:
  * https://api.x.com/1.1/statuses/home&#95;timeline
  * https://api.x.com/1.1/statuses/user&#95;timeline
  * https://api.x.com/1.1/statuses/mention&#95;timeline
* Endpoint de X API v2:
  * https://api.x.com/2/users/:id/timelines/reverse&#95;chronological
  * https://api.x.com/2/users/:id/tweets
  * https://api.x.com/2/users/:id/mentions

**Requisitos de App y Project**

Los endpoints de X API v2 requieren que uses credenciales de una [App de desarrollador](/es/resources/fundamentals/developer-apps) que esté asociada a un [Project](/es/resources/fundamentals/developer-apps) al autenticar tus solicitudes. Todos los endpoints de X API v1.1 pueden usar credenciales de Apps o de Apps asociadas a un Project.

**Límites de frecuencia**

|     |     |
| :--- | :--- |
| **mentions&#95;timeline:**<br /><br />75 solicitudes por 15 min con OAuth 1.0a User Context | **user mention timeline: **<br /><br />180 solicitudes por ventana de 15 minutos con OAuth 1.0a User Context  <br />450 solicitudes por ventana de 15 minutos con OAuth 2.0 Bearer Token |
| **home&#95;timelime:**<br /><br />15 solicitudes por 15 minutos  <br /><br />Se pueden obtener hasta 800 Publicaciones en la cronología de inicio | **reverse chronological home timeline:**<br /><br />180 solicitudes por 15 minutos<br /><br />Puedes recuperar todas las Publicaciones creadas en una cronología durante los últimos 7 días, así como las 800 más recientes independientemente de la fecha de creación. |

**Parámetros de la solicitud**

|     |     |
| :--- | :--- |
| **Standard timelines v1.1** | **timelines v2** |
| Obligatorio: user&#95;id o screen&#95;name | Obligatorio: el ID de usuario específico se indica en el parámetro de ruta |
| Opcional:<br /><br />count - establece el número máximo de resultados devueltos por solicitud<br /><br />exclude&#95;replies - elimina las respuestas de los resultados<br /><br />Include&#95;rts - cuando se establece en 0 elimina los Retweets de los resultados<br /><br />trim&#95;user - elimina los objetos de usuario rehidratados de los resultados<br /><br />tweet&#95;mode - establece el formato de data devuelto para los resultados, establécelo en extended para Publicaciones de más de 140 caracteres<br /><br />since&#95;id - establece el ID de la Publicación más antigua en el resultado (exclusivo)<br /><br />max&#95;id - establece el ID de la Publicación más reciente en el resultado (inclusivo) | Opcional:<br /><br />max&#95;results - establece el número máximo de resultados devueltos por solicitud<br /><br />exclude=retweets,replies - elimina Retweets o respuestas de los resultados<br /><br />tweet.fields - establece los campos del objeto Publicación que se van a devolver<br /><br />user.fields - establece los campos del objeto Usuario que se van a devolver<br /><br />place.fields - establece los campos del objeto place que se van a devolver<br /><br />media.fields - establece los campos del objeto media que se van a devolver<br /><br />poll.fields - establece los campos del objeto poll que se van a devolver<br /><br />expansions - establece los campos ampliados y la data que se va a devolver<br /><br />start&#95;time - establece la marca de tiempo created&#95;at más temprana para los resultados<br /><br />end&#95;time - establece la marca de tiempo created&#95;at más reciente para los resultados<br /><br />since&#95;id - establece el ID de la Publicación más antigua para los resultados (exclusivo)<br /><br />until&#95;id - establece el ID de la Publicación más reciente en el resultado (exclusivo) |

**Formato de data de la respuesta**

|     |     |
| :--- | :--- |
| **Standard search v1.1** | **Search Posts v2** |
| [<br />    tweet object,<br />    tweet object<br />  ] | <br />  &quot;data&quot;: [id,text,id,text],<br />  &quot;meta&quot;: <br />    &quot;oldest&#95;id&quot;: &quot;1337085692623646724&quot;,<br />    &quot;newest&#95;id&quot;: &quot;1334183616172019713&quot;,<br />    &quot;previous&#95;token&quot;: &quot;77qpymm88g5h9vqkluldpw91lr0qzfz1sqydh841iz48k&quot;,<br />    &quot;result&#95;count&quot;: 10,<br />    &quot;next&#95;token&quot;: &quot;7140dibdnow9c7btw3w29gqolns6a1ipl3kzeae41vsxk&quot;<br />  <br /> |

**Formato JSON de X API v2**

X API v2 está introduciendo nuevos diseños JSON para los objetos devueltos por las APIs, incluidos los objetos de [Publicación](/es/x-api/fundamentals/data-dictionary#tweet) y de [usuario](/es/x-api/fundamentals/data-dictionary#user). Puedes obtener más información sobre el formato de X API v2 y cómo usar campos y expansions visitando nuestra [guía](/es/x-api/fundamentals/data-dictionary#how-to-use-fields-and-expansions) y leyendo nuestro [diccionario de data](/es/x-api/fundamentals/data-dictionary) más amplio.

* En el nivel raíz de JSON, los endpoints estándar devuelven objetos de Publicación en una matriz statuses, mientras que X API v2 devuelve una matriz data.
* En lugar de hacer referencia a &quot;statuses&quot; Retweeted y Quoted, el JSON de X API v2 hace referencia a Tuits Retweeted y Quoted. Muchos campos heredados y obsoletos, como contributors y user.translator&#95;type, se están eliminando.
* En lugar de usar tanto favorites (en el objeto de Publicación) como favorites (en el objeto de usuario), X API v2 usa el término like.
* X está adoptando la convención de que los valores JSON sin contenido (por ejemplo, null) no se escriben en el payload. Los atributos de Publicación y usuario solo se incluyen si tienen un valor distinto de null.

Una de las mayores diferencias entre las versiones de endpoints estándar v1.1 y X API v2 es cómo seleccionas qué campos se devuelven en tu payload. Para los endpoints estándar, había varios parámetros que podías usar para identificar qué campos o conjuntos de campos se devolverían en el payload, mientras que la versión de X API v2 simplifica estos diferentes parámetros en [fields](/es/x-api/fundamentals/fields) y [expansions](/es/x-api/fundamentals/expansions).

* campos: los endpoints de X API v2 te permiten seleccionar qué campos se incluyen en tu payload. Por ejemplo, los objetos Publicación, usuario, Media, Place y Poll tienen cada uno una lista de campos que se pueden devolver (o no).

* expansions: se usa para expandir los objetos complementarios referenciados en los payloads JSON de Publicación. Por ejemplo, todos los Retweets y respuestas hacen referencia a otras Publicaciones. Al establecer expansions=referenced&#95;tweets.id, estos otros objetos de Publicación se expanden de acuerdo con la configuración de tweet.fields. Otros objetos como usuarios, encuestas y medios también se pueden expandir.

* conversation&#95;id

* Dos nuevos campos de [annotations](/es/x-api/fundamentals/post-annotations), incluidos context y entities

* Varios campos nuevos de [metrics](/es/x-api/fundamentals/metrics)

Hemos preparado una [guía de migración de formato de data](/es/x-api/migrate/data-format-migration#migrating-from-standard-v1-1s-data-format-to-v2) que puede ayudarte a mapear los campos estándar de v1.1 a los campos más recientes de v2. Esta guía también te proporcionará los parámetros específicos expansions y fields que deberás pasar con tu solicitud v2 para devolver campos concretos.

<div id="user-posts-timeline-v2">
  ### Cronología de publicaciones de usuario (v2)
</div>

<CodeGroup dropdown>
  ```bash cURL
  curl "https://api.x.com/2/users/2244994945/tweets?max_results=100&tweet.fields=created_at,public_metrics&exclude=retweets,replies" \
    -H "Authorization: Bearer $BEARER_TOKEN"
  ```

  ```python Python SDK
  from xdk import Client

  client = Client(bearer_token="YOUR_BEARER_TOKEN")

  # Obtener la cronología de publicaciones del usuario
  for page in client.posts.get_user_posts(
      "2244994945",
      tweet_fields=["created_at", "public_metrics"],
      exclude=["retweets", "replies"],
      max_results=100
  ):
      for post in page.data:
          print(f"{post.created_at}: {post.text[:50]}...")
  ```

  ```javascript JavaScript SDK
  import { Client } from "@xdevplatform/xdk";

  const client = new Client({ bearerToken: "YOUR_BEARER_TOKEN" });

  // Obtener la cronología de publicaciones del usuario
  const paginator = client.posts.getUserPosts("2244994945", {
    tweetFields: ["created_at", "public_metrics"],
    exclude: ["retweets", "replies"],
    maxResults: 100,
  });

  for await (const page of paginator) {
    page.data?.forEach((post) => {
      console.log(`${post.created_at}: ${post.text?.slice(0, 50)}...`);
    });
  }
  ```
</CodeGroup>
