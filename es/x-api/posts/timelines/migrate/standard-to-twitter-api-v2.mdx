<div id="standard-v11-timelines-to-x-api-v2-timelines">
  ## Cronologías estándar v1.1 a cronologías de X API v2
</div>

Si has estado trabajando con los endpoints de cronologías de v1.1 (statuses/user&#95;timeline y statuses/mentions&#95;timeline), el objetivo de esta guía es ayudarte a entender las similitudes y diferencias entre los endpoints de cronologías estándar y los de X API v2, para que puedas migrar tu integración actual a la nueva versión.

* **Similitudes:**
  * Autenticación:
    * OAuth 1.0a User Context (cronología de inicio en orden cronológico inverso, cronología de Publicaciones de usuario y cronología de menciones de usuario)
    * OAuth 2.0 App-Only (cronología de Publicaciones de usuario)
  * Límite de acceso histórico: la cronología de usuario (cronología de Publicaciones de usuario) proporciona acceso a las 3200 Publicaciones más recientes; la cronología de menciones (cronología de menciones de usuario) proporciona acceso a las 800 menciones más recientes.
  * Compatibilidad con historial de edición de Publicaciones y metadatos
  * Límites de frecuencia (cronología de Publicaciones de usuario)
  * Sondeo de actualización (refresh polling): posibilidad de recuperar nuevos resultados desde el since&#95;id
  * Recorrido de cronologías mediante id de Publicación
  * Especificaciones de resultados:
    * Orden de resultados: resultados devueltos en orden cronológico inverso
    * Posibilidad de excluir respuestas (solo cronología de Publicaciones de usuario)
    * Posibilidad de excluir Retuits (solo cronología de Publicaciones de usuario)
* **Diferencias**
  * Nueva capacidad de autenticación:
    * OAuth 2.0 App-Only (cronología de menciones de usuario)
    * OAuth 2.0 Authorization Code Flow with PKCE (cronología de inicio en orden cronológico inverso, cronología de Publicaciones de usuario y cronología de menciones de usuario)
  * Requisitos de acceso: requisitos de App y Project de X API v2
  * Límites de frecuencia (cronología de menciones de usuario y cronología de inicio en orden cronológico inverso)
  * Método de paginación adicional
    * Diferente valor de max&#95;results (count) por respuesta
  * Formato de los datos de la respuesta
  * Parámetros de solicitud
    * Formato de datos personalizado según los parámetros de solicitud, incluidos los campos v2 y expansions
    * Datos adicionales disponibles: métricas, anotaciones de Publicaciones, encuestas

<div id="similarities">
  ### Similitudes
</div>

**Autenticación**

El endpoint v1.1 statuses/user&#95;timeline y el endpoint de cronología de Publicaciones de usuario de X API v2 admiten tanto [OAuth 1.0a User Context](/es/resources/fundamentals/authentication) como [OAuth 2.0 App-Only](/es/resources/fundamentals/authentication#bearer-token-also-known-as-app-only). Por lo tanto, puedes seguir usando el mismo método de autenticación y los mismos tokens de autorización si migras a la versión de X API v2.

**Acceso histórico**

El endpoint v1.1 statuses/user&#95;timeline y el endpoint de cronología de Publicaciones de usuario de X API v2 devolverán ambos las 3200 Publicaciones más recientes, incluidos los retweets.

El endpoint v1.1 statuses/mentions&#95;timeline y el endpoint de cronología de menciones de usuario de X API v2 pueden devolver las 800 Publicaciones más recientes.

**Compatibilidad con el historial de edición de Publicaciones y metadatos**

Ambas versiones proporcionan metadatos que describen cualquier historial de edición. Consulta las [Referencias de la API de flujo filtrado](/es/x-api/posts/filtered-stream#api-reference-index) y la [página de fundamentos de edición de Publicaciones](/es/x-api/fundamentals/edit-posts) para más detalles.

**Límites de frecuencia**

|     |     |
| :--- | :--- |
| **Standard v1.1** | **X API v2** |
| user&#95;timeline:<br /><br />900 solicitudes por 15 minutos con OAuth 1.0a User Context<br /><br />1500 solicitudes por 15 minutos con OAuth 2.0 App-Only | Cronología de Publicaciones de usuario:<br /><br />900 solicitudes por ventana de 15 minutos con OAuth 1.0a User Context<br /><br />1500 solicitudes por ventana de 15 minutos con OAuth 2.0 App-Only |

**Actualización mediante sondeo con since&#95;id**

Ambas versiones permiten sondear resultados recientes usando since&#95;id.

**Recorrido de cronologías por ID de Publicación**

Ambos endpoints tienen la capacidad de recorrer las cronologías usando las “marcas de tiempo” de ID de Publicación, basadas en la forma en que se construyen las ID de Publicación. La funcionalidad es en general la misma, excepto por lo siguiente:

|     |     |
| :--- | :--- |
| **Standard timelines v1.1** | **timelines v2** |
| since&#95;id (exclusivo)<br /><br />max&#95;id (inclusivo) | since&#95;id (exclusivo)<br /><br />until&#95;id (también exclusivo, frente a max&#95;id, que era inclusivo) |

**Parámetros de filtrado de Respuesta**

|     |     |
| :--- | :--- |
| **Standard timelines v1.1** | **timelines v2** |
| Parámetros de filtrado de Respuesta:<br /><br />* include&#95;rts<br />* exclude&#95;replies | Parámetros de filtrado de Respuesta:<br /><br />* exclude=retweets,replies |
| Ejemplo <br /><br />https://api.x.com/1.1/statuses/user&#95;timeline.json?user&#95;id=2244994945&amp;include&#95;rts=0&amp;&amp;exclude&#95;replies=1 | Ejemplo:<br /><br />https://api.x.com/2/users/2244994945/tweets?max&#95;results=100&amp;exclude=retweets,replies |
| Notas:<br /><br />Para user&#95;timeline:<br /><br />* Usar include&#95;rts=0 no cambia el posible límite histórico de Publicaciones de las 3200 más recientes | Notas:<br /><br />Para la cronología de Publicaciones de usuario:<br /><br />* Usar exclude=retweets no cambia el posible límite histórico de Publicaciones de las 3200 más recientes <br />* Usar exclude=replies reduce el posible límite histórico de Publicaciones a las 800 respuestas más recientes |

<div id="differences">
  ### Diferencias
</div>

**Autenticación**

**El endpoint v1.1 statuses/mentions&#95;timeline solo admite [OAuth 1.0a User Context](https://developer-staging.x.com/resources/fundamentals/authentication). El endpoint de timeline de menciones de usuario de X API v2 admite [OAuth 1.0a User Context](/es/resources/fundamentals/authentication), [OAuth 2.0 App-Only](/es/resources/fundamentals/authentication#bearer-token-also-known-as-app-only) y [OAuth 2.0 Authorization Code with PKCE](/es/resources/fundamentals/authenticationoauth-2-0/authorization-code "Este método permite que una app autorizada actúe en nombre del usuario, como si fuera el propio usuario. Normalmente se utiliza para acceder o publicar información pública de un usuario específico y es útil cuando tu app necesita conocer la relación entre un usuario y lo que devuelve este endpoint. Haz clic para aprender cómo autenticarte con OAuth 2.0 Authorization Code with PKCE.") **

Si quieres aprovechar la posibilidad de acceder a métricas privadas o promocionadas mediante el endpoint de timeline de Publicaciones de usuario de X API v2, deberás utilizar OAuth 1.0a User Context o OAuth 2.0 Authorization Code with PKCE y pasar los tokens de acceso de usuario relacionados con el usuario que publicó la Publicación para la cual deseas acceder a métricas.

**URLs de endpoint**

Ten en cuenta que los endpoints de timelines de X API v2 requieren un parámetro de ruta :id para el ID de usuario.

* Endpoints estándar v1.1:
  * https://api.x.com/1.1/statuses/home&#95;timeline
  * https://api.x.com/1.1/statuses/user&#95;timeline
  * https://api.x.com/1.1/statuses/mention&#95;timeline
* Endpoint de X API v2:
  * https://api.x.com/2/users/:id/timelines/reverse&#95;chronological
  * https://api.x.com/2/users/:id/tweets
  * https://api.x.com/2/users/:id/mentions

**Requisitos de App y Project**

Los endpoints de X API v2 requieren que utilices credenciales de una [App de desarrollador](/es/resources/fundamentals/developer-apps) que esté asociada a un [Project](/es/resources/fundamentals/developer-apps) al autenticar tus solicitudes. Todos los endpoints de X API v1.1 pueden utilizar credenciales de Apps o de Apps asociadas con un Project.

**Límites de frecuencia**

|     |     |
| :--- | :--- |
| **mentions&#95;timeline:**<br /><br />75 solicitudes por 15 minutos con OAuth 1.0a User Context | **user mention timeline: **<br /><br />180 solicitudes por ventana de 15 minutos con OAuth 1.0a User Context  <br />450 solicitudes por ventana de 15 minutos con OAuth 2.0 Bearer Token |
| **home&#95;timelime:**<br /><br />15 solicitudes por 15 minutos  <br /><br />Se pueden obtener hasta 800 Publicaciones en el timeline de inicio | **reverse chronological home timeline:**<br /><br />180 solicitudes por 15 minutos<br /><br />Puedes obtener todas las Publicaciones creadas en un timeline durante los últimos 7 días, así como las 800 más recientes, independientemente de su fecha de creación. |

**Parámetros de solicitud**

|     |     |
| :--- | :--- |
| **Standard timelines v1.1** | **timelines v2** |
| Obligatorio: user&#95;id o screen&#95;name | Obligatorio: el ID de usuario específico se indica en el parámetro de ruta |
| Opcional:<br /><br />count - establece el número máximo de resultados devueltos por solicitud<br /><br />exclude&#95;replies - elimina las respuestas de los resultados<br /><br />Include&#95;rts - cuando se establece en 0 elimina los Retuits de los resultados<br /><br />trim&#95;user - elimina los objetos de usuario rehidratados de los resultados<br /><br />tweet&#95;mode - establece el formato de data devuelta para los resultados; configúralo en extended para Publicaciones de más de 140 caracteres<br /><br />since&#95;id - establece el ID de Publicación más antiguo en el resultado (exclusivo)<br /><br />max&#95;id - establece el ID de Publicación más reciente en el resultado (inclusivo) | Opcional:<br /><br />max&#95;results - establece el número máximo de resultados devueltos por solicitud<br /><br />exclude=retweets,replies - elimina los Retuits o las respuestas de los resultados<br /><br />tweet.fields - establece los campos del objeto Post que se devolverán<br /><br />user.fields - establece los campos del objeto User que se devolverán<br /><br />place.fields - establece los campos del objeto place que se devolverán<br /><br />media.fields - establece los campos del objeto media que se devolverán<br /><br />poll.fields - establece los campos del objeto poll que se devolverán<br /><br />expansions - establece los campos y la data ampliada que se devolverán<br /><br />start&#95;time - establece la hora created&#95;at más antigua para los resultados<br /><br />end&#95;time - establece la hora created&#95;at más reciente para los resultados<br /><br />since&#95;id - establece el ID de Publicación más antiguo para los resultados (exclusivo)<br /><br />until&#95;id - establece el ID de Publicación más reciente en el resultado (exclusivo) |

**Formato de los datos de la respuesta**

|     |     |
| :--- | :--- |
| **Standard search v1.1** | **Search Posts v2** |
| [<br />    tweet object,<br />    tweet object<br />  ] | <br />  &quot;data&quot;: [id,text,id,text],<br />  &quot;meta&quot;: <br />    &quot;oldest&#95;id&quot;: &quot;1337085692623646724&quot;,<br />    &quot;newest&#95;id&quot;: &quot;1334183616172019713&quot;,<br />    &quot;previous&#95;token&quot;: &quot;77qpymm88g5h9vqkluldpw91lr0qzfz1sqydh841iz48k&quot;,<br />    &quot;result&#95;count&quot;: 10,<br />    &quot;next&#95;token&quot;: &quot;7140dibdnow9c7btw3w29gqolns6a1ipl3kzeae41vsxk&quot;<br />  <br /> |

**Formato JSON de X API v2**

X API v2 está introduciendo nuevos diseños JSON para los objetos devueltos por las API, incluidos los objetos de [Publicación](/es/x-api/fundamentals/data-dictionary#tweet) y de [usuario](/es/x-api/fundamentals/data-dictionary#user). Puedes obtener más información sobre el formato de X API v2 y cómo usar campos y expansions visitando nuestra [guía](/es/x-api/fundamentals/data-dictionary#how-to-use-fields-and-expansions) y leyendo nuestro [diccionario de datos](/es/x-api/fundamentals/data-dictionary) más amplio.

* En el nivel raíz de JSON, los endpoints estándar devuelven objetos de Publicación en una matriz statuses, mientras que X API v2 devuelve una matriz data.
* En lugar de hacer referencia a &quot;statuses&quot; Retweeted y Quoted, el JSON de X API v2 hace referencia a Tuits retuiteados y citados. Muchos campos heredados y obsoletos, como contributors y user.translator&#95;type, se están eliminando.
* En lugar de usar tanto favorites (en el objeto Post) como favorites (en el objeto user), X API v2 utiliza el término me gusta.
* X está adoptando la convención de que los valores JSON sin valor (por ejemplo, null) no se escriben en la carga útil. Los atributos de Publicación y de usuario solo se incluyen si tienen un valor distinto de null.

Una de las diferencias más grandes entre las versiones de endpoint estándar v1.1 y X API v2 es cómo seleccionas qué campos se devuelven en tu carga útil. Para los endpoints estándar, hay varios parámetros que puedes usar para identificar qué campos o conjuntos de campos se devolverán en la carga útil, mientras que la versión de X API v2 simplifica estos diferentes parámetros en [campos](/es/x-api/fundamentals/fields) y [expansions](/es/x-api/fundamentals/expansions).

* fields: Los endpoints de X API v2 te permiten seleccionar qué campos se proporcionan en tu payload. Por ejemplo, los objetos Publicación, usuario, Media, Place y Poll tienen cada uno una lista de campos que se pueden devolver (o no).

* expansions: Se usan para expandir los objetos complementarios referenciados en los payloads JSON de Publicación. Por ejemplo, todos los Retuits y las respuestas hacen referencia a otras Publicaciones. Al establecer expansions=referenced&#95;tweets.id, estos otros objetos de Publicación se expanden según la configuración de tweet.fields. También se pueden expandir otros objetos como usuarios, encuestas (polls) y medios.

* conversation&#95;id

* Dos nuevos campos de [annotations](/es/x-api/fundamentals/post-annotations), incluidos context y entities

* Varios campos nuevos de [metrics](/es/x-api/fundamentals/metrics)

Hemos preparado una [guía de migración del formato de data](/es/x-api/migrate/data-format-migration#migrating-from-standard-v1-1s-data-format-to-v2) que puede ayudarte a mapear los campos estándar de v1.1 a los campos más recientes de v2. Esta guía también te proporcionará el parámetro específico de expansions y fields que deberás pasar con tu solicitud v2 para devolver campos específicos.

<div id="user-posts-timeline-v2">
  ### Cronología de Publicaciones de un usuario (v2)
</div>

<CodeGroup dropdown>
  ```bash cURL
  curl "https://api.x.com/2/users/2244994945/tweets?max_results=100&tweet.fields=created_at,public_metrics&exclude=retweets,replies" \
    -H "Authorization: Bearer $BEARER_TOKEN"
  ```

  ```python Python SDK
  from xdk import Client

  client = Client(bearer_token="YOUR_BEARER_TOKEN")

  # Obtener la cronología de Publicaciones de un usuario
  for page in client.posts.get_user_posts(
      "2244994945",
      tweet_fields=["created_at", "public_metrics"],
      exclude=["retweets", "replies"],
      max_results=100
  ):
      for post in page.data:
          print(f"{post.created_at}: {post.text[:50]}...")
  ```

  ```javascript JavaScript SDK
  import { Client } from "@xdevplatform/xdk";

  const client = new Client({ bearerToken: "YOUR_BEARER_TOKEN" });

  // Obtener la cronología de Publicaciones de un usuario
  const paginator = client.posts.getUserPosts("2244994945", {
    tweetFields: ["created_at", "public_metrics"],
    exclude: ["retweets", "replies"],
    maxResults: 100,
  });

  for await (const page of paginator) {
    page.data?.forEach((post) => {
      console.log(`${post.created_at}: ${post.text?.slice(0, 50)}...`);
    });
  }
  ```
</CodeGroup>
