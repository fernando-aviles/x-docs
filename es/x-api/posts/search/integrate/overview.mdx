<div id="authentication">
  ## Autenticación
</div>

<div id="recent-search">
  ### Búsqueda reciente
</div>

La búsqueda reciente admite varios métodos de autenticación:

| Método | Caso de uso |
|:-------|:---------|
| [OAuth 2.0 App-Only](/es/resources/fundamentals/authentication#oauth-2-0) | Datos de publicaciones públicas |
| [OAuth 2.0 Authorization Code with PKCE](/es/resources/fundamentals/authentication#oauth-2-0-authorization-code-flow-with-pkce-2) | Métricas privadas |
| [OAuth 1.0a User Context](/es/resources/fundamentals/authentication) | Métricas privadas |

<div id="full-archive-search">
  ### Búsqueda en el archivo completo
</div>

La búsqueda en el archivo completo solo admite autenticación [OAuth 2.0 de solo aplicación (App-Only)](/es/resources/fundamentals/authentication#oauth-2-0).

<Warning>
  Las métricas privadas (`non_public_metrics`, `organic_metrics`, `promoted_metrics`) no están disponibles en la búsqueda en el archivo completo porque esta solo admite autenticación de solo aplicación.
</Warning>

<div id="building-queries">
  ## Crear consultas
</div>

Las consultas usan operadores para hacer coincidir Publicaciones. Combina operadores con lógica booleana:

```
(AI OR "machine learning") lang:en -is:retweet has:links
```

<div id="query-length-limits">
  ### Límites de longitud de las consultas
</div>

| Nivel de acceso | Búsqueda reciente | Búsqueda en el archivo completo |
|:-------------|:--------------|:--------------------|
| Self-serve | 512 caracteres | 1,024 caracteres |
| Enterprise | 4,096 caracteres | 4,096 caracteres |

<div id="operator-types">
  ### Tipos de operadores
</div>

| Tipo | Descripción | Ejemplo |
|:-----|:------------|:--------|
| **Independiente** | Se puede usar por sí solo | `#python`, `from:user` |
| **Requiere conjunción** | Debe usarse con un operador independiente | `has:media`, `is:retweet` |

<div id="fields-and-expansions">
  ## Campos y expansions
</div>

De forma predeterminada, la respuesta incluye solo `id`, `text` y `edit_history_tweet_ids`. Usa parámetros para solicitar datos adicionales.

<div id="example-request">
  ### Ejemplo de solicitud
</div>

<CodeGroup dropdown>
  ```bash cURL
  curl "https://api.x.com/2/tweets/search/recent?\
  query=python&\
  tweet.fields=created_at,public_metrics,author_id&\
  expansions=author_id,attachments.media_keys&\
  user.fields=username,verified&\
  media.fields=url,type" \
    -H "Authorization: Bearer $BEARER_TOKEN"
  ```

  ```python Python SDK
  from xdk import Client

  client = Client(bearer_token="YOUR_BEARER_TOKEN")

  # Buscar publicaciones recientes
  for page in client.posts.search_recent(
      query="python",
      tweet_fields=["created_at", "public_metrics", "author_id"],
      expansions=["author_id", "attachments.media_keys"],
      user_fields=["username", "verified"],
      media_fields=["url", "type"],
      max_results=100
  ):
      for post in page.data:
          print(f"{post.text} - Likes: {post.public_metrics.like_count}")
  ```

  ```javascript JavaScript SDK
  import { Client } from "@xdevplatform/xdk";

  const client = new Client({ bearerToken: "YOUR_BEARER_TOKEN" });

  // Buscar publicaciones recientes
  const paginator = client.posts.searchRecent("python", {
    tweetFields: ["created_at", "public_metrics", "author_id"],
    expansions: ["author_id", "attachments.media_keys"],
    userFields: ["username", "verified"],
    mediaFields: ["url", "type"],
    maxResults: 100,
  });

  for await (const page of paginator) {
    page.data?.forEach((post) => {
      console.log(`${post.text} - Likes: ${post.public_metrics?.like_count}`);
    });
  }
  ```
</CodeGroup>

<div id="available-expansions">
  ### Expansions disponibles
</div>

| Expansión | Devuelve |
|:----------|:--------|
| `author_id` | Objeto de usuario del autor |
| `attachments.media_keys` | Objetos de medios adjuntos |
| `attachments.poll_ids` | Objetos de encuesta adjuntos |
| `referenced_tweets.id` | Publicaciones citadas o respondidas |
| `geo.place_id` | Objetos de lugares |
| `entities.mentions.username` | Objetos de usuario mencionados |

<div id="pagination">
  ## Paginación
</div>

Los endpoints de búsqueda devuelven resultados en páginas. Usa el `next_token` de la respuesta para recuperar páginas adicionales.

<div id="how-it-works">
  ### Cómo funciona
</div>

1. Realiza tu solicitud inicial con `max_results`
2. Revisa el objeto `meta` en busca de `next_token`
3. Incluye `next_token` en las solicitudes posteriores
4. Repite hasta que ya no se devuelva ningún `next_token`

<div id="example">
  ### Ejemplo
</div>

<CodeGroup dropdown>
  ```bash cURL
  # Primera solicitud
  curl "https://api.x.com/2/tweets/search/recent?query=python&max_results=100" \
    -H "Authorization: Bearer $BEARER_TOKEN"

  # Solicitud posterior con el token de paginación
  curl "https://api.x.com/2/tweets/search/recent?query=python&max_results=100&next_token=NEXT_TOKEN" \
    -H "Authorization: Bearer $BEARER_TOKEN"
  ```

  ```python Python SDK
  from xdk import Client

  client = Client(bearer_token="YOUR_BEARER_TOKEN")

  # El SDK gestiona la paginación automáticamente
  all_posts = []

  for page in client.posts.search_recent(query="python", max_results=100):
      if page.data:
          all_posts.extend(page.data)

  print(f"Se encontraron {len(all_posts)} publicaciones")
  ```

  ```javascript JavaScript SDK
  import { Client } from "@xdevplatform/xdk";

  const client = new Client({ bearerToken: "YOUR_BEARER_TOKEN" });

  async function getAllResults(query) {
    const allPosts = [];

    // El SDK gestiona la paginación automáticamente
    const paginator = client.posts.searchRecent(query, { maxResults: 100 });

    for await (const page of paginator) {
      if (page.data) {
        allPosts.push(...page.data);
      }
    }

    return allPosts;
  }

  // Uso
  const posts = await getAllResults("python");
  console.log(`Se encontraron ${posts.length} publicaciones`);
  ```
</CodeGroup>

<div id="post-edits">
  ## Edición de publicaciones
</div>

Las publicaciones se pueden editar hasta 5 veces en un período de 30 minutos. Los endpoints de búsqueda siempre devuelven la versión más reciente.

<div id="considerations">
  ### Consideraciones
</div>

* `edit_history_tweet_ids` contiene todos los ids de Publicación (de la más antigua a la más reciente)
* Las Publicaciones recuperadas después de la ventana de 30 minutos representan la versión final
* En casos de uso casi en tiempo real, las Publicaciones recientes aún pueden editarse
