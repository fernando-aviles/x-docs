<div id="authentication">
  ### Autenticación
</div>

Todos los endpoints de X API v2 requieren que autentiques tus solicitudes con un conjunto de credenciales, también conocidas como claves y tokens.

Estos endpoints específicos requieren el uso de [OAuth 1.0a User Context](/es/resources/fundamentals/authentication), lo que significa que debes usar un conjunto de claves de API y Access Tokens de usuario para realizar una solicitud correcta. Los Access Tokens deben estar asociados con el usuario en cuyo nombre estás realizando la solicitud. Si deseas generar un conjunto de Access Tokens para otro usuario, este debe autorizar o autenticar tu App mediante el [flujo OAuth con 3 participantes (3-legged OAuth flow)](/es/resources/fundamentals/authentication#obtaining-access-tokens-using-3-legged-oauth-flow).

Ten en cuenta que OAuth 1.0a puede ser difícil de usar. Si no estás familiarizado con este método de autenticación, te recomendamos usar una [biblioteca](/es/x-api/tools-and-libraries/overview), usar una herramienta como Postman o usar OAuth 2.0 para autenticar tus solicitudes.

[OAuth 2.0 Authorization Code with PKCE](/es/resources/fundamentals/authentication#oauth-2-0-authorization-code-flow-with-pkce-2) permite un mayor control sobre el ámbito de una aplicación y sobre los flujos de autorización en varios dispositivos. OAuth 2.0 te permite elegir scopes específicos y granulares que te otorgan permisos concretos en nombre de un usuario.

Para habilitar OAuth 2.0 en tu App, debes activarlo en la configuración de autenticación de tu App, que se encuentra en la sección de configuración de la App en la Consola de Desarrollador.

<div id="developer-console-projects-and-developer-apps">
  ### Consola de Desarrollador, Projects y Apps de desarrollador
</div>

Para obtener un conjunto de credenciales de autenticación que funcionen con los endpoints de X API v2, debes contar con una [cuenta de desarrollador](/es/resources/fundamentals/developer-portal), haber configurado un [Project](/es/resources/fundamentals/developer-apps) dentro de esa cuenta y haber creado una [App de desarrollador](/es/resources/fundamentals/developer-apps) dentro de ese Project. Luego podrás encontrar tus claves y tokens dentro de tu App de desarrollador.

<div id="rate-limits">
  ### Límites de frecuencia
</div>

Cada día, miles de desarrolladores realizan solicitudes a la X API. Para ayudar a gestionar el gran volumen de estas solicitudes, se aplican [límites de frecuencia](https://developer.x.com/x-api/fundamentals/rate-limits) a cada endpoint que limitan la cantidad de solicitudes que puedes realizar en nombre de tu app o en nombre de un usuario autenticado.

Estos endpoints tienen límites de frecuencia a nivel de usuario, lo que significa que el usuario autenticado en cuyo nombre realizas la solicitud solo puede llamar al endpoint un número determinado de veces desde cualquier App de desarrollador. Existe un límite de frecuencia por usuario de 200 solicitudes cada 15 minutos para el método POST. El método DELETE tiene un límite de frecuencia de 50 solicitudes cada 15 minutos. Además, hay un límite de [300 solicitudes cada 3 horas](https://blog.x.com/developer/en_us/topics/tools/2018/new-developer-requirements-to-protect-our-platform), incluidas las publicaciones creadas mediante manage Posts o manage Retweets.

<div id="source-labels">
  ### Etiquetas de origen
</div>

El nombre de tu aplicación y la URL de tu sitio web se mostrarán como la [etiqueta de origen](https://help.x.com/en/using-twitter/how-to-tweet#source-labels) dentro de los metadatos de cualquier Publicación creada mediante programación por tu aplicación. Si cambias el caso de uso de una App de X, asegúrate de actualizar el caso de uso en estos ajustes para garantizar que cumples con los [Términos para Desarrolladores](https://developer.x.com/content/developer-twitter/en/developer-terms/agreement-and-policy).

<div id="profile-settings">
  ### Configuración de perfil
</div>

Solo puedes añadir una ubicación a las Publicaciones si tienes la geolocalización habilitada en la configuración de tu perfil. Si no tienes la geolocalización habilitada, todavía puedes añadir un parámetro de ubicación en el cuerpo de tu solicitud, pero no se adjuntará a tu Publicación. Lo mismo ocurre con el etiquetado de usuarios en imágenes. Si el usuario al que estás etiquetando no tiene habilitado el etiquetado de fotos, sus nombres no aparecerán en la lista de usuarios etiquetados aunque la Publicación se cree correctamente.

<div id="adding-media-to-a-post">
  ### Agregar contenido multimedia a una Publicación
</div>

Actualmente, no hay una forma de subir completamente contenido multimedia usando la v2 de X API. Sin embargo, puedes adjuntar contenido multimedia que hayas subido previamente a una Publicación. Puedes usar id de contenido multimedia que ya se hayan [subido usando el endpoint de contenido multimedia de la v1](https://developer.x.com/en/docs/twitter-api/v1/media/upload-media/api-reference/post-media-upload) o [X Media Studio](https://media.x.com/en/articles/products/2018/media-studio). Estos id de contenido multimedia deben ser tuyos o de un usuario autenticado.

<div id="create-a-post">
  ### Crear una Publicación
</div>

<CodeGroup dropdown>
  ```bash cURL
  curl -X POST "https://api.x.com/2/tweets" \
    -H "Authorization: OAuth ..." \
    -H "Content-Type: application/json" \
    -d '{"text": "Hello world!"}'
  ```

  ```python Python SDK
  from xdk import Client
  from xdk.oauth1_auth import OAuth1

  oauth1 = OAuth1(
      api_key="YOUR_API_KEY",
      api_secret="YOUR_API_SECRET",
      access_token="YOUR_ACCESS_TOKEN",
      access_token_secret="YOUR_ACCESS_TOKEN_SECRET"
  )

  client = Client(auth=oauth1)

  # Crear una Publicación
  response = client.posts.create(text="Hello world!")
  print(f"Publicación creada: {response.data.id}")
  ```

  ```javascript JavaScript SDK
  import { Client, OAuth1 } from "@xdevplatform/xdk";

  const oauth1 = new OAuth1({
    apiKey: "YOUR_API_KEY",
    apiSecret: "YOUR_API_SECRET",
    accessToken: "YOUR_ACCESS_TOKEN",
    accessTokenSecret: "YOUR_ACCESS_TOKEN_SECRET",
  });

  const client = new Client({ oauth1 });

  // Crear una Publicación
  const response = await client.posts.create({ text: "Hello world!" });
  console.log(`Publicación creada: ${response.data?.id}`);
  ```
</CodeGroup>
