Comienza a trabajar con la X API en tres pasos: regístrate, crea una aplicación y guarda tus credenciales.

<Button href="https://console.x.com">Regístrate ahora</Button>

***

<div id="step-1-create-a-developer-account">
  ## Paso 1: Crea una cuenta de desarrollador
</div>

<Steps>
  <Step title="Ve a la Consola de Desarrollador">
    Visita [console.x.com](https://console.x.com) e inicia sesión con tu cuenta de X.
  </Step>

  <Step title="Acepta el Acuerdo de Desarrollador">
    Revisa y acepta el Acuerdo de Desarrollador y la Política para Desarrolladores.
  </Step>

  <Step title="Completa tu perfil">
    Proporciona información básica sobre cómo utilizarás la API.
  </Step>
</Steps>

***

<div id="step-2-create-an-app">
  ## Paso 2: Crea una aplicación
</div>

Después de registrarte, crea una aplicación para obtener tus credenciales de API:

<Steps>
  <Step title="Haz clic en &#x22;New App&#x22;">
    Desde el panel de la Consola de Desarrollador, crea una nueva aplicación.
  </Step>

  <Step title="Introduce los detalles de la aplicación">
    Proporciona un nombre, una descripción y un caso de uso para tu aplicación.
  </Step>

  <Step title="Genera las credenciales">
    La consola generará tus claves y tokens de API.
  </Step>
</Steps>

***

<div id="step-3-save-your-credentials">
  ## Paso 3: Guarda tus credenciales
</div>

Recibirás varias credenciales según tus necesidades de autenticación:

| Credencial | Propósito |
|:-----------|:---------|
| **API Key y Secret** | Identifican tu aplicación. Se usan para generar tokens y firmar solicitudes OAuth 1.0a. |
| **Bearer Token** | Autenticación de solo aplicación para leer datos públicos. |
| **Access Token y Secret** | Permiten realizar solicitudes en nombre de tu propia cuenta (OAuth 1.0a). |
| **Client ID y Secret** | Autenticación OAuth 2.0 para solicitudes con contexto de usuario. |

<Warning>
  **Guárdalas de inmediato.** Las credenciales solo se muestran una vez. Almacénalas en un gestor de contraseñas o un almacén seguro. Si las pierdes, tendrás que regenerarlas (lo que invalidará las anteriores).
</Warning>

***

<div id="which-credentials-do-you-need">
  ## ¿Qué credenciales necesitas?
</div>

<Tabs>
  <Tab title="Lectura de datos públicos">
    Usa el **Bearer Token** para un acceso sencillo y de solo lectura a datos públicos.

    ```bash
    curl "https://api.x.com/2/users/by/username/xdevelopers" \
      -H "Authorization: Bearer $BEARER_TOKEN"
    ```

    Ideal para: buscar publicaciones, consultar usuarios, leer tendencias.
  </Tab>

  <Tab title="Actuar como un usuario">
    Usa **OAuth 2.0** (recomendado) o **OAuth 1.0a** para actuar en nombre de los usuarios.

    OAuth 2.0 ofrece permisos granulares: solicita solo los permisos que necesitas.

    Ideal para: publicar, dar Me gusta, seguir, acceder a mensajes directos (MD).

    [Guía de OAuth 2.0 →](/es/resources/fundamentals/authentication/oauth-2-0/overview)
  </Tab>

  <Tab title="Actuar como tú mismo">
    Usa tu **Access Token &amp; Secret** para hacer solicitudes como tu propia cuenta.

    Estos tokens representan la cuenta que es propietaria de la aplicación.

    Ideal para: pruebas, bots personales, tu propia automatización.
  </Tab>
</Tabs>

<div id="credential-security-best-practices">
  ## Mejores prácticas de seguridad de credenciales
</div>

<CardGroup cols={2}>
  <Card title="Usa variables de entorno" icon="terminal">
    Nunca incluyas las credenciales directamente en tu código fuente.
  </Card>

  <Card title="No hagas commit en Git" icon="code-branch">
    Agrega los archivos de credenciales a `.gitignore`.
  </Card>

  <Card title="Rota periódicamente" icon="arrows-rotate">
    Regenera las credenciales periódicamente como medida de seguridad.
  </Card>

  <Card title="Usa scopes mínimos" icon="shield-check">
    Solicita solo los permisos de OAuth que tu aplicación necesita.
  </Card>
</CardGroup>
