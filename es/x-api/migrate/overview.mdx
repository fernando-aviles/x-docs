<div id="what-is-the-x-api-v2">
  ## ¿Qué es la X API v2?
</div>

La X API v2 es ahora la X API principal y es donde se concentran la inversión en producto y la innovación. Nos hemos asociado con desarrolladores para crear la próxima generación de la X API y atender mejor a nuestra diversa comunidad de desarrolladores. Basándonos en sus comentarios, hemos rediseñado la API para cubrir mejor una gama más amplia de necesidades, incorporar nuevas características y endpoints, y mejorar la experiencia del desarrollador.

En los últimos años, nos hemos asociado con desarrolladores y hemos rediseñado la API para cubrir mejor una gama más amplia de necesidades, incorporar nuevas características y endpoints, y mejorar la experiencia del desarrollador. Estamos comprometidos a seguir construyendo una plataforma de desarrollo abierta y estamos entusiasmados por ver lo que creas con la X API v2.

<div id="why-migrate">
  ## ¿Por qué migrar?
</div>

La X API v2 está desarrollada sobre una base moderna y más sostenible e incluye tanto endpoints de reemplazo mejorados para la versión estándar v1.1 y los productos empresariales como funcionalidad totalmente nueva. Recomendamos encarecidamente a los clientes de las APIs heredadas (v1.1 y enterprise) que comiencen a migrar a v2, ya que nuestra intención es retirarlas eventualmente. Usa la X API para escuchar y analizar la conversación pública, interactuar con las personas en X e innovar.

En esta sección, analizaremos los endpoints y la funcionalidad.

<div id="discover-new-and-updated-response-objects">
  ### Descubre objetos de respuesta nuevos y actualizados
</div>

Los siguientes seis objetos de datos están disponibles con los endpoints v2:

| Objeto | Descripción |
|:--------|:-------------|
| [Tweet](/es/x-api/fundamentals/data-dictionary#tweet) | El objeto Tweet tiene una larga lista de campos de nivel raíz, como `id`, `text` y `created_at`. Los objetos Tweet también son el objeto principal de varios objetos secundarios, incluidos `user`, `media`, `poll` y `place`. |
| [User](/es/x-api/fundamentals/data-dictionary#user) | El objeto User contiene metadatos de la cuenta de usuario de X que describen al usuario de referencia. |
| [Spaces](/es/x-api/fundamentals/data-dictionary#space) | El objeto Space consta de campos como `state`, `host_id`, `is_ticketed` e incluso `lang`. |
| [Lists](/es/x-api/fundamentals/data-dictionary#list) | El objeto List contiene información básica sobre la lista solicitada, incluidos `description`, `member_count` y `owner_id`. |
| [Media](/es/x-api/fundamentals/data-dictionary#media) | Si un Tuit contiene contenido multimedia (como imágenes), el objeto Media se puede solicitar usando el parámetro `media.fields` e incluye campos como `media_key`, `type`, `url`, `preview_image_url` y más. |
| [Poll](/es/x-api/fundamentals/data-dictionary#poll) | Una encuesta incluida en un Tuit no es un objeto principal en ningún endpoint, pero se puede encontrar y ampliar en el objeto Tweet. |
| [Place](/es/x-api/fundamentals/data-dictionary#place) | El objeto Place consta de campos como `place_id`, el objeto `geo`, `country_code` y más. Esta información se puede usar para identificar Tuits y estudiarlos por ubicación. |

Obtén más información sobre [cómo usar campos y expansions](/es/x-api/fundamentals/data-dictionary#how-to-use-fields-and-expansions).

<div id="flexibility-to-choose-which-objects-and-fields-you-receive">
  ### Flexibilidad para elegir qué objetos y campos recibes
</div>

Al realizar una solicitud a un endpoint GET, recibirás el objeto de datos principal asociado a ese endpoint, que incluirá un conjunto de campos predeterminados. Por ejemplo, el objeto Tuit entrega los campos `id` y `text` como predeterminados.

Si deseas recuperar campos adicionales con tu solicitud, tendrás que usar los parámetros [fields](/es/x-api/fundamentals/fields) y [expansions](/es/x-api/fundamentals/expansions). El parámetro expansions te permite recuperar objetos de datos relacionados, como el Tuit fijado de un usuario o un objeto multimedia, mientras que los operadores de campos te permiten solicitar campos específicos dentro de los objetos devueltos más allá de los predeterminados.

A continuación se muestra una lista completa de las expansions que puedes solicitar con los diferentes endpoints de X API v2:

| Objeto / Recurso | Expansions disponibles |
|:-------------------|:----------------------|
| Tweets            | `author_id`, `edit_history_tweet_ids`, `entities.mentions.username`, `in_reply_to_user_id`, `referenced_tweets.id`, `referenced_tweets.id.author_id`, `attachments.poll_ids`, `attachments.media_keys`, `geo.place_id` |
| Users             | `pinned_tweet_id` |
| Spaces            | `invited_user_ids`, `speaker_ids`, `creator_id`, `host_ids`, `topic_ids` |

Obtén más información sobre [cómo usar fields y expansions](/es/x-api/fundamentals/data-dictionary#how-to-use-fields-and-expansions).

<div id="edit-tweets">
  ## Editar tuits
</div>

Los endpoints de X API v2 proporcionan metadatos de tuits editados. La función *Editar tuit* se introdujo por primera vez para pruebas internas entre empleados de X el 1 de septiembre de 2022. A partir de esa fecha, los tuits elegibles pueden editarse durante 30 minutos y hasta 5 veces. Obtén más información sobre [Editar tuits](/es/x-api/fundamentals/edit-posts).
Con X API v2, un desarrollador puede averiguar:

* Si un tuit era elegible para edición en el momento de su creación. Algunos tuits, como aquellos con encuestas o tuits programados, no se pueden editar.
* Los tuits son editables durante 30 minutos y se pueden editar hasta 5 veces. Para los tuits editables puedes ver si aún queda tiempo para editarlos y cuántas ediciones adicionales son posibles.
* Si estás viendo una versión editada de un tuit (en la mayoría de los casos la API devolverá la versión más reciente de un tuit, a menos que se solicite específicamente una versión anterior mediante el Tweet ID).
* El historial completo de ediciones del tuit.
* La interacción atribuida a cada versión del tuit.

<div id="ready-to-migrate">
  ## Listo para migrar
</div>

Para usar los endpoints de v2, necesitarás lo siguiente:

* [Una cuenta de desarrollador](https://developer.x.com/en/portal/petition/essential/basic-info)
* [Una App de desarrollador](https://developer.x.com/en/apps) creada dentro de un [Project](resources/fundamentals/projects)
* [Claves y tokens](resources/fundamentals/authentication) de esa App de desarrollador del Project

Ten en cuenta la importancia de usar claves y tokens de una App dentro de un Project. Si utilizas claves y tokens de una App fuera de un Project, no podrás realizar solicitudes a los endpoints de v2.

Una vez que tengas una cuenta de desarrollador, puedes configurar todo lo anterior en el [Developer Console](https://developer.x.com/en/portal/petition/essential/basic-info).

<div id="authentication">
  ### Autenticación
</div>

Con la nueva Twitter API, utilizarás dos patrones de autenticación diferentes, OAuth 1.0a User Context y OAuth 2.0 Bearer Token, para acceder a distintos endpoints. Cada uno cumple un propósito diferente al realizar solicitudes a los endpoints:

OAuth 1.0a User Context es obligatorio cuando realizas una solicitud en nombre de un usuario de Twitter.
OAuth 2.0 Bearer Token es obligatorio para realizar solicitudes en nombre de tu App de desarrollador.

<div id="migrating-to-the-new-data-format">
  ## Migración al nuevo formato de datos
</div>

A medida que pasas de v1.1 o enterprise a v2, es importante entender que el formato en el que se entregan los datos ha cambiado significativamente. Hemos añadido nuevos campos, modificado el orden de los campos y, en algunos casos, eliminado elementos por completo.

Para obtener más información sobre estos cambios, estamos desarrollando una serie de guías que te ayudarán a relacionar los campos del formato de datos anterior a v2 con los campos más recientes, y describirán cómo solicitar estos nuevos campos.

Puedes obtener más información visitando nuestra sección de [migración de formatos de datos](/es/x-api/migrate/data-format-migration) en este centro de migración, o visitando nuestras guías específicas de formato de datos:

* [Formato nativo a X API v2 (v1.1 estándar)](/es/x-api/migrate/data-format-migration#migrating-from-standard-v1-1s-data-format-to-v2)
* [Native Enriched a X API v2 (enterprise)](/es/x-api/migrate/data-format-migration#migrating-from-native-enriched-data-format-to-v2)
