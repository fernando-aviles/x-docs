La X API devuelve objetos JSON estructurados que representan publicaciones, usuarios, medios y más. Esta referencia documenta todos los campos disponibles para cada tipo de objeto.

***

</div>

<div id="post-tweet">
  ## Publicación (Tuit)
</div>

Las publicaciones son la unidad básica de contenido en X. Cada objeto de Publicación incluye texto, metadatos y referencias a objetos relacionados como autores, contenido multimedia y encuestas.

**Campos predeterminados:** `id`, `text`, `edit_history_tweet_ids`

Usa `tweet.fields` para solicitar campos adicionales y `expansions` para incluir objetos relacionados.

**Recuperar un objeto de Tuit**

**Solicitud de ejemplo**

En la siguiente solicitud, solicitamos campos para el Tuit en el endpoint [Tweets lookup](/es/resources/fundamentals/rate-limits). Asegúrate de reemplazar `$BEARER_TOKEN` por tu propio [Bearer Token](/es/resources/fundamentals/authentication) generado.

```bash
curl --request GET 'https://api.x.com/2/tweets?ids=1212092628029698048&tweet.fields=attachments,author_id,context_annotations,created_at,entities,geo,id,in_reply_to_user_id,lang,possibly_sensitive,public_metrics,referenced_tweets,text,withheld&expansions=referenced_tweets.id' --header 'Authorization: Bearer $BEARER_TOKEN'
```

<div id="user">
  ### Usuario
</div>

El objeto de usuario contiene metadatos de la cuenta de usuario de Twitter que describen al usuario de referencia. El objeto de usuario es el objeto principal que se devuelve en el endpoint [users lookup](/es/x-api/users/lookup/introduction). Cuando solicites campos de usuario adicionales en este endpoint, simplemente usa el parámetro de campos `user.fields`.

El objeto de usuario también se puede encontrar como un objeto secundario y expandido en el objeto Tweet. El objeto está disponible para expansión con `?expansions=author_id` o `?expansions=in_reply_to_user_id` para obtener el objeto condensado con únicamente los campos predeterminados. Usa la expansión con el parámetro de campos `user.fields` cuando solicites campos adicionales para completar el objeto.

<div id="space">
  ### Space
</div>

Los Spaces permiten la expresión y la interacción mediante conversaciones de audio en vivo. El diccionario de datos de Space contiene metadatos relevantes sobre un Space; todos los detalles se actualizan en tiempo real.

Los objetos de usuario se pueden encontrar y expandir en el recurso de usuario. Estos objetos están disponibles para expansión si añades al menos uno de `host_ids`, `creator_id`, `speaker_ids`, `mentioned_user_ids` al parámetro de consulta `expansions`.

A diferencia de los Tuits, los Spaces son efímeros y dejan de estar disponibles cuando terminan o cuando su creador los cancela. Cuando tu aplicación gestiona datos de Spaces, eres responsable de devolver la información más actualizada y debes eliminar los datos que ya no estén disponibles en la plataforma. Los [endpoints de consulta de Spaces](/es/x-api/spaces/lookup/introduction) pueden ayudarte a garantizar que respetas las expectativas e intenciones de los usuarios.

<div id="direct-message-events">
  ### Eventos de Mensaje Directo
</div>

Las conversaciones de Mensaje Directo (DM) están compuestas por eventos. La X API v2 actualmente admite tres tipos de eventos: MessageCreate, ParticipantsJoin y ParticipantsLeave.

Los objetos de eventos de DM se devuelven a través de los endpoints de [búsqueda de Mensajes Directos](/es/x-api/direct-messages/lookup/introduction), y se crea un evento MessageCreate cuando los Mensajes Directos se crean correctamente con los endpoints de [Administrar Mensajes Directos](/es/x-api/direct-messages/lookup/introduction).

Al solicitar eventos de DM, se incluyen tres atributos predeterminados del objeto de evento, o campos: id, event&#95;type y text. Para recibir campos de evento adicionales, usa el parámetro [fields](/es/x-api/fundamentals/fields) dm&#95;event.fields para seleccionar otros. Otros campos de evento disponibles incluyen los siguientes: dm&#95;conversation&#95;id, created&#95;at, sender&#95;id, attachments, participant&#95;ids y referenced&#95;tweets.

Varios de estos campos proporcionan los ID de otros objetos de X relacionados con el evento de Mensaje Directo:

* sender&#95;id - El ID de la cuenta que envió el mensaje o que invitó a un participante a una conversación de grupo
* participant&#95;ids - Un arreglo de ID de cuentas. Para los eventos ParticipantsJoin y ParticipantsLeave, este arreglo contendrá un único ID de la cuenta que creó el evento
* attachments - Proporciona los ID de medios del contenido que el remitente ha subido a X
* referenced&#95;tweets - Si se encuentra una URL de un Tuit en el campo text, el ID de ese Tuit se incluye en la respuesta

Las [expansions](/es/x-api/fundamentals/expansions) sender&#95;id, participant&#95;ids, referenced&#95;tweets.id y attachments.media&#95;keys están disponibles para ampliar estos ID de objetos de X.

Las publicaciones en comunidades pueden ser vistas por cualquier persona en X, pero solo quienes estén dentro de la propia comunidad pueden interactuar y participar en la conversación.

<div id="how-to-use-fields-and-expansions">
  ## Cómo usar campos y expansions
</div>

De forma predeterminada, los objetos de datos de X API v2 incluyen una pequeña cantidad de campos predeterminados cuando realizas una solicitud sin utilizar los parámetros [fields](/es/x-api/fundamentals/fields) o [expansions](/es/x-api/fundamentals/expansions). Esta guía explica cómo usar los parámetros de consulta `fields` y `expansions` en tu solicitud para recibir objetos y campos adicionales en tu respuesta.

En esta guía, solicitaremos varios campos en la siguiente captura de pantalla de un tuit.
 

![Esta imagen incluye una captura de pantalla de un tuit publicado por @X. Puedes ver el texto del tuit, el nombre de usuario, la fecha y hora de publicación, la fuente y las métricas públicas. También incluye un video. ](https://cdn.cms-twdigitalassets.com/content/dam/developer-twitter/ScreenShotDataDictionaryGuide.png.twimg.1920.png)

Como puedes ver en la captura de pantalla, hay varios elementos visibles de información relacionados con el tuit, incluido el autor del tuit, las métricas del tuit, la marca temporal de creación, el video y la cantidad de visualizaciones del video. También hay varios elementos de datos que no son visibles en la captura de pantalla, pero que aun así están disponibles para solicitar.

Al realizar una solicitud a la API, la respuesta predeterminada es simple y contiene solo los campos predeterminados del tuit (id y text). También solo recibirás el objeto principal que se devuelve con el endpoint que estés utilizando, y no ninguno de los objetos de datos asociados que puedan estar relacionados con el objeto principal.

Esta simplicidad, junto con los parámetros fields y expansions, te permite solicitar solo aquellos campos que necesitas, según tu caso de uso. 
 

<div id="requesting-additional-fields-and-objects">
  #### Solicitud de campos y objetos adicionales.
</div>

En primer lugar, solicitaremos un [objeto Tuit](/es/x-api/fundamentals/data-dictionary#tweet) utilizando un ID de Tuit y el [endpoint GET /tweets](/es/x-api/posts/lookup/introduction).

Solicitud:

```bash
curl --request GET --url 'https://api.x.com/2/tweets?ids=1260294888811347969' \
  --header 'Authorization: Bearer $BEARER_TOKEN'
```

Respuesta:

```
{
    "data": [
        {
            "id": "1260294888811347969",
            "text": "No te pierdas los Tuits sobre tu Tuit. \n\nAhora en iOS, puedes ver los Retuits con comentarios en un solo lugar. https://t.co/oanjZfzC6y"
        }
    ]
}
```

La siguiente guía paso a paso te mostrará cómo recuperar los datos adicionales que se pueden ver en la captura de pantalla.

1. Identifica los campos adicionales que deseas solicitar utilizando nuestro [modelo de objetos](/es/x-api/fundamentals/data-dictionary#tweet) o revisando la lista de campos en las páginas de referencia de la API de los endpoints.

   En este caso, solicitaremos los siguientes campos adicionales:
   attachments, author&#95;id, created&#95;at, public&#95;metrics.

2. Construye el parámetro de consulta `tweet.fields` usando como valor los campos anteriores en una lista separada por comas:
   `?tweet.fields=attachments,author_id,created_at,public_metrics`

3. Añade el parámetro de consulta a la solicitud GET /tweets que realizaste anteriormente.

Solicitud:

`curl --request GET --url 'https://api.x.com/2/tweets?ids=1260294888811347969&tweet.fields=attachments,author_id,created_at,public_metrics' \   --header 'Authorization: Bearer $BEARER_TOKEN'`

Respuesta:

```
{
    "data": [
        {
            "id": "1260294888811347969",
            "text": "No te pierdas los Tuits sobre tu Tuit. \n\nAhora en iOS, puedes ver los Retuits con comentarios, todo en un solo lugar. https://t.co/oanjZfzC6y",
            "author_id": "783214",
            "public_metrics": {
                "retweet_count": 5219,
                "reply_count": 1828,
                "like_count": 17141,
                "quote_count": 3255

                "media_keys": [

                ]

        }

}
```

4. A continuación, vamos a solicitar campos relacionados con el video que se incluyó en el Tuit. Para hacerlo, usaremos el parámetro `expansions` con `attachments.media_keys` como valor y lo agregaremos a la solicitud.

?expansions=attachments.media&#95;keys

Solicitud:

```bash
curl --request GET --url 'https://api.x.com/2/tweets?ids=1260294888811347969&tweet.fields=attachments,author_id,created_at,public_metrics&expansions=attachments.media_keys' \
  --header 'Authorization: Bearer $BEARER_TOKEN'
```

Respuesta, con el objeto de medios representado en el objeto includes:

```
{
    "data": [
        {
            "id": "1260294888811347969",
            "text": "No te pierdas los Tuits sobre tu Tuit. \n\nAhora en iOS, puedes ver los Retuits con comentarios, todo en un solo lugar. https://t.co/oanjZfzC6y",

                "retweet_count": 5219,
                "reply_count": 1828,
                "like_count": 17141,
                "quote_count": 3255

                ]
            },

        }
    ],

        "media": [
            {
                "media_key": "13_1260294804770041858",
                "type": "video"
            }
        ]
    }
}
```

5. Y finalmente, vamos a solicitar el número de visualizaciones y la duración del video. Estos no son campos predeterminados, por lo que tenemos que solicitarlos específicamente. Usa el parámetro `media.fields` con los valores separados por comas `public_metrics` y `duration_ms` en tu solicitud.

?media.fields=public&#95;metrics,duration&#95;ms

Solicitud:
 

`curl --request GET --url 'https://api.x.com/2/tweets?ids=1260294888811347969&tweet.fields=attachments,author_id,created_at,public_metrics&expansions=attachments.media_keys&media.fields=duration_ms,public_metrics' --header 'Authorization: Bearer $BEARER_TOKEN'`

        {
            "id": "1260294888811347969",

            "attachments": {
                "media_keys": [
                    "13_1260294804770041858"
                ]
            }
        }
    ],

        "media": [
            {
                "duration_ms": 36503,
                "media_key": "13_1260294804770041858",

                    "view_count": 1534703

En total, incluimos los siguientes parámetros en este ejemplo:

* ids=1260294888811347969
* tweet.fields=attachments,author&#95;id,created&#95;at,public&#95;metrics
* expansions=attachments.media&#95;keys
* media.fields=public&#95;metrics,duration&#95;ms
   

Al combinarlos, la cadena de consulta completa se ve así:

```
?ids=1260294888811347969&tweet.fields=attachments,author\_id,created\_at,public\_metrics&expansions=attachments.media\_keys&media.fields=public\_metrics,duration\_ms
```
