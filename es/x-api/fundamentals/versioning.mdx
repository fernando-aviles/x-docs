X API usa números de versión en las rutas de los endpoints para proporcionar estabilidad, al tiempo que permite su evolución. Comprender nuestra estrategia de versionado ayuda a planificar las integraciones y a mantenerse al día.

***

<div id="current-versions">
  ## Versiones actuales
</div>

| Versión | Estado | Descripción |
|:--------|:-------|:------------|
| **v2** | Actual | Endpoints modernos, precios flexibles, todas las nuevas funciones |
| **v1.1** | Heredada | Soporte limitado, actualizaciones mínimas |
| **Enterprise** | Disponible | Acceso de gran volumen con soporte dedicado |

<Tip>
  Usa **X API v2** para todos los proyectos nuevos. Aquí es donde se incorporan todas las nuevas funciones.
</Tip>

<div id="version-in-urls">
  ## Versión en las URL
</div>

El número de versión aparece en la ruta del endpoint:

```
https://api.x.com/2/tweets
                   ^
                   versión
```

<div id="breaking-vs-non-breaking-changes">
  ## Cambios incompatibles vs. compatibles
</div>

<div id="breaking-changes-require-code-updates">
  ### Cambios incompatibles (requieren actualizaciones de código)
</div>

Estos cambios solo se producen en versiones principales:

* Eliminación de un endpoint
* Eliminación de un campo de respuesta
* Eliminación de un parámetro de consulta
* Incorporación de un nuevo parámetro obligatorio
* Cambio del tipo de dato de un campo
* Cambio de nombre de un campo o recurso
* Cambio de códigos de respuesta o tipos de error
* Modificación de los ámbitos de autorización

<div id="non-breaking-changes-additive">
  ### Cambios retrocompatibles (aditivos)
</div>

Estos pueden producirse en cualquier momento sin cambios de versión:

* Agregar un nuevo endpoint
* Agregar un nuevo parámetro opcional
* Agregar un nuevo campo de respuesta
* Agregar nuevos permisos de OAuth
* Cambiar el texto del mensaje de error
* Establecer campos en null por motivos de privacidad y seguridad

  ## Programa de lanzamientos
</div>

| Tipo | Frecuencia | Información |
|:-----|:----------|:------------|
| **Versiones principales** | Como máximo una vez al año | Se proporcionan guías de migración |
| **Cambios no disruptivos** | De forma continua | Actualizaciones del registro de cambios |
| **Parches de seguridad** | Según sea necesario | Pueden aplicarse a la versión actual |

***

<div id="deprecation-policy">
  ## Política de obsolescencia
</div>

Cuando lanzamos una nueva versión principal:

1. **Obsolescencia**: La versión anterior se marca como obsoleta
2. **Período de soporte**: La versión obsoleta continúa funcionando durante un período determinado
3. **Retiro**: La versión obsoleta se elimina

<div id="definitions">
  ### Definiciones
</div>

| Estado | Significado |
|:-------|:--------|
| **Activo** | Con soporte completo, con nuevas funciones y correcciones |
| **Obsoleto** | Sin nuevas funciones; solo corrección de errores críticos; se desaconseja su uso |
| **Retirado** | Ya no disponible |
