Cada objeto en X API —publicaciones, usuarios, listas, mensajes directos, Spaces— tiene un ID único. Comprender cómo funcionan estos ID ayuda a crear integraciones fiables.

***

<div id="id-format">
  ## Formato de las ID
</div>

Las ID de X son **enteros sin signo de 64 bits** generados mediante un sistema denominado &quot;Snowflake&quot;. Cada ID codifica:

* **Marca de tiempo** — cuándo se creó el objeto
* **Número de trabajador** — qué servidor generó la ID
* **Número de secuencia** — orden dentro de ese milisegundo

Esto implica que las ID están aproximadamente ordenadas por tiempo: las ID más altas generalmente representan objetos más recientes.

<Tip>
  Las ID son globalmente únicas en todo X, no solo dentro de un único tipo de objeto.
</Tip>

***

<div id="string-vs-integer-representation">
  ## Representación como cadena de texto frente a entero
</div>

<Warning>
  **Utiliza siempre IDs como cadenas de texto en tu código.** Algunos lenguajes de programación (como JavaScript) no pueden representar con precisión enteros de 64 bits.
</Warning>

En JavaScript, los enteros están limitados a 53 bits. Esto provoca pérdida de precisión con IDs grandes:

```javascript
// ¡Esto pierde precisión!
const id = 10765432100123456789;
console.log(id.toString()); // "10765432100123458000" — ¡incorrecto!

// Usa cadenas de texto en su lugar
const id = "10765432100123456789";
console.log(id); // "10765432100123456789" — ¡correcto!
```

<div id="api-versions">
  ### Versiones de la API
</div>

| Versión | Formato de ID |
|:--------|:----------|
| **X API v2** | Los ID se devuelven como cadenas de texto de forma predeterminada |
| **X API v1.1** | Devuelve tanto `id` (entero) como `id_str` (cadena de texto) — usa siempre `id_str` |

<div id="working-with-ids">
  ## Uso de IDs
</div>

<div id="storing-ids">
  ### Almacenar IDs
</div>

Almacena los IDs como cadenas de texto o enteros de 64 bits en tu base de datos:

| Base de datos | Tipo recomendado |
|:---------|:-----------------|
| PostgreSQL | `BIGINT` o `TEXT` |
| MySQL | `BIGINT UNSIGNED` o `VARCHAR(20)` |
| MongoDB | String |
| SQLite | `TEXT` (los enteros de SQLite tienen un máximo de 63 bits) |

<div id="comparing-ids">
  ### Comparación de identificadores
</div>

Al comparar identificadores para ordenarlos cronológicamente:

```python
# Python - safe for 64-bit integers
if int(id1) > int(id2):
    print("id1 is newer")

# JavaScript - comparar como cadenas (funciona lexicográficamente para IDs de la misma longitud)
# O usar BigInt
if (BigInt(id1) > BigInt(id2)) {
    console.log("id1 is newer");
}
```

  ## Tipos de ID comunes
</div>

| Objeto | ID de ejemplo | Notas |
|:-------|:-----------|:------|
| Publicación (Tuit) | `1234567890123456789` | También llamado ID de Tuit |
| Usuario | `2244994945` | Las cuentas más antiguas tienen IDs más cortos |
| Lista | `1234567890` | |
| Space | `1YqGodQbNXDxv` | Alfanumérico, no usa el formato Snowflake |
| Evento de MD | `1234567890123456789` | |
