<div id="general">
  ## General
</div>

<AccordionGroup>
  <Accordion title="¿Qué es OAuth?">
    OAuth es un protocolo de autenticación que permite a los usuarios aprobar que una aplicación actúe en su nombre sin compartir su contraseña. Puedes encontrar más información en [oauth.net](http://oauth.net/).
  </Accordion>

  <Accordion title="¿Cómo genero tokens de acceso?">
    Debes tener una [X app](/es/resources/fundamentals/developer-apps) para generar tokens de acceso. Obtén más información sobre los tokens de acceso [aquí](/es/resources/fundamentals/authentication#oauth-1-0a-2). 
  </Accordion>

  <Accordion title="¿Cómo creo una X app?">
    Debes tener una [cuenta de desarrollador](/es/resources/fundamentals/developer-portal) para crear una [X app](/es/resources/fundamentals/developer-apps). Puedes registrarte [aquí](https://developer.x.com/en/portal/petition/essential/basic-info).
  </Accordion>

  <Accordion title="Si ya tengo una X app, ¿cómo veo y edito esa aplicación?">
    Puedes ver y editar tu aplicación desde el [X app dashboard](https://developer.x.com/content/developer-twitter/en/apps) si has iniciado sesión en tu cuenta de X en developer.x.com.
  </Accordion>
</AccordionGroup>

<div id="technical">
  ## Técnico
</div>

<AccordionGroup>
  <Accordion title="¿Cuánto tiempo dura un token de acceso?">
    Los tokens de acceso no caducan explícitamente. Un token de acceso se invalidará si un usuario revoca explícitamente una aplicación en la configuración de su cuenta de X, o si X suspende una aplicación. Si una aplicación se suspende, habrá una nota en el panel de la [aplicación de X](/es/resources/fundamentals/developer-apps) que indica que ha sido suspendida.
  </Accordion>

  <Accordion title="¿Qué pasa si un token de acceso se vuelve inválido?">
    Supón que el token de acceso de un usuario *puede* volverse inválido en cualquier momento. Si esto sucede, pídele al usuario que vuelva a autorizar la aplicación. Garantizar que esta situación se gestione correctamente es importante para ofrecer una buena experiencia de usuario.
  </Accordion>

  <Accordion title="La página de registro de la aplicación pregunta sobre el acceso de lectura/escritura. ¿Qué se considera una escritura?">
    Muchos usuarios confían en una aplicación para leer su información, pero no necesariamente para cambiar la información de su perfil o publicar nuevas publicaciones. Actualizar información mediante la X API (ya sea el nombre, la ubicación o añadir una nueva publicación) requiere un HTTP POST. Cualquier método de la API que requiera un HTTP POST se considera un método de escritura y requiere acceso de lectura y escritura.
  </Accordion>
</AccordionGroup>
