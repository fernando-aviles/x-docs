<div id="general">
  ## Información general
</div>

<AccordionGroup>
  <Accordion title="¿Qué es OAuth?">
    OAuth es un protocolo de autenticación que permite a los usuarios autorizar que una aplicación actúe en su nombre sin compartir su contraseña. Puedes encontrar más información en [oauth.net](http://oauth.net/).
  </Accordion>

  <Accordion title="¿Cómo genero tokens de acceso?">
    Debes tener una [X app](/es/resources/fundamentals/developer-apps) para generar tokens de acceso. Más información sobre los tokens de acceso [aquí](/es/resources/fundamentals/authentication#oauth-1-0a-2). 
  </Accordion>

  <Accordion title="¿Cómo creo una X app?">
    Debes tener una [cuenta de desarrollador](/es/resources/fundamentals/developer-portal) para crear una [X app](/es/resources/fundamentals/developer-apps). Puedes registrarte para obtener una [aquí](https://developer.x.com/en/portal/petition/essential/basic-info).
  </Accordion>

  <Accordion title="Si ya tengo una X app, ¿cómo veo y edito esa app?">
    Puedes ver y editar tu app desde el [panel de X apps](https://developer.x.com/content/developer-twitter/en/apps) si has iniciado sesión en tu cuenta de X en developer.x.com.
  </Accordion>
</AccordionGroup>

<div id="technical">
  ## Técnico
</div>

<AccordionGroup>
  <Accordion title="¿Cuánto dura un token de acceso?">
    Los tokens de acceso no tienen una caducidad explícita. Un token de acceso se invalidará si un usuario revoca explícitamente una aplicación en la configuración de su cuenta de X, o si X suspende una aplicación. Si se suspende una aplicación, habrá una nota en el panel de control de [X app](/es/resources/fundamentals/developer-apps) que indicará que ha sido suspendida.
  </Accordion>

  <Accordion title="¿Qué pasa si un token de acceso deja de ser válido?">
    Supón que el token de acceso de un usuario *puede* dejar de ser válido en cualquier momento. Si esto ocurre, solicita al usuario que vuelva a autorizar la aplicación. Asegurarse de que esta situación se gestione correctamente es importante para ofrecer una buena experiencia de usuario.
  </Accordion>

  <Accordion title="La página de registro de la aplicación pregunta sobre acceso de lectura/escritura. ¿Qué se considera una operación de escritura?">
    Muchos usuarios confían en que una aplicación lea su información, pero no necesariamente que cambie la información de su perfil de usuario o publique nuevas publicaciones. Actualizar información mediante la X API (ya sea el nombre, la ubicación o publicar una nueva publicación) requiere una solicitud HTTP POST. Cualquier método de la API que requiera una solicitud HTTP POST se considera un método de escritura y requiere permisos de lectura y escritura.
  </Accordion>
</AccordionGroup>
