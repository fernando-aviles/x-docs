<div id="bearer-token-also-known-as-app-only">
  ### Bearer Token (también conocido como solo App)
</div>

OAuth 2.0 Bearer Token autentica las solicitudes en nombre de tu [App de desarrollador](/es/resources/fundamentals/developer-apps). Como este método es específico de la App, no involucra a ningún usuario. Este método suele utilizarse para desarrolladores que necesitan acceso de solo lectura a información pública. 

Este método de autenticación requiere que envíes un Bearer Token con tu solicitud, el cual puedes generar en la sección Keys and tokens de tu App de desarrollador. A continuación se muestra un ejemplo de cómo es una solicitud con un Bearer Token falso:

```json
  curl "https://api.x.com/2/tweets?ids=1261326399320715264,1278347468690915330" \
  -H "Authorization: Bearer AAAAAAAAAAAAAAAAAAAAAFnz2wAAAAAAxTmQbp%2BIHDtAhTBbyNJon%2BA72K4%3DeIaigY0QBrv6Rp8KZQQLOTpo9ubw5Jt?WRE8avbi"
```

Las llamadas a la API que utilizan autenticación solo de aplicación están [sujetas a límites de frecuencia](/es/resources/fundamentals/rate-limits) por endpoint, a nivel de la App.

Para usar este método, necesitarás un Bearer Token, que puedes generar pasando tu API Key y Secret por el endpoint [POST oauth2/token](/es/resources/fundamentals/authentication/api-reference#post-oauth2-token), o generándolo en la sección &quot;keys and token&quot; de la configuración de tu App en la [Consola de Desarrollador](/es/resources/fundamentals/developer-portal).

Si deseas revocar un Bearer Token, puedes usar el endpoint [POST oauth2/invalidate&#95;token](/es/resources/fundamentals/authentication/api-reference#post-oauth2-invalidate-token), o hacer clic donde dice &quot;revoke&quot; junto al Bearer Token en la sección &quot;keys and tokens&quot; de la configuración de tu App.

<div id="oauth-20-authorization-code-flow-with-pkce">
  ### Flujo de código de autorización de OAuth 2.0 con PKCE
</div>

El flujo de código de autorización de OAuth 2.0 con PKCE te permite autenticarte en nombre de otra persona usuaria con mayor control sobre los ámbitos de acceso (scopes) de una aplicación y mejora los flujos de autorización entre varios dispositivos. En otras palabras, quienes desarrollan aplicaciones para personas en X tendrán más control sobre la información que su aplicación solicita a sus usuarias y usuarios, de modo que solo tengas que pedir a tus usuarios finales los datos y la información que realmente necesitas.

Este protocolo de autorización moderno te permitirá presentar a tus usuarios finales un flujo de consentimiento más optimizado para autorizar tu aplicación, que solo muestra los ámbitos de acceso específicos que les has solicitado. Esto no solo reduce tu carga de datos, sino que también puede aumentar la confianza de tus usuarios finales.
