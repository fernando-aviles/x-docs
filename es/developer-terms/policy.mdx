<div id="x-developers">
  ## X + Desarrolladores
</div>

X valora a los desarrolladores. Nos entusiasman y sorprenden las herramientas y servicios que esta comunidad crea al aprovechar el poder de los datos de X. Como parte de nuestro compromiso con esta comunidad, nuestro objetivo es proporcionar acceso a los datos que sea abierto y justo para los desarrolladores, seguro para las personas en X y beneficioso para la plataforma de X en su conjunto. Para cumplir estos objetivos, hemos elaborado la Política para Desarrolladores como una guía para ayudar a las personas a comprender nuestras reglas y expectativas sobre el uso adecuado de la API y del Contenido de X.

Esta Política para Desarrolladores (“**Política**”) proporciona reglas y pautas para los desarrolladores que interactúan con el ecosistema de aplicaciones, servicios, sitio web, páginas web y contenido de X. Forma parte de tu contrato con X, que rige el acceso a y el uso de X API y del Contenido de X (ya sea como parte del Acuerdo para Desarrolladores u otro acuerdo escrito con X). Las infracciones de la Política se consideran infracciones de tu acuerdo. Esta Política puede modificarse periódicamente sin previo aviso. Los términos en mayúsculas utilizados en esta Política que no se definan en esta Política tendrán los significados respectivos que se les atribuyen en el [Acuerdo para Desarrolladores](/es/developer-terms/agreement) o en el Acuerdo Marco de Licencia.

<div id="using-this-policy">
  ## Uso de esta política
</div>

Hemos estructurado esta política para que sea lo más fácil de seguir posible. Tenga siempre presentes las siguientes secciones de esta política mientras usa la X API y el Contenido de X:

1. **Prepárese para el éxito** - Usted es responsable de cumplir todas las políticas de X. Es importante que revise y comprenda esta Política, así como las políticas a las que enlazamos en este documento, antes de acceder a la X API y al Contenido de X. El tiempo que dedique a revisar nuestras políticas puede ahorrarle horas de trabajo adicional más adelante.

2. **La privacidad y el control son esenciales** - Proteger y defender la privacidad de las personas en X forma parte del ADN fundamental de nuestra empresa. Por ello, prohibimos el uso de datos de X de cualquier forma que sea incompatible con las expectativas razonables de privacidad de las personas. Al desarrollar sobre la X API o acceder al Contenido de X, usted desempeña un papel especial en la protección de este compromiso, principalmente respetando la privacidad de las personas y proporcionándoles transparencia y control sobre cómo se usan sus datos.

3. **Siga las Directrices de uso de la plataforma** - Obtener la aprobación para acceder a la X API y al Contenido de X es solo el primer paso. Nuestras Directrices de uso de la plataforma deben ser su primera referencia siempre que tenga preguntas sobre cómo garantizar el cumplimiento de las políticas para su uso previsto de la plataforma X.

Más abajo proporcionamos muchos más detalles sobre lo que significa cada una de estas tres secciones clave. Revíselas detenidamente para asegurarse de que su uso de la X API y del Contenido de X sea coherente con nuestras políticas.

Si consideramos que está infringiendo esta Política (o cualquier otra política de X), podemos suspender o revocar de forma permanente su acceso a la X API y al Contenido de X.

Por último, tenga en cuenta que X puede supervisar su uso de la X API para mejorar las aplicaciones de X, para examinar cualquier uso comercial y para garantizar que cumple con su caso de uso aprobado y con esta Política.

Gracias por leer, y gracias por desarrollar con nosotros. ¡Estamos deseando ver lo que crea!

<div id="set-yourself-up-for-success">
  ## Prepárate para el éxito
</div>

Puedes evitar muchos posibles inconvenientes al usar la X API si te aseguras de que tu servicio se haya creado de la manera correcta desde el primer día. Esta sección de la Política para Desarrolladores contiene reglas que todos los desarrolladores deben seguir antes de usar la X API o X Content.

Los planes Free, Basic y Pro (descritos en [developer.x.com/en](http://developer.x.com/en)) están diseñados para aficionados, creación rápida de prototipos comerciales, integraciones de productos de X en etapas iniciales y aplicaciones que dan soporte a un número limitado de usuarios finales. Si utilizas la X API y X Content más allá de este alcance, debes solicitar (o ya estar suscrito a) un plan Enterprise (tal como se describe en [developer.x.com/en](http://developer.x.com/en)).

**Revisamos todos los usos propuestos de la plataforma para desarrolladores de X para verificar el cumplimiento de las políticas, por lo que estás obligado a revelar (y actualizar, según corresponda) tu uso previsto de la X API y X Content para que se te conceda y mantengas el acceso.** Todos los desarrolladores nuevos deben [solicitar una cuenta de desarrollador](https://developer.x.com/portal/petition/essential/basic-info) para acceder a la X API. Los desarrolladores actuales sin una cuenta de desarrollador aprobada deben solicitar una, según las indicaciones de X. Como parte de este proceso, deberás proporcionarnos una descripción por escrito de los usos previstos de la X API y X Content.

La descripción de tu caso de uso es vinculante para ti, y cualquier desviación sustancial de esta puede constituir una infracción de nuestras reglas y dar lugar a medidas de cumplimiento. Debes notificarnos cualquier modificación sustancial de tu caso de uso y recibir aprobación antes de comenzar a utilizar X Content para ese nuevo propósito. No hacerlo puede dar lugar a la suspensión y cancelación de tu acceso a la API y a los datos.

**Al desarrollar sobre la X API o acceder a X Content, debes cumplir con TODAS las políticas de X.** Estas incluyen esta [Política para Desarrolladores](/es/developer-terms/policy), las [Reglas de automatización](https://help.x.com/rules-and-policies/x-automation), los [Requisitos de visualización](https://developer.x.com/developer-terms/display-requirements.html), las [Reglas de usos restringidos de la API](/es/developer-terms/restricted-use-cases), las [Reglas de X](https://help.x.com/rules-and-policies/x-rules) y los [Recursos de la marca X](https://about.x.com/who-we-are/brand-toolkit), así como cualquier otro acuerdo que celebres con X relacionado con tu uso de la X API o X Content, incluidos, entre otros, el [Acuerdo para Desarrolladores](/es/developer-terms/agreement) o un Master Licensing Agreement u Order (según corresponda). También debes cumplir con cualquier modificación de estas políticas y con cualquier política nueva que X publique. Es tu responsabilidad supervisar el uso de tu servicio y diseñarlo de forma que se eviten infracciones de las políticas de X por parte de las personas que lo utilizan. No hacerlo puede dar lugar a la suspensión o cancelación de tu acceso a la API y a X Content.

**No puedes registrar múltiples aplicaciones para un solo caso de uso o para casos de uso sustancialmente similares o superpuestos.** En este contexto, un “caso de uso” es un conjunto coherente de análisis, visualizaciones o acciones realizadas a través de una aplicación. Las versiones de una herramienta o servicio de tipo &quot;white label&quot; no están permitidas. Si planeas ofrecer versiones &quot;white label&quot; de tu aplicación, debes notificárnoslo y recibir una aprobación específica de nuestra parte.

*Como única excepción a estas reglas,* puedes crear y usar un máximo de 3 aplicaciones para las instancias de desarrollo, staging y producción del mismo servicio. Estas aplicaciones deben estar registradas en una sola cuenta y deben identificarse claramente (en el nombre y la descripción) como instancias de dev, staging y prod de un único servicio. **No puedes utilizar aplicaciones de desarrollo o de staging para fines de producción.**

**Debes mantener en privado todas las claves de API u otras credenciales de acceso.** No puedes usar, ni fomentar ni facilitar que otros usen, claves de API u otras credenciales de acceso que pertenezcan a terceros.

**Tu acuerdo de licencia con X limita tu uso de la X API y X Content. Entre otras cosas, la X API tiene límites de frecuencia que ayudan a garantizar un uso justo de los datos y a combatir el spam en la plataforma.** No puedes exceder ni eludir los límites de frecuencia, ni ninguna otra limitación o restricción descrita en esta Política o en tu acuerdo con X, indicada en el [Sitio para Desarrolladores](https://developer.x.com/) o que X te haya comunicado.

**No puedes eliminar ni modificar ningún aviso o marca de propiedad en X Content recibido a través de la X API.** Esto ayuda a garantizar que las personas sepan de dónde proviene X Content y a quién pertenece.

**Por razones de integridad de los datos y de salud de la plataforma, no puedes interferir, interceptar, interrumpir ni deshabilitar ninguna función de la X API o del servicio de X.** En otras palabras, utiliza las APIs tal como están concebidas y documentadas en [developer.x.com](https://developer.x.com/). Consulta nuestras [directrices de HackerOne](https://hackerone.com/x) para obtener más detalles sobre el uso aceptable.

<div id="privacy-and-control-are-essential">
  ## La privacidad y el control son esenciales
</div>

X se toma la privacidad en serio, y esperamos que todas las personas que usan X Content y la X API hagan lo mismo. Cualquier uso de la plataforma de desarrollo de X, la X API o X Content de una manera que sea inconsistente con las expectativas razonables de privacidad de las personas puede estar sujeto a medidas de aplicación, que pueden incluir la suspensión y la revocación del acceso a la API y a X Content.

Tu compromiso con la privacidad y el control debe extenderse a todos los usos de X Content y a todos los aspectos del servicio que desarrolles utilizando nuestra API. Para ello, las personas que usen tu servicio deben comprender y aceptar cómo utilizas sus datos y cómo accedes a X en su nombre. Esto se puede lograr proporcionando a las personas una política de privacidad clara, completa y transparente, así como garantizando que obtengas el consentimiento expreso e informado de cada persona que use tu servicio antes de realizar cualquier acción en su nombre. **Ten en cuenta que el hecho de que una persona inicie sesión en tu servicio no constituye por sí solo consentimiento.**

<div id="consent-permissions">
  ## Consentimiento y permisos
</div>

**En particular, debes obtener el consentimiento expreso e informado de las personas antes de realizar cualquiera de las siguientes acciones:**

* Realizar *cualquier* acción en su nombre. Esto incluye (entre otras cosas):
  * Publicar contenido en X
  * Seguir/dejar de seguir cuentas
  * Modificar la información del perfil o de la cuenta
  * Agregar hashtags o cualquier otro contenido a las Publicaciones

* Volver a publicar contenido al que se accede a través de medios distintos de X API u otras herramientas de X

* Usar el Contenido de X de una persona para promocionar un producto o servicio

* Almacenar contenido no público, como Mensajes Directos (DM), o cualquier otra información privada o confidencial

* Compartir o publicar contenido protegido, o cualquier otra información privada o confidencial

**Si tu servicio permite que las personas publiquen contenido en X, debes hacer lo siguiente antes de publicar:**

* Mostrar exactamente qué se va a publicar
* Dejar claro a las personas que usan tu servicio qué información de geolocalización (si la hay) se agregará al contenido

**Si tu servicio permite que las personas publiquen contenido tanto en tu servicio como en X, debes hacer lo siguiente antes de publicar:**

* Obtener permiso para publicar el contenido
* Explicar dónde vas a publicar el contenido

**Debes respetar el estado protegido y bloqueado de todo el Contenido de X. No puedes ofrecer contenido obtenido mediante el token de autenticación de una persona a otra persona que no esté autorizada a ver ese contenido.**

* **Cuentas protegidas:** El contenido de una [cuenta protegida](https://help.x.com/safety-and-security/public-and-protected-posts) solo está disponible para las personas que hayan sido aprobadas por el propietario para seguir esa cuenta. Por lo tanto, si administras un servicio que accede a cuentas protegidas, solo puedes hacerlo para ofrecer dicho contenido a las personas específicas que tengan permiso para verlo.
* **Cuentas bloqueadas:** Las personas en X pueden [bloquear](https://help.x.com/using-x/blocking-and-unblocking-accounts) el acceso a sus cuentas por cualquier motivo que elijan. La combinación de información obtenida a partir de tokens (o de cualquier otra acción basada en la API) para eludir esta decisión no está permitida.

**Dado que los Mensajes Directos (DM) son de naturaleza no pública, los servicios que proporcionan funcionalidades de DM deben tomar medidas adicionales para proteger la privacidad personal. No puedes ofrecer contenido de DM a personas que no estén autorizadas a ver ese contenido. Si tu servicio ofrece funcionalidad de DM, también debes:**

* Notificar a las personas si envías eventos de confirmación de lectura para los DM. Puedes hacerlo proporcionando un aviso directamente en tu servicio, o mostrando las confirmaciones de lectura de otras personas participantes en una conversación.
* Obtener consentimiento antes de configurar contenido multimedia para que se envíe en un DM como “shared” (es decir, reutilizable en varios DM). Si permites que contenido multimedia en un DM sea “shared”, debes proporcionar un aviso claro de que este contenido será accesible para cualquier persona que tenga la URL del contenido multimedia.

<div id="content-compliance">
  ## Cumplimiento de contenido
</div>

**Si almacenas contenido de X sin conexión, debes mantenerlo actualizado para que refleje el estado actual de ese contenido en X.** En concreto, debes eliminar o modificar cualquier contenido que poseas si se elimina o modifica en X. Esto debe hacerse tan pronto como sea razonablemente posible, o dentro de las 24 horas posteriores a la recepción de una solicitud para hacerlo por parte de X o del propietario de la cuenta de X correspondiente, o según lo exija tu acuerdo con X o la legislación aplicable. Esto debe hacerse salvo que la ley lo prohíba, y solo en ese caso con el permiso expreso y por escrito de X.

El contenido modificado puede adoptar diversas formas. Esto incluye (entre otras cosas):

* Contenido que se ha hecho privado o ha pasado a tener estado protegido
* Contenido que se ha suspendido en la plataforma
* Contenido al que se le han eliminado las etiquetas de geolocalización
* Contenido que se ha retenido o eliminado en X

<div id="off-x-matching">
  ## Emparejamiento fuera de X
</div>

**Limitamos las circunstancias en las que puedes vincular a una persona en X con información obtenida o almacenada fuera de X.** El emparejamiento fuera de X implica asociar Contenido de X, incluido un @handle de X o un id de usuario, con una persona, hogar, dispositivo, navegador u otro identificador ajeno a X. Solo puedes hacer esto si cuentas con el consentimiento expreso y voluntario de la persona antes de realizar la asociación, o según se describe a continuación.

En situaciones en las que no tengas el consentimiento expreso y voluntario de una persona para vincular su identidad en X con un identificador fuera de X, exigimos que cualquier conexión que establezcas se base únicamente en información que alguien razonablemente esperaría que se utilice para ese fin. Además, en ausencia del consentimiento expreso y voluntario de la persona, solo puedes intentar emparejar tus registros sobre alguien con una identidad en X basándote en:

* **Información proporcionada directamente a ti por la persona.** Ten en cuenta que los registros sobre personas con las que no tienes una relación previa, incluidos datos sobre individuos obtenidos de terceros, no cumplen este estándar; y/o
* **Datos públicos.** “Datos públicos” en este contexto se refiere a:
  * Información sobre una persona que hayas obtenido de un recurso público y de acceso general (como un directorio de miembros de una asociación profesional)
  * Información en X sobre una persona que esté disponible públicamente, incluida:
    * Publicaciones
    * Información de perfil, incluida la biografía de la cuenta y la ubicación declarada públicamente
    * Nombre para mostrar y @handle

<div id="your-privacy-policy">
  ## Tu política de privacidad
</div>

**Debes mostrar la política de privacidad de tu servicio a las personas antes de que puedan descargarlo, instalarlo o registrarse en tu servicio.** Debe incluir como mínimo la siguiente información:

* La información que recopilas de las personas que usan tu servicio
* Cómo utilizas y compartes esa información (incluida la que compartes con X)
* Cómo pueden ponerse en contacto contigo las personas para realizar consultas y solicitudes relacionadas con su información

Tu política de privacidad debe ser coherente con todas las leyes aplicables y ofrecer a las personas un nivel de protección que no sea inferior al de [la Política de Privacidad de X](https://x.com/privacy) y la [política de privacidad de nuestros otros servicios y filiales corporativas](https://help.x.com/rules-and-policies/x-services-and-corporate-affiliates). Debes interrumpir tu acceso a X API y el uso de todo el Contenido de X si no puedes cumplir con tu Política de Privacidad y/o con la de X.

<div id="using-geo-data">
  ## Uso de datos geográficos
</div>

**El uso de datos geográficos conlleva restricciones adicionales debido a la naturaleza sensible de esta información.** Si tu servicio añade información de ubicación a las Publicaciones, debes informar a las personas de lo siguiente:

* Cuándo añades información de ubicación
* Si añades información de ubicación como una etiqueta geográfica (geotag) o como datos de anotación
* Si tu información de ubicación se muestra como un lugar o como coordenadas geográficas

Si tu aplicación permite que las personas publiquen con su ubicación, debes cumplir íntegramente con las [directrices geográficas](/es/developer-terms/geo-guidelines) de X.

**Cualquier uso de datos de ubicación o información geográfica de forma independiente está prohibido.** No puedes (ni permitir que otros lo hagan) almacenar, agregar o almacenar en caché datos de ubicación y otra información geográfica incluida en X Content, salvo como parte de una Publicación. Por ejemplo, no puedes separar los datos de ubicación o la información geográfica de las Publicaciones para mostrar dónde han estado las personas a lo largo del tiempo. Se permiten los mapas de calor y las herramientas relacionadas que muestren actividad geográfica agregada (por ejemplo, el número de personas en una ciudad que utilizan un hashtag).

<div id="x-passwords">
  ## Contraseñas de X
</div>

**No puedes almacenar contraseñas de X ni solicitar que las personas te proporcionen directamente su contraseña de X, las credenciales de su cuenta o la información de su App de desarrollador (incluida la consumer key).** Recomendamos usar [Iniciar sesión con X](/es/fundamentals/authentication/guides/log-in-with-x) como herramienta de autenticación para vincular tu servicio con las personas en X.

<div id="platform-usage-guidelines">
  ## Directrices de uso de la plataforma

¿Te has tomado el tiempo de revisar las políticas de X y de configurar correctamente tu acceso a la API? ¿Tu servicio sigue las directrices de privacidad y control de X? Las Directrices de Uso de la Plataforma de X proporcionan la ayuda necesaria para garantizar que tu uso del Contenido de X cumpla las normas desde el primer día y a lo largo de todo el ciclo de vida de tu servicio. Sugerimos revisar estas reglas con regularidad para asegurarte de que tu integración funcione de forma segura y beneficiosa para las personas en X y para la plataforma de X en su conjunto.

<div id="spam-bots-and-automation">
  ## Spam, bots y automatización
</div>

**Está prohibido el uso de la X API y de los productos para desarrolladores para crear spam o participar en cualquier forma de manipulación de la plataforma.** Debes revisar las Reglas de X sobre [manipulación de la plataforma y spam](https://help.x.com/rules-and-policies/platform-manipulation) y asegurarte de que tu servicio no infrinja nuestras políticas ni permita que otras personas lo hagan.

**Los servicios que realizan acciones de escritura, como publicar Publicaciones, seguir cuentas o enviar Mensajes Directos, deben cumplir con las [Reglas de automatización](https://help.x.com/rules-and-policies/x-automation).** En particular, debes:

* Obtener siempre el consentimiento explícito antes de enviar a las personas [respuestas automatizadas o Mensajes Directos](https://twittercommunity.com/t/policy-clarification-automated-replies-and-mentions/94444)
* Respetar de inmediato las solicitudes de dejar de recibir comunicaciones tuyas
* Nunca realizar acciones masivas, agresivas o similares al spam, incluido el [seguimiento masivo](https://twittercommunity.com/t/policy-clarification-aggressive-following-and-inorganic-following-behavior/92769)
* Nunca publicar contenido idéntico o sustancialmente similar en [varias cuentas](https://blog.twitter.com/developer/en_us/topics/tips/2018/automation-and-the-use-of-multiple-accounts.html)

**Si gestionas una cuenta bot basada en la API, debes indicar claramente qué es la cuenta y quién es responsable de ella.** Nunca debes engañar ni confundir a las personas sobre si tu cuenta es o no un bot. Una buena manera de hacerlo es incluir en la biografía del perfil una declaración de que la cuenta es un bot.

<div id="x-performance-benchmarking">
  ## Evaluación comparativa del rendimiento de X
</div>

**No puedes usar la X API para medir la disponibilidad, el rendimiento, la funcionalidad o el uso de X con fines de evaluación comparativa, competitivos o comerciales.** Por ejemplo, nunca debes usar la X API para:

* Calcular métricas agregadas de X, como el número total de usuarios activos mensuales (MA) o usuarios activos diarios (DA)
* Calcular métricas agregadas de Publicaciones en X, como el número total de Publicaciones publicadas por día o el número de interacciones de cuentas
* Medir o analizar la capacidad de respuesta de X
* Medir o analizar el spam o la seguridad en X, salvo lo permitido a continuación

**Apoyamos la investigación que ayuda a mejorar la salud de la conversación en X.** No puedes divulgar públicamente ninguna investigación o conclusión relacionada con la X API o el Contenido de X, ni desarrollar, crear u ofrecer servicios que utilicen la X API o el Contenido de X para medir, analizar o intentar identificar comportamientos o contenido que infrinjan las políticas de X sin el permiso expreso y por escrito de X.

**Investigadores DSA:** Si necesitas ponerte en contacto con X en relación con el acceso conforme al art. 40 del Reglamento de Servicios Digitales, comunícate con [**EU-Questions@X.com**](mailto:EU-Questions@X.com). Si deseas solicitar acceso como investigador, envía una [solicitud](https://forms.gle/btDwenPF7M3hgSvw7).

<div id="public-display-of-posts">
  ## Visualización pública de Publicaciones
</div>

**Debes mantener la integridad de todo el Contenido de X que muestres públicamente o a las personas que usan tu servicio.** Si no utilizas [X for Websites](https://developer.x.com/docs/twitter-for-websites/overview) para mostrar contenido, entonces debes usar la X API para recuperar la versión más reciente disponible para mostrarlo. Si el contenido mostrado deja de estar disponible a través de la X API, debes eliminarlo de tu servicio tan pronto como sea razonablemente posible o, como máximo, dentro de las 24 horas siguientes a la recepción de una solicitud de eliminación de X, del titular de la cuenta de X correspondiente o según lo exija la legislación aplicable.

**Existen reglas específicas que debes seguir si muestras Contenido de X sin conexión.** Sigue las [directrices](https://developer.x.com/developer-terms/display-requirements) para usar Publicaciones en emisiones si muestras Publicaciones sin conexión.

**Si incrustas o muestras Publicaciones, debes ponerte en contacto con nosotros acerca de tu acceso a la X API si tu sitio supera los 10 millones de impresiones diarias.** X se reserva el derecho de exigir condiciones adicionales como requisito para tu uso de la X API. Las restricciones adicionales sobre el uso para desarrolladores de X for Websites incluyen:

* **Publicaciones incrustadas y/o líneas de tiempo incrustadas**
  * Debes proporcionar a las personas un aviso legalmente suficiente que revele completamente la recopilación y el uso por parte de X de datos sobre las actividades de navegación en tu sitio web, incluso para publicidad basada en intereses y personalización. También debes obtener el consentimiento legalmente suficiente de las personas para dicha recopilación y uso
  * Debes proporcionar instrucciones legalmente suficientes sobre cómo las personas pueden inhabilitar la publicidad basada en intereses y la personalización de X, según se describe [aquí](https://help.x.com/x-for-websites-ads-info-and-privacy)

* **Widgets de X for Websites**
  * Debes garantizar que las personas reciban información clara y completa sobre, y otorguen su consentimiento para, el almacenamiento y acceso a cookies u otra información en sus dispositivos, según se describe en el documento de [uso de cookies](https://help.x.com/rules-and-policies/x-cookies) de X, cuando la ley exija proporcionar dicha información y obtener dicho consentimiento

* **Servicios dirigidos a menores de 13 años**
  * Los servicios dirigidos a menores de 13 años deben inhabilitar la personalización de X en cualquier Publicación incrustada y/o línea de tiempo incrustada estableciendo el parámetro de exclusión en ‘true’, como se describe [aquí](https://developer.x.com/docs/twitter-for-websites/privacy)

<div id="content-redistribution">
  ## Redistribución de contenido

**El mejor lugar para obtener Contenido de X es directamente de X.
