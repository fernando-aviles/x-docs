<div id="x-developers">
  ## X + Desarrolladores
</div>

En X valoramos a los desarrolladores. Nos entusiasman y sorprenden las herramientas y servicios que esta comunidad crea aprovechando el poder de los datos de X. Como parte de nuestro compromiso con esta comunidad, nuestro objetivo es proporcionar un acceso a los datos que sea abierto y justo para los desarrolladores, seguro para las personas en X y beneficioso para la plataforma de X en su conjunto. Para avanzar en estos objetivos, hemos elaborado la Política para Desarrolladores como una guía para ayudar a las personas a entender nuestras reglas y expectativas sobre el uso apropiado de la X API y del Contenido de X.

Esta Política para Desarrolladores (“**Política**”) proporciona reglas y pautas para los desarrolladores que interactúan con el ecosistema de aplicaciones, servicios, sitio web, páginas web y contenido de X. Forma parte de tu contrato con X, que regula el acceso a y el uso de la X API y del Contenido de X (ya sea como parte del Acuerdo para Desarrolladores u otro acuerdo escrito con X). Las infracciones de la Política se consideran infracciones de tu acuerdo. Esta Política puede modificarse periódicamente sin previo aviso. Los términos en mayúscula utilizados en esta Política que no estén definidos en esta Política tendrán los respectivos significados que se les atribuyen en el [Acuerdo para Desarrolladores](/es/developer-terms/agreement) o en el Acuerdo Maestro de Licencia.

<div id="using-this-policy">
  ## Uso de esta política
</div>

Hemos estructurado esta política para que sea lo más fácil de seguir posible. Mantén presente la información de las siguientes secciones de la política mientras utilizas la X API y el Contenido de X:

1. **Prepárate para el éxito** - Eres responsable de cumplir con todas las políticas de X. Es importante que revises y comprendas esta Política, así como las políticas a las que enlazamos en este documento, antes de acceder a la X API y al Contenido de X. El tiempo que dediques a revisar nuestras políticas puede ahorrarte horas de trabajo adicional más adelante.

2. **La privacidad y el control son esenciales** - Proteger y defender la privacidad de las personas en X forma parte del ADN de nuestra empresa. Por ello, prohibimos el uso de datos de X de cualquier manera que sea incompatible con las expectativas razonables de privacidad de las personas. Al desarrollar con la X API o acceder al Contenido de X, tienes un papel especial en la protección de este compromiso, sobre todo respetando la privacidad de las personas y proporcionándoles transparencia y control sobre cómo se utiliza su información.

3. **Sigue las Directrices de uso de la plataforma** - Obtener la aprobación para acceder a la X API y al Contenido de X es solo el primer paso. Nuestras Directrices de uso de la plataforma deberían ser tu primera referencia siempre que tengas preguntas sobre cómo garantizar el cumplimiento de las políticas para tu uso previsto de la plataforma de X.

A continuación proporcionamos muchos más detalles sobre lo que significa cada una de estas tres secciones clave. Revísalas atentamente para asegurarte de que tu uso de la X API y del Contenido de X sea coherente con nuestras políticas.

Si consideramos que estás infringiendo esta Política (o cualquier otra política de X), podemos suspender o revocar de forma permanente tu acceso a la X API y al Contenido de X.

Por último, ten en cuenta que X puede supervisar tu uso de la X API para mejorar las Aplicaciones de X, examinar cualquier uso comercial y garantizar que cumples con tu caso de uso aprobado y con esta Política.

Gracias por leer, y gracias por construir con nosotros. ¡Esperamos ver lo que creas!

<div id="set-yourself-up-for-success">
  ## Prepárate para el éxito
</div>

Puedes evitar muchos posibles inconvenientes al usar la X API si te aseguras de que tu servicio se haya creado de la manera correcta desde el primer día. Esta sección de la Política para Desarrolladores contiene reglas que todos los desarrolladores deben seguir antes de usar la X API o el Contenido de X.

Los planes Free, Basic y Pro (tal como se describen en [developer.x.com/en](http://developer.x.com/en)) están diseñados para aficionados, creación de prototipos comerciales, integraciones de productos de X en etapa inicial y aplicaciones que dan soporte a un número limitado de usuarios finales. Si usas la X API y el Contenido de X más allá de este alcance, entonces debes solicitar (o ya estar suscrito a) un plan Enterprise (tal como se describe en [developer.x.com/en](http://developer.x.com/en)).

**Revisamos todos los usos propuestos de la plataforma para desarrolladores de X para verificar el cumplimiento de las políticas, por lo que debes revelar (y actualizar, según corresponda) tu uso previsto de la X API y el Contenido de X para que se te conceda y mantengas el acceso.** Todos los desarrolladores nuevos deben [solicitar una cuenta de desarrollador](https://developer.x.com/portal/petition/essential/basic-info) para acceder a la X API. Los desarrolladores actuales sin una cuenta de desarrollador aprobada deben solicitar una, según lo indique X. Como parte de este proceso, deberás proporcionarnos una descripción por escrito de tus usos previstos de la X API y el Contenido de X.

La descripción de tu caso de uso es vinculante para ti, y cualquier desviación sustancial de la misma puede constituir una violación de nuestras reglas y dar lugar a medidas de aplicación. Debes notificarnos cualquier modificación sustancial de tu caso de uso y recibir nuestra aprobación antes de comenzar a usar Contenido de X para ese nuevo propósito. No hacerlo puede resultar en la suspensión y cancelación de tu acceso a la API y a los datos.

**Al desarrollar sobre la X API o acceder al Contenido de X, debes cumplir con TODAS las políticas de X.** Estas incluyen esta [Política para Desarrolladores](/es/developer-terms/policy), las [Reglas de Automatización](https://help.x.com/rules-and-policies/x-automation), los [Requisitos de Visualización](https://developer.x.com/developer-terms/display-requirements.html), las [Reglas de Usos Restringidos de la API](/es/developer-terms/restricted-use-cases), las [Reglas de X](https://help.x.com/rules-and-policies/x-rules) y los [Recursos de Marca de X](https://about.x.com/who-we-are/brand-toolkit), así como cualquier otro acuerdo que celebres con X relacionado con tu uso de la X API o el Contenido de X, incluidos, entre otros, el [Acuerdo para Desarrolladores](/es/developer-terms/agreement) o un Acuerdo o Pedido Maestro de Licencias (según corresponda). También debes cumplir con cualquier modificación de estas políticas y con cualquier política nueva que X implemente. Es tu responsabilidad supervisar el uso de tu servicio y diseñarlo para evitar violaciones de las políticas de X por parte de las personas que lo utilizan. No hacerlo puede resultar en la suspensión o cancelación de tu acceso a la API y al Contenido de X.

**No puedes registrar múltiples aplicaciones para un solo caso de uso o para casos de uso sustancialmente similares o superpuestos.** En este contexto, un “caso de uso” es un conjunto coherente de análisis, visualizaciones o acciones realizadas a través de una aplicación. Las versiones de una herramienta o servicio de tipo &quot;white label&quot; no están permitidas. Si planeas crear versiones &quot;white label&quot; de tu aplicación, debes notificarnos y recibir nuestra aprobación por separado.

*Como única excepción a estas reglas,* puedes crear y usar un máximo de 3 aplicaciones para las instancias de desarrollo, staging (preproducción) y producción del mismo servicio. Estas apps deben estar registradas en una sola cuenta y deben identificarse claramente (en el nombre y la descripción) como instancias dev, staging y prod de un solo servicio. **No puedes usar aplicaciones de desarrollo o de staging para fines de producción.**

**Debes mantener todas las claves de API u otras credenciales de acceso en privado.** No puedes usar, ni alentar ni facilitar que otros usen, claves de API u otras credenciales de acceso que pertenezcan a otras personas.

**Tu acuerdo de licencia con X limita tu uso de la X API y el Contenido de X. Entre otras cosas, la X API tiene límites de tasa que ayudan a garantizar un uso justo de los datos y a combatir el spam en la plataforma.** No puedes exceder ni eludir los límites de tasa, ni ninguna otra limitación o restricción descrita en esta Política o en tu acuerdo con X, listada en el [Sitio para Desarrolladores](https://developer.x.com/) o que te sea comunicada por X.

**No puedes eliminar ni alterar ningún aviso o marca de propiedad en el Contenido de X recibido a través de la X API.** Esto ayuda a garantizar que las personas sepan de dónde proviene el Contenido de X y a quién pertenece.

**Por razones de integridad de los datos y de la salud de la plataforma, no puedes interferir, interceptar, interrumpir ni deshabilitar ninguna función de la X API o del servicio de X.** En otras palabras, usa las API tal como están previstas y documentadas en [developer.x.com](https://developer.x.com/). Consulta nuestras [directrices de HackerOne](https://hackerone.com/x) para obtener más detalles sobre el uso aceptable.

<div id="privacy-and-control-are-essential">
  ## La privacidad y el control son esenciales
</div>

X se toma muy en serio la privacidad, y esperamos que todas las personas que utilicen Contenido de X y la X API hagan lo mismo. Cualquier uso de la plataforma para desarrolladores de X, de la X API o del Contenido de X de un modo que no se ajuste a las expectativas razonables de privacidad de las personas puede estar sujeto a acciones de cumplimiento, que pueden incluir la suspensión y la cancelación del acceso a la X API y al Contenido de X.

Tu compromiso con la privacidad y el control debe extenderse a todos los usos del Contenido de X y a todos los aspectos del servicio que desarrolles utilizando nuestra X API. Para ello, las personas que usan tu servicio deben comprender y consentir cómo utilizas sus datos y cómo accedes a X en su nombre. Esto se puede lograr proporcionando a las personas una política de privacidad clara, exhaustiva y transparente, así como garantizando que obtengas el consentimiento expreso e informado de cada persona que use tu servicio antes de realizar cualquier acción en su nombre. **Ten en cuenta que el hecho de que una persona se autentique en tu servicio no constituye por sí solo consentimiento.**

<div id="consent-permissions">
  ## Consentimiento y permisos
</div>

**En particular, debes obtener el consentimiento expreso e informado de las personas antes de realizar cualquiera de las siguientes acciones:**

* Realizar *cualquier* acción en su nombre. Esto incluye (entre otras cosas):
  * Publicar contenido en X
  * Seguir/dejar de seguir cuentas
  * Modificar la información del perfil o de la cuenta
  * Agregar hashtags o cualquier otro contenido a las Publicaciones

* Volver a publicar contenido al que se accedió por medios distintos de la X API u otras herramientas de X

* Usar el Contenido de X de alguien para promocionar un producto o servicio

* Almacenar contenido no público como Mensajes Directos (DMs), o cualquier otra información privada o confidencial

* Compartir o publicar contenido protegido, o cualquier otra información privada o confidencial

**Si tu servicio permite que las personas publiquen contenido en X, debes hacer lo siguiente antes de publicar:**

* Mostrar exactamente qué se publicará
* Dejar claro a las personas que usan tu servicio qué información geográfica (si la hay) se agregará al contenido

**Si tu servicio permite que las personas publiquen contenido tanto en tu servicio como en X, debes hacer lo siguiente antes de publicar:**

* Obtener permiso para publicar el contenido
* Explicar dónde publicarás el contenido

**Debes respetar el estado protegido y bloqueado de todo el Contenido de X. No puedes ofrecer contenido obtenido usando el token de autenticación de una persona a otra persona que no esté autorizada para ver ese contenido.**

* **Cuentas protegidas:** El contenido de una [cuenta protegida](https://help.x.com/safety-and-security/public-and-protected-posts) solo está disponible para las personas a las que el propietario haya aprobado para seguir esa cuenta. Por lo tanto, si operas un servicio que accede a cuentas protegidas, solo puedes hacerlo para ofrecer dicho contenido a las personas específicas con permiso para ver ese contenido.
* **Cuentas bloqueadas:** Las personas en X pueden [bloquear](https://help.x.com/using-x/blocking-and-unblocking-accounts) el acceso a sus cuentas por cualquier motivo que elijan. No se permite combinar información obtenida de tokens (o realizar cualquier otra acción basada en la API) para eludir esta decisión.

**Dado que los Mensajes Directos (DMs) son de naturaleza no pública, los servicios que ofrecen funciones de DM deben tomar medidas adicionales para salvaguardar la privacidad personal. No puedes ofrecer contenido de DMs a personas que no estén autorizadas para ver ese contenido. Si tu servicio ofrece funcionalidad de DMs, también debes:**

* Notificar a las personas si envías eventos de confirmación de lectura para DMs. Puedes hacer esto proporcionando un aviso directamente en tu servicio o mostrando las confirmaciones de lectura de otros participantes en una conversación.
* Obtener consentimiento antes de configurar contenido multimedia para enviarse en un DM como &quot;compartido&quot; (es decir, reutilizable en varios DMs). Si permites que el contenido multimedia en un DM sea &quot;compartido&quot;, debes proporcionar un aviso claro de que este contenido será accesible para cualquier persona que tenga la URL del contenido.

<div id="content-compliance">
  ## Cumplimiento del contenido
</div>

**Si almacenas Contenido de X sin conexión, debes mantenerlo actualizado con el estado vigente de ese contenido en X.** En particular, debes eliminar o modificar cualquier contenido que tengas si se elimina o modifica en X. Esto debe hacerse tan pronto como sea razonablemente posible, o dentro de las 24 horas siguientes a la recepción de una solicitud en tal sentido por parte de X o del titular de la cuenta de X correspondiente, o según lo exija tu acuerdo con X o la legislación aplicable. Esto debe hacerse salvo que la ley lo prohíba, y en ese caso únicamente con el permiso expreso y por escrito de X.

El contenido modificado puede adoptar diversas formas. Esto incluye (entre otras):

* Contenido que se haya hecho privado o que haya pasado a tener estado protegido
* Contenido que haya sido suspendido de la plataforma
* Contenido al que se le hayan eliminado las etiquetas de geolocalización
* Contenido que se haya retenido o retirado de X

<div id="off-x-matching">
  ## Coincidencias fuera de X
</div>

**Limitamos las circunstancias en las que puedes vincular a una persona en X con información obtenida o almacenada fuera de X.** La coincidencia fuera de X implica asociar Contenido de X, incluido un @handle de X o un user ID de X, con una persona, un hogar, un dispositivo, un navegador u otro identificador fuera de X. Solo puedes hacer esto si cuentas con el consentimiento expreso y específico (opt‑in) de la persona antes de realizar la asociación, o según se describe a continuación.

En las situaciones en las que no cuentes con el consentimiento expreso y específico (opt‑in) de una persona para vincular su identidad en X con un identificador fuera de X, exigimos que cualquier conexión que establezcas se base únicamente en información que alguien razonablemente esperaría que se utilizara con ese fin. Además, en ausencia del consentimiento expreso y específico (opt‑in) de la persona, solo puedes intentar hacer coincidir tus registros sobre alguien con una identidad en X basándote en:

* **Información proporcionada directamente a ti por la persona.** Ten en cuenta que los registros sobre personas con las que no tienes una relación previa, incluidos los datos sobre personas obtenidos de terceros, no cumplen esta norma; y/o
* **Datos públicos.** En este contexto, “datos públicos” se refiere a:
  * Información sobre una persona que hayas obtenido de un recurso público y de acceso general (como un directorio de miembros de una asociación profesional)
  * Información en X sobre una persona que esté disponible públicamente, incluidos:
    * Publicaciones
    * Información de perfil, incluida la biografía de la cuenta y la ubicación declarada públicamente
    * Nombre para mostrar y @handle

<div id="your-privacy-policy">
  ## Tu política de privacidad
</div>

**Debes mostrar la política de privacidad de tu servicio a las personas antes de permitirles descargar, instalar o registrarse en tu servicio.** Debe incluir como mínimo la siguiente información:

* La información que recopilas de las personas que usan tu servicio
* Cómo utilizas y compartes esa información (incluida la que compartas con X)
* Cómo pueden ponerse en contacto contigo para realizar consultas y solicitudes relacionadas con su información

Tu política de privacidad debe ser coherente con todas las leyes aplicables y debe ofrecer un nivel de protección para las personas que no sea inferior al de la [Política de Privacidad de X](https://x.com/privacy) y la [política de privacidad de nuestros otros servicios y afiliadas corporativas](https://help.x.com/rules-and-policies/x-services-and-corporate-affiliates). Debes interrumpir tu acceso a la X API y dejar de utilizar todo el Contenido de X si no puedes cumplir con tu Política de Privacidad y/o la de X.

<div id="using-geo-data">
  ## Uso de datos geográficos
</div>

**El uso de datos geográficos conlleva restricciones adicionales debido a la naturaleza sensible de esta información.** Si tu servicio añade información de ubicación a las Publicaciones, debes informar a las personas:

* Cuándo añades información de ubicación
* Si añades la información de ubicación como geoetiqueta o como datos de anotaciones
* Si tu información de ubicación se indica como un lugar o como coordenadas geográficas

Si tu aplicación permite que las personas publiquen con su ubicación, debes cumplir íntegramente con las [geo guidelines](/es/developer-terms/geo-guidelines) de X.

**Cualquier uso de datos de ubicación o información geográfica de forma independiente está prohibido.** No puedes (ni puedes permitir que otros lo hagan) almacenar, agregar o guardar en caché datos de ubicación y otra información geográfica contenida en el Contenido de X, salvo como parte de una Publicación. Por ejemplo, no puedes separar los datos de ubicación o la información geográfica de las Publicaciones para mostrar dónde han estado las personas a lo largo del tiempo. Se permiten los mapas de calor y las herramientas relacionadas que muestren actividad geográfica agregada (por ejemplo, el número de personas en una ciudad que usan un hashtag).

<div id="x-passwords">
  ## Contraseñas de X
</div>

**No debes almacenar contraseñas de X ni solicitar que las personas te proporcionen directamente su contraseña de X, las credenciales de su cuenta o la información de su App de desarrollador (incluida la consumer key).** Recomendamos utilizar [Sign-in with X](/es/fundamentals/authentication/guides/log-in-with-x) como herramienta de autenticación para conectar tu servicio con las personas en X.

Las Pautas de uso de la plataforma de X ofrecen la orientación necesaria para garantizar que el uso que haces del Contenido de X sea conforme a las normas desde el primer día y durante todo el ciclo de vida de tu servicio. Te recomendamos revisar estas reglas con regularidad para asegurarte de que tu integración funcione de forma segura y beneficiosa para las personas en X y para la plataforma de X en su conjunto.

<div id="spam-bots-and-automation">
  ## Spam, bots y automatización
</div>

**Está prohibido usar la X API y los productos para desarrolladores para crear spam o participar en cualquier forma de manipulación de la plataforma.** Debes revisar las Reglas de X sobre [manipulación de la plataforma y spam](https://help.x.com/rules-and-policies/platform-manipulation) y asegurarte de que tu servicio no infrinja nuestras políticas ni permita a otras personas infringirlas.

**Los servicios que realizan acciones de escritura, incluida la publicación de Publicaciones, seguir cuentas o enviar Mensajes Directos, deben cumplir las [Reglas de automatización](https://help.x.com/rules-and-policies/x-automation).** En particular, debes:

* Obtener siempre el consentimiento explícito antes de enviar a las personas [respuestas automatizadas o Mensajes Directos](https://twittercommunity.com/t/policy-clarification-automated-replies-and-mentions/94444)
* Respetar de inmediato las solicitudes para dejar de recibir comunicaciones tuyas
* Nunca realizar acciones masivas, agresivas o con apariencia de spam, incluido el [seguimiento masivo](https://twittercommunity.com/t/policy-clarification-aggressive-following-and-inorganic-following-behavior/92769)
* Nunca publicar contenido idéntico o sustancialmente similar en [varias cuentas](https://blog.twitter.com/developer/en_us/topics/tips/2018/automation-and-the-use-of-multiple-accounts.html)

**Si estás operando una cuenta bot basada en la API, debes indicar claramente en qué consiste la cuenta y quién es responsable de ella.** Nunca debes engañar ni confundir a las personas sobre si tu cuenta es o no un bot. Una buena forma de hacerlo es incluir en la biografía del perfil una declaración de que la cuenta es un bot.

<div id="x-performance-benchmarking">
  ## Evaluación comparativa del rendimiento de X
</div>

**No puede usar la X API para medir la disponibilidad, el rendimiento, la funcionalidad o el uso de X con fines de evaluación comparativa, competitivos o comerciales.** Por ejemplo, nunca debe usar la X API para:

* Calcular métricas agregadas de X, como el número total de Usuarios Activos Mensuales (MAs) o Usuarios Activos Diarios (DAs)
* Calcular métricas agregadas de Publicaciones de X, como el número total de Publicaciones realizadas por día o el número de interacciones con cuentas
* Medir o analizar la capacidad de respuesta de X
* Medir o analizar el spam o la seguridad en X, salvo lo permitido a continuación

**Apoyamos la investigación que ayuda a mejorar la salud de las conversaciones en X.** No puede divulgar públicamente ninguna investigación ni hallazgo relacionado con la X API o Contenido de X, ni desarrollar, crear u ofrecer servicios que utilicen la X API o Contenido de X y que midan, analicen o intenten identificar comportamientos o contenido que infrinjan las políticas de X sin el permiso expreso y por escrito de X.

**Investigadores DSA:** Si necesita ponerse en contacto con X en relación con el acceso en virtud del art. 40 de la Digital Services Act, escriba a [**EU-Questions@X.com**](mailto:EU-Questions@X.com). Si desea solicitar acceso como investigador, envíe una [solicitud](https://forms.gle/btDwenPF7M3hgSvw7).

<div id="public-display-of-posts">
  ## Exhibición pública de Publicaciones
</div>

**Debes mantener la integridad de todo el Contenido de X que muestres públicamente o a las personas que usan tu servicio.** Si no utilizas [X para sitios web](https://developer.x.com/docs/twitter-for-websites/overview) para mostrar contenido, entonces debes usar la X API para recuperar la versión más reciente disponible para su exhibición. Si el contenido mostrado deja de estar disponible a través de la X API, entonces debes retirarlo de tu servicio tan pronto como sea razonablemente posible, o dentro de las 24 horas posteriores a la recepción de una solicitud de retirada por parte de X, del titular de la cuenta de X correspondiente, o según lo exija la ley aplicable.

**Existen reglas específicas que debes seguir si muestras Contenido de X sin conexión.** Sigue las [directrices](https://developer.x.com/developer-terms/display-requirements) para el uso de Publicaciones en emisiones si muestras Publicaciones sin conexión.

**Si incrustas o muestras Publicaciones, debes ponerte en contacto con nosotros sobre tu acceso a la X API si tu sitio supera los 10 millones de impresiones diarias.** X se reserva el derecho de exigir términos adicionales como condición para tu uso de la X API. Las restricciones adicionales sobre el uso de X para sitios web por parte de desarrolladores incluyen:

* **Publicaciones incrustadas y/o cronologías incrustadas**
  * Debes proporcionar a las personas un aviso legalmente suficiente que revele por completo la recopilación y el uso, por parte de X, de datos sobre las actividades de navegación en tu sitio web, incluso para publicidad basada en intereses y personalización. También debes obtener el consentimiento legalmente suficiente de las personas para dicha recopilación y uso
  * Debes proporcionar instrucciones legalmente suficientes sobre cómo las personas pueden optar por no recibir la publicidad basada en intereses y la personalización de X, según se describe [aquí](https://help.x.com/x-for-websites-ads-info-and-privacy)

* **Widgets de X para sitios web**
  * Debes asegurarte de que se proporcione a las personas información clara y completa sobre el almacenamiento y el acceso a cookies u otra información en sus dispositivos, y que presten su consentimiento a ello, según se describe en el documento de X sobre [uso de cookies](https://help.x.com/rules-and-policies/x-cookies), cuando la ley exija proporcionar dicha información y obtener dicho consentimiento

* **Servicios dirigidos a menores de 13 años**
  * Los servicios dirigidos a menores de 13 años deben inhabilitar la personalización de X en cualquier Publicación incrustada y/o cronologías incrustadas configurando el parámetro de exclusión voluntaria como ‘true’, según se describe [aquí](https://developer.x.com/docs/twitter-for-websites/privacy)

<div id="content-redistribution">
  ## Redistribución de contenido
</div>

**El mejor lugar para obtener Contenido de X es directamente de X. En consecuencia, restringimos la redistribución de Contenido de X a terceros.** Si proporcionas Contenido de X a terceros, incluidos conjuntos de datos descargables o a través de una API, solo puedes distribuir Post IDs, Direct Message IDs y/o User IDs (salvo lo descrito a continuación).

En total, no puedes distribuir más de 1,500,000 Post IDs a ninguna entidad (incluidas múltiples personas asociadas a una misma entidad) dentro de cualquier período de 30 días, a menos que hayas recibido autorización por escrito de X. Además, los desarrolladores pueden proporcionar hasta 500 Post Objects públicos y/o User Objects a cada persona que use tu servicio diariamente si esto se hace mediante medios no automatizados (por ejemplo, la descarga de hojas de cálculo o archivos PDF).

Se permite a los investigadores académicos distribuir Post IDs y/o User IDs únicamente con fines de investigación no comercial en nombre de una institución académica, y que haya sido aprobada por escrito por X, o para la revisión por pares o validación de dicha investigación. Solo se podrán utilizar tantos Post IDs o User IDs como sean necesarios para dicha investigación y que hayan sido aprobados por X.

Todo Contenido de X proporcionado a terceros sigue estando sujeto a esta Política, y dichos terceros deben aceptar los [Términos de servicio](https://x.com/tos) de X, la [Política de privacidad](https://x.com/privacy), el [Acuerdo de desarrollador](/es/developer-terms/agreement) y la [Política para desarrolladores](/es/developer-terms/policy) antes de recibir dichas descargas. No puedes permitir que ninguna entidad eluda otras limitaciones o restricciones sobre la distribución de Contenido de X incluidas en esta [Política](/es/developer-terms/policy), en el [Acuerdo de desarrollador](/es/developer-terms/agreement) o en cualquier otro acuerdo con X.

**Nota:** Esta Sección no se aplica a los investigadores con acceso a X API en virtud del art. 40 de la Ley de Servicios Digitales de la UE (2022) (“**DSA**”), quienes en su lugar están sujetos a los procedimientos y restricciones establecidos en la DSA y en el Acuerdo de desarrollador.

<div id="pay-to-engage">
  ## Pagar por interactuar
</div>

**Tu servicio no debe compensar a las personas por realizar acciones en X, ya que eso genera interacciones no auténticas que perjudican la salud de la plataforma.** Al usar la X API no puedes vender ni recibir compensación monetaria o virtual por ninguna acción en X. Esto incluye, entre otros, Publicaciones, seguir cuentas, dejar de seguir cuentas, reposts, Me gusta, comentarios y respuestas.

<div id="service-authenticity">
  ## Autenticidad del servicio
</div>

**Debes identificar claramente tu servicio para que las personas puedan comprender su origen y propósito.** No utilices nombres, logotipos o URL que oculten la identidad y las funciones de tu servicio, o que impliquen falsamente una afiliación con X o con terceros. Ten en cuenta que está prohibido crear aplicaciones con el propósito de vender nombres o impedir que otras personas los usen.

**No puedes usar ninguna URL (incluidas las URL acortadas) para tu servicio que dirija a las personas a:**

* Un sitio que no esté relacionado con tu servicio
* Un sitio de spam o malware
* Un sitio que incite a las personas a infringir las políticas de X

<div id="x-name-logo-and-likeness">
  ## Nombre, logotipo e imagen de X
</div>

**Solo puedes usar y mostrar el nombre y el logotipo de X para identificar a X como la fuente del Contenido de X.** Nunca debes usar el nombre y el logotipo de X, la insignia del programa X Official Partner Program ni ninguna otra marca o nombre similar de una manera que cree una falsa impresión de respaldo, patrocinio o asociación con X. Los [recursos de marca](https://about.x.com/who-we-are/brand-toolkit) de X contienen información detallada para ayudarte a usar la marca X de la manera correcta.

**Solo puedes usar la insignia de cuenta verificada de X (X Verified Account badge) y cualquier otra categorización mejorada de cuentas tal como te la comunique X a través de la API.** Esto ayuda a que las personas sepan que el contenido que muestra tu servicio es equivalente al que se muestra en X.

<div id="advertising-on-x">
  ## Publicidad en X
</div>

**Existen restricciones sobre cómo y dónde puedes mostrar publicidad en relación con Contenido de X.** Para empezar, tus anuncios no pueden parecerse a una Publicación ni poder confundirse razonablemente con una. Otras normas sobre publicidad incluyen:

* **Debe existir una separación clara entre el Contenido de X y tus anuncios.** No puedes colocar ningún anuncio dentro de la cronología de X, aparte de los X Ads.
* **X se reserva el derecho a mostrar publicidad a través de la X API.** Si decides mostrar X Ads una vez que empecemos a distribuirlos a través de la API, compartiremos contigo una parte de los ingresos publicitarios de acuerdo con los términos y condiciones pertinentes.
* **No puedes usar Contenido de X ni información obtenida de la X API para dirigir publicidad a personas fuera de la plataforma de X.**

<div id="x-login">
  ## Inicio de sesión con X
</div>

**Debes ofrecer a las personas opciones fáciles de encontrar para iniciar y cerrar sesión en X, por ejemplo, mediante el protocolo OAuth.** La opción *Iniciar sesión con X* debe mostrarse al menos con la misma visibilidad que cualquier otra función de registro o inicio de sesión en tu servicio. También debes ofrecer a las personas que no tengan una cuenta de X la oportunidad de crear una cuenta en X.

**Una vez que alguien en tu servicio se autentique mediante *Iniciar sesión con X* debes mostrar claramente su identidad en X.** La identidad en X incluye el @handle actual de la persona en X, el avatar y el logotipo de X. Cualquier visualización en tu servicio de los seguidores de alguien en X debe mostrar claramente que la relación está asociada con X.

<div id="x-cards">
  ## X Cards
</div>

**Para garantizar una experiencia de calidad, debes desarrollar tu Card para que se muestre correctamente en todas las plataformas donde se presenten Cards.** Entre las reglas adicionales que debes seguir al usar Cards se incluyen:

* Debes marcar tu Publicación como &quot;true&quot; para contenido multimedia sensible si planeas mostrar dicho contenido dentro de una Card
* Debes usar HTTPS para alojar todos los recursos dentro de tu Card. Tu Card nunca debe generar advertencias activas del navegador sobre contenido mixto
* El contenido de audio y video debe incluir controles para detener o pausar y, en el caso de videos que se reproduzcan automáticamente, debe tener el sonido desactivado de forma predeterminada

**No puedes exceder ni eludir las limitaciones de X aplicadas a cualquier Card, incluido el uso previsto de la Card.** Entre las restricciones adicionales sobre el uso de Cards se incluyen:

* No puedes colocar contenido patrocinado de terceros dentro de Cards sin la aprobación de X
* No puedes adjuntar incentivos monetarios (incluida la moneda virtual) dentro de tu Card o en X desde tu Card
* No puedes incluir contenido o acciones dentro de tu Card que sean engañosos o que no sean contextualmente relevantes, como URL y contenido multimedia.
* Solo puedes adjuntar una App Card a una Publicación cuando alguien esté promoviendo o mencionando explícitamente la app en la Publicación
