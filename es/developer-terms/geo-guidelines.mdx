<div id="introduction">
  ## Introducción
</div>

Publicar con ubicación es la función de geolocalización en la X API. Esta función ayuda a proporcionar una experiencia más significativa para los usuarios al hacer que las publicaciones tengan más contexto. Por ejemplo, “¡Fuegos artificiales!” es mucho más relevante cuando se asocia con una ubicación: “¡Fuegos artificiales!” desde el barrio SoMa en San Francisco, California. Esperamos colaborar con el ecosistema de desarrolladores para crear experiencias excelentes en torno a esta funcionalidad.

<div id="user-privacy-and-user-control-of-their-location-information">
  ## Privacidad del usuario y control del usuario sobre su información de ubicación
</div>

Para garantizar una experiencia segura y satisfactoria, los desarrolladores deben ser respetuosos con la privacidad del usuario cuando gestionan su ubicación, así como proporcionar una coherencia mínima en la experiencia de “Publicar con ubicación”. A continuación se indican algunos puntos clave que deben tenerse en cuenta y que ayudan a proteger la privacidad del usuario y a garantizar que los usuarios comprendan el impacto de sus acciones:

<div id="general-guidelines">
  ## Directrices generales
</div>

* Los usuarios deben dar su consentimiento para usar la función Publicar con ubicación (activar la ubicación).
* Los usuarios deben otorgar un permiso explícito para que su ubicación exacta se muestre junto con sus publicaciones. Si la función de ubicación en tu cliente es “persistente”, es decir, una vez que se activa la ubicación siempre acompaña a una publicación, es posible que desees mostrar solo nombres de lugares (place&#95;ids) y permitir que los usuarios acepten además compartir la latitud y longitud exactas por cada publicación o como un ajuste alternativo específico.
* Cuando accedas a los datos de ubicación de tus usuarios para publicar una publicación, no debes almacenar esa información por separado de la publicación sin el permiso explícito del usuario.
* Debe quedar claro para los usuarios qué nivel de información de ubicación, si la hay, se mostrará asociada con su publicación. Una forma de hacer esto es mostrar un mapa de cómo se presentará esta información antes de que se publique la publicación. Si la latitud y longitud exactas forman parte de la información (o son la única información) publicada por el usuario en el cliente, debe quedar claro para el usuario que se publicarán sus coordenadas exactas.
* Los usuarios deben poder activar y desactivar su ubicación cada vez que redacten una publicación.
* Debes seguir los términos de la [Developer Policy](/es/developer-terms/policy.html) de X, incluida la obligación de no agregar, almacenar en caché ni guardar datos de ubicación y otra información geográfica procedente de la X API, excepto como parte de una publicación, y no puedes usar dichos datos de ubicación o información geográfica de forma independiente.

<div id="specific-examples">
  ## Ejemplos específicos
</div>

Ejemplo 1: *Sin añadir explícitamente latitud y longitud (esta es la interfaz de usuario actual del X Web Client)*

1. Mostrar un enlace a “Añadir tu ubicación” cuando un usuario redacte una publicación.
2. En segundo plano, usar la llamada a la API de X [reverse&#95;geocode](https://developer.x.com/en/docs/geo/places-near-location/api-reference/get-geo-reverse_geocode.html) y pasar la latitud, la longitud, la precisión de tu ubicación y la granularidad preferida del usuario (que, de forma predeterminada, es “vecindario”).
3. Mostrar el nombre del lugar predeterminado (X intentará ordenarlos de una manera que tenga sentido; el orden es tal que un cliente de X puede simplemente mostrar la lista sin necesidad de modificarla).
4. Permitir que el usuario seleccione una ubicación diferente de la lista (por ejemplo, cambiar de “SoMa, San Francisco” a “South Beach, San Francisco”).
5. Importante: Sé transparente con el usuario si vas a mostrar información de ubicación exacta. Asegúrate de que el usuario sepa si se mostrará información de ubicación exacta.
6. Permitir que el usuario elija activar o desactivar la ubicación cada vez que redacte una publicación.

Ejemplo 2: *Implementaciones de geotagging existentes*

Varias aplicaciones cliente de X tienen implementada la función original de geotagging (que solo transmitía lat/lon sin proporcionar place&#95;IDs). El comportamiento predeterminado de la API imita este comportamiento; es decir, como desarrollador no necesitas hacer ningún cambio en tu aplicación existente para mantener el comportamiento actual. De hecho, si simplemente pasas una coordenada lat/lon a X, X realizará automáticamente la geocodificación inversa de esa latitud y longitud y mostrará el place&#95;ID además de la lat/lon para las áreas donde tengamos datos disponibles.

Asegúrate de que sea transparente para tus usuarios que sus coordenadas exactas se están utilizando y mostrando en X. Una buena práctica para las aplicaciones existentes sería permitir a los usuarios activar o desactivar su ubicación para cada publicación. También puedes permitir que tus usuarios compartan solo place&#95;IDs en lugar de coordenadas exactas como una configuración predeterminada “persistente”.

<div id="x-storage-of-user-location-data">
  ## Almacenamiento de datos de ubicación del usuario por parte de X
</div>

X almacenará los datos enviados por el cliente de la siguiente manera:

* X guardará todos los datos que un usuario decida mostrar públicamente a sus seguidores. Esto es similar a cómo X almacena la marca de tiempo que indica cuándo se realizó la publicación, lo que significa que, si un usuario publica con sus coordenadas exactas, X almacenará esta ubicación exacta junto con la publicación durante todo el tiempo que la publicación exista. Los usuarios pueden borrar los datos de ubicación de sus publicaciones haciendo clic en el botón “clear my location history” en la página de Configuración, como se describe [aquí](https://support.twitter.com/articles/122236-how-to-tweet-with-your-location).

<div id="summary">
  ## Resumen
</div>

La incorporación de la ubicación a una publicación aporta una enorme cantidad de contexto y valor desde la perspectiva del usuario. Sin embargo, las implementaciones de ubicación en tu cliente deben tratar la privacidad y la transparencia hacia el usuario como consideraciones clave al diseñar un producto centrado en la ubicación.

Si tienes alguna pregunta o comentario sobre privacidad, ubicación u otras funciones de geolocalización, por favor [contáctanos.](https://support.twitter.com/forms/platform)
