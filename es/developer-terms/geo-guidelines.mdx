<div id="introduction">
  ## Introducción
</div>

Posting With Location es la función de geoetiquetado en la X API. Esta función ayuda a ofrecer una experiencia más significativa a los usuarios al proporcionar más contexto a las publicaciones. Por ejemplo, “¡Fuegos artificiales!” es mucho más relevante cuando se asocia con una ubicación: “¡Fuegos artificiales!” desde el barrio de SoMa en San Francisco, California. Esperamos seguir trabajando con el ecosistema de desarrolladores para crear excelentes experiencias en torno a esta funcionalidad.

<div id="user-privacy-and-user-control-of-their-location-information">
  ## Privacidad del usuario y control sobre su información de ubicación
</div>

Para garantizar una experiencia segura y satisfactoria, los desarrolladores deben ser cuidadosos con la privacidad del usuario al gestionar su ubicación, además de proporcionar una coherencia básica en la experiencia de “Publicar con ubicación”. A continuación se indican algunos puntos clave a tener en cuenta que ayudan a proteger la privacidad del usuario y a garantizar que los usuarios entiendan el impacto de sus acciones:

<div id="general-guidelines">
  ## Directrices generales
</div>

* Los usuarios deben aceptar explícitamente usar la función «Publicar con ubicación» (activar la ubicación).
* Los usuarios deben dar un permiso explícito para que su ubicación exacta se muestre junto con sus publicaciones. Si la función de ubicación en tu cliente es “persistente”, es decir, una vez que se activa la ubicación siempre acompaña a una publicación, es posible que quieras mostrar solo nombres de lugares (`place_ids`) y permitir que los usuarios acepten además mostrar la latitud y longitud exactas para cada publicación o como una configuración alternativa específica.
* Cuando accedas a los datos de ubicación de tus usuarios para publicar una publicación, no debes almacenar esa información por separado de la publicación sin el permiso explícito del usuario.
* Debe quedar claro para los usuarios qué nivel de información de ubicación, si la hubiera, se mostrará asociada con su publicación. Una forma de hacer esto es mostrar un mapa de cómo se representará esta información antes de que la publicación se publique. Si la latitud y longitud exactas forman parte de la información (o son la única información) publicada por el usuario en el cliente, debe quedar claro para el usuario que sus coordenadas exactas se publicarán.
* Los usuarios deben poder activar y desactivar su ubicación cada vez que redacten una publicación.
* Debes cumplir los términos de la [Developer Policy](/es/developer-terms/policy.html) de X, incluido el requisito de que no puedes agregar, almacenar en caché ni guardar datos de ubicación y otra información geográfica de la X API, salvo como parte de una publicación, y no puedes utilizar dichos datos de ubicación o información geográfica de forma independiente.

<div id="specific-examples">
  ## Ejemplos específicos
</div>

Ejemplo 1: *Sin añadir latitud y longitud explícitas (esta es la interfaz de usuario actual del X Web Client)*

1. Mostrar un enlace a “Agregar tu ubicación” cuando un usuario redacta una publicación;
2. En segundo plano, usar la llamada a la API [reverse&#95;geocode](https://developer.x.com/en/docs/geo/places-near-location/api-reference/get-geo-reverse_geocode.html) de X y pasar la latitud, la longitud, la precisión de tu posición y la granularidad preferida del usuario (que, de forma predeterminada, es “vecindario”);
3. Mostrar el nombre del lugar predeterminado (X intentará ordenarlos de una manera que tenga sentido; el orden es tal que un cliente de X puede simplemente mostrar la lista sin necesidad de modificarla);
4. Permitir que el usuario seleccione una ubicación diferente de la lista (por ejemplo, cambiar de “SoMa, San Francisco” a “South Beach, San Francisco”).
5. Importante: Sé transparente con el usuario si vas a mostrar información de ubicación exacta. Asegúrate de que el usuario sepa si se mostrará información de ubicación exacta.
6. Permitir que el usuario pueda activar o desactivar la ubicación cada vez que redacte una publicación.

Ejemplo 2: *Implementaciones de georreferenciación existentes*

Varias aplicaciones cliente de X tienen implementada la función original de georreferenciación (que solo transmite lat/long sin proporcionar place&#95;IDs). El comportamiento predeterminado de la API imita este comportamiento; es decir, como desarrollador no necesitas hacer ningún cambio en tu aplicación existente para mantener el comportamiento actual. De hecho, si simplemente pasas una coordenada lat/long a X, X realizará automáticamente la geocodificación inversa de esa latitud y longitud y mostrará el place&#95;ID además de la lat/long en las áreas donde tengamos datos disponibles.

Asegúrate de que sea transparente para tus usuarios que sus coordenadas exactas se están usando y mostrando en X. Una práctica recomendada para las aplicaciones existentes sería permitir a los usuarios activar o desactivar su ubicación por cada publicación. También puedes permitir que tus usuarios compartan solo place&#95;IDs en lugar de coordenadas exactas como una configuración predeterminada “persistente”.

<div id="x-storage-of-user-location-data">
  ## Almacenamiento de datos de ubicación de usuarios por parte de X
</div>

X almacenará los datos enviados por el cliente de la siguiente manera:

* X guardará todos los datos que un usuario elija mostrar públicamente a sus seguidores. Esto es similar a cómo X almacena la marca de tiempo que indica cuándo se hizo la publicación; es decir, si un usuario publica con sus coordenadas exactas, X almacenará esta ubicación exacta junto con la publicación durante todo el tiempo que esta exista. Los usuarios pueden borrar los datos de ubicación de sus publicaciones haciendo clic en el botón “clear my location history” en la página de Configuración, como se describe [aquí](https://support.twitter.com/articles/122236-how-to-tweet-with-your-location)).

<div id="summary">
  ## Resumen
</div>

La incorporación de ubicación a una publicación añade una enorme cantidad de contexto y valor desde la perspectiva del usuario. Sin embargo, las implementaciones de ubicación en tu cliente deben realizarse con cuidado y tener la privacidad y la transparencia para el usuario como consideraciones clave al diseñar un producto centrado en la ubicación.

Si tienes alguna pregunta o comentario sobre privacidad, ubicación u otras funciones de geolocalización, por favor [contáctanos.](https://support.twitter.com/forms/platform)
