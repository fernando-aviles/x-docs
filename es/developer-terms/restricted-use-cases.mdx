El uso de nuestra plataforma para desarrolladores requiere que revises y aceptes nuestro [Acuerdo y Política para Desarrolladores](/es/developer-terms/agreement), así como nuestras políticas relacionadas, incluidas las [Display Requirements](https://developer.x.com/en/developer-terms/display-requirements.html) y las [Automation Rules](https://help.twitter.com/en/rules-and-policies/twitter-automation). Entre otras cosas, nuestros acuerdos y políticas ofrecen orientación sobre varios casos de uso restringidos. A continuación, proporcionamos información adicional sobre algunas de estas restricciones.

<div id="sensitive-information">
  ## Información sensible
</div>

Debes tener cuidado al usar datos de X para derivar o inferir características potencialmente sensibles sobre las personas usuarias de X. Nunca debes derivar ni inferir, ni almacenar información derivada o inferida, sobre un usuario de X en relación con su:

* Salud (incluido el embarazo)
* Situación o condición financiera negativa
* Afiliación o creencias políticas
* Origen racial o étnico
* Afiliación o creencias religiosas o filosóficas
* Vida sexual u orientación sexual
* Pertenencia a un sindicato
* Presunta o real comisión de un delito

Se permite el análisis agregado del contenido de X que no almacene ningún dato personal (por ejemplo, user IDs, usernames y otros identificadores), siempre que el análisis también cumpla con las leyes aplicables y con todas las disposiciones del Developer Agreement and Policy.

<div id="off-x-matching">
  ## Coincidencias fuera de X
</div>

Las coincidencias fuera de X consisten en asociar contenido de X, incluido un nombre de usuario de X o un id de usuario, con una persona, un hogar, un dispositivo, un navegador u otro identificador ajeno a X. Un ejemplo sería asociar un nombre de usuario de X con los registros de clientes de una empresa (es decir, “John Doe” en tu registro de clientes corresponde a @johndoe en X).

Queremos que las personas se sientan cómodas creando una identidad separada y, si lo desean, seudónima en X. Si tienes la intención de asociar cualquier información sobre un usuario de X con un identificador ajeno a X, exigimos que obtengas el consentimiento expreso y voluntario (opt-in) del usuario antes de realizar la asociación. Por ejemplo, puedes obtener este consentimiento si el usuario comparte directamente contigo su nombre de usuario de X como parte de un proceso de registro en tu servicio.

En situaciones en las que no tengas el consentimiento expreso y voluntario de un usuario para vincular su identidad en X con un identificador ajeno a X, exigimos que cualquier conexión que establezcas se base únicamente en información que un usuario pueda razonablemente esperar que se utilice para ese fin. Si un usuario se sorprendería al saber que estás utilizando la información que proporcionó para vincular su cuenta de X con una identidad fuera de X, no lo hagas. Además, en ausencia del consentimiento expreso y voluntario de una persona, solo puedes intentar hacer coincidir tus registros sobre alguien con una identidad en X basándote en:

* **Información proporcionada directamente a ti por el usuario.** Los registros sobre personas con las que no tienes una relación previa, incluidos los datos sobre personas obtenidos de terceros, no cumplen esta norma; y/o
* **Datos públicos.** En este contexto, “datos públicos” se refiere a:
  * Información sobre un usuario que obtuviste de un recurso público y de acceso general (como un directorio de miembros de una asociación profesional)
  * Información en X sobre un usuario que esté disponible públicamente, incluidos:
    * Publicaciones
    * Información de perfil, incluida la biografía de un usuario y su ubicación declarada públicamente
    * Nombre para mostrar y nombre de usuario

<div id="redistribution-of-x-content">
  ## Redistribución de contenido de X
</div>

Si necesitas compartir contenido de X que obtuviste a través de X API con otra parte, la mejor manera de hacerlo es compartiendo IDs de Publicación, IDs de Mensaje Directo y/o IDs de Usuario, que el usuario final del contenido puede luego rehidratar (es decir, solicitar la Publicación completa, el Usuario o el contenido del Mensaje Directo) usando X API. Esto ayuda a garantizar que los usuarios finales del contenido de X siempre obtengan la información más actualizada directamente de nosotros.

Permitimos la redistribución limitada de contenido de X rehidratado por medios no automatizados. Si decides compartir contenido de X rehidratado con otra parte de esta manera, solo puedes compartir hasta 50.000 objetos de Publicación pública y/o objetos de Usuario rehidratados por destinatario, por día, y no debes poner estos datos a disposición del público (por ejemplo, como un archivo adjunto a una publicación de blog o en un repositorio público de GitHub).

Hay algunos otros puntos a tener en cuenta sobre la redistribución de contenido de X:

* Solo puedes distribuir hasta un total de 1.500.000 IDs de Publicación a una sola entidad dentro de un período de 30 días, a menos que hayas recibido permiso previo expreso por escrito de X.
* Las personas que redistribuyen IDs de Publicación y/o IDs de Usuario en nombre de una institución académica con el único propósito de realizar investigación no comercial tienen permitido redistribuir un número ilimitado de IDs de Publicación y/o IDs de Usuario.
* Para solicitar permiso para compartir contenido de X como se describe arriba, utiliza el formulario de asistencia de API Policy.

En la medida en que se te permita distribuir contenido de X a un tercero, ten en cuenta que este contenido sigue estando sujeto al Developer Agreement y a la Developer Policy, y esos terceros deben aceptar los [Términos de servicio](https://twitter.com/en/tos) de X, la [Política de privacidad](https://twitter.com/en/privacy), el [Developer Agreement](/es/developer-terms/agreement) y la [Developer Policy](/es/developer-terms/policy) antes de recibir contenido de X.

<div id="multiple-applications">
  ## Múltiples aplicaciones
</div>

No está permitido registrar varias aplicaciones para un único caso de uso, ni para casos de uso sustancialmente similares o superpuestos. Obtenga más información sobre estas políticas [aquí](https://twittercommunity.com/t/policy-clarification-multiple-applications-for-the-same-use-case/92080).

En este contexto, definimos “caso de uso” como un conjunto coherente de análisis, visualizaciones o acciones realizadas a través de una aplicación. Proporcionar el mismo servicio o aplicación a distintos usuarios finales cuenta como un solo caso de uso; sin embargo, las versiones de “marca blanca” de una herramienta o servicio no están incluidas. Si planea ofrecer versiones de “marca blanca” de su aplicación, debe notificárnoslo y recibir una aprobación independiente de nuestra parte. Estas reglas se aplican tanto a las aplicaciones que registra usted, como a las aplicaciones registradas por los usuarios finales de su herramienta o servicio; exigir a sus usuarios finales que registren aplicaciones con el fin de usar su herramienta o servicio podría dar lugar a medidas de cumplimiento en su contra, contra sus aplicaciones, sus clientes y/o los usuarios finales de su herramienta o servicio.

La única excepción a esta regla es crear instancias de desarrollo (“dev”), pruebas (“staging”) y producción (“prod”) del mismo servicio. Asegúrese de que estas aplicaciones estén claramente etiquetadas (por ejemplo, en el nombre o la descripción de la aplicación) y de no utilizar aplicaciones de desarrollo o de pruebas con fines de producción.

<div id="automation-spam-and-auto-responses">
  ## Automatización, spam y respuestas automáticas
</div>

El uso de las API y los productos para desarrolladores de X para crear spam o participar en comportamientos de spam está prohibido. Debes revisar las [Reglas de X](https://t.co/rules) sobre spam y asegurarte de que tu aplicación no las incumpla ni permita que los usuarios las incumplan.

Si tu aplicación se utilizará para realizar acciones de escritura en el servicio de X, incluidas publicar Publicaciones, seguir cuentas o enviar Mensajes Directos, debes revisar cuidadosamente las [Reglas sobre automatización](https://support.twitter.com/articles/76915) para garantizar que tu servicio cumpla con nuestras pautas. En particular, debes:

* Obtener siempre el consentimiento explícito de un usuario antes de enviarle [respuestas o mensajes automatizados](https://twittercommunity.com/t/policy-clarification-automated-replies-and-mentions/94444)
* Respetar de inmediato las solicitudes de los usuarios de dejar de recibir comunicaciones tuyas
* Nunca realizar acciones masivas, agresivas o de tipo spam, incluido el [seguimiento masivo](https://twittercommunity.com/t/policy-clarification-aggressive-following-and-inorganic-following-behavior/92769)
* Nunca publicar contenido idéntico o sustancialmente similar en [múltiples cuentas](https://blog.twitter.com/developer/en_us/topics/tips/2018/automation-and-the-use-of-multiple-accounts.html)

<div id="measuring-the-x-service">
  ## Medición del servicio de X
</div>

No utilices las X API para medir la disponibilidad, el rendimiento, la funcionalidad o el uso de X con fines de benchmarking o competencia. Por ejemplo, nunca debes usar las X API para:

* Calcular métricas agregadas de usuarios de X, como el número total de usuarios o cuentas activas
* Calcular métricas agregadas de Publicaciones de X, como el número total de Publicaciones por día o el número de interacciones de usuarios o de cuentas
* Medir o analizar el spam o la seguridad en X, salvo en los casos permitidos en las [Reglas de X](https://help.twitter.com/en/rules-and-policies/twitter-rules)

<div id="surveillance-privacy-and-user-protection">
  ## Vigilancia, privacidad y protección de los usuarios
</div>

En X, la protección y defensa de la privacidad de nuestros usuarios forma parte del ADN de nuestra empresa, y nuestros productos para desarrolladores y de datos reflejan ese compromiso. Creemos que los datos de X pueden ser una poderosa fuerza para el bien en el mundo — desde salvar vidas durante inundaciones en Yakarta hasta ayudar al USGS a rastrear terremotos o colaborar con la ONU para alcanzar los Objetivos de Desarrollo Sostenible. Sin embargo, prohibimos el uso de los datos de X y de las X APIs por parte de cualquier entidad con fines de vigilancia, o de cualquier otra manera que sea inconsistente con las expectativas razonables de privacidad de nuestros usuarios. Punto.

Describimos los usos prohibidos de nuestros datos y productos para desarrolladores en el [Developer Agreement](/es/developer-terms/agreement), incluidas las prohibiciones sobre investigar o rastrear a usuarios de X o su contenido, así como rastrear, alertar o monitorear eventos sensibles (como protestas, manifestaciones o reuniones de organización comunitaria).

Otras categorías de actividades prohibidas según estos términos incluyen (entre otras):

* Investigar o rastrear grupos y organizaciones sensibles, como sindicatos o grupos de activistas
* Verificaciones de antecedentes o cualquier forma de investigación o filtrado extremo
* Análisis de riesgo crediticio o de seguros
* Perfilado individual o segmentación psicográfica
* Reconocimiento facial

Estas políticas se aplican a todos los usuarios de nuestras APIs. Cualquier uso indebido de las X APIs para estos fines estará sujeto a medidas de cumplimiento, que pueden incluir la suspensión y la revocación del acceso.

Para obtener información adicional dirigida a autoridades encargadas de hacer cumplir la ley que soliciten información sobre cuentas de X, visita [https://t.co/le](https://t.co/le).

Además, en este momento, X prohíbe cualquier uso de las X APIs y/o X Content para ajustar o entrenar un modelo foundation o frontier, con la excepción de [Grok](https://help.x.com/en/using-x/about-grok).
