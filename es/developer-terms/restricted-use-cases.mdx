El uso de nuestra plataforma para desarrolladores requiere que debes revisar y aceptar nuestro [Acuerdo y política para desarrolladores](/es/developer-terms/agreement), así como nuestras políticas relacionadas, incluidas las [Display Requirements](https://developer.x.com/en/developer-terms/display-requirements.html) y las [Automation Rules](https://help.twitter.com/en/rules-and-policies/twitter-automation). Entre otras cosas, nuestros acuerdos y políticas ofrecen orientación sobre varios casos de uso restringido. A continuación, ofrecemos información adicional sobre algunas de estas restricciones.

<div id="sensitive-information">
  ## Información sensible
</div>

Debes tener cuidado al utilizar datos de X para derivar o inferir características potencialmente sensibles sobre los usuarios de X. Nunca debes derivar ni inferir, ni almacenar información derivada o inferida, sobre lo siguiente relativo a un usuario de X:

* Salud (incluido el embarazo)
* Situación o condición financiera desfavorable
* Afiliación o creencias políticas
* Origen racial o étnico
* Afiliación o creencias religiosas o filosóficas
* Vida sexual u orientación sexual
* Afiliación sindical
* Comisión presunta o real de un delito

Se permite el análisis agregado de contenido de X que no almacene ningún dato personal (por ejemplo, IDs de usuario, nombres de usuario y otros identificadores), siempre que el análisis también cumpla con las leyes aplicables y con todas las disposiciones del Developer Agreement and Policy.

<div id="off-x-matching">
  ## Coincidencias fuera de X
</div>

Las coincidencias fuera de X implican asociar contenido de X, incluido un nombre de usuario de X o un id de usuario, con una persona, hogar, dispositivo, navegador u otro identificador ajeno a X. Un ejemplo sería asociar un nombre de usuario de X con los registros de clientes de una empresa (es decir, “John Doe” en tu registro de clientes se asocia con @johndoe en X).

Queremos que las personas se sientan cómodas creando una identidad separada y, si así lo eligen, seudónima en X. Si tienes la intención de asociar cualquier información sobre un usuario de X con un identificador fuera de X, exigimos que obtengas el consentimiento expreso del usuario, de tipo opt‑in, antes de hacer la asociación. Por ejemplo, podrías obtener este consentimiento si el usuario comparte directamente contigo su nombre de usuario en X (handle) como parte de un proceso de registro en tu servicio.

En situaciones en las que no tengas el consentimiento expreso opt‑in del usuario para vincular su identidad en X con un identificador fuera de X, exigimos que cualquier conexión que establezcas se base únicamente en información que un usuario razonablemente esperaría que se utilizara para ese propósito. Si un usuario se sorprendería al enterarse de que estás utilizando la información que proporcionó para vincular su cuenta de X con una identidad fuera de X, no lo hagas. Además, en ausencia del consentimiento expreso opt‑in de una persona, solo puedes intentar hacer coincidir tus registros sobre alguien con una identidad de X basándote en:

* **Información proporcionada directamente a ti por el usuario.** Los registros sobre personas con las que no tienes una relación previa, incluidos datos sobre personas obtenidos de terceros, no cumplen este estándar; y/o
* **Datos públicos.** “Datos públicos” en este contexto se refiere a:
  * Información sobre un usuario que obtuviste de un recurso público y de acceso general (como un directorio de miembros de una asociación profesional)
  * Información en X sobre un usuario que está disponible públicamente, incluyendo:
    * Publicaciones
    * Información de perfil, incluida la biografía del usuario y su ubicación declarada públicamente
    * Nombre visible y nombre de usuario

<div id="redistribution-of-x-content">
  ## Redistribución de contenido de X
</div>

Si necesitas compartir contenido de X que obtuviste a través de las API de X con otra parte, la mejor manera de hacerlo es compartiendo ids de Publicaciones, ids de Mensajes Directos y/o ids de Usuarios, que el usuario final del contenido puede luego rehidratar (es decir, solicitar la Publicación, el Usuario o el contenido de Mensaje Directo completo) usando las API de X. Esto ayuda a garantizar que los usuarios finales del contenido de X siempre obtengan la información más actualizada directamente de nosotros.

Permitimos una redistribución limitada de contenido rehidratado de X por medios no automatizados. Si decides compartir contenido rehidratado de X con otra parte de esta manera, solo puedes compartir hasta 50.000 Objetos de Publicaciones públicas y/o Objetos de Usuarios rehidratados por destinatario, por día, y no debes poner estos datos a disposición del público (por ejemplo, como archivo adjunto a una entrada de blog o en un repositorio público de GitHub).

Hay algunos otros puntos a tener en cuenta sobre la redistribución de contenido de X:

* Solo puedes distribuir hasta un total de 1.500.000 ids de Publicaciones a una sola entidad dentro de un período de 30 días, a menos que hayas recibido previamente permiso expreso por escrito de X.
* Las personas que redistribuyen ids de Publicaciones y/o ids de Usuarios en nombre de una institución académica con el único propósito de investigación no comercial tienen permitido redistribuir un número ilimitado de ids de Publicaciones y/o ids de Usuarios.
* Para solicitar permiso para compartir contenido de X como se describe arriba, utiliza el formulario de soporte de API Policy.

En la medida en que se te permita distribuir contenido de X a un tercero, ten en cuenta que este contenido sigue estando sujeto al Developer Agreement and Policy, y esos terceros deben aceptar los [Términos de servicio](https://twitter.com/en/tos) de X, la [Política de privacidad](https://twitter.com/en/privacy), el [Developer Agreement](/es/developer-terms/agreement) y la [Developer Policy](/es/developer-terms/policy) antes de recibir contenido de X.

<div id="multiple-applications">
  ## Varias aplicaciones
</div>

No está permitido registrar varias aplicaciones para un único caso de uso, o para casos de uso sustancialmente similares o superpuestos. Obtén más información sobre estas políticas [aquí](https://twittercommunity.com/t/policy-clarification-multiple-applications-for-the-same-use-case/92080).

En este contexto, definimos “caso de uso” como un conjunto coherente de análisis, visualizaciones o acciones realizadas a través de una aplicación. Proporcionar el mismo servicio o aplicación a distintos usuarios finales cuenta como un solo caso de uso; sin embargo, las versiones &quot;white label&quot; de una herramienta o servicio no se incluyen. Si planeas ofrecer versiones &quot;white label&quot; de tu aplicación, debes notificárnoslo y recibir nuestra aprobación por separado. Estas reglas se aplican tanto a las aplicaciones que registras tú como a las aplicaciones registradas por los usuarios finales de tu herramienta o servicio; exigir a tus usuarios finales que registren aplicaciones con el fin de usar tu herramienta o servicio podría dar lugar a medidas de cumplimiento en tu contra, contra tus aplicaciones, tus clientes y/o los usuarios finales de tu herramienta o servicio.

La única excepción a esta regla es crear instancias de desarrollo (“dev”), pruebas (“staging”) y producción (“prod”) del mismo servicio. Asegúrate de que estas aplicaciones estén claramente etiquetadas (por ejemplo, en el nombre o la descripción de la aplicación) y de que no utilices aplicaciones de desarrollo o de pruebas con fines de producción.

<div id="automation-spam-and-auto-responses">
  ## Automatización, spam y respuestas automáticas
</div>

Está prohibido usar las APIs y los productos para desarrolladores de X para crear spam o participar en comportamientos de tipo spam. Debe revisar las [Reglas de X](https://t.co/rules) sobre spam y asegurarse de que su aplicación no infrinja nuestras políticas ni permita que los usuarios las infrinjan.

Si su aplicación se utilizará para realizar acciones de escritura en el servicio de X, incluidas publicar Publicaciones, seguir cuentas o enviar Mensajes Directos, debe revisar detenidamente las [Reglas de automatización](https://support.twitter.com/articles/76915) para asegurarse de que su servicio cumpla nuestras directrices. En particular, debe:

* Obtener siempre el consentimiento explícito de un usuario antes de enviarle [respuestas o mensajes automatizados](https://twittercommunity.com/t/policy-clarification-automated-replies-and-mentions/94444)
* Respetar de inmediato las solicitudes de los usuarios de dejar de recibir comunicaciones de su parte
* No realizar nunca acciones masivas, agresivas o de tipo spam, incluido el [seguimiento masivo](https://twittercommunity.com/t/policy-clarification-aggressive-following-and-inorganic-following-behavior/92769)
* No publicar nunca contenido idéntico o sustancialmente similar en [múltiples cuentas](https://blog.twitter.com/developer/en_us/topics/tips/2018/automation-and-the-use-of-multiple-accounts.html)

<div id="measuring-the-x-service">
  ## Medir el servicio de X
</div>

No uses las X API para medir la disponibilidad, el rendimiento, la funcionalidad o el uso de X con fines de evaluación comparativa o competitivos. Por ejemplo, nunca debes usar las X API para:

* Calcular métricas agregadas de usuarios de X, como el número total de usuarios o cuentas activos
* Calcular métricas agregadas de Publicaciones de X, como el número total de Publicaciones por día o el número de interacciones de usuarios o de cuentas
* Medir o analizar el spam o la seguridad en X, salvo en los casos permitidos en las [X Rules](https://help.twitter.com/en/rules-and-policies/twitter-rules)

<div id="surveillance-privacy-and-user-protection">
  ## Vigilancia, privacidad y protección de los usuarios
</div>

En X, la protección y defensa de la privacidad de nuestros usuarios forma parte del ADN mismo de nuestra empresa, y nuestros productos para desarrolladores y de datos reflejan ese compromiso. Creemos que los datos de X pueden ser una fuerza poderosa para el bien en el mundo — desde salvar vidas durante inundaciones en Yakarta hasta ayudar al USGS a rastrear terremotos o trabajar con la ONU para lograr los Objetivos de Desarrollo Sostenible. Sin embargo, prohibimos el uso de los datos de X y de las X APIs por parte de cualquier entidad con fines de vigilancia, o de cualquier otra forma que sea incompatible con las expectativas razonables de privacidad de nuestros usuarios. Punto.

Describimos los usos prohibidos de nuestros datos y productos para desarrolladores en el [Developer Agreement](/es/developer-terms/agreement), incluidas las prohibiciones de investigar o rastrear a usuarios de X o su contenido, así como rastrear, alertar o monitorear eventos sensibles (como protestas, manifestaciones o reuniones de organización comunitaria).

Otras categorías de actividades prohibidas en virtud de estos términos incluyen (a título enunciativo y no limitativo):

* Investigar o rastrear grupos y organizaciones sensibles, como sindicatos o grupos de activistas
* Verificaciones de antecedentes o cualquier forma de escrutinio/extrema evaluación
* Análisis de riesgo crediticio o de seguros
* Elaboración de perfiles individuales o segmentación psicográfica
* Reconocimiento facial

Estas políticas se aplican a todos los usuarios de nuestras APIs. Cualquier uso indebido de las X APIs para estos fines estará sujeto a acciones de aplicación, que pueden incluir la suspensión y revocación del acceso.

Para obtener información adicional destinada a autoridades encargadas de la aplicación de la ley que busquen información sobre cuentas de X, visita [https://t.co/le](https://t.co/le).

Además, en este momento, X prohíbe cualquier uso de las X APIs y/o X Content para ajustar (fine-tune) o entrenar un modelo foundation o frontier, con la excepción de [Grok](https://help.x.com/en/using-x/about-grok).
