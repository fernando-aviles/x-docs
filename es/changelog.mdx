  ### Cambio en el comportamiento de los eventos de DM

  Hoy hemos realizado un cambio en el comportamiento de los eventos de DM de X API V2. Con el nuevo cambio, el array participant&#95;ids solo se incluirá para los eventos ParticipantsJoin y ParticipantsLeave, y solo enumerará a las personas que se unieron o salieron en el momento del evento. El evento MessageCreate ya no incluirá el array participant&#95;ids. Obtén más información [aquí](https://devcommunity.x.com/t/upcoming-change-to-x-api-dm-events-endpoints-behavior/241841).

<Update label="Aug 3, 2022" description="X API v2">
  ### Adición de alias para operadores de filtrado

  Se añadieron &quot;alias&quot; de operadores de filtrado/consulta a los endpoints de búsqueda y de filtered stream, en enterprise, premium y v2. En muchos casos, el operador se refiere a Publicaciones en lugar de statuses, por ejemplo, &quot;in&#95;reply&#95;to&#95;tweet&#95;id&quot; como alias de &quot;in&#95;reply&#95;to&#95;status&#95;id&quot;. En otros casos, el nuevo alias del operador aporta más claridad al cotejo realizado. Por ejemplo, dado que las Publicaciones solo pueden tener un adjunto de video, se proporciona un nuevo alias &quot;has:video&#95;link&quot; para &quot;has:videos&quot;. Consulta la [tabla de operadores de v2 filtered stream](https://developer.x.com/en/docs/twitter-api/tweets/filtered-stream/integrate/build-a-rule#list) para ver más ejemplos.
</Update>

<Update label="14 de dic de 2021" description="X API v2: Autenticación">
  ### Compatibilidad con la autenticación OAuth 2.0

  A partir de hoy, todos los desarrolladores pueden autenticarse usando OAuth 2.0 seleccionando OAuth 2.0 como método de autenticación en la Consola de Desarrollador. Hemos añadido compatibilidad para clientes confidenciales y públicos y para que todos los endpoints v2 relevantes utilicen este método de autenticación como parte de este lanzamiento.

  OAuth 2.0 es un protocolo de autorización estándar del sector que ofrece a los desarrolladores más control sobre los scopes de una aplicación y mejora los flujos de autorización en múltiples dispositivos. En otras palabras, los desarrolladores que crean aplicaciones para las personas en X tendrán más control sobre la información que su app solicita a sus usuarios, de modo que solo tengas que pedir a tus usuarios finales los datos y la información que realmente necesitas.

  Este moderno protocolo de autorización te permitirá ofrecer a tus usuarios finales un flujo de consentimiento más simplificado para autorizar tu app, que solo muestre los scopes específicos que les has solicitado.

  Para obtener más información sobre este lanzamiento, visita nuestro anuncio en el foro.
</Update>

<Update label="15 de nov de 2021" description="X API v2: Acceso anticipado">
  ### Actualizaciones importantes de la plataforma para X API v2

  **Actualizaciones importantes de la plataforma: X API v2 es ahora la versión principal, nuevos niveles de acceso Essential y Elevated, y cambios de políticas**

  Hoy anunciamos que X API v2 es ahora la versión principal de la X API. Hemos lanzado suficientes endpoints y funcionalidades en X API v2 para satisfacer las necesidades del 90 % de todas las apps existentes creadas sobre la X API.

  Hoy lanzamos los siguientes cambios para seguir mejorando la experiencia de desarrolladores con X API v2:

  * Acceso Essential rápido y gratuito a la API y acceso Elevated gratuito para los desarrolladores cuyos casos de uso hayan sido aprobados. Tenemos muchos más detalles sobre estos niveles de acceso disponibles en nuestra página Sobre la X API.

  * Estamos eliminando texto en nuestra Developer Policy que restringía cómo creas con las funciones principales de X y limitaba la cantidad de usuarios que puedes admitir a través de tu app.

    * Estamos abriendo nuestra plataforma para animarte a crear herramientas y productos que hagan que X sea mejor, más saludable y amplíe la conversación pública. [Consulta una lista de soluciones que nos encantaría que crearas](https://developer.x.com/en/docs/twitter-api/what-to-build).

    * En concreto, hemos eliminado términos que restringían la replicación de la experiencia de X, incluidas las funciones principales de X, así como términos que requerían permiso para tener números elevados de tokens de usuario.

    * Sabemos que crear soluciones que ayuden a las personas en X a menudo significa que un desarrollador tiene que crear (o replicar) algunas de las cosas que están disponibles en X. Estos cambios en nuestra Developer Policy están pensados para aportar claridad al ecosistema de desarrolladores y ofrecer una plataforma de API abierta que facilite a los desarrolladores crear, innovar y tener un impacto en la conversación pública.

  Entramos en mucho más detalle sobre este lanzamiento y los lanzamientos de X API que nos han llevado a este momento en nuestra [publicación en el foro](https://devcommunity.x.com/t/ushering-in-a-new-era-for-the-twitter-developer-platform-with-the-twitter-api-v2/162087).

  Además de explorar entradas anteriores del registro de cambios, hemos reunido algunos recursos clave que puedes revisar para entender todo lo que se ha lanzado en X API v2 hasta la fecha:

  * [Mapa de endpoints de X API](/es/x-api/migrate/x-api-endpoint-map)

  * [Sobre la X API](/es/x-api/getting-started/about-x-api)
</Update>

<Update label="Dec 18, 2020" description="Campo de configuración de respuestas de conversación para publicaciones en X API v2">
  ### Adición del campo Reply Settings

  Hoy lanzamos un nuevo campo en el objeto de la publicación, llamado reply&#95;settings. Este campo está disponible en todos los endpoints de X API v2 que devuelven publicaciones, incluidos post lookup, hide replies, recent search, sampled stream, filtered stream, follows lookup, user post timeline y user mention timeline, o mediante [ampliando](/es/x-api/fundamentals/expansions) el objeto de la publicación en cualquier endpoint.

  Este campo indica cómo el autor de la publicación ha permitido que otros respondan a sus publicaciones, ya sea todo el mundo, solo las personas que menciona en la publicación o aquellas a las que sigue. Los valores devueltos por el campo `reply_settings` incluyen `everyone`, `mentionedUsers` y `following`. Si no se han establecido controles de conversación para la publicación, este campo seguirá apareciendo en el objeto de la publicación con el valor `everyone`.
</Update>

<Update label="10 de mayo de 2018" description="X API: Estándar v1.1">
  ### Cambios en el renderizado de la carga útil de citas

  Hoy incorporamos un cambio en la forma en que se renderizan las URL en la carga útil de citas.

  Estamos añadiendo una nueva entidad llamada &quot;quoted&#95;status&#95;permalink&quot; para garantizar que se pueda hacer referencia a la publicación citada y eliminaremos el enlace t.co del campo &quot;text&quot; de la publicación citada.

  Con el nuevo formato, el enlace t.co ya no se añade al campo &quot;text&quot; de la publicación citada en el objeto &quot;quoted&#95;status&quot;.

  Además, ya no incluiremos la url t.co, expanded&#95;url y display&#95;url de la publicación citada en la entidad &quot;urls&quot;. En su lugar, se añadirán a un nuevo objeto &quot;quoted&#95;status&#95;permalink&quot; con los atributos de URL &quot;url&quot;, &quot;expanded&quot; y &quot;display&quot;. Esto significa que el objeto &quot;quoted&#95;status&#95;permalink&quot; quedará reservado para el enlace t.co que apunta de nuevo a la publicación citada, mientras que el array &quot;entities.urls&quot; se puede usar para identificar cualquier enlace compartido dentro de la publicación original o la cita.

  Lee nuestra [publicación en el foro](https://devcommunity.x.com/t/updating-how-urls-are-rendered-in-the-quote-tweet-payload/105473) y la [documentación actualizada](https://devcommunity.x.com/t/upcoming-changes-to-the-developer-platform/104603) para obtener más detalles.

  Dentro de 30 días a partir de hoy, es decir, después del 4 de agosto de 2017, la API de búsqueda de 30 días (tanto de 30 días como de archivo completo) ya no admitirá el operador url&#95;contains: (el soporte de url&#95;contains: finalizará realmente con el primer despliegue posterior a esa fecha). La retirada de este operador se anunció como parte de la migración a Gnip 2.0 en agosto de 2016. Cuando finalice el soporte del operador, cualquier consulta que use url&#95;contains: será rechazada por no ser válida.
</Update>

<Update label="5 may 2017" description="X API: Standard v1.1">
  ### Parámetros opcionales para comandos de MD

  El parámetro opcional `enable_dm_commands` para statuses/update permitirá que las aplicaciones eliminen el soporte de comandos de mensajes directos (MD) antes de tiempo, antes de que finalice el período de transición. El valor predeterminado es *true* (es decir, el comportamiento heredado actual), pero se puede establecer en *false* para obtener el nuevo comportamiento posterior al 1 de noviembre. El parámetro opcional `fail_dm_commands` para statuses/update hará que los comandos de MD devuelvan HTTP 403 (código de error 151) desde la API cuando se establezca en *true*. El valor predeterminado es *false*. Obtén más información sobre esta actualización [en nuestro foro](https://devcommunity.x.com/t/retiring-legacy-dm-commands-on-the-standard-tweet-api/86653).
</Update>

<Update label="22 feb 2017" description="X API: Enterprise v1.1">
  ### Nuevos enriquecimientos y cambios en el payload

  ¡Nuevo enriquecimiento! Los metadatos de encuestas ahora están disponibles a través de nuestras APIs empresariales. Consulta la [documentación](/es/x-api/enterprise-gnip-2.0/fundamentals/account-activity#migration-introduction) para obtener más detalles.

Esto solo está disponible en formato enriquecido nativo.

  Formato de payload predeterminado: Los streams creados recientemente en los productos de Gnip ahora usarán por defecto el formato JSON original.
