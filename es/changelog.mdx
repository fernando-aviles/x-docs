  ### Cambio en el comportamiento de los eventos de DM

  Hoy hemos realizado un cambio en el comportamiento de los eventos de DM de X API V2. <Update label="Aug 3, 2022" description="X API v2">
  ### Adición de alias de operadores de filtrado

  Se añadieron alias de operadores de filtrado/consulta a los endpoints de búsqueda y filtered stream, en enterprise, premium y v2. En muchos casos, el operador se refiere a publicaciones en lugar de statuses, por ejemplo, &quot;in&#95;reply&#95;to&#95;tweet&#95;id&quot; como alias de &quot;in&#95;reply&#95;to&#95;status&#95;id&quot;. En otros casos, el nuevo alias del operador aporta más claridad a la coincidencia que se realiza. Por ejemplo, dado que las publicaciones solo pueden tener un adjunto de video, se proporciona un nuevo alias &quot;has:video&#95;link&quot; para &quot;has:videos&quot;. Consulta la [tabla de operadores de v2 filtered stream](https://developer.x.com/en/docs/twitter-api/tweets/filtered-stream/integrate/build-a-rule#list) para ver más ejemplos.
</Update>

<Update label="14 de diciembre de 2021" description="X API v2: Autenticación">
  ### Compatibilidad con la autenticación OAuth 2.0

  A partir de hoy, todos los desarrolladores pueden autenticarse mediante OAuth 2.0 seleccionando OAuth 2.0 como método de autenticación en la Consola de desarrollador. Hemos añadido compatibilidad para clientes confidenciales y públicos y para que todos los endpoints v2 relevantes utilicen este método de autenticación como parte de este lanzamiento.

  OAuth 2.0 es un protocolo de autorización estándar de la industria que ofrece a los desarrolladores más control sobre los permisos (scopes) de una aplicación y mejora los flujos de autorización entre varios dispositivos. En otras palabras, los desarrolladores que crean aplicaciones para las personas en X tendrán más control sobre la información que su App solicita a sus usuarios, de modo que solo tengas que pedir a tus usuarios finales los datos y la información que necesitas.

  Este protocolo de autorización moderno te permitirá presentar a tus usuarios finales un flujo de consentimiento más sencillo y optimizado para autorizar tu App, que solo muestra los permisos específicos que has solicitado.

  Para obtener más información sobre este lanzamiento, visita nuestro anuncio en el foro.
</Update>

<Update label="15 de noviembre de 2021" description="X API v2: Acceso anticipado">
  ### Actualizaciones importantes de la plataforma para X API v2

  **Actualizaciones importantes de la plataforma: X API v2 ahora es la versión principal, nuevos niveles de acceso Essential y Elevated, y cambios en las Políticas**

  Hoy anunciamos que X API v2 es ahora la versión principal de X API. Hemos lanzado suficientes endpoints y funcionalidades en X API v2 para satisfacer las necesidades del 90 % de todas las Apps existentes creadas sobre X API.

  Hoy lanzamos los siguientes cambios para seguir mejorando la experiencia de desarrollador de X API v2:

  * Acceso Essential rápido y gratuito a la API, y acceso Elevated gratuito para los desarrolladores cuyos casos de uso hayan sido aprobados. Tenemos muchos más detalles sobre estos niveles de acceso disponibles en nuestra página Acerca de X API.

  * Eliminamos lenguaje en nuestra Developer Policy que restringía cómo puedes crear con las funciones principales de X y limitaba el número de usuarios que puedes admitir a través de tu App.

    * Estamos abriendo nuestra plataforma para animarte a crear herramientas y productos que hagan que X sea mejor, más saludable y amplíe la conversación pública. [Consulta una lista de soluciones que nos encantaría que crearas](https://developer.x.com/en/docs/twitter-api/what-to-build).

    * En concreto, hemos eliminado términos que restringían la replicación de la experiencia de X, incluidas las funciones principales de X, así como términos que exigían permiso para tener un alto número de tokens de usuario.

    * Sabemos que crear soluciones que ayuden a las personas en X a menudo significa que un desarrollador tiene que crear (o replicar) algunas de las cosas que están disponibles en X. Estos cambios en nuestra Developer Policy tienen como objetivo aportar claridad al ecosistema de desarrolladores y ofrecer una plataforma API abierta que facilite a los desarrolladores crear, innovar y tener un impacto en la conversación pública.

  Entramos en mucho más detalle sobre este lanzamiento y sobre los lanzamientos de X API que llevaron a este momento en nuestra [publicación del foro](https://devcommunity.x.com/t/ushering-in-a-new-era-for-the-twitter-developer-platform-with-the-twitter-api-v2/162087).

  Además de explorar entradas anteriores del registro de cambios, hemos reunido algunos recursos clave que puedes revisar para entender todo lo que se ha lanzado en X API v2 hasta la fecha:

  * [Mapa de endpoints de X API](/es/x-api/migrate/x-api-endpoint-map)

  * [Acerca de X API](/es/x-api/getting-started/about-x-api)
</Update>

<Update label="10 de mayo de 2018" description="X API: Standard v1.1">
  ### Cambios en la representación del payload de citas

  Hoy incorporamos un cambio en la forma en que se representarán las URL en el payload de la cita.

  Estamos agregando una nueva entidad llamada &quot;quoted&#95;status&#95;permalink&quot; para garantizar que se pueda hacer referencia a la publicación citada y quitaremos el enlace t.co del campo &quot;text&quot; de la publicación citada.

  Con el nuevo formato, el enlace t.co ya no se agrega al campo &quot;text&quot; de la publicación citada en el objeto &quot;quoted&#95;status&quot;.

  Además, ya no incluiremos la t.co url, expanded&#95;url y display&#95;url de la publicación citada en la entidad ‘urls’. En su lugar, se añadirán a un nuevo objeto &quot;quoted&#95;status&#95;permalink&quot; con atributos de URL &quot;url&quot;, &quot;expanded&quot; y &quot;display&quot;. Esto significa que el objeto &quot;quoted&#95;status&#95;permalink&quot; se reservará para el enlace t.co que apunta de nuevo a la publicación citada, mientras que el array &quot;entities.urls&quot; se puede usar para identificar cualquier enlace compartido dentro de la publicación original o la cita.

  Lee nuestra [publicación en el foro](https://devcommunity.x.com/t/updating-how-urls-are-rendered-in-the-quote-tweet-payload/105473) y la [documentación actualizada](https://devcommunity.x.com/t/upcoming-changes-to-the-developer-platform/104603) para obtener más detalles.
</Update>

La retirada de este operador se anunció como parte de la migración a Gnip 2.0 en agosto de 2016. Cuando finalice el soporte del operador, cualquier consulta que use url&#95;contains: será rechazada por no ser válida.
</Update>

<Update label="5 de may de 2017" description="X API: Standard v1.1">
  ### Parámetros opcionales para comandos de MD

  El parámetro opcional `enable_dm_commands` para statuses/update permitirá que las aplicaciones eliminen el soporte para comandos de MD antes de tiempo, antes de que termine el período de transición. El valor predeterminado es *true* (es decir, el comportamiento heredado actual), pero se puede establecer en *false* para obtener el nuevo comportamiento posterior al 1 de noviembre. El parámetro opcional `fail_dm_commands` para statuses/update hará que los comandos de MD devuelvan HTTP 403 (código de error 151) de la API cuando se establezca en *true*. El valor predeterminado es *false*. Lee más sobre esta actualización [en nuestro foro](https://devcommunity.x.com/t/retiring-legacy-dm-commands-on-the-standard-tweet-api/86653).
