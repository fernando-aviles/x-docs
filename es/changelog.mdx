<Update label="Jun 3, 2025" description="X API">
  ### Cambio en el comportamiento de los eventos de MD

  Hoy realizamos un cambio en el comportamiento de los eventos de MD de X API v2. Con el nuevo cambio, el array `participant_ids` solo se incluirá para los eventos `ParticipantsJoin` y `ParticipantsLeave`, y solo enumerará a los participantes que se unieron o se fueron en el momento del evento. El evento `MessageCreate` ya no incluirá el array `participant_ids`. Obtén más información [aquí](https://devcommunity.x.com/t/upcoming-change-to-x-api-dm-events-endpoints-behavior/241841).
</Update>

<Update label="3 ago 2022" description="X API v2">
  ### Adición de alias de operadores de filtrado

  Se añadieron operadores de filtrado/consulta «alias» a los endpoints de búsqueda y filtered stream, en enterprise, premium y v2. En muchos casos, el operador se refiere a publicaciones en lugar de statuses, por ejemplo, «in&#95;reply&#95;to&#95;tweet&#95;id» como alias de «in&#95;reply&#95;to&#95;status&#95;id». En otros casos, el nuevo alias del operador aporta más claridad al tipo de coincidencia que se realiza. Por ejemplo, dado que las publicaciones solo pueden tener un vídeo adjunto, se proporciona un nuevo alias «has:video&#95;link» para «has:videos». Consulta la [tabla de operadores de v2 filtered stream](https://developer.x.com/en/docs/twitter-api/tweets/filtered-stream/integrate/build-a-rule#list) para ver más ejemplos.
</Update>

<Update label="Dec 14, 2021" description="X API v2: Autenticación">
  ### Compatibilidad con la autenticación OAuth 2.0

  A partir de hoy, todos los desarrolladores pueden autenticarse usando OAuth 2.0 seleccionando OAuth 2.0 como método de autenticación en el Developer Console. Hemos añadido compatibilidad para clientes confidenciales y públicos y hemos habilitado todos los endpoints v2 relevantes para que utilicen este método de autenticación como parte de este lanzamiento.

  OAuth 2.0 es un protocolo de autorización estándar del sector que ofrece a los desarrolladores más control sobre los permisos (scopes) de una aplicación y mejora los flujos de autorización en múltiples dispositivos. En otras palabras, los desarrolladores que crean aplicaciones para personas en X tendrán más control sobre la información que su app solicita a sus usuarios, de modo que solo tengas que pedir a tus usuarios finales los datos y la información que necesitas.

  Este protocolo de autorización moderno te permitirá presentar a tus usuarios finales un flujo de consentimiento más sencillo para autorizar tu app, que solo muestra los scopes específicos que les has solicitado.

  Para obtener más información sobre este lanzamiento, visita nuestro anuncio en el foro.
</Update>

<Update label="Nov 15, 2021" description="X API v2: Acceso anticipado">
  ### Actualizaciones importantes de la plataforma a X API v2

  **Actualizaciones importantes de la plataforma: X API v2 es ahora la versión principal, nuevos niveles de acceso Essential y Elevated, y cambios en las Políticas**

  Hoy anunciamos que X API v2 es ahora la versión principal de X API. Hemos lanzado suficientes endpoints y funcionalidad en X API v2 para satisfacer las necesidades del 90 % de todas las apps existentes creadas sobre X API.

  Hoy lanzamos los siguientes cambios para seguir mejorando la experiencia de desarrollador con X API v2:

  * Acceso Essential rápido y gratuito a la API, y acceso Elevated gratuito para los desarrolladores cuyos casos de uso hayan sido aprobados. Tenemos muchos más detalles sobre estos niveles de acceso disponibles en nuestra página Acerca de X API.

  * Estamos eliminando redacción de nuestra Developer Policy que restringía cómo creas con las funciones principales de X y que limitaba el número de usuarios que puedes admitir a través de tu app.

    * Estamos abriendo nuestra plataforma para animarte a crear herramientas y productos que hagan que X sea mejor, más saludable y que amplíen la conversación pública. [Consulta una lista de soluciones que nos encantaría que crearas](https://developer.x.com/en/docs/twitter-api/what-to-build).

    * En concreto, hemos eliminado términos que restringían la replicación de la experiencia de X, incluidas las funciones principales de X, así como términos que requerían permiso para tener un alto número de tokens de usuario.

    * Sabemos que crear soluciones que ayuden a las personas en X a menudo significa que un desarrollador tiene que crear (o replicar) algunas de las cosas que están disponibles en X. Estos cambios en nuestra Developer Policy están pensados para aportar claridad al ecosistema de desarrolladores y proporcionar una plataforma de API abierta que facilite a los desarrolladores crear, innovar y tener un impacto en la conversación pública.

  Entramos en mucho más detalle sobre este lanzamiento y los lanzamientos de X API que nos han llevado hasta este momento en nuestra [publicación en el foro](https://devcommunity.x.com/t/ushering-in-a-new-era-for-the-twitter-developer-platform-with-the-twitter-api-v2/162087).

  Además de explorar entradas anteriores del registro de cambios, hemos reunido algunos recursos clave que puedes revisar para entender todo lo que se ha lanzado en X API v2 hasta la fecha:

  * [Mapa de endpoints de X API](/es/x-api/migrate/x-api-endpoint-map)

  * [Acerca de X API](/es/x-api/getting-started/about-x-api)
</Update>

<Update label="Dec 18, 2020" description="Campo de configuración de respuestas de conversación para publicaciones en X API v2">
  ### Adición del campo reply_settings

  Hoy lanzamos un nuevo campo en el objeto de publicación llamado reply&#95;settings. Este campo está disponible en todos los endpoints de X API v2 que devuelven publicaciones, incluidos post lookup, hide replies, recent search, sampled stream, filtered stream, follows lookup, user post timeline y user mention timeline, o mediante [expansions](/es/x-api/fundamentals/expansions) del objeto de publicación en cualquier endpoint.

  Este campo indica cómo el autor de la publicación ha permitido que otros respondan a sus publicaciones, ya sea todo el mundo, solo las personas a las que menciona en la publicación o aquellas a las que sigue. Los valores devueltos por el campo `reply_settings` incluyen `everyone`, `mentionedUsers` y `following`. Si no se configuran controles de conversación para la publicación, este campo seguirá apareciendo en el objeto de publicación con el valor `everyone`.
</Update>

<Update label="10 de mayo de 2018" description="X API: Standard v1.1">
  ### Cambios en la representación de la carga útil de cita

  Hoy incorporamos un cambio en la forma en que se mostrarán las URL en la carga útil de cita.

  Estamos agregando una nueva entidad denominada &quot;quoted&#95;status&#95;permalink&quot; para garantizar que se pueda hacer referencia a la publicación citada y eliminaremos el enlace t.co del campo &quot;text&quot; de la publicación citada.

  Con el nuevo formato, el enlace t.co ya no se agrega al campo &quot;text&quot; de la publicación citada en el objeto &quot;quoted&#95;status&quot;.

  Además, ya no incluiremos la url t.co, expanded&#95;url y display&#95;url de la publicación citada en la entidad ‘urls’. En su lugar, estas se agregarán a un nuevo objeto &quot;quoted&#95;status&#95;permalink&quot; con los atributos de URL &quot;url&quot;, &quot;expanded&quot; y &quot;display&quot;. Esto significa que el objeto &quot;quoted&#95;status&#95;permalink&quot; se reservará para el enlace t.co de regreso a la publicación citada, mientras que el array &quot;entities.urls&quot; se puede usar para identificar cualquier enlace compartido dentro de la publicación original o de la cita.

  Lee nuestra [publicación en el foro](https://devcommunity.x.com/t/updating-how-urls-are-rendered-in-the-quote-tweet-payload/105473) y la [documentación actualizada](https://devcommunity.x.com/t/upcoming-changes-to-the-developer-platform/104603) para obtener más detalles.

Cuando finalice el soporte del operador, cualquier consulta que use url&#95;contains: será rechazada por no ser válida.
</Update>
