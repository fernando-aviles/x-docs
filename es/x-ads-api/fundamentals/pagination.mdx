Para admitir un número máximo mayor de campañas y la recuperación eficiente de todas las entidades asociadas con una cuenta, la Advertiser API ahora es compatible con la paginación en muchos endpoints GET. El mecanismo de paginación es fácil de usar y muy similar a la paginación con cursor de la API REST, como se describe en [Using cursors to navigate collections](https://developer.x.com/en/docs/x-api/v1/pagination).

<div id="getting-started">
  ## Introducción
</div>

Para determinadas solicitudes GET, ahora aceptamos los parámetros de consulta `cursor` y `count`, que ambos son opcionales. Si una respuesta contiene más de `count` entidades, estos endpoints ahora devolverán las primeras `count` entidades y una clave `next_cursor` en el JSON de la respuesta.

`GET https://ads-api.x.com/5/accounts/abc1/campaigns?count=50`

```json
{
  "data": \[...\],
  "next_cursor": "c-3yvu1pzhd3i7",
  "request": {...}
}
```

Para obtener el siguiente conjunto de respuestas, debes agregar `cursor` a tus parámetros de consulta:

`GET https://ads-api.x.com/5/accounts/abc1/campaigns?cursor=c-3yvu1pzhd3i7&count=50`

```json
{
  "data": \[...\],
  "next_cursor": "c-3w3zdyg8ywan",
  "request": {...}
}
```


<div id="going-deeper">
  ## Profundizando
</div>

Para la mayoría de los endpoints, el valor máximo de `count` es **1,000**, el mínimo es **1** y el valor predeterminado es **200**.

El valor proporcionado por `next_cursor` siempre es una cadena de texto y debe considerarse opaco; la implementación está sujeta a cambios. Si se devuelven menos de `count` entidades en la página actual del conjunto de resultados, el valor de `next_cursor` será `null`.

**Nota:** los endpoints de análisis no admiten este estilo de paginación. La paginación en los endpoints de estadísticas se admite especificando períodos de tiempo. Consulta la documentación de esos endpoints concretos para obtener más información.
