<div id="overview">
  ## Descripción general
</div>

Cada mes realizamos cambios e implementamos varias funciones nuevas en la X Ads API. Estos cambios casi siempre son compatibles con versiones anteriores; sin embargo, solemos tener un puñado de cambios incompatibles cada año. Hemos recibido comentarios de desarrolladores sobre los desafíos que nuestro rápido ritmo de cambios en la Ads API representa para sus ciclos de desarrollo a la hora de implementar nuevas funciones, gestionar deprecaciones y probar cambios. Queremos mejorar la experiencia de los desarrolladores al usar nuestra plataforma de Ads, por lo que introdujimos el concepto de versionar nuestros endpoints.

A continuación, algunas definiciones de conceptos de los que hablamos:

**Versión**: Se refiere al número de versión que se encuentra en la ruta de la URL de cualquier solicitud a la Ads API, por ejemplo: GET /{version_number}/accounts. Este estilo de versionado se conoce como versionado URI.

**Cambios incompatibles**: Los cambios incompatibles son cualquier cambio que requiera recursos de desarrollo para mantener la funcionalidad existente. Esto incluye los recursos utilizados para investigar los cambios que deben realizarse, determinar las funciones/endpoints que se están marcando como obsoletos y la implementación final de todos estos cambios. Una lista de cambios incompatibles incluye elementos como:

* Eliminar un parámetro de la solicitud/respuesta de la API

* Modificar el nombre de cualquier parámetro o endpoint

* Cambiar la representación de valores (preview&#95;url → card&#95;uri)

* Cambiar el comportamiento de los endpoints (por ejemplo, estadísticas async vs sync)

* Agregar/cambiar parámetros opcionales u obligatorios (por ejemplo, hacer que nombre sea un campo obligatorio en la solicitud)

**Deprecación**: Las versiones o productos obsoletos dejarán de estar admitidos y se recomienda que los desarrolladores dejen de utilizar estas APIs.

**Retiro (sunset)**: Una vez que un producto o API se retira (sunset), el conjunto de endpoints correspondiente dejará de estar accesible a través de la API.

<div id="versioning-strategy">
  ## Estrategia de versionado
</div>

Los principios principales de la estrategia son:

1. Todos los cambios incompatibles se agruparán en una nueva versión

2. El periodo de deprecación de las versiones existentes cuando se anuncie una nueva versión será de 6 meses

3. En cualquier momento, la API permitirá solicitudes de dos versiones simultáneamente; sin embargo, la más antigua de las dos no contará con soporte

4. Para facilitar una adopción más rápida de nuevos productos, estos se lanzarán de forma continua (fuera de la cadencia de versionado)

5. Todas las respuestas de la API contendrán un `x-current-api-version`, que se establecerá en la versión actual de la API, además de un encabezado `x-api-warn` al llamar a cualquier endpoint de API marcado como obsoleto.

Si hubiera cambios fundamentales en los requisitos del producto que requieran un cambio incompatible en la API (por ejemplo, desaprobar la segmentación por múltiples grupos de edad), enviaremos un aviso con 90 días de antelación para anunciar este cambio incompatible y, transcurridos al menos 90 días desde la publicación del aviso, se implementará el cambio incompatible

  ### v5
</div>

Hoy, 28 de febrero de 2019, X presenta Ads API v5, con actualizaciones centradas en mejorar la escalabilidad y la eficiencia.

Esta versión incluye un nuevo endpoint para determinar qué entidades estuvieron activas en un período de tiempo determinado, estadísticas para Media Creatives (es decir, videos In-stream e imágenes en la X Audience Platform), la posibilidad de obtener *múltiples* cards por URI de la card y más flexibilidad para recuperar criterios de segmentación y otras entidades. Por último, las non-media app cards y el endpoint POST `accounts/:account_id/account_media` se han declarado obsoletos.

Recomendamos a todos los socios que migren a la versión más reciente de la API lo antes posible para evitar cualquier interrupción del servicio. *La versión 3 de la Ads API ha llegado al final de su vida útil y ya no está disponible.*

<div id="new">
  #### Nuevo
</div>

**Determinación de qué entidades estuvieron activas**

El endpoint [Active Entities](/es/x-ads-api/analytics#active-entities-2) indica si las métricas de analíticas para entidades de anuncios han cambiado. Diseñado para utilizarse junto con los endpoints de analíticas, Active Entities funciona especificando un tipo de entidad y un rango de fechas —con un máximo de 90 días— y devuelve una lista de IDs de entidades para las que tu plataforma debería solicitar analíticas. No se deben consultar IDs distintos de los devueltos en solicitudes de analíticas posteriores.

Este endpoint admite los siguientes tipos de entidad: `CAMPAIGN`, `FUNDING_INSTRUMENT`, `LINE_ITEM`, `MEDIA_CREATIVE` y `PROMOTED_TWEET`.

**Estadísticas de `MEDIA_CREATIVE`**

Los endpoints de analíticas de Ads API ahora proporcionan métricas para entidades Media Creative. Las Media Creatives son la forma en que se promocionan los anuncios in-stream o las imágenes en X Audience Platform. La interfaz de X Ads muestra las métricas de Media Creative en las pestañas “In-stream videos” y “Display creatives”. Tanto los endpoints de analíticas [sincrónicos](/es/x-ads-api/analytics#get-stats-accounts-account-id) como [asincrónicos](/es/x-ads-api/analytics#asynchronous-analytics) ahora admiten el valor de enumeración de entidad `MEDIA_CREATIVE`.

**Obtener varias cards**

Mejorando la [versión v3](https://devcommunity.x.com/t/ads-api-version-3/100732) del endpoint diseñado para recuperar una sola card por su valor de card URI, ahora es posible obtener *varias* cards usando el endpoint [GET accounts/:account&#95;id/cards/all](/es/x-ads-api/creatives#cards-fetch). Ahora, en lugar de hacer una solicitud por cada card, puedes recuperar hasta 200 cards en una sola solicitud.

Dos cosas a tener en cuenta:

1. La ruta de la URL ahora es `accounts/:account_id/cards/all`. (La ruta anterior ya no está disponible). Esto es para mantener la coherencia con [el endpoint](/es/x-ads-api/creatives#cards-fetch) diseñado para recuperar una card por id.
2. El parámetro de solicitud obligatorio ahora se llama card&#95;uris (en plural).

**Flexibilidad en la recuperación**

El endpoint [GET accounts/:account&#95;id/targeting&#95;criteria](/es/x-ads-api/campaign-management#get-accounts-account-id-targeting-criteria) ahora admite múltiples IDs de line items. El parámetro line&#95;item&#95;ids, que acepta hasta 200 IDs, es obligatorio. Anteriormente, solo se aceptaba un único line item, lo que dificultaba la sincronización. Con este cambio, ahora es posible recuperar más segmentaciones en menos tiempo.

Los siguientes endpoints ahora también admiten múltiples IDs de line items, aunque el parámetro line&#95;item&#95;ids es opcional para estos.

* [GET accounts/:account&#95;id/line&#95;item&#95;apps](https://developer.x.com/en/docs/x-ads-api/campaign-management/api-reference/line-item-apps#get-accounts-account-id-line-item-apps)
* [GET accounts/:account&#95;id/media&#95;creatives](/es/x-ads-api/campaign-management#get-accounts-account-id-media-creatives)
* [GET accounts/:account&#95;id/promoted&#95;accounts](/es/x-ads-api/campaign-management#get-accounts-account-id-promoted-accounts)
* [GET accounts/:account&#95;id/preroll&#95;call&#95;to&#95;actions](/es/x-ads-api/creatives#preroll-call-to-actions)

<div id="changed">
  #### Cambiado
</div>

**Recuperación de campañas y line items en borrador**

Se ha actualizado la forma en que se recuperan las campañas y los line items en borrador. Ahora, el parámetro with&#95;draft(boolean), cuando se establece en true, devuelve *tanto* entidades en borrador como entidades no en borrador. Esto es coherente con la forma en que se recuperan las entidades eliminadas (es decir, usando with&#95;deleted). Anteriormente, obtener tanto entidades en borrador como no en borrador requería al menos dos solicitudes. Ahora, esto se puede hacer en una sola llamada a la API.

| **v4** | **v5** |
| :--- | :--- | :--- |
| `draft_only` | `with_draft` |     |

**Segmentación por duración de activación de red**

La Ads API ha resuelto un problema de visualización en el que, después de agregar la segmentación Network Activation Duration, el tipo de segmentación en la Respuesta incluía el sufijo &#95;IN&#95;SEC. Hacer referencia a segundos resultaba confuso, ya que Network Activation Duration siempre se representa en meses. Esta corrección hace que la representación sea coherente y reduce la confusión.

| **v4** | **v5** |
| :--- | :--- | :--- |
| `NETWORK_ACTIVATION_DURATION_IN_SEC` | `NETWORK_ACTIVATION_DURATION` |     |

**Recuentos totales y cursores**

En v5, with&#95;total&#95;count y cursor son exclusivos. Especificar ambos en una solicitud devolverá el código de error EXCLUSIVE&#95;PARAMETERS. Antes de v5, with&#95;total&#95;count se ignoraba cuando cursor se especificaba. Este cambio hace explícita la relación.

<div id="removed">
  #### Eliminado
</div>

Se están eliminando tres campos de las respuestas de Ads API: preview&#95;url, account&#95;id y parent&#95;ids. El esfuerzo de ingeniería necesario para estos tres es mínimo.

* En v4, se anunció que el parámetro de respuesta preview&#95;url para las cards siempre era null. El paso final en esta migración es eliminar preview&#95;url de todas las respuestas de cards.
* El atributo de respuesta account&#95;id se está eliminando para los siguientes recursos, dado que el id de cuenta de anuncios ya está presente en la URL, así como en request.params. (Es intencional excluir los instrumentos de financiación de esta lista, ya que los parent IDs deberían estar presentes en los objetos de respuesta, cuando sea posible, y las account IDs son entidades padre de los instrumentos de financiación).
  * Account media
  * App event providers
  * App event tags
  * Campaigns
  * Cards
  * Line items
  * Promotable users
  * Targeting criteria
* Para las solicitudes [GET accounts/:account&#95;id/targeting&#95;criteria](/es/x-ads-api/campaign-management#get-accounts-account-id-targeting-criteria), ya no devolvemos el campo parent&#95;ids, ya que siempre era un array vacío.

**Non-media app cards**

En v5, las non-media app cards ya no son compatibles. [Anteriormente](https://devcommunity.x.com/t/deprecation-announcement-app-download-cards/87807), se eliminó la capacidad de crear o editar non-media app cards. Ahora, los endpoints restantes para este recurso se están desaprobando.

* Nota: Esto **no** afecta a las image and video app download cards.

**Account media creates**

El endpoint POST accounts/:account&#95;id/account&#95;media ya no está disponible en v5. Otros endpoints para este recurso *no* se ven afectados. La razón de este cambio es que, al agregar contenido multimedia a la [Media Library](/es/x-ads-api/creatives#media-library), hay casos en los que esos recursos *automáticamente* se agregan como entidades de Account Media y tratar de agregar un recurso ya existente al recurso Account Media da como resultado un error. Esto sucede en los siguientes casos:

* Los recursos `AMPLIFY_VIDEO` agregados a la Media Library se agregan automáticamente como recursos de Account Media con el tipo creativo `PREROLL`.
* Las imágenes con dimensiones específicas agregadas a la Media Library se agregan automáticamente como recursos de Account Media. El tipo creativo (por ejemplo, `INTERSTITIAL`) depende de las dimensiones de la imagen. (Para las dimensiones, consulta nuestra página de [Enumerations](/es/x-ads-api/introduction).)

La versión 4 de la Ads API se lanza hoy, 28 de agosto de 2018.

Consulta nuestra página de [Versions](/es/x-ads-api/introduction) para obtener detalles sobre nuestra estrategia de versionado.

<div id="new">
  #### Nuevo
</div>

***Audiences API***

La nueva Audiences API se basa en nuestro nuevo backend de procesamiento de audiencias, que proporciona una mayor solidez y fiabilidad. Este nuevo endpoint permitirá a los socios proporcionar varios tipos de identificadores de usuario para un mismo usuario, lo que significa que podemos utilizar señales adicionales para la coincidencia. La documentación de referencia para el nuevo endpoint de Audience se puede encontrar [aquí](/es/x-ads-api/audiences). Nuestro plan es seguir publicando actualizaciones y mejoras de este producto durante el resto del año.

Los siguientes endpoints dejarán de estar disponibles en la v4 debido a que su funcionalidad es redundante (seguirán funcionando en la v3 y se retirarán por completo (**sunset**) cuando la v3 deje de estar disponible):

* TON Upload:
  * GET accounts/:account&#95;id/tailored&#95;audience&#95;changes
  * GET accounts/:account&#95;id/tailored&#95;audience&#95;changes/:tailored&#95;audience&#95;change&#95;id
  * POST accounts/:account&#95;id/tailored&#95;audience&#95;changes
  * PUT accounts/:accounti&#95;d/tailored&#95;audiences/global&#95;opt&#95;out
* Real Time Audiences:
  * POST tailored&#95;audience&#95;memberships

Por último, el parámetro `list_type` se eliminará de la solicitud y la respuesta en *todos* los [endpoints de Tailored Audiences](/es/x-ads-api/audiences) en la versión 4.

***Settings Endpoints***

Ahora ofrecemos la posibilidad de que los administradores de cuentas definan y actualicen la configuración de usuario, de cuenta y fiscal. Los [User settings](/es/x-ads-api/campaign-management#get-accounts-account-id-user-settings-user-id) corresponden a las preferencias de contacto específicas del usuario para una cuenta de anuncios determinada. Usando el endpoint [PUT accounts/:account&#95;id](/es/x-ads-api/campaign-management#put-accounts-account-id), los anunciantes ahora pueden actualizar el nombre de su cuenta y el tipo de industria. Por último, los endpoints de [tax settings](/es/x-ads-api/campaign-management#get-accounts-account-id-tax-settings) permiten a los anunciantes en países donde se aplica un impuesto sobre el valor añadido (IVA) actualizar información como el nombre de la empresa, la dirección, el id de IVA y si la cuenta es propiedad del anunciante o de una agencia que anuncia en nombre de un anunciante.

Estamos actualizando los valores del enum para el parámetro `lookalike_expansion` en los endpoints [POST accounts/:account&#95;id/line&#95;items](/es/x-ads-api/campaign-management#post-accounts-account-id-line-items) y [PUT accounts/:accountit/line&#95;items/:line&#95;item&#95;id](/es/x-ads-api/campaign-management#put-accounts-account-id-line-items-line-item-id).

| :--- | :--- |

* [POST accounts/:account&#95;id/cards/image&#95;app&#95;download](https://devcommunity.x.com/t/ads-api-version-11/168814)
* [PUT accounts/:account&#95;id/cards/image&#95;app&#95;download/:card&#95;id](https://developer.x.com/content/developer-twitterhttps://developer.x.com/en/docs/ads/creatives/api-reference/image-app-download#put-accounts-account-id-cards-image-app-download-card-id)
* [POST accounts/:account&#95;id/cards/video&#95;app&#95;download](https://developer.x.com/content/developer-twitter/en/docs/ads/creatives/api-reference/video-app-download#post-accounts-account-id-cards-video-app-download)
* [PUT accounts/:account&#95;id/cards/video&#95;app&#95;download/:card&#95;id](https://developer.x.com/content/developer-twitter/en/docs/ads/creatives/api-reference/video-app-download#put-accounts-account-id-cards-video-app-download-card-id)

Esto no afecta el comportamiento ni los valores aceptados para estos parámetros y es únicamente un cambio de nombre.

**`preview_url` siempre null**

Como se prometió en el anuncio de v3, todas las tarjetas existentes ahora tienen un `card_uri`. Como resultado, el valor de `preview_url` siempre será `null`.

Como recordatorio, asocie una tarjeta con un Tuit mediante su valor `card_uri`. Consulte la siguiente solicitud de ejemplo.

$ twurl -X POST -H ads-api.x.com &quot;/4/accounts/18ce54d4x5t/tweet?text=Version 4&amp;card&#95;uri=card://958225772740714496&quot;

<div id="removed">
  #### Eliminado
</div>

**Endpoints de vídeo**

Los endpoints accounts/:account&#95;id/videos ya no estarán disponibles en v4. Este endpoint ha quedado obsoleto con la introducción de los endpoints de [Media Library](/es/x-ads-api/creatives#get-accounts-account-id-media-library). Consulta la siguiente comparación de uso.

* Endpoint de vídeos de v3: `twurl -H ads-api.x.com "/3/accounts/18ce54d4x5t/videos"`

* Endpoint de Media Library de v4 para vídeos: `twurl -H ads-api.x.com "/4/accounts/18ce54d4x5t/media_library?media_type=VIDEO"`

Los endpoints de Media Library tienen paridad completa con los endpoints de vídeos y también admiten funcionalidades adicionales, como la capacidad de gestionar imágenes y GIF. Se pide a los socios que usen exclusivamente Media Library para cualquier gestión de contenido multimedia.

**`as_user_id` en la vista de Tuit**

El parámetro `as_user_id` disponible en el endpoint [GET accounts/:account&#95;id/tweet/preview/:tweet&#95;id](/es/x-ads-api/creatives#get-accounts-account-id-tweets) ya no será aceptado. La vista previa siempre se mostrará como si fuera el autor del Tuit.

La versión 3 de la Ads API [se lanzó](https://devcommunity.x.com/t/ads-api-version-3/100732) el 1 de febrero de 2018. La versión 2 de la Ads API llegará al final de su vida útil el 1 de agosto de 2018.

También anunciamos que quedará en desuso el endpoint [PUT accounts/:account&#95;id/targeting&#95;criteria](/es/x-ads-api/campaign-management#get-accounts-account-id-targeting-criteria). Por último, la versión 3 incluye algunos cambios menores en parámetros y respuestas y un límite de tamaño de lote más bajo.

Como con la [versión 2](https://devcommunity.x.com/t/ads-api-version-2/90360), damos a los socios **6 meses** para la transición. El **2018-08-01**, la v2 de la Ads API se desactivará. Recomendamos que todos los socios y desarrolladores migren a v3 tan pronto como sea posible.

**Audience Intelligence**

Audience Intelligence ofrece información en tiempo real sobre los hashtags, @handles y eventos más relevantes para una audiencia determinada de X. Por ejemplo, introduce &quot;Male 18-34&quot; en EE. UU. y verás #nintendoswitch, #cardinal y @ricegum en tendencia entre esta audiencia.

Los [endpoints](/es/x-ads-api/audiences) de Audience Intelligence proporcionan la siguiente funcionalidad:

* Dada una audiencia de entrada, recuperar los hashtags, @handles y eventos más relevantes.
* Dada una audiencia de entrada, recuperar información demográfica clave (como edad, género e ingresos del hogar).
* Dada una palabra clave, recuperar la serie temporal del volumen de Tuits.

**Media Library**

La [Media Library](/es/x-ads-api/creatives#get-accounts-account-id-media-library) proporciona la capacidad de gestionar imágenes, GIFs y vídeos para cuentas de anuncios. Estos objetos multimedia se pueden usar en Tuits y para crear tarjetas. También se pueden reutilizar en múltiples creatividades, eliminando la necesidad de subir el mismo recurso varias veces.

Los objetos de la biblioteca se identifican mediante un media&#95;key. Las media keys son valores de tipo cadena de texto con el siguiente formato: por ejemplo, 13&#95;875943225764098048. En la Ads API, avanzamos hacia el uso de media keys para todos los medios.

**Flujo de trabajo de tarjetas mejorado**

Todos nuestros endpoints de tarjetas ahora admiten media keys. Esto permite que los objetos de la Media Library se utilicen para crear o actualizar tarjetas.

Además, estamos introduciendo dos endpoints nuevos para [recuperar los detalles de tarjetas](/es/x-ads-api/creatives#fetching-cards). Estos endpoints se pueden usar para buscar tarjetas utilizadas en Tuits o Tuits programados, por ejemplo, especificando el card&#95;uri o el id. Anteriormente, esto no era posible.

  #### Otros cambios
</div>

Además de estas nuevas funcionalidades, incluimos los siguientes cambios en la versión 3.

**Nuevo**

* La respuesta del endpoint [GET insights/keywords/search](/es/x-ads-api/audiences) ahora incluye un atributo related&#95;keywords con 30 términos relacionados con las palabras clave de entrada.

**Cambiado**

* El tamaño máximo de lote de criterios de segmentación ahora es 500.
* Los atributos de respuesta card&#95;uri y preview&#95;url ahora son mutuamente excluyentes. Cuando una tarjeta tiene un card&#95;uri, el preview&#95;url será null. Cuando una tarjeta no tiene un card&#95;uri, solo se devolverá el preview&#95;url.
  * Todas las tarjetas creadas a partir del 2018-01-29 tendrán un card&#95;uri.
  * Para la versión 4, todas las tarjetas existentes tendrán un card&#95;uri.
* Ya no es posible *crear* tarjetas con imágenes 5:2. Aunque las tarjetas existentes basadas en imágenes 5:2 seguirán funcionando, recomendamos a los socios cambiar al uso de las relaciones de aspecto con mejor rendimiento 1.91:1 o 1:1 (donde se admitan).

**Eliminado**

* El endpoint [PUT accounts/:account&#95;id/targeting&#95;criteria](/es/x-ads-api/campaign-management#get-accounts-account-id-targeting-criteria) ya no está disponible. Hemos decidido realizar este cambio porque el comportamiento de reemplazo con este endpoint generaba confusión entre los anunciantes y no era coherente con nuestros otros endpoints PUT que actualizan un único recurso a la vez. En su lugar, los socios deben usar el endpoint [POST batch/accounts/:account&#95;id/targeting&#95;criteria](/es/x-ads-api/campaign-management#post-batch-accounts-account-id-targeting-criteria), que proporciona mayor flexibilidad, incluida la posibilidad de agregar y eliminar segmentación en una sola solicitud.
* El atributo de respuesta paused ya no se devuelve para instrumentos de financiación. En su lugar, revise el atributo de respuesta entity&#95;status para determinar si un instrumento de financiación está en pausa o no. Además, dado que paused y cancelled corresponden al mismo valor, cancelled tampoco se devuelve ya en la respuesta.
* Hemos eliminado el parámetro card&#95;id del endpoint [GET accounts/:account&#95;id/tweet/preview](/es/x-ads-api/creatives#get-accounts-account-id-tweets).
* Dado que no es posible recuperar Tuits programados eliminados, el parámetro with&#95;deleted ya no se admite.
* El parámetro draft&#95;only se ha eliminado de los siguientes endpoints, ya que estas entidades nunca pueden estar en estado de borrador:
  * [GET accounts/:account&#95;id/targeting&#95;criteria](/es/x-ads-api/campaign-management#get-accounts-account-id-targeting-criteria)
  * [GET accounts/:account&#95;id/promoted&#95;tweets](/es/x-ads-api/campaign-management#get-accounts-account-id-promoted-tweets)
  * [GET accounts/:account&#95;id/promoted&#95;accounts](/es/x-ads-api/campaign-management#get-accounts-account-id-promoted-accounts)
  * [GET accounts/:account&#95;id/media&#95;creatives](/es/x-ads-api/campaign-management#get-accounts-account-id-media-creatives)
  * [GET accounts/:account&#95;id/preroll&#95;call&#95;to&#95;actions](/es/x-ads-api/creatives#get-accounts-account-id-preroll-call-to-actions)

**Nota**

Tanto las Video Website Cards como los Tuits programados han salido ahora de la fase beta. **Cambios en la versión 1:[¶](#changes-in-version-1 "Enlace permanente a este encabezado")**

* [Compatibilidad con versiones](https://blog.x.com/2016/versioning-is-coming-to-twitter-s-ads-apis)

* [Cambios en la estimación de alcance](https://developer.x.com/en/docs/ads/campaign-management/api-reference/reach-estimate.html#get-accounts-account-id-reach-estimate):
* Para ofrecer una mejor estimación del alcance, el endpoint ahora tiene en cuenta el presupuesto. Los siguientes parámetros pasan a ser obligatorios:
  * [nuevo] `campaign_daily_budget_amount_local_micro`
  * `currency`
  * `bid`
  * `objective`
* El objeto de respuesta ha cambiado y ahora devuelve intervalos para los valores de respuesta.
* `infinite_count` ha sido renombrado como `infinite_bid_count` para evitar confusión sobre su propósito
* Además de `count` e `infinite_bid_count`, ahora también se devolverán estos nuevos datos:
  * `impressions`
  * `engagements`
  * `estimated_daily_spend_local_micro`
* Cambio en el tipo de datos para audiencias personalizadas
* El campo `data_type` para Tailored Audiences se ha cambiado de `tailored_audiences` a `tailored_audience` en todas nuestras respuestas.
* Las Audiencias personalizadas compartidas ahora están disponibles en una beta *solo mediante API*. Las audiencias personalizadas compartidas permiten que una sola audiencia se utilice en varias cuentas de anuncios. Usa el endpoint [POST accounts/:account&#95;id/tailored&#95;audiences/:tailored&#95;audience&#95;id/permissions](/es/x-ads-api/audiences) (y endpoints relacionados) para administrar los permisos de una audiencia personalizada que quieras compartir entre cuentas de anuncios.
* Mejoras significativas en la forma de recopilar [análisis](/es/x-ads-api/analytics) de rendimiento para las cuentas de anunciantes:
* Para alinearnos con nuestras [mejores prácticas](/es/x-ads-api/analytics#best-practices), ahora solo permitiremos obtener datos correspondientes a un máximo de **7 días** para los [endpoints síncronos de estadísticas](/es/x-ads-api/analytics#get-stats-accounts-account-id).
* Para simplificar la obtención de métricas, hemos reemplazado el parámetro `metrics` con un nuevo parámetro `metric_groups`. Los desarrolladores simplemente deben especificar qué grupos de métricas desean recibir para una solicitud determinada.
  * Cualquier solicitud de métricas que no sean pertinentes para una entidad determinada se excluirá de la respuesta y se representará como valores `null`. *Estas métricas no computarán para tu límite de costo de analítica.*
* La respuesta se ha **simplificado significativamente** y ahora se ajustará mejor a la forma en que las métricas se muestran en nuestra interfaz de usuario.
  * Anteriormente exponíamos una métrica independiente para cada ubicación (Promoted Tweets in Search, Promoted Tweets in Timelines, Promoted Tweets in Profiles &amp; Tweet Details, X Audience Platform). Ahora devolveremos un conjunto estandarizado de métricas para cada una (en lugar de `promoted_tweet_timeline_impressions`, `promoted_tweet_search_impressions`, `promoted_tweets_profile_impressions`, `promoted_tweets_tpn_impressions`); estas ahora se expondrán, cuando se soliciten, en una de las siguientes categorías como una única métrica, `impressions` (esto se aplica a todas las métricas):
  * `ALL_ON_TWITTER`
  * `PUBLISHER_NETWORK`
  * Cuando realices una solicitud, obtendrás una única métrica `impressions` para que hacer coincidir los valores con los de nuestra interfaz de usuario sea más sencillo.
  * Debes realizar dos consultas para obtener tanto los datos de `ALL_ON_TWITTER` como de `PUBLISHER_NETWORK`, ya que estos no pueden combinarse.
* Los [endpoints de estadísticas asíncronas](/es/x-ads-api/analytics#asynchronous-analytics) ya están disponibles, gracias a los comentarios de nuestros desarrolladores.
  * Un nuevo conjunto de endpoints para solicitar estadísticas de forma *asíncrona*, ya sea para datos que no necesitas de inmediato o para extracciones de datos históricos.
  * Pon en cola un trabajo de estadísticas mediante un único nuevo endpoint. Recuperaremos los datos que has solicitado según lo permitan los recursos.
  * Puedes consultar un endpoint de estado del trabajo para determinar si los datos están disponibles.
  * Una vez que los datos estén disponibles, proporcionaremos un ID de recuperación para que descargues la Respuesta JSON, que reflejará la respuesta del endpoint síncrono.
  * Solicita hasta **90 días** de datos de hasta **20 entidades** en un solo trabajo.
* Consulta nuestra guía de migración a Analytics v1, que incluye la correspondencia entre las métricas de v0 y las de v1
* Mejoras del entorno Sandbox * Ahora puedes [crear varias cuentas de anuncios de prueba](/es/x-ads-api/campaign-management#post-accounts) en el entorno Sandbox. * Ahora puedes crear varios instrumentos de financiación para una cuenta de anuncios de prueba, únicamente en el entorno Sandbox. Esto te permite probar todos nuestros tipos de instrumentos de financiación. Anteriormente, solo había disponible una fuente de financiación `CREDIT_CARD` para realizar pruebas. * ¿Quieres probar una función beta? Ahora puedes activar o desactivar funciones para una cuenta en el entorno Sandbox para adaptarlas a tus necesidades de pruebas.
