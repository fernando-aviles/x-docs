<div id="overview">
  ## Descripción general
</div>

Cada mes realizamos cambios e implementamos varias funciones nuevas en la X Ads API. Estos cambios casi siempre son retrocompatibles; sin embargo, solemos tener un puñado de cambios no retrocompatibles cada año. Hemos recibido comentarios de desarrolladores sobre los desafíos que nuestro ritmo rápido de cambios en la Ads API plantea para sus ciclos de desarrollo al implementar nuevas funciones, gestionar deprecaciones y probar cambios. Queremos mejorar la experiencia de desarrollador al usar nuestra plataforma de Ads, y por eso introdujimos el concepto de versionar nuestros endpoints.

Algunas definiciones de conceptos sobre los que hablamos:

**Versión**: Se refiere al número de versión que se encuentra en la ruta de la URL de cualquier solicitud a la Ads API, por ejemplo: GET /{version_number}/accounts. Este estilo de versionado se conoce como versionado por URI.

**Cambios no retrocompatibles**: Los cambios no retrocompatibles son aquellos que requieren recursos de desarrollo para mantener la funcionalidad existente. Esto incluye los recursos utilizados para investigar los cambios que deben realizarse, determinar las funciones/endpoints que se van a deprecar y la implementación final de todos estos cambios. Una lista de cambios no retrocompatibles incluye, por ejemplo, cosas como:

* Eliminar un parámetro de la solicitud/respuesta de la API

* Modificar el nombre de cualquier parámetro o endpoint

* Cambiar la representación de valores (preview&#95;url → card&#95;uri)

* Cambiar el comportamiento de los endpoints (por ejemplo, estadísticas async vs sync)

* Agregar/cambiar parámetros opcionales u obligatorios (por ejemplo, hacer que nombre sea un campo obligatorio en la solicitud)

**Deprecación**: Las versiones o productos en deprecación dejarán de contar con soporte y se recomienda que los desarrolladores dejen de usar estas APIs.

**Sunset**: Una vez que un producto o una API entra en fase de sunset, el conjunto correspondiente de endpoints dejará de estar disponible a través de la API.

<div id="versioning-strategy">
  ## Estrategia de versionado
</div>

Los principios básicos de la estrategia son:

1. Todos los cambios incompatibles se agruparán en una nueva versión

2. El periodo de obsolescencia para las versiones existentes será de 6 meses cada vez que se anuncie una nueva versión

3. En cualquier momento, la API permitirá solicitudes de dos versiones simultáneamente; sin embargo, la más antigua de las dos no tendrá soporte

4. Con el fin de facilitar una adopción más rápida de nuevos productos, estos se lanzarán de forma continua (fuera de la cadencia de versionado)

5. Todas las respuestas de la API contendrán un `x-current-api-version`, que se establecerá en la versión actual de la API, además de un encabezado `x-api-warn` al llamar a cualquier endpoint de API obsoleto.

Si se produjera algún cambio fundamental en los requisitos del producto que requiriera un cambio incompatible en la API (por ejemplo, descontinuar la segmentación por múltiples intervalos de edad), enviaremos un aviso con 90 días de antelación para anunciar este cambio incompatible y, transcurridos al menos 90 días desde la publicación del aviso, se implementará el cambio incompatible.

<div id="v5">
  ### v5
</div>

Hoy, 28 de febrero de 2019, X presenta Ads API v5, con actualizaciones centradas en mejorar la escalabilidad y la eficiencia.

Esta versión incluye un nuevo endpoint para determinar qué entidades estuvieron activas en un período de tiempo determinado, estadísticas para Media Creatives (es decir, vídeos in-stream e imágenes en X Audience Platform), la posibilidad de obtener *múltiples* cards por URI de card y más flexibilidad a la hora de recuperar criterios de segmentación y otras entidades. Además, hemos corregido algunos errores y actualizado los nombres de parámetros y los atributos de la respuesta. Por último, las app cards sin contenido multimedia (non-media app cards) y el endpoint POST `accounts/:account_id/account_media` han quedado obsoletos.

Como en versiones anteriores, habrá un período de transición de 6 meses para migrar a v5. El **2019-08-28** la versión 4 de Ads API dejará de estar disponible. Recomendamos a todos los socios que migren a la última versión de la API tan pronto como sea posible para evitar cualquier interrupción del servicio. *La versión 3 de Ads API ha llegado al final de su vida útil y ya no está disponible.*

<div id="new">
  #### Nuevo
</div>

**Determinación de qué entidades estuvieron activas**

El endpoint [Active Entities](/es/x-ads-api/analytics#active-entities-2) indica si las métricas de analítica para entidades de anuncios han cambiado. Diseñado para usarse junto con los endpoints de analítica, Active Entities funciona especificando un tipo de entidad y un intervalo de fechas (con un máximo de 90 días) y devuelve una lista de ID de entidad para las que tu plataforma debería solicitar analítica. No se deben consultar en solicitudes de analítica posteriores las ID distintas de las devueltas.

Este endpoint admite los siguientes tipos de entidad: `CAMPAIGN`, `FUNDING_INSTRUMENT`, `LINE_ITEM`, `MEDIA_CREATIVE` y `PROMOTED_TWEET`.

**Estadísticas de `MEDIA_CREATIVE`**

Los endpoints de analítica de Ads API ahora proporcionan métricas para entidades Media Creative. Los Media Creative son la forma en que se promocionan los anuncios in-stream o las imágenes en X Audience Platform. La interfaz de X Ads muestra las métricas de Media Creative en las pestañas “In-stream videos” y “Display creatives”. Tanto los endpoints de analítica [sincrónicos](/es/x-ads-api/analytics#get-stats-accounts-account-id) como [asincrónicos](/es/x-ads-api/analytics#asynchronous-analytics) ahora admiten la enumeración de entidad `MEDIA_CREATIVE`.

**Obtener varias cards**

Mejorando la [versión v3](https://devcommunity.x.com/t/ads-api-version-3/100732) del endpoint diseñado para recuperar una sola card por el valor de su URI de card, ahora es posible obtener *varias* cards usando el endpoint [GET accounts/:account&#95;id/cards/all](/es/x-ads-api/creatives#cards-fetch). Ahora, en lugar de hacer una solicitud por cada card, puedes recuperar hasta 200 cards en una sola solicitud.

Dos aspectos a tener en cuenta:

1. La ruta de la URL ahora es `accounts/:account_id/cards/all`. (La ruta anterior ya no está disponible). Esto es para mantener la coherencia con [el endpoint](/es/x-ads-api/creatives#cards-fetch) diseñado para recuperar una card por ID.
2. El parámetro de solicitud obligatorio ahora se llama card&#95;uris (en plural).

**Flexibilidad al recuperar información**

El endpoint [GET accounts/:account&#95;id/targeting&#95;criteria](/es/x-ads-api/campaign-management#get-accounts-account-id-targeting-criteria) ahora admite múltiples ID de line items. El parámetro line&#95;item&#95;ids, que acepta hasta 200 ID, es obligatorio. Anteriormente solo se aceptaba un único line item, lo que dificultaba la sincronización. Con este cambio, ahora es posible recuperar más segmentaciones en menos tiempo.

Los siguientes endpoints ahora también admiten múltiples ID de line items, aunque el parámetro line&#95;item&#95;ids es opcional en estos casos.

* [GET accounts/:account&#95;id/line&#95;item&#95;apps](https://developer.x.com/en/docs/x-ads-api/campaign-management/api-reference/line-item-apps#get-accounts-account-id-line-item-apps)
* [GET accounts/:account&#95;id/media&#95;creatives](/es/x-ads-api/campaign-management#get-accounts-account-id-media-creatives)
* [GET accounts/:account&#95;id/promoted&#95;accounts](/es/x-ads-api/campaign-management#get-accounts-account-id-promoted-accounts)
* [GET accounts/:account&#95;id/preroll&#95;call&#95;to&#95;actions](/es/x-ads-api/creatives#preroll-call-to-actions)

<div id="changed">
  #### Cambiado
</div>

**Recuperación de campañas y líneas de pedido en borrador**

La forma en que se recuperan las campañas y las líneas de pedido en borrador se ha actualizado. Ahora, el parámetro with&#95;draft(boolean), cuando se establece en true, devuelve *tanto* entidades en borrador como no en borrador. Esto es coherente con la forma en que se recuperan las entidades eliminadas (es decir, usando with&#95;deleted). Anteriormente, obtener tanto entidades en borrador como no en borrador requería al menos dos solicitudes. Ahora, esto se puede hacer en una sola llamada a la API.

| **v4** | **v5** |
| :--- | :--- | :--- |
| `draft_only` | `with_draft` |     |

**Segmentación por duración de activación de la red**

La Ads API ha resuelto un problema de visualización en el que, después de agregar la segmentación de Network Activation Duration, el tipo de segmentación en la Respuesta incluía un sufijo &#95;IN&#95;SEC. Hacer referencia a segundos resultaba confuso, ya que Network Activation Duration siempre se representa en meses. Esta corrección hace que la representación sea coherente y reduce la confusión.

| **v4** | **v5** |
| :--- | :--- | :--- |
| `NETWORK_ACTIVATION_DURATION_IN_SEC` | `NETWORK_ACTIVATION_DURATION` |     |

**Recuentos totales y cursores**

En v5, with&#95;total&#95;count y cursor son excluyentes. Especificar ambos en una solicitud devolverá el código de error EXCLUSIVE&#95;PARAMETERS. Antes de v5, with&#95;total&#95;count se ignoraba cuando se especificaba cursor. Este cambio hace que la relación sea explícita.

<div id="removed">
  #### Eliminados
</div>

Se están eliminando tres campos de las respuestas de Ads API: preview&#95;url, account&#95;id y parent&#95;ids. El nivel de esfuerzo de ingeniería requerido para estos tres es mínimo.

* En v4, se anunció que el parámetro de respuesta preview&#95;url para cards siempre era null. El paso final en esta migración es eliminar preview&#95;url de todas las respuestas de cards.
* El atributo de respuesta account&#95;id se está eliminando para los siguientes recursos, dado que el ID de la cuenta de anuncios ya está presente en la URL, así como en request.params. (Es intencional excluir los instrumentos de financiación de esta lista, ya que los IDs principales deben estar presentes en los objetos de respuesta, cuando sea posible, y los IDs de cuenta son entidades principales de los instrumentos de financiación).
  * Account media
  * App event providers
  * App event tags
  * Campaigns
  * Cards
  * Line items
  * Promotable users
  * Targeting criteria
* Para las solicitudes [GET accounts/:account&#95;id/targeting&#95;criteria](/es/x-ads-api/campaign-management#get-accounts-account-id-targeting-criteria), ya no devolvemos el campo parent&#95;ids, ya que siempre era un array vacío.

**Non-media app cards**

En v5, las non-media app cards ya no se admiten. [Anteriormente](https://devcommunity.x.com/t/deprecation-announcement-app-download-cards/87807), se eliminó la posibilidad de crear o editar non-media app cards. Ahora, los endpoints restantes para este recurso se están dejando de admitir.

* Nota: Esto **no** afecta a las image app download cards ni a las video app download cards.

**Creación de Account Media**

El endpoint POST accounts/:account&#95;id/account&#95;media ya no está disponible en v5. Otros endpoints para este recurso *no* se ven afectados. La razón de este cambio es que, al agregar contenido multimedia a la [Media Library](/es/x-ads-api/creatives#media-library), hay casos en los que esos recursos *automáticamente* se agregan como entidades de Account Media, y tratar de agregar un recurso ya existente al recurso Account Media da como resultado un error. Esto ocurre en los siguientes casos.

* Los recursos `AMPLIFY_VIDEO` agregados a la Media Library se agregan automáticamente como recursos de Account Media con el tipo de creativo `PREROLL`.
* Las imágenes con dimensiones específicas agregadas a la Media Library se agregan automáticamente como recursos de Account Media. El tipo de creativo (por ejemplo, `INTERSTITIAL`) depende de las dimensiones de la imagen. (Para las dimensiones, consulta nuestra página de [Enumerations](/es/x-ads-api/introduction).)

<div id="v4">
  ### v4
</div>

La versión 4 de la Ads API se lanza hoy, 28 de agosto de 2018.

Esta versión incluye mejoras en nuestro producto [Audiences](/es/x-ads-api/audiences), incluida una nueva interfaz de API impulsada por un sistema de procesamiento de audiencias más sólido. La versión 4 también incluye un conjunto de endpoints para administrar la configuración de usuario, cuenta e impuestos. Además, los endpoints accounts/:account&#95;id/videos se han declarado obsoletos. Esta versión también incluye algunos cambios menores en los parámetros y en los nombres de las respuestas.

Al igual que con la versión 3, ofrecemos un período de transición de 6 meses. A partir del **2019-02-28**, la versión 3 de la Ads API ya no estará disponible. Recomendamos a todos los socios que migren a la última versión de la API lo antes posible para evitar cualquier interrupción del servicio. Consulta nuestra página de [Versions](/es/x-ads-api/introduction) para obtener más detalles sobre nuestra estrategia de versionado.

#### New

***Audience API***

La nueva Audiences API está creada sobre nuestro nuevo backend de procesamiento de audiencias, que proporciona mayor solidez y confiabilidad. Este nuevo endpoint permitirá a los socios proporcionar múltiples tipos de identificadores de usuario para un mismo usuario, lo que significa que podemos utilizar señales adicionales para la correlación. La documentación de referencia para el nuevo endpoint de Audiences se puede encontrar [aquí](/es/x-ads-api/audiences). Planeamos seguir lanzando actualizaciones y mejoras de este producto durante el resto del año.

Los siguientes endpoints ya no estarán disponibles en v4 debido a funcionalidad redundante (seguirán funcionando en v3 y se **retirarán** por completo cuando v3 ya no esté disponible):

* TON Upload:
  * GET accounts/:account&#95;id/tailored&#95;audience&#95;changes
  * GET accounts/:account&#95;id/tailored&#95;audience&#95;changes/:tailored&#95;audience&#95;change&#95;id
  * POST accounts/:account&#95;id/tailored&#95;audience&#95;changes
  * PUT accounts/:accounti&#95;d/tailored&#95;audiences/global&#95;opt&#95;out
* Real Time Audiences:
  * POST tailored&#95;audience&#95;memberships

Por último, el parámetro `list_type` se eliminará de la solicitud y la respuesta en *todos* los [endpoints de Tailored Audiences](/es/x-ads-api/audiences) en la versión 4.

***Settings Endpoints***

Ahora ofrecemos la posibilidad de que los administradores de cuenta configuren y actualicen la configuración de usuario, cuenta e impuestos. La [configuración de usuario](/es/x-ads-api/campaign-management#get-accounts-account-id-user-settings-user-id) corresponde a las preferencias de contacto específicas del usuario para una cuenta de anuncios determinada. Usando el endpoint [PUT accounts/:account&#95;id](/es/x-ads-api/campaign-management#put-accounts-account-id), los anunciantes ahora pueden actualizar el nombre de su cuenta y el tipo de industria. Por último, los endpoints de [tax settings](/es/x-ads-api/campaign-management#get-accounts-account-id-tax-settings) permiten a los anunciantes en países donde se cobra un impuesto al valor agregado (IVA) actualizar información como el nombre de la empresa, la dirección, el identificador de IVA y si la cuenta pertenece al anunciante o a una agencia que anuncia en nombre de un anunciante.

#### Cambios

***Cambios de nombre universales para Lookalike***

Estamos actualizando los valores del tipo de enumeración (`enum`) para el parámetro `lookalike_expansion` en los endpoints [POST accounts/:account&#95;id/line&#95;items](/es/x-ads-api/campaign-management#post-accounts-account-id-line-items) y [PUT accounts/:accountit/line&#95;items/:line&#95;item&#95;id](/es/x-ads-api/campaign-management#put-accounts-account-id-line-items-line-item-id).

| **v3** | **v4** |
| :--- | :--- |
| `NARROW` | `DEFINED` |
| `BALANCED` | `EXPANDED` |

**Uso de `country_code` en todas partes**

Como parte de un esfuerzo más amplio en torno a la [consistencia](https://devcommunity.x.com/t/feedback-ads-api-consistency/109145) en la Ads API, estamos cambiando el nombre de los parámetros en los siguientes endpoints de `app_country_code` a `country_code`.

* [POST accounts/:account&#95;id/cards/image&#95;app&#95;download](https://devcommunity.x.com/t/ads-api-version-11/168814)
* [PUT accounts/:account&#95;id/cards/image&#95;app&#95;download/:card&#95;id](https://developer.x.com/content/developer-twitterhttps://developer.x.com/en/docs/ads/creatives/api-reference/image-app-download#put-accounts-account-id-cards-image-app-download-card-id)
* [POST accounts/:account&#95;id/cards/video&#95;app&#95;download](https://developer.x.com/content/developer-twitter/en/docs/ads/creatives/api-reference/video-app-download#post-accounts-account-id-cards-video-app-download)
* [PUT accounts/:account&#95;id/cards/video&#95;app&#95;download/:card&#95;id](https://developer.x.com/content/developer-twitter/en/docs/ads/creatives/api-reference/video-app-download#put-accounts-account-id-cards-video-app-download-card-id)

Esto no afecta el comportamiento ni los valores aceptados para estos parámetros y es únicamente un cambio de nombre.

**`preview_url` siempre null**

Tal como se prometió en el anuncio de la v3, todas las tarjetas existentes ahora tienen un `card_uri`. Como resultado, el valor de `preview_url` siempre será `null`.

Como recordatorio, asocia una tarjeta con un Tuit mediante su valor `card_uri`. Consulta el siguiente ejemplo de solicitud.

$ twurl -X POST -H ads-api.x.com &quot;/4/accounts/18ce54d4x5t/tweet?text=Version 4&amp;card&#95;uri=card://958225772740714496&quot;

<div id="removed">
  #### Eliminados
</div>

**Endpoints de video**

Los endpoints accounts/:account&#95;id/videos ya no estarán disponibles en la v4. Este endpoint ha quedado obsoleto con la introducción de los endpoints de [Media Library](/es/x-ads-api/creatives#get-accounts-account-id-media-library). Consulta la siguiente comparación de uso.

* endpoint de videos de v3: `twurl -H ads-api.x.com "/3/accounts/18ce54d4x5t/videos"`

* endpoint de Media Library de v4 para videos: `twurl -H ads-api.x.com "/4/accounts/18ce54d4x5t/media_library?media_type=VIDEO"`

Los endpoints de Media Library tienen paridad total con los endpoints de videos y también admiten funcionalidad adicional, como la capacidad de gestionar imágenes y GIF. Se solicita a los socios que utilicen Media Library exclusivamente para cualquier administración de contenido multimedia.

**`as_user_id` en vista de Tuit**

El parámetro `as_user_id` disponible en el endpoint [GET accounts/:account&#95;id/tweet/preview/:tweet&#95;id](/es/x-ads-api/creatives#get-accounts-account-id-tweets) ya no será aceptado. La vista previa siempre se representará desde la perspectiva del autor del Tuit.

<div id="v3">
  ### v3
</div>

La versión 3 de la Ads API [se lanzó](https://devcommunity.x.com/t/ads-api-version-3/100732) el 1 de febrero de 2018. La versión 2 de la Ads API llegará al final de su vida útil el 1 de agosto de 2018.

Esta versión incluye nuestro nuevo producto Audience Intelligence, acceso a la Media Library y flujos de trabajo de tarjetas mejorados. También anunciamos la obsolescencia del endpoint [PUT accounts/:account&#95;id/targeting&#95;criteria](/es/x-ads-api/campaign-management#get-accounts-account-id-targeting-criteria). Por último, la versión 3 incluye algunos cambios menores en parámetros y respuestas y un límite inferior para el tamaño de los lotes.

Al igual que con la [versión 2](https://devcommunity.x.com/t/ads-api-version-2/90360), damos a los socios **6 meses** para la transición. El **2018-08-01**, la v2 de la Ads API se desactivará. Recomendamos a todos los socios y desarrolladores que migren a v3 lo antes posible.

**Audience Intelligence**

Audience Intelligence ofrece información en tiempo real sobre los principales hashtags, @handles y eventos más relevantes para una audiencia de X determinada. Por ejemplo, introduce &quot;Hombre 18-34&quot; en EE. UU. y verás #nintendoswitch, #cardinal y @ricegum en tendencia entre esta audiencia.

Los [endpoints](/es/x-ads-api/audiences) de Audience Intelligence proporcionarán la siguiente funcionalidad:

* Dada una audiencia de entrada, obtener los hashtags, @handles y eventos más relevantes.
* Dada una audiencia de entrada, obtener información demográfica clave (como edad, género e ingresos del hogar).
* Dada una palabra clave, obtener la serie temporal del volumen de Tuits.

**Media Library**

La [Media Library](/es/x-ads-api/creatives#get-accounts-account-id-media-library) permite gestionar imágenes, GIF y vídeos para cuentas de anuncios. Estos objetos multimedia se pueden usar en Tuits y para crear tarjetas. También se pueden reutilizar en múltiples creatividades, lo que elimina la necesidad de cargar el mismo recurso varias veces.

Los objetos de la biblioteca se identifican mediante una media&#95;key. Las media keys son valores de tipo cadena de texto con el siguiente formato: 13&#95;875943225764098048, por ejemplo. En la Ads API, avanzamos hacia el uso de media keys para todos los elementos multimedia.

**Flujo de trabajo de tarjetas mejorado**

Todos nuestros endpoints de tarjetas ahora admiten media keys. Esto permite usar objetos de la Media Library para crear o actualizar tarjetas.

Además, introducimos dos nuevos endpoints para [recuperar detalles de tarjetas](/es/x-ads-api/creatives#fetching-cards). Estos endpoints pueden utilizarse para buscar tarjetas usadas en Tuits o Tuits programados, por ejemplo, especificando ya sea el card&#95;uri o el id. Antes, esto no era posible.

  #### Otros cambios

Además de estas nuevas funciones, incluimos los siguientes cambios en la versión 3.

**Nuevo**

* La respuesta del endpoint [GET insights/keywords/search](/es/x-ads-api/audiences) ahora incluye un atributo related&#95;keywords con 30 términos relacionados con las palabras clave de entrada.

**Cambiado**

* El tamaño máximo de lote de criterios de segmentación ahora es 500.
* Los atributos de respuesta card&#95;uri y preview&#95;url ahora son mutuamente excluyentes. Cuando una tarjeta tiene una card&#95;uri, el preview&#95;url será null. Cuando una tarjeta no tiene una card&#95;uri, solo se devolverá el preview&#95;url.
  * Todas las tarjetas creadas a partir de 2018-01-29 tendrán una card&#95;uri.
  * Para la versión 4, todas las tarjetas existentes tendrán una card&#95;uri.
* Ya no es posible *crear* tarjetas con imágenes 5:2. Aunque las tarjetas existentes basadas en imágenes 5:2 seguirán funcionando, recomendamos a los socios que cambien a las relaciones de aspecto de mayor rendimiento 1.91:1 o 1:1 (cuando se admitan)

**Eliminado**

* El endpoint [PUT accounts/:account&#95;id/targeting&#95;criteria](/es/x-ads-api/campaign-management#get-accounts-account-id-targeting-criteria) ya no está disponible. Hemos decidido realizar este cambio porque el comportamiento de reemplazo con este endpoint causaba confusión a los anunciantes y no era coherente con nuestros otros endpoints PUT, que actualizan un único recurso a la vez. En su lugar, los socios deben utilizar el endpoint [POST batch/accounts/:account&#95;id/targeting&#95;criteria](/es/x-ads-api/campaign-management#post-batch-accounts-account-id-targeting-criteria), que ofrece mayor flexibilidad, incluida la capacidad de agregar y eliminar segmentaciones en una única solicitud.
* El atributo de respuesta paused ya no se devuelve para los instrumentos de financiación. En su lugar, consulte el atributo de respuesta entity&#95;status para determinar si un instrumento de financiación está en estado paused o no. Además, dado que paused y cancelled corresponden al mismo valor, cancelled tampoco se devuelve en la respuesta.
* Hemos eliminado el parámetro card&#95;id del endpoint [GET accounts/:account&#95;id/tweet/preview](/es/x-ads-api/creatives#get-accounts-account-id-tweets).
* Debido a que no es posible recuperar Tuits programados eliminados, el parámetro with&#95;deleted ya no es compatible.
* El parámetro draft&#95;only se ha eliminado de los siguientes endpoints, ya que estas entidades nunca pueden estar en estado de borrador:
  * [GET accounts/:account&#95;id/targeting&#95;criteria](/es/x-ads-api/campaign-management#get-accounts-account-id-targeting-criteria)
  * [GET accounts/:account&#95;id/promoted&#95;tweets](/es/x-ads-api/campaign-management#get-accounts-account-id-promoted-tweets)
  * [GET accounts/:account&#95;id/promoted&#95;accounts](/es/x-ads-api/campaign-management#get-accounts-account-id-promoted-accounts)
  * [GET accounts/:account&#95;id/media&#95;creatives](/es/x-ads-api/campaign-management#get-accounts-account-id-media-creatives)
  * [GET accounts/:account&#95;id/preroll&#95;call&#95;to&#95;actions](/es/x-ads-api/creatives#get-accounts-account-id-preroll-call-to-actions)

**Cambios incompatibles/funciones obsoletas[¶](#breaking-changes-deprecations "Enlace permanente a este encabezado")**

* `total_count` ahora es un atributo de respuesta opcional. Solo estará disponible si `with_total_count` se establece en `true`

* Los campos `paused` y `draft_only` en los objetos de solicitud y respuesta `line_items` y `campaigns` se han reemplazado por un único parámetro `entity_status`

La única excepción es que, en v2, `CITY` ahora es `METROS`, para reflejar correctamente el hecho de que el tipo de ubicación se refiere a Designated Market Areas (DMAs) o “metros”.

* `display_properties` en los endpoints PUT accounts/:account&#95;id/promoted&#95;tweets. Este valor tampoco se devolverá ya como parte de la respuesta

* Como resultado del punto anterior, ya no es posible actualizar (PUT) entidades promoted&#95;tweets

* Se ha eliminado el parámetro `line_item_id` en el endpoint [GET accounts/:account&#95;id/promoted&#95;tweets](/es/x-ads-api/campaign-management#get-accounts-account-id-promoted-tweets)

* Ya no será posible crear tarjetas de sitio web 5:2 en los endpoints v2

* El atributo de respuesta `data_type` ya no se devuelve

**Cambios en la versión 1:[¶](#changes-in-version-1 "Permalink to this headline")**

* [Compatibilidad con versiones](https://blog.x.com/2016/versioning-is-coming-to-twitter-s-ads-apis)
* El [objetivo](/es/x-ads-api/campaign-management#objective-based-campaigns) `CUSTOM` ya no es compatible
* [Batch endpoints](/es/x-ads-api/campaign-management#post-batch-accounts-account-id-campaigns) ya están disponibles de forma general
* [Cambios en la estimación de alcance](https://developer.x.com/en/docs/ads/campaign-management/api-reference/reach-estimate.html#get-accounts-account-id-reach-estimate):
* Para ofrecer una mejor estimación del alcance, el endpoint ahora tiene en cuenta el presupuesto. Los siguientes parámetros ahora son obligatorios:
  * [nuevo] `campaign_daily_budget_amount_local_micro`
  * `currency`
  * `bid`
  * `objective`
* El objeto de respuesta ha cambiado y ahora incluye rangos para los valores de respuesta.
* `infinite_count` se ha renombrado como `infinite_bid_count` para evitar confusión sobre su propósito
* Además de `count` e `infinite_bid_count`, ahora se devolverán los siguientes nuevos datos:
  * `impressions`
  * `engagements`
  * `estimated_daily_spend_local_micro`
* Cambio del tipo de datos para audiencias personalizadas
* El `data_type` para Tailored Audiences se ha cambiado de `tailored_audiences` a `tailored_audience` en todas nuestras respuestas.
* Las Shared Tailored Audiences ahora están disponibles como una beta *solo mediante API*. Las Shared Tailored Audiences permiten que una única audiencia se utilice en varias cuentas de anuncios. Usa el endpoint [POST accounts/:account&#95;id/tailored&#95;audiences/:tailored&#95;audience&#95;id/permissions](/es/x-ads-api/audiences) (y los endpoints relacionados) para administrar los permisos de una audiencia personalizada que quieras compartir entre cuentas de anuncios.
* Mejoras significativas en la forma de recopilar [estadísticas](/es/x-ads-api/analytics) de rendimiento de las cuentas de anunciantes:
* Para alinearnos con nuestras [mejores prácticas](/es/x-ads-api/analytics#best-practices), ahora solo permitiremos extraer datos de hasta **7 días** para los [endpoints síncronos de estadísticas](/es/x-ads-api/analytics#get-stats-accounts-account-id).
* Para simplificar la obtención de métricas, hemos reemplazado el parámetro `metrics` por un nuevo parámetro `metric_groups`. Los desarrolladores solo tienen que indicar qué grupos de métricas quieren que se devuelvan para una solicitud determinada.
  * Cualquier solicitud de métricas que no sean adecuadas para una entidad determinada se excluirá de la respuesta y se representará como valores `null`. *Estas métricas no se contabilizarán para tu límite de costos de analítica.*
* La respuesta se ha **simplificado significativamente** y ahora se alineará más estrechamente con la forma en que se muestran las métricas en nuestra interfaz de usuario.
  * Anteriormente exponíamos una métrica independiente para cada ubicación (Tuits promocionados en Búsqueda, Tuits promocionados en Líneas de tiempo, Tuits promocionados en Perfiles y detalles del Tuit, X Audience Platform). Ahora devolveremos un conjunto estandarizado de métricas para cada una (en lugar de `promoted_tweet_timeline_impressions`, `promoted_tweet_search_impressions`, `promoted_tweets_profile_impressions`, `promoted_tweets_tpn_impressions`), que se expondrán, cuando se soliciten en una de las siguientes categorías, como una única métrica denominada `impressions` (esto se aplica a todas las métricas):
  * `ALL_ON_TWITTER`
  * `PUBLISHER_NETWORK`
  * Cuando realices una solicitud, obtendrás una única métrica `impressions` para que conciliar los valores con nuestra interfaz de usuario sea más sencillo.
  * Debes hacer dos consultas para obtener tanto los datos de `ALL_ON_TWITTER` como los de `PUBLISHER_NETWORK`, ya que estos no pueden combinarse.
* ¡Los [endpoints de estadísticas asíncronas](/es/x-ads-api/analytics#asynchronous-analytics) ya están disponibles, gracias a los comentarios de nuestros desarrolladores!
  * Un nuevo conjunto de endpoints para solicitar estadísticas *de forma asíncrona*, para datos que no necesitas de inmediato o para extracciones de datos históricos.
  * Pon en cola un job de estadísticas usando un único endpoint nuevo. Obtendremos los datos que has solicitado según lo permitan los recursos.
  * Puedes consultar un endpoint de estado del job para determinar si los datos están disponibles.
  * Una vez que los datos estén disponibles, te proporcionaremos un ID de recuperación para que descargues la respuesta JSON, que reflejará la respuesta del endpoint sincrónico.
  * Consulta hasta **90 días** de datos de hasta **20 entidades** en un único job.
* Consulta nuestra guía de migración de Analytics v1, que incluye la correspondencia de las métricas v0 con las métricas v1
* Mejoras en el entorno Sandbox * Ahora puedes [crear varias cuentas de anuncios de prueba](/es/x-ads-api/campaign-management#post-accounts) en el entorno Sandbox. * Ahora puedes crear múltiples instrumentos de financiación para una cuenta de anuncios de prueba únicamente en el entorno Sandbox. Esto te permite probar todos nuestros tipos de instrumentos de financiación. Antes, solo estaba disponible una fuente de financiación `CREDIT_CARD` para realizar pruebas. * ¿Quieres probar una función beta? Ahora puedes activar o desactivar funciones para una cuenta en el entorno Sandbox y así ajustarlas a tus necesidades de prueba.
