<div id="overview">
  ## Overview
</div>

Los elementos creativos son cualquier entidad que se pueda promocionar en una campaña. Las publicaciones pueden incluir texto, imágenes, GIFs, videos o tarjetas. Las tarjetas pueden incluir imágenes o videos.

Los elementos creativos de imagen, GIF o video se suben mediante [POST media/upload](/es/x-api/media/upload-media#post-media-upload), un endpoint de carga sencillo que solo admite imágenes, o los endpoints POST media/upload (chunked). Estos se pueden agregar a

Tarjetas:

* POST accounts/:account&#95;id/cards
  Tuits:
* POST accounts/:account&#95;id/tweets - Para agregar tarjetas a los tuits, utiliza el parámetro card&#95;uri.
  Tuits programados:
* POST accounts/:account&#95;id/scheduled&#95;tweets

Para obtener más detalles sobre las tarjetas, consulta la página Cards. La página Promoted Video ofrece detalles sobre cómo asociar videos con tarjetas o tuits.

<div id="cards">
  ### Tarjetas
</div>

La Ads API admite varios tipos de tarjetas que se pueden usar en Tuits y luego promocionar en campañas. **Nota**: una vez publicado el Tuit, los detalles de la tarjeta serán visibles públicamente. Esto puede incluir información sobre el usuario titular de la tarjeta.

<div id="image">
  #### Imagen
</div>

Las siguientes especificaciones de imagen se aplican a los recursos utilizados en [Cards](/es/x-ads-api/creatives#cards-2). Las imágenes deben tener un tamaño máximo de 3 MB y un ancho mínimo de 800 px. Además, admitimos las siguientes relaciones de aspecto ancho:alto.

* Website: 1:1 y 1.91:1
* Image App Download: 1:1 y 1.91:1
* Poll: 1.91:1
* Image Conversation: 1.91:1
* Image Direct Message: 1.91:1

Admitimos los siguientes formatos de imagen: .bmp, .jpeg y .png.

<div id="video">
  #### Video
</div>

Las siguientes especificaciones de video se aplican a los recursos utilizados en [Cards](/es/x-ads-api/creatives#cards-2). Se admiten las siguientes relaciones de aspecto (ancho:alto).

* Video Website: 16:9 y 1:1
* Video App Download: 16:9 y 1:1
* Poll: 16:9
* Video Conversation: 16:9
* Video Direct Message: 16:9

<div id="promoted-video">
  ### Video promocionado
</div>

Este documento ofrece una breve descripción general del proceso para subir y promocionar video a través de la Ads API.

La Ads API admite video promocionado en [Tuits](/es/x-ads-api/creatives#tweets-2) y en las siguientes tarjetas:

* [Video de sitio web](https://devcommunity.x.com/t/ads-api-version-11/168814)
* [Descarga de app en video](https://devcommunity.x.com/t/ads-api-version-11/168814)
* [Conversación en video](/es/x-ads-api/creatives#video-conversation-cards)

Primero, sube el video usando el endpoint [POST media/upload (chunked)](https://developer.x.com/en/docs/media/upload-media/api-reference/post-media-upload-init.html). Utilizando el `media_id`, asocia el video a una cuenta publicitaria usando el endpoint POST accounts/:account&#95;id/videos. El `id` del video, a veces denominado `media_key`, se utilizará en solicitudes posteriores. Es una cadena de texto que comienza con un entero (int), va seguida de un guion bajo y termina con un valor long. Por ejemplo: `13_875943225764098048`.

<div id="promoted-video-in-tweets">
  #### Video promocionado en Tuits
</div>

Para crear un Tuit, usa el endpoint [POST accounts/:account&#95;id/tweet](/es/x-ads-api/creatives#get-accounts-account-id-tweets) junto con el `id` del video. En este paso, también puedes proporcionar un título del video, una descripción y una llamada a la acción (CTA). Estos valores son visibles para los usuarios.

<div id="promoted-video-in-cards">
  #### Video promocionado en Cards
</div>

Las Video App Download y Video Conversation Cards permiten agregar imágenes de portada. Sube una imagen para usarla en estas Cards mediante el endpoint [POST media/upload](https://developer.x.com/en/docs/media/upload-media/api-reference/post-media-upload.html).

Crea la Card utilizando uno de los siguientes endpoints:

* [POST accounts/:account&#95;id/cards/video&#95;website](https://devcommunity.x.com/t/ads-api-version-11/168814)
* [POST accounts/:account&#95;id/cards/video&#95;app&#95;download](https://devcommunity.x.com/t/ads-api-version-11/168814)
* [POST accounts/:account&#95;id/cards/video&#95;conversation](https://devcommunity.x.com/t/ads-api-version-11/168814)

usando el `id` del video y, opcionalmente, el `media_id` de la imagen (para la imagen de portada).

Finalmente, crea el Tuit utilizando el endpoint POST accounts/:account&#95;id/tweet. Las Cards se adjuntan a los tuits mediante el parámetro `card_uri`.

<div id="general-information">
  #### Información general
</div>

Para obtener instrucciones detalladas sobre la carga de video a través de la API, consulta la [Guía de carga de video](https://developer.x.com/en/docs/media/upload-media/uploading-media.html).

Los videos también se pueden promocionar como recursos de pre-roll. Consulta la [Guía del objetivo de reproducciones de video pre-roll](/es/x-ads-api/campaign-management#video-views-preroll-objective) para una explicación detallada.

* (A partir de 2015-10-22) Al cargar videos que se usarán en contenido promocionado, el parámetro `media_category` debe configurarse con el valor `amplify_video` para todas las solicitudes con el comando `INIT` al endpoint [POST media/upload (chunked)](https://developer.x.com/en/docs/media/upload-media/api-reference/post-media-upload-init.html). El uso de este nuevo parámetro garantiza que el video se procese de forma asíncrona y se prepare para su uso en contenido promocionado. El comando `STATUS` se puede usar para comprobar la finalización del procesamiento asíncrono después de cargar el video.
* La duración máxima permitida actualmente para videos promocionados es de 10 minutos con un tamaño de archivo de 500 MB o menos.
* El video cargado debe ser mp4 o mov.
* El video cargado generalmente se procesa rápidamente, pero los tiempos de procesamiento pueden variar según la duración del video y el tamaño del archivo.
* Las imágenes de portada cargadas deben estar en formato png o jpg. No hay requisitos de relación de aspecto o tamaño, pero la imagen de portada se ajustará para adaptarse al reproductor de video.

<div id="scheduled-tweets">
  ### Tuits programados
</div>

<div id="introduction">
  #### Introducción
</div>

Los tuits programados permiten a un anunciante o usuario crear un Tuit que se pueda programar para publicarse en una fecha posterior. Además de poder crear y administrar estos tuits, la API permite asociar estos tuits con una línea de pedido, para que se promocionen una vez que el Tuit se publique. Esto permite a los anunciantes preparar tuits nativos y planificar sus creatividades de campaña con antelación a cualquier iniciativa clave. Por ejemplo, preparar una creatividad de Tuit para que se publique inmediatamente tras el anuncio de un nuevo producto.

El conjunto completo de funcionalidades que proporcionan los endpoints de la API de tuits programados se enumera a continuación:

* Crear, modificar y ver nuevos tuits programados
* Asociar un tuit programado con una línea de pedido
* Consultar y administrar tuits programados existentes
* Una vez que un tuit programado se publique, recuperar el `id` del Tuit publicado

<div id="api-endpoints">
  #### Extremos de la API
</div>

A continuación se enumeran todos los extremos relacionados con la funcionalidad anterior:

<div id="scheduled-tweet-management">
  #### Gestión de Tuits programados
</div>

* [GET accounts/:account&#95;id/scheduled&#95;tweets](/es/x-ads-api/creatives#get-accounts-account-id-scheduled-tweets) (obtener una lista de todos los Tuits programados)
* [GET accounts/:account&#95;id/scheduled&#95;tweets/:scheduled&#95;tweet&#95;id](/es/x-ads-api/creatives#get-accounts-account-id-scheduled-tweets) (buscar un Tuit programado específico usando su `id`)
* [POST accounts/:account&#95;id/scheduled&#95;tweets](/es/x-ads-api/creatives#post-accounts-account-id-scheduled-tweets) (crear un nuevo Tuit programado)
* [PUT accounts/:account&#95;id/scheduled&#95;tweets/:scheduled&#95;tweet&#95;id](/es/x-ads-api/creatives#example-request-39) (modificar un Tuit programado existente)
* [DELETE accounts/:account&#95;id/scheduled&#95;tweets/:scheduled&#95;tweet&#95;id](/es/x-ads-api/creatives#example-request-40) (eliminar un Tuit programado usando su `id`)
* [GET accounts/:account&#95;id/scheduled&#95;tweets/preview/:scheduled&#95;tweet&#95;id](/es/x-ads-api/creatives#scheduled-tweets-2) (obtener una vista previa de un Tuit programado existente)

<div id="scheduled-promoted-tweets">
  #### Tuits promocionados programados
</div>

* [GET accounts/:account&#95;id/scheduled&#95;promoted&#95;tweets](/es/x-ads-api/campaign-management#get-accounts-account-id-scheduled-promoted-tweets) (obtener una lista de todos los tuits promocionados programados)
* [GET accounts/:account&#95;id/scheduled&#95;promoted&#95;tweets/:scheduled&#95;promoted&#95;tweet&#95;id](/es/x-ads-api/campaign-management#get-accounts-account-id-scheduled-promoted-tweets-scheduled-promoted-tweet-id) (buscar un tuit promocionado programado usando su `id`)
* [POST accounts/:account&#95;id/scheduled&#95;promoted&#95;tweets](/es/x-ads-api/campaign-management#post-accounts-account-id-scheduled-promoted-tweets) (crear un nuevo tuit promocionado programado)
* [DELETE accounts/:account&#95;id/scheduled&#95;promoted&#95;tweets/:scheduled&#95;promoted&#95;tweet&#95;id](/es/x-ads-api/campaign-management#delete-accounts-account-id-scheduled-promoted-tweets-scheduled-promoted-tweet-id) (eliminar un tuit promocionado programado existente usando su `id`)

<div id="scheduled-tweet-view">
  #### Vista de Tuit programado
</div>

* [GET accounts/:account&#95;id/scheduled&#95;tweets/preview/:scheduled&#95;tweet&#95;id](/es/x-ads-api/creatives#scheduled-tweets-2) (ver un Tuit programado existente)

Debido a que los Tuits programados son entidades separadas de los Tuits publicados, se ejecutan dos conjuntos diferentes de validaciones al crear o editar estos Tuits. El primer conjunto de reglas de validación se ejecuta durante el paso de creación del Tuit programado, específicamente:

<div id="scheduled-tweet-create">
  #### Creación de Tuit programado:
</div>

* Verifica que el usuario autenticado tenga acceso para crear Tuits orgánicos para un @handle dado. Los privilegios para crear Tuits solo promocionados requieren que el usuario autenticado sea un usuario de la cuenta con [permisos de Tweet composer](https://developer.x.com/content/developer-twitter/en/docs/ads/campaign-management/api-reference/authenticated-user-access#get-accounts-account-id-authenticated-user-access)
* Verifica que no haya más de 30 Tuits que estén programados para crearse dentro de una ventana de 15 minutos en torno a la hora `scheduled_at`. Un mensaje de error SCHEDULED&#95;TWEET&#95;LIMIT&#95;EXCEEDED indica que se han programado demasiados Tuits dentro del mismo intervalo futuro de 15 minutos. Los anunciantes deberán eliminar un Tuit programado existente o mover la hora de `scheduled_at` hacia antes o después.

<div id="scheduled-tweet-goes-live">
  #### El Tuit programado se &quot;publica&quot;:
</div>

* Estas reglas de validación se ejecutan en el momento indicado por scheduled&#95;at y son idénticas a las que se aplican al crear un Tuit normal en la API. Por ejemplo, un Tuit programado no se publicará y el scheduled&#95;status se establecerá en FAILED si el Tuit programado contiene tanto una imagen como un GIF.

<div id="workflow">
  #### Flujo de trabajo
</div>

**Crear un nuevo tuit programado**

Se puede crear un nuevo tuit programado utilizando el endpoint [POST accounts/:account&#95;id/scheduled&#95;tweets](https://developer.x.com/content/developer-twitter/en/docs/ads/creatives/api-reference/scheduled-tweets#post-accounts-account-id-scheduled-tweets). Este endpoint tiene los siguientes parámetros obligatorios: la hora `scheduled_at`, junto con el `text` del tuit si no se incluyen entidades de medios en el tuit. Además, este endpoint ofrece algunas opciones adicionales que te permiten crear un tuit programado en nombre de otro @handle mediante el parámetro `as_user_id`, junto con la posibilidad de añadir una tarjeta (`card_uri`) y cualquier medio (`media_ids`). Ten en cuenta que un tuit solo puede contener entidades del mismo tipo, es decir, vídeo, GIF o imagen. El parámetro `nullcast` controla si el tuit es un tuit “solo promocionado” o no. Todos los nuevos tuits programados se crean como &quot;solo promocionados&quot; (`nullcast=true`) de forma predeterminada. Si `nullcast=false`, entonces se crea un tuit programado orgánico.

Una vez que un tuit programado se crea correctamente, la respuesta contendrá un campo `id`, que se refiere al identificador único del propio tuit programado. Además de este campo, también se devuelve otro campo llamado `tweet_id`. Este campo es `null` inicialmente; sin embargo, una vez que el tuit se publique, este campo se rellenará con el ID del tuit “en vivo”.

```
twurl -H 'ads-api.x.com' -X POST "/6/accounts/:account_id/scheduled_tweets" -d 'scheduled_at=2017-12-24T23:59:00Z&text=Happy Holidays!'
```

Esto creará el siguiente Tuit programado:

```json
{
  "request": {
    "params": {
      "text": "Happy Holidays!",
      "scheduled_at": "2017-12-24T23:59:00Z"
    }
  },
  "data": {
    "completed_at": null,
    "id_str": "917507899668099072",
    "text": "Happy Holidays!",
    "user_id": "3271358660",
    "scheduled_status": "SCHEDULED",
    "id": 917507899668099100,
    "nullcast": true,
    "created_at": "2017-10-09T21:51:44Z",
    "scheduled_at": "2017-12-24T23:59:00Z",
    "card_uri": null,
    "updated_at": "2017-10-09T21:51:44Z",
    "tweet_id": null,
    "media_keys": []
  }
}
```

Una vez que este Tuit programado se publique, el campo `tweet_id` se completará con el ID del Tuit &quot;en vivo&quot;.

**Asociar un Tuit programado con un elemento de línea**

Si bien los Tuits programados se pueden usar para crear Tuits orgánicos, también permitimos que los socios creen un Tuit &quot;solo promocionado&quot; (`nullcast=true`), cualquiera de los cuales se puede asociar con un elemento de línea. Para facilitar esto, también proporcionamos un endpoint [POST accounts/:account&#95;id/scheduled&#95;promoted&#95;tweets](https://developer.x.com/content/developer-twitter/en/docs/ads/campaign-management/api-reference/scheduled-promoted-tweets#post-accounts-account-id-scheduled-promoted-tweets). Este endpoint solo permite que se asocie un solo Tuit programado promocionado con un elemento de línea en una única llamada a la API. Para asociar varios Tuits programados con el mismo elemento de línea, es necesario realizar varias llamadas a la API.

Ten en cuenta que no es posible modificar un Tuit programado promocionado existente.

```
twurl -H 'ads-api.x.com' -X POST "/6/accounts/:account_id/scheduled_promoted_tweets" -d 'line_item_id=a44qc&scheduled_tweet_id=917507899668099072'
```

```json
{
  "data": {
    "line_item_id": "a44qc",
    "id": "26576",
    "created_at": "2017-10-09T22:24:16Z",
    "updated_at": "2017-10-09T22:24:16Z",
    "scheduled_tweet_id": "917507899668099072",
    "tweet_id": null,
    "deleted": false
  },
  "request": {
    "params": {
      "line_item_id": "a44qc",
      "scheduled_tweet_id": 917507899668099100,
      "account_id": "aaaaa"
    }
  }
}
```

Este endpoint solo crea una asociación entre un Tuit programado dado y un elemento de línea. Una vez que las fechas de vuelo de la campaña/elemento de línea estén vigentes, el elemento de línea comenzará automáticamente a publicar el Tuit “en vivo” correspondiente. Aunque sí validamos en este paso que el Tuit programado esté en el estado `SCHEDULED`, y que el Tuit programado dado sea válido para el objetivo indicado, no se ejecutan otras validaciones. Cualquier regla de validación restante que aplique al elemento de línea y al Tuit programado se ejecuta cuando el Tuit pasa a estar “en vivo”.

Para garantizar que no haya problemas con la entrega de la campaña, se recomienda que el Tuit programado tenga el campo `scheduled_at` establecido en una hora anterior a las fechas de vuelo de la campaña/elemento de línea.

Por ejemplo, supongamos que el Tuit programado está configurado para activarse después de la fecha de inicio de la campaña (y que solo haya un único Tuit asociado con un único elemento de línea), entonces la campaña estará `ACTIVE`; sin embargo, dado que el Tuit programado aún no está en vivo, no habrá creatividades disponibles para su publicación.

**Administración de Tuits programados**

El conjunto restante de endpoints permite a los consumidores de la API administrar todos sus Tuits programados y Tuits promocionados programados. Estas API se pueden usar para devolver una lista de todos los Tuits programados, opcionalmente filtrados por un estado determinado, así como para buscar un Tuit programado específico por su `id`.

<div id="what-happens-when-a-scheduled-tweet-goes-live">
  #### ¿Qué sucede cuando un Tuit programado se publica?
</div>

Una vez que un Tuit programado está a punto de publicarse, o en otras palabras en el momento `scheduled_at`, se realizan las siguientes actualizaciones:

* Se crea el Tuit publicado, aunque esto puede tener una latencia de hasta 1 segundo
* Se agrega el `tweet_id` a las siguientes entidades:
* Tuit programado
* Tuit programado promocionado
* Se crea una nueva entidad de Tuit promocionado

<div id="best-practices">
  #### Mejores prácticas
</div>

Se recomiendan las siguientes mejores prácticas al crear o promocionar Tuits programados:

* Asegúrate de que el Tuit sea válido al crear el Tuit programado (por ejemplo, un Tuit solo puede tener una imagen, un video o un GIF, y no cualquier combinación de los tres)
* Asegúrate de que las fechas de la campaña (es decir, `start_time` y `end_time`) se alineen con la hora `scheduled_at` del Tuit programado
* Los Tuits programados no deben programarse con más de un año de antelación (365 días)
* Actualmente no se admite la vista previa de Tuits programados (es la posibilidad de previsualizar Tuits programados antes de crearlos)

### Biblioteca de medios

<div id="introduction">
  #### Introducción
</div>

Los endpoints de Media Library permiten gestionar imágenes, GIFs y vídeos para cuentas de X Ads. Los recursos multimedia de la biblioteca se pueden usar en Tuits y para crear tarjetas. También se pueden reutilizar en múltiples [creativos](https://developer.x.com/content/developer-twitter/en/docs/ads/creatives/overview), lo que elimina la necesidad de subir el mismo recurso varias veces.

<div id="api-endpoints">
  #### Extremos de la API

* [POST media/upload](https://developer.x.com/content/developer-twitter/en/docs/media/upload-media/api-reference/post-media-upload#post-media-upload) o [POST media/upload (chunked)](https://developer.x.com/content/developer-twitter/en/docs/media/upload-media/api-reference/post-media-upload-init#post-media-upload-init) (subir contenido multimedia)

<div id="request-parameters">
  #### Parámetros de la solicitud
</div>

Todas las solicitudes POST de Media Library requieren un identificador de contenido multimedia. Este valor se devuelve durante el paso de carga. Al usar el `media_id`, como en el ejemplo anterior, también se debe especificar una `media_category`. Hay cuatro posibles valores de categoría: `AMPLIFY_VIDEO`, `TWEET_GIF`, `TWEET_IMAGE` y `TWEET_VIDEO`.

Opcionalmente, se pueden establecer los valores `name` y `file_name` para los objetos de la Media Library. Estos atributos ayudan a los usuarios a distinguir entre variantes de contenido multimedia en la Media Library.

En el caso de los videos, también es posible establecer un título y una descripción. Estos valores están pensados para pasarse como los parámetros de solicitud `video_title` y `video_description` con el endpoint [POST accounts/:account&#95;id/tweet](https://developer.x.com/content/developer-twitter/en/docs/ads/creatives/api-reference/tweets#post-accounts-account-id-tweet). En el Tuit, este texto aparece debajo del video.

<div id="attributes">
  #### Atributos
</div>

Media Library presenta formalmente el concepto de media&#95;key. Este es el identificador único de los objetos en la biblioteca. Las media keys son valores de cadena de texto con el siguiente formato: 13&#95;875943225764098048. Son totalmente compatibles con todos nuestros endpoints de tarjetas.

Además, la respuesta de Media Library incluye el media&#95;id, representado como una cadena de texto. Esto se incluye para los recursos que actualmente no aceptan una media key: [Tuits](https://developer.x.com/content/developer-twitter/en/docs/ads/creatives/api-reference/tweets#post-accounts-account-id-tweet)*, [Vista previa de tuit](https://developer.x.com/content/developer-twitter/en/docs/ads/creatives/api-reference/tweets#get-accounts-account-id-tweet-preview)* y [Tuits programados](https://developer.x.com/content/developer-twitter/en/docs/ads/creatives/api-reference/scheduled-tweets#post-accounts-account-id-scheduled-tweets). Estamos trabajando para admitir media keys en todas partes.

El atributo aspect&#95;ratio se devuelve para GIFs y videos. Puede usarse para filtrar medios que se utilizarán en tarjetas que solo aceptan relaciones de aspecto específicas.

*Estos endpoints admiten el parámetro video&#95;id, que es una media key.

<div id="identifying-cards">

</div>

<div id="introduction">

</div>

Las Cards son formatos de anuncio personalizables que utilizan contenido multimedia y que pueden asociarse con un sitio web, una aplicación o con llamadas a la acción para impulsar determinadas interacciones de los usuarios, como iniciar un Mensaje Directo. Se pueden adjuntar a Tuits, Tuits programados o borradores de Tuit.

A las Cards se puede hacer referencia en objetos Tuit de dos maneras: mediante el card&#95;uri de la Card o mediante su preview&#95;url. A continuación se presentan valores de ejemplo para cada uno.

| card&#95;uri | preview&#95;url |
| :--- | :--- |
| card://1043282691834048513 | https://cards.x.com/cards/18ce54d4x5t/68w3s |

**Nota**: A partir de la versión 3 de Ads API, solo se genera y devuelve el card&#95;uri en la respuesta de cards para las Cards recién creadas.

**Nota**: A partir de la versión 5 de Ads API, el preview&#95;url en la respuesta de cards ya no se devuelve.

En otras palabras, si el Tuit se creó usando el parámetro de solicitud card&#95;uri, el valor de la URI de la Card aparecerá en la respuesta. Por otro lado, si el preview&#95;url se incluyó como parte del texto del Tuit, la URL de vista previa aparecerá en la respuesta.

<div id="identifying-media">
  ### Identificar contenido multimedia
</div>

<div id="introduction">
  #### Introducción
</div>

El contenido multimedia (imágenes, GIF y videos) se puede agregar a Tuits y tarjetas. Además, los videos se pueden usar como recursos de pre-roll y las imágenes se pueden promocionar en la [X Audience Platform](https://developer.x.com/en/docs/ads/measurement/overview/twitter-audience-platform). Esta sección describe cómo encontrar referencias de contenido multimedia en estas entidades.

Hay dos tipos de identificadores de contenido multimedia: ID y claves. A continuación se presentan valores de ejemplo para cada uno.

| **ID de medio** | **Clave de medio** |
| :--- | :--- |
| 1029825579531807971 | 13&#95;1029825579531807971 |

La clave de medio es la ID con un prefijo numérico y un guion bajo.

<div id="images">
  #### Imágenes
</div>

La siguiente tabla muestra los tipos de identificadores disponibles actualmente en la respuesta de cada recurso relacionado con imágenes, así como los nombres de los atributos correspondientes.

| **Recurso** | **Identificador** | **Atributo(s)** |
| :--- | :--- | :--- |
| Tarjetas de imagen | Ninguno |  |
| Tuit | Ambos | `entities["media"]["id_str"]`  `entities["media"]["media_key"]` |
| Tuit programado | Ambos | `media_ids` y `media_keys` |
| Borrador de Tuit | Ambos | `media_ids` y `media_keys` |
| Medios de la cuenta | Ninguno |  |
| Biblioteca de medios | Ambos | `media_id` y `media_key` |

Las tarjetas de imagen y las imágenes de Medios de la cuenta no incluyen una referencia a ningún identificador de medios. Los Tuits solo incluyen ids de medio. Los Tuits programados y los borradores de Tuit incluyen tanto el id de medio como la clave de medio. La Biblioteca de medios también devuelve ambos.

Para los Tuits, los campos id e id&#95;str en el objeto dentro del array entities[&quot;media&quot;] corresponden al id de medio. En los casos en que un Tuit incluya varias imágenes, las referencias a cada entidad de medios solo se pueden encontrar en extended&#95;entities[&quot;media&quot;].

Además de las referencias a identificadores, a menudo es importante tener acceso a la URL de la imagen.

| **Recurso** | **Atributo(s)** | **Formato** |
| :--- | :--- | :--- |
| Tarjetas de imagen | `image` | .jpg |
| Tuit* | `entities["media"][0]["media_url"]` o `extended_entities["media"][i]["media_url"]` | .jpg |
| Tuit programado | Ninguno |  |
| Borrador de Tuit | Ninguno |  |
| Medios de la cuenta | `media_url` | .jpg |
| Biblioteca de medios | `media_url` | .jpg |

* La ubicación de esta URL depende de si el Tuit contiene una sola imagen o varias imágenes.

Todas las tarjetas de imagen incluyen un atributo de la respuesta relativo a la imagen que contiene la URL de la imagen de X. (Para las tarjetas de descarga de aplicaciones con imagen, el nombre es wide&#95;app&#95;image).

Para los Tuits, la ubicación de la URL de medios depende tanto del tipo de medio como del endpoint que se esté utilizando. Para los Tuits con una sola imagen, la URL se puede encontrar en entities[&quot;media&quot;][0][&quot;media&#95;url&quot;]. Esto es cierto tanto para la Ads API como para la API estándar. Cuando los Tuits contienen varias imágenes, sin embargo, las URL solo se pueden encontrar en extended&#95;entities[&quot;media&quot;][i][&quot;media&#95;url&quot;]. Esto solo está disponible en la API estándar.

<div id="media-library">
  #### Biblioteca de medios
</div>

A veces es necesario recuperar información adicional sobre un recurso multimedia. Un caso de uso, para tarjetas de video, es obtener la URL mp4 en lugar de la vmap. Esto está disponible en la Biblioteca de medios. Para obtener detalles sobre la información disponible, consulta nuestra [guía de la Biblioteca de medios](https://developer.x.com/content/developer-twitter/en/docs/ads/creatives/guides/media-library). La mayoría de los recursos que pertenecen al usuario FULL promotable de la cuenta de anuncios se pueden encontrar en la biblioteca. Sin embargo, hay algunas excepciones.

**Obtención de contenido multimedia**

Como se indicó arriba, las tarjetas de imagen no contienen referencias ni a media IDs ni a media keys. Como resultado, no es posible recuperar sus recursos a través de la Biblioteca de medios. Esto también se aplica a las imágenes de [Account Media](https://developer.x.com/content/developer-twitter/en/docs/ads/creatives/api-reference/account-media#account-media).

Las tarjetas de video requieren que el recurso de video forme parte de la Biblioteca de medios (o del recurso Videos anterior) antes de crearlas. Como resultado, estos recursos siempre se podrán recuperar en la Biblioteca de medios. Esto también se aplica a los recursos PREROLL de Account Media.

Por último, siempre se garantiza que los medios en los Tuits estén en la Biblioteca de medios.

La siguiente tabla resume qué recursos se pueden recuperar en la Biblioteca de medios, teniendo en cuenta si la respuesta del recurso incluye un identificador que se pueda usar en la búsqueda.

| **Recurso** | **En la Biblioteca de medios** |
| :--- | :--- |
| Tarjetas de imagen | No |
| Tarjetas de video | Sí* |
| Tuits (cualquier medio)** | Sí |
| Tuits programados | Sí |
| Borradores de Tuits | Sí |
| Imágenes de Account Media | No |
| Videos de Account Media (`PREROLL`) | Sí |

* Para tarjetas donde `video_content_id` es una media key. Cuando el valor es un media ID, el recurso aún existe en la Biblioteca de medios, pero recuperarlo implica anteponerle un prefijo numérico y un guion bajo.
** Los Tuits solo devuelven media IDs. Aunque se garantiza que el recurso existe en la Biblioteca de medios, su obtención implica anteponerle un prefijo numérico y un guion bajo.

**Interacciones con Account Media**

Hay dos casos en los que los recursos multimedia agregados a la biblioteca se agregan automáticamente al recurso Account Media.

* Cuando se agrega un recurso AMPLIFY&#95;VIDEO a la Biblioteca de medios, se agrega automáticamente como un recurso de Account Media con un tipo de creativo PREROLL.
* Cuando se agregan a la Biblioteca de medios imágenes que tienen dimensiones específicas (consulta &quot;Creative Types&quot; en nuestra [página de enumeraciones](https://developer.x.com/content/developer-twitter/en/docs/ads/general/overview/enums)), se agregan automáticamente como recursos de Account Media. El tipo de creativo (por ejemplo, INTERSTITIAL) depende de las dimensiones de la imagen.

<div id="tweets">
  ### Tuits
</div>

<div id="introduction">
  #### Introducción
</div>

La API de anuncios de X admite tres tipos de Tuits: publicados, programados y en borrador.

<div id="nullcasted-tweets">
  #### Tuits de solo promoción (nullcasted)
</div>

Los tuits pueden ser de solo promoción (nullcasted, también conocidos como &quot;Promoted-only&quot;) u orgánicos. Los tuits de solo promoción, una vez publicados, no aparecen en la cronología pública del usuario, aunque son públicos. Los tuits orgánicos, en cambio, se muestran a los seguidores del usuario y sí aparecen en la cronología pública del usuario.

**Creación de Tuits**

Cada uno de los tres endpoints de creación de Tweet admite un parámetro booleano `nullcast` que ofrece al usuario de la API la opción de crear tuits de solo promoción u orgánicos. Los tuits de solo promoción pueden ser creados por el propio usuario o por cualquier persona que tenga permiso para crear Tuits en nombre del usuario. Los tuits orgánicos solo pueden ser creados por el [usuario completamente promocionable](https://developer.x.com/content/developer-twitter/en/docs/tutorials/ads-api-hierarchy-terminology#promotable-users).

**Actualización de Tuits**

Es posible actualizar la propiedad `nullcast` para Tuits programados y borradores. En el caso de los Tuits programados, se pueden hacer ediciones hasta la hora `scheduled_at` del Tuit. Los borradores de Tuits pueden editarse indefinidamente. Una vez publicados, sin embargo, no es posible cambiar un Tuit de solo promoción a orgánico o viceversa.

<div id="promoting-tweets">
  #### Promocionar Tuits
</div>

Solo se pueden promocionar Tuits publicados y programados. Estos pueden ser nullcast u orgánicos; no existe ninguna restricción. Un anunciante puede promocionar sus propios Tuits o los Tuits de otro usuario, siempre que cuente con el permiso correspondiente. (Consulta [Promoting another user&#39;s Tweets](https://developer.x.com/content/developer-twitter/en/docs/tutorials/promoting-another-users-content) para obtener más información).

Se pueden promocionar varios Tuits en una sola campaña. De manera similar, se puede promocionar un único Tuit en una o más campañas.

Para promocionar Tuits publicados, usa el endpoint [POST accounts/:account&#95;id/promoted&#95;tweets](https://developer.x.com/content/developer-twitter/en/docs/ads/campaign-management/api-reference/promoted-tweets#post-accounts-account-id-promoted-tweets). Este asocia los Tuits publicados con un elemento de línea. Para promocionar Tuits programados, usa el endpoint [POST accounts/:account&#95;id/scheduled&#95;promoted&#95;tweets](https://developer.x.com/content/developer-twitter/en/docs/ads/campaign-management/api-reference/scheduled-promoted-tweets#post-accounts-account-id-scheduled-promoted-tweets).

<div id="tweet-ids">
  #### IDs de Tuit
</div>

Los IDs de Tuits publicados, programados y borrador son [numéricos](https://developer.x.com/content/developer-twitter/en/docs/basics/twitter-ids): son números enteros sin signo de 64 bits. Por ejemplo, el ID del siguiente Tuit publicado es 1166476031668015104.

Cuando se promocionan Tuits publicados o programados, se crea una entidad de Tuit promocionado correspondiente. Estas entidades tienen sus propios IDs, que son alfanuméricos y se representan como valores codificados en base 36. Por ejemplo, promocionar el Tuit publicado anterior —es decir, asociarlo a un line item 6c62d— devuelve la siguiente respuesta de la API.

```
$ twurl -X POST -H ads-api.x.com "/9/accounts/18ce54d4x5t/promoted_tweets?line_item_id=6c62d&tweet_ids=1166476031668015104"
{
  "request": {
    "params": {
      "tweet_ids": [
        1166476031668015104
      ],
      "line_item_id": "6c62d",
      "account_id": "18ce54d4x5t"
    }
  },
  "data": [
    {
      "line_item_id": "6c62d",
      "id": "3qwlq6",
      "entity_status": "ACTIVE",
      "created_at": "2019-09-12T21:39:10Z",
      "updated_at": "2019-09-12T21:39:10Z",
      "approval_status": "ACCEPTED",
      "tweet_id": "1166476031668015104",
      "deleted": false
    }
  ],
  "total_count": 1
}
```

Además del ID del Tuit y el ID del elemento de línea, que se pasaron en la solicitud de creación, la respuesta incluye un campo id con el valor 3qw1q6, que corresponde al ID del Tuit promocionado.

<div id="carousels">
  ### Carruseles
</div>

<div id="introduction">
  #### Introducción
</div>

La X Ads API admite la creación y obtención de carruseles de vídeo e imagen. El carrusel es un tipo de tarjeta que puede contener entre 2 y 6 recursos multimedia. La tarjeta de carrusel puede dirigir a un usuario a un sitio web o animarlo a instalar una aplicación móvil. Para obtener más información sobre los carruseles, sus beneficios, buenas prácticas y preguntas frecuentes, consulta nuestra página [Carousel Ads on X](https://business.x.com/en/advertising/carousels.html).

Un carrusel, como cualquier otro tipo de tarjeta, se puede usar en Tuits y esos Tuits luego se pueden promocionar. El flujo de trabajo es el mismo al que ya estás acostumbrado:

1. Cargar contenido multimedia
2. Crear la tarjeta
3. Crear el Tuit
4. Promocionar el Tuit

La única diferencia está en cómo se crea la tarjeta. Mientras que otras solicitudes de creación de tarjetas aceptan parámetros de consulta, las solicitudes de creación de tarjetas de carrusel solo aceptan cuerpos JSON en solicitudes POST.

<div id="endpoints">
  #### Endpoints
</div>

La Ads API permite crear y obtener carruseles.

Para crear cualquier tipo de carrusel, usa el endpoint [POST accounts/:account&#95;id/cards](https://developer.x.com/en/docs/twitter-ads-api/creatives/api-reference/cards#post-accounts-account-id-cards). Para obtener carruseles, usa el endpoint [GET accounts/:account&#95;id/cards](https://developer.x.com/en/docs/twitter-ads-api/creatives/api-reference/cards#get-accounts-account-id-cards).

<div id="json-post-body">
  #### Cuerpo de la solicitud POST en JSON
</div>

Los carruseles se crean utilizando dos componentes. El primero especifica los recursos multimedia que se utilizarán. El segundo especifica información sobre el sitio web o la aplicación.

En concreto, una tarjeta de carrusel se crea utilizando los siguientes componentes, en este orden:

* Un componente `SWIPEABLE_MEDIA`, que acepta un array de claves de medios
* *Uno* de los siguientes:
* Un componente `DETAILS` para especificar información del sitio web
* Un componente `BUTTON` para especificar información de la aplicación

El componente `SWIPEABLE_MEDIA` debe incluir un array `media_keys` en el que puedes especificar entre 2 y 6 imágenes o videos. El orden en el que se pasan las claves de medios determina el orden en el que se mostrarán.

```
{
  "type": "SWIPEABLE_MEDIA",
  "media_keys": [
    "13_1089771253848666112",
    "13_1191948012077092867"
  ]
}
```

Como recordatorio, puedes obtener claves de medios realizando una solicitud al endpoint [GET accounts/:account&#95;id/media&#95;library](https://developer.x.com/en/docs/twitter-ads-api/creatives/api-reference/media-library#get-accounts-account-id-media-library).

La composición del segundo objeto de componente depende de si deseas dirigir a un usuario a un sitio web o invitarlo a instalar una app. La tabla a continuación resume las dos opciones. (**Nota**: todas las claves enumeradas son obligatorias).

|                                   | **Sitio web**                                                      | **Aplicación**                                    |
| :-------------------------------- | :----------------------------------------------------------------- | :------------------------------------------------ |
| Especificar el tipo de componente | `"type": "DETAILS"`                                                | `"type": "BUTTON"`                                |
| Título/Etiqueta                   | `"title": "X"`                                                     | `"label": { "type": "ENUM", "value": "INSTALL" }` |
| Destino                           | `"destination": { "type": "WEBSITE", "url": "https://www.x.com" }` | `"destination": { "type": "APP", ... }`           |

Con todo esto, a continuación se muestra un ejemplo de cuerpo de solicitud POST en JSON para un carrusel de sitio web.

```
{
  "name": "website carousel",
  "components": [
    {
      "type": "SWIPEABLE_MEDIA",
      "media_keys": [
        "13_1089771253848666112",
        "13_1191948012077092867"
      ]
    },
    {
      "type": "DETAILS",
      "title": "X",
      "destination": {
        "type": "WEBSITE",
        "url": "https://www.x.com"
      }
    }
  ]
}
```

Los objetos de destino de la aplicación dentro de los componentes `BUTTON` requieren un código de país y al menos un identificador de aplicación. Opcionalmente aceptan enlaces profundos (deep links). Para obtener una descripción de estos campos, consulta la [documentación de referencia](https://developer.x.com/en/docs/twitter-ads-api/creatives/api-reference/cards#app-destination).

Con todo esto, a continuación se muestra un ejemplo del cuerpo de una solicitud POST en JSON para un carrusel de aplicaciones.

```
{
  "name": "app carousel",
  "components": [
    {
      "type": "SWIPEABLE_MEDIA",
      "media_keys": [
        "13_1089771253848666112",
        "13_1191948012077092867"
      ]
    },
    {
      "type": "BUTTON",
      "label": {
        "type": "ENUM",
        "value": "INSTALL"
      },
      "destination": {
        "type": "APP",
        "country_code": "US",
        "googleplay_app_id": "com.twitter.android",
        "iphone_app_id": "333903271"
      }
    }
  ]
}
```

<div id="creative-metadata-tagging">
  ### etiquetado de metadatos de creatividades
</div>

<div id="introduction">
  #### Introducción
</div>

Esta guía está dirigida a socios creativos, agencias y desarrolladores creativos para que etiqueten los activos utilizados en campañas de X y puedan comprender mejor el valor y el rendimiento de cada activo individual.

**Nota:** Los activos multimedia solo deben ser etiquetados por el socio o desarrollador que los crea. Si el usuario del activo multimedia no creó dicho activo, no implemente el etiquetado de metadatos.

El etiquetado de metadatos creativos proporciona atribución de las imágenes y videos creados por socios creativos, independientemente de dónde se cargue el activo en X o de la entidad que lo cargue. Para establecer la conexión entre el activo creativo y el socio creativo, se utiliza el estándar [XMP](https://exiftool.org/TagNames/XMP.html).

<div id="tagging-creative-assets">
  #### Etiquetado de recursos creativos
</div>

La siguiente tabla muestra los tipos de identificadores disponibles actualmente en la respuesta de cada recurso relacionado con imágenes, así como el nombre o nombres de los atributos correspondientes. Se necesita una herramienta de etiquetado para etiquetar recursos creativos. Se recomienda [ExifTool](https://exiftool.org/), una biblioteca de Perl independiente de la plataforma junto con una [aplicación de línea de comandos](https://exiftool.org/exiftool_pod.html) para leer, escribir y editar metadatos. Consulta todos los [tipos de archivo](https://exiftool.org/#supported) compatibles.

Sigue las [instrucciones para instalar ExifTool](https://exiftool.org/install.html). También hay paquetes de software ofrecidos por [Homebrew](https://formulae.brew.sh/) que simplifican aún más la instalación al proporcionar el [comando de instalación de exiftool](https://formulae.brew.sh/formula/exiftool) para macOS y Linux. Confirma que la herramienta esté instalada correctamente introduciendo exiftool -ver en la línea de comandos para obtener el número de versión de la herramienta. Obtén más información sobre los parámetros de comando de ExifTool en la [documentación de ExifTool](https://exiftool.org/).

Los socios creativos pueden asignar etiquetas de metadatos a recursos creativos nuevos o existentes con su X app&#95;id en la etiqueta contributor XMP y en la etiqueta date. Los recursos creativos seguirán las restricciones de tamaño existentes al [subir contenido multimedia](https://developer.x.com/en/docs/twitter-api/v1/media/upload-media/overview). 

**Nota:** El uso por parte de X de la etiqueta contributor XMP garantiza que los metadatos capturen valores exclusivamente para campañas en X.

`exiftool -contributor="<YOUR APP ID>" -creative_file.jpg`

`exiftool -date="<date>" -creative_file.jpg`

El app&#95;id se puede encontrar en la [Developer Console](https://developer.x.com/en/portal/dashboard) en Projects &amp; Apps. Ejemplo: 16489123

En el siguiente ejemplo se agrega app&#95;id como etiqueta contributor y date como etiqueta date para una imagen:

```
app_id:858382169
```

```
date:2022-03-13
```

```
creative_file: eiffel_tower.jpg
```

```
exiftool -contributor=858382169 eiffel_tower.jpg
```

```
   1 archivo de imagen actualizado
```

```
exiftool -date=2022-03-13 eiffel_tower.jpg
```

```

```

Comprueba que la imagen se haya etiquetado correctamente: 

`exiftool -xmp:all -G1 <filename>`

Ejemplo:

`exiftool -xmp:all -G1 eiffel_tower.jpg`

```

```

<div id="get-accountsaccount_idaccount_media">
  #### GET accounts/:account_id/account_media
</div>

Recupera detalles de parte o de todo el contenido multimedia de la cuenta asociado con la cuenta actual.

<div id="resource-url">
  #### URL del recurso
</div>

`https://ads-api.x.com/12/accounts/:account_id/account_media`

<div id="parameters">
  #### Parámetros
</div>

| Nombre | Descripción |
| :--- | :--- |
| account&#95;id   *obligatorio* | El identificador de la cuenta utilizada. Aparece en la ruta del recurso y, por lo general, es un parámetro obligatorio para todas las solicitudes de la Advertiser API, excluyendo [GET accounts](https://developer.x.com/en/docs/ads/campaign-management/api-reference/accounts#get-accounts). La cuenta especificada debe estar asociada con el usuario autenticado.  Tipo: cadena de texto  Ejemplo: `18ce54d4x5t` |
| account&#95;media&#95;ids   *opcional* | Restringe la respuesta solo a los medios de la cuenta que desees, especificando una lista de identificadores separados por comas. Se pueden proporcionar hasta 200 IDs.  Tipo: cadena de texto  Ejemplo: `3wpx` |
| count   *opcional* | Especifica el número de registros que se intentarán recuperar por cada solicitud individual.  Tipo: int  Predeterminado: `200`   Mín., Máx.: `1`, `1000` |
| creative&#95;types   *opcional* | Restringe la respuesta solo a los medios de la cuenta que coincidan con los tipos creativos especificados. Se puede indicar más de un tipo creativo separando con comas los valores del enum.  Tipo: enum  Posibles valores: `BANNER`, `BANNER_TABLET`, `INTERSTITIAL`, `INTERSTITIAL_LANDSCAPE`, `INTERSTITIAL_LANDSCAPE_TABLET`, `INTERSTITIAL_TABLET`, `MEDIUM_RECTANGLE`, `PREROLL`, `VAST_PREROLL` |
| cursor   *opcional* | Especifica un cursor para obtener la siguiente página de resultados. Consulta [Pagination](https://developer.x.com/x-ads-api/introduction) para más información.  Tipo: cadena de texto  Ejemplo: `8x7v00oow` |

<div id="components">
  #### Componentes
</div>

Cada componente debe incluir un campo `type` que determina el esquema del objeto. La Ads API admite los siguientes tipos de componentes, agrupados en componentes basados en contenido multimedia y en la descripción.

* Medios:
* `MEDIA`: un único video o imagen
* `SWIPEABLE_MEDIA`: entre 2 y 6 videos o imágenes
* Descripción:
* `DETAILS`
* `BUTTON`

Cada componente tiene un conjunto de campos obligatorios (además de la clave `type`). Estos se enumeran en la siguiente tabla.

| `type` del componente | Campo                   | Tipo de valor             |
| :-------------------- | :---------------------- | :------------------------ |
| `MEDIA`               | `media_key`             | cadena de texto           |
| `SWIPEABLE_MEDIA`     | `media_keys`            | array de cadenas de texto |
| `DETAILS`             | `title`   `destination` | cadena de texto   objeto  |
| `BUTTON`              | `label`   `destination` | objeto          objeto    |

A continuación se muestra un ejemplo de un componente `BUTTON` en el contexto del array `components` (omitiendo intencionalmente la clave `name`). (Los puntos suspensivos indican lugares donde sería necesario especificar más información.)

```
{
  "components": [
    {
      "type": "BUTTON",
      "label": {
        ...
      },
      "destination": {
        ...
      }
    }
  ]
}
```

El orden en el que se especifican los objetos de componentes define el orden de arriba hacia abajo en el que se mostrarán. Las Cards deben crearse usando un componente basado en contenido multimedia y un componente `DETAILS` o `BUTTON`. Los componentes basados en descripciones se muestran debajo del contenido multimedia y tienen destinos asociados, ya sean URL o aplicaciones móviles.

**Label**

Las etiquetas definen el texto que se muestra en los botones y, por lo tanto, solo se aplican al componente `BUTTON`. Los objetos de tipo Label tienen dos claves obligatorias: `type` y `value`. El campo `type` debe establecerse en `ENUM` y el `value` puede ser uno de los siguientes valores: `BOOK`, `CONNECT`, `INSTALL`, `OPEN`, `ORDER`, `PLAY` o `SHOP`.

A partir del ejemplo anterior, el siguiente fragmento muestra el objeto `label` dentro del componente `BUTTON`.

```
{
  "components": [
    {
      "type": "BUTTON",
      "label": {
        "type": "ENUM",
        "value": "INSTALL"
      },
      "destination": {
        ...
      }
    }
  ]
}
```

**Destino**

Los destinos son a donde los anunciantes quieren llevar a los usuarios. Siempre son obligatorios dentro de los componentes `DETAILS` o `BUTTON`. Hay dos tipos de destino: `WEBSITE` o `APP`.

**Nota**: Los destinos de sitio web solo se pueden usar con componentes `DETAILS` y los destinos de app solo se pueden usar con componentes `BUTTON`.

El siguiente ejemplo muestra la estructura general de la carga útil (payload) (pero incluye datos no funcionales).

```
{
  "name": "some name",
  "components": [
    {
      "type": "TYPE_ENUM",
      "key": "value"
    }
  ]
}
```

<div id="post-accountsaccount_idtweet">
  #### POST accounts/:account_id/tweet
</div>

Crea un Tuit para el usuario totalmente promocionable (predeterminado) de la cuenta o para el usuario especificado en el parámetro `as_user_id`. Se admite la creación tanto de Tuits nullcasted (predeterminado) como orgánicos. Los Tuits nullcasted no aparecen en la cronología pública y no se muestran a los seguidores. Cualquiera de los dos tipos se puede usar en campañas.

Si el usuario autenticado no es el usuario promocionable `FULL` de esta cuenta, verifica si tiene permiso para tuitear en nombre de este usuario haciendo una solicitud al endpoint [GET accounts/:account&#95;id/authenticated&#95;user&#95;access](https://developer.x.com/en/docs/ads/campaign-management/api-reference/authenticated-user-access#get-accounts-account-id-authenticated-user-access). Un permiso de `TWEET_COMPOSER` indica que el usuario puede usar este endpoint para crear Tuits nullcasted en nombre del [usuario promocionable](https://developer.x.com/en/docs/ads/campaign-management/api-reference/promotable-users#get-accounts-account-id-promotable-users) `FULL`.

Cuando uses el [endpoint upload.x.com](https://developer.x.com/rest/reference/post/media/upload) para contenido multimedia, pasa el mismo valor de `user_id` para el parámetro `additional_owners` que el valor de `as_user_id` que envías a este endpoint.
