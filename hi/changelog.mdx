<Update label="3 अग॰ 2022" description="X API v2">
  ### Filtering Operator Aliases जोड़ा जाना

  Filtering/query operator &quot;aliases&quot; को enterprise, premium और v2 में search और filtered stream endpoints में जोड़ा गया है। कई मामलों में, operator statuses के बजाय posts को संदर्भित करता है, जैसे &quot;in&#95;reply&#95;to&#95;tweet&#95;id&quot;, &quot;in&#95;reply&#95;to&#95;status&#95;id&quot; का एक alias है। अन्य मामलों में, नया operator alias किए जाने वाले matching को अधिक स्पष्ट बनाता है। उदाहरण के लिए, क्योंकि posts में केवल एक video attachment हो सकता है, &quot;has:videos&quot; के लिए नया &quot;has:video&#95;link&quot; alias दिया गया है। अधिक उदाहरण देखने के लिए [v2 filtered stream operator table](https://developer.x.com/en/docs/twitter-api/tweets/filtered-stream/integrate/build-a-rule#list) देखें।
</Update>

<Update label="14 दिस॰ 2021" description="X API v2: प्रमाणीकरण">
  ### OAuth 2.0 प्रमाणीकरण के लिए समर्थन

  आज से सभी डेवलपर, डेवलपर कंसोल में OAuth 2.0 को प्रमाणीकरण विधि के रूप में चुनकर, OAuth 2.0 के जरिए प्रमाणीकरण कर सकते हैं। इस रिलीज़ के तहत हमने गोपनीय और सार्वजनिक क्लाइंट्स के साथ-साथ सभी प्रासंगिक v2 एंडपॉइंट्स के लिए भी इस प्रमाणीकरण विधि का समर्थन जोड़ा है।

  OAuth 2.0 एक उद्योग-मानक प्राधिकरण प्रोटोकॉल है, जो डेवलपर्स को किसी ऐप के स्कोप्स पर अधिक नियंत्रण देता है और कई डिवाइसों में प्राधिकरण फ़्लो को बेहतर बनाता है। दूसरे शब्दों में, X पर लोगों के लिए ऐप्लिकेशन बनाने वाले डेवलपर्स को इस बात पर अधिक नियंत्रण मिलेगा कि उनका ऐप अपने उपयोगकर्ताओं से कौन-सी जानकारी माँगता है, ताकि आपको अपने एंड-यूज़र्स से केवल वही डेटा और जानकारी माँगनी पड़े जिसकी आपको ज़रूरत है।

  यह आधुनिक प्राधिकरण प्रोटोकॉल आपको अपने एंड-यूज़र्स के लिए अपने ऐप को अधिकृत करने हेतु अधिक सुव्यवस्थित सहमति फ़्लो उपलब्ध कराएगा, जिसमें केवल वही विशिष्ट स्कोप्स दिखेंगे जिनका आपने उनसे अनुरोध किया है।

  इस लॉन्च के बारे में अधिक जानने के लिए, कृपया हमारी फ़ोरम घोषणा देखें।

  * हम अपनी Developer Policy से वह भाषा हटा रहे हैं जो इस बात को सीमित करती थी कि आप X की मुख्य सुविधाओं के साथ कैसे निर्माण कर सकते हैं, और अपने ऐप के माध्यम से कितने उपयोगकर्ताओं को समर्थन दे सकते हैं।

    * हम अपने प्लेटफ़ॉर्म को इस उद्देश्य से खोल रहे हैं कि आप ऐसे टूल्स और उत्पाद बनाएँ जो X को बेहतर और अधिक स्वस्थ बनाएँ तथा सार्वजनिक संवाद का विस्तार करें। [उन समाधानों की सूची देखें जिन्हें हम आपको बनाते देखना चाहेंगे](https://developer.x.com/en/docs/twitter-api/what-to-build)।

    * विशेष रूप से, हमने वे शर्तें हटा दी हैं जो X अनुभव की प्रतिकृति बनाने पर प्रतिबंध लगाती थीं, जिनमें X की मुख्य सुविधाओं से जुड़ी शर्तें भी शामिल थीं, साथ ही वे शर्तें भी जो बड़ी संख्या में यूज़र टोकन रखने के लिए अनुमति अनिवार्य करती थीं।

  आज, हम [Academic Research product track](/hi/resources/fundamentals/developer-apps) को [X API v2](/hi/x-api/introduction) में पेश कर रहे हैं। यह अपडेट Academic Researchers के लिए एक नई आवेदन प्रक्रिया प्रस्तुत करता है, जिसके तहत स्वीकृत शोधकर्ताओं को एक Academic Research [Project](/hi/resources/fundamentals/developer-apps) मिलेगा, जो उन्हें अधिक एक्सेस और उन्नत कार्यक्षमता प्रदान करेगा।

  नए Academic Research product track के साथ, आप निम्नलिखित का उपयोग कर सकेंगे:

  * नया X API v2 [full-archive search endpoint](/hi/x-api/posts/full-archive-search), जो फिलहाल केवल Academic Research product track के लिए उपलब्ध है।

  * [post cap](/hi/x-api/fundamentals/post-cap) बढ़ाकर 10 मिलियन, जो Basic [access level](https://developer.x.com/en/products/x-api/early-access/guide#na_2) पर [Standard product track](/hi/resources/fundamentals/developer-apps) के लिए उपलब्ध 500,000 से अधिक है।

  * [recent search](/hi/x-api/posts/recent-search), [full-archive search](/hi/x-api/posts/full-archive-search), और [filtered stream](/hi/x-api/posts/filtered-stream) के लिए उपलब्ध नए फ़िल्टर ऑपरेटर, जिनमें `$` (यानी cashtag), `bio` (केवल filtered stream के माध्यम से उपलब्ध), `bio_name` (केवल filtered stream के माध्यम से उपलब्ध), `bio_location` (केवल filtered stream के माध्यम से उपलब्ध), `place`, `place_country`, `point_radius`, `bounding_box`, `-is:nullcast`, `has:cashtags` और `has:geo` शामिल हैं।

  * filtered stream के लिए नियमों की सीमा बढ़ाकर 1,000 समवर्ती नियम, जो Basic access level पर Standard product track के लिए उपलब्ध 25 से अधिक है।

  * क्वेरी और नियमों की वर्ण-सीमा बढ़ाकर 1,024 वर्ण, जो Basic access level पर Standard product tack के लिए उपलब्ध 512 वर्ण-सीमा से अधिक है

  इस लॉन्च के बारे में अधिक जानने के लिए, कृपया हमारी [forum announcement](https://devcommunity.x.com/t/introducing-the-new-academic-research-product-track/148632) देखें।
</Update>

<Update label="18 दिस॰, 2020" description="v2 X API के लिए conversation reply settings पोस्ट फ़ील्ड">
  ### Reply Settings फ़ील्ड जोड़ा गया

  आज हम post object में `reply_settings` नाम का एक नया फ़ील्ड लॉन्च कर रहे हैं। यह फ़ील्ड उन सभी X API v2 endpoints पर उपलब्ध है जो पोस्ट्स लौटाते हैं, जिनमें post lookup, hide replies, recent search, sampled stream, filtered stream, follows lookup, user post timeline, और user mention timeline endpoints शामिल हैं, या किसी भी endpoint में post object को [expanding](/hi/x-api/fundamentals/expansions) करके उपलब्ध है।

  यह फ़ील्ड बताता है कि post author ने दूसरों को अपनी पोस्ट्स का जवाब देने की अनुमति किस तरह दी है—चाहे वह सभी के लिए हो, केवल उन लोगों के लिए जिनका वे पोस्ट में उल्लेख करते हैं, या उन लोगों के लिए जिन्हें वे फ़ॉलो करते हैं। `reply_settings` फ़ील्ड द्वारा लौटाए गए मानों में `everyone`, `mentionedUsers`, और `following` शामिल हैं। अगर पोस्ट के लिए कोई conversation controls सेट नहीं हैं, तब भी यह post object में इस फ़ील्ड के लिए `everyone` मान के साथ दिखाई देगा।
</Update>

  हमने [GET /tweets]https://developer.x.com/en/docs/labs/tweets-and-users/api-reference/get-tweets.html) endpoint में दो नए expansions जोड़े हैं:

  entities.mentions.username किसी पोस्ट में पहचाने गए किसी भी user mention के username को एक पूर्ण user object में expand करेगा।

  `referenced_tweets.id.author_id` किसी भी referenced पोस्ट के author की ID को expand करता है, जब अनुरोधित पोस्ट्स में से कोई एक repost, Quoted पोस्ट या Reply हो। यह expansion referenced post ID को भी एक पूर्ण object में expand करेगा।
</Update>

<Update label="11 जून, 2019" description="GET /tweets और GET /users अब Labs में समर्थित हैं">
  ### Labs में Tweets और Users Endpoints के लिए समर्थन

  पहले दो endpoints अब Labs portal के माध्यम से उपलब्ध हैं। शुरुआत करने के लिए सुनिश्चित करें कि आपके पास स्वीकृत डेवलपर खाता है और आपने Labs access के लिए आवेदन किया है।

  समकक्ष v1.1 कार्यक्षमता से [मुख्य अंतर](https://developer.x.com/content/developer-twitter/en/docs/labs/overview/whats-new) में शामिल हैं:

  * single object &quot;show&quot; function और batch &quot;lookups&quot; के लिए एक ही endpoint

  * [Expansion parameters]) एक ही अनुरोध में अतिरिक्त objects शामिल करने का समर्थन करते हैं (उदा. mentioned users, referenced posts)

  * [Format parameters]) कम या अधिक विस्तृत payloads के साथ अलग-अलग data projections का समर्थन करते हैं

  * auth method (user context या bearer token) चाहे जो हो, rate limiting ऐप स्तर पर होती है

  इस लॉन्च के बारे में हमारी [forum announcement](https://devcommunity.x.com/t/twitter-developer-labs-is-open-to-all-developers/126717) में अधिक जानें।
</Update>

<Update label="13 फ़रवरी, 2019" description="X API: Enterprise v1.1">
  ### is:reply Operator जोड़ा गया

  आज, is:reply operator [enterprise search APIs](/hi/x-api/enterprise-gnip-2.0/fundamentals/search-api) और [premium search endpoints](https://developer.x.com/content/developer-twitter/en/docs/tweets/search/api-reference/premium-search) के paid version में उपयोग के लिए उपलब्ध हो गया है।

  is:reply Boolean operator का उपयोग पोस्ट्स के सभी replies को फ़िल्टर करने या किसी rule से मेल खाने वाले explicit replies को हटाने के लिए किया जा सकता है। यह operator ठीक उसी तरह काम करता है जैसे is:quote operator।

  ध्यान रखें कि Search API के साथ, सभी ‘is:’ और ‘has:’ operators का उपयोग किसी standalone operator, जैसे keyword या hashtag, के साथ मिलाकर किया जाना चाहिए।

  आप इस operator के बारे में [documentation](/hi/x-api/enterprise-gnip-2.0/fundamentals/rules-filtering) में अधिक जान सकते हैं।
</Update>

  Usage API में एक उत्पाद का नाम Historical PowerTrack Subscription से बदलकर Historical PowerTrack 2.0 किया जा रहा है, ताकि उत्पाद का नामकरण हमारे अन्य उपयोगकर्ता-सामना वाले शब्दों के अनुरूप हो सके। इस अपडेट के साथ ग्राहकों को बिल्कुल वही डेटा, उसी प्रारूप में मिलेगा। यह बदलाव आपको products.type JSON object में दिखाई देगा।

  यदि आपके कोई प्रश्न हैं, तो कृपया अपने अकाउंट मैनेजर से संपर्क करें।

  ### Quote Payload रेंडरिंग में बदलाव

  आज हम quote payload में URLs रेंडर होने के तरीके में एक बदलाव कर रहे हैं।

  हम &quot;quoted&#95;status&#95;permalink&quot; नाम की एक नई entity जोड़ रहे हैं, ताकि quoted पोस्ट को संदर्भित किया जा सके, और quoted पोस्ट के &quot;text&quot; field से t.co लिंक हटा रहे हैं।

  नए फ़ॉर्मैट में, t.co लिंक अब &quot;quoted&#95;status&quot; object में quoted पोस्ट के &quot;text&quot; field में नहीं जोड़ा जाएगा।

  इसके अलावा, अब हम quoted पोस्ट का t.co url, expanded&#95;url और display&#95;url को ‘urls’ entity में नहीं रखेंगे। इसके बजाय, इन्हें &quot;url&quot;, &quot;expanded&quot; और &quot;display&quot; URL attributes वाले नए &quot;quoted&#95;status&#95;permalink&quot; object में जोड़ा जाएगा। इसका मतलब है कि &quot;quoted&#95;status&#95;permalink&quot; object केवल quoted पोस्ट के t.co लिंक के लिए आरक्षित होगा, जबकि &quot;entities.urls&quot; array का इस्तेमाल original पोस्ट या quote में साझा किए गए किसी भी लिंक की पहचान करने के लिए किया जा सकता है।

  अधिक जानकारी के लिए कृपया हमारी [forum post](https://devcommunity.x.com/t/updating-how-urls-are-rendered-in-the-quote-tweet-payload/105473) और [updated documentation](https://devcommunity.x.com/t/upcoming-changes-to-the-developer-platform/104603) पढ़ें।
