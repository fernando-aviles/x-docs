X API v2 का नवीनतम संस्करण एक बड़ा बदलाव है। इसलिए, हमने इस माइग्रेशन अनुभाग को कुछ भागों में बाँटा है:

| X API v2 में नया क्या है        | X API v2 में जारी किए गए नए endpoints और फ़ंक्शनैलिटी के बारे में जानें।                                                         |
| :------------------------------ | :------------------------------------------------------------------------------------------------------------------------------- |
| माइग्रेट करने के लिए तैयार हैं? | गाइड और निर्देशों के एक सेट के साथ अपना माइग्रेशन शुरू करें।                                                                     |
| डेटा फ़ॉर्मैट माइग्रेशन गाइड    | जानें कि अपने उन डेटा parsers को कैसे फिर से तैयार करें, जो पहले standard v1.1 और enterprise डेटा फ़ॉर्मैट्स के साथ काम करते थे। |

<div id="what-is-the-x-api-v2">
  ## X API v2 क्या है?
</div>

X API v2 अब मुख्य X API है, और अब उत्पाद निवेश और नवाचार का केंद्र यही है। हमने डेवलपर्स के साथ मिलकर X API की अगली पीढ़ी तैयार की है, ताकि हमारे विविध डेवलपर समुदाय की ज़रूरतों को बेहतर ढंग से पूरा किया जा सके। डेवलपर्स से मिले फ़ीडबैक के आधार on, हमने API को फिर से बनाया है, ताकि ज़रूरतों की अधिक व्यापक शृंखला को बेहतर ढंग से पूरा किया जा सके, नई सुविधाएँ और endpoints जोड़े जा सकें, और डेवलपर अनुभव को बेहतर बनाया जा सके।

X API v2 अब मुख्य X API है, और अब उत्पाद निवेश और नवाचार का केंद्र यही है। पिछले कुछ वर्षों में, हमने डेवलपर्स के साथ मिलकर API को फिर से बनाया, ताकि ज़रूरतों की अधिक व्यापक शृंखला को बेहतर ढंग से पूरा किया जा सके, नई सुविधाएँ और endpoints जोड़े जा सकें, और डेवलपर अनुभव को बेहतर बनाया जा सके। हम एक खुला डेवलपर प्लेटफ़ॉर्म बनाते रहने के लिए प्रतिबद्ध हैं, और यह देखने के लिए उत्साहित हैं कि आप X API v2 के साथ क्या बनाते हैं।

<div id="why-migrate">
  ## माइग्रेट क्यों करें?
</div>

X API v2 को एक आधुनिक और अधिक टिकाऊ आधार पर बनाया गया है। इसमें मानक v1.1 और enterprise उत्पादों के लिए बेहतर प्रतिस्थापन एंडपॉइंट्स के साथ-साथ बिल्कुल नई कार्यक्षमताएँ भी शामिल हैं। हम legacy APIs (v1.1 और enterprise) के ग्राहकों को दृढ़ता से प्रोत्साहित करते हैं कि वे v2 पर माइग्रेट करना शुरू करें, क्योंकि अंततः हमारा इन्हें अप्रचलित करने का इरादा है। सार्वजनिक बातचीत को सुनने और उसका विश्लेषण करने, X पर लोगों से जुड़ने, और नवाचार करने के लिए X API का उपयोग करें।

इस अनुभाग में, हम एंडपॉइंट्स और कार्यक्षमता पर चर्चा करेंगे।

<div id="v2-endpoints">
  ## V2 एंडपॉइंट्स
</div>

आप नीचे दी गई गाइड के माध्यम से v2 एंडपॉइंट्स की पूरी सूची और उनके pre-v2 समकक्ष देख सकते हैं:

<Button href="/hi/x-api/migrate/x-api-endpoint-map">
  X API एंडपॉइंट मैप
</Button>

हालाँकि X API v2 में अधिकांश एंडपॉइंट्स पुराने एंडपॉइंट्स के विकल्प हैं, हमने कई नए एंडपॉइंट्स भी पेश किए हैं। यहाँ कुछ नए एंडपॉइंट्स के उदाहरण दिए गए हैं, जिन्हें हमने v2 में जारी किया है:

* [Spaces endpoints](/hi/x-api/spaces/introduction), ताकि लोग X Spaces का बेहतर उपयोग कर सकें और डेवलपर्स ऑडियो बातचीत के भविष्य को आकार देने में मदद कर सकें।
* [Hide replies](/hi/x-api/posts/hide-replies/introduction), जो आपको ऐसे टूल बनाने की सुविधा देता है, जो अपमानजनक, ध्यान भटकाने वाले या भ्रामक जवाबों के प्रभाव को बड़े पैमाने पर सीमित करने में मदद करते हैं।
* नए सूचियों के एंडपॉइंट्स, जो आपको [सूचियों को pin और unpin करने](/hi/x-api/lists/pinned-lists/introduction) या किसी व्यक्ति की pin की गई सूचियों को देखने की सुविधा देते हैं।
* नए [batch compliance endpoints](/hi/x-api/compliance/batch-compliance/introduction), जो आपको यह सुनिश्चित करने की सुविधा देते हैं कि आपका संग्रहीत उपयोगकर्ता और Tweet डेटा अनुपालन में है।

<div id="discover-new-and-updated-response-objects">
  ### नए और अपडेट किए गए रिस्पॉन्स ऑब्जेक्ट्स के बारे में जानें

निम्नलिखित छह डेटा ऑब्जेक्ट v2 endpoints के साथ उपलब्ध हैं:

| Object                                                 | Description                                                                                                                                                                                                                   |
| :----------------------------------------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [Tweet](/hi/x-api/fundamentals/data-dictionary#tweet)     | Tweet ऑब्जेक्ट में `id`, `text`, और `created_at` जैसे रूट-लेवल फ़ील्ड्स की लंबी सूची होती है। Tweet ऑब्जेक्ट कई child objects का parent object भी है, जिनमें `user`, `media`, `poll`, और `place` शामिल हैं।                   |
| [उपयोगकर्ता](/hi/x-api/fundamentals/data-dictionary#user) | user ऑब्जेक्ट में संदर्भित उपयोगकर्ता का वर्णन करने वाला X user account metadata शामिल होता है।                                                                                                                               |
| [Spaces](/hi/x-api/fundamentals/data-dictionary#space)    | Space ऑब्जेक्ट में `state`, `host_id`, `is_ticketed`, और यहाँ तक कि `lang` जैसे फ़ील्ड्स शामिल होते हैं।                                                                                                                      |
| [सूचियाँ](/hi/x-api/fundamentals/data-dictionary#list)    | List ऑब्जेक्ट में अनुरोधित सूची के बारे में बुनियादी जानकारी होती है, जिसमें `description`, `member_count`, और `owner_id` शामिल हैं।                                                                                          |
| [Media](/hi/x-api/fundamentals/data-dictionary#media)     | अगर किसी Tweet में media (जैसे images) शामिल है, तो `media.fields` parameter का उपयोग करके media ऑब्जेक्ट का अनुरोध किया जा सकता है। इसमें `media_key`, `type`, `url`, `preview_image_url`, आदि जैसे फ़ील्ड्स शामिल होते हैं। |
| [Poll](/hi/x-api/fundamentals/data-dictionary#poll)       | Tweet में शामिल poll किसी भी endpoint पर primary object नहीं होता, लेकिन इसे Tweet ऑब्जेक्ट में पाया जा सकता है और expand किया जा सकता है।                                                                                    |
| [Place](/hi/x-api/fundamentals/data-dictionary#place)     | place ऑब्जेक्ट में `place_id`, `geo` object, `country_code`, आदि जैसे फ़ील्ड्स होते हैं। इस जानकारी का उपयोग Tweets की पहचान करने और स्थान के आधार पर Tweets का अध्ययन करने के लिए किया जा सकता है।                           |

[फ़ील्ड्स और expansions का उपयोग कैसे करें](/hi/x-api/fundamentals/data-dictionary#how-to-use-fields-and-expansions) के बारे में और जानें।

<div id="flexibility-to-choose-which-objects-and-fields-you-receive">
  ### यह चुनने की सुविधा कि आपको कौन-से ऑब्जेक्ट और फ़ील्ड्स मिलें
</div>

किसी GET endpoint पर अनुरोध करने पर, आपको उस endpoint से संबंधित प्राथमिक data object मिलेगा, जिसमें डिफ़ॉल्ट फ़ील्ड्स का एक सेट शामिल होता है। उदाहरण के लिए, Tweet object डिफ़ॉल्ट रूप से `id` और `text` फ़ील्ड्स देता है।

अगर आप अपने अनुरोध के साथ अतिरिक्त फ़ील्ड्स पाना चाहते हैं, तो आपको [फ़ील्ड्स](/hi/x-api/fundamentals/fields) और [expansions](/hi/x-api/fundamentals/expansions) पैरामीटर का उपयोग करना होगा। expansions पैरामीटर आपको संबंधित data object, जैसे किसी user का pinned Tweet या media object, प्राप्त करने देता है, जबकि field operators आपको लौटाए गए objects में डिफ़ॉल्ट से आगे के विशिष्ट फ़ील्ड्स का अनुरोध करने की सुविधा देते हैं।

यहाँ expansions की पूरी सूची दी गई है, जिनका अनुरोध आप अलग-अलग X API v2 endpoints के साथ कर सकते हैं:

| ऑब्जेक्ट / संसाधन | उपलब्ध Expansions                                                                                                                                                                                                      |
| :---------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Tweets            | `author_id`, `edit_history_tweet_ids`, `entities.mentions.username`, `in_reply_to_user_id`, `referenced_tweets.id`, `referenced_tweets.id.author_id`, `attachments.poll_ids`, `attachments.media_keys`, `geo.place_id` |
| Users             | `pinned_tweet_id`                                                                                                                                                                                                      |
| Spaces            | `invited_user_ids`, `speaker_ids`, `creator_id`, `host_ids`, `topic_ids`                                                                                                                                               |

[फ़ील्ड्स और expansions का उपयोग कैसे करें](/hi/x-api/fundamentals/data-dictionary#how-to-use-fields-and-expansions) के बारे में और जानें।

<div id="edit-tweets">
  ## Tweets संपादित करें
</div>

X API v2 endpoints संपादित किए गए Tweet का मेटाडेटा प्रदान करते हैं। *Tweets संपादित करें* सुविधा को पहली बार 1 सितंबर, 2022 को X कर्मचारियों के बीच परीक्षण के लिए पेश किया गया था। उस तारीख से, पात्र Tweets को 30 मिनट तक और अधिकतम 5 बार संपादित किया जा सकता है। [Edit Tweets](/hi/x-api/fundamentals/edit-posts) के बारे में और जानें।
X API v2 का उपयोग करके, डेवलपर यह पता कर सकता है:

* क्या कोई Tweet बनाए जाने के समय संपादन के लिए पात्र था। कुछ Tweets, जैसे polls वाले या scheduled Tweets, संपादित नहीं किए जा सकते।
* Tweets को 30 मिनट तक और अधिकतम 5 बार संपादित किया जा सकता है। संपादन-योग्य Tweets के लिए आप देख सकते हैं कि संपादन के लिए कितना समय बचा है और कितने और संपादन किए जा सकते हैं।
* क्या आप किसी Tweet का संपादित संस्करण देख रहे हैं (ज़्यादातर मामलों में API किसी Tweet का सबसे हाल का संस्करण लौटाता है, जब तक कि Tweet ID के ज़रिए किसी खास पुराने संस्करण का अनुरोध न किया गया हो)।
* Tweet का पूरा संपादन इतिहास।
* Tweet के हर संस्करण से जुड़ा एंगेजमेंट।

<div id="track-threaded-conversations">
  ## थ्रेडेड बातचीत को ट्रैक करें
</div>

एक नया Tweet फ़ील्ड यह पहचानने में मदद करता है कि कोई Tweet किस बातचीत थ्रेड से संबंधित है। conversation ID उस Tweet की Tweet ID होती है जिसने बातचीत शुरू की थी। [बातचीत ट्रैकिंग](/hi/x-api/fundamentals/conversation-id) के बारे में अधिक जानें।

<div id="ready-to-migrate">
  ## माइग्रेट करने के लिए तैयार
</div>

v2 endpoints का उपयोग करने के लिए, आपको निम्नलिखित चीज़ों की आवश्यकता होगी:

* [एक डेवलपर खाता](https://developer.x.com/en/portal/petition/essential/basic-info)
* [एक डेवलपर ऐप](https://developer.x.com/en/apps), जो एक [Project](resources/fundamentals/projects) के भीतर बनाया गया हो
* उस Project के डेवलपर ऐप से [कुंजियाँ और टोकन](resources/fundamentals/authentication)

कृपया इस बात का विशेष ध्यान रखें कि कुंजियाँ और टोकन Project के भीतर मौजूद किसी App से ही उपयोग किए जाएँ। यदि आप किसी ऐसे App की कुंजियाँ और टोकन उपयोग कर रहे हैं जो किसी Project के बाहर है, तो आप v2 endpoints पर अनुरोध नहीं कर पाएँगे।

एक बार आपके पास डेवलपर खाता हो जाने पर, आप ऊपर दी गई सभी चीज़ें [डेवलपर कंसोल](https://developer.x.com/en/portal/petition/essential/basic-info) में सेट अप कर सकते हैं।

<div id="authentication">
  ### प्रमाणीकरण
</div>

नए Twitter API के साथ, अलग-अलग endpoint तक पहुँचने के लिए आप दो अलग-अलग प्रमाणीकरण पैटर्न का उपयोग करेंगे: OAuth 1.0a User Context और OAuth 2.0 बेयरर टोकन। endpoint पर अनुरोध करते समय, दोनों का उद्देश्य अलग-अलग होता है:

किसी Twitter उपयोगकर्ता की ओर से अनुरोध करने पर OAuth 1.0a User Context आवश्यक होता है
आपके developer ऐप की ओर से अनुरोध करने के लिए OAuth 2.0 बेयरर टोकन आवश्यक होता है

<div id="tools-and-code">
  ## टूल और कोड
</div>

शुरुआत करने और नए endpoints तथा क्षमताओं से परिचित होने में आपकी मदद के लिए, आपके काम को तेज़ी से आगे बढ़ाने के कुछ विकल्प हमारे पास हैं:

* हमारे पास एक Twitter [Postman collection](https://app.getpostman.com/run-collection/9956214-784efcda-ed4c-4491-a4c0-a26470a67400) है, जिसकी मदद से आप Postman client का उपयोग करके अलग-अलग endpoints पर अनुरोध भेज सकते हैं और उनसे कनेक्ट कर सकते हैं। authentication का परीक्षण करने और endpoints के साथ प्रयोग करने का यह एक आसान तरीका है।
* हमने Ruby, Python, Node, Java और कई अन्य भाषाओं के लिए Twitter-supported और third-party libraries की एक सूची भी उपलब्ध कराई है। अतिरिक्त संदर्भ के लिए, हमारे [tools and libraries page](/hi/x-api/tools-and-libraries/overview) पर नज़र डालें।

<div id="migrating-to-the-new-data-format">
  ## नए डेटा फ़ॉर्मैट पर माइग्रेट करना
</div>

जब आप v1.1 या enterprise से v2 पर माइग्रेट करते हैं, तो यह समझना महत्वपूर्ण है कि डेटा डिलीवर किए जाने के फ़ॉर्मैट में काफ़ी बड़े बदलाव हुए हैं। हमने नए फ़ील्ड्स जोड़े हैं, फ़ील्ड्स के क्रम में बदलाव किया है, और कुछ मामलों में कुछ एलिमेंट्स को पूरी तरह हटा भी दिया है।

इन बदलावों के बारे में अधिक जानने के लिए, हम गाइड्स की एक श्रृंखला तैयार कर रहे हैं, जो pre-v2 डेटा फ़ॉर्मैट के फ़ील्ड्स को नए फ़ील्ड्स से मैप करने में आपकी मदद करेगी और यह बताएगी कि इन नए फ़ील्ड्स का अनुरोध कैसे करें।

आप इस migration hub के हमारे [डेटा फ़ॉर्मैट माइग्रेशन](/hi/x-api/migrate/data-format-migration) सेक्शन पर जाकर, या हमारे विशिष्ट डेटा फ़ॉर्मैट गाइड्स पर जाकर अधिक जान सकते हैं:

* [Native format से X API v2 तक (standard v1.1)](/hi/x-api/migrate/data-format-migration#migrating-from-standard-v1-1s-data-format-to-v2)
* [Native Enriched से X API v2 तक (enterprise)](/hi/x-api/migrate/data-format-migration#migrating-from-native-enriched-data-format-to-v2)
* [Activity Streams से X API v2 तक (enterprise)](/hi/x-api/migrate/data-format-migration#migrating-from-activity-streams-data-format-to-v2)

<div id="whats-next">
  ## आगे क्या है?
</div>

आपमें से जो कुछ समय से प्लेटफ़ॉर्म का उपयोग कर रहे हैं, वे देखेंगे कि कई नए endpoint मौजूदा [standard v1.1](https://developer.x.com/en/docs/twitter-api/v1) और [enterprise](/hi/x-api/enterprise-gnip-2.0/enterprise-gnip) endpoints के अनुरूप हैं। वास्तव में, हमारा इरादा है कि भविष्य में ये तीनों संस्करणों की जगह ले लें।

हमने एक तालिका तैयार की है, ताकि आप समझ सकें कि [X API endpoints map](/hi/x-api/migrate/x-api-endpoint-map) पिछले संस्करणों से कैसे संबंधित है।

अगर आप देखना चाहते हैं कि आगे क्या आने वाला है, तो कृपया हमारा [product roadmap](https://trello.com/b/myf7rKwV/twitter-developer-platform-roadmap) देखें।

हमारे पास एक [changelog](https://developer.x.com/en/updates/changelog) भी है, जिसे देखकर आप समझ सकते हैं कि हम अब तक क्या जारी कर चुके हैं।
