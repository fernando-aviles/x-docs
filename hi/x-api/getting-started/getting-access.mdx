X API के साथ तीन चरणों में शुरुआत करें: साइन अप करें, एक ऐप बनाएं और अपने क्रेडेंशियल्स सहेज लें।

<Button href="https://console.x.com">अभी साइन अप करें</Button>

***

<div id="step-1-create-a-developer-account">
  ## चरण 1: डेवलपर खाता बनाएँ
</div>

<Steps>
  <Step title="डेवलपर कंसोल पर जाएँ">
    [console.x.com](https://console.x.com) पर जाएँ और अपने X खाते से साइन इन करें।
  </Step>

  <Step title="Developer Agreement स्वीकार करें">
    Developer Agreement और Policy की समीक्षा करके उन्हें स्वीकार करें।
  </Step>

  <Step title="अपनी प्रोफ़ाइल पूरी करें">
    आप API का उपयोग कैसे करेंगे, इसके बारे में बुनियादी जानकारी दें।
  </Step>
</Steps>

***

<div id="step-2-create-an-app">
  ## चरण 2: एक ऐप बनाएँ
</div>

साइन अप करने के बाद, अपने API क्रेडेंशियल पाने के लिए एक ऐप बनाएँ:

<Steps>
  <Step title="'New App' पर क्लिक करें">
    डेवलपर कंसोल डैशबोर्ड से एक नया ऐप बनाएँ।
  </Step>

  <Step title="ऐप का विवरण दर्ज करें">
    अपने ऐप का नाम, विवरण और उपयोग का उद्देश्य दर्ज करें।
  </Step>

  <Step title="क्रेडेंशियल जनरेट करें">
    कंसोल आपकी API कुंजियाँ और टोकन जनरेट करेगा।
  </Step>
</Steps>

***

<div id="step-3-save-your-credentials">
  ## चरण 3: अपने क्रेडेंशियल सहेजें
</div>

आपकी प्रमाणीकरण संबंधी ज़रूरतों के आधार पर आपको कई क्रेडेंशियल मिलेंगे:

| क्रेडेंशियल                   | उद्देश्य                                                                                                   |
| :---------------------------- | :--------------------------------------------------------------------------------------------------------- |
| **API Key &amp; Secret**      | आपके ऐप की पहचान करते हैं। टोकन जनरेट करने और OAuth 1.0a अनुरोधों पर हस्ताक्षर करने के लिए उपयोग होते हैं। |
| **बेयरर टोकन**              | सार्वजनिक डेटा पढ़ने के लिए केवल-ऐप प्रमाणीकरण।                                                            |
| **Access Token &amp; Secret** | अपने खाते की ओर से अनुरोध करने के लिए (OAuth 1.0a)।                                                        |
| **Client ID &amp; Secret**    | उपयोगकर्ता-कॉन्टेक्स्ट अनुरोधों के लिए OAuth 2.0 प्रमाणीकरण।                                               |

<Warning>
  **इन्हें तुरंत सहेज लें।** क्रेडेंशियल केवल एक बार दिखाए जाते हैं। इन्हें किसी पासवर्ड मैनेजर या सुरक्षित वॉल्ट में संग्रहीत करें। यदि ये खो जाते हैं, तो आपको इन्हें फिर से जनरेट करना होगा (जिससे पुराने क्रेडेंशियल अमान्य हो जाएंगे)।
</Warning>

***

<div id="which-credentials-do-you-need">
  ## आपको कौन-से क्रेडेंशियल्स चाहिए?
</div>

<Tabs>
  <Tab title="सार्वजनिक डेटा पढ़ना">
    सार्वजनिक डेटा तक आसान, सिर्फ़-पढ़ने की पहुँच के लिए **बेयरर टोकन** का उपयोग करें।

    ```bash
    curl "https://api.x.com/2/users/by/username/xdevelopers" \
      -H "Authorization: Bearer $BEARER_TOKEN"
    ```

    इनके लिए सबसे उपयुक्त: पोस्ट्स खोजना, उपयोगकर्ताओं की जानकारी देखना, ट्रेंड्स देखना।
  </Tab>

  <Tab title="उपयोगकर्ता के रूप में कार्य करना">
    उपयोगकर्ताओं की ओर से कार्रवाई करने के लिए **OAuth 2.0** (अनुशंसित) या **OAuth 1.0a** का उपयोग करें।

    OAuth 2.0 सूक्ष्म स्तर के स्कोप देता है—सिर्फ़ उन्हीं अनुमतियों का अनुरोध करें जिनकी आपको ज़रूरत है।

    इनके लिए सबसे उपयुक्त: पोस्ट करना, लाइक करना, फ़ॉलो करना, DMs ऐक्सेस करना।

    [OAuth 2.0 गाइड →](/hi/resources/fundamentals/authentication/oauth-2-0/overview)
  </Tab>

  <Tab title="अपने रूप में कार्य करना">
    अपने खाते के रूप में अनुरोध करने के लिए अपने **Access Token &amp; Secret** का उपयोग करें।

    ये टोकन उस खाते का प्रतिनिधित्व करते हैं जो ऐप का स्वामी है।

    इनके लिए सबसे उपयुक्त: टेस्टिंग, व्यक्तिगत bots, आपका अपना automation।
  </Tab>
</Tabs>
