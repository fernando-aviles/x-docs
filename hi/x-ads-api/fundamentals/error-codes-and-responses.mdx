<div id="typical-response-structure">
  ## सामान्य प्रतिक्रिया संरचना
</div>

सफल प्रतिक्रियाओं को 200-श्रेणी के HTTP कोड और JSON-आधारित पेलोड से दर्शाया जाता है, जिसमें अनुरोधित, निर्मित, संशोधित या हटाई गई ऑब्जेक्ट(s) के साथ-साथ आपके अनुरोध के बारे में सर्वर की व्याख्या भी शामिल होती है।

यदि आपने कोई सफल अनुरोध भेजा होता, तो प्रतिक्रिया के हिस्से के रूप में आपको एक `request` नोड मिलता, जो आपके अनुरोध को उसी रूप में लौटाता है।

*उदाहरण:* [GET accounts/abcdefg/campaigns?with&#95;deleted=true](/hi/x-ads-api/campaign-management#campaigns)

```json
{
  /* आपके प्रतिक्रिया का डेटा... */,
  "request": {
    "params": {
      "account_id": "abcdefg",
      "with_deleted": "true"
    }
  }
}
```

JSON प्रतिक्रियाओं में `data` फ़ील्ड में उपयोग किए जा रहे संसाधन से जुड़े विशिष्ट ऑब्जेक्ट शामिल होंगे। जब प्रतिक्रिया में एक या अधिक परिणाम हो सकते हैं, तो `data` नोड का प्रारूप JSON array होगा। जब प्रतिक्रिया में केवल एक परिणाम संभव हो, तो इसे JSON hash के रूप में लौटाया जाएगा। कुछ दुर्लभ मामलों में, आपको ऐसी प्रतिक्रिया दिखाई दे सकती है जिसमें सामान्यतः किसी collection के बजाय hashmap शामिल हो। इस स्थिति में, मान लें कि वह एकल hashmap `type` फ़ील्ड में निर्दिष्ट उसी type का एक ऑब्जेक्ट है।

<div id="error-response-structure">
  ## त्रुटि प्रतिक्रिया संरचना
</div>

त्रुटि प्रतिक्रियाएँ non-200-series HTTP कोड के साथ लौटाई जाती हैं। आमतौर पर इसके साथ एक JSON प्रतिक्रिया जुड़ी होती है, लेकिन कुछ त्रुटियों में अलग प्रकार का body भी मिल सकता है। ऐसी परिस्थितियों में, जहाँ प्रतिक्रिया संरचना को parse नहीं किया जा सकता, HTTP कोड के मूल अर्थ को प्राथमिकता दें। उदाहरण के लिए, कभी-कभी आपको HTML प्रतिक्रिया के साथ HTTP 404 दिखाई दे सकता है। इस स्थिति में, यह मान लेना सुरक्षित है कि सामग्री नहीं मिली (HTTP 404 का अर्थ है “Not Found”).

सामान्य त्रुटि प्रतिक्रियाएँ सफल प्रतिक्रियाओं जैसी ही संरचना का पालन करती हैं। त्रुटि का प्रकार प्रतिक्रिया के `errors` node में बताया जाता है। `errors/code` node एक CAPS&#95;CASE constant error code दर्शाता है, जिसका उपयोग आप समाधान से संबंधित निर्णय प्रोग्राम के माध्यम से लेने के लिए कर सकते हैं। `errors/message` node त्रुटि का (आमतौर पर) अंग्रेज़ी में, मनुष्यों द्वारा पढ़ा जा सकने वाला विवरण दर्शाता है। त्रुटि के बारे में अधिक सूक्ष्म जानकारी देने के लिए अतिरिक्त फ़ील्ड्स भी जोड़े जा सकते हैं।

```json
{
  "errors": [
    {
      "parameter": "start_time",
      "details": "invalid date",
      "code": "INVALID_PARAMETER",
      "value": "",
      "message": "Expected time, got \"\" for start_time"
    }
  ],
  "request": {
    "params": {
      "account_id": "hkk5"
    }
  }
}
```

ऊपर दिए गए उदाहरण में, analytics endpoint के लिए `start_time` पैरामीटर का अमान्य मान देकर एक अनुरोध किया गया था। अमान्य पैरामीटर वाले अनुरोधों के लिए `errors/code` `INVALID_PARAMETER` होता है।
