<div id="general">
  ## सामान्य
</div>

<AccordionGroup>
  <Accordion title="OAuth क्या है?">
    OAuth एक प्रमाणीकरण प्रोटोकॉल है, जो उपयोगकर्ताओं को अपना पासवर्ड साझा किए बिना किसी एप्लिकेशन को उनकी ओर से काम करने की अनुमति देने की स्वीकृति देता है। अधिक जानकारी [oauth.net](http://oauth.net/) पर मिल सकती है।
  </Accordion>

  <Accordion title="मैं access tokens कैसे generate करूँ?">
    access tokens generate करने के लिए, आपके पास एक [X ऐप](/hi/resources/fundamentals/developer-apps) होना चाहिए। access tokens के बारे में अधिक जानें [यहाँ](/hi/resources/fundamentals/authentication#oauth-1-0a-2)। 
  </Accordion>

  <Accordion title="मैं एक X ऐप कैसे बनाऊँ?">
    एक [X ऐप](/hi/resources/fundamentals/developer-apps) बनाने के लिए, आपके पास एक [डेवलपर खाता](/hi/resources/fundamentals/developer-portal) होना चाहिए। आप इसके लिए [यहाँ](https://developer.x.com/en/portal/petition/essential/basic-info) साइन अप कर सकते हैं।
  </Accordion>

  <Accordion title="अगर मेरे पास पहले से एक X ऐप है, तो मैं उसे कैसे देखूँ और संपादित करूँ?">
    अगर आप developer.x.com पर अपने X खाते में लॉग इन हैं, तो आप [X ऐप डैशबोर्ड](https://developer.x.com/content/developer-twitter/en/apps) से अपने ऐप को देख और संपादित कर सकते हैं।
  </Accordion>
</AccordionGroup>

<div id="technical">
  ## तकनीकी
</div>

<AccordionGroup>
  <Accordion title="एक access token कितने समय तक वैध रहता है?">
    Access token की वैधता स्पष्ट रूप से समाप्त नहीं होती। अगर कोई उपयोगकर्ता अपने X खाता सेटिंग्स में किसी एप्लिकेशन की अनुमति स्पष्ट रूप से रद्द कर देता है, या X किसी एप्लिकेशन को निलंबित कर देता है, तो access token अमान्य हो जाएगा। अगर किसी एप्लिकेशन को निलंबित किया जाता है, तो [X ऐप](/hi/resources/fundamentals/developer-apps) डैशबोर्ड में यह बताने वाला एक नोट दिखाई देगा कि उसे निलंबित कर दिया गया है।
  </Accordion>

  <Accordion title="अगर कोई access token अमान्य हो जाए तो क्या होगा?">
    मानकर चलें कि किसी उपयोगकर्ता का access token *कभी भी* अमान्य हो सकता है। अगर ऐसा होता है, तो उपयोगकर्ता को एप्लिकेशन को फिर से अधिकृत करने के लिए कहें। अच्छे उपयोगकर्ता अनुभव के लिए यह सुनिश्चित करना ज़रूरी है कि इस स्थिति को सहजता से संभाला जाए।
  </Accordion>

  <Accordion title="एप्लिकेशन registration page read/write access के बारे में पूछता है। write में क्या शामिल होता है?">
    कई उपयोगकर्ता किसी एप्लिकेशन को अपनी जानकारी पढ़ने की अनुमति देते हैं, लेकिन ज़रूरी नहीं कि वे उसे अपनी उपयोगकर्ता प्रोफ़ाइल जानकारी बदलने या नई status पोस्ट करने की अनुमति भी दें। X API के ज़रिए जानकारी अपडेट करने के लिए — चाहे वह नाम हो, स्थान हो, या नई status जोड़ना हो — HTTP POST की आवश्यकता होती है। कोई भी API method जिसके लिए HTTP POST आवश्यक हो, उसे write method माना जाता है और उसके लिए read &amp; write access चाहिए।
  </Accordion>
</AccordionGroup>
