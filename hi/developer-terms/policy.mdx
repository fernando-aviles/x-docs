<div id="x-developers">
  ## X + डेवलपर्स
</div>

X को डेवलपर्स से प्यार है। X डेटा की शक्ति का उपयोग करके यह समुदाय जो टूल और सेवाएँ बनाता है, उनसे हम बेहद प्रसन्न और प्रभावित हैं। इस समुदाय के प्रति अपनी प्रतिबद्धता के तहत, हमारा लक्ष्य ऐसा डेटा ऐक्सेस उपलब्ध कराना है जो डेवलपर्स के लिए खुला और निष्पक्ष हो, X पर लोगों के लिए सुरक्षित हो, और समग्र रूप से X प्लेटफ़ॉर्म के लिए लाभकारी हो। इन लक्ष्यों को आगे बढ़ाने के लिए, हमने Developer Policy को एक मार्गदर्शिका के रूप में तैयार किया है, ताकि लोग API और X Content के उपयुक्त उपयोग के बारे में हमारे नियमों और अपेक्षाओं को समझ सकें।

यह Developer Policy (“**नीति**”) उन डेवलपर्स के लिए नियम और दिशानिर्देश प्रदान करती है जो X के ऐप्लिकेशन, सेवाओं, वेबसाइट, वेब पेजों और कॉन्टेंट के इकोसिस्टम के साथ इंटरैक्ट करते हैं। यह X API और X Content तक पहुँच तथा उनके उपयोग को नियंत्रित करने वाले X के साथ आपके अनुबंध का हिस्सा है (चाहे वह Developer Agreement के अंतर्गत हो या X के साथ किसी अन्य लिखित समझौते के अंतर्गत)। नीति का उल्लंघन आपके समझौते का उल्लंघन माना जाएगा। इस नीति में समय-समय पर बिना सूचना के बदलाव किए जा सकते हैं। इस नीति में प्रयुक्त बड़े अक्षरों में लिखे गए वे शब्द, जिन्हें इस नीति में परिभाषित नहीं किया गया है, उनके वही अर्थ होंगे जो [Developer Agreement](/hi/developer-terms/agreement) या Master License Agreement में उन्हें दिए गए हैं।

<div id="using-this-policy">
  ## इस नीति का उपयोग
</div>

हमने इस नीति को इस तरह व्यवस्थित किया है कि इसका पालन करना आपके लिए यथासंभव आसान हो। X API और X Content का उपयोग करते समय, कृपया नीचे दिए गए नीति अनुभागों की जानकारी हमेशा ध्यान में रखें:

1. **सफलता के लिए खुद को तैयार करें** - X की सभी नीतियों का पालन करना आपकी ज़िम्मेदारी है। X API और X Content तक पहुँचने से पहले यह ज़रूरी है कि आप इस नीति की, साथ ही इस दस्तावेज़ में लिंक की गई नीतियों की भी, समीक्षा करें और उन्हें समझें। हमारी नीतियों को समझने में लगाया गया समय आगे चलकर आपको दोबारा काम करने में लगने वाले कई घंटे बचा सकता है।

2. **गोपनीयता और नियंत्रण आवश्यक हैं** - X पर लोगों की गोपनीयता की रक्षा और सुरक्षा करना हमारी कंपनी के मूल सिद्धांतों का हिस्सा है। इसलिए, हम X डेटा के ऐसे किसी भी उपयोग की अनुमति नहीं देते जो लोगों की गोपनीयता संबंधी उचित अपेक्षाओं के विपरीत हो। X API पर निर्माण करके या X Content तक पहुँचकर, इस प्रतिबद्धता की रक्षा करने में आपकी एक विशेष भूमिका है—सबसे महत्वपूर्ण रूप से, लोगों की गोपनीयता का सम्मान करके और उन्हें यह पारदर्शिता व नियंत्रण देकर कि उनके डेटा का उपयोग कैसे किया जाता है।

3. **प्लेटफ़ॉर्म उपयोग दिशानिर्देशों का पालन करें** - X API और X Content तक पहुँच की स्वीकृति मिलना केवल पहला कदम है। X प्लेटफ़ॉर्म के अपने नियोजित उपयोग के लिए नीति-अनुपालन कैसे सुनिश्चित करें, इस बारे में जब भी आपके मन में कोई सवाल हो, हमारे प्लेटफ़ॉर्म उपयोग दिशानिर्देश आपकी पहली संदर्भ सामग्री होने चाहिए।

नीचे हमने इन तीनों प्रमुख अनुभागों के अर्थ के बारे में और अधिक विस्तार से जानकारी दी है। कृपया उनकी सावधानीपूर्वक समीक्षा करें, ताकि यह सुनिश्चित किया जा सके कि X API और X Content का आपका उपयोग हमारी नीतियों के अनुरूप है।

यदि हमें लगता है कि आप इस नीति (या किसी अन्य X नीति) का उल्लंघन कर रहे हैं, तो हम X API और X Content तक आपकी पहुँच को निलंबित कर सकते हैं या स्थायी रूप से रद्द कर सकते हैं।

अंत में, कृपया ध्यान दें कि X, X Applications को बेहतर बनाने, किसी भी व्यावसायिक उपयोग की जाँच करने, और आपके स्वीकृत उपयोग-मामले तथा इस नीति के अनुपालन को सुनिश्चित करने के लिए X API के आपके उपयोग की निगरानी कर सकता है।

इसे पढ़ने के लिए धन्यवाद, और हमारे साथ निर्माण करने के लिए भी आपका धन्यवाद! आप क्या बनाते हैं, यह देखने के लिए हम उत्सुक हैं!

<div id="set-yourself-up-for-success">
  ## सफलता के लिए खुद को तैयार करें
</div>

यदि आप शुरू से ही यह सुनिश्चित करें कि आपकी सेवा सही तरीके से बनाई गई है, तो X API का उपयोग करते समय कई संभावित समस्याओं से बचा जा सकता है। Developer Policy के इस अनुभाग में वे नियम दिए गए हैं जिनका X API या X Content का उपयोग करने से पहले सभी डेवलपर्स को पालन करना आवश्यक है।

Free, Basic, और Pro प्लान (जैसा कि [developer.x.com/en](http://developer.x.com/en) पर बताया गया है) शौकिया उपयोग, व्यावसायिक प्रोटोटाइपिंग, शुरुआती चरण के X उत्पाद इंटीग्रेशन, और सीमित अंतिम-उपयोगकर्ताओं वाले ऐप्लिकेशनों के समर्थन के लिए बनाए गए हैं। यदि आप X API और X Content का उपयोग इस दायरे से आगे करते हैं, तो आपको Enterprise प्लान के लिए आवेदन करना होगा (या उस प्लान की सदस्यता पहले से ले रखनी होगी) (जैसा कि [developer.x.com/en](http://developer.x.com/en) पर बताया गया है)।

**हम नीति-अनुपालन की पुष्टि करने के लिए X डेवलपर प्लेटफ़ॉर्म के सभी प्रस्तावित उपयोगों की समीक्षा करते हैं — इसलिए आपको X API और X Content के अपने नियोजित उपयोग का खुलासा करना (और जहाँ लागू हो, उसे अपडेट करना) आवश्यक है, ताकि आपको एक्सेस दिया जा सके और वह बनाए रखा जा सके।** सभी नए डेवलपर्स को X API तक पहुँच पाने के लिए [डेवलपर खाते के लिए आवेदन करना](https://developer.x.com/portal/petition/essential/basic-info) होगा। जिन मौजूदा डेवलपर्स के पास स्वीकृत डेवलपर खाता नहीं है, उन्हें X के निर्देशानुसार उसके लिए आवेदन करना होगा। इस प्रक्रिया के हिस्से के रूप में, आपको X API और X Content के अपने इच्छित उपयोगों का लिखित विवरण हमें देना होगा।

आपके उपयोग-मामले का विवरण आपके लिए बाध्यकारी है, और उससे कोई भी महत्वपूर्ण विचलन हमारे नियमों का उल्लंघन माना जा सकता है तथा उसके परिणामस्वरूप प्रवर्तन कार्रवाई हो सकती है। अपने उपयोग-मामले में किसी भी महत्वपूर्ण बदलाव के बारे में आपको हमें सूचित करना होगा और उस नए उद्देश्य के लिए X Content का उपयोग शुरू करने से पहले स्वीकृति प्राप्त करनी होगी। ऐसा न करने पर आपकी API और डेटा तक पहुँच निलंबित या समाप्त की जा सकती है।

**X API पर निर्माण करके या X Content तक पहुँच प्राप्त करके, आपको X की सभी नीतियों का पालन करना होगा।** इनमें यह [Developer Policy](/hi/developer-terms/policy), [Automation Rules](https://help.x.com/rules-and-policies/x-automation), [Display Requirements](https://developer.x.com/developer-terms/display-requirements.html), [API Restricted Uses Rules](/hi/developer-terms/restricted-use-cases), [X Rules](https://help.x.com/rules-and-policies/x-rules), और [X Brand Resources](https://about.x.com/who-we-are/brand-toolkit) शामिल हैं, साथ ही X API या X Content के आपके उपयोग से संबंधित X के साथ किए गए अन्य किसी भी समझौते भी, जिनमें [Developer Agreement](/hi/developer-terms/agreement) या Master Licensing Agreement या Order (जहाँ लागू हो) शामिल हैं, हालांकि इन्हीं तक सीमित नहीं हैं। आपको इन नीतियों में किए गए किसी भी संशोधन और X द्वारा जारी की गई किसी भी नई नीतियों का भी पालन करना होगा। यह आपकी जिम्मेदारी है कि आप अपनी सेवा के उपयोग की निगरानी करें और अपनी सेवा को इस तरह डिज़ाइन करें कि उसका उपयोग करने वाले लोग X नीति का उल्लंघन न कर सकें। ऐसा न करने पर आपकी API और X Content तक पहुँच निलंबित या समाप्त की जा सकती है।

**आप किसी एक उपयोग-मामले या अत्यधिक समान अथवा आपस में ओवरलैप होने वाले उपयोग-मामलों के लिए कई ऐप पंजीकृत नहीं कर सकते।** इस संदर्भ में, “उपयोग-मामला” से आशय किसी ऐप्लिकेशन के माध्यम से किए जाने वाले विश्लेषणों, प्रदर्शनों या कार्रवाइयों के एक सुसंगत समूह से है। किसी टूल या सेवा के &quot;white label&quot; संस्करण अनुमत नहीं हैं। यदि आप अपने ऐप्लिकेशन के “white label” संस्करण बनाने की योजना रखते हैं, तो आपको हमें सूचित करना होगा और हमसे अलग स्वीकृति लेनी होगी।

*इन नियमों के एकमात्र अपवाद के रूप में,* आप एक ही सेवा के development, staging, और production इंस्टेंस के लिए अधिकतम 3 ऐप बना और उपयोग कर सकते हैं। ये ऐप एक ही खाते में पंजीकृत होने चाहिए, और इन्हें (नाम और विवरण में) स्पष्ट रूप से dev, staging, और prod इंस्टेंस के रूप में पहचाना जाना चाहिए। **आप development या staging ऐप का उपयोग production उद्देश्यों के लिए नहीं कर सकते।**

**आपको सभी API keys या अन्य access credentials को गोपनीय रखना होगा।** आप दूसरों के स्वामित्व वाली API keys या अन्य access credentials का उपयोग नहीं कर सकते, और न ही दूसरों को ऐसा करने के लिए प्रोत्साहित या सक्षम कर सकते हैं।

**X के साथ आपका लाइसेंस समझौता X API और X Content के आपके उपयोग को सीमित करता है। अन्य बातों के अलावा, X API में रेट लिमिट्स हैं, जो डेटा के निष्पक्ष उपयोग को सुनिश्चित करने और प्लेटफ़ॉर्म पर स्पैम से निपटने में मदद करती हैं।** आप रेट लिमिट्स, या इस Policy अथवा X के साथ आपके समझौते में वर्णित किसी भी अन्य सीमा या प्रतिबंध को पार या दरकिनार नहीं कर सकते, चाहे वे [Developer Site](https://developer.x.com/) पर सूचीबद्ध हों या X द्वारा आपको बताए गए हों।

**आप X API के माध्यम से प्राप्त X Content पर मौजूद किसी भी स्वामित्व-सूचना या चिह्न को हटा या बदल नहीं सकते।** इससे यह सुनिश्चित करने में मदद मिलती है कि लोग जान सकें कि X Content कहाँ से आ रहा है और उसका स्वामी कौन है।

**डेटा अखंडता और प्लेटफ़ॉर्म की सुव्यवस्था के कारणों से, आप X API या X सेवा की किसी भी सुविधा में हस्तक्षेप, अवरोधन, व्यवधान, या उसे निष्क्रिय नहीं कर सकते।** दूसरे शब्दों में, APIs का उपयोग उसी प्रकार करें जैसा उनका उद्देश्य है और जैसा [developer.x.com](https://developer.x.com/) पर प्रलेखित है। स्वीकार्य उपयोग के बारे में अधिक जानकारी के लिए हमारे [HackerOne guidelines](https://hackerone.com/x) देखें।

  ## गोपनीयता और नियंत्रण अनिवार्य हैं
</div>

X गोपनीयता को गंभीरता से लेता है, और हम अपेक्षा करते हैं कि X Content और X API का उपयोग करने वाला हर व्यक्ति भी ऐसा ही करे। X डेवलपर प्लेटफ़ॉर्म, X API, या X Content का कोई भी ऐसा उपयोग जो लोगों की गोपनीयता के बारे में उनकी उचित अपेक्षाओं के अनुरूप न हो, प्रवर्तन कार्रवाई के अधीन हो सकता है, जिसमें API और X Content की पहुँच का निलंबन या समाप्ति शामिल हो सकती है।

गोपनीयता और नियंत्रण के प्रति आपकी प्रतिबद्धता, X Content के सभी उपयोगों और हमारी API का उपयोग करके आपके द्वारा बनाई गई सेवा के सभी पहलुओं तक लागू होनी चाहिए। इसके लिए, आपकी सेवा का उपयोग करने वाले लोगों को यह समझना और इसके लिए सहमति देना आवश्यक है कि आप उनके डेटा का उपयोग कैसे करते हैं, और उनकी ओर से X तक कैसे पहुँचते हैं। यह लोगों को एक स्पष्ट, व्यापक और पारदर्शी गोपनीयता नीति प्रदान करके, और साथ ही आपकी सेवा का उपयोग करने वाले प्रत्येक व्यक्ति से उनकी ओर से कोई भी कार्रवाई करने से पहले स्पष्ट और सूचित सहमति प्राप्त करके सुनिश्चित किया जा सकता है। **कृपया ध्यान दें कि केवल किसी व्यक्ति का आपकी सेवा में प्रमाणित हो जाना अपने-आप में सहमति नहीं माना जाता।**

<div id="consent-permissions">
  ## सहमति और अनुमतियाँ
</div>

**विशेष रूप से, निम्न में से कोई भी कार्य करने से पहले आपको लोगों की स्पष्ट और सूचित सहमति लेनी होगी:**

* उनकी ओर से *कोई भी* कार्रवाई करना। इसमें शामिल है (लेकिन यह इन्हीं तक सीमित नहीं है):
  * X पर सामग्री पोस्ट करना
  * खातों को फ़ॉलो/अनफ़ॉलो करना
  * प्रोफ़ाइल या खाते की जानकारी में बदलाव करना
  * पोस्ट्स में हैशटैग या कोई अन्य सामग्री जोड़ना

* X API या अन्य X टूल्स के अलावा किसी अन्य माध्यम से प्राप्त सामग्री को पुनर्प्रकाशित करना

* किसी उत्पाद या सेवा का प्रचार करने के लिए किसी व्यक्ति की X Content का उपयोग करना

* गैर-सार्वजनिक सामग्री, जैसे डायरेक्ट मैसेज (DMs), या कोई अन्य निजी या गोपनीय जानकारी संग्रहीत करना

* संरक्षित सामग्री, या किसी अन्य निजी या गोपनीय जानकारी को साझा या प्रकाशित करना

**यदि आपकी सेवा लोगों को X पर सामग्री पोस्ट करने की अनुमति देती है, तो प्रकाशित करने से पहले आपको निम्न कार्य करने होंगे:**

* ठीक वही दिखाएँ जो प्रकाशित किया जाएगा
* आपकी सेवा का उपयोग करने वाले लोगों को स्पष्ट रूप से बताएँ कि सामग्री में कौन-सी भौगोलिक जानकारी (यदि कोई हो) जोड़ी जाएगी

**यदि आपकी सेवा लोगों को आपकी सेवा और X दोनों पर सामग्री पोस्ट करने की अनुमति देती है, तो प्रकाशित करने से पहले आपको निम्न कार्य करने होंगे:**

* सामग्री पोस्ट करने की अनुमति प्राप्त करें
* बताएँ कि आप सामग्री कहाँ पोस्ट करेंगे

**आपको सभी X Content की संरक्षित और ब्लॉक की गई स्थिति का सम्मान करना होगा। आप किसी एक व्यक्ति के authentication token का उपयोग करके प्राप्त सामग्री किसी ऐसे दूसरे व्यक्ति को उपलब्ध नहीं करा सकते, जो उस सामग्री को देखने के लिए अधिकृत नहीं है।**

* **संरक्षित खाते:** एक [protected account](https://help.x.com/safety-and-security/public-and-protected-posts) की सामग्री केवल उन लोगों के लिए उपलब्ध होती है, जिन्हें स्वामी ने उस खाते को फ़ॉलो करने की अनुमति दी है। इसलिए, यदि आप ऐसी सेवा चलाते हैं जो संरक्षित खातों तक पहुँचती है, तो आप ऐसा केवल उस सामग्री को उन्हीं विशिष्ट लोगों तक पहुँचाने के लिए कर सकते हैं जिन्हें उसे देखने की अनुमति है।
* **ब्लॉक किए गए खाते:** X पर लोग अपनी इच्छा के अनुसार किसी भी कारण से अपने खातों तक पहुँच को [block](https://help.x.com/using-x/blocking-and-unblocking-accounts) कर सकते हैं। इस विकल्प को दरकिनार करने के लिए tokens (या किसी अन्य API-आधारित कार्रवाई) से प्राप्त जानकारी को मिलाना अनुमत नहीं है।

**क्योंकि डायरेक्ट मैसेज (DMs) स्वभाव से गैर-सार्वजनिक होते हैं, DM सुविधाएँ प्रदान करने वाली सेवाओं को व्यक्तिगत गोपनीयता की सुरक्षा के लिए अतिरिक्त कदम उठाने होंगे। आप DM सामग्री उन लोगों को उपलब्ध नहीं करा सकते जो उसे देखने के लिए अधिकृत नहीं हैं। यदि आपकी सेवा DM कार्यक्षमता प्रदान करती है, तो आपको यह भी करना होगा:**

* यदि आप DMs के लिए read receipt events भेजते हैं, तो लोगों को इसकी सूचना दें। आप यह सूचना सीधे अपनी सेवा में दे सकते हैं, या किसी बातचीत में अन्य प्रतिभागियों के read receipts दिखाकर ऐसा कर सकते हैं।
* किसी DM में भेजे जाने वाले मीडिया को &quot;shared&quot; (अर्थात कई DMs में पुन: उपयोग किए जाने योग्य) के रूप में कॉन्फ़िगर करने से पहले सहमति प्राप्त करें। यदि आप किसी DM में मीडिया को “shared” होने की अनुमति देते हैं, तो आपको स्पष्ट सूचना देनी होगी कि यह सामग्री मीडिया के URL वाले किसी भी व्यक्ति के लिए सुलभ होगी।

  ## सामग्री अनुपालन
</div>

**यदि आप X Content को ऑफ़लाइन संग्रहीत करते हैं, तो आपको उसे X पर उस X Content की मौजूदा स्थिति के अनुरूप अद्यतन रखना होगा।** विशेष रूप से, यदि कोई सामग्री X पर हटा दी जाती है या उसमें संशोधन किया जाता है, तो आपके पास मौजूद उस सामग्री को भी आपको हटाना या संशोधित करना होगा। यह कार्य यथाशीघ्र, या X अथवा संबंधित X खाता-स्वामी से ऐसा करने का अनुरोध मिलने के 24 घंटों के भीतर, या X के साथ आपके अनुबंध अथवा लागू कानून के तहत जैसा भी अपेक्षित हो, किया जाना चाहिए। यह कार्य तब तक किया जाना चाहिए, जब तक कानून इसके विपरीत रोक न लगाता हो, और ऐसी स्थिति में भी केवल X की स्पष्ट लिखित अनुमति के साथ।

संशोधित सामग्री कई रूपों में हो सकती है। इसमें शामिल हैं (लेकिन इन्हीं तक सीमित नहीं हैं):

* ऐसी सामग्री जिसे निजी बना दिया गया हो या जिसे संरक्षित स्थिति मिल गई हो
* ऐसी सामग्री जिसे प्लेटफ़ॉर्म से निलंबित कर दिया गया हो
* ऐसी सामग्री जिसके geotags हटा दिए गए हों
* ऐसी सामग्री जिसे X पर रोका गया हो या हटा दिया गया हो

<div id="off-x-matching">
  ## Off-X मिलान
</div>

**हम उन परिस्थितियों को सीमित करते हैं जिनमें आप X पर किसी व्यक्ति का मिलान Off-X से प्राप्त या वहाँ संग्रहीत जानकारी के साथ कर सकते हैं।** Off-X मिलान में X Content, जिसमें X @handle या यूज़र id शामिल है, को किसी व्यक्ति, परिवार, डिवाइस, ब्राउज़र या किसी अन्य Off-X पहचानकर्ता से जोड़ना शामिल है। आप ऐसा केवल तभी कर सकते हैं, जब यह संबंध स्थापित करने से पहले आपके पास उस व्यक्ति की स्पष्ट opt-in सहमति हो, या जैसा कि नीचे बताया गया है।

ऐसी स्थितियों में, जहाँ किसी व्यक्ति की X पहचान को किसी Off-X पहचानकर्ता से जोड़ने के लिए आपके पास उसकी स्पष्ट, opt-in सहमति नहीं है, हम अपेक्षा करते हैं कि आपके द्वारा स्थापित कोई भी संबंध केवल ऐसी जानकारी पर आधारित हो, जिसका उस उद्देश्य के लिए उपयोग किया जाना कोई व्यक्ति युक्तिसंगत रूप से अपेक्षित करे। इसके अतिरिक्त, किसी व्यक्ति की स्पष्ट opt-in सहमति के बिना, आप किसी व्यक्ति के बारे में अपने रिकॉर्ड का X पहचान से मिलान करने का प्रयास केवल निम्नलिखित के आधार पर कर सकते हैं:

* **वह जानकारी जो व्यक्ति ने सीधे आपको दी हो।** ध्यान दें कि उन व्यक्तियों के बारे में रिकॉर्ड, जिनसे आपका कोई पूर्व संबंध नहीं है, जिसमें तृतीय पक्षों से प्राप्त व्यक्तियों का डेटा भी शामिल है, इस मानक को पूरा नहीं करते; और/या
* **सार्वजनिक डेटा।** इस संदर्भ में “सार्वजनिक डेटा” से आशय है:
  * किसी व्यक्ति के बारे में वह जानकारी, जो आपने किसी सार्वजनिक, सामान्यतः उपलब्ध संसाधन से प्राप्त की हो (जैसे किसी पेशेवर संघ के सदस्यों की निर्देशिका)
  * X पर किसी व्यक्ति के बारे में सार्वजनिक रूप से उपलब्ध जानकारी, जिसमें शामिल हैं:
    * पोस्ट्स
    * प्रोफ़ाइल जानकारी, जिसमें अकाउंट bio और सार्वजनिक रूप से बताई गई लोकेशन शामिल है
    * डिस्प्ले नाम और @handle

<div id="using-geo-data">
  ## भू-डेटा का उपयोग
</div>

**इस जानकारी की संवेदनशील प्रकृति के कारण भू-डेटा के उपयोग पर अतिरिक्त प्रतिबंध लागू होते हैं।** यदि आपकी सेवा पोस्ट्स में स्थान संबंधी जानकारी जोड़ती है, तो आपको लोगों को यह बताना होगा:

* आप स्थान संबंधी जानकारी कब जोड़ते हैं
* क्या आप स्थान संबंधी जानकारी geotag के रूप में जोड़ते हैं या annotations data के रूप में
* क्या आपकी स्थान संबंधी जानकारी place के रूप में सूचीबद्ध है या भौगोलिक निर्देशांकों के रूप में

यदि आपका ऐप लोगों को अपने स्थान के साथ पोस्ट करने की अनुमति देता है, तो आपको X के [भू-निर्देशों](/hi/developer-terms/geo-guidelines) का पूरी तरह पालन करना होगा।

**स्थान डेटा या भौगोलिक जानकारी का स्वतंत्र रूप से कोई भी उपयोग प्रतिबंधित है।** आप X Content में शामिल स्थान डेटा और अन्य भौगोलिक जानकारी को, पोस्ट के हिस्से के अलावा, संग्रहीत, एकत्रित या cache नहीं कर सकते (और न ही दूसरों को ऐसा करने की अनुमति दे सकते हैं)। उदाहरण के लिए, आप यह दिखाने के लिए कि समय के साथ लोग कहाँ-कहाँ रहे हैं, पोस्ट्स से स्थान डेटा या भौगोलिक जानकारी को अलग नहीं कर सकते। समेकित भू-गतिविधि दिखाने वाले heat maps और संबंधित टूल्स (उदाहरण के लिए, किसी शहर में hashtag का उपयोग करने वाले लोगों की संख्या) की अनुमति है।

* लोगों को [स्वचालित उत्तर या डायरेक्ट मैसेज](https://twittercommunity.com/t/policy-clarification-automated-replies-and-mentions/94444) भेजने से पहले हमेशा उनकी स्पष्ट सहमति लेनी चाहिए
* आपसे संपर्क न किए जाने के अनुरोधों का तुरंत सम्मान करना चाहिए
* कभी भी बड़े पैमाने पर, आक्रामक या स्पैम जैसे कार्य नहीं करने चाहिए, जिनमें [बड़ी संख्या में फ़ॉलो करना](https://twittercommunity.com/t/policy-clarification-aggressive-following-and-inorganic-following-behavior/92769) शामिल है
* [एकाधिक खातों](https://blog.twitter.com/developer/en_us/topics/tips/2018/automation-and-the-use-of-multiple-accounts.html) पर कभी भी एक जैसी या काफी मिलती-जुलती सामग्री पोस्ट नहीं करनी चाहिए

**यदि आप API-आधारित बॉट खाता चला रहे हैं, तो आपको स्पष्ट रूप से बताना होगा कि यह खाता क्या है और इसके लिए कौन ज़िम्मेदार है।** आपको लोगों को इस बारे में कभी गुमराह या भ्रमित नहीं करना चाहिए कि आपका खाता बॉट है या नहीं। ऐसा करने का एक अच्छा तरीका यह है कि प्रोफ़ाइल बायो में यह उल्लेख शामिल करें कि यह खाता एक बॉट है।

  ## सामग्री का पुनर्वितरण

**X Content प्राप्त करने का सर्वोत्तम स्थान सीधे X है। इसलिए, हम तीसरे पक्षों को X Content के पुनर्वितरण को सीमित करते हैं।** यदि आप तीसरे पक्षों को X Content उपलब्ध कराते हैं, जिसमें डाउनलोड किए जा सकने वाले डेटासेट या API के माध्यम से उपलब्ध कराई गई सामग्री शामिल है, तो आप केवल पोस्ट IDs, Direct Message IDs, और/या User IDs ही वितरित कर सकते हैं (नीचे वर्णित स्थिति को छोड़कर)।

शैक्षणिक शोधकर्ताओं को केवल किसी शैक्षणिक संस्थान की ओर से किए जा रहे गैर-व्यावसायिक शोध के उद्देश्यों के लिए, जिसे X ने लिखित रूप में स्वीकृत किया हो, या ऐसे शोध की peer review या validation के लिए पोस्ट IDs और/या User IDs वितरित करने की अनुमति है। ऐसे शोध के लिए केवल उतने ही पोस्ट IDs या User IDs उपयोग किए जा सकते हैं, जितने आवश्यक हों और जिन्हें X ने स्वीकृत किया हो।

* **आप X Content या X API से प्राप्त जानकारी का उपयोग X प्लेटफ़ॉर्म के बाहर लोगों को विज्ञापन दिखाने के लिए लक्षित करने हेतु नहीं कर सकते।**
