次のページでは、X API に含まれる Spaces エンドポイントについて説明します。Spaces 全般の詳細については、[help.x.com](https://help.x.com/en/using-twitter/spaces) を参照してください。 

Spaces は、ライブ音声での会話による表現と交流を可能にします。Spaces エンドポイントは、Spaces を中心とした新たな機能を構築するためのツールを提供します。これらのエンドポイントを使用して、ライブまたはスケジュール済みの Spaces を取得したり、ユーザーが興味を持ちそうな Spaces を見つけられるような発見機能を構築したりできます。

私たちは、Spaces を私たちが用意した形にとどめず、皆さんの創造性によってさらに拡張していただくことをおすすめします。これらのエンドポイントを使うことで、タイトルに含まれるキーワードに基づいてリスナーに Spaces をおすすめしたり、ユーザーがフォローしているアカウントのうち、ライブまたは今後開催予定の Spaces をホストしているアカウントを表示したりできます。また、ホストが自分の Spaces のパフォーマンスをより深く理解し、オーディエンスに関する洞察を得られるよう支援することも可能です。

<div id="understanding-the-lifecycle-of-spaces">
  #### Spaces のライフサイクルの理解
</div>

X Developer Platform 上の他のリソースとは異なり、Spaces には定められたライフサイクルがあります。Spaces は開始予定日の最大 14 日前までスケジュールでき、終了後は利用できなくなります。ホストは、開始前であれば、スケジュール済みの Space をいつでもキャンセルできます。

Spaces はライブ中であればアクセス可能ですが、終了すると Spaces エンドポイントを使用して取得することはできなくなり、この状態を示すエラーメッセージが返されます。

アプリで Spaces の data を扱う場合、常に最新の情報を返し、プラットフォーム上で利用できなくなった data を削除する責任があります。[Spaces lookup endpoint](/ja/x-api/spaces/lookup/introduction) を使用することで、ユーザーの期待や意図を確実に尊重できます。
 

<div id="roles-in-spaces">
  ### Spaces における役割
</div>

これらのエンドポイントは、X アプリにおける Spaces の仕組みを反映したものです。Spaces では、X ユーザーは Space との関わり方や Space 内での行動に応じて、特定の役割を持つことができます。
 

<div id="creator-or-primary-host">
  ### 作成者（またはプライマリホスト）
</div>

Primary Host は Space を作成したユーザーであり、その Space 自体の所有者です。現在、Space には Host を 1 人しか設定できないため、その Primary Host が唯一の Host になります。[Spaces data dictionary](/ja/x-api/fundamentals/data-dictionary#space) では、Primary Host の情報は `creator_id` フィールドに含まれており、これは [user object](/ja/x-api/fundamentals/data-dictionary#user) に展開できます。
 

<div id="hosts">
  ### ホスト
</div>

メインホストは、1人以上のユーザーを共同ホストに指定できます。Spaces のデータ辞書では、これらのホストは `host_ids` として表され、ユーザーオブジェクトのリストに展開できます。ホストの指定は Space の開催中に変更される可能性があり、これらのエンドポイントから返されるメタデータは、リクエスト時点のステータスを反映します。

アプリでは、`creator_id` の値を確認することでメインホストを特定し、`host_ids` の値を確認することで共同ホストを特定できます。
 

<div id="speaker">
  ### スピーカー
</div>

スピーカーとは、Space 内で発言する権限を持つユーザーのことです。任意の時点で 0 人以上のスピーカーが存在でき、1 つの Space にはホストを含めて最大 10 人までのスピーカーが参加できます。Space データディクショナリでは、スピーカーは `speaker_ids` リストで返され、このリストを展開することでユーザーオブジェクトの一覧を取得できます。
 

<div id="listener">
  ### リスナー
</div>

リスナーはスペースを視聴し、あらかじめ定義されたリアクションを使っていつでも反応でき、ホストがスペースの設定で許可している場合はスピーカーになるようリクエストすることもできます。リスナーに関する情報は、participant&#95;count フィールドで、（ホストを含む）参加者の合計数としてのみ返されます。
