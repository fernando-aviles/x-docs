<div id="overview">
  ## 概要
</div>

[`Enterprise`](https://developer.x.com/en/products/x-api/enterprise)

*これは、マネージドアクセスレベルでのみ利用可能なエンタープライズ API です。この API を利用するには、まずエンタープライズセールスチームとの間でアカウントの契約を行う必要があります。 [詳細はこちら](/ja/x-api/enterprise-gnip-2.0/enterprise-gnip)*

Engagement API は、投稿のインプレッションおよびエンゲージメント指標へのアクセスを提供します。ほとんどの指標とエンドポイントでは [OAuth 1.0a ユーザーコンテキスト](/ja/resources/fundamentals/authentication) を使用して認証する必要がありますが、[OAuth 2.0 Bearer Token](/ja/resources/fundamentals/authentication#oauth-2-0) と /totals エンドポイントを使用することで、公開されている「いいね」「リポスト」「返信」「動画再生数」の指標にアクセスできます。  

**注:** 一部の X の Web ダッシュボードで表示されるレポートデータと、Engagement API でレポートされるデータに相違が見られる場合があります。これは、通常 Web ダッシュボードが、選択された時間範囲内に発生したエンゲージメントやインプレッションのみを表示するために発生します。たとえば、Web ダッシュボードでは暦月の期間内に行われた投稿のエンゲージメントのみを表示する一方で、Engagement API では、その月の期間外であっても、要求された時間範囲内に含まれるエンゲージメントを表示することがあります。これらの場合は、Engagement API を正確な情報源として扱ってください。
 

<div id="request-endpoints">
  ### リクエストエンドポイント
</div>

Engagement API には 3 つのエンドポイントが用意されています。

<div id="current-totals-totals">
  #### 現在の合計: [/totals]
</div>

* リクエストは、対象の投稿についてのインプレッションの合計値とエンゲージメントの合計値を返します
* 使用できる指標は次のものに限定されます: インプレッション、エンゲージメント、いいね、返信、リポスト、引用ポスト、および動画再生数
* OAuth 1.0a ユーザーコンテキストを使用して、**直近90日以内** に作成された投稿の **Impressions** および **Engagements** 指標を取得できます
* OAuth 2.0 Bearer Token を使用して、**任意の投稿** の **Favorites, Retweets, Quote Tweets, Replies,** および **Video Views** 指標を取得できます
* 結果は、リクエストが行われた時点のインプレッションとエンゲージメントの現在の合計に基づいています
* ダッシュボードレポートの作成や、さまざまな @ハンドルにわたるエンゲージメント率の算出に最適です
* 1回のリクエストで最大 250 件の投稿に対する指標の取得をサポートします
   

<div id="last-28-hours-28hr">
  #### 過去28時間: [/28hr]
</div>

* リクエストでは、インプレッションの合計指標、エンゲージメントの合計指標、および過去28時間に発生した個々のエンゲージメント指標の内訳を返すことができます
* データは投稿IDごと、または時系列の集計（全体、日別、時間別）でグループ化できます
* 直近に作成されたコンテンツのパフォーマンスを追跡するのに最適です
* 利用可能なすべての指標をサポートします
* 1回のリクエストで最大25件の投稿の指標をリクエストできます
   

<div id="historical-historical">
  #### 履歴: [/historical]
</div>

* リクエストでは、直近1年間について、インプレッション、エンゲージメント、および個々のエンゲージメント指標の内訳を、投稿の作成時刻ではなくエンゲージメント時刻に基づいて取得できます。
* リクエストは開始日と終了日のパラメータをサポートしており、最大4週間までの特定の期間に絞り込むことができます。
* 投稿のエンゲージメントデータは、過去365日分まで取得できます。
* data は投稿 ID ごと、または日単位・時間単位などの時系列の集計単位でグループ化できます。
* 直近のパフォーマンスを過去のベンチマークと比較したり、特定の @handle のパフォーマンスの経時的な推移を把握したりするのに最適です。
* 利用可能なすべての指標をサポートします。
* 1回のリクエストで最大25件の投稿の指標をリクエストできます。

<div id="engagement-groupings">
  ### エンゲージメントのグルーピング
</div>

グルーピングを使用すると、返されるエンゲージメント指標を任意の形で整理できます。1 回のリクエストで指定できるグルーピングは最大 3 つです。指標は、次の値の 1 つ以上でグループ化できます。

*3 つすべてのエンドポイントでサポートされる項目:*

* tweet.id
* engagement.type
   

*`/28hr` と `/historical` は時系列の指標を提供できるため、次の項目もサポートします:*

* engagement.day
* engagement.hour

グルーピングの詳細については、「ガイド」セクション内の [Engagement API のグルーピング](/ja/x-api/enterprise-gnip-2.0/fundamentals/engagement-api#engagement-api-groupings) ページをご覧ください。

<div id="introduction">

</div>

このドキュメントの目的は、開発者向けに Engagement API との連携方法を紹介することです。まずはなぜ連携するのかについて説明し、その後で技術的な「方法」の詳細に踏み込んでいきます。

<div id="what-does-the-engagement-api-provide">
  ##### **Engagement API は何を提供しますか？**
</div>

* Engagement API は、当該アカウントがあなたのアプリに対し、自身に代わってメトリクスの取得を許可していることを前提に、任意の X アカウントが過去 90 日間に行った投稿に対するインプレッションおよびエンゲージメントのデータを提供します。これは、[3-legged OAuth](/ja/resources/fundamentals/authentication#obtaining-access-tokens-using-3-legged-oauth-flow) を使用してそのアカウントがあなたのアプリに対して権限を付与している場合に適用されます。この強力でありながら実装が容易なソリューションにより、インプレッションや URL クリック、#ハッシュタグ クリックなど、さまざまな詳細なエンゲージメントに即時アクセスできます。
* Engagement API は、任意の投稿について、いいね、リツイート、引用ツイート、返信、動画再生数の総計メトリクスを提供します。これは、任意の投稿または投稿の集合に関する基本的なエンゲージメントデータを取得する強力な手段として利用できます。
* Engagement API は、15 以上のパフォーマンスメトリクスを用いてコンテンツのパフォーマンスを効果的に計測することで、X 上での ROI を測定できるようにし、ソーシャルリスニング、マーケティング、およびパブリッシングプラットフォームに新たな価値を提供します。
* Engagement API はリクエスト/レスポンス型の API であり、アプリ開発者は Post ID、取得したいメトリクス、および時間範囲を含むリクエストを送信でき、それに対して API は即座に data を返します。
   

<div id="why-integrate-example-use-cases">
  ##### **なぜ統合するのか？ ユースケース例**
</div>

* 自分のコンテンツがどれだけの人に閲覧されているかを把握する。動画の再生数、リンクのクリック数、ハッシュタグのクリック数、アプリのインストール数などを確認する。
* 合計値と時系列の両方のエンゲージメント指標を生成する。
* 任意の公開された投稿について、基本的なエンゲージメント指標（いいね、リツイート、引用ツイート、返信）を把握する。
* これらの指標を使って、どのタイプの投稿が効果的かを判断し、そのような投稿をより頻繁に行うことで、コンテンツのインプレッション数とエンゲージメントをさらに増やす。
* 自分の投稿のいずれかが100件のいいね、または別のしきい値に達するたびに、別の自社アカウントからのリツイートなどのマーケティング行動を自動化する。
* A/Bテストのためのツールとして、キャンペーン同士を比較・ベンチマークする。
* カスタマーサービス部門向けに、どのタイプのコンテンツがユーザーの共感を得ているかを分析し、どのように・いつ対応するかを判断する。
* 自分のプラットフォームから配信されたコンテンツのアナリティクスを表示する。
   

[Engagement API は 2016 年にリリースされ](https://blog.x.com/official/en_us/a/2016/gnip-s-engagement-api-is-now-generally-available.html)、このような詳細なエンゲージメント指標を大規模に提供した最初の X API です。Engagement API は使いやすく、プロセスの自動化を可能にします。以下は、統合例を示したケーススタディです。

* [赤十字社と共にキャンペーンの成果を測定する](https://blog.x.com/developer/en_us/topics/spotlight/2016/measuring-campaign-success-with-the-red-cross.html)[](https://simplymeasured.com/blog/true-twitter-impressions-and-url-clicks-new-from-simply-measured/#sm.0007werel134td8zqf02m2mduumr6)

<div id="integrating-the-engagement-api">
  #### Engagement API の統合
</div>

<div id="introduction-to-api">
  ##### **API の概要**
</div>

Engagement API はシンプルな RESTful API で、JSON でエンコードされたリクエストを受け取り、JSON でエンコードされたエンゲージメント指標を返します。リクエストは主に次の 3 つの要素で構成されます（詳細なドキュメントはリンク先を参照してください）。

* ***Post IDs*（投稿 ID）** の配列。
* 関心のある[指標タイプ](https://developer.x.com/en/docs/x-api/v1/metrics/get-tweet-engagement/overview#EngagementTypes)を指定する配列。タイプには「impressions」（インプレッション）、「retweets」（リツイート）、「hashtag&#95;clicks」、「user&#95;follows」などが含まれます。
* API レスポンス内でエンゲージメント data をどのように構成するかを指定する JSON 構造である [Engagement groupings](/ja/x-api/enterprise-gnip-2.0/fundamentals/engagement-api#engagement-api-groupings)。

多くの場合、Engagement Types と Groupings はリクエストごとにほぼ固定であり、更新されるのは Post IDs のみです。

Engagement API は[3 つのエンドポイント](https://developer.x.com/en/docs/x-api/v1/metrics/get-tweet-engagement/overview#RequestEndpoints)を提供します。

* **Totals** - 投稿ごとのエンゲージメントの総計を提供します。一部の指標はすべての投稿に対して利用できますが、その他の指標は過去 90 日間分のみ利用できます。
* **28 hour** - 直近 28 時間分の時系列エンゲージメント指標を提供します。
* **Historical** - 2014 年 9 月 1 日以降に投稿されたものについて、最大 4 週間連続の時系列エンゲージメント指標を提供します。

**/totals** エンドポイントでは、1 回のリクエストで最大 **250 件の投稿** の指標をリクエストできます。**/28hour** および **/historical** エンドポイントでは、**1 リクエストあたり 25 件** の指標をリクエストできます。

Engagement API へのアクセス方法について説明したのち、API リクエストの実行手順を確認し、OAuth の概要を示し、その他の技術リソースへのリンクを提供します。

<div id="getting-api-access">
  ##### **API へのアクセスを取得する**
</div>

このドキュメントを読んでいる場合、すでに Engagement API へのアクセス権を取得済みである可能性が高いです。まだの場合は、エンタープライズのアカウントマネージャーに連絡するか、[こちら](/ja/x-api/enterprise-gnip-2.0/enterprise-gnip)からエンタープライズアクセスを申請してください。

最初のステップは、承認済みの開発者アカウントを使用し、[Developer Console](/ja/resources/fundamentals/developer-portal) 経由で [X app](/ja/resources/fundamentals/developer-apps) を作成することです。アクセス権を付与するために、このアプリケーションに関連付けられた数値のアプリケーション ID をアカウントマネージャーに共有する必要があります。開発者アカウントを新たに申請する必要がある場合は、[こちら](/ja/resources/fundamentals/developer-apps)から行うことができます。

最初のステップは、JSON 形式で API リクエストを構築することです。これは、配列に入れた 2 つの投稿 ID、関心のあるエンゲージメントタイプの配列、およびメトリクスをレスポンス内でどのように整理するかを指定する、任意の名前を付けた &quot;groupings&quot; JSON オブジェクトで構成されます。リクエストは次のようになります。

```json
{
  "tweet_ids": [
    1260294888811347969, 850006245121695744
  ],
  "engagement_types": [
    "retweets", "quote_tweets", "favorites", "replies"
  ],
  "groupings": {
    "engagement-types-by-id": {
      "group_by": [
        "Tweet.id", "engagement.type"
      ]
    }
  }
}
```

これらの合計メトリクスを取得するには、`https://data-api.x.com/insights/engagement/totals` エンドポイントにこの JSON リクエストを POST します。

リクエストが JSON でエンコードされていることと、Gzip 圧縮されていること（リクエストボディが大きくなる場合があります）を示すために、次のヘッダーを含めます。

* Content-Type: application/json
* Accept-Encoding: gzip
   

リクエストを送信する際は OAuth を使用して認証します。これについては次のセクションで詳しく説明します。

API は次のペイロードを返します。

```json
{
  "grouping name": {
    "1260294888811347969": {
      "favorites": "17111",
      "quote_tweets": "3254",
      "replies": "1828",
      "retweets": "5218"
    },
    "850006245121695744": {
      "favorites": "492",
      "quote_tweets": "66",
      "replies": "42",
      "retweets": "324"
    }
  }
}
```

レスポンスでは、要求したメトリクスが「groupings」の定義どおりの構造で格納されています。最初の階層では Post ID ごとにメトリクスが並び、その下の階層ではエンゲージメントタイプごとにメトリクスが並んでいます。

簡単ですね。OAuth での認証が初めての場合は、次のセクションを参照してください。

<div id="authenticating-with-oauth">
  #### OAuth を使用した認証
</div>

OAuth はテクノロジー業界で非常によく使われている認証の標準仕様です。すでに OAuth（他の X API など）を使用している場合は、おそらく言語ごとの OAuth パッケージを利用しており、細かくややこしい部分はそのパッケージが抽象化してくれているはずです。OAuth に不慣れな場合は、[X API での OAuth](/ja/resources/fundamentals/authentication) のページにアクセスするか、直接 [https://oauth.net](https://oauth.net/) にアクセスして詳細を学んでください。そのうえで、まずは自分が統合に用いる言語向けの OAuth パッケージを探し、そこから始めることをお勧めします。これらのパッケージを使う場合、認証までの一般的な流れは、キーとトークンを設定し、何らかの HTTP オブジェクトを作成し、そのオブジェクトを使ってリクエストを送信する、という形になります。

たとえば Ruby の世界では、次の疑似コードは Ruby の gem である「oauth」を使って OAuth 対応アプリを構築し、POST リクエストを行うためのレシピを表しています。

```js
require 'oauth'

#Assemble JSON request (as above).
request = make_json_request()

#Build an app consumer object with my app consumer key and secret.
consumer = OAuth::Consumer.new(keys['consumer_key'], keys['consumer_secret'], {:site => ‘https://data-api.x.com’})
#権限を提供するアカウントから提供されたトークンを使用してユーザートークンを構築する。アプリのみの#リクエストを行う場合（/totalsエンドポイントで権限を必要としないツイートを確認する場合）、この手順は#スキップできる。
token = {:oauth_token => keys['access_token'], :oauth_token_secret => keys['access_token_secret']}

#Create oauth-enabled app object.
app = OAuth::AccessToken.from_hash(consumer, token)
#Make POST request.
result = app.post(“/insights/engagement/totals", request, {"content-type" => "application/json", "Accept-Encoding" => "gzip"})
```

Engagement API は、アプリケーションのみの認証とユーザーコンテキスト認証の両方をサポートしています。/totals エンドポイントで所有していない公開投稿のエンゲージメント指標を収集する場合、ユーザーの許可は不要であり、アプリケーションのみの認証を使用できます。この場合、認証にはアプリキーとシークレットのみを使用します。

OAuth を使用すると、ユーザーに関連付けられたトークンを使って、アプリが「別のユーザーに代わって」API リクエストを行うこともできます。あなたがユーザートークンを保持しているユーザーによって公開された、いわゆる「所有している」投稿のエンゲージメント指標を生成する場合は、ユーザーコンテキストでリクエストを行います。これは、アプリキーとユーザー固有のアクセストークンの両方で認証することを意味します。これらのユーザーアクセストークンは通常、&#39;[Sign-in with X](/ja/resources/fundamentals/authentication#log-in-with-x)&#39; プロセスを通じて、またはユーザーから直接取得されます（ユーザーからトークンを直接取得する場合は、[twurl](https://github.com/xdevplatform/xurl) を使用する必要があることに注意してください）。ユーザーがトークンを提供すると、それらは有効期限が切れることはなく、ユーザーが自分のトークンをリセットするかパスワードを変更しない限り、そのユーザーに代わってリクエストを行うために Engagement API で使用できます。これらの変更が行われた場合、ユーザーは新しいトークンを提供する必要があります。

どのメトリクスにどの認証が必要かは、[この表](/ja/x-api/enterprise-gnip-2.0/fundamentals/engagement-api#engagement-api-groupings)で確認できます。

<div id="selecting-an-engagement-api-endpoint">
  ### エンゲージメント API エンドポイントの選択
</div>

エンゲージメント API には、次の 3 つの異なるエンドポイントがあります。

* **[Totals](/ja/x-api/enterprise-gnip-2.0/fundamentals/engagement-api#post-insights-engagement)** - 所有している（「owned」）投稿および所有していない（「unowned」）投稿から、選択したメトリクスの全体合計値を提供します。一部のメトリクスはすべての投稿で利用できますが、その他のメトリクスは過去 90 日以内に公開された投稿でのみ利用できます。1 回のリクエストで最大 250 件の投稿を処理できます。
* **[28 hour](/ja/x-api/enterprise-gnip-2.0/fundamentals/engagement-api#post-insights-engagement)** - 過去 28 時間に投稿された「owned」投稿のエンゲージメントメトリクスを時系列データとして提供します。1 回のリクエストで最大 25 件の投稿を処理できます。
* **[Historical](/ja/x-api/enterprise-gnip-2.0/fundamentals/engagement-api#post-insights-engagement-historical)** - 2014 年 9 月 1 日以降に投稿された「owned」投稿について、最大 4 週分の連続した期間のエンゲージメントメトリクスを時系列データとして提供します。1 回のリクエストで最大 25 件の投稿を処理できます。
   

各エンドポイントには固有の特徴があります。3 つすべてを利用する場合でも、どれがユースケースに最も適しているかを検討している場合でも、それぞれの違いを理解しておくことが重要です。

以下では、いくつかの重要な概念を紹介し、3 つのエンドポイントをさらに詳しく説明したうえで、一般的に特定のエンドポイントに対応づけられるサンプルユースケースを提示します。これらの情報が、3 つすべてをより効率的に統合する際、または目的に最も適した単一のエンドポイントを選択する際の一助となることを想定しています。
 

<div id="key-concepts">
  #### 重要な概念
</div>

Engagement API の 3 つのエンドポイントが提供する機能や data を理解するうえで役立つ、重要な概念がいくつかあります。
 

<div id="impressions-and-engagement-metrics">
  ##### インプレッションとエンゲージメント指標
</div>

インプレッションは、特定の投稿が X プラットフォーム上でオーガニックなコンテキストで表示された回数を表します。プロモーションまたは有料コンテキストで表示された投稿によって生じたインプレッションは含まれません。Engagement API 以前は、投稿のインプレッションは潜在的な閲覧回数のみを示す指標でした。これは、投稿の作成者アカウントのフォロワー数と、そのコンテンツをリツイートしたアカウントのフォロワー数を集計することに基づいていました。実際にはユーザーがその投稿を見ていないという一般的な状況は考慮されていませんでした。

Engagement API によって生成されるインプレッション指標は、投稿が画面表示のために実際にレンダリングされた回数を測定したものです。自分のアカウントのフォロワーが投稿を見逃した場合、そのフォロワーについてはインプレッションとしてカウントされません。

Engagement API は、投稿が表示された際にユーザーが取りうる、それぞれ異なるアクションを表す 14 種類の独立したエンゲージメント[指標タイプ](/ja/x-api/enterprise-gnip-2.0/fundamentals/engagement-api#available-metrics)を提供します。これには、リツイート、いいね、返信、#ハッシュタグ、リンクやメディアといったエンティティのクリック、投稿者のフォロー、投稿者プロフィールの閲覧などが含まれます。これらすべての個別アクションは、1 つの「Engagements」指標に集約されます。

<div id="owned-and-unowned-x-content">
  ##### 所有投稿と非所有投稿の X コンテンツ
</div>

Engagement API では、所有投稿と非所有投稿を明確に区別します。所有投稿とは、自分のアカウントから投稿された投稿、またはエンゲージメントデータをリクエストする権限を取得した投稿を指します。他の X API と同様に、他の X ユーザー／アカウントから、代理で API リクエストを実行できるようにするアクセス・トークンを共有してもらうことで権限を取得します。これらのトークンを取得する一般的な方法は、[「Sign in with X」プロセス](/ja/resources/fundamentals/authentication#log-in-with-x)を利用することです。

`/totals` エンドポイントは、所有投稿と非所有投稿の両方についてエンゲージメントデータを提供します。非所有投稿については、投稿の表示画面で公開されているエンゲージメント指標（いいね、リツイート、返信）をリクエストできます。これらの指標について Engagement API が提供する価値は、こうした指標を大規模に自動取得できる点にあります。所有投稿については、`/totals` エンドポイントはインプレッション指標および（合計）エンゲージメント指標も提供します。

`/28hr` および `/historical` エンドポイントは所有投稿のみの指標を提供します。つまり、これらのエンドポイントに対してリクエストを送信する際には、ユーザーコンテキストを渡す必要があります。

<div id="total-and-time-series-engagement-data">
  ##### 合計および時系列エンゲージメントデータ
</div>

`/totals` エンドポイントは、その名前が示すとおり、エンゲージメントタイプごとの合計値のみを提供します。ここでの数値は、その投稿が作成されてから現在までの最新の累計値を表します。投稿が作成された直後に、その指標を繰り返しリクエストすると、これらの合計値は通常、リクエストのたびに変化します。

`/28hr` および `/historical` エンドポイントは、合計値と時系列データの両方を提供できます。時系列データをリクエストする場合、エンゲージメント指標は日次または時間単位のデータとして集計できます。   

`/28hr` および `/historical` エンドポイントで時系列データをリクエストする方法については、[エンゲージメントのグルーピング](/ja/x-api/enterprise-gnip-2.0/fundamentals/engagement-api#engagement-api-groupings)に関するドキュメントを参照してください。

<div id="endpoints-and-example-use-cases">
  #### エンドポイントとユースケースの例
</div>

上で説明した特性や違いを踏まえると、各エンドポイントは一般的に異なるユースケースに対応します。特定のユースケースに最適なエンドポイントを判断しやすくするために、以下にユーザーから想定される要望の例と、それを最も適切に満たすエンドポイントを示します。

<div id="totals">
  ##### **/totals**
</div>

* 一部の指標タイプ（Impressions、Engagements、Favorites、Retweets、Quote Tweets、Replies、Video Views）にだけアクセスできれば十分だ。
* 自分の投稿だけでなく、任意の投稿の基本的なエンゲージメントデータにアクセスしたい。
* 競合他社とのパフォーマンスを比較したい。
* 自分の投稿以外も含むハッシュタグやキャンペーンの基本的なエンゲージメント指標を追跡したい。
* 日別や時間別に分割されたデータは不要で、リクエストした時点の合計値だけ分かればよい。
* レポートやダッシュボードで表示するための 1 つの指標が必要で、自分でデータを保存したくない。
* ページ読み込み時にデータを表示したいので、リクエストを送信してレスポンスを受け取るだけでよい。
* 1 日あたり数十万件から数百万件の投稿のデータにアクセスする必要がある。
   

<div id="28hr">
  ##### **/28hr**
</div>

* 17種類すべてのメトリクスタイプへアクセスする必要がある。
* 直近28時間以内のごく最近の投稿データを表示したい。
* 1日1回実行されるジョブで必要なデータを取得しており、直近1日分のデータだけ取得できればよい。
* メトリクスを日単位または時間単位に分解して取得する必要がある。
* ダッシュボードで時間単位のアクティビティの時系列推移を表示したい。
* 1日に数十万件規模の投稿に対して高いアクセスレベルが必要である。
* ストレージ容量があり、1日1回データをリフレッシュしつつ、累積値を保持できる。
   

<div id="historical">
  ##### **/historical**
</div>

* 17種類すべてのメトリクスタイプへのアクセスが必要です。
* 2014年9月までさかのぼって作成された投稿の過去データを取得する必要があります。
* キャンペーン同士を比較する詳細な過去分析を表示したいです。
* メトリクスを日単位または時間単位で細かく分けて取得する必要があります。
* Engagement API への高いアクセスレベルは必要なく、1日に数百から数千件程度の投稿のデータを取得できれば十分です。

<div id="engagement-api-key-characteristics">
  ### Engagement API の主な特性
</div>

* **RESTful API** で JSON データを返し、JSON データボディを持つ POST リクエストをサポートします。
* **リクエストの種類:** クライアントアプリは次の種類のリクエストを行うことができます:
  * **合計エンゲージメント** -- /totals エンドポイントへの HTTP POST リクエスト
  * **直近 28 時間のエンゲージメント** -- /28hr エンドポイントへの HTTP POST リクエスト
  * **履歴エンゲージメント** -- /historical エンドポイントへの HTTP POST リクエスト
* **OAuth 認証:**
  * [OAuth 1.0 User Context](/ja/resources/fundamentals/authentication): [3-legged OAuth](https://developer.x.com/resources/fundamentals/authentication/obtaining-user-access-tokens) を使ってあなたのアプリを認可したユーザーが所有する投稿について、利用可能なすべてのメトリクスを利用できます。リクエストを行う際には、そのユーザーの Access Token を使用する必要があります。[](/ja/resources/fundamentals/authentication)
  * [OAuth 2.0 Bearer Token](/ja/resources/fundamentals/authentication#oauth-2-0): 特定のメトリクス（リツイート、引用ツイート、返信、いいね、動画再生数）は、任意の公開投稿に対して利用できます。 
* **リクエストのメタデータと構造**: リクエストデータは、Post ID の配列、エンゲージメントタイプの配列、およびエンゲージメントのグルーピング構造から成る JSON オブジェクトです。
* **リクエストあたりの投稿数:**
  * /totals エンドポイント: 最大 250 件の Post ID
  * /28hr エンドポイント: 最大 25 件の Post ID
  * /historical エンドポイント: 最大 25 件の Post ID
* **エンゲージメントメトリクスの利用可能範囲:**
  * **/totals** -- 投稿が公開されてからのメトリクス合計。インプレッションとエンゲージメントは、過去 90 日以内に公開された投稿について利用でき、リツイート、引用ツイート、返信、いいね、動画再生数はすべての投稿について利用できます。
  * **/28hr** -- リクエスト時点からさかのぼった直近 28 時間。
  * **/historical** -- 2014 年 9 月 1 日に開始する任意の 28 日間。
* **メトリクスタイプ**: 各リクエストには [Metric Types](http://support.gnip.com/apis/engagement_api/overview.html#EngagementTypes) の配列が含まれます。これらの利用可否はエンドポイントに依存し、/totals エンドポイントからリクエストする場合は、投稿がユーザーから許可されているかどうかにも依存します。
  * /totals エンドポイント:
    * すべての投稿: いいね、リツイート、引用ツイート、返信、動画再生数
    * OAuth 1.0a User Context が必要: インプレッション、エンゲージメント、いいね、返信、リツイート
  * /28hr および /historical エンドポイント（Post 所有者の Access Token を用いた OAuth 1.0a User Context が必要）: インプレッション、エンゲージメント、いいね、返信、リツイート、URL クリック、ハッシュタグクリック、詳細クリック、パーマリンククリック、メディアクリック、アプリインストール試行、アプリ起動、投稿メール、動画再生数、メディア再生数
* **エンゲージメントグルーピング:** 各リクエストには [Engagement Groupings](/ja/x-api/enterprise-gnip-2.0/fundamentals/engagement-api#engagement-api-groupings) の配列が含まれます。これらのグルーピングを使用して、返されるメトリクスの整理方法をカスタマイズできます。1 つのリクエストには最大 3 つまでのグルーピングを含めることができます。メトリクスは次の値で整理できます:
  * すべてのエンドポイント: Post ID、エンゲージメントタイプ
  * /28hr および /historical エンドポイント: これらのエンドポイントでは、次の追加グルーピングを指定した場合に時系列データを提供します: エンゲージメント日、エンゲージメント時
* **インテグレーションに関する前提:** お客様のチームには次の責任があります。
  * Engagement API に HTTP リクエストを送信し、リクエストに含まれる Post ID のエンゲージメントメトリクスを返せるクライアントアプリを作成・維持すること。
* **制限事項**
* 動画再生数は、投稿から 1800 日経過していない投稿についてのみ利用できます。

<div id="authenticating-with-the-engagement-api">
  ### Engagement API での認証
</div>

> **ご留意ください**: 
>
> Engagement API を利用開始する前に、X があなたの開発者用 App に対して Engagement API へのアクセスを有効化する必要があります。そのため、認証に使用する予定の App ID をアカウントマネージャーまたはテクニカルサポートチームに必ず共有してください。

Engagement API では 2 つの認証方法が利用できます: [OAuth 1.0a](/ja/resources/fundamentals/authentication#oauth-1-0a-2) と [OAuth 2.0 Bearer Token](/ja/resources/fundamentals/authentication#bearer-token-also-known-as-app-only) です。 

**OAuth 2.0 Bearer Token**（「application-only」とも呼ばれます）は、公開されているエンゲージメント指標にアクセスできるようにします。この認証方法は、[/totals endpoint](/ja/x-api/enterprise-gnip-2.0/fundamentals/engagement-api#post-insights-engagement-totals) へのリクエスト時に、公開されている任意の投稿に対する Favorites（別名 Likes）、Retweets、Quote Tweets、Replies、および動画再生数の合計カウントを取得するために使用できます。 

**OAuth 1.0a**（「user context」とも呼ばれます）は、ユーザーの代理としてリクエストを行い、そのユーザーが保有する非公開のエンゲージメント指標へアクセスすることを可能にします。 

この認証方法は、次の場合に必須です:

* [/28hr endpoint](/ja/x-api/enterprise-gnip-2.0/fundamentals/engagement-api#post-insights-engagement-28hr) と [/historical endpoint](/ja/x-api/enterprise-gnip-2.0/fundamentals/engagement-api#post-insights-engagement-historical) に送信されるすべてのリクエスト
* 次のいずれかの非公開指標へアクセスする場合: Impressions、Engagements、Media Views、Media Engagements、URL Clicks、Hashtag Clicks、Detail Expands、Permalink Clicks、App Install Attempts、App Opens、Email Post、User Follows、および User Profile Clicks

OAuth 1.0a を使用してリクエストを送信する際には、対象の投稿または保護されたリソースを所有するユーザーの Access Tokens（Access Token と Secret）を含める必要があります。保護されたユーザーデータをリクエストする際に正しいユーザーの Access Tokens を指定しなかった場合、Engagement API は `403 Forbidden` エラーを返します。

Engagement API は、たとえそれらの投稿の所有ユーザーの代理として認証している場合であっても、[protected Posts](https://help.x.com/en/safety-and-security/public-and-protected-tweets) のエンゲージメントデータを取得することはできません。このようなリクエストを行うと、`400 Bad Request` エラーが返され、メッセージは `"Tweet ID(s) are unavailable"` となります。

自分自身の X アカウント（つまり、開発者用 App を所有しているアカウント）を代理してリクエストを送信する場合は、[Developer Console](https://developer.x.com/en/portal/projects-and-apps) 内の、その開発者用 App の “Keys and tokens” タブから、必須の Access Tokens を直接生成できます。

他のユーザーを代理してリクエストを行う場合は、必須の Access Tokens を取得するために 3-legged OAuth フローを使用する必要があります。これを行う方法の詳細については、次のドキュメントを参照してください: [OAuth 1.0a: how to obtain a user’s access tokens](/ja/resources/fundamentals/authentication#oauth-1-0a-2)。

追加のサンプル（OAuth 1.0a を使用した認証方法を含む）については、[X Developers による Engagement API 向けの Python サンプルコード](https://github.com/xdevplatform/enterprise-scripts-python/tree/master/Engagement-API)を参照してください。

<div id="interpreting-the-metrics">
  ### 指標の解釈
</div>

**Note:** 一部の X のウェブダッシュボードに表示されるデータと、Engagement API で返される data の内容に差異が見られる場合があります。これは、ウェブダッシュボードが通常、選択した期間内に発生したエンゲージメントおよび／またはインプレッションのみを表示するために生じます。たとえば、ウェブダッシュボードはカレンダー上の 1 か月の範囲内で発生した投稿へのエンゲージメントのみを表示する一方で、Engagement API では、その月の範囲を超えていても、要求した時間範囲内に含まれるエンゲージメントが表示される場合があります。このようなケースでは、Engagement API を正しいデータソースとして扱ってください。
 

<div id="impressions-and-engagement-data">
  #### インプレッションとエンゲージメントデータ
</div>

Engagement API は **オーガニック** なインプレッションとエンゲージメントデータを提供します。

インプレッションは、特定の投稿が X プラットフォーム上でオーガニックなコンテキストにおいて表示された回数を表します。プロモーションまたは有料のコンテキストで表示された投稿から発生したインプレッションは**含まれません**。

エンゲージメントは、特定の投稿に対して閲覧者が **オーガニック** および **プロモーション** の両方のコンテキストで何らかのアクションを行った回数を表します。エンゲージメントには、リツイート、いいね、返信、URL クリック、ハッシュタグクリック、メンションクリック、メディア再生などが含まれますが、これらに限定されるものではありません。含まれるエンゲージメントアクションの完全な一覧については、「Engagement Data」セクションを参照してください。 

ベースラインとなるエンゲージメント率を算出するには、分析対象期間における特定の投稿について、総エンゲージメント数を総インプレッション数で割ってください。

インプレッションおよびエンゲージメントデータは、自社が保有する @ハンドル、またはアプリケーションに対して自分の投稿の詳細閲覧を許可している @ハンドル の投稿に対してのみ取得できます。内部的には、Engagement API は、契約上の @ハンドル上限に対してリクエストされた一意の @ハンドル数を追跡します。@ハンドルのリクエスト利用状況を、月を通してクライアント側でも追跡することを推奨します。  

<div id="video-metrics">
  #### 動画メトリクス
</div>

X では、メディアのインプレッションを表すメトリクスがいくつか存在します。1 つ目は動画再生数メトリクスで、動画の 50% 以上が少なくとも 2 秒間視認可能であるという MRC（Media Rating Council）の標準に基づいています。2 つ目はメディアビュー数（Media Views）で、動画、Vine、GIF、画像を対象に、オートプレイおよびクリック再生のすべてのビューを合算したものです。

動画再生数メトリクスは、/28hour および /historical エンドポイントを通じて自社が所有する投稿に対して利用できるほか、/totals エンドポイントを通じて自社が所有していないすべての投稿に対しても利用できます。 

X のユーザーインターフェース内で表示される動画再生数メトリクスも同じ MRC 標準を使用していますが、X が自社で保有・運営するプラットフォーム（モバイルアプリとウェブサイト）に表示される動画再生数メトリクスと、各種 Engagement API エンドポイント経由で取得する数値との間に差異が生じる場合がある点に注意してください。

* /totals エンドポイントおよび X のユーザーインターフェースで提供される動画再生数は、対象の動画が投稿されているすべての投稿を合算した再生数として表示されます。つまり、/totals 経由で配信され、X の UI に表示されるメトリクスには、その動画がリポストや別の投稿として再投稿されたあらゆるインスタンスからの再生数が合算されています。
* /28hour および /historical Engagement API エンドポイントで提供される動画再生数は、メトリクスを取得している特定の投稿によって発生した再生数のみを含みます。 
   

投稿が 1800 日より前のものである場合、その投稿についての動画再生数は提供されない点に注意してください。その代わり、1800 日より前の投稿を一覧にしたオブジェクトを返します。リクエストした投稿については、その他のメトリクスはすべて別のオブジェクトで引き続き取得できます。以下はレスポンスの例です。

```json

    "479311209565413376",
    "477139122520219648"
  ],
  "grouping name": {
    "479311209565413376": {
      "favorites": "69",
      "impressions": "1692",
      "retweets": "142",
      "video_views": "0"
    },
    "477139122520219648": {
      "favorites": "10",
      "impressions": "1023",
      "retweets": "6",
      "video_views": "0"
    },
    "1397568983931392004": {
      "favorites": "268",

    }
  }

```

Media Views メトリックは、/28hour および /historical エンドポイントを使用した、所有している投稿に対してのみ利用できます。

<div id="engagement-api-groupings">
  ### Engagement API のグルーピング
</div>

グルーピングを利用すると、返されるエンゲージメント指標を任意の方法で整理できます。1 回のリクエストにつき、最大 3 つのグルーピングを含めることができます。指標は次の値の 1 つ以上でグルーピングできます。

*3 つすべてのエンドポイントでサポートされる値:*

* tweet.id
* engagement.type
   

*`/28hr` および `/historical` は時系列のメトリクスを返すことができるため、次の値もサポートします:*

* engagement.day
* engagement.hour

グルーピングは指定した順序で適用されるため、`group_by` 値の順序を変更することで、取得結果の形式を変えることができます。4 つの `group_by` 値を含むグルーピングは、次の 2 つのフォーマットのいずれかでのみサポートされます。

```bash
"group_by": [
    "tweet.id",
    "engagement.type",
    "engagement.day",
    "engagement.hour"
  ]
```

または

```bash
"group_by": [
    "engagement.type",
    "tweet.id",
    "engagement.day",
    "engagement.hour"
]
```

たとえば、メトリックタイプ別の総計を生成したい場合は、リクエストの一部として次の「groupings」指定を含めてください（リクエストの組み立て方法の詳細については、[APIリファレンス](/ja/x-api/enterprise-gnip-2.0/fundamentals/engagement-api#post-insights-engagement)ページを参照してください）。

```json
{
  "engagement_types": [
    "favorites",
    "replies",
    "retweets"
  ],
  "groupings": {
    "Grand Totals": {
      "group_by": [
        "engagement.type"
      ]
    }
  }
}
```

このグルーピングを使用すると、Engagement API の JSON レスポンスには、メトリクスタイプ別の総計を格納したルートレベルの `"Grand Totals"` 属性が含まれます。

```json
{
  "Grand Totals": {
    "favorites": "12",
    "replies": "2",
    "retweets": "2"
  }
}
```

単一の投稿に対して、Post IDごとにグループ化された4時間分の時系列メトリクスを生成するには、次の Grouping の指定をリクエストに含めます。

```json
{
  "start": "2016-02-10T17:00:00Z",
  "end": "2016-02-10T21:00:00Z",
  "tweet_ids": [
    "697506383516729344"
  ],
  "engagement_types": [
    "impressions",
    "engagements"
  ],
  "groupings": {
    "Tweets_MetricType_TimeSeries": {
      "group_by": [
        "tweet.id",
        "engagement.type",
        "engagement.hour"
      ]
    }
  }
}
```

このグループ化を行うと、Engagement API の JSON レスポンスには、ルートレベルの `"Tweets_MetricType_TimeSeries"` 属性が含まれ、その中に投稿 ID ごと、さらに指標タイプごとに分解された、対応する 1 時間ごとの時系列データが格納されます。

```json
{
  "Tweets_MetricType_TimeSeries": {
    "697506383516729344": {
      "impressions": {
        "2016-02-10": {
          "17": "551",
          "18": "412",
          "19": "371",
          "20": "280"
        }
      },
      "engagements": {
        "2016-02-10": {
          "17": "8",
          "18": "6",
          "19": "3",
          "20": "0"
        }
      }
    }
  }
}
```

<div id="authentication">
  #### **Authentication**
</div>

Engagement API を利用するには HTTPS を使用する必要があり、User Context（ユーザーコンテキスト）および Application-Only OAuth の両方をサポートしています。Engagement API へのほとんどのリクエストでは 3-Legged OAuth（User Context の特定バージョン）の利用が必要です。これは、Twitter のアカウントマネージャーによって Engagement API へのアクセス用に登録・承認されたアプリの consumer key と consumer secret に加え、ツイート所有者の access token と access token secret を使用してエンドポイントを呼び出すことを意味します。次のリクエストにはこのタイプの OAuth が必要です。

* 所有しているツイートに限定される Impressions と Engagements メトリクスタイプを取得するための /totals へのあらゆるリクエスト
* /28hr へのあらゆるリクエスト
* /historical へのあらゆるリクエスト

Engagement API への一部のリクエストは Application-Only OAuth を使用して実行できます。この場合、consumer key と consumer secret、または Bearer Token だけを提供すれば問題ありません。次のリクエストはこのタイプの OAuth で実行できます。

* どのツイートに対しても取得可能な Favorites、Replies、Retweets、または Video Views メトリクスタイプを取得するための /totals へのあらゆるリクエスト

いずれのリクエストでも、[developer.x.com](https://developer.x.com/en/portal/dashboard) で利用可能なアプリ管理コンソールを使用して Twitter アプリと対応する API key を設定する必要があります。

注意: developer.x.com 上で Twitter アカウントにログインしている場合、既存の [Twitter apps](/ja/resources/fundamentals/developer-apps) は [Twitter app dashboard](https://developer.x.com/en/apps) から表示および編集できます。

アプリを設定したら、その app ID は Engagement API に対してアプリがリクエストを行えるよう、アカウント担当者による承認を受ける必要があります。Access token は「現在のユーザー」を表現するために使用する必要があり、別のユーザーに代わって実行されるリクエストは有効なトークンで署名されていなければなりません。OAuth 署名ベース文字列を準備する前に、URL および POST ボディ内で[予約文字を適切にエンコードしている](https://tools.ietf.org/html/rfc3986)ことを確認してください。

OAuth の利用開始方法についての詳細は、次のリンクを参照してください。

* [OAuth の概要](/ja/resources/fundamentals/authentication)
* [User Context とも呼ばれる 3-Legged OAuth の使用](/ja/resources/fundamentals/authentication#obtaining-access-tokens-using-3-legged-oauth-flow)
* [Application-Only OAuth の使用](/ja/resources/fundamentals/authentication#bearer-token-also-known-as-app-only)

| 200 | OK  | リクエストは正常に完了しました。 |
| 400 | Bad Request | このレスポンスは通常、リクエストに無効な JSON が含まれている場合、または JSON ペイロードがまったく送信されなかった場合に返されます。 |
| 401 | Unauthorized | 無効な認証情報により HTTP 認証に失敗しました。OAuth キーとトークンを確認してください。 |
| 404 | Not Found | リクエストが送信された URL にリソースが存在しません。誤った URL を使用した可能性があります。 |
| 429 | Too Many Requests | アプリケーションが API リクエストの上限を超過しました。 |
| 500 | Internal Server Error | Gnip 側でエラーが発生しました。指数バックオフ方式を使用してリクエストを再試行してください。 |
| 502 | Proxy Error | Gnip 側でエラーが発生しました。指数バックオフ方式を使用してリクエストを再試行してください。 |
| 503 | Service Unavailable | Gnip 側でエラーが発生しました。指数バックオフ方式を使用してリクエストを再試行してください。 |

<div id="error-messages">
  #### **エラーメッセージ**
</div>

さまざまな状況において、Engagement API は状況に応じたエラーメッセージを返します。アプリケーション側では、これらを適切に処理できるようにしておく必要があります。以下の表では、一般的なエラーメッセージの例と、その解釈方法を示します。多くの場合、Engagement API は 200 OK レスポンスの一部として、特定のエラーメッセージおよび追加情報とともに、利用可能な data の一部のみを返すことがある点に注意してください。

| Error Message | 説明 |
| :--- | :--- |
| `"errors":["Your account could not be authenticated. Reason: Access token not found"]` | リクエストの認証部分に関するエラーです。&quot;Reason&quot; には、エラーのトラブルシューティングに役立つ情報が含まれているはずです。解決できない場合は、&quot;Reason&quot; を含むエラー全体をサポートチームに送信してください。 |
| `"errors":["1 Tweet ID(s) are unavailable"],"unavailable_tweet_ids": ["TWEET_IDS"]` | リクエストした Tweet の ID が 1 つ以上、すでに利用できなくなっています。これは通常、それらのツイートが削除されたか、その他の理由により公開されていないことを示します。 |
| `"errors":["Impressions & engagements for tweets older than 90 days (*TIME_PERIOD*) are not supported"],"unsupported_for_impressions_engagements_tweet_ids":[*TWEET_IDS*]` | `/totals` エンドポイントに対してリクエストした Tweet ID が 90 日より古く、インプレッションやエンゲージメント指標を返す対象としてサポートされていません。 |
| `"errors":["Forbidden to access tweets: *TWEET_IDS*"]` | 第三者の代わりに data を取得するために使用している認証トークンに基づき、リクエストした Tweet ID へのアクセスが許可されていません。 |
