<div id="overview">
  ## Overview
</div>

[`Enterprise`](https://developer.x.com/en/products/x-api/enterprise)

*これはマネージドアクセスレベルでのみ利用可能なエンタープライズ API です。この API を使用するには、まずエンタープライズセールスチームとのアカウント設定が必要です。 [詳細はこちら](/ja/x-api/enterprise-gnip-2.0/enterprise-gnip)*

Engagement API は、投稿のインプレッションおよびエンゲージメント指標へのアクセスを提供します。ほとんどの指標およびエンドポイントでは [OAuth 1.0a User Context](/ja/resources/fundamentals/authentication) を使用して認証する必要がありますが、[OAuth 2.0 Bearer Token](/ja/resources/fundamentals/authentication#oauth-2-0) と /totals エンドポイントを使用することで、公開されている「お気に入り」「リポスト（Retweet）」「返信（Reply）」「動画再生数（Video Views）」の指標にアクセスできます。  

**注:** 一部の X のウェブダッシュボードに表示されるレポートデータと、Engagement API でレポートされるデータとの間に差異が見られる場合があります。これは、ウェブダッシュボードでは通常、選択された期間内に発生したエンゲージメントおよび／またはインプレッションのみを表示するためです。たとえば、ウェブダッシュボードは暦月の範囲内での投稿のエンゲージメントのみを表示する一方で、Engagement API は、その月の範囲外であっても、リクエストされた期間内に含まれるエンゲージメントを表示する場合があります。このような場合には、Engagement API を有効かつ正確な情報源として扱ってください。
 

<div id="request-endpoints">
  ### リクエストエンドポイント
</div>

Engagement API にはエンドポイントが 3 つあります。

<div id="current-totals-totals">
  #### 現在の合計: [/totals]
</div>

* リクエストでは、指定した投稿に対するインプレッションの合計値とエンゲージメントの合計値が返されます
* 利用できるメトリックは次のものに限定されます: Impressions、Engagements、Favorites、Replies、Retweets、Quote Tweets、Video Views
* OAuth 1.0a ユーザーコンテキストを使用して、**過去90日以内** に作成された投稿の **Impressions** および **Engagements** メトリックを取得できます
* OAuth 2.0 Bearer Token を使用して、**任意の投稿** の **Favorites、Retweets、Quote Tweets、Replies、Video Views** メトリックを取得できます
* 結果は、リクエスト送信時点でのインプレッションとエンゲージメントの現在の合計値に基づきます
* ダッシュボードレポートの作成や、さまざまな @ハンドル全体でのエンゲージメント率の算出に最適です
* 1 回のリクエストで最大 250 件の投稿のメトリック取得をサポートします
   

<div id="last-28-hours-28hr">
  #### 直近28時間: [/28hr]
</div>

* リクエストでは、インプレッションの合計指標、エンゲージメントの合計指標、そして直近28時間に発生した個別のエンゲージメント指標の内訳を返すことができます
* dataは投稿 IDごと、または時系列の集計（全体、日単位、時間単位）としてグループ化できます
* 最近作成されたコンテンツのパフォーマンスを追跡するのに最適です
* 利用可能なすべての指標をサポートします
* 1リクエストあたり最大25件の投稿の指標を取得できます
   

<div id="historical-historical">
  #### 履歴: [/historical]
</div>

* リクエストでは、直近1年間分について、インプレッション、エンゲージメント、および個々のエンゲージメント指標の内訳を、投稿の作成時刻ではなくエンゲージメント発生時刻に基づいて返すことができます。
* リクエストは開始日と終了日のパラメータをサポートしており、最大4週間の期間内で特定の時間枠に絞り込む柔軟性があります。
* 投稿エンゲージメントのデータは、過去365日分に制限されています。
* データは投稿IDごと、または集計された時系列（日単位または時間単位）でグループ化できます。
* 直近のパフォーマンスを過去のベンチマークと比較・評価したり、@handle のパフォーマンスの過去推移を把握する用途に最適です。
* 利用可能なすべてのメトリクスをサポートします。
* 1回のリクエストで最大25件の投稿に対する指標の取得をサポートします。

<div id="engagement-groupings">
  ### エンゲージメントのグルーピング
</div>

グルーピングを使用すると、返されるエンゲージメント指標を任意の方法で整理できます。1 回のリクエストにつき、最大 3 つのグルーピングを含めることができます。指標は、次の値の 1 つ以上でグループ化できます。

*すべての 3 つのエンドポイントでサポートされる項目:*

* tweet.id
* engagement.type
   

`/28hr` と `/historical` は時系列の指標を提供するため、次の項目をサポートします:

* engagement.day
* engagement.hour

グルーピングの詳細については、「Guides」セクション内の [Engagement API Grouping](/ja/x-api/enterprise-gnip-2.0/fundamentals/engagement-api#engagement-api-groupings) ページを参照してください。

<div id="introduction">
  #### Introduction
</div>

このドキュメントの目的は、開発者向けに Engagement API との統合に関する入門的な情報を提供することです。まず、なぜ統合するのかという点から説明を始め、その後で技術的な観点からどのように統合するのかを詳しく見ていきます。

<div id="what-does-the-engagement-api-provide">
  ##### **Engagement API は何を提供しますか？**
</div>

* Engagement API は、任意の X アカウントが所有する投稿について、過去 90 日分のインプレッション数およびエンゲージメントのデータを提供します。ただし、そのアカウントが [3-legged OAuth](/ja/resources/fundamentals/authentication#obtaining-access-tokens-using-3-legged-oauth-flow) を使用して、あなたのアプリが代理でメトリクスをリクエストすることを承認している必要があります。この強力でありながら実装が容易なソリューションにより、インプレッション数や URL クリック、#ハッシュタグクリックなどの詳細なエンゲージメントにすぐにアクセスできます。
* Engagement API は、任意の投稿に対して、いいね、リツイート、引用ツイート、返信、動画再生数といったメトリクスの合計集計値を提供します。これは、任意の投稿または投稿の集合について、基本的なエンゲージメントデータを取得する強力な手段として利用できます。
* Engagement API は、15 以上のパフォーマンス指標を用いてコンテンツのパフォーマンスを効果的に測定し、X 上での ROI を測定できるようにすることで、ソーシャルリスニング、マーケティング、パブリッシングプラットフォームに新たな価値を提供します。
* Engagement API はリクエスト/レスポンス型の API であり、アプリ開発者は投稿 ID、必要なメトリクス、および期間を指定してリクエストを送信でき、API はそれに対するデータを即座に返します。
   

<div id="why-integrate-example-use-cases">
  ##### **なぜ統合するのか？ユースケース例**
</div>

* 自分のコンテンツの総リーチを把握し、どれだけ多くの人に閲覧されているかを確認します。動画の再生数、リンクのクリック数、ハッシュタグのクリック数、アプリのインストール数などを確認します。
* 合計値と時系列の両方のエンゲージメント指標を生成します。
* 任意の公開投稿について、基本的なエンゲージメント指標（いいね、リツイート、引用ツイート、返信）を把握します。
* これらの指標を使って、どのような投稿が効果的なのかを判断し、それらをより頻繁に投稿することで、コンテンツのインプレッション数とエンゲージメント数を増やします。
* 自分の投稿の「いいね」が100件、または別のしきい値に達するたびに、別の自社アカウントからコンテンツをリツイートするといったマーケティング行動を自動化します。
* A/B テストのツールとして、キャンペーン同士をベンチマークし、相互に比較します。
* カスタマーサービス部門において、どのようなコンテンツが利用者の共感を得ているのかを分析し、どのように・いつ対応するかを判断します。
* 自社プラットフォームから配信されたコンテンツのアナリティクスを表示します。
   

[Engagement API は 2016 年にローンチされ](https://blog.x.com/official/en_us/a/2016/gnip-s-engagement-api-is-now-generally-available.html)、大規模に詳細なエンゲージメント指標を提供した最初の X API です。Engagement API は使いやすく、プロセスの自動化を可能にします。以下は、その統合例を説明したケーススタディです。

* [Red Cross を活用したキャンペーン成功の測定](https://blog.x.com/developer/en_us/topics/spotlight/2016/measuring-campaign-success-with-the-red-cross.html)[](https://simplymeasured.com/blog/true-twitter-impressions-and-url-clicks-new-from-simply-measured/#sm.0007werel134td8zqf02m2mduumr6)

Engagement API を導入する「理由」を見てきたところで、次は技術的な詳細を掘り下げていきます。

<div id="integrating-the-engagement-api">
  #### Engagement API の統合
</div>

<div id="introduction-to-api">
  ##### **API の概要**
</div>

Engagement API は、JSON でエンコードされたリクエストを受け取り、JSON でエンコードされたエンゲージメント指標を返すシンプルな RESTful API です。リクエストは主に次の 3 つの要素で構成されます（詳細はリンク先のドキュメントを参照してください）。

* ***投稿ID*** の配列。
* 関心のある[メトリクスタイプ](https://developer.x.com/en/docs/x-api/v1/metrics/get-tweet-engagement/overview#EngagementTypes)を指定する配列。タイプには「impressions」「retweets」「hashtag&#95;clicks」「user&#95;follows」などが含まれます。
* [Engagement groupings](/ja/x-api/enterprise-gnip-2.0/fundamentals/engagement-api#engagement-api-groupings)。これは、API レスポンス内でエンゲージメント data をどのように配置するかを指定する JSON 構造です。

多くの場合、Engagement Types と Groupings はリクエストごとに比較的一定であり、更新されるのは投稿IDのみです。

Engagement API は[3 つのエンドポイント](https://developer.x.com/en/docs/x-api/v1/metrics/get-tweet-engagement/overview#RequestEndpoints)を提供します。

* **Totals** - 投稿に対するエンゲージメントの合計値を提供します。一部の指標はすべての投稿で利用できますが、その他の指標は過去 90 日分のみ利用できます。
* **28 hour** - 直近 28 時間の時系列エンゲージメント指標を提供します。
* **Historical** - 2014 年 9 月 1 日以降に投稿された投稿について、最大 4 週間連続分の時系列エンゲージメント指標を提供します。

**/totals** エンドポイントでは、1 回のリクエストで最大 **250 件の投稿** の指標をリクエストできます。**/28hour** および **/historical** エンドポイントでは、**1 リクエストあたり投稿 25 件** をサポートします。

Engagement API へのアクセス方法を説明した後、API リクエストの実行手順、OAuth の概要、その他の技術リソースへのリンクを順に説明します。

<div id="getting-api-access">
  ##### **API アクセスの取得**
</div>

このドキュメントを読んでいる場合は、すでに Engagement API へのアクセスを取得している可能性が高いです。まだの場合は、Enterprise のアカウントマネージャーに連絡するか、[こちら](/ja/x-api/enterprise-gnip-2.0/enterprise-gnip) から Enterprise アクセスを申請してください。

最初のステップは、承認済みの開発者アカウントを使用し、[開発者コンソール](/ja/resources/fundamentals/developer-portal) 経由で [X app](/ja/resources/fundamentals/developer-apps) を作成することです。アクセス権を付与してもらうために、このアプリケーションに関連付けられている数値の App ID をアカウントマネージャーに共有する必要があります。開発者アカウントを申請する必要がある場合は、[こちら](/ja/resources/fundamentals/developer-apps) から申請できます。

最初のステップは、JSON 形式の API リクエストを作成することです。これは、2 つの投稿 ID を要素とする配列、関心のあるエンゲージメントタイプの配列、そしてレスポンス内で指標をどのように配置したいかを指定する、任意の名前を付けられる「groupings」JSON オブジェクトで構成されます。リクエストは次のようになります。

```json
{
  "tweet_ids": [
    1260294888811347969, 850006245121695744
  ],
  "engagement_types": [
    "retweets", "quote_tweets", "favorites", "replies"
  ],
  "groupings": {
    "engagement-types-by-id": {
      "group_by": [
        "Tweet.id", "engagement.type"
      ]
    }
  }
}
```

これらの合計メトリクスを取得するために、`https://data-api.x.com/insights/engagement/totals` エンドポイントに対して、この JSON リクエストを POST します。

リクエストが JSON でエンコードされており、かつ Gzip 圧縮されていること（リクエストボディが大きくなる可能性があるため）を示すために、次のヘッダーを含めます。

* Content-Type: application/json
* Accept-Encoding: gzip
   

リクエストを送信する際は OAuth で認証します。これについては次のセクションで詳しく説明します。

API は次のペイロードを返します。

```json
{
  "grouping name": {
    "1260294888811347969": {
      "favorites": "17111",
      "quote_tweets": "3254",
      "replies": "1828",
      "retweets": "5218"
    },
    "850006245121695744": {
      "favorites": "492",
      "quote_tweets": "66",
      "replies": "42",
      "retweets": "324"
    }
  }
}
```

レスポンスには、「groupings」の定義で説明されている構造に従って、要求したメトリクスが含まれている点に注意してください。最初の階層では投稿IDごとにメトリクスが列挙され、その次の階層でエンゲージメントタイプごとに列挙されています。

ここまではかなりシンプルです。OAuth での認証が初めての場合は、次のセクションを参照してください。

<div id="authenticating-with-oauth">
  #### OAuth での認証
</div>

OAuth は技術業界全般で広く利用されている標準的な認証方式です。すでに OAuth（他の X API など）を使用している場合は、おそらく言語ごとの OAuth パッケージを使って、複雑な詳細を抽象化しているでしょう。OAuth を初めて利用する場合は、[Oauth with the X API](/ja/resources/fundamentals/authentication) ページをご覧いただくか、直接 [https://oauth.net](https://oauth.net/) にアクセスして詳しい情報を確認してください。そのうえで、まずは統合に使いたいプログラミング言語向けの OAuth パッケージを探して利用することをおすすめします。これらのパッケージを使う場合、認証までの一般的な流れは、キーとトークンを設定し、何らかの HTTP オブジェクトを作成し、そのオブジェクトを使ってリクエストを送信する、というものです。

たとえば Ruby の世界では、次の疑似コードは、Ruby の gem「oauth」を使って OAuth 対応アプリを構築し、POST リクエストを送信する手順のレシピを表しています。

```js
require 'oauth'

#Assemble JSON request (as above).
request = make_json_request()

#Build an app consumer object with my app consumer key and secret.
consumer = OAuth::Consumer.new(keys['consumer_key'], keys['consumer_secret'], {:site => ‘https://data-api.x.com’})
#権限を提供するアカウントから提供されたトークンを使用してユーザートークンを構築する。アプリのみの#リクエストを行う場合（/totalsエンドポイントで権限を必要としないツイートを確認する場合）、この手順は#スキップできる。
token = {:oauth_token => keys['access_token'], :oauth_token_secret => keys['access_token_secret']}

#Create oauth-enabled app object.
app = OAuth::AccessToken.from_hash(consumer, token)
#Make POST request.
result = app.post(“/insights/engagement/totals", request, {"content-type" => "application/json", "Accept-Encoding" => "gzip"})
```

Engagement API は、アプリケーション専用認証とユーザーコンテキスト認証の両方をサポートしています。/totals エンドポイントで自身が所有していない公開投稿のエンゲージメントメトリクスを収集する場合、ユーザーの許可は不要であり、アプリケーション専用認証を使用できます。この場合は、認証にアプリのキーとシークレットのみを使用します。

OAuth では、ユーザーに関連付けられたトークンを使って、アプリが「別のユーザーに代わって」API リクエストを行うこともできます。所有している投稿、つまりユーザートークンを保持しているユーザーが公開した投稿のエンゲージメントメトリクスを生成する場合は、ユーザーコンテキストでリクエストを行うことになります。これは、アプリキーとユーザー固有のアクセストークンの両方で認証を行うことを意味します。これらのユーザーアクセストークンは通常、「&#39;[Sign-in with X](/ja/resources/fundamentals/authentication#log-in-with-x)&#39;」プロセスで提供されるか、ユーザーから直接取得されます（ユーザーからトークンを直接取得する場合は、必ず [twurl](https://github.com/xdevplatform/xurl) を使用する必要があることに注意してください）。一度ユーザーがトークンを提供すると、そのトークンは有効期限切れにならず、ユーザーがトークンをリセットするかパスワードを変更しない限り、そのユーザーに代わってリクエストを行うために Engagement API で使用できます。その場合は、新しいトークンを提供してもらう必要があります。

どのメトリクスにどの認証が必要かは、[この表](/ja/x-api/enterprise-gnip-2.0/fundamentals/engagement-api#engagement-api-groupings)で確認できます。

<div id="selecting-an-engagement-api-endpoint">
  ### エンゲージメント API エンドポイントの選択
</div>

Engagement API には、次の 3 つの異なるエンドポイントがあります。

* **[合計](/ja/x-api/enterprise-gnip-2.0/fundamentals/engagement-api#post-insights-engagement)** - 自社が所有する「owned」または所有していない「unowned」投稿から、選択された指標の合計値を提供します。一部の指標はすべての投稿で利用できますが、その他の指標は過去 90 日以内に公開された投稿に対してのみ利用できます。1 リクエストあたり最大 250 件の投稿を指定できます。
* **[28 時間](/ja/x-api/enterprise-gnip-2.0/fundamentals/engagement-api#post-insights-engagement)** - 過去 28 時間における「owned」投稿の時系列エンゲージメント指標を提供します。1 リクエストあたり最大 25 件の投稿を指定できます。
* **[履歴](/ja/x-api/enterprise-gnip-2.0/fundamentals/engagement-api#post-insights-engagement-historical)** - 2014 年 9 月 1 日以降に投稿された「owned」投稿について、最大 4 週間連続の時系列エンゲージメント指標を提供します。1 リクエストあたり最大 25 件の投稿を指定できます。
   

各エンドポイントにはそれぞれ固有の特性があります。3 つすべてを利用する場合でも、どれがユースケースに最も適しているかを検討している場合でも、それぞれの違いを理解しておくことが重要です。

以下では、いくつかの重要な概念を紹介し、3 つのエンドポイントをさらに詳しく説明したうえで、一般的に特定のエンドポイントに対応するサンプルユースケースを提示します。これらの情報が、3 つすべてをより効率的に統合する際、あるいは単一のエンドポイントから目的に最も適したものを選択する際の一助となることを期待しています。
 

<div id="key-concepts">
  #### 重要な概念
</div>

3 つの Engagement API エンドポイントが提供する機能やデータの違いを理解するうえで役立つ、いくつかの重要な概念があります。
 

<div id="impressions-and-engagement-metrics">
  ##### インプレッションとエンゲージメント指標
</div>

インプレッションは、特定の投稿が X プラットフォーム上でオーガニックなコンテキストにおいて閲覧された回数を表します。Promoted または Paid コンテキストで表示された投稿から生成されるインプレッションは含まれません。Engagement API 以前は、投稿インプレッションは潜在的な閲覧数の指標にすぎませんでした。これは、投稿の作者アカウントのフォロワー数と、そのコンテンツをリツイートしたアカウントのフォロワー数を合計することで算出されており、特定のユーザーが実際にはその投稿を見ていないという一般的な状況は考慮されていませんでした。

Engagement API によって生成されるインプレッション指標は、投稿が実際に画面表示用にレンダリングされた回数を示す実測値です。あなたのアカウントのフォロワーがあなたの投稿を見逃した場合、その表示はインプレッションとしてカウントされません。

Engagement API は、14 種類の固有のエンゲージメント [メトリックタイプ](/ja/x-api/enterprise-gnip-2.0/fundamentals/engagement-api#available-metrics)について指標を提供します。これらは、それぞれユーザーが投稿を目にしたときに取りうる特定のアクションを表します。これには、リツイート、いいね、返信、#hashtags、リンク、メディアなどのエンティティのクリック、作者のフォロー、作者のプロフィールの閲覧が含まれます。これらすべての個別アクションは、単一の「エンゲージメント」指標に集約されます。

<div id="owned-and-unowned-x-content">
  ##### 自分の X コンテンツと他者の X コンテンツ
</div>

Engagement では、自分が所有する投稿と所有していない投稿を明確に区別します。所有している投稿とは、自分のアカウントから投稿された投稿、または Engagement データをリクエストする許可を取得した投稿を指します。他の X API と同様に、この許可は、他の X ユーザー／アカウントから、あなたがそのユーザーに代わって API リクエストを実行できるようにするアクセス・トークンを共有してもらうことで取得します。これらのトークンを取得する一般的な方法として、[「Sign in with X」プロセス](/ja/resources/fundamentals/authentication#log-in-with-x) があります。

`/totals` エンドポイントは、自分が所有する投稿と所有していない投稿の両方についてエンゲージメントデータを提供します。所有していない投稿については、投稿の表示画面で一般公開されているエンゲージメント指標（「Favorite」「Retweet」「Reply」）をリクエストできます。これらの指標について Engagement API が提供する価値は、これらの指標を大規模に自動取得できる点にあります。自分が所有する投稿に対しては、`/totals` エンドポイントは Impression と（合計）Engagement の指標も提供します。

`/28hr` および `/historical` エンドポイントは、自分が所有する投稿のみを対象とした指標を提供します。つまり、これらのエンドポイントへのリクエストを行う際には、ユーザーコンテキストを渡す必要があります。

<div id="total-and-time-series-engagement-data">
  ##### 合計および時系列エンゲージメントデータ
</div>

`/totals` エンドポイントは、その名前が示すとおり、エンゲージメントタイプごとの総計のみを提供します。ここで返される数値は、その投稿が作成されてから現在までの最新の累計を表します。投稿が作成された直後に、そのメトリクスを繰り返しリクエストすると、通常はリクエストのたびにこれらの累計値が変化します。

`/28hr` および `/historical` エンドポイントは、総計と時系列データの両方を提供できます。時系列データをリクエストする場合、エンゲージメントメトリクスは日次または時間単位のデータに集計できます。   

`/28hr` および `/historical` エンドポイントで時系列データをリクエストする方法については、[engagement groupings](/ja/x-api/enterprise-gnip-2.0/fundamentals/engagement-api#engagement-api-groupings) に関するドキュメントを参照してください。

<div id="endpoints-and-example-use-cases">
  #### エンドポイントとユースケースの例
</div>

上で説明した特性や違いを踏まえると、各エンドポイントは一般的に異なるタイプのユースケースに対応します。どのエンドポイントが特定のユースケースに最適かを判断する際の参考として、以下にいくつかのユーザーの想定発言と、それぞれに最も適したエンドポイントを示します。

<div id="totals">
  ##### **/totals**
</div>

* 一部の指標タイプ（Impressions、Engagements、Favorites、Retweets、Quote Tweets、Replies、Video Views）だけにアクセスできればよい。
* 自分が所有する投稿だけでなく、任意の投稿について、基本的なエンゲージメントに関するデータにアクセスしたい。
* 自社のパフォーマンスを競合他社と比較したい。
* 自分が所有していない投稿も含むハッシュタグやキャンペーンについて、基本的なエンゲージメント統計を追跡したい。
* 日別や時間別に分解されたデータは不要で、リクエスト時点での最新の合計値だけ分かればよい。
* レポートやダッシュボードに表示する単一の指標だけが必要で、データを保存したくない。
* ページ読み込み時にデータを表示したいので、リクエストを送ってレスポンスを受け取れればよい。
* 1 日あたり数十万〜数百万件の投稿のデータにアクセスする必要がある。
   

<div id="28hr">
  ##### **/28hr**
</div>

* 17種類すべてのメトリクスタイプにアクセスする必要がある。
* 直近28時間に投稿された投稿のデータを表示したい。
* 1日に1回実行されるジョブがあり、必要なデータは直近1日分だけ取得できればよい。
* メトリクスを日単位または時間単位に分けて取得する必要がある。
* ダッシュボードで、時間ごとのアクティビティの時系列の内訳を表示したい。
* 1日あたり数十万件規模の投稿に対する高いアクセス上限が必要である。
* ストレージ機能があり、1日1回データを更新して、累積の集計を保持できる。
   

<div id="historical">
  ##### **/historical**
</div>

* 17種類すべてのメトリクスタイプへのアクセスが必要です。
* 2014年9月までさかのぼって作成された投稿の過去データを取得する必要があります。
* キャンペーン同士を比較する詳細な過去分析を表示したいと考えています。
* メトリクスを日別または時間別に分解して取得する必要があります。
* Engagement API への高スループットなアクセスは必要なく、1日に数百〜数千件程度の投稿のデータを取得できれば十分です。

<div id="engagement-api-key-characteristics">
  ### Engagement API の主な特性
</div>

* **RESTful API** で JSON データを返し、JSON データ本文を持つ POST リクエストをサポートします。
* **リクエストの種類:** クライアントアプリは次の種類のリクエストを行うことができます。
  * **合計エンゲージメント** -- /totals エンドポイントへの HTTP POST リクエスト
  * **直近 28 時間のエンゲージメント** -- /28hr エンドポイントへの HTTP POST リクエスト
  * **過去のエンゲージメント** -- /historical エンドポイントへの HTTP POST リクエスト
* **OAuth 認証:**
  * [OAuth 1.0 User Context](/ja/resources/fundamentals/authentication): 利用可能なすべてのメトリックは、[3-legged OAuth](https://developer.x.com/resources/fundamentals/authentication/obtaining-user-access-tokens) を使用してあなたのアプリを認可したユーザーが所有する投稿に対して取得できます。リクエストを行う際には、そのユーザーのアクセストークンを使用する必要があります。[](/ja/resources/fundamentals/authentication)
  * [OAuth 2.0 Bearer Token](/ja/resources/fundamentals/authentication#oauth-2-0): 特定のメトリック（リポスト、引用ポスト、返信、お気に入り、動画再生数）は、任意の公開投稿に対して取得できます。 
* **リクエストのメタデータと構造**: リクエストデータは、投稿 ID の配列、エンゲージメントタイプの配列、およびエンゲージメントのグルーピング構造から成る JSON オブジェクトです。
* **リクエストあたりの投稿数:**
  * /totals エンドポイント: 投稿 ID は最大 250 件
  * /28hr エンドポイント: 投稿 ID は最大 25 件
  * /historical エンドポイント: 投稿 ID は最大 25 件
* **エンゲージメントメトリックの提供範囲:**
  * **/totals** -- 投稿されてから現在までのメトリックの合計。インプレッション数とエンゲージメント数は、過去 90 日以内に投稿された投稿について利用可能であり、リポスト、引用ポスト、返信、お気に入り、動画再生数はすべての投稿に対して利用可能です。
  * **/28hr** -- リクエスト時点から直近 28 時間。
  * **/historical** -- 2014 年 9 月 1 日以降に開始する任意の 28 日間。
* **メトリックタイプ**: 各リクエストには、[Metric Types](http://support.gnip.com/apis/engagement_api/overview.html#EngagementTypes) の配列が含まれます。利用可能なメトリックは、エンドポイントおよび（/totals エンドポイントからリクエストする場合は）投稿がユーザーから権限付与されているかどうかによって異なります。
  * /totals エンドポイント:
    * すべての投稿: お気に入り、リポスト、引用ポスト、返信、動画再生数
    * OAuth 1.0a User Context が必要: インプレッション数、エンゲージメント数、お気に入り、返信、リポスト
  * /28hr および /historical エンドポイント（投稿所有者のアクセストークンを使用した OAuth 1.0a User Context が必要）: インプレッション数、エンゲージメント数、お気に入り、返信、リポスト、URL クリック、ハッシュタグクリック、詳細クリック、パーマリンククリック、メディアクリック、アプリインストール試行、アプリ起動、投稿メール、動画再生数、メディア再生数
* **エンゲージメントグルーピング:** 各リクエストには、[Engagement Groupings](/ja/x-api/enterprise-gnip-2.0/fundamentals/engagement-api#engagement-api-groupings) の配列が含まれます。これらのグルーピングを使用して、返されるメトリックの整理方法をカスタマイズできます。各リクエストには最大 3 つまでのグルーピングを含めることができます。メトリックは次の値で整理できます。
  * すべてのエンドポイント: 投稿 ID、エンゲージメントタイプ
  * /28hr および /historical エンドポイント: 追加のグルーピングとして「エンゲージメント日」「エンゲージメント時間」を指定すると、これらのエンドポイントは時系列データを提供します。
* **インテグレーションに関する前提条件:** あなたのチームには、以下の責任があります。
  * Engagement API に HTTP リクエストを送信し、リクエストに含まれる投稿 ID に対するエンゲージメントメトリックを返すことができるクライアントアプリを作成・維持すること。
* **制限事項**
* 動画再生数は、投稿から 1800 日以内の投稿に対してのみ利用可能です。

<div id="authenticating-with-the-engagement-api">
  ### Engagement API での認証
</div>

> **ご注意ください**: 
>
> Engagement API を使い始める前に、X があなたの開発者用 App に対して Engagement API へのアクセスを有効化する必要があります。このため、認証に使用する予定の App ID をアカウントマネージャーまたはテクニカルサポートチームと共有してください。

Engagement API では 2 つの認証方法が利用できます: [OAuth 1.0a](/ja/resources/fundamentals/authentication#oauth-1-0a-2) と [OAuth 2.0 Bearer Token](/ja/resources/fundamentals/authentication#bearer-token-also-known-as-app-only) です。 

**OAuth 2.0 Bearer Token**（「application-only」とも呼ばれます）は、公開されているエンゲージメントメトリクスにアクセスできるようにします。この認証方法は、[/totals エンドポイント](/ja/x-api/enterprise-gnip-2.0/fundamentals/engagement-api#post-insights-engagement-totals) へのリクエスト時に、公開されている任意の投稿について、Favorites（別名 Likes）、Retweets、Quote Tweets、Replies、動画再生数の合計値を取得するために使用できます。 

**OAuth 1.0a**（「user context」とも呼ばれます）は、ユーザーを代理してリクエストを送信し、そのユーザーに属する非公開のエンゲージメントメトリクスにアクセスできるようにします。 

この認証方法が必須となるのは次のケースです:

* [/28hr エンドポイント](/ja/x-api/enterprise-gnip-2.0/fundamentals/engagement-api#post-insights-engagement-28hr) および [/historical エンドポイント](/ja/x-api/enterprise-gnip-2.0/fundamentals/engagement-api#post-insights-engagement-historical) に送信されるすべてのリクエスト
* 次のいずれかの非公開メトリクスへのアクセス: Impressions、Engagements、Media Views、Media Engagements、URL Clicks、Hashtag Clicks、Detail Expands、Permalink Clicks、App Install Attempts、App Opens、Email Post、User Follows、User Profile Clicks

OAuth 1.0a を使用してリクエストを送信する場合、対象となる投稿または保護されたリソースの所有者であるユーザーの Access Tokens（Access Token と Secret）を含める必要があります。保護されたユーザーデータをリクエストする際に正しいユーザーの Access Tokens を指定しない場合、Engagement API は `403 Forbidden` エラーを返します。

Engagement API は、たとえこれらの投稿の所有者を代理して認証している場合でも、[保護された投稿](https://help.x.com/en/safety-and-security/public-and-protected-tweets) のエンゲージメント data を取得することはできません。このようなリクエストを行うと、`400 Bad Request` エラーが返され、メッセージは `"Tweet ID(s) are unavailable"` となります。

自分自身の X アカウント（つまり、開発者用 App を所有しているアカウント）を代理してリクエストを送信している場合は、[開発者コンソール](https://developer.x.com/en/portal/projects-and-apps) の開発者用 App の「Keys and tokens」タブから、必要な Access Tokens を直接生成できます。

他のユーザーを代理してリクエストを送信する場合は、必要な Access Tokens を取得するために 3-legged OAuth フローを使用する必要があります。これを行う方法の詳細については、次のドキュメントを参照してください: [OAuth 1.0a: how to obtain a user’s access tokens](/ja/resources/fundamentals/authentication#oauth-1-0a-2)。

追加のサンプル（OAuth 1.0a を使用した認証方法を含む）については、[X Developers による Engagement API 向けの Python サンプルコード](https://github.com/xdevplatform/enterprise-scripts-python/tree/master/Engagement-API) を参照してください。

<div id="interpreting-the-metrics">
  ### メトリクスの解釈
</div>

**注:** 一部の X のウェブダッシュボードで報告されるデータと、Engagement API によって返されるデータに差異が見られる場合があります。これは、ウェブダッシュボードが通常、選択した期間内に発生したエンゲージメントやインプレッションのみを表示するためです。たとえば、ウェブダッシュボードは暦月の期間内に行われた投稿へのエンゲージメントのみを表示する一方で、Engagement API では、その月の範囲を超えていても、リクエストした時間範囲内であればエンゲージメントを含めて報告する場合があります。こうしたケースでは、Engagement API を信頼すべき正式なデータソースと見なしてください。
 

<div id="impressions-and-engagement-data">
  #### インプレッションとエンゲージメントのデータ
</div>

Engagement API は、**オーガニック**のインプレッションおよびエンゲージメントのデータを提供します。

インプレッションは、特定の投稿が X プラットフォーム上でオーガニックなコンテキストで閲覧された回数を表します。プロモーション（広告）または有料のコンテキストで表示された投稿から発生したインプレッションは**含まれません**。

エンゲージメントは、特定の投稿に対して閲覧者が **オーガニック**および**プロモーション**の両方のコンテキストで何らかのアクションを行った回数を表します。エンゲージメントには、リツイート、いいね、返信、URL クリック、ハッシュタグクリック、メンションのクリック、メディア再生などが含まれますが、これらに限定されません。含まれるエンゲージメントアクションの完全な一覧については、「Engagement Data」セクションを参照してください。 

ベースラインのエンゲージメント率を算出するには、分析対象期間において、特定の投稿の総エンゲージメント数を、その投稿の総インプレッション数で割った値を使用してください。

インプレッションおよびエンゲージメントのデータは、自社が保有する @handle の投稿、またはあなたのアプリケーションに対して自分の投稿の詳細閲覧を許可した @handle の投稿に対してのみ取得できます。内部的には、Engagement API は、契約で定められた @handle の上限に対してリクエストされた一意の @handle の数を追跡します。クライアント側でも、月間を通じて @handle のリクエスト利用状況を追跡することを推奨します。  

<div id="video-metrics">
  #### 動画メトリクス
</div>

X では、メディアのインプレッションを表すメトリクスがいくつかあります。1つ目は動画再生数メトリクスで、動画の 50% 以上が画面内に少なくとも 2 秒間表示されているという MRC 標準に基づいています。2つ目は Media Views で、動画、vine、gif、画像にわたるメディアのすべての再生（自動再生およびクリックによる再生）をカウントしたものです。

動画再生数メトリクスは、/28hour および /historical エンドポイント経由で所有している投稿に対して利用できるほか、/totals エンドポイント経由ですべての非所有の投稿に対しても利用できます。 

X のユーザーインターフェース内の動画再生数メトリクスも同じ MRC 標準を使用していますが、X が所有・運営するプラットフォーム（モバイルアプリおよびウェブサイト）に表示される動画再生数メトリクスと、各種 Engagement API エンドポイント経由で取得する数値との間に差異が生じる場合がある点に注意してください。

* /totals エンドポイントおよび X のユーザーインターフェースで提供される動画再生数は、特定の動画が投稿されたすべての投稿にまたがって集計された動画再生数を表示します。つまり、/totals 経由で提供され、X の UI に表示されるメトリクスには、その動画がリツイートされたり、別の投稿として再投稿されたすべてのインスタンスからの再生数が合算されます。
* /28hour および /historical Engagement API エンドポイントで提供される動画再生数には、メトリクスを取得している特定の投稿によって生成された再生数のみが含まれます。 
   

1800 日より前に投稿された投稿については、動画再生数は提供していない点に注意してください。その代わりに、1800 日より前の投稿を一覧にしたオブジェクトを返します。要求した投稿については、それ以外のすべてのメトリクスを別のオブジェクトで引き続き受け取ることができます。以下はレスポンスの例です。

    "477139122520219648"
  ],
  "grouping name": {

      "favorites": "69",
      "impressions": "1692",
      "retweets": "142",
      "video_views": "0"
    },
    "477139122520219648": {
      "favorites": "10",

Media Views メトリックは、/28hour エンドポイントおよび /historical エンドポイントで取得する自社の投稿に対してのみ利用できます。

<div id="engagement-api-groupings">
  ### Engagement API のグルーピング
</div>

グルーピングを使用すると、返されるエンゲージメント指標を柔軟に整理できます。1 回のリクエストで指定できるグルーピングは最大 3 つです。次の値の 1 つ以上で指標をグループ化できます。

*3 つのエンドポイントすべてでサポートされる項目:*

* tweet.id
* engagement.type
   

*`/28hr` と `/historical` は時系列指標を提供できるため、次の項目もサポートします:*

* engagement.day
* engagement.hour

グルーピングは指定した順番どおりに解釈されるため、`group_by` の値の順序を変えることで、求める結果の形式を変更できます。4 つの `group_by` 値を含むグルーピングは、次の 2 つの形式のいずれかでのみサポートされます。

```bash
"group_by": [
    "tweet.id",
    "engagement.type",
    "engagement.day",
    "engagement.hour"
  ]
```

または

```bash
"group_by": [
    "engagement.type",
    "tweet.id",
    "engagement.day",
    "engagement.hour"
]
```

たとえば、メトリックタイプごとの総計を生成したい場合は、リクエストの一部として次の「groupings」指定を含めてください（リクエストの組み立て方法の詳細については、[APIリファレンス](/ja/x-api/enterprise-gnip-2.0/fundamentals/engagement-api#post-insights-engagement)ページを参照してください）。

```json
{
  "engagement_types": [
    "favorites",
    "replies",
    "retweets"
  ],
  "groupings": {
    "Grand Totals": {
      "group_by": [
        "engagement.type"
      ]
    }
  }
}
```

このグループ設定により、Engagement API の JSON レスポンスには、メトリクスのタイプごとの総計を格納したルートレベルの `"Grand Totals"` 属性が含まれるようになります。

```json
{
  "Grand Totals": {
    "favorites": "12",
    "replies": "2",
    "retweets": "2"
  }
}
```

単一の投稿について、投稿IDごとにグループ化された4時間分のメトリクスの時系列を生成するには、リクエストに次のGrouping指定を含めます。

```json
{
  "start": "2016-02-10T17:00:00Z",
  "end": "2016-02-10T21:00:00Z",
  "tweet_ids": [
    "697506383516729344"
  ],
  "engagement_types": [
    "impressions",
    "engagements"
  ],
  "groupings": {
    "Tweets_MetricType_TimeSeries": {
      "group_by": [
        "tweet.id",
        "engagement.type",
        "engagement.hour"
      ]
    }
  }
}
```

このグルーピングを指定すると、Engagement API の JSON レスポンスにはルートレベルに `"Tweets_MetricType_TimeSeries"` 属性が含まれ、その中に投稿 ID ごと、さらにメトリクスタイプごとに区分されたメトリクスと、それに対応する 1 時間ごとの時系列データが格納されます。

```json
{
  "Tweets_MetricType_TimeSeries": {
    "697506383516729344": {
      "impressions": {
        "2016-02-10": {
          "17": "551",
          "18": "412",
          "19": "371",
          "20": "280"
        }
      },
      "engagements": {
        "2016-02-10": {
          "17": "8",
          "18": "6",
          "19": "3",
          "20": "0"
        }
      }
    }
  }
}
```

<div id="authentication">
  #### **Authentication**
</div>

Engagement API を利用するには HTTPS の使用が必須であり、User Context と Application-Only OAuth の両方をサポートしています。ほとんどの Engagement API リクエストでは 3-Legged OAuth（User Context の特定のバージョン）の利用が必要です。これは、Engagement API へのアクセスについて Twitter アカウントマネージャーによって登録・承認されたアプリの consumer key と consumer secret に加えて、ツイート所有者の access token と access token secret を使用してエンドポイントを呼び出すことを意味します。以下のリクエストでは、このタイプの OAuth が必須です。

* 所有するツイートに限定される Impressions および Engagements のメトリクス種別を取得するための /totals へのリクエスト
* /28hr へのリクエスト
* /historical へのリクエスト

一部の Engagement API リクエストは Application-Only OAuth を使って実行できます。この場合、必要なのは consumer key と consumer secret、または Bearer Token だけです。次のリクエストはこのタイプの OAuth で実行できます。

* 任意のツイートに対して取得可能な Favorites、Replies、Retweets、または Video Views のメトリクス種別を取得するための /totals へのリクエスト

いずれのリクエストでも、[developer.x.com](https://developer.x.com/en/portal/dashboard) にあるアプリ管理コンソールを使用して、Twitter アプリおよび対応する API key を設定する必要があります。

注意: developer.x.com 上で Twitter アカウントにログインしている場合は、[Twitter app dashboard](https://developer.x.com/en/apps) から既存の [Twitter apps](/ja/resources/fundamentals/developer-apps) を表示および編集できます。

アプリを設定したら、Engagement API に対してアプリからリクエストを送信できるようにするために、その app ID を担当のアカウント担当者によって承認してもらう必要があります。Access token は「現在のユーザー」を表すために使用し、別のユーザーに代わって行うリクエストには、有効なトークンで署名する必要があります。OAuth の署名ベース文字列を作成する前に、URL および POST 本文内で[予約文字をエンコード](https://tools.ietf.org/html/rfc3986) していることを確認してください。

OAuth の利用開始方法についての詳細は、次のリンクを参照してください。

* [OAuth の概要](/ja/resources/fundamentals/authentication)
* [User Context とも呼ばれる 3 Legged OAuth の使用方法](/ja/resources/fundamentals/authentication#obtaining-access-tokens-using-3-legged-oauth-flow)
* [Application-Only OAuth の使用方法](/ja/resources/fundamentals/authentication#bearer-token-also-known-as-app-only)

| 401 | Unauthorized | 無効な認証情報のため、HTTP 認証に失敗しました。OAuth キーとトークンを確認してください。 |
| 404 | Not Found | リクエストが送信された URL 上にリソースが見つかりませんでした。誤った URL が使用された可能性があります。 |
| 429 | Too Many Requests | アプリが API リクエストの上限を超えました。 |
| 500 | Internal Server Error | Gnip 側でエラーが発生しました。指数バックオフ方式でリクエストを再試行してください。 |
| 502 | Proxy Error | Gnip 側でエラーが発生しました。指数バックオフ方式でリクエストを再試行してください。 |
| 503 | Service Unavailable | Gnip 側でエラーが発生しました。指数バックオフ方式でリクエストを再試行してください。 |

<div id="error-messages">
  #### **エラーメッセージ**
</div>

さまざまな状況において、Engagement API は状況に応じたエラーメッセージを返します。アプリケーション側では、これらに適切に対処できるようにしておく必要があります。以下の表では、代表的なエラーメッセージの例と、その解釈方法を示します。多くの場合、Engagement API は、200 OK レスポンスの一部として、利用可能な data に対する部分的な結果と、追加情報を含む特定のエラーメッセージを同時に返す点に注意してください。

| エラーメッセージ | 説明 |
| :--- | :--- |
| `"errors":["Your account could not be authenticated. Reason: Access token not found"]` | リクエストの認証コンポーネントで発生したエラーです。“Reason” には、エラーのトラブルシューティングに役立つ情報が含まれます。解決できない場合は、“Reason” を含むエラー全文をサポートチームにお送りください。 |
| `"errors":["1 Tweet ID(s) are unavailable"],"unavailable_tweet_ids": ["TWEET_IDS"]` | リクエストされた 1 つまたは複数の Tweet ID が利用できません。通常は、ツイートが削除されたか、その他の理由により公開されていないことを示します。 |
| `"errors":["Impressions & engagements for tweets older than 90 days (*TIME_PERIOD*) are not supported"],"unsupported_for_impressions_engagements_tweet_ids":[*TWEET_IDS*]` | /totals エンドポイントに対してリクエストされた Tweet ID が、90 日以内のツイートではないため、インプレッションまたはエンゲージメント指標を返す対象外になっています。 |
| `"errors":["Forbidden to access tweets: *TWEET_IDS*"]` | リクエストされた Tweet ID は、第三者の代わりに data を取得するために使用している認証トークンの権限ではアクセスできません。 |
