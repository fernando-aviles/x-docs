<div id="introduction">
  ## Introduction
</div>

`Enterprise`

Enterprise エンリッチメントは、一部のデータ API のレスポンスペイロードに含まれる追加メタデータです。有料サブスクリプションプランでのみ利用できます。

以下の表では、各エンリッチメントの概要を示します。

| Enrichment: | Description: |
| :--- | :--- |
| Expanded and Enhanced URLs | 投稿本文に含まれる短縮 URL（例: bitly）を自動的に展開し、遷移先ページから HTML の title および description メタデータを取得して提供します。 |
| Matching rules object | 受信した投稿にどのルールが一致したかを示します。このオブジェクトは、レスポンスオブジェクト内でルールタグおよびルール ID を返します。 |
| Poll metadata | 投稿内に投票が存在することを示し、投票の選択肢一覧に加えて、投票の有効期間と終了時刻の両方を含みます。 |
| Profile geo | ユーザープロフィールの位置情報から導出されたデータで、[longitude, latitude] 座標（可能な場合）および関連する場所のメタデータを含みます。 |

<div id="expanded-and-enhanced-urls">
  ### 展開および拡張された URL
</div>

Expanded and Enhanced URL エンリッチメントは、投稿本文に含まれる短縮 URL を自動的に展開し、その結果得られた URL をペイロード内のメタデータとして含めます。さらに、このエンリッチメントは、遷移先ページの `title` と `description` から取得した HTML ページのメタデータも提供します。

**重要な詳細:**

* 短縮リンクを展開するために、システムは指定された URL に対して HTTP HEAD リクエストを送信し、最終的な URL に到達するまでリダイレクトをたどります。この最終的な URL（ページのコンテンツ自体ではありません）のみがレスポンスペイロードに含まれます。

* URL エンリッチメントにより、リアルタイムストリームには 5〜10 秒程度のレイテンシーが追加されます。

* Full Archive Search API へのリクエストについては、展開済み URL エンリッチメントのデータは、作成から 13 か月以内の投稿に対してのみ利用できます。

* URL エンリッチメントは、投稿内に含まれる投稿へのリンク（引用ツイートを含む）、Moments へのリンク、プロフィールへのリンクには利用できません。 
   

<div id="post-payload">
  #### 投稿ペイロード
</div>

Expanded and Enhanced URL のエンリッチメントは、投稿ペイロードの `entities` オブジェクト内、具体的には `entitites.urls.unwound` オブジェクトに含まれています。これは以下のメタデータフィールドを提供します。

* 展開された URL - `unwound.url`
* 展開された HTTP ステータス - `unwound.status`
* 展開された URL の HTML タイトル - 最大 300 文字 - `unwound.title`
* 展開された URL の HTML 説明 - 最大 1000 文字 - `unwound.description`

**これは URL エンリッチメントを含む [entities オブジェクト](/ja/x-api/enterprise-gnip-2.0/fundamentals/data-dictionary#x-entities) の例です。**

```
"entities": {
    "hashtags": [

    ],
    "urls": [
      {
        "url": "https:\/\/t.co\/HkTkwFq8UT",
        "expanded_url": "http:\/\/bit.ly\/2wYTb9y",
        "display_url": "bit.ly\/2wYTb9y",
        "unwound": {
          "url": "https:\/\/www.forbes.com\/sites\/laurencebradford\/2016\/12\/08\/11-websites-to-learn-to-code-for-free-in-2017\/",
          "status": 200,
          "title": "11 Websites To Learn To Code For Free In 2017",
          "description": "It\u2019s totally possible to learn to code for free...but what are the best resources to achieve that? Here are 11 websites where you can get started."
        },
        "indices": [
          10,
          33
        ]
      }
    ],
    "user_mentions": [

    ],
    "symbols": [

    ]
  },
```

**これは、エンリッチされていない投稿リンクを含む entities オブジェクトの例です：**

```
"entities": {
  "urls": [{
    "url": "https://t.co/SywNbZdDmb",
    "expanded_url": "https://x.com/XDevelopers/status/1050118621198921728",
    "display_url": "x.com/XDevelopers/s…",
     "indices": [
        142,
        165
     ]
   }
  ]
}
```

<div id="filtering-operators">
  #### フィルタリングオペレーター
</div>

次のオペレーターは、URL メタデータ内の関連フィールドに対してフィルターを行い、トークン化された一致を返します。

**url:**

* 例: 「url:tennis」
* 単語「tennis」を含む任意の展開済み URL に対するトークン化マッチ
* 「url:npr.org」のように指定することで、特定の Web サイトからのリンクを含めたり除外したりするフィルターとしても利用できます

**url&#95;title:**

* 例: 「url&#95;title:tennis」
* 単語「tennis」を含む任意の展開済み URL の HTML title に対するトークン化マッチ
* ペイロードに含まれる HTML title データに対してマッチし、これは最大 300 文字に制限されています。

**url&#95;description:**

* 例: 「url&#95;description:tennis」
* 単語「tennis」を含む任意の展開済み URL の HTML description に対するトークン化マッチ
* ペイロードに含まれる HTML description に対してマッチし、これは最大 1000 文字に制限されています。
   

<div id="http-status-codes">
  #### HTTP Status Codes
</div>

展開された URL のエンリッチメントでは、展開しようとしている最終的な URL の HTTP ステータスコードも提供します。通常は 200 が返されます。その他の 400 番台の値は、URL の解決に問題があることを示します。

URL を展開しようとすると、さまざまなステータスコードが返される可能性があります。URL の展開処理中にリダイレクトが発生した場合、次のいずれかの状態になるまでリダイレクトをたどり続けます。

* 200 番台のコードに到達した場合（成功）
* リダイレクト以外の系列のコードに到達した場合（失敗）
* 最終 URL が妥当な時間内に解決できずにタイムアウトした場合（408 - timeout を返す）
* 何らかの例外が発生した場合
   

例外が発生した場合は、理由と返されるステータスコードとの間で、次のマッピングを使用します。

| 理由 | 返されるステータスコード |
| :--- | :--- |
| SSL 例外 | 403 (Forbidden) |
| URL によって展開が許可されていない | 405 |
| ソケットタイムアウト | 408 (Timeout) |
| 不明なホスト例外 | 404 (Not Found) |
| サポートされていない操作 | 404 (Not Found) |
| 接続例外 | 404 (Not Found) |
| 不正な引数 | 400 (Bad Request) |
| その他すべて | 400 (Bad Request) |

<div id="matching-rules">
  ### マッチングルール
</div>

matching&#95;rules のエンリッチメントは、受信した投稿に対してどのルールがマッチしたかを示すメタデータのオブジェクトです。これは主に PowerTrack ストリームで使用されます。

マッチングは、ルールに含まれる語句との完全一致で行われ、アクティビティのコンテンツを句読点の有無の両方でスキャンして実施されます。マッチングは大文字と小文字を区別しません。コンテンツ内にルールで定義されたすべての語句が含まれていると判定された場合、ルートレベルに、そのマッチを引き起こしたルールを示す matching&#95;rules オブジェクトが含まれます。

**PowerTrack**

PowerTrack（リアルタイム、Replay、Historical）経由で配信される投稿には、次のように matching&#95;rules オブジェクトが含まれます。

```
"matching_rules": [{
        "tag": null,
        "id": 907728589029646336,
        "id_str": "907728589029646336"
    }]
```

PowerTrack では、`matching_rules` オブジェクトは、その結果にマッチした *すべての* ルールを表します。言い換えると、複数のルールが特定の投稿にマッチした場合でも、その投稿は一度だけ配信されますが、`matching_rules` 要素にはマッチしたすべてのルールが含まれます。

<div id="poll-metadata">
  ### 投票メタデータ
</div>

投票メタデータは、すべてのプロダクト（Realtime &amp; Historical APIs）で無料で利用できるエンリッチメントであり、拡張されたネイティブ形式のペイロードに含まれます。このメタデータには、投稿内に投票が存在すること、投票の選択肢一覧、さらに投票の継続時間と有効期限時刻が含まれます。このエンリッチメントにより、投票の存在を容易に認識でき、表示用に投票付き投稿を正しくレンダリングできるようになります。

<div id="important-details">
  ##### 重要な詳細:
</div>

* すべてのエンタープライズ API（PowerTrack、Replay、Search、Historical PowerTrack）で利用可能
  * *注:* Replay と Historical PowerTrack では、このメタデータは 2017年2月22日に初めて利用可能になりました。
* 投票内容や投票結果は含まれません
* 現時点ではフィルター／オペレーターによる絞り込みはサポートされていません
* **拡張ネイティブ形式 (enriched native format)** でのみ利用可能
  * 拡張ネイティブ形式はユーザーが制御できる設定であり、Console からいつでも変更できます: *Select a Product (PowerTrack, Replay, Search) &gt; Settings tab &gt; Output Format (Leave data in its original format)*

<div id="post-payload">
  #### 投稿ペイロード
</div>

投票付き投稿には、ペイロード内の “entities.polls” オブジェクトに次のメタデータが含まれます。

* 番号 (1〜4) と選択肢テキストを含む、最大 4 個の選択肢からなる “options” 配列
* 投票の終了日時
* 投票の継続時間

参考として、以下のサンプルペイロードを参照してください。

#### サンプルペイロード

以下は、追加された投票メタデータを含む、拡張されたネイティブ形式のペイロードの抜粋です。

```json
"entities":{
          "hashtags":[],
          "urls":[],
          "user_mentions":[],
          "symbols":[],
          "polls":[
             {
                "options":[
                   {
                      "position":1,
                      "text":"The better answer"
                   },
                   {
                      "position":2,
                      "text":"The best answer"
                   }
                ],
                "end_datetime":"Sat Feb 04 15:33:11 +0000 2017",
                "duration_minutes":1440
             }
          ]
       },
```

<div id="profile-geo">
  ### プロフィールの位置情報
</div>

#### はじめに

多くの X ユーザーのプロフィールには、ユーザーが提供した公開位置情報が含まれています。このデータは `user.location` に通常の文字列型として返されます（[ユーザーオブジェクトのデータ辞書](/ja/x-api/enterprise-gnip-2.0/fundamentals/data-dictionary#native-enriched-user-object) を参照）。Profile Geo エンリッチメント機能は、可能な場合に位置情報文字列をジオコーディングおよび正規化することで、`user.location` の値に関連する構造化された地理データを付加します。緯度・経度の座標と、関連する場所に関するメタデータの両方は、エンタープライズ API 製品において投稿ペイロードの一部として含まれている場合に *のみ* `user.derived.locations` に追加されます。このデータは [enriched native 形式](/ja/x-api/enterprise-gnip-2.0/fundamentals/data-dictionary) を使用している場合に利用でき、[PowerTrack ルール](/ja/x-api/enterprise-gnip-2.0/fundamentals/rules-filtering#enterprise-operators) を組み合わせてフィルタリングできます。

<Note>
  **Note:** Profile Geo エンリッチメントを作成するために使用される補助的な地理データの一部は GeoNames.org から提供されており、X はこれを [Creative Commons Attribution 3.0 License](https://creativecommons.org/licenses/by/3.0/us/legalcode) のもとで使用しています。
</Note>

Profile Geo データは、X の PowerTrack、Replay、Volume Stream、Search、Historical PowerTrack API で提供されます。

<div id="profile-geo-data">
  #### プロフィール Geo データ
</div>

| 拡張ネイティブフィールド名 | 値の例 | 説明 |
| :--- | :--- | :--- |
| user.derived.locations.country | United States | 投稿を作成したユーザーの所在地の国。 |
| user.derived.locations.country&#95;code | US  | 投稿を作成したユーザーの所在地の国に対応する 2 文字の ISO-3166 国コード。 |
| user.derived.locations.locality | Birmingham | 投稿を作成したユーザーの所在地のローカリティ（通常は市区町村）。 |
| user.derived.locations.region | Alabama | 投稿を作成したユーザーの所在地の地域（通常は州 / 県）。 |
| user.derived.locations.sub&#95;region | Jefferson County | 投稿を作成したユーザーの所在地のサブリージョン（通常は郡）。 |
| user.derived.locations.full&#95;name | Birmingham, Alabama, United States | 投稿を作成したユーザーの所在地を表すフルネーム（サブリージョンを除く）。 |
| User.derived.locations.geo | See Below | 投稿を作成したユーザーの所在地のうち、最も詳細な位置情報に対応する座標の緯度 / 経度値を含む配列。 |

Historical PowerTrack、Search、および PowerTrack API は、Profile Geo データに基づくフィルタリングをサポートします。Profile Geo データで、どのオペレーターがフィルタリングに利用できるかについては、該当するプロダクトのドキュメントを参照してください。

</div>

```
            "locations": \[
                {

        }

```

<div id="limitations">
  #### 制限事項
</div>

* Profile Geo エンリッチメントは、プロフィールの location 文字列で表現されている地理的な場所について、最適な候補となる場所を推定しようとします。類似した名前の場所が複数存在する場合や、名称があいまいな場合などの要因により、結果が常に正確であるとは限りません。
* ユーザーのプロフィールの location フィールド（actor.location）に値が設定されていない場合、分類は行いません。
* 精度レベル: Profile Geo エンリッチメントが国レベルまたは地域レベルにおいてのみ十分な確信をもって判定できる場合、subRegion や locality といった、より細かい地理情報はペイロードから省略されます。
* Profile Geo エンリッチメントは、エンリッチメント結果の精度レベルに対応する緯度/経度の座標（単一点）を提供します。これらの座標は、エンリッチメントされた位置結果の地理的中心を表します。たとえば、精度レベルが国レベルの場合、その座標はその国の地理的中心に設定されます。
* 住所プロパティ（locality/region/country/country code）用に提供される PowerTrack オペレーターは、多様なルールの組み合わせを可能にするため、意図的に細かい粒度になっています。同じ名前を共有する複数の場所のうち特定の場所を対象とする場合は、住所ルールを組み合わせることを検討してください。たとえば、次のようにすることで「San Francisco, Philippines」へのマッチを避けることができます: profile&#95;locality:&quot;San Francisco&quot; profile&#95;region:California 個々の Profile Geo フィールドを対象とするルールを作成する際は、粒度を細かくするほど取得できる結果が限定されることに留意してください。都市単位のデータを取得しようとする場合でも、その都市と大きく重なりを持つ地域がある場合は、地域ルールのみに依存したほうがよいこともあります。たとえば、スイスの都市 Zurich の場合、profile&#95;region:&quot;Zurich&quot; を使用することで、周辺地域を含めて効果的にターゲティングできます。
* ネイティブ Geo 投稿との併用: Profile Geo エンリッチメントは、ペイロード内のネイティブ geo 値とは異なる、投稿に対する代替的な地理情報を提供します。これら 2 種類の地理情報を組み合わせることで、特定のエリアに関連する可能性のあるすべての投稿（利用可能な地理データに基づく）を取得できますが、概念的に同一のものではありません。
