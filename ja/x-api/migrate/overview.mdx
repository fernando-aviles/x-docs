<div id="what-is-the-x-api-v2">
  ## X API v2 とは何ですか？
</div>

X API v2 は現在、主要な X API であり、プロダクトへの投資とイノベーションの主軸となっています。私たちは開発者の皆さんと連携し、次世代の X API を構築して、多様な開発者コミュニティをより良く支援できるよう取り組んできました。開発者からのフィードバックに基づき、より幅広いニーズに応えられるよう API を再設計し、新しい機能やエンドポイントを導入するとともに、開発者エクスペリエンスを改善しました。

X API v2 は現在、主要な X API であり、プロダクトへの投資とイノベーションの主軸となっています。ここ数年にわたり、私たちは開発者の皆さんと協力し、より幅広いニーズに応え、新しい機能やエンドポイントを導入し、開発者エクスペリエンスを向上させるために API を再構築してきました。私たちは、オープンな開発者プラットフォームを今後も構築し続けることを約束しており、X API v2 を使って皆さんがどのようなものを構築されるのか、とても楽しみにしています。

<div id="why-migrate">
  ## なぜ移行するのか?
</div>

X API v2 は、モダンでより持続可能な基盤の上に構築されており、従来の v1.1 標準およびエンタープライズ製品に対する改良版の代替エンドポイントに加えて、まったく新しい機能も提供します。レガシー API（v1.1 およびエンタープライズ）をご利用のお客様には、最終的にこれらを廃止する予定であるため、v2 への移行を強く推奨します。X API を使用してパブリックな会話を収集・分析し、X 上の人々とつながり、イノベーションを起こしてください。

このセクションでは、エンドポイントとその機能について説明します。

<div id="v2-endpoints">
  ## v2 エンドポイント
</div>

v2 エンドポイントと、その v2 以前の対応エンドポイントの一覧は、次のガイドで確認できます。

<Button href="/ja/x-api/migrate/x-api-endpoint-map">
  X API エンドポイントマップ
</Button>

X API v2 のエンドポイントの多くは既存エンドポイントの置き換えですが、いくつかの新しいエンドポイントも導入しています。以下は、v2 で新たに公開したエンドポイントの例です。

* [Spaces エンドポイント](/ja/x-api/spaces/introduction)：人々が X Spaces をより活用できるようにし、開発者が音声会話の未来を形作ることを支援します。
* [返信を非表示にする](/ja/x-api/posts/hide-replies/introduction)：不適切であったり、注意をそらしたり、誤解を招く返信の影響を、大規模に抑制するためのツールを構築できます。
* 新しい Lists エンドポイント：[リストをピン留めおよびピン留め解除](/ja/x-api/lists/pinned-lists/introduction)したり、特定のユーザーがピン留めしている Lists を取得したりできます。
* 新しい [バッチコンプライアンスエンドポイント](/ja/x-api/compliance/batch-compliance/introduction)：保持しているユーザーおよびツイートのデータがコンプライアンス要件に準拠していることを確認できます。

<div id="discover-new-and-updated-response-objects">
  ### 新しいレスポンスオブジェクトと更新されたレスポンスオブジェクトを確認する
</div>

以下の 6 種類のデータオブジェクトが v2 エンドポイントで利用可能です。

| Object | Description |
|:--------|:-------------|
| [Tweet](/ja/x-api/fundamentals/data-dictionary#tweet) | Tweet オブジェクトには、`id`、`text`、`created_at` などのルートレベルフィールドが多数含まれています。Tweet オブジェクトは、`user`、`media`、`poll`、`place` など複数の子オブジェクトの親オブジェクトでもあります。 |
| [User](/ja/x-api/fundamentals/data-dictionary#user) | User オブジェクトには、参照されているユーザーを表す X のユーザーアカウントメタデータが含まれます。 |
| [Spaces](/ja/x-api/fundamentals/data-dictionary#space) | Space オブジェクトは、`state`、`host_id`、`is_ticketed`、`lang` などのフィールドで構成されています。 |
| [Lists](/ja/x-api/fundamentals/data-dictionary#list) | List オブジェクトには、要求されたリストに関する基本情報が含まれており、`description`、`member_count`、`owner_id` などのフィールドがあります。 |
| [Media](/ja/x-api/fundamentals/data-dictionary#media) | ツイートにメディア（画像など）が含まれている場合、`media.fields` パラメータを使用して Media オブジェクトをリクエストでき、`media_key`、`type`、`url`、`preview_image_url` などのフィールドを取得できます。 |
| [Poll](/ja/x-api/fundamentals/data-dictionary#poll) | ツイートに含まれる投票は、どのエンドポイントにおいても主要オブジェクトではありませんが、Tweet オブジェクト内で見つけて展開できます。 |
| [Place](/ja/x-api/fundamentals/data-dictionary#place) | Place オブジェクトは、`place_id`、`geo` オブジェクト、`country_code` などのフィールドで構成されています。この情報は、ツイートを識別し、場所ごとにツイートを分析するために使用できます。 |

[fields と expansions の使用方法](/ja/x-api/fundamentals/data-dictionary#how-to-use-fields-and-expansions)について、詳しくはこのページを参照してください。

<div id="flexibility-to-choose-which-objects-and-fields-you-receive">
  ### 取得するオブジェクトとフィールドを柔軟に選択可能
</div>

GET エンドポイントへのリクエストを行うと、そのエンドポイントに関連する主要なデータオブジェクトが返され、そこには一連のデフォルトのフィールドが含まれます。たとえば、Tweet オブジェクトはデフォルトで `id` と `text` フィールドを返します。

追加のフィールドを取得したい場合は、[fields](/ja/x-api/fundamentals/fields) パラメーターと [expansions](/ja/x-api/fundamentals/expansions) パラメーターを使用する必要があります。`expansions` パラメーターを使用すると、ユーザーの固定表示ツイートやメディアオブジェクトなどの関連データオブジェクトを取得できます。一方、`fields` パラメーターを使用すると、デフォルト以外にも、返却されるオブジェクト内の特定のフィールドを指定してリクエストできます。

以下は、さまざまな X API v2 エンドポイントでリクエストできる `expansions` の一覧です。

| Object / Resource | 利用可能な expansions |
|:-------------------|:----------------------|
| Tweets            | `author_id`, `edit_history_tweet_ids`, `entities.mentions.username`, `in_reply_to_user_id`, `referenced_tweets.id`, `referenced_tweets.id.author_id`, `attachments.poll_ids`, `attachments.media_keys`, `geo.place_id` |
| Users             | `pinned_tweet_id` |
| Spaces            | `invited_user_ids`, `speaker_ids`, `creator_id`, `host_ids`, `topic_ids` |

[fields と expansions の使い方](/ja/x-api/fundamentals/data-dictionary#how-to-use-fields-and-expansions)について詳しくご確認ください。

<div id="edit-tweets">
  ## ツイートの編集
</div>

X API v2 のエンドポイントでは、編集済みツイートのメタデータを提供します。*ツイートを編集* 機能は、2022 年 9 月 1 日に X 社員向けテストとして初めて導入されました。その日以降、対象となるツイートは 30 分間、最大 5 回まで編集できます。詳細は、[ツイートの編集](/ja/x-api/fundamentals/edit-posts)をご覧ください。
X API v2 を使用すると、開発者は次のことを把握できます。

* 作成時点でツイートが編集対象であったかどうか。一部のツイート（投票付きツイートや予約投稿されたツイートなど）は編集できません。
* ツイートは 30 分間編集可能で、最大 5 回まで編集できます。編集可能なツイートについては、編集可能時間が残っているかどうか、また残り何回編集できるかを確認できます。
* 表示しているツイートが編集済みバージョンかどうか（特定の過去バージョンがツイート ID でリクエストされない限り、多くの場合、API はツイートの最新バージョンを返します）。
* ツイートの完全な編集履歴。
* ツイートの各バージョンにひもづくエンゲージメント。

</div>

新しいツイートフィールドによって、ツイートがどの会話スレッドに属しているかを特定できるようになりました。会話 ID は、その会話を開始したツイートの Tweet ID です。詳しくは、[会話の追跡](/ja/x-api/fundamentals/conversation-id)をご覧ください。

<div id="ready-to-migrate">
  ## 移行の準備
</div>

v2 エンドポイントを利用するには、以下が必要です。

* [開発者アカウント](https://developer.x.com/en/portal/petition/essential/basic-info)
* [Project](resources/fundamentals/projects) 内で作成された [開発者用 App](https://developer.x.com/en/apps)
* その Project の開発者用 App に紐づく [キーとトークン](resources/fundamentals/authentication)

Project 内の App のキーとトークンを利用することが重要である点に注意してください。Project の外にある App のキーやトークンを使用している場合、v2 エンドポイントへリクエストを送信することはできません。

開発者アカウントを取得したら、[開発者コンソール](https://developer.x.com/en/portal/petition/essential/basic-info) で上記すべてを設定できます。

<div id="authentication">
  ### 認証
</div>

新しい Twitter API では、さまざまなエンドポイントにアクセスするために、2 種類の認証方式である OAuth 1.0a ユーザーコンテキスト と OAuth 2.0 Bearer Token を使用します。それぞれ、エンドポイントにリクエストを送信する際の用途が異なります。

OAuth 1.0a ユーザーコンテキストは、Twitter ユーザーに代わってリクエストを行う場合に必須です
OAuth 2.0 Bearer Token は、開発者用 App に代わってリクエストを行う場合に必須です

<div id="tools-and-code">
  ## ツールとコード
</div>

新しいエンドポイントや機能に慣れ、作業を開始するにあたって、すぐに利用できるいくつかのオプションを用意しています。

* Twitter の [Postman collection](https://app.getpostman.com/run-collection/9956214-784efcda-ed4c-4491-a4c0-a26470a67400) を使用すると、Postman クライアントを使って個々のエンドポイントにリクエストを送信して接続できます。これは、認証をテストし、エンドポイントを試すための手軽な方法です。
* また、Twitter がサポートするものとサードパーティ製のものの両方を含む、Ruby、Python、Node、Java などのライブラリ一覧も提供しています。詳しくは [ツールとライブラリのページ](/ja/x-api/tools-and-libraries/overview)を参照してください。

<div id="migrating-to-the-new-data-format">
  ## 新しいデータ形式への移行
</div>

v1.1 または enterprise から v2 へ移行する際には、データが提供される形式が大きく変化していることを理解しておくことが重要です。新しいフィールドを追加し、フィールドの並び順を変更し、場合によっては要素そのものを削除しています。

これらの変更について詳しく理解していただくために、v2 以前のデータ形式におけるフィールドを新しいフィールドへマッピングし、新しいフィールドをどのようにリクエストするかを説明する一連のガイドを作成しています。

この移行ハブの [data formats migration](/ja/x-api/migrate/data-format-migration) セクションや、以下の個別のデータ形式ガイドで詳しい情報をご覧いただけます。

* [ネイティブ形式から X API v2（標準 v1.1）への移行](/ja/x-api/migrate/data-format-migration#migrating-from-standard-v1-1s-data-format-to-v2)
* [Native Enriched 形式から X API v2（enterprise）への移行](/ja/x-api/migrate/data-format-migration#migrating-from-native-enriched-data-format-to-v2)

<div id="whats-next">
  ## 今後について
</div>

本プラットフォームをしばらくご利用いただいている方は、多くの新しいエンドポイントが既存の [standard v1.1](https://developer.x.com/en/docs/twitter-api/v1) や [enterprise](/ja/x-api/enterprise-gnip-2.0/enterprise-gnip) のエンドポイントと整合していることにお気付きかもしれません。将来的には、これらが 3 つすべてのバージョンを置き換える予定です。

[X API エンドポイント対応表](/ja/x-api/migrate/x-api-endpoint-map) を用意しましたので、X API のエンドポイントが従来バージョンとどのように対応しているかを確認できます。

今後の予定を確認したい場合は、[プロダクトロードマップ](https://trello.com/b/myf7rKwV/twitter-developer-platform-roadmap) をご覧ください。

すでにリリースされた内容については、[変更履歴](https://developer.x.com/en/updates/changelog) でも確認できます。
