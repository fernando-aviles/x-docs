<div id="what-is-the-x-api-v2">
  ## X API v2 とは?
</div>

X API v2 は現在、主要な X API であり、プロダクトへの投資とイノベーションはここに集約されています。多様な開発者コミュニティのニーズにこれまで以上に応えられるよう、私たちは開発者の皆さんと連携して次世代の X API を構築しました。開発者からのフィードバックに基づき、より幅広いニーズに対応できるよう API を再設計し、新しい機能やエンドポイントを導入し、開発者エクスペリエンスを改善しました。

X API v2 は現在、主要な X API であり、プロダクトへの投資とイノベーションはここに集約されています。ここ数年にわたり、私たちは開発者の皆さんと協力して、より幅広いニーズに対応し、新機能やエンドポイントを導入し、開発者エクスペリエンスを向上させるために API を再構築してきました。私たちは、オープンな開発者向けプラットフォームを今後も構築し続けることを約束しており、皆さんが X API v2 を使ってどのようなものを構築してくださるのかを楽しみにしています。

<div id="why-migrate">
  ## なぜ移行する必要があるのか
</div>

X API v2 は、最新かつより持続可能な基盤の上に構築されており、スタンダードな v1.1 およびエンタープライズ製品向けの改善された代替エンドポイントに加えて、全く新しい機能も備えています。レガシー API（v1.1 およびエンタープライズ）の利用者には、将来的にこれらを廃止する予定であるため、v2 への移行を強く推奨します。X API を使用して公開された会話を取得・分析し、X 上の人々と連携し、新たなイノベーションを生み出してください。

このセクションでは、エンドポイントと機能について説明します。

X API v2 の endpoints の多くは既存機能の置き換えですが、いくつかの新しい endpoints も導入しています。以下は、v2 で新たに提供された endpoints の例です。

* [Spaces endpoints](/ja/x-api/spaces/introduction)：人々が X Spaces をより活用できるようにし、開発者が音声による会話の未来を形作る支援ができるようにします。
* [Hide replies](/ja/x-api/posts/hide-replies/introduction)：攻撃的、紛らわしい、あるいは誤解を招く返信の影響を、大規模に抑制するためのツールを構築できるようにします。
* 新しい Lists endpoints：Lists を[ピン留めおよびピン留め解除](/ja/x-api/lists/pinned-lists/introduction)したり、あるユーザーがピン留めしている Lists を取得したりできます。
* 新しい [batch compliance endpoints](/ja/x-api/compliance/batch-compliance/introduction)：保持しているユーザーおよびツイートのデータがコンプライアンス要件に準拠していることを確認できるようにします。

<div id="discover-new-and-updated-response-objects">
  ### 新規および更新済みレスポンスオブジェクトの確認
</div>

次の 6 つのデータオブジェクトが v2 エンドポイントで利用できます。

| Object | Description |
|:--------|:-------------|
| [Tweet](/ja/x-api/fundamentals/data-dictionary#tweet) | Tweet オブジェクトには、`id`、`text`、`created_at` などのルートレベルのフィールドが多数含まれます。Tweet オブジェクトは、`user`、`media`、`poll`、`place` など複数の子オブジェクトの親オブジェクトでもあります。 |
| [User](/ja/x-api/fundamentals/data-dictionary#user) | User オブジェクトには、参照されているユーザーを説明する X ユーザーアカウントのメタデータが含まれます。 |
| [Spaces](/ja/x-api/fundamentals/data-dictionary#space) | Space オブジェクトは、`state`、`host_id`、`is_ticketed`、`lang` などのフィールドで構成されます。 |
| [Lists](/ja/x-api/fundamentals/data-dictionary#list) | List オブジェクトには、`description`、`member_count`、`owner_id` など、リクエストされたリストに関する基本情報が含まれます。 |
| [Media](/ja/x-api/fundamentals/data-dictionary#media) | ツイートにメディア（画像など）が含まれている場合、`media.fields` パラメータを使用して media オブジェクトをリクエストでき、その中に `media_key`、`type`、`url`、`preview_image_url` などのフィールドが含まれます。 |
| [Poll](/ja/x-api/fundamentals/data-dictionary#poll) | ツイートに含まれる投票は、どのエンドポイントにおいてもプライマリオブジェクトではありませんが、Tweet オブジェクト内で見つけて展開できます。 |
| [Place](/ja/x-api/fundamentals/data-dictionary#place) | Place オブジェクトは、`place_id`、`geo` オブジェクト、`country_code` などのフィールドで構成されます。この情報を使用してツイートを特定し、位置情報別にツイートを分析することができます。 |

[フィールドと展開の使用方法](/ja/x-api/fundamentals/data-dictionary#how-to-use-fields-and-expansions)の詳細をご覧ください。

<div id="flexibility-to-choose-which-objects-and-fields-you-receive">
  ### 受け取るオブジェクトとフィールドを柔軟に選択する
</div>

GET エンドポイントへのリクエストを行うと、そのエンドポイントに関連する主要な data オブジェクトが返され、その中にはデフォルトのフィールドのセットが含まれます。たとえば、Tweet オブジェクトはデフォルトで `id` と `text` のフィールドを返します。

リクエストで追加のフィールドを取得したい場合は、[fields](/ja/x-api/fundamentals/fields) パラメータと [expansions](/ja/x-api/fundamentals/expansions) パラメータを使用する必要があります。`expansions` パラメータを使うと、ユーザーのピン留めされたツイートやメディアオブジェクトなどの関連する data オブジェクトを取得でき、`fields` パラメータを使うと、デフォルトに加えて返されるオブジェクト内で特定のフィールドを指定して取得できます。

以下は、各種 X API v2 エンドポイントでリクエスト可能な expansions の一覧です。

| Object / Resource | 利用可能な Expansions |
|:-------------------|:----------------------|
| Tweets            | `author_id`, `edit_history_tweet_ids`, `entities.mentions.username`, `in_reply_to_user_id`, `referenced_tweets.id`, `referenced_tweets.id.author_id`, `attachments.poll_ids`, `attachments.media_keys`, `geo.place_id` |
| Users             | `pinned_tweet_id` |
| Spaces            | `invited_user_ids`, `speaker_ids`, `creator_id`, `host_ids`, `topic_ids` |

[fields と expansions の使い方](/ja/x-api/fundamentals/data-dictionary#how-to-use-fields-and-expansions)について詳しくは、こちらを参照してください。

<div id="edit-tweets">
  ## ツイートを編集
</div>

X API v2 のエンドポイントは、編集された Tweet に関するメタデータを提供します。*Edit Tweet* 機能は 2022 年 9 月 1 日に、まず X 社員を対象としたテストとして導入されました。この日以降、対象となるツイートは 30 分間のあいだに最大 5 回まで編集できます。[Edit Tweets](/ja/x-api/fundamentals/edit-posts) についての詳細はこちらをご覧ください。
X API v2 を使用すると、開発者は次のことを把握できます。

* ツイートが作成時点で編集対象だったかどうか。一部のツイート（投票付きツイートや予約投稿されたツイートなど）は編集できません。
* ツイートは 30 分間編集可能であり、最大 5 回まで編集できます。編集可能なツイートについては、編集可能な残り時間と、あと何回編集できるかを確認できます。
* 表示しているツイートが編集後のバージョンかどうか（多くの場合、API はツイートの最新バージョンを返しますが、特定の過去バージョンが Tweet ID でリクエストされた場合はその限りではありません）。
* ツイートの編集履歴全体。
* ツイートの各バージョンに紐付けられたエンゲージメント。

<div id="ready-to-migrate">
  ## 移行の準備が整ったら
</div>

v2 エンドポイントを使用するには、次のものが必要です。

* [開発者アカウント](https://developer.x.com/en/portal/petition/essential/basic-info)
* [Project](resources/fundamentals/projects) 内で作成された [開発者用 App](https://developer.x.com/en/apps)
* その Project の開発者用 App から取得した [Keys and tokens](resources/fundamentals/authentication)

Project 内の App から取得した keys と tokens を使用することが重要である点に注意してください。Project の外にある App から keys と tokens を使用している場合、v2 エンドポイントへリクエストを送信することはできません。

開発者アカウントを取得したら、[Developer Console](https://developer.x.com/en/portal/petition/essential/basic-info) で上記すべてを設定できます。

<div id="authentication">
  ### 認証
</div>

新しい Twitter API では、さまざまなエンドポイントにアクセスするために、2 つの異なる認証方式である OAuth 1.0a ユーザーコンテキストと OAuth 2.0 Bearer Token を使用します。各方式は、エンドポイントへのリクエストを行う際にそれぞれ異なる目的を果たします。

OAuth 1.0a ユーザーコンテキストは、Twitter ユーザーに代わってリクエストを行う場合に必須です\
OAuth 2.0 Bearer Token は、自分の開発者用 App に代わってリクエストを行う場合に必須です

<div id="tools-and-code">
  ## ツールとコード
</div>

新しいエンドポイントや機能に慣れ、作業をすぐに始められるよう、いくつかのオプションを用意しています。

* Twitter の [Postman collection](https://app.getpostman.com/run-collection/9956214-784efcda-ed4c-4491-a4c0-a26470a67400) を提供しており、Postman クライアントを使って個々のエンドポイントにリクエストを送信し、接続できます。これは認証をテストし、エンドポイントを試すための手軽な方法です。
* また、Twitter がサポートするものとサードパーティ製のものの両方を含む、Ruby、Python、Node、Java などの多くのライブラリ一覧も用意しています。詳細については、[ツールとライブラリのページ](/ja/x-api/tools-and-libraries/overview) を参照してください。

<div id="migrating-to-the-new-data-format">
  ## 新しいデータ形式への移行
</div>

v1.1 または enterprise から v2 へ移行する際には、データの提供形式が大きく変わっていることを理解しておくことが重要です。新しいフィールドを追加し、フィールドの並び順を変更し、場合によっては要素を完全に削除しています。

これらの変更についてさらに詳しく理解していただくために、v2 以前のデータ形式のフィールドを新しいフィールドにマッピングし、これらの新しいフィールドのリクエスト方法を説明する一連のガイドを作成しています。

この移行ハブ内の [data formats migration](/ja/x-api/migrate/data-format-migration) セクション、または個別のデータ形式ガイドをご覧いただくことで、詳しい情報を確認できます。
