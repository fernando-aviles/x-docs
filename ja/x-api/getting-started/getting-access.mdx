X API の利用を開始するには、サインアップ、アプリの作成、認証情報の保存の 3 ステップが必要です。

<Button href="https://console.x.com">今すぐサインアップ</Button>

***

<div id="step-1-create-a-developer-account">
  ## ステップ 1: 開発者アカウントを作成する
</div>

<Steps>
  <Step title="Developer Console にアクセスする">
    [console.x.com](https://console.x.com) にアクセスし、X アカウントでサインインします。
  </Step>

  <Step title="Developer Agreement に同意する">
    Developer Agreement とポリシーを確認し、同意します。
  </Step>

  <Step title="プロフィールを完成させる">
    API の利用目的に関する基本情報を入力します。
  </Step>
</Steps>

***

<div id="step-2-create-an-app">
  ## ステップ 2: アプリを作成する
</div>

サインアップ後、API 認証情報を取得するためのアプリを作成します。

<Steps>
  <Step title="「New App」をクリック">
    Developer Console のダッシュボードから新しいアプリを作成します。
  </Step>

  <Step title="アプリの詳細を入力">
    アプリの名前、説明、およびユースケースを入力します。
  </Step>

  <Step title="認証情報を生成する">
    コンソールで API キーとトークンが生成されます。
  </Step>
</Steps>

***

<div id="step-3-save-your-credentials">
  ## ステップ 3: 認証情報を保存する
</div>

利用する認証方式に応じて、いくつかの認証情報が発行されます。

| Credential | 目的 |
|:-----------|:--------|
| **API Key &amp; Secret** | アプリを識別します。トークンを生成し、OAuth 1.0a リクエストに署名するために使用されます。 |
| **Bearer Token** | 公開データを読み取るためのアプリ専用認証に使用されます。 |
| **Access Token &amp; Secret** | 自分のアカウントとしてリクエストを行うために使用されます（OAuth 1.0a）。 |
| **Client ID &amp; Secret** | ユーザーコンテキストのリクエストに対する OAuth 2.0 認証に使用されます。 |

<Warning>
  **すぐに保存してください。** 認証情報は一度しか表示されません。パスワードマネージャーやセキュアな保管庫に保存してください。紛失した場合は再生成する必要があり（その際、古い認証情報は無効になります）。
</Warning>

***

<div id="which-credentials-do-you-need">
  ## どの認証情報が必要ですか？
</div>

<Tabs>
  <Tab title="公開データの閲覧">
    公開データへのシンプルな読み取り専用アクセスには **Bearer Token** を使用します。

    ```bash
    curl "https://api.x.com/2/users/by/username/xdevelopers" \
      -H "Authorization: Bearer $BEARER_TOKEN"
    ```

    主な用途: 投稿の検索、ユーザー情報の取得、トレンドの閲覧。
  </Tab>

  <Tab title="ユーザーとして操作する">
    ユーザーに代わって操作するには、**OAuth 2.0**（推奨）または **OAuth 1.0a** を使用します。

    OAuth 2.0 ではきめ細かなスコープを利用でき、必要な権限だけをリクエストできます。

    主な用途: 投稿、いいね、フォロー、DM へのアクセス。

    [OAuth 2.0 ガイド →](/ja/resources/fundamentals/authentication/oauth-2-0/overview)
  </Tab>

  <Tab title="自分のアカウントとして操作する">
    自分のアカウントとしてリクエストを行うには、**Access Token &amp; Secret** を使用します。

    これらのトークンは、そのアプリの所有者であるアカウントを表します。

    主な用途: テスト、個人用ボット、自分用の自動化。
  </Tab>
</Tabs>

<div id="credential-security-best-practices">
  ## 資格情報セキュリティのベストプラクティス
</div>

<CardGroup cols={2}>
  <Card title="環境変数を使用する" icon="terminal">
    資格情報をソースコード内にハードコードしないでください。
  </Card>

  <Card title="Git にコミットしない" icon="code-branch">
    資格情報ファイルを `.gitignore` に追加してください。
  </Card>

  <Card title="定期的にローテーションする" icon="arrows-rotate">
    セキュリティ対策として、定期的に資格情報を再生成してください。
  </Card>

  <Card title="最小限のスコープを使用する" icon="shield-check">
    アプリに必要な OAuth 権限だけを要求してください。
  </Card>
</CardGroup>
