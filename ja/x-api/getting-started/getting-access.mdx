X API を利用開始するには、サインアップ、アプリの作成、認証情報の保存という 3 つのステップを行います。

<Button href="https://console.x.com">今すぐサインアップ</Button>

***

<div id="step-1-create-a-developer-account">
  ## ステップ 1: 開発者アカウントを作成する
</div>

<Steps>
  <Step title="開発者コンソールにアクセスする">
    [console.x.com](https://console.x.com) にアクセスし、X アカウントでサインインします。
  </Step>

  <Step title="Developer Agreement に同意する">
    Developer Agreement とポリシーを確認し、同意します。
  </Step>

  <Step title="プロフィールを完了する">
    API をどのように利用するかについての基本情報を入力します。
  </Step>
</Steps>

***

<div id="step-2-create-an-app">
  ## ステップ 2: アプリを作成する
</div>

サインアップ後、API クレデンシャルを取得するためのアプリを作成します。

<Steps>
  <Step title="「New App」をクリックする">
    開発者コンソールのダッシュボードから、新しいアプリを作成します。
  </Step>

  <Step title="アプリの詳細を入力">
    アプリの名前、説明、ユースケースを入力します。
  </Step>

  <Step title="クレデンシャルを生成">
    コンソールによって API キーとトークンが生成されます。
  </Step>
</Steps>

***

<div id="step-3-save-your-credentials">
  ## ステップ 3：認証情報を保存する
</div>

認証方法の要件に応じて、いくつかの認証情報が発行されます。

| Credential | 目的 |
|:-----------|:--------|
| **API Key &amp; Secret** | アプリを識別します。トークンの生成と OAuth 1.0a リクエストの署名に使用されます。 |
| **Bearer Token** | 公開データを読み取るための、アプリ単体での認証に使用されます。 |
| **Access Token &amp; Secret** | 自分のアカウントとしてリクエストを送信します（OAuth 1.0a）。 |
| **Client ID &amp; Secret** | ユーザーコンテキストのリクエストに対する OAuth 2.0 認証に使用されます。 |

<Warning>
  **すぐに保存してください。** 認証情報は一度しか表示されません。パスワードマネージャーや安全な保管庫に保存してください。紛失した場合は再生成する必要があり、その際に古い認証情報は無効になります。
</Warning>

***

<div id="which-credentials-do-you-need">
  ## どの認証情報が必要ですか？
</div>

<Tabs>
  <Tab title="公開データの読み取り">
    公開データをシンプルに読み取り専用で利用する場合は、**Bearer Token** を使用します。

    ```bash
    curl "https://api.x.com/2/users/by/username/xdevelopers" \
      -H "Authorization: Bearer $BEARER_TOKEN"
    ```

    主な用途: 投稿の検索、ユーザーの参照、トレンドの閲覧。
  </Tab>

  <Tab title="ユーザーとして動作する">
    ユーザーに代わって操作するには **OAuth 2.0**（推奨）または **OAuth 1.0a** を使用します。

    OAuth 2.0 では細かなスコープ制御が可能で、必要な権限だけをリクエストできます。

    主な用途: 投稿の作成、いいね、フォロー、DM へのアクセス。

    [OAuth 2.0 ガイド →](/ja/resources/fundamentals/authentication/oauth-2-0/overview)
  </Tab>

  <Tab title="自分自身として動作する">
    自分のアカウントとしてリクエストを行うには、**Access Token と Secret** を使用します。

    これらのトークンは、そのアプリを所有するアカウントを表します。

    主な用途: テスト、個人用ボット、自分用の自動化。
  </Tab>
</Tabs>

<div id="credential-security-best-practices">
  ## 認証情報のセキュリティに関するベストプラクティス
</div>

<CardGroup cols={2}>
  <Card title="環境変数を使用する" icon="terminal">
    認証情報をソースコード内にハードコードしないでください。
  </Card>

  <Card title="Git にコミットしない" icon="code-branch">
    認証情報を含むファイルを `.gitignore` に追加してください。
  </Card>

  <Card title="定期的にローテーションする" icon="arrows-rotate">
    セキュリティ対策として、認証情報を定期的に再発行してください。
  </Card>

  <Card title="最小限のスコープを使用する" icon="shield-check">
    アプリに必要な最小限の OAuth 権限だけをリクエストしてください。
  </Card>
</CardGroup>
