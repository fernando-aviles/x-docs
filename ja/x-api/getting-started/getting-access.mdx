X API を利用開始するには、サインアップ、App の作成、認証情報の保存という 3 つのステップを実行します。

<Button href="https://console.x.com">今すぐサインアップ</Button>

***

<div id="step-1-create-a-developer-account">
  ## ステップ 1: 開発者アカウントを作成する
</div>

<Steps>
  <Step title="開発者コンソールにアクセスする">
    [console.x.com](https://console.x.com) にアクセスし、Xアカウントでサインインします。
  </Step>

  <Step title="Developer Agreement に同意する">
    Developer Agreement およびポリシーを確認し、同意します。
  </Step>

  <Step title="プロフィールを完了する">
    API の利用方法についての基本情報を入力します。
  </Step>
</Steps>

***

<div id="step-2-create-an-app">
  ## ステップ 2: App を作成する
</div>

サインアップ後、App を作成して API 認証情報を取得します。

<Steps>
  <Step title="「New App」をクリック">
    開発者コンソールのダッシュボードから、新しい App を作成します。
  </Step>

  <Step title="App の詳細を入力">
    App の名前、説明、利用目的を入力します。
  </Step>

  <Step title="認証情報を生成">
    コンソールによって API キーとトークンが生成されます。
  </Step>
</Steps>

***

<div id="step-3-save-your-credentials">
  ## ステップ 3: 認証情報を保存する
</div>

認証要件に応じて、次のような認証情報が発行されます。

| Credential | Purpose |
|:-----------|:--------|
| **API Key &amp; Secret** | アプリを識別します。トークンを生成し、OAuth 1.0a リクエストに署名するために使用されます。 |
| **ベアラートークン** | 公開データを読み取るための App 専用認証です。 |
| **Access Token &amp; Secret** | 自分のアカウントを代表してリクエストを送信するために使用します (OAuth 1.0a) 。 |
| **Client ID &amp; Secret** | ユーザーコンテキストのリクエスト用の OAuth 2.0 認証です。 |

<Warning>
  **すぐに保存してください。** 認証情報は一度しか表示されません。パスワードマネージャーや安全な保管庫に保存してください。紛失した場合は再発行が必要になり (その際、古い認証情報は無効になります) 、元に戻すことはできません。
</Warning>

***

<div id="which-credentials-do-you-need">
  ## どの認証情報が必要ですか？
</div>

<Tabs>
  <Tab title="公開データの読み取り">
    公開データにシンプルに読み取り専用でアクセスするには、**ベアラートークン** を使用します。

    ```bash
    curl "https://api.x.com/2/users/by/username/xdevelopers" \
      -H "Authorization: Bearer $BEARER_TOKEN"
    ```

    最適な用途: 投稿の検索、ユーザー情報の取得、トレンドの閲覧。
  </Tab>

  <Tab title="ユーザーとして操作する">
    ユーザーの代理として操作するには、**OAuth 2.0** (推奨) または **OAuth 1.0a** を使用します。

    OAuth 2.0 ではスコープを細かく指定でき、必要な権限だけをリクエストできます。

    最適な用途: ポスト、いいね、フォロー、DM へのアクセス。

    [OAuth 2.0 ガイド →](/ja/resources/fundamentals/authentication/oauth-2-0/overview)
  </Tab>

  <Tab title="自分自身として操作する">
    自分のアカウントとしてリクエストを送信するには、**Access Token &amp; Secret** を使用します。

    これらのトークンは、その App を所有しているアカウントを表します。

    最適な用途: テスト、個人ボット、自分用の自動化。
  </Tab>
</Tabs>

<div id="credential-security-best-practices">
  ## 認証情報セキュリティのベストプラクティス
</div>

<CardGroup cols={2}>
  <Card title="環境変数を使用する" icon="terminal">
    ソースコード内に認証情報をハードコードしないでください。
  </Card>

  <Card title="Git にコミットしない" icon="code-branch">
    認証情報を含むファイルを `.gitignore` に追加してください。
  </Card>

  <Card title="定期的にローテーションする" icon="arrows-rotate">
    セキュリティ対策として、定期的に認証情報を再生成してください。
  </Card>

  <Card title="最小限のスコープを使用する" icon="shield-check">
    App に必要な OAuth 権限だけをリクエストしてください。
  </Card>
</CardGroup>
