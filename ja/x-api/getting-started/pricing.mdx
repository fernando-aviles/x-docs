<div id="deduplication">
  ## 重複排除
</div>

すべてのリソースは、**UTC を基準とした 24 時間（1 日）のウィンドウ**内で重複排除されます。あるリソース（投稿など）をリクエストして課金された場合、そのウィンドウ内に同じリソースを再度リクエストしても、追加料金は発生しません。

これは次のことを意味します。

* 同じ投稿を 1 日に複数回リクエストしても、課金は 1 回としてカウントされます
* 重複排除ウィンドウは UTC の午前 0 時にリセットされます
* これは、すべての課金対象リソース（投稿、ユーザーなど）に適用されます

<Note>
  重複排除は**厳密な保証ではない（ソフトな保証である）**ことに注意してください。大半のケースでは重複排除が行われますが、サービス障害などの特定の例外的なケースでは、リソースが重複排除されない場合があります。
</Note>

<div id="credit-balance">
  ## クレジット残高
</div>

クレジット残高は Developer Console 上に表示されます。API リクエストを行うと、クレジットはリアルタイムで消費されます。

<Warning>
  サービスの中断を避けるため、クレジット残高を定期的に確認してください。API への継続的なアクセスを確保するには、残高がゼロになる前にクレジットを追加してください。

  ***注:** アカウントのクレジット残高がわずかにマイナスになる場合があります。この場合、マイナス分を補うためにクレジットを追加するまで、API リクエストはブロックされます。*
</Warning>

<div id="auto-recharge">
  ### 自動チャージ
</div>

自動チャージを有効にすると、クレジット残高が自動的に補充され、サービスの中断を防ぐことができます。Developer Console で次の設定を行います。

| 設定 | 説明 |
|:--------|:------------|
| **Recharge amount** | 自動チャージが行われるときに追加される金額（例: $25） |
| **Trigger threshold** | 残高がこの金額を下回ったときに自動チャージが実行されます（例: $5） |

<Note>
  自動チャージを利用するには、デフォルトとして設定された保存済みの支払い方法が必要です。Developer Console から、またはサポートに連絡することで、いつでもキャンセルできます。
</Note>

<div id="spending-limits">
  ### 支出上限
</div>

請求サイクルごとに支出可能な最大額を設定して、コストを管理します。上限に達すると、次の請求サイクルまで API リクエストは停止されます。

| Option | Description |
|:-------|:------------|
| **Spending limit** | 請求サイクルごとの最大支出額として、具体的なドル金額を設定します |

<Tip>
  特に開発やテスト中の予期しない料金発生を防ぐために、支出上限を活用してください。
</Tip>

<div id="monitoring-usage">
  ## 利用状況の監視
</div>

[Usage エンドポイント](/ja/x-api/usage/introduction) を使用して、API の利用状況をプログラムから把握できます。

```bash
curl "https://api.x.com/2/usage/tweets" \
  -H "Authorization: Bearer $BEARER_TOKEN"
```

これは日次の投稿利用数を返し、次のことに役立ちます。

* 予算に対する利用量を追跡する
* 上限に近づいたときのアラートを設定する
* 利用量の多いエンドポイントを特定する
* 利用状況レポートを作成する
