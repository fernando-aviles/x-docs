<div id="deduplication">
  ## 重複排除
</div>

すべてのリソースは、**UTC における 1 日（24 時間）のウィンドウ**内で重複排除されます。あるリソース（投稿など）をリクエストして課金が発生した場合、同じリソースをそのウィンドウ内に再度リクエストしても、追加の料金は発生しません。

これは次のことを意味します:

* 同じ投稿を 1 日のうちに複数回リクエストしても、料金は 1 回分の課金としてカウントされる
* 重複排除ウィンドウは UTC の午前 0 時にリセットされる
* これはすべての課金対象リソース（投稿、ユーザーなど）に適用される

<Note>
  重複排除は**ソフトな保証**です。大半のケースでは行われますが、サービス障害などの特定の例外的なケースでは、リソースが重複排除されない場合があります。
</Note>

<div id="credit-balance">
  ## クレジット残高
</div>

クレジット残高は開発者コンソールに表示されます。クレジットは、API リクエストを行うたびにリアルタイムで差し引かれます。

<Warning>
  サービスの中断を避けるため、クレジット残高を定期的に確認してください。API へのアクセスを継続できるよう、残高がゼロになる前にクレジットを追加してください。

  ***注:** アカウントのクレジット残高がわずかにマイナスになる場合があります。この場合、マイナス残高を解消するためにクレジットを追加するまで、API リクエストはブロックされます。*
</Warning>

<div id="auto-recharge">
  ### 自動チャージ
</div>

自動チャージを有効にすると、クレジット残高が自動的に補充され、サービスの中断を防ぐことができます。開発者コンソールで次の設定を行います。

| 設定 | 説明 |
|:--------|:------------|
| **チャージ金額** | 自動チャージが実行されたときに追加される金額（例：$25） |
| **発動閾値** | 残高がこの金額を下回ったときに自動チャージが有効になる（例：$5） |

<Note>
  自動チャージを利用するには、デフォルトの支払い方法として保存された決済手段が必要です。自動チャージは、開発者コンソールから、またはサポートに連絡することで、いつでも停止できます。
</Note>

<div id="spending-limits">
  ### 支出上限
</div>

請求サイクルごとに支出できる最大金額を設定して、コストを管理できます。上限に達すると、次の請求サイクルまで API リクエストは停止されます。

| Option | Description |
|:-------|:------------|
| **Spending limit** | 請求サイクルごとの最大支出額として、特定のドル金額を設定します |

<Tip>
  特に開発およびテスト中の予期しない料金を防ぐために、支出上限を活用してください。
</Tip>

<div id="monitoring-usage">
  ## 利用状況の監視
</div>

[Usage エンドポイント](/ja/x-api/usage/introduction) を使用して、API の利用状況をプログラムによって追跡できます。

```bash
curl "https://api.x.com/2/usage/tweets" \
  -H "Authorization: Bearer $BEARER_TOKEN"
```

これは日別の投稿利用回数を返し、次のことに役立ちます。

* 予算に対する利用量を追跡する
* 上限に近づいたときにアラートを設定する
* 利用量の多いエンドポイントを特定する
* 利用状況レポートを作成する
