X API v2 では **従量課金** モデルを採用しています。課金は、App 単位で追跡される実際の API 利用量に基づいて行われます。

***

<div id="how-billing-works">
  ## 課金の仕組み
</div>

| 概念 | 説明 |
|:--------|:------------|
| **クレジット制** | 事前にクレジットを購入し、API を使うごとに差し引かれます |
| **リクエスト単位の料金** | エンドポイントごとに料金が異なります |
| **リアルタイム追跡** | 開発者コンソールで利用状況をリアルタイムに確認できます |
| **上限なし** | 必要なだけ利用可能で、月間の利用上限はありません |

***

<div id="deduplication">
  ## 重複排除
</div>

<Note>
  **日次の重複排除**: 同じ投稿が1日のうちに複数のクエリから返された場合でも、請求上は1回分としてのみカウントされます。
</Note>

これは次のことを意味します。

* 同じ投稿を1日のうちに複数回取得する = 課金は1回分
* 翌日に同じ投稿を再取得する = 課金がさらに1回分発生
* 同じリクエスト内に含まれる異なる投稿 = それぞれ個別にカウント

<div id="monitoring-usage">
  ## 利用状況の監視
</div>

[開発者コンソール](https://console.x.com)で利用状況を確認できます。

| 指標 | 説明 |
|:-------|:------------|
| **Total usage** | 請求期間中に取得された投稿数 |
| **By endpoint** | エンドポイント種別ごとの内訳 |
| **By app** | 開発者 App ごとの利用状況 |
| **Cost tracking** | コストのリアルタイム計算 |
| **Credit balance** | 残っている前払いクレジット |

<div id="pricing-details">
  ## 料金の詳細
</div>

各エンドポイントおよび操作ごとの最新の料金情報は、[開発者コンソール](https://console.x.com)で確認できます。

料金は次の要因によって異なる場合があります。

* エンドポイントのtype（search / lookup / stream など）
* 操作（read / write）
* データの範囲（recent / full-archive）

<div id="faqs">
  ## よくある質問
</div>

<Accordion title="クレジットを使い切るとどうなりますか？">
  クレジットを追加購入するまで、API リクエストはエラーになります。中断を避けるために残高アラートを設定してください。
</Accordion>

<Accordion title="月額の最低利用料はありますか？">
  いいえ、ありません。使用した分だけお支払いいただきます。利用量も費用もゼロの月があってもかまいません。
</Accordion>

<Accordion title="ストリーミングはどのように課金されますか？">
  filtered stream を通じて配信された一意の投稿ごとに利用分としてカウントされ、日次で重複排除が行われます。
</Accordion>

<Accordion title="失敗したリクエストもカウントされますか？">
  いいえ。データを返す成功したレスポンスのみが課金対象となります。
</Accordion>
