X API では、エンドポイントパスにバージョン番号を含めることで、進化を可能にしながら安定性を確保しています。バージョニング戦略を理解することで、連携の計画を立て、常に最新の状態を維持できます。

***

<div id="current-versions">
  ## 現行のバージョン
</div>

| Version | Status | Description |
|:--------|:-------|:------------|
| **v2** | 現行 | 最新のエンドポイント、柔軟な料金体系、すべての新機能に対応 |
| **v1.1** | レガシー | サポートは限定的で、アップデートは最小限 |
| **Enterprise** | 提供中 | 専任サポート付きの大規模アクセス向け |

<Tip>
  新しいプロジェクトでは必ず **X API v2** を使用してください。新機能はすべて X API v2 に追加されます。
</Tip>

***

<div id="version-in-urls">
  ## URL 内のバージョン
</div>

バージョン番号はエンドポイントパスに含まれます。

```
https://api.x.com/2/tweets
                   ^
                   version
```

<div id="breaking-vs-non-breaking-changes">
  ## 互換性を破る変更と互換性を保つ変更
</div>

<div id="breaking-changes-require-code-updates">
  ### 破壊的変更（コードの修正が必要）
</div>

これらの変更はメジャーバージョンアップ時にのみ発生します：

* エンドポイントの削除
* レスポンスフィールドの削除
* クエリパラメータの削除
* 新しい必須パラメータの追加
* フィールドのデータ型の変更
* フィールドまたはリソースの名称変更
* レスポンスコードまたはエラーの種類の変更
* 認可スコープの変更

<div id="non-breaking-changes-additive">
  ### 後方互換性を損なわない変更（追加）
</div>

これらはバージョンを変更せず、いつでも行うことができます。

* 新しいエンドポイントの追加
* 新しいオプションパラメーターの追加
* 新しいレスポンスのフィールドの追加
* 新しい OAuth スコープの追加
* エラーメッセージ文言の変更
* プライバシー／セキュリティ上の理由によるフィールドの null 設定

<div id="release-schedule">
  ## リリーススケジュール
</div>

| タイプ | 頻度 | 通知 |
|:-----|:----------|:-------|
| **メジャーバージョン** | 多くても年1回 | 移行ガイドを提供します |
| **後方互換性を損なわない変更** | 継続的 | 変更履歴を更新します |
| **セキュリティパッチ** | 必要に応じて | 現行バージョンに適用されることがあります |

***

<div id="deprecation-policy">
  ## 非推奨ポリシー
</div>

新しいメジャーバージョンをリリースした場合：

1. **非推奨**: 以前のバージョンを非推奨としてマークします
2. **サポート期間**: 非推奨バージョンは、定められた期間中は引き続き利用できます
3. **廃止**: 非推奨バージョンは廃止されます

<div id="definitions">
  ### 定義
</div>

| ステータス | 意味 |
|:-------|:--------|
| **Active** | 新機能追加や不具合修正を含め、完全にサポートされています |
| **Deprecated** | 新機能の追加は行われません。致命的なバグにのみ対応します。利用は推奨されません |
| **Retired** | もはや利用できません |
