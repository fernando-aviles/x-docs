X API では、エンドポイントパスにバージョン番号を含めることで、安定性を保ちつつ進化を可能にしています。バージョニング戦略を理解しておくことで、連携を計画し、常に最新の仕様に追随できます。

***

<div id="current-versions">
  ## 現行バージョン
</div>

| Version | Status | Description |
|:--------|:-------|:------------|
| **v2** | 現行 | 最新のエンドポイント、柔軟な料金体系、すべての新機能を提供 |
| **v1.1** | レガシー | サポートは限定的で、更新は最小限 |
| **Enterprise** | 提供中 | 専任サポート付きの大規模データアクセス |

<Tip>
  新規プロジェクトはすべて **X API v2** を使用してください。新機能はすべてこのバージョンで提供されます。
</Tip>

***

<div id="version-in-urls">
  ## URL のバージョン
</div>

バージョン番号はエンドポイントのパスに含まれます。

```
https://api.x.com/2/tweets
                   ^
                   version
```

<div id="breaking-vs-non-breaking-changes">
  ## 後方互換性を破る変更と後方互換性を保つ変更
</div>

<div id="breaking-changes-require-code-updates">
  ### 互換性を壊す変更（コードの更新が必要）
</div>

これらの変更はメジャーバージョンアップ時にのみ行われます。

* エンドポイントの削除
* レスポンスフィールドの削除
* クエリパラメータの削除
* 新しい必須パラメータの追加
* フィールドのデータタイプの変更
* フィールドやリソース名の変更
* レスポンスコードまたはエラータイプの変更
* 認可スコープの変更

<div id="non-breaking-changes-additive">
  ### 後方互換性を損なわない変更（追加的）
</div>

これらはバージョン変更を行わずに、いつでも実施できます：

* 新しいエンドポイントの追加
* 新しいオプションパラメータの追加
* 新しいレスポンスフィールドの追加
* 新しい OAuth スコープの追加
* エラーメッセージ文言の変更
* プライバシー／セキュリティ上の理由によるフィールドの null 設定

<div id="release-schedule">
  ## リリーススケジュール
</div>

| タイプ | 頻度 | 通知 |
|:-----|:----------|:-------|
| **メジャーバージョン** | 年1回を上限 | マイグレーションガイドを提供 |
| **互換性を損なわない変更** | 随時 | 変更履歴を更新 |
| **セキュリティパッチ** | 必要に応じて | 現行バージョンに適用される場合があります |

***

<div id="deprecation-policy">
  ## 非推奨ポリシー
</div>

新しいメジャーバージョンをリリースする際には、次のように扱います。

1. **非推奨化**: 既存バージョンを非推奨としてマークします
2. **サポート期間**: 非推奨バージョンは、定められた期間中は引き続き利用できます
3. **提供終了**: 非推奨バージョンは提供を終了し、利用できなくなります

<div id="definitions">
  ### 定義
</div>

| ステータス | 意味 |
|:-------|:--------|
| **Active** | 新機能の追加および不具合修正を含め、継続的にサポートされています |
| **Deprecated** | 新機能は追加されず、重大なバグのみが修正対象となり、利用は非推奨です |
| **Retired** | もはや利用できません |
