X API v2 は、すべてのエンドポイントで一貫したパターンになるように設計されています。1 つのエンドポイントの動作を理解すれば、同じパターンを他のあらゆる場所にも適用できます。

***

<div id="consistent-patterns">
  ## 一貫したパターン
</div>

<div id="url-structure">
  ### URL 構造
</div>

すべての v2 エンドポイントは一貫したパターンに従っています。

```
/version/resource/{id}?parameters
/version/resource/verb?parameters
```

例：

```
/2/tweets/1234567890                    # Get a specific post
/2/tweets/search/recent                 # Search recent posts
/2/users/by/username/xdevelopers        # Get user by username
/2/users/1234/followers                 # ユーザーのフォロワーを取得
```

<div id="response-structure">
  ### レスポンス構造
</div>

すべてのレスポンスは同じトップレベルの構造になっています。

```json
{
  "data": { ... },       // プライマリオブジェクト
  "includes": { ... },   // 展開されたオブジェクト
  "meta": { ... },       // ページネーション、カウント
  "errors": [ ... ]      // 部分的なエラー(存在する場合)
}
```

<div id="id-format">
  ### ID の形式
</div>

すべての ID は、言語間の互換性を確保するため、文字列型で返されます。

```json
{
  "id": "1234567890123456789",
  "author_id": "2244994945"
}
```

***

<div id="fields-and-expansions">
  ## フィールドと展開
</div>

同じ [フィールド](/ja/x-api/fundamentals/fields) および [展開](/ja/x-api/fundamentals/expansions) パラメーターを一貫して利用できます。

| オブジェクト | フィールドパラメーター | 適用範囲 |
|:-------|:-----------------|:-------------|
| 投稿 | `tweet.fields` | 投稿を返すすべてのエンドポイント |
| User | `user.fields` | ユーザーを返すすべてのエンドポイント |
| Media | `media.fields` | メディアの展開をサポートするすべてのエンドポイント |
| Poll | `poll.fields` | Poll の展開をサポートするすべてのエンドポイント |
| Place | `place.fields` | Place の展開をサポートするすべてのエンドポイント |

***

<div id="object-schemas">
  ## オブジェクトスキーマ
</div>

同じオブジェクトタイプは、どのエンドポイントから返されても同じフィールドを持ちます。

* search からの投稿は、lookup からの投稿と同じフィールドを持ちます
* followers からの User は、search からの User と同じフィールドを持ちます
* 展開されたオブジェクトは、対応する単体オブジェクトと同じフィールドを持ちます

***

<div id="authentication">
  ## 認証
</div>

すべてのエンドポイントで同じ認証方法を使用します。

| 方法 | ヘッダー形式 |
|:-------|:--------------|
| Bearer Token | `Authorization: Bearer {token}` |
| OAuth 1.0a | `Authorization: OAuth {parameters}` |
| OAuth 2.0 | `Authorization: Bearer {user_token}` |

***

<div id="error-handling">
  ## エラー処理
</div>

エラーは一貫したフォーマットで返されます。

```json
{
  "title": "Invalid Request",
  "detail": "The query parameter is missing",
  "type": "https://api.x.com/2/problems/invalid-request"
}
```

[すべてのエラータイプを確認 →](/ja/x-api/fundamentals/response-codes-and-errors)

***

<div id="pagination">
  ## ページネーション
</div>

すべてのページネーション対応エンドポイントは同じトークンシステムを使用しています。

| パラメータ | 説明 |
|:----------|:------------|
| `max_results` | 1ページあたりの結果数 |
| `pagination_token` | `next_token` または `previous_token` からのトークン |

[ページネーションの詳細 →](/ja/x-api/fundamentals/pagination)

***

<div id="naming-conventions">
  ## 命名規則
</div>

* アメリカ英語の綴りを使用する（`favourites` ではなく `favorites`）
* フィールド名にはスネークケースを使用する（`author_id`、`created_at`）
* 用語を一貫して使用する（フィールドでは `repost_count` ではなく `retweet_count`）

***

<div id="empty-values">
  ## 空の値
</div>

値のないフィールドは、`null` として返されるのではなく、レスポンスから省略されます。

```json
// User without a bio
{
  "id": "1234",
  "name": "Example User",
  "username": "example"
  // "description" は省略されており、null ではない
}
```

***

<div id="entity-consistency">
  ## エンティティの整合性
</div>

`entities` オブジェクトには、テキストから解析されたエンティティのみが含まれます:

* `urls`
* `hashtags`
* `mentions`
* `cashtags`

メディアと投票は `entities` ではなく、`attachments` に含まれます。
