レート制限は、各エンドポイントに対して送信できるリクエスト数を制御します。制限を超過すると、ウィンドウがリセットされるまで 429 エラーが返されます。

***

<div id="how-rate-limits-work">
  ## レート制限の仕組み
</div>

| 概念 | 説明 |
|:--------|:------------|
| **時間枠** | 通常は 15 分または 24 時間 |
| **ユーザー単位の制限** | OAuth 1.0a または OAuth 2.0 のユーザートークンごとに適用 |
| **アプリ単位の制限** | Bearer Token（アプリのみ / app-only）ごとに適用 |
| **エンドポイント単位** | 各エンドポイントごとに固有の制限が設定されています |

***

<div id="checking-your-limits">
  ## レート制限の確認
</div>

レスポンスヘッダーに現在のレート制限の状態が表示されます。

```
x-rate-limit-limit: 900
x-rate-limit-remaining: 847
x-rate-limit-reset: 1705420800
```

| Header                   | Description                     |
| :----------------------- | :------------------------------ |
| `x-rate-limit-limit`     | 許可される最大リクエスト数                   |
| `x-rate-limit-remaining` | レート制限ウィンドウ内で残っているリクエスト数         |
| `x-rate-limit-reset`     | レート制限ウィンドウがリセットされる Unix タイムスタンプ |

<div id="handling-rate-limits">
  ## レート制限の扱い方
</div>

レート制限に達すると、HTTP ステータスコード 429 のレスポンスが返されます。

```json
{
  "errors": [{
    "code": 88,
    "message": "Rate limit exceeded"
  }]
}
```

<div id="recovery-strategy">
  ### 復旧戦略
</div>

1. `x-rate-limit-reset` ヘッダーでウィンドウのリセット時刻を確認する
2. 再試行する前にその時刻まで待機する
3. 必要に応じて指数バックオフを適用する

```python
import time

def make_request_with_backoff(url, headers):
    response = requests.get(url, headers=headers)
    
    if response.status_code == 429:
        reset_time = int(response.headers.get('x-rate-limit-reset', 0))
        wait_time = max(reset_time - time.time(), 60)
        time.sleep(wait_time)
        return make_request_with_backoff(url, headers)
    
    return response
```

  ## レート制限と課金
</div>

レート制限と課金は別々に扱われます。

| 概念 | 目的 |
|:--------|:--------|
| **レート制限** | システムの安定性を保つためにリクエスト頻度を制御する |
| **利用ベース課金** | 取得したデータに対して料金を請求する（従量課金） |

レート制限の範囲内に収まっていても利用料金が発生する場合があり、また、追加料金が発生しなくてもレート制限に達する場合があります。

***

  ## エンタープライズ向けレート制限
</div>

エンタープライズのお客様には、個別のレート制限が適用されます。担当のアカウントマネージャーにお問い合わせいただくか、[Enterprise アクセスを申請](/ja/enterprise/forms/enterprise-api-interest)してください。
