X API は標準的な HTTP ステータスコードを使用します。成功したリクエストでは 2xx 系コードが返され、エラーの場合は詳細を含むレスポンス本文とともに 4xx または 5xx 系コードが返されます。

***

<div id="http-status-codes">
  ## HTTP ステータスコード
</div>

<div id="success-codes">
  ### 成功コード
</div>

| Code | Meaning | Description |
|:-----|:--------|:------------|
| **200** | OK | リクエストは成功しました |
| **201** | Created | リソースが作成されました（POST リクエスト） |
| **204** | No Content | レスポンスボディなしで成功しました（DELETE リクエスト） |

<div id="client-error-codes">
  ### クライアントエラーコード
</div>

| Code | Meaning | Common causes |
|:-----|:--------|:--------------|
| **400** | Bad Request | 無効な JSON、不正なクエリ、必須パラメータの不足 |
| **401** | Unauthorized | 認証情報が無効または不足している |
| **403** | Forbidden | 認証は有効だが、このリソースまたは操作を行う権限がない |
| **404** | Not Found | リソースが存在しないか、削除されている |
| **409** | Conflict | ストリームにルールが設定されていない（filtered stream のみ） |
| **429** | Too Many Requests | レート制限または利用上限を超過 |

<div id="server-error-codes">
  ### サーバーエラーコード
</div>

| コード | 意味 | 対処方法 |
|:-----|:--------|:-----------|
| **500** | 内部サーバーエラー | しばらく待ってから再試行し、[ステータスページ](/ja/status) を確認してください |
| **502** | 不正なゲートウェイ | しばらく待ってから再試行してください |
| **503** | サービス利用不可 | X に高負荷がかかっています。しばらく待ってから再試行してください |
| **504** | ゲートウェイタイムアウト | しばらく待ってから再試行してください |

***

<div id="error-response-format">
  ## エラーレスポンスの形式
</div>

エラーレスポンスには、構造化された詳細情報が含まれます。

```json
{
  "title": "Invalid Request",
  "detail": "The 'query' parameter is required.",
  "type": "https://api.x.com/2/problems/invalid-request"
}
```

| フィールド    | 説明              |
| :------- | :-------------- |
| `type`   | エラーの種類を識別する URI |
| `title`  | エラーの簡潔な説明       |
| `detail` | このエラーに関する具体的な説明 |

エラーの種類に応じて、追加のフィールドが含まれる場合があります。

***

<div id="error-types">
  ## エラータイプ
</div>

| タイプ | 説明 |
|:-----|:------------|
| `about:blank` | 汎用的なエラー（HTTPステータスコードを参照） |
| `.../invalid-request` | リクエストが不正な形式である、またはパラメータが無効 |
| `.../resource-not-found` | 投稿、ユーザー、その他のリソースが存在しない |
| `.../not-authorized-for-resource` | 非公開／保護されたコンテンツへのアクセス権がない |
| `.../client-forbidden` | アプリが登録されていない、または必要なアクセス権がない |
| `.../usage-capped` | 利用上限を超過している |
| `.../rate-limit-exceeded` | レート制限を超過している |
| `.../streaming-connection` | ストリーミング接続の問題 |
| `.../rule-cap` | Filtered Stream のルール数が上限を超えている |
| `.../invalid-rules` | ルールの構文エラー |
| `.../duplicate-rules` | ルールがすでに存在する |

***

<div id="partial-errors">
  ## 部分的なエラー
</div>

一部のリクエストは部分的に成功する場合があります。200 レスポンスには `data` と `errors` の両方が含まれている場合があります。

```json
{
  "data": [
    {"id": "123", "text": "Hello"}
  ],
  "errors": [
    {
      "resource_id": "456",
      "resource_type": "tweet",
      "title": "Not Found Error",
      "detail": "Could not find tweet with id: [456].",
      "type": "https://api.x.com/2/problems/resource-not-found"
    }
  ]
}
```

これは、複数のリソースを一度にリクエストした際に、その一部が利用できない場合に発生します。

<div id="troubleshooting-common-errors">
  ## よく発生するエラーのトラブルシューティング
</div>

<Accordion title="401 Unauthorized">
  **認証を確認する:**

  * エンドポイントに対して正しい認証方式を使用していることを確認する
  * 資格情報が再生成されていないことを確認する
  * `Authorization` ヘッダーの形式を確認する
  * OAuth 1.0a の場合は署名計算が正しいか検証する

  [認証ガイド →](/ja/resources/fundamentals/authentication/overview)
</Accordion>

<Accordion title="403 Forbidden">
  **アクセスを確認する:**

  * アプリがこのエンドポイントへのアクセス権を持っていることを確認する
  * 一部のエンドポイントでは特定の登録や承認が必要になる場合がある
  * ユーザーコンテキストのエンドポイントには適切な OAuth スコープが必要
  * リソースが非公開または保護対象である可能性がある
</Accordion>

<Accordion title="429 Too Many Requests">
  **レート制限時の対応:**

  * 再試行可能なタイミングは `x-rate-limit-reset` ヘッダーで確認する
  * 指数バックオフを実装する
  * レスポンスのキャッシュを検討する
  * リクエストを時間枠全体に分散する

  [レート制限ガイド →](/ja/x-api/fundamentals/rate-limits)
</Accordion>

<Accordion title="400 Bad Request">
  **リクエストを修正する:**

  * JSON 構文を検証する
  * 必須パラメーターが欠けていないか確認する
  * パラメーターのタイプ（文字列と数値）を確認する
  * クエリ内の特殊文字をエスケープする
</Accordion>

<Accordion title="Missing expected posts">
  **次の要因を確認する:**

  * 保護されたアカウントの投稿は、認可がある場合にのみ表示される
  * 削除された投稿は 404 を返す
  * 一部の投稿は特定の地域では表示が制限されることがある
  * 検索クエリの構文が正しいことを確認する
</Accordion>

<Accordion title="Stream disconnections">
  **再接続を処理する:**

  * バックオフ付きの自動再接続を実装する
  * 取り逃した `data` を復元するためのリカバリ機能を使用する
  * バッファのフル状態による切断（クライアントの処理が追いついていない）を確認する
  * 少なくとも 1 つのストリームルールが存在することを確認する

  [ストリーミングガイド →](/ja/x-api/posts/filtered-stream/integrate/handling-disconnections)
</Accordion>

<div id="rate-limit-headers">
  ## レート制限ヘッダー
</div>

すべてのレスポンスにはレート制限に関する情報が含まれています。

```
x-rate-limit-limit: 900
x-rate-limit-remaining: 847
x-rate-limit-reset: 1705420800
```

| ヘッダー                     | 説明                         |
| :----------------------- | :------------------------- |
| `x-rate-limit-limit`     | 現在のウィンドウにおけるリクエスト上限数       |
| `x-rate-limit-remaining` | 残りのリクエスト数                  |
| `x-rate-limit-reset`     | ウィンドウがリセットされる Unix タイムスタンプ |
