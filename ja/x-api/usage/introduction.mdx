Usage エンドポイントを使用すると、利用した投稿数を含む API の使用状況を監視できます。コストを管理し、利用上限を超えないようにするために、使用状況をプログラムで追跡してください。

<div id="overview">
  ## 概要
</div>

<CardGroup cols={2}>
  <Card title="投稿の利用状況" icon="chart-simple">
    消費された投稿数を追跡します
  </Card>

  <Card title="日別の内訳" icon="calendar-days">
    日別の利用状況を表示します
  </Card>

  <Card title="アプリ単位" icon="gauge">
    アプリ単位での利用状況を監視します
  </Card>
</CardGroup>

***

<div id="endpoint">
  ## エンドポイント
</div>

| Method | Endpoint | Description |
|:-------|:---------|:------------|
| GET | [`/2/usage/tweets`](/ja/x-api/usage/get-usage) | 投稿の利用状況に関するデータを取得 |

***

<div id="response-data">
  ## レスポンス data
</div>

レスポンスには、日次の投稿消費数が含まれます。

```json
{
  "data": {
    "daily_project_usage": [
      {
        "date": "2024-01-15",
        "usage": [
          {
            "app_id": "12345678",
            "tweets_consumed": 15420
          }
        ]
      }
    ],
    "project_id": "1234567890",
    "project_cap": 10000000
  }
}
```

<div id="fields">
  ### フィールド
</div>

| フィールド | 説明 |
|:------|:------------|
| `daily_project_usage` | 日別利用状況を表す data の配列 |
| `date` | YYYY-MM-DD 形式の日付 |
| `app_id` | アプリの id |
| `tweets_consumed` | その日に消費された投稿数 |
| `project_cap` | 月間投稿上限 |
--------------------------

<div id="use-cases">
  ## リクエスト例
</div>

```bash
curl "https://api.x.com/2/usage/tweets" \
  -H "Authorization: Bearer $BEARER_TOKEN"
```

***

<div id="getting-started">
  ## ユースケース
</div>

* **コスト監視** — プランの上限に対する利用状況を追跡する
* **アラート** — 上限に近づいたときのアラートを設定する
* **最適化** — 消費量の多いエンドポイントを特定する
* **レポーティング** — 利用状況レポートを作成する

<Tip>
  リソースは UTC に基づく 24 時間ウィンドウ内で重複排除されるため、同じリソースを 1 日のうちに複数回リクエストしても、課金上は 1 回分としてカウントされます。 [料金について詳しく見る →](/ja/x-api/getting-started/pricing)
</Tip>
