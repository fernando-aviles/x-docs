ストリーミングデータを利用する際には、接続時間を最大化し、条件に一致したすべてのデータを受信することが基本的な目標となります。つまり、冗長接続を活用し、切断を自動的に検知して迅速に再接続し、失われたデータを復旧するための計画を用意しておくことが重要です。

このインテグレーションガイドでは、冗長接続、バックフィル、および復旧といった、さまざまな冗長化および復旧機能について説明します。
 

<div id="redundant-connections">
  ## 冗長接続
</div>

冗長接続を使用すると、ストリームに対して同時に複数の接続を確立できます。これにより、2 つの別個のコンシューマーで同じストリームに接続し、両方の接続から同じデータを受信することで冗長性が確保されます。したがって、1 つのストリームが切断された場合やアプリケーションのプライマリサーバーが障害を起こした場合など、さまざまな状況に備えて、アプリにホットフェイルオーバーを実現できます。

冗長ストリームを使用するには、プライマリ接続で使用しているものと同じ URL に接続するだけです。ストリームのデータは、両方の接続を通じて送信されます。

<div id="backfill">
  ## バックフィル
</div>

切断を検知したら、システムはストリームに自動的に再接続できるようにしておく必要があります。可能であれば、適切なリカバリ機能を使って data をバックフィルできるよう、切断がどのくらいの時間続いたかを記録しておくべきです。 

切断時間が 5 分以下であることが分かっている場合は、バックフィル用パラメータ `backfillMinutes` を使用できます。このパラメータを `GET /powerstream` リクエストに付与すると、直近 1〜5 分以内に設定しているルールにマッチした投稿を受け取ることができます。通常、これらの古い投稿は新しくマッチした投稿よりも先に配信され、さらに投稿の重複排除は行われません。つまり、切断が 90 秒だったにもかかわらず 2 分分のバックフィル data を要求した場合、30 秒分の重複した投稿を受け取ることになり、システム側でそれを許容できる必要があります。以下は、バックフィルパラメータを付与したリクエストの例です。

`curl 'https://api.x.com/2/powerstream?backfillMinutes=5' -H "Authorization: Bearer $ACCESS_TOKEN"`

切断時間が 5 分を超えていた場合は、[recent search endpoint](/ja/x-api/posts/search/introduction) またはリカバリ機能を利用して、取り逃した data をリクエストできます。 

<div id="recovery">
  ## リカバリ
</div>

5分間のバックフィル・ウィンドウ内に再接続できなかった場合、Recovery 機能を使用して直近24時間以内の取り逃したデータを復旧できます。

ストリーミングリカバリ機能により、バックフィル・ウィンドウを最大24時間まで延長できます。Recovery を使用すると、取り逃したデータの期間を「再生」できます。`startTime` と `endTime` リクエストパラメータを使用して接続リクエストを行うと、リカバリストリームが開始されます。接続後、Recovery は指定された期間のストリームを再ストリーミングし、その後切断されます。  

|     |     |     |
| :--- | :--- | :--- |
| **名前** | **タイプ** | **説明** |
| `startTime` | date (ISO 8601) | YYYY-MM-DDTHH:mm:ssZ (ISO 8601/RFC 3339)。<br /><br />復旧を開始する UTC の開始時刻を示す日時。 |
| `endTime` | date (ISO 8601) | YYYY-MM-DDTHH:mm:ssZ (ISO 8601/RFC 3339)。<br /><br />復旧を終了する UTC の終了時刻を示す日時。 |

リクエスト URL の例: `https://api.x.com/2/powerstream?startTime=2022-07-12T15:10:00Z&endTime=2022-07-12T15:20:00Z`
