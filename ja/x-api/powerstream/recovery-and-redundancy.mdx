ストリーミングデータを利用する場合、接続時間を最大化し、マッチしたすべてのデータを受信することが重要な目標です。つまり、冗長接続を活用し、切断を自動的に検出して迅速に再接続し、失われたデータを復旧するための計画を用意しておくことが重要です。

このインテグレーションガイドでは、冗長接続、バックフィル、およびリカバリといった、さまざまな復旧および冗長化機能について説明します。
 

<div id="redundant-connections">
  ## 冗長接続
</div>

冗長接続を使用すると、ストリームに同時に複数の接続を確立できます。これにより、2 つの別々のコンシューマーで同じストリームに接続し、両方の接続を通じて同じ data を受信することで冗長性を確保できます。これによって、1 つのストリームが切断された場合やアプリケーションのプライマリサーバーが障害を起こした場合など、さまざまな状況に対してアプリでホットフェイルオーバーを実現できます。

冗長ストリームを使用するには、プライマリ接続に使用しているものと同じ URL に接続するだけです。ストリームの data は、両方の接続を通じて送信されます。

<div id="backfill">
  ## バックフィル
</div>

切断を検知したら、システムはストリームへ自動的に再接続できるようにしておく必要があります。可能であれば、どのくらいの時間切断されていたかを記録し、適切なリカバリ機能を使用してデータをバックフィルできるようにしてください。 

切断時間が5分以下であると判断できた場合は、バックフィルのためのパラメータ `backfillMinutes` を使用できます。`GET /powerstream` リクエストにこのパラメータを指定すると、過去1〜5分間に設定しているルールにマッチした投稿を受信します。通常、これらの古い投稿は新たにマッチした投稿よりも先に配信され、また投稿の重複排除は行われません。つまり、90秒間切断されていた状態で2分分のバックフィルデータを要求した場合、30秒分の重複した投稿を受け取ることになり、システム側でそれを許容できるようにしておく必要があります。バックフィルパラメータを使ったリクエスト例は次のとおりです。

`curl 'https://api.x.com/2/powerstream?backfillMinutes=5' -H "Authorization: Bearer $ACCESS_TOKEN"`

切断時間が5分を超えていると判断できた場合は、[recent search エンドポイント](/ja/x-api/posts/search/introduction) かリカバリ機能を利用して、取り逃したデータをリクエストできます。 

<div id="recovery">
  ## リカバリ
</div>

5 分間のバックフィルウィンドウ内に再接続できない場合でも、リカバリ機能を使用すると直近 24 時間以内に取り逃したデータを復元できます。

ストリーミングリカバリ機能を使用すると、バックフィルウィンドウを 24 時間まで拡張できます。リカバリ機能を利用すると、取り逃したデータの期間を「再生」できます。`startTime` と `endTime` リクエストパラメータを指定して接続リクエストを行うと、リカバリストリームが開始されます。接続が確立されると、リカバリ機能は指定された期間のデータを再ストリームし、その後切断されます。  

|     |     |     |
| :--- | :--- | :--- |
| **名前** | **タイプ** | **説明** |
| `startTime` | date (ISO 8601) | YYYY-MM-DDTHH:mm:ssZ (ISO 8601/RFC 3339)。<br /><br />復元を開始する UTC の開始日時を示します。 |
| `endTime` | date (ISO 8601) | YYYY-MM-DDTHH:mm:ssZ (ISO 8601/RFC 3339)。<br /><br />復元を終了する UTC の終了日時を示します。 |

リクエスト URL の例: `https://api.x.com/2/powerstream?startTime=2022-07-12T15:10:00Z&endTime=2022-07-12T15:20:00Z`
