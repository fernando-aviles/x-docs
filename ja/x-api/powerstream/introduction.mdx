Powerstream は、公開 X データにアクセスするための、最速のリアルタイムストリーミング API です。レガシーの GNIP Powetrack API と同様に、キーワード、演算子、メタデータに基づいて投稿をフィルタリングするルールを使用します。Powerstream エンドポイントへの永続的な HTTP 接続が確立されると、ほぼリアルタイムで条件に一致した投稿の受信を開始できます。

現在、Powerstream は最大 1,000 個のルールをサポートしており、各ルールは 2,048 文字まで指定できます。

<div id="key-features">
  ## 主な機能:
</div>

* **リアルタイムのデータ配信**: ルールにマッチするデータをほぼリアルタイムで取得できます。
* **精密なフィルタリング**: 演算子付きのブールクエリを使用して、探しているデータだけを正確にフィルタリングできます。
* **配信方式**: HTTP/1.1 のチャンク転送エンコーディングによる JSON レスポンス。
* **ローカルデータセンターサポート**: レプリケーション遅延を回避してレイテンシを抑えるため、ローカルデータセンターからの投稿のみを取得できます。

<Note>
  Powerstream API は、一部の Enterprise プランで利用可能なプレミアム機能です。

  Powerstream へのアクセスに関心がある場合や、Enterprise 向けサービスの詳細をご希望の場合は、[Enterprise Request Form](/ja/forms/enterprise-api-interest) から営業チームまでお問い合わせください。
  Powerstream がどのようにお客様のニーズにお応えできるか、喜んでご相談させていただきます。
</Note>

<div id="quick-start">
  ## クイックスタート
</div>

このセクションでは、Python と `requests` ライブラリを使用して PowerStream エンドポイントの利用を迅速に開始する方法を紹介します。`pip install requests` でインストールしてください。すべての例は OAuth 2.0 Bearer Token 認証を使用します。`YOUR_BEARER_TOKEN` を実際のトークンに置き換えてください（`os.getenv('BEARER_TOKEN')` などを使って安全に管理してください）。

各エンドポイントについて、コードスニペットとともに説明します。ファイルの先頭に次の import 文があるものとします。

```python
import requests
import json
import time
import sys
import os  # 環境変数用
```

<div id="setup">
  ### セットアップ
</div>

```python
bearer_token = os.getenv('BEARER_TOKEN') or "YOUR_BEARER_TOKEN"  # セキュリティのため環境変数を使用
base_url = "https://api.x.com/2/powerstream"
rules_url = f"{base_url}/rules"  # ルール管理用
headers = {
   "Authorization": f"Bearer {bearer_token}",
   "Content-Type": "application/json"
}
```

<div id="1-create-rules-post-rules">
  ### 1. ルールを作成 (POST /rules)
</div>

ストリームをフィルターするためのルールを追加します。

```python
data = {
   "rules": [
       {
           "value": "(cat OR dog) lang:en -is:retweet",
           "tag": "pet-monitor"
       },
       # 必要に応じてルールを追加してください（最大100件まで）
   ]
}

response = requests.post(rules_url, headers=headers, json=data)
if response.status_code == 201:
   rules_added = response.json().get("data", {}).get("rules", [])
   print("Rules added:")
   for rule in rules_added:
       print(f"ID: {rule['id']}, Value: {rule['value']}, Tag: {rule.get('tag', 'N/A')}")
else:
   print(f"Error {response.status_code}: {response.text}")
```

<div id="2-delete-rules-post-rules">
  ### 2. ルールを削除する (POST /rules)
</div>

id（推奨）または value を指定して、ルールを削除します。

```python
data = {
   "rules": [
       {
           "value": "(cat OR dog) lang:en -is:retweet",
           "tag": "pet-monitor"
       },
       # 必要に応じてルールを追加してください(最大100件)
   ]
}

response = requests.delete(rules_url, headers=headers, json=data)
if response.status_code == 200:
   deleted = response.json().get("data", {})
   print(f"Deleted count: {deleted.get('deleted', 'N/A')}")
   if 'not_deleted' in deleted:
       print("Not deleted:", deleted['not_deleted'])
else:
   print(f"Error {response.status_code}: {response.text}")
```

**Tip**: すべてのルールを削除するには、まず GET リクエストでルールを取得し、id を抽出してから一括で削除します。

<div id="3-get-rules-get-rules">
  ### 3. ルールの取得 (GET /rules)
</div>

有効なルールをすべて取得します。

```python
response = requests.get(rules_url, headers=headers)
if response.status_code == 200:
   rules = response.json().get("data", {}).get("rules", [])
   if rules:
       print("Active rules:")
       for rule in rules:
           print(f"ID: {rule['id']}, Value: {rule['value']}, Tag: {rule.get('tag', 'N/A')}")
   else:
       print("No active rules.")
else:
   print(f"Error {response.status_code}: {response.text}")
```

<div id="4-powerstream-get-stream">
  ### 4. PowerStream (GET /stream)
</div>

リアルタイムの投稿を取得するストリームに接続します。行単位で読み取るには `stream=True` を指定してください。堅牢性を高めるため、再接続ロジックを実装してください。

```python
stream_url = base_url

def main():
   while True:
       response = requests.request("GET", stream_url, headers=headers, stream=True)
       print(response.status_code)
       for response_line in response.iter_lines():
           if response_line:
               json_response = json.loads(response_line)
               print(json.dumps(json_response, indent=4, sort_keys=True))
               if response.status_code != 200:
                   print(response.headers)
                   raise Exception(
                       "リクエストがエラーを返しました: {} {}".format(
                           response.status_code, response.text
                       )
                   )
```

<div id="local-datacenter-support">
  #### ローカルデータセンターサポート
</div>

レイテンシを最適化するために、Powerstream では、接続が確立されているローカルデータセンターで生成または作成された投稿のみを取得するオプションを利用できます。これによりレプリケーション遅延を回避でき、他のデータセンターからの投稿と比較して、より高速な配信が可能になります。これを有効にするには、クエリパラメーター `?localDcOnly=true` をストリームエンドポイント（例: `/2/powerstream?localDcOnly=true`）に指定します。接続先のデータセンターは、ストリームの初期 data ペイロード内と、レスポンスの HTTP ヘッダーの両方で示されます。

コードで使用するには：

```python
# ローカルデータセンターのみの場合:
stream_url = "https://api.x.com/2/powerstream?localDcOnly=true"
```

`localDcOnly` パラメータが有効な場合、ストリームが最初に接続するとき、どのローカルデータセンターが使用されているかを示す次のレスポンスヘッダーが含まれます。

```bash
'x-powerstream-datacenter': 'atla',
'x-powerstream-localdconly': 'true'
```

さらに、データセンターを指定する初期ペイロードも送信されます。

```bash
{
    "type": "connection_metadata",
    "datacenter": "atla",
    "timestamp": 1762557264155
}
```

<Note>
  **Tip:** レイテンシを最適化するには、異なる地理的ロケーション（例：米国東海岸のアトランタ近郊と米国西海岸のポートランド近郊）から接続を構成し、それぞれに対して `localDcOnly=true` を有効にします。これにより、各データセンターの投稿により高速にアクセスできます。クライアント側でストリームを集約し、複数データセンターの data を統合してください。
</Note>

<div id="operators">
  ## 演算子
</div>

フィルタリングルールを設定するには、キーワードと演算子を使用します。利用可能な演算子の一覧を以下に示します。

<div id="field-based-operators">
  ### フィールドベースの演算子
</div>

<div id="user-operators">
  #### ユーザー演算子
</div>

| 演算子 | 概要 | 例 |
|----------|---------|---------|
| `from:` | 特定のユーザーからの投稿に一致します | `from:xdevelopers` または `from:123456` |
| `to:` | 特定のユーザー宛ての投稿に一致します | `to:jvaleski` |
| `retweets_of:` | 特定のユーザーのリポストに一致します | `retweets_of:xdevelopers` |

<div id="content-operators">
  #### コンテンツ演算子
</div>

| Operator | Summary | Example |
|----------|---------|---------|
| `contains:` | 本文に特定のテキストやキーワードを含む投稿に一致します | `contains:hello` または `contains:-2345.432` |
| `url_contains:` | 特定のテキストを含む URL を持つ投稿に一致します | `url_contains:"com/willplayforfood"` |
| `lang:` | 特定の言語の投稿に一致します | `lang:en` |

<div id="entity-operators">
  #### エンティティ演算子
</div>

| Operator | Summary | Example |
|----------|---------|---------|
| `has:` | 特定のエンティティを含む投稿に一致します（オプション: mentions, geo, links, media, lang, symbols, images, videos） | `has:images`, `has:geo`, `has:mentions` |
| `is:` | 特定のタイプ、または特定のプロパティを持つ投稿に一致します（オプション: retweet, reply） | `is:retweet`, `is:reply` |

<div id="location-operators">
  #### ロケーションオペレーター
</div>

| Operator | Summary | Example |
|----------|---------|---------|
| `place:` | 特定の場所（ロケーション）からの投稿に一致 | `place:"Belmont Central"`, `place:02763fa2a7611cf3` |
| `bounding_box:` | 地理的なバウンディングボックス内の投稿に一致 | `bounding_box:[-112.424083 42.355283 -112.409111 42.792311]` |
| `point_radius:` | ある地点を中心とした半径内の投稿に一致 | `point_radius:[-111.464973 46.371179 25mi]`, `point_radius:[-111.464973 46.371179 15km]` |

<div id="advancedcontent-operators">
  #### 高度な／コンテンツ関連オペレーター
</div>

| Operator | Summary | Example |
|----------|---------|---------|
| `bio:` | 特定の自己紹介文を持つユーザーの投稿に一致します（フレーズ一致を使用） | N/A |
| `bio_name:` | 自己紹介文内に特定の名前が含まれるユーザーの投稿に一致します（フレーズ一致を使用） | N/A |

<div id="additional-operators">
  #### 追加オペレーター
</div>

| Operator | 概要 | 例 |
|----------|---------|---------|
| `retweets_of_status_id:` | 特定の投稿の再投稿に一致します | `retweets_of_status_id:1234567890123456789` |
| `in_reply_to_status_id:` | 特定の投稿への返信に一致します | `in_reply_to_status_id:1234567890123456789` |

<div id="non-field-operators">
  ### フィールド以外の演算子
</div>

<div id="special-syntax-operators">
  #### 特殊構文オペレーター
</div>

| 演算子 | 概要 | 例 |
|----------|---------|---------|
| `@` | メンション用演算子 | `@username` |
| フレーズマッチング | フレーズを完全一致で検索します | `"exact phrase"` |

<div id="logical-operators">
  #### 論理演算子
</div>

| 演算子 | 概要 | 例 |
|----------|---------|---------|
| `OR` | 式同士の論理和 (OR) | `x OR facebook` |
| Space/AND | 式同士の論理積 (AND) | `x facebook`（両方の語句が含まれている必要があります） |
| `()` | 複雑な式のグルーピング | `(x OR facebook) iphone` |
| `-` | 否定／除外 | `x -facebook`（facebook を含まない x） |

<div id="limits-best-practices">
  ## 制限とベストプラクティス
</div>

* レート制限：ルール管理は 24 時間あたり最大 50 リクエスト。ストリームにはレート制限はありません（ただし接続数の上限があります）。
* 再接続：切断された場合は指数バックオフ方式で再接続してください。
* 監視：`Connection: keep-alive` ヘッダーを使用してください。
