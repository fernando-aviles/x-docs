<div id="recent-search-pagination">
  ### Recent search エンドポイントのページネーション
</div>

<div id="introduction">
  #### はじめに
</div>

検索クエリは、通常 1 回の API レスポンスで返せる数よりも多くの投稿にマッチします。その場合、データは一連の「ページ」として返されます。ページネーションとは、全ページをリクエストしてデータセット全体を取得するための仕組みのことです。

以下は、recent search のページネーションに関する基本事項です。

* recent search エンドポイントは、クエリに対して少なくとも 1 ページのレスポンスを返し、追加のページが利用可能な場合は JSON レスポンス内に next&#95;token を提供します。一致する投稿を取得するには、このプロセスを、レスポンスにトークンが含まれなくなるまで繰り返すことができます。

* next&#95;token は失効しません。同じ next&#95;token の値を使用して複数回リクエストした場合、リクエストしたタイミングに関係なく、同じ結果が返されます。

* 投稿は UTC タイムゾーンで新しい順（逆時系列）に配信されます。これは各ページ内だけでなく、複数ページにまたがっても同様です。 
  * 最初のレスポンス内の最初の投稿は、クエリにマッチする中で最も新しい投稿です。
  * 最後のレスポンス内の最後の投稿は、クエリにマッチする中で最も古い投稿です。

* max&#95;results リクエストパラメータを使用すると、レスポンスごとに返される投稿数を設定できます。デフォルトは 10 件の投稿で、最大は 100 件です。 

* すべてのページネーション実装では、レスポンスペイロードから next&#95;token をパースし、それを「次ページ」の検索リクエストに含める必要があります。これらの「次ページ」リクエストをどのように構築するかの詳細は、以下を参照してください。
   

recent search エンドポイントは、次の 2 つの基本的な利用パターンをサポートするよう設計されています。

* **過去データの取得 (Get historical)** - 関心のある期間から、一致する投稿をリクエストするパターンです。これは、過去の調査を目的とした一度きりのリクエストであることが多いです。検索リクエストは、start&#95;time と end&#95;time のリクエストパラメータに基づいて行うことができます。recent search エンドポイントは、最も新しい一致投稿から始まり、投稿を新しい順（逆時系列）で返します。 

* **ポーリング (Polling)** - 最後に受信した投稿以降に投稿された、一致する投稿をリクエストするパターンです。これらのユースケースは、ほぼリアルタイムの利用を目的とし、新しい関心対象の投稿を「監視」するための頻繁なリクエストが特徴です。recent search エンドポイントは、「ポーリング」パターンをサポートするために since&#95;id リクエストパラメータを提供しています。投稿 ID によるナビゲーションを支援するため、until&#95;id リクエストパラメータも利用できます。
   

次に、historical モードについて説明します。これは recent search エンドポイントのデフォルトモードであり、ページネーションの基本を示すものです。その後で、ポーリングのユースケースの例を説明します。ポーリングによってページネーションが発生する場合、検索リクエストを管理するための追加ステップが必要になります。
 

<div id="retrieving-historical-data">
  #### 履歴データの取得
</div>

このセクションでは、関心のある期間（現在は直近 7 日間に限定）から投稿を取得する方法を、start&#95;time と end&#95;time のリクエストパラメータを使って説明します。履歴リクエストは、通常、調査や分析を目的とした単発のリクエストです。 

特定期間のデータを取得するリクエストを送信することは、recent search エンドポイントのデフォルト動作です。検索リクエストで start&#95;time、end&#95;time、since&#95;id のいずれのリクエストパラメータも指定しない場合、end&#95;time のデフォルトは「現在」（実際にはクエリ時刻の 30 秒前）となり、start&#95;time のデフォルトは 7 日前となります。

エンドポイントは、最も新しい投稿から始まり、逆時系列で並んだ最初の「ページ」の投稿を返します。レスポンスの JSON ペイロードには、追加のデータのページがある場合、next&#95;token も含まれます。マッチする投稿をページ数に関係なくすべて収集するには、next&#95;token が返されなくなるまでリクエストを繰り返します。 

例えば、直近 1 週間で snow というキーワードを含む投稿に対する初回リクエストは次のようになります。

https://api.x.com/2/tweets/search/recent?query=snow

レスポンスには、最新の 10 件の投稿とともに、JSON レスポンス内の次の「meta」属性（メタデータ）が含まれます。

```
"meta": {
        "newest_id": "1204860593741553664",
        "oldest_id": "1204860580630278147",
        "next_token": "b26v89c19zqg8o3fobd8v73egzbdt3qao235oql",
        "result_count": 10
    }
```

次の 10 件の投稿を取得するには、この next&#95;token を元のリクエストに追加します。リクエストは次のようになります。

https://api.x.com/2/tweets/search/recent?query=snow&amp;next&#95;token=b26v89c19zqg8o3fobd8v73egzbdt3qao235oql

next&#95;token を探してそれを後続のリクエストに含める処理は、すべての投稿（または任意の件数）が収集されるまで、あるいは指定した回数のリクエストが実行されるまで繰り返すことができます。ユースケースにおいてデータの完全性（クエリに一致するものをすべて収集すること）が重要な場合は、単純な &quot;request.next&#95;token が null になるまで繰り返す&quot; という設計で十分です。

<div id="polling-and-listening-use-cases">
  #### ポーリングおよびリッスンのユースケース
</div>

このセクションでは、`since_id` リクエストパラメータを使用して recent search エンドポイントをポーリングし、最近の投稿を取得する方法を説明します。 

ポーリングのユースケースでは、「関心のある新しい投稿はあるか？」というクエリを継続的かつ高頻度に実行します。時間を基準にリクエストを行う履歴系のユースケースとは異なり、ポーリングのユースケースでは、通常リクエストは投稿IDを基準に行われます。

ポーリングの利用パターンで重要なのは、X プラットフォーム上のすべての新しい投稿には、一般的に昇順になるように「発行」される[一意の ID](/ja/resources/fundamentals/x-ids) が付与されているという点です。ある投稿の ID が別の投稿より小さい場合、その投稿はより早い時点で投稿されたことを意味します。

recent search エンドポイントは、投稿IDを使って投稿アーカイブをたどれるようになっています。エンドポイントからのレスポンスには、`oldest_id` と `newest_id` の投稿IDが含まれます。ポーリングモードでは、これまでに受け取った中で最大／最新の ID を `since_id` に設定してリクエストを行います。 

たとえば、「snow」に関する新しい投稿を 5 分ごとに検索していて、最後に受け取った投稿の投稿IDが 10000 だったとします。ポーリングするタイミングになったとき、リクエストは次のようになります。

https://api.x.com/2/tweets/search/recent?query=snow&amp;since&#95;id=10000

次に、前回のリクエスト以降に 7 件の投稿が行われたとします。これらはすべて 1 つの data の「ページ」に収まるため、`next_token` はありません。レスポンスには、最新（最も新しい）の投稿の投稿IDが含まれます。

```
"meta": {
        "newest_id": "12000",
        "oldest_id": "10005",
        "result_count": 7
    }
```

次のポーリングクエリを行うために、この newest&#95;id の値を使って次の since&#95;id パラメータを設定します。

`https://api.x.com/2/tweets/search/recent?query=snow&since_id=12000`

利用可能な追加の data があり、next トークンが返される場合でも、必要なのは最初のページの結果に含まれる newest&#95;id の値だけです。各ページの data には newest&#95;id と oldest&#95;id の値が含まれますが、次回の定期的なポーリングリクエストに必要なのは、最初のページで返される値のみです。したがって、ポーリング方式を実装している場合や、ID の範囲で投稿を検索している場合には、ページネーションロジックはやや複雑になります。 

ここで、新たに 18 件の一致する投稿があるとします。エンドポイントは、この 5 分間の期間に対応する最初のレスポンスとして、1 ページ分の data が完全に埋まったレスポンスと、次のページの data をリクエストするための next&#95;token を返します。また、次の 5 分後のポーリング間隔で使用するために必要な、最新の投稿 ID も含まれます。

```
"meta": {
        "newest_id": "13800",
        "oldest_id": "12500",
        "next_token": "fnsih9chihsnkjbvkjbsc",
        "result_count": 10
    }
```

この5分間の期間にマッチするすべてのデータを取得するには、前のリクエストと同じ since&#95;id の値を指定しつつ、next&#95;token を次のリクエストに含めて送信します。

https://api.x.com/2/tweets/search/recent?query=snow&amp;since&#95;id=12000&amp;next&#95;token=fnsih9chihsnkjbvkjbsc

```
"meta": {
        "newest_id": "12300",
        "oldest_id": "12010",
        "result_count": 8
    }
```

2 回目のレスポンスには残りの 8 件の投稿が含まれ、next&#95;token は返されません。newest&#95;id の値 (12300) は更新せず、代わりに最初のレスポンスの newest&#95;id の値に基づいて、次の since&#95;id を指定したリクエストを行います。

https://api.x.com/2/tweets/search/recent?query=snow&amp;since&#95;id=13800
