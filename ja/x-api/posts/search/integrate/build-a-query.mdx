検索エンドポイントは、GET リクエストで 1 つのクエリを受け取り、そのクエリに一致する過去の投稿の集合を返します。クエリは、さまざまな投稿属性に一致する演算子で構成されます。

***

<div id="query-limitations">
  ## クエリの制限
</div>

ご利用の [アクセスレベル](/ja/x-api/getting-started/about-x-api) によって、クエリには次の制限が適用されます。

| アクセスレベル | 最近の検索 | 全アーカイブ検索 |
| :--- | :--- | :--- |
| Self-serve | 512文字 | 1,024文字 |
| Enterprise | 4,096文字 | 4,096文字 |

***

<div id="operator-availability">
  ## オペレーターの利用可否
</div>

ほとんどのオペレーターはどの開発者でも利用できますが、一部は特定のアクセスレベルでのみ利用できます。

* **Core operators:** 任意の [Project](/ja/resources/fundamentals/developer-apps) を使用している場合に利用可能です
* **Advanced operators:** 特定のアクセスレベルを持つ Project を使用している場合に利用可能です

利用可否の詳細については、[オペレーター一覧](/ja/x-api/posts/search/integrate/operators)を参照してください。

***

<div id="operator-types-standalone-and-conjunction-required">
  ## 演算子のタイプ: 単独使用可能と結合必須
</div>

**単独演算子** は、それ単体でも、（結合が必要な演算子を含む）他のどの演算子と組み合わせても使用できます。

たとえば、このクエリが動作するのは、`#hashtag` が単独演算子であるためです。

```
#xapiv2
```

**連結必須の演算子** は、それ単体ではクエリ内で使用できません。少なくとも 1 つの単独で使用可能な演算子と組み合わせて使用する必要があります。これは、これらの演算子だけを使用すると、非常に大量の投稿にマッチしてしまうためです。

たとえば、次のクエリは連結必須の演算子のみを含んでいるため、**サポートされません**。

```
has:media
```

```
has:links OR is:retweet
```

単独の演算子（たとえば `"X data"` のようなフレーズ）を追加すると、クエリは正しく動作します。

```
"X data" has:mentions (has:media OR has:links)
```

***

<div id="boolean-operators-and-grouping">
  ## ブール演算子とグループ化
</div>

複数の演算子を、次の記法を使って組み合わせます。

| Operator | Description | Example |
| :--- | :--- | :--- |
| **AND** (スペース) | 投稿は両方の条件に一致する必要があります | `snow day #NoSchool` は「snow」と「day」と #NoSchool をすべて含む投稿にマッチします |
| **OR** | 投稿はいずれかの条件に一致する必要があります | `grumpy OR cat OR #meme` は「grumpy」または「cat」または #meme を含む投稿にマッチします |
| **NOT** (ダッシュ) | この条件に一致する投稿を除外します | `cat #meme -grumpy` は「cat」と #meme を含むが「grumpy」を含まない投稿にマッチします |
| **Grouping** (かっこ) | 演算子をまとめてグループ化します | `(grumpy cat) OR (#meme has:images)` は、いずれか一方のグループにマッチします |

<Note>
  **否定演算子について**

  * 演算子 `-is:nullcast` は常に否定条件として使用する必要があります
  * 否定された演算子は単独では使用できません
  * グループ化した演算子全体を否定しないでください。`skiing -(snow OR day OR noschool)` の代わりに `skiing -snow -day -noschool` を使用してください
</Note>

***

<div id="order-of-operations">
  ## 演算の順序
</div>

AND と OR を組み合わせる場合:

1. まず AND ロジックで接続された条件がまとめて評価されます
2. 次に、その結果に対して OR ロジックが適用されます

**例:**

| Query                    | Evaluated as               |
| :----------------------- | :------------------------- |
| `apple OR iphone ipad`   | `apple OR (iphone ipad)`   |
| `ipad iphone OR android` | `(iphone ipad) OR android` |

あいまいさをなくすには、かっこを使用してください:

```
(apple OR iphone) ipad
```

```
iphone (ipad OR android)
```

***

<div id="punctuation-diacritics-and-case-sensitivity">
  ## 句読点、ダイアクリティカルマーク、大文字と小文字の区別
</div>

**ダイアクリティカルマーク:** アクセントやダイアクリティカルマークを含む検索クエリは、それらのアクセントの有無にかかわらず投稿に一致します。たとえば、`Diacrítica` は *Diacrítica* と *Diacritica* の両方に一致します。

**大文字と小文字の区別:** すべての演算子は大文字と小文字を区別しません。クエリ `cat` は *cat*、*CAT*、*Cat* に一致します。

<Note>
  **Filtered stream は異なる動作をします**

  [Filtered stream のルールを作成する](/ja/x-api/posts/filtered-stream/integrate/build-a-rule)場合、アクセント付きのキーワードは、そのアクセントを含む投稿にのみ一致します。たとえば、`Diacrítica` は *Diacrítica* にのみ一致し、*Diacritica* には一致しません。
</Note>

***

<div id="quote-tweet-matching">
  ## 引用ツイートのマッチング
</div>

Search Posts を使用する場合、演算子は引用ツイートのコンテンツにはマッチしますが、引用された元の投稿のコンテンツにはマッチ **しません**。

<Note>
  [Filtered stream](/ja/x-api/posts/filtered-stream/introduction) はこれとは異なり、引用ツイートと元の投稿の両方のコンテンツにマッチします。
</Note>

***

<div id="specificity-and-efficiency">
  ## 具体性と効率性
</div>

<Warning>
  単一キーワードやハッシュタグといった広範な演算子の使用は推奨されません。膨大な数の投稿にマッチし、利用上限をすぐに消費してしまいます。
</Warning>

**効果的なクエリを構築するためのヒント:**

1. **最初は具体的にして、そこから広げる** — 関連性の高い結果を返す、ターゲットを絞ったクエリを作成する
2. **複数の演算子を使う** — 演算子を組み合わせて結果を絞り込む
3. **文字数を意識する** — クエリ文字列全体が上限にカウントされる

**クエリの発展例:**

```
# Too broad - 200,000+ Posts per day
happy

# Better - adds language filter and exclusions
(happy OR happiness) lang:en -birthday -is:retweet

# さらに良い例 - 59文字でより具体的
(happy OR happiness) place_country:GB -birthday -is:retweet
```

<div id="iteratively-building-a-query">
  ## クエリを段階的に作成する
</div>

<div id="step-1-start-with-a-basic-query">
  ### ステップ 1: 基本的なクエリから始める
</div>

```
happy OR happiness
```

<div id="step-2-test-and-narrow-based-on-results">
  ### ステップ 2: 結果に基づいてテストし、絞り込む
</div>

多言語の投稿が含まれていることに気付きました。言語フィルターを追加しましょう:

```
(happy OR happiness) lang:en
```

誕生日のお祝いメッセージが多く含まれています。これらとリツイートを除外しましょう:

```
(happy OR happiness) lang:en -birthday -is:retweet
```

<div id="step-3-broaden-for-better-coverage">
  ### ステップ 3: カバレッジを広げる
</div>

より多くのセンチメントを捉えるために、関連するキーワードを追加しましょう:

```
(happy OR happiness OR excited OR elated) lang:en -birthday -is:retweet
```

<div id="step-4-adjust-for-trends">
  ### ステップ 4: トレンドに応じて調整する
</div>

ホリデー関連の投稿が含まれているので、除外します:

```
(happy OR happiness OR excited OR elated) lang:en -birthday -is:retweet -holidays
```

<div id="adding-a-query-to-your-request">
  ## リクエストへのクエリの追加
</div>

`query` パラメータを使用して、クエリを HTTP エンコードします。

```bash
curl "https://api.x.com/2/tweets/search/recent?\
query=cat%20has%3Amedia%20-grumpy&\
tweet.fields=created_at&\
max_results=100" \
  -H "Authorization: Bearer $BEARER_TOKEN"
```

<div id="query-examples">
  ## クエリの例
</div>

<div id="tracking-a-natural-disaster">
  ### 自然災害の追跡
</div>

ハリケーン・ハービーに関する気象機関の投稿を取得します:

**クエリ:**

```
has:geo (from:NWSNHC OR from:NHC_Atlantic OR from:NWSHouston OR from:NWSSanAntonio OR from:USGS_TexasRain OR from:USGS_TexasFlood OR from:JeffLindner1) -is:retweet
```

**完全なリクエスト URL：**

```
https://api.x.com/2/tweets/search/recent?query=has%3Ageo%20(from%3ANWSNHC%20OR%20from%3ANHC_Atlantic%20OR%20from%3ANWSHouston%20OR%20from%3ANWSSanAntonio%20OR%20from%3AUSGS_TexasRain%20OR%20from%3AUSGS_TexasFlood%20OR%20from%3AJeffLindner1)%20-is%3Aretweet
```

<div id="sentiment-analysis-for-nowplaying">
  ### #nowplaying のセンチメント分析
</div>

**ポジティブなセンチメント:**

```
#nowplaying (happy OR exciting OR excited OR favorite OR fav OR amazing OR lovely OR incredible) (place_country:US OR place_country:MX OR place_country:CA) -horrible -worst -sucks -bad -disappointing
```

**ネガティブなセンチメント:**

```
#nowplaying (horrible OR worst OR sucks OR bad OR disappointing) (place_country:US OR place_country:MX OR place_country:CA) -happy -exciting -excited -favorite -fav -amazing -lovely -incredible
```

<div id="using-post-annotations">
  ### 投稿アノテーションを使用する
</div>

`context:` 演算子を使って、画像付きの、猫以外のペットに関する日本語の投稿を検索します。

まず、[Post lookup](/ja/x-api/posts/lookup/introduction) で `tweet.fields=context_annotations` を使用して、domain.entity の ID を特定します。

* Cats: `domain` 66、`entity` 852262932607926273
* Pets: `domain` 65、`entity` 852262932607926273

**クエリ:**

```
context:65.852262932607926273 -context:66.852262932607926273 -is:retweet has:images lang:ja
```
