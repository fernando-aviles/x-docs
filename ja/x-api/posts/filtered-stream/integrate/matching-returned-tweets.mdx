<div id="matching-returned-posts-to-their-associated-rule">
  ### 返される投稿を対応するルールと照合する
</div>

filtered stream エンドポイントでは、単一の接続で複数のルールを設定できます。ストリームで投稿の受信を開始する前に、どのタイプの投稿に関心があるかを指定するルールを作成する必要があります。 

ユーザー属性、位置情報、言語など、さまざまな属性に基づいて投稿とマッチさせるルールを指定する際、そのルールを上位レベルで区別するためにタグを付与できます。とくに多くのルールを運用している場合、タグはルールに文脈を持たせる良い方法です。フィルタリングルールは、どの投稿アクティビティが接続を通じて送信されるかを決定します。

別のタイプの投稿を取得するために新しいフィルタリングルールを追加する必要がある場合や、既存のルールを削除する必要がある場合は、アプリから [POST tweets/search/stream/rules](/ja/x-api/posts/filtered-stream#post-2-tweets-search-stream-rules) エンドポイントにリクエストを送信して行えます。このリクエストが送信されると、フィルタリングルールは自動的に更新され、再接続することなく変更がそのままデータストリームに反映されます。多くの場合、ルールの追加は約 20 秒以内に反映されます。まれではありますが、外部要因（たとえばネットワーク接続）によっては、マッチする投稿を受信し始めるまでにそれ以上の時間がかかる場合があります。list rule エンドポイントでルールが見つからない場合は、ルール作成リクエストが成功しているかを確認してください。これは、ログにエラーメッセージが出力されていないかを確認することで行えます。

<div id="matching-rules">
  #### マッチしたルール
</div>

アクティビティが filtered stream 接続を通じて配信されると、そのアクティビティには matching&#95;rules 配列が含まれ、配信された投稿に対してどのフィルターリストがマッチしたかが示されます。

Post ペイロードには、特定の投稿が配信される原因となった rule id と tag を含む追加の文字列型メタデータが含まれます。複数のルールが 1 件の投稿にマッチした場合でも、そのアクティビティは 1 回だけ配信され、そのメタデータ内にマッチしたすべてのルールが含まれます。matching&#95;rules を利用すると、特定の投稿と特定のルールを簡単に関連付けることができ、多数の異なるルールを持つ場合に特に有用です。このように単一のストリームを通じて data が配信されるため、一意の id と tag を持たせておくことがマッチングのために不可欠です。 

**以下は、Post ペイロード内で「matching&#95;rules」配列がどのように含まれるかの例です。**

```"matching_rules": [
    {
      "id": "1166916266197536768",
      "tag": "test-rule-tag-00000"
    },
    {
      "id": "1166916266197536769",
      "tag": "test-rule-tag-12345"
    }
  ]
```

<div id="rule-tags">
  #### ルールタグ
</div>

フィルタリングルールは作成時にタグを付けて作成できます。ルールタグ自体には特別な意味はなく、ルールに付随して運ばれる不透明な文字列として扱われます。これらは返されるアクティビティの matching&#95;rules メタデータに含まれ、より高いレベルでルールを区別しやすくすることを目的としています。 

タグは、フィルタリングルールを論理的なグループにまとめる簡単な方法を提供します。たとえば、特定のルールに対して一意の ID をタグとして生成し、アプリが処理するアクティビティ内でその ID を参照することで、結果を特定の顧客、キャンペーン、カテゴリー、その他の関連グループと関連付けることができます。

タグは既存のルールに対して更新することはできず、ルール作成時にのみ指定できる点に注意してください。タグを「更新」または「名前変更」するには、まずそのルールを削除し、目的のタグを付けて再度追加する必要があります。最善の方法は、タグとして一意の識別子を使用し、システム側でそれを自分のアプリ内のさまざまなデータポイントと関連付けることです。こうすることで、ルールセット自体を変更することなく対応できます。
