フィルタードストリームエンドポイントでは、ストリームに適用した一連のルールに一致する投稿が配信されます。ルールは、さまざまな投稿属性にマッチするオペレーターで構成されます。

複数のルールは、[POST /tweets/search/stream/rules](/ja/x-api/posts/filtered-stream#post-2-tweets-search-stream-rules) エンドポイントを使用して適用できます。ルールを追加し、[GET /tweets/search/stream](/ja/x-api/posts/filtered-stream#get-2-tweets-search-stream) を使って接続すると、ルールに一致する投稿のみが配信されます。ルールを追加または削除するために接続を切断する必要はありません。

***

<div id="rule-limitations">
  ## ルールの制限事項
</div>

ルール数の上限は、[アクセスレベル](/ja/x-api/getting-started/about-x-api)によって異なります。具体的な上限については、[フィルタ済みストリームの概要](/ja/x-api/posts/filtered-stream/introduction)を参照してください。

***

<div id="operator-types-standalone-and-conjunction-required">
  ## 演算子のタイプ: 単独利用可能なものと結合必須のもの
</div>

**単独演算子** は、単体で使用することも、他の任意の演算子（結合が必要な演算子を含む）と組み合わせて使用することもできます。

たとえば、次のルールが有効なのは、`#hashtag` が単独演算子であるためです。

```
#xapiv2
```

**結合必須演算子** は、ルール内で単独では使用できません。少なくとも 1 つの単独演算子と組み合わせて使用する必要があります。これは、これらの演算子だけを使用すると、非常に大量の投稿にマッチしてしまうためです。

たとえば、次のルールは結合必須演算子だけを含んでいるため、**サポートされません**。

```
has:media
```

```
has:links OR is:retweet
```

`"X data"` というフレーズのような単独の演算子を追加すると、そのルールは正しく機能します。

```
"X data" has:mentions (has:media OR has:links)
```

***

<div id="boolean-operators-and-grouping">
  ## ブール演算子とグルーピング
</div>

これらの演算子を組み合わせて複数の条件を指定できます。

| Operator | 説明 | 例 |
| :--- | :--- | :--- |
| **AND** (スペース) | 投稿は両方の条件を満たす必要があります | `snow day #NoSchool` は「snow」かつ「day」かつ #NoSchool を含む投稿に一致します |
| **OR** | 投稿はいずれか一方の条件を満たせばよい | `grumpy OR cat OR #meme` は「grumpy」または「cat」または #meme を含む投稿に一致します |
| **NOT** (ハイフン) | この条件に一致する投稿を除外します | `cat #meme -grumpy` は「cat」と #meme を含み、「grumpy」を含まない投稿に一致します |
| **Grouping** (かっこ) | 演算子をまとめてグループ化します | `(grumpy cat) OR (#meme has:images)` はどちらかのグループに一致します |

<Note>
  **否定演算についての注意**

  * `sample:` を除き、すべての演算子は否定できます
  * 演算子 `-is:nullcast` は常に否定形（マイナス記号付き）で指定する必要があります
  * 否定した演算子だけを単独で使うことはできません
  * グループ化した演算子全体を否定しないでください。`skiing -(snow OR day OR noschool)` の代わりに `skiing -snow -day -noschool` を使用してください
</Note>

***

<div id="order-of-operations">
  ## 演算の順序
</div>

AND と OR を組み合わせる場合：

1. AND ロジックで接続された演算子がまずまとめて評価されます
2. 次に、OR ロジックで接続された演算子が適用されます

**例:**

| クエリ                      | 評価結果                       |
| :----------------------- | :------------------------- |
| `apple OR iphone ipad`   | `apple OR (iphone ipad)`   |
| `ipad iphone OR android` | `(iphone ipad) OR android` |

あいまいさをなくすには、かっこを使用してください：

```
(apple OR iphone) ipad
```

```
iphone (ipad OR android)
```

***

<div id="punctuation-diacritics-and-case-sensitivity">
  ## 句読点、ダイアクリティカルマーク、大文字と小文字の区別
</div>

**ダイアクリティカルマーク（発音区別記号）:** アクセントを含む Filtered stream のルールは、同じくアクセントを含む投稿にのみマッチします。たとえば、`diacrítica` は *diacrítica* にはマッチしますが、*diacritica* にはマッチしません。

**大文字と小文字の区別:** すべての演算子は大文字と小文字を区別しません。たとえば、ルール `cat` は *cat*、*CAT*、*Cat* にマッチします。

<Note>
  **検索における投稿の挙動は異なります**

  [検索クエリを構築する](/ja/x-api/posts/search/integrate/build-a-query)場合、アクセント付きのキーワードは、アクセントの有無を問わず投稿にマッチします。たとえば、`Diacrítica` は *Diacrítica* と *Diacritica* の両方にマッチします。
</Note>

***

<div id="quote-tweet-matching">
  ## 引用ツイートのマッチング
</div>

filtered stream を使用する場合、オペレーターは引用ツイートの内容**と**引用された元の投稿の内容の両方を対象にマッチします。

<Note>
  [Search Posts](/ja/x-api/posts/search/introduction) は挙動が異なります。引用ツイートの内容のみにマッチし、元の投稿にはマッチしません。
</Note>

***

<div id="specificity-and-efficiency">
  ## 具体性と効率性
</div>

<Warning>
  単一のキーワードやハッシュタグといった広範なオペレーターだけを使うことは推奨されません。そのようなルールは非常に多くの投稿にマッチし、接続リソースを急速に消費してしまいます。
</Warning>

**効果的なルールを構築するためのヒント:**

1. **最初は具体的に、あとから広げる** — 関連性の高い結果を返す、絞り込まれたルールを作成する
2. **複数のオペレーターを使う** — オペレーターを組み合わせて結果を絞り込む
3. **文字数を意識する** — ルール全体の文字列が上限のカウント対象になる

**進め方の例:**

```
# Too broad - 200,000+ Posts per day
happy

# Better - adds language filter and exclusions
(happy OR happiness) lang:en -birthday -is:retweet

# さらに良い - 59文字、より具体的
(happy OR happiness) place_country:GB -birthday -is:retweet
```

<div id="iteratively-building-a-rule">
  ## ルールを段階的に構築する
</div>

<div id="step-1-start-with-a-basic-rule">
  ### ステップ1：まずは基本ルールから始める
</div>

```
happy OR happiness
```

<div id="step-2-test-and-narrow-based-on-results">
  ### ステップ 2: テストし、結果に基づいて絞り込む
</div>

さまざまな言語の投稿があることがわかりました。言語フィルターを追加しましょう:

```
(happy OR happiness) lang:en
```

誕生日のお祝い投稿が多数含まれています。これらとリツイートを除外しましょう：

```
(happy OR happiness) lang:en -birthday -is:retweet
```

<div id="step-3-broaden-for-better-coverage">
  ### ステップ 3: カバレッジ向上のために拡張する
</div>

より多くのセンチメントをカバーできるようにします。関連キーワードを追加します:

```
(happy OR happiness OR excited OR elated) lang:en -birthday -is:retweet
```

<div id="step-4-adjust-for-trends">
  ### ステップ 4: トレンドに応じて調整する
</div>

ホリデー関連の投稿が含まれています。これらを除外します:

```
(happy OR happiness OR excited OR elated) lang:en -birthday -is:retweet -holidays
```

<div id="adding-and-removing-rules">
  ## ルールの追加と削除
</div>

ルールを追加または削除するには、[POST /2/tweets/search/stream/rules](/ja/x-api/posts/filtered-stream#post-2-tweets-search-stream-rules) を使用します。

<div id="adding-rules">
  ### ルールの追加
</div>

`value`（ルール）と任意の `tag`（一致する投稿を識別するため）を含む `add` の JSON ボディを送信します。

```bash
curl -X POST "https://api.x.com/2/tweets/search/stream/rules" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -d '{
    "add": [
      {"value": "cat has:media", "tag": "cats with media"},
      {"value": "cat has:media -grumpy", "tag": "happy cats with media"},
      {"value": "meme", "tag": "funny things"},
      {"value": "meme has:images"}
    ]
  }'
```

<div id="removing-rules">
  ### ルールの削除
</div>

削除対象のルールの id を含む `delete` JSON ボディを送信します。

```bash
curl -X POST "https://api.x.com/2/tweets/search/stream/rules" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -d '{
    "delete": {
      "ids": [
        "1165037377523306498",
        "1165037377523306499"
      ]
    }
  }'
```

<div id="rule-examples">
  ## ルールの例
</div>

<div id="tracking-a-natural-disaster">
  ### 自然災害の追跡
</div>

ハリケーン・ハービーに関する気象機関の投稿にマッチさせる:

```json
{
  "value": "-is:retweet has:geo (from:NWSNHC OR from:NHC_Atlantic OR from:NWSHouston OR from:NWSSanAntonio OR from:USGS_TexasRain OR from:USGS_TexasFlood OR from:JeffLindner1)",
  "tag": "ハリケーン・ハービー - 位置情報を含む気象機関"
}
```

<div id="sentiment-analysis-for-nowplaying">
  ### #nowplaying のセンチメント分析
</div>

**ポジティブなセンチメント:**

```json
{
  "value": "#nowplaying (happy OR exciting OR excited OR favorite OR fav OR amazing OR lovely OR incredible) (place_country:US OR place_country:MX OR place_country:CA) -horrible -worst -sucks -bad -disappointing",
  "tag": "#nowplaying positive"
}
```

**ネガティブな感情:**

```json
{
  "value": "#nowplaying (horrible OR worst OR sucks OR bad OR disappointing) (place_country:US OR place_country:MX OR place_country:CA) -happy -exciting -excited -favorite -fav -amazing -lovely -incredible",
  "tag": "#nowplaying negative"
}
```

<div id="using-post-annotations">
  ### 投稿アノテーションの使用
</div>

`context:` 演算子を使って、日本語で書かれたペット（猫以外）に関する画像付きの投稿を検索します。

まず、[Post lookup](/ja/x-api/posts/lookup/introduction) で `tweet.fields=context_annotations` を指定して、domain と entity の ID を特定します。

* 猫: `domain` 66、`entity` 852262932607926273
* ペット: `domain` 65、`entity` 852262932607926273

```json
{
  "value": "context:65.852262932607926273 -context:66.852262932607926273 -is:retweet has:images lang:ja",
  "tag": "Japanese pets with images - no cats"
}
```
