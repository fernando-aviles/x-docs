このページでは、Post カウントエンドポイントを統合する際に役立つツールと主要な概念について説明します。

***

<div id="helpful-tools">
  ## 便利なツール
</div>

いくつかの重要な概念を見ていく前に、これらのエンドポイントの動作をテストするには、次のいずれかのツールまたはコードサンプルを利用することをおすすめします。

<div id="code-samples">
  ### コードサンプル
</div>

お好みのプログラミング言語でこれらのエンドポイントを使い始めたい方のために、出発点として利用できるコードサンプルをいくつか [GitHub ページ](https://github.com/xdevplatform/Twitter-API-v2-sample-code)で提供しています。その中には [Python クライアント](https://github.com/xdevplatform/search-tweets-python)も含まれています。

<div id="libraries">
  ### ライブラリ
</div>

用意されている多数の[コミュニティ製サードパーティライブラリ](/ja/x-api/tools-and-libraries/overview)を活用して、利用を開始してください。v2 エンドポイントに対応しているライブラリは、該当するバージョンタグを手がかりに見つけることができます。

<div id="postman">
  ### Postman
</div>

Postman は、これらのエンドポイントを試したり検証したりするのに便利なツールです。各 Postman リクエストには、そのエンドポイントで指定可能なすべてのパラメータが含まれており、どのような項目が利用できるかをすばやく把握するのに役立ちます。Postman コレクションについて詳しくは、[Postman を使う](/ja/tutorials/postman-getting-started)ページをご覧ください。

<div id="key-concepts">
  ## 基本概念
</div>

<div id="authentication">
  ### 認証
</div>

すべての X API v2 エンドポイントでは、キーやトークンとも呼ばれる一連の認証情報を使用してリクエストを[認証](/ja/resources/fundamentals/authentication)する必要があります。このエンドポイントでは、[OAuth 2.0 ベアラートークン](/ja/resources/fundamentals/authentication#oauth-2-0)の利用が必須であり、リクエストを成功させるには[ベアラートークン](/ja/resources/fundamentals/authentication#bearer-token-also-known-as-app-only)を渡す必要があります。ベアラートークンは、開発者用 App 内から直接生成するか、[POST oauth2/token](/ja/resources/fundamentals/authentication#post-oauth2-token) エンドポイントを使用して生成できます。

<div id="developer-console-projects-and-developer-apps">
  ### 開発者コンソール、プロジェクト、および開発者 App
</div>

いずれの X API v2 エンドポイントを利用する場合でも、[開発者アカウント](/ja/resources/fundamentals/developer-portal)を作成し、そのアカウント内に[プロジェクト](/ja/resources/fundamentals/developer-apps)を作成し、そのプロジェクト内に[開発者 App](/ja/resources/fundamentals/developer-apps)を作成している必要があります。該当の開発者 App 内のキーとトークンは、最近のポスト数エンドポイントで利用できます。全アーカイブポスト数エンドポイントを使用したい場合や、高度な検索演算子およびより長いクエリ文字列を利用したい場合は、エンタープライズアクセスの承認を受ける必要があります。

詳しくは、エンタープライズアクセスに関するセクションをご覧ください。

<div id="rate-limits">
  ### レート制限
</div>

毎日、何千人もの開発者が X API へリクエストを送信しています。トラフィック量を管理するために、各エンドポイントには[レート制限](/ja/x-api/fundamentals/rate-limits)が設定されており、これによって各開発者が App に代わって、または認証済みユーザーに代わって送信できるリクエスト数が制限されます。

このエンドポイントには App レベルのレート制限が適用されます。これは、開発者であるあなたが、使用している認証情報で識別される任意の App から、このエンドポイントに対して一定期間内に送信できるリクエスト数に上限があることを意味します。

<div id="building-queries">
  ### クエリの構築
</div>

これらのエンドポイントの中心的な機能は、単一のクエリを使用して投稿をフィルタリングし、返される件数を算出する点にあります。これらのクエリは、メッセージのキーワード、ハッシュタグ、URL などの投稿およびユーザーの属性にマッチするオペレーターで構成されます。オペレーター同士をブールロジックとかっこで組み合わせることで、クエリのマッチング動作をより細かく調整できます。

詳しくは、[クエリの構築方法](/ja/x-api/posts/counts/integrate/build-a-query)に関するガイドを参照してください。

<div id="pagination">
  ### ページネーション
</div>

直近のポスト数を取得する場合、`next_token` は返されません。これは、集計の粒度に関わらず、直近7日間のポスト数を1回の API 呼び出しで取得できることを意味します。

フルアーカイブのポスト数を取得する場合、直近30日分のデータを取得できます。30日より前のデータについては、追加のデータを取得するためにページネーションを行う際に使用できる `next_token` が返されます。
