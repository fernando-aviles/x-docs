このページでは、Post カウント用エンドポイントを統合するためのツールと主要な概念を説明します。

***

<div id="helpful-tools">
  ## 役立つツール
</div>

いくつかの重要な概念を見ていく前に、これらのエンドポイントの動作を試すにあたって、次のいずれかのツールまたはコードサンプルを使用することをおすすめします。

<div id="code-samples">
  ### コードサンプル
</div>

お好みのプログラミング言語のコードで、これらのエンドポイントを利用するためのセットアップを行いたい場合は、出発点として使えるコードサンプルをいくつか[GitHub ページ](https://github.com/xdevplatform/Twitter-API-v2-sample-code)で提供しています。[Python クライアント](https://github.com/xdevplatform/search-tweets-python)も含まれています。

<div id="libraries">
  ### ライブラリ
</div>

[コミュニティ製のサードパーティライブラリ](/ja/x-api/tools-and-libraries/overview)のいずれかを活用して、導入をスムーズに進めましょう。v2 エンドポイントに対応したライブラリは、適切なバージョンタグが付いたものを探すことで見つけることができます。

<div id="postman">
  ### Postman
</div>

Postman は、これらのエンドポイントをテストするために利用できる優れたツールです。各 Postman リクエストには、そのエンドポイントで使用できるすべてのパラメーターが含まれており、利用可能な項目をすばやく理解するのに役立ちます。Postman コレクションについてさらに詳しくは、[Using Postman](/ja/tutorials/postman-getting-started) ページをご覧ください。

<div id="key-concepts">
  ## 重要な概念
</div>

<div id="authentication">
  ### 認証
</div>

すべての X API v2 エンドポイントでは、キーやトークンとも呼ばれる一連のクレデンシャルを使用してリクエストを[認証](/ja/resources/fundamentals/authentication)する必要があります。このエンドポイントでは [OAuth 2.0 Bearer Token](/ja/resources/fundamentals/authentication#oauth-2-0) を使用する必要があり、リクエストを成功させるには [Bearer Token](/ja/resources/fundamentals/authentication#bearer-token-also-known-as-app-only) を渡す必要があります。Bearer Token は、開発者用 App 内から直接生成することも、[POST oauth2/token](/ja/resources/fundamentals/authentication#post-oauth2-token) エンドポイントを使用して生成することもできます。

<div id="developer-console-projects-and-developer-apps">
  ### 開発者コンソール、Project、および開発者用 App
</div>

いずれの X API v2 エンドポイントを利用する場合でも、[開発者アカウント](/ja/resources/fundamentals/developer-portal)を取得し、そのアカウント内で [Project](/ja/resources/fundamentals/developer-apps) を設定し、その Project 内に [開発者用 App](/ja/resources/fundamentals/developer-apps) を作成する必要があります。その開発者用 App 内のキーとトークンは、最近の投稿数用エンドポイントで利用できます。全アーカイブの投稿数用エンドポイントを使用したい場合、または高度な演算子やより長いクエリを利用したい場合は、エンタープライズアクセスの承認が必要です。

詳しくは、エンタープライズアクセスに関するセクションをご覧ください。

<div id="rate-limits">
  ### レート制限
</div>

毎日、多くの開発者が X API にリクエストを送信しています。トラフィック量を管理するために、各エンドポイントには[レート制限](/ja/x-api/fundamentals/rate-limits)が設定されており、アプリまたは認証済みユーザーに代わって各開発者が行えるリクエスト数が制限されています。

このエンドポイントには App レベルのレート制限が適用されます。つまり、開発者であるあなたは、使用している認証情報によって識別される任意の App から、このエンドポイントに対して一定期間内に送信できるリクエスト数が制限されます。

<div id="building-queries">
  ### クエリの構築
</div>

これらのエンドポイントの主な特徴は、単一のクエリを使って投稿をフィルタリングし、あなたに返されるカウント結果を生成する点にあります。これらのクエリは、メッセージのキーワード、ハッシュタグ、URL などの投稿およびユーザー属性に一致するオペレーターで構成されます。オペレーターはブール論理や括弧を使って組み合わせることができ、クエリのマッチング動作をより細かく調整できます。

詳細については、[クエリの作成方法](/ja/x-api/posts/counts/integrate/build-a-query)に関するガイドを参照してください。

<div id="pagination">
  ### ページネーション
</div>

直近の投稿数については、`next_token` は返されません。つまり、粒度に関係なく、1 回の API 呼び出しで直近 7 日間の投稿ボリュームを取得できます。

フルアーカイブの投稿数については、直近 30 日間の data を取得できます。30 日より前の期間の data については、追加の data を取得するためにページネーションで使用できる `next_token` が返されます。
