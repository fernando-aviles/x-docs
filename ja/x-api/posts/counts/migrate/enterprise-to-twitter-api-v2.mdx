<div id="enterprise-compared-to-x-api-v2">
  ### Enterprise と X API v2 の比較
</div>

**共通点**

* 粒度
* ページネーション
* タイムゾーン

**相違点**

* エンドポイント URL
* App および Project の要件
* 利用可能な期間
* レスポンス data のフォーマット
* HTTP メソッド
* リクエストの時刻フォーマット
* リクエストパラメータ
* フィルタリング演算子

<div id="similarities">
  #### 類似点
</div>

**粒度**

返されるデータの粒度を選択するためのパラメータは異なります（エンタープライズ版では `bucket`、v2 版では `granularity`）が、そのパラメータに指定できる値は同じで、デフォルトの動作も同一です。

* `day`
* `hour` (default)
* `minute`

**ページネーション**

v2 には追加のページネーション機能があります（`since_id` と `until_id` を使用して投稿 ID で移動できる新しいページネーションパラメータ）。しかし、エンタープライズ版と v2 のどちらでも、時間を使ったページネーションが可能です（エンタープライズ版では `fromDate` と `toDate`、v2 では `start_time` と `end_time`）。

エンタープライズ版を使用している場合は、ページネーションに `next` パラメータを使用し、次ページ用トークンのフィールド名は `next` となり、レスポンスのルート直下に配置されます。

v2 を使用している場合は、ページネーションに `next_token` または `pagination_token` パラメータのいずれかを使用でき、次ページ用トークンはレスポンス内の `meta.next_token` に配置されます。
 

**タイムゾーン**

ページネーションのセクションで述べたように、エンタープライズ版と v2 のどちらでも、時間を使って異なるページのデータを取得できます。いずれの場合も、これらのパラメータを使用する際のタイムゾーンとして UTC を使用します。

<div id="differences">
  #### 違い
</div>

**エンドポイント URL**

* Enterprise エンドポイント:
  * 30 日間 - `http://gnip-api.x.com/search/30day/accounts/:account_name/:label/counts.json`
  * 全アーカイブ - `http://gnip-api.x.com/search/fullarchive/accounts/:account_name/:label/counts.json`
* X API v2 エンドポイント
  * 最近 (7 日間) - `https://api.x.com/2/tweets/counts/recent`
  * 全アーカイブ - `https://api.x.com/2/tweets/counts/all`

**App と Project の要件**

X API v2 エンドポイントでは、リクエストの認証時に、[Project](/ja/resources/fundamentals/developer-apps) に関連付けられた [開発者用 App](/ja/resources/fundamentals/developer-apps) の認証情報を使用する必要があります。すべての X API v1.1 エンドポイントでは、単独の App の認証情報、または Project に関連付けられた App の認証情報を使用できます。
 

**利用可能な期間**

Enterprise API と X API v2 の両方で、全アーカイブの投稿に対する投稿ボリュームのデータを取得できるエンドポイントが用意されています。

ただし、X API v2 には Enterprise API のような 30 日間の期間用エンドポイントはありません。その代わり、前述の全アーカイブ用、または [v2 Search Posts エンドポイント](/ja/x-api/posts/search/introduction) と整合する 7 日間の期間用エンドポイントが用意されています。
 

**レスポンスデータの形式**

Enterprise と X API v2 で受け取るデータの形式には、いくつか細かな違いがあります。

* Enterprise のカウントデータは `results` オブジェクト内にありますが、v2 のカウントデータは `data` オブジェクト内にあります。
* Enterprise のカウントのフィールドは `timePeriod` (開始時間) と `count` ですが、v2 では期間を `start` と `end` フィールドに分割し (Enterprise とは異なる日付/時刻フォーマットを使用し、「リクエスト時刻フォーマット」で説明されています)、`count` フィールドは `tweet_count` に名前が変更されています。
* Enterprise のメタデータにはルートレベルで `totalCount`、`next`、および `requestParameters` オブジェクトが含まれます。これに対して v2 では `requestParameters` オブジェクトは含まれず、代わりに次の項目をルートレベルに存在する `meta` オブジェクトに移動し名前を変更しています: `total_tweet_count` と `next_token`。
   

**HTTP メソッド**

Enterprise バージョンの API では、JSON ボディを伴う POST HTTP メソッド、またはクエリ文字列を伴う GET HTTP メソッドのいずれかでリクエストを送信できます。

v2 では、クエリ文字列を伴う GET HTTP メソッドのみ使用できます。
 

**リクエスト時刻フォーマット**

このエンドポイントの Enterprise バージョンでは、ページネーション用パラメータと `timePeriod` レスポンスフィールドの両方で、次の日時フォーマットを使用します: `YYYYMMDDHHmm`

v2 エンドポイントでは、ページネーション用パラメータと `start` および `end` レスポンスフィールドの両方で、次の ISO 8601/RFC 3339 日時フォーマットを使用します: `YYYY-MM-DDTHH:mm:ssZ`

**リクエストパラメータ**

以下は、Enterprise と X API v2 におけるリクエストパラメータの一覧表です。

| Enterprise | Search Posts v2 |
| :--- | :--- |
| query | query |
| bucket | granularity |
| fromDate (YYMMDDHHmm) | start&#95;time (YYYY-MM-DDTHH:mm:ssZ) |
| toDate (YYMMDDHHmm) | end&#95;time (YYYY-MM-DDTHH:mm:ssZ) |
|     | since&#95;id |
|     | until&#95;id |
| next | next&#95;token と pagination&#95;token |

**フィルタリングオペレーター**

Enterprise と X API v2 間でのオペレーターはほぼ同じですが、利用可能なオペレーターにいくつか違いがあり、X API v2 バージョンのみに導入された新しいオペレーターもあります。

X API v2、Enterprise、さらには Premium で利用可能なオペレーターの完全な一覧表については、[Post counts 移行ランディングページ](/ja/x-api/posts/counts/migrate/overview)を参照してください。
