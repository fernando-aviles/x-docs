このガイドでは、投稿ルックアップエンドポイントをアプリケーションに統合するために必要な主要な概念について説明します。

***

<div id="authentication">
  ## 認証
</div>

すべての X API v2 エンドポイントには認証が必要です。ユースケースに合った認証方法を選択してください。

| 認証方法 | 主な用途 | プライベートメトリクスへのアクセス可否 |
|:-------|:---------|:---------------------------|
| [OAuth 2.0 App-Only](/ja/resources/fundamentals/authentication#oauth-2-0) | サーバー間、公開データ | いいえ |
| [OAuth 2.0 Authorization Code with PKCE](/ja/resources/fundamentals/authentication#oauth-2-0-authorization-code-flow-with-pkce-2) | ユーザー向けアプリ | はい（アプリを承認したユーザーの投稿） |
| [OAuth 1.0a User Context](/ja/resources/fundamentals/authentication) | レガシー統合 | はい（アプリを承認したユーザーの投稿） |

<div id="app-only-authentication">
  ### アプリケーション専用認証
</div>

公開されている投稿データを取得するには、Bearer Token を使用します。

<CodeGroup dropdown>
  ```bash cURL
  curl "https://api.x.com/2/tweets/1234567890" \
    -H "Authorization: Bearer $BEARER_TOKEN"
  ```

  ```python Python SDK
  from xdk import Client

  client = Client(bearer_token="YOUR_BEARER_TOKEN")

  # ID を指定して単一の投稿を取得
  response = client.posts.get("1234567890")
  print(response.data)
  ```

  ```javascript JavaScript SDK
  import { Client } from "@xdevplatform/xdk";

  const client = new Client({ bearerToken: "YOUR_BEARER_TOKEN" });

  const response = await client.posts.get("1234567890");
  console.log(response.data);
  ```
</CodeGroup>

<div id="user-context-authentication">
  ### User Context 認証
</div>

非公開メトリクスにアクセスするには、投稿の作成者として認証してください。

<Warning>
  次のフィールドには User Context 認証が必要です:

  * `tweet.fields.non_public_metrics`
  * `tweet.fields.promoted_metrics`
  * `tweet.fields.organic_metrics`
  * `media.fields.non_public_metrics`
  * `media.fields.promoted_metrics`
  * `media.fields.organic_metrics`
</Warning>

***

<div id="fields-and-expansions">
  ## フィールドと展開
</div>

X API v2 はデフォルトで最小限の data のみが返されます。必要な情報だけを取得するには、`fields` と `expansions` を使用してください。

<div id="default-response">
  ### デフォルトのレスポンス
</div>

```json
{
  "data": {
    "id": "1234567890",
    "text": "Hello world!",
    "edit_history_tweet_ids": ["1234567890"]
  }
}
```

<div id="available-fields">
  ### 利用可能なフィールド
</div>

<Accordion title="tweet.fields">
  | Field | Description |
  |:------|:------------|
  | `created_at` | 投稿の作成タイムスタンプ |
  | `author_id` | 投稿者のユーザーID |
  | `public_metrics` | いいね、リポスト、返信、引用数 |
  | `entities` | ハッシュタグ、メンション、URL、キャッシュタグ |
  | `attachments` | メディアキー、投票ID |
  | `conversation_id` | スレッド識別子 |
  | `context_annotations` | トピック／エンティティの分類情報 |
  | `in_reply_to_user_id` | 返信先のユーザー |
  | `lang` | 検出された言語 |
  | `source` | 投稿に使用されたクライアント |
  | `possibly_sensitive` | センシティブなコンテンツを示すフラグ |
  | `reply_settings` | 返信できる相手の範囲 |
</Accordion>

<Accordion title="user.fields (requires author_id expansion)">
  | Field | Description |
  |:------|:------------|
  | `username` | @ハンドル |
  | `name` | 表示名 |
  | `profile_image_url` | アバターURL |
  | `verified` | 認証ステータス |
  | `description` | 自己紹介 |
  | `public_metrics` | フォロワー数／フォロー数 |
  | `created_at` | アカウント作成日時 |
</Accordion>

<Accordion title="media.fields (requires attachments.media_keys expansion)">
  | Field | Description |
  |:------|:------------|
  | `url` | メディアURL |
  | `preview_image_url` | サムネイルURL |
  | `type` | photo、video、animated&#95;gif |
  | `duration_ms` | 動画の再生時間 |
  | `height`, `width` | 縦横サイズ |
  | `alt_text` | アクセシビリティ用テキスト |
</Accordion>

<div id="example-with-fields">
  ### フィールド指定の例
</div>

<CodeGroup dropdown>
  ```bash cURL
  curl "https://api.x.com/2/tweets/1234567890?\
  tweet.fields=created_at,public_metrics,entities&\
  expansions=author_id,attachments.media_keys&\
  user.fields=username,verified&\
  media.fields=url,type" \
    -H "Authorization: Bearer $BEARER_TOKEN"
  ```

  ```python Python SDK
  from xdk import Client

  client = Client(bearer_token="YOUR_BEARER_TOKEN")

  # 追加のフィールドと展開を含む投稿を取得します
  response = client.posts.get(
      "1234567890",
      tweet_fields=["created_at", "public_metrics", "entities"],
      expansions=["author_id", "attachments.media_keys"],
      user_fields=["username", "verified"],
      media_fields=["url", "type"]
  )

  print(response.data)
  print(response.includes)  # 展開されたユーザーおよびメディアオブジェクトを含みます
  ```

  ```javascript JavaScript SDK
  import { Client } from "@xdevplatform/xdk";

  const client = new Client({ bearerToken: "YOUR_BEARER_TOKEN" });

  const response = await client.posts.get("1234567890", {
    tweetFields: ["created_at", "public_metrics", "entities"],
    expansions: ["author_id", "attachments.media_keys"],
    userFields: ["username", "verified"],
    mediaFields: ["url", "type"],
  });

  console.log(response.data);
  console.log(response.includes); // 展開されたユーザーおよびメディアオブジェクトを含みます
  ```
</CodeGroup>

<div id="post-edits">
  ## 投稿の編集
</div>

投稿は、作成後30分以内であれば最大5回まで編集できます。

<div id="how-it-works">
  ### 仕組み
</div>

* 各編集のたびに新しい投稿IDが作成されます
* `edit_history_tweet_ids` にはすべてのバージョンが格納されます（古いものから順）
* エンドポイントは常に最新バージョンを返します

<div id="example-response">
  ### レスポンス例
</div>

```json
{
  "data": {
    "id": "1234567893",
    "text": "Hello world! (edited twice)",
    "edit_history_tweet_ids": [
      "1234567890",
      "1234567891",
      "1234567893"
    ]
  }
}
```

<Tip>
  30 分の編集可能時間を過ぎた後に取得した投稿は、最終版を表します。リアルタイムのユースケースでは、公開された直後の投稿は、まだ編集される可能性がある点に注意してください。
</Tip>

<div id="error-handling">
  ## エラー処理
</div>

<div id="common-errors">
  ### 一般的なエラー
</div>

| Status | エラー内容 | 解決方法 |
|:-------|:-----------|:---------|
| 400 | 無効なリクエスト | パラメータの形式を確認してください |
| 401 | 認証されていません | 認証情報を確認してください |
| 403 | アクセスが禁止されています | アプリの権限を確認してください |
| 404 | 見つかりません | 投稿が削除されたか、存在しません |
| 429 | リクエストが多すぎます | しばらく待ってから再試行してください（レート制限を参照） |

<div id="deleted-or-protected-posts">
  ### 削除済みまたは保護された投稿
</div>

削除された投稿、またはあなたがフォローしていない保護されたアカウントの投稿の場合:

* 単一投稿のルックアップは `404` を返します
* 複数投稿のルックアップでは、その投稿は結果から省かれ、`errors` 配列が返されます

```json
{
  "data": [
    { "id": "1234567890", "text": "Available post" }
  ],
  "errors": [
    {
      "resource_id": "1234567891",
      "resource_type": "tweet",
      "title": "Not Found Error",
      "detail": "Could not find tweet with id: [1234567891]."
    }
  ]
}
```

  ## ベストプラクティス
</div>

<CardGroup cols={2}>
  <Card title="バッチリクエスト" icon="layer-group">
    multi-Post エンドポイントを使用して一度に最大 100 件の投稿を取得し、API コール数を削減します。
  </Card>

  <Card title="必要なフィールドのみをリクエスト" icon="filter">
    レスポンスサイズと処理時間を最小限に抑えるために、必要なフィールドのみを指定します。
  </Card>

  <Card title="レスポンスをキャッシュ" icon="database">
    同一コンテンツへの繰り返しリクエストを減らすために、投稿の data をローカルにキャッシュします。
  </Card>

  <Card title="編集への対応" icon="clock-rotate-left">
    リアルタイムアプリケーションの場合は、30 分の編集ウィンドウ後に投稿を再取得することを検討してください。
  </Card>
</CardGroup>
