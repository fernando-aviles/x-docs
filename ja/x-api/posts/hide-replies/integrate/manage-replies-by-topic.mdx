<div id="manage-replies-by-topic">
  ### トピック別に返信を管理する
</div>

hide replies エンドポイントを利用すると、人やブランドの会話をトピックに沿った状態に保てるようにする連携機能を構築できます。このページでは、hide replies と [recent search](/ja/x-api/posts/recent-search) エンドポイントを使って会話を管理する方法を説明します。

recent search には、ある会話およびその返信を取得する機能があり、さらに Post のペイロードでは各 Post のコンテキストとトピックを言語に依存せず把握するために [Post annotations](/ja/x-api/fundamentals/post-annotations) が返されます。

アプリのフローには、会話を表示・管理するためのコントロールが含まれます。

1. ユーザーの投稿を読み取り、その返信を管理するための許可をユーザーに求めます。

2. Post の URL から直近の会話を取得し、その会話が認証中のユーザーによるものであることを確認します。

3. recent search エンドポイントを呼び出し、会話内の各 Post を表示します。リクエストには会話 ID を用いた検索クエリとアノテーションの expansion を含め、X による解釈に基づいて、その Post がスポーツ関連かどうかを判定します。

4. ユーザーが選択したときに返信を非表示にするために、Hide replies を呼び出します。また、誤って非表示にした場合に備えて、この操作を元に戻せる手段も提供し、常にユーザーがコントロールできるようにします。 

5. 会話が長くなる場合は、[検索結果をページングする](/ja/x-api/posts/search/integrate/paginate)ためのコントロールを提供します。
    

<div id="optimize-for-the-user-and-for-usage">
  #### ユーザー（と利用状況）のために最適化する
</div>

ユーザーが実行しようとしているあらゆるアクションを、自分でコントロールできるようなフローを設計できます。この原則を念頭に置くことで、投稿の閲覧を最適化できる連携も構築しやすくなります。

1. 認証済みユーザーは自分が開始した会話しか管理できないため、その条件を満たさない場合はフローを早い段階で終了させるべきです。
   * 最初に投稿のルックアップリクエストを行います。投稿の URL が無効である場合や、その会話が認証済みユーザーによって開始されていない場合は、フローを早期終了させます。
   * こうすることで、その会話が認証済みユーザーによってモデレートできない場合に、アプリが recent search リクエストを行う必要がなくなります。
2. 個別にリクエストを行わないよう、同じリクエスト内で[ユーザーおよび投稿のフィールド](/ja/x-api/fundamentals/fields)を要求します。この方法はアプリのパフォーマンス向上にも役立ちます。
3. 不要なリクエストは行わないようにします。このアプリは返信の非表示ステータスをユーザーのブラウザーにキャッシュします。これは大規模な会話で役立ち、ユーザーが後からモデレーション作業を再開したい場合に便利であり、返信を非表示または再表示するためのリクエストをアプリ側で最適化するのにも役立ちます。
