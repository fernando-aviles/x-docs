<div id="manage-replies-by-topic">
  ### トピック別に返信を管理する
</div>

Hide replies エンドポイントを使用すると、人やブランドが会話をトピックに沿ったものに保てるようにする統合機能を構築できます。このページでは、Hide replies エンドポイントと [recent search](/ja/x-api/posts/recent-search) エンドポイントを使って会話を管理する方法を説明します。

Recent search には、会話とその返信を取得する機能があり、Post ペイロードには、言語に関係なく各投稿のコンテキストとトピックを理解するのに役立つ [Post annotations](/ja/x-api/fundamentals/post-annotations) が含まれています。

アプリのフローには、会話を表示および管理するためのコントロールが含まれます。

1. ユーザーの投稿とその返信を読み取り、管理するための許可をユーザーに求めます。

2. 投稿の URL から直近の会話を取得し、その会話が認証中のユーザーのものであることを確認します。

3. 会話内の各投稿を表示するために recent search エンドポイントを呼び出します。リクエストには会話 ID を指定した検索クエリと annotation の展開を含め、X による解釈にもとづいて、その投稿がスポーツ関連かどうかを判定します。

4. ユーザーが選択したときに返信を非表示にするために Hide replies を呼び出します。また、ユーザーが常に操作をコントロールできるよう、この操作を取り消す手段も提供します。 

5. 会話が長い場合は、[検索結果をページングする](/ja/x-api/posts/search/integrate/paginate) ためのコントロールを提供します。
    

<div id="optimize-for-the-user-and-for-usage">
  #### ユーザー（および利用状況）に最適化する
</div>

ユーザーが実行しようとしているあらゆるアクションについて、その主導権をユーザー側に持たせるようなフローを設計できます。この原則を念頭に置くことで、投稿の閲覧に最適化された連携機能を構築することにもつながります。

1. 認証済みユーザーは自分が開始した会話しか管理できないため、その条件を満たさない場合はフローを早期終了させるべきです。
   * 最初に投稿のルックアップリクエストを行います。投稿 URL が有効でない場合や、その会話が認証ユーザーによって開始されたものではない場合は、フローを早期終了します。
   * こうすることで、会話が認証ユーザーによってモデレートできない場合には、アプリが recent search リクエストを行う必要がなくなります。
2. 別々のリクエストを送らなくても済むように、同じリクエスト内で [ユーザーおよび投稿のフィールド](/ja/x-api/fundamentals/fields) をリクエストします。このアプローチは、アプリのパフォーマンス向上にもつながります。
3. 不要なリクエストは行わないようにします。このアプリは、返信が非表示かどうかのステータスをユーザーのブラウザーにキャッシュします。これは、会話が大規模な場合に、ユーザーが後からモデレーション作業を再開したいときに便利であり、返信を非表示または再表示するためのリクエストをアプリ側で最適化するのに役立ちます。
