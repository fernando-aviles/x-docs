Batch Compliance エンドポイントでは、投稿 ID やユーザー ID のデータセットをアップロードし、それらの現在のコンプライアンスステータスを取得できます。これを利用して、削除された投稿、凍結されたアカウント、その他のコンプライアンスイベントを特定できます。

<div id="how-it-works">
  ## 仕組み
</div>

1. **ジョブを作成する** — タイプ（投稿またはユーザー）とアップロード用URLを指定します
2. **IDをアップロードする** — 提供されたURLにデータセットをアップロードします
3. **処理完了を待つ** — ジョブは非同期で処理されます
4. **結果をダウンロードする** — 各IDのコンプライアンス状況を取得します

***

<div id="endpoints">
  ## エンドポイント
</div>

| Method | Endpoint | 説明 |
|:-------|:---------|:------------|
| POST | [`/2/compliance/jobs`](/ja/x-api/compliance/create-compliance-job) | 新しいコンプライアンスジョブを作成する |
| GET | [`/2/compliance/jobs/:id`](/ja/x-api/compliance/get-compliance-job-by-id) | ジョブのステータスを取得する |
| GET | [`/2/compliance/jobs`](/ja/x-api/compliance/get-compliance-jobs) | すべてのジョブを一覧表示する |

***

<div id="job-types">
  ## ジョブタイプ
</div>

| タイプ | 説明 |
|:-----|:------------|
| `tweets` | 投稿のコンプライアンス状態を確認 |
| `users` | ユーザーのコンプライアンス状態を確認 |

***

<div id="compliance-events">
  ## コンプライアンスイベント
</div>

<div id="post-events">
  ### 投稿イベント
</div>

| Event | Description |
|:------|:------------|
| `deleted` | 投稿がユーザーによって削除されました |
| `bounced` | 投稿がコンプライアンスチェックに失敗しました |
| `protected` | アカウントが非公開設定になりました |
| `suspended` | アカウントが凍結されました |
| `scrub_geo` | 位置情報データが削除されました |

<div id="user-events">
  ### ユーザーイベント
</div>

| Event | Description |
|:------|:------------|
| `deleted` | アカウントが削除された |
| `suspended` | アカウントが凍結された |
| `protected` | アカウントが非公開になった |
| `deactivated` | アカウントが無効化された |

***

<div id="example-create-a-job">
  ## 例：ジョブの作成
</div>

```bash
curl -X POST "https://api.x.com/2/compliance/jobs" \
  -H "Authorization: Bearer $BEARER_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "type": "tweets",
    "name": "my-compliance-job"
  }'
```
