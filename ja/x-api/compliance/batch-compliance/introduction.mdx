Batch Compliance エンドポイントでは、投稿 ID またはユーザー ID のデータセットをアップロードし、それらの現在のコンプライアンスステータスを取得できます。これを使用して、削除された投稿、凍結されたアカウント、その他のコンプライアンスイベントを特定できます。

<div id="how-it-works">
  ## 仕組み
</div>

1. **ジョブを作成** — タイプ（投稿またはユーザー）とアップロード URL を指定します
2. **ID をアップロード** — 提供された URL にデータセットをアップロードします
3. **処理を待機** — ジョブは非同期で処理されます
4. **結果をダウンロード** — 各 ID のコンプライアンス状況を取得します

***

<div id="endpoints">
  ## エンドポイント
</div>

| メソッド | エンドポイント | 説明 |
|:-------|:---------|:------------|
| POST | [`/2/compliance/jobs`](/ja/x-api/compliance/create-compliance-job) | 新しいコンプライアンスジョブを作成する |
| GET | [`/2/compliance/jobs/:id`](/ja/x-api/compliance/get-compliance-job-by-id) | ジョブのステータスを取得する |
| GET | [`/2/compliance/jobs`](/ja/x-api/compliance/get-compliance-jobs) | すべてのジョブを一覧表示する |

***

<div id="job-types">
  ## ジョブの種類
</div>

| タイプ | 説明 |
|:-----|:------------|
| `tweets` | 投稿のコンプライアンスステータスを確認します |
| `users` | ユーザーのコンプライアンスステータスを確認します |

***

<div id="compliance-events">
  ## コンプライアンスイベント
</div>

<div id="post-events">
  ### 投稿イベント
</div>

| Event | 説明 |
|:------|:------------|
| `deleted` | 投稿がユーザーにより削除されました |
| `bounced` | 投稿がコンプライアンスチェックに失敗しました |
| `protected` | アカウントが非公開になりました |
| `suspended` | アカウントが凍結されました |
| `scrub_geo` | 位置情報データが削除されました |

<div id="user-events">
  ### ユーザーイベント
</div>

| Event | Description |
|:------|:------------|
| `deleted` | アカウントが削除されました |
| `suspended` | アカウントが凍結されました |
| `protected` | アカウントが保護されました |
| `deactivated` | アカウントが無効化されました |

***

<div id="example-create-a-job">
  ## 例：ジョブの作成
</div>

```bash
curl -X POST "https://api.x.com/2/compliance/jobs" \
  -H "Authorization: Bearer $BEARER_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "type": "tweets",
    "name": "my-compliance-job"
  }'
```
