Batch Compliance エンドポイントを使用すると、ポスト ID またはユーザー ID のデータセットをアップロードし、現在のコンプライアンスステータスを取得できます。これにより、削除された投稿、凍結されたアカウント、その他のコンプライアンスイベントを特定できます。

<div id="how-it-works">
  ## 仕組み
</div>

1. **ジョブを作成** — `type` (投稿またはユーザー) とアップロード先 URL を指定します
2. **ID をアップロード** — 提供された URL にデータセットをアップロードします
3. **処理を待機** — ジョブは非同期で実行されます
4. **結果をダウンロード** — 各 ID のコンプライアンス状況を取得します

***

<div id="endpoints">
  ## エンドポイント
</div>

| Method | Endpoint | 説明 |
|:-------|:---------|:------------|
| POST | [`/2/compliance/jobs`](/ja/x-api/compliance/create-compliance-job) | 新しいコンプライアンスジョブを作成する |
| GET | [`/2/compliance/jobs/:id`](/ja/x-api/compliance/get-compliance-job-by-id) | ジョブのステータスを取得する |
| GET | [`/2/compliance/jobs`](/ja/x-api/compliance/get-compliance-jobs) | すべてのジョブを一覧表示する |

***

<div id="job-types">
  ## ジョブの種類
</div>

| タイプ | 説明 |
|:-----|:------------|
| `tweets` | ポストのコンプライアンスステータスを確認する |
| `users` | ユーザーのコンプライアンスステータスを確認する |

***

<div id="compliance-events">
  ## コンプライアンスイベント
</div>

<div id="post-events">
  ### ポストイベント
</div>

| Event | Description |
|:------|:------------|
| `deleted` | ポストがユーザーによって削除されました |
| `bounced` | ポストがコンプライアンスチェックに失敗しました |
| `protected` | アカウントが非公開設定になりました |
| `suspended` | アカウントが凍結されました |
| `scrub_geo` | 位置情報データが削除されました |

<div id="user-events">
  ### ユーザーイベント
</div>

| Event | 説明 |
|:------|:------------|
| `deleted` | アカウントが削除された |
| `suspended` | アカウントが凍結された |
| `protected` | アカウントが保護された |
| `deactivated` | アカウントが無効化された |

***

<div id="example-create-a-job">
  ## 例: ジョブを作成する
</div>

```bash
curl -X POST "https://api.x.com/2/compliance/jobs" \
  -H "Authorization: Bearer $BEARER_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "type": "tweets",
    "name": "my-compliance-job"
  }'
```
