<div id="overview">
  ## Overview
</div>

フィルタ済みストリームのエンドポイントグループは、開発者が公開投稿のストリームをフィルタリングできるようにします。このエンドポイントグループの機能には、ルールの作成と管理を行い、それらのルールを適用して、一致する公開投稿を返す投稿ストリームをフィルタリングできる複数のエンドポイントが含まれます。このエンドポイントグループを使用すると、特定のトピックやイベントを監視したり、コンペティションに関する会話をモニタリングしたり、トレンドがどのように形成されるかを把握したり、その他多くのことが可能になります。

開発者は REST の [rules endpoint](/ja/x-api/posts/filtered-stream#post-2-tweets-search-stream-rules) を使用して、定義された条件に一致する投稿をフィルタリングするためのルールを追加および削除できます。これらの [rules](/ja/x-api/posts/filtered-stream#building-rules-for-filtered-stream) は、メッセージのキーワード、ハッシュタグ、URL などの投稿属性にマッチするオペレーターを使用して作成できます。オペレーターおよびルール句は、ブールロジックや括弧と組み合わせることで、フィルターのマッチング動作をより細かく制御できます。 

一連のルールを追加したら、X が JSON 形式で [Post objects](/ja/x-api/fundamentals/data-dictionary#tweet) を配信し始める webhook を登録できます。webhook には、ルールに一致するコンテンツのみが配信されます。

このエンドポイントは編集済み投稿をサポートします。webhook には、1 つ以上のフィルターに一致する編集済み投稿と、その編集履歴（投稿 ID の配列を含む）が配信されます。編集履歴のない投稿については、この配列には単一の ID が格納されます。編集された投稿については、この配列には複数の ID が含まれ、編集の順序を反映した昇順に並び、配列の最後の要素が最新バージョンになります。投稿編集の仕組みについて詳しくは、[Posts edits fundamentals](/ja/x-api/fundamentals/edit-posts) ページを参照してください。 

**注意:** このエンドポイントグループは、ルールの設定方法という点では [v2 filtered stream endpoint](/ja/x-api/posts/filtered-stream/introduction) と類似しています。唯一の違いは、ルールに一致した投稿の配信メカニズムです。

* v2 filtered stream endpoint の場合は、永続的な接続を確立し、ルールに一致する投稿をリッスンする必要があります。
* この filtered stream webhook endpoint の場合は、webhook を登録すると、X がルールに一致する投稿を webhook に配信します。

これにより、クライアント側の切断や、サービスの通常の再起動に伴うサーバー側の切断を処理する必要がなくなります。毎秒数百件のイベントを配信することが想定されるため、webhook サーバーはこれらの同時接続試行を処理できる必要があります。

このエンドポイントは現在エンタープライズ開発者向けに提供されており、次の構成をサポートします。

* Project あたり 25,000 件以上のルール
* ルールの作成時にすべてのオペレーターを使用可能
* 最大 2,048 文字までのルールを作成可能
* エンタープライズアクセスについては[こちら](https://developer.x.com/en/products/x-api/enterprise/enterprise-api-interest-form)から申請してください

filtered stream から返される投稿は、月間の [Post cap](/ja/x-api/fundamentals/post-cap) にカウントされます。
