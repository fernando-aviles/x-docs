レート制限は、一定期間内に実行できる API リクエストの数を制御します。これにより、プラットフォーム全体での公平な利用とシステムの安定性が確保されます。

***

<div id="how-rate-limits-work">
  ## レート制限の仕組み
</div>

| 概念 | 説明 |
|:--------|:------------|
| **時間枠** | ほとんどの制限は 15 分ごとにリセットされます |
| **ユーザー単位の制限** | OAuth 1.0a または OAuth 2.0 のユーザートークンを使用する場合に適用されます |
| **アプリ単位の制限** | Bearer Token（アプリのみ認証）を使用する場合に適用されます |
| **エンドポイント別** | 各エンドポイントごとに独自の制限が設定されています |

***

<div id="checking-your-limits">
  ## レート制限の確認
</div>

すべての API レスポンスには、現在のレート制限状況を示すヘッダーが含まれています。

```
x-rate-limit-limit: 900
x-rate-limit-remaining: 847
x-rate-limit-reset: 1705420800
```

| Header                   | Description                |
| :----------------------- | :------------------------- |
| `x-rate-limit-limit`     | 現在の時間ウィンドウで許可される最大リクエスト数   |
| `x-rate-limit-remaining` | 現在の時間ウィンドウで残っているリクエスト数     |
| `x-rate-limit-reset`     | 制限がリセットされる時刻（Unix タイムスタンプ） |

***

<div id="rate-limit-errors">
  ## レート制限エラー
</div>

レート制限を超えると、**429 Too Many Requests** のレスポンスが返されます。

```json
{
  "errors": [{
    "code": 88,
    "message": "Rate limit exceeded"
  }]
}
```

<div id="best-practices">
  ## ベストプラクティス
</div>

<CardGroup cols={2}>
  <Card title="レスポンスをキャッシュする" icon="database">
    同じデータに対する重複したリクエストを減らすために、APIのレスポンスをローカルに保存します。
  </Card>

  <Card title="指数バックオフを使用する" icon="clock-rotate-left">
    レート制限に達した場合は、再試行する前に待機します。再試行のたびに待機時間を2倍にします。
  </Card>

  <Card title="ヘッダーを確認する" icon="list-check">
    レート制限に達するのを防ぐために、レート制限ヘッダーを監視します。
  </Card>

  <Card title="ストリーミングを使用する" icon="signal-stream">
    リアルタイムのデータが必要な場合は、検索エンドポイントをポーリングする代わりに filtered stream を使用します。
  </Card>
</CardGroup>
