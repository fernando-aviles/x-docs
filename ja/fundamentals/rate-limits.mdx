レート制限は、所定の時間内に実行できる API リクエスト数を制御します。これにより、プラットフォーム全体での公平な利用とシステムの安定性が確保されます。

***

<div id="rate-limits-by-product">
  ## プロダクトごとのレート制限
</div>

各 X API プロダクトには、それぞれ独自のレート制限方式があります。

  <Card title="X API v2" icon="square-x-twitter" href="/ja/x-api/fundamentals/rate-limits">

<div id="how-rate-limits-work">
  ## レート制限の仕組み
</div>

| 概念 | 説明 |
|:--------|:------------|
| **時間枠** | ほとんどのレート制限は15分ごとにリセットされます |
| **ユーザー単位の制限** | OAuth 1.0a または OAuth 2.0 のユーザートークンを使用する場合に適用されます |
| **アプリ単位の制限** | Bearer Token（アプリのみ）による認証を使用する場合に適用されます |
| **エンドポイント固有** | 各エンドポイントごとに独自の制限が設定されています |

***

<div id="checking-your-limits">
  ## レート制限の確認
</div>

すべての API レスポンスには、現在のレート制限状況を示すヘッダーが含まれています。

```
x-rate-limit-limit: 900
x-rate-limit-remaining: 847
x-rate-limit-reset: 1705420800
```

| Header                   | Description                  |
| :----------------------- | :--------------------------- |
| `x-rate-limit-limit`     | 現在の時間枠で許可される最大リクエスト数         |
| `x-rate-limit-remaining` | 現在の時間枠で残っているリクエスト数           |
| `x-rate-limit-reset`     | 制限がリセットされる時刻を表す Unix タイムスタンプ |

***

<div id="rate-limit-errors">
  ## レート制限エラー
</div>

レート制限を超えると、**429 Too Many Requests** レスポンスが返されます。

```json
{
  "errors": [{
    "code": 88,
    "message": "Rate limit exceeded"
  }]
}
```

<div id="best-practices">
  ## ベストプラクティス
</div>

<CardGroup cols={2}>
  <Card title="レスポンスをキャッシュする" icon="database">
    同じデータに対する繰り返しのリクエストを減らすため、API レスポンスをローカルに保存します。
  </Card>

  <Card title="指数バックオフを使用する" icon="clock-rotate-left">
    レート制限が適用された場合は、再試行する前に待機します。再試行のたびに待機時間を 2 倍にします。
  </Card>

  <Card title="ヘッダーを確認する" icon="list-check">
    レート制限関連のヘッダーを監視し、上限に達する前に回避できるようにします。
  </Card>

  <Card title="ストリーミングを使用する" icon="signal-stream">
    リアルタイムのデータが必要な場合は、検索エンドポイントをポーリングするのではなく、フィルタードストリームを使用します。
  </Card>
</CardGroup>
