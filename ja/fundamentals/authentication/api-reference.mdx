<div id="post-oauthrequest_token">
  ### POST oauth/request_token
</div>

Consumer アプリケーションがユーザー認可を要求するための OAuth Request Token を取得できるようにします。このメソッドは、[OAuth 1.0a 認証フロー](http://oauth.net/core/1.0/#anchor9)の [セクション 6.1](https://oauth.net/core/1.0/#auth_step1) に記載された要件を満たします。

**すべての OAuth 認可ステップで HTTPS を使用する必要があります。**

**使用上の注意:** `oauth_nonce` には ASCII の値のみが受け付けられます。

**リソース URL[](#resource-url "この見出しへのパーマリンク")**

`https://api.x.com/oauth/request_token`

**リソース情報[](#resource-information "この見出しへのパーマリンク")**

|     |     |
| :--- | :--- |
| レスポンス形式 | JSON |
| 認証は必要ですか？ | いいえ |
| レート制限はありますか？ | はい |

**パラメーター[](#parameters "この見出しへのパーマリンク")**

| Name | Required | Description | Example |
| :--- | :--- | :--- | :--- |
| oauth&#95;callback | 必須 | OAuth 1.0a に準拠するため、このパラメーターは**必須**です。ここで指定した値は、ユーザーがお使いのアプリケーションによる自分のアカウントへのアクセスを承認した場合にリダイレクトされる URL として使用されます。アウトオブバンドの PIN モードでは `oob` を設定します。これは、デスクトップ／モバイルアプリケーションで使用するカスタムコールバックを指定する方法でもあります。事前登録済みのコールバックがあるかどうかにかかわらず、このステップでは常に `oauth_callback` を送信してください。<br /><br />このエンドポイントで使用するコールバック URL はいずれも、developer.x.com 上のアプリの設定内で構成されている必要があります。* | `http://themattharris.local/auth.php` `twitterclient://callback` |
| x&#95;auth&#95;access&#95;type | 任意 | アプリケーションがユーザーのアカウントに要求するアクセスレベルを上書きします。サポートされる値は `read` または `write` です。このパラメーターは、開発者が読み取り／書き込みアプリケーションを登録しつつ、必要に応じて読み取り専用アクセスのみを要求できるようにすることを目的としています。 |     |

コールバック URL を承認する方法については[このページ](/ja/resources/fundamentals/developer-apps#callback-urls)をご覧ください。

**注意** - developer.x.com 上で X アカウントにログインしている場合、既存の [X アプリ](/ja/resources/fundamentals/developer-apps) は [X アプリダッシュボード](https://developer.x.com/en/apps) から表示および編集できます。

**リクエスト例[](#example-request "この見出しへのパーマリンク")**

Request URL: `POST https://api.x.com/oauth/request_token`

Request POST Body: *N/A*

Authorization Header: `OAuth oauth_nonce="K7ny27JTpKVsTgdyLdDfmQQWVLERj2zAK5BslRsqyw", oauth_callback="http%3A%2F%2Fmyapp.com%3A3005%2Ftwitter%2Fprocess_callback", oauth_signature_method="HMAC-SHA1", oauth_timestamp="1300228849", oauth_consumer_key="OqEqJeafRSF11jBMStrZz", oauth_signature="Pc%2BMLdv028fxCErFyi8KXFM%2BddU%3D", oauth_version="1.0"`

Response: `oauth_token=Z6eEdO8MOmk394WozF5oKyuAv855l4Mlqo7hhlSLik&oauth_token_secret=Kd75W4OQfb2oJTV0vzGzeXftVAwgMnEK9MumzYcM&oauth_callback_confirmed=true`

<div id="get-oauthauthorize">
  ### GET oauth/authorize
</div>

Consumer アプリケーションが OAuth Request Token を使用してユーザー認可を要求できるようにします。このメソッドは、[OAuth 1.0 認証フロー](http://oauth.net/core/1.0/#anchor9)の [Section 6.2](http://oauth.net/core/1.0/#auth_step2) に対応します。デスクトップアプリケーションは必ずこのメソッドを使用しなければならず、[GET oauth / authenticate](/ja/resources/fundamentals/authentication/api-reference#get-oauth-authenticate) は使用できません。

**使用上の注意:** `oauth_callback` はこのメソッドには送信されません。代わりに [POST oauth / request&#95;token](/ja/resources/fundamentals/authentication/api-reference#post-oauth-request-token) に指定してください。

**Resource URL[](#resource-url "この見出しへのパーマリンク")**

`https://api.x.com/oauth/authorize`

**Resource Information[](#resource-information "この見出しへのパーマリンク")**

|     |     |
| :--- | :--- |
| レスポンス形式 | JSON |
| 認証が必要か | Yes |
| レート制限 | Yes |

**Parameters[](#parameters "この見出しへのパーマリンク")**

|     |     |     |     |     |
| :--- | :--- | :--- | :--- | :--- |
| Name | Required | Description | Default Value | Example |
| force&#95;login | optional | 正しいユーザーアカウントが認可されるように、ユーザーに資格情報の再入力を強制します。 |     |     |
| screen&#95;name | optional | OAuth ログイン画面のユーザー名入力ボックスを、指定した値であらかじめ入力します。 |     |     |

**Example request[](#example-request "この見出しへのパーマリンク")**

Web ブラウザーで `oauth/authorize` ステップにユーザーをリダイレクトする際に、`oauth_token` パラメーターを含めてください:
`https://api.x.com/oauth/authorize?oauth_token=Z6eEdO8MOmk394WozF5oKyuAv855l4Mlqo7hhlSLik`

<div id="get-oauthauthenticate">
  ### GET oauth/authenticate
</div>

Consumer アプリケーションが OAuth の `request_token` を使用してユーザーに承認を求めることができるようにします。

このメソッドは、コールバック認証フローを使用するアプリケーション向けに、[OAuth 1.0 authentication flow](http://oauth.net/core/1.0/#anchor9) の [Section 6.2](http://oauth.net/core/1.0/#auth_step2) を置き換えるものです。`force_login` パラメーターが `true` に設定されていない限り、このメソッドは現在ログイン中のユーザーをアクセス承認の対象アカウントとして使用します。

このメソッドは、ユーザーがすでにアプリケーションに権限を付与している場合、ユーザーが再度アプリケーションを承認しなくてもリダイレクトが行われるという点で、[GET oauth / authorize](/ja/resources/fundamentals/authentication/api-reference#get-oauth-authorize) と異なります。この動作を実現するには、[application record](https://developer.x.com/apps) で *Use Sign in with X* 設定を有効にする必要があります。

**Resource URL[](#resource-url "Permalink to this headline")**

`https://api.x.com/oauth/authenticate`

**Resource Information[](#resource-information "Permalink to this headline")**

|     |     |
| :--- | :--- |
| レスポンス形式 | JSON |
| 認証が必要? | Yes |
| レート制限あり? | Yes |

**Parameters[](#parameters "Permalink to this headline")**

|     |     |     |     |     |
| :--- | :--- | :--- | :--- | :--- |
| 名前 | 必須 | 説明 | デフォルト値 | 例 |
| force&#95;login | optional | 正しいユーザーのアカウントが承認されるように、ユーザーに認証情報の入力を強制します。 |     | *true* |
| screen&#95;name | optional | OAuth ログイン画面のユーザー名入力欄を、指定した値であらかじめ入力します。 |     |     |

**Example request[](#example-request "Permalink to this headline")**

Web ブラウザーで `oauth/authenticate` ステップにユーザーをリダイレクトし、oauth&#95;token パラメーターを含めます。
`https://api.x.com/oauth/authenticate?oauth_token=Z6eEdO8MOmk394WozF5oKyuAv855l4Mlqo7hhlSLik`

<div id="post-oauthaccess_token">
  ### POST oauth/access_token
</div>

コンシューマーアプリケーションが OAuth Request Token を OAuth Access Token に交換できるようにします。このメソッドは、[OAuth 1.0 authentication flow](http://oauth.net/core/1.0/#anchor9) の [Section 6.3](http://oauth.net/core/1.0/#auth_step3) に対応します。

**Resource URL[](#resource-url "Permalink to this headline")**

`https://api.x.com/oauth/access_token`

**Resource Information[](#resource-information "Permalink to this headline")**

|     |     |
| :--- | :--- |
| Response formats | JSON |
| Requires authentication? | Yes |
| Rate limited? | Yes |

**Parameters[](#parameters "Permalink to this headline")**

|     |     |     |     |     |
| :--- | :--- | :--- | :--- | :--- |
| Name | Required | Description | Default Value | Example |
| oauth&#95;token | 必須 | ここで指定する oauth&#95;token は、request&#95;token ステップで返された oauth&#95;token と同一である必要があります。 |     |     |
| oauth&#95;verifier | 必須 | OAuth の Web フローを使用している場合、このパラメータをコールバック URL で返された *oauth&#95;verifier* の値に設定します。アウトオブバンド OAuth を使用している場合、この値を PIN コードに設定します。OAuth 1.0a 準拠のため、このパラメータは **必須** です。OAuth 1.0a は厳格に適用されており、*oauth&#95;verifier* を使用していないアプリケーションは OAuth フローを完了できません。 |     |     |

**Example request[](#example-request "Permalink to this headline")**

`POST https://api.x.com/oauth/access_token?oauth_token=qLBVyoAAAAAAx72QAAATZxQWU6P&oauth_verifier=ghLM8lYmAxDbaqL912RZSRjCCEXKDIzx`

PIN ベースフローからの例: `POST https://api.x.com/oauth/access_token?oauth_token=9Npq8AAAAAAAx72QBRABZ4DAfY9&oauth_verifier=4868795`

**Example response[](#example-response "Permalink to this headline")**

`oauth_token=6253282-eWudHldSbIaelX7swmsiHImEL4KinwaGloHANdrY&oauth_token_secret=2EEfA6BG5ly3sR3XjE0IBSnlQu4ZrUzPiYTmrkVU&user_id=6253282&screen_name=xapi`

<div id="post-oauthinvalidate_token">
  ### POST oauth/invalidate_token
</div>

登録済みアプリケーションがクライアント認証情報を提示することで、発行済みの OAuth access&#95;token を失効させることができます。access&#95;token がいったん無効化されると、新たにアクセストークンを発行しようとした場合は別のアクセストークンが払い出され、無効化されたトークンを使用することはできなくなります。

**リソース URL[](#resource-url "Permalink to this headline")**

`https://api.x.com/1.1/oauth/invalidate_token`

**リソース情報[](#resource-information "Permalink to this headline")**

|          |                                  |
| :------- | :------------------------------- |
| レスポンス形式  | JSON                             |
| 認証は必須か   | はい - 無効化したいアクセストークンを持つユーザーコンテキスト |
| レート制限対象か | はい                               |

**リクエスト例[](#example-request "Permalink to this headline")**

```bash
        curl --request POST
          --url 'https://api.x.com/1.1/oauth/invalidate_token.json'
          --header 'authorization: OAuth oauth_consumer_key="CLIENT_KEY",
         oauth_nonce="AUTO_GENERATED_NONCE", oauth_signature="AUTO_GENERATED_SIGNATURE",
         oauth_signature_method="HMAC-SHA1", oauth_timestamp="AUTO_GENERATED_TIMESTAMP",
         oauth_token="ACCESS_TOKEN", oauth_version="1.0"'
```

**レスポンスの例[](#example-response "この見出しへのパーマリンク")**

```bash
        HTTP/1.1 200 OK
        Content-Type: application/json; charset=utf-8
        Content-Length: 127
        ...

        {"access_token":"ACCESS_TOKEN"}
```

**トークンが無効になった後のエラーレスポンス例[](#example-error-response-after-token-has-been-invalidated "Permalink to this headline")**

```bash
        HTTP/1.1 401 Authorization Required
        ...

        {"errors": [{
          "code": 89,
          "message": "Invalid or expired token."}
        ]}
```

<div id="post-oauth2token">
  ### POST oauth2/token
</div>

登録済みアプリケーションが OAuth 2 Bearer Token を取得できるエンドポイントです。取得した Bearer Token は、ユーザーコンテキストなしでアプリケーション自身として API リクエストを行うために使用できます。これは [Application-only authentication](/ja/resources/fundamentals/authentication/oauth-2-0/application-only) と呼ばれます。

Bearer Token は oauth2/invalidate&#95;token を使って無効化できます。いったん Bearer Token が無効化されると、新たに作成した際には異なる Bearer Token が払い出され、以前のトークンは使用できなくなります。

1 つのアプリケーションに対して同時に存在できる有効な Bearer Token は 1 つのみであり、このメソッドへのリクエストを繰り返しても、トークンが無効化されるまでは既に存在する同じトークンが返されます。

成功したレスポンスには、払い出された Bearer Token を表す JSON 構造が含まれます。

このメソッドで受け取ったトークンはキャッシュしてください。あまりに頻繁にリクエストを行うと、HTTP 403（コード 99）で拒否されます。

**Resource URL[](#resource-url "Permalink to this headline")**

`https://api.x.com/oauth2/token`

**Resource Information[](#resource-information "Permalink to this headline")**

|                          |                                                            |
| :----------------------- | :--------------------------------------------------------- |
| Response formats         | JSON                                                       |
| Requires authentication? | はい - API key をユーザー名、API key secret をパスワードとする Basic 認証が必要です |
| Rate limited?            | はい                                                         |

**Parameters[](#parameters "Permalink to this headline")**

|                |          |                                                                                                                                                                                                   |               |                          |
| :------------- | :------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | :------------ | :----------------------- |
| Name           | Required | Description                                                                                                                                                                                       | Default Value | Example                  |
| grant&#95;type | 必須       | アプリケーションが要求する grant のタイプを指定します。現時点では *client&#95;credentials* のみが許可されています。詳細については [Application-Only Authentication](/ja/resources/fundamentals/authentication/oauth-2-0/application-only) を参照してください。 |               | *client&#95;credentials* |

**Example request[](#example-request "Permalink to this headline")**

```bash
    POST /oauth2/token HTTP/1.1
    Host: api.x.com
    User-Agent: My X App v1.0.23
    Authorization: Basic eHZ6MWV2R ... o4OERSZHlPZw==
    Content-Type: application/x-www-form-urlencoded;charset=UTF-8
    Content-Length: 29
    Accept-Encoding: gzip

    grant_type=client_credentials
```

**レスポンス例：**

```bash
    HTTP/1.1 200 OK
    Status: 200 OK
    Content-Type: application/json; charset=utf-8
    ...
    Content-Encoding: gzip
    Content-Length: 140

    {"token_type":"bearer","access_token":"AAAA%2FAAA%3DAAAAAAAA"}
```

<div id="post-oauth2invalidate_token">
  ### POST oauth2/invalidate_token
</div>

登録済みアプリケーションは、クライアント認証情報を提示することで、発行済みの oAuth 2.0 Bearer Token を失効させることができます。一度 Bearer Token が失効すると、新たな Bearer Token の発行を試みた場合には別の Bearer Token が発行され、失効したトークンは使用できなくなります。

成功したレスポンスには、失効した Bearer Token を記述した JSON 構造が含まれます。

**Resource URL[](#resource-url "この見出しへのパーマリンク")**

`https://api.x.com/oauth2/invalidate_token`

**Resource Information[](#resource-information "この見出しへのパーマリンク")**

|                          |                                                                                                                                                                                           |
| :----------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Response formats         | JSON                                                                                                                                                                                      |
| Requires authentication? | Yes - [OAuth 1.0a](/ja/resources/fundamentals/authentication/oauth-1-0a) with the application&#39;s consumer API keys and the application owner&#39;s access token &amp; access token secret |
| Rate limited?            | Yes                                                                                                                                                                                       |

**Parameters[](#parameters "この見出しへのパーマリンク")**

| Name             | Required | Description            |
| :--------------- | :------- | :--------------------- |
| access&#95;token | 必須       | 失効させたい Bearer Token の値 |

**Example request[](#example-request "この見出しへのパーマリンク")**

```
        curl --request POST
          --url 'https://api.x.com/oauth2/invalidate_token?access_token=AAAA%2FAAA%3DAAAAAAAA'
          --header 'authorization: OAuth oauth_consumer_key="CLIENT_KEY",
         oauth_nonce="AUTO_GENERATED_NONCE", oauth_signature="AUTO_GENERATED_SIGNATURE",
         oauth_signature_method="HMAC-SHA1", oauth_timestamp="AUTO_GENERATED_TIMESTAMP",
         oauth_token="ACCESS_TOKEN", oauth_version="1.0"'
```

**レスポンス例[](#example-response "この見出しへの固定リンク")**

```
         Status: 200 OK
         Content-Type: application/json; charset=utf-8
         Content-Length: 135
         ...
       {
        "access_token": "AAAA%2FAAA%3DAAAAAAAA"
        }
```
