X API は膨大な量のデータを扱います。このデータを開発者とユーザーの双方に対して安全に保護する手段が認証です。認証にはいくつかの方法があり、以下にそれぞれを示します。

ほとんどの開発者は、認証まわりの複雑さを意識する必要はありません。クライアントライブラリがこれらの煩雑な処理を自動的に行うためです。

利用可能なクライアントライブラリの一覧は、[Tools and libraries](/ja/resources/tools-and-libraries) ページで確認できます。

<div id="authentication-methods">
  ## 認証方法
</div>

<CardGroup cols={2}>
  <Card title="OAuth 1.0a ユーザーコンテキスト" href="/ja/resources/fundamentals/authentication/oauth-1-0a/api-key-and-secret">
    OAuth 1.0a により、認可された X の開発者用 App は、非公開のアカウント情報にアクセスしたり、X アカウントに代わって X 上でアクションを実行したりできます。

    <br />

    [**詳細はこちら**](/ja/resources/fundamentals/authentication/oauth-1-0a/api-key-and-secret)
  </Card>

  <Card title="App only" href="/ja/resources/fundamentals/authentication/oauth-2-0/overview">
    App only Access Token により、X の開発者用 App は X 上で公開されている情報にアクセスできます。

    <br />

    [**詳細はこちら**](/ja/resources/fundamentals/authentication/oauth-2-0/overview)
  </Card>

  <Card title="Basic 認証" href="/ja/resources/fundamentals/authentication/basic-auth">
    X のエンタープライズ API の多くは、HTTP Basic Authentication の使用を必要とします。

    <br />

    [**詳細はこちら**](/ja/resources/fundamentals/authentication/basic-auth)
  </Card>

  <Card title="OAuth 2.0 Authorization Code フロー（PKCE 使用）" href="/ja/resources/fundamentals/authentication/oauth-2-0/authorization-code">
    OAuth 2.0 User Context により、別のアカウントに代わって認証を行い、アプリケーションのスコープをより詳細に制御しつつ、複数のデバイスにまたがる認可フローも実現できます。

    <br />

    [**詳細はこちら**](/ja/resources/fundamentals/authentication/oauth-2-0/authorization-code)
  </Card>
</CardGroup>

<Note>
  **注意:**
  App の API Keys と App only Access Token に加えて、ご自身の Access Token と Access Token Secret は、[開発者コンソール](/ja/resources/fundamentals/developer-portal) 内の [X developer Apps](/ja/resources/fundamentals/developer-apps) セクションから取得できます。

  **他のユーザーに代わってリクエストを送信したい場合は、**そのユーザー用に別個の Access Token 一式を [3-legged OAuth flow](https://developer.x.com/resources/fundamentals/authentication/obtaining-user-access-tokens) を使って生成し、そのユーザーのトークンを OAuth 1.0a ユーザーコンテキストまたは OAuth 2.0 ユーザーコンテキストのリクエストに付与する必要があります。
</Note>
