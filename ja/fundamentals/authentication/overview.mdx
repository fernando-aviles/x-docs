X API では、膨大な量のデータを扱います。このデータを開発者とユーザーの双方にとって安全に保護する手段が認証です。認証にはいくつかの方法があり、主なものを以下に示します。

ほとんどの開発者は、認証の複雑さを意識する必要はありません。クライアントライブラリがこれらの処理を自動的に行うためです。

利用可能なクライアントライブラリの一覧は、[ツールとライブラリ](/ja/resources/tools-and-libraries) ページで確認できます。

<div id="authentication-methods">
  ## 認証方法
</div>

<CardGroup cols={2}>
  <Card title="OAuth 1.0a ユーザーコンテキスト" href="/ja/resources/fundamentals/authentication/oauth-1-0a/api-key-and-secret">
    OAuth 1.0a を使用すると、認可された X の開発者用 App が、非公開のアカウント情報にアクセスしたり、X アカウントを代表して X 上でアクションを実行したりできます。

    <br />

    [**詳細を見る**](/ja/resources/fundamentals/authentication/oauth-1-0a/api-key-and-secret)
  </Card>

  <Card title="App only" href="/ja/resources/fundamentals/authentication/oauth-2-0/overview">
    App only Access Token を使用すると、X の開発者用 App が X 上で公開されている情報にアクセスできます。

    <br />

    [**詳細を見る**](/ja/resources/fundamentals/authentication/oauth-2-0/overview)
  </Card>

  <Card title="Basic authentication" href="/ja/resources/fundamentals/authentication/basic-auth">
    多くの X エンタープライズ API では、HTTP Basic Authentication の使用が必要です。

    <br />

    [**詳細を見る**](/ja/resources/fundamentals/authentication/basic-auth)
  </Card>

  <Card title="OAuth 2.0 Authorization Code Flow with PKCE" href="/ja/resources/fundamentals/authentication/oauth-2-0/authorization-code">
    OAuth 2.0 User Context を使用すると、アプリケーションのスコープをより細かく制御しつつ、別のアカウントを代表して認証を行い、複数デバイスにまたがる認可フローを実現できます。

    <br />

    [**詳細を見る**](/ja/resources/fundamentals/authentication/oauth-2-0/authorization-code)
  </Card>
</CardGroup>

<Note>
  **注:**
  自身の開発者用 App の API Key と App only Access Token、ならびに自身の Access Token と Access Token Secret は、[Developer Console](/ja/resources/fundamentals/developer-portal) 内の [X developer Apps](/ja/resources/fundamentals/developer-apps) セクションから取得できます。

  **別のユーザーを代表してリクエストを行いたい場合は、** そのユーザー向けに別の Access Token 一式を [3-legged OAuth flow](https://developer.x.com/resources/fundamentals/authentication/obtaining-user-access-tokens) を使用して生成し、そのユーザーのトークンを OAuth 1.0a ユーザーコンテキスト または OAuth 2.0 User Context のリクエストに付与する必要があります。
</Note>
