X API エンドポイントにアクセスするには、TLS 接続が必須です。TLS を利用した通信は、公開インターネットを経由してユーザーと X API 間で情報が送受信される際に、その情報を保護することでユーザーのプライバシーとセキュリティを守ります。X API への接続には、TLS バージョン 1.2 が必要です。


<div id="verification">
  ## 検証
</div>

<div id="use-an-up-to-date-root-store">
  ### 最新のルートストアを使用する
</div>

X の証明書を検証する際、アプリケーションやライブラリが信頼でき、かつ最新のルートストアを使用していることが重要です。可能であれば、オペレーティングシステムが提供するルートストアを利用するのが最も簡単な方法となる場合があります。あるいは、[Mozilla (NSS) ルートストア](https://www.mozilla.org/en-US/about/governance/policies/security-group/certs/) は公開かつ透明な形で適切に管理されています。curl も、[このストアの PEM 形式バージョン](https://curl.haxx.se/docs/caextract.html) を提供しています。

現在、X が発行する証明書の大部分は [DigiCert High Assurance EV Root CA](https://www.digicert.com/digicert-root-certificates.htm) によるものですが、これは X 関連証明書の 100% に当てはまるわけではなく、将来にわたって常にそうである保証もありません。そのため、現在使用されている DigiCert のルート証明書のみに信頼を置く設計にすると、将来的にアプリケーションで問題が発生する可能性があります。

<div id="check-crls-and-the-ocsp-status">
  ### CRL と OCSP ステータスを確認する[](#check-crls-and-the-ocsp-status "Permalink to this headline")
</div>

多くのアプリケーションは、返された証明書に対して証明書失効リスト (CRL: Certificate Revocation List) を確認せず、あるいはその確認をオペレーティングシステムに任せています。X の証明書を受け入れる前に、アプリケーションまたは TLS ライブラリが CRL と OCSP (Online Certificate Status Protocol) の検証を必ず実行するよう構成されていることを確認してください。

<div id="cdns">
  ### CDNs[](#cdns "この見出しへのパーマリンク")
</div>

メディアを含むツイートを表示する場合は、画像を表示する際に使用する HTTPS URL として `media_url_https` 属性を利用してください。将来的には、API エンドポイントから提供されるすべての URL に対して HTTPS パスが提供される予定です。

<div id="provide-an-indication-of-security-status">
  ## セキュリティ状態を示す情報を提供する
</div>

可能であれば、アプリケーションと X 間の現在のセキュリティ状態を示す表示を行ってください。一部の Web ブラウザはロックアイコンを表示することでこれを示し、その他のブラウザでは説明的なメッセージによって現在の接続状態を示します。
