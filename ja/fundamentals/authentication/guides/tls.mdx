X API エンドポイントにアクセスするには、TLS 接続が必須です。TLS による通信は、公開インターネット上を通過するユーザーと X API 間の情報を保護することで、ユーザーのプライバシーとセキュリティを維持します。X API への接続には、TLS バージョン 1.2 が必須です。


<div id="verification">
  ## 検証
</div>

<div id="use-an-up-to-date-root-store">
  ### 最新のルートストアを使用する
</div>

X 証明書を検証する際、アプリケーションやライブラリが信頼できる最新のルートストアを使用していることが重要です。可能であれば、オペレーティングシステムが提供するルートストアを使用するのが、最も簡単な方法となる場合があります。あるいは、[Mozilla (NSS) root store](https://www.mozilla.org/en-US/about/governance/policies/security-group/certs/) は公開かつ透明な形で適切に運用・管理されています。cURL も、[このストアの PEM 形式のバージョン](https://curl.haxx.se/docs/caextract.html) を提供しています。

X は現在、発行している証明書の大部分を [DigiCert High Assurance EV Root CA](https://www.digicert.com/digicert-root-certificates.htm) から発行していますが、これは X 関連証明書の 100% に当てはまるわけではなく、将来にわたって常にそうであるとも限りません。そのため、現在使用されている DigiCert のルート証明書だけを信頼する構成にしていると、将来的にアプリで問題が発生する可能性があります。

<div id="check-crls-and-the-ocsp-status">
  ### CRL と OCSP ステータスを確認する[](#check-crls-and-the-ocsp-status "この見出しへのパーマリンク")
</div>

多くのアプリケーションは、返された証明書について Certificate Revocation List（証明書失効リスト）を確認せず、あるいはその処理をオペレーティングシステムに任せています。X の証明書を受け入れる前に、利用しているアプリケーションまたは TLS ライブラリが、CRL および OCSP（Online Certificate Status Protocol）の検証を必ず実施するように設定されていることを確認してください。

<div id="cdns">
  ### CDN[](#cdns "Permalink to this headline")
</div>

メディアを含むツイートを表示する場合は、画像を表示する際に使用する HTTPS の URL として `media_url_https` 属性を使用してください。将来的には、API エンドポイントから返されるすべての URL が HTTPS のパスを返すようになります。

<div id="provide-an-indication-of-security-status">
  ## セキュリティ状態を示す
</div>

可能であれば、アプリケーションとXとの間の現在の状態が分かるように表示してください。いくつかのWebブラウザはロックアイコンによってこれを示し、他のブラウザは説明的なメッセージで現在の接続状態を示します。
