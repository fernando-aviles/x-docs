<div id="api-key-and-secret">
  ### API Key and Secret
</div>

API Key と Secret（Consumer Key と Secret とも呼ばれます）は、X API にアクセスするために必要となる、最も基本的な認証情報です。これらの認証情報は Xアプリのユーザー名とパスワードのように機能し、どのアプリからのリクエストかを X API が把握するために使用されます。 

これらの認証情報は、[authentication endpoints](/ja/resources/fundamentals/authentication/api-reference) によって、[ユーザー Access Tokens と Secrets](/ja/resources/fundamentals/authentication/oauth-1-0a/api-key-and-secret) や [Bearer Tokens](/ja/resources/fundamentals/authentication/oauth-2-0/bearer-tokens) などの追加の認証情報を生成するために使用できます。また、OAuth 1.0a ユーザーコンテキスト認証を必要とするリクエストを[承認する](/ja/resources/fundamentals/authentication/oauth-1-0a/authorizing-a-request)際には、Access Tokens やその他の認可パラメータと組み合わせて、これらの認証情報を使用する必要があります。 

<div id="how-to-acquire-an-api-key-and-secret">
  #### API Key と Secret の取得方法
</div>

X の API Key と Secret を取得するには、次の手順に従ってください。

1. [X の開発者アカウントに登録する](https://developer.x.com/en/apply-for-access)
2. [開発者コンソール](/ja/resources/fundamentals/developer-portal)内で [X App](/ja/resources/fundamentals/developer-apps) を作成します。なお、[X API v2](/ja/x-api/introduction) を利用する場合は、開発者用 App のキーおよびトークンを使用する必要があります。
    

X App を作成すると、API Key と Secret に加えて、Bearer Token が表示されます。これらの認証情報は一度しか表示されませんので、パスワードマネージャーなどの安全な場所に必ず保存してください。

キーやトークンの扱い方については、認証情報が漏えいした場合に取るべき対応も含めて、[認証のベストプラクティス](/ja/resources/fundamentals/authentication/guides/authentication-best-practices) ページで詳しく説明しています。
 

<div id="how-to-find-and-regenerate-your-api-key-and-secret-after-app-creation">
  #### アプリ作成後に API Key と Secret を見つけて再生成する方法
</div>

すでにアプリを作成済みで、API Key と Secret を確認または再生成する必要がある場合は、次の手順に従ってください。

1. 開発者コンソールにアクセスします
2. サイドナビで「Apps」ドロップダウンを展開します
3. 確認または再生成したい API Key と Secret が関連付けられているアプリを開きます
4. 「Keys and tokens」タブに移動します

このタブで、アプリに関連付けられているすべての認証情報を確認できます。 
 

<div id="how-to-use-your-api-key-and-secret">
  #### API Key と Secret の使用方法
</div>

X Developer Platform をまだ触り始めた段階であれば、まずはプラットフォームで何ができるかを確認するために、[ツールやライブラリ](/ja/resources/tools-and-libraries) を利用することをおすすめします。これらのツールは認証を適切に処理してくれるため、多くの時間やストレスを軽減できます。特に、開発初心者の方には [Postman の使い始めガイド](/ja/tutorials/postman-getting-started) や [Insomnia](https://insomnia.rest/) から始めることを推奨します。 

リクエストを一から自分で構築したい場合は、[OAuth 1.0a リクエストの認可](/ja/resources/fundamentals/authentication/oauth-1-0a/authorizing-a-request) に関するガイドを参照してください。
