<div id="bearer-token-also-known-as-app-only">
  ### Bearer Token（app-only とも呼ばれます）
</div>

OAuth 2.0 Bearer Token は、[開発者用 App](/ja/resources/fundamentals/developer-apps) に代わってリクエストを認証します。この認証方式は App 固有であり、ユーザーは一切関与しません。通常、この方式は公開情報への読み取り専用アクセスを必要とする開発者向けです。 

この認証方式では、リクエストに Bearer Token を含めて送信する必要があります。Bearer Token は、開発者用 App の「Keys and tokens」セクション内で生成できます。以下は、ダミーの Bearer Token を使用したリクエスト例です。

```json
  curl "https://api.x.com/2/tweets?ids=1261326399320715264,1278347468690915330" \
  -H "Authorization: Bearer AAAAAAAAAAAAAAAAAAAAAFnz2wAAAAAAxTmQbp%2BIHDtAhTBbyNJon%2BA72K4%3DeIaigY0QBrv6Rp8KZQQLOTpo9ubw5Jt?WRE8avbi"
```

アプリ専用認証を使用した API 呼び出しには、App 単位でエンドポイントごとに[レート制限](/ja/resources/fundamentals/rate-limits)が適用されます。

この方法を使用するには Bearer Token が必要です。Bearer Token は、API Key と Secret を [POST oauth2/token](/ja/resources/fundamentals/authentication/api-reference#post-oauth2-token) エンドポイントに渡して生成するか、[Developer Console](/ja/resources/fundamentals/developer-portal) 内の App 設定にある「keys and token」セクションで生成できます。

Bearer Token を無効化したい場合は、[POST oauth2/invalidate&#95;token](/ja/resources/fundamentals/authentication/api-reference#post-oauth2-invalidate-token) エンドポイントを使用するか、App 設定の「keys and tokens」セクションで Bearer Token の横に表示されている「revoke」をクリックしてください。

<div id="oauth-20-authorization-code-flow-with-pkce">
  ### OAuth 2.0 Authorization Code Flow with PKCE
</div>

OAuth 2.0 Authorization Code Flow with PKCE を使用すると、他のユーザーに代わって認証を行う際に、アプリケーションのスコープをより細かく制御でき、複数デバイス間にまたがる認可フローも改善できます。言い換えると、X 上のユーザー向けにアプリケーションを構築する開発者は、自身の App が利用者から要求する情報をより厳密に管理できるようになり、エンドユーザーには本当に必要なデータと情報だけを要求すればよいことになります。

この最新の認可プロトコルを使用することで、エンドユーザーに対して、アプリを認可してもらうための同意フローを、よりシンプルな形で提示できます。この同意フローには、開発者が要求した特定のスコープだけが表示されます。これにより、扱うデータの負荷が軽減されるだけでなく、エンドユーザーからの信頼向上にもつながる可能性があります。
