<div id="bearer-token-also-known-as-app-only">
  ### Bearer Token（app-only とも呼ばれます）
</div>

OAuth 2.0 Bearer Token は、[開発者用 App](/ja/resources/fundamentals/developer-apps)に代わってリクエストを認証します。この方法は App 固有であるため、ユーザーは関与しません。通常、公開情報への読み取り専用アクセスが必要な開発者向けに利用されます。 

この認証方法では、リクエストに Bearer Token を付与する必要があります。Bearer Token は、開発者用 App の「Keys and tokens」セクションで生成できます。以下は、ダミーの Bearer Token を使用したリクエストの例です。

```json
  curl "https://api.x.com/2/tweets?ids=1261326399320715264,1278347468690915330" \
  -H "Authorization: Bearer AAAAAAAAAAAAAAAAAAAAAFnz2wAAAAAAxTmQbp%2BIHDtAhTBbyNJon%2BA72K4%3DeIaigY0QBrv6Rp8KZQQLOTpo9ubw5Jt?WRE8avbi"
```

アプリ専用認証を使用した API 呼び出しには、エンドポイントごとにアプリレベルで[レート制限](/ja/resources/fundamentals/rate-limits)が適用されます。

この方法を使用するには、Bearer Token が必要です。これは、API キーとシークレットを [POST oauth2/token](/ja/resources/fundamentals/authentication/api-reference#post-oauth2-token) エンドポイントに渡して生成するか、[開発者コンソール](/ja/resources/fundamentals/developer-portal) のアプリ設定内の「keys and token」セクションで生成することもできます。

Bearer Token を失効させたい場合は、 [POST oauth2/invalidate&#95;token](/ja/resources/fundamentals/authentication/api-reference#post-oauth2-invalidate-token) エンドポイントを使用するか、アプリ設定内の「keys and tokens」セクションで Bearer Token の横にある「revoke」をクリックしてください。

<div id="oauth-20-authorization-code-flow-with-pkce">
  ### OAuth 2.0 Authorization Code Flow with PKCE
</div>

OAuth 2.0 Authorization Code Flow with PKCE を使用すると、別のユーザーになり代わって認証を行う際に、アプリケーションのスコープをより細かく制御でき、複数デバイス間での認可フローを改善できます。言い換えると、X 上のユーザー向けにアプリケーションを構築する開発者は、自身の App がユーザーから要求する情報をより細かく制御できるようになり、エンドユーザーには必要な data と情報だけを要求すればよくなります。

この最新の認可プロトコルを利用することで、エンドユーザーに対して、アプリを認可するための、よりシンプルで効率的な同意フローを提示できます。このフローでは、要求した特定のスコープのみが表示されます。これにより data の扱いに関する負担が減るだけでなく、エンドユーザーからの信頼向上にもつながる可能性があります。
