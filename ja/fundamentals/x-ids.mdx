X API のすべてのオブジェクト（投稿、ユーザー、リスト、DM、スペース）には一意の ID が割り当てられています。これらの ID の仕組みを理解することで、信頼性の高い連携機能を構築することができます。

***

<div id="id-format">
  ## ID の形式
</div>

X の ID は、&quot;Snowflake&quot; と呼ばれるシステムによって生成される **64 ビット符号なし整数** です。各 ID には次の情報がエンコードされています。

* **Timestamp** — オブジェクトが作成された時刻
* **Worker number** — どのサーバーがその ID を生成したか
* **Sequence number** — そのミリ秒内での順序

つまり、ID はおおよそ時系列順になります。値が大きい ID ほど、一般的により新しいオブジェクトを表します。

<Tip>
  ID は、単一のオブジェクトのタイプ内だけでなく、X 全体を通じてグローバルに一意です。
</Tip>

***

<div id="string-vs-integer-representation">
  ## 文字列型と整数型の表現
</div>

<Warning>
  **コード内では常に文字列型のidを使用してください。** 一部のプログラミング言語（JavaScript など）では、64 ビット整数を正確に表現できません。
</Warning>

JavaScript では、整数は 53 ビットに制限されています。そのため、大きな id では精度が失われます。

```javascript
// これは精度が失われます!
const id = 10765432100123456789;
console.log(id.toString()); // "10765432100123458000" — 誤り!

// 代わりに文字列を使用してください
const id = "10765432100123456789";
console.log(id); // "10765432100123456789" — 正しい!
```

<div id="api-versions">
  ### API バージョン
</div>

| バージョン | ID 形式 |
|:--------|:----------|
| **X API v2** | ID はデフォルトで文字列型として返されます |
| **X API v1.1** | `id` (整数) と `id_str` (文字列型) の両方を返します — 常に `id_str` を使用してください |

<div id="working-with-ids">
  ## ID の取り扱い
</div>

<div id="storing-ids">
  ### ID の保存
</div>

ID はデータベース内で文字列型または 64 ビット整数として保存してください：

| Database | 推奨されるタイプ |
|:---------|:-----------------|
| PostgreSQL | `BIGINT` または `TEXT` |
| MySQL | `BIGINT UNSIGNED` または `VARCHAR(20)` |
| MongoDB | 文字列型 |
| SQLite | `TEXT`（SQLite の整数は最大 63 ビットです） |

<div id="comparing-ids">
  ### id の比較
</div>

id を時系列順に並べて比較する場合:

```python
# Python - safe for 64-bit integers
if int(id1) > int(id2):
    print("id1 is newer")

# JavaScript - 文字列として比較(同じ長さのIDに対して辞書順で機能する)
# またはBigIntを使用
if (BigInt(id1) > BigInt(id2)) {
    console.log("id1 is newer");
}
```
