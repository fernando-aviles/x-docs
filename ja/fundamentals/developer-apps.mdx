App は API 認証情報を保持するコンテナです。各 App は固有のキー、トークン、設定を持ちます。

---

<div id="app-credentials">
  ## アプリの認証情報
</div>

アプリを作成すると、次の認証情報を生成できます。

| 認証情報 | ユースケース |
|:-----------|:---------|
| **API Key & Secret** | OAuth 1.0a で認証します。リクエストの署名やユーザー用トークンの生成に使用されます。 |
| **Access Token & Secret** | 自分のアカウントを代表してリクエストを行います（OAuth 1.0a）。 |
| **Client ID & Secret** | OAuth 2.0 で認証します。認可コードフローに使用されます。 |
| **Bearer Token** | 公開データエンドポイント向けのアプリ単体での認証（App-only authentication）に使用されます。 |

<Tip>
新しいプロジェクトには **OAuth 2.0** を選択してください。きめ細かなスコープを提供し、X API v2 のユーザーコンテキストエンドポイントでは必須です。
</Tip>

<div id="creating-an-app">
  ## アプリを作成する
</div>

<Steps>
  <Step title="開発者コンソールを開く">
    [console.x.com](https://console.x.com) にアクセスしてサインインします。
  </Step>
  <Step title="Create App をクリックする">
    アプリの名前、説明、ユースケースを入力します。
  </Step>
  <Step title="認証情報を生成する">
    作成後、必要なキーとトークンを生成します。
  </Step>
  <Step title="安全に保管する">
    認証情報はすぐに保存してください。表示されるのは一度きりです。
  </Step>
</Steps>

<div id="app-permissions-oauth-10a">
  ## アプリの権限 (OAuth 1.0a)
</div>

OAuth 1.0a アプリには 3 つの権限レベルがあります。

<Tabs>
  <Tab title="読み取り専用">
    - 投稿、ユーザー、および公開データを閲覧
    - 投稿、いいね、その他の変更は行えない
    - ダイレクトメッセージにはアクセスできない
  </Tab>
  <Tab title="読み取りと書き込み">
    - すべての読み取り権限
    - 投稿および投稿の削除
    - ユーザーのフォロー/フォロー解除
    - いいねと Repost
    - ダイレクトメッセージにはアクセスできない
  </Tab>
  <Tab title="読み取り、書き込み、およびDM">
    - すべての読み取りおよび書き込み権限
    - ダイレクトメッセージの送信および閲覧
  </Tab>
</Tabs>

<Note>
権限を変更する場合、更新されたスコープに対応した新しいトークンを取得するには、ユーザーがアプリを再承認する必要があります。
</Note>

<div id="oauth-20-app-types">
  ## OAuth 2.0 アプリタイプ
</div>

OAuth 2.0 を設定する際には、アプリのタイプを選択します。

| タイプ | クライアント | ユースケース |
|:-----|:-------|:---------|
| **Web App** | Confidential | シークレットを安全に保存できるサーバーサイドアプリケーション |
| **Automated App / Bot** | Confidential | サーバー上で動作するボットや自動化サービス |
| **Native App** | Public | シークレットを安全に保存できないモバイルまたはデスクトップアプリ |
| **Single Page App** | Public | ブラウザベースの JavaScript アプリ |

**Confidential クライアント**は Client Secret を受け取ります。**Public クライアント**は PKCE のみを使用します。

<div id="callback-urls">
  ## コールバックURL
</div>

OAuthフローにはコールバックURL（リダイレクトURI）が必須です。ユーザーがアプリを承認すると、認可コードとともにコールバックURLにリダイレクトされます。

<div id="requirements">
  ### 要件
</div>

- 開発者コンソールで、アプリの許可リストにコールバックURLを追加する
- URLは完全に一致している必要がある（末尾のスラッシュも含む）
- アプリごとに最大 **10個のコールバックURL**
- 本番環境では `https://` を使用する
- ローカル開発環境では `http://127.0.0.1` を使用する（`localhost` ではない）

<div id="disallowed-protocols">
  ### 使用が禁止されているプロトコル
</div>

次のプロトコルは使用できません: `javascript`、`data`、`file`、`ftp`、`mailto`、`telnet`、およびその他の非標準スキーム。

<Accordion title="使用が禁止されているプロトコルの一覧">
`vbscript`, `javascript`, `vbs`, `data`, `mocha`, `keyword`, `livescript`, `ftp`, `file`, `gopher`, `acrobat`, `callto`, `daap`, `itpc`, `itms`, `firefoxurl`, `hcp`, `ldap`, `mailto`, `mmst`, `mmsu`, `msbd`, `rtsp`, `mso-offdap`, `snews`, `news`, `nntp`, `outlook`, `stssync`, `rlogin`, `telnet`, `tn3270`, `shell`, `sip`
</Accordion>

<div id="automated-account-labels">
  ## 自動アカウントラベル
</div>

アプリでボットアカウントを運用している場合、そのアカウントを自動アカウントとしてラベル付けできます。

1. ボットアカウントの **設定** を開きます
2. **あなたのアカウント** → **自動化** を選択します
3. 管理用アカウントをリンクします

これにより、ユーザーからの信頼を高め、ボットをスパムと明確に区別できるようになります。

<div id="troubleshooting">
  ## トラブルシューティング
</div>

<Accordion title="コールバック URL が承認されていないエラー">
コールバック URL が、プロトコルや末尾のスラッシュも含めて、開発者コンソールに登録した内容と完全に一致していることを確認してください。クエリパラメーターとして渡す際は、その URL を HTTP エンコードしてください。

```json
{
  "errors": [{
    "code": 415,
    "message": "Callback URL not approved for this client application."
  }]
}
```
</Accordion>

<Accordion title="アプリが凍結されている">
アプリが凍結されて表示される場合は、X プラットフォーム チームからの通知メールが届いていないか確認してください。異議申し立てを行うには、[Platform Help Form](https://help.x.com/forms/platform) を使用してください。
</Accordion>
