安全なアプリケーションを構築することは、ユーザーと X プラットフォームの双方を保護するうえで重要です。このガイドでは、X API を利用する開発者向けの重要なセキュリティ プラクティスを解説します。

***

<div id="core-requirements">
  ## コア要件
</div>

<CardGroup cols={2}>
  <Card title="TLS は必須" icon="lock">
    すべての API リクエストで HTTPS を使用する必要があります。暗号化されていない HTTP は拒否されます。
  </Card>

  <Card title="認証情報の保護" icon="key">
    クライアント側のコード、ログ、リポジトリに API キーやトークンを決して含めないでください。
  </Card>
</CardGroup>

<div id="protecting-credentials">
  ## 資格情報の保護
</div>

API キーやトークンはアプリへのアクセスの鍵です。安全に管理してください。

<Steps>
  <Step title="環境変数を使用する">
    資格情報はコード内ではなく、環境変数に保存してください。

    ```bash
    export X_API_KEY="your-api-key"
    export X_API_SECRET="your-api-secret"
    ```
  </Step>

  <Step title="シークレットを決してコミットしない">
    資格情報ファイルを `.gitignore` に追加してください。`git-secrets` のようなツールを使って、誤ってコミットしてしまうことを防ぎます。
  </Step>

  <Step title="定期的にローテーションする">
    鍵は定期的に再生成し、漏えいが疑われる場合は直ちに再生成してください。
  </Step>

  <Step title="最小限の権限を使用する">
    アプリで実際に必要な OAuth スコープだけをリクエストしてください。
  </Step>
</Steps>

<div id="if-credentials-are-compromised">
  ### 資格情報が漏えいした場合
</div>

1. [開発者コンソール](https://console.x.com) で**直ちに再生成する**
2. **古いトークンを失効させる** — 再生成すると古い資格情報は自動的に無効になる
3. **利用状況を監査する** — 不正な API アクティビティがないか確認する
4. **アプリを更新する** — 新しい資格情報をすべての環境にデプロイする

<div id="application-security">
  ## アプリケーション セキュリティ
</div>

<div id="input-validation">
  ### 入力検証
</div>

ユーザーからの入力を決して信用しないでください。使用する前に、すべてのデータを検証し、サニタイズ（無害化）してください。

```python
# 悪い例 - インジェクション攻撃に対して脆弱
query = f"from:{user_input}"

# 良い例 - 最初に入力を検証
import re
if re.match(r'^[a-zA-Z0-9_]{1,15}$', user_input):
    query = f"from:{user_input}"
```

<div id="output-encoding">
  ### 出力エンコード
</div>

XSS を防ぐために、X API のデータを HTML に表示する前にエスケープしてください。

```javascript
// 悪い例 - XSSに対して脆弱
element.innerHTML = tweet.text;

// 良い例 - HTMLをエスケープ
element.textContent = tweet.text;
```

<div id="common-vulnerabilities-to-prevent">
  ### 防止すべき一般的な脆弱性
</div>

| 脆弱性 | 対策 |
|:--------------|:-----------|
| **XSS** | レンダリング前に、ユーザー生成コンテンツをすべてエスケープ処理する |
| **CSRF** | フォームで CSRF 対策トークンを使用し、OAuth の state パラメータを検証する |
| **SQL Injection** | プレースホルダーを使ったパラメータ化クエリを使用し、ユーザー入力を決して連結しない |
| **Open redirects** | コールバック URL を許可リストと照合して検証する |

<div id="oauth-security">
  ## OAuth のセキュリティ
</div>

<div id="state-parameter">
  ### state パラメータ
</div>

CSRF を防ぐため、OAuth フローでは必ず `state` パラメータを使用してください。

```python
import secrets

# 認可前にstateを生成
state = secrets.token_urlsafe(32)
session['oauth_state'] = state

# コールバック後にstateを検証
if request.args.get('state') != session.get('oauth_state'):
    abort(403)  # stateが一致しません - CSRF攻撃の可能性があります
```

<div id="token-storage">
  ### トークンの保存
</div>

| トークン種別 | 保存方法の推奨 |
|:-----------|:-----------------------|
| **Access tokens** | 暗号化されたデータベースまたはセキュアなボールト |
| **Refresh tokens** | 追加のアクセス制御を施した暗号化されたデータベース |
| **Bearer tokens** | 環境変数またはセキュアな設定 |
--------------------------------------

<div id="resources">
  ## コンプライアンス チェックリスト
</div>

<Accordion title="X API 開発者向けセキュリティ要件">
  * [ ] すべての API リクエストで TLS/HTTPS を使用している
  * [ ] 認証情報を安全に保管している（コードやログ内に保存していない）
  * [ ] ユーザートークンを保存時に暗号化している
  * [ ] すべてのユーザーからの入力データに対して入力検証を行っている
  * [ ] XSS を防ぐために出力エンコードを行っている
  * [ ] OAuth フローに CSRF 対策を実装している
  * [ ] セキュリティログを有効化している（機密情報を含まない）
  * [ ] インシデント対応計画を文書化している
  * [ ] 依存関係を定期的に更新している
  * [ ] 要求する OAuth スコープを最小限に抑えている
</Accordion>
