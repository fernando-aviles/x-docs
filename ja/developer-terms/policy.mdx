<div id="x-developers">
  ## X + Developers
</div>

X は開発者を大切にしています。X のデータの力を活用して、このコミュニティが生み出すツールやサービスには、常に感心させられています。私たちはこのコミュニティへの取り組みの一環として、開発者に対してオープンかつ公平であり、X を利用する人々にとって安全であり、X プラットフォーム全体にとって有益となるデータアクセスを提供することを目指しています。こうした目的を推進するために、API および X コンテンツの適切な利用に関する当社のルールおよび期待を理解してもらうための指針として「Developer Policy (開発者ポリシー) 」を策定しました。

本 Developer Policy (「**本ポリシー**」) は、X のアプリケーション、サービス、ウェブサイト、ウェブページおよびコンテンツから構成されるエコシステムとやり取りを行う開発者向けのルールおよびガイドラインを定めるものです。本ポリシーは、X API および X コンテンツへのアクセスおよびその利用を規定する、X とお客様との契約 (Developer Agreement もしくは X と締結したその他の書面による契約のいずれか) を構成する一部です。本ポリシーへの違反は、当該契約への違反とみなされます。本ポリシーは、予告なく随時変更されることがあります。本ポリシーで使用される用語のうち、本ポリシー内で定義されていない大文字表記の用語は、それぞれ [Developer Agreement](/ja/developer-terms/agreement) または Master License Agreement において付与された意味を有するものとします。

</div>

1. **成功のための準備を整える** - あなたは、すべての X ポリシーを順守する責任があります。X API と X コンテンツにアクセスする前に、このポリシーおよび本ドキュメント内で参照しているポリシーを確認し、内容を理解することが重要です。ポリシーの確認に時間をかけることで、将来的に何時間分もの手戻り作業を防げる可能性があります。

3. **プラットフォーム利用ガイドラインに従う** - X API と X コンテンツへのアクセスが承認されることは、最初の一歩にすぎません。X プラットフォームの利用を計画するにあたり、ポリシー順守をどのように確保すべきか疑問が生じた場合には、まずプラットフォーム利用ガイドラインを参照してください。

これら 3 つの主要なセクションがそれぞれ何を意味するかについて、以下でさらに詳しく説明しています。X API および X コンテンツの利用が当社のポリシーと整合していることを確認するため、必ず注意深くお読みください。

当社が、あなたが本ポリシー (または他の X ポリシー) に違反していると判断した場合、X API および X コンテンツへのアクセスを一時停止、または永久に取り消すことがあります。

最後に、X は、X アプリケーションの改善、商用利用の確認、承認されたユースケースおよび本ポリシーへの準拠を確保する目的で、あなたによる X API の利用状況を監視する場合があることにご留意ください。

ここまでお読みいただきありがとうございます。また、X とともにプロダクトを構築していただいていることに感謝します。あなたが何を創り出すのかを楽しみにしています。

<div id="privacy-and-control-are-essential">
  ## プライバシーとコントロールは不可欠です
</div>

X はプライバシーを真剣に捉えており、X コンテンツおよび X API を利用するすべての人にも同様の姿勢を求めます。人々が合理的に期待しうるプライバシーに反する形で X 開発者プラットフォーム、X API、または X コンテンツを利用した場合、API および X コンテンツへのアクセスの一時停止や停止 (終了) を含む措置の対象となる可能性があります。

プライバシーとコントロールへの取り組みは、X コンテンツのあらゆる利用、および当社の API を用いて構築するサービスのあらゆる側面にまで及ぶ必要があります。そのため、あなたのサービスを利用する人は、あなたがその人のデータをどのように利用し、その人に代わってどのように X にアクセスするのかを理解し、同意していなければなりません。これは、利用者に対して明確で包括的かつ透明性の高いプライバシーポリシーを提示するとともに、利用者に代わっていかなる行為を行う前に、あなたのサービスを利用するすべての人から明示的かつ十分な情報に基づく同意を得ることで実現できます。**なお、人があなたのサービスに対して認証を行うこと自体は、それだけで同意とみなされるわけではないことに注意してください。**

<div id="consent-permissions">
  ## 同意と許可
</div>

**特に、以下のいずれかを行う前に、人々から明示的かつ十分な説明に基づく同意を得なければなりません。**

* 本人に代わって *いかなる* 行為を行うこと。これには以下が含まれます (ただしこれらに限定されません) ：
  * X にコンテンツを投稿すること
  * アカウントのフォロー／フォロー解除を行うこと
  * プロフィールまたはアカウント情報を変更すること
  * 投稿にハッシュタグやその他のコンテンツを追加すること

* X API またはその他の X のツール以外の手段でアクセスしたコンテンツを再公開すること

* 他者の X コンテンツを、製品やサービスの宣伝に利用すること

* ダイレクトメッセージ (DM) などの非公開コンテンツ、またはその他の私的もしくは機密情報を保存すること

* 保護されたコンテンツ、またはその他の私的もしくは機密情報を共有または公開すること

**あなたのサービスが、人々に X へコンテンツを投稿できるようにしている場合、公開前に次のことを行わなければなりません。**

* 何が公開されるのかを正確に表示すること
* コンテンツにどのような位置情報 (ある場合) が付与されるかを、あなたのサービスの利用者に明確に示すこと

**あなたのサービスが、あなたのサービスと X の両方にコンテンツを投稿できるようにしている場合、公開前に次のことを行わなければなりません。**

* コンテンツを投稿する許可を取得すること
* コンテンツをどこに投稿するのかを説明すること

**すべての X コンテンツにおける保護ステータスおよびブロックステータスを尊重しなければなりません。ある人物の認証トークンを使って取得したコンテンツを、そのコンテンツを閲覧する権限のない別の人物に提供してはなりません。**

* **保護されたアカウント：** [保護されたアカウント](https://help.x.com/safety-and-security/public-and-protected-posts) のコンテンツは、そのアカウントをフォローすることを所有者から承認された人にのみ利用可能です。したがって、あなたが保護されたアカウントにアクセスするサービスを運用している場合、そのコンテンツを閲覧する許可を持つ特定の人々に対してのみ、そのコンテンツを提供する目的でアクセスしなければなりません。
* **ブロックされたアカウント：** X を利用する人々は、任意の理由で自分のアカウントへのアクセスを[ブロック](https://help.x.com/using-x/blocking-and-unblocking-accounts)することができます。トークン (またはその他の API ベースのアクション) から取得した情報を組み合わせ、この選択を回避することは認められません。

**ダイレクトメッセージ (DM) は性質上非公開であるため、DM 機能を提供するサービスは、個人のプライバシーを保護するために追加の対策を講じる必要があります。DM コンテンツを、そのコンテンツを閲覧する権限のない人に提供してはなりません。あなたのサービスが DM 機能を提供する場合、次のことも行わなければなりません。**

* DM の既読通知イベントを送信する場合は、その旨を人々に通知すること。これは、サービス内で直接通知を表示するか、会話の他の参加者からの既読通知を表示することで行うことができます。
* DM で送信されるメディアを「shared」 (すなわち複数の DM 間で再利用可能) として設定する前に、同意を得ること。DM 内のメディアを「shared」として許可する場合、そのメディアの URL を知っている人であれば誰でもこのコンテンツにアクセスできることを、明確な通知として示さなければなりません。

<div id="content-compliance">
  ## コンテンツのコンプライアンス
</div>

**X コンテンツをオフラインで保存する場合、そのコンテンツを X 上の最新の状態に常に保っておく必要があります。** 具体的には、X 上でコンテンツが削除または変更された場合には、あなたが保有する同じコンテンツも削除または変更しなければなりません。これは、合理的に可能な限り速やかに、または X もしくは該当する X アカウントの所有者からその実施を求める要請を受けてから 24 時間以内に、あるいは X との契約または適用される法令によって別途定められた期間内に実施する必要があります。これは、法令により禁止されている場合を除き行わなければならず、そのような場合であっても、X による明示的な書面での許可がある場合に限り例外とされます。

変更されたコンテンツにはさまざまな形態があります。これには以下が含まれますが、これらに限定されるものではありません。

* 非公開にされた、または保護ステータスを付与されたコンテンツ
* プラットフォーム上でアカウント停止等の措置を受けたコンテンツ
* ジオタグ (位置情報タグ) が削除されたコンテンツ
* X 上で保留 (非表示) または削除されたコンテンツ

<div id="off-x-matching">
  ## X外でのマッチング
</div>

**X上の人物を、X外で取得または保存された情報と照合できる状況は、厳しく制限されています。** X外でのマッチングとは、Xコンテンツ (Xの@handleやユーザーIDを含む) を、人物、世帯、デバイス、ブラウザ、その他のX外の識別子と関連付けることを指します。こうした関連付けは、その人物から事前に明示的なオプトイン同意を取得している場合、または以下で説明する場合にのみ認められます。

人物のXアイデンティティをX外の識別子にリンクするための明示的なオプトイン同意がない状況では、あなたが行うあらゆる関連付けは、その目的で利用されることを合理的に予期できる情報のみに基づいている必要があります。さらに、その人物の明示的なオプトイン同意がない場合、あなたが、誰かに関する自らの記録をXアイデンティティにマッチさせようと試みることができるのは、次の情報に基づく場合に限られます。

* **その人物があなたに直接提供した情報。** なお、あなたとの間に事前の関係がない個人に関する記録 (第三者から取得した個人データを含む) は、この基準を満たしません。および／または
* **公開データ。** この文脈における「公開データ」とは、次を指します。
  * あなたが、公的に一般利用可能なリソース (職業団体の会員名簿など) から取得した、その人物に関する情報
  * X上で、その人物について公開されている情報。具体的には次のものを含みます。
    * 投稿
    * アカウントの自己紹介文や公開されている所在地を含むプロフィール情報
    * 表示名および@handle

<div id="your-privacy-policy">
  ## プライバシーポリシー
</div>

**あなたのサービスのプライバシーポリシーは、利用者があなたのサービスをダウンロード、インストール、またはサインアップできるようにする前に表示しなければなりません。** プライバシーポリシーには、少なくとも次の情報を開示する必要があります。

* あなたのサービスを利用する人々から収集する情報
* その情報の利用および共有方法 (X への共有を含みます) 
* 人々が自分の情報に関する問い合わせや要請を行うために、どのようにあなたに連絡できるか

あなたのプライバシーポリシーは、適用されるすべての法律と整合している必要があり、[X のプライバシーポリシー](https://x.com/privacy)および[当社の他のサービスおよび企業関連会社のプライバシーポリシー](https://help.x.com/rules-and-policies/x-services-and-corporate-affiliates)と比べて、人々に対してそれ未満の保護しか提供しないものであってはなりません。自社または X のプライバシーポリシーを順守できない場合、X API へのアクセスおよびすべての X コンテンツの利用を中止しなければなりません。

<div id="using-geo-data">
  ## ジオデータの使用
</div>

**この情報が機微な性質を持つため、ジオデータの利用には追加の制限があります。** サービスがポストに位置情報を付加する場合、利用者に対して次の点を開示する必要があります。

* いつ位置情報を追加するのか
* 位置情報をジオタグとして追加するのか、あるいはアノテーションデータとして追加するのか
* 位置情報が「場所」として表示されるのか、地理座標として表示されるのか

アプリケーションが利用者に位置情報付きで投稿できるようにしている場合、X の[ジオガイドライン](/ja/developer-terms/geo-guidelines)を完全に遵守しなければなりません。

**位置データや地理情報を単独で利用することは禁止されています。** ポストの一部として利用する場合を除き、X コンテンツに含まれる位置データおよびその他の地理情報を保存、集約、またはキャッシュしてはなりません。たとえば、個人が時間の経過とともにどこにいたかを示すために、位置データや地理情報をポストから切り離して利用することはできません。ヒートマップや、集約されたジオアクティビティ (例：ある都市でハッシュタグを使用している人数) を表示する関連ツールは許可されています。

</div>

**X コンテンツを入手する最良の手段は、X から直接取得することです。そのため、X コンテンツを第三者へ再配布することには制限があります。** ダウンロード可能なデータセットや API 経由で提供する場合を含め、X コンテンツを第三者に提供する場合は、 (以下で説明する場合を除き) Post ID、Direct Message ID、および／または User ID のみを配布できます。

<div id="x-cards">

</div>

**高品質なユーザー体験を確保するため、Cards が表示されるすべてのプラットフォームで正しくレンダリングされるように Card を開発する必要があります。** Cards を使用する際に従うべき追加ルールは次のとおりです。

* URL やメディアなど、誤解を招く、または文脈的に関連性のないコンテンツやアクションを Card に含めてはなりません
* 当該ポスト内で誰かがそのアプリを明示的に宣伝または言及している場合にのみ、そのポストに App Card を添付することができます
