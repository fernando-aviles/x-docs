<div id="introduction">
  ## はじめに
</div>

Posting With Location は、X API におけるジオタグ機能です。この機能により、投稿に文脈を持たせることで、ユーザーにとってより意味のある体験を提供できます。たとえば、「花火だ！」という投稿も、位置情報が付与されることで、「カリフォルニア州サンフランシスコの SoMa 地区からの『花火だ！』」のように、より意味のあるものになります。私たちは、この機能を活用してすばらしい体験を創出してくださる開発者エコシステムの皆さんと一緒に取り組めることを楽しみにしています。

<div id="user-privacy-and-user-control-of-their-location-information">
  ## ユーザーのプライバシーと位置情報に対するユーザーのコントロール
</div>

良好で安全な利用体験を確保するために、開発者はユーザーの位置情報を扱う際にユーザーのプライバシーに配慮し、「位置情報付きで投稿」機能における基本的な一貫性を提供する必要があります。以下は、ユーザーのプライバシーを保護し、ユーザーが自分の行動の影響を理解できるようにするために留意すべき主なポイントです。

<div id="general-guidelines">
  ## 一般的なガイドライン
</div>

* ユーザーは、「Posting With Location」機能を利用するために自らオプトインする必要があります（位置情報を「オン」にする）。
* ユーザーは、自分の投稿に正確な位置情報を表示することについて、明示的な許可を与える必要があります。クライアント上の位置情報機能が「スティッキー」、つまり一度位置情報をオンにすると常に投稿に付随する仕様である場合は、場所名（place&#95;ids）のみを表示し、投稿ごと、または特定の代替設定として、正確な緯度・経度の表示についてユーザーに追加でオプトインを求めることを検討してください。
* 投稿を行うためにユーザーの位置情報データにアクセスする場合、その情報は、ユーザーからの明示的な許可がない限り、投稿とは別に保存してはなりません。
* ユーザーの投稿に関連して、どの程度の位置情報（もしあれば）が表示されるかを、ユーザーにはっきりと示さなければなりません。その一つの方法として、投稿が公開される前に、その情報がどのように表示されるかを地図で見せることが挙げられます。正確な緯度・経度が、クライアント上でユーザーによって公開される情報の一部（または唯一の情報）である場合、ユーザーに対して、自分の正確な座標が公開されることを明確に伝えなければなりません。
* ユーザーは、投稿を作成するたびに、自分の位置情報をオン／オフできる必要があります。
* X の [Developer Policy](/ja/developer-terms/policy.html) に従わなければなりません。これには、投稿の一部として扱う場合を除き、X API から取得した位置情報データおよびその他の地理情報を集約、キャッシュ、保存してはならず、そのような位置情報や地理情報を単体で利用してはならない、という要件が含まれます。

<div id="specific-examples">
  ## 具体的な例
</div>

例 1: *緯度・経度を明示的に追加しない場合（現在の X Web クライアントの UI）*

1. ユーザーが投稿を作成する際に、「Add your location（現在地を追加）」へのリンクを表示する。
2. バックグラウンドで X の [reverse&#95;geocode](https://developer.x.com/en/docs/geo/places-near-location/api-reference/get-geo-reverse_geocode.html) API 呼び出しを行い、緯度、経度、測位精度、およびユーザーの希望する粒度（デフォルトでは「neighborhood」）を渡す。
3. デフォルトの場所の名前を表示する（X は妥当な順序になるよう並べ替えを行うため、X クライアント側ではそのリストを変更せずにそのまま表示できる）。
4. ユーザーがリストから別の場所を選択できるようにする（例: “SoMa, San Francisco” から “South Beach, San Francisco” に変更）。
5. 重要: 正確な位置情報を表示する場合は、その旨をユーザーに明確に伝えること。正確な位置情報が表示されるかどうかをユーザーが認識できるようにすること。
6. ユーザーが投稿を作成するたびに、位置情報をオンまたはオフにできるようにする。

例 2: *既存のジオタグ機能の実装*

いくつかの X クライアントアプリは、元々のジオタグ機能（place&#95;ID を付与せずに緯度・経度のみを送信する機能）を実装しています。API のデフォルトの挙動はこの動作を模倣しており、つまり開発者としては、現在の挙動を維持するために既存アプリを変更する必要はありません。実際、単に緯度・経度（lat/lon）座標を X に渡すだけで、X はその緯度と経度を自動的にリバースジオコーディングし、利用可能な地域については lat/lon に加えて place&#95;ID も表示します。

ユーザーの正確な座標が X 上で利用・表示されていることが、ユーザーにとって明確になるようにしてください。既存アプリにおけるベストプラクティスとしては、ユーザーが投稿ごとに位置情報のオン／オフを切り替えられるようにすることです。また、デフォルトの「スティッキー」な設定として、正確な座標ではなく place&#95;ID のみを共有するようユーザーが選択できるようにすることもできます。

<div id="x-storage-of-user-location-data">
  ## ユーザー位置情報のXによる保存
</div>

Xはクライアントから渡されたデータを次のように保存します。

* Xは、ユーザーがフォロワーに対して公開表示することを選択したすべてのデータを保存します。これは、Xが投稿された日時を示すタイムスタンプを保存する方法と同様です。つまり、ユーザーが正確な座標付きで投稿した場合、投稿が存在する限り、Xはその投稿とともにこの正確な位置情報を保存します。ユーザーは、[こちら](https://support.twitter.com/articles/122236-how-to-tweet-with-your-location))で説明されているとおり、設定ページの「位置情報履歴を消去」ボタンをクリックすることで、自分の投稿から位置情報データを削除できます。

<div id="summary">
  ## まとめ
</div>

投稿に位置情報を追加することで、ユーザーの視点から非常に多くの文脈情報と価値がもたらされます。ただし、クライアントアプリケーションで位置情報を実装する際には、位置情報に特化したプロダクトを設計するうえで、プライバシーとユーザーへの透明性を最重要事項として慎重に扱う必要があります。
