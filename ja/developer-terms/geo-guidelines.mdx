<div id="introduction">
  ## はじめに
</div>

Posting With Location は、X API における位置情報付き投稿（ジオタグ）機能です。この機能により、投稿に位置情報を付与することで文脈が加わり、ユーザーにとってより意味のある体験を提供できます。たとえば、「花火！」という投稿も、場所情報と結び付けることで、「カリフォルニア州サンフランシスコの SoMa 地区からの『花火！』」のように、はるかに関連性の高いものになります。私たちは、この機能を活用した優れた体験を創出していくために、開発者エコシステムの皆さまと協力できることを楽しみにしています。

<div id="user-privacy-and-user-control-of-their-location-information">
  ## ユーザーのプライバシーと位置情報に対するユーザーコントロール
</div>

良好で安全な利用体験を提供するために、開発者はユーザーの位置情報を取り扱う際にプライバシーへ十分に配慮するとともに、「位置情報付きで投稿」機能における体験に一定の一貫性を持たせる必要があります。ユーザーのプライバシーを保護し、ユーザーが自らの行動の影響を理解できるようにするために、次の点を念頭に置いてください。

<div id="general-guidelines">
  ## 一般的なガイドライン
</div>

* 投稿に位置情報を付与する「Posting With Location」機能を利用する場合、ユーザーは自らオプトイン（位置情報を「オン」にする）しなければなりません。
* ユーザーは、自身の投稿に正確な位置情報を表示することについて明示的に許可しなければなりません。あなたのクライアントでの位置情報機能が「スティッキー（sticky）」、つまり一度位置情報をオンにすると常に投稿に付随する仕様である場合には、場所の名前（place&#95;ids）のみを表示し、ユーザーが投稿ごと、または特定の代替設定として、正確な緯度・経度の表示に改めてオプトインできるようにすることを推奨します。
* ユーザーの投稿を行うためにユーザーの位置情報データへアクセスする場合、その情報は、ユーザーからの明示的な許可がない限り、投稿とは別に保存してはなりません。
* ユーザーの投稿と関連付けて、どのレベルの位置情報が（もしあれば）表示されるのかがユーザーにとって明確でなければなりません。その一例として、投稿が公開される前に、この情報がどのように表示されるかを示す地図を表示することが挙げられます。クライアント上で、公開される情報の一部（または唯一の情報）として正確な緯度・経度が含まれる場合、ユーザーに対し、正確な座標が公開されることを明確に示す必要があります。
* ユーザーは、投稿を作成するたびに、自身の位置情報をオン／オフできるようにする必要があります。
* X の [Developer Policy](/ja/developer-terms/policy.html)（開発者ポリシー）の条件に必ず従わなければなりません。ここには、投稿の一部として扱う場合を除き、X API から取得した位置情報およびその他の地理情報を集約、キャッシュ、保存してはならないこと、また、これらの位置情報や地理情報を単独で利用してはならないことが含まれます。

<div id="specific-examples">
  ## 具体例
</div>

例 1: *緯度と経度を明示的に追加しない場合（これは現在の X Web Client の UI です）*

1. ユーザーが投稿を作成するときに「位置情報を追加」のリンクを表示する。
2. バックグラウンドで X の [reverse&#95;geocode](https://developer.x.com/en/docs/geo/places-near-location/api-reference/get-geo-reverse_geocode.html) API 呼び出しを使用し、緯度、経度、取得した位置の精度、およびユーザーの希望する粒度（デフォルトでは「neighborhood」）を渡す。
3. デフォルトの場所の名前を表示する（X は、X クライアントが一覧をそのまま表示できるよう、合理的と思われる順序で並べ替えを試みる）。
4. ユーザーがリストから別の位置情報を選択できるようにする（例: 「SoMa, San Francisco」から「South Beach, San Francisco」へ変更する）。
5. 重要: 正確な位置情報を表示する場合は、その旨をユーザーに対して明確に示すこと。正確な位置情報が表示されるかどうかをユーザーが確実に把握できるようにすること。
6. ユーザーが投稿を作成するたびに、位置情報をオンまたはオフにできるようにする。

例 2: *既存のジオタグ実装*

多くの X クライアントアプリは、place&#95;ID を提供せずに緯度/経度のみを配信する、元々のジオタグ機能を実装しています。API のデフォルト動作はこの挙動を模倣するものであり、つまり、開発者としては、現在の挙動を維持するために既存アプリを変更する必要はありません。実際、単に lat/lon 座標を X に渡すだけで、X はその緯度と経度を自動的にリバースジオコーディングし、利用可能なデータが存在する地域については、lat/lon に加えて place&#95;ID も表示します。

ユーザーの正確な座標が X 上で使用および表示されることについて、ユーザーに対して透明性が確保されていることを確認してください。既存アプリにおけるベストプラクティスとしては、ユーザーが投稿ごとに位置情報をオンまたはオフにできるようにすることが挙げられます。デフォルトの「スティッキー」な設定として、ユーザーが正確な座標ではなく place&#95;ID のみを共有できるようにすることもできます。

<div id="x-storage-of-user-location-data">
  ## X によるユーザー位置情報データの保存
</div>

X はクライアントから渡されたデータを次のように保存します。

* X は、ユーザーが自分のフォロワーに対して公開することを選択したすべてのデータを保存します。これは、投稿が行われた時間を示すタイムスタンプを X が保存する方法と同様です。つまり、ユーザーが正確な座標付きで投稿した場合、投稿が存在する限り、X はその投稿とともにこの正確な位置情報を保存します。ユーザーは、[こちら](https://support.twitter.com/articles/122236-how-to-tweet-with-your-location)) で説明されているとおり、設定ページの「clear my location history」ボタンをクリックすることで、自分の投稿から位置情報データを削除できます。

<div id="summary">
  ## まとめ
</div>

投稿に位置情報を追加すると、ユーザーにとって非常に多くのコンテキストと価値が生まれます。ただし、クライアントで位置情報を実装する際には、プライバシー保護とユーザーへの透明性を、位置情報に特化したプロダクトを設計するうえでの最重要な検討事項として慎重に扱う必要があります。
