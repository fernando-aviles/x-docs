当社の開発者プラットフォームを利用するには、[Developer Agreement and Policy](/ja/developer-terms/agreement) に加え、[Display Requirements](https://developer.x.com/en/developer-terms/display-requirements.html) や [Automation Rules](https://help.twitter.com/en/rules-and-policies/twitter-automation) を含む関連ポリシーを確認し、同意していただく必要があります。これらの契約およびポリシーでは、その他の事項とあわせて、利用が制限されるいくつかのユースケースについてのガイダンスを提供しています。以下では、これらの制限の一部について、追加情報を記載しています。

<div id="sensitive-information">
  ## 機微な情報
</div>

X データを用いて X ユーザーの潜在的に機微な属性を導出または推測する場合には、十分に注意しなければなりません。X ユーザーについて、以下の情報を決して導出または推測したり、そのように導出・推測された情報を保存したりしてはいけません。

* 健康状態 (妊娠を含む) 
* 不利な財務状況または状態
* 政治的な所属または信条
* 人種的または民族的出自
* 宗教的または哲学的な所属または信条
* 性生活または性的指向
* 労働組合への加入状況
* 疑われているまたは実際の犯罪行為

個人データ (たとえば、ユーザー ID、ユーザー名、その他の識別子) を一切保存しない形で X コンテンツを集計して分析することは、当該分析が適用法令および Developer Agreement and Policy のすべての条項に準拠していることを条件に認められます。

<div id="off-x-matching">
  ## X 外でのマッチング
</div>

X 外でのマッチングとは、X のコンテンツ (X のユーザー名やユーザー ID を含む) を、人物、世帯、デバイス、ブラウザ、その他の X 外の識別子と関連付けることを指します。たとえば、X のユーザー名を、企業の顧客レコードと関連付けるケースです (例：「John Doe」というあなたの顧客レコードが、X 上の @johndoe とマッチされる場合) 。

人々が X 上で、必要に応じて別の、そして希望する場合には仮名のアイデンティティを安心して作成できるようにしたいと考えています。X ユーザーに関するいかなる情報でも、そのユーザーの X 外の識別子と関連付けることを意図している場合は、その関連付けを行う前に、そのユーザーから明示的なオプトイン同意を取得する必要があります。たとえば、ユーザーがあなたのサービスへのサインアッププロセスの一環として、自分の X ハンドルをあなたに直接共有することで、この同意を得ることができます。

ユーザーの X のアイデンティティを X 外の識別子とリンクするための、ユーザーからの明示的なオプトイン同意がない状況では、あなたが行うあらゆる紐付けは、その目的で利用されることをユーザーが合理的に予期しうる情報のみに基づいていなければなりません。ユーザーが、自分が提供した情報を使って、自分の X アカウントが X 外のアイデンティティと紐付けられていると知ったら驚くような場合は、そのような行為は行わないでください。さらに、本人からの明示的なオプトイン同意がない限り、あなたが保有する誰かに関する記録を X のアイデンティティとマッチさせようと試みることができるのは、次の情報に基づく場合に限られます。

* **ユーザーがあなたに直接提供した情報。** あなたとの間にこれまで何ら関係のない個人に関する記録 (第三者から取得した個人データを含む) は、この基準を満たしません。および／または
* **公開データ。** この文脈でいう「公開データ」とは、次を指します。
  * あなたが公的で一般に利用可能なリソース (たとえば、ある職業団体の会員名簿など) から取得した、そのユーザーに関する情報
  * X 上でそのユーザーについて一般公開されている情報。これには、次のものが含まれます。
    * 投稿
    * ユーザーの自己紹介文 (bio) や公開されている位置情報を含むプロフィール情報
    * 表示名とユーザー名

<div id="redistribution-of-x-content">
  ## X コンテンツの再配布
</div>

X API を通じて取得した X コンテンツを第三者と共有する必要がある場合、最良の方法はポスト ID、ダイレクトメッセージ ID、および／またはユーザー ID を共有することです。コンテンツのエンドユーザーは、X API を使用してそれらをリハイドレート (すなわち、完全なポスト、ユーザー、またはダイレクトメッセージのコンテンツをリクエスト) できます。これにより、X コンテンツのエンドユーザーが、常に最新の情報を X から直接取得できるようになります。

ハイドレート済みの X コンテンツについて、非自動化された手段による限定的な再配布を認めています。この方法でハイドレート済みの X コンテンツを第三者と共有する場合、受領者 1 名あたり 1 日につき、ハイドレート済みの公開ポストオブジェクトおよび／またはユーザーオブジェクトを最大 50,000 件までしか共有できません。また、このデータをブログ記事への添付ファイルや公開 GitHub リポジトリなどの形で一般に公開してはなりません。

X コンテンツを再配布する際に留意すべき点が、他にもいくつかあります。

* X から事前の明示的な書面による許可を受けていない限り、30 日間にわたり単一の組織に対して配布できるポスト ID の合計は 1,500,000 件までです。
* 非営利の研究のみを目的として学術機関の代理でポスト ID および／またはユーザー ID を再配布する個人は、ポスト ID および／またはユーザー ID を無制限に再配布することが認められます。
* 上記のとおり X コンテンツの共有許可をリクエストするには、API Policy サポートフォームをご利用ください。

第三者に X コンテンツを配布することが許可されている範囲においても、このコンテンツには引き続き Developer Agreement および Developer Policy が適用され、第三者は X コンテンツを受領する前に、X の[利用規約](https://twitter.com/en/tos)、[プライバシーポリシー](https://twitter.com/en/privacy)、[Developer Agreement](/ja/developer-terms/agreement)、および [Developer Policy](/ja/developer-terms/policy) に同意しなければなりません。

<div id="multiple-applications">
  ## 複数のアプリケーション
</div>

単一のユースケース、または実質的に類似もしくは重複するユースケースに対して、複数のアプリケーションを登録することはできません。これらのポリシーの詳細については[こちら](https://twittercommunity.com/t/policy-clarification-multiple-applications-for-the-same-use-case/92080)をご覧ください。

この文脈において「ユースケース」とは、アプリケーションを通じて実行される一貫した分析・表示・アクションのセットを指します。同じサービスまたはアプリケーションを異なるエンドユーザーに提供する場合は 1 つのユースケースとみなされます。ただし、ツールまたはサービスの「ホワイトラベル」版は除きます。アプリケーションの「ホワイトラベル」版を提供する予定がある場合は、事前に当社へ通知し、個別に承認を受ける必要があります。これらのルールは、お客様が登録するアプリケーションだけでなく、お客様のツールまたはサービスのエンドユーザーが登録するアプリケーションにも適用されます。お客様のツールまたはサービスを利用する目的でエンドユーザーにアプリケーションの登録を求めた結果、お客様ご自身、お客様のアプリケーション、お客様の顧客、および／またはお客様のツールまたはサービスのエンドユーザーに対して、措置が講じられる可能性があります。

このルールの唯一の例外は、同一サービスに対して開発用 (「dev」) 、ステージング用、および本番用 (「prod」) インスタンスを作成する場合です。これらのアプリケーションには (たとえばアプリケーション名や説明で) 明確にラベル付けし、開発用またはステージング用アプリケーションを本番目的で使用しないようにしてください。

<div id="automation-spam-and-auto-responses">
  ## 自動化、スパム、および自動応答
</div>

スパムを作成したり、スパム的な行為に関与したりする目的で X の API および開発者向けプロダクトを使用することは禁止されています。スパムに関する [X ルール](https://t.co/rules) を確認し、あなたのアプリケーションが当社のポリシーに違反せず、またユーザーに違反させることがないようにしてください。

あなたのアプリケーションが、ポストの投稿、アカウントのフォロー、ダイレクトメッセージの送信など、X サービス上で書き込みアクションを行うために使用される場合は、サービスが当社のガイドラインに準拠していることを確認するために、[自動化ルール](https://support.twitter.com/articles/76915) を慎重に確認する必要があります。特に、次の点を守ってください。

* [自動返信や自動メッセージ](https://twittercommunity.com/t/policy-clarification-automated-replies-and-mentions/94444) を送信する前に、必ずユーザーから明示的な同意を得ること
* あなたからの連絡を希望しないというユーザーからのリクエストには、直ちに従うこと
* [大量フォロー](https://twittercommunity.com/t/policy-clarification-aggressive-following-and-inorganic-following-behavior/92769) を含む、大量・攻撃的・スパム的な行為を決して行わないこと
* [複数のアカウント](https://blog.twitter.com/developer/en_us/topics/tips/2018/automation-and-the-use-of-multiple-accounts.html) に対して、同一または実質的に類似したコンテンツを決して投稿しないこと

<div id="measuring-the-x-service">
  ## X サービスの測定
</div>

ベンチマークや競合他社との比較を目的として、X の可用性、パフォーマンス、機能、または利用状況を測定するために X API を使用してはなりません。たとえば、次のような目的で X API を使用してはなりません。

* アクティブユーザー数やアカウント総数など、X ユーザーに関する集計メトリクスを算出すること
* 1 日あたりのポスト総数や、ユーザーエンゲージメント数、アカウントエンゲージメント数など、X ポストに関する集計メトリクスを算出すること
* [X Rules](https://help.twitter.com/en/rules-and-policies/twitter-rules) で許可されている場合を除き、X 上のスパムやセキュリティを測定または分析すること

<div id="surveillance-privacy-and-user-protection">
  ## 監視、プライバシー、ユーザー保護
</div>

X では、ユーザーのプライバシーを保護し擁護することが、当社の企業としての根幹に組み込まれており、その姿勢は開発者向けおよびデータ製品にも反映されています。私たちは、X データが世界にとって大きな善の力になりうると信じています — ジャカルタの洪水時に人命を救うことから、USGS による地震の追跡、さらには国連と協力して持続可能な開発目標 (SDGs) を達成する取り組みまで、その可能性は多岐にわたります。しかし、私たちは、監視目的で、またはユーザーが合理的に期待するプライバシーに反するいかなる形でも、X データおよび X API を利用することを、あらゆる主体に対して禁止します。断じて認めません。

[Developer Agreement](/ja/developer-terms/agreement) では、X データおよび開発者向け製品の禁止される利用方法について説明しています。そこには、X ユーザーまたはそのコンテンツの調査や追跡、さらには (抗議活動、集会、コミュニティによる組織的な会合などの) センシティブな出来事の追跡、警告、監視が含まれます。

本条件の下で禁止される活動カテゴリーには、以下のようなものが含まれます (これらに限定されません) 。

* 労働組合や活動家グループなど、センシティブなグループや組織の調査または追跡
* 身辺調査や、あらゆる形態の過度な審査・精査
* クレジットまたは保険リスクの分析
* 個人プロファイリングや心理特性に基づくセグメンテーション
* 顔認識

これらのポリシーは、当社 API のすべての利用者に適用されます。これらの目的で X API を不正利用した場合、アクセスの一時停止や終了を含む執行措置の対象となります。

X アカウントに関する情報を求める法執行機関向けの追加情報については、[https://t.co/le](https://t.co/le) を参照してください。

さらに現時点では、X は、[Grok](https://help.x.com/en/using-x/about-grok) を例外として、X API および／または X コンテンツを用いて、基盤モデルまたはフロンティアモデルをファインチューニングまたは学習させるいかなる利用も禁止しています。
