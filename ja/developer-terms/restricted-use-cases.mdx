当社の開発者プラットフォームをご利用いただくには、[Developer Agreement and Policy](/ja/developer-terms/agreement) および関連ポリシー（[Display Requirements](https://developer.x.com/en/developer-terms/display-requirements.html) や [Automation Rules](https://help.twitter.com/en/rules-and-policies/twitter-automation) など）を確認し、同意していただく必要があります。これらの契約およびポリシーでは、その他の事項に加えて、いくつかの利用が制限されるユースケースに関する指針を示しています。以下では、これらの制限の一部について、補足情報を提供します。

<div id="sensitive-information">
  ## 機微な情報
</div>

X ユーザーに関する潜在的に機微な特性を導き出したり推定したりする目的で X のデータを利用する場合には、細心の注意を払ってください。次のような X ユーザーに関する情報を、新たに導き出したり推定したり、またはそのように導出・推定された情報を保存したりしてはなりません。

* 健康状態（妊娠を含む）
* 否定的な財政状況または経済状態
* 政治的所属または信条
* 人種的または民族的出自
* 宗教的または哲学的所属または信条
* 性生活または性的指向
* 労働組合への加盟状況
* 疑われている、または実際に行われた犯罪行為

個人データ（たとえば、ユーザー ID、ユーザー名、その他の識別子）を一切保存しない形での X コンテンツの集約分析は認められますが、その分析も、適用される法令および Developer Agreement and Policy のすべての条項を順守している必要があります。

<div id="off-x-matching">
  ## X 外でのマッチング
</div>

X 外でのマッチングとは、X のコンテンツ（X のユーザー名やユーザー id を含む）を、人物、世帯、デバイス、ブラウザ、またはその他の X 外の識別子と関連付けることを指します。例としては、X のユーザー名を企業の顧客記録と関連付ける場合が挙げられます（たとえば、あなたの顧客記録の「John Doe」が、X 上の @johndoe と一致させられる場合など）。

人々が X 上で、必要に応じて別個の、そして望むのであれば仮名のアイデンティティを安心して作成できるようにしたいと考えています。X ユーザーに関するあらゆる情報を X 外の識別子と関連付ける場合、その関連付けを行う前に、ユーザーから明示的なオプトイン同意を取得することを求めます。例えば、ユーザーがあなたのサービスへのサインアッププロセスの一環として、自身の X のハンドルを直接共有することで、この同意を得ることができます。

ユーザーの X 上のアイデンティティを X 外の識別子にリンクするための、ユーザーによる明示的なオプトイン同意がない状況では、あなたが行うあらゆる関連付けは、その目的で利用されることをユーザーが合理的に予期できる情報のみに基づく必要があります。ユーザーが、自分が提供した情報を使って、自身の X アカウントが X 以外のアイデンティティとリンクされていることを知って驚くような場合は、そのようなことは行わないでください。さらに、個人の明示的なオプトイン同意がない限り、次のいずれかに基づいてのみ、その人に関するあなたの記録を X 上のアイデンティティにマッチさせようとすることができます。

* **ユーザーがあなたに直接提供した情報。** あなたとの事前の関係が一切ない個人に関する記録（第三者から取得した個人に関する data を含む）は、この基準を満たしません。および／または
* **公開 data。** この文脈における「公開 data」とは、次を指します。
  * 公開されており一般に利用可能なリソース（職業団体の会員名簿など）から取得した、ユーザーに関する情報
  * X 上で公に利用可能な、ユーザーに関する情報。これには次が含まれます。
    * 投稿
    * ユーザーの自己紹介や公開されている所在地を含むプロフィール情報
    * 表示される名前およびユーザー名

<div id="redistribution-of-x-content">
  ## X コンテンツの再配布
</div>

X API を通じて取得した X コンテンツを第三者と共有する必要がある場合は、投稿 ID、ダイレクトメッセージ ID、および／またはユーザー ID を共有する方法が最適です。コンテンツのエンドユーザーは、それらの ID を使用して X API を通じてリハイドレート（つまり、完全な投稿、ユーザー、またはダイレクトメッセージのコンテンツを再取得）できます。これにより、X コンテンツのエンドユーザーが、常に最新の情報を直接 X から取得できるようになります。

X では、自動化されていない手段による、リハイドレートされた X コンテンツの限定的な再配布を認めています。この方法でリハイドレート済み X コンテンツを第三者と共有する場合、1 受信者あたり 1 日につき、リハイドレート済みの公開投稿オブジェクトおよび／またはユーザーオブジェクトを合計 50,000 件までしか共有できず、これらのデータを公開の場で利用可能にしてはなりません（例：ブログ記事への添付ファイルとして提供する場合や、公開された GitHub リポジトリ内で提供する場合など）。

X コンテンツを再配布する際には、次の点にも注意してください。

* 30 日間の期間において、事前に X から明示的な書面による許可を得ていない限り、単一の組織に対して配布できる投稿 ID の総数は 1,500,000 件までに限られます。
* 非商用の学術研究のみを目的として学術機関を代表し、投稿 ID および／またはユーザー ID を再配布する個人は、投稿 ID および／またはユーザー ID を無制限に再配布することが認められます。
* 上記のとおり X コンテンツを共有する許可をリクエストするには、API Policy サポートフォームをご利用ください。

X コンテンツを第三者に配布することが認められている範囲においても、そのコンテンツは引き続き Developer Agreement および Developer Policy の対象であり、これらの第三者は X コンテンツを受領する前に、X の [Terms of Service](https://twitter.com/en/tos)、[Privacy Policy](https://twitter.com/en/privacy)、[Developer Agreement](/ja/developer-terms/agreement)、および [Developer Policy](/ja/developer-terms/policy) に同意する必要があります。

<div id="multiple-applications">
  ## 複数のアプリケーション
</div>

単一のユースケース、または実質的に類似もしくは重複するユースケースに対して、複数のアプリケーションを登録することは許可されません。これらのポリシーの詳細については[こちら](https://twittercommunity.com/t/policy-clarification-multiple-applications-for-the-same-use-case/92080)をご覧ください。

この文脈において「ユースケース」とは、アプリケーションを通じて実行される、一貫した分析・表示・アクションの集合を指します。同一のサービスやアプリケーションを異なるエンドユーザーに提供する場合は、1つのユースケースとして扱われます。ただし、ツールやサービスの「ホワイトラベル」版はこれに含まれません。アプリケーションの「ホワイトラベル」版を提供する予定がある場合は、必ず当社に通知し、個別の承認を受ける必要があります。これらのルールは、あなたが登録するアプリケーションと、あなたのツールやサービスのエンドユーザーが登録するアプリケーションの両方に適用されます。あなたのツールやサービスを利用する目的でエンドユーザーにアプリケーション登録を求めた場合には、あなたやあなたのアプリケーション、あなたの顧客、またはあなたのツールやサービスのエンドユーザーに対して、制裁措置やその他の対応が取られる可能性があります。

このルールの唯一の例外は、同一サービスについて、開発用（「dev」）、ステージング用、および本番用（「prod」）インスタンスを作成する場合です。これらのアプリケーションは（たとえばアプリケーションの名前や説明の中で）明確に区別してラベル付けし、開発用またはステージング用アプリケーションを本番用途で使用しないようにしてください。

<div id="automation-spam-and-auto-responses">
  ## 自動化、スパム、および自動レスポンス
</div>

スパムを作成したり、スパム行為に関与したりする目的で X の API や開発者向けプロダクトを利用することは禁止されています。スパムに関する [X ルール](https://t.co/rules) を確認し、あなたのアプリケーションが、またその利用者が、当社のポリシーに違反しないよう必ずご留意ください。

あなたのアプリケーションが、投稿の作成、アカウントのフォロー、ダイレクトメッセージの送信など、X サービス上で書き込み操作を行うために使用される場合は、サービスが当社のガイドラインに準拠していることを確認するために、[Automation Rules](https://support.twitter.com/articles/76915) を慎重に確認する必要があります。特に、次の点を遵守してください。

* [自動返信やメッセージ](https://twittercommunity.com/t/policy-clarification-automated-replies-and-mentions/94444) を送信する前に、必ずユーザーから明示的な同意を得る
* あなたからの連絡を受け取らないことを希望するユーザーからのリクエストには、直ちに従う
* [大量フォロー](https://twittercommunity.com/t/policy-clarification-aggressive-following-and-inorganic-following-behavior/92769) を含む、大量・攻撃的・スパム的なアクションを決して行わない
* [複数のアカウント](https://blog.twitter.com/developer/en_us/topics/tips/2018/automation-and-the-use-of-multiple-accounts.html) にまたがって、同一または実質的に類似したコンテンツを投稿しない

<div id="measuring-the-x-service">
  ## X サービスの計測
</div>

X の可用性、パフォーマンス、機能、または利用状況を、ベンチマークや競合分析を目的として測定するために X API を利用しないでください。たとえば、X API を使用して次のことを行ってはなりません。

* アクティブユーザー数やアカウント総数など、X ユーザーに関する集計指標を算出すること
* 1 日あたりの投稿総数、ユーザーエンゲージメント数、アカウントエンゲージメント数など、X 上の投稿に関する集計指標を算出すること
* [X Rules](https://help.twitter.com/en/rules-and-policies/twitter-rules) において許可されている場合を除き、X 上のスパムやセキュリティを測定または分析すること

<div id="surveillance-privacy-and-user-protection">
  ## 監視、プライバシー、ユーザー保護
</div>

X では、ユーザーのプライバシーを守ることが当社の中核的な DNA に組み込まれており、開発者向けおよびデータ製品にもそのコミットメントが反映されています。X のデータは、ジャカルタの洪水時の人命救助、USGS による地震の追跡、国連との協働による持続可能な開発目標の達成支援など、世界に良い影響をもたらす強力な力になり得ると考えています。ただし当社は、監視を目的とする、またはユーザーが合理的に期待するプライバシーに反するその他いかなる方法による X データおよび X API の利用を、あらゆる主体に対して禁止しています。例外はありません。

当社のデータおよび開発者向け製品の禁止されている利用方法については、[Developer Agreement](/ja/developer-terms/agreement) で説明しており、その中には、X ユーザーやそのコンテンツの調査・追跡の禁止、ならびに（抗議活動、集会、地域コミュニティによる組織化ミーティングなどの）機微なイベントの追跡、アラート、監視の禁止が含まれます。

これらの条項の下で禁止される活動カテゴリには、次のようなものが含まれます（ただしこれらに限定されません）。

* 労働組合やアクティビスト団体など、機微な集団および組織の調査または追跡
* 身辺調査またはあらゆる形態の過度な事前審査
* クレジットまたは保険リスク分析
* 個人プロファイリングまたはサイコグラフィック・セグメンテーション
* 顔認識

これらのポリシーは、当社 API のすべての利用者に適用されます。これらの目的での X API の不正利用は、アクセスの一時停止や恒久的な停止を含む執行措置の対象となります。

X アカウントに関する情報を求める法執行機関向けの追加情報については、[https://t.co/le](https://t.co/le) を参照してください。

さらに現時点では、[Grok](https://help.x.com/en/using-x/about-grok) を例外として、X は、X API および／または X Content を使用して、ファウンデーションモデルまたはフロンティアモデルをファインチューニングまたは学習させるあらゆる利用を禁止しています。
