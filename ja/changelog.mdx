<Update label="Aug 3, 2022" description="X API v2">
  ### フィルタリング演算子エイリアスの追加

  フィルタリング／クエリ演算子の「エイリアス」が、エンタープライズ、プレミアム、および v2 全体の search と filtered stream エンドポイントに追加されました。多くの場合、演算子は statuses ではなく投稿を参照します。たとえば、&quot;in&#95;reply&#95;to&#95;status&#95;id&quot; のエイリアスとして &quot;in&#95;reply&#95;to&#95;tweet&#95;id&quot; が追加されています。別のケースでは、新しい演算子エイリアスによって、実行されるマッチング内容がより明確になります。たとえば、投稿には動画の添付が 1 つしか持てないため、&quot;has:videos&quot; に対する新しいエイリアスとして &quot;has:video&#95;link&quot; が提供されます。さらに多くの例については、[v2 filtered stream operator table](https://developer.x.com/en/docs/twitter-api/tweets/filtered-stream/integrate/build-a-rule#list) を参照してください。
</Update>

<Update label="Dec 14, 2021" description="X API v2：認証">
  ### OAuth 2.0 認証のサポート

  本日より、すべての開発者は、開発者コンソールで認証方法として OAuth 2.0 を選択することで、OAuth 2.0 を使って認証できるようになりました。今回のリリースでは、機密クライアントおよびパブリッククライアントに加え、関連するすべての v2 エンドポイントで、この認証方法を利用できるようサポートを追加しました。

  OAuth 2.0 は業界標準の認可プロトコルであり、アプリケーションのスコープをより細かく制御できるようにし、複数デバイスにまたがる認可フローを改善します。言い換えると、X を利用する人向けのアプリケーションを構築する開発者は、自身のアプリがユーザーからリクエストする情報をより細かく制御できるようになり、エンドユーザーには必要なデータと情報のみを求めればよくなります。

  この最新の認可プロトコルにより、あなたのアプリを認可する際に、エンドユーザーに対して、要求している特定のスコープのみを表示する、よりシンプルでスムーズな同意フローを提示できるようになります。

  このリリースの詳細については、フォーラムのお知らせをご覧ください。
</Update>

<Update label="Nov 15, 2021" description="X API v2：早期アクセス">
  ### X API v2 に対する主要なプラットフォームアップデート

  **主なプラットフォームアップデート:X API v2 が主要バージョンに、新しい Essential および Elevated アクセス、ポリシーの変更**

  本日、X API v2 が X API の主要バージョンになったことをお知らせします。X API v2 には、X API 上に構築されている既存のすべてのアプリの 90% のニーズを満たすのに十分な数のエンドポイントと機能が実装されています。

  X API v2 の開発者体験をさらに向上させるため、本日、以下の変更を導入します。

  * API への迅速で無料の Essential アクセス、およびユースケースが承認された開発者向けの無料の Elevated アクセスを提供します。これらのアクセスレベルの詳細については、「About the X API」ページで詳しく説明しています。

  * X のコア機能の活用方法を制限し、アプリでサポートできるユーザー数を制限していた開発者ポリシー上の文言を削除します。

    * あなたが X をより良く、より健全にし、パブリックな会話を拡張するツールやプロダクトを構築できるよう、プラットフォームを開放します。[私たちがぜひ構築してほしいと考えているソリューションの一覧はこちらをご覧ください](https://developer.x.com/en/docs/twitter-api/what-to-build)。

    * 特に、X の体験の複製を制限していた条項（X のコア機能に関するものを含む）や、多数のユーザートークンを保持する際に許可を要件としていた条項を削除しました。

    * X を利用する人々を支援するソリューションを構築するには、開発者が X 上で提供されているものの一部を構築（または複製）しなければならない場合が多いことを理解しています。今回の開発者ポリシーの変更は、開発者エコシステムに明確性をもたらし、開発者がパブリックな会話において構築・イノベーション・価値創出をしやすくする、オープンな API プラットフォームを提供することを目的としています。

  このリリースおよびここに至るまでの X API のリリースについては、[フォーラム投稿](https://devcommunity.x.com/t/ushering-in-a-new-era-for-the-twitter-developer-platform-with-the-twitter-api-v2/162087)でさらに詳しく説明しています。

  以前の変更履歴もあわせて確認していただくため、これまでに X API v2 でリリースされた内容を理解するのに役立つ、主なリソースをまとめました。

<Update label="2018年5月10日" description="X API: Standard v1.1">
  ### 引用ペイロードのレンダリングの変更

  本日、引用ペイロード内での URL のレンダリング方法を変更しました。

  引用された投稿を参照できるようにするため、新しいエンティティ &quot;quoted&#95;status&#95;permalink&quot; を追加し、引用された投稿の &quot;text&quot; フィールドから t.co リンクを削除しました。

  詳細については、[フォーラム投稿](https://devcommunity.x.com/t/updating-how-urls-are-rendered-in-the-quote-tweet-payload/105473)および[更新されたドキュメント](https://devcommunity.x.com/t/upcoming-changes-to-the-developer-platform/104603)をお読みください。

</Update>

<Update label="May 5, 2017" description="X API: Standard v1.1">
  ### DM コマンド用のオプションパラメータ

  `statuses/update` のオプションパラメータ `enable_dm_commands` を使用すると、移行期間が終了する前に、アプリケーションが DM コマンドのサポートを早期に削除できるようになります。デフォルト値は *true*（つまり現在のレガシー動作）ですが、*false* に設定すると、11月1日以降の新しい動作になります。`statuses/update` のオプションパラメータ `fail_dm_commands` を *true* に設定すると、DM コマンドは API から HTTP 403（エラーコード 151）を返すようになります。デフォルト値は *false* です。このアップデートの詳細は[フォーラム](https://devcommunity.x.com/t/retiring-legacy-dm-commands-on-the-standard-tweet-api/86653)をご覧ください。
