<div id="how-to-get-access-to-the-ads-api">
  ## Ads API へのアクセス方法
</div>

1. [開発者アカウント](https://developer.x.com/en/apply-for-access)に登録します。
2. [開発者用 App](https://developer.x.com/app) を作成し、トークンを安全に保管します。
3. [ads.x.com/help](https://ads.x.com/help) にアクセスし、各開発者用 App ごとに Ads API へのアクセスを申請します。

<Note>**注:** すでに X Developer Platform で開発を行っていて開発者アカウントをお持ちの場合は、手順 3 に進んでください。</Note>

<div id="step-one-signup-for-a-developer-account">
  ### ステップ1：開発者アカウントにサインアップする
</div>

X のいずれの API 製品にリクエストを送信する場合でも、まず開発者アカウントにサインアップする必要があります。Developer Console で App と開発者用 App を作成します。これにより、すべての API リクエストを認証するために使用する認証情報一式が発行されます。

<Button href="https://developer.x.com/en/apply-for-access">
  開発者アカウントにサインアップする
</Button>

<div id="step-two-save-your-apps-key-and-tokens-and-keep-them-secure">
  ### ステップ 2: App のキーとトークンを保存し、安全に管理する
</div>

開発者用 App では、一連の API Keys（Consumer Keys とも呼ばれます）が提供されます。また、個人の X アカウントに代わってリクエストを送信するために使用できる一連の Access Tokens と、OAuth 2.0 Bearer Token を必要とするエンドポイントの認証に使用できる Bearer Token を生成することもできます。これらのキーやトークンは再生成しない限り有効期限が切れないため、環境変数を作成するか、安全なパスワードマネージャーを使用することをお勧めします。

また、App の詳細ページの URL に記載されている App ID も控えておいてください。これは、次のステップで Ads API へのアクセスをリクエストする際に役立ちます。

<Note>
**注意:** キーとトークンは Developer Console 上で一度しか表示されないため、生成後すぐにこれらの認証情報をパスワード管理システムに保存することが重要です。

キーやトークンを紛失したり忘れてしまった場合は、それらを再生成する必要があります。これにより新しいキーとトークンが作成され、古いものは無効になります。つまり、以前の認証情報を使用して構築していた連携をすべて更新しなければなりません。

[認証に関するベストプラクティス](https://developer.x.com/en/docs/authentication/guides/authentication-best-practices)についての詳細をご覧ください。
</Note>

<div id="step-three-apply-for-access-to-the-ads-api">
  ### ステップ3：Ads API へのアクセスを申請する
</div>

この時点で、すでに [X API へのベーシックアクセス](https://developer.x.com/en/docs/twitter-api/v1)は取得していますが、特定の X Ads API 機能にはまだアクセスできません。次に、Ads API へのアクセス申請を行い、承認を受ける必要があります。[ads.x.com/help](https://ads.x.com/help) にアクセスし、各開発者用 App ごとに Ads API へのアクセス申請を送信してください。

<div id="access-tiers">
  ### アクセスティア
</div>

申請プロセスの一環として、必要なアクセスレベルを指定する必要があります。[アプリレベルおよび広告アカウントレベルの権限](https://developer.x.com/en/docs/twitter-ads-api/obtaining-ads-account-access#levels-of-access)の詳細をご確認ください。

<div id="conversion-only">
  #### コンバージョン専用
</div>

モバイルおよび Web コンバージョンのエンドポイントに、読み取りおよび書き込み権限付きでアクセスできます。

<div id="standard-access">
  #### 標準アクセス
</div>

Analytics、Campaign Management、Creatives、Custom Audiences、Conversion の各エンドポイントへの読み取りおよび書き込みアクセス権。

<Note>**注:** アプリが Ads API へのアクセス承認を受けた後、[ユーザーアクセストークンを再生成](https://developer.x.com/resources/fundamentals/authentication/obtaining-user-access-tokens)して、適切に[認証された Ads API リクエスト](https://developer.x.com/en/docs/twitter-ads-api/making-authenticated-requests)を行う必要があります。</Note>

<Note>**注:** 2023 年 7 月以前にアクセスを申請した Ads API 開発者は、異なるレベルのアクセス権や権限を持っている場合があり、OAuth トークンが 5 個に制限されていることがあります。追加のエンドポイントへのアクセスや既存アプリケーションのトークン制限の解除については、[アクセスの拡張](https://developer.x.com/en/docs/twitter-ads-api/increasing-access)に関するガイドを参照してください。</Note>

<div id="make-your-first-request">
  ## はじめてのリクエストを送信する
</div>

Ads API へのアクセスをテストするには、[GET accounts](https://developer.x.com/en/docs/twitter-ads-api/campaign-management/api-reference/accounts) エンドポイントにリクエストを送信します。このエンドポイントは、現在認証されているユーザーがアクセス権を持つ広告アカウントを返します。このリクエストで取得した広告アカウントの ID を、後続の API リクエストで使用して、特定の広告アカウントのデータを読み書きします。コマンドラインで [Twurl](https://developer.x.com/en/docs/tutorials/using-twurl) を使用する場合、リクエストは次のようになります。

**リクエスト例**

```bash
twurl -H ads-api.x.com "/11/accounts"
```

**レスポンスの例**

```json

    "params": {}
  },
  "data": [
```
