<div id="how-to-get-access-to-the-ads-api">
  ## Ads API へのアクセス方法
</div>

1. [開発者アカウント](https://developer.x.com/en/apply-for-access)に登録します。
2. [開発者用 App](https://developer.x.com/app) を作成し、トークンを安全に保管します。
3. [ads.x.com/help](https://ads.x.com/help) にアクセスし、各開発者用 App ごとに Ads API へのアクセスをリクエストします。

<Note>**注:** すでに X Developer Platform を利用していて開発者アカウントをお持ちの場合は、ステップ 3 に進んでください。</Note>

<div id="step-one-signup-for-a-developer-account">
  ### ステップ1：開発者アカウントに登録する
</div>

X の任意の API プロダクトにリクエストを送信するには、まず開発者アカウントに登録する必要があります。開発者コンソール内で、App と開発者用 App を作成します。これにより、API へのすべてのリクエストの認証に使用する一連の認証情報が発行されます。

<Button href="https://developer.x.com/en/apply-for-access">
  開発者アカウントに登録する
</Button>

<div id="step-two-save-your-apps-key-and-tokens-and-keep-them-secure">
  ### ステップ 2: App のキーとトークンを保存し、安全に保管する
</div>

開発者用 App 内で、API Key（Consumer Key とも呼ばれます）のセットが提供されます。個人の X アカウントに代わってリクエストを行うために使用できる Access Token のセットや、OAuth 2.0 Bearer Token を必要とするエンドポイントの認証に使用できる Bearer Token を生成することもできます。これらのキーとトークンは再生成しない限り有効期限が切れないため、環境変数として保存するか、安全なパスワードマネージャーを使用することをお勧めします。

また、App ID も控えておいてください。これは App 詳細画面の URL に表示されています。これにより、次のステップで Ads API へのアクセスをリクエストする手続きが容易になります。

<Note>
**注意:** キーとトークンは開発者コンソール上で 1 回しか表示されないため、生成後すぐにパスワード管理システムにこれらの認証情報を保存することが重要です。

キーやトークンを紛失、または忘れてしまった場合は、それらを再生成する必要があります。これにより新しいキーとトークンが作成され、古いものは無効になります。これは、以前の認証情報で設定していたあらゆる連携を更新しなければならないことを意味します。

[認証に関するベストプラクティス](https://developer.x.com/en/docs/authentication/guides/authentication-best-practices)について、さらに詳しくご覧ください。
</Note>

<div id="step-three-apply-for-access-to-the-ads-api">
  ### ステップ3: Ads API へのアクセスを申請する
</div>

この時点で、すでに [X API への基本アクセス](https://developer.x.com/en/docs/twitter-api/v1) はありますが、X Ads API 固有の機能にはまだアクセスできません。次に、Ads API へのアクセスを申請し、承認を受ける必要があります。[ads.x.com/help](https://ads.x.com/help) にアクセスし、使用する開発者用 App ごとに Ads API へのアクセスリクエストを送信してください。

<div id="access-tiers">
  ### アクセスレベル
</div>

申請手続きの一環として、必要なアクセスレベルを指定する必要があります。詳しくは、[アプリレベルおよび広告アカウントレベルの権限](https://developer.x.com/en/docs/twitter-ads-api/obtaining-ads-account-access#levels-of-access)を参照してください。

<div id="conversion-only">
  #### コンバージョンのみ
</div>

モバイルおよびウェブのコンバージョン用エンドポイントへの読み取りおよび書き込み権限。

<div id="standard-access">
  #### 標準アクセス
</div>

Analytics、Campaign Management、Creatives、Custom Audiences、Conversion エンドポイントへの読み取りおよび書き込み権限付きアクセス。

<Note>**注:** アプリが Ads API へのアクセス承認を受けた後、適切に[認証された Ads API リクエスト](https://developer.x.com/en/docs/twitter-ads-api/making-authenticated-requests)を行うには、[ユーザーアクセス・トークンを再生成](https://developer.x.com/resources/fundamentals/authentication/obtaining-user-access-tokens)する必要があります。</Note>

<Note>**注:** 2023 年 7 月以前に Ads API へのアクセスをリクエストした開発者は、異なるアクセスレベルや権限が設定されている場合があり、OAuth トークンが 5 個に制限されている可能性があります。追加のエンドポイントへのアクセスや、既存アプリケーションのトークン制限解除については、[アクセス拡張](https://developer.x.com/en/docs/twitter-ads-api/increasing-access)に関するガイドを参照してください。</Note>

<div id="make-your-first-request">
  ## 最初のリクエストを送信する
</div>

Ads API へのアクセスをテストするには、[GET accounts](https://developer.x.com/en/docs/twitter-ads-api/campaign-management/api-reference/accounts) エンドポイントにリクエストを送信します。このエンドポイントは、現在認可されているユーザーがアクセスできる広告アカウントを返します。このリクエストで返される広告アカウントの ID を、後続の API リクエストで使用して、特定の広告アカウントのデータを読み書きします。コマンドラインで [Twurl](https://developer.x.com/en/docs/tutorials/using-twurl) を使用すると、リクエストは次のようになります。

**リクエスト例**

```bash
twurl -H ads-api.x.com "/11/accounts"
```

**レスポンスの例**

```json

  },
  "data": [
```
