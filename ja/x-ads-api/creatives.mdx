<div id="overview">
  ## 概要
</div>

クリエイティブとは、キャンペーン内でプロモーションの対象とできるあらゆるエンティティを指します。投稿にはテキスト、画像、GIF、動画、またはカードを含めることができます。カードには画像または動画を含めることができます。

画像、GIF、または動画のクリエイティブは、[POST media/upload](/ja/x-api/media/upload-media#post-media-upload)（画像のみをサポートするシンプルなアップロードエンドポイント）または POST media/upload (chunked) エンドポイントのいずれかを使用してアップロードできます。これらは次の場所に追加できます。

カード:

* POST accounts/:account&#95;id/cards

ツイート:

* POST accounts/:account&#95;id/tweets - カードをツイートに追加するには、card&#95;uri パラメータを使用します。

予約ツイート:

* POST accounts/:account&#95;id/scheduled&#95;tweets

カードの詳細については、Cards ページを参照してください。動画とカードまたはツイートとの関連付けについては、Promoted Video ページを参照してください。

<div id="cards">
  ### カード
</div>

Ads API は、キャンペーンでプロモーションできるツイートに使用できる複数のカードタイプをサポートしています。**注意**: 一度ツイートされると、カードの詳細は一般に公開されます。これには、カードの所有者であるユーザーに関する情報が含まれる場合があります。

<div id="image">
  #### 画像
</div>

以下の画像仕様は、[Cards](/ja/x-ads-api/creatives#cards-2) で使用されるアセットに適用されます。画像は 3MB 以下で、幅が 800px 以上である必要があります。さらに、以下の横:縦のアスペクト比をサポートしています。

* Website: 1:1 および 1.91:1
* Image App Download: 1:1 および 1.91:1
* Poll: 1.91:1
* Image Conversation: 1.91:1
* Image Direct Message: 1.91:1

サポートされる画像形式は .bmp、.jpeg、.png です。

<div id="video">
  #### 動画
</div>

以下の動画仕様は、[Cards](/ja/x-ads-api/creatives#cards-2) で使用するアセットに適用されます。サポートされているアスペクト比（横:縦）は次のとおりです。

* Video Website: 16:9 および 1:1
* Video App Download: 16:9 および 1:1
* Poll: 16:9
* Video Conversation: 16:9
* Video Direct Message: 16:9

<div id="promoted-video">
  ### Promoted Video
</div>

このドキュメントでは、Ads API を使用して動画をアップロードしてプロモーションする手順の概要を説明します。

Ads API は、[ツイート](/ja/x-ads-api/creatives#tweets-2) 内および次のカードでの Promoted Video をサポートしています。

* [Video Website](https://devcommunity.x.com/t/ads-api-version-11/168814)
* [Video App Download](https://devcommunity.x.com/t/ads-api-version-11/168814)
* [Video Conversation](/ja/x-ads-api/creatives#video-conversation-cards)

まず、[POST media/upload (chunked)](https://developer.x.com/en/docs/media/upload-media/api-reference/post-media-upload-init.html) エンドポイントを使用して動画をアップロードします。次に、`media_id` を使用して、POST accounts/:account&#95;id/videos エンドポイントで動画を広告アカウントに関連付けます。動画の `id`（`media_key` と呼ばれることもあります）は、以降のリクエストで使用されます。これは、先頭が整数で始まり、その後にアンダースコアが続き、最後に大きな数値が来る文字列型です。たとえば、`13_875943225764098048` のような形式になります。

<div id="promoted-video-in-tweets">
  #### ツイート内のプロモーション動画
</div>

ツイートを作成するには、動画の `id` とともに [POST accounts/:account&#95;id/tweet](/ja/x-ads-api/creatives#get-accounts-account-id-tweets) エンドポイントを使用します。この手順で、動画タイトル、説明文、行動喚起（CTA）も指定できます。これらの値はユーザーに表示されます。

<div id="promoted-video-in-cards">
  #### カードにおけるプロモ動画
</div>

Video App Download カードと Video Conversation カードでは、ポスター画像を追加できます。これらのカードで使用する画像は、[POST media/upload](https://developer.x.com/en/docs/media/upload-media/api-reference/post-media-upload.html) エンドポイントを使ってアップロードします。

次のいずれかのエンドポイントを使用してカードを作成します。

* [POST accounts/:account&#95;id/cards/video&#95;website](https://devcommunity.x.com/t/ads-api-version-11/168814)
* [POST accounts/:account&#95;id/cards/video&#95;app&#95;download](https://devcommunity.x.com/t/ads-api-version-11/168814)
* [POST accounts/:account&#95;id/cards/video&#95;conversation](https://devcommunity.x.com/t/ads-api-version-11/168814)

動画の `id` と、必要に応じて画像の `media_id`（ポスター画像用）を指定します。

最後に、POST accounts/:account&#95;id/tweet エンドポイントを使ってツイートを作成します。カードは `card_uri` パラメータでツイートに添付します。

<div id="general-information">
  #### 一般情報
</div>

API を通じた動画アップロードの詳細な手順については、[Video Upload Guide](https://developer.x.com/en/docs/media/upload-media/uploading-media.html) を参照してください。

動画はプレロールアセットとしてプロモーション配信することもできます。詳しい説明は [Video Views Pre-roll Objective Guide](/ja/x-ads-api/campaign-management#video-views-preroll-objective) を参照してください。

* （2015-10-22 時点）プロモーション用コンテンツで使用する動画をアップロードする際は、[POST media/upload (chunked)](https://developer.x.com/en/docs/media/upload-media/api-reference/post-media-upload-init.html) エンドポイントへのすべての `INIT` コマンドリクエストで、`media_category` パラメータに `amplify_video` を設定する必要があります。この新しいパラメータを使用することで、動画が非同期で事前処理され、プロモーション用コンテンツで使用できるように準備されます。動画アップロード後の非同期処理の完了状況は、`STATUS` コマンドを使用して確認できます。
* プロモーション動画の最大長は現在 10 分で、ファイルサイズは 500MB 以下です。
* アップロードする動画は mp4 または mov 形式である必要があります。
* アップロードされた動画は通常は迅速に処理されますが、処理時間は動画の長さやファイルサイズによって変動します。
* アップロードするポスター画像は png または jpg 形式にしてください。アスペクト比やサイズの要件はありませんが、ポスター画像は動画プレーヤーに合わせて調整されます。

<div id="scheduled-tweets">
  ### 予約ツイート
</div>

<div id="introduction">
  #### はじめに
</div>

予約ツイート機能を使用すると、広告主やユーザーは後日公開されるようにツイートをあらかじめ作成・予約できます。これらのツイートを作成および管理できるだけでなく、API を使用して、それらのツイートが公開されたタイミングでプロモーションできるようラインアイテムに関連付けることもできます。これにより、広告主はネイティブツイートを事前に作成・準備し、重要な施策に先立ってキャンペーンクリエイティブを計画できます。たとえば、新製品発表と同時に即時公開されるツイートクリエイティブをあらかじめステージングしておく、といった使い方が可能です。

Scheduled Tweets API エンドポイントで提供される機能の一覧は次のとおりです。

* 新しく予約したツイートの作成、変更、表示
* 予約ツイートをラインアイテムに関連付ける
* 既存の予約ツイートの検索および管理
* 予約ツイートが公開された後、その公開済みツイートの `id` を取得

  #### API エンドポイント
</div>

* [POST accounts/:account&#95;id/scheduled&#95;tweets](/ja/x-ads-api/creatives#post-accounts-account-id-scheduled-tweets) (新しい予約済みツイートを作成)
* [PUT accounts/:account&#95;id/scheduled&#95;tweets/:scheduled&#95;tweet&#95;id](/ja/x-ads-api/creatives#example-request-39) (既存の予約済みツイートを更新)
* [DELETE accounts/:account&#95;id/scheduled&#95;tweets/:scheduled&#95;tweet&#95;id](/ja/x-ads-api/creatives#example-request-40) (`id` を使用して予約済みツイートを削除)
* [GET accounts/:account&#95;id/scheduled&#95;tweets/preview/:scheduled&#95;tweet&#95;id](/ja/x-ads-api/creatives#scheduled-tweets-2) (既存の予約済みツイートをプレビュー表示)

  #### 予約済みプロモーションツイート
</div>

* [GET accounts/:account&#95;id/scheduled&#95;promoted&#95;tweets](/ja/x-ads-api/campaign-management#get-accounts-account-id-scheduled-promoted-tweets) (すべての予約済みプロモーションツイートの一覧を取得)
* [GET accounts/:account&#95;id/scheduled&#95;promoted&#95;tweets/:scheduled&#95;promoted&#95;tweet&#95;id](/ja/x-ads-api/campaign-management#get-accounts-account-id-scheduled-promoted-tweets-scheduled-promoted-tweet-id) (指定した `id` の予約済みプロモーションツイートを取得)
* [POST accounts/:account&#95;id/scheduled&#95;promoted&#95;tweets](/ja/x-ads-api/campaign-management#post-accounts-account-id-scheduled-promoted-tweets) (新しい予約済みプロモーションツイートを作成)
* [DELETE accounts/:account&#95;id/scheduled&#95;promoted&#95;tweets/:scheduled&#95;promoted&#95;tweet&#95;id](/ja/x-ads-api/campaign-management#delete-accounts-account-id-scheduled-promoted-tweets-scheduled-promoted-tweet-id) (指定した `id` の既存の予約済みプロモーションツイートを削除)

<div id="scheduled-tweet-view">
  #### 予約ツイートの表示
</div>

* [GET accounts/:account&#95;id/scheduled&#95;tweets/preview/:scheduled&#95;tweet&#95;id](/ja/x-ads-api/creatives#scheduled-tweets-2)（既存の予約ツイートを表示）

予約ツイートは「ライブ」のツイートとは別個のエンティティであるという性質上、これらのツイートを作成または編集する際には、2 種類のバリデーションが実行されます。最初のバリデーションルールは、予約ツイートの作成時、具体的には次のタイミングで実行されます。

<div id="scheduled-tweet-create">
  #### 予約ツイートの作成:
</div>

* 認証済みユーザーが、指定された @handle に対してオーガニックツイートを作成するアクセス権を持っていることを検証します。プロモーション専用ツイートを作成するには、認証済みユーザーが [Tweet composer permissions](https://developer.x.com/content/developer-twitter/en/docs/ads/campaign-management/api-reference/authenticated-user-access#get-accounts-account-id-authenticated-user-access) を持つアカウントユーザーである必要があります。
* `scheduled_at` 時刻の前後 15 分のウィンドウ内で、作成が予約されているツイートが 30 件を超えていないことを検証します。`SCHEDULED_TWEET_LIMIT_EXCEEDED` エラーメッセージは、同じ将来の 15 分間の時間枠内に予約ツイートが多すぎることを示します。広告主は既存の予約ツイートを削除するか、`scheduled_at` の時刻を前または後ろにずらす必要があります。

<div id="scheduled-tweet-goes-live">
  #### スケジュール済みツイートが公開されるとき:
</div>

* これらの検証ルールは scheduled&#95;at の時点で実行され、API で通常のツイートを作成する際に適用されるルールと同一です。たとえば、スケジュール済みツイートに画像と GIF の両方が含まれている場合、そのスケジュール済みツイートは公開されず、scheduled&#95;status は FAILED に設定されます

<div id="workflow">
  #### ワークフロー
</div>

**新しい予約ツイートを作成する**

新しい予約ツイートは、[POST accounts/:account&#95;id/scheduled&#95;tweets](https://developer.x.com/content/developer-twitter/en/docs/ads/creatives/api-reference/scheduled-tweets#post-accounts-account-id-scheduled-tweets) エンドポイントを使用して作成できます。このエンドポイントには、`scheduled_at` の時刻と、ツイートにメディアエンティティが含まれていない場合のツイート本文 `text` という必須パラメータがあります。さらに、このエンドポイントでは、`as_user_id` パラメータを使用して別の @handle 名義で予約ツイートを作成したり、カード（`card_uri`）やメディア（`media_ids`）を追加したりできる、いくつかの追加オプションを利用できます。なお、1 つのツイートには同じタイプのエンティティのみを含めることができます。つまり、Video、Gif、Image のいずれか 1 種類に限定されます。`nullcast` パラメータは、そのツイートが「Promoted-Only」ツイートかどうかを制御します。新しく作成された予約ツイートはすべて、デフォルトで「Promoted-Only」（`nullcast=true`）です。`nullcast=false` の場合は、オーガニックの予約ツイートが作成されます。

予約ツイートが正常に作成されると、レスポンスには予約ツイート自体の一意の識別子を示す `id` フィールドが含まれます。このフィールドに加えて、`tweet_id` というフィールドも返されます。このフィールドは最初は `null` ですが、ツイートが実際に投稿されると、このフィールドには「ライブ」ツイートの ID が設定されます。

```
twurl -H 'ads-api.x.com' -X POST "/6/accounts/:account_id/scheduled_tweets" -d 'scheduled_at=2017-12-24T23:59:00Z&text=Happy Holidays!'
```

これにより、以下の予約ツイートが作成されます。

```json
{
  "request": {
    "params": {
      "text": "Happy Holidays!",
      "scheduled_at": "2017-12-24T23:59:00Z"
    }
  },
  "data": {
    "completed_at": null,
    "id_str": "917507899668099072",
    "text": "Happy Holidays!",
    "user_id": "3271358660",
    "scheduled_status": "SCHEDULED",
    "id": 917507899668099100,
    "nullcast": true,
    "created_at": "2017-10-09T21:51:44Z",
    "scheduled_at": "2017-12-24T23:59:00Z",
    "card_uri": null,
    "updated_at": "2017-10-09T21:51:44Z",
    "tweet_id": null,
    "media_keys": []

}
```

この予約ツイートが公開されると、`tweet_id` フィールドに実際に公開されたツイートの ID が設定されます。

**予約ツイートをラインアイテムに関連付ける**

予約ツイートはオーガニックツイートを作成するために使用できますが、パートナーは「Promoted-Only」（`nullcast=true`）ツイートを作成することもでき、いずれもラインアイテムに関連付けることが可能です。これを可能にするために、[POST accounts/:account&#95;id/scheduled&#95;promoted&#95;tweets](https://developer.x.com/content/developer-twitter/en/docs/ads/campaign-management/api-reference/scheduled-promoted-tweets#post-accounts-account-id-scheduled-promoted-tweets) エンドポイントも提供しています。このエンドポイントでは、1 回の API 呼び出しにつき 1 件の予約済みプロモツイートのみをラインアイテムに関連付けることができます。同じラインアイテムに複数の予約ツイートを関連付けるには、複数回の API 呼び出しが必要です。

既存の予約済みプロモツイートを変更することはできない点に注意してください。

```
twurl -H 'ads-api.x.com' -X POST "/6/accounts/:account_id/scheduled_promoted_tweets" -d 'line_item_id=a44qc&scheduled_tweet_id=917507899668099072'
```

```json
{
  "data": {
    "line_item_id": "a44qc",
    "id": "26576",
    "created_at": "2017-10-09T22:24:16Z",
    "updated_at": "2017-10-09T22:24:16Z",
    "scheduled_tweet_id": "917507899668099072",
    "tweet_id": null,
    "deleted": false
  },
  "request": {
    "params": {
      "line_item_id": "a44qc",
      "scheduled_tweet_id": 917507899668099100,
      "account_id": "aaaaa"
    }
  }
}
```

このエンドポイントは、指定された予約ツイートとラインアイテムとの関連付けのみを作成します。キャンペーン／ラインアイテムのフライト期間が開始されると、そのラインアイテムは対応する「ライブ」ツイートの配信を自動的に開始します。この段階では、予約ツイートが `SCHEDULED` 状態であること、および指定された予約ツイートが指定されたオブジェクティブに対して有効であることは検証しますが、それ以外の検証は行われません。ラインアイテムおよび予約ツイートに適用される残りのバリデーションルールは、ツイートが「ライブ」になるタイミングで実行されます。

キャンペーン配信に問題が発生しないようにするために、予約ツイートの `scheduled_at` は、キャンペーン／ラインアイテムのフライト期間の開始より前の時間に設定しておくことを推奨します。

たとえば、予約ツイートがキャンペーン開始日より後にライブになるよう設定されている（かつ、1 つのラインアイテムに 1 つのツイートのみが紐づいている）場合、キャンペーンは `ACTIVE` にはなりますが、予約ツイートがまだライブになっていないため、配信可能なクリエイティブが存在しないことになります。

**予約ツイートの管理**

残りのエンドポイント群では、API 利用者がすべての予約ツイートおよび予約プロモツイートを管理できます。これらの API は、任意の状態でフィルタリングしたすべての予約ツイートの一覧を返したり、`id` を指定して特定の予約ツイートを取得したりするために使用できます。

<div id="what-happens-when-a-scheduled-tweet-goes-live">
  #### 予約ツイートが公開されるとどうなりますか？
</div>

ある予約ツイートが公開されるタイミング、つまり `scheduled_at` 時刻になると、次の更新が行われます。

* 「ライブ」ツイートが作成されますが、最大 1 秒の遅延が発生する場合があります
* `tweet_id` が次のエンティティに追加されます:
* 予約ツイート
* プロモーション予約ツイート
* 新しいプロモーションツイートのエンティティが作成されます

<div id="best-practices">
  #### ベストプラクティス
</div>

予約ツイートを作成または配信するときは、次のベストプラクティスに従うことを推奨します。

* 予約ツイートを作成する際、そのツイートが有効な形式になっていることを確認してください（たとえば、1 つのツイートには画像・動画・GIF のいずれか 1 種類のみを含めることができ、3 つを組み合わせて含めることはできません）
* キャンペーンのフライト期間（`start_time` と `end_time`）が、予約ツイートの `scheduled_at` 時刻と一致していることを確認してください
* 予約ツイートは、1 年（365 日）以上先の日時には予約しないでください
* 現在、予約ツイートに対するツイートプレビュー機能はサポートされていません（作成前に予約ツイートをプレビューする機能を指します）

### メディアライブラリ

<div id="introduction">
  #### はじめに
</div>

Media Library エンドポイントでは、X 広告アカウントで使用する画像、GIF、動画を管理できます。ライブラリ内のメディアアセットは、ツイートやカードの作成に利用できます。また、同じアセットを何度もアップロードする必要がないよう、複数の[クリエイティブ](https://developer.x.com/content/developer-twitter/en/docs/ads/creatives/overview)で再利用することも可能です。

<div id="api-endpoints">
  #### API エンドポイント
</div>

* [POST media/upload](https://developer.x.com/content/developer-twitter/en/docs/media/upload-media/api-reference/post-media-upload#post-media-upload) または [POST media/upload (chunked)](https://developer.x.com/content/developer-twitter/en/docs/media/upload-media/api-reference/post-media-upload-init#post-media-upload-init)（メディアをアップロードする）
* [POST accounts/:account&#95;id/media&#95;library](https://developer.x.com/x-ads-api/creatives#get-accounts-account-id-media-library#post-accounts-account-id-media-library)（メディアを Media Library に追加する）

<div id="adding-to-the-library">

</div>

メディアをライブラリに追加する処理は 2 段階で行われます。まず、[POST media/upload](https://developer.x.com/content/developer-twitter/en/docs/media/upload-media/api-reference/post-media-upload#post-media-upload) エンドポイント、または [POST media/upload (chunked)](https://developer.x.com/content/developer-twitter/en/docs/media/upload-media/api-reference/post-media-upload-init#post-media-upload-init) の一連のエンドポイントのいずれかを使用してアセットをアップロードします。マルチパートアップロード処理の詳細については、[Chunked media upload](https://developer.x.com/content/developer-twitter/en/docs/media/upload-media/uploading-media/chunked-media-upload) ガイドを参照してください。


<div id="request-parameters">
  #### リクエストパラメーター
</div>

すべての Media Library の POST リクエストにはメディア識別子が必要です。この値はアップロード時に返されます。上記の例のように `media_id` を使用する場合は、`media_category` も指定する必要があります。使用可能なカテゴリ値は 4 種類あり、`AMPLIFY_VIDEO`、`TWEET_GIF`、`TWEET_IMAGE`、`TWEET_VIDEO` です。

Media Library 内のオブジェクトには、オプションで `name` と `file_name` の値を設定できます。これらの属性は、ライブラリ内でメディアのバリエーションを区別するのに役立ちます。

動画の場合は、`title` と説明文を設定することもできます。これらの値は、[POST accounts/:account&#95;id/tweet](https://developer.x.com/content/developer-twitter/en/docs/ads/creatives/api-reference/tweets#post-accounts-account-id-tweet) エンドポイントで `video_title` および `video_description` リクエストパラメーターとして渡すことを想定しています。ツイート内では、このテキストは動画の下に表示されます。

<div id="attributes">
  #### Attributes
</div>

Media Library では、media&#95;key という概念が正式に導入されています。これはライブラリ内のオブジェクトを一意に識別するための識別子です。メディアキーは次の形式の文字列値です: 13&#95;875943225764098048。これらはすべてのカードエンドポイントで完全にサポートされています。

さらに、Media Library のレスポンスには media&#95;id も文字列として含まれます。これは現在 media key を受け付けないリソース、つまり [ツイート](https://developer.x.com/content/developer-twitter/en/docs/ads/creatives/api-reference/tweets#post-accounts-account-id-tweet)*、[ツイートプレビュー](https://developer.x.com/content/developer-twitter/en/docs/ads/creatives/api-reference/tweets#get-accounts-account-id-tweet-preview)*、および[予約ツイート](https://developer.x.com/content/developer-twitter/en/docs/ads/creatives/api-reference/scheduled-tweets#post-accounts-account-id-scheduled-tweets)向けに含まれています。すべての箇所で media key をサポートできるよう、現在対応を進めています。

aspect&#95;ratio 属性は GIF と動画に対して返されます。これは、特定のアスペクト比のみを受け付けるカードで使用するメディアをフィルタリングするために利用できます。

*これらのエンドポイントは、media key である video&#95;id パラメータをサポートしています。

<div id="identifying-cards">
  ### Card の識別
</div>

<div id="introduction">
  #### はじめに
</div>

カードは、メディアを利用するカスタマイズ可能な広告フォーマットで、ウェブサイトやアプリ、あるいはダイレクトメッセージ開始などの特定のユーザーエンゲージメントを促すコールトゥアクションと関連付けることができます。カードは、ツイート、予約投稿ツイート、または下書きツイートに添付できます。

Tweet オブジェクトでは、カードは 2 通りのいずれかの方法で参照されます。`card_uri` か `preview_url` のいずれかです。各値の例を以下に示します。

| card&#95;uri | preview&#95;url |
| :--- | :--- |
| card://1043282691834048513 | https://cards.x.com/cards/18ce54d4x5t/68w3s |

**注**: Ads API バージョン 3 以降、新しく作成されたカードについては `card_uri` のみが生成され、cards レスポンスで返されます。

**注**: Ads API バージョン 5 以降、cards レスポンスには `preview_url` は返されません。

Tweet オブジェクトのレスポンス内でどちらの参照タイプが使われるかは、そのツイートがどのように作成されたかによって決まります。言い換えると、`card_uri` リクエストパラメーターを使用してツイートが作成された場合、レスポンスには card URI の値が表示されます。一方で、ツイート本文の一部として `preview_url` が含まれていた場合、レスポンスにはプレビュー URL が表示されます。

<div id="identifying-media">
  ### メディアの特定
</div>

<div id="introduction">
  #### はじめに
</div>

画像、GIF、動画といったメディアは、ツイートやカードに追加できます。さらに、動画はプレロール用アセットとして利用でき、画像は [X Audience Platform](https://developer.x.com/en/docs/ads/measurement/overview/twitter-audience-platform) でプロモーションすることも可能です。本セクションでは、これらのエンティティ間でメディア参照を特定する方法について説明します。

メディア識別子には ID とキーの 2 種類があります。それぞれの例は以下のとおりです。

| **メディア ID** | **メディアキー** |
| :--- | :--- |
| 1029825579531807971 | 13&#95;1029825579531807971 |

メディアキーは、ID の先頭に数値のプレフィックスとアンダースコアを付加したものです。

<div id="image">
  #### 画像
</div>

次の表は、各画像関連リソースのレスポンスで現在利用可能な識別子のタイプと、それに対応する属性名を示しています。

| **Resource** | **Identifier** | **Attribute(s)** |
| :--- | :--- | :--- |
| Image cards | なし |  |
| Tweet | 両方 | `entities["media"]["id_str"]`  `entities["media"]["media_key"]` |
| Scheduled Tweet | 両方 | `media_ids` and `media_keys` |
| Draft Tweet | 両方 | `media_ids` and `media_keys` |
| Account Media | なし |  |
| Media Library | 両方 | `media_id` and `media_key` |

Image cards と Account Media の画像には、いかなるメディア識別子への参照も一切含まれていません。ツイートにはメディアIDのみが含まれます。Scheduled ツイートと Draft ツイートには、メディアIDとメディアキーの両方が含まれます。Media Library も同様に両方を返します。

ツイートの場合、entities[&quot;media&quot;] 配列内のオブジェクトにある id および id&#95;str フィールドは、メディアIDに対応します。ツイートに複数の画像が含まれている場合、それぞれのメディアエンティティへの参照は extended&#95;entities[&quot;media&quot;] 内でのみ取得できます。

識別子への参照に加えて、画像の URL へアクセスできることも重要な場合がよくあります。

| **Resource** | **Attribute(s)** | **Format** |
| :--- | :--- | :--- |
| Image cards | `image` | .jpg |
| Tweet* | `entities["media"][0]["media_url"]` or `extended_entities["media"][i]["media_url"]` | .jpg |
| Scheduled Tweet | なし |  |
| Draft Tweet | なし |  |
| Account Media | `media_url` | .jpg |
| Media Library | `media_url` | .jpg |

* この URL の位置は、ツイートに含まれる画像が単一か複数かによって異なります。

すべての Image cards には、X の画像 URL を含む image レスポンス属性が存在します（image app download cards の場合、この属性名は wide&#95;app&#95;image です）。

ツイートの場合、メディア URL の位置は、メディアのタイプと使用しているエンドポイントの両方に依存します。画像が1枚だけのツイートでは、URL は entities[&quot;media&quot;][0][&quot;media&#95;url&quot;] にあります。これは Ads API と Standard API の両方で同様です。一方、ツイートに複数の画像が含まれている場合、URL は extended&#95;entities[&quot;media&quot;][i][&quot;media&#95;url&quot;] 内でのみ取得できます。これは Standard API でのみ利用可能です。

<div id="video">
  #### 動画
</div>

次の表は、各動画関連リソースのレスポンスで現在利用可能な識別子のタイプと、それに対応する属性名を示しています。

| **Resource** | **Identifier** | **Attribute(s)** |
| :--- | :--- | :--- |
| 動画カード | どちらか一方 | `video_content_id` |
| 動画付き投票カード | なし |  |
| ツイート | 両方 | `entities["media"]["id_str"]`  `entities["media"]["media_key"]` |
| スケジュール済みツイート | 両方 | `media_ids` と `media_keys` |
| 下書きツイート | 両方 | `media_ids` と `media_keys` |
| アカウントメディア | メディアキー | `video_id` |
| メディアライブラリ | 両方 | `media_id` と `media_key` |

動画カード（動画付き投票カードを除く）には `video_content_id` レスポンス属性が含まれますが、返される値のタイプに一貫性がありません。メディア ID が返される場合もあれば、メディアキーが返される場合もあります。

動画の URL へのアクセス方法は、以下のとおりです。

| **Resource** | **Attribute(s)** | **Format** |
| :--- | :--- | :--- |
| 動画カード | `video_url` と `video_hls_url` | .vmap  .m3u8 |
| 動画付きツイート | `extended_entities["media"][i]["video_info"]["variants"][j]["url"]` | .mp4 |
| スケジュール済みツイート | なし |  |
| 下書きツイート | なし |  |
| アカウントメディア | なし |  |
| メディアライブラリ | `media_url` | .mp4 |

動画カードには `video_url` および `video_hls_url` レスポンス属性が含まれ、それぞれ .vmap および .m3u8 の URL を返します。

<div id="media-library">
  #### Media Library
</div>

メディアアセットに関する追加情報を取得する必要が生じることがあります。ユースケースの 1 つとして、ビデオカードで vmap URL ではなく mp4 URL を取得したい場合があります。これは Media Library から取得できます。利用可能な情報の詳細については、[Media Library Guide](https://developer.x.com/content/developer-twitter/en/docs/ads/creatives/guides/media-library) を参照してください。広告アカウントの FULL promotable user に属するほとんどのアセットはライブラリ内にありますが、いくつか例外もあります。

**メディアの取得**

前述のとおり、画像カードには media ID や media key への参照が含まれていません。その結果、Media Library 経由でこれらのアセットを取得することはできません。これは [Account Media](https://developer.x.com/content/developer-twitter/en/docs/ads/creatives/api-reference/account-media#account-media) の画像についても同様です。

ビデオカードでは、作成前にビデオアセットが Media Library（もしくはその前身である Videos リソース）の一部である必要があります。そのため、これらのアセットは常に Media Library から取得可能です。これは Account Media の PREROLL アセットについても同様です。

最後に、ツイート内のメディアは必ず Media Library 内に存在することが保証されています。

以下の表は、リソースのレスポンスにルックアップに使用する識別子が含まれているかどうかを考慮しつつ、Media Library からどのアセットを取得できるかをまとめたものです。

| **Resource** | **In the Media Library** |
| :--- | :--- |
| Image cards | No |
| Video cards | Yes* |
| Tweets (any media)** | Yes |
| Scheduled Tweets | Yes |
| Draft Tweets | Yes |
| Account media images | No |
| Account media videos (`PREROLL`) | Yes |

* `video_content_id` が media key であるカードの場合。値が media ID の場合でもアセット自体は Media Library に存在しますが、取得するにはその値に数値のプレフィックスとアンダースコアを付加する必要があります。
** ツイートは media ID のみを返します。アセットが Media Library に存在することは保証されていますが、取得には media ID に数値のプレフィックスとアンダースコアを付加する必要があります。

**Account Media との連携**

Media Library に追加されたメディアアセットが自動的に Account Media リソースにも追加されるケースが 2 つあります。

* AMPLIFY&#95;VIDEO アセットが Media Library に追加されると、自動的に PREROLL クリエイティブタイプの Account Media アセットとして追加されます。
* 特定の寸法（[enumerations ページ](https://developer.x.com/content/developer-twitter/en/docs/ads/general/overview/enums) の「Creative Types」を参照）を持つ画像が Media Library に追加されると、自動的に Account Media アセットとして追加されます。クリエイティブタイプ（例: INTERSTITIAL）は画像の寸法によって決まります。

<div id="tweets">
  ### ツイート
</div>

<div id="introduction">
  #### はじめに
</div>

X Ads API は、公開済み、予約投稿、下書きの 3 種類のツイートをサポートしています。

<div id="nullcasted-tweets">
  #### Nullcasted ツイート
</div>

ツイートは、nullcast（「Promoted-only」とも呼ばれます）かオーガニックのいずれかになります。Nullcasted ツイートは、公開されてもユーザーの公開タイムラインには表示されませんが、ツイート自体は公開ツイートです。一方、オーガニックツイートはユーザーのフォロワーに配信され、ユーザーの公開タイムラインにも表示されます。

**ツイートの作成**

3 つのツイート作成エンドポイントそれぞれは、ツイートを nullcasted にするかオーガニックにするかを選択できる Boolean 型の `nullcast` パラメータをサポートしています。Nullcasted ツイートは、そのユーザー本人、またはそのユーザーの代理としてツイートを作成する権限を持つ他のユーザーによって作成できます。オーガニックツイートを作成できるのは、[full promotable user](https://developer.x.com/content/developer-twitter/en/docs/tutorials/ads-api-hierarchy-terminology#promotable-users) のみです。

**ツイートの更新**

予約済みツイートおよび下書きツイートについては、`nullcast` プロパティを更新できます。予約済みツイートの場合、ツイートの `scheduled_at` 時刻まで編集が可能です。下書きツイートは、無期限に編集できます。ただし一度公開されると、そのツイートを nullcasted からオーガニックへ、あるいはその逆へ変更することはできません。

<div id="promoting-tweets">
  #### ツイートのプロモーション
</div>

プロモーションできるのは、公開済みまたは予約済みのツイートのみです。これらは nullcast されたものでもオーガニックなものでも構いません。制限はありません。広告主は、自身のツイートだけでなく、許可を得ている場合は他のユーザーのツイートもプロモーションできます。（詳細は「[Promoting another user&#39;s Tweets](https://developer.x.com/content/developer-twitter/en/docs/tutorials/promoting-another-users-content)」を参照してください。）

1つのキャンペーン内で複数のツイートをプロモーションできます。同様に、1つのツイートを1つ以上のキャンペーンでプロモーションすることも可能です。

公開済みツイートをプロモーションするには、[POST accounts/:account&#95;id/promoted&#95;tweets エンドポイント](https://developer.x.com/content/developer-twitter/en/docs/ads/campaign-management/api-reference/promoted-tweets#post-accounts-account-id-promoted-tweets)を使用します。これにより、公開済みツイートがラインアイテムに関連付けられます。予約済みツイートをプロモーションするには、[POST accounts/:account&#95;id/scheduled&#95;promoted&#95;tweets](https://developer.x.com/content/developer-twitter/en/docs/ads/campaign-management/api-reference/scheduled-promoted-tweets#post-accounts-account-id-scheduled-promoted-tweets) エンドポイントを使用します。

<div id="tweet-ids">

</div>

公開済み、予約済み、および下書きのツイートIDは[数値](https://developer.x.com/content/developer-twitter/en/docs/basics/twitter-ids)であり、64ビット符号なし整数です。たとえば、次の公開済みツイートのIDは 1166476031668015104 です。

<div id="carousels">
  ### カルーセル
</div>

#### 概要

X Ads API は、動画カルーセルおよび画像カルーセルの作成と取得をサポートしています。カルーセルは、2〜6 個のメディアアセットを含めることができるカードタイプです。カルーセルカードは、ユーザーをウェブサイトに誘導したり、モバイルアプリのインストールを促したりできます。カルーセルの概要、利点、ベストプラクティス、FAQ については、[Carousel Ads on X](https://business.x.com/en/advertising/carousels.html) ページを参照してください。

カルーセルは、他のカードタイプと同様に投稿内で使用でき、これらの投稿をプロモーションできます。ワークフローは、これまでどおりです。

1. メディアをアップロードする
2. カードを作成する
3. 投稿を作成する
4. 投稿をプロモーションする

唯一の違いは、カードの作成方法です。他のカード作成リクエストがクエリパラメータを受け付けるのに対して、カルーセルカード作成リクエストは JSON POST ボディのみを受け付けます。

<div id="endpoints">
  #### エンドポイント
</div>

Ads API ではカルーセルの作成と取得がサポートされています。

あらゆるタイプのカルーセルを作成するには、[POST accounts/:account&#95;id/cards](https://developer.x.com/en/docs/twitter-ads-api/creatives/api-reference/cards#post-accounts-account-id-cards) エンドポイントを使用します。カルーセルを取得するには、[GET accounts/:account&#95;id/cards](https://developer.x.com/en/docs/twitter-ads-api/creatives/api-reference/cards#get-accounts-account-id-cards) エンドポイントを使用します。

<div id="json-post-body">
  #### JSON POST Body
</div>

カルーセルは 2 つのコンポーネントから構成されます。1 つ目は使用するメディアアセットを指定するコンポーネントです。2 つ目はウェブサイトまたはアプリに関する情報を指定するコンポーネントです。

具体的には、カルーセルカードは次のコンポーネントを、この順番で組み合わせて作成します。

* メディアキーの配列を受け取る `SWIPEABLE_MEDIA` コンポーネントが 1 つ
* 次のいずれか *1 つ*：
  * ウェブサイト情報を指定するための `DETAILS` コンポーネント
  * アプリ情報を指定するための `BUTTON` コンポーネント

`SWIPEABLE_MEDIA` コンポーネントには `media_keys` 配列を含める必要があり、その中で 2〜6 個の画像または動画を指定できます。渡したメディアキーの順序によって、表示される順序が決まります。

```
{
  "type": "SWIPEABLE_MEDIA",
  "media_keys": [
    "13_1089771253848666112",
    "13_1191948012077092867"
  ]
}
```

念のため、[GET accounts/:account&#95;id/media&#95;library](https://developer.x.com/en/docs/twitter-ads-api/creatives/api-reference/media-library#get-accounts-account-id-media-library) エンドポイントにリクエストを送信することで、メディアキーを取得できます。

2 つ目のコンポーネントオブジェクトの構成は、ユーザーをウェブサイトに誘導したいのか、アプリのインストールを促したいのかによって変わります。以下の表は、この 2 つのオプションをまとめたものです。（**注記**: 記載されているキーはすべて必須です。）

|               | **ウェブサイト**                                                         | **アプリ**                                           |
| :------------ | :----------------------------------------------------------------- | :------------------------------------------------ |
| コンポーネントのタイプ指定 | `"type": "DETAILS"`                                                | `"type": "BUTTON"`                                |
| タイトル/ラベル      | `"title": "X"`                                                     | `"label": { "type": "ENUM", "value": "INSTALL" }` |
| 遷移先           | `"destination": { "type": "WEBSITE", "url": "https://www.x.com" }` | `"destination": { "type": "APP", ... }`           |

これらを踏まえると、ウェブサイトカルーセル用の JSON POST リクエストボディの例は次のとおりです。

```
{
  "name": "website carousel",
  "components": [
    {
      "type": "SWIPEABLE_MEDIA",
      "media_keys": [
        "13_1089771253848666112",
        "13_1191948012077092867"
      ]
    },
    {
      "type": "DETAILS",
      "title": "X",
      "destination": {
        "type": "WEBSITE",
        "url": "https://www.x.com"
      }
    }
  ]
}
```

`BUTTON` コンポーネント内のアプリ遷移先オブジェクトには、国コードと少なくとも 1 つのアプリ識別子が必要です。オプションでディープリンクを指定できます。これらのフィールドの説明については、[リファレンスドキュメント](https://developer.x.com/en/docs/twitter-ads-api/creatives/api-reference/cards#app-destination)を参照してください。

これらを踏まえたアプリカルーセル用の JSON POST ボディの例を、以下に示します。

```
{
  "name": "app carousel",
  "components": [
    {
      "type": "SWIPEABLE_MEDIA",
      "media_keys": [
        "13_1089771253848666112",
        "13_1191948012077092867"
      ]
    },
    {
      "type": "BUTTON",
      "label": {
        "type": "ENUM",
        "value": "INSTALL"
      },
      "destination": {
        "type": "APP",
        "country_code": "US",
        "googleplay_app_id": "com.twitter.android",
        "iphone_app_id": "333903271"
      }
    }
  ]
}
```

<div id="creative-metadata-tagging">
  ### クリエイティブ・メタデータのタグ付け
</div>

<div id="introduction">
  #### はじめに
</div>

このガイドは、クリエイティブパートナー、代理店、およびクリエイティブ開発者が、X キャンペーン内で使用されるアセットにタグ付けして、各アセットの価値とパフォーマンスをより正確に把握できるようにするためのものです。

**注:** メディアアセットにタグ付けできるのは、そのメディアアセットを作成したパートナーまたは開発者のみです。メディアアセットの利用者がそのメディアアセットを作成していない場合は、メタデータのタグ付けを行わないでください。

Creative Metadata Tagging を使用すると、クリエイティブパートナーによって作成された画像および動画に対して、そのアセットが X 上のどこにアップロードされる場合でも、またどのような主体がアセットをアップロードする場合でも、アトリビューション（帰属情報）を付与できます。クリエイティブアセットとクリエイティブパートナーを関連付けるために、[XMP](https://exiftool.org/TagNames/XMP.html) 標準を使用します。

<div id="tagging-creative-assets">
  #### クリエイティブアセットへのタグ付け
</div>

次の表は、各画像関連リソースのレスポンスで現在利用可能な識別子タイプと、その識別子に対応する属性名を示しています。クリエイティブアセットにタグ付けするにはタグ付けツールが必要です。[ExifTool](https://exiftool.org/) は、メタ情報の読み取り、書き込み、編集を行うための、プラットフォーム非依存の Perl ライブラリおよび [コマンドラインアプリケーション](https://exiftool.org/exiftool_pod.html) であり、推奨ツールです。サポートされているすべての [ファイルタイプ](https://exiftool.org/#supported) を参照してください。

[ExifTool のインストール手順](https://exiftool.org/install.html) に従ってください。[Homebrew](https://formulae.brew.sh/) が提供するソフトウェアパッケージもあり、macOS および Linux 向けの [exiftool インストールコマンド](https://formulae.brew.sh/formula/exiftool) を提供することで、インストールをさらに簡単にできます。コマンドラインで `exiftool -ver` と入力し、このツールのバージョン番号が返されることを確認して、ツールが正しくインストールされていることを確認してください。ExifTool のコマンドパラメータについて詳しくは、[ExifTool ドキュメント](https://exiftool.org/) を参照してください。

クリエイティブパートナーは、新規または既存のクリエイティブアセットに対し、自身の X app&#95;id を contributor XMP タグおよび date タグのメタデータとして付与できます。クリエイティブアセットには、[メディアのアップロード](https://developer.x.com/en/docs/twitter-api/v1/media/upload-media/overview) 時の既存のサイズ制限が適用されます。 

**注:** X で contributor XMP タグを使用することにより、メタデータでは X 上のキャンペーン専用の値のみが取得されるようになります。

`exiftool -contributor="<YOUR APP ID>" -creative_file.jpg`

`exiftool -date="<date>" -creative_file.jpg`

app&#95;id は、[Developer Console](https://developer.x.com/en/portal/dashboard) の Projects &amp; Apps 内で確認できます。例: 16489123

次の例では、画像に対して app&#95;id を contributor タグとして、date を date タグとして追加しています。

```
app_id:858382169
```

```
date:2022-03-13
```

```
creative_file: eiffel_tower.jpg
```

```
exiftool -contributor=858382169 eiffel_tower.jpg
```

```
   1 image files updated
```

```
exiftool -date=2022-03-13 eiffel_tower.jpg
```

```
  1 image files updated
```

画像に正しくタグが付いていることを確認してください: 

`exiftool -xmp:all -G1 <filename>`

例:

`exiftool -xmp:all -G1 eiffel_tower.jpg`

```
[XMP]        XMP Toolkit            : Image::ExifTool 12.30
```

```
[XMP]        Contributor            : 858382169
```

```
[XMP]        Date                   : 2022:03:13
```

<div id="post-accountsaccount_idcards">
  #### POST accounts/:account_id/cards
</div>

指定されたアカウントに紐づく新しいカードを作成します。

カード作成リクエストでは、JSON の POST ボディのみが受け付けられます。`Content-Type` は `application/json` に設定する必要があります。

詳細な利用例については、[Carousels Guide](https://developer.x.com/en/docs/twitter-ads-api/creatives/guides/carousels) を参照してください。

#### リソースURL

`https://ads-api.x.com/12/accounts/:account_id/cards`

#### パラメーター

POST リクエストの JSON 本文には、カードの `name` と `components` の配列を含めなければなりません。コンポーネントはオブジェクトとして表現され、カードの広告主向けの属性を記述します。

次の例は、ペイロードの一般的な構造を示したものであり、実際には動作しない情報が含まれています。

```
{
  "name": "some name",
  "components": [
    {
      "type": "TYPE_ENUM",
      "key": "value"
    }
  ]
}
```

コンポーネントに関する追加情報は以下のとおりです。

| 名前                     | 説明                                                                                                                                                                                                                                                     |
| :--------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| account&#95;id   *必須*  | 利用するアカウントの識別子です。リソースのパス内に現れ、[GET accounts](https://developer.x.com/en/docs/ads/campaign-management/api-reference/accounts#get-accounts) を除くすべての Advertiser API リクエストで一般的に必須パラメーターです。指定されたアカウントは認証済みユーザーに関連付けられている必要があります。  タイプ: 文字列型  例: `18ce54d4x5t` |
| name   *必須*            | カードの名前です。最大長: 80 文字。  タイプ: 文字列型  例: `component based card`                                                                                                                                                                                             |
| components   *場合により必須* | カードを作成するために使用するコンポーネントを記述します。詳細は下記を参照してください。`slides` と同時には指定できません。  **注**: コンポーネントの順序は重要です。  タイプ: オブジェクトの配列                                                                                                                                            |
| slides   *場合により必須*     | Multi-Destination Carousels を作成するためにこの配列の配列を使用します。各カードをコンポーネントのグループとして記述します。各スライドはカードを完全に表現している必要があります。`components` と同時には指定できません。  **注**: 各スライドの順序は重要です。  タイプ: 配列の配列                                                                                   |

<div id="components">
  #### コンポーネント
</div>

すべてのコンポーネントには、オブジェクトのスキーマを決定する `type` フィールドを含める必要があります。Ads API は、メディアベースおよび説明ベースのコンポーネントに分類される、次のコンポーネントのタイプをサポートします。

* メディア:
* `MEDIA`: 単一の動画または画像
* `SWIPEABLE_MEDIA`: 2〜6 個の動画または画像
* 説明:
* `DETAILS`
* `BUTTON`

各コンポーネントには（`type` キーに加えて）必須フィールドのセットがあります。これらは次の表に一覧されています。

| Component `type`  | Field                   | Value type      |
| :---------------- | :---------------------- | :-------------- |
| `MEDIA`           | `media_key`             | 文字列型            |
| `SWIPEABLE_MEDIA` | `media_keys`            | 文字列型の配列         |
| `DETAILS`         | `title`   `destination` | 文字列型   オブジェクト   |
| `BUTTON`          | `label`   `destination` | オブジェクト   オブジェクト |

以下は、`components` 配列内での `BUTTON` コンポーネントの例です（意図的に `name` キーを省略しています）。（省略記号は、追加の情報を指定する必要がある箇所を示しています。）

```
{
  "components": [
    {
      "type": "BUTTON",
      "label": {
        ...
      },
      "destination": {
        ...
      }
    }
  ]
}
```

コンポーネントオブジェクトを指定する順序によって、レンダリングされる際の上から下への順番が決まります。カードは 1 つのメディアベースのコンポーネントと、`DETAILS` コンポーネントまたは `BUTTON` コンポーネントのいずれかを組み合わせて作成する必要があります。説明ベースのコンポーネントはメディアの下にレンダリングされ、URL もしくはモバイルアプリのいずれかを遷移先として持ちます。

**Label**

Label はボタンに表示されるテキストを定義するため、`BUTTON` コンポーネントにのみ適用されます。Label オブジェクトには 2 つの必須キー `type` と `value` があります。`type` は `ENUM` に設定する必要があり、`value` には `BOOK`、`CONNECT`、`INSTALL`、`OPEN`、`ORDER`、`PLAY`、`SHOP` のいずれかを指定できます。

前の例を基に、次のコードは `BUTTON` コンポーネント内の `label` オブジェクトを示しています。

```
{
  "components": [
    {
      "type": "BUTTON",
      "label": {
        "type": "ENUM",
        "value": "INSTALL"
      },
      "destination": {
        ...
      }
    }
  ]
}
```

**宛先**

宛先は、広告主がユーザーを誘導しようとする先です。宛先は `DETAILS` または `BUTTON` コンポーネント内で常に必須です。宛先のタイプは `WEBSITE` と `APP` の 2 種類があります。

**注**: Website 宛先は `DETAILS` コンポーネントでのみ使用でき、App 宛先は `BUTTON` コンポーネントでのみ使用できます。

**Website 宛先**

| 名前          | 説明                                                                                     |
| :---------- | :------------------------------------------------------------------------------------- |
| type   *必須* | 宛先のタイプであり、そのスキーマを決定します。  タイプ: enum  取りうる値: `WEBSITE`                                   |
| url   *必須*  | ユーザーをリダイレクトするウェブサイトの URL。  タイプ: 文字列型  例: `https://devcommunity.x.com/c/advertiser-api` |

**App 宛先**

| 名前                                               | 説明                                                                                                                                          |
| :----------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------ |
| type   *必須*                                      | 宛先のタイプであり、そのスキーマを決定します。  タイプ: enum  取りうる値: `APP`                                                                                            |
| country&#95;code   *必須*                          | アプリが販売されている国を示す、[ISO 3166-1 alpha-2](https://en.wikipedia.org/wiki/ISO_3166-1_alpha-2) に基づく 2 文字の国コード。  タイプ: 文字列型  例: `US`                  |
| googleplay&#95;app&#95;id   *場合により必須*            | Google Play アプリケーションのパッケージ名。  **注**: `ios_app_store_identifier` または `googleplay_app_id` の少なくとも一方が必須です。  タイプ: 文字列型  例: `com.twitter.android` |
| ios&#95;app&#95;store&#95;identifier   *場合により必須* | iOS App Store の識別子。  **注**: `ios_app_store_identifier` または `googleplay_app_id` の少なくとも一方が必須です。  タイプ: 文字列型  例: `333903271`                    |
| googleplay&#95;deep&#95;link   *任意*              | プロモーション対象の Android アプリへのディープリンク。  **注**: `googleplay_app_id` が指定されている場合にのみ使用できます。  タイプ: 文字列型                                                |
| ios&#95;deep&#95;link   *任意*                     | プロモーション対象の iOS アプリへのディープリンク。  **注**: `ios_app_store_identifier` が指定されている場合にのみ使用できます。  タイプ: 文字列型                                             |

  #### POST accounts/:account_id/tweet
</div>

このエンドポイントは、アカウントのフルプロモータブルユーザー（デフォルト）または `as_user_id` パラメーターで指定したユーザーのツイートを作成します。nullcast（デフォルト）およびオーガニックのツイート作成の両方がサポートされています。nullcast ツイートは公開タイムラインに表示されず、フォロワーにも配信されません。どちらのタイプもキャンペーンで使用できます。

認証済みユーザーがこのアカウントの `FULL` プロモータブルユーザーでない場合は、[GET accounts/:account&#95;id/authenticated&#95;user&#95;access](https://developer.x.com/en/docs/ads/campaign-management/api-reference/authenticated-user-access#get-accounts-account-id-authenticated-user-access) エンドポイントにリクエストを送信し、そのユーザーの代理でツイートする権限があるかどうかを確認してください。`TWEET_COMPOSER` 権限がある場合、そのユーザーはこのエンドポイントを使用して、`FULL` [プロモータブルユーザー](https://developer.x.com/en/docs/ads/campaign-management/api-reference/promotable-users#get-accounts-account-id-promotable-users) の代理で nullcast ツイートを作成できます。

メディアに対して [upload.x.com エンドポイント](https://developer.x.com/rest/reference/post/media/upload) を使用する場合、このエンドポイントに渡す `as_user_id` の値と同じ `user_id` の値を、`additional_owners` パラメーターに指定してください。
