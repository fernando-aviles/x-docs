<div id="overview">
  ## 概要
</div>

クリエイティブとは、キャンペーン内でプロモーション可能なあらゆるエンティティを指します。投稿にはテキスト、画像、GIF、動画、またはカードを含めることができます。カードには画像または動画を含めることができます。

画像、GIF、または動画のクリエイティブは、[POST media/upload](/ja/x-api/media/upload-media#post-media-upload)（画像のみをサポートするシンプルなアップロードエンドポイント）か、POST media/upload (chunked) エンドポイントのいずれかを使用してアップロードします。これらは次のリソースに追加できます。

カード:

* POST accounts/:account&#95;id/cards
  ツイート:
* POST accounts/:account&#95;id/tweets - ツイートにカードを追加するには、card&#95;uri パラメータを使用します。
  予約ツイート:
* POST accounts/:account&#95;id/scheduled&#95;tweets

カードの詳細については、Cards ページを参照してください。Promoted Video ページでは、カードまたはツイートに動画を関連付ける方法の詳細を確認できます。

<div id="cards">
  ### Cards
</div>

Ads API では、キャンペーンでプロモーションできるツイート内で使用可能な複数のカードタイプをサポートしています。**注**: いったんツイートされると、カードの詳細は一般に公開されます。これには、そのカードを所有するユーザーに関する情報が含まれる場合があります。

<div id="image">
  #### 画像
</div>

以下の画像仕様は、[Cards](/ja/x-ads-api/creatives#cards-2) で使用されるアセットに適用されます。画像は 3MB 以下で、幅が 800px 以上である必要があります。また、次のアスペクト比（横:縦）をサポートします。

* Website: 1:1 および 1.91:1
* Image App Download: 1:1 および 1.91:1
* Poll: 1.91:1
* Image Conversation: 1.91:1
* Image Direct Message: 1.91:1

サポートされる画像形式は .bmp、.jpeg、.png です。

<div id="video">
  #### 動画
</div>

以下の動画仕様は、[Cards](/ja/x-ads-api/creatives#cards-2)で使用されるアセットに適用されます。サポートされる横:縦のアスペクト比は次のとおりです。

* Video Website: 16:9 および 1:1
* Video App Download: 16:9 および 1:1
* Poll: 16:9
* Video Conversation: 16:9
* Video Direct Message: 16:9

<div id="promoted-video">
  ### プロモ動画
</div>

このドキュメントでは、Ads API を使用して動画をアップロードし、プロモーションするプロセスの概要を簡潔に説明します。

Ads API は、[ツイート](/ja/x-ads-api/creatives#tweets-2) 内のプロモ動画および次のカードでのプロモ動画をサポートしています。

* [Video Website](https://devcommunity.x.com/t/ads-api-version-11/168814)
* [Video App Download](https://devcommunity.x.com/t/ads-api-version-11/168814)
* [Video Conversation](/ja/x-ads-api/creatives#video-conversation-cards)

まず、[POST media/upload (chunked)](https://developer.x.com/en/docs/media/upload-media/api-reference/post-media-upload-init.html) エンドポイントを使用して動画をアップロードします。`media_id` を使用して、POST accounts/:account&#95;id/videos エンドポイント経由で動画を広告アカウントに関連付けます。動画の `id` は `media_key` と呼ばれることもあり、その後のリクエストで使用されます。これは、整数で始まり、その後にアンダースコアが続き、最後に大きな数値（long 値）が続く文字列型です。例として、`13_875943225764098048` のようになります。

<div id="promoted-video-in-tweets">
  #### ツイートでのプロモ動画
</div>

ツイートを作成するには、動画の `id` と合わせて [POST accounts/:account&#95;id/tweet](/ja/x-ads-api/creatives#get-accounts-account-id-tweets) エンドポイントを使用します。この段階で、動画のタイトル、説明文、CTA（行動喚起）も指定できます。これらの値はユーザーにそのまま表示されます。

<div id="promoted-video-in-cards">
  #### カードでのプロモーション動画
</div>

Video App Download カードと Video Conversation カードでは、ポスター画像を追加できます。これらのカードで使用する画像は、[POST media/upload](https://developer.x.com/en/docs/media/upload-media/api-reference/post-media-upload.html) エンドポイントを使用してアップロードします。

次のいずれかのエンドポイントを使用してカードを作成します。

* [POST accounts/:account&#95;id/cards/video&#95;website](https://devcommunity.x.com/t/ads-api-version-11/168814)
* [POST accounts/:account&#95;id/cards/video&#95;app&#95;download](https://devcommunity.x.com/t/ads-api-version-11/168814)
* [POST accounts/:account&#95;id/cards/video&#95;conversation](https://devcommunity.x.com/t/ads-api-version-11/168814)

動画の `id` と、必要に応じて画像の `media_id`（ポスター画像用）を使用します。

最後に、POST accounts/:account&#95;id/tweet エンドポイントを使用してツイートを作成します。カードは `card_uri` パラメータを使用してツイートに添付されます。

<div id="general-information">
  #### 一般情報
</div>

API 経由での動画アップロードに関する詳細な手順については、[Video Upload Guide](https://developer.x.com/en/docs/media/upload-media/uploading-media.html) を参照してください。

動画はプレロール用アセットとしてプロモーションすることもできます。詳細な説明については [Video Views Pre-roll Objective Guide](/ja/x-ads-api/campaign-management#video-views-preroll-objective) を参照してください。

* （2015-10-22 時点）プロモーションコンテンツで使用する動画をアップロードする場合、[POST media/upload (chunked)](https://developer.x.com/en/docs/media/upload-media/api-reference/post-media-upload-init.html) エンドポイントへのすべての `INIT` コマンドリクエストで、`media_category` パラメータに `amplify_video` の値を設定する必要があります。この新しいパラメータを使用すると、動画が非同期で事前処理され、プロモーションコンテンツで使用できるように準備されます。動画アップロード後の非同期処理の完了確認には `STATUS` コマンドを使用できます。
* 現在許可されているプロモーション動画の最大長は 10 分で、ファイルサイズは 500MB 以下です。
* アップロードされる動画は mp4 または mov 形式である必要があります。
* アップロードされた動画は通常、短時間で処理されますが、処理時間は動画の長さやファイルサイズによって変動します。
* アップロードされるポスター画像は png または jpg 形式である必要があります。アスペクト比やサイズの要件はありませんが、ポスター画像は動画プレーヤーに合わせて自動的に調整されます。

<div id="scheduled-tweets">
  ### 予約ツイート
</div>

<div id="introduction">
  #### はじめに
</div>

Scheduled Tweets を使用すると、広告主やユーザーは、後の日時に公開されるツイートを作成してスケジュールできます。これらのツイートを作成および管理できるだけでなく、API を使用してこれらのツイートをラインアイテムに関連付け、ツイートが公開されたタイミングでプロモーションすることもできます。これにより、広告主はネイティブツイートをあらかじめ用意し、主要な取り組みに先立ってキャンペーンクリエイティブを計画できます。たとえば、新製品発表と同時に公開されるようにツイートクリエイティブを事前に用意しておく、といった使い方が可能です。

Scheduled Tweets API エンドポイントが提供する機能は次のとおりです。

* 新しくスケジュールされたツイートの作成、変更、閲覧
* スケジュール済みツイートをラインアイテムに関連付ける
* 既存のスケジュール済みツイートの照会および管理
* スケジュール済みツイートが公開されたら、公開済みツイートの `id` を取得

<div id="api-endpoints">
  #### API エンドポイント
</div>

上記の機能に関連するすべてのエンドポイントは以下のとおりです。

<div id="scheduled-tweet-management">
  #### 予約済みツイートの管理
</div>

* [GET accounts/:account&#95;id/scheduled&#95;tweets](/ja/x-ads-api/creatives#get-accounts-account-id-scheduled-tweets) (すべての予約済みツイートの一覧を取得)
* [GET accounts/:account&#95;id/scheduled&#95;tweets/:scheduled&#95;tweet&#95;id](/ja/x-ads-api/creatives#get-accounts-account-id-scheduled-tweets) (`id` を使用して特定の予約済みツイートを取得)
* [POST accounts/:account&#95;id/scheduled&#95;tweets](/ja/x-ads-api/creatives#post-accounts-account-id-scheduled-tweets) (新しい予約済みツイートを作成)
* [PUT accounts/:account&#95;id/scheduled&#95;tweets/:scheduled&#95;tweet&#95;id](/ja/x-ads-api/creatives#example-request-39) (既存の予約済みツイートを更新)
* [DELETE accounts/:account&#95;id/scheduled&#95;tweets/:scheduled&#95;tweet&#95;id](/ja/x-ads-api/creatives#example-request-40) (`id` を使用して予約済みツイートを削除)
* [GET accounts/:account&#95;id/scheduled&#95;tweets/preview/:scheduled&#95;tweet&#95;id](/ja/x-ads-api/creatives#scheduled-tweets-2) (既存の予約済みツイートをプレビュー)

<div id="scheduled-promoted-tweets">
  #### 予約済みプロモツイート
</div>

* [GET accounts/:account&#95;id/scheduled&#95;promoted&#95;tweets](/ja/x-ads-api/campaign-management#get-accounts-account-id-scheduled-promoted-tweets)（すべての予約済みプロモツイートの一覧を取得します）
* [GET accounts/:account&#95;id/scheduled&#95;promoted&#95;tweets/:scheduled&#95;promoted&#95;tweet&#95;id](/ja/x-ads-api/campaign-management#get-accounts-account-id-scheduled-promoted-tweets-scheduled-promoted-tweet-id)（`id` を使用して予約済みプロモツイートを取得します）
* [POST accounts/:account&#95;id/scheduled&#95;promoted&#95;tweets](/ja/x-ads-api/campaign-management#post-accounts-account-id-scheduled-promoted-tweets)（新しい予約済みプロモツイートを作成します）
* [DELETE accounts/:account&#95;id/scheduled&#95;promoted&#95;tweets/:scheduled&#95;promoted&#95;tweet&#95;id](/ja/x-ads-api/campaign-management#delete-accounts-account-id-scheduled-promoted-tweets-scheduled-promoted-tweet-id)（`id` を使用して既存の予約済みプロモツイートを削除します）

<div id="scheduled-tweet-view">
  #### 予約ツイートの表示
</div>

* [GET accounts/:account&#95;id/scheduled&#95;tweets/preview/:scheduled&#95;tweet&#95;id](/ja/x-ads-api/creatives#scheduled-tweets-2)（既存の予約ツイートを表示）

予約ツイートは「ライブ」のツイートとは別個のエンティティであるため、これらのツイートを作成または編集する際には、2種類の検証ルールセットが実行されます。1つ目の検証ルールセットは、予約ツイートの作成時、具体的には次の段階で実行されます。

<div id="scheduled-tweet-create">
  #### スケジュール済みツイートの作成:
</div>

* 認証済みユーザーが、指定された @handle に対してオーガニックツイートを作成するアクセス権を持っていることを検証します。Promoted-Only ツイートの作成権限には、認証済みユーザーがそのアカウントのユーザーであり、かつ [ツイートコンポーザー権限](https://developer.x.com/content/developer-twitter/en/docs/ads/campaign-management/api-reference/authenticated-user-access#get-accounts-account-id-authenticated-user-access) を持っている必要があります。
* `scheduled_at` 時刻の前後 15 分のウィンドウ内で作成がスケジュールされているツイートが 30 件を超えていないことを検証します。`SCHEDULED_TWEET_LIMIT_EXCEEDED` エラーメッセージは、同じ将来の 15 分間の時間枠内にスケジュールされたスケジュール済みツイートが多すぎることを示します。広告主は既存のスケジュール済みツイートを削除するか、`scheduled_at` 時刻を前後いずれかにずらす必要があります。

<div id="scheduled-tweet-goes-live">
  #### 予約済みツイートが公開されるとき:
</div>

* これらのバリデーションルールは scheduled&#95;at の時刻に実行され、API で通常のツイートを作成する際に適用されるものと同じです。例えば、予約済みツイートに画像と GIF の両方が含まれている場合、その予約済みツイートは公開されず、scheduled&#95;status が FAILED に設定されます。

<div id="workflow">
  #### ワークフロー
</div>

**新しい予約ツイートを作成する**

新しい予約ツイートは、[POST accounts/:account&#95;id/scheduled&#95;tweets](https://developer.x.com/content/developer-twitter/en/docs/ads/creatives/api-reference/scheduled-tweets#post-accounts-account-id-scheduled-tweets) エンドポイントを使用して作成できます。このエンドポイントには、必須パラメータとして `scheduled_at` 時刻と、ツイートにメディアエンティティが含まれていない場合のツイート `text` が必要です。さらに、このエンドポイントでは、`as_user_id` パラメータを利用して別の @handle の代わりに予約ツイートを作成したり、カード（`card_uri`）やメディア（`media_ids`）を追加したりできる、いくつかの追加オプションも提供しています。なお、ツイートには同じタイプのエンティティのみを含めることができます。つまり、Video、Gif、Image のいずれか一種類のエンティティだけを含めることができます。`nullcast` パラメータは、そのツイートが「Promoted-Only」ツイートかどうかを制御します。新しく作成されたすべての予約ツイートは、デフォルトで &quot;Promoted-Only&quot;（`nullcast=true`）です。`nullcast=false` の場合はオーガニックな予約ツイートが作成されます。

予約ツイートが正常に作成されると、レスポンスには `id` フィールドが含まれます。これは予約ツイート自体の一意の識別子を指します。このフィールドに加えて、`tweet_id` という別のフィールドも返されます。このフィールドは最初は `null` ですが、ツイートが公開されると、このフィールドに「ライブ」ツイートの ID が設定されます。

```
twurl -H 'ads-api.x.com' -X POST "/6/accounts/:account_id/scheduled_tweets" -d 'scheduled_at=2017-12-24T23:59:00Z&text=Happy Holidays!'
```

これにより、以下の予約ツイートが作成されます。

```json
{

    "params": {

この予約ツイートが公開されると、`tweet_id` フィールドには公開されたツイートの ID が設定されます。

**予約済みツイートをラインアイテムに関連付ける**

予約済みツイートはオーガニックツイートの作成に使用できますが、パートナーは「プロモーション専用」(`nullcast=true`) ツイートも作成でき、いずれもラインアイテムに関連付けることができます。これを可能にするために、[POST accounts/:account&#95;id/scheduled&#95;promoted&#95;tweets](https://developer.x.com/content/developer-twitter/en/docs/ads/campaign-management/api-reference/scheduled-promoted-tweets#post-accounts-account-id-scheduled-promoted-tweets) エンドポイントも提供しています。このエンドポイントでは、1 回の API 呼び出しにつき、1 件のプロモーション専用の予約済みツイートのみをラインアイテムに関連付けることができます。同じラインアイテムに複数の予約済みツイートを関連付けるには、複数回の API 呼び出しが必要です。

既存の予約済みプロモーションツイートを変更することはできない点にご注意ください。

```
twurl -H 'ads-api.x.com' -X POST "/6/accounts/:account_id/scheduled_promoted_tweets" -d 'line_item_id=a44qc&scheduled_tweet_id=917507899668099072'
```

    "params": {
      "line_item_id": "a44qc",
      "scheduled_tweet_id": 917507899668099100,
      "account_id": "aaaaa"
    }
  }
}
```

このエンドポイントは、指定された予約ツイートとラインアイテム間の関連付けを作成するだけです。キャンペーン／ラインアイテムのフライト期間が開始すると、そのラインアイテムは対応する「ライブ」のツイートの配信を自動的に開始します。このステップでは、予約ツイートが `SCHEDULED` 状態であること、および指定された目的に対してその予約ツイートが有効であることは検証しますが、それ以外の検証は実行されません。ラインアイテムと予約ツイートに適用される残りの検証ルールは、ツイートが「ライブ」になるタイミングで実行されます。

キャンペーン配信に問題が発生しないようにするために、予約ツイートの `scheduled_at` は、キャンペーン／ラインアイテムのフライト期間が開始する前の時刻に設定することを推奨します。

たとえば、予約ツイートがキャンペーン開始日より後にライブになるよう設定されている（かつ、1 つのラインアイテムに 1 つのツイートしか関連付けられていない）場合、キャンペーン自体は `ACTIVE` になりますが、予約ツイートがまだライブになっていないため、配信可能なクリエイティブが存在しない状態になります。

**予約ツイートの管理**

残りのエンドポイント群を使用すると、API 利用者はすべての予約ツイートおよび予約プロモツイートを管理できます。これらの API を使用して、すべての予約ツイートの一覧を（任意で指定された状態でフィルタして）取得したり、`id` を指定して特定の予約ツイートを取得したりできます。

<div id="what-happens-when-a-scheduled-tweet-goes-live">
  #### 予約済みツイートが公開されると何が起こりますか?
</div>

特定の予約済みツイートが公開されるタイミング、つまり `scheduled_at` の時刻に達すると、次の更新が行われます。

* 「ライブ」ツイートが作成されますが、最大 1 秒程度の遅延が発生する場合があります
* `tweet_id` が次のエンティティに追加されます:
* 予約済みツイート
* プロモーション用の予約済みツイート
* 新しいプロモーション用ツイートのエンティティが作成されます

<div id="best-practices">
  #### ベストプラクティス
</div>

予約ツイートを作成またはプロモーションを行う際は、次のベストプラクティスに従うことを推奨します。

* 予約ツイートを作成する際には、そのツイートが有効な形式になっていることを確認してください（例: 1 つのツイートには画像、動画、GIF のいずれか 1 種類のみを含めることができ、3 種類を組み合わせることはできません）
* キャンペーンの配信期間（`start_time` と `end_time`）が、予約ツイートの `scheduled_at` 時刻と一致していることを確認してください
* 予約ツイートは、現在から 1 年先（365 日）を超える日時には設定しないでください
* 予約ツイートに対するツイートプレビューは現在サポートされていません（ここでいうツイートプレビューとは、作成前に予約ツイートをプレビューする機能を指します）

<div id="adding-to-the-library">

<div id="request-parameters">
  #### リクエストパラメータ
</div>

すべての Media Library の POST リクエストでは、メディア識別子が必要です。この値はアップロード処理の際に返されます。上記の例のように `media_id` を使用する場合、`media_category` も指定する必要があります。使用可能なカテゴリ値は 4 種類あり、AMPLIFY&#95;VIDEO、TWEET&#95;GIF、TWEET&#95;IMAGE、TWEET&#95;VIDEO です。

オプションとして、Media Library 内のオブジェクトに対して `name` および `file_name` の値を設定できます。これらの属性は、ライブラリ内でメディアのバリエーションを見分けるのに役立ちます。

動画の場合、`title` と説明文を設定することも可能です。これらの値は、[POST accounts/:account&#95;id/tweet](https://developer.x.com/content/developer-twitter/en/docs/ads/creatives/api-reference/tweets#post-accounts-account-id-tweet) エンドポイントへのリクエストパラメータ `video_title` および `video_description` として渡すことを想定しています。投稿内では、このテキストは動画の下に表示されます。

<div id="attributes">
  #### 属性
</div>

Media Library では、`media_key` という概念が正式に導入されています。これはライブラリ内のオブジェクトの一意の識別子です。メディアキーは、次の形式の文字列型の値です: 13&#95;875943225764098048。これらはすべてのカード関連エンドポイントで完全にサポートされています。

さらに、Media Library のレスポンスには、文字列として表現される `media_id` が含まれます。これは、現在まだメディアキーを受け付けていないリソース用に含まれています: [Tweets](https://developer.x.com/content/developer-twitter/en/docs/ads/creatives/api-reference/tweets#post-accounts-account-id-tweet)*、[Tweet preview](https://developer.x.com/content/developer-twitter/en/docs/ads/creatives/api-reference/tweets#get-accounts-account-id-tweet-preview)*、および [Scheduled Tweets](https://developer.x.com/content/developer-twitter/en/docs/ads/creatives/api-reference/scheduled-tweets#post-accounts-account-id-scheduled-tweets)。現在、あらゆる場所でメディアキーをサポートできるよう対応を進めています。

`aspect_ratio` 属性は GIF と動画について返されます。これは、特定のアスペクト比のみを受け付けるカードで使用するメディアをフィルタリングするために利用できます。

*これらのエンドポイントは、メディアキーである `video_id` パラメータをサポートしています。

<div id="identifying-cards">
  ### Card の識別
</div>

<div id="introduction">
  #### はじめに
</div>

Cards はメディアを利用したカスタマイズ可能な広告フォーマットで、ウェブサイトやアプリ、あるいはダイレクトメッセージの開始など特定のユーザーエンゲージメントを促すコールトゥアクションと関連付けることができます。Cards はツイート、予約ツイート、または下書きツイートに付与できます。

Cards は Tweet オブジェクト内で 2 通りの方法で参照されます。Card の `card_uri` による方法と、`preview_url` による方法です。それぞれの例は以下のとおりです。

| card&#95;uri | preview&#95;url |
| :--- | :--- |
| card://1043282691834048513 | https://cards.x.com/cards/18ce54d4x5t/68w3s |

**注記**: Ads API バージョン 3 以降、新しく作成された Card に対しては `card_uri` のみが生成され、cards レスポンスで返されます。

**注記**: Ads API バージョン 5 以降、cards レスポンスでは `preview_url` は返されません。

Tweet オブジェクトのレスポンス内でどのタイプの参照が使われるかは、そのツイートの作成方法によって決まります。言い換えると、`card_uri` リクエストパラメータを使用してツイートが作成された場合、その card URI の値がレスポンスに含まれます。一方、`preview_url` がツイート本文の一部として含まれていた場合は、その preview URL がレスポンスに含まれます。

<div id="identifying-tweets-with-preview_url">

</div>

<div id="identifying-media">
  ### メディアの識別
</div>

<div id="introduction">
  #### はじめに
</div>

画像、GIF、動画などのメディアは、ツイートやカードに追加できます。さらに、動画はプレロールアセットとして使用でき、画像は [X Audience Platform](https://developer.x.com/en/docs/ads/measurement/overview/twitter-audience-platform) 上でプロモーション配信できます。このセクションでは、これらのエンティティ全体にわたってメディア参照を特定する方法について説明します。

メディア識別子には 2 つのタイプがあります: ID とキーです。それぞれの例は以下のとおりです。

| **メディアID** | **メディアキー** |
| :--- | :--- |
| 1029825579531807971 | 13&#95;1029825579531807971 |

メディアキーは、ID の前に数値のプレフィックスとアンダースコアを付けたものです。

<div id="image">
  #### 画像
</div>

次の表は、各画像関連リソースのレスポンスで現在利用可能な識別子タイプと、それに対応する属性名を示しています。

| **Resource** | **Identifier** | **Attribute(s)** |
| :--- | :--- | :--- |
| Image cards | None |  |
| Tweet | Both | `entities["media"]["id_str"]`  `entities["media"]["media_key"]` |
| Scheduled Tweet | Both | `media_ids` and `media_keys` |
| Draft Tweet | Both | `media_ids` and `media_keys` |
| Account Media | None |  |
| Media Library | Both | `media_id` and `media_key` |

Image cards と Account Media の画像には、いずれのメディア識別子への参照も含まれません。Tweet にはメディア ID のみが含まれます。Scheduled Tweet と Draft Tweet には、メディア ID とメディアキーの両方が含まれます。Media Library も同様に両方を返します。

Tweet の場合、`entities["media"]` 配列内のオブジェクトにある `id` および `id_str` フィールドがメディア ID に対応します。1 つの Tweet に複数の画像が含まれる場合、それぞれのメディアエンティティへの参照は `extended_entities["media"]` にのみ存在します。

識別子への参照に加えて、画像の URL にアクセスできることも重要な場合がよくあります。

| **Resource** | **Attribute(s)** | **Format** |
| :--- | :--- | :--- |
| Image cards | `image` | .jpg |
| Tweet* | `entities["media"][0]["media_url"]` または `extended_entities["media"][i]["media_url"]` | .jpg |
| Scheduled Tweet | None |  |
| Draft Tweet | None |  |
| Account Media | `media_url` | .jpg |
| Media Library | `media_url` | .jpg |

* この URL の場所は、Tweet に単一の画像が含まれるか複数の画像が含まれるかによって異なります。

すべての Image cards には、X の画像 URL を含む `image` レスポンス属性があります（image app download cards の場合、属性名は `wide_app_image` です）。

Tweet の場合、メディア URL の場所は、メディアのタイプと使用しているエンドポイントの両方に依存します。単一の画像を含む Tweet については、URL は `entities["media"][0]["media_url"]` にあります。これは Ads API と Standard API の両方で同様です。しかし、Tweet に複数の画像が含まれる場合、URL は `extended_entities["media"][i]["media_url"]` にのみ存在します。これは Standard API でのみ利用可能です。

<div id="video">
  #### 動画
</div>

次の表は、各動画関連リソースのレスポンスで現在利用可能な識別子の種類と、それに対応する属性名を示しています。

| **リソース** | **識別子** | **属性** |
| :--- | :--- | :--- |
| Video cards | いずれか一方 | `video_content_id` |
| Video poll cards | なし |  |
| ツイート | 両方 | `entities["media"]["id_str"]`  `entities["media"]["media_key"]` |
| 予約ツイート | 両方 | `media_ids` and `media_keys` |
| 下書きツイート | 両方 | `media_ids` and `media_keys` |
| アカウントメディア | メディアキー | `video_id` |
| メディアライブラリ | 両方 | `media_id` and `media_key` |

Video cards（動画付きの投票カードを除く）には video&#95;content&#95;id レスポンス属性が含まれますが、返される値の種類には一貫性がありません。メディア ID の場合もあれば、メディアキーの場合もあります。

動画の URL へのアクセス方法については、以下の表を参照してください。

| **リソース** | **属性** | **形式** |
| :--- | :--- | :--- |
| Video cards | `video_url` と `video_hls_url` | .vmap  .m3u8 |
| 動画付きツイート | `extended_entities["media"][i]["video_info"]["variants"][j]["url"]` | .mp4 |
| 予約ツイート | なし |  |
| 下書きツイート | なし |  |
| アカウントメディア | なし |  |
| メディアライブラリ | `media_url` | .mp4 |

Video cards には、.vmap と .m3u8 の URL をそれぞれ持つ video&#95;url と video&#95;hls&#95;url のレスポンス属性が含まれます。

<div id="media-library">
  #### Media Library
</div>

メディアアセットに関する追加情報を取得する必要がある場合があります。たとえばビデオカードでは、vmap URL ではなく mp4 URL を取得したいケースがあります。これは Media Library（メディアライブラリ）で利用できます。利用可能な情報の詳細については、[Media Library Guide](https://developer.x.com/content/developer-twitter/en/docs/ads/creatives/guides/media-library) を参照してください。広告アカウントの FULL プロモータブルユーザーに属するほとんどのアセットはライブラリ内にありますが、いくつかの例外もあります。

**メディアの取得**

前述のとおり、画像カードには media ID や media key への参照が含まれていません。その結果、Media Library を通じてこれらのアセットを取得することはできません。これは [Account Media](https://developer.x.com/content/developer-twitter/en/docs/ads/creatives/api-reference/account-media#account-media) の画像についても同様です。

ビデオカードを作成する前に、そのビデオアセットは Media Library（またはそれ以前の Videos リソース）の一部である必要があります。その結果、これらのアセットは常に Media Library から取得できます。これは Account Media の PREROLL アセットについても同様です。

最後に、ツイート内のメディアは常に Media Library 内に存在することが保証されています。

以下の表は、リソースのレスポンスに検索に使用する識別子が含まれているかどうかを踏まえて、どのアセットが Media Library から取得可能かをまとめたものです。

| **Resource** | **In the Media Library** |
| :--- | :--- |
| Image cards | No |
| Video cards | Yes* |
| Tweets (any media)** | Yes |
| Scheduled Tweets | Yes |
| Draft Tweets | Yes |
| Account media images | No |
| Account media videos (`PREROLL`) | Yes |

* `video_content_id` が media key であるカードの場合です。値が media ID の場合でもアセットは Media Library 内に存在しますが、取得には先頭に数値のプレフィックスとアンダースコアを付与する必要があります。\
** ツイートは media ID のみを返します。アセットは Media Library 内に存在することが保証されていますが、取得には先頭に数値のプレフィックスとアンダースコアを付与する必要があります。

**Account Media との連携**

Media Library に追加されたメディアアセットが自動的に Account Media リソースにも追加されるケースが 2 つあります。

* AMPLIFY&#95;VIDEO アセットが Media Library に追加されると、自動的に Account Media アセットとして、クリエイティブタイプ PREROLL として追加されます。
* 特定のサイズ（[enumerations ページ](https://developer.x.com/content/developer-twitter/en/docs/ads/general/overview/enums) の「Creative Types」を参照）の画像が Media Library に追加されると、自動的に Account Media アセットとして追加されます。クリエイティブタイプ（例: INTERSTITIAL）は画像のサイズによって決まります。

<div id="tweets">
  ### ツイート
</div>

<div id="introduction">
  #### はじめに
</div>

X Ads API では、公開済み、予約済み、下書きの 3 つのツイートのタイプをサポートしています。

<div id="nullcasted-tweets">
  #### Nullcasted ツイート
</div>

ツイートは、nullcast（「Promoted-only」とも呼ばれる）かオーガニックかのいずれかです。Nullcasted ツイートは公開されてもユーザーの公開タイムラインには表示されませんが、公開ツイートである点は同じです。一方、オーガニックツイートはユーザーのフォロワーに配信され、ユーザーの公開タイムラインにも表示されます。

**ツイートの作成**

3 つのツイート作成エンドポイントにはそれぞれ Boolean 型の `nullcast` パラメータがあり、API ユーザーは nullcasted ツイートかオーガニックツイートのどちらを作成するか選択できます。Nullcasted ツイートは、当該ユーザー本人、またはユーザーの代理でツイートを作成する権限を持つ任意のユーザーが作成できます。オーガニックツイートを作成できるのは、[full promotable user](https://developer.x.com/content/developer-twitter/en/docs/tutorials/ads-api-hierarchy-terminology#promotable-users) のみです。

**ツイートの更新**

予約済みツイートおよび下書きツイートについては、`nullcast` プロパティを更新できます。予約済みツイートについては、そのツイートの `scheduled_at` 時刻まで編集が可能です。下書きツイートは無期限に編集できます。ただし一度公開されると、そのツイートの nullcast 設定を、nullcasted からオーガニック、あるいはその逆に変更することはできません。

<div id="promoting-tweets">
  #### ツイートのプロモーション
</div>

プロモーションできるのは、公開済みツイートと予約済みツイートのみです。これらは nullcast されたツイートでもオーガニックツイートでもかまいません。制限はありません。広告主は、自分自身のツイートだけでなく、許可を得ている場合は他のユーザーのツイートもプロモーションできます（詳しくは「[Promoting another user&#39;s Tweets](https://developer.x.com/content/developer-twitter/en/docs/tutorials/promoting-another-users-content)」を参照してください）。

1つのキャンペーン内で複数のツイートをプロモーションできます。同様に、1つのツイートを1つ以上のキャンペーンでプロモーションすることも可能です。

公開済みツイートをプロモーションするには、[POST accounts/:account&#95;id/promoted&#95;tweets エンドポイント](https://developer.x.com/content/developer-twitter/en/docs/ads/campaign-management/api-reference/promoted-tweets#post-accounts-account-id-promoted-tweets)を使用します。これにより、公開済みツイートがラインアイテムに関連付けられます。予約済みツイートをプロモーションするには、[POST accounts/:account&#95;id/scheduled&#95;promoted&#95;tweets エンドポイント](https://developer.x.com/content/developer-twitter/en/docs/ads/campaign-management/api-reference/scheduled-promoted-tweets#post-accounts-account-id-scheduled-promoted-tweets)を使用します。

<div id="tweet-ids">
  #### ツイートID
</div>

公開済み、予約済み、および下書きのツイートIDは[数値](https://developer.x.com/content/developer-twitter/en/docs/basics/twitter-ids)で、64ビット符号なし整数です。たとえば、次の公開済みツイートのIDは 1166476031668015104 です。

公開済みまたは予約済みツイートをプロモーションとして配信すると、対応するプロモツイートエンティティが作成されます。これらのエンティティにはそれぞれ固有のIDがあり、英数字で構成され、基数36でエンコードされた値として表現されます。たとえば、上記の公開済みツイートをプロモーションする、つまり line item 6c62d に関連付けると、次の API レスポンスが返されます。

<div id="carousels">
  ### カルーセル
</div>

<div id="introduction">
  #### はじめに
</div>

X Ads API では、動画カルーセルおよび画像カルーセルの作成と取得をサポートしています。カルーセルは、2〜6 個のメディアアセットを含めることができるカードタイプです。カルーセルカードは、ユーザーをウェブサイトに誘導したり、モバイルアプリのインストールを促したりできます。カルーセルの概要、その利点、ベストプラクティス、FAQ については、[Carousel Ads on X](https://business.x.com/en/advertising/carousels.html) のページを参照してください。

カルーセルは、他のカードタイプと同様にツイートで使用でき、そのツイートをプロモーション配信することができます。ワークフローは、これまでどおり次のとおりです。

1. メディアをアップロードする
2. カードを作成する
3. ツイートを作成する
4. ツイートをプロモーション配信する

唯一の違いはカードの作成方法にあります。他のカード作成リクエストがクエリパラメータを受け付けるのに対し、カルーセルカード作成リクエストは JSON POST ボディのみを受け付けます。

<div id="endpoints">
  #### エンドポイント
</div>

Ads API では、カルーセルの作成と取得が可能です。

任意の種類のカルーセルを作成するには、[POST accounts/:account&#95;id/cards](https://developer.x.com/en/docs/twitter-ads-api/creatives/api-reference/cards#post-accounts-account-id-cards) エンドポイントを使用します。カルーセルを取得するには、[GET accounts/:account&#95;id/cards](https://developer.x.com/en/docs/twitter-ads-api/creatives/api-reference/cards#get-accounts-account-id-cards) エンドポイントを使用します。

<div id="json-post-body">
  #### JSON POST Body
</div>

カルーセルは 2 つのコンポーネントから構成されます。1 つ目は使用するメディアアセットを指定し、2 つ目はウェブサイトまたはアプリのいずれかに関する情報を指定します。

具体的には、カルーセルカードは次のコンポーネントをこの順序で使用して作成されます。

* メディアキーの配列を受け取る `SWIPEABLE_MEDIA` コンポーネントを 1 つ
* 次のいずれか *1 つ*:
* ウェブサイト情報を指定するための `DETAILS` コンポーネント
* アプリ情報を指定するための `BUTTON` コンポーネント

`SWIPEABLE_MEDIA` コンポーネントには `media_keys` 配列を含める必要があり、その中で 2～6 個の画像または動画を指定できます。渡したメディアキーの順序によって、レンダリングされる順序が決まります。

```
{
  "type": "SWIPEABLE_MEDIA",
  "media_keys": [
    "13_1089771253848666112",
    "13_1191948012077092867"
  ]
}
```

念のため、[GET accounts/:account&#95;id/media&#95;library](https://developer.x.com/en/docs/twitter-ads-api/creatives/api-reference/media-library#get-accounts-account-id-media-library) エンドポイントにリクエストを送信することで、メディアキーを取得できます。

2つ目の component オブジェクトの構成は、ユーザーをウェブサイトに誘導するか、アプリのインストールを促すかによって異なります。以下の表は、これら 2 つのオプションをまとめたものです。（**注**：記載されているキーはすべて必須です。）

|                   | **Website**（ウェブサイト）                                                | **App**（アプリ）                                      |
| :---------------- | :----------------------------------------------------------------- | :------------------------------------------------ |
| component のタイプを指定 | `"type": "DETAILS"`                                                | `"type": "BUTTON"`                                |
| タイトル/ラベル          | `"title": "X"`                                                     | `"label": { "type": "ENUM", "value": "INSTALL" }` |
| 遷移先               | `"destination": { "type": "WEBSITE", "url": "https://www.x.com" }` | `"destination": { "type": "APP", ... }`           |

これらを組み合わせると、ウェブサイト向けカルーセルの JSON POST ボディの例は次のようになります。

```
{
  "name": "website carousel",
  "components": [
    {
      "type": "SWIPEABLE_MEDIA",
      "media_keys": [
        "13_1089771253848666112",
        "13_1191948012077092867"
      ]
    },
    {
      "type": "DETAILS",
      "title": "X",
      "destination": {
        "type": "WEBSITE",
        "url": "https://www.x.com"
      }
    }
  ]
}
```

`BUTTON` コンポーネント内のアプリ宛先オブジェクトには、国コードと少なくとも 1 つのアプリ識別子が必要です。オプションでディープリンクを指定できます。これらのフィールドの説明については、[リファレンスドキュメント](https://developer.x.com/en/docs/twitter-ads-api/creatives/api-reference/cards#app-destination)を参照してください。

これらを踏まえたアプリカルーセルの JSON POST リクエストボディの例を以下に示します。

```
{
  "name": "app carousel",
  "components": [
    {
      "type": "SWIPEABLE_MEDIA",
      "media_keys": [
        "13_1089771253848666112",
        "13_1191948012077092867"
      ]
    },
    {
      "type": "BUTTON",
      "label": {
        "type": "ENUM",
        "value": "INSTALL"
      },
      "destination": {
        "type": "APP",
        "country_code": "US",
        "googleplay_app_id": "com.twitter.android",
        "iphone_app_id": "333903271"
      }
    }
  ]
}
```

<div id="creative-metadata-tagging">
  ### クリエイティブメタデータのタグ付け
</div>

<div id="introduction">
  #### はじめに
</div>

このガイドは、クリエイティブパートナー、代理店、クリエイティブ開発者が、X キャンペーン内で使用されるアセットにタグ付けを行い、個々のアセットの価値とパフォーマンスをより深く把握できるようにするためのものです。

**注:** メディアアセットには、そのメディアアセットを作成したパートナーまたは開発者のみがタグ付けを行う必要があります。メディアアセットの利用者がそのメディアアセットを作成していない場合は、メタデータタグ付けを実装しないでください。

Creative Metadata Tagging を使用すると、アセットが X にどこからアップロードされるか、またアセットをアップロードする主体が誰であるかにかかわらず、Creative Partner によって作成された画像や動画に対してアトリビューションを付与できます。クリエイティブアセットとクリエイティブパートナーとの関連付けを行うために、[XMP](https://exiftool.org/TagNames/XMP.html) 標準が使用されます。

<div id="tagging-creative-assets">
  #### クリエイティブアセットへのタグ付け
</div>

次の表は、各画像関連リソースのレスポンスで現在利用可能な識別子タイプと、それに対応する属性名を示しています。クリエイティブアセットにタグを付けるには、タグ付けツールが必要です。[ExifTool](https://exiftool.org/) は、メタ情報の読み取り、書き込み、編集を行うための、プラットフォーム非依存の Perl ライブラリおよび [コマンドラインアプリケーション](https://exiftool.org/exiftool_pod.html)であり、推奨ツールです。サポートされているすべての[ファイルタイプ](https://exiftool.org/#supported)を参照してください。

[ExifTool のインストール手順](https://exiftool.org/install.html)に従ってセットアップしてください。[Homebrew](https://formulae.brew.sh/) が提供するソフトウェアパッケージもあり、macOS と Linux 向けの [exiftool インストールコマンド](https://formulae.brew.sh/formula/exiftool)によって、インストールをさらに簡略化できます。コマンドラインで `exiftool -ver` と入力し、ツールのバージョン番号が返ってくることを確認して、ツールが正しくインストールされているか検証してください。ExifTool のコマンドパラメータについて詳しくは、[ExifTool ドキュメント](https://exiftool.org/)を参照してください。

クリエイティブパートナーは、新規または既存のクリエイティブアセットに対して、自身の X app&#95;id を contributor XMP タグおよび date タグに設定することで、メタデータタグを付与できます。クリエイティブアセットには、[メディアのアップロード](https://developer.x.com/en/docs/twitter-api/v1/media/upload-media/overview)時と同じサイズ制限が適用されます。 

**注:** X による contributor XMP タグの使用により、メタデータには X 上のキャンペーン専用の値のみが記録されることが保証されます。

`exiftool -contributor="<YOUR APP ID>" -creative_file.jpg`

`exiftool -date="<date>" -creative_file.jpg`

app&#95;id は、[開発者コンソール](https://developer.x.com/en/portal/dashboard)の Projects &amp; Apps で確認できます。例: 16489123

次の例では、画像に対して app&#95;id を contributor タグとして、date を date タグとして追加します。

```
app_id:858382169
```

```
date:2022-03-13
```

```
creative_file: eiffel_tower.jpg
```

```
exiftool -contributor=858382169 eiffel_tower.jpg
```

```
   1 image files updated
```

```
exiftool -date=2022-03-13 eiffel_tower.jpg
```

```
  1 image files updated
```

画像に正しくタグが付与されていることを確認します: 

`exiftool -xmp:all -G1 <filename>`

例:

`exiftool -xmp:all -G1 eiffel_tower.jpg`

```
[XMP]        XMP Toolkit            : Image::ExifTool 12.30
```

```
[XMP]        Contributor            : 858382169
```

```
[XMP]        Date                   : 2022:03:13
```

</div>

指定されたアカウントに紐づく新しいカードを作成します。

カード作成リクエストは、JSON 形式の POST ボディのみを受け付けます。`Content-Type` は `application/json` に設定する必要があります。

詳しい使用例については、[Carousels Guide](https://developer.x.com/en/docs/twitter-ads-api/creatives/guides/carousels) を参照してください。

</div>

`https://ads-api.x.com/12/accounts/:account_id/cards`

#### パラメーター

JSON の POST 本文には、カードの `name` と `components` の配列を含める必要があります。コンポーネントはオブジェクトとして表され、カードの広告主向けの属性を記述します。

次の例は、ペイロードのおおまかな構造を示したものです（実際には動作しない情報が含まれます）。

```
{
  "name": "some name",
  "components": [
    {
      "type": "TYPE_ENUM",
      "key": "value"
    }
  ]
}
```

components に関する追加情報は以下を参照してください。

| Name                   | Description                                                                                                                                                                                                                                                |
| :--------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| account&#95;id   *必須*  | レバレッジドアカウントの識別子です。リソースのパス内に含まれ、[GET accounts](https://developer.x.com/en/docs/ads/campaign-management/api-reference/accounts#get-accounts) を除くすべての Advertiser API リクエストで、通常は必須パラメーターです。指定されたアカウントは、認証済みユーザーに関連付けられている必要があります。  タイプ: 文字列型  例: `18ce54d4x5t` |
| name   *必須*            | カードの名前です。最大長: 80 文字。  タイプ: 文字列型  例: `component based card`                                                                                                                                                                                                 |
| components   *状況により必須* | カードを作成するために使用する components を指定します。components に関する追加情報は以下を参照してください。`slides` と同時には指定できません。  **注意**: components の順序は重要です。  タイプ: オブジェクトの配列                                                                                                                     |
| slides   *状況により必須*     | Multi-Destination Carousels を作成するために、この配列の配列を使用します。各カードを components のグループとして記述します。各スライドは 1 枚のカードを完全に表現している必要があります。`components` と同時には指定できません。  **注意**: 各スライドの順序は重要です。  タイプ: 配列の配列                                                                           |

<div id="components">
  #### コンポーネント
</div>

すべてのコンポーネントには、そのオブジェクトのスキーマを決定する `type` フィールドを含める必要があります。Ads API は、メディアベースと説明ベースのコンポーネントに分類される、以下のコンポーネントタイプをサポートします。

* メディア:
* `MEDIA`: 単一の動画または画像
* `SWIPEABLE_MEDIA`: 2〜6 個の動画または画像
* 説明:
* `DETAILS`
* `BUTTON`

各コンポーネントには（`type` キーに加えて）一連の必須フィールドがあります。これらは次の表に示します。

| Component `type`  | Field                   | 値の型             |
| :---------------- | :---------------------- | :-------------- |
| `MEDIA`           | `media_key`             | 文字列型            |
| `SWIPEABLE_MEDIA` | `media_keys`            | 文字列型の配列         |
| `DETAILS`         | `title`   `destination` | 文字列型   オブジェクト   |
| `BUTTON`          | `label`   `destination` | オブジェクト   オブジェクト |

以下は、`components` 配列内での `BUTTON` コンポーネントの例です（意図的に `name` キーを省略しています）。（省略記号は、さらに情報を指定する必要がある箇所を示しています。）

```
{
  "components": [
    {
      "type": "BUTTON",
      "label": {
        ...
      },
      "destination": {
        ...
      }
    }
  ]
}
```

コンポーネントオブジェクトが指定される順序が、それらが上から下へレンダリングされる順序を定義します。Card は、1 つのメディアベースのコンポーネントと、`DETAILS` または `BUTTON` コンポーネントのいずれかを組み合わせて作成する必要があります。説明ベースのコンポーネントはメディアの下にレンダリングされ、URL またはモバイルアプリのいずれかを遷移先として持ちます。

**ラベル**

ラベルはボタンに表示されるテキストを定義するため、`BUTTON` コンポーネントにのみ適用されます。ラベルオブジェクトには、`type` と `value` という 2 つの必須キーがあります。`type` は `ENUM` に設定する必要があり、`value` には `BOOK`、`CONNECT`、`INSTALL`、`OPEN`、`ORDER`、`PLAY`、`SHOP` のいずれかを指定できます。

前の例に基づいて、次に示すのは `BUTTON` コンポーネント内の `label` オブジェクトです。

```
{
  "components": [
    {
      "type": "BUTTON",
      "label": {
        "type": "ENUM",
        "value": "INSTALL"
      },
      "destination": {
        ...
      }
    }
  ]
}
```

**遷移先**

遷移先は、広告主がユーザーを誘導したい場所です。`DETAILS` コンポーネントまたは `BUTTON` コンポーネントのいずれかの中で常に必須です。遷移先のタイプには `WEBSITE` と `APP` の 2 種類があります。

**注意**: Website タイプの遷移先は `DETAILS` コンポーネントでのみ使用でき、App タイプの遷移先は `BUTTON` コンポーネントでのみ使用できます。

**Website 遷移先**

| Name        | Description                                                                            |
| :---------- | :------------------------------------------------------------------------------------- |
| type   *必須* | 遷移先のタイプであり、そのスキーマを決定します。  型: enum  取りうる値: `WEBSITE`                                    |
| url   *必須*  | ユーザーをリダイレクトする Web サイトの URL。  型: 文字列型  例: `https://devcommunity.x.com/c/advertiser-api` |

**App 遷移先**

| Name                                               | Description                                                                                                                                 |
| :------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------ |
| type   *必須*                                        | 遷移先のタイプであり、そのスキーマを決定します。  型: enum  取りうる値: `APP`                                                                                             |
| country&#95;code   *必須*                            | アプリが販売されている国を表す、[ISO 3166-1 alpha-2](https://en.wikipedia.org/wiki/ISO_3166-1_alpha-2) の 2 文字の国コード。  型: 文字列型  例: `US`                       |
| googleplay&#95;app&#95;id   *場合によっては必須*            | Google Play アプリケーションのパッケージ名。  **注意**: 次のいずれか一方は必須です: `ios_app_store_identifier` または `googleplay_app_id`。  型: 文字列型  例: `com.twitter.android` |
| ios&#95;app&#95;store&#95;identifier   *場合によっては必須* | iOS App Store の識別子。  **注意**: 次のいずれか一方は必須です: `ios_app_store_identifier` または `googleplay_app_id`。  型: 文字列型  例: `333903271`                    |
| googleplay&#95;deep&#95;link   *任意*                | プロモーションしている Android アプリへのディープリンク。  **注意**: `googleplay_app_id` が指定されている場合にのみ使用できます。  型: 文字列型                                                |
| ios&#95;deep&#95;link   *任意*                       | プロモーションしている iOS アプリへのディープリンク。  **注意**: `ios_app_store_identifier` が指定されている場合にのみ使用できます。  型: 文字列型                                             |

アカウントの `FULL` プロモート可能ユーザー（デフォルト）、または `as_user_id` パラメータで指定されたユーザーのツイートを作成します。nullcast（デフォルト）およびオーガニックのツイート作成の両方をサポートします。nullcast ツイートはパブリックタイムラインに表示されず、フォロワーにも配信されません。どちらの種類もキャンペーンで使用できます。

認証済みユーザーがこのアカウントの `FULL` プロモート可能ユーザーではない場合、そのユーザーがこのユーザーの代わりにツイートする権限を持っているかどうかを確認するには、[GET accounts/:account&#95;id/authenticated&#95;user&#95;access](https://developer.x.com/en/docs/ads/campaign-management/api-reference/authenticated-user-access#get-accounts-account-id-authenticated-user-access) エンドポイントにリクエストを送信します。`TWEET_COMPOSER` 権限が付与されている場合、そのユーザーはこのエンドポイントを使用して、`FULL` [プロモート可能ユーザー](https://developer.x.com/en/docs/ads/campaign-management/api-reference/promotable-users#get-accounts-account-id-promotable-users) の代わりに nullcast ツイートを作成できます。

メディアのアップロードに [upload.x.com エンドポイント](https://developer.x.com/rest/reference/post/media/upload) を使用する場合、このエンドポイントに渡す `as_user_id` の値と同じ `user_id` の値を、`additional_owners` パラメータに指定してください。
