<div id="overview">
  ## 概要
</div>

毎月、X Ads API に変更を加え、複数の新機能をリリースしています。これらの変更のほとんどは後方互換性がありますが、毎年いくつかの破壊的変更が発生する傾向があります。開発者からは、Ads API の頻繁な変更ペースが、新機能の実装、非推奨対応、変更のテストといった開発サイクルに与える影響についてフィードバックを受けています。私たちは Ads プラットフォームを利用する開発者体験を向上させたいと考えており、そのためにエンドポイントのバージョニングという概念を導入しました。

ここで言及するいくつかの概念を定義します。

**バージョン (Version)**: Ads API リクエストの URL パスに含まれるバージョン番号を指します。例: GET /{version_number}/accounts。このスタイルのバージョニングは URI バージョニングと呼ばれます。

**破壊的変更 (Breaking Changes)**: 既存の機能を維持するために開発者のリソースを必要とするあらゆる変更です。これには、必要な変更の調査、非推奨となる機能／エンドポイントの特定、およびそれらすべての変更を最終的に実装するために必要なリソースが含まれます。破壊的変更の例としては、次のようなものがあります。

* API リクエスト／レスポンスからパラメータを削除する

* いずれかのパラメータまたはエンドポイントの名前を変更する

* 値の表現方法を変更する (preview&#95;url → card&#95;uri)

* エンドポイントの動作を変更する (例: 非同期 vs 同期の統計)

* 任意または必須パラメータを追加／変更する (例: リクエスト内で name フィールドを必須にする)

**非推奨 (Deprecation)**: 非推奨となったバージョンまたはプロダクトはサポート対象外となり、開発者はこれらの API の使用を中止することが推奨されます。

**サンセット (Sunset)**: プロダクトまたは API がサンセットされると、対応するエンドポイント群には API 経由でアクセスできなくなります。

<div id="versioning-strategy">
  ## バージョニング戦略
</div>

この戦略の主な原則は次のとおりです。

1. すべての破壊的変更は新しいバージョンにまとめて含める

2. 新しいバージョンがアナウンスされた際、既存バージョンの非推奨期間は 6 か月とする

3. 常に、API は同時に 2 つのバージョンからのリクエストを許可するが、そのうち古い方のバージョンはサポート対象外となる

4. 新しいプロダクトのより迅速な採用を可能にするため、新しいプロダクトはバージョン更新のサイクルとは別に、継続的にリリースされる

5. すべての API レスポンスには、API の現在のバージョンを示す `x-current-api-version` が含まれ、さらに非推奨となっている API エンドポイントを呼び出した場合には、`x-api-warn` ヘッダーも併せて含まれる。

API の破壊的変更を必要とするような根本的なプロダクト要件の変更（例: 複数の年齢区分ターゲティングの非推奨化）が発生した場合、この破壊的変更をアナウンスする 90 日前通知を送付し、通知の送付から少なくとも 90 日経過後に、この破壊的変更をデプロイする。

<div id="v9">
  ### v9
</div>

本日 2021年3月3日より、X Ads API のバージョン 9（v9）が利用可能になりました。このリリースは、機能面での互換性を高め、キャンペーン作成を簡素化し、Cards および Mobile App Promotion エンドポイントに対する重要なアップデートを導入することを目的としています。

これまでのバージョンと同様に、v9 への移行のために 6 か月間の移行期間が設けられます。2021年8月31日をもって、既存のバージョン 8（v8）の Ads API は利用できなくなります。サービス中断を回避するため、すべての開発者の皆様に対し、できるだけ早く Ads API の最新バージョンへ移行することを推奨します。

<Note>
  **注:** 本リリースをもって、Ads API のバージョン 7（v7）はサポート終了となり、利用できなくなりました。
</Note>

詳細については、[developer forum でのアナウンス](https://devcommunity.x.com/t/ads-api-version-9/150316)をご覧ください。

<div id="v5">
  ### v5
</div>

2019年2月28日、X はスケールと効率の実現に焦点を当てたアップデートを含む Ads API v5 をリリースしました。

このリリースには、指定した期間にどのエンティティがアクティブであったかを判定するための新しいエンドポイント、Media Creatives（すなわち X Audience Platform 上のインストリーム動画および画像）の統計情報、カード URI によって*複数*のカードを取得する機能、さらにターゲティング条件やその他のエンティティを取得する際の柔軟性向上などが含まれます。加えて、いくつかのバグ修正を行い、パラメーター名およびレスポンス属性を更新しました。最後に、メディアを含まないアプリカードと、POST `accounts/:account_id/account_media` エンドポイントは非推奨となりました。

これまでのバージョンと同様に、v5 への移行には 6 か月の移行期間を設けています。**2019-08-28** 以降、Ads API のバージョン 4 は利用できなくなります。サービスの中断を回避するため、すべてのパートナーの皆様には、可能な限り早く最新バージョンの API へ移行していただくことを推奨します。*Ads API のバージョン 3 はサポート終了となっており、すでに利用できません。*

<div id="new">
  #### 新機能
</div>

**どのエンティティがアクティブかを判定する**

[Active Entities](/ja/x-ads-api/analytics#active-entities-2) エンドポイントは、広告エンティティのアナリティクス指標が変更されたかどうかを示します。アナリティクス用エンドポイントと併用されることを想定しており、Active Entities はエンティティタイプと日付範囲（最大 90 日間）を指定することで動作し、プラットフォーム側でアナリティクスを取得すべきエンティティ ID の配列を返します。返却されたものに含まれていない ID については、その後のアナリティクスリクエストでクエリすべきではありません。

このエンドポイントは、次のエンティティタイプをサポートします: `CAMPAIGN`、`FUNDING_INSTRUMENT`、`LINE_ITEM`、`MEDIA_CREATIVE`、`PROMOTED_TWEET`。

**`MEDIA_CREATIVE` の指標**

Ads API のアナリティクスエンドポイントで、Media Creative エンティティ向けの指標が利用可能になりました。Media Creative は、X Audience Platform 上のインストリーム広告や画像をプロモーションするための仕組みです。X Ads UI では、「In-stream videos」タブおよび「Display creatives」タブに Media Creative の指標が表示されます。[同期](/ja/x-ads-api/analytics#get-stats-accounts-account-id)および[非同期](/ja/x-ads-api/analytics#asynchronous-analytics)の両方のアナリティクスエンドポイントが、`MEDIA_CREATIVE` エンティティ enum をサポートするようになりました。

**複数のカードを取得**

カード URI の値で単一のカードを取得するために設計されたエンドポイントの [v3 リリース](https://devcommunity.x.com/t/ads-api-version-3/100732) を拡張し、[GET accounts/:account&#95;id/cards/all](/ja/x-ads-api/creatives#cards-fetch) エンドポイントを使って *複数* のカードを取得できるようになりました。これにより、カードごとにリクエストを送信する代わりに、1 回のリクエストで最大 200 件のカードを取得できます。

注意点が 2 つあります。

1. URL パスは `accounts/:account_id/cards/all` に変更されました。（以前のパスは利用できなくなりました。）これは、ID によってカードを取得するために設計された [エンドポイント](/ja/x-ads-api/creatives#cards-fetch) と一貫性を保つためです。
2. 必須のリクエストパラメータの名前は、card&#95;uris（複数形）になりました。

**取得の柔軟性**

[GET accounts/:account&#95;id/targeting&#95;criteria](/ja/x-ads-api/campaign-management#get-accounts-account-id-targeting-criteria) エンドポイントが、複数の line item の ID をサポートするようになりました。最大 200 個の ID を受け付ける line&#95;item&#95;ids パラメータが必須です。以前は単一の line item しか受け付けず、同期が困難でした。この変更により、より多くのターゲティングをより短時間で取得できるようになりました。

以下のエンドポイントも複数の line item の ID をサポートするようになりましたが、これらでは line&#95;item&#95;ids パラメータは任意です。

* [GET accounts/:account&#95;id/line&#95;item&#95;apps](https://developer.x.com/en/docs/x-ads-api/campaign-management/api-reference/line-item-apps#get-accounts-account-id-line-item-apps)
* [GET accounts/:account&#95;id/media&#95;creatives](/ja/x-ads-api/campaign-management#get-accounts-account-id-media-creatives)
* [GET accounts/:account&#95;id/promoted&#95;accounts](/ja/x-ads-api/campaign-management#get-accounts-account-id-promoted-accounts)
* [GET accounts/:account&#95;id/preroll&#95;call&#95;to&#95;actions](/ja/x-ads-api/creatives#preroll-call-to-actions)

<div id="changed">
  #### 変更点
</div>

**ドラフトキャンペーンおよびラインアイテムの取得**

ドラフトキャンペーンおよびラインアイテムの取得方法が更新されました。`with_draft(boolean)` パラメータを `true` に設定すると、ドラフトと非ドラフトの両方のエンティティが返されるようになりました。これは、削除済みエンティティの取得方法（`with_deleted` を使用）と一貫しています。これまでは、ドラフトと非ドラフトの両方のエンティティを取得するには、少なくとも 2 回のリクエストが必要でしたが、現在は 1 回の API 呼び出しで完了します。

| **v4** | **v5** |
| :--- | :--- | :--- |
| `draft_only` | `with_draft` |     |

**Network Activation Duration ターゲティング**

Ads API は、Network Activation Duration ターゲティングを追加した後、レスポンス内のターゲティングタイプに `_IN_SEC` サフィックスが含まれてしまう表示上の不具合を解消しました。Network Activation Duration は常に月単位で表現されるため、秒を参照する表記は混乱を招いていました。この修正により、表現が統一され、混乱が軽減されます。

| **v4** | **v5** |
| :--- | :--- | :--- |
| `NETWORK_ACTIVATION_DURATION_IN_SEC` | `NETWORK_ACTIVATION_DURATION` |     |

**合計件数とカーソル**

v5 では、`with_total_count` と `cursor` は排他的です。1 つのリクエスト内で両方を指定すると、`EXCLUSIVE_PARAMETERS` エラーコードが返されます。v5 以前では、`cursor` が指定されている場合、`with_total_count` は無視されていました。この変更により、両者の関係が明示的になりました。

<div id="removed">
  #### 削除内容
</div>

Ads API のレスポンスから、preview&#95;url、account&#95;id、parent&#95;ids の 3 つのフィールドが削除されます。これら 3 つに対するエンジニアリング上の対応工数はごくわずかです。

* v4 では、カードに対する preview&#95;url レスポンスパラメータは常に null であることが告知されていました。この移行の最終ステップとして、すべてのカードレスポンスから preview&#95;url を削除します。
* 次のリソースについては、広告アカウント ID がすでに URL 内および request.params に含まれているため、account&#95;id レスポンス属性が削除されます。（この一覧から資金提供手段（funding instruments）を意図的に除外しています。可能な限り parent ID はレスポンスオブジェクトに含まれるべきであり、account ID は funding instruments の親エンティティであるためです。）
  * アカウントメディア
  * アプリイベントプロバイダ
  * アプリイベントタグ
  * キャンペーン
  * カード
  * ラインアイテム
  * プロモーション可能ユーザー
  * ターゲティング条件
* [GET accounts/:account&#95;id/targeting&#95;criteria](/ja/x-ads-api/campaign-management#get-accounts-account-id-targeting-criteria) リクエストでは、parent&#95;ids フィールドは常に空の配列であったため、今後は返されません。

**メディア以外のアプリカード**

v5 では、メディア以外のアプリカードはサポートされなくなります。以前、[こちら](https://devcommunity.x.com/t/deprecation-announcement-app-download-cards/87807) で、メディア以外のアプリカードの作成および編集機能は削除されていました。今回、このリソース用に残っていたエンドポイントが非推奨となります。

* 注: これは画像および動画のアプリダウンロードカードには**影響しません**。

**アカウントメディアの作成**

POST accounts/:account&#95;id/account&#95;media エンドポイントは v5 では利用できません。このリソースのその他のエンドポイントには**影響はありません**。この変更の理由は、[Media Library](/ja/x-ads-api/creatives#media-library) にメディアを追加する際、それらのアセットが自動的に Account Media エンティティとして追加されるケースがあり、すでに存在するアセットを Account Media リソースに追加しようとするとエラーになるためです。これは次のケースで発生します。

* Media Library に追加された `AMPLIFY_VIDEO` アセットは、自動的に `PREROLL` クリエイティブタイプを持つ Account Media アセットとして追加されます。
* 特定のサイズの画像を Media Library に追加すると、自動的に Account Media アセットとして追加されます。クリエイティブタイプ（例: `INTERSTITIAL`）は画像のサイズに依存します。（サイズの詳細については、[Enumerations](/ja/x-ads-api/introduction) ページを参照してください。）

<div id="v4">
  ### v4
</div>

Ads API バージョン 4 は本日、2018 年 8 月 28 日にリリースされました。

このリリースには、[Audiences](/ja/x-ads-api/audiences) 製品の改善が含まれており、より堅牢なオーディエンス処理バックエンドを利用した新しい API インターフェースが導入されています。バージョン 4 には、ユーザー、アカウント、および税情報設定を管理するための一連のエンドポイントも含まれています。さらに、accounts/:account&#95;id/videos エンドポイントは非推奨となります。このリリースには、いくつかのマイナーなパラメータおよびレスポンス名の変更も含まれています。

バージョン 3 と同様に、6 か月の移行期間を提供します。**2019-02-28** 以降、Ads API バージョン 3 は利用できなくなります。サービスの中断を回避するため、すべてのパートナーに対し、できるだけ早く最新バージョンの API へ移行することを推奨します。バージョニング戦略の詳細については、[Versions](/ja/x-ads-api/introduction) ページを参照してください。

#### 新規

***Audiences API***

新しい Audiences API は、新しいオーディエンス処理バックエンド上に構築されており、堅牢性と信頼性が強化されています。この新しいエンドポイントにより、パートナーは 1 人のユーザーに対して複数種類のユーザー識別子を提供できるようになります。これにより、マッチングに利用できるシグナルが追加されます。新しい Audience エンドポイントのリファレンスドキュメントは[こちら](/ja/x-ads-api/audiences)から参照できます。今後も年内を通じて、本プロダクトのアップデートや改善を継続的にリリースしていく予定です。

以下のエンドポイントは、機能が重複しているため v4 では利用できなくなります（v3 では引き続き動作し、v3 が利用できなくなった時点で完全に**廃止**されます）。

* TON Upload:
  * GET accounts/:account&#95;id/tailored&#95;audience&#95;changes
  * GET accounts/:account&#95;id/tailored&#95;audience&#95;changes/:tailored&#95;audience&#95;change&#95;id
  * POST accounts/:account&#95;id/tailored&#95;audience&#95;changes
  * PUT accounts/:accounti&#95;d/tailored&#95;audiences/global&#95;opt&#95;out
* Real Time Audiences:
  * POST tailored&#95;audience&#95;memberships

最後に、バージョン 4 では、*すべての* [Tailored Audiences エンドポイント](/ja/x-ads-api/audiences)において、リクエストおよびレスポンスから `list_type` パラメータが削除されます。

***Settings Endpoints***

アカウント管理者は、ユーザー、アカウント、および税務設定を設定および更新できるようになりました。[User settings](/ja/x-ads-api/campaign-management#get-accounts-account-id-user-settings-user-id) は、特定の広告アカウントに対するユーザー固有の連絡先設定に対応します。[PUT accounts/:account&#95;id](/ja/x-ads-api/campaign-management#put-accounts-account-id) エンドポイントを使用すると、広告主はアカウントの名前と業種タイプを更新できるようになりました。最後に、[tax settings](/ja/x-ads-api/campaign-management#get-accounts-account-id-tax-settings) エンドポイントにより、付加価値税（VAT）が課される国の広告主は、会社名、住所、VAT ID、アカウントが広告主本人のものか、あるいは広告主に代わって出稿する代理店が所有しているかといった情報を更新できます。

念のため、カードをツイートに関連付ける際は、その `card_uri` の値を使用してください。次のリクエスト例を参照してください。

$ twurl -X POST -H ads-api.x.com &quot;/4/accounts/18ce54d4x5t/tweet?text=Version 4&amp;card&#95;uri=card://958225772740714496&quot;

**動画エンドポイント**

* v3 videos エンドポイント: `twurl -H ads-api.x.com "/3/accounts/18ce54d4x5t/videos"`

* v4 の動画向け Media Library エンドポイント: `twurl -H ads-api.x.com "/4/accounts/18ce54d4x5t/media_library?media_type=VIDEO"`

Media Library エンドポイントは videos エンドポイントと完全に機能が同等であり、加えて画像や GIF を扱う機能などもサポートします。パートナーの皆様には、あらゆるメディア管理に Media Library を一元的にご利用いただくようお願いします。

<div id="v3">
  ### v3
</div>

Ads API のバージョン 3 は、2018 年 2 月 1 日に[リリース](https://devcommunity.x.com/t/ads-api-version-3/100732)されました。Ads API のバージョン 2 は 2018 年 8 月 1 日をもってサポート終了となります。

このリリースには、新しい Audience Intelligence 製品、Media Library へのアクセス、およびカードワークフローの改善が含まれます。あわせて、[PUT accounts/:account&#95;id/targeting&#95;criteria](/ja/x-ads-api/campaign-management#get-accounts-account-id-targeting-criteria) エンドポイントの廃止を発表します。最後に、バージョン 3 では、いくつかの軽微なパラメータおよびレスポンスの変更と、バッチサイズ上限の引き下げが行われています。

[バージョン 2](https://devcommunity.x.com/t/ads-api-version-2/90360) と同様に、パートナーには移行期間として **6 か月** を設けています。**2018-08-01** に Ads API の v2 は停止されます。すべてのパートナーおよび開発者の皆様には、できるだけ早く v3 への移行をお願いいたします。

**Audience Intelligence**

Audience Intelligence は、特定の X オーディエンスにとって最も関連性の高いハッシュタグ、@ハンドル（@handles）、およびイベントに関するリアルタイムのインサイトを提供します。たとえば、米国在住の 18〜34 歳男性を指定すると、このオーディエンスでトレンドになっている #nintendoswitch、#cardinal、@ricegum などが表示されます。

Audience Intelligence の[エンドポイント](/ja/x-ads-api/audiences)は、以下の機能を提供します。

* 入力したオーディエンスを指定して、そのオーディエンスに最も関連性の高いハッシュタグ、@ハンドル、およびイベントを取得します。
* 入力したオーディエンスを指定して、年齢、性別、世帯収入などの主要なデモグラフィック情報を取得します。
* キーワードを指定して、そのキーワードに関するツイートボリュームの時系列データを取得します。

**Media Library**

[Media Library](/ja/x-ads-api/creatives#get-accounts-account-id-media-library) では、広告アカウント向けの画像、GIF、および動画を管理できます。これらのメディアオブジェクトは、ツイートやカードの作成に利用できます。また、複数のクリエイティブ間で再利用できるため、同じアセットを何度もアップロードする必要がなくなります。

ライブラリ内のオブジェクトは media&#95;key で識別されます。media&#95;key は、たとえば 13&#95;875943225764098048 のような形式の文字列型の値です。Ads API では、すべてのメディアで media&#95;key を使用する方向に移行しています。

**カードワークフローの改善**

すべてのカード関連エンドポイントが media&#95;key をサポートするようになりました。これにより、Media Library 内のオブジェクトを使用してカードを作成または更新できます。

さらに、[カードの詳細取得](/ja/x-ads-api/creatives#fetching-cards)用の新しい 2 つのエンドポイントを導入しました。これらのエンドポイントを使用すると、たとえば card&#95;uri または id を指定して、ツイートまたは予約ツイートで使用されているカードを検索できます。これはこれまで不可能でした。

  #### その他の変更

これらの新機能に加えて、バージョン 3 には次の変更が含まれます。

**新規**

* [GET insights/keywords/search](/ja/x-ads-api/audiences) エンドポイントのレスポンスに、入力キーワードに関連する 30 個の関連キーワードを含む related&#95;keywords 属性が追加されました。

**変更**

* ターゲティング条件のバッチサイズの上限が 500 になりました。
* card&#95;uri と preview&#95;url のレスポンス属性は相互排他的になりました。カードに card&#95;uri がある場合、preview&#95;url は null になります。カードに card&#95;uri がない場合は、preview&#95;url のみが返されます。
  * 2018-01-29 以降に作成されたすべてのカードには card&#95;uri が付きます。
  * バージョン 4 までに、既存のすべてのカードに card&#95;uri が付きます。
* 5:2 画像を使用したカードを *新規作成* することはできなくなりました。既存の 5:2 画像ベースのカードは引き続き機能しますが、パートナーの皆様には、（サポートされている場合）よりパフォーマンスの高い 1.91:1 または 1:1 のアスペクト比を使用するよう移行することを推奨します。

**削除**

* [PUT accounts/:account&#95;id/targeting&#95;criteria](/ja/x-ads-api/campaign-management#get-accounts-account-id-targeting-criteria) エンドポイントは利用できなくなりました。この変更を行ったのは、このエンドポイントの replace 動作が広告主に混乱を招き、1 回に 1 つのリソースを更新する他の PUT エンドポイントと一貫していなかったためです。代わりに、パートナーは [POST batch/accounts/:account&#95;id/targeting&#95;criteria](/ja/x-ads-api/campaign-management#post-batch-accounts-account-id-targeting-criteria) エンドポイントを使用してください。このエンドポイントは、1 回のリクエストでターゲティングの追加と削除の両方が可能になるなど、より高い柔軟性を提供します。
* funding instrument に対しては、paused レスポンス属性は返されなくなりました。代わりに、funding instrument が一時停止されているかどうかを判断するには、entity&#95;status レスポンス属性を参照してください。さらに、paused と cancelled は同じ値に対応しているため、レスポンスでは cancelled も返されなくなりました。
* [GET accounts/:account&#95;id/tweet/preview](/ja/x-ads-api/creatives#get-accounts-account-id-tweets) エンドポイントから card&#95;id パラメータを削除しました。
* 削除済みの Scheduled Tweets は取得できないため、with&#95;deleted パラメータはサポートされなくなりました。
* 次のエンドポイントから draft&#95;only パラメータを削除しました。これらのエンティティはドラフト状態になることがないためです。
  * [GET accounts/:account&#95;id/targeting&#95;criteria](/ja/x-ads-api/campaign-management#get-accounts-account-id-targeting-criteria)
  * [GET accounts/:account&#95;id/promoted&#95;tweets](/ja/x-ads-api/campaign-management#get-accounts-account-id-promoted-tweets)
  * [GET accounts/:account&#95;id/promoted&#95;accounts](/ja/x-ads-api/campaign-management#get-accounts-account-id-promoted-accounts)
  * [GET accounts/:account&#95;id/media&#95;creatives](/ja/x-ads-api/campaign-management#get-accounts-account-id-media-creatives)
  * [GET accounts/:account&#95;id/preroll&#95;call&#95;to&#95;actions](/ja/x-ads-api/creatives#get-accounts-account-id-preroll-call-to-actions)

**注記**

Video Website Cards と Scheduled Tweets は、どちらもベータ版を終了しました。ローンチ以降に Scheduled Tweets に対して行った変更については、[このスレッド](https://devcommunity.x.com/t/announcement-update-to-scheduled-tweets/94869) を参照してください。これには、Scheduled Tweets 向けの HTML [プレビュー](https://devcommunity.x.com/t/announcement-tweet-preview-improvements/96577) を生成する機能も含まれます。

* [GET accounts/:account&#95;id/promoted&#95;tweets](/ja/x-ads-api/campaign-management#get-accounts-account-id-promoted-tweets) エンドポイントの `line_item_id` パラメータは削除されました

* v2 エンドポイントでは 5:2 Website Card を新規作成することはできなくなります

* `data_type` レスポンス属性は返されなくなりました

* テイラードオーディエンスのデータ型の変更
* Tailored Audiences の `data_type` は、当社のすべてのレスポンスで `tailored_audiences` から `tailored_audience` に変更されました。
* Shared Tailored Audiences は現在、*API 専用*のベータ版として利用可能です。Shared Tailored Audiences を使用すると、1 つのオーディエンスを複数の広告アカウント間で利用できます。広告アカウント間で共有したい Tailored Audience の権限を管理するには、[POST accounts/:account&#95;id/tailored&#95;audiences/:tailored&#95;audience&#95;id/permissions](/ja/x-ads-api/audiences)（および関連する）エンドポイントを使用してください。
* 広告主アカウントのパフォーマンス[アナリティクス](/ja/x-ads-api/analytics)の取得方法が大幅に改善されました。
* [X Ads API のベストプラクティス](/ja/x-ads-api/analytics#best-practices)に準拠するため、[同期統計エンドポイント](/ja/x-ads-api/analytics#get-stats-accounts-account-id)から取得できるデータは、最大**7日分**までに制限されます。
* メトリクスの取得処理を簡略化するために、`metrics` パラメータを新しい `metric_groups` パラメータに置き換えました。開発者は、特定のリクエストについて、どのメトリクスグループを返却してほしいかを指定するだけで済みます。
  * 指定したエンティティに対して有効でない指標をリクエストした場合、それらはレスポンスから除外され、`null` 値として表現されます。*これらの指標は、アナリティクスのコスト上限には含まれません。*
* レスポンスは**大幅に単純化**され、メトリクスが当社のUIにおける表示方法とより密接に対応する形になりました。
  * 以前は、配信面ごと（検索の Promoted Tweets、タイムラインの Promoted Tweets、プロフィール &amp; ツイート詳細の Promoted Tweets、X Audience Platform）に個別の指標を公開していました。今後は、それぞれについて標準化された指標セットを返します。つまり、`promoted_tweet_timeline_impressions`、`promoted_tweet_search_impressions`、`promoted_tweets_profile_impressions`、`promoted_tweets_tpn_impressions` を返す代わりに、以下のいずれかのカテゴリを指定してリクエストした場合は、単一の指標 `impressions` として公開されます（これはすべての指標に適用されます）。
  * `ALL_ON_TWITTER`
  * `PUBLISHER_NETWORK`
  * リクエストを行うと、UI 上の値と一致させやすくするために、単一の `impressions` 指標が返されます。
  * `ALL_ON_TWITTER` と `PUBLISHER_NETWORK` の両方の data を取得するには、2 回クエリを実行する必要があります。これらは 1 回のリクエストでは結合できません。
* 開発者からのフィードバックに基づき、[非同期統計エンドポイント](/ja/x-ads-api/analytics#asynchronous-analytics) が新たに利用可能になりました。
  * 統計データを*非同期で*リクエストするための新しいエンドポイントセット。すぐには不要なデータや、過去データの取得に使用できます。
  * 新しい単一のエンドポイントを使って統計ジョブをキューに投入できます。リソースが許す限り、リクエストされたデータを取得します。
  * データが利用可能かどうかを確認するために、ジョブステータス用エンドポイントを呼び出すことができます。
  * データが利用可能になると、同期エンドポイントからのレスポンスと同じ構造の JSON レスポンスをダウンロードするためのピックアップ ID を提供します。
  * 1 つのジョブで最大 **90 日分**、最大 **20 件のエンティティ** までのデータをクエリできます。
* アナリティクス v1 への移行ガイドを参照してください。v0 メトリクスと v1 メトリクスのマッピングも記載されています。
* Sandbox の改善点 * Sandbox 環境で[複数のテスト広告アカウントを作成](/ja/x-ads-api/campaign-management#post-accounts)できるようになりました。 * Sandbox 環境においてのみ、1つのテスト広告アカウントに対して複数の資金手段を作成できるようになりました。これにより、すべての資金手段タイプでテストを行うことができます。以前はテストに利用できる資金手段は `CREDIT_CARD` のみでした。 * ベータ機能をテストしたい場合は、Sandbox 環境でアカウントごとに機能をオン／オフ切り替えできるようになり、テストニーズに柔軟に対応できます。

  ### v0

Ads API のバージョン 0 は 2013 年 2 月 21 日に正式にリリースされ、2016 年 10 月 31 日までサポートされていました。

バージョン 0 のすべてのアナリティクスエンドポイントは非推奨となり、2016 年 10 月 31 日以降は存在しなくなります。これらのエンドポイントは、バージョン 1 の 3 つのアナリティクスエンドポイントに置き換えられています。

リーチ見積もりエンドポイントは、バージョン 1 で新しい挙動になります。
