<div id="overview">
  ## 概要
</div>

毎月のように、私たちは X Ads API に変更を加え、いくつかの新機能をリリースしています。これらの変更のほとんどは常に後方互換性がありますが、年に数回は互換性を壊す破壊的変更が発生する傾向があります。Ads API における変更ペースの速さが、新機能の実装、非推奨対応、変更のテストといった開発サイクルに与える影響について、開発者の皆さまからフィードバックを受けてきました。私たちは Ads プラットフォームを利用する際の開発者エクスペリエンスを向上させたいと考えており、そのためにエンドポイントのバージョニングという概念を導入しました。

ここで取り上げるいくつかの概念について、以下のとおり定義します。

**Version**: Ads API リクエストの URL パスに含まれるバージョン番号を指します。例: GET /{version_number}/accounts。このスタイルのバージョニングは URI バージョニングとして知られています。

**Breaking Changes（破壊的変更）**: 破壊的変更とは、既存の機能を維持するために開発者リソースを必要とするあらゆる変更を指します。これには、必要な変更内容の調査に用いるリソース、非推奨となる機能やエンドポイントの判別、およびそれらすべての変更の最終的な実装にかかるリソースが含まれます。破壊的変更の例としては、次のようなものがあります。

* API リクエスト/レスポンス からパラメータを削除する

* 任意のパラメータやエンドポイントの名前を変更する

* 値の表現方法を変更する（preview&#95;url → card&#95;uri）

* エンドポイントの動作を変更する（例: 統計取得を非同期から同期に変更する）

* 任意パラメータや必須パラメータを追加/変更する（例: リクエスト内で名前を必須フィールドにする）

**Deprecation（非推奨）**: 非推奨となったバージョンやプロダクトはサポート対象外となり、開発者はこれらの API の利用を停止することが推奨されます。

**Sunset（サンセット）**: プロダクトまたは API がサンセットされると、それに対応するエンドポイント群には API 経由でアクセスできなくなります。

<div id="versioning-strategy">
  ## バージョニング戦略
</div>

この戦略の主な原則は次のとおりです。

1. すべての破壊的変更は新しいバージョンにまとめて行う

2. 新しいバージョンがアナウンスされた際、既存バージョンの非推奨期間は 6 か月とする

3. 任意の時点で、API は 2 つのバージョンからのリクエストを同時に受け付けるが、そのうち古い方のバージョンはサポート対象外となる

4. 新しいプロダクトをより迅速に採用できるようにするため、これらはバージョニングのリリースサイクルとは別に、随時リリースされる

5. すべての API レスポンスには、現在の API バージョンが設定された `x-current-api-version` ヘッダーが含まれ、さらに、非推奨の API エンドポイントを呼び出す際には `x-api-warn` ヘッダーも付与される。

API の破壊的変更（例: 複数の年齢バケットターゲティングの非推奨）を必要とする、本質的なプロダクト要件の変更が発生した場合には、この破壊的変更を告知するための 90 日前通知を行い、その通知から少なくとも 90 日が経過した後に、その破壊的変更をデプロイします。

<div id="v9">
  ### v9
</div>

本日 2021 年 3 月 3 日、X Ads API のバージョン 9（v9）がリリースされました。本リリースは、機能の整合性を高め、キャンペーン作成を簡素化し、Cards および Mobile App Promotion エンドポイントに対する重要なアップデートを導入することを目的としています。

これまでのバージョンと同様に、v9 への移行には 6 か月間の移行期間を設けています。2021 年 8 月 31 日をもって、既存の Ads API のバージョン 8（v8）はご利用いただけなくなります。サービス中断を回避するため、すべての開発者の皆様には、できるだけ早く Ads API の最新バージョンへ移行されることをお勧めします。

<Note>
  **Note:** 本リリースに伴い、Ads API のバージョン 7（v7）はサポート終了となり、ご利用いただけなくなりました。
</Note>

詳細については、[Developer Forum 上のお知らせ](https://devcommunity.x.com/t/ads-api-version-9/150316)をご覧ください。

<div id="v5">
  ### v5
</div>

本日 2019 年 2 月 28 日、X はスケールと効率性の向上に焦点を当てたアップデートを含む Ads API v5 をリリースしました。

このリリースには、指定した期間中にどのエンティティがアクティブだったかを特定するための新しいエンドポイント、Media Creatives（X Audience Platform 上のインストリーム動画および画像）の統計情報、カード URI によって&#95;複数&#95;のカードを取得する機能、ターゲティング条件やその他のエンティティを取得する方法の柔軟性向上が含まれています。加えて、いくつかのバグ修正を行い、パラメータ名およびレスポンス属性の更新を行いました。最後に、メディア以外のアプリカードと POST `accounts/:account_id/account_media` エンドポイントは非推奨となりました。

これまでのバージョンと同様に、v5 への移行期間として 6 か月間の移行期間が設けられます。**2019-08-28** 以降、Ads API のバージョン 4 は利用できなくなります。サービスの中断を避けるため、すべてのパートナーには、可能な限り速やかに最新バージョンの API へ移行いただくことを推奨します。*Ads API のバージョン 3 はサポート期間が終了しており、すでに利用できません。*

#### 新規

**どのエンティティがアクティブかの判定**

[Active Entities](/ja/x-ads-api/analytics#active-entities-2) エンドポイントは、広告エンティティのアナリティクス指標が変更されたかどうかを示します。アナリティクス用エンドポイントと組み合わせて使用することを目的としており、Active Entities はエンティティタイプと日付範囲（最大 90 日間）を指定することで動作し、お使いのプラットフォームがアナリティクスを取得すべきエンティティ ID の配列を返します。返されなかった ID については、その後のアナリティクスリクエストでクエリを行うべきではありません。

このエンドポイントは、次のエンティティタイプをサポートします：`CAMPAIGN`、`FUNDING_INSTRUMENT`、`LINE_ITEM`、`MEDIA_CREATIVE`、`PROMOTED_TWEET`。

**`MEDIA_CREATIVE` の統計**

Ads API のアナリティクスエンドポイントでは、Media Creative エンティティ向けの指標が取得できるようになりました。Media Creative は、インストリーム広告や X Audience Platform 上の画像をプロモートするためのエンティティです。X Ads UI では、Media Creative の指標は「In-stream videos」タブおよび「Display creatives」タブに表示されます。[同期](/ja/x-ads-api/analytics#get-stats-accounts-account-id)および[非同期](/ja/x-ads-api/analytics#asynchronous-analytics)の両方のアナリティクスエンドポイントで、`MEDIA_CREATIVE` エンティティ enum がサポートされるようになりました。

**複数カードの取得**

カード URI の値で単一のカードを取得するために設計されたエンドポイントの [v3 リリース](https://devcommunity.x.com/t/ads-api-version-3/100732) を拡張し、[GET accounts/:account&#95;id/cards/all](/ja/x-ads-api/creatives#cards-fetch) エンドポイントを使用して *複数* のカードを取得できるようになりました。これにより、カードごとに個別のリクエストを送信する代わりに、1 回のリクエストで最大 200 枚のカードを取得できます。

注意点は次の 2 つです。

1. URL パスは現在 `accounts/:account_id/cards/all` です。（以前のパスは利用できません。）これは、ID でカードを取得するために設計された [エンドポイント](/ja/x-ads-api/creatives#cards-fetch) と整合性を保つためです。
2. 必須のリクエストパラメータ名は、card&#95;uris（複数形）になりました。

**取得の柔軟性向上**

[GET accounts/:account&#95;id/targeting&#95;criteria](/ja/x-ads-api/campaign-management#get-accounts-account-id-targeting-criteria) エンドポイントで、複数の Line Item ID をサポートするようになりました。最大 200 個の ID を受け付ける line&#95;item&#95;ids パラメータが必須です。以前は単一の Line Item しか受け付けておらず、同期が難しい状況でした。この変更により、より多くのターゲティング情報を短時間で取得できるようになりました。

次のエンドポイントも複数の Line Item ID をサポートするようになりましたが、これらでは line&#95;item&#95;ids パラメータは任意です。

* [GET accounts/:account&#95;id/line&#95;item&#95;apps](https://developer.x.com/en/docs/x-ads-api/campaign-management/api-reference/line-item-apps#get-accounts-account-id-line-item-apps)
* [GET accounts/:account&#95;id/media&#95;creatives](/ja/x-ads-api/campaign-management#get-accounts-account-id-media-creatives)
* [GET accounts/:account&#95;id/promoted&#95;accounts](/ja/x-ads-api/campaign-management#get-accounts-account-id-promoted-accounts)
* [GET accounts/:account&#95;id/preroll&#95;call&#95;to&#95;actions](/ja/x-ads-api/creatives#preroll-call-to-actions)

<div id="changed">
  #### 変更点
</div>

**ドラフトキャンペーンおよびラインアイテムの取得**

ドラフトキャンペーンとラインアイテムの取得方法が更新されました。現在は、`with_draft(boolean)` パラメータを `true` に設定すると、ドラフトと非ドラフトの両方のエンティティが返されます。これは、削除済みエンティティの取得方法（`with_deleted` を使用）と一貫しています。以前は、ドラフトと非ドラフトの両方のエンティティを取得するには少なくとも 2 回のリクエストが必要でしたが、現在は 1 回の API コールで実行できます。

| **v4** | **v5** |
| :--- | :--- | :--- |
| `draft_only` | `with_draft` |     |

**Network Activation Duration ターゲティング**

Ads API は、Network Activation Duration ターゲティングを追加した後に、レスポンス内のターゲティングタイプに `_IN_SEC` というサフィックスが含まれてしまう表示上の不具合を解消しました。Network Activation Duration は常に月単位で表現されるため、秒を示す参照があることは混乱を招いていました。この修正により、表現が一貫したものとなり、混乱が軽減されます。

| **v4** | **v5** |
| :--- | :--- | :--- |
| `NETWORK_ACTIVATION_DURATION_IN_SEC` | `NETWORK_ACTIVATION_DURATION` |     |

**合計件数とカーソル**

v5 では、`with_total_count` と `cursor` は排他的です。リクエスト内で両方を指定すると、`EXCLUSIVE_PARAMETERS` エラーコードが返されます。v5 以前は、`cursor` が指定されている場合、`with_total_count` は無視されていました。この変更により、両者の関係が明示的になりました。

<div id="removed">
  #### 削除される項目
</div>

Ads API のレスポンスから、preview&#95;url、account&#95;id、parent&#95;ids の 3 つのフィールドが削除されます。これら 3 つに対する開発側の対応工数は最小限です。

* v4 では、カード用の preview&#95;url レスポンスパラメータは常に null であると告知されていました。このマイグレーションの最終ステップとして、すべてのカードのレスポンスから preview&#95;url を削除します。
* 次のリソースについては、広告アカウント ID が URL と request.params の両方にすでに含まれているため、account&#95;id レスポンス属性は削除されます。（この一覧から funding instruments を除外しているのは意図的です。可能な限り、親 ID はレスポンスオブジェクトに含まれるべきであり、アカウント ID は funding instruments に対する親エンティティであるためです。）
  * アカウントメディア
  * アプリイベントプロバイダ
  * アプリイベントタグ
  * キャンペーン
  * カード
  * ラインアイテム
  * プロモート対象ユーザー
  * ターゲティング条件
* [GET accounts/:account&#95;id/targeting&#95;criteria](/ja/x-ads-api/campaign-management#get-accounts-account-id-targeting-criteria) リクエストでは、parent&#95;ids フィールドは常に空の配列であったため、今後は返されません。

**非メディアアプリカード**

v5 では、非メディアアプリカードはサポートされなくなります。 [以前](https://devcommunity.x.com/t/deprecation-announcement-app-download-cards/87807)に、非メディアアプリカードを作成または編集する機能は削除されました。今回、このリソース用の残りのエンドポイントが非推奨となります。

* 注: これは画像および動画のアプリダウンロードカードには**影響しません**。

**アカウントメディアの作成**

POST accounts/:account&#95;id/account&#95;media エンドポイントは v5 では利用できなくなります。このリソースに対する他のエンドポイントには影響は&#95;ありません&#95;。この変更の理由は、[Media Library](/ja/x-ads-api/creatives#media-library) にメディアを追加する際、そのアセットが&#95;自動的に&#95;アカウントメディアエンティティとして追加されるケースがあり、すでに存在するアセットをアカウントメディアリソースに追加しようとするとエラーになるためです。これは次の場合に発生します。

* `AMPLIFY_VIDEO` アセットを Media Library に追加すると、自動的に `PREROLL` クリエイティブタイプのアカウントメディアアセットとして追加されます。
* 特定のサイズの画像を Media Library に追加すると、自動的にアカウントメディアアセットとして追加されます。クリエイティブタイプ（例: `INTERSTITIAL`）は画像のサイズに依存します。（サイズについては、[Enumerations](/ja/x-ads-api/introduction) ページを参照してください。）

Ads API バージョン 4 を本日 2018 年 8 月 28 日にリリースしました。

このリリースでは、より堅牢なオーディエンス処理バックエンドを基盤とした新しい API インターフェースを含む、[Audiences](/ja/x-ads-api/audiences) プロダクトの改善を行いました。バージョン 4 には、ユーザー、アカウント、および税務設定を管理するための一連のエンドポイントも含まれています。加えて、accounts/:account&#95;id/videos エンドポイントは非推奨となります。このリリースには、そのほかにもいくつかの軽微なパラメータおよびレスポンス名の変更が含まれます。

バージョン 3 と同様に、6 か月間の移行期間を設けています。**2019-02-28** をもって、Ads API バージョン 3 は利用できなくなります。サービスの中断を避けるため、すべてのパートナーの皆さまには、できるだけ早く最新バージョンの API へ移行していただくことを推奨します。バージョン管理戦略の詳細については、[Versions](/ja/x-ads-api/introduction) ページをご覧ください。

<div id="new">
  #### New
</div>

***Audience API***

新しい Audiences API は、新しいオーディエンス処理バックエンド上に構築されており、堅牢性と信頼性が向上しています。この新しいエンドポイントにより、パートナーは 1 人のユーザーに対して複数のユーザー識別子タイプを提供できるようになり、その結果、マッチングに利用できるシグナルが追加されます。新しい Audience エンドポイントのリファレンスドキュメントは[こちら](/ja/x-ads-api/audiences)をご覧ください。今年残りの期間を通じて、このプロダクトのアップデートと改善を継続的にリリースしていく予定です。

以下のエンドポイントは、機能が重複しているため v4 では利用できなくなります（v3 では引き続き動作し、v3 が利用できなくなった時点で完全に**廃止**されます）。

* TON Upload:
  * GET accounts/:account&#95;id/tailored&#95;audience&#95;changes
  * GET accounts/:account&#95;id/tailored&#95;audience&#95;changes/:tailored&#95;audience&#95;change&#95;id
  * POST accounts/:account&#95;id/tailored&#95;audience&#95;changes
  * PUT accounts/:accounti&#95;d/tailored&#95;audiences/global&#95;opt&#95;out
* Real Time Audiences:
  * POST tailored&#95;audience&#95;memberships

最後に、バージョン 4 では、`list_type` パラメータは&#95;すべての&#95; [Tailored Audiences エンドポイント](/ja/x-ads-api/audiences)のリクエストおよびレスポンスから削除されます。

***Settings Endpoints***

アカウント管理者がユーザー、アカウント、および税務設定を設定・更新できるようになりました。[User settings](/ja/x-ads-api/campaign-management#get-accounts-account-id-user-settings-user-id) は、特定の広告アカウントに対するユーザー固有の連絡先設定に対応します。[PUT accounts/:account&#95;id](/ja/x-ads-api/campaign-management#put-accounts-account-id) エンドポイントを使用すると、広告主はアカウントの名前と業種タイプを更新できるようになりました。最後に、[tax settings](/ja/x-ads-api/campaign-management#get-accounts-account-id-tax-settings) エンドポイントでは、付加価値税（VAT）が課税される国の広告主が、会社名、住所、VAT ID、アカウントが広告主本人に帰属するか、あるいは広告主に代わって広告を行う代理店に帰属するかといった情報を更新できます。

<div id="v3">
  ### v3
</div>

Ads API のバージョン 3 は、2018 年 2 月 1 日に[リリースされました](https://devcommunity.x.com/t/ads-api-version-3/100732)。Ads API のバージョン 2 は 2018 年 8 月 1 日にサポート終了となります。

このリリースには、新しい Audience Intelligence プロダクト、Media Library へのアクセス、カードワークフローの改善が含まれます。また、[PUT accounts/:account&#95;id/targeting&#95;criteria](/ja/x-ads-api/campaign-management#get-accounts-account-id-targeting-criteria) エンドポイントの非推奨化も発表しています。最後に、バージョン 3 では、いくつかの軽微なパラメータおよびレスポンスの変更と、バッチサイズ上限の引き下げがあります。

[バージョン 2](https://devcommunity.x.com/t/ads-api-version-2/90360) のときと同様に、パートナーの皆さまには移行期間として **6 か月** を設けています。**2018-08-01** に Ads API の v2 は停止されます。すべてのパートナーおよび開発者の方には、できるだけ早く v3 への移行を強くお勧めします。

**Audience Intelligence**

Audience Intelligence は、特定の X オーディエンスにとって最も関連性の高いハッシュタグ、@handle、イベントに関するリアルタイムのインサイトを提供します。たとえば「米国在住・男性 18〜34 歳」と入力すると、このオーディエンスの間で #nintendoswitch、#cardinal、@ricegum などがトレンドになっていることが分かります。

Audience Intelligence の[エンドポイント](/ja/x-ads-api/audiences)では、次の機能を利用できます。

* 入力オーディエンスを指定し、最も関連性の高いハッシュタグ、@handle、イベントを取得する。
* 入力オーディエンスを指定し、年齢、性別、世帯収入などの主要なデモグラフィック情報を取得する。
* キーワードを指定し、そのキーワードに関するツイート数の時系列データを取得する。

**Media Library**

[Media Library](/ja/x-ads-api/creatives#get-accounts-account-id-media-library) は、広告アカウントにおける画像、GIF、動画を管理する機能を提供します。これらのメディアオブジェクトは、ツイートおよびカードの作成に利用できます。また、複数のクリエイティブで再利用できるため、同じアセットを何度もアップロードする必要がなくなります。

ライブラリ内のオブジェクトは media&#95;key で識別されます。media&#95;key は、たとえば 13&#95;875943225764098048 のような形式の文字列型の値です。Ads API では、すべてのメディアに対して media&#95;key を使用する方向に移行しています。

**カードワークフローの改善**

すべてのカード関連エンドポイントが media&#95;key をサポートするようになりました。これにより、Media Library 内のオブジェクトを使用してカードを作成または更新できるようになります。

さらに、新たに 2 つの[カード詳細取得](/ja/x-ads-api/creatives#fetching-cards)用エンドポイントを導入しています。これらのエンドポイントは、たとえば card&#95;uri または id を指定することで、ツイートまたは予約ツイートで使用されているカードを検索するために利用できます。以前はこれは不可能でした。

<div id="other-changes">
  #### その他の変更
</div>

これらの新機能に加えて、バージョン 3 では次の変更を行っています。

**新規**

* [GET insights/keywords/search](/ja/x-ads-api/audiences) エンドポイントのレスポンスに、入力されたキーワードに関連する 30 個の関連キーワードを含む `related_keywords` 属性が追加されました。

**変更**

* ターゲティング条件バッチの最大サイズは 500 になりました。
* `card_uri` と `preview_url` のレスポンス属性は相互排他になりました。カードに `card_uri` がある場合、`preview_url` は `null` になります。カードに `card_uri` がない場合は、`preview_url` のみが返されます。
  * 2018-01-29 以降に作成されたすべてのカードには `card_uri` が設定されます。
  * バージョン 4 までに、既存のすべてのカードに `card_uri` が設定されます。
* 5:2 画像を使用したカードを新規に *作成* することはできなくなりました。既存の 5:2 画像ベースのカードは引き続き動作しますが、パートナーの皆様には、（サポートされている場合）パフォーマンスの高い 1.91:1 または 1:1 のアスペクト比の利用への移行を推奨します。

**削除**

* [PUT accounts/:account&#95;id/targeting&#95;criteria](/ja/x-ads-api/campaign-management#get-accounts-account-id-targeting-criteria) エンドポイントは利用できなくなりました。この変更は、このエンドポイントのリプレース動作が広告主に混乱を与え、1 回に 1 つのリソースを更新する他の PUT エンドポイントと一貫していなかったために行いました。代わりに、1 回のリクエストでターゲティングの追加と削除の両方が可能になるなど、より高い柔軟性を提供する [POST batch/accounts/:account&#95;id/targeting&#95;criteria](/ja/x-ads-api/campaign-management#post-batch-accounts-account-id-targeting-criteria) エンドポイントを使用してください。
* `paused` レスポンス属性は、資金管理オブジェクトには返されなくなりました。代わりに、その資金管理オブジェクトが一時停止されているかどうかを判断するには、`entity_status` レスポンス属性を参照してください。さらに、`paused` と `cancelled` は同じ値に対応しているため、`cancelled` もレスポンスでは返されなくなりました。
* [GET accounts/:account&#95;id/tweet/preview](/ja/x-ads-api/creatives#get-accounts-account-id-tweets) エンドポイントから `card_id` パラメータを削除しました。
* 削除された予約済みツイートを取得することはできないため、`with_deleted` パラメータはサポートされなくなりました。
* 次のエンドポイントでは、これらのエンティティがドラフト状態になることはないため、`draft_only` パラメータを削除しました。
  * [GET accounts/:account&#95;id/targeting&#95;criteria](/ja/x-ads-api/campaign-management#get-accounts-account-id-targeting-criteria)
  * [GET accounts/:account&#95;id/promoted&#95;tweets](/ja/x-ads-api/campaign-management#get-accounts-account-id-promoted-tweets)
  * [GET accounts/:account&#95;id/promoted&#95;accounts](/ja/x-ads-api/campaign-management#get-accounts-account-id-promoted-accounts)
  * [GET accounts/:account&#95;id/media&#95;creatives](/ja/x-ads-api/campaign-management#get-accounts-account-id-media-creatives)
  * [GET accounts/:account&#95;id/preroll&#95;call&#95;to&#95;actions](/ja/x-ads-api/creatives#get-accounts-account-id-preroll-call-to-actions)

**注記**

Video Website Cards と予約済みツイートは、どちらもベータ版ではなくなりました。ローンチ以降に予約済みツイートに対して行った変更については、[こちらのスレッド](https://devcommunity.x.com/t/announcement-update-to-scheduled-tweets/94869) を参照してください。ここには、予約済みツイート向けの HTML [プレビュー](https://devcommunity.x.com/t/announcement-tweet-preview-improvements/96577) を生成する機能も含まれています。

* PUT accounts/:account&#95;id/promoted&#95;tweets エンドポイントでの `display_properties` は廃止されました。この値はレスポンスの一部としても返されなくなります

* 前項の結果として、promoted&#95;tweets エンティティを更新 (PUT) することはできなくなりました

* [GET accounts/:account&#95;id/promoted&#95;tweets](/ja/x-ads-api/campaign-management#get-accounts-account-id-promoted-tweets) エンドポイントでの `line_item_id` パラメータは削除されました

* v2 エンドポイントでは 5:2 Website Cards を新規作成できなくなります

* `data_type` レスポンス属性は返されなくなりました

* テイラードオーディエンスのデータ型の変更
* Tailored Audiences の `data_type` は、すべてのレスポンスで `tailored_audiences` から `tailored_audience` に変更されました。
* Shared Tailored Audiences は現在、*API 専用* のベータ版として利用可能です。この機能を使用すると、1 つのオーディエンスを複数の広告アカウント間で共用できます。複数の広告アカウント間で共有したい tailored audience の権限を管理するには、[POST accounts/:account&#95;id/tailored&#95;audiences/:tailored&#95;audience&#95;id/permissions](/ja/x-ads-api/audiences)（および関連エンドポイント）を使用してください。
* 広告主アカウントのパフォーマンス[分析](/ja/x-ads-api/analytics)データの取得方法が大幅に改善されました。
* [X Ads API のベストプラクティス](/ja/x-ads-api/analytics#best-practices)に合わせて、[同期統計エンドポイント](/ja/x-ads-api/analytics#get-stats-accounts-account-id)で取得できる data は、今後は**最大7日分**までに制限されます。
* メトリクスの取得を簡素化するため、`metrics` パラメータを新しい `metric_groups` パラメータに置き換えました。開発者は、特定のリクエストに対してどのメトリクスグループを返してほしいかを明示的に指定する必要があります。
  * あるエンティティに対して不適切なメトリクスをリクエストした場合、そのメトリクスはレスポンスから除外され、`null` 値として表現されます。*これらのメトリクスは、アナリティクスのコスト上限にはカウントされません。*
* レスポンスは**大幅に簡素化され**、メトリクスの公開方法がUIでの表示形式とより整合するようになりました。
  * 以前は、各掲載場所ごとに個別の指標（検索内の Promoted Tweets、タイムライン内の Promoted Tweets、プロフィールおよびツイート詳細内の Promoted Tweets、X Audience Platform）を提供していました。今後は、それぞれについて標準化された指標セットを返します（`promoted_tweet_timeline_impressions`、`promoted_tweet_search_impressions`、`promoted_tweets_profile_impressions`、`promoted_tweets_tpn_impressions` を返す代わりに）、以下のいずれかのカテゴリーでリクエストされた場合に、単一の指標 `impressions` として返されます（これはすべての指標に適用されます）。
  * `ALL_ON_TWITTER`
  * `PUBLISHER_NETWORK`
  * リクエストを行うと、UI 上の値と照合しやすくするために、単一の `impressions` 指標のみが返されます。
  * `ALL_ON_TWITTER` と `PUBLISHER_NETWORK` の両方の data を取得するには、2 回クエリを実行する必要があります。これらを 1 回のクエリで結合することはできません。
* 開発者の皆さまからのフィードバックを受けて、[非同期統計エンドポイント](/ja/x-ads-api/analytics#asynchronous-analytics) の提供を開始しました。
  * 統計情報を*非同期で*リクエストするための新しいエンドポイント群。すぐには不要なデータや履歴データを取得する際に利用できます。
  * 新しい単一のエンドポイントを使って統計ジョブをキューに登録します。リソース状況に応じて、リクエストされたdataを取得します。
  * dataが利用可能かどうかを確認するために、ジョブステータスエンドポイントをクエリできます。
  * dataが利用可能になると、同期エンドポイントのレスポンスと同等の内容を持つJSONレスポンスをダウンロードするための取得用IDを提供します。
  * 1つのジョブで最大**90日分**、最大**20個のエンティティ**のdataをクエリできます。
* v0 メトリクスから v1 メトリクスへのマッピングを含む analytics v1 の移行ガイドをご覧ください
* Sandbox の改善 * Sandbox 環境で[複数のテスト広告アカウントを作成](/ja/x-ads-api/campaign-management#post-accounts)できるようになりました。 * Sandbox 環境内のテスト広告アカウントに対して複数の資金手段を作成できるようになりました。これにより、すべての資金手段タイプでテストできます。以前は、テストに使用できる資金源は `CREDIT_CARD` のみでした。 * ベータ機能をテストしたい場合は、Sandbox 環境でアカウントごとに機能のオン／オフを切り替えて、テスト要件に合わせられるようになりました。
