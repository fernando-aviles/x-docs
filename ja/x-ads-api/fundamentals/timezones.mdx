<div id="timezones-accounts-and-billing">
  ## タイムゾーン、アカウント、および請求
</div>

日時値は常に UTC 時刻で返されます（日時値の末尾にある Z は UTC を示します）。POST または PUT コマンドでは、ISO 8601 標準形式のタイムゾーン表記を用いることで、任意のタイムゾーンの日時を指定できます。時刻は [ISO-8601](http://en.wikipedia.org/wiki/ISO_8601) のサブセットで表現されます。より具体的には、本 API の日付フォーマットに対応する strptime 文字列は `%Y-%m-%dT%l:%M:%S%z` です。公式な請求数値が確定される基準となる実際の時刻は、広告主のアカウントのタイムゾーンによって決定されます。

アカウントレベルで API を呼び出すとき（[GET accounts](/ja/x-ads-api/campaign-management#accounts)）、タイムゾーン情報は次のような形式で取得されます。

```json
    {
      "request": {
        "params": {
          "account_id": "18ce54d4x5t"
        }
      },
      "data": {
        "name": "API McTestface",
        "business_name": null,
        "timezone": "America/Los_Angeles",
        "timezone_switch_at": "2016-07-21T07:00:00Z",
        "id": "18ce54d4x5t",
        "created_at": "2016-07-21T22:42:09Z",
        "salt": "54cb7b5a34183f77d82dd6d0f4329691",
        "updated_at": "2017-09-09T06:42:14Z",
        "business_id": null,
        "approval_status": "ACCEPTED",
        "deleted": false
      }
    }
```

これには 2 つのタイムゾーン値が含まれます。`timezone`（概要については [Wikipedia の timezones ページ](https://en.wikipedia.org/wiki/Tz_database#Names_of_time_zones) を参照）と `timezone_switch_at` です。`timezone_switch_at` は UTC タイムゾーン（+00:00）で指定されますが、常に指定されたタイムゾーンの午前 0 時を表します。

広告主のタイムゾーンは API 経由では変更できません。この属性は、X の広告主担当アカウントマネージャーによって契約／請求レベルで設定されます。

アカウントが America/Los&#95;Angeles タイムゾーンから新しいローカル値に切り替わる日には、データにギャップが発生するため、レポートを作成したりアナリティクスのエンドポイントにクエリを実行したりする際には `timezone_switch_at` の値に注意してください。

<div id="specifying-datetime-values-with-timezone">
  ### タイムゾーン付き日時値の指定
</div>

日時値は常に UTC 時刻で返されます（日時値の末尾にある `Z` によって示されます）。POST または PUT コマンドでは、[ISO 8601 standard](http://en.wikipedia.org/wiki/ISO_8601) のタイムゾーン形式を使用することで、任意のタイムゾーンで日時を指定できます。たとえば、`2017-07-10T08:00:00-0800` は有効な入力値であり、自動的に UTC の `2017-07-10T16:00:00Z` に変換されます。

`granularity` が `DAY` または `TOTAL` の analytics エンドポイントを使用する場合、`start_time` の値は、アカウント保有者のローカルタイムゾーンにおける対象日の午前 0 時で指定する必要があります。使用されるタイムゾーンオフセットは、対象日ではなく当日のオフセットになります。たとえば、America/Los&#95;Angeles の広告アカウントが太平洋夏時間（Pacific Daylight Time）の期間にある場合、UTC オフセットは -0700 です。したがって、analytics リクエストでは、時刻は `start_time=2017-05-21T07:00:00Z` または `start_time=2017-05-21T00:00:00-0700` のように指定します。広告アカウントが Asia/Tokyo にあり、オフセットが常に +09:00 の場合、値は `start_time=2017-05-20T15:00:00Z` または `start_time=2017-05-21T00:00:00+0900` のように指定します。

<div id="accepted-utc-offset-formats">
  ### 使用可能なUTCオフセット形式
</div>

[ISO 8601 Time zone designators](http://en.wikipedia.org/wiki/ISO_8601#Time_zone_designators) を参照してください。

サポートされている形式: `Z`, `-HHMM`, `+HHMM`, `-HH:MM`, `+HH:MM`, `-HH`, `+HH`
