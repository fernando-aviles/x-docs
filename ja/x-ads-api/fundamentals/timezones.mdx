<div id="timezones-accounts-and-billing">
  ## タイムゾーン、アカウント、課金
</div>

日時の値は常に UTC 時刻（日時値の末尾にある Z で示されます）で返されます。POST または PUT コマンドでは、タイムゾーンについて ISO 8601 の標準形式を用いることで、任意のタイムゾーンで日時を指定できます。時刻は [ISO-8601](http://en.wikipedia.org/wiki/ISO_8601) のサブセットを使って表現されます。より具体的には、当社の日付形式に対応する strptime 形式の文字列は `'%Y-%m-%dT%l:%M:%S%z'` です。広告主アカウントのタイムゾーンによって、正式な課金数値が確定される実際の時刻が決まります。

アカウントレベルで API を問い合わせると（[GET accounts](/ja/x-ads-api/campaign-management#accounts)）、次のようなタイムゾーン情報が取得されます。

```json
    {
      "request": {
        "params": {
          "account_id": "18ce54d4x5t"
        }
      },
      "data": {
        "name": "API McTestface",
        "business_name": null,
        "timezone": "America/Los_Angeles",
        "timezone_switch_at": "2016-07-21T07:00:00Z",
        "id": "18ce54d4x5t",
        "created_at": "2016-07-21T22:42:09Z",
        "salt": "54cb7b5a34183f77d82dd6d0f4329691",
        "updated_at": "2017-09-09T06:42:14Z",
        "business_id": null,
        "approval_status": "ACCEPTED",
        "deleted": false
      }
    }
```

これには2つのタイムゾーン値が含まれます：`timezone`（概要については [Wikipedia の timezones](https://en.wikipedia.org/wiki/Tz_database#Names_of_time_zones) を参照）と `timezone_switch_at` です。`timezone_switch_at` は UTC タイムゾーン（+00:00）で指定されますが、常に指定されたタイムゾーンにおける午前 0 時を表します。

広告主のタイムゾーンは API 経由では変更できません。この属性は、X における広告主のアカウントマネージャーによって、契約／請求レベルで設定されます。

アカウントが America/Los&#95;Angeles タイムゾーンから新しいローカル値に切り替わる日に時刻のずれが発生するため、レポートを作成したりアナリティクス用エンドポイントにクエリを送信したりする際には、`timezone_switch_at` の値に注意してください。

<div id="specifying-datetime-values-with-timezone">
  ### タイムゾーン付き日時値の指定
</div>

日時値は常に UTC 時刻で返されます（日時値の末尾にある `Z` が UTC を示します）。POST または PUT コマンドでは、任意のタイムゾーンの日時を、タイムゾーンを表す [ISO 8601 standard](http://en.wikipedia.org/wiki/ISO_8601) 形式を使用して指定できます。たとえば、`2017-07-10T08:00:00-0800` は有効な入力値であり、自動的に UTC の値 `2017-07-10T16:00:00Z` に変換されます。

`granularity` が `DAY` または `TOTAL` の analytics エンドポイントを使用する場合、`start_time` 値は、アカウント保有者のローカルタイムゾーンにおける対象日の午前 0 時として指定する必要があります。使用されるタイムゾーンオフセットは、「対象日」ではなく「現在の日付」のオフセットになります。たとえば、America/Los&#95;Angeles の広告アカウントが Pacific Daylight Time 期間中であれば、UTC オフセットは -0700 です。したがって、analytics リクエストでは、時刻は `start_time=2017-05-21T07:00:00Z` または `start_time=2017-05-21T00:00:00-0700` のように指定する必要があります。広告アカウントが Asia/Tokyo にあり、オフセットが常に +09:00 の場合、値は `start_time=2017-05-20T15:00:00Z` または `start_time=2017-05-21T00:00:00+0900` のように指定します。

  ### 利用可能なUTCオフセット形式
</div>

サポートされている形式: `Z`, `-HHMM`, `+HHMM`, `-HH:MM`, `+HH:MM`, `-HH`, `+HH`
