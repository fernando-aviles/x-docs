1 つのアカウントに紐付けられるキャンペーン数の上限拡大と、そのアカウントに関連するすべてのエンティティを効率的に取得できるようにするために、Advertiser API では多くの GET エンドポイントでページネーションがサポートされるようになりました。ページネーションの仕組みは使いやすく、[Using cursors to navigate collections](https://developer.x.com/en/docs/x-api/v1/pagination) で説明されている REST API のカーソルベースのページネーションと非常によく似ています。

<div id="getting-started">
  ## はじめに
</div>

一部の GET リクエストでは、オプションのクエリパラメーター `cursor` と `count` を受け付けるようになりました。レスポンスに含まれるエンティティ数が `count` を超える場合、これらのエンドポイントは先頭の `count` 個のエンティティと、レスポンス JSON 内の `next_cursor` キーを返します。

`GET https://ads-api.x.com/5/accounts/abc1/campaigns?count=50`

```json
{
  "data": \[...\],
  "next_cursor": "c-3yvu1pzhd3i7",
  "request": {...}
}
```

次の一連のレスポンスを取得するには、クエリパラメーターに `cursor` を追加します。

`GET https://ads-api.x.com/5/accounts/abc1/campaigns?cursor=c-3yvu1pzhd3i7&count=50`

```json
{
  "data": \[...\],
  "next_cursor": "c-3w3zdyg8ywan",
  "request": {...}
}
```


<div id="going-deeper">
  ## さらに詳しく
</div>

ほとんどのエンドポイントでは、`count` の最大値は **1,000**、最小値は **1**、デフォルト値は **200** です。

`next_cursor` によって提供される値は常に文字列型であり、不透明な値として扱う必要があります。実装は変更される可能性があります。現在の結果セットのページで `count` 未満のエンティティしか返されなかった場合、`next_cursor` の値は `null` になります。

**注:** analytics エンドポイントは、この形式のページネーションをサポートしていません。stats エンドポイントでのページングは、期間を指定することでサポートされています。詳しくは、各エンドポイントのドキュメントを参照してください。
