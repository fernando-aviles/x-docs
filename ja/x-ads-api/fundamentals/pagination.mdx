より多くのキャンペーンを扱えるようにし、アカウントに関連付けられたすべてのエンティティを効率的に取得できるようにするために、Advertiser API は現在、多くの GET エンドポイントでページネーションをサポートしています。このページネーションの仕組みは使いやすく、[Using cursors to navigate collections](https://developer.x.com/en/docs/x-api/v1/pagination) で説明されている REST API のカーソルベースのページネーションと非常によく似ています。

<div id="getting-started">
  ## はじめに
</div>

特定の GET リクエストについて、オプションのクエリパラメータとして `cursor` と `count` が利用できるようになりました。レスポンスに含まれるエンティティが `count` を超える場合、これらのエンドポイントは、先頭の `count` 個のエンティティと、レスポンス JSON 内の `next_cursor` キーを返します。

`GET https://ads-api.x.com/5/accounts/abc1/campaigns?count=50`

```json
{
  "data": \[...\],
  "next_cursor": "c-3yvu1pzhd3i7",
  "request": {...}
}
```

次の一連のレスポンスを取得するには、クエリパラメータに `cursor` を追加します。

`GET https://ads-api.x.com/5/accounts/abc1/campaigns?cursor=c-3yvu1pzhd3i7&count=50`

```json
{
  "data": \[...\],
  "next_cursor": "c-3w3zdyg8ywan",
  "request": {...}
}
```


<div id="going-deeper">
  ## さらに詳しく
</div>

ほとんどのエンドポイントでは、`count` の最大値は **1,000**、最小値は **1**、デフォルト値は **200** です。

`next_cursor` によって提供される値は常に文字列型であり、不透明な値として扱う必要があります。実装は今後変更される可能性があります。現在のページで返されるエンティティ数が `count` より少ない場合、`next_cursor` の値は `null` になります。

**注意:** analytics エンドポイントは、この形式のページネーションをサポートしていません。stats エンドポイントでのページングは、時間範囲を指定することでサポートされます。詳しくは、それぞれのエンドポイントのドキュメントを参照してください。
