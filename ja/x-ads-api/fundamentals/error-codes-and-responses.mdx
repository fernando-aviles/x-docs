<div id="typical-response-structure">
  ## 一般的なレスポンス構造
</div>

成功したレスポンスは、200 番台の HTTP ステータスコードと、要求されたオブジェクトの取得・作成・更新・削除結果に加えて、サーバーがリクエストをどのように解釈したかを表す情報を含む JSON ベースのペイロードによって示されます。

成功したリクエストを送信すると、レスポンスの一部として、送信したリクエスト内容をそのまま返す `request` ノードが含まれます。

*例:* [GET accounts/abcdefg/campaigns?with&#95;deleted=true](/ja/x-ads-api/campaign-management#campaigns)

```json
{
  /* レスポンスのdata... */,
  "request": {
    "params": {
      "account_id": "abcdefg",
      "with_deleted": "true"
    }
  }
}
```

JSON レスポンス内の `data` フィールドには、対象のリソースに紐づく特定のオブジェクトが格納されます。`data` ノードの形式は、レスポンスに 1 件以上の結果が含まれる可能性がある場合は JSON 配列になります。レスポンスとして 1 件の結果しか返されない場合は、JSON ハッシュとして返されます。まれに、通常であればコレクションを含むレスポンスが、代わりにハッシュマップを含む形で返されることがあります。この場合、その単一のハッシュマップは、`type` フィールドで指定されているものと同じタイプのオブジェクトであるとみなしてください。

<div id="error-response-structure">
  ## エラーレスポンスの構造
</div>

エラーレスポンスは、2xx 系以外の HTTP ステータスコードで返されます。通常は JSON レスポンスが返されますが、一部のエラーでは別種のレスポンスボディが返されることもあります。レスポンス構造をパースできない状況では、HTTP ステータスコード本来の意味を優先して判断してください。たとえば、HTML レスポンスとともに HTTP 404 が返される場合があります。このケースでは、そのコンテンツが見つからないと判断して問題ありません（HTTP 404 は「Not Found（見つかりません）」を意味します）。

一般的なエラーレスポンスは、成功時のレスポンスと似た構造を取ります。エラーの内容は、レスポンス内の `errors` ノードで示されます。`errors/code` ノードには、プログラムから解決方法の判断に利用できる CAPS&#95;CASE 形式の定数エラーコードが入ります。`errors/message` ノードには、エラー内容の（通常は）人間が読める英語での説明が入ります。エラーに関するより詳細な情報を示すために、追加のフィールドが付与される場合があります。

```json
{
  "errors": [
    {
      "parameter": "start_time",
      "details": "無効な日付",
      "code": "INVALID_PARAMETER",
      "value": "",
      "message": "start_time には時刻が必要ですが、\"\" が指定されました"
    }
  ],
  "request": {
    "params": {
      "account_id": "hkk5"
    }
  }
}
```

上記の例では、analytics エンドポイントへのリクエストで `start_time` パラメータに無効な値が指定されていました。無効なパラメータがあるリクエストの `errors/code` は `INVALID_PARAMETER` です。
