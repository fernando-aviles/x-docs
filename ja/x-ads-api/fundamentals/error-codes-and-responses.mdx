<div id="typical-response-structure">
  ## 一般的なレスポンス構造
</div>

成功したレスポンスは、200 番台の HTTP コードと、要求されたオブジェクト（取得、作成、変更、削除されたもの）に加え、サーバーがリクエストをどのように解釈したかを表す JSON ベースのペイロードによって示されます。

成功したリクエストを送信した場合、レスポンスには、送信したリクエストをそのまま反映した `request` ノードが含まれます。

*例:* [GET accounts/abcdefg/campaigns?with&#95;deleted=true](/ja/x-ads-api/campaign-management#campaigns)

```json
{
  /* レスポンスのdata... */,
  "request": {
    "params": {
      "account_id": "abcdefg",
      "with_deleted": "true"
    }
  }
}
```

JSON レスポンス内の `data` フィールドには、対象のリソースに紐づく特定のオブジェクトが格納されます。`data` ノードの形式は、レスポンスに 1 件以上の結果が含まれる可能性がある場合は JSON 配列になります。レスポンスとして 1 件の結果しか返らない場合は、JSON オブジェクトとして返されます。まれに、通常であればコレクションを含むはずのレスポンスが、代わりにハッシュマップを含んでいる場合があります。この場合、その単一のハッシュマップは、`type` フィールドで指定されているものと同じタイプのオブジェクトであるとみなしてください。

<div id="error-response-structure">
  ## エラーレスポンスの構造
</div>

エラーレスポンスは 200 番台以外の HTTP コードとともに返されます。通常は JSON レスポンスが返されますが、エラーによっては異なる形式のボディが返されることもあります。レスポンス構造をパースできない状況では、HTTP コード本来の意味を優先して判断してください。たとえば、HTML レスポンスとともに HTTP 404 が返される場合があります。このケースでは、そのコンテンツが見つからないとみなして問題ありません（HTTP 404 は「Not Found」を意味します）。

一般的なエラーレスポンスは、成功時のレスポンスとよく似た構造になっています。エラーの内容はレスポンス内の `errors` ノードで示されます。`errors/code` ノードには、プログラムから解決方法の判断に利用できる、大文字スネークケース形式（CAPS&#95;CASE）の定数エラーコードが格納されます。`errors/message` ノードには、そのエラーについての（通常は）人間が読める英語での説明が格納されます。エラーに関するより詳細な情報を示すために、追加のフィールドが付与される場合もあります。

```json
{
  "errors": [
    {
      "parameter": "start_time",
      "details": "無効な日付",
      "code": "INVALID_PARAMETER",
      "value": "",
      "message": "start_timeには時刻が必要ですが、\"\"が指定されました"
    }
  ],
  "request": {
    "params": {
      "account_id": "hkk5"
    }
  }
}
```

上記の例では、`start_time` パラメータに無効な値を指定して analytics エンドポイントにリクエストしています。無効なパラメータを含むリクエストの場合の `errors/code` は `INVALID_PARAMETER` です。
