마지막 업데이트: 2014년 10월 22일.

<div id="introduction">
  ## 소개
</div>

Posting With Location은 X API의 위치 태그 지정(지오태깅) 기능입니다. 이 기능은 포스트에 위치 정보를 더해 문맥을 풍부하게 함으로써, 사용자에게 더 의미 있는 경험을 제공하는 데 도움이 됩니다. 예를 들어 “Fireworks!”라는 문구는 위치와 함께 제공될 때, 즉 “Fireworks!”가 캘리포니아 주 샌프란시스코의 SoMa Neighborhood에서 작성된 것으로 표시될 때 훨씬 더 의미 있게 다가옵니다. 우리는 이 기능을 중심으로 뛰어난 경험을 만들어 가기 위해 개발자 생태계와 함께 협력하기를 기대합니다.

<div id="user-privacy-and-user-control-of-their-location-information">
  ## 사용자 프라이버시 및 위치 정보에 대한 사용자 제어
</div>

안전하고 원활한 사용 경험을 보장하기 위해 개발자는 사용자의 위치 정보를 다룰 때 사용자 프라이버시에 유의하고, “위치와 함께 게시하기” 경험 전반에 걸쳐 기본적인 일관성을 제공해야 합니다. 다음은 사용자 프라이버시를 보호하고 사용자가 자신의 행동이 미치는 영향을 이해하는 데 도움이 되는 주요 사항입니다.

<div id="general-guidelines">
  ## 일반 지침
</div>

* 사용자는 위치와 함께 게시하기(Posting With Location) 기능을 사용하기 위해 반드시 옵트인(직접 설정하여 ‘켜기’)해야 합니다.
* 사용자는 자신의 포스트와 함께 정확한 위치가 표시되도록 명시적으로 허가해야 합니다. 클라이언트의 위치 기능이 ‘sticky’(한 번 위치를 켜면 이후 포스트에 항상 위치가 동반되는 형태)인 경우, 장소 이름(place&#95;ids)만 표시하고, 포스트별 또는 별도의 설정에서 사용자가 정확한 위도와 경도 표시를 추가로 옵트인할 수 있도록 하는 방식을 고려할 수 있습니다.
* 사용자의 위치 데이터를 사용해 포스트를 게시할 때, 사용자로부터 명시적인 허가를 받지 않는 한 해당 정보를 포스트와 분리하여 저장해서는 안 됩니다.
* 사용자의 포스트와 연관하여 어느 수준의 위치 정보(있다면)가 표시될지 사용자에게 명확해야 합니다. 이를 구현하는 한 가지 방법은 포스트가 게시되기 전에 이 정보가 어떤 방식으로 표시될지를 보여주는 지도를 제공하는 것입니다. 클라이언트에서 게시되는 정보의 일부(또는 전부)가 정확한 위도와 경도인 경우, 사용자는 자신의 정확한 좌표가 게시된다는 사실을 명확히 인지할 수 있어야 합니다.
* 사용자는 포스트를 작성할 때마다 위치를 켜거나 끌 수 있어야 합니다.
* X의 [Developer Policy](/ko/developer-terms/policy.html) 약관을 준수해야 합니다. 여기에는 포스트의 일부인 경우를 제외하고, X API에서 가져온 위치 데이터 및 기타 지리 정보를 집계, 캐시 또는 저장할 수 없으며, 또한 이러한 위치 데이터나 지리 정보를 단독으로 사용할 수 없다는 요구 사항이 포함됩니다.

<div id="specific-examples">
  ## 구체적인 예시
</div>

예시 1: *위도와 경도의 명시적 추가 없음 (현재 X 웹 클라이언트 UI)*

1. 사용자가 포스트를 작성할 때 “내 위치 추가” 링크를 표시합니다.
2. 백그라운드에서 X [reverse&#95;geocode](https://developer.x.com/en/docs/geo/places-near-location/api-reference/get-geo-reverse_geocode.html) API 호출을 사용하고, 위도, 경도, 위치 측정값의 정확도, 그리고 사용자가 선호하는 세분화 수준(기본값은 “neighborhood”)을 전달합니다.
3. 기본 장소에 대한 이름을 표시합니다(X는 X 클라이언트가 별도의 수정 없이 목록을 그대로 표시할 수 있도록, 의미 있는 순서로 이를 정렬하려고 시도합니다).
4. 사용자가 목록에서 다른 위치를 선택할 수 있도록 하십시오(예: “SoMa, San Francisco”에서 “South Beach, San Francisco”로 변경).
5. 중요: 정확한 위치 정보를 표시할 경우, 사용자에게 이를 투명하게 알리십시오. 정확한 위치 정보가 표시될 것인지 사용자가 명확히 인지할 수 있도록 하십시오.
6. 사용자가 포스트를 작성할 때마다 위치를 켜거나 끌 수 있는 선택권을 제공하십시오.

예시 2: *기존 지오태깅 구현*

여러 X 클라이언트 앱에는 원래의 지오태깅 기능(위치 ID(place&#95;ID)를 제공하지 않고 위도/경도(lat/lon)만 전송하는 기능)이 구현되어 있습니다. API의 기본 동작은 이 동작을 그대로 따릅니다. 즉, 개발자인 여러분은 현재의 동작을 유지하기 위해 기존 앱을 변경할 필요가 없습니다. 실제로 X에 위도/경도 좌표만 전달하더라도, X는 해당 위도와 경도를 자동으로 역지오코딩하고, data를 보유한 영역에 대해서는 위도/경도와 함께 place&#95;ID도 추가로 표시합니다.

사용자의 정확한 좌표가 X에서 사용되고 표시된다는 점이 사용자에게 투명하게 전달되도록 하십시오. 기존 앱에 대한 모범 사례로는, 사용자에게 포스트별로 위치를 켜거나 끌 수 있도록 허용하는 것이 좋습니다. 또한 기본 “고정(sticky)” 설정으로, 정확한 좌표 대신 place&#95;ID만 공유하도록 사용자가 선택할 수 있게 할 수도 있습니다.

<div id="x-storage-of-user-location-data">
  ## X의 사용자 위치 데이터 저장
</div>

X는 클라이언트에서 전달된 데이터를 다음과 같이 저장합니다.

* X는 사용자가 자신의 팔로워에게 공개하기로 선택한 모든 데이터를 저장합니다. 이는 X가 포스트가 작성된 시점을 나타내는 타임스탬프를 저장하는 방식과 유사합니다. 즉, 사용자가 자신의 정확한 좌표와 함께 포스트를 게시하는 경우, 해당 포스트가 존재하는 한 X는 이 정확한 위치를 포스트와 함께 저장합니다. 사용자는 [여기](https://support.twitter.com/articles/122236-how-to-tweet-with-your-location))에 설명된 대로 설정 페이지에서 “내 위치 기록 지우기” 버튼을 클릭하여 포스트에서 위치 데이터를 삭제할 수 있습니다.

<div id="summary">
  ## 요약
</div>

포스트에 위치 정보를 추가하면 사용자 관점에서 매우 풍부한 맥락과 가치를 더할 수 있습니다. 그러나 위치 중심의 제품을 설계할 때 클라이언트에서 위치를 구현하는 방식은 개인정보 보호와 사용자에 대한 투명성을 핵심 기준으로 삼아 신중하게 결정해야 합니다.

개인정보 보호, 위치, 기타 지리 정보 기능과 관련해 질문이나 의견이 있으시면 [문의해 주세요.](https://support.twitter.com/forms/platform)
