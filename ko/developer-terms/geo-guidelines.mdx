<div id="introduction">
  ## 소개
</div>

Posting With Location은 X API의 지오태깅 기능입니다. 이 기능은 포스트에 위치 정보를 더해 맥락을 강화함으로써 사용자에게 더욱 의미 있는 경험을 제공하는 데 도움이 됩니다. 예를 들어 “Fireworks!”라는 문구는, 미국 캘리포니아주 샌프란시스코의 SoMa 동네에서 작성된 “Fireworks!”처럼 위치와 함께 제공될 때 훨씬 더 관련성이 높아집니다. 우리는 이 기능을 중심으로 뛰어난 경험을 만들어 나가기 위해 개발자 생태계와 함께 일하기를 기대하고 있습니다!

<div id="user-privacy-and-user-control-of-their-location-information">
  ## 사용자 개인정보 및 위치 정보에 대한 사용자 제어
</div>

안전하고 원활한 사용 경험을 제공하려면 개발자는 사용자의 위치 정보를 처리할 때 사용자 개인정보를 신중하게 다루고, 동시에 “위치 정보와 함께 포스트하기” 경험에서 기본적인 일관성을 제공해야 합니다. 다음은 사용자 개인정보를 보호하고 사용자가 자신의 행동이 미치는 영향을 이해하도록 돕기 위해 염두에 두어야 할 핵심 사항들입니다:

<div id="general-guidelines">
  ## 일반 가이드라인
</div>

* 사용자는 ‘위치와 함께 포스트하기’ 기능을 사용하기 위해 반드시 옵트인(위치 기능을 “켜기”)해야 합니다.
* 사용자는 자신의 포스트에 정확한 위치 정보가 표시되는 것에 대해 명시적으로 동의해야 합니다. 클라이언트의 위치 기능이 “고정(sticky)”되어 있어 한 번 위치를 켜면 이후 포스트에도 계속 위치가 함께 표시되는 경우, 장소 이름(place&#95;ids)만 표시하고, 각 포스트별로 또는 별도의 설정을 통해 사용자가 위도·경도 등 정확한 위치 공개에 추가로 옵트인하도록 허용하는 것이 좋습니다.
* 사용자의 위치 데이터에 접근해 포스트를 게시하는 경우, 사용자로부터 명시적인 허락을 받지 않는 한 해당 정보를 포스트와 별도로 저장해서는 안 됩니다.
* 사용자의 포스트와 함께 어떤 수준의 위치 정보(표시되는 경우)가 노출되는지 사용자에게 명확해야 합니다. 이를 위한 한 가지 방법은, 포스트가 게시되기 전에 해당 정보가 어떻게 표시될지 보여주는 지도를 제공하는 것입니다. 클라이언트에서 사용자가 게시하는 정보에 정확한 위도와 경도가 포함되거나(또는 그 정보만 포함되는) 경우, 자신의 정확한 좌표가 게시된다는 사실을 사용자가 명확히 인지할 수 있어야 합니다.
* 사용자는 포스트를 작성할 때마다 위치 기능을 켜고 끌 수 있어야 합니다.
* X의 [Developer Policy](/ko/developer-terms/policy.html)를 반드시 준수해야 합니다. 여기에는, 포스트의 일부인 경우를 제외하고 X API에서 가져온 위치 데이터 및 기타 지리 정보를 집계, 캐시 또는 저장할 수 없으며, 그러한 위치 데이터나 지리 정보를 단독으로 사용할 수 없다는 요구 사항이 포함됩니다.

<div id="specific-examples">
  ## 구체적인 예시
</div>

예시 1: *명시적인 위도와 경도 추가 없음(현재 X 웹 클라이언트 UI)*

1. 사용자가 포스트를 작성할 때 “Add your location” 링크를 표시합니다.
2. 백그라운드에서 X [reverse&#95;geocode](https://developer.x.com/en/docs/geo/places-near-location/api-reference/get-geo-reverse_geocode.html) API 호출을 사용해 위도, 경도, 위치 측정 정확도, 그리고 사용자의 선호 세분화 수준(기본값은 “neighborhood”)을 전달합니다.
3. 기본 장소의 이름을 표시합니다(X는 X 클라이언트가 수정 없이 목록을 그대로 표시할 수 있도록, 의미 있는 순서로 이를 정렬하려고 시도합니다).
4. 사용자에게 목록에서 다른 위치를 선택할 수 있도록 합니다(예: “SoMa, San Francisco”에서 “South Beach, San Francisco”로 변경).
5. 중요: 정확한 위치 정보를 표시하는 경우 사용자에게 투명하게 알리십시오. 정확한 위치 정보가 표시되는지 사용자가 명확히 인지하도록 해야 합니다.
6. 매 포스트를 작성할 때마다 위치 사용 여부를 켜거나 끌 수 있는 선택권을 사용자에게 제공합니다.

예시 2: *기존 지오태깅 구현*

다수의 X 클라이언트 앱은 원래의 지오태깅 기능(단지 lat/lon만 전송하고 place&#95;IDs는 제공하지 않는 기능)을 구현해 두었습니다. API의 기본 동작은 이 동작을 그대로 따릅니다. 즉, 개발자로서 현재의 동작을 유지하기 위해 기존 앱을 변경할 필요가 없습니다. 실제로 X에 lat/lon 좌표만 전달하더라도, X는 해당 위도와 경도를 자동으로 역지오코딩하여, 사용 가능한 데이터가 있는 영역에 대해서는 lat/lon과 함께 place&#95;ID도 추가로 표시합니다.

사용자의 정확한 좌표가 X에서 사용 및 표시되고 있다는 점이 사용자에게 투명하게 전달되도록 해야 합니다. 기존 앱에 대한 모범 사례로는, 사용자에게 포스트별로 위치를 켜거나 끌 수 있도록 허용하는 것이 있습니다. 또한 기본값이 되는 “sticky” 설정으로, 사용자가 정확한 좌표 대신 place&#95;IDs만 공유하도록 설정할 수도 있습니다.

<div id="x-storage-of-user-location-data">
  ## X의 사용자 위치 데이터 저장
</div>

X는 클라이언트에서 전달된 데이터를 다음과 같이 저장합니다:

* X는 사용자가 팔로워에게 공개하도록 선택한 모든 데이터를 저장합니다. 이는 X가 포스트가 작성된 시점을 나타내는 타임스탬프를 저장하는 방식과 유사합니다. 즉, 사용자가 자신의 정확한 좌표를 포함해 포스트를 게시하는 경우, 해당 포스트가 존재하는 동안 X는 이 정확한 위치 정보를 포스트와 함께 저장합니다. 사용자는 [여기](https://support.twitter.com/articles/122236-how-to-tweet-with-your-location)에 설명된 대로 설정 페이지에서 “clear my location history” 버튼을 클릭하여 자신의 포스트에서 위치 데이터를 삭제할 수 있습니다.

<div id="summary">
  ## 요약
</div>

포스트에 위치 정보를 추가하면 사용자 입장에서 맥락과 가치를 크게 높일 수 있습니다. 다만 클라이언트에서 위치 정보를 구현할 때에는, 위치 중심 제품을 설계하는 과정에서 개인정보 보호와 사용자에 대한 투명성을 핵심 요소로 신중히 고려해야 합니다.

개인정보 보호, 위치, 기타 지리/위치 관련 기능에 대해 궁금한 점이나 의견이 있으면 [문의해 주세요.](https://support.twitter.com/forms/platform)
