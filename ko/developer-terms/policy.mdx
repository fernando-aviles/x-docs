<div id="x-developers">
  ## X + 개발자
</div>

X는 개발자를 소중히 여깁니다. X data의 힘을 활용해 이 커뮤니티가 만들어 내는 다양한 도구와 서비스에 늘 기쁘고 놀라워하고 있습니다. 이 커뮤니티에 대한 우리의 약속의 일환으로, 개발자에게는 개방적이고 공정하며, X를 이용하는 사람들에게는 안전하고, X 플랫폼 전체에도 이로운 방식으로 data에 대한 접근을 제공하는 것을 목표로 합니다. 이러한 목표를 달성하기 위해, 우리는 API 및 X Content의 적절한 사용에 관한 우리의 규칙과 기대 사항을 이해하는 데 도움이 되는 안내서로서 Developer Policy를 마련했습니다.

이 Developer Policy(“**Policy**”)는 X의 애플리케이션, 서비스, 웹사이트, 웹 페이지 및 콘텐츠로 구성된 생태계와 상호작용하는 개발자를 위한 규칙과 지침을 제공합니다. 이는 X API 및 X Content에 대한 접근 및 사용을 규율하는 X와의 계약(Developer Agreement 또는 X와 체결한 기타 서면 계약)의 일부를 구성합니다. Policy를 위반하는 행위는 귀하의 계약 위반으로 간주됩니다. 이 Policy는 별도의 통지 없이 수시로 변경될 수 있습니다. 이 Policy에서 사용되었으나 이 Policy 내에서 정의되지 않은 대문자로 시작하는 용어는 [Developer Agreement](/ko/developer-terms/agreement) 또는 Master License Agreement에서 부여된 각각의 의미를 갖습니다.

<div id="using-this-policy">
  ## 이 정책 사용 방법
</div>

우리는 이 정책을 최대한 쉽게 이해하고 준수할 수 있도록 구성했습니다. X API 및 X 콘텐츠를 사용할 때 아래 정책 섹션의 내용을 항상 염두에 두시기 바랍니다:

1. **성공을 위한 준비** - 귀하는 모든 X 정책을 준수할 책임이 있습니다. X API 및 X 콘텐츠에 액세스하기 전에, 이 정책과 이 문서에 링크된 정책들을 검토하고 이해하는 것이 중요합니다. 정책을 검토하는 데 들이는 시간은 앞으로 발생할 수 있는 수시간의 재작업을 줄이는 데 도움이 될 수 있습니다.

2. **프라이버시와 통제권은 필수적입니다** - X를 이용하는 사람들의 프라이버시를 보호하고 지키는 일은 우리 회사의 핵심 정체성에 깊이 자리 잡고 있습니다. 따라서 우리는 사람들이 합리적으로 기대하는 프라이버시 수준에 반하는 방식으로 X 데이터가 사용되는 것을 금지합니다. X API를 기반으로 서비스를 구축하거나 X 콘텐츠에 접근함으로써, 귀하는 이 약속을 지키는 데 있어 특별한 역할을 맡게 되며, 특히 사람들의 프라이버시를 존중하고, 그들의 데이터가 어떻게 사용되는지에 대한 투명성과 통제권을 제공해야 합니다.

3. **플랫폼 사용 지침을 따르세요** - X API 및 X 콘텐츠에 대한 접근 승인을 받는 것은 첫 단계일 뿐입니다. 계획 중인 X 플랫폼 사용이 정책을 준수하는지에 관해 의문이 생길 때마다 가장 먼저 참고해야 할 문서는 우리의 플랫폼 사용 지침입니다.

아래에서 이 세 가지 핵심 섹션 각각이 의미하는 바를 훨씬 더 자세히 설명합니다. X API 및 X 콘텐츠 사용이 우리의 정책과 일치하는지 확인하기 위해 반드시 주의 깊게 검토해 주시기 바랍니다.

당사가 귀하가 이 정책(또는 다른 X 정책)을 위반하고 있다고 판단하는 경우, X API 및 X 콘텐츠에 대한 귀하의 접근을 일시 중단하거나 영구적으로 철회할 수 있습니다.

마지막으로, X는 X 애플리케이션을 개선하고, 상업적 사용을 검토하며, 승인된 사용 사례 및 이 정책에 대한 귀하의 준수 여부를 확인하기 위해 귀하의 X API 사용을 모니터링할 수 있다는 점을 유의해 주시기 바랍니다.

읽어 주셔서 감사드리며, 우리와 함께 구축해 주셔서 감사합니다! 여러분이 무엇을 만들어 나갈지 기대하고 있습니다!

<div id="set-yourself-up-for-success">
  ## 성공을 위한 기반 마련
</div>

X API를 사용할 때 처음부터 올바른 방식으로 서비스를 구축하면 많은 잠재적인 문제를 피할 수 있습니다. 이 Developer Policy 섹션에는 X API 또는 X Content를 사용하기 전에 모든 개발자가 반드시 따라야 하는 규칙이 포함되어 있습니다.

[developer.x.com/en](http://developer.x.com/en)에 설명된 Free, Basic, Pro 플랜은 취미 활동, 상업적 프로토타이핑, 초기 단계의 X 제품 통합, 그리고 제한된 수의 최종 사용자를 가진 애플리케이션을 위해 설계되었습니다. X API 및 X Content를 이 범위를 넘어 사용하려는 경우, Enterprise 플랜([developer.x.com/en](http://developer.x.com/en)에 설명됨)에 신청하거나 이미 구독하고 있어야 합니다.

**당사는 정책 준수 여부를 확인하기 위해 X 개발자 플랫폼의 모든 제안된 사용 사례를 검토합니다. 따라서 X API와 X Content에 대한 액세스 권한을 부여받고 이를 유지하기 위해, 계획된 사용 목적을 공개하고 (해당되는 경우) 업데이트해야 합니다.** 모든 신규 개발자는 X API에 액세스하기 위해 [개발자 계정을 신청](https://developer.x.com/portal/petition/essential/basic-info)해야 합니다. 승인된 개발자 계정이 없는 기존 개발자도 X의 지시에 따라 계정을 신청해야 합니다. 이 프로세스의 일환으로, X API와 X Content의 예정된 사용 목적에 대한 서면 설명을 제공해야 합니다.

사용 사례 설명은 귀하에게 구속력이 있으며, 이와 실질적으로 다르게 사용하는 경우 당사 규칙을 위반한 것으로 간주되어 제재 조치가 이루어질 수 있습니다. 사용 사례를 실질적으로 변경하려는 경우, 그 새로운 목적을 위해 X Content를 사용하기 전에 반드시 당사에 통지하고 승인을 받아야 합니다. 이를 이행하지 않으면 API 및 data 액세스가 중단되거나 해지될 수 있습니다.

**X API를 기반으로 서비스를 구축하거나 X Content에 액세스하는 경우, 모든 X 정책을 준수해야 합니다.** 여기에는 이 [Developer Policy](/ko/developer-terms/policy), [Automation Rules](https://help.x.com/rules-and-policies/x-automation), [Display Requirements](https://developer.x.com/developer-terms/display-requirements.html), [API Restricted Uses Rules](/ko/developer-terms/restricted-use-cases), [X Rules](https://help.x.com/rules-and-policies/x-rules), [X Brand Resources](https://about.x.com/who-we-are/brand-toolkit)는 물론, X API 또는 X Content 사용과 관련하여 X와 체결하는 모든 기타 계약(예: [Developer Agreement](/ko/developer-terms/agreement), Master Licensing Agreement 또는 Order(해당되는 경우))이 포함됩니다. 또한 이러한 정책의 변경 사항과 X가 새로 도입하는 모든 정책도 준수해야 합니다. 귀하는 자신의 서비스 사용을 모니터링하고, 사용자가 X 정책을 위반하지 않도록 서비스를 설계할 책임이 있습니다. 이를 이행하지 않을 경우, API 및 X Content 액세스의 중단 또는 해지로 이어질 수 있습니다.

**단일 사용 사례 또는 실질적으로 유사하거나 중복되는 사용 사례에 대해 여러 개의 애플리케이션을 등록해서는 안 됩니다.** 여기서 “사용 사례(use case)”란 애플리케이션을 통해 수행되는 분석, 표시, 또는 동작의 일관된 집합을 의미합니다. 도구 또는 서비스의 &quot;화이트 라벨(white label)&quot; 버전은 허용되지 않습니다. 애플리케이션의 “화이트 라벨” 버전을 제공하려는 경우, 반드시 당사에 통지하고 별도의 승인을 받아야 합니다.

*이 규칙에 대한 단 하나의 예외로,* 동일한 서비스의 development, staging, production 인스턴스를 위해 최대 3개의 애플리케이션을 생성하고 사용할 수 있습니다. 이 앱들은 하나의 계정에 등록되어야 하며, 단일 서비스의 dev, staging, prod 인스턴스임을 이름과 설명에 명확히 표시해야 합니다. **development 또는 staging 애플리케이션을 production 용도로 사용할 수 없습니다.**

**모든 API 키 및 기타 액세스 자격 증명은 비공개로 유지해야 합니다.** 타인이 소유한 API 키 또는 기타 액세스 자격 증명을 사용하거나, 다른 사람이 이를 사용하도록 조장하거나 돕는 행위를 해서는 안 됩니다.

**X와의 라이선스 계약은 X API 및 X Content 사용을 제한합니다. 특히 X API에는 공정한 데이터 사용을 보장하고 플랫폼의 스팸을 방지하기 위한 rate limit가 존재합니다.** 이 Policy 또는 X와의 계약에 설명되어 있거나, [Developer Site](https://developer.x.com/)에 나와 있거나, X로부터 통지받은 rate limit 또는 기타 제한이나 제약을 초과하거나 우회해서는 안 됩니다.

**X API를 통해 수신한 X Content에 포함된 모든 독점적 고지나 표식을 제거하거나 변경해서는 안 됩니다.** 이는 사람들이 X Content의 출처와 소유자를 명확히 알 수 있도록 하기 위한 것입니다.

**데이터 무결성과 플랫폼의 건전성을 위해, X API 또는 X 서비스의 어떤 기능도 방해, 가로채기, 교란, 또는 비활성화해서는 안 됩니다.** 다시 말해, [developer.x.com](https://developer.x.com/)에 문서화된 의도와 방식대로 API를 사용해야 합니다. 허용 가능한 사용에 대한 자세한 내용은 [HackerOne guidelines](https://hackerone.com/x)를 참고하십시오.

<div id="privacy-and-control-are-essential">
  ## 프라이버시와 통제권은 필수적입니다
</div>

X는 프라이버시를 중요하게 여기며, X Content와 X API를 사용하는 모든 분도 마찬가지로 프라이버시를 중시하기를 기대합니다. X 개발자 플랫폼, X API 또는 X Content를 사람들이 합리적으로 기대하는 프라이버시 수준과 일치하지 않는 방식으로 사용하는 경우, API 및 X Content 액세스의 정지나 종료를 포함할 수 있는 제재 조치의 대상이 될 수 있습니다.

프라이버시와 통제권에 대한 귀하의 책임은 X Content의 모든 사용과, 당사 API를 사용하여 구축하는 서비스의 모든 측면에까지 확장되어야 합니다. 이를 위해 귀하의 서비스를 사용하는 사람들은 귀하가 그들의 데이터를 어떻게 사용하고, 그들을 대신해 X에 어떻게 액세스하는지 이해하고 동의해야 합니다. 이는 사람들에게 명확하고 포괄적이며 투명한 개인정보 처리방침을 제공하고, 그들을 대신하여 어떤 조치를 취하기 전에 귀하의 서비스를 사용하는 각 개인으로부터 명시적이고 충분한 설명에 기반한 동의를 받는 방식으로 달성할 수 있습니다. **귀하의 서비스에 인증을 완료했다는 사실만으로는 동의가 성립되지 않는다는 점에 유의하시기 바랍니다.**

<div id="consent-permissions">
  ## Consent &amp; permissions
</div>

**특히, 아래와 같은 행위를 하기 전에 반드시 이용자로부터 명시적이고 충분한 설명을 거친 동의를 받아야 합니다.**

* 이용자를 대신해 *어떠한* 조치라도 취하는 경우. 여기에는 (이에 한정되지 않고) 다음이 포함됩니다.
  * X에 콘텐츠를 게시하는 것
  * 계정을 팔로우/언팔로우하는 것
  * 프로필 또는 계정 정보를 수정하는 것
  * 포스트에 해시태그나 기타 다른 콘텐츠를 추가하는 것

* X API 또는 기타 X 도구 이외의 수단으로 접근한 콘텐츠를 재게시하는 것

* 다른 사람의 X 콘텐츠를 사용해 제품이나 서비스를 홍보하는 것

* Direct Messages(DM)와 같은 비공개 콘텐츠나 기타 모든 사적 또는 기밀 정보를 저장하는 것

* 보호된 콘텐츠나 기타 모든 사적 또는 기밀 정보를 공유하거나 게시하는 것

**서비스가 이용자에게 X에 콘텐츠를 게시할 수 있는 기능을 제공하는 경우, 게시 전에 다음을 수행해야 합니다.**

* 게시될 내용을 그대로 보여줍니다.
* 콘텐츠에 어떤 위치 정보(있는 경우)가 추가될지, 서비스를 이용하는 사람에게 명확히 알립니다.

**서비스가 이용자에게 귀하의 서비스와 X 모두에 콘텐츠를 게시할 수 있는 기능을 제공하는 경우, 게시 전에 다음을 수행해야 합니다.**

* 해당 콘텐츠를 게시하는 데 필요한 허가를 받습니다.
* 콘텐츠를 어디에 게시할 것인지 설명합니다.

**모든 X 콘텐츠의 보호 및 차단 상태를 준수해야 합니다. 한 사람의 인증 토큰을 사용해 얻은 콘텐츠를, 그 콘텐츠를 볼 권한이 없는 다른 사람에게 제공해서는 안 됩니다.**

* **Protected accounts:** [protected account](https://help.x.com/safety-and-security/public-and-protected-posts)의 콘텐츠는 계정 소유자가 팔로우를 승인한 사람에게만 제공됩니다. 따라서 보호된 계정에 접근하는 서비스를 운영하는 경우, 해당 콘텐츠를 볼 권한이 있는 특정 사람에게 그 콘텐츠를 제공하는 목적에 한해서만 이를 사용할 수 있습니다.
* **Blocked accounts:** X 이용자는 원하는 어떤 이유로든 자신의 계정에 대한 접근을 [block](https://help.x.com/using-x/blocking-and-unblocking-accounts)할 수 있습니다. 이러한 선택을 우회하기 위해 토큰(또는 기타 API 기반 작업)을 통해 얻은 정보를 섞어 사용하거나 결합하는 행위는 허용되지 않습니다.

**Direct Messages(DM)는 본질적으로 비공개이므로, DM 기능을 제공하는 서비스는 개인 정보 보호를 위해 추가적인 조치를 취해야 합니다. DM 콘텐츠를 볼 권한이 없는 사람에게 DM 콘텐츠를 제공해서는 안 됩니다. 서비스가 DM 기능을 제공하는 경우 다음 사항도 준수해야 합니다.**

* DM에 대해 읽음 확인 이벤트를 전송하는 경우 이를 이용자에게 알려야 합니다. 이는 서비스 내에 직접 고지를 제공하거나, 대화에 참여한 다른 이용자의 읽음 확인을 표시하는 방식으로 할 수 있습니다.
* DM에서 전송되는 미디어를 &quot;shared&quot;(즉, 여러 DM에서 재사용 가능)로 설정하기 전에 동의를 받아야 합니다. DM에서 미디어를 &quot;shared&quot;로 허용하는 경우, 이 콘텐츠는 해당 미디어 URL을 가진 누구나 접근할 수 있다는 점을 명확히 고지해야 합니다.

<div id="content-compliance">
  ## 콘텐츠 규정 준수
</div>

**X 콘텐츠를 오프라인으로 저장하는 경우, 해당 콘텐츠를 X에서의 현재 상태와 일치하도록 최신 상태로 유지해야 합니다.** 구체적으로, 특정 콘텐츠가 X에서 삭제되거나 수정된 경우, 보유 중인 해당 콘텐츠도 삭제하거나 수정해야 합니다. 이러한 조치는 합리적으로 가능한 한 신속하게, 또는 X나 해당 X 계정 소유자가 이러한 조치를 요청한 후 24시간 이내에, 또는 X와의 계약이나 관련 법률에 따라 요구되는 기간 내에 이행해야 합니다. 이는 법률에 의해 금지된 경우를 제외하고, 그러한 경우에도 X의 명시적인 서면 허가가 있는 경우에만 예외가 인정됩니다.

수정된 콘텐츠는 다양한 형태를 취할 수 있습니다. 여기에는 (이에 제한되지 않고) 다음이 포함됩니다:

* 비공개로 전환되었거나 보호 상태를 갖게 된 콘텐츠
* 플랫폼에서 정지된 콘텐츠
* 지오태그가 제거된 콘텐츠
* X에서 보류되었거나 제거된 콘텐츠

개인의 X 아이덴티티를 X 외부 식별자와 연결하기 위한 명시적 옵트인 동의를 받지 않은 상황에서는, 귀하가 생성하는 모든 연결은 합리적인 사람이 그 목적을 위해 사용될 것이라고 예상할 수 있는 정보에만 기반해야 합니다. 또한, 개인의 명시적 옵트인 동의가 없는 경우에는 다음을 기반으로 할 때에만, 특정인에 대해 귀하가 보유한 기록을 X 아이덴티티와 매칭하려고 시도할 수 있습니다.

* **개인이 귀하에게 직접 제공한 정보.** 귀하와 기존 관계가 없는 개인에 대한 기록(예: 제3자로부터 획득한 개인에 대한 데이터)은 이 기준을 충족하지 못한다는 점에 유의하십시오. 그리고/또는
* **공개 데이터.** 이 문맥에서 “공개 데이터”는 다음을 의미합니다.
  * (전문 협회 회원 디렉터리와 같은) 공개적으로, 일반에 제공되는 자료에서 귀하가 획득한 개인에 관한 정보
  * 다음을 포함하여 X에서 개인에 대해 공개적으로 이용 가능한 정보:
    * 포스트
    * 계정 소개(bio) 및 공개된 위치를 포함한 프로필 정보
    * 표시 이름과 @handle

<div id="using-geo-data">
  ## 지리 데이터 사용
</div>

**지리 데이터는 정보의 민감한 특성 때문에 사용에 추가적인 제한이 적용됩니다.** 귀하의 서비스가 포스트에 위치 정보를 추가하는 경우, 사용자에게 다음 사항을 고지해야 합니다.

* 언제 위치 정보를 추가하는지
* 위치 정보를 지오태그(geotag)로 추가하는지, 아니면 annotations data로 추가하는지
* 위치 정보가 장소(Place)로 표시되는지, 아니면 지리 좌표로 표시되는지

애플리케이션이 사용자가 자신의 위치와 함께 게시할 수 있도록 허용하는 경우 X의 [지리 가이드라인](/ko/developer-terms/geo-guidelines)을 전부 준수해야 합니다.

**위치 데이터나 지리 정보를 단독으로 사용하는 것은 금지됩니다.** 귀하는 X Content에 포함된 위치 데이터 및 기타 지리 정보를 포스트의 일부로 사용하는 경우를 제외하고, 이를 저장, 집계 또는 캐시할 수 없으며(또한 다른 사람이 그렇게 하도록 허용할 수도 없습니다). 예를 들어, 시간이 지나면서 개인이 어디에 있었는지를 보여주기 위해 포스트에서 위치 데이터나 지리 정보를 분리해 사용할 수 없습니다. 집계된 지리 기반 활동(예: 특정 도시에서 해시태그를 사용하는 사람 수)을 보여주는 히트맵 및 관련 도구는 허용됩니다.

  ## 플랫폼 사용 지침
</div>

X의 정책을 충분히 검토하고, API 접근 권한을 올바르게 설정했나요? 서비스가 X의 개인정보 보호 및 제어 지침을 준수하고 있나요? 이 두 질문에 모두 “예”라고 답할 수 있다면 이제 X API와 X 콘텐츠를 사용할 준비가 된 것입니다. X의 플랫폼 사용 지침은 서비스의 전체 수명 주기에 걸쳐 X 콘텐츠 사용이 첫날부터 지속적으로 정책을 준수하도록 하기 위해 필요한 안내를 제공합니다. 통합이 X를 이용하는 사람들과 X 플랫폼 전체에 안전하고 유익한 방식으로 동작하는지 확인하기 위해, 이러한 규칙을 정기적으로 검토할 것을 권장합니다.

<div id="spam-bots-and-automation">
  ## 스팸, 봇, 자동화
</div>

**스팸을 생성하거나 어떤 형태로든 플랫폼 조작에 관여하기 위해 X API 및 개발자 제품을 사용하는 것은 금지됩니다.** X 규정의 [플랫폼 조작 및 스팸](https://help.x.com/rules-and-policies/platform-manipulation) 관련 조항을 검토하고, 서비스가 당사 정책을 위반하지 않으며, 다른 사람이 이를 위반하도록 하거나 가능하게 하지 않도록 해야 합니다.

**포스트 게시, 계정 팔로우, 다이렉트 메시지 전송 등 쓰기 동작을 수행하는 서비스는 [Automation Rules](https://help.x.com/rules-and-policies/x-automation)를 따라야 합니다.** 특히 다음 사항을 준수해야 합니다.

* 사람들에게 [자동 응답 또는 다이렉트 메시지](https://twittercommunity.com/t/policy-clarification-automated-replies-and-mentions/94444)를 보내기 전에 항상 명시적 동의를 받습니다.
* 더 이상 연락받기를 원치 않는다는 요청이 있으면 즉시 이를 존중합니다.
* [대량 팔로우](https://twittercommunity.com/t/policy-clarification-aggressive-following-and-inorganic-following-behavior/92769)를 포함하여 대량, 공격적, 스팸성 행동을 절대 수행하지 않습니다.
* [여러 계정](https://blog.twitter.com/developer/en_us/topics/tips/2018/automation-and-the-use-of-multiple-accounts.html)에 걸쳐 동일하거나 실질적으로 유사한 콘텐츠를 절대 게시하지 않습니다.

**API 기반 봇 계정을 운영하는 경우, 해당 계정이 어떤 계정이며 누가 책임자인지 명확하게 표시해야 합니다.** 계정이 봇인지 아닌지에 대해 사람들을 오도하거나 혼란스럽게 해서는 안 됩니다. 이를 위한 좋은 방법은 프로필 소개에 해당 계정이 봇이라는 문구를 포함하는 것입니다.

<div id="public-display-of-posts">
  ## 포스트의 공개 표시
</div>

**공개적으로 또는 귀하의 서비스를 이용하는 사람들에게 표시하는 모든 X 콘텐츠의 무결성을 반드시 유지해야 합니다.** 콘텐츠를 표시하기 위해 [X for Websites](https://developer.x.com/docs/twitter-for-websites/overview)를 사용하지 않는 경우, 표시할 수 있는 가장 최신 버전을 가져오기 위해 X API를 사용해야 합니다. 표시된 콘텐츠가 X API를 통해 더 이상 제공되지 않는 경우, 합리적으로 가능한 범위 내에서 최대한 신속하게, 또는 X나 해당 X 계정 소유자로부터 삭제 요청을 받은 후 24시간 이내에, 또는 관련 법률에서 달리 요구하는 경우 그에 따라, 귀하의 서비스에서 해당 콘텐츠를 삭제해야 합니다.

**X 콘텐츠를 오프라인으로 표시하는 경우 따라야 하는 특정 규칙이 있습니다.** 포스트를 오프라인으로 표시하는 경우, 방송에서 포스트를 사용할 때의 [가이드라인](https://developer.x.com/developer-terms/display-requirements)을 따라야 합니다.

**포스트를 임베드하거나 표시하는 경우, 귀하의 사이트가 하루 1,000만 노출 수를 초과하면 X API 접근과 관련하여 당사에 문의해야 합니다.** X는 귀하의 X API 사용 조건으로 추가 약관을 요구할 권리를 보유합니다. X for Websites를 개발 목적으로 사용할 때 적용되는 추가 제한 사항은 다음과 같습니다.

* **임베드된 포스트 및/또는 임베드된 타임라인**
  * 귀하는 귀하의 웹사이트에서의 탐색 활동에 대해, 관심 기반 광고 및 개인화를 포함하여, X가 데이터를 수집·이용한다는 사실을 완전히 공개하는 법적으로 충분한 고지를 사람들에게 제공해야 합니다. 또한 그러한 수집 및 이용에 대해 사람들로부터 법적으로 유효한 동의를 받아야 합니다.

**X 콘텐츠를 얻기에 가장 적합한 곳은 X 자체입니다. 따라서 우리는 X 콘텐츠의 제3자 재배포를 제한합니다.** 다운로드 가능한 데이터 세트 또는 API를 통해 X 콘텐츠를 제3자에게 제공하는 경우, 아래에 설명된 예외를 제외하고는 포스트 ID, 다이렉트 메시지 ID 및/또는 사용자 ID만 배포할 수 있습니다.

총합 기준으로, 30일 기간 내에 어느 하나의 단체(하나의 단체에 속한 여러 개인을 모두 포함)에 1,500,000개를 초과하는 포스트 ID를 배포할 수 없으며, X로부터 서면 허가를 받은 경우에만 예외로 할 수 있습니다. 추가로, 비자동화된 방식(예: 스프레드시트 또는 PDF 다운로드)을 통해 이루어지는 경우에 한해, 개발자는 귀하의 서비스를 사용하는 각 사용자에게 매일 최대 500개의 공개 포스트 객체 및/또는 사용자 객체를 제공할 수 있습니다.

학술 연구자는 학술 기관을 대신해 수행하는 비상업적 연구 목적에 한하여, 그리고 그러한 연구가 X로부터 서면 승인을 받았거나 동료 심사 또는 해당 연구의 검증을 위한 경우에 한하여, 포스트 ID 및/또는 사용자 ID를 배포할 수 있습니다. 그러한 연구를 위해 필요하며 X로부터 승인을 받은 범위 내에서의 포스트 ID 또는 사용자 ID만 사용할 수 있습니다.

제3자에게 제공되는 모든 X 콘텐츠는 여전히 본 정책의 적용을 받으며, 그러한 제3자는 해당 다운로드를 받기 전에 X [서비스 약관](https://x.com/tos), [개인정보 처리방침](https://x.com/privacy), [Developer Agreement](/ko/developer-terms/agreement), 및 [Developer Policy](/ko/developer-terms/policy)에 동의해야 합니다. 귀하는 이 [Policy](/ko/developer-terms/policy), [Developer Agreement](/ko/developer-terms/agreement) 또는 X와 체결한 기타 어떠한 계약에 포함된 X 콘텐츠 배포에 대한 다른 한도나 제한을 우회할 수 있도록 어떤 단체에도 허용해서는 안 됩니다.

</div>

**품질 높은 사용 경험을 제공하려면, 카드를 표시하는 모든 플랫폼에서 올바르게 렌더링되도록 카드를 개발해야 합니다.** 카드를 사용할 때 따라야 하는 추가 규칙은 다음과 같습니다.

* 카드 내에 민감한 미디어를 표시할 계획이라면, 해당 포스트의 민감한 미디어 표시 설정을 ‘true’로 지정해야 합니다
* 카드 내에서 사용하는 모든 리소스를 호스팅할 때는 HTTPS를 사용해야 합니다. 카드는 활성 혼합 콘텐츠에 대한 브라우저 경고를 절대로 발생시켜서는 안 됩니다
* 오디오 및 비디오 콘텐츠에는 중지 또는 일시정지 컨트롤이 포함되어야 하며, 자동 재생되는 비디오는 기본적으로 ‘소리 끔’ 상태여야 합니다

**카드(카드의 의도된 사용 방식 포함)에 대해 X가 설정한 제한을 초과하거나 이를 우회해서는 안 됩니다.** 카드 사용과 관련한 추가 제한은 다음과 같습니다.

* X의 승인을 받지 않고 카드에 제3자 스폰서드 콘텐츠를 포함시켜서는 안 됩니다
* 카드 내에서 또는 카드로부터 X 상에서 금전적 인센티브(가상 화폐 포함)를 부여해서는 안 됩니다
* 카드 내에 URL 및 미디어와 같이 오해의 소지가 있거나 문맥상 관련성이 없는 콘텐츠 또는 동작을 포함시켜서는 안 됩니다
