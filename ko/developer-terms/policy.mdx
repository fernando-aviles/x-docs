<div id="x-developers">
  ## X + 개발자
</div>

X는 개발자를 소중히 여깁니다. X 데이터의 힘을 활용해 이 커뮤니티가 만들어 내는 다양한 도구와 서비스에 늘 기쁨과 놀라움을 느끼고 있습니다. 이 커뮤니티에 대한 우리의 약속의 일환으로, 우리는 개발자에게는 개방적이고 공정하며, X를 이용하는 사람들에게는 안전하고, X 플랫폼 전체에도 이로운 방식으로 데이터 접근을 제공하는 것을 목표로 합니다. 이러한 목표를 달성하기 위해, 우리는 API 및 X 콘텐츠의 적절한 사용에 관한 우리의 규칙과 기대를 이해하는 데 도움이 되도록 지침 역할을 하는 개발자 정책(Developer Policy)을 마련했습니다.

이 개발자 정책(“**정책**”)은 X의 애플리케이션, 서비스, 웹사이트, 웹 페이지 및 콘텐츠로 구성된 생태계와 상호 작용하는 개발자를 위한 규칙과 가이드라인을 제공합니다. 이 정책은 X API 및 X 콘텐츠에 대한 접근 및 사용을 규율하는, X와 체결한 계약(개발자 계약 또는 X와의 기타 서면 계약의 일부로서)의 일부입니다. 정책 위반은 귀하의 계약 위반으로 간주됩니다. 이 정책은 예고 없이 수시로 변경될 수 있습니다. 이 정책에서 사용되지만 정의되지 않은 대문자로 시작하는 용어는 [개발자 계약](/ko/developer-terms/agreement) 또는 마스터 라이선스 계약에서 각각 부여된 의미를 갖습니다.

<div id="using-this-policy">
  ## 이 정책 사용 방법
</div>

이 정책은 최대한 이해하고 따르기 쉽도록 구성되어 있습니다. X API 및 X 콘텐츠를 사용할 때는 아래 정책 섹션의 내용을 항상 염두에 두시기 바랍니다:

1. **성공을 위한 준비** - 모든 X 정책을 준수할 책임은 귀하에게 있습니다. X API 및 X 콘텐츠에 접근하기 전에, 이 정책과 이 문서에서 링크하는 다른 정책들을 검토하고 이해하는 것이 중요합니다. 정책을 검토하는 데 들이는 시간이 향후 재작업에 들일 수 있는 많은 시간을 절약해 줄 수 있습니다.

2. **프라이버시와 통제권은 필수적입니다** - X에서 사람들의 프라이버시를 보호하고 수호하는 것은 우리 회사의 핵심 DNA에 내재되어 있습니다. 따라서 우리는 사람들의 합리적인 프라이버시 기대에 반하는 방식으로 X 데이터를 사용하는 것을 금지합니다. X API를 기반으로 서비스를 구축하거나 X 콘텐츠에 접근함으로써, 귀하는 이 약속을 지키는 데 있어 특별한 역할을 맡게 되며, 가장 중요한 것은 사람들의 프라이버시를 존중하고 그들의 데이터가 어떻게 사용되는지에 대해 투명성과 통제권을 제공하는 것입니다.

3. **플랫폼 사용 지침을 따르십시오** - X API 및 X 콘텐츠에 대한 접근 승인을 받는 것은 첫걸음에 불과합니다. X 플랫폼을 어떻게 사용할 계획인지에 대해 정책 준수 여부가 궁금할 때마다, 플랫폼 사용 지침이 가장 먼저 확인해야 할 곳입니다.

이 세 가지 핵심 섹션 각각의 의미에 대해 아래에서 더 자세히 설명합니다. 귀하의 X API 및 X 콘텐츠 사용이 우리의 정책과 일치하는지 확인할 수 있도록, 이 내용을 주의 깊게 검토해 주십시오.

당사가 귀하가 본 정책(또는 다른 X 정책)을 위반하고 있다고 판단하는 경우, X API 및 X 콘텐츠에 대한 귀하의 접근을 일시 중단하거나 영구적으로 철회할 수 있습니다.

마지막으로, X는 X 애플리케이션을 개선하고, 상업적 사용 여부를 검토하며, 승인된 사용 사례 및 본 정책에 대한 준수 여부를 확인하기 위해 귀하의 X API 사용을 모니터링할 수 있음을 유의해 주십시오.

읽어 주시고 X와 함께 구축해 주셔서 감사합니다! 귀하가 무엇을 만들어 내실지 기대하겠습니다!

<div id="set-yourself-up-for-success">
  ## 성공을 위한 기반 마련
</div>

X API를 사용할 때 서비스가 처음부터 올바른 방식으로 구축되어 있다면 많은 잠재적인 문제를 피할 수 있습니다. 이 Developer Policy 섹션에는 X API 또는 X 콘텐츠를 사용하기 전에 모든 개발자가 따라야 하는 규칙이 포함되어 있습니다.

[developer.x.com/en](http://developer.x.com/en)에 설명된 Free, Basic, Pro 플랜은 취미용, 상업적 프로토타입, 초기 단계 X 제품 통합, 그리고 최종 사용자 수가 제한적인 애플리케이션 지원을 위해 설계되었습니다. 이 범위를 넘어 X API 및 X 콘텐츠를 사용하는 경우, Enterprise 플랜([developer.x.com/en](http://developer.x.com/en)에 설명됨)을 신청하거나 이미 구독하고 있어야 합니다.

**X 개발자 플랫폼에 대한 모든 예정된 사용 방식은 정책 준수 여부를 확인하기 위해 검토되며, 이에 따라 X API 및 X 콘텐츠에 대한 액세스 권한을 부여·유지받으려면 해당 사용 계획을 공개하고(해당되는 경우 갱신하여) 명시해야 합니다.** 모든 신규 개발자는 X API에 접근하기 위해 [개발자 계정을 신청](https://developer.x.com/portal/petition/essential/basic-info)해야 합니다. 승인된 개발자 계정이 없는 기존 개발자는 X의 안내에 따라 개발자 계정을 신청해야 합니다. 이 과정의 일환으로, X API 및 X 콘텐츠의 의도된 사용 목적에 대한 서면 설명을 제공해야 합니다.

사용 사례 설명은 귀하에게 구속력을 가지며, 이에 실질적으로 반하는 방식으로 사용하는 경우 당사 규칙 위반에 해당할 수 있고 집행 조치로 이어질 수 있습니다. 사용 사례에 실질적인 변경이 있는 경우, 그 변경 사항을 당사에 통지하고, 해당 새로운 목적을 위해 X 콘텐츠 사용을 시작하기 전에 승인을 받아야 합니다. 이를 이행하지 않으면 API 및 데이터 접근의 정지 또는 종료로 이어질 수 있습니다.

**X API를 기반으로 구축하거나 X 콘텐츠에 접근하는 경우, 모든 X 정책을 준수해야 합니다.** 여기에는 본 [Developer Policy](/ko/developer-terms/policy), [Automation Rules](https://help.x.com/rules-and-policies/x-automation), [Display Requirements](https://developer.x.com/developer-terms/display-requirements.html), [API Restricted Uses Rules](/ko/developer-terms/restricted-use-cases), [X Rules](https://help.x.com/rules-and-policies/x-rules), [X Brand Resources](https://about.x.com/who-we-are/brand-toolkit)가 포함되며, X API 또는 X 콘텐츠 사용과 관련하여 X와 체결하는 기타 모든 계약(예: [Developer Agreement](/ko/developer-terms/agreement) 또는 Master Licensing Agreement 또는 Order(해당되는 경우 등))도 포함됩니다. 또한 이러한 정책에 대한 모든 수정 사항 및 X가 새로 도입하는 모든 정책도 준수해야 합니다. 귀하의 서비스 사용을 모니터링하고, 서비스 설계 시 사용자가 X 정책을 위반하지 못하도록 방지하는 것은 전적으로 귀하의 책임입니다. 이를 이행하지 않을 경우, 귀하의 API 및 X 콘텐츠 접근은 정지되거나 종료될 수 있습니다.

**단일 사용 사례 또는 실질적으로 유사하거나 중복되는 사용 사례에 대해 여러 애플리케이션을 등록할 수 없습니다.** 이 맥락에서 “사용 사례(use case)”란 애플리케이션을 통해 수행되는 일관된 분석, 표시 또는 동작의 집합을 의미합니다. 도구나 서비스의 &quot;화이트 레이블(white label)&quot; 버전은 허용되지 않습니다. 애플리케이션의 &quot;화이트 레이블&quot; 버전을 제공할 계획이 있는 경우, 당사에 통지하고 별도의 승인을 받아야 합니다.

*이러한 규칙에 대한 단일 예외로,* 동일한 서비스의 development, staging, production 인스턴스를 위해 최대 3개의 애플리케이션을 생성하고 사용할 수 있습니다. 이 앱들은 단일 계정에 등록되어야 하며, 각각의 이름과 설명에서 단일 서비스의 dev, staging, prod 인스턴스임을 명확하게 식별할 수 있어야 합니다. **development 또는 staging 애플리케이션을 production 용도로 사용할 수 없습니다.**

**모든 API 키 및 기타 접근 자격 증명은 비공개로 유지해야 합니다.** 타인이 소유한 API 키 또는 기타 접근 자격 증명을 사용할 수 없으며, 타인이 이를 사용하도록 조장하거나 지원할 수도 없습니다.

**X와 체결한 라이선스 계약은 귀하의 X API 및 X 콘텐츠 사용을 제한합니다. 특히, X API에는 플랫폼에서 공정한 데이터 사용을 보장하고 스팸과 싸우기 위한 요청 한도가 존재합니다.** 본 정책 또는 X와의 계약에 설명되어 있거나, [Developer Site](https://developer.x.com/)에 게시되어 있거나, X가 귀하에게 통지한 요청 한도 또는 그 밖의 어떠한 제한이나 제약도 초과하거나 우회해서는 안 됩니다.

**X API를 통해 수신한 X 콘텐츠에 포함된 어떤 독점 표시나 기재도 삭제하거나 변경할 수 없습니다.** 이는 사람들이 X 콘텐츠의 출처와 소유자를 명확히 알 수 있도록 하기 위한 것입니다.

**데이터 무결성과 플랫폼의 건전성을 위해, X API 또는 X 서비스의 어떠한 기능도 방해, 가로채기, 중단 또는 비활성화해서는 안 됩니다.** 즉, [developer.x.com](https://developer.x.com/)에 의도와 문서로 명시된 대로 API를 사용해야 합니다. 허용 가능한 사용에 대한 보다 자세한 내용은 [HackerOne 가이드라인](https://hackerone.com/x)을 참고하십시오.

<div id="privacy-and-control-are-essential">
  ## 프라이버시와 통제는 필수적입니다
</div>

X는 프라이버시를 매우 중요하게 여기며, X 콘텐츠와 X API를 사용하는 모든 분들도 이에 동참하기를 기대합니다. X 개발자 플랫폼, X API 또는 X 콘텐츠를 사람들이 합리적으로 기대하는 프라이버시 수준에 어긋나는 방식으로 사용하는 경우, API 및 X 콘텐츠 접근의 정지 또는 종료를 포함한 제재 조치의 대상이 될 수 있습니다.

프라이버시와 통제에 대한 귀하의 책임은 X 콘텐츠의 모든 사용과, 당사의 API를 사용해 구축하는 서비스의 모든 측면에까지 확장되어야 합니다. 이를 위해, 귀하의 서비스를 사용하는 사람들은 귀하가 그들의 데이터를 어떻게 사용하고, 그들을 대신해 어떻게 X에 접근하는지 이해하고 이에 동의해야 합니다. 이를 위해 사람들에게 명확하고 포괄적이며 투명한 개인정보 처리방침을 제공하고, 그들을 대신해 어떤 조치를 취하기 전에 서비스 사용 중인 각 개인으로부터 명시적이고 충분한 설명에 기반한 동의를 확보해야 합니다. **사람이 귀하의 서비스에 로그인 또는 인증했다는 사실만으로는 동의로 간주될 수 없다는 점에 유의하시기 바랍니다.**

<div id="consent-permissions">
  ## 동의 및 권한
</div>

**특히, 아래와 같은 행위를 하기 전에 당사자들로부터 명시적이고 사전에 충분한 설명을 제공한 동의를 받아야 합니다.**

* 다른 사람을 대신하여 *어떠한* 행동이라도 수행하는 경우. 여기에는 (이에 국한되지 않고) 다음이 포함됩니다.
  * X에 콘텐츠를 게시하는 것
  * 계정을 팔로우/언팔로우하는 것
  * 프로필 또는 계정 정보를 수정하는 것
  * 포스트에 해시태그 또는 기타 콘텐츠를 추가하는 것

* X API 또는 기타 X 도구가 아닌 다른 수단으로 접근한 콘텐츠를 다시 게시하는 것

* 다른 사람의 X 콘텐츠를 사용하여 제품이나 서비스를 홍보하는 것

* 다이렉트 메시지(DM)와 같은 비공개 콘텐츠 또는 기타 개인적이거나 기밀인 정보를 저장하는 것

* 보호된 콘텐츠 또는 기타 개인적이거나 기밀인 정보를 공유하거나 게시하는 것

**귀하의 서비스가 이용자가 X에 콘텐츠를 게시할 수 있도록 허용하는 경우, 게시하기 전에 다음을 수행해야 합니다.**

* 정확히 무엇이 게시될 것인지 보여줍니다.
* 귀하의 서비스를 이용하는 사람들에게 어떤 위치 정보(있는 경우)가 콘텐츠에 추가되는지 명확히 알립니다.

**귀하의 서비스가 이용자가 귀하의 서비스와 X 모두에 콘텐츠를 게시할 수 있도록 허용하는 경우, 게시하기 전에 다음을 수행해야 합니다.**

* 콘텐츠를 게시할 수 있는 권한을 획득합니다.
* 콘텐츠를 어디에 게시할 것인지 설명합니다.

**모든 X 콘텐츠의 보호 및 차단 상태를 존중해야 합니다. 한 사람의 인증 토큰을 사용해 얻은 콘텐츠를, 해당 콘텐츠를 볼 권한이 없는 다른 사람에게 제공해서는 안 됩니다.**

* **보호된 계정:** [보호된 계정](https://help.x.com/safety-and-security/public-and-protected-posts)의 콘텐츠는 해당 계정을 팔로우하도록 계정 소유자가 승인한 사람에게만 제공됩니다. 따라서 귀하가 보호된 계정에 접근하는 서비스를 운영하는 경우, 그러한 콘텐츠를 해당 콘텐츠를 볼 권한이 있는 특정 사람들에게 제공하는 목적에 한해서만 접근해야 합니다.
* **차단된 계정:** X 이용자는 원하는 어떤 이유로든 자신의 계정에 대한 접근을 [차단](https://help.x.com/using-x/blocking-and-unblocking-accounts)할 수 있습니다. 이 선택을 우회하기 위해 토큰(또는 기타 API 기반 작업)으로 얻은 정보를 서로 뒤섞어 사용하는 행위는 허용되지 않습니다.

**다이렉트 메시지(DM)는 비공개적 특성을 가지므로, DM 기능을 제공하는 서비스는 개인 정보 보호를 위해 추가적인 조치를 취해야 합니다. DM 콘텐츠를 볼 권한이 없는 사람에게 DM 콘텐츠를 제공해서는 안 됩니다. 귀하의 서비스가 DM 기능을 제공하는 경우 다음도 수행해야 합니다.**

* DM에 대해 읽음 확인(read receipt) 이벤트를 전송하는 경우 이를 사람들에게 알립니다. 이는 귀하의 서비스 내에서 직접 고지를 제공하거나, 대화에 참여한 다른 사람들의 읽음 확인을 표시함으로써 수행할 수 있습니다.
* DM에서 전송되는 미디어를 &quot;shared&quot;(즉, 여러 DM 간에 재사용 가능)로 설정하기 전에 동의를 얻습니다. DM 내 미디어를 &quot;shared&quot;로 허용하는 경우, 이 콘텐츠가 해당 미디어의 URL을 가진 누구에게나 접근 가능하다는 점을 명확한 고지로 제공해야 합니다.

<div id="content-compliance">
  ## 콘텐츠 규정 준수
</div>

**X 콘텐츠를 오프라인으로 저장하는 경우, X에서의 해당 콘텐츠의 현재 상태와 일치하도록 최신 상태를 유지해야 합니다.** 특히, X에서 삭제되거나 수정된 콘텐츠가 있는 경우, 보유 중인 해당 콘텐츠도 삭제하거나 수정해야 합니다. 이는 합리적으로 가능한 한 신속하게, 또는 X나 해당 X 계정 소유자로부터 그러한 요청을 받은 때로부터 24시간 이내에, 혹은 X와의 계약 또는 관련 법률에 따라 요구되는 기간 내에 수행되어야 합니다. 이 조치는 관련 법률에 의해 달리 금지되지 않는 한 이행되어야 하며, 그러한 경우에도 X의 명시적인 서면 허가가 있는 때에만 예외가 인정됩니다.

수정된 콘텐츠는 다양한 형태를 취할 수 있습니다. 여기에는 다음과 같은 경우가 포함되나 이에 제한되지 않습니다:

* 비공개로 전환되었거나 보호 상태가 된 콘텐츠
* 플랫폼에서 정지된 콘텐츠
* 지오태그가 제거된 콘텐츠
* X에서 차단되었거나 삭제된 콘텐츠

<div id="off-x-matching">
  ## X 외 매칭
</div>

**X 상의 개인을 X 외부에서 얻거나 저장한 정보와 매칭할 수 있는 상황은 엄격히 제한됩니다.** X 외 매칭이란 X 콘텐츠(예: X @handle 또는 user ID 포함)를 개인, 가구, 기기, 브라우저 또는 기타 X 외부 식별자와 연관시키는 행위를 의미합니다. 이러한 연관은 사전에 해당 개인으로부터 명시적인 옵트인 동의를 받았을 때에만, 또는 아래에 설명된 경우에만 허용됩니다.

개인의 X 아이덴티티를 X 외부 식별자와 연결하는 것에 대해 그 사람의 명시적인 옵트인 동의를 받지 못한 상황에서는, 귀하가 만드는 모든 연결은 그 목적을 위해 사용될 것이라고 누군가가 합리적으로 예상할 수 있는 정보에만 근거해야 합니다. 또한, 개인의 명시적 옵트인 동의가 없는 경우, 특정 개인에 대한 귀하의 기록을 X 아이덴티티와 매칭하려는 시도는 다음에 근거해서만 할 수 있습니다.

* **당사자가 귀하에게 직접 제공한 정보.** 귀하와 사전 관계가 없는 개인에 대한 기록(제3자로부터 취득한 개인 데이터 포함)은 이 기준을 충족하지 못한다는 점에 유의해야 합니다. 및/또는
* **공개 데이터.** 이 문맥에서 “공개 데이터”는 다음을 의미합니다.
  * 귀하가 공적이고 일반에게 공개된 자료(예: 어떤 직업 협회의 회원 명단)에서 취득한 개인에 대한 정보
  * 다음과 같이 X 상에서 개인에 대해 공개적으로 제공되는 정보:
    * 포스트
    * 계정 소개(bio)와 공개된 위치를 포함한 프로필 정보
    * 표시 이름과 @handle

<div id="using-geo-data">
  ## 지리 데이터 사용
</div>

**지리 데이터는 정보의 민감한 특성 때문에 추가적인 제한이 적용됩니다.** 서비스가 포스트에 위치 정보를 추가하는 경우, 이용자에게 다음을 고지해야 합니다:

* 언제 위치 정보를 추가하는지
* 위치 정보를 지오태그로 추가하는지, 아니면 주석 데이터로 추가하는지
* 위치 정보가 장소로 표시되는지, 아니면 지리 좌표로 표시되는지

애플리케이션이 이용자가 자신의 위치 정보와 함께 게시할 수 있도록 허용하는 경우, X의 [지리 가이드라인](/ko/developer-terms/geo-guidelines)을 전적으로 준수해야 합니다.

**위치 데이터 또는 지리 정보를 단독으로 사용하는 것은 금지됩니다.** X 콘텐츠에 포함된 위치 데이터 및 기타 지리 정보는 게시물의 일부인 경우를 제외하고 저장, 집계 또는 캐시할 수 없으며, 다른 사람이 그렇게 하도록 허용해서도 안 됩니다. 예를 들어, 개인이 시간이 지남에 따라 어디에 있었는지를 표시하기 위해 위치 데이터 또는 지리 정보를 포스트에서 분리해서는 안 됩니다. 집계된 지리 활동(예: 특정 도시에서 해시태그를 사용하는 사람 수)을 보여주는 히트맵 및 관련 도구는 허용됩니다.

<div id="platform-usage-guidelines">
  ## 플랫폼 사용 가이드라인
</div>

X의 정책을 충분히 검토하고 API 접근 권한을 올바르게 설정했나요? 서비스는 X의 프라이버시 및 제어 관련 가이드라인을 준수하고 있나요? 이 두 질문에 모두 “예”라고 답할 수 있다면, 이제 X API와 X 콘텐츠를 사용할 준비가 된 것입니다. X의 플랫폼 사용 가이드라인은 서비스의 전체 라이프사이클 전반에 걸쳐, X 콘텐츠 사용이 첫날부터 지속적으로 정책을 준수할 수 있도록 필요한 도움을 제공합니다. 통합된 기능이 X를 이용하는 사람들과 X 플랫폼 전체에 대해 안전하고 유익한 방식으로 운영되고 있는지 확인하기 위해 이러한 규칙을 정기적으로 검토할 것을 권장합니다.

<div id="spam-bots-and-automation">
  ## 스팸, 봇, 그리고 자동화
</div>

**스팸을 생성하거나 어떤 형태로든 플랫폼 조작에 관여하기 위해 X API 및 개발자 제품을 사용하는 것은 금지됩니다.** [플랫폼 조작 및 스팸](https://help.x.com/rules-and-policies/platform-manipulation)에 대한 X 규칙을 검토하고, 서비스 자체가 정책을 위반하지 않을 뿐만 아니라, 다른 사람들이 이를 위반하도록 가능하게 하지 않도록 하십시오.

**포스트 게시, 계정 팔로우, 다이렉트 메시지 전송 등 쓰기 작업을 수행하는 서비스는 [자동화 규칙](https://help.x.com/rules-and-policies/x-automation)을 따라야 합니다.** 특히, 다음 사항을 준수해야 합니다:

* 사람들에게 [자동 응답 또는 다이렉트 메시지](https://twittercommunity.com/t/policy-clarification-automated-replies-and-mentions/94444)를 보내기 전에 항상 명시적인 동의를 받으십시오.
* 귀하로부터 연락을 받지 않겠다는 옵트아웃 요청이 있을 경우 즉시 이에 따르십시오.
* [대량 팔로우](https://twittercommunity.com/t/policy-clarification-aggressive-following-and-inorganic-following-behavior/92769)를 포함하여 대량, 공격적, 또는 스팸성 행위를 절대 수행하지 마십시오.
* [여러 계정](https://blog.twitter.com/developer/en_us/topics/tips/2018/automation-and-the-use-of-multiple-accounts.html)에 동일하거나 실질적으로 유사한 콘텐츠를 절대 게시하지 마십시오.

**API 기반 봇 계정을 운영하는 경우, 해당 계정의 성격과 책임 주체가 누구인지 명확히 표시해야 합니다.** 계정이 봇인지 여부에 대해 사람들을 호도하거나 혼란스럽게 해서는 안 됩니다. 이를 위한 좋은 방법은 프로필 소개(bio)에 해당 계정이 봇임을 명시하는 문구를 포함하는 것입니다.

**X API를 사용하여 X의 가용성, 성능, 기능 또는 사용량을 벤치마킹, 경쟁 또는 상업적 목적을 위해 측정할 수 없습니다.** 예를 들어, X API를 다음과 같은 목적으로 사용해서는 안 됩니다:

<div id="public-display-of-posts">
  ## 포스트의 공개 표시

**공개적으로 또는 귀하의 서비스를 이용하는 사람들에게 표시하는 모든 X 콘텐츠의 무결성을 반드시 유지해야 합니다.** 콘텐츠를 표시하기 위해 [X for Websites](https://developer.x.com/docs/twitter-for-websites/overview)를 사용하지 않는 경우, 표시용으로 사용 가능한 가장 최신 버전을 조회하기 위해 X API를 사용해야 합니다. 표시된 콘텐츠가 X API를 통해 더 이상 제공되지 않는 경우, 합리적으로 가능한 한 신속하게, 또는 X나 해당 X 계정 소유자로부터 삭제 요청을 받은 후 24시간 이내에, 또는 관련 법률에서 달리 요구되는 경우에는 그에 따라, 해당 콘텐츠를 귀하의 서비스에서 제거해야 합니다.

**포스트를 임베드하거나 표시하는 경우, 귀하의 사이트의 일일 노출 수가 1,000만 회를 초과하면 X API 액세스에 관해 반드시 당사에 연락해야 합니다.** X는 X API 사용의 조건으로 추가 약관을 요구할 권리를 보유합니다. X for Websites를 사용하는 개발자에 대한 추가 제한 사항은 다음과 같습니다:

  * 사용자에게 [여기](https://help.x.com/x-for-websites-ads-info-and-privacy)에 설명된 대로 X의 관심기반 광고 및 개인화를 어떻게 옵트아웃할 수 있는지에 대한 법적으로 유효한 안내를 제공해야 합니다.

* **X for Websites 위젯**
  * 법률상 해당 정보 제공 및 동의 획득이 요구되는 경우, X의 [쿠키 사용](https://help.x.com/rules-and-policies/x-cookies)에 설명된 대로, 사용자에게 그들의 기기에 쿠키 또는 기타 정보가 저장·접근되는 것에 관한 명확하고 포괄적인 정보와 이에 대한 동의가 제공되도록 해야 합니다.

* **13세 미만 아동을 대상으로 하는 서비스**
  * 13세 미만 아동을 대상으로 하는 서비스는, [여기](https://developer.x.com/docs/twitter-for-websites/privacy)에 설명된 대로 임베드된 포스트 및/또는 임베드된 타임라인에서 X 맞춤화를 해제하기 위해 옵트아웃 파라미터를 ‘true’로 설정해야 합니다.

<div id="content-redistribution">
  ## 콘텐츠 재배포
</div>

**X 콘텐츠를 얻기에 가장 좋은 곳은 X 그 자체입니다. 따라서 X는 X 콘텐츠의 제3자에 대한 재배포를 제한합니다.** 다운로드 가능한 데이터 세트나 API를 통해 등 제3자에게 X 콘텐츠를 제공하는 경우, (아래에서 설명한 예외를 제외하고) Post IDs, Direct Message IDs 및/또는 User IDs만 배포할 수 있습니다.

어느 30일 기간이든, X로부터 서면 허가를 받지 않는 한, 단일 엔터티(해당 엔터티에 소속된 여러 개인을 모두 포함)를 대상으로 1,500,000개를 초과하는 Post IDs를 배포할 수 없습니다. 또한, 개발자는 비자동화 수단(예: 스프레드시트 또는 PDF 다운로드)을 통해 이루어지는 경우에 한해, 귀하의 서비스를 이용하는 각 사용자에게 매일 최대 500개의 public Posts Objects 및/또는 User Objects를 제공할 수 있습니다.

학술 연구자는 학술 기관을 대신하여 비상업적 연구를 수행하기 위한 목적으로, 그리고 X로부터 서면 승인을 받은 연구이거나 해당 연구의 동료 심사 또는 검증을 위한 목적으로, 오직 Post IDs 및/또는 User IDs만을 배포할 수 있습니다. 그러한 연구를 위해 필요하며 X가 승인한 범위 내에서만 Post IDs 또는 User IDs를 사용할 수 있습니다.

제3자에게 제공되는 모든 X 콘텐츠는 계속해서 본 정책의 적용을 받으며, 해당 제3자는 이러한 다운로드를 받기 전에 X [이용 약관](https://x.com/tos), [개인정보 처리방침](https://x.com/privacy), [Developer Agreement](/ko/developer-terms/agreement) 및 [Developer Policy](/ko/developer-terms/policy)에 동의해야 합니다. 귀하는 이 [정책](/ko/developer-terms/policy), [Developer Agreement](/ko/developer-terms/agreement) 또는 X와 체결한 기타 계약에 포함된 X 콘텐츠 배포에 관한 다른 제한이나 한도를 어떤 엔터티도 우회할 수 있도록 허용해서는 안 됩니다.

**참고:** 본 섹션은 EU Digital Services Act (2022) 제40조(“**DSA**”)에 따라 X API에 접근 권한을 가진 연구자에게는 적용되지 않으며, 이들은 대신 DSA 및 Developer Agreement에 명시된 절차와 제한의 적용을 받습니다.

<div id="advertising-on-x">
  ## X에서 광고하기
</div>

**X 콘텐츠 주변에서 광고를 게재할 수 있는 방식과 위치에는 제한이 있습니다.** 우선, 귀하의 광고는 게시물(Post)과 유사하게 보이거나 사람들이 게시물로 오인할 수 있는 형태여서는 안 됩니다. 광고와 관련된 기타 규칙은 다음과 같습니다.

* **X 콘텐츠와 귀하의 광고 사이에는 명확한 구분이 있어야 합니다.** X Ads를 제외하고, X 타임라인 내에 어떤 광고도 게재할 수 없습니다.
* **X는 X API를 통해 광고를 제공할 권리를 보유합니다.** 우리가 API를 통해 X Ads를 제공하기 시작한 이후 귀하가 이를 게재하기로 선택하는 경우, 적용 가능한 약관에 따라 광고 수익의 일부를 귀하와 공유합니다.
* **귀하는 X 플랫폼 외부에서 이용자를 타게팅하기 위해 X 콘텐츠 또는 X API에서 얻은 정보를 광고 목적으로 사용할 수 없습니다.**

아래에 나열된 X 서비스나 기능을 사용하는 경우, 다음의 추가 규칙이 적용됩니다:

<div id="x-login">
  ## X 로그인
</div>

**사용자가 X에 로그인하고 로그아웃할 수 있는 옵션을 쉽게 찾을 수 있도록 제공해야 합니다. 예를 들어 OAuth 프로토콜을 사용할 수 있습니다.** *Sign in with X* 옵션은 귀하의 서비스에서 제공되는 다른 회원가입 또는 로그인 기능만큼, 또는 그보다 더 눈에 띄게 표시되어야 합니다. 또한 X 계정이 없는 사용자에게도 X를 통해 계정을 생성할 수 있는 기회를 제공해야 합니다.

**사용자가 귀하의 서비스에서 *Sign in with X*를 통해 인증을 완료한 경우, 해당 사용자의 X 식별 정보를 명확하게 표시해야 합니다.** X 식별 정보에는 사용자의 현재 X @handle, 아바타, 그리고 X 로고가 포함됩니다. 귀하의 서비스에서 사용자의 X 팔로워를 표시하는 경우, 해당 팔로우 관계가 X와 연관된 것임을 명확하게 보여 주어야 합니다.

<div id="x-cards">
  ## X Cards
</div>

**양질의 경험을 제공하려면 Card가 표시되는 모든 플랫폼에서 올바르게 렌더링되도록 Card를 개발해야 합니다.** Card를 사용할 때 따라야 하는 추가 규칙은 다음과 같습니다.

* Card 내에 민감한 미디어를 표시할 계획이라면, 해당 게시물에 민감한 미디어 여부를 ‘true’로 설정해야 합니다.
* Card 내의 모든 에셋을 호스팅할 때는 HTTPS를 사용해야 합니다. Card로 인해 브라우저에서 활성 혼합 콘텐츠 경고가 표시되어서는 안 됩니다.
* 오디오 및 비디오 콘텐츠에는 중지 또는 일시정지 컨트롤이 포함되어야 하며, 자동 재생되는 비디오의 기본값은 ‘소리 끔’이어야 합니다.

**Card에 적용된 X의 모든 제한(해당 Card의 의도된 사용 방식에 대한 제한을 포함)을 초과하거나 이를 우회해서는 안 됩니다.** Card 사용에 대한 추가 제한은 다음과 같습니다.

* X의 승인을 받지 않고 타사 스폰서형 콘텐츠를 Card 내에 배치해서는 안 됩니다.
* Card 내에서 또는 Card를 통해 X 상에서 금전적 인센티브(가상 화폐 포함)를 부여해서는 안 됩니다.
* URL 및 미디어와 같이 오해의 소지가 있거나 문맥상 관련성이 없는 콘텐츠 또는 동작을 Card 내에 포함해서는 안 됩니다.
* 게시물에서 누군가가 해당 앱을 명시적으로 홍보하거나 언급하는 경우에만 App Card를 게시물에 첨부할 수 있습니다.
