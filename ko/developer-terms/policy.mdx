<div id="x-developers">
  ## X + 개발자
</div>

X는 개발자를 사랑합니다. 우리는 X data의 힘을 활용해 이 커뮤니티가 만들어내는 다양한 도구와 서비스에 늘 기쁨과 감탄을 느끼고 있습니다. 이 커뮤니티에 대한 우리의 약속의 일환으로, 우리는 개발자에게는 개방적이고 공정하며, X를 사용하는 사람들에게는 안전하고, X 플랫폼 전체에 이로운 data 접근을 제공하는 것을 목표로 합니다. 이러한 목표를 달성하기 위해, 우리는 사람들이 적절한 API 및 X Content 사용에 관한 우리의 규칙과 기대치를 이해하는 데 도움을 주기 위한 안내서로서 Developer Policy를 마련했습니다.

이 Developer Policy(“**Policy**”)는 X의 애플리케이션, 서비스, 웹사이트, 웹 페이지 및 콘텐츠 생태계와 상호작용하는 개발자를 위한 규칙과 지침을 제공합니다. 이는 X API 및 X Content에 대한 접근 및 사용을 규율하는 X와의 계약(Developer Agreement 또는 X와의 기타 서면 계약의 일부로서)의 일부입니다. Policy를 위반하는 행위는 귀하의 계약 위반으로 간주됩니다. 이 Policy는 사전 고지 없이 수시로 변경될 수 있습니다. 이 Policy에서 사용되지만 이 Policy에서 정의되지 않은 대문자로 시작하는 용어는 [Developer Agreement](/ko/developer-terms/agreement) 또는 Master License Agreement에서 각각 부여된 의미를 갖습니다.

<div id="using-this-policy">
  ## 이 정책 사용 방법
</div>

이 정책을 여러분이 최대한 쉽게 이해하고 따를 수 있도록 구성했습니다. X API 및 X Content를 사용할 때, 아래 정책 섹션의 내용을 항상 염두에 두시기 바랍니다.

1. **성공을 위한 준비(Set Yourself Up for Success)** - X의 모든 정책을 준수할 책임은 여러분에게 있습니다. X API와 X Content에 액세스하기 전에 이 정책은 물론, 이 문서에서 링크한 정책들도 검토하고 이해하는 것이 중요합니다. 당사의 정책을 검토하는 데 들이는 시간은 향후 수 시간에 이를 수 있는 재작업을 줄여 줄 수 있습니다.

2. **프라이버시와 통제는 필수적입니다** - X에서 사람들의 프라이버시를 보호하고 수호하는 일은 우리 회사의 핵심 DNA에 내재되어 있습니다. 따라서 우리는 사람들이 합리적으로 기대하는 프라이버시 수준과 어긋나는 방식으로 X 데이터를 사용하는 것을 금지합니다. X API를 기반으로 서비스를 구축하거나 X Content에 액세스함으로써, 여러분은 이 약속을 지키는 데 있어 특별한 역할을 맡게 되며, 무엇보다 사람들의 프라이버시를 존중하고 그들의 데이터가 어떻게 사용되는지에 대해 투명성을 제공하며, 통제권을 보장하는 것이 중요합니다.

3. **플랫폼 사용 가이드라인을 따르십시오** - X API와 X Content에 대한 액세스 승인을 받는 것은 첫 단계에 불과합니다. X 플랫폼을 계획한 방식으로 사용할 때 정책을 어떻게 준수할 수 있는지 궁금한 점이 있을 경우, 가장 먼저 참고해야 할 곳은 우리의 플랫폼 사용 가이드라인입니다.

이 세 가지 핵심 섹션 각각의 의미에 대해서는 아래에서 더 자세히 설명합니다. X API와 X Content의 사용이 우리의 정책과 일치하는지 확인하기 위해, 반드시 주의 깊게 검토해 주시기 바랍니다.

우리가 여러분이 이 정책(또는 다른 어떤 X 정책이라도)을 위반하고 있다고 판단하는 경우, X API 및 X Content에 대한 여러분의 액세스를 일시 중단하거나 영구적으로 철회할 수 있습니다.

마지막으로, X는 X 애플리케이션을 개선하고, 상업적 사용 여부를 검토하며, 승인된 사용 사례 및 이 정책에 대한 여러분의 준수 여부를 확인하기 위해 여러분의 X API 사용을 모니터링할 수 있다는 점을 유의하시기 바랍니다.

읽어 주셔서 감사드리며, 우리와 함께 개발해 주셔서 감사합니다! 여러분이 무엇을 만들어 내실지 기대하고 있습니다!

<div id="set-yourself-up-for-success">
  ## 성공적인 시작을 위한 준비
</div>

X API를 사용할 때, 처음부터 올바른 방식으로 서비스를 구축하면 많은 잠재적인 문제를 예방할 수 있습니다. 이 Developer Policy 섹션에는 X API 또는 X Content를 사용하기 전에 모든 개발자가 반드시 따라야 하는 규칙이 포함되어 있습니다.

Free, Basic, Pro 요금제([developer.x.com/en](http://developer.x.com/en)에 설명됨)는 취미용, 상업적 프로토타이핑, 초기 단계 X 제품 연동, 그리고 제한된 최종 사용자 수를 가진 애플리케이션을 위해 설계되었습니다. 이 범위를 넘어 X API 및 X Content를 사용하는 경우, Enterprise 요금제([developer.x.com/en](http://developer.x.com/en)에 설명됨)를 신청(또는 이미 구독)해야 합니다.

**X 개발자 플랫폼의 제안된 모든 사용 사례는 정책 준수 여부를 확인하기 위해 검토되므로, X API 및 X Content에 대한 액세스 권한을 부여받고 이를 유지하려면 계획된 사용 목적을 공개하고(필요 시 갱신하여) 알려야 합니다.** 모든 신규 개발자는 X API에 액세스하기 위해 [개발자 계정을 신청](https://developer.x.com/portal/petition/essential/basic-info)해야 합니다. 현재 개발자 중 승인된 개발자 계정이 없는 경우, X의 안내에 따라 계정을 신청해야 합니다. 이 과정의 일환으로, X API 및 X Content의 예정된 사용 목적에 대한 서면 설명을 제공해야 합니다.

사용 사례 설명은 귀하에게 구속력을 가지며, 그로부터 실질적으로 벗어나는 경우 당사의 규칙 위반이 될 수 있고, 그에 따른 조치가 이루어질 수 있습니다. 사용 사례에 실질적인 변경이 있는 경우, 해당 변경 내용에 대해 당사에 통지하고, 그 새로운 목적을 위해 X Content를 사용하기 전에 승인을 받아야 합니다. 이를 이행하지 않을 경우, API 및 데이터 액세스의 중단 또는 종료로 이어질 수 있습니다.

**X API를 기반으로 서비스를 구축하거나 X Content에 액세스하는 경우, 모든 X 정책을 준수해야 합니다.** 여기에는 이 [Developer Policy](/ko/developer-terms/policy), [Automation Rules](https://help.x.com/rules-and-policies/x-automation), [Display Requirements](https://developer.x.com/developer-terms/display-requirements.html), [API Restricted Uses Rules](/ko/developer-terms/restricted-use-cases), [X Rules](https://help.x.com/rules-and-policies/x-rules), [X Brand Resources](https://about.x.com/who-we-are/brand-toolkit)뿐만 아니라, X API 또는 X Content 사용과 관련하여 X와 체결하는 기타 모든 계약(예: [Developer Agreement](/ko/developer-terms/agreement) 또는 Master Licensing Agreement 또는 Order(해당되는 경우))이 포함됩니다. 또한, 이러한 정책의 변경 사항 및 X가 새로 도입하는 모든 정책을 준수해야 합니다. 귀하는 자신의 서비스 사용을 모니터링하고, 사용자가 X 정책을 위반하지 않도록 서비스를 설계할 책임이 있습니다. 이를 이행하지 않을 경우, API 및 X Content 액세스의 중단 또는 종료로 이어질 수 있습니다.

**하나의 사용 사례 또는 실질적으로 유사하거나 중복되는 사용 사례에 대해 여러 개의 애플리케이션을 등록할 수 없습니다.** 이 문맥에서 “사용 사례(use case)”란 애플리케이션을 통해 수행되는 일관된 분석, 표시, 또는 행동의 집합을 의미합니다. 툴 또는 서비스의 &quot;화이트 라벨(white label)&quot; 버전은 허용되지 않습니다. 애플리케이션의 “화이트 라벨” 버전을 제공할 계획이 있는 경우, 반드시 당사에 통지하고 별도의 승인을 받아야 합니다.

*이 규칙에 대한 단 하나의 예외로,* 동일한 서비스의 개발(dev), 스테이징(staging), 운영(prod) 인스턴스를 위해 최대 3개의 애플리케이션을 생성하고 사용할 수 있습니다. 이러한 앱은 단일 계정에 등록되어야 하며, 하나의 서비스에 대한 dev, staging, prod 인스턴스임이 (이름과 설명에) 명확히 표시되어야 합니다. **개발 또는 스테이징 애플리케이션을 운영(프로덕션) 목적에 사용할 수 없습니다.**

**모든 API 키 및 기타 액세스 자격 증명은 비공개로 유지해야 합니다.** 다른 사람이 소유한 API 키 또는 기타 액세스 자격 증명을 사용하거나, 다른 사람이 이를 사용하도록 조장하거나 용이하게 해서는 안 됩니다.

**X와의 라이선스 계약은 X API 및 X Content 사용을 제한합니다. 그 중 하나로, X API에는 공정한 데이터 사용을 보장하고 플랫폼의 스팸을 방지하기 위한 rate limit(요청 한도)가 있습니다.** 이 Policy 또는 X와의 계약에 설명되어 있거나, [Developer Site](https://developer.x.com/)에 기재되어 있거나, X가 귀하에게 통지한 rate limit 또는 기타 모든 제한이나 제약을 초과하거나 이를 우회할 수 없습니다.

**X API를 통해 수신한 X Content에 포함된 독점 공지 또는 표기를 제거하거나 변경할 수 없습니다.** 이는 사람들이 X Content의 출처와 소유자를 명확히 알 수 있도록 하기 위한 것입니다.

**데이터 무결성과 플랫폼 건전성을 위해, X API 또는 X 서비스의 어떠한 기능도 방해, 가로채기, 중단 또는 비활성화할 수 없습니다.** 다시 말해, [developer.x.com](https://developer.x.com/)에 문서화된 의도된 방식대로 API를 사용해야 합니다. 허용 가능한 사용에 대한 자세한 내용은 [HackerOne 가이드라인](https://hackerone.com/x)을 참조하세요.

<div id="privacy-and-control-are-essential">
  ## 프라이버시와 통제권은 필수적입니다
</div>

X는 프라이버시를 매우 중요하게 여기며, X Content와 X API를 사용하는 모든 분들도 동일하게 이를 준수하기를 기대합니다. X 개발자 플랫폼, X API 또는 X Content를 사람들이 합리적으로 기대하는 프라이버시 수준에 어긋나는 방식으로 사용하는 경우, API 및 X Content에 대한 액세스의 일시 중지나 종료를 포함한 제재 조치의 대상이 될 수 있습니다.

프라이버시와 통제권에 대한 여러분의 책임은 X Content의 모든 활용과, 여러분이 우리의 API를 사용해 구축하는 서비스의 모든 측면에까지 확장되어야 합니다. 이를 위해, 여러분의 서비스를 사용하는 사람들이 여러분이 그들의 데이터를 어떻게 사용하고, 그들을 대신하여 X에 어떻게 접근하는지 이해하고 이에 동의해야 합니다. 이를 위해 사람들에게 명확하고 포괄적이며 투명한 개인정보 처리방침을 제공하고, 그들을 대신해 어떤 조치를 취하기 전에 여러분의 서비스를 사용하는 각 개인으로부터 명시적이고 충분한 설명에 기반한 동의를 받는 것이 중요합니다. **한 사람이 여러분의 서비스에 인증(로그인)했다는 사실만으로는 동의가 성립했다고 볼 수 없다는 점에 유의하세요.**

<div id="consent-permissions">
  ## 동의 및 권한
</div>

**특히, 아래와 같은 작업을 수행하기 전에 사용자로부터 명시적이고 충분한 설명에 기반한 동의를 반드시 받아야 합니다.**

* 사용자를 대신해 *어떠한* 조치라도 수행하는 경우. 여기에는 (이에 국한되지 않고) 다음이 포함됩니다.
  * X에 콘텐츠 게시
  * 계정 팔로우/언팔로우
  * 프로필 또는 계정 정보 수정
  * 포스트에 해시태그 또는 기타 콘텐츠 추가

* X API 또는 기타 X 도구 이외의 수단으로 접근한 콘텐츠를 다시 게시하는 행위

* 타인의 X 콘텐츠를 사용하여 제품 또는 서비스를 홍보하는 행위

* 다이렉트 메시지(DM)와 같은 비공개 콘텐츠 또는 기타 사적이거나 기밀인 정보를 저장하는 행위

* 보호된 콘텐츠 또는 기타 사적이거나 기밀인 정보를 공유하거나 게시하는 행위

**서비스를 통해 사용자가 X에 콘텐츠를 게시할 수 있도록 하는 경우, 게시 전에 다음을 반드시 수행해야 합니다.**

* 어떤 내용이 게시될지 정확히 보여주기
* 서비스 이용자에게 해당 콘텐츠에 어떤 위치 정보(있는 경우)가 추가될지 명확하게 알리기

**서비스를 통해 사용자가 귀하의 서비스와 X 모두에 콘텐츠를 게시할 수 있도록 하는 경우, 게시 전에 다음을 반드시 수행해야 합니다.**

* 콘텐츠를 게시할 수 있는 권한을 얻기
* 콘텐츠를 어디에 게시할 것인지 설명하기

**모든 X 콘텐츠의 보호 및 차단 상태를 존중해야 합니다. 한 사용자의 인증 토큰을 사용해 취득한 콘텐츠를, 해당 콘텐츠를 볼 권한이 없는 다른 사용자에게 제공해서는 안 됩니다.**

* **보호된 계정:** [보호된 계정](https://help.x.com/safety-and-security/public-and-protected-posts)의 콘텐츠는 그 계정을 팔로우하도록 계정 소유자가 승인한 사용자만 볼 수 있습니다. 따라서 보호된 계정에 접근하는 서비스를 운영하는 경우, 해당 콘텐츠를 볼 권한을 가진 특정 사용자에게만 그러한 콘텐츠를 제공해야 합니다.
* **차단된 계정:** X 이용자는 원하는 어떤 이유로든 자신의 계정에 대한 접근을 [차단](https://help.x.com/using-x/blocking-and-unblocking-accounts)할 수 있습니다. 이 선택을 우회하기 위해 토큰(또는 기타 API 기반 작업)을 통해 얻은 정보를 혼합하여 사용하는 행위는 허용되지 않습니다.

**다이렉트 메시지(DM)는 비공개적 특성을 가지므로, DM 기능을 제공하는 서비스는 개인정보 보호를 위해 추가적인 조치를 취해야 합니다. DM 콘텐츠를 볼 권한이 없는 사람에게 DM 콘텐츠를 제공해서는 안 됩니다. 서비스가 DM 기능을 제공하는 경우 다음 사항도 준수해야 합니다.**

* DM에 대한 읽음 확인 이벤트를 전송하는 경우 이를 사용자에게 고지해야 합니다. 이는 서비스 내에서 직접 고지를 제공하거나, 대화 중 다른 참가자의 읽음 확인을 표시하는 방식으로 수행할 수 있습니다.
* DM으로 전송될 미디어를 &quot;공유&quot; 형식(즉, 여러 DM에서 재사용 가능)으로 설정하기 전에 동의를 받아야 합니다. DM의 미디어를 &quot;공유&quot;할 수 있도록 허용하는 경우, 해당 미디어의 URL을 가진 누구나 이 콘텐츠에 접근할 수 있다는 점을 명확히 고지해야 합니다.

<div id="content-compliance">
  ## 콘텐츠 준수
</div>

**X 콘텐츠를 오프라인으로 저장하는 경우, X에서의 해당 콘텐츠의 현재 상태와 일치하도록 최신 상태로 유지해야 합니다.** 구체적으로, X에서 삭제되거나 수정된 콘텐츠가 있다면, 여러분이 보유한 해당 콘텐츠도 삭제하거나 수정해야 합니다. 이는 합리적으로 가능한 한 신속하게, 또는 X나 해당 X 계정 소유자로부터 그러한 조치를 요청받은 시점으로부터 24시간 이내에, 또는 X와 체결한 계약이나 관련 법률에 따라 요구되는 기간 내에 이루어져야 합니다. 법률에 의해 달리 금지되지 않는 한 이러한 조치를 이행해야 하며, 법률상 금지가 있는 경우에도 X의 명시적인 서면 허가가 있는 때에만 예외가 인정됩니다.

수정된 콘텐츠는 다양한 형태를 취할 수 있습니다. 여기에는 (이에 국한되지 않고) 다음이 포함됩니다:

* 비공개로 전환되었거나 보호 상태가 된 콘텐츠
* 플랫폼에서 정지된 콘텐츠
* 지오태그가 제거된 콘텐츠
* X에서 보류되었거나 제거된 콘텐츠

<div id="off-x-matching">

**당사는 X 상의 개인과 X 외부에서 획득하거나 보관한 정보를 매칭할 수 있는 상황을 제한합니다.** X 외부 매칭이란 X @handle 또는 사용자 ID를 포함한 X 콘텐츠를 개인, 가구, 기기, 브라우저 또는 기타 X 외부 식별자와 연결하는 것을 의미합니다. 이러한 연결은 그 개인으로부터 사전에 명시적인 옵트인 동의를 받았거나, 아래에 설명된 경우에만 할 수 있습니다.

개인의 X 정체성을 X 외부 식별자와 연결하는 데 필요한 그 개인의 명시적인 옵트인 동의를 보유하고 있지 않은 상황에서는, 귀하가 시도하는 모든 연결이 합리적으로 그 목적을 위해 사용될 것이라고 예상할 수 있는 정보에만 근거해야 합니다. 또한 개인의 명시적인 옵트인 동의가 없는 경우, 귀하는 다음에 근거하여서만 특정인에 관한 귀하의 기록을 X 정체성과 매칭하려고 시도할 수 있습니다.

* **개인이 귀하에게 직접 제공한 정보.** 귀하와 아무런 선행 관계가 없는 개인에 대한 기록(제3자로부터 취득한 개인 관련 데이터 포함)은 이 기준을 충족하지 못한다는 점에 유의하십시오. 및/또는
* **공개 데이터.** 이와 같은 맥락에서 “공개 데이터”란 다음을 의미합니다.
  * 귀하가 공적이고 일반에 공개된 자원(예: 직업협회 회원 명부)에서 취득한 개인에 대한 정보
  * X에서 해당 개인에 대해 공개적으로 이용 가능한 정보로서, 다음을 포함합니다.
    * 포스트
    * 계정 소개(bio) 및 공개적으로 명시된 위치를 포함한 프로필 정보
    * 표시 이름(display name) 및 @handle

<div id="using-geo-data">
  ## 지리 정보(geo data) 사용
</div>

**지리 정보는 해당 정보의 민감한 특성으로 인해 추가적인 제한이 적용됩니다.** 서비스에서 포스트에 위치 정보를 추가하는 경우, 이용자에게 다음 사항을 고지해야 합니다.

* 언제 위치 정보를 추가하는지
* 위치 정보를 지오태그(geotag)로 추가하는지, 아니면 annotations data로 추가하는지
* 위치 정보가 장소(place)로 표시되는지, 아니면 지리 좌표로 표시되는지

애플리케이션에서 이용자가 자신의 위치 정보를 포함해 게시할 수 있도록 허용하는 경우, X의 [geo 가이드라인](/ko/developer-terms/geo-guidelines)을 전면적으로 준수해야 합니다.

**위치 data 또는 지리 정보를 단독으로 사용하는 행위는 금지됩니다.** 포스트의 일부로 사용하는 경우를 제외하고, X 콘텐츠에 포함된 위치 data 및 기타 지리 정보를 저장·집계·캐시할 수 없으며, 다른 사람이 그렇게 하도록 허용해서도 안 됩니다. 예를 들어, 시간이 지남에 따라 특정 개인이 어디에 있었는지를 보여주기 위해 포스트에서 위치 data 또는 지리 정보를 분리해 사용하는 것은 허용되지 않습니다. 반면, 도시 내에서 특정 해시태그를 사용하는 사람 수와 같이 집계된 geo 활동을 보여주는 히트맵 및 관련 도구는 허용됩니다.

<div id="spam-bots-and-automation">
  ## 스팸, 봇, 그리고 자동화
</div>

**X API 및 개발자 제품을 사용하여 스팸을 생성하거나 어떠한 형태로든 플랫폼 조작에 관여하는 행위는 금지됩니다.** [플랫폼 조작 및 스팸](https://help.x.com/rules-and-policies/platform-manipulation)에 관한 X 규칙을 검토하고, 귀하의 서비스가 당사의 정책을 위반하지 않을 뿐 아니라, 이용자가 정책을 위반하도록 만들지도 않도록 해야 합니다.

**포스트 게시, 계정 팔로우, 다이렉트 메시지 발송 등을 포함해 쓰기 작업을 수행하는 서비스는 [Automation Rules](https://help.x.com/rules-and-policies/x-automation)를 준수해야 합니다.** 특히 다음 사항을 따라야 합니다.

* 사람들에게 [자동화된 답글 또는 다이렉트 메시지](https://twittercommunity.com/t/policy-clarification-automated-replies-and-mentions/94444)를 보내기 전에 항상 명시적인 동의를 받아야 합니다.
* 귀하로부터 연락받지 않기를 원한다는 요청이 있으면 즉시 이를 존중하고 더 이상 연락하지 않아야 합니다.
* [대량 팔로우](https://twittercommunity.com/t/policy-clarification-aggressive-following-and-inorganic-following-behavior/92769)를 포함해 대량·공격적·스팸성 행동을 절대 수행해서는 안 됩니다.
* [여러 계정](https://blog.twitter.com/developer/en_us/topics/tips/2018/automation-and-the-use-of-multiple-accounts.html)에 걸쳐 동일하거나 실질적으로 유사한 콘텐츠를 절대 게시해서는 안 됩니다.

**API 기반 봇 계정을 운영하는 경우, 해당 계정이 어떤 계정인지와 누가 책임자인지를 명확히 표시해야 합니다.** 귀하의 계정이 봇인지 아닌지에 대해 사람들을 오도하거나 혼란스럽게 해서는 안 됩니다. 이를 위한 좋은 방법은 프로필 소개(bio)에 해당 계정이 봇이라는 문구를 포함하는 것입니다.

<div id="x-performance-benchmarking">

<div id="public-display-of-posts">
  ## 포스트의 공개 표시
</div>

**공개적으로 또는 귀하의 서비스를 이용하는 사람들에게 표시하는 모든 X 콘텐츠의 완전성을 반드시 유지해야 합니다.** 콘텐츠 표시를 위해 [X for Websites](https://developer.x.com/docs/twitter-for-websites/overview)를 사용하지 않는 경우, 표시 가능한 최신 버전을 가져오기 위해 X API를 사용해야 합니다. 표시된 콘텐츠가 X API를 통해 더 이상 제공되지 않게 되면, 합리적으로 가능한 한 신속하게, 또는 X나 해당 X 계정 소유자로부터 삭제 요청을 받은 후 24시간 이내에, 또는 관련 법률에서 요구하는 경우 그에 따라 귀하의 서비스에서 해당 콘텐츠를 제거해야 합니다.

**X 콘텐츠를 오프라인으로 표시하는 경우 따라야 하는 구체적인 규칙이 있습니다.** 포스트를 오프라인에서 표시하는 경우, 방송에서 포스트를 사용할 때 적용되는 [가이드라인](https://developer.x.com/developer-terms/display-requirements)을 따라야 합니다.

**포스트를 임베드하거나 표시하는 경우, 사이트의 일일 노출 수가 1,000만 회를 초과하면 X API 액세스와 관련하여 당사에 연락해야 합니다.** X는 귀하의 X API 사용에 대한 조건으로 추가 약관을 요구할 권리를 보유합니다. X for Websites를 사용하는 개발자에 대한 추가 제한은 다음과 같습니다.

* **임베드된 포스트 및/또는 임베드된 타임라인**
  * 귀하의 웹사이트에서의 탐색 활동에 관해 X가 수집·이용하는 정보(관심 기반 광고 및 개인 맞춤화를 포함)에 대해, 이를 완전하게 공개하는 법적으로 충분한 고지를 이용자에게 제공해야 합니다. 또한 그러한 정보 수집 및 이용에 대해 이용자로부터 법적으로 유효한 동의를 받아야 합니다.
  * [여기](https://help.x.com/x-for-websites-ads-info-and-privacy)에 설명된 대로, 이용자가 X의 관심 기반 광고 및 개인 맞춤화를 옵트아웃할 수 있는 방법에 대해 법적으로 충분한 안내를 제공해야 합니다.

* **X for Websites 위젯**
  * 법에서 이러한 정보 제공 및 동의 확보를 요구하는 경우, X의 [쿠키 사용](https://help.x.com/rules-and-policies/x-cookies)에 설명된 대로, 이용자의 기기에 쿠키 또는 기타 정보를 저장·접근하는 행위에 대해 명확하고 포괄적인 정보를 제공하고, 이에 대한 동의를 받도록 해야 합니다.

* **13세 미만 아동을 대상으로 하는 서비스**
  * 13세 미만 아동을 대상으로 하는 서비스는, [여기](https://developer.x.com/docs/twitter-for-websites/privacy)에 설명된 대로 옵트아웃 매개변수를 ‘true’로 설정하여, 임베드된 포스트 및/또는 임베드된 타임라인에서 X의 맞춤 설정을 옵트아웃해야 합니다.

<div id="content-redistribution">
  ## 콘텐츠 재배포
</div>

**X 콘텐츠를 얻을 수 있는 가장 좋은 방법은 X로부터 직접 제공받는 것입니다. 따라서, 우리는 X 콘텐츠의 제3자 재배포를 제한합니다.** 다운로드 가능한 데이터 세트 또는 API를 통해 제공하는 경우를 포함해 제3자에게 X 콘텐츠를 제공하는 경우, 아래에 설명된 경우를 제외하고는 포스트 ID, 다이렉트 메시지 ID 및/또는 사용자 ID만 배포할 수 있습니다.

총합 기준으로, 어떤 30일 기간 동안에도 단일 법인(해당 법인에 소속된 복수의 개인을 포함함)에게 1,500,000개를 초과하는 포스트 ID를 X로부터 서면 허가 없이 배포할 수 없습니다. 또한, 개발자는 자동화되지 않은 수단(예: 스프레드시트 또는 PDF 다운로드)을 사용하는 경우에 한해, 매일 귀하의 서비스를 이용하는 각 개인에게 최대 500개의 공개 포스트 오브젝트 및/또는 사용자 오브젝트를 제공할 수 있습니다.

학술 연구자는 비영리 학술 연구를 수행하기 위한 목적에 한해, 그리고 해당 연구가 X로부터 서면으로 승인되었거나, 그러한 연구에 대한 동료 평가 또는 검증을 위한 경우에 한해, 포스트 ID 및/또는 사용자 ID를 배포할 수 있습니다. 그러한 연구를 위해 필요하고 X에 의해 승인된 범위 내에서만 포스트 ID 또는 사용자 ID를 사용할 수 있습니다.

제3자에게 제공되는 모든 X 콘텐츠는 본 정책의 적용을 계속 받으며, 해당 제3자는 그러한 다운로드를 받기 전에 X의 [서비스 약관](https://x.com/tos), [개인정보 처리방침](https://x.com/privacy), [Developer Agreement](/ko/developer-terms/agreement), 및 [Developer Policy](/ko/developer-terms/policy)에 동의해야 합니다. 귀하는 본 [정책](/ko/developer-terms/policy), [Developer Agreement](/ko/developer-terms/agreement) 또는 X와의 기타 어떤 계약에 포함된 X 콘텐츠 배포에 대한 다른 제한 또는 제약을 어떤 법인이나 단체든 우회할 수 있도록 해서는 안 됩니다.

**참고:** 본 절은 EU Digital Services Act (2022) 제40조(“**DSA**”)를 통해 X API에 접근하는 연구자에게는 적용되지 않으며, 이들은 대신 DSA 및 Developer Agreement에 규정된 절차와 제한의 적용을 받습니다.

* **X 콘텐츠와 귀하의 광고 사이에는 명확한 구분이 있어야 합니다.** X Ads 이외에는 X 타임라인 내에 어떠한 광고도 배치할 수 없습니다.

<div id="x-login">

</div>

**사람들이 X에 로그인하고 로그아웃할 수 있는 옵션을 쉽게 찾을 수 있도록 제공해야 합니다. 예를 들어 OAuth 프로토콜을 통해 제공할 수 있습니다.** *Sign in with X* 옵션은 귀하의 서비스에 있는 다른 어떤 가입 또는 로그인 기능만큼 눈에 띄게 표시되어야 합니다. 또한 X 계정이 없는 사람들에게도 X를 통해 계정을 생성할 수 있는 기회를 제공해야 합니다.

<div id="x-cards">
  ## X 카드
</div>

**양질의 사용자 경험을 보장하려면, 카드가 카드가 표시되는 모든 플랫폼에서 올바르게 렌더링되도록 개발해야 합니다.** 카드를 사용할 때 따라야 하는 추가 규칙은 다음과 같습니다.

* 카드 내에 민감한 미디어를 표시할 계획이라면, 해당 포스트의 민감한 미디어 플래그를 ‘true’로 설정해야 합니다.
* 카드 내의 모든 에셋을 호스팅할 때는 HTTPS를 사용해야 합니다. 카드는 브라우저에서 활성 혼합 콘텐츠 관련 경고를 발생시켜서는 안 됩니다.
* 오디오 및 비디오 콘텐츠에는 정지 또는 일시정지 컨트롤이 포함되어야 하며, 자동 재생되는 비디오의 경우 기본 설정이 ‘음소거’이어야 합니다.

**카드에 대해 X가 부과한 제한(카드의 의도된 사용 목적 포함)을 초과하거나 이를 우회해서는 안 됩니다.** 카드 사용에 대한 추가 제한은 다음과 같습니다.

* X의 승인을 받지 않고 제3자 후원 콘텐츠를 카드 내에 배치해서는 안 됩니다.
* 카드 내에서나 카드와 연결된 X 상에서 금전적 인센티브(가상 화폐 포함)를 제공해서는 안 됩니다.
* URL 및 미디어와 같이 오해의 소지가 있거나 문맥상 관련성이 없는 콘텐츠 또는 동작을 카드에 포함해서는 안 됩니다.
* 해당 포스트에서 앱을 명시적으로 홍보하거나 언급하는 경우에만, 포스트에 앱 카드를 첨부할 수 있습니다.
