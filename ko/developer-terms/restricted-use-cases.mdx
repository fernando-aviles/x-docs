<div id="sensitive-information">
  ## 민감한 정보
</div>

X data를 사용하여 X 사용자의 민감할 수 있는 특성을 도출하거나 추론할 때에는 주의를 기울여야 합니다. 다음과 같은 X 사용자의 정보를 도출하거나 추론하거나, 그렇게 도출·추론된 정보를 저장해서는 안 됩니다.

* 건강(임신 여부 포함)
* 부정적인 재정 상태 또는 재정 상황
* 정치적 성향 또는 신념
* 인종적 또는 민족적 배경
* 종교적 또는 철학적 성향 또는 신념
* 성생활 또는 성적 지향
* 노동조합 가입 여부
* 범죄 혐의 또는 실제 범죄 행위

개인 데이터(예: user id, username 및 기타 식별자)를 저장하지 않는 X 콘텐츠에 대한 집계 분석은, 해당 분석이 관련 법률 및 Developer Agreement and Policy의 모든 조항을 준수하는 한 허용됩니다.

<div id="off-x-matching">
  ## Off-X 매칭
</div>

Off-X 매칭은 X 사용자 이름 또는 사용자 ID를 포함한 X 콘텐츠를 사람, 가구, 기기, 브라우저 또는 기타 X 외부 식별자와 연관시키는 것을 말합니다. 한 예로, X 사용자 이름을 어떤 기업의 고객 기록(예: 고객 기록의 “John Doe”를 X의 @johndoe와 매칭하는 경우)과 연관시키는 것을 들 수 있습니다.

우리는 사람들이 X에서 원할 경우 가명으로 별도의 정체성을 만들더라도 안심할 수 있기를 바랍니다. X 사용자의 어떤 정보를 X 외부 식별자와 연관시키려는 경우, 그러한 연관을 수행하기 전에 해당 사용자로부터 명시적인 옵트인(opt-in) 동의를 받아야 합니다. 예를 들어, 사용자가 귀하의 서비스 가입 절차의 일환으로 자신의 X 사용자 이름(핸들)을 귀하에게 직접 제공하는 경우 이 동의를 얻을 수 있습니다.

사용자의 X 정체성과 X 외부 식별자를 연결하는 데 필요한, 사용자에 대한 명시적인 옵트인 동의가 없는 상황에서는, 귀하가 설정하는 모든 연결은 사용자 입장에서 그 목적을 위해 사용될 것이라고 합리적으로 예상할 수 있는 정보에만 기반해야 합니다. 사용자가, 귀하가 그들이 제공한 정보를 사용해 자신의 X 계정을 X 외부의 정체성과 연결하고 있다는 사실을 알게 되었을 때 놀랄 것 같다면, 그렇게 하지 마십시오. 추가로, 개인의 명시적인 옵트인 동의가 없는 경우, 귀하는 다음을 기반으로 해서만 어떤 사람에 대한 귀하의 기록을 X 정체성과 매칭하려고 시도할 수 있습니다:

* **사용자가 귀하에게 직접 제공한 정보.** 귀하와 사전 관계가 전혀 없는 개인에 대한 기록, 제3자로부터 취득한 개인 데이터는 이 기준을 충족하지 않습니다. 그리고/또는
* **공개 데이터.** 이 문맥에서 “공개 데이터”는 다음을 의미합니다:
  * 귀하가 공개적으로 일반에 제공되는 리소스(예: 어떤 직업 협회의 회원 목록)에서 취득한 사용자 정보
  * X 상에서 공개적으로 제공되는 사용자 정보로, 다음을 포함합니다:
    * 포스트
    * 사용자의 소개(bio) 및 공개적으로 명시된 위치를 포함한 프로필 정보
    * 표시 이름과 사용자 이름

<div id="redistribution-of-x-content">
  ## X 콘텐츠의 재배포
</div>

X API를 통해 얻은 X 콘텐츠를 다른 당사자와 공유해야 하는 경우, 가장 좋은 방법은 포스트 ID, 다이렉트 메시지 ID 및/또는 사용자 ID를 공유하는 것입니다. 그러면 콘텐츠 최종 사용자가 X API를 사용해 이를 리하이드레이트(즉, 전체 포스트, 사용자 또는 다이렉트 메시지 콘텐츠를 다시 요청)할 수 있습니다. 이는 X 콘텐츠 최종 사용자가 항상 X로부터 최신 정보를 직접 제공받을 수 있도록 돕습니다.

당사는 비자동화된 수단을 통한 리하이드레이트된 X 콘텐츠의 제한적인 재배포를 허용합니다. 이 방식으로 리하이드레이트된 X 콘텐츠를 다른 당사자와 공유하기로 선택하는 경우, 수신자 1명당 1일 기준으로 리하이드레이트된 공개 포스트 객체(Post Objects) 및/또는 사용자 객체(User Objects)를 최대 50,000개까지만 공유할 수 있으며, 이 data를 공개적으로 이용 가능하게 만들어서는 안 됩니다(예: 블로그 포스트의 첨부 파일로 제공하거나 공개 GitHub 리포지토리에 게시하는 행위 등).

X 콘텐츠를 재배포할 때 유의해야 할 몇 가지 추가 사항은 다음과 같습니다.

* X로부터 사전에 명시적인 서면 허가를 받지 않은 한, 30일 동안 단일 단체에 배포할 수 있는 포스트 ID의 총합은 1,500,000개를 초과할 수 없습니다.
* 비상업적 연구만을 목적으로 학술 기관을 대신해 포스트 ID 및/또는 사용자 ID를 재배포하는 개인은 무제한의 포스트 ID 및/또는 사용자 ID를 재배포할 수 있습니다.
* 위에 설명된 방식으로 X 콘텐츠를 공유할 수 있는 허가를 요청하려면 API Policy 지원 양식을 사용해 주십시오.

X 콘텐츠를 제3자에게 배포할 수 있는 범위 내에서, 이 콘텐츠는 여전히 Developer Agreement 및 Developer Policy의 적용을 받으며, 해당 제3자는 X 콘텐츠를 제공받기 전에 X [이용약관](https://twitter.com/en/tos), [개인정보 처리방침](https://twitter.com/en/privacy), [Developer Agreement](/ko/developer-terms/agreement) 및 [Developer Policy](/ko/developer-terms/policy)에 동의해야 함을 유의하십시오.

<div id="multiple-applications">
  ## 여러 개의 애플리케이션
</div>

단일 사용 사례 또는 실질적으로 유사하거나 중복되는 사용 사례에 대해 여러 개의 애플리케이션을 등록하는 것은 허용되지 않습니다. 이러한 정책에 대해 자세히 알아보려면 [여기](https://twittercommunity.com/t/policy-clarification-multiple-applications-for-the-same-use-case/92080)를 참조하세요.

이 문맥에서 “사용 사례(use case)”는 애플리케이션을 통해 수행되는 일관된 분석, 표시, 또는 작업의 집합을 의미합니다. 동일한 서비스나 애플리케이션을 서로 다른 최종 사용자에게 제공하는 것은 하나의 사용 사례로 간주됩니다. 다만, 도구나 서비스의 &quot;화이트 라벨(white label)&quot; 버전은 여기에 포함되지 않습니다. 애플리케이션의 &quot;화이트 라벨&quot; 버전을 제공할 계획이라면, 반드시 당사에 이를 통지하고 별도의 승인을 받아야 합니다. 이러한 규칙은 귀하가 등록하는 애플리케이션뿐만 아니라, 귀하의 도구나 서비스를 사용하는 최종 사용자가 등록하는 애플리케이션에도 적용됩니다. 귀하의 도구나 서비스를 사용하기 위한 목적으로 최종 사용자에게 애플리케이션 등록을 요구하는 경우, 귀하, 귀하의 애플리케이션, 귀하의 고객 및/또는 귀하의 도구나 서비스의 최종 사용자에 대한 제재 조치로 이어질 수 있습니다.

이 규칙의 유일한 예외는 동일한 서비스에 대한 개발(“dev”), 스테이징(staging), 프로덕션(“prod”) 인스턴스를 생성하는 경우입니다. 이러한 애플리케이션이 명확하게 구분되도록 표시되어 있는지(예를 들어 애플리케이션 이름이나 설명에) 확인하고, 개발 또는 스테이징 애플리케이션을 프로덕션 목적으로 사용하지 마십시오.

<div id="automation-spam-and-auto-responses">
  ## 자동화, 스팸 및 자동 응답
</div>

스팸을 생성하거나 스팸성 행위를 하기 위해 X의 API 및 개발자 제품을 사용하는 것은 금지됩니다. 스팸 관련 [X 규칙](https://t.co/rules)을 검토하고, 애플리케이션이 당사의 정책을 위반하지 않으며, 사용자도 이를 위반하지 않도록 해야 합니다.

애플리케이션이 포스트 게시, 계정 팔로우, 다이렉트 메시지 전송 등 X 서비스에서 쓰기 작업을 수행하는 데 사용될 예정이라면, 서비스가 당사의 가이드라인을 준수하는지 확인하기 위해 [자동화 규칙](https://support.twitter.com/articles/76915)을 신중히 검토해야 합니다. 특히 다음 사항을 준수해야 합니다.

* 사용자에게 [자동화된 답글 또는 메시지](https://twittercommunity.com/t/policy-clarification-automated-replies-and-mentions/94444)를 보내기 전에 항상 명시적인 동의를 받아야 합니다.
* 귀하로부터 연락을 받지 않겠다는 사용자의 요청은 즉시 존중해야 합니다.
* [대량 팔로우](https://twittercommunity.com/t/policy-clarification-aggressive-following-and-inorganic-following-behavior/92769)를 포함하여 대량, 공격적 또는 스팸성 행위를 절대 수행해서는 안 됩니다.
* [여러 계정](https://blog.twitter.com/developer/en_us/topics/tips/2018/automation-and-the-use-of-multiple-accounts.html)에 동일하거나 실질적으로 유사한 콘텐츠를 절대 게시해서는 안 됩니다.

<div id="measuring-the-x-service">
  ## X 서비스 측정
</div>

벤치마킹이나 경쟁 목적을 위해 X의 가용성, 성능, 기능 또는 사용량을 측정하는 용도로 X API를 사용해서는 안 됩니다. 예를 들어, 다음과 같은 목적으로 X API를 사용해서는 안 됩니다.

* 전체 활성 사용자 수 또는 계정 수와 같은 X 사용자 집계 지표를 계산하는 것
* 일일 포스트 총량, 사용자 참여 수 또는 계정 참여 수와 같은 X 포스트 집계 지표를 계산하는 것
* [X 규칙](https://help.twitter.com/en/rules-and-policies/twitter-rules)에서 허용하는 경우를 제외하고, X에서의 스팸 또는 보안을 측정하거나 분석하는 것

<div id="surveillance-privacy-and-user-protection">
  ## 감시, 프라이버시, 그리고 사용자 보호
</div>

X에서는 사용자 프라이버시를 보호하고 수호하는 일이 우리 회사의 핵심 DNA에 내재되어 있으며, 개발자 및 데이터 제품 역시 이러한 약속을 반영합니다. 우리는 X 데이터가 자카르타 홍수 시 인명 구조부터 USGS의 지진 추적, UN과의 협력을 통한 지속가능발전목표(SDGs) 달성 지원에 이르기까지 전 세계에 선한 영향력을 발휘할 수 있는 강력한 도구가 될 수 있다고 믿습니다. 그러나 우리는 어떤 주체이든 감시 목적이나, 사용자의 합리적인 프라이버시 기대와 일치하지 않는 그 어떠한 방식으로도 X 데이터 및 X API를 사용하는 것을 금지합니다. 예외는 없습니다.

당사 데이터 및 개발자 제품의 금지된 사용 방식은 [Developer Agreement](/ko/developer-terms/agreement)에 설명되어 있으며, 여기에는 X 사용자 또는 그들의 콘텐츠를 조사하거나 추적하는 행위, 시위, 집회, 커뮤니티 조직 모임과 같은 민감한 이벤트를 추적·알림·모니터링하는 행위에 대한 금지가 포함됩니다.

이 약관에 따라 금지되는 기타 활동 범주는 다음과 같으며, 이에 한정되지 않습니다.

* 노동조합이나 행동주의 단체 등 민감한 그룹 및 조직을 조사하거나 추적하는 행위
* 백그라운드 체크 또는 어떠한 형태의 과도한 신원 심사
* 신용 또는 보험 리스크 분석
* 개인 프로파일링 또는 사이코그래픽 세분화
* 안면 인식

이 정책은 모든 API 사용자에게 적용됩니다. 위와 같은 목적으로 X API를 오용하는 경우, 접근 정지 및 종료를 포함할 수 있는 제재 조치의 대상이 됩니다.

X 계정 관련 정보를 요청하는 법 집행 기관을 위한 추가 정보는 [https://t.co/le](https://t.co/le)를 방문하십시오.

또한, 현 시점에서 X는 [Grok](https://help.x.com/en/using-x/about-grok)을 예외로 하고, 파운데이션 모델 또는 프런티어 모델을 파인튜닝(fine-tune)하거나 학습(train)하는 데 X API 및/또는 X 콘텐츠를 사용하는 모든 행위를 금지합니다.
