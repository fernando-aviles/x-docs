<div id="sensitive-information">
  ## 민감한 정보
</div>

X 사용자의 잠재적으로 민감한 특성을 파악하거나 추론하기 위해 X data를 사용할 때에는 주의를 기울여야 합니다. 다음과 같은 X 사용자의 정보를 파악하거나 추론하거나, 그러한 방식으로 파악·추론한 정보를 저장해서는 안 됩니다.

* 건강(임신 포함)
* 부정적인 재정 상태 또는 재정적 상황
* 정치적 성향 또는 신념
* 인종 또는 민족적 출신
* 종교적 또는 철학적 성향 또는 신념
* 성생활 또는 성적 지향
* 노동조합 가입 여부
* 혐의 또는 실제 범죄 행위

개인 data(예: 사용자 ID, 사용자 이름 및 기타 식별자)를 전혀 저장하지 않는 X 콘텐츠에 대한 집계 분석은, 해당 분석이 관련 법률과 Developer Agreement 및 Policy의 모든 조항을 준수하는 한 허용됩니다.

<div id="off-x-matching">
  ## Off-X 매칭
</div>

Off-X 매칭은 X 사용자 이름이나 사용자 ID를 포함한 X 콘텐츠를 사람, 가구, 기기, 브라우저 또는 기타 Off-X 식별자와 연결하는 것을 의미합니다. 예를 들어, X 사용자 이름을 비즈니스의 고객 기록과 연결하는 것(예: 고객 기록의 “John Doe”가 X의 @johndoe와 매칭되는 경우)이 이에 해당합니다.

우리는 사람들이 X에서 별도의, 그리고 원한다면 가명 기반의 정체성을 만들 수 있다고 편안하게 느끼기를 바랍니다. X 사용자의 정보와 Off-X 식별자를 연결하려는 경우, 해당 연결을 수행하기 전에 반드시 사용자로부터 명시적이고 옵트인 방식의 동의를 받아야 합니다. 예를 들어, 사용자가 귀하의 서비스 가입 절차 중에 자신의 X 사용자 이름(핸들)을 직접 제공하는 경우, 이를 통해 동의를 받을 수 있습니다.

사용자의 X 정체성을 Off-X 식별자와 연결하기 위한 명시적 옵트인 동의가 없는 상황에서는, 사용자가 해당 목적으로 사용될 것이라고 합리적으로 예상할 수 있는 정보에만 근거하여 연결을 시도해야 합니다. 사용자가 자신이 제공한 정보를 사용해 자신의 X 계정을 X 외부의 정체성과 연결하고 있다는 사실을 알게 되었을 때 놀랄 것 같다면, 그렇게 하지 마십시오. 또한, 개인의 명시적 옵트인 동의가 없는 경우, 다음에 근거해서만 특정인에 대한 귀하의 기록을 X 정체성과 매칭하려고 시도할 수 있습니다.

* **사용자가 귀하에게 직접 제공한 정보.** 귀하와 사전 관계가 전혀 없는 개인(제3자로부터 획득한 개인에 대한 데이터 포함)에 관한 기록은 이 기준을 충족하지 않습니다. 그리고/또는
* **공개 데이터.** 이 문맥에서 “공개 데이터”는 다음을 의미합니다.
  * 귀하가 공적으로, 일반에 공개된 리소스(예: 어떤 직업 협회 회원 명부)에서 얻은 사용자에 관한 정보
  * X에서 사용자에 대해 공개적으로 이용 가능한 정보로, 다음을 포함합니다.
    * 포스트
    * 사용자의 소개(bio) 및 공개적으로 명시한 위치를 포함한 프로필 정보
    * 표시 이름 및 사용자 이름

<div id="redistribution-of-x-content">
  ## X 콘텐츠 재배포
</div>

X API를 통해 획득한 X 콘텐츠를 제3자와 공유해야 하는 경우, 가장 좋은 방법은 포스트 ID, 다이렉트 메시지 ID 및/또는 유저 ID를 공유하는 것입니다. 그러면 콘텐츠의 최종 사용자가 X API를 사용하여 이를 리하이드레이트(rehydrate, 예: 전체 포스트, 유저 또는 다이렉트 메시지 콘텐츠를 요청)할 수 있습니다. 이렇게 하면 X 콘텐츠의 최종 사용자가 항상 가장 최신 정보를 X로부터 직접 제공받을 수 있습니다.

당사는 비자동화된 수단을 통한 리하이드레이트된 X 콘텐츠의 제한적 재배포를 허용합니다. 이러한 방식으로 리하이드레이트된 X 콘텐츠를 제3자와 공유하기로 선택한 경우, 수신자 1인당 1일 기준으로 리하이드레이트된 공개 포스트 오브젝트 및/또는 유저 오브젝트를 최대 50,000개까지만 공유할 수 있으며, 이 데이터를 공개적으로 이용 가능하게 만들어서는 안 됩니다(예: 블로그 게시물의 첨부 파일로 제공하거나 공개 GitHub 리포지토리에 게시하는 경우 등).

X 콘텐츠를 재배포할 때 유의해야 할 몇 가지 추가 사항은 다음과 같습니다.

* X로부터 사전 명시적 서면 허가를 받지 않은 이상, 30일 기간 동안 단일 엔티티에 대해 최대 1,500,000개의 포스트 ID만 배포할 수 있습니다.
* 비상업적 연구만을 유일한 목적으로 하는 학술 기관을 대신하여 포스트 ID 및/또는 유저 ID를 재배포하는 개인은 무제한의 포스트 ID 및/또는 유저 ID를 재배포할 수 있습니다.
* 위에 설명된 바와 같이 X 콘텐츠 공유에 대한 허가를 요청하려면 API Policy 지원 양식을 사용해 주세요.

허용된 범위 내에서 X 콘텐츠를 제3자에게 배포하는 경우에도, 이 콘텐츠는 계속해서 Developer Agreement 및 Developer Policy의 적용을 받으며, 그러한 제3자는 X 콘텐츠를 수령하기 전에 X [이용 약관](https://twitter.com/en/tos), [개인정보 처리방침](https://twitter.com/en/privacy), [Developer Agreement](/ko/developer-terms/agreement), 및 [Developer Policy](/ko/developer-terms/policy)에 동의해야 합니다.

<div id="multiple-applications">
  ## 여러 애플리케이션
</div>

단일 사용 사례 또는 본질적으로 유사하거나 중복되는 사용 사례에 대해 여러 애플리케이션을 등록하는 것은 허용되지 않습니다. 이러한 정책에 대해 자세히 알아보려면 [여기](https://twittercommunity.com/t/policy-clarification-multiple-applications-for-the-same-use-case/92080)를 참고하세요.

이 문맥에서 “사용 사례(use case)”는 애플리케이션을 통해 수행되는 일관된 분석, 표시 또는 작업의 집합으로 정의합니다. 동일한 서비스나 애플리케이션을 서로 다른 최종 사용자에게 제공하는 것은 하나의 사용 사례로 간주됩니다. 다만, 도구나 서비스의 &quot;화이트 라벨(white label)&quot; 버전은 이에 포함되지 않습니다. 애플리케이션의 &quot;화이트 라벨&quot; 버전을 제공할 계획이라면, 반드시 당사에 이를 통지하고 별도의 승인을 받아야 합니다. 이러한 규칙은 귀하가 등록하는 애플리케이션뿐 아니라, 귀하의 도구나 서비스를 사용하는 최종 사용자가 등록하는 애플리케이션에도 적용됩니다. 귀하의 도구나 서비스를 사용하기 위한 목적으로 최종 사용자에게 애플리케이션 등록을 요구하는 경우, 귀하, 귀하의 애플리케이션, 고객 및/또는 귀하의 도구나 서비스의 최종 사용자에 대해 제재 조치가 취해질 수 있습니다.

이 규칙의 유일한 예외는 동일한 서비스에 대해 개발(“dev”), 스테이징, 운영(“prod”) 인스턴스를 생성하는 경우입니다. 이러한 애플리케이션이 확실히 구분되도록 (예를 들어 애플리케이션 이름이나 설명에) 명확히 표시하고, 운영 목적에 개발 또는 스테이징 애플리케이션을 사용하지 마세요.

<div id="automation-spam-and-auto-responses">
  ## 자동화, 스팸, 자동 응답
</div>

스팸을 생성하거나 스팸성 행위에 가담하기 위한 목적으로 X의 API 및 개발자 제품을 사용하는 것은 금지됩니다. 스팸 관련 [X 규칙](https://t.co/rules)을 검토하고, 애플리케이션이 X 정책을 위반하지 않으며 사용자로 하여금 이를 위반하도록 하지 않도록 해야 합니다.

애플리케이션이 포스트를 게시하거나 계정을 팔로우하고 다이렉트 메시지를 전송하는 등 X 서비스에서 쓰기 작업을 수행하는 데 사용될 예정이라면, 서비스가 당사 가이드라인을 준수하는지 확인하기 위해 [자동화 규칙](https://support.twitter.com/articles/76915)을 주의 깊게 검토해야 합니다. 특히 다음 사항을 준수해야 합니다.

* [자동화된 답글이나 메시지](https://twittercommunity.com/t/policy-clarification-automated-replies-and-mentions/94444)를 전송하기 전에 항상 사용자로부터 명시적인 동의를 받으십시오.
* 귀하로부터 연락을 받지 않겠다는 사용자의 요청은 즉시 존중하십시오.
* [대량 팔로우](https://twittercommunity.com/t/policy-clarification-aggressive-following-and-inorganic-following-behavior/92769)를 포함하여 대량, 공격적 또는 스팸성 행동을 절대 수행하지 마십시오.
* [여러 계정](https://blog.twitter.com/developer/en_us/topics/tips/2018/automation-and-the-use-of-multiple-accounts.html)에 동일하거나 실질적으로 유사한 콘텐츠를 게시하지 마십시오.

<div id="measuring-the-x-service">
  ## X 서비스 측정
</div>

벤치마킹이나 경쟁 목적을 위해 X의 가용성, 성능, 기능, 사용량을 측정하는 데 X API를 사용해서는 안 됩니다. 예를 들어 다음과 같은 목적으로 X API를 사용해서는 안 됩니다.

* 전체 활성 사용자 수 또는 계정 수와 같은 X 사용자 지표의 총합을 계산하는 것
* 하루 포스트 총량, 사용자 참여 수 또는 계정 참여 수와 같은 X 포스트 지표의 총합을 계산하는 것
* [X 규칙](https://help.twitter.com/en/rules-and-policies/twitter-rules)에서 허용한 경우를 제외하고, X에서의 스팸이나 보안을 측정하거나 분석하는 것

<div id="surveillance-privacy-and-user-protection">
  ## 감시, 프라이버시 및 이용자 보호
</div>

X에서는 이용자의 프라이버시를 보호하고 수호하는 것을 회사의 핵심 DNA로 삼고 있으며, 당사의 개발자 및 데이터 제품은 이러한 의지를 그대로 반영합니다. 우리는 X data가 자카르타 홍수 시 인명 구조, USGS의 지진 추적, UN과의 협력을 통한 지속가능발전목표(SDGs) 달성 등 전 세계에 선한 영향력을 미칠 수 있는 강력한 힘이 될 수 있다고 믿습니다. 그러나 우리는 어떤 주체든 감시 목적이나 그 밖에 이용자의 합리적인 프라이버시 기대에 반하는 방식으로 X data 및 X API를 사용하는 것을 금지합니다. 예외는 없습니다.

우리는 [Developer Agreement](/ko/developer-terms/agreement)에서 데이터 및 개발자 제품의 금지된 사용 사례를 설명하고 있으며, 여기에는 X 이용자 또는 그 콘텐츠를 조사하거나 추적하는 행위, 시위·집회·커뮤니티 조직 모임과 같은 민감한 사건을 추적·경보·모니터링하는 행위에 대한 금지도 포함됩니다.

이 조건에 따라 금지되는 활동 범주는 (이에 국한되지 않으며) 다음을 포함합니다.

* 노동조합이나 행동주의 단체 등 민감한 집단 및 조직 조사 또는 추적
* 신원 조회 또는 어떠한 형태의 극단적인 심사
* 신용 또는 보험 리스크 분석
* 개인 프로파일링 또는 심리·성향 기반 세분화
* 얼굴 인식

이 정책은 모든 API 이용자에게 적용됩니다. 이러한 목적을 위해 X API를 오용하는 경우, 접근 정지 및 종료를 포함한 제재 조치의 대상이 됩니다.

X 계정 관련 정보를 요청하려는 법 집행 기관을 위한 추가 정보는 [https://t.co/le](https://t.co/le)에서 확인하시기 바랍니다.

또한, 현 시점에서 X는 [Grok](https://help.x.com/en/using-x/about-grok)을 예외로 하고, 파운데이션(foundation) 또는 프런티어(frontier) 모델을 파인튜닝(fine-tune)하거나 학습시키기 위한 X API 및/또는 X Content의 모든 사용을 금지합니다.
