* **보호된 계정:** [보호된 계정](https://help.x.com/safety-and-security/public-and-protected-posts)의 콘텐츠는 해당 계정을 팔로우하도록 계정 소유자가 승인한 사람에게만 제공됩니다. 따라서 보호된 계정에 접근하는 서비스를 운영하는 경우, 그러한 콘텐츠를 볼 권한이 있는 특정 사용자에게만 해당 콘텐츠를 제공하는 목적에 한해서만 접근해야 합니다.
* **차단된 계정:** X 이용자는 원하는 어떠한 이유로든 자신의 계정에 대한 접근을 [차단](https://help.x.com/using-x/blocking-and-unblocking-accounts)할 수 있습니다. 이 선택을 우회하기 위해 토큰(또는 기타 API 기반 작업)으로 취득한 정보를 섞어 사용하는 것은 허용되지 않습니다.

**다이렉트 메시지(DM)는 비공개적 특성을 가지므로, DM 기능을 제공하는 서비스는 개인정보 보호를 위해 추가적인 조치를 취해야 합니다. DM 콘텐츠를 볼 권한이 없는 사람에게 해당 콘텐츠를 제공해서는 안 됩니다. 서비스에서 DM 기능을 제공하는 경우 다음도 준수해야 합니다.**

* DM에 대해 읽음 확인 이벤트를 전송하는 경우 이를 사용자에게 고지해야 합니다. 이는 서비스 내에서 직접 고지를 제공하거나, 대화에 참여한 다른 사용자의 읽음 확인을 표시하는 방식으로 할 수 있습니다.
* DM으로 전송되는 미디어를 &quot;공유&quot;(즉, 여러 DM에서 재사용 가능)로 설정하기 전에 동의를 받아야 합니다. DM의 미디어를 “공유”되도록 허용하는 경우, 이 콘텐츠가 해당 미디어의 URL을 가진 누구에게나 접근 가능하다는 사실을 명확히 고지해야 합니다.

<div id="content-compliance">
  ### 콘텐츠 규정 준수
</div>

**X 콘텐츠를 오프라인 상태로 저장하는 경우, 해당 콘텐츠를 X 상의 최신 상태와 일치하도록 유지해야 합니다.** 구체적으로, 어떤 콘텐츠가 X에서 삭제되거나 수정되었다면, 보유 중인 해당 콘텐츠도 삭제하거나 수정해야 합니다. 이는 합리적으로 가능한 한 신속하게, 또는 X나 해당 X 계정 소유자로부터 그러한 요청을 받은 후 24시간 이내에, 또는 X와의 계약이나 관련 법률에서 정한 기간 내에 이루어져야 합니다. 이는 관련 법률에 의해 금지되지 않는 한 반드시 준수해야 하며, 법률상 허용되는 예외가 있는 경우에도 X의 명시적 서면 허가가 있어야 합니다.

수정된 콘텐츠는 다양한 형태를 취할 수 있습니다. 여기에는 (이에 한정되지 않고) 다음이 포함됩니다:

* 비공개로 전환되었거나 보호 상태가 된 콘텐츠
* 플랫폼에서 정지된 콘텐츠
* 위치 태그(geotag)가 제거된 콘텐츠
* X에서 제한(보류)되었거나 제거된 콘텐츠

<div id="off-x-matching">

</div>

**X 외부에서 획득하거나 보관한 정보를 사용해 X 상의 사람과 매칭할 수 있는 상황은 제한됩니다.** X 외부 매칭이란 X 콘텐츠(X @handle 또는 사용자 id 포함)를 사람, 가구, 기기, 브라우저 또는 기타 X 외부 식별자와 연결하는 것을 의미합니다. 이러한 연결은 해당 사람으로부터 그러한 연결을 하기 전에 명시적인 옵트인 동의를 받았거나, 아래에 설명된 경우에만 할 수 있습니다.

어떤 사람의 X 아이덴티티를 X 외부 식별자와 연결하는 것에 대해 그 사람의 명시적인 옵트인 동의가 없는 상황에서는, 귀하가 설정하는 모든 연결이 그 목적을 위해 사용될 것이라고 합리적으로 예상할 수 있는 정보에만 기반해야 합니다. 추가로, 사람의 명시적인 옵트인 동의가 없는 경우, 귀하가 보유한 어떤 사람에 대한 기록을 X 아이덴티티와 매칭하려는 시도는 다음에만 기반할 수 있습니다.

* **해당 사람이 귀하에게 직접 제공한 정보.** 귀하와 기존 관계가 없는 개인에 대한 기록(제3자로부터 획득한 개인 데이터 포함)은 이 기준을 충족하지 못한다는 점에 유의해야 합니다. 그리고/또는
* **공개 데이터.** 이 문맥에서 “공개 데이터”란 다음을 의미합니다.
  * 귀하가 공개적으로 일반에 공개된 자원(예: 직능 단체 회원 명부)에서 획득한, 특정인에 대한 정보
  * X 상에서 특정인에 대해 공개적으로 이용 가능한 정보로서, 다음을 포함합니다.
    * 포스트
    * 계정 소개(bio) 및 공개적으로 표시된 위치를 포함한 프로필 정보
    * 표시 이름 및 @handle

<div id="using-geo-data">
  ### 지리 데이터 사용
</div>

**지리 데이터는 정보의 민감한 특성으로 인해 추가적인 제한이 적용됩니다.** 귀하의 서비스가 포스트에 위치 정보를 추가하는 경우, 사람들에게 다음 사항을 고지해야 합니다.

* 언제 위치 정보를 추가하는지
* 위치 정보를 지오태그로 추가하는지, 아니면 annotations data로 추가하는지 여부
* 위치 정보가 장소로 표시되는지, 아니면 지리 좌표로 표시되는지 여부

귀하의 애플리케이션이 이용자가 자신의 위치 정보를 포함해 게시하도록 허용하는 경우, X의 [지리 가이드라인](/ko/developer-terms/geo-guidelines)을 전부 준수해야 합니다.

**위치 데이터나 지리 정보를 단독으로 사용하는 것은 금지됩니다.** 귀하는 (그리고 다른 사람이 그러도록 허용해서도) 포스트의 일부인 경우를 제외하고, X 콘텐츠에 포함된 위치 데이터 및 기타 지리 정보를 저장, 집계 또는 캐시할 수 없습니다. 예를 들어, 시간이 지남에 따라 특정 개인이 어디에 있었는지 보여주기 위해 포스트에서 위치 데이터나 지리 정보를 분리해서는 안 됩니다. 집계된 지리 활동(예: 특정 도시에서 해시태그를 사용하는 사람 수)을 보여주는 히트맵 및 관련 도구는 허용됩니다.

<div id="spam-bots-and-automation">

</div>

**스팸을 생성하거나 어떠한 형태로든 플랫폼 조작에 관여하기 위해 X API 및 개발자 제품을 사용하는 것은 금지됩니다.** [플랫폼 조작 및 스팸](https://help.x.com/rules-and-policies/platform-manipulation)에 대한 X 규칙을 검토하고, 귀하의 서비스가 해당 정책을 위반하지 않으며, 또한 사람들로 하여금 정책을 위반하도록 허용하거나 조장하지 않도록 해야 합니다.

**포스트 게시, 계정 팔로우, 다이렉트 메시지 발송 등 쓰기 작업을 수행하는 서비스는 [Automation Rules](https://help.x.com/rules-and-policies/x-automation)를 따라야 합니다.** 특히, 다음 사항을 준수해야 합니다.

* 사람들에게 [자동 응답 또는 다이렉트 메시지](https://twittercommunity.com/t/policy-clarification-automated-replies-and-mentions/94444)를 보내기 전에 항상 명시적인 동의를 받아야 합니다.
* 귀하에게서의 연락을 거부(opt-out)하겠다는 요청을 즉시 수용해야 합니다.
* [대량 팔로우](https://twittercommunity.com/t/policy-clarification-aggressive-following-and-inorganic-following-behavior/92769)를 포함해 대량, 공격적 또는 스팸성 행동을 절대 수행하면 안 됩니다.
* [여러 계정](https://blog.twitter.com/developer/en_us/topics/tips/2018/automation-and-the-use-of-multiple-accounts.html)에 동일하거나 실질적으로 유사한 콘텐츠를 절대 게시하면 안 됩니다.

**API 기반 봇 계정을 운영하는 경우, 해당 계정이 어떤 계정인지와 누가 책임을 지는지 명확하게 표시해야 합니다.** 귀하의 계정이 봇인지 아닌지에 대해 사람들을 오도하거나 혼란스럽게 해서는 안 됩니다. 이를 위한 좋은 방법은 계정의 프로필 소개란에 해당 계정이 봇이라는 설명을 포함하는 것입니다.

<div id="x-performance-benchmarking">

**벤치마킹, 경쟁 또는 상업적 목적을 위해 X의 가용성, 성능, 기능 또는 사용량을 측정하는 데 X API를 사용할 수 없습니다.** 예를 들어, X API를 사용하여 다음과 같은 작업을 해서는 안 됩니다:

<div id="public-display-of-posts">
  ### 포스트의 공개 표시
</div>

**공개적으로 또는 귀하의 서비스를 이용하는 사람들에게 표시하는 모든 X 콘텐츠의 무결성을 유지해야 합니다.** 콘텐츠 표시를 위해 [X for Websites](https://developer.x.com/docs/twitter-for-websites/overview)를 사용하지 않는 경우, 표시 가능한 최신 버전을 가져오기 위해 X API를 사용해야 합니다. 표시된 콘텐츠가 더 이상 X API를 통해 제공되지 않는 경우, 합리적으로 가능한 한 신속하게, 또는 X나 해당 X 계정 소유자로부터 삭제 요청을 받은 후 24시간 이내에, 또는 관련 법률에 의해 요구되는 때에 귀하의 서비스에서 해당 콘텐츠를 제거해야 합니다.

**X 콘텐츠를 오프라인에서 표시하는 경우 따라야 하는 특정 규칙이 있습니다.** 포스트를 오프라인으로 표시하는 경우, 방송에서 포스트를 사용할 때의 [가이드라인](https://developer.x.com/developer-terms/display-requirements)을 따라야 합니다.

**포스트를 임베드하거나 표시하는 경우, 귀하의 사이트가 일일 1,000만 회 이상의 노출을 초과하면 X API 액세스와 관련하여 저희에게 연락해야 합니다.** X는 귀하의 X API 사용 조건으로서 추가 약관을 요구할 권리를 보유합니다. X for Websites를 개발 목적으로 사용하는 경우 적용되는 추가 제한 사항은 다음과 같습니다.

* **임베드된 포스트 및/또는 임베드된 타임라인**

<div id="content-redistribution">
  ### 콘텐츠 재배포
</div>

**X 콘텐츠를 얻기 위한 최선의 방법은 X로부터 직접 제공받는 것입니다. 따라서 우리는 X 콘텐츠를 제3자에게 재배포하는 행위를 제한합니다.** 다운로드 가능한 데이터 세트 또는 API를 통해 X 콘텐츠를 제3자에게 제공하는 경우, 아래에 설명된 예외를 제외하면 포스트 ID, 다이렉트 메시지 ID 및/또는 사용자 ID만 배포할 수 있습니다.

어떤 단일 법인(단일 법인에 소속된 여러 개인을 모두 포함함)에 대해서도, 30일 기간 동안 X로부터 서면 허가를 받지 않는 한 총 1,500,000개의 포스트 ID를 초과하여 배포할 수 없습니다. 또한, 자동화되지 않은 수단(예: 스프레드시트 또는 PDF 다운로드)을 통해 이루어지는 경우에 한해, 개발자는 귀하의 서비스를 사용하는 각 개인에게 하루 기준 최대 500개의 공개 포스트 객체 및/또는 사용자 객체를 제공할 수 있습니다.

학술 연구자는 학술 기관을 대신한 비상업적 연구 목적 또는 해당 연구의 동료 평가나 검증 목적에 한하여, 그리고 그러한 연구가 X로부터 서면으로 승인된 경우에만 포스트 ID 및/또는 사용자 ID를 배포할 수 있습니다. 그러한 연구에 필요하며 X로부터 승인된 범위 내에서만 포스트 ID 또는 사용자 ID를 사용할 수 있습니다.

제3자에게 제공되는 모든 X 콘텐츠는 계속해서 본 정책의 적용을 받으며, 해당 제3자는 이러한 다운로드를 받기 전에 X의 [이용약관](https://x.com/tos), [개인정보 처리방침](https://x.com/privacy), [개발자 계약](/ko/developer-terms/agreement) 및 [개발자 정책](/ko/developer-terms/policy)에 동의해야 합니다. 귀하는 이 [정책](/ko/developer-terms/policy), [개발자 계약](/ko/developer-terms/agreement) 또는 X와의 기타 어떠한 계약에 포함된 X 콘텐츠 배포에 대한 다른 한도나 제한을 어떤 법인도 우회할 수 있도록 해서는 안 됩니다.

**참고:** 본 섹션은 EU 디지털 서비스 법(2022) 제40조(“**DSA**”)에 따라 X API 접근 권한을 가진 연구자에게는 적용되지 않으며, 이들은 대신 DSA 및 개발자 계약에 규정된 절차와 제한의 적용을 받습니다.

<div id="x-login">

<div id="x-cards">

</div>

**양질의 이용 경험을 제공하기 위해, Cards가 표시되는 모든 플랫폼에서 올바르게 렌더링되도록 Card를 개발해야 합니다.** Cards를 사용할 때 따라야 하는 추가 규칙은 다음과 같습니다.

* Card 내에 민감한 미디어를 표시할 계획이 있는 경우, 해당 포스트의 민감한 미디어 플래그를 ‘true’로 설정해야 합니다.
* Card 내에 포함된 모든 에셋을 호스팅할 때는 HTTPS를 사용해야 합니다. Card로 인해 브라우저에서 활성 혼합 콘텐츠 관련 경고가 발생해서는 안 됩니다.
* 오디오 및 비디오 콘텐츠에는 정지 또는 일시정지 컨트롤이 포함되어야 하며, 자동 재생되는 비디오 콘텐츠는 기본적으로 ‘음소거’ 상태여야 합니다.

**Card, 포함하여 Card의 의도된 사용 범위에 대해 X가 설정한 제한을 초과하거나 이를 우회해서는 안 됩니다.** Cards의 사용에 대한 추가 제한은 다음과 같습니다.

* X의 승인을 받지 않은 제3자 후원 콘텐츠를 Cards 안에 배치해서는 안 됩니다.
* Card 내에서 또는 Card를 통해 X에서 금전적 인센티브(가상 화폐 포함)를 제공해서는 안 됩니다.
* URL 및 미디어와 같이 오해의 소지가 있거나 문맥상 관련성이 없는 콘텐츠나 동작을 Card에 포함해서는 안 됩니다.
* 사용자가 포스트에서 해당 앱을 명시적으로 홍보하거나 언급하는 경우에만 포스트에 App Card를 첨부할 수 있습니다.
