<div id="protecting-credentials">
  ## 자격 증명 보호
</div>

API 키와 토큰은 앱의 열쇠입니다. 안전하게 보호하세요:

<Steps>
  <Step title="환경 변수를 사용하세요">
    자격 증명은 코드가 아닌 환경 변수에 저장하세요.

    ```bash
    export X_API_KEY="your-api-key"
    export X_API_SECRET="your-api-secret"
    ```
  </Step>

  <Step title="비밀 정보는 절대 커밋하지 마세요">
    자격 증명 파일을 `.gitignore`에 추가하세요. `git-secrets` 같은 도구를 사용해 실수로 커밋되는 것을 방지하세요.
  </Step>

  <Step title="정기적으로 교체하세요">
    키를 주기적으로 다시 발급하고, 유출이 의심되면 즉시 재발급하세요.
  </Step>

  <Step title="최소 권한만 사용하세요">
    앱에 실제로 필요한 OAuth 범위만 요청하세요.
  </Step>
</Steps>

<div id="if-credentials-are-compromised">
  ### 자격 증명이 유출된 경우
</div>

1. [개발자 콘솔](https://console.x.com)에서 **즉시 재발급**하세요.
2. **기존 토큰을 폐기**하세요 — 재발급 시 이전 자격 증명은 자동으로 무효화됩니다.
3. **사용 내역을 점검**하세요 — 무단 API 활동이 있었는지 확인하세요.
4. **앱을 업데이트**하세요 — 모든 환경에 새 자격 증명을 배포하세요.

<div id="application-security">
  ## 애플리케이션 보안
</div>

<div id="input-validation">
  ### 입력 검증
</div>

사용자 입력을 절대 신뢰하지 마세요. 사용하기 전에 모든 데이터를 검증하고 정제하세요:

```python
# Bad - vulnerable to injection
query = f"from:{user_input}"

# Good - validate input first
import re
if re.match(r'^[a-zA-Z0-9_]{1,15}$', user_input):
    query = f"from:{user_input}"
```

<div id="output-encoding">
  ### 출력 인코딩
</div>

XSS를 방지하기 위해 HTML에 표시하기 전에 X API data는 이스케이프하세요:

```javascript
// 나쁜 예 - XSS에 취약함
element.innerHTML = tweet.text;

// 좋은 예 - HTML 이스케이프 처리
element.textContent = tweet.text;
```

<div id="common-vulnerabilities-to-prevent">
  ### 방지해야 할 일반적인 취약점
</div>

| 취약점 | 예방 방법 |
|:--------------|:-----------|
| **XSS** | 렌더링하기 전에 사용자가 생성한 콘텐츠를 모두 이스케이프 처리합니다 |
| **CSRF** | 폼에 anti-CSRF 토큰을 사용하고, OAuth state 매개변수를 검증합니다 |
| **SQL Injection** | 파라미터화된 쿼리를 사용하고, 사용자 입력을 절대 문자열로 연결하지 않습니다 |
| **Open redirects** | 콜백 URL을 허용 목록과 대조하여 검증합니다 |

<div id="oauth-security">
  ## OAuth 보안
</div>

<div id="state-parameter">
  ### state 매개변수
</div>

CSRF를 방지하기 위해 OAuth 흐름에서는 항상 `state` 매개변수를 사용하세요:

```python
import secrets

# 인증 전 state 생성
state = secrets.token_urlsafe(32)
session['oauth_state'] = state

# 콜백 후 state 확인
if request.args.get('state') != session.get('oauth_state'):
    abort(403)  # State 불일치 - CSRF 공격 가능성
```

<div id="token-storage">
  ### 토큰 저장
</div>

| 토큰 유형 | 저장 권장 사항 |
|:-----------|:-----------------------|
| **Access tokens** | 암호화된 데이터베이스 또는 보안 비밀 저장소(secure vault) |
| **Refresh tokens** | 추가 접근 제어가 적용된 암호화된 데이터베이스 |
| **Bearer tokens** | 환경 변수 또는 보안이 적용된 설정 |

<div id="compliance-checklist">
  ## 컴플라이언스 점검표
</div>

<Accordion title="X API 개발자를 위한 보안 요구사항">
  * [ ] 모든 API 요청에 TLS/HTTPS 사용
  * [ ] 자격 증명 정보를 안전하게 저장 (코드나 로그에 저장 금지)
  * [ ] 저장 시 사용자 토큰 암호화
  * [ ] 사용자 제공 데이터에 대한 입력 검증
  * [ ] XSS 방지를 위한 출력 인코딩
  * [ ] OAuth 플로우에 대한 CSRF 보호 적용
  * [ ] 보안 로깅 활성화 (민감한 데이터 제외)
  * [ ] 보안 사고 대응 계획 문서화
  * [ ] 종속성 정기적으로 업데이트
  * [ ] 최소한의 OAuth 범위만 요청
</Accordion>
