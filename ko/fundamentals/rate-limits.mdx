요청 한도는 일정 기간 동안 보낼 수 있는 API 요청 수를 제한합니다. 이는 플랫폼 전반에서 공정한 사용과 시스템 안정성을 보장하기 위한 장치입니다.

***

<div id="how-rate-limits-work">
  ## 레이트 리밋이 작동하는 방식
</div>

| 개념 | 설명 |
|:--------|:------------|
| **시간 구간** | 대부분의 한도는 15분마다 재설정됩니다 |
| **사용자별 한도** | OAuth 1.0a 또는 OAuth 2.0 사용자 토큰을 사용할 때 적용됩니다 |
| **앱별 한도** | Bearer Token(앱 전용) 인증을 사용할 때 적용됩니다 |
| **엔드포인트별 한도** | 각 엔드포인트마다 별도의 한도가 있습니다 |

***

<div id="checking-your-limits">
  ## 한도 확인하기
</div>

모든 API 응답에는 현재 레이트 리밋 상태를 보여 주는 헤더가 포함됩니다.

```
x-rate-limit-limit: 900
x-rate-limit-remaining: 847
x-rate-limit-reset: 1705420800
```

| Header                   | Description              |
| :----------------------- | :----------------------- |
| `x-rate-limit-limit`     | 현재 윈도우에서 허용되는 최대 요청 횟수   |
| `x-rate-limit-remaining` | 현재 윈도우에서 남아 있는 요청 횟수     |
| `x-rate-limit-reset`     | 제한이 재설정되는 시점의 Unix 타임스탬프 |

***

<div id="rate-limit-errors">
  ## Rate limit 오류
</div>

요청 한도(rate limit)를 초과하면 **429 Too Many Requests** 응답을 받게 됩니다:

```json
{
  "errors": [{
    "code": 88,
    "message": "Rate limit exceeded"
  }]
}
```
