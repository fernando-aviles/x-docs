요청 한도는 일정 기간 동안 보낼 수 있는 API 요청 횟수를 제한합니다. 이를 통해 플랫폼 전반에서 공정한 사용과 시스템 안정성을 유지합니다.

***

<div id="rate-limits-by-product">
  ## 제품별 요청 한도
</div>

각 X API 제품은 서로 다른 방식으로 요청 한도를 적용합니다:

<CardGroup cols={3}>
  <Card title="X API v2" icon="square-x-twitter" href="/ko/x-api/fundamentals/rate-limits">
    15분 단위의 시간 창을 기준으로 엔드포인트별 요청 한도가 적용됩니다. 자세한 표와 복구 방법을 확인하세요.
  </Card>

  <Card title="Enterprise API" icon="building" href="/ko/x-api/enterprise-gnip-2.0/fundamentals/rate-limits">
    엔터프라이즈 계약과 데이터 패키지를 기반으로 맞춤형 요청 한도가 적용됩니다.
  </Card>

  <Card title="X Ads API" icon="rectangle-ad" href="/ko/x-ads-api/fundamentals/rate-limiting">
    광고 관리 및 분석 엔드포인트에 특화된 요청 한도가 적용됩니다.
  </Card>
</CardGroup>

***

<div id="how-rate-limits-work">
  ## 요청 한도 동작 방식
</div>

| 개념 | 설명 |
|:--------|:------------|
| **시간 창** | 대부분의 요청 한도는 15분마다 초기화됩니다 |
| **사용자별 한도** | OAuth 1.0a 또는 OAuth 2.0 사용자 토큰을 사용할 때 적용됩니다 |
| **App별 한도** | Bearer 토큰(App 전용) 인증을 사용할 때 적용됩니다 |
| **엔드포인트별** | 각 엔드포인트마다 별도의 한도가 있습니다 |

***

<div id="checking-your-limits">
  ## 요청 한도 확인
</div>

모든 API 응답에는 현재 요청 한도(rate limit) 상태를 나타내는 헤더가 포함되어 있습니다:

```
x-rate-limit-limit: 900
x-rate-limit-remaining: 847
x-rate-limit-reset: 1705420800
```

| Header                   | Description            |
| :----------------------- | :--------------------- |
| `x-rate-limit-limit`     | 현재 윈도 내에서 허용되는 최대 요청 수 |
| `x-rate-limit-remaining` | 현재 윈도 내에서 남아 있는 요청 수   |
| `x-rate-limit-reset`     | 제한이 초기화되는 유닉스 타임스탬프    |

***

<div id="rate-limit-errors">
  ## Rate limit 오류
</div>

요청 rate limit을 초과하면 **429 Too Many Requests** 응답을 받습니다:

```json
{
  "errors": [{
    "code": 88,
    "message": "Rate limit exceeded"
  }]
}
```
