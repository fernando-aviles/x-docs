앱은 API 자격 증명을 보관하는 컨테이너입니다. 각 앱에는 고유한 키, 토큰 및 설정이 있습니다.

---

<div id="app-credentials">
  ## 앱 자격 증명
</div>

앱을 생성하면 다음과 같은 자격 증명을 발급할 수 있습니다:

| 자격 증명 | 사용 사례 |
|:-----------|:---------|
| **API Key & Secret** | OAuth 1.0a로 인증합니다. 요청에 서명하거나 사용자 토큰을 생성하는 데 사용됩니다. |
| **Access Token & Secret** | 자신의 계정(OAuth 1.0a)으로 요청을 보낼 때 사용합니다. |
| **Client ID & Secret** | OAuth 2.0으로 인증합니다. Authorization Code 플로우에 사용됩니다. |
| **Bearer Token** | 공개 data 엔드포인트용 앱 전용 인증에 사용됩니다. |

<Tip>
새로운 Project에는 **OAuth 2.0**을 선택하세요. 세분화된 권한 범위(scope)를 제공하며, X API v2 사용자 컨텍스트 엔드포인트에 필수입니다.
</Tip>

<div id="app-permissions-oauth-10a">
  ## 앱 권한 (OAuth 1.0a)
</div>

OAuth 1.0a 앱에는 세 가지 권한 수준이 있습니다.

<Tabs>
  <Tab title="읽기 전용">
    - 포스트, 사용자 및 공개 데이터 보기
    - 포스트 작성, 좋아요 또는 기타 수정 작업을 할 수 없음
    - 다이렉트 메시지(DM)에 접근할 수 없음
  </Tab>
  <Tab title="읽기 및 쓰기">
    - 모든 읽기 권한
    - 포스트 작성 및 삭제
    - 사용자 팔로우/언팔로우
    - 좋아요 및 리포스트
    - 다이렉트 메시지(DM)에 접근할 수 없음
  </Tab>
  <Tab title="읽기, 쓰기 및 DM">
    - 모든 읽기 및 쓰기 권한
    - 다이렉트 메시지(DM) 전송 및 읽기
  </Tab>
</Tabs>

<Note>
권한을 변경하면 사용자가 업데이트된 권한 범위가 적용된 새로운 토큰을 발급받기 위해 앱을 다시 승인해야 합니다.
</Note>

<div id="oauth-20-app-types">
  ## OAuth 2.0 앱 유형
</div>

OAuth 2.0을 설정할 때 앱 유형을 선택하세요:

| 유형 | 클라이언트 | 사용 사례 |
|:-----|:-------|:---------|
| **Web App** | 기밀 | 시크릿을 안전하게 저장할 수 있는 서버 측 애플리케이션 |
| **Automated App / Bot** | 기밀 | 서버에서 실행되는 봇 및 자동화 서비스 |
| **Native App** | 공용 | 시크릿을 안전하게 저장할 수 없는 모바일 또는 데스크톱 앱 |
| **Single Page App** | 공용 | 브라우저 기반 JavaScript 앱 |

**기밀 클라이언트**는 클라이언트 시크릿(Client Secret)을 받습니다. **공용 클라이언트**는 PKCE만 사용합니다.

<div id="callback-urls">
  ## 콜백 URL
</div>

OAuth 플로우에는 콜백 URL(리디렉트 URI)이 필수입니다. 사용자가 앱을 승인하면, 인증 코드가 포함된 상태로 콜백 URL로 리디렉션됩니다.

<div id="requirements">
  ### 요구 사항
</div>

- Developer Console에서 앱의 허용 목록에 콜백 URL을 추가하세요
- URL은 끝의 슬래시까지 포함해 정확히 일치해야 합니다
- 앱당 콜백 URL은 최대 **10개**까지 설정할 수 있습니다
- 운영 환경에서는 `https://`를 사용하세요
- 로컬 개발 환경에서는 `localhost`가 아닌 `http://127.0.0.1`를 사용하세요

<div id="disallowed-protocols">
  ### 허용되지 않는 프로토콜
</div>

다음 프로토콜은 사용할 수 없습니다: `javascript`, `data`, `file`, `ftp`, `mailto`, `telnet` 및 기타 비표준 스킴.

<Accordion title="허용되지 않는 프로토콜 전체 목록">
`vbscript`, `javascript`, `vbs`, `data`, `mocha`, `keyword`, `livescript`, `ftp`, `file`, `gopher`, `acrobat`, `callto`, `daap`, `itpc`, `itms`, `firefoxurl`, `hcp`, `ldap`, `mailto`, `mmst`, `mmsu`, `msbd`, `rtsp`, `mso-offdap`, `snews`, `news`, `nntp`, `outlook`, `stssync`, `rlogin`, `telnet`, `tn3270`, `shell`, `sip`
</Accordion>

<div id="automated-account-labels">
  ## 자동화 계정 레이블
</div>

앱에서 봇 계정을 운영하는 경우, 해당 계정을 자동화된 계정으로 표시(레이블)할 수 있습니다:

1. 봇 계정의 **Settings**로 이동합니다
2. **Your account** → **Automation**을 선택합니다
3. 관리 계정을 연결합니다

이렇게 하면 사용자와의 신뢰를 구축하고, 봇 계정을 스팸과 구분할 수 있습니다.

<div id="troubleshooting">
  ## 문제 해결
</div>

<Accordion title="Callback URL 미승인 오류">
Developer Console에 등록된 callback URL과 프로토콜, 끝에 오는 슬래시까지 모두 정확히 일치하는지 확인하세요. 쿼리 매개변수로 전달할 때는 URL을 HTTP로 인코딩하세요.

```json
{
  "errors": [{
    "code": 415,
    "message": "Callback URL not approved for this client application."
  }]
}
```
</Accordion>

<Accordion title="앱이 정지된 경우">
앱이 정지된 상태로 표시되는 경우, X 플랫폼 팀에서 보낸 안내 메일을 확인하세요. 재심사를 요청하려면 [Platform Help Form](https://help.x.com/forms/platform)을 사용하세요.
</Accordion>
