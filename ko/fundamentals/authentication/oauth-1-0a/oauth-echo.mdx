<div id="oauth-echo">
  ### OAuth Echo
</div>

OAuth Echo는 API와 상호 작용하는 동안 제3자에게 OAuth 인가를 안전하게 위임하는 방식입니다.

이 상호 작용에는 네 개의 주체가 관여합니다:

* **사용자(User)** — 특정한, 인가된 X 애플리케이션을 통해 X를 사용하고 있는 사람
* **소비자(Consumer)** — 제3자 미디어 제공자(예: 사진 공유 사이트)와 상호 작용을 시도하는 X 애플리케이션
* **위임자(Delegator)** — 제3자 미디어 제공자
* **서비스 제공자(Service Provider)** — 즉, X 자체
     

요약하면, 애플리케이션과 사용자를 대신해 위임자가 X API로 전송할 요청을 준비하는 것입니다. 원래라면 서명된 OAuth 요청이 되었을 내용을 HTTP 헤더에 넣고, 위임자에게 중간 작업을 완료한 뒤 그 요청을 X로 보내 달라고 요청합니다.

예를 들어, 사용자가 사진을 업로드하고자 한다고 가정해 보겠습니다. 소비자는 `POST`로 위임자의 업로드 메서드를 호출합니다. 이 `POST`에는 이미지를 포함해야 할 뿐 아니라, HTTP 헤더에 다음 두 가지 항목도 추가로 포함해야 합니다:

* `x-auth-service-provider` — 실질적으로 신원 위임이 전송되어야 할 영역(realm)입니다. X의 경우, 이를 https://api.x.com/1.1/account/verify_credentials.json으로 설정합니다. iOS5 기반 X 연동에서는 이 URL에 추가 `application_id` 파라미터를 붙이며, 이는 `x-verify-credentials-authorization`에 사용되는 `oauth_signature`를 계산하는 데도 사용됩니다.
* `x-verify-credentials-authorization` — 소비자는 OAuth를 사용해 HTTP 헤더에서 https://api.x.com/1.1/account/verify_credentials.json을 호출하는 데 필요한 모든 OAuth 파라미터를 생성해야 합니다(예: `OAuth oauth_consumer_key="..."`, `oauth_token="..."`, `oauth_signature_method="..."`, `oauth_signature="..."`, `oauth_timestamp="..."`, `oauth_nonce="..."`, `oauth_version="..."` 와 같은 형태여야 합니다).
     

전체 트랜잭션 과정이 `oauth_timestamp`가 여전히 유효한 시간 안에 완료되어야 한다는 점을 명심하십시오.

또는 이 두 파라미터를 헤더로 보내는 대신, `POST` 본문에 `x_auth_service_provider`와 `x_verify_credentials_authorization`로 보낼 수도 있습니다. 이 경우, 다른 요청에서 파라미터를 인코딩할 때와 마찬가지로, 해당 파라미터들을 이스케이프하여 OAuth 서명 베이스 문자열(signature base string)에 포함해야 한다는 점을 기억하십시오. 가능한 한 작업을 분리하기 위해 HTTP 헤더를 사용하는 것이 가장 좋습니다.

이 시점에서 위임자의 목표는 미디어를 저장하기 전에 사용자가 스스로 주장하는 사람인지 확인하는 것입니다. 위임자가 업로드 메서드를 통해 위의 모든 데이터를 수신하면, 이미지를 임시로 저장한 다음, `x-auth-service-provider` 헤더에 지정된 엔드포인트(이 예에서는 https://api.x.com/1.1/account/verify_credentials.json)를, 소비자가 `x-verify-credentials-authorization` 헤더에 제공한 것과 동일한 OAuth 인증 헤더를 사용해 호출해야 합니다.
 

<div id="oauth-echo-best-practices">
  #### OAuth Echo 모범 사례
</div>

조회 작업을 수행할 때는 하드코딩된 값을 사용하지 말고, 반드시 `x-auth-service-provider`가 제공하는 URL을 사용하십시오. 예를 들어 Apple iOS는 모든 OAuth 요청에 추가적인 `application_id` 매개변수를 포함하며, OAuth Echo의 각 단계에서 이 매개변수가 유지되어야 합니다.

OAuth 인가 부분에서는 `x-verify-credentials-authorization`의 헤더 값을 가져와, 서비스 제공자에 대한 호출에 사용할 별도의 Authorization 헤더에 그대로 넣으십시오. 그리고 추가로, `x-auth-service-provider`에 들어 있는 값이 기대한 값이 맞는지 확인하십시오.

* 서비스 제공자가 HTTP 200을 반환하면 정상입니다. Delegator는 이미지를 영구적으로 저장하고 URL을 생성한 뒤 이를 반환해야 합니다.
* 서비스 제공자가 HTTP 200을 반환하지 않으면 이미지를 폐기하고 Consumer에 오류를 반환해야 합니다.
