<div id="api-key-and-secret">
  ### API Key and Secret
</div>

API Key와 Secret(Consumer Key와 Secret이라고도 함)은 X API에 액세스하는 데 필요한 가장 기본적인 자격 증명입니다. 이 자격 증명은 X 앱의 사용자 이름과 비밀번호 역할을 하며, X API는 이를 사용해 어떤 앱에서 요청이 들어오는지 파악합니다. 

이 자격 증명은 [인증 엔드포인트](/ko/resources/fundamentals/authentication/api-reference)를 통해 [사용자 Access Token 및 Secret](/ko/resources/fundamentals/authentication/oauth-1-0a/api-key-and-secret), [Bearer Token](/ko/resources/fundamentals/authentication/oauth-2-0/bearer-tokens)과 같은 추가 자격 증명을 생성하는 데 사용할 수 있습니다. 또한 OAuth 1.0a User Context 인증이 필요한 요청을 [승인](/ko/resources/fundamentals/authentication/oauth-1-0a/authorizing-a-request)하려면 이 자격 증명을 Access Token 및 다른 인가 매개변수와 함께 사용해야 합니다. 

<div id="how-to-acquire-an-api-key-and-secret">
  #### API Key 및 Secret을 발급받는 방법
</div>

X API Key 및 Secret을 발급받으려면 다음 단계를 따라 주세요.

1. [X 개발자 계정에 가입합니다](https://developer.x.com/en/apply-for-access)
2. [Developer Console](/ko/resources/fundamentals/developer-portal) 내에서 [X App](/ko/resources/fundamentals/developer-apps)을 생성합니다. [X API v2](/ko/x-api/introduction)를 사용하려면 반드시 개발자 App에서 발급된 키와 토큰을 사용해야 합니다.
    

X App을 생성하면 API Key 및 Secret과 함께 Bearer Token이 제공됩니다. 이 자격 증명은 한 번만 표시되므로, 비밀번호 관리자나 다른 안전한 위치에 반드시 저장해 두시기 바랍니다.

키와 토큰을 어떻게 관리해야 하는지에 대해서는, 자격 증명이 유출되었을 때 취해야 할 조치에 대한 세부 내용을 포함하여, [인증 모범 사례](/ko/resources/fundamentals/authentication/guides/authentication-best-practices) 페이지에서 추가 권장 사항을 확인할 수 있습니다.
 

<div id="how-to-find-and-regenerate-your-api-key-and-secret-after-app-creation">
  #### App 생성 후 API Key 및 Secret을 찾고 재생성하는 방법
</div>

이미 App을 생성했고 API Key와 Secret을 찾아야 하거나 재생성해야 하는 경우, 아래 단계를 따르세요.

1. Developer Console로 이동합니다.
2. 사이드 내비게이션에서 &#39;Apps&#39; 드롭다운을 확장합니다.
3. 찾거나 재생성하려는 API Key 및 Secret이 연결된 App을 엽니다.
4. Keys and tokens 탭으로 이동합니다.

여기에서 App과 연결된 모든 자격 증명을 확인할 수 있습니다. 
 

<div id="how-to-use-your-api-key-and-secret">
  #### API Key와 Secret 사용 방법
</div>

X Developer Platform을 탐색해 보는 단계라면, 먼저 [tool or library](/ko/resources/tools-and-libraries)를 사용해 플랫폼에서 어떤 기능을 제공하는지 살펴보는 것을 권장합니다. 이러한 도구는 인증을 원활하게 처리해 주며, 많은 시간과 좌절감을 줄여 줄 수 있습니다. 특히 초보 개발자에게는 [Postman 시작하기](/ko/tutorials/postman-getting-started) 또는 [Insomnia](https://insomnia.rest/)를 사용하는 것을 권장합니다. 

요청을 처음부터 직접 구성해 보고 싶다면, [OAuth 1.0a 요청 인가](/ko/resources/fundamentals/authentication/oauth-1-0a/authorizing-a-request) 가이드를 읽어 보세요.
