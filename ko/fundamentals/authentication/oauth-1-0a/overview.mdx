<div id="oauth-10a">
  ## OAuth 1.0a
</div>

X 개발자 플랫폼의 많은 엔드포인트는 OAuth 1.0a 방식을 사용해 X 계정을 대신하여 작업하거나 API 요청을 수행합니다. 예를 들어, X 개발자 App이 있다면, 사용자가 해당 App을 인증하기만 하면 어떤 X 계정이든 그 계정을 대신해 API 요청을 보낼 수 있습니다.

참고: HMAC-SHA1 및 퍼센트 인코딩과 같은 개념에 익숙하지 않은 경우, 아래의 &quot;유용한 도구&quot; 섹션을 확인하는 것을 권장합니다. 이 섹션에는 인증 과정을 크게 단순화해 주는 여러 API 클라이언트가 나열되어 있습니다.

<div id="key-concepts">
  ### 핵심 개념
</div>

<div id="signing-a-request-with-keys-and-tokens">
  #### 키와 토큰으로 요청 서명하기
</div>

각 API 요청은 미리 발급한 여러 키와 토큰을 Authorization 헤더로 전달해 서명해야 합니다. 먼저, [X 개발자 App](/ko/resources/fundamentals/developer-apps) 상세 페이지에서 다음과 같은 키와 토큰을 생성할 수 있습니다:

|     |     |
| :--- | :--- |
| API 키와 시크릿:<br /><br />`oauth_consumer_key`<br /><br />`oauth_consumer_secret` | API 요청을 보낼 때 X 개발자 App을 나타내는 사용자 이름과 비밀번호에 해당하는 값이라고 보면 됩니다. |
| Access token과 시크릿:<br /><br />`oauth_token`<br /><br />`oauth_token_secret` | Access token과 access token secret은 OAuth 1.0a API 요청을 인증하는 데 사용되는 사용자별 자격 증명입니다. 이 값들은 요청이 어떤 X 계정을 대신해 수행되는지 지정합니다.<br /><br />개발자 계정과 연결된 X 계정과 동일한 계정을 대신해 App이 요청을 보내도록 하려면, [X 개발자 App의]/resources/fundamentals/developer-apps) 상세 페이지에서 자신의 access token과 token secret을 생성할 수 있습니다.<br /><br />다른 사용자를 대신하는 access token을 생성하려면 아래의 &quot;사용자를 대신하여 요청 보내기&quot;를 참조하세요. |

<div id="making-requests-on-behalf-of-users">
  #### 사용자를 대신해 요청 보내기
</div>

서명을 생성할 때는 요청을 대신 보내려는 사용자를 나타내는 액세스 토큰 세트가 필요합니다.

X 개발자 App을 소유한 X 계정을 나타내는 액세스 토큰 세트는 [app’s details page](https://developer.x.com/content/developer-twitter/en/apps)에서 생성할 수 있습니다. 하지만 다른 X 계정을 대신해 요청을 보내고자 하는 경우, 그 계정의 소유자가 [3-legged OAuth flow](/ko/resources/fundamentals/authentication#obtaining-access-tokens-using-3-legged-oauth-flow)의 일부로 자신의 계정에 로그인하여 여러분에게 액세스 권한을 부여해야 합니다. 이 과정의 결과물은 OAuth 1.0a 요청을 보내는 데 사용할 수 있는 액세스 토큰 세트(oauth&#95;token 및 oauth&#95;token&#95;secret)입니다.

이 키와 토큰을 얻은 후에는 직접 [서명을 생성](/ko/resources/fundamentals/authentication#creating-a-signature)할 수도 있습니다. 하지만 이 작업에 익숙하지 않다면 권장하지 않으며, OAuth 1.0a가 필요한 엔드포인트에 요청을 보낼 때는 아래에 언급된 도구 중 하나를 사용하는 것이 좋습니다.

참고용으로, 생성된 모든 토큰을 Authorization 헤더에 전달하는 서명된 cURL 요청 예시는 다음과 같습니다.

```bash
curl --request POST \
  --url 'https://api.x.com/1.1/statuses/update.json?status=Hello%20world' \
  --header 'authorization: OAuth oauth_consumer_key="CONSUMER_API_KEY", oauth_nonce="OAUTH_NONCE", oauth_signature="OAUTH_SIGNATURE", oauth_signature_method="HMAC-SHA1", oauth_timestamp="OAUTH_TIMESTAMP", oauth_token="ACCESS_TOKEN", oauth_version="1.0"' \
```

<Note>
  **참고:** 사용자 액세스 토큰은 민감한 정보이므로 각별히 주의해서 보호해야 합니다. 액세스 토큰이 생성되면, 해당 토큰이 대표하는 사용자는 애플리케이션이 토큰을 안전하게 보호할 것이라고 신뢰하는 것입니다. API 키와 사용자 액세스 토큰의 보안이 모두 침해되면, 애플리케이션을 통해 비공개 정보와 계정 기능에 대한 액세스가 노출될 수 있습니다. [키와 액세스 토큰 보안](/ko/resources/fundamentals/developer-apps)에 대해 더 자세히 알아보시기를 권장합니다.
</Note>

<div id="useful-tools">
  ### 유용한 도구
</div>

[요청에 서명하기](/ko/resources/fundamentals/authentication#creating-a-signature) 과정은 복잡합니다. 인증 토큰의 대부분을 자동으로 생성해 주는 API 클라이언트 라이브러리를 사용할 것을 권장합니다:

|     |     |
| :--- | :--- |
| [Postman](https://www.getpostman.com/) | REST API 요청을 생성하고 전송할 수 있는 API 클라이언트입니다. 이 도구에 대해 더 알아보려면 “[Postman 시작하기](/ko/tutorials/postman-getting-started)” 튜토리얼을 참고하세요. |
| [Insomnia](https://insomnia.rest/) | Insomnia는 쿠키 관리, 환경 변수, 코드 생성, 인증 기능을 제공하는 Mac, Windows, Linux용 REST API 클라이언트입니다. |
