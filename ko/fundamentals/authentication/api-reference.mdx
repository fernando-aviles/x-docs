<div id="post-oauthrequest_token">
  ### POST oauth/request_token
</div>

Consumer 애플리케이션이 사용자 인가를 요청하기 위한 OAuth Request Token을 얻을 수 있도록 합니다. 이 메서드는 [OAuth 1.0 인증 플로우](http://oauth.net/core/1.0/#anchor9)의 [섹션 6.1](https://oauth.net/core/1.0/#auth_step1)을 충족합니다.

**모든 OAuth 인가 단계에서 HTTPS 사용이 필수입니다.**

**사용 시 참고:** `oauth_nonce`에는 ASCII 값만 허용됩니다.

**리소스 URL[](#resource-url "Permalink to this headline")**

`https://api.x.com/oauth/request_token`

**리소스 정보[](#resource-information "Permalink to this headline")**

|     |     |
| :--- | :--- |
| 응답 형식 | JSON |
| 인증 필요 여부? | 아니요  |
| 레이트 리밋 적용 여부? | 예 |

**매개변수[](#parameters "Permalink to this headline")**

| 이름 | 필수 여부 | 설명 | 예시 |
| :--- | :--- | :--- | :--- |
| oauth&#95;callback | 필수 | OAuth 1.0a 규격을 준수하기 위해 이 매개변수는 **필수**입니다. 여기에서 지정하는 값은 사용자가 애플리케이션이 자신의 계정에 접근하는 것을 승인할 경우 리디렉션되는 URL로 사용됩니다. out-of-band PIN 모드의 경우 `oob`로 설정합니다. 이는 데스크톱/모바일 애플리케이션에서 사용할 커스텀 콜백을 지정하는 방법이기도 합니다. 사전에 콜백을 등록해 두었더라도, 이 단계에서는 항상 `oauth_callback`을 전송해야 합니다.<br /><br />이 엔드포인트에서 사용하는 모든 콜백 URL은 developer.x.com의 앱 설정에서 구성되어 있어야 합니다* | `http://themattharris.local/auth.php` `twitterclient://callback` |
| x&#95;auth&#95;access&#95;type | 선택 | 애플리케이션이 사용자 계정에 요청하는 접근 수준을 재정의합니다. 지원되는 값은 `read` 또는 `write`입니다. 이 매개변수는 개발자가 읽기/쓰기 애플리케이션을 등록하더라도, 필요 시 읽기 전용 접근만 요청할 수 있도록 하기 위한 것입니다. |     |

콜백 URL을 승인하는 방법에 대해 자세히 알아보려면 [이 페이지](/ko/resources/fundamentals/developer-apps#callback-urls)를 참고하세요.

**참고** - developer.x.com에서 X 계정으로 로그인한 상태라면 [X 앱 대시보드](https://developer.x.com/en/apps)를 통해 기존 [X 앱](/ko/resources/fundamentals/developer-apps)을 조회하고 수정할 수 있습니다.

**요청 예시[](#example-request "Permalink to this headline")**

요청 URL: `POST https://api.x.com/oauth/request_token`

요청 POST 본문: *해당 없음*

Authorization 헤더: `OAuth oauth_nonce="K7ny27JTpKVsTgdyLdDfmQQWVLERj2zAK5BslRsqyw", oauth_callback="http%3A%2F%2Fmyapp.com%3A3005%2Ftwitter%2Fprocess_callback", oauth_signature_method="HMAC-SHA1", oauth_timestamp="1300228849", oauth_consumer_key="OqEqJeafRSF11jBMStrZz", oauth_signature="Pc%2BMLdv028fxCErFyi8KXFM%2BddU%3D", oauth_version="1.0"`

응답: `oauth_token=Z6eEdO8MOmk394WozF5oKyuAv855l4Mlqo7hhlSLik&oauth_token_secret=Kd75W4OQfb2oJTV0vzGzeXftVAwgMnEK9MumzYcM&oauth_callback_confirmed=true`

<div id="get-oauthauthorize">
  ### GET oauth/authorize
</div>

Consumer 애플리케이션이 OAuth Request Token 을 사용해 사용자 승인을 요청할 수 있도록 합니다. 이 메서드는 [OAuth 1.0 인증 플로우](http://oauth.net/core/1.0/#anchor9)의 [섹션 6.2](http://oauth.net/core/1.0/#auth_step2)에 해당합니다. 데스크톱 애플리케이션은 반드시 이 메서드를 사용해야 하며([GET oauth / authenticate](/ko/resources/fundamentals/authentication/api-reference#get-oauth-authenticate)는 사용할 수 없습니다).

**사용 참고:** `oauth_callback` 은 이 메서드로는 절대 전송되지 않으며, 대신 [POST oauth / request&#95;token](/ko/resources/fundamentals/authentication/api-reference#post-oauth-request-token)에 제공해야 합니다.

**리소스 URL[](#resource-url "Permalink to this headline")**

`https://api.x.com/oauth/authorize`

**리소스 정보[](#resource-information "Permalink to this headline")**

|     |     |
| :--- | :--- |
| 응답 형식 | JSON |
| 인증 필요 여부 | 예 |
| 레이트 리밋 적용 여부 | 예 |

**파라미터[](#parameters "Permalink to this headline")**

|     |     |     |     |     |
| :--- | :--- | :--- | :--- | :--- |
| 이름 | 필수 여부 | 설명 | 기본값 | 예시 |
| force&#95;login | 선택 사항 | 올바른 사용자의 계정이 승인되었는지 보장하기 위해, 사용자에게 자격 증명 입력을 강제로 요구합니다. |     |     |
| screen&#95;name | 선택 사항 | OAuth 로그인 화면의 사용자 이름 입력 칸을 지정한 값으로 미리 채웁니다. |     |     |

**요청 예시[](#example-request "Permalink to this headline")**

웹 브라우저에서 `oauth/authorize` 단계로 사용자를 리다이렉트하면서 oauth&#95;token 파라미터를 포함합니다:
`https://api.x.com/oauth/authorize?oauth_token=Z6eEdO8MOmk394WozF5oKyuAv855l4Mlqo7hhlSLik`

<div id="get-oauthauthenticate">
  ### GET oauth/authenticate
</div>

Consumer 애플리케이션이 OAuth `request_token`을 사용하여 사용자 승인을 요청할 수 있게 해 줍니다.

이 메서드는 콜백 인증 플로우를 사용하는 애플리케이션을 위한 [OAuth 1.0 인증 플로우](http://oauth.net/core/1.0/#anchor9)의 [섹션 6.2](http://oauth.net/core/1.0/#auth_step2)를 대체합니다. 이 메서드는 `force_login` 매개변수가 `true`로 설정되지 않은 한 현재 로그인한 사용자를 액세스 권한 승인용 계정으로 사용합니다.

이 메서드는 사용자가 이미 애플리케이션에 권한을 부여한 경우, 사용자가 애플리케이션을 다시 승인하지 않아도 리디렉트가 발생한다는 점에서 [GET oauth / authorize](/ko/resources/fundamentals/authentication/api-reference#get-oauth-authorize)와 다릅니다. 이 동작을 사용하려면 [application record](https://developer.x.com/apps)에서 *Use Sign in with X* 설정을 활성화해야 합니다.

**Resource URL[](#resource-url "이 제목의 고유 링크")**

`https://api.x.com/oauth/authenticate`

**Resource Information[](#resource-information "이 제목의 고유 링크")**

|     |     |
| :--- | :--- |
| 응답 형식 | JSON |
| 인증 필요? | 예 |
| 요청 한도 적용? | 예 |

**Parameters[](#parameters "이 제목의 고유 링크")**

|     |     |     |     |     |
| :--- | :--- | :--- | :--- | :--- |
| 이름 | 필수 여부 | 설명 | 기본값 | 예시 |
| force&#95;login | 선택 | 올바른 사용자의 계정이 승인되도록 사용자가 자격 증명을 입력하도록 강제합니다. |     | *true* |
| screen&#95;name | 선택 | OAuth 로그인 화면의 사용자 이름 입력 상자를 지정한 값으로 미리 채웁니다. |     |     |

**Example request[](#example-request "이 제목의 고유 링크")**

웹 브라우저에서 oauth&#95;token 매개변수를 포함하여 사용자를 `oauth/authenticate` 단계로 리디렉트합니다:
`https://api.x.com/oauth/authenticate?oauth_token=Z6eEdO8MOmk394WozF5oKyuAv855l4Mlqo7hhlSLik`

<div id="post-oauthaccess_token">
  ### POST oauth/access_token
</div>

Consumer 애플리케이션이 OAuth Request Token을 OAuth Access Token으로 교환할 수 있게 합니다. 이 메서드는 [OAuth 1.0 인증 플로우](http://oauth.net/core/1.0/#anchor9)의 [섹션 6.3](http://oauth.net/core/1.0/#auth_step3)을 충족합니다.

**Resource URL[](#resource-url "이 제목의 퍼머링크")**

`https://api.x.com/oauth/access_token`

**Resource Information[](#resource-information "이 제목의 퍼머링크")**

|     |     |
| :--- | :--- |
| Response formats | JSON |
| Requires authentication? | Yes |
| Rate limited? | Yes |

**Parameters[](#parameters "이 제목의 퍼머링크")**

|     |     |     |     |     |
| :--- | :--- | :--- | :--- | :--- |
| Name | Required | Description | Default Value | Example |
| oauth&#95;token | 필수 | 여기의 oauth&#95;token은 request&#95;token 단계에서 반환된 oauth&#95;token과 동일해야 합니다. |     |     |
| oauth&#95;verifier | 필수 | OAuth 웹 플로우를 사용하는 경우, 이 매개변수를 콜백 URL에서 반환된 *oauth&#95;verifier* 값으로 설정합니다. out-of-band OAuth를 사용하는 경우, 이 값을 PIN 코드로 설정합니다. OAuth 1.0a 사양을 준수하려면 이 매개변수는 **필수**입니다. OAuth 1.0a는 엄격하게 적용되며, *oauth&#95;verifier* 를 사용하지 않는 애플리케이션은 OAuth 플로우를 완료하지 못합니다. |     |     |

**Example request[](#example-request "이 제목의 퍼머링크")**

`POST https://api.x.com/oauth/access_token?oauth_token=qLBVyoAAAAAAx72QAAATZxQWU6P&oauth_verifier=ghLM8lYmAxDbaqL912RZSRjCCEXKDIzx`

PIN 기반의 경우: `POST https://api.x.com/oauth/access_token?oauth_token=9Npq8AAAAAAAx72QBRABZ4DAfY9&oauth_verifier=4868795`

**Example response[](#example-response "이 제목의 퍼머링크")**

`oauth_token=6253282-eWudHldSbIaelX7swmsiHImEL4KinwaGloHANdrY&oauth_token_secret=2EEfA6BG5ly3sR3XjE0IBSnlQu4ZrUzPiYTmrkVU&user_id=6253282&screen_name=xapi`

<div id="post-oauthinvalidate_token">
  ### POST oauth/invalidate_token
</div>

등록된 애플리케이션은 클라이언트 자격 증명을 제시하여 발급된 OAuth access&#95;token을 무효화할 수 있습니다. access&#95;token이 무효화되면, 새 액세스 토큰을 생성할 때는 다른 액세스 토큰이 발급되며, 무효화된 토큰은 더 이상 사용할 수 없습니다.

**리소스 URL[](#resource-url "이 제목에 대한 고정 링크")**

`https://api.x.com/1.1/oauth/invalidate_token`

**리소스 정보[](#resource-information "이 제목에 대한 고정 링크")**

|           |                                 |
| :-------- | :------------------------------ |
| 응답 형식     | JSON                            |
| 인증 필요?    | 예 - 무효화하려는 액세스 토큰이 포함된 사용자 컨텍스트 |
| 요청 한도 적용? | 예                               |

**요청 예시[](#example-request "이 제목에 대한 고정 링크")**

```bash
        curl --request POST
          --url 'https://api.x.com/1.1/oauth/invalidate_token.json'
          --header 'authorization: OAuth oauth_consumer_key="CLIENT_KEY",
         oauth_nonce="AUTO_GENERATED_NONCE", oauth_signature="AUTO_GENERATED_SIGNATURE",
         oauth_signature_method="HMAC-SHA1", oauth_timestamp="AUTO_GENERATED_TIMESTAMP",
         oauth_token="ACCESS_TOKEN", oauth_version="1.0"'
```

**예시 응답[](#example-response "이 제목에 대한 고유 링크")**

```bash
        HTTP/1.1 200 OK
        Content-Type: application/json; charset=utf-8
        Content-Length: 127
        ...

        {"access_token":"ACCESS_TOKEN"}
```

**토큰이 무효화된 후 발생하는 오류 응답 예시[](#example-error-response-after-token-has-been-invalidated "이 제목에 대한 고유 링크")**

```bash
        HTTP/1.1 401 Authorization Required
        ...

        {"errors": [{
          "code": 89,
          "message": "Invalid or expired token."}
        ]}
```

<div id="post-oauth2token">
  ### POST oauth2/token
</div>

등록된 애플리케이션이 OAuth 2 Bearer Token을 발급받을 수 있도록 합니다. 이 토큰은 사용자 컨텍스트 없이 애플리케이션 자체를 대신해 API 요청을 수행하는 데 사용할 수 있습니다. 이를 [Application-only authentication](/ko/resources/fundamentals/authentication/oauth-2-0/application-only)이라고 합니다.

Bearer Token은 oauth2/invalidate&#95;token을 사용해 무효화할 수 있습니다. Bearer Token이 한 번 무효화되면, 새로 생성하려는 시도에서는 다른 Bearer Token이 발급되며 이전 토큰은 더 이상 사용할 수 없습니다.

하나의 애플리케이션에 대해 동시에 존재할 수 있는 Bearer Token은 하나뿐이며, 이 메서드에 반복적으로 요청하면 무효화되기 전까지는 이미 존재하는 동일한 토큰이 반환됩니다.

성공 응답에는 부여된 Bearer Token을 설명하는 JSON 구조가 포함됩니다.

이 메서드를 통해 받은 토큰은 캐시해야 합니다. 너무 자주 시도하면, 요청은 코드 99와 함께 HTTP 403으로 거부됩니다.

**리소스 URL[](#resource-url "Permalink to this headline")**

`https://api.x.com/oauth2/token`

**리소스 정보[](#resource-information "Permalink to this headline")**

|                  |                                                               |
| :--------------- | :------------------------------------------------------------ |
| 응답 형식            | JSON                                                          |
| 인증 필요 여부         | 예 - API key를 사용자 이름으로, API key secret을 비밀번호로 사용하는 Basic 인증 필요 |
| Rate limit 적용 여부 | 예                                                             |

**파라미터[](#parameters "Permalink to this headline")**

|                |          |                                                                                                                                                                                          |               |                          |
| :------------- | :------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :------------ | :----------------------- |
| Name           | Required | Description                                                                                                                                                                              | Default Value | Example                  |
| grant&#95;type | required | 애플리케이션에서 요청하는 grant 유형을 지정합니다. 현재는 *client&#95;credentials*만 허용됩니다. 자세한 내용은 [Application-Only Authentication](/ko/resources/fundamentals/authentication/oauth-2-0/application-only)을 참조하세요. |               | *client&#95;credentials* |

**요청 예시[](#example-request "Permalink to this headline")**

```bash
    POST /oauth2/token HTTP/1.1
    Host: api.x.com
    User-Agent: My X App v1.0.23
    Authorization: Basic eHZ6MWV2R ... o4OERSZHlPZw==
    Content-Type: application/x-www-form-urlencoded;charset=UTF-8
    Content-Length: 29
    Accept-Encoding: gzip

    grant_type=client_credentials
```

**예시 응답:**

```bash
    HTTP/1.1 200 OK
    Status: 200 OK
    Content-Type: application/json; charset=utf-8
    ...
    Content-Encoding: gzip
    Content-Length: 140

    {"token_type":"bearer","access_token":"AAAA%2FAAA%3DAAAAAAAA"}
```

<div id="post-oauth2invalidate_token">
  ### POST oauth2/invalidate_token
</div>

등록된 애플리케이션이 클라이언트 자격 증명을 제시하여 발급된 OAuth 2.0 Bearer Token을 무효화(revoke)할 수 있도록 합니다. Bearer Token이 무효화되면 새로 발급을 시도할 때는 다른 Bearer Token이 생성되며, 무효화된 토큰은 더 이상 사용할 수 없습니다.

성공 응답에는 무효화된 Bearer Token을 설명하는 JSON 구조가 포함됩니다.

**Resource URL[](#resource-url "Permalink to this headline")**

`https://api.x.com/oauth2/invalidate_token`

**Resource Information[](#resource-information "Permalink to this headline")**

|                          |                                                                                                                                                    |
| :----------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------- |
| Response formats         | JSON                                                                                                                                               |
| Requires authentication? | Yes - 애플리케이션의 consumer API 키와 애플리케이션 소유자의 access token 및 access token secret을 사용하는 [OAuth 1.0a](/ko/resources/fundamentals/authentication/oauth-1-0a) |
| Rate limited?            | Yes                                                                                                                                                |

**Parameters[](#parameters "Permalink to this headline")**

| Name             | Required | Description           |
| :--------------- | :------- | :-------------------- |
| access&#95;token | required | 무효화하려는 Bearer Token 값 |

**Example request[](#example-request "Permalink to this headline")**

```
        curl --request POST
          --url 'https://api.x.com/oauth2/invalidate_token?access_token=AAAA%2FAAA%3DAAAAAAAA'
          --header 'authorization: OAuth oauth_consumer_key="CLIENT_KEY",
         oauth_nonce="AUTO_GENERATED_NONCE", oauth_signature="AUTO_GENERATED_SIGNATURE",
         oauth_signature_method="HMAC-SHA1", oauth_timestamp="AUTO_GENERATED_TIMESTAMP",
         oauth_token="ACCESS_TOKEN", oauth_version="1.0"'
```

**응답 예시[](#example-response "이 제목의 퍼머링크")**

```
         Status: 200 OK
         Content-Type: application/json; charset=utf-8
         Content-Length: 135
         ...
       {
        "access_token": "AAAA%2FAAA%3DAAAAAAAA"
        }
```
