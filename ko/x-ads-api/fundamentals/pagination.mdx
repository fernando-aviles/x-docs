---
title: 페이지네이션
keywords: ["Ads API pagination", "pagination", "cursor pagination", "page through results", "Ads API pagination tokens"]
---

계정과 연결된 캠페인의 최대 허용 수를 늘리고 계정과 연관된 모든 엔터티를 효율적으로 검색할 수 있도록, Advertiser API는 이제 다수의 GET 엔드포인트에서 페이지네이션을 지원합니다. 이 페이징 메커니즘은 사용하기 쉽고, [컬렉션 탐색을 위한 커서 사용](https://developer.x.com/en/docs/x-api/v1/pagination)에 설명된 REST API의 커서 기반 페이지네이션 방식과 매우 유사합니다.

<div id="getting-started">
  ## 시작하기
</div>

특정 GET 요청에서는 이제 선택적인 `cursor` 및 `count` 쿼리 매개변수를 사용할 수 있습니다. 응답에 포함된 엔티티 수가 `count`보다 많으면, 이러한 엔드포인트는 처음 `count`개의 엔티티를 반환하고 응답 JSON에 `next_cursor` 키를 함께 포함합니다.

`GET https://ads-api.x.com/5/accounts/abc1/campaigns?count=50`

```json
{
  "data": \[...\],
  "next_cursor": "c-3yvu1pzhd3i7",
  "request": {...}
}
```

다음 일련의 응답을 가져오려면 쿼리 매개변수에 `cursor`를 추가하면 됩니다:

`GET https://ads-api.x.com/5/accounts/abc1/campaigns?cursor=c-3yvu1pzhd3i7&count=50`

```json
{
  "data": \[...\],
  "next_cursor": "c-3w3zdyg8ywan",
  "request": {...}
}
```


<div id="going-deeper">
  ## 더 자세히 살펴보기
</div>

대부분의 엔드포인트에서 `count` 값의 최대치는 **1,000**, 최소치는 **1**, 기본값은 **200**입니다.

`next_cursor`에 의해 제공되는 값은 항상 문자열이며, 내부 구조를 해석하지 않는 불투명한 값으로 간주해야 합니다. 해당 구현은 변경될 수 있습니다. 현재 결과 집합의 페이지에서 반환된 엔티티 수가 `count` 값보다 적으면 `next_cursor` 값은 `null`이 됩니다.

**참고:** analytics 엔드포인트는 이 방식의 페이지네이션을 지원하지 않습니다. stats 엔드포인트의 페이징은 시간 구간을 지정하는 방식으로 지원됩니다. 자세한 내용은 각 개별 엔드포인트의 문서를 참조하세요.
