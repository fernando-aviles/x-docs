<div id="overview">
  ## 개요
</div>

매달 우리는 X Ads API에 변경 사항을 적용하고 여러 가지 신규 기능을 출시합니다. 이러한 변경 사항은 거의 항상 하위 호환성을 유지하지만, 매년 소수의 호환성이 깨지는 변경 사항이 발생하곤 합니다. Ads API의 빠른 변경 주기가 새로운 기능 구현, 사용 중단 처리, 변경 사항 테스트 등 개발 주기에 미치는 영향과 관련해 개발자들로부터 많은 피드백을 받았습니다. 우리는 Ads 플랫폼을 사용하는 개발자 경험을 개선하고자 하며, 그 일환으로 엔드포인트에 버전 관리 개념을 도입했습니다.

아래는 이 문서에서 다루는 몇 가지 개념에 대한 정의입니다.

**Version**: 모든 Ads API 요청의 URL 경로에 포함된 버전 번호를 의미합니다. 예: GET /{version_number}/accounts. 이러한 방식의 버전 관리는 URI 버전 관리라고 합니다.

**Breaking Changes**: 호환성이 깨지는 변경 사항은 기존 기능을 유지하기 위해 개발자 리소스가 필요한 모든 변경을 의미합니다. 여기에는 어떤 변경을 해야 하는지 조사하는 리소스, 사용 중단되는 기능/엔드포인트를 파악하는 작업, 그리고 이러한 모든 변경 사항을 최종적으로 구현하는 데 필요한 리소스가 포함됩니다. 호환성이 깨지는 변경 사항의 예시는 다음과 같습니다.

* API 요청/응답에서 매개변수를 제거하는 경우
* 매개변수나 엔드포인트의 이름을 수정하는 경우
* 값의 표현 방식 변경 (preview&#95;url → card&#95;uri)
* 엔드포인트 동작 방식 변경 (예: 비동기 vs 동기 통계)
* 선택적 또는 필수 매개변수 추가/변경 (예: 요청에서 이름 필드를 필수로 만드는 경우)

**Deprecation**: 사용 중단(Deprecated)된 버전이나 제품은 더 이상 지원되지 않으며, 개발자는 해당 API 사용을 중단하는 것이 권장됩니다.

**Sunset**: 제품이나 API가 Sunset되면, 해당 엔드포인트 세트는 더 이상 API를 통해 접근할 수 없게 됩니다.

<div id="versioning-strategy">
  ## 버전 관리 전략
</div>

이 전략의 주요 원칙은 다음과 같습니다:

1. 모든 호환성 파괴 변경 사항은 새 버전에 묶어서 제공됩니다.

2. 새 버전이 발표될 때마다 기존 버전에 대한 사용 중단 예고 기간은 6개월입니다.

3. 언제든지 API는 동시에 두 개의 버전에서 들어오는 요청을 허용하지만, 이 중 더 오래된 버전은 지원되지 않습니다.

4. 신규 제품의 더 빠른 도입을 위해, 이러한 제품들은 버전 주기와는 별개로 수시로 출시됩니다.

5. 모든 API 응답에는 현재 API 버전으로 설정되는 `x-current-api-version` 헤더가 포함되며, 사용 중단된 API 엔드포인트를 호출할 경우 `x-api-warn` 헤더도 함께 포함됩니다.

API에 호환성 파괴 변경(예: 여러 연령대 타기팅 옵션 사용 중단)이 필요할 정도의 근본적인 제품 요구 사항 변경이 있을 경우, 이 호환성 파괴 변경을 알리기 위해 90일 사전 예고를 발송하며, 공지 발송 후 최소 90일이 지난 뒤에 해당 호환성 파괴 변경을 배포합니다.

<div id="v9">
  ### v9
</div>

2021년 3월 3일부로 X Ads API 버전 9(v9)이 제공됩니다. 이번 릴리스는 기능 동등성을 높이고 캠페인 생성을 단순화하며, Cards 및 Mobile App Promotion 엔드포인트에 대한 핵심 업데이트를 도입하기 위해 설계되었습니다.

이전 버전과 마찬가지로 v9로 마이그레이션하기 위한 6개월 전환 기간이 제공됩니다. 2021년 8월 31일 이후에는 기존 Ads API 버전 8(v8)을 더 이상 사용할 수 없습니다. 서비스 중단을 방지하기 위해 가능한 한 빨리 Ads API의 최신 버전으로 마이그레이션할 것을 권장합니다.

<Note>
  **참고:** 이번 릴리스 시점을 기준으로 Ads API 버전 7(v7)은 수명 종료(EOL)에 도달하여 더 이상 제공되지 않습니다.
</Note>

자세한 내용은 [developer forum의 공지](https://devcommunity.x.com/t/ads-api-version-9/150316)를 참고하세요.

<div id="v8">
  ### v8
</div>

오늘, 2020년 9월 20일, 우리는 새로운 Tailored Audiences 기능을 도입하고, ads.x.com과 기능을 맞추며, 개발자 경험을 개선하기 위해 설계된 X Ads API 버전 8을 소개합니다.

이전 버전과 마찬가지로 v8로 마이그레이션할 수 있도록 6개월의 전환 기간이 제공됩니다. 2021-03-02부터는 Ads API 버전 7을 더 이상 사용할 수 없습니다. 서비스 중단을 방지하기 위해 모든 개발자분들께 가능한 한 빨리 최신 버전의 API로 마이그레이션하실 것을 권장합니다.

자세한 내용은 [개발자 포럼의 공지](https://devcommunity.x.com/t/ads-api-version-8/141914)를 참조하세요.

<div id="v7">
  ### v7
</div>

2020년 3월 20일 오늘, X는 [ads.x.com](http://ads.x.com/)과의 기능을 최대한 일치시키도록 설계된 X Ads API 버전 7을 소개합니다.

이전 [버전들](https://developer.x.com/en/docs/ads/general/overview/versions)과 마찬가지로 v7로 마이그레이션하기 위한 6개월 전환 기간이 제공됩니다. 2020-09-01부터는 Ads API 버전 6이 더 이상 제공되지 않습니다. 서비스 중단을 방지하기 위해 모든 개발자 여러분께 가능한 한 빨리 최신 버전의 API로 마이그레이션할 것을 권장합니다. Ads API 버전 5는 수명 종료(end of life)에 도달하여 더 이상 제공되지 않습니다.

자세한 내용은 [개발자 포럼의 공지](https://devcommunity.x.com/t/ads-api-version-7/135093)를 참조하세요.

<div id="v6">
  ### v6
</div>

2019년 8월 28일, X는 일관성을 높이고 개발자 경험을 개선하는 데 초점을 맞춘 Ads API v6를 도입합니다.

이번 릴리스에는 트윗을 조회하기 위한 새로운 엔드포인트, 프로모션 계정용 통계, 엔터티를 이름으로 검색하는 기능, 그리고 현재 처리 중인 비동기 애널리틱스 작업 건수에 대한 정보가 포함되어 있습니다. 추가로, 미디어를 사용하는 엔드포인트와 타깃팅 기준 엔드포인트에 일관성을 높이기 위한 업데이트를 적용했습니다. 마지막으로, 일부 매개변수 이름과 응답 속성을 소폭 수정하고 Scoped Timeline 엔드포인트를 사용 중단(deprecate)할 예정입니다.

자세한 내용은 [개발자 포럼의 공지](https://devcommunity.x.com/t/ads-api-version-6/129060)를 참조하세요.

<div id="v5">
  ### v5
</div>

오늘인 2019년 2월 28일, X는 규모 확장과 효율성 제고에 초점을 맞춘 업데이트가 포함된 Ads API v5를 소개합니다.

이번 릴리스에는 지정된 기간 동안 어떤 엔티티가 활성 상태였는지 확인할 수 있는 새로운 엔드포인트, Media Creatives(예: X Audience Platform의 인스트림 동영상 및 이미지)에 대한 통계, 카드 URI로 *여러* 카드를 가져오는 기능, 그리고 타기팅 기준 및 기타 엔티티를 조회하는 방식에 대한 더 큰 유연성이 포함되어 있습니다. 또한 일부 버그를 수정했으며 파라미터 이름과 응답 속성을 업데이트했습니다. 마지막으로 non‑media app 카드와 POST `accounts/:account_id/account_media` 엔드포인트는 사용이 중단(deprecated)되었습니다.

이전 버전과 마찬가지로 v5로 마이그레이션하기 위한 6개월의 전환 기간이 제공됩니다. **2019-08-28** 이후에는 Ads API 버전 4를 더 이상 사용할 수 없습니다. 모든 파트너가 서비스 중단을 피할 수 있도록 가능한 한 빨리 최신 버전의 API로 마이그레이션할 것을 권장합니다. *Ads API 버전 3은 수명 종료(end of life)에 도달하여 더 이상 사용할 수 없습니다.*

<div id="new">
  #### 신규
</div>

**활성 상태였던 엔티티 판별**

[Active Entities](/ko/x-ads-api/analytics#active-entities-2) 엔드포인트는 광고 엔티티에 대한 애널리틱스 지표에 변경 사항이 있었는지를 나타냅니다. 애널리틱스 엔드포인트와 함께 사용되도록 설계된 Active Entities는 엔티티 유형과 날짜 범위(최대 90일)를 지정하면, 귀사의 플랫폼이 애널리틱스를 요청해야 하는 엔티티 id 배열을 반환합니다. 반환된 id 이외의 항목은 이후 애널리틱스 요청에서 조회하지 않아야 합니다.

이 엔드포인트는 다음 엔티티 유형을 지원합니다: `CAMPAIGN`, `FUNDING_INSTRUMENT`, `LINE_ITEM`, `MEDIA_CREATIVE`, `PROMOTED_TWEET`.

**`MEDIA_CREATIVE` 통계**

Ads API의 애널리틱스 엔드포인트가 이제 Media Creative 엔티티에 대한 지표도 제공합니다. Media Creative는 X Audience Platform에서 인스트림 광고 또는 이미지를 프로모션하는 데 사용되는 방식입니다. X Ads UI에서는 “In-stream videos” 및 “Display creatives” 탭에서 Media Creative 지표를 표시합니다. [동기식](/ko/x-ads-api/analytics#get-stats-accounts-account-id) 및 [비동기식](/ko/x-ads-api/analytics#asynchronous-analytics) 애널리틱스 엔드포인트 모두 이제 `MEDIA_CREATIVE` 엔티티 enum을 지원합니다.

**여러 카드 가져오기**

카드 URI 값으로 단일 카드를 조회하도록 설계된 엔드포인트의 [v3 릴리스](https://devcommunity.x.com/t/ads-api-version-3/100732)를 개선하여, 이제 [GET accounts/:account&#95;id/cards/all](/ko/x-ads-api/creatives#cards-fetch) 엔드포인트를 사용해 *여러* 카드를 가져올 수 있습니다. 이제 각 카드마다 요청을 보내는 대신 한 번의 요청으로 최대 200개의 카드를 조회할 수 있습니다.

다음 두 가지 사항을 유의하세요.

1. URL 경로가 이제 `accounts/:account_id/cards/all`입니다. (이전 경로는 더 이상 사용할 수 없습니다.) 이는 id로 카드를 조회하도록 설계된 [엔드포인트](/ko/x-ads-api/creatives#cards-fetch)와 일관성을 유지하기 위한 것입니다.
2. 필수 요청 매개변수 이름이 이제 card&#95;uris(복수형)입니다.

**조회 유연성 향상**

[GET accounts/:account&#95;id/targeting&#95;criteria](/ko/x-ads-api/campaign-management#get-accounts-account-id-targeting-criteria) 엔드포인트가 이제 여러 개의 라인 아이템 id를 지원합니다. 최대 200개의 id를 받을 수 있는 line&#95;item&#95;ids 매개변수가 필수입니다. 이전에는 단일 라인 아이템만 허용되어 동기화가 어려웠습니다. 이 변경으로 더 많은 타겟팅 정보를 더 짧은 시간 안에 조회할 수 있게 되었습니다.

다음 엔드포인트들 또한 이제 여러 개의 라인 아이템 id를 지원하지만, 이들에 대해서는 line&#95;item&#95;ids 매개변수가 선택 사항입니다.

* [GET accounts/:account&#95;id/line&#95;item&#95;apps](https://developer.x.com/en/docs/x-ads-api/campaign-management/api-reference/line-item-apps#get-accounts-account-id-line-item-apps)
* [GET accounts/:account&#95;id/media&#95;creatives](/ko/x-ads-api/campaign-management#get-accounts-account-id-media-creatives)
* [GET accounts/:account&#95;id/promoted&#95;accounts](/ko/x-ads-api/campaign-management#get-accounts-account-id-promoted-accounts)
* [GET accounts/:account&#95;id/preroll&#95;call&#95;to&#95;actions](/ko/x-ads-api/creatives#preroll-call-to-actions)

<div id="changed">
  #### 변경 사항
</div>

**드래프트 캠페인 및 라인 아이템 가져오기**

드래프트 캠페인과 라인 아이템을 가져오는 방식이 업데이트되었습니다. 이제 with&#95;draft(boolean) 매개변수를 true로 설정하면 드래프트 및 비드래프트 엔티티가 *모두* 반환됩니다. 이는 삭제된 엔티티를 가져오는 방식(예: with&#95;deleted 사용)과 일관됩니다. 이전에는 드래프트와 비드래프트 엔티티를 모두 가져오려면 최소 두 번의 요청이 필요했습니다. 이제 단일 API 호출로 이를 수행할 수 있습니다.

| **v4** | **v5** |
| :--- | :--- | :--- |
| `draft_only` | `with_draft` |     |

**Network Activation Duration 타게팅**

Ads API는 Network Activation Duration 타게팅을 추가한 뒤, 응답의 타게팅 유형에 &#95;IN&#95;SEC 접미사가 포함되던 표시 문제를 해결했습니다. Network Activation Duration은 항상 개월 수로 표현되므로, 초(second)를 참조하는 것은 혼란을 야기했습니다. 이 수정으로 표현 방식이 일관성을 갖게 되었으며 혼란이 줄어들었습니다.

| **v4** | **v5** |
| :--- | :--- | :--- |
| `NETWORK_ACTIVATION_DURATION_IN_SEC` | `NETWORK_ACTIVATION_DURATION` |     |

**총 개수 및 커서**

v5에서는 with&#95;total&#95;count와 cursor가 상호 배타적입니다. 요청에서 둘 다 지정하면 EXCLUSIVE&#95;PARAMETERS 오류 코드가 반환됩니다. v5 이전에는 cursor가 지정된 경우 with&#95;total&#95;count는 무시되었습니다. 이 변경으로 둘 사이의 관계가 명시적으로 정의됩니다.

<div id="removed">
  #### 제거된 항목
</div>

다음 세 개의 필드가 Ads API 응답에서 제거됩니다: preview&#95;url, account&#95;id, parent&#95;ids. 이 세 항목에 대한 개발 작업량은 최소 수준입니다.

* v4에서 카드에 대한 preview&#95;url 응답 매개변수가 항상 null임이 이미 공지되었습니다. 이번 마이그레이션의 마지막 단계는 모든 카드 응답에서 preview&#95;url을 제거하는 것입니다.
* 광고 계정 ID는 이미 URL과 request.params에 포함되어 있으므로, 다음 리소스에 대해서는 account&#95;id 응답 속성이 제거됩니다. (자금 조달 수단(funding instruments)이 이 목록에서 의도적으로 제외된 이유는, 가능한 경우 상위 ID가 응답 객체에 포함되어야 하며, 계정 ID는 자금 조달 수단의 상위 엔터티이기 때문입니다.)
  * 계정 미디어
  * 앱 이벤트 제공자
  * 앱 이벤트 태그
  * 캠페인
  * 카드
  * 라인 아이템
  * 프로모션 대상 사용자
  * 타기팅 기준
* [GET accounts/:account&#95;id/targeting&#95;criteria](/ko/x-ads-api/campaign-management#get-accounts-account-id-targeting-criteria) 요청의 경우, parent&#95;ids 필드는 항상 빈 배열이었기 때문에 더 이상 반환되지 않습니다.

**비미디어 앱 카드**

v5에서는 비미디어 앱 카드를 더 이상 지원하지 않습니다. [이전에](https://devcommunity.x.com/t/deprecation-announcement-app-download-cards/87807) 비미디어 앱 카드를 생성하거나 편집하는 기능이 제거되었습니다. 이제 이 리소스에 대한 남은 엔드포인트가 사용 중단(deprecated)됩니다.

* 참고: 이는 이미지 및 동영상 앱 다운로드 카드에는 **영향을 주지 않습니다**.

**계정 미디어 생성**

POST accounts/:account&#95;id/account&#95;media 엔드포인트는 v5에서 더 이상 사용할 수 없습니다. 이 리소스에 대한 다른 엔드포인트는 영향을 받지 *않습니다*. 이 변경의 이유는 [Media Library](/ko/x-ads-api/creatives#media-library)에 미디어를 추가할 때, 해당 애셋이 *자동으로* Account Media 엔터티로 추가되는 경우가 있으며, 이미 존재하는 애셋을 Account Media 리소스에 다시 추가하려고 하면 오류가 발생하기 때문입니다. 이는 다음과 같은 경우에 발생합니다.

* Media Library에 추가된 `AMPLIFY_VIDEO` 애셋은 `PREROLL` 크리에이티브 유형을 가진 Account Media 애셋으로 자동 추가됩니다.
* 특정 크기의 이미지를 Media Library에 추가하면 해당 이미지는 자동으로 Account Media 애셋으로 추가됩니다. 크리에이티브 유형(예: `INTERSTITIAL`)은 이미지 크기에 따라 달라집니다. (크기 정보는 [Enumerations](/ko/x-ads-api/introduction) 페이지를 참고하세요.)

<div id="v4">
  ### v4
</div>

Ads API 버전 4가 오늘(2018년 8월 28일) 출시되었습니다.

이번 릴리스에는 더 강력해진 오디언스 처리 백엔드를 기반으로 한 새로운 API 인터페이스를 포함한 [Audiences](/ko/x-ads-api/audiences) 제품 개선 사항이 포함되어 있습니다. 버전 4에는 사용자, 계정 및 세금 설정을 관리하기 위한 일련의 엔드포인트도 포함됩니다. 추가로, accounts/:account&#95;id/videos 엔드포인트는 사용 중단(deprecated)됩니다. 또한 이번 릴리스에는 일부 파라미터 및 응답 이름 변경 사항도 포함되어 있습니다.

버전 3과 마찬가지로 6개월 전환 기간을 제공합니다. **2019-02-28** 이후에는 Ads API 버전 3을 더 이상 사용할 수 없습니다. 모든 파트너가 서비스 중단을 피하기 위해 가능한 한 빨리 최신 버전의 API로 마이그레이션할 것을 권장합니다. 버전 관리 전략에 대한 자세한 내용은 [Versions](/ko/x-ads-api/introduction) 페이지를 참조하세요.

  #### 신규
</div>

***Audience API***

새로운 Audiences API는 향상된 견고성과 안정성을 제공하는 새로운 오디언스 처리 백엔드 위에 구축되었습니다. 이 신규 엔드포인트를 사용하면 파트너가 단일 사용자에 대해 여러 사용자 식별자 유형을 제공할 수 있으며, 이를 통해 매칭에 추가적인 신호를 활용할 수 있습니다. 새로운 Audience 엔드포인트에 대한 참고 문서는 [여기](/ko/x-ads-api/audiences)에서 확인할 수 있습니다. 올해 남은 기간 동안 이 제품에 대한 업데이트와 개선 사항을 계속해서 제공할 계획입니다.

다음 엔드포인트는 기능이 중복되기 때문에 v4에서는 더 이상 제공되지 않습니다(여전히 v3에서는 동작하며, v3가 더 이상 제공되지 않을 때 완전히 사용 중단됩니다).

* TON Upload:
  * GET accounts/:account&#95;id/tailored&#95;audience&#95;changes
  * GET accounts/:account&#95;id/tailored&#95;audience&#95;changes/:tailored&#95;audience&#95;change&#95;id
  * POST accounts/:account&#95;id/tailored&#95;audience&#95;changes
  * PUT accounts/:accounti&#95;d/tailored&#95;audiences/global&#95;opt&#95;out
* Real Time Audiences:
  * POST tailored&#95;audience&#95;memberships

마지막으로, 버전 4에서는 *모든* [Tailored Audiences 엔드포인트](/ko/x-ads-api/audiences)의 요청 및 응답에서 `list_type` 매개변수가 제거됩니다.

***Settings Endpoints***

이제 계정 관리자는 사용자, 계정 및 세금 설정을 설정하고 업데이트할 수 있습니다. [User settings](/ko/x-ads-api/campaign-management#get-accounts-account-id-user-settings-user-id)는 특정 광고 계정에 대한 사용자별 연락 선호 설정에 해당합니다. [PUT accounts/:account&#95;id](/ko/x-ads-api/campaign-management#put-accounts-account-id) 엔드포인트를 사용하면 광고주는 계정 이름과 업종 유형을 업데이트할 수 있습니다. 마지막으로, [tax settings](/ko/x-ads-api/campaign-management#get-accounts-account-id-tax-settings) 엔드포인트를 사용하면 부가가치세(VAT)가 부과되는 국가의 광고주가 회사 이름, 주소, VAT ID, 계정이 광고주 소유인지, 아니면 광고주를 대신해 광고하는 에이전시 소유인지를 비롯한 정보를 업데이트할 수 있습니다.

**`preview_url`은 항상 null**

v3 공지에서 약속한 대로, 이제 모든 기존 카드에는 `card_uri`가 있습니다. 그 결과, `preview_url` 값은 항상 `null`입니다.

다시 한 번 말씀드리면, 카드의 `card_uri` 값을 사용하여 카드를 포스트와 연결하십시오. 아래 예시 요청을 참조하세요.

$ twurl -X POST -H ads-api.x.com &quot;/4/accounts/18ce54d4x5t/tweet?text=Version 4&amp;card&#95;uri=card://958225772740714496&quot;

#### 제거됨

**비디오 엔드포인트**

accounts/:account&#95;id/videos 엔드포인트는 v4에서 더 이상 제공되지 않습니다. 이 엔드포인트는 [Media Library](/ko/x-ads-api/creatives#get-accounts-account-id-media-library) 엔드포인트의 도입으로 더 이상 사용되지 않습니다. 아래의 사용 예 비교를 참고하세요.

* v3 videos 엔드포인트: `twurl -H ads-api.x.com "/3/accounts/18ce54d4x5t/videos"`

* v4 동영상용 media library 엔드포인트: `twurl -H ads-api.x.com "/4/accounts/18ce54d4x5t/media_library?media_type=VIDEO"`

Media Library 엔드포인트는 videos 엔드포인트와 기능 면에서 완전히 호환되며, 이미지 및 GIF 처리 기능과 같은 추가 기능도 지원합니다. 파트너는 모든 미디어 관리 작업에 Media Library만을 사용해 주시기 바랍니다.

**Tweet View의 `as_user_id`**

[GET accounts/:account&#95;id/tweet/preview/:tweet&#95;id](/ko/x-ads-api/creatives#get-accounts-account-id-tweets) 엔드포인트에서 사용 가능하던 `as_user_id` 파라미터는 더 이상 허용되지 않습니다. 미리보기는 항상 트윗 작성자로서 렌더링됩니다.

<div id="v3">
  ### v3
</div>

Ads API 버전 3은 2018년 2월 1일에 [출시되었습니다](https://devcommunity.x.com/t/ads-api-version-3/100732). Ads API 버전 2는 2018년 8월 1일에 사용 종료(EOL)에 도달합니다.

이번 릴리스에는 새로운 Audience Intelligence 제품, Media Library에 대한 액세스, 그리고 개선된 카드 워크플로우가 포함됩니다. 또한 [PUT accounts/:account&#95;id/targeting&#95;criteria](/ko/x-ads-api/campaign-management#get-accounts-account-id-targeting-criteria) 엔드포인트의 사용 중단도 발표합니다. 마지막으로, 버전 3에는 일부 파라미터와 응답의 소규모 변경 사항과 더 낮아진 배치 크기 제한이 포함되어 있습니다.

[버전 2](https://devcommunity.x.com/t/ads-api-version-2/90360)와 마찬가지로, 파트너에게 전환을 위한 **6개월**을 제공합니다. **2018-08-01**에 Ads API v2는 종료됩니다. 모든 파트너와 개발자들이 가능한 한 빨리 v3로 마이그레이션할 것을 권장합니다.

**Audience Intelligence**

Audience Intelligence는 특정 X 오디언스와 가장 관련성이 높은 상위 해시태그, @핸들, 이벤트에 대한 실시간 인사이트를 제공합니다. 예를 들어, 미국의 남성 18–34세를 입력하면 이 오디언스 사이에서 #nintendoswitch, #cardinal, @ricegum과 같은 항목이 트렌드임을 확인할 수 있습니다.

Audience Intelligence [엔드포인트](/ko/x-ads-api/audiences)는 다음 기능을 제공합니다.

* 입력 오디언스를 기준으로 상위 관련 해시태그, @핸들 및 이벤트를 조회
* 입력 오디언스를 기준으로 핵심 인구통계 정보(예: 나이, 성별, 가구 소득)를 조회
* 키워드를 기준으로 트윗 볼륨 시계열 데이터를 조회

**Media Library**

[Media Library](/ko/x-ads-api/creatives#get-accounts-account-id-media-library)는 광고 계정용 이미지, GIF, 동영상을 관리할 수 있는 기능을 제공합니다. 이러한 미디어 객체는 트윗 및 카드 생성에 사용할 수 있습니다. 또한 여러 크리에이티브에서 재사용할 수 있으므로 동일한 에셋을 여러 번 업로드할 필요가 없습니다.

라이브러리 내 객체는 media&#95;key로 식별됩니다. Media key는 예를 들어 13&#95;875943225764098048과 같은 형식의 문자열 값입니다. Ads API에서는 모든 미디어에 대해 media key 사용으로 전환해 나가고 있습니다.

**개선된 카드 워크플로우**

모든 카드 엔드포인트가 이제 media key를 지원합니다. 이를 통해 Media Library의 객체를 사용해 카드를 생성하거나 업데이트할 수 있습니다.

또한 [카드 세부 정보 조회](/ko/x-ads-api/creatives#fetching-cards)를 위한 두 개의 새로운 엔드포인트를 도입하고 있습니다. 이 엔드포인트는 트윗 또는 예약 트윗에서 사용된 카드를 조회하는 데 사용할 수 있으며, 예를 들어 card&#95;uri 또는 id를 지정하여 조회할 수 있습니다. 이전에는 이것이 불가능했습니다.

<div id="other-changes">
  #### 기타 변경 사항
</div>

이러한 신규 기능 외에도 버전 3에는 다음과 같은 변경 사항이 포함되어 있습니다.

**신규**

* [GET insights/keywords/search](/ko/x-ads-api/audiences) 엔드포인트 응답에는 이제 입력 키워드와 관련된 30개의 용어를 담은 related&#95;keywords 속성이 포함됩니다.

**변경**

* 타기팅 기준 배치의 최대 크기가 이제 500으로 증가했습니다.
* card&#95;uri 및 preview&#95;url 응답 속성은 이제 상호 배타적입니다. 카드에 card&#95;uri가 있으면 preview&#95;url은 null입니다. 카드에 card&#95;uri가 없으면 preview&#95;url만 반환됩니다.
  * 2018-01-29부터 생성된 모든 카드는 card&#95;uri를 갖습니다.
  * 버전 4까지 모든 기존 카드가 card&#95;uri를 갖게 됩니다.
* 5:2 이미지를 사용하는 카드를 새로 *생성* 하는 것은 더 이상 불가능합니다. *기존* 5:2 이미지 기반 카드는 계속 동작하지만, 파트너가 (지원되는 경우) 더 높은 성과를 보이는 1.91:1 또는 1:1 종횡비를 사용하는 것으로 전환할 것을 권장합니다.

**삭제**

* [PUT accounts/:account&#95;id/targeting&#95;criteria](/ko/x-ads-api/campaign-management#get-accounts-account-id-targeting-criteria) 엔드포인트는 더 이상 사용할 수 없습니다. 이 엔드포인트의 replace 동작이 광고주에게 혼란을 야기했고, 한 번에 하나의 리소스만 업데이트하는 다른 PUT 엔드포인트와도 일관성이 없었기 때문에 이 변경을 적용하기로 결정했습니다. 대신 파트너는 [POST batch/accounts/:account&#95;id/targeting&#95;criteria](/ko/x-ads-api/campaign-management#post-batch-accounts-account-id-targeting-criteria) 엔드포인트를 사용해야 하며, 이는 단일 요청에서 타기팅을 추가하고 제거할 수 있는 기능 등 더 큰 유연성을 제공합니다.
* paused 응답 속성은 더 이상 자금 조달 수단(funding instruments)에 대해 반환되지 않습니다. 대신 자금 조달 수단이 일시 중지되었는지 여부를 확인하려면 entity&#95;status 응답 속성을 참조해야 합니다. 추가로, paused와 cancelled가 동일한 값에 대응하기 때문에 응답에서 cancelled 역시 더 이상 반환되지 않습니다.
* [GET accounts/:account&#95;id/tweet/preview](/ko/x-ads-api/creatives#get-accounts-account-id-tweets) 엔드포인트에서 card&#95;id 매개변수를 제거했습니다.
* 삭제된 Scheduled Tweets는 조회할 수 없기 때문에 with&#95;deleted 매개변수는 더 이상 지원되지 않습니다.
* 다음 엔드포인트에서는 해당 엔티티가 초안 상태가 될 수 없으므로 draft&#95;only 매개변수가 제거되었습니다.
  * [GET accounts/:account&#95;id/targeting&#95;criteria](/ko/x-ads-api/campaign-management#get-accounts-account-id-targeting-criteria)
  * [GET accounts/:account&#95;id/promoted&#95;tweets](/ko/x-ads-api/campaign-management#get-accounts-account-id-promoted-tweets)
  * [GET accounts/:account&#95;id/promoted&#95;accounts](/ko/x-ads-api/campaign-management#get-accounts-account-id-promoted-accounts)
  * [GET accounts/:account&#95;id/media&#95;creatives](/ko/x-ads-api/campaign-management#get-accounts-account-id-media-creatives)
  * [GET accounts/:account&#95;id/preroll&#95;call&#95;to&#95;actions](/ko/x-ads-api/creatives#get-accounts-account-id-preroll-call-to-actions)

**참고**

Video Website Cards와 Scheduled Tweets는 이제 베타 단계가 아닙니다. 출시 이후 Scheduled Tweets에 대해 적용된 변경 사항은 [이 스레드](https://devcommunity.x.com/t/announcement-update-to-scheduled-tweets/94869)를 참고하세요. 여기에는 Scheduled Tweets에 대한 HTML [미리보기](https://devcommunity.x.com/t/announcement-tweet-preview-improvements/96577)를 생성하는 기능도 포함됩니다.

Ads API 버전 2는 2017년 7월 10일에 [출시](https://devcommunity.x.com/t/ads-api-version-2/90360)되었습니다. Ads API 버전 1은 2018년 1월 10일에 지원이 종료됩니다.

**주요 변경 사항/사용 중단[¶](#breaking-changes-deprecations "Permalink to this headline")**

* `total_count`는 이제 선택적 응답 속성입니다. `with_total_count`가 `true`로 설정된 경우에만 제공됩니다.

* `line_items` 및 `campaigns` 요청 및 응답 객체의 `paused` 및 `draft_only` 필드는 단일 `entity_status` 매개변수로 대체되었습니다.

* [POST accounts/:account&#95;id/tweet](/ko/x-ads-api/creatives) 및 [GET accounts/:account&#95;id/tweet/preview](/ko/x-ads-api/creatives#get-accounts-account-id-tweets) 엔드포인트에서 `status` 매개변수 이름이 `text`로 변경되었습니다.

* [GET targeting&#95;criteria/locations](/ko/x-ads-api/campaign-management#get-targeting-criteria-locations) 엔드포인트의 `location_type` 열거형 값이 이제 복수형입니다. 예를 들어 `COUNTRY`는 `COUNTRIES`, `REGION`은 `REGIONS`로 변경되었습니다. 한 가지 예외로, v2에서는 `CITY`가 `METROS`로 변경되었는데, 이는 위치 유형이 Designated Marker Areas(DMA) 또는 “metros”를 가리킨다는 사실을 정확히 반영하기 위한 것입니다.

* PUT accounts/:account&#95;id/promoted&#95;tweets 엔드포인트의 `display_properties`. 이 값은 응답의 일부로 더 이상 반환되지 않습니다.

* 앞선 항목의 결과로, 더 이상 promoted&#95;tweets 엔터티를 업데이트(PUT)할 수 없습니다.

* [GET accounts/:account&#95;id/promoted&#95;tweets](/ko/x-ads-api/campaign-management#get-accounts-account-id-promoted-tweets) 엔드포인트의 `line_item_id` 매개변수가 제거되었습니다.

* v2 엔드포인트에서는 5:2 Website Card를 더 이상 생성할 수 없습니다.

* `data_type` 응답 속성은 더 이상 반환되지 않습니다.

| `name` | `objective` |
| `start_time` | `product_type` |
|     | `placements` |

**Notes[¶](#notes "Permalink to this headline")**

* 초안 라인 아이템 또는 캠페인은 `entity_status`가 `DRAFT`인 상태에서만 `PAUSED` 또는 `ACTIVE`로 전환할 수 있습니다.
* 여러 라인 아이템을 포함한 전체 캠페인을 활성화하려면, 캠페인에 속한 각 라인 아이템과 캠페인 자체 모두의 `entity_status`를 `ACTIVE`로 설정해야 합니다.
* 캠페인이나 라인 아이템의 `entity_status`를 변경하려면, 해당하는 PUT 엔드포인트를 사용합니다.

* [도달 추정치 변경 사항](https://developer.x.com/en/docs/ads/campaign-management/api-reference/reach-estimate.html#get-accounts-account-id-reach-estimate):
* 더 정확한 도달 범위 추정을 제공하기 위해 이제 이 엔드포인트는 예산을 고려합니다. 다음 매개변수는 이제 필수입니다:
  * [신규] `campaign_daily_budget_amount_local_micro`
  * `currency`
  * `bid`
  * `objective`
* 응답 객체의 구조가 변경되어 이제 응답 값의 범위를 반환합니다.
* `infinite_count`는 용도를 더 명확히 하고 혼동을 피하기 위해 `infinite_bid_count`로 이름이 변경되었습니다
* `count` 및 `infinite_bid_count` 외에 이제 다음과 같은 새로운 데이터 항목이 반환됩니다:
  * `impressions`
  * `engagements`
  * `estimated_daily_spend_local_micro`
* 맞춤형 오디언스 데이터 유형 변경
* 모든 응답에서 Tailored Audiences의 `data_type`이 `tailored_audiences`에서 `tailored_audience`로 변경되었습니다.
* 공유 Tailored Audiences는 이제 *API 전용* 베타로 제공됩니다. 공유 Tailored Audiences를 사용하면 하나의 오디언스를 여러 광고 계정에서 사용할 수 있습니다. 여러 광고 계정 간에 공유하려는 Tailored Audience의 권한을 관리하려면 [POST accounts/:account&#95;id/tailored&#95;audiences/:tailored&#95;audience&#95;id/permissions](/ko/x-ads-api/audiences) (및 관련 엔드포인트)를 사용하세요.
* 광고주 계정의 성과 [analytics](/ko/x-ads-api/analytics) 수집 방식에 대폭적인 개선 사항:
* 우리의 [모범 사례](/ko/x-ads-api/analytics#best-practices)에 맞추어, 이제 [동기식 통계 엔드포인트](/ko/x-ads-api/analytics#get-stats-accounts-account-id)를 통해 조회할 수 있는 데이터는 최대 **7일치**로 제한됩니다.
* 메트릭을 조회하는 작업을 단순화하기 위해 `metrics` 파라미터를 새로운 `metric_groups` 파라미터로 대체했습니다. 이제 개발자는 각 요청에서 어떤 메트릭 그룹을 반환받을지 지정하기만 하면 됩니다.
  * 요청한 메트릭이 해당 엔티티에 적합하지 않은 경우, 해당 메트릭은 응답에서 제외되고 `null` 값으로 표시됩니다. *이러한 메트릭은 애널리틱스 비용 한도에 포함되지 않습니다.*
* 응답을 **대폭 단순화했으며**, 이제 UI에서 지표가 표시되는 방식과 더 가깝게 일치합니다.
  * 이전에는 노출 위치별로(검색에서의 Promoted Tweets, 타임라인에서의 Promoted Tweets, 프로필 및 트윗 상세에서의 Promoted Tweets, X Audience Platform) 각각 별도의 지표를 제공했습니다. 이제는 각 위치에 대해 표준화된 지표 세트를 반환합니다. (기존의 `promoted_tweet_timeline_impressions`, `promoted_tweet_search_impressions`, `promoted_tweets_profile_impressions`, `promoted_tweets_tpn_impressions` 대신) 아래 카테고리 중 하나로 요청했을 때 단일 지표인 `impressions`로 제공됩니다(이는 모든 지표에 적용됩니다).
  * `ALL_ON_TWITTER`
  * `PUBLISHER_NETWORK`
  * 요청을 보내면 UI의 값과 더 쉽게 매칭할 수 있도록 단일 `impressions` 지표를 받게 됩니다.
  * `ALL_ON_TWITTER` 및 `PUBLISHER_NETWORK` data를 모두 받으려면 두 번의 쿼리를 수행해야 하며, 이 둘은 결합할 수 없습니다.
* 개발자 여러분의 피드백을 반영하여 이제 [비동기 통계 엔드포인트](/ko/x-ads-api/analytics#asynchronous-analytics)를 사용할 수 있습니다!

  * 새로운 단일 endpoint를 사용해 통계 작업을 대기열에 추가합니다. 리소스가 허용하는 범위 내에서 요청한 data를 수집합니다.
  * data를 사용할 수 있는지 확인하기 위해 작업 상태 endpoint를 조회할 수 있습니다.
  * data가 준비되면, 동기식 endpoint의 응답과 동일한 JSON 응답을 다운로드할 수 있도록 픽업 ID를 제공합니다.
  * 하나의 작업에서 최대 **90일**치 data를, 최대 **20개 엔터티**에 대해 조회할 수 있습니다.
* v0 메트릭과 v1 메트릭 간 매핑이 포함된 analytics v1 마이그레이션 가이드를 확인하세요
* Sandbox 개선 사항 * 이제 Sandbox 환경에서 [여러 개의 테스트 광고 계정](/ko/x-ads-api/campaign-management#post-accounts)을 생성할 수 있습니다. * 이제 Sandbox 환경에서 테스트 광고 계정에 대해 여러 개의 결제 수단(funding instrument)을 생성할 수 있습니다. 이를 통해 모든 결제 수단 유형을 테스트할 수 있습니다. 이전에는 테스트에 사용할 수 있는 `CREDIT_CARD` 결제 수단만 제공되었습니다. * 베타 기능을 테스트하고 싶으신가요? 이제 Sandbox 환경에서 계정별로 기능을 켜거나 꺼서, 테스트 요구 사항에 맞게 기능을 토글할 수 있습니다.
