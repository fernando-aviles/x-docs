<div id="how-to-get-access-to-the-ads-api">
  ## Ads API에 액세스하는 방법
</div>

1. [개발자 계정](https://developer.x.com/en/apply-for-access)에 가입합니다.
2. [개발자 App](https://developer.x.com/app)을 생성하고 토큰을 안전하게 보호합니다.
3. 각 개발자 App에 대해 Ads API 액세스를 요청하려면 [ads.x.com/help](https://ads.x.com/help)에 방문해 요청을 제출합니다.

<Note>**참고:** 이미 X Developer Platform을 사용 중이고 개발자 계정이 있다면, 3단계로 건너뛰십시오.</Note>

<div id="step-one-signup-for-a-developer-account">
  ### 1단계: 개발자 계정에 가입하기
</div>

X의 API 제품에 요청을 보내려면 먼저 개발자 계정에 가입해야 합니다. 개발자 콘솔에서 App과 개발자 App을 생성하세요. 그러면 API에 대한 모든 요청을 인증하는 데 사용할 자격 증명을 받게 됩니다.

<Button href="https://developer.x.com/en/apply-for-access">
  개발자 계정에 가입하기
</Button>

<div id="step-two-save-your-apps-key-and-tokens-and-keep-them-secure">
  ### 2단계: App의 키와 토큰을 저장하고 안전하게 보호하기
</div>

개발자 App 내에서 API Keys(Consumer Keys라고도 함) 세트를 제공받게 됩니다. 또한 개인 X 계정을 대신해 요청을 보내는 데 사용할 수 있는 Access Tokens 세트와, OAuth 2.0 Bearer Token이 필요한 엔드포인트를 인증하는 데 사용할 수 있는 Bearer Token을 생성할 수 있습니다. 이러한 키와 토큰은 다시 생성하지 않는 한 만료되지 않으므로, 환경 변수를 설정하거나 보안성이 검증된 비밀번호 관리 프로그램을 사용하는 것을 권장합니다.

또한 App 세부 정보 페이지의 URL에서 찾을 수 있는 App ID를 반드시 메모해 두세요. 다음 단계에서 Ads API 이용 권한을 요청할 때 더 수월해집니다.

<Note>
**참고:** 키와 토큰은 개발자 콘솔에서 한 번만 표시되므로, 생성 즉시 비밀번호 관리 시스템에 이 자격 증명을 저장하는 것이 매우 중요합니다.

키와 토큰을 분실했거나 기억하지 못하는 경우에는 다시 생성해야 하며, 이때 새 키와 토큰이 만들어지고 기존 값은 더 이상 유효하지 않게 됩니다. 이는 이전 자격 증명을 사용해 설정해 둔 모든 연동을 업데이트해야 함을 의미합니다.

[인증 모범 사례](https://developer.x.com/en/docs/authentication/guides/authentication-best-practices)에 대해 더 알아보세요.
</Note>

<div id="step-three-apply-for-access-to-the-ads-api">
  ### 3단계: Ads API 액세스 신청
</div>

현재 [기본 X API 액세스](https://developer.x.com/en/docs/twitter-api/v1)는 보유하고 있지만, X Ads API의 특정 기능에 대한 액세스는 없는 상태입니다. 다음으로 Ads API 액세스를 요청하고 승인을 받아야 합니다. 각 개발자 App에 대해 Ads API 액세스를 요청하려면 [ads.x.com/help](https://ads.x.com/help)를 방문해 요청을 제출하세요.

<div id="access-tiers">
  ### 액세스 티어
</div>

신청 과정에서 필요한 액세스 수준을 지정해야 합니다. [앱 수준 및 광고 계정 수준 권한](https://developer.x.com/en/docs/twitter-ads-api/obtaining-ads-account-access#levels-of-access)에 대해 자세히 알아보세요.

<div id="conversion-only">
  #### 전환 전용
</div>

모바일 및 웹 전환 엔드포인트에 대한 읽기 및 쓰기 액세스 권한이 제공됩니다.

<div id="standard-access">
  #### 표준 액세스
</div>

Analytics, Campaign Management, Creatives, Custom Audiences, Conversion 엔드포인트에 대한 읽기 및 쓰기 권한이 제공됩니다.

<Note>**참고:** 앱이 Ads API 액세스 승인을 받은 뒤에는, 올바르게 [인증된 Ads API 요청](https://developer.x.com/en/docs/twitter-ads-api/making-authenticated-requests)을 보내기 위해 기존 사용자 액세스 토큰을 모두 [다시 생성](https://developer.x.com/resources/fundamentals/authentication/obtaining-user-access-tokens)해야 합니다.</Note>

<Note>**참고:** 2023년 7월 이전에 액세스를 요청한 Ads API 개발자는 상이한 수준의 액세스 권한을 가지고 있을 수 있으며, OAuth 토큰이 최대 다섯 개로 제한될 수 있습니다. 추가 엔드포인트에 대한 액세스 권한을 얻거나 기존 애플리케이션의 토큰 제한을 해제하려면 [액세스 수준 늘리기](https://developer.x.com/en/docs/twitter-ads-api/increasing-access) 가이드를 참조하세요.</Note>

<div id="make-your-first-request">
  ## 첫 번째 요청 보내기
</div>

Ads API에 대한 접근 권한을 테스트하려면 [GET accounts](https://developer.x.com/en/docs/twitter-ads-api/campaign-management/api-reference/accounts) 엔드포인트에 요청을 보내세요. 이 엔드포인트는 현재 인증된 사용자가 접근할 수 있는 광고 계정을 반환합니다. 이후 API 요청에서 이 응답에 포함된 광고 계정 ID를 사용해 특정 광고 계정의 데이터를 읽고 쓸 수 있습니다. 명령줄에서 [Twurl](https://developer.x.com/en/docs/tutorials/using-twurl)을 사용할 경우 요청은 다음과 같은 형태가 됩니다.

**요청 예시**

```bash
twurl -H ads-api.x.com "/11/accounts"
```

**응답 예시**

