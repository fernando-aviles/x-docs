<div id="how-to-get-access-to-the-ads-api">
  ## Ads API 사용 권한을 얻는 방법
</div>

1. [개발자 계정](https://developer.x.com/en/apply-for-access)에 가입합니다.
2. [개발자 App](https://developer.x.com/app)을 생성하고 토큰을 안전하게 관리합니다.
3. [ads.x.com/help](https://ads.x.com/help)에 방문하여 각 개발자 App에 대해 Ads API 사용 권한을 요청합니다.

<Note>**참고:** 이미 X Developer Platform에서 개발 중이고 개발자 계정을 보유하고 있다면, 3단계로 건너뛰어도 됩니다.</Note>

<div id="step-one-signup-for-a-developer-account">
  ### 1단계: 개발자 계정에 가입하기
</div>

X의 어떤 API 제품이든 요청을 보내려면 먼저 개발자 계정에 가입해야 합니다. Developer Console 내에서 App과 개발자 App을 생성하세요. 그러면 API에 대한 모든 요청을 인증하는 데 사용할 자격 증명 세트를 발급받게 됩니다.

<Button href="https://developer.x.com/en/apply-for-access">
  개발자 계정에 가입하기
</Button>

<div id="step-two-save-your-apps-key-and-tokens-and-keep-them-secure">
  ### 2단계: App의 키와 토큰을 저장하고 안전하게 보호하기
</div>

개발자 App 내에서 API Keys(Consumer Keys라고도 함) 세트가 발급됩니다. 또한 개인 X 계정을 대신해 요청을 보낼 수 있는 Access Tokens 세트와, OAuth 2.0 Bearer Token이 필요한 엔드포인트를 인증하는 데 사용할 수 있는 Bearer Token을 생성할 수도 있습니다. 이러한 키와 토큰은 다시 생성하기 전까지는 만료되지 않으므로, 환경 변수를 사용하거나 안전한 비밀번호 관리자 도구를 사용할 것을 권장합니다.

또한 App 세부 정보 페이지의 URL에서 확인할 수 있는 App ID를 반드시 기록해 두십시오. 이렇게 하면 다음 단계에서 Ads API 액세스를 요청하기가 더 쉬워집니다.

<Note>
**참고:** 키와 토큰은 Developer Console에 한 번만 표시되므로, 생성하는 즉시 비밀번호 관리 도구에 이 자격 증명을 저장하는 것이 중요합니다.

키와 토큰을 분실하거나 잊어버린 경우 다시 생성해야 하며, 이때 새 키와 토큰이 생성되고 기존 키와 토큰은 더 이상 유효하지 않습니다. 이는 이전 자격 증명으로 설정해 두었던 모든 연동을 업데이트해야 함을 의미합니다.

[인증 모범 사례](https://developer.x.com/en/docs/authentication/guides/authentication-best-practices)에 대해 자세히 알아보세요.
</Note>

<div id="step-three-apply-for-access-to-the-ads-api">
  ### 3단계: Ads API 액세스 신청
</div>

현재 [기본 X API 액세스](https://developer.x.com/en/docs/twitter-api/v1)는 갖고 있지만, 특정 X Ads API 기능에 대한 액세스는 없습니다. 다음으로 Ads API 액세스를 요청하고 승인을 받아야 합니다. 각 개발자 App마다 Ads API 액세스 요청을 제출하려면 [ads.x.com/help](https://ads.x.com/help)를 방문하세요.

<div id="access-tiers">
  ### 액세스 등급
</div>

신청 과정에서 필요한 액세스 수준을 지정해야 합니다. [앱 수준 및 광고 계정 수준 권한](https://developer.x.com/en/docs/twitter-ads-api/obtaining-ads-account-access#levels-of-access)에 대해 자세히 알아보세요.

<div id="conversion-only">
  #### 전환 전용
</div>

읽기 및 쓰기 권한이 있는 모바일 및 웹 전환 엔드포인트에 대한 액세스.

<div id="standard-access">
  #### 표준 액세스
</div>

읽기 및 쓰기 권한으로 Analytics, Campaign Management, Creatives, Custom Audiences, Conversion 엔드포인트에 접근할 수 있습니다.

<Note>**참고:** 앱이 Ads API 액세스 승인을 받은 후에는 [인증된 Ads API 요청](https://developer.x.com/en/docs/twitter-ads-api/making-authenticated-requests)을 적절하게 수행하기 위해 [모든 사용자 액세스 토큰을 재발급](https://developer.x.com/resources/fundamentals/authentication/obtaining-user-access-tokens)해야 합니다.</Note>

<Note>**참고:** 2023년 7월 이전에 액세스를 요청한 Ads API 개발자는 액세스 수준과 권한이 다를 수 있으며, OAuth 토큰이 5개로 제한될 수 있습니다. 추가 엔드포인트에 대한 액세스를 받거나 기존 애플리케이션의 토큰 한도를 해제하려면 [액세스 확대](https://developer.x.com/en/docs/twitter-ads-api/increasing-access) 가이드를 참고하세요.</Note>

<div id="make-your-first-request">
  ## 첫 번째 요청 보내기
</div>

Ads API에 대한 접근 권한을 테스트하려면 [GET accounts](https://developer.x.com/en/docs/twitter-ads-api/campaign-management/api-reference/accounts) 엔드포인트로 요청을 보내세요. 이 엔드포인트는 현재 인증된 사용자가 접근할 수 있는 광고 계정들을 반환합니다. 이후 API 요청에서 이 응답에서 받은 광고 계정 id를 사용하여 특정 광고 계정의 data를 조회하고 작성할 수 있습니다. 명령줄에서 [Twurl](https://developer.x.com/en/docs/tutorials/using-twurl)을 사용하면 요청은 다음과 같은 형태가 됩니다.

**요청 예제**

```bash
twurl -H ads-api.x.com "/11/accounts"
```

**응답 예제**

```json

    "params": {}
  },
```
