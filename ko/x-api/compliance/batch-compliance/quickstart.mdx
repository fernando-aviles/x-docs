이 가이드는 포스트 또는 사용자의 컴플라이언스 상태를 확인하기 위한 배치 컴플라이언스 작업을 생성하는 과정을 단계별로 설명합니다.

<Note>
  **사전 준비 사항**

  시작하기 전에 다음이 필요합니다:

  * 승인된 App이 있는 [개발자 계정](https://developer.x.com/en/portal/petition/essential/basic-info)
  * App의 Bearer Token
</Note>

***

<Steps>
  <Step title="작업 생성" icon="plus">
    유형(트윗 또는 사용자)을 지정하여 새 컴플라이언스 작업을 생성합니다:

    <Tabs>
      <Tab title="cURL">
        ```bash
        curl -X POST "https://api.x.com/2/compliance/jobs" \
          -H "Authorization: Bearer $BEARER_TOKEN" \
          -H "Content-Type: application/json" \
          -d '{
            "type": "tweets",
            "name": "my-compliance-job"
          }'
        ```
      </Tab>

      <Tab title="Python">
        ```python
        import requests

        bearer_token = "YOUR_BEARER_TOKEN"

        url = "https://api.x.com/2/compliance/jobs"
        headers = {
            "Authorization": f"Bearer {bearer_token}",
            "Content-Type": "application/json"
        }
        payload = {
            "type": "tweets",
            "name": "my-compliance-job"
        }

        response = requests.post(url, headers=headers, json=payload)
        print(response.json())
        ```
      </Tab>
    </Tabs>

    **응답:**

    ```json
    {
      "data": {
        "id": "1234567890",
        "type": "tweets",
        "name": "my-compliance-job",
        "status": "created",
        "upload_url": "https://storage.googleapis.com/...",
        "download_url": "https://storage.googleapis.com/...",
        "created_at": "2024-01-15T10:00:00.000Z"
      }
    }
    ```

    다음 단계를 위해 `upload_url`과 `download_url`을 저장해 두세요.
  </Step>

  <Step title="데이터 파일 준비" icon="file">
    한 줄에 하나의 ID만 포함되도록 텍스트 파일을 생성합니다:

    ```
    1234567890
    1234567891
    1234567892
    1234567893
    ```

    `ids.txt`로 저장합니다.
  </Step>

  <Step title="데이터 업로드" icon="upload">
    제공된 `upload_url`로 파일을 업로드합니다:

    ```bash
    curl -X PUT "UPLOAD_URL_FROM_RESPONSE" \
      -H "Content-Type: text/plain" \
      --data-binary @ids.txt
    ```
  </Step>

  <Step title="작업 상태 확인" icon="clock">
    완료될 때까지 작업 상태를 주기적으로 확인합니다:

    ```bash
    curl "https://api.x.com/2/compliance/jobs/1234567890" \
      -H "Authorization: Bearer $BEARER_TOKEN"
    ```

    **작업 상태:**

    | Status        | Description          |
    | :------------ | :------------------- |
    | `created`     | 작업이 생성되었으며 업로드를 대기 중 |
    | `in_progress` | 데이터를 처리 중            |
    | `complete`    | 결과를 다운로드할 준비가 완료됨    |
    | `failed`      | 작업 실패                |
    | `expired`     | 완료되기 전에 작업이 만료됨      |
  </Step>

  <Step title="결과 다운로드" icon="download">
    상태가 `complete`가 되면 `download_url`에서 다운로드합니다:

    ```bash
    curl "DOWNLOAD_URL_FROM_RESPONSE" -o results.json
    ```

    **결과 형식** (한 줄에 하나의 JSON 객체):

    ```json
    {"id": "1234567890", "action": "delete", "created_at": "2024-01-10T12:00:00.000Z", "redacted_at": "2024-01-12T08:30:00.000Z", "reason": "deleted"}
    {"id": "1234567891", "action": "delete", "created_at": "2024-01-10T12:00:00.000Z", "redacted_at": "2024-01-13T14:20:00.000Z", "reason": "suspended"}
    ```

    컴플라이언스 이벤트가 있는 ID만 결과에 표시됩니다. 결과에 없는 ID도 여전히 유효합니다.
  </Step>
</Steps>

<div id="compliance-actions">
  ## 컴플라이언스 조치
</div>

<AccordionGroup>
  <Accordion title="포스트 컴플라이언스 이벤트">
    | 작업 | 사유 | 설명 |
    |:-------|:-------|:------------|
    | `delete` | `deleted` | 포스트가 삭제되었습니다 |
    | `delete` | `bounced` | 포스트가 컴플라이언스 검사를 통과하지 못했습니다 |
    | `delete` | `protected` | 계정이 보호 계정이 되었습니다 |
    | `delete` | `suspended` | 계정이 정지되었습니다 |
    | `delete` | `scrub_geo` | 위치 정보가 제거되었습니다 |
  </Accordion>

  <Accordion title="사용자 컴플라이언스 이벤트">
    | 작업 | 사유 | 설명 |
    |:-------|:-------|:------------|
    | `delete` | `deleted` | 계정이 삭제되었습니다 |
    | `delete` | `suspended` | 계정이 정지되었습니다 |
    | `delete` | `protected` | 계정이 보호 계정이 되었습니다 |
    | `delete` | `deactivated` | 계정이 비활성화되었습니다 |
  </Accordion>
</AccordionGroup>

  ## 모든 작업 나열하기

```bash
  -H "Authorization: Bearer $BEARER_TOKEN"
```
