Batch Compliance 엔드포인트를 사용하면 게시물 id 또는 사용자 id로 구성된 데이터셋을 업로드하고, 해당 리소스의 현재 컴플라이언스 상태를 받을 수 있습니다. 이를 통해 삭제된 게시물, 정지된 계정 및 기타 컴플라이언스 이벤트를 식별할 수 있습니다.

<div id="how-it-works">
  ## 작동 방식
</div>

1. **작업 생성** — type(포스트 또는 사용자)와 업로드 URL을 지정합니다
2. **ID 업로드** — 제공된 URL로 데이터세트를 업로드합니다
3. **처리 대기** — 작업이 비동기적으로 처리됩니다
4. **결과 다운로드** — 각 ID에 대한 컴플라이언스 상태를 확인합니다

***

<div id="endpoints">
  ## 엔드포인트
</div>

| Method | Endpoint | Description |
|:-------|:---------|:------------|
| POST | [`/2/compliance/jobs`](/ko/x-api/compliance/create-compliance-job) | 새 컴플라이언스 작업을 생성합니다 |
| GET | [`/2/compliance/jobs/:id`](/ko/x-api/compliance/get-compliance-job-by-id) | 작업 상태를 조회합니다 |
| GET | [`/2/compliance/jobs`](/ko/x-api/compliance/get-compliance-jobs) | 모든 작업을 나열합니다 |

***

<div id="job-types">
  ## 작업 유형
</div>

| Type | Description |
|:-----|:------------|
| `tweets` | 게시물 컴플라이언스 상태를 확인 |
| `users` | 사용자 컴플라이언스 상태를 확인 |

***

<div id="compliance-events">
  ## 규정 준수 이벤트
</div>

<div id="post-events">
  ### 게시물 이벤트
</div>

| Event | Description |
|:------|:------------|
| `deleted` | 사용자가 게시물을 삭제함 |
| `bounced` | 게시물이 규정 준수 검사를 통과하지 못함 |
| `protected` | 계정이 보호 상태가 됨 |
| `suspended` | 계정이 정지됨 |
| `scrub_geo` | 위치 정보가 제거됨 |

<div id="user-events">
  ### 사용자 이벤트
</div>

| 이벤트 | 설명 |
|:------|:------------|
| `deleted` | 계정이 삭제됨 |
| `suspended` | 계정이 정지됨 |
| `protected` | 계정이 보호됨 |
| `deactivated` | 계정이 비활성화됨 |

***

<div id="example-create-a-job">
  ## 예시: 작업 생성하기
</div>

```bash
curl -X POST "https://api.x.com/2/compliance/jobs" \
  -H "Authorization: Bearer $BEARER_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "type": "tweets",
    "name": "my-compliance-job"
  }'
```
