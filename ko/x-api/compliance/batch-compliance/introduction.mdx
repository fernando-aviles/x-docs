Batch Compliance 엔드포인트를 사용하면 포스트 ID 또는 사용자 ID로 구성된 데이터 세트를 업로드하고, 해당 ID들의 현재 컴플라이언스 상태를 조회할 수 있습니다. 이를 통해 삭제된 포스트, 정지된 계정 및 기타 컴플라이언스 이벤트를 식별할 수 있습니다.

<div id="how-it-works">
  ## 동작 방식
</div>

1. **작업 생성** — 유형(포스트 또는 사용자)과 업로드 URL을 지정합니다.
2. **id 업로드** — 제공된 URL로 데이터셋을 업로드합니다.
3. **처리 대기** — 작업이 비동기적으로 처리됩니다.
4. **결과 다운로드** — 각 id에 대한 규정 준수 상태를 가져옵니다.

***

<div id="endpoints">
  ## 엔드포인트
</div>

| Method | Endpoint | Description |
|:-------|:---------|:------------|
| POST | [`/2/compliance/jobs`](/ko/x-api/compliance/create-compliance-job) | 새 컴플라이언스 작업 생성 |
| GET | [`/2/compliance/jobs/:id`](/ko/x-api/compliance/get-compliance-job-by-id) | 작업 상태 가져오기 |
| GET | [`/2/compliance/jobs`](/ko/x-api/compliance/get-compliance-jobs) | 모든 작업 목록 가져오기 |

***

<div id="job-types">
  ## 작업 유형
</div>

| 유형 | 설명 |
|:-----|:------------|
| `tweets` | 포스트 규정 준수 상태 확인 |
| `users` | 사용자 규정 준수 상태 확인 |

***

<div id="compliance-events">
  ## 규정 준수 이벤트
</div>

<div id="post-events">
  ### 포스트 이벤트
</div>

| Event | Description |
|:------|:------------|
| `deleted` | 사용자가 포스트를 삭제함 |
| `bounced` | 포스트가 컴플라이언스 검사를 통과하지 못함 |
| `protected` | 계정이 보호 상태가 됨 |
| `suspended` | 계정이 정지됨 |
| `scrub_geo` | 위치 정보가 제거됨 |

<div id="user-events">
  ### 사용자 이벤트
</div>

| 이벤트 | 설명 |
|:------|:------------|
| `deleted` | 계정이 삭제됨 |
| `suspended` | 계정이 정지됨 |
| `protected` | 계정이 보호됨 |
| `deactivated` | 계정이 비활성화됨 |

***

<div id="example-create-a-job">
  ## 예제: 작업 생성
</div>

```bash
curl -X POST "https://api.x.com/2/compliance/jobs" \
  -H "Authorization: Bearer $BEARER_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "type": "tweets",
    "name": "my-compliance-job"
  }'
```
