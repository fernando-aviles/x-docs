이 가이드는 레거시 Enterprise Account Activity API에서 V2 Account Activity API로 마이그레이션하는 데 도움이 됩니다. 핵심 기능은 그대로 유지되지만, 엔드포인트 구조와 인증 방식은 X API v2와의 일관성을 위해 업데이트되었습니다.

<div id="summary-of-changes">
  ### 변경 사항 요약
</div>

* **API 형식**: 엔드포인트는 /1.1/account\_activity/ 대신 /2/account\_activity/ 기본 경로를 사용합니다.  
* **웹훅 관리**: 웹훅 생성, 목록 조회, 검증(CRC), 삭제는 [V2 Webhooks API](https://github.com/m-rosinsky/XWebhookTest/blob/main/app.py)에서 처리합니다.  
* **인증**: V2 엔드포인트에는 다음 중 하나의 인증이 필요합니다.  
  * 사용자별 작업(예: 사용자를 구독에 등록하는 작업)의 경우 **OAuthUser**(3-legged OAuth).  
  * 앱 수준 작업(예: 구독 목록 조회/삭제)의 경우 **OAuth2 App Only**(Bearer Token).  
  * V1.1은 종종 OAuth 1.0a를 포함해 요구 사항이 다양했습니다.  
* **엔드포인트 매핑**:

| V1.1 Endpoint | V2에 해당하는 엔드포인트 / 작업 | 비고 |
| ----- | ----- | ----- |
| POST /1.1/account\_activity/webhooks.json?url=\<URL\> | POST /2/webhooks | [문서](https://docs.x.com/x-api/webhooks/introduction). OAuth2AppOnly 필요. |
| GET /1.1/account\_activity/webhooks.json | GET /2/webhooks | [문서](https://docs.x.com/x-api/webhooks/introduction). OAuth2AppOnly 필요. |
| PUT /1.1/account\_activity/webhooks/:webhook\_id.json | PUT /2/webhooks/:webhook\_id | CRC를 트리거합니다. [문서](https://docs.x.com/x-api/webhooks/introduction). OAuth2AppOnly 필요. |
| DELETE /1.1/account\_activity/webhooks/:webhook\_id.json | DELETE /2/webhooks/:webhook\_id | [문서](https://docs.x.com/x-api/webhooks/introduction). OAuth2AppOnly 필요. |
| POST /1.1/account\_activity/webhooks/:webhook\_id/subscriptions/all.json | POST /2/account\_activity/webhooks/:webhook\_id/subscriptions/all | OAuthUser 필요. |
| GET /1.1/account\_activity/subscriptions/count.json | GET /2/account\_activity/subscriptions/count | OAuth2AppOnly 필요. |
| GET /1.1/account\_activity/webhooks/:webhook\_id/subscriptions/all.json | GET /2/account\_activity/webhooks/:webhook\_id/subscriptions/all | OAuthUser 필요. |
| GET /1.1/account\_activity/webhooks/:webhook\_id/subscriptions/all/list.json | GET /2/account\_activity/webhooks/:webhook\_id/subscriptions/all/list | OAuth2AppOnly 필요. |
| DELETE /1.1/account\_activity/webhooks/:webhook\_id/subscriptions/:user\_id/all | DELETE /2/account\_activity/webhooks/:webhook\_id/subscriptions/:user\_id/all | OAuth2AppOnly 필요. |
| DELETE /1.1/account\_activity/webhooks/:webhook\_id/subscriptions/all | 사용 중단 / 직접 대응 엔드포인트 없음 | 개별 삭제를 사용하거나 DELETE /2/webhooks/:webhook\_id로 웹훅을 제거하십시오. |

* **응답 형식**: AAAPI 문서에서 성공 및 오류 응답 구조를 검토하십시오.

마이그레이션 시, 새로운 기본 경로를 사용하도록 코드를 업데이트하고, 인증 플로우를 조정하며, [V2 Webhooks API](https://docs.x.com/x-api/webhooks/introduction)를 사용해 웹훅을 관리하십시오.

<div id="how-to-migrate">
  ### 마이그레이션 방법
</div>

* **패키지 결정**:  
  * Account Activity API 액세스를 위해 Enterprise 또는 Self-serve 패키지 중에서 선택할 때 다음을 고려합니다.  
    * 필요한 webhook 수  
    * 현재/예상 구독 수 또는 인가된 사용자 수  
    * X 클라이언트 애플리케이션 수  
    * 원하는 지원 수준(포럼 기반 vs. 관리형 Enterprise 1:1 지원)  
    * 가격 세부 정보(Enterprise의 경우 영업팀에 문의)  
* **인증을 OAuth 2.0으로 업데이트**:  
  * 사용 중인 X App에 “Read, Write, and Access Direct Messages” 권한이 있는지 확인합니다.  
  * V2 엔드포인트용으로 OAuth 2.0을 사용하도록 전환합니다. 스코프가 변경된 경우 사용자를 다시 인가받으십시오.  
  * Developer Console을 사용하여 다음을 관리합니다.  
    * OAuth 2.0 Access Token  
    * Client ID 및 Client Secret  
* **Webhook 확인 또는 재구성**:  
  * 기존 webhook URL을 사용하거나 새 URL을 설정합니다(예: https://your\_domain.com/webhook/twitter).  
  * webhook을 등록하고 관리하려면 [V2 Webhooks API documentation](https://docs.x.com/x-api/webhooks/introduction)을 따르십시오.  
* **샘플 앱:**  
  * [Simple webhook server](https://github.com/m-rosinsky/XWebhookTest/blob/main/app.py)  
    * CRC 검사에 응답하고 POST 이벤트를 수신하는 방법을 보여주는 단일 Python 스크립트입니다.  
  * [Account Activity API sample dashboard](https://github.com/xdevplatform/account-activity-dashboard-enterprise/tree/master)  
    * webhook과 구독을 관리하고, 앱 내에서 직접 실시간 이벤트를 수신할 수 있도록 [bun.sh](http://bun.sh)로 구현된 웹 앱입니다.
