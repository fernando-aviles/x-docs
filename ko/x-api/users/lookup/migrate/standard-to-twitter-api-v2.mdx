<div id="standard-v11-compared-to-x-api-v2">
  ### 표준 v1.1과 X API v2 비교
</div>

표준 v1.1의 GET users/show 및 GET users/lookup을 사용해 왔다면, 이 가이드는 표준 users 조회 엔드포인트와 X API v2 users 조회 엔드포인트 간의 공통점과 차이점을 이해하는 데 도움이 되도록 구성되었습니다.

* **유사점**
  * OAuth 1.0a User Context
  * 요청당 사용자 수 제한
* **차이점**
  * 엔드포인트 URL
  * 앱 및 Project 요구 사항
  * 응답 data 형식
  * 요청 매개변수

<div id="similarities">
  #### 유사점
</div>

**OAuth 1.0a User Context 인증 방법**

표준 엔드포인트는 [OAuth 1.0a User Context](/ko/resources/fundamentals/authentication#oauth-1-0a-2)를 지원하고, 새로운 X API v2 users lookup 엔드포인트는 OAuth 1.0a User Context와 [App only](/ko/resources/fundamentals/authentication#oauth-2-0)를 모두 지원합니다. 따라서 이전에 표준 v1.1 users lookup 엔드포인트 중 하나를 사용하고 있었다면, X API v2 버전으로 마이그레이션하더라도 동일한 인증 방법을 계속 사용할 수 있습니다.

사용하는 인증 라이브러리/패키지에 따라 다를 수 있지만, App only 인증은 시작하기 가장 쉬운 방법인 경우가 많으며, 간단한 요청 헤더만으로 설정할 수 있습니다. App only Access Token을 생성하는 방법은 [이 App only 가이드](/ko/resources/fundamentals/authentication#bearer-token-also-known-as-app-only)를 참고하세요.

**요청당 사용자 수 제한**

표준 v1.1 GET users/lookup 엔드포인트는 요청당 최대 100명의 사용자를 지정할 수 있습니다. 이는 GET /users 및 GET /users/by 엔드포인트에도 동일하게 적용됩니다. 최대 100명의 사용자를 모두 지정하려면 ids (GET /users) 파라미터 또는 username (GET /users/by) 파라미터를 쿼리 파라미터로 전달하고, 사용자 ID/username 목록을 쉼표로 구분해 포함해야 합니다.

<div id="differences">
  #### 차이점
</div>

**엔드포인트 URL**

* 표준 v1.1 엔드포인트:
  * https://api.x.com/1.1/users/show (단일 id 또는 username 조회)
  * https://api.x.com/1.1/users/lookup (복수 id 또는 username 조회)
* X API v2 엔드포인트:
  * https://api.x.com/2/users (복수 id 조회)
  * https://api.x.com/2/users/:id (단일 id 조회)
  * https://api.x.com/2/users/by (복수 username 조회)
  * https://api.x.com/2/users/by/username/:username (단일 username 조회)

**App 및 Project 요구 사항**

X API v2 엔드포인트를 사용하려면, 요청을 인증할 때 [개발자 App](/ko/resources/fundamentals/developer-apps)에 속해 있고 [Project](/ko/resources/fundamentals/developer-apps)에 연동된 자격 증명을 사용해야 합니다. 모든 X API v1.1 엔드포인트는 Project에 연동되지 않은 App 또는 Project에 연동된 App의 자격 증명을 모두 사용할 수 있습니다.

**응답 data 형식**

표준 v1.1과 X API v2 엔드포인트 버전 간의 가장 큰 차이점 중 하나는 페이로드에서 어떤 필드를 반환할지 선택하는 방식입니다.

표준 엔드포인트의 경우, 기본적으로 많은 응답 필드를 받고, 그다음에 어떤 필드 또는 필드 세트를 페이로드에서 반환할지 지정하기 위해 매개변수를 선택적으로 사용할 수 있습니다.

X API v2 버전은 기본적으로 user id, 이름(name), username 필드만 제공합니다. 추가 필드나 객체를 요청하려면 [fields](/ko/x-api/fundamentals/fields) 및 [expansions](/ko/x-api/fundamentals/expansions) 매개변수를 사용해야 합니다. 이 엔드포인트에서 요청한 모든 user 필드는 기본 user 객체에 반환됩니다. 확장된 포스트 객체와 필드는 응답 내 includes 객체에 반환됩니다. 그런 다음 user와 확장된 포스트 객체에 모두 포함된 ID를 매칭하여, 확장된 객체를 user 객체에 다시 매칭할 수 있습니다.

이 새로운 매개변수에 대해서는 각각의 가이드 또는 [fields 및 expansions 사용 방법](/ko/x-api/fundamentals/data-dictionary#how-to-use-fields-and-expansions)에 대한 가이드를 참고하시기 바랍니다.

또한, 표준 v1.1 필드를 새로운 v2 필드에 매핑하는 데 도움이 되는 [data 형식 마이그레이션 가이드](/ko/x-api/migrate/data-format-migration#migrating-from-standard-v1-1s-data-format-to-v2)도 제공하고 있습니다. 이 가이드는 특정 필드를 반환하기 위해 v2 요청과 함께 전달해야 하는 Expansions 및 fields 매개변수도 구체적으로 제공합니다.

특정 필드를 요청하는 방식의 변경 사항 외에도, X API v2는 [포스트](/ko/x-api/fundamentals/data-dictionary#tweet) 및 [user](/ko/x-api/fundamentals/data-dictionary#user) 객체를 포함하여 API가 반환하는 객체에 대해 새로운 JSON 설계를 도입하고 있습니다.

* JSON 루트 수준에서, 표준 엔드포인트는 포스트 객체를 statuses 배열로 반환하는 반면, X API v2는 data 배열로 반환합니다.
* 리트윗된(Retweeted) 및 인용된(Quoted) &quot;statuses&quot;를 참조하는 대신, X API v2 JSON은 리트윗된 트윗과 인용된 트윗을 참조합니다. contributors, user.translator&#95;type과 같은 많은 레거시 및 사용 중단 필드는 제거되고 있습니다.
* 포스트 객체에서 favorites, user 객체에서 favourites를 모두 사용하는 대신, X API v2는 like라는 용어를 사용합니다.
* X는 값이 없는 JSON 값(예: null)은 페이로드에 기록하지 않는 규칙을 채택하고 있습니다. 포스트와 user 속성은 null이 아닌 값을 가진 경우에만 포함됩니다.

또한 [포스트 객체](/ko/x-api/fundamentals/data-dictionary#tweet)에 다음을 포함한 새로운 필드 세트를 도입했습니다.

* [conversation&#95;id](/ko/x-api/fundamentals/conversation-id) 필드
* context 및 entities를 포함하는 두 개의 새로운 [annotations](/ko/x-api/fundamentals/post-annotations) 필드
* 여러 개의 새로운 [metrics](/ko/x-api/fundamentals/metrics) 필드
* 특정 포스트에 누가 답글을 달 수 있는지를 보여주는 새로운 reply&#95;setting 필드

**요청 매개변수**

다음 표준 v1.1 요청 매개변수에는 X API v2에서의 대응 항목이 있습니다.

|     |     |
| :--- | :--- |
| **Standard** | **X API v2** |
| user&#95;id | ids |
| screen&#95;name | username |

또한 X API v2에서 지원되지 않는 표준 users lookup 요청 매개변수 집합도 있습니다.

| Standard | 설명 |
| :--- | :--- |
| include&#95;entities | 이 매개변수는 포스트 페이로드에서 entities 노드를 제거하는 데 사용됩니다. 필드를 추가하는 fields 및 expansions 기능으로 대체되었습니다. |

<div id="code-examples">
  ### 코드 예제
</div>

다음 예제에서는 표준 v1.1 엔드포인트와 이에 대응하는 v2 엔드포인트를 보여줍니다.

**단일 사용자 조회: v1.1 `GET users/show` → v2 `GET /users/by/username/:username`**

<CodeGroup dropdown>
  ```bash cURL (v1.1)
  curl --request GET \
    --url 'https://api.x.com/1.1/users/show.json?screen_name=XDevelopers' \
    --header 'Authorization: Bearer $ACCESS_TOKEN'
  ```

  ```bash cURL (v2)
  curl --request GET \
    --url 'https://api.x.com/2/users/by/username/XDevelopers?user.fields=created_at,description,public_metrics' \
    --header 'Authorization: Bearer $ACCESS_TOKEN'
  ```

  ```python Python (v2)
  import requests

  bearer_token = "YOUR_BEARER_TOKEN"
  url = "https://api.x.com/2/users/by/username/XDevelopers"

  params = {
      "user.fields": "created_at,description,public_metrics"
  }

  headers = {"Authorization": f"Bearer {bearer_token}"}
  response = requests.get(url, headers=headers, params=params)

  print(response.json())
  ```

  ```python Python SDK
  from xdk import Client

  client = Client(bearer_token="YOUR_BEARER_TOKEN")

  # 추가 필드를 포함해 사용자 이름(username)으로 사용자 조회
  response = client.users.get_by_username(
      "XDevelopers",
      user_fields=["created_at", "description", "public_metrics"]
  )

  print(f"Name: {response.data.name}")
  print(f"Followers: {response.data.public_metrics.followers_count}")
  ```

  ```javascript JavaScript SDK
  import { Client } from "@xdevplatform/xdk";

  const client = new Client({ bearerToken: "YOUR_BEARER_TOKEN" });

  const response = await client.users.getByUsername("XDevelopers", {
    userFields: ["created_at", "description", "public_metrics"],
  });

  console.log(`Name: ${response.data?.name}`);
  console.log(`Followers: ${response.data?.public_metrics?.followers_count}`);
  ```
</CodeGroup>

**여러 사용자 조회: v1.1 `GET users/lookup` → v2 `GET /users/by`**

<CodeGroup dropdown>
  ```bash cURL (v1.1)
  curl --request GET \
    --url 'https://api.x.com/1.1/users/lookup.json?screen_name=XDevelopers,X,XAPI' \
    --header 'Authorization: Bearer $ACCESS_TOKEN'
  ```

  ```bash cURL (v2)
  curl --request GET \
    --url 'https://api.x.com/2/users/by?usernames=XDevelopers,X,XAPI&user.fields=created_at,public_metrics' \
    --header 'Authorization: Bearer $ACCESS_TOKEN'
  ```

  ```python Python (v2)
  import requests

  bearer_token = "YOUR_BEARER_TOKEN"
  url = "https://api.x.com/2/users/by"

  params = {
      "usernames": "XDevelopers,X,XAPI",
      "user.fields": "created_at,public_metrics"
  }

  headers = {"Authorization": f"Bearer {bearer_token}"}
  response = requests.get(url, headers=headers, params=params)

  for user in response.json()["data"]:
      print(f"{user['username']}: {user['public_metrics']['followers_count']} followers")
  ```

  ```python Python SDK
  from xdk import Client

  client = Client(bearer_token="YOUR_BEARER_TOKEN")

  # 여러 사용자를 사용자 이름(username)으로 조회
  response = client.users.get_users_by_usernames(
      usernames=["XDevelopers", "X", "XAPI"],
      user_fields=["created_at", "public_metrics"]
  )

  for user in response.data:
      print(f"{user.username}: {user.public_metrics.followers_count} followers")
  ```

  ```javascript JavaScript SDK
  import { Client } from "@xdevplatform/xdk";

  const client = new Client({ bearerToken: "YOUR_BEARER_TOKEN" });

  const response = await client.users.getUsersByUsernames({
    usernames: ["XDevelopers", "X", "XAPI"],
    userFields: ["created_at", "public_metrics"],
  });

  response.data?.forEach((user) => {
    console.log(`${user.username}: ${user.public_metrics?.followers_count} followers`);
  });
  ```
</CodeGroup>
