<div id="manage-follows-standard-v11-compared-to-x-api-v2">
  #### 팔로우 관리: Standard v1.1과 X API v2 비교
</div>

Standard v1.1의 [POST friendships/create](https://developer.x.com/en/docs/twitter-api/v1/accounts-and-users/follow-search-get-users/api-reference/post-friendships-create) 및 [POST friendships/destroy](https://developer.x.com/en/docs/twitter-api/v1/accounts-and-users/follow-search-get-users/api-reference/post-friendships-destroy) 엔드포인트를 사용해 왔다면, 이 가이드는 Standard 엔드포인트와 X API v2 팔로우 관리 엔드포인트 간의 공통점과 차이점을 이해하는 데 도움이 되도록 작성되었습니다.

* **유사점**
  * OAuth 1.0a User Context
* **차이점**
  * 엔드포인트 URL
  * 앱 및 Project 요구 사항
  * HTTP 메서드
  * 요청 매개변수

<div id="similarities">
  #### 유사점
</div>

**OAuth 1.0a User Context 인증 방식**

두 엔드포인트 버전 모두 [OAuth 1.0a User Context](/ko/resources/fundamentals/authentication#oauth-1-0a-2)를 지원합니다. 따라서 이전에 표준 v1.1 팔로우 관리 엔드포인트 중 하나를 사용하고 있었다면, X API v2 버전으로 마이그레이션하더라도 동일한 인증 방식을 그대로 계속 사용할 수 있습니다.

<div id="differences">
  #### 차이점
</div>

**엔드포인트 URL**

* Standard v1.1 엔드포인트:
  * POST https://api.x.com/1.1/friendships/create.json
    (사용자를 팔로우)
  * POST https://api.x.com/1.1/friendships/destroy.json
    (사용자 팔로우 해제)
* X API v2 엔드포인트:
  * POST https://api.x.com/2/users/:id/following
    (사용자를 팔로우)
  * DELETE https://api.x.com/2/users/:source&#95;user&#95;id/following/:target&#95;user&#95;id
    (사용자 팔로우 해제)

**App 및 Project 요구 사항**

X API v2 엔드포인트는 요청을 인증할 때 [developer App](/ko/resources/fundamentals/developer-apps)의 자격 증명을 사용해야 하며, 이 App은 [Project](/ko/resources/fundamentals/developer-apps)에 연결되어 있어야 합니다. 모든 X API v1.1 엔드포인트는 Project에 연결되지 않은 App이든 Project에 연결된 App이든 모두 해당 App의 자격 증명을 사용할 수 있습니다.

**요청 파라미터**

다음 Standard v1.1 요청 파라미터에는 X API v2에서의 대응 항목이 있습니다:

| Standard v1.1 | X API v2 |
| :--- | :--- |
| 해당 없음 | id (POST), source&#95;user&#95;id (DELETE) |
| user&#95;id | target&#95;user&#95;id |
| screen&#95;name | 해당 없음 |

Standard v1.1 파라미터는 쿼리 파라미터로 전달되는 반면, X API v2 파라미터는 요청 본문 파라미터(POST 엔드포인트의 경우) 또는 경로 파라미터(DELETE 엔드포인트의 경우)로 전달된다는 점에 유의하세요.

또한, v2의 id 및 source&#95;user&#95;id는 Standard v1.1 엔드포인트를 사용할 때는 필수가 아닙니다. 이는 OAuth 1.0a User Context와 함께 전달된 액세스 토큰을 통해 어떤 사용자가 팔로우/언팔로우를 시작했는지 추론되었기 때문입니다.

<div id="follow-a-user-v2">
  ### 사용자를 팔로우 (v2)
</div>

<CodeGroup dropdown>
  ```bash cURL
  curl -X POST "https://api.x.com/2/users/123456789/following" \
    -H "Authorization: OAuth ..." \
    -H "Content-Type: application/json" \
    -d '{"target_user_id": "2244994945"}'
  ```

  ```python Python
  # OAuth 1.0a User Context 인증이 필요합니다
  import requests
  from requests_oauthlib import OAuth1

  auth = OAuth1(
      "API_KEY", "API_SECRET",
      "ACCESS_TOKEN", "ACCESS_TOKEN_SECRET"
  )

  url = "https://api.x.com/2/users/123456789/following"
  response = requests.post(url, auth=auth, json={"target_user_id": "2244994945"})
  print(response.json())
  ```

  ```python Python SDK
  from xdk import Client
  from xdk.oauth1_auth import OAuth1

  oauth1 = OAuth1(
      api_key="YOUR_API_KEY",
      api_secret="YOUR_API_SECRET",
      access_token="YOUR_ACCESS_TOKEN",
      access_token_secret="YOUR_ACCESS_TOKEN_SECRET"
  )

  client = Client(auth=oauth1)

  # 사용자를 팔로우합니다
  response = client.users.follow(
      source_user_id="123456789",
      target_user_id="2244994945"
  )
  print(f"Following: {response.data.following}")
  ```

  ```javascript JavaScript SDK
  import { Client, OAuth1 } from "@xdevplatform/xdk";

  const oauth1 = new OAuth1({
    apiKey: "YOUR_API_KEY",
    apiSecret: "YOUR_API_SECRET",
    accessToken: "YOUR_ACCESS_TOKEN",
    accessTokenSecret: "YOUR_ACCESS_TOKEN_SECRET",
  });

  const client = new Client({ oauth1 });

  // 사용자를 팔로우합니다
  const response = await client.users.follow("123456789", {
    targetUserId: "2244994945",
  });
  console.log(`Following: ${response.data?.following}`);
  ```
</CodeGroup>
