<div id="deduplication">
  ## 중복 제거
</div>

모든 리소스는 **UTC 기준 24시간(하루) 기간** 내에서 중복 제거됩니다. 어떤 리소스(예: 포스트)를 요청하여 과금이 발생한 후, 같은 기간 내에 동일한 리소스를 다시 요청하더라도 추가 요금이 부과되지 않습니다.

이는 다음을 의미합니다:

* 하루 동안 같은 포스트를 여러 번 요청해도 하나의 과금으로만 계산됩니다
* 중복 제거 기준 기간은 매일 UTC 자정에 초기화됩니다
* 이는 모든 과금 대상 리소스(포스트, 사용자 등)에 적용됩니다

<Note>
  중복 제거는 **완전하게 보장되는 것이 아닌 soft guarantee**입니다. 대부분의 경우에는 중복 제거가 이루어지지만, 서비스 중단과 같은 특정 예외 상황에서는 리소스가 중복 제거되지 않을 수 있습니다.
</Note>

<div id="credit-balance">
  ## 크레딧 잔액
</div>

크레딧 잔액은 Developer Console에 표시됩니다. API 요청을 보낼 때마다 크레딧이 실시간으로 차감됩니다.

<Warning>
  서비스 중단을 방지하려면 크레딧 잔액을 정기적으로 확인하세요. API 액세스를 중단 없이 유지하려면 잔액이 0이 되기 전에 크레딧을 추가하세요.

  ***참고:** 계정 크레딧 잔액이 소폭 마이너스가 될 수 있습니다. 이 경우 마이너스 잔액을 메울 만큼 크레딧을 추가할 때까지 API 요청이 차단됩니다.*
</Warning>

<div id="auto-recharge">
  ### 자동 충전
</div>

자동 충전을 활성화하면 크레딧 잔액이 자동으로 충전되어 서비스 중단을 방지할 수 있습니다. Developer Console에서 다음과 같이 설정하세요:

| Setting | Description |
|:--------|:------------|
| **Recharge amount** | 자동 충전이 실행될 때 추가로 결제될 금액 (예: $25) |
| **Trigger threshold** | 잔액이 이 금액 아래로 떨어지면 자동 충전이 실행되는 기준 금액 (예: $5) |

<Note>
  자동 충전을 사용하려면 기본 결제 수단이 저장되어 있고 기본값으로 설정되어 있어야 합니다. Developer Console에서 언제든지 취소하거나, 지원팀에 문의하여 취소할 수 있습니다.
</Note>

<div id="spending-limits">
  ### 지출 한도
</div>

비용을 관리하기 위해 청구 주기마다 사용할 최대 금액을 설정하세요. 한도에 도달하면 다음 청구 주기까지 API 요청이 차단됩니다.

| Option | Description |
|:-------|:------------|
| **Spending limit** | 청구 주기마다 허용되는 최대 지출 금액(달러 기준)을 설정합니다 |

<Tip>
  특히 개발 및 테스트 단계에서 예기치 않은 청구를 방지하기 위해 지출 한도를 설정해 두세요.
</Tip>

<div id="monitoring-usage">
  ## 사용량 모니터링
</div>

[Usage endpoint](/ko/x-api/usage/introduction)를 사용해 API 사용량을 프로그래밍 방식으로 추적하세요.

```bash
curl "https://api.x.com/2/usage/tweets" \
  -H "Authorization: Bearer $BEARER_TOKEN"
```

이는 일별 포스트 사용량 집계를 반환하여 다음과 같은 작업에 도움이 됩니다:

* 예산 대비 사용량 추적
* 한도에 근접했을 때 알림 설정
* 사용량이 많은 엔드포인트 식별
* 사용량 보고서 생성
