<div id="step-3-save-your-credentials">
  ## 3단계: 자격 증명 저장하기
</div>

인증 방식에 따라 여러 종류의 자격 증명을 받게 됩니다:

| Credential | Purpose |
|:-----------|:--------|
| **API Key &amp; Secret** | 앱을 식별합니다. 토큰을 생성하고 OAuth 1.0a 요청에 서명하는 데 사용됩니다. |
| **Bearer Token** | 공개 데이터를 읽기 위한 앱 전용 인증에 사용됩니다. |
| **Access Token &amp; Secret** | 본인 계정을 대신해 요청을 보낼 때 사용됩니다(OAuth 1.0a). |
| **Client ID &amp; Secret** | 사용자 컨텍스트 요청을 위한 OAuth 2.0 인증에 사용됩니다. |

<Warning>
  **즉시 저장하세요.** 자격 증명은 한 번만 표시됩니다. 비밀번호 관리자나 보안 금고에 보관하세요. 분실한 경우 다시 생성해야 하며, 이때 기존 자격 증명은 더 이상 유효하지 않습니다.
</Warning>

***

<div id="which-credentials-do-you-need">
  ## 어떤 자격 증명이 필요한가요?
</div>

<Tabs>
  <Tab title="공개 데이터 읽기">
    공개 데이터에 대한 단순 읽기 전용 액세스에는 **Bearer Token**을 사용합니다.

    ```bash
    curl "https://api.x.com/2/users/by/username/xdevelopers" \
      -H "Authorization: Bearer $BEARER_TOKEN"
    ```

    권장 용도: 포스트 검색, 사용자 조회, 트렌드 읽기.
  </Tab>

  <Tab title="사용자 대신 동작하기">
    사용자를 대신해 동작하려면 **OAuth 2.0**(권장) 또는 **OAuth 1.0a**를 사용합니다.

    OAuth 2.0은 세분화된 권한 스코프를 제공하므로, 필요한 권한만 요청할 수 있습니다.

    권장 용도: 포스트 작성, 좋아요, 팔로우, DM에 접근.

    [OAuth 2.0 가이드 →](/ko/resources/fundamentals/authentication/oauth-2-0/overview)
  </Tab>

  <Tab title="내 계정으로 동작하기">
    **Access Token &amp; Secret**을 사용해 자신의 계정으로 요청을 보냅니다.

    이 토큰들은 앱을 소유한 계정을 나타냅니다.

    권장 용도: 테스트, 개인용 봇, 나만의 자동화.
  </Tab>
</Tabs>
