X API v2는 모든 엔드포인트에 일관된 패턴이 적용되도록 설계되었습니다. 한 엔드포인트의 동작 방식을 이해하면 동일한 패턴을 어디서나 활용할 수 있습니다.

***

<div id="consistent-patterns">
  ## 일관된 패턴
</div>

<div id="url-structure">
  ### URL 구조
</div>

모든 v2 엔드포인트는 일정한 패턴을 따릅니다.

```
/version/resource/{id}?parameters
/version/resource/verb?parameters
```

예시:

```
/2/tweets/1234567890                    # Get a specific post
/2/tweets/search/recent                 # Search recent posts
/2/users/by/username/xdevelopers        # 사용자 이름으로 사용자 조회
/2/users/1234/followers                 # Get user's followers
```

<div id="response-structure">
  ### 응답 구조
</div>

모든 응답은 동일한 최상위 구조를 따릅니다:

```json
{
  "data": { ... },       // 기본 객체
  "includes": { ... },   // 확장된 객체
  "meta": { ... },       // 페이지네이션, 개수
  "errors": [ ... ]      // 부분 오류(있는 경우)
}
```

<div id="id-format">
  ### ID 형식
</div>

모든 id는 프로그래밍 언어 간 호환성을 보장하기 위해 문자열로 반환됩니다.

```json
{
  "id": "1234567890123456789",
  "author_id": "2244994945"
}
```

***

<div id="fields-and-expansions">
  ## 필드 및 expansions
</div>

동일한 [필드](/ko/x-api/fundamentals/fields) 및 [expansions](/ko/x-api/fundamentals/expansions) 파라미터를 일관된 방식으로 사용할 수 있습니다:

| 객체 | 필드 파라미터 | 적용 범위 |
|:-------|:-----------------|:-------------|
| 포스트 | `tweet.fields` | 포스트를 반환하는 모든 엔드포인트 |
| 사용자 | `user.fields` | 사용자를 반환하는 모든 엔드포인트 |
| 미디어 | `media.fields` | media expansions를 사용하는 모든 엔드포인트 |
| 투표 | `poll.fields` | poll expansions를 사용하는 모든 엔드포인트 |
| 장소 | `place.fields` | place expansions를 사용하는 모든 엔드포인트 |

***

<div id="object-schemas">
  ## Object schemas
</div>

같은 유형의 객체는 어느 엔드포인트에서 반환되든 항상 같은 필드를 가집니다:

* 검색(search) 엔드포인트에서 반환된 포스트는 조회(lookup) 엔드포인트에서 반환된 포스트와 동일한 필드를 가집니다
* 팔로워(followers) 엔드포인트에서 반환된 User는 검색(search) 엔드포인트에서 반환된 User와 동일한 필드를 가집니다
* 확장된 객체는 해당 객체를 단독으로 요청했을 때 반환되는 객체와 동일합니다

***

<div id="authentication">
  ## 인증
</div>

모든 엔드포인트에서 다음과 같은 인증 방식을 사용합니다:

| 방식 | 헤더 형식 |
|:-------|:--------------|
| Bearer Token | `Authorization: Bearer {token}` |
| OAuth 1.0a | `Authorization: OAuth {parameters}` |
| OAuth 2.0 | `Authorization: Bearer {user_token}` |

***

<div id="error-handling">
  ## 오류 처리
</div>

오류는 다음과 같은 일관된 형식을 따릅니다:

```json
{
  "title": "Invalid Request",
  "detail": "The query parameter is missing",
  "type": "https://api.x.com/2/problems/invalid-request"
}
```

[전체 오류 유형 보기 →](/ko/x-api/fundamentals/response-codes-and-errors)

<div id="pagination">
  ## 페이지네이션
</div>

페이지네이션이 가능한 모든 엔드포인트는 동일한 토큰 시스템을 사용합니다.

| 매개변수 | 설명 |
|:----------|:------------|
| `max_results` | 페이지당 결과 수 |
| `pagination_token` | `next_token` 또는 `previous_token`에서 받은 토큰 |

[페이지네이션에 대해 더 알아보기 →](/ko/x-api/fundamentals/pagination)

***

<div id="naming-conventions">
  ## 명명 규칙
</div>

* 미국식 영어 철자 사용 (`favorites`, `favourites`가 아님)
* 필드 이름에는 snake&#95;case 사용 (`author_id`, `created_at`)
* 용어를 일관되게 사용 (`retweet_count`, 필드에서는 `repost_count`를 사용하지 않음)

***

<div id="empty-values">
  ## 비어 있는 값
</div>

값이 없는 필드는 `null`로 반환되지 않고 응답에서 생략됩니다:

```json
// User without a bio
{
  "id": "1234",
  "name": "Example User",
  "username": "example"
  // "description"은 null이 아니라 생략됨
}
```

***

<div id="entity-consistency">
  ## 엔티티 일관성
</div>

`entities` 객체에는 텍스트에서 파싱된 엔티티만 포함합니다:

* `urls`
* `hashtags`
* `mentions`
* `cashtags`

미디어와 투표는 `entities`가 아니라 `attachments`에 포함됩니다.
