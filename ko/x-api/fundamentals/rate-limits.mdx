사용량 제한은 각 엔드포인트에 대해 보낼 수 있는 요청 수를 관리합니다. 제한을 초과하면 제한 시간 창이 재설정될 때까지 429 오류가 반환됩니다.

***

<div id="how-rate-limits-work">
  ## Rate limit 동작 방식
</div>

| 개념 | 설명 |
|:--------|:------------|
| **시간 창** | 보통 15분 또는 24시간 |
| **사용자별 한도** | OAuth 1.0a 또는 OAuth 2.0 사용자 토큰에 대해 적용 |
| **앱별 한도** | Bearer Token (app-only)에 대해 적용 |
| **엔드포인트별** | 각 엔드포인트마다 자체 한도가 있음 |

***

<div id="checking-your-limits">
  ## 요청 한도 확인
</div>

응답 헤더에는 현재 요청 한도 상태가 표시됩니다:

```
x-rate-limit-limit: 900
x-rate-limit-remaining: 847
x-rate-limit-reset: 1705420800
```

| Header                   | Description                  |
| :----------------------- | :--------------------------- |
| `x-rate-limit-limit`     | 허용되는 최대 요청 수                 |
| `x-rate-limit-remaining` | 현재 제한 윈도우에서 남은 요청 수          |
| `x-rate-limit-reset`     | 제한 윈도우가 초기화되는 시점의 Unix 타임스탬프 |

</div>

요청 한도에 도달하면 429 응답을 받게 됩니다:

```json
{
  "errors": [{
    "code": 88,
    "message": "Rate limit exceeded"
  }]
}
```

<div id="recovery-strategy">
  ### 복구 전략
</div>

1. 요청 한도 윈도우가 언제 초기화되는지 확인하기 위해 `x-rate-limit-reset` 값을 확인합니다.
2. 재시도하기 전에 해당 시점까지 대기합니다.
3. 필요하다면 지수 백오프를 사용합니다.

```python
import time

def make_request_with_backoff(url, headers):
    response = requests.get(url, headers=headers)
    
    if response.status_code == 429:
        reset_time = int(response.headers.get('x-rate-limit-reset', 0))
        wait_time = max(reset_time - time.time(), 60)
        time.sleep(wait_time)
        return make_request_with_backoff(url, headers)
    
    return response
```

<div id="rate-limits-vs-billing">
  ## 레이트 리밋과 과금
</div>

레이트 리밋과 과금은 서로 독립적입니다:

| 개념 | 목적 |
|:--------|:--------|
| **레이트 리밋** | 시스템 안정성을 위해 요청 빈도 제어 |
| **사용량 기반 과금** | 조회한 data 사용량에 따라 요금 청구 (사용량 기반 과금) |

레이트 리밋 내에서 요청하더라도 사용량 요금이 발생할 수 있고, 추가 요금 없이도 레이트 리밋에 도달할 수 있습니다.
