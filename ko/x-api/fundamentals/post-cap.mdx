X API v2는 **사용량 기반 종량제(pay-per-usage)** 과금 방식을 사용합니다. 앱 단위에서 추적되는 실제 API 사용량에 따라 과금됩니다.

***

<div id="how-billing-works">
  ## 과금 방식
</div>

| 개념 | 설명 |
|:--------|:------------|
| **크레딧 기반** | API 사용 시 차감되는 크레딧을 선불로 구매 |
| **요청 단위 과금** | 엔드포인트별로 요청 단가가 다름 |
| **실시간 추적** | 개발자 콘솔에서 사용량을 실시간으로 모니터링 |
| **한도 없음** | 월간 한도 없이 필요한 만큼 사용 가능 |

<div id="deduplication">
  ## 중복 제거
</div>

<Note>
  **일일 중복 제거**: 동일한 포스트가 하루 동안 여러 쿼리에서 반환되더라도, 과금에는 하루에 한 번만 반영됩니다.
</Note>

이는 다음을 의미합니다:

* 같은 포스트를 하루에 여러 번 조회 = 1회 과금
* 다음 날에 동일한 포스트를 다시 조회 = 추가 1회 과금
* 하나의 요청에 서로 다른 포스트 여러 개를 조회 = 각 포스트별로 별도 과금

  ## 사용량 모니터링
</div>

[개발자 콘솔](https://console.x.com)에서 사용량을 확인하세요:

| Metric | Description |
|:-------|:------------|
| **Total usage** | 청구 기간 동안 조회된 포스트 수 |
| **By endpoint** | 엔드포인트 유형별 사용량 세부 내역 |
| **By app** | 개발자 App별 사용량 |
| **Cost tracking** | 실시간 비용 계산 |
| **Credit balance** | 남은 선불 크레딧 잔액 |

<div id="pricing-details">
  ## 가격 세부 정보
</div>

엔드포인트와 작업별 최신 가격은 [개발자 콘솔](https://console.x.com)에서 확인하세요.

가격은 다음 요소에 따라 달라질 수 있습니다.

* 엔드포인트 유형(검색 vs. 조회 vs. 스트림)
* 작업(읽기 vs. 쓰기)
* 데이터 범위(최근 vs. 전체 아카이브)

<div id="faqs">
  ## 자주 묻는 질문
</div>

<Accordion title="크레딧을 모두 소진하면 어떻게 되나요?">
  더 많은 크레딧을 구매할 때까지 API 요청이 실패합니다. 중단을 방지하려면 잔액 알림을 설정하세요.
</Accordion>

<Accordion title="월 최소 사용량이 있나요?">
  없습니다. 사용한 만큼만 지불합니다. 사용량과 비용이 모두 0인 달이 있어도 됩니다.
</Accordion>

<Accordion title="스트리밍은 어떻게 과금되나요?">
  filtered stream을 통해 전달되는 각 고유 포스트는 일 단위 중복 제거 후 사용량으로 집계됩니다.
</Accordion>

<Accordion title="실패한 요청도 과금되나요?">
  아니요. `data`를 반환하는 성공한 응답만 과금됩니다.
</Accordion>
