X API v2는 **사용량 기반(pay-per-usage)** 요금제를 사용합니다. 실제 API 사용량에 따라 과금되며, 앱 단위로 사용량이 추적됩니다.

***

<div id="how-billing-works">
  ## 과금 방식
</div>

| 개념 | 설명 |
|:--------|:------------|
| **크레딧 기반** | 크레딧을 미리 구매해 두고, API를 사용할 때마다 차감됩니다 |
| **요청당 과금** | 엔드포인트마다 비용이 다릅니다 |
| **실시간 추적** | Developer Console에서 사용량을 모니터링합니다 |
| **한도 없음** | 월별 한도 없이 필요한 만큼 사용할 수 있습니다 |

<div id="deduplication">
  ## 중복 제거
</div>

<Note>
  **일별 중복 제거**: 동일한 포스트가 하루 동안 여러 쿼리에서 반환되더라도, 요금 청구 시에는 한 번만 과금됩니다.
</Note>

이는 다음을 의미합니다:

* 같은 포스트를 하루에 여러 번 조회 = 1회 과금
* 다음 날에 같은 포스트를 다시 조회 = 추가 1회 과금
* 한 요청에 서로 다른 포스트 여러 개가 포함된 경우 = 각 포스트별로 별도 과금

<div id="monitoring-usage">
  ## 사용량 모니터링
</div>

[Developer Console](https://console.x.com)에서 사용량을 모니터링하세요:

| Metric | Description |
|:-------|:------------|
| **Total usage** | 청구 기간 동안 조회된 포스트 수 |
| **By endpoint** | 엔드포인트 유형별 사용량 |
| **By app** | 개발자 App별 사용량 |
| **Cost tracking** | 실시간 비용 추적 |
| **Credit balance** | 잔여 선불 크레딧 |

<div id="pricing-details">
  ## 요금 세부 정보
</div>

엔드포인트 및 작업별 최신 요금은 [Developer Console](https://console.x.com)에서 확인하세요.

요금은 다음에 따라 달라질 수 있습니다.

* 엔드포인트 유형(검색 / 조회 / 스트림)
* 작업(읽기 / 쓰기)
* 데이터 범위(최근 / 전체 아카이브)

<div id="faqs">
  ## 자주 묻는 질문
</div>

<Accordion title="크레딧을 모두 사용하면 어떻게 되나요?">
  더 많은 크레딧을 구매할 때까지 API 요청은 실패하게 됩니다. 중단을 방지하려면 크레딧 잔액 알림을 설정하세요.
</Accordion>

<Accordion title="월 최소 사용량이 있나요?">
  없습니다. 사용한 만큼만 요금이 청구됩니다. 사용량과 비용이 0인 달이 있어도 됩니다.
</Accordion>

<Accordion title="스트리밍은 어떻게 과금되나요?">
  filtered stream을 통해 전송되는 각 고유한 포스트는 일 단위 중복 제거를 거쳐 사용량에 포함됩니다.
</Accordion>

<Accordion title="실패한 요청도 과금되나요?">
  아니요. data를 반환하는 성공한 응답만 요금이 청구됩니다.
</Accordion>
