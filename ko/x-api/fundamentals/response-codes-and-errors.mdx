X API는 표준 HTTP 상태 코드를 사용합니다. 성공적인 요청은 2xx 코드를 반환하고, 오류가 있는 요청은 응답 본문에 자세한 정보와 함께 4xx 또는 5xx 코드를 반환합니다.

***

<div id="http-status-codes">
  ## HTTP 상태 코드
</div>

<div id="success-codes">
  ### 성공 코드
</div>

| Code | Meaning | Description |
|:-----|:--------|:------------|
| **200** | OK | 요청 성공 |
| **201** | Created | 리소스 생성됨 (POST 요청) |
| **204** | No Content | 응답 본문 없이 성공 (DELETE 요청) |

<div id="client-error-codes">
  ### 클라이언트 오류 코드
</div>

| Code | 의미 | 일반적인 원인 |
|:-----|:--------|:--------------|
| **400** | 잘못된 요청 (Bad Request) | 잘못된 JSON, 형식이 잘못된 쿼리, 필수 매개변수 누락 |
| **401** | 인증 실패 (Unauthorized) | 잘못되었거나 누락된 인증 자격 증명 |
| **403** | 접근 거부 (Forbidden) | 인증은 유효하지만 이 리소스나 작업에 대한 권한이 없음 |
| **404** | 찾을 수 없음 (Not Found) | 리소스가 존재하지 않거나 삭제됨 |
| **409** | 충돌 (Conflict) | 스트림에 규칙이 없음 (필터링된 스트림에만 해당) |
| **429** | 요청이 너무 많음 (Too Many Requests) | 요청 제한(레이트 리밋) 또는 사용 한도 초과 |

<div id="server-error-codes">
  ### 서버 오류 코드
</div>

| 코드 | 의미 | 조치 |
|:-----|:--------|:-----------|
| **500** | 내부 서버 오류 | 잠시 기다렸다가 다시 시도하세요. [상태 페이지](/ko/status)를 확인하세요. |
| **502** | 잘못된 게이트웨이 | 잠시 기다렸다가 다시 시도하세요. |
| **503** | 서비스를 사용할 수 없음 | X에 과부하가 걸렸습니다. 잠시 기다렸다가 다시 시도하세요. |
| **504** | 게이트웨이 시간 초과 | 잠시 기다렸다가 다시 시도하세요. |

***

<div id="error-response-format">
  ## 오류 응답 형식
</div>

오류 응답에는 다음과 같은 구조화된 세부 정보가 포함됩니다:

```json
{
  "title": "Invalid Request",
  "detail": "The 'query' parameter is required.",
  "type": "https://api.x.com/2/problems/invalid-request"
}
```

| Field    | Description      |
| :------- | :--------------- |
| `type`   | 오류 유형을 식별하는 URI  |
| `title`  | 간단한 오류 설명        |
| `detail` | 이 오류에 대한 구체적인 설명 |

오류 유형에 따라 추가 필드가 있을 수 있습니다.

***

<div id="error-types">
  ## 오류 유형
</div>

| Type | Description |
|:-----|:------------|
| `about:blank` | 일반 오류 (HTTP 상태 코드를 참조하세요) |
| `.../invalid-request` | 잘못된 형식의 요청 또는 유효하지 않은 매개변수 |
| `.../resource-not-found` | 포스트, 사용자 또는 다른 리소스가 존재하지 않음 |
| `.../not-authorized-for-resource` | 비공개/보호된 콘텐츠에 대한 접근 권한 없음 |
| `.../client-forbidden` | 앱이 등록되지 않았거나 필요한 접근 권한이 없음 |
| `.../usage-capped` | 사용량 한도 초과 |
| `.../rate-limit-exceeded` | 요청 한도 초과 |
| `.../streaming-connection` | 스트림 연결 문제 |
| `.../rule-cap` | 필터링된 스트림 규칙이 너무 많음 |
| `.../invalid-rules` | 규칙 구문 오류 |
| `.../duplicate-rules` | 규칙이 이미 존재함 |

<div id="partial-errors">
  ## 부분 오류
</div>

일부 요청은 부분적으로 성공할 수 있습니다. 200 응답에는 `data`와 `errors`가 모두 포함될 수 있습니다:

```json
{
  "data": [
    {"id": "123", "text": "Hello"}
  ],
  "errors": [
    {
      "resource_id": "456",
      "resource_type": "tweet",
      "title": "Not Found Error",
      "detail": "Could not find tweet with id: [456].",
      "type": "https://api.x.com/2/problems/resource-not-found"
    }
  ]
}
```

여러 리소스를 요청하는 과정에서 그중 일부를 사용할 수 없는 경우에 발생합니다.

***

<div id="troubleshooting-common-errors">
  ## 일반적인 오류 문제 해결
</div>

<Accordion title="401 Unauthorized">
  **인증을 확인하세요:**

  * 해당 엔드포인트에 올바른 인증 방식을 사용하고 있는지 확인하세요
  * 자격 증명이 재생성되지 않았는지 확인하세요
  * `Authorization` 헤더 형식을 확인하세요
  * OAuth 1.0a의 경우, 서명 계산이 올바른지 검증하세요

  [인증 가이드 →](/ko/resources/fundamentals/authentication/overview)
</Accordion>

<Accordion title="403 Forbidden">
  **액세스를 확인하세요:**

  * 앱이 이 엔드포인트에 접근할 수 있는지 확인하세요
  * 일부 엔드포인트는 별도의 등록 또는 승인이 필요합니다
  * 사용자 컨텍스트 엔드포인트에는 적절한 OAuth 범위가 필요합니다
  * 리소스가 비공개이거나 보호 상태일 수 있습니다
</Accordion>

<Accordion title="429 Too Many Requests">
  **요청 한도 초과:**

  * 다시 시도할 시점을 확인하려면 `x-rate-limit-reset` 헤더를 확인하세요
  * 지수 백오프를 구현하세요
  * 응답을 캐싱하는 것을 고려하세요
  * 요청을 할당된 시간 구간 전체에 걸쳐 분산하세요

  [요청 한도(레이트 리밋) 가이드 →](/ko/x-api/fundamentals/rate-limits)
</Accordion>

<Accordion title="400 Bad Request">
  **요청을 수정하세요:**

  * JSON 구문을 검증하세요
  * 필수 매개변수가 누락되지 않았는지 확인하세요
  * 매개변수 유형(문자열 vs 숫자)을 검증하세요
  * 쿼리에서 특수 문자를 이스케이프 처리하세요
</Accordion>

<Accordion title="Missing expected posts">
  **다음 요소를 확인하세요:**

  * 보호된 계정의 포스트는 인증이 있어야만 볼 수 있습니다
  * 삭제된 포스트는 404를 반환합니다
  * 일부 포스트는 특정 지역에서 노출이 제한될 수 있습니다
  * 검색 쿼리 구문이 올바른지 확인하세요
</Accordion>

<Accordion title="Stream disconnections">
  **재연결 처리:**

  * 백오프와 함께 자동 재연결을 구현하세요
  * 누락된 데이터에 대해 복구 기능을 사용하세요
  * 버퍼가 가득 차 끊어진 것은 아닌지 확인하세요(클라이언트가 데이터를 충분히 빠르게 소비하지 않는 경우)
  * 최소 한 개 이상의 스트림 규칙이 존재하는지 확인하세요

  [스트리밍 가이드 →](/ko/x-api/posts/filtered-stream/integrate/handling-disconnections)
</Accordion>

<div id="rate-limit-headers">
  ## 요청 한도 헤더
</div>

각 응답에는 요청 한도 정보가 포함되어 있습니다:

```
x-rate-limit-limit: 900
x-rate-limit-remaining: 847
x-rate-limit-reset: 1705420800
```

| Header                   | Description                |
| :----------------------- | :------------------------- |
| `x-rate-limit-limit`     | 현재 시간 창에서 허용되는 최대 요청 수     |
| `x-rate-limit-remaining` | 남은 요청 수                    |
| `x-rate-limit-reset`     | 시간 창이 재설정되는 시점의 Unix 타임스탬프 |
