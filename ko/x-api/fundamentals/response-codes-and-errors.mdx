X API는 표준 HTTP 상태 코드를 사용합니다. 성공한 요청은 2xx대 상태 코드를 반환하고, 오류가 발생한 요청은 응답 본문에 세부 정보와 함께 4xx대 또는 5xx대 상태 코드를 반환합니다.

***

<div id="http-status-codes">
  ## HTTP 상태 코드
</div>

<div id="success-codes">
  ### 성공 코드
</div>

| Code | Meaning | Description |
|:-----|:--------|:------------|
| **200** | OK | 요청이 성공했습니다 |
| **201** | Created | 리소스가 생성되었습니다(POST 요청) |
| **204** | No Content | 응답 본문 없이 성공했습니다(DELETE 요청) |

<div id="client-error-codes">
  ### 클라이언트 오류 코드
</div>

| Code | 의미 | 일반적인 원인 |
|:-----|:--------|:--------------|
| **400** | 잘못된 요청 | 유효하지 않은 JSON, 형식이 잘못된 쿼리, 필수 매개변수 누락 |
| **401** | 인증되지 않음 | 잘못되었거나 누락된 인증 자격 증명 |
| **403** | 접근 거부 | 인증은 유효하지만 이 리소스나 작업에 대한 권한이 없음 |
| **404** | 찾을 수 없음 | 리소스가 존재하지 않거나 삭제됨 |
| **409** | 충돌 | 스트림에 규칙이 없음(필터링된 스트림에만 해당) |
| **429** | 요청 횟수 초과 | 요청 속도 제한 또는 사용량 한도 초과 |

<div id="server-error-codes">
  ### 서버 오류 코드
</div>

| Code | 의미 | 대응 방법 |
|:-----|:--------|:-----------|
| **500** | Internal Server Error | 잠시 기다린 후 다시 시도하고 [상태 페이지](/ko/status)를 확인하세요 |
| **502** | Bad Gateway | 잠시 기다린 후 다시 시도하세요 |
| **503** | Service Unavailable | X에 과부하가 걸렸습니다. 잠시 기다린 후 다시 시도하세요 |
| **504** | Gateway Timeout | 잠시 기다린 후 다시 시도하세요 |

***

<div id="error-response-format">
  ## 오류 응답 형식
</div>

오류 응답에는 다음과 같은 구조화된 세부 정보가 포함됩니다.

```json
{
  "title": "Invalid Request",
  "detail": "The 'query' parameter is required.",
  "type": "https://api.x.com/2/problems/invalid-request"
}
```

| 필드       | 설명               |
| :------- | :--------------- |
| `type`   | 오류 유형을 식별하는 URI  |
| `title`  | 간단한 오류 설명        |
| `detail` | 이 오류에 대한 구체적인 설명 |

오류 유형에 따라 추가 필드가 포함될 수 있습니다.

***

<div id="error-types">
  ## 오류 유형
</div>

| 유형 | 설명 |
|:-----|:------------|
| `about:blank` | 일반 오류 (HTTP 상태 코드를 참조하세요) |
| `.../invalid-request` | 형식이 잘못된 요청 또는 유효하지 않은 매개변수 |
| `.../resource-not-found` | 포스트, 사용자 또는 기타 리소스가 존재하지 않음 |
| `.../not-authorized-for-resource` | 비공개/보호된 콘텐츠에 대한 액세스 권한 없음 |
| `.../client-forbidden` | 앱이 등록되지 않았거나 필요한 액세스 권한이 없음 |
| `.../usage-capped` | 사용 한도를 초과함 |
| `.../rate-limit-exceeded` | 요청 한도(rate limit)를 초과함 |
| `.../streaming-connection` | 스트림 연결 문제 |
| `.../rule-cap` | 필터링된 스트림 규칙이 너무 많음 |
| `.../invalid-rules` | 규칙 구문 오류 |
| `.../duplicate-rules` | 규칙이 이미 존재함 |

<div id="partial-errors">
  ## 부분 오류
</div>

일부 요청은 부분적으로 성공할 수 있습니다. 200 응답에는 `data`와 `errors`가 모두 포함될 수 있습니다:

```json
{
  "data": [
    {"id": "123", "text": "Hello"}
  ],
  "errors": [
    {
      "resource_id": "456",
      "resource_type": "tweet",
      "title": "Not Found Error",
      "detail": "Could not find tweet with id: [456].",
      "type": "https://api.x.com/2/problems/resource-not-found"
    }
  ]
}
```

여러 리소스를 한 번에 요청했을 때 그중 일부를 사용할 수 없으면 이 오류가 발생합니다.

<div id="troubleshooting-common-errors">
  ## 일반적인 오류 문제 해결
</div>

<Accordion title="401 Unauthorized">
  **인증을 확인하세요:**

  * 엔드포인트에 맞는 올바른 인증 방식을 사용 중인지 확인하세요
  * 자격 증명이 다시 생성되지 않았는지 확인하세요
  * `Authorization` 헤더 형식을 확인하세요
  * OAuth 1.0a의 경우, 서명 계산이 올바른지 확인하세요

  [인증 가이드 →](/ko/resources/fundamentals/authentication/overview)
</Accordion>

<Accordion title="403 Forbidden">
  **접근 권한을 확인하세요:**

  * 앱이 이 엔드포인트에 접근할 수 있는지 확인하세요
  * 일부 엔드포인트는 별도 등록 또는 승인이 필요합니다
  * 사용자 컨텍스트 엔드포인트는 적절한 OAuth 스코프가 필요합니다
  * 리소스가 비공개이거나 보호 상태일 수 있습니다
</Accordion>

<Accordion title="429 Too Many Requests">
  **요청 한도 초과:**

  * 언제 다시 시도할 수 있는지 `x-rate-limit-reset` 헤더를 확인하세요
  * 지수 백오프를 구현하세요
  * 응답을 캐시하는 것을 고려하세요
  * 요청을 시간 구간 전체에 고르게 분산하세요

  [요청 제한 가이드 →](/ko/x-api/fundamentals/rate-limits)
</Accordion>

<Accordion title="400 Bad Request">
  **요청을 수정하세요:**

  * JSON 문법을 검증하세요
  * 누락된 필수 매개변수가 있는지 확인하세요
  * 매개변수 유형(문자열 vs. 숫자)을 검증하세요
  * 쿼리에서 특수 문자를 이스케이프하세요
</Accordion>

<Accordion title="Missing expected posts">
  **다음을 확인하세요:**

  * 보호된 계정의 포스트는 인증이 있어야만 볼 수 있습니다
  * 삭제된 포스트는 404를 반환합니다
  * 일부 포스트는 특정 지역에서 제한될 수 있습니다
  * 검색 쿼리 문법이 올바른지 확인하세요
</Accordion>

<Accordion title="Stream disconnections">
  **재연결 처리:**

  * 백오프를 사용해 자동 재연결을 구현하세요
  * 누락된 data를 복구하기 위한 기능을 활용하세요
  * 버퍼가 가득 차 끊어진 것인지 확인하세요(클라이언트가 충분히 빠르게 소비하지 못한 경우)
  * 최소 한 개 이상의 스트림 규칙이 존재하는지 확인하세요

  [스트리밍 가이드 →](/ko/x-api/posts/filtered-stream/integrate/handling-disconnections)
</Accordion>

<div id="rate-limit-headers">
  ## Rate limit 헤더
</div>

모든 응답에는 Rate limit 관련 정보가 포함됩니다.

```
x-rate-limit-limit: 900
x-rate-limit-remaining: 847
x-rate-limit-reset: 1705420800
```

| Header                   | 설명                          |
| :----------------------- | :-------------------------- |
| `x-rate-limit-limit`     | 현재 제한 구간에서 허용되는 최대 요청 수     |
| `x-rate-limit-remaining` | 남은 요청 수                     |
| `x-rate-limit-reset`     | 제한 구간이 초기화되는 시각(Unix 타임스탬프) |
