X API는 엔드포인트 경로에 버전 번호를 사용하여 변경에 유연하게 대응하면서도 안정성을 유지합니다. 당사의 버전 관리 전략을 이해하면 통합을 계획하고 최신 상태를 유지하는 데 도움이 됩니다.

***

<div id="current-versions">
  ## 현재 버전
</div>

| Version | Status | Description |
|:--------|:-------|:------------|
| **v2** | 현재 | 최신 엔드포인트, 유연한 요금제, 모든 신규 기능 제공 |
| **v1.1** | 레거시 | 제한적인 지원, 최소한의 업데이트 |
| **Enterprise** | 사용 가능 | 전용 지원이 포함된 대량 액세스 |

<Tip>
  새 프로젝트에는 항상 **X API v2**를 사용하세요. 새로운 기능은 모두 여기에서 제공됩니다.
</Tip>

***

<div id="version-in-urls">
  ## URL에서의 버전
</div>

버전 번호는 엔드포인트 경로에 표시됩니다:

```
https://api.x.com/2/tweets
                   ^
                   version
```

<div id="breaking-vs-non-breaking-changes">
  ## 호환성을 깨는 변경 vs. 호환성을 깨지 않는 변경
</div>

<div id="breaking-changes-require-code-updates">
  ### 호환성을 깨는(Breaking) 변경 사항 (코드 업데이트 필요)
</div>

다음 변경 사항은 메이저 버전 업그레이드 시에만 발생합니다:

* 엔드포인트 제거
* 응답 필드 제거
* 쿼리 파라미터 제거
* 새로운 필수 파라미터 추가
* 필드의 데이터 type 변경
* 필드 또는 리소스 이름 변경
* 응답 코드 또는 오류 type 변경
* 인가 범위 수정

<div id="non-breaking-changes-additive">
  ### 하위 호환성을 깨지 않는(추가적인) 변경
</div>

이러한 변경은 버전을 올리지 않고도 언제든지 발생할 수 있습니다:

* 새로운 endpoint 추가
* 새로운 선택적 파라미터 추가
* 새로운 응답 필드 추가
* 새로운 OAuth scope 추가
* 오류 메시지 텍스트 변경
* 프라이버시/보안상의 이유로 필드를 null로 설정

<div id="release-schedule">
  ## 릴리스 일정
</div>

| 유형 | 빈도 | 공지 |
|:-----|:----------|:-------|
| **메이저 버전** | 최대 연 1회 | 마이그레이션 가이드 제공 |
| **하위 호환성을 유지하는 변경** | 수시로 | 변경 로그 업데이트 |
| **보안 패치** | 필요 시 | 현재 버전에 적용될 수 있음 |

<div id="deprecation-policy">
  ## 사용 중단 정책
</div>

새로운 메이저 버전을 출시할 때:

1. **사용 중단(Deprecation)**: 이전 버전을 사용 중단 대상으로 지정합니다.
2. **지원 기간**: 사용 중단된 버전은 정해진 기간 동안 계속 지원됩니다.
3. **폐기(Retirement)**: 사용 중단된 버전이 제거됩니다.

<div id="definitions">
  ### 정의
</div>

| 상태 | 의미 |
|:-------|:--------|
| **Active** | 새 기능과 수정이 계속 제공되는, 완전히 지원되는 상태 |
| **Deprecated** | 새 기능은 제공되지 않고, 심각한 버그만 수정되며, 사용이 권장되지 않는 상태 |
| **Retired** | 더 이상 사용할 수 없는 상태 |
