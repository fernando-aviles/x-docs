X API는 엔드포인트 경로에 버전 번호를 포함해 API를 발전시키면서도 안정성을 보장합니다. 우리의 버전 관리 전략을 이해하면 통합을 계획하고 최신 상태를 유지하는 데 도움이 됩니다.

***

<div id="current-versions">
  ## 현재 버전
</div>

| 버전 | 상태 | 설명 |
|:--------|:-------|:------------|
| **v2** | 현재 | 최신 엔드포인트, 유연한 요금제, 모든 신규 기능 제공 |
| **v1.1** | 레거시 | 제한적인 지원, 최소한의 업데이트 |
| **Enterprise** | 제공 중 | 전용 지원이 포함된 대량 액세스 |

<Tip>
  새로운 프로젝트에는 **X API v2**를 사용하세요. 모든 신규 기능은 이 버전에 먼저 제공됩니다.
</Tip>

***

<div id="version-in-urls">
  ## URL에서의 버전
</div>

버전 번호는 엔드포인트 경로에 포함됩니다:

```
https://api.x.com/2/tweets
                   ^
                   version
```

<div id="breaking-vs-non-breaking-changes">
  ## 하위 호환성을 깨는 변경과 깨지 않는 변경
</div>

<div id="breaking-changes-require-code-updates">
  ### 비호환 변경 사항(코드 업데이트 필요)
</div>

이러한 변경 사항은 주요 버전 업그레이드 시에만 발생합니다.

* 엔드포인트 제거
* 응답 필드 제거
* 쿼리 매개변수 제거
* 새로운 필수 매개변수 추가
* 필드의 데이터 유형 변경
* 필드 또는 리소스 이름 변경
* 응답 코드 또는 오류 유형 변경
* 인가 스코프 수정

<div id="non-breaking-changes-additive">
  ### 호환성을 깨지 않는 변경(추가)
</div>

다음 변경은 버전 변경 없이도 언제든지 적용될 수 있습니다:

* 새 엔드포인트 추가
* 새 선택적 매개변수 추가
* 새 응답 필드 추가
* 새 OAuth 범위 추가
* 오류 메시지 텍스트 변경
* 개인정보 보호/보안상의 이유로 필드를 null로 설정

  ## 릴리스 일정
</div>

| 유형 | 빈도 | 공지 |
|:-----|:----------|:-------|
| **주요 버전** | 연 1회 이내 | 마이그레이션 가이드 제공 |
| **비호환성을 유발하지 않는 변경 사항** | 수시로 | 변경 로그 업데이트 |
| **보안 패치** | 필요 시 | 현재 버전에 적용될 수 있음 |

<div id="deprecation-policy">
  ## 사용 중단 정책
</div>

새로운 메이저 버전을 출시할 때는 다음과 같이 진행됩니다.

1. **사용 중단 공지**: 이전 버전은 사용 중단(deprecated) 상태로 지정됩니다
2. **지원 기간**: 사용 중단된 버전은 정해진 기간 동안 계속 지원됩니다
3. **사용 종료**: 사용 중단된 버전은 최종적으로 제거됩니다

<div id="definitions">
  ### 정의
</div>

| 상태 | 의미 |
|:-------|:--------|
| **Active** | 신규 기능과 수정 사항이 계속 제공됨 |
| **Deprecated** | 신규 기능 추가 없음, 치명적 버그만 수정, 사용 권장되지 않음 |
| **Retired** | 더 이상 사용할 수 없음 |
