X API는 지속적인 발전을 가능하게 하면서도 안정성을 제공하기 위해 엔드포인트 경로에 버전 번호를 사용합니다. 우리의 버전 관리 전략을 이해하면 통합을 계획하고 최신 상태를 유지하는 데 도움이 됩니다.

***

<div id="current-versions">
  ## 현재 버전
</div>

| Version | Status | Description |
|:--------|:-------|:------------|
| **v2** | 현재 | 최신 엔드포인트, 유연한 요금제, 모든 신규 기능 제공 |
| **v1.1** | 레거시 | 제한적인 지원, 최소한의 업데이트 |
| **Enterprise** | 사용 가능 | 전담 지원이 포함된 대량 액세스 |

<Tip>
  모든 신규 Project에는 **X API v2**를 사용하세요. 모든 신규 기능은 여기에 먼저 제공됩니다.
</Tip>

***

<div id="version-in-urls">
  ## URL에서의 버전
</div>

버전 번호는 엔드포인트 경로에 표시됩니다:

```
https://api.x.com/2/tweets
                   ^
                   version
```

<div id="breaking-vs-non-breaking-changes">
  ## 호환성 파괴 변경 vs. 비호환성 파괴 변경
</div>

<div id="breaking-changes-require-code-updates">
  ### 호환성을 깨는 변경 사항(코드 업데이트 필요)
</div>

이러한 변경 사항은 메이저 버전 업그레이드 시에만 발생합니다:

* 엔드포인트 삭제
* 응답 필드 삭제
* 쿼리 파라미터 삭제
* 새로운 필수 매개변수 추가
* 필드의 data 유형 변경
* 필드 또는 리소스 이름 변경
* 응답 코드 또는 오류 유형 변경
* 권한 스코프 수정

<div id="non-breaking-changes-additive">
  ### 비호환성을 발생시키지 않는 변경 사항(추가적 변경)
</div>

이러한 변경은 버전 변경 없이 언제든지 이루어질 수 있습니다:

* 새 엔드포인트 추가
* 새 선택적 매개변수 추가
* 새 응답 필드 추가
* 새 OAuth 범위 추가
* 오류 메시지 텍스트 변경
* 개인정보 보호/보안상의 이유로 필드를 null로 설정

  ## 릴리스 일정
</div>

| 유형 | 빈도 | 공지 |
|:-----|:----------|:-------|
| **메이저 버전** | 연 1회 이하 | 마이그레이션 가이드 제공 |
| **호환성을 깨뜨리지 않는 변경 사항** | 수시 | 변경 로그 업데이트 |
| **보안 패치** | 필요 시 | 현재 버전에 적용될 수 있음 |

<div id="deprecation-policy">
  ## 지원 중단 정책
</div>

새로운 메이저 버전을 출시할 때는 다음과 같이 진행됩니다.

1. **지원 중단 공지(Deprecation)**: 이전 버전을 지원 중단 대상 버전으로 지정합니다.
2. **지원 기간**: 지원 중단 대상 버전은 정해진 기간 동안 계속 사용할 수 있습니다.
3. **사용 중지(Retirement)**: 지원 중단 대상 버전은 더 이상 제공되지 않습니다.

<div id="definitions">
  ### 정의
</div>

| Status | 의미 |
|:-------|:--------|
| **Active** | 새로운 기능과 수정 사항이 계속 제공되어 완전히 지원되는 상태 |
| **Deprecated** | 새로운 기능은 제공되지 않고, 치명적인 버그만 수정되며 사용이 권장되지 않는 상태 |
| **Retired** | 더 이상 사용할 수 없는 상태 |
