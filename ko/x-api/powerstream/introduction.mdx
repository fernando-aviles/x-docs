Powerstream은 공개 X 데이터에 접근하기 위한 가장 빠른 실시간 스트리밍 API입니다. 레거시 GNIP Powetrack API와 마찬가지로, Powerstream은 키워드, 연산자, 메타데이터를 기반으로 포스트를 필터링하는 규칙(rules)을 사용합니다. Powerstream 엔드포인트에 지속적인 HTTP 연결을 수립하면, 거의 실시간에 가까운 속도로 규칙과 일치하는 포스트를 수신할 수 있습니다.

현재 Powerstream은 최대 1,000개의 규칙을 지원하며, 각 규칙의 길이는 최대 2048자입니다.

<div id="key-features">
  ## 주요 기능:
</div>

* **실시간 data 전송**: 규칙과 일치하는 data를 거의 실시간으로 받아볼 수 있습니다.
* **정밀한 필터링**: 연산자가 포함된 불리언 쿼리를 사용해 원하는 data만 정확하게 필터링할 수 있습니다.
* **전달 방식**: HTTP/1.1 청크 전송 인코딩을 사용하는 JSON 응답.
* **로컬 데이터 센터 지원**: 복제 지연을 피하여 지연 시간을 줄이기 위해 로컬 데이터 센터의 포스트만 가져옵니다.

<Note>
  Powerstream API는 일부 Enterprise 요금제에서 제공되는 프리미엄 기능입니다.

  Powerstream 사용을 원하시거나 Enterprise 제품에 대해 더 자세히 알고 싶으시다면, [Enterprise Request Form](/ko/forms/enterprise-api-interest)을 제출해 영업팀에 문의해 주세요.
  Powerstream이 귀하의 요구 사항을 어떻게 지원할 수 있는지 함께 논의하겠습니다.
</Note>

<div id="quick-start">
  ## 빠른 시작
</div>

이 섹션에서는 Python과 `requests` 라이브러리를 사용해 PowerStream 엔드포인트를 빠르게 사용하는 방법을 보여줍니다. `pip install requests`로 설치하세요. 모든 예제는 OAuth 2.0 Bearer Token 인증을 사용합니다. `YOUR_BEARER_TOKEN`을 실제 토큰으로 바꿔 넣으세요(예: `os.getenv('BEARER_TOKEN')`를 통해 안전하게 보관).

각 엔드포인트를 코드 스니펫과 함께 살펴봅니다. 파일 상단에 다음과 같은 import 문이 있다고 가정합니다:

```python
import requests
import json
import time
import sys
import os  # 환경 변수용
```

<div id="setup">
  ### 설정
</div>

```python
bearer_token = os.getenv('BEARER_TOKEN') or "YOUR_BEARER_TOKEN"  # 보안을 위해 환경 변수 사용
base_url = "https://api.x.com/2/powerstream"
rules_url = f"{base_url}/rules"  # 규칙 관리용
headers = {
   "Authorization": f"Bearer {bearer_token}",
   "Content-Type": "application/json"
}
```

<div id="1-create-rules-post-rules">
  ### 1. 규칙 생성 (POST /rules)
</div>

스트림을 필터링하는 규칙을 추가합니다.

```python
data = {
   "rules": [
       {
           "value": "(cat OR dog) lang:en -is:retweet",
           "tag": "pet-monitor"
       },
       # 필요에 따라 규칙 추가 (최대 100개)
   ]
}

response = requests.post(rules_url, headers=headers, json=data)
if response.status_code == 201:
   rules_added = response.json().get("data", {}).get("rules", [])
   print("Rules added:")
   for rule in rules_added:
       print(f"ID: {rule['id']}, Value: {rule['value']}, Tag: {rule.get('tag', 'N/A')}")
else:
   print(f"Error {response.status_code}: {response.text}")
```

<div id="2-delete-rules-post-rules">
  ### 2. 규칙 삭제 (POST /rules)
</div>

id(권장) 또는 value를 기준으로 규칙을 삭제합니다.

```python
data = {
   "rules": [
       {
           "value": "(cat OR dog) lang:en -is:retweet",
           "tag": "pet-monitor"
       },
       # 필요에 따라 규칙을 추가하세요 (최대 100개)
   ]
}

response = requests.delete(rules_url, headers=headers, json=data)
if response.status_code == 200:
   deleted = response.json().get("data", {})
   print(f"Deleted count: {deleted.get('deleted', 'N/A')}")
   if 'not_deleted' in deleted:
       print("Not deleted:", deleted['not_deleted'])
else:
   print(f"Error {response.status_code}: {response.text}")
```

**팁**: 모든 규칙을 삭제하려면, 먼저 GET 요청으로 규칙을 가져온 다음 ID를 추출해 한 번에 삭제하세요.

<div id="3-get-rules-get-rules">
  ### 3. 규칙 조회 (GET /rules)
</div>

모든 활성 규칙을 조회합니다.

```python
response = requests.get(rules_url, headers=headers)
if response.status_code == 200:
   rules = response.json().get("data", {}).get("rules", [])
   if rules:
       print("Active rules:")
       for rule in rules:
           print(f"ID: {rule['id']}, Value: {rule['value']}, Tag: {rule.get('tag', 'N/A')}")
   else:
       print("No active rules.")
else:
   print(f"Error {response.status_code}: {response.text}")
```

<div id="4-powerstream-get-stream">
  ### 4. PowerStream (GET /stream)
</div>

실시간 포스트를 수신하기 위해 스트림에 연결하세요. 한 줄씩 읽으려면 `stream=True`를 사용하세요. 견고성을 위해 재연결 로직을 구현하세요.

```python
stream_url = base_url

def main():
   while True:
       response = requests.request("GET", stream_url, headers=headers, stream=True)
       print(response.status_code)
       for response_line in response.iter_lines():
           if response_line:
               json_response = json.loads(response_line)
               print(json.dumps(json_response, indent=4, sort_keys=True))
               if response.status_code != 200:
                   print(response.headers)
                   raise Exception(
                       "Request returned an error: {} {}".format(
                           response.status_code, response.text
                       )
                   )
```

<div id="local-datacenter-support">
  #### 로컬 데이터센터 지원
</div>

지연 시간 최적화를 위해 Powerstream은 연결이 설정된 로컬 데이터센터에서 생성된 포스트만 가져오도록 선택할 수 있는 옵션을 제공합니다. 이렇게 하면 복제 지연을 피할 수 있어, 다른 데이터센터에서 온 포스트보다 더 빠르게 전달됩니다. 이를 활성화하려면 스트림 엔드포인트에 `?localDcOnly=true` 쿼리 매개변수를 추가합니다(예: `/2/powerstream?localDcOnly=true`). 연결된 데이터센터는 스트림의 초기 data 페이로드와 응답의 HTTP 헤더 모두에 표시됩니다.

코드에서 사용하려면:

```python
# 로컬 데이터센터 전용:
stream_url = "https://api.x.com/2/powerstream?localDcOnly=true"
```

`localDcOnly` 매개변수가 활성화된 경우, 스트림이 처음 연결될 때 어떤 로컬 데이터센터를 사용 중인지 나타내는 다음과 같은 응답 헤더가 포함됩니다:

```bash
'x-powerstream-datacenter': 'atla',
'x-powerstream-localdconly': 'true'
```

이와 더불어 데이터센터를 지정하는 초기 페이로드도 함께 전송합니다.

```bash
{
    "type": "connection_metadata",
    "datacenter": "atla",
    "timestamp": 1762557264155
}
```

<Note>
  **팁:** 지연 시간을 최적화하려면 서로 다른 지리적 위치(예: 미국 동부 해안 애틀랜타 인근, 미국 서부 해안 포틀랜드 인근)에 각각 연결을 설정하고, 각 연결에 `localDcOnly=true`를 설정하세요. 이렇게 하면 각 데이터센터의 포스트에 더 빠르게 액세스할 수 있습니다. 데이터센터 간 data를 결합하기 위해, 스트림을 애플리케이션 측에서 집계하세요.
</Note>

</div>

필터링 규칙을 설정할 때 키워드와 연산자를 사용할 수 있습니다. 아래에서 사용 가능한 연산자 목록을 확인하세요.

<div id="field-based-operators">
  ### 필드 기반 연산자
</div>

<div id="user-operators">
  #### 사용자 연산자
</div>

| 연산자 | 요약 | 예시 |
|----------|---------|---------|
| `from:` | 특정 사용자가 작성한 포스트와 일치 | `from:xdevelopers` 또는 `from:123456` |
| `to:` | 특정 사용자에게 보낸 포스트와 일치 | `to:jvaleski` |
| `retweets_of:` | 특정 사용자의 포스트를 리포스트한 포스트와 일치 | `retweets_of:xdevelopers` |

<div id="content-operators">
  #### 콘텐츠 연산자
</div>

| Operator | Summary | Example |
|----------|---------|---------|
| `contains:` | 특정 텍스트/키워드를 포함하는 포스트를 검색합니다 | `contains:hello` 또는 `contains:-2345.432` |
| `url_contains:` | URL에 특정 텍스트가 포함된 포스트를 검색합니다 | `url_contains:"com/willplayforfood"` |
| `lang:` | 특정 언어의 포스트를 검색합니다 | `lang:en` |

<div id="entity-operators">
  #### 엔터티 연산자
</div>

| Operator | Summary | Example |
|----------|---------|---------|
| `has:` | 특정 엔터티를 포함하는 포스트를 검색합니다 (옵션: mentions, geo, links, media, lang, symbols, images, videos) | `has:images`, `has:geo`, `has:mentions` |
| `is:` | 특정 유형이거나 특정 속성을 가진 포스트를 검색합니다 (옵션: retweet, reply) | `is:retweet`, `is:reply` |

<div id="location-operators">
  #### 위치 연산자
</div>

| 연산자 | 요약 | 예시 |
|----------|---------|---------|
| `place:` | 특정 장소/위치에서 작성된 포스트와 일치 | `place:"Belmont Central"`, `place:02763fa2a7611cf3` |
| `bounding_box:` | 지정된 지리적 경계 박스 내의 포스트와 일치 | `bounding_box:[-112.424083 42.355283 -112.409111 42.792311]` |
| `point_radius:` | 특정 지점을 중심으로 한 반경 내의 포스트와 일치 | `point_radius:[-111.464973 46.371179 25mi]`, `point_radius:[-111.464973 46.371179 15km]` |

<div id="limits-best-practices">
  ## 제한 사항 및 모범 사례
</div>

* 요청 제한: 규칙 관리의 경우 24시간당 50개의 요청, 스트림에는 제한 없음(단, 연결 제한은 적용됨).
* 재연결: 연결이 끊어졌을 때 지수 백오프 전략을 사용합니다.
* 모니터링: `Connection: keep-alive` 헤더를 사용합니다.
