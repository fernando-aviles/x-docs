이 가이드는 포스트 조회 엔드포인트를 애플리케이션에 통합하는 데 필요한 핵심 개념을 다룹니다.

***

<div id="authentication">
  ## 인증
</div>

모든 X API v2 엔드포인트는 인증이 필요합니다. 사용 사례에 가장 적합한 방법을 선택하세요:

| 방식 | 적합한 용도 | 비공개 메트릭에 접근 가능 여부 |
|:-------|:---------|:---------------------------|
| [OAuth 2.0 앱 전용](/ko/resources/fundamentals/authentication#oauth-2-0) | 서버 간 통신, 공개 데이터 | 아니요 |
| [PKCE를 사용하는 OAuth 2.0 Authorization Code](/ko/resources/fundamentals/authentication#oauth-2-0-authorization-code-flow-with-pkce-2) | 사용자 대상 앱 | 예 (권한이 부여된 사용자의 포스트) |
| [OAuth 1.0a User Context](/ko/resources/fundamentals/authentication) | 레거시 통합 | 예 (권한이 부여된 사용자의 포스트) |

<div id="app-only-authentication">
  ### App-Only 인증
</div>

공개 포스트 데이터에 액세스하려면 Bearer Token을 사용합니다:

<CodeGroup dropdown>
  ```bash cURL
  curl "https://api.x.com/2/tweets/1234567890" \
    -H "Authorization: Bearer $BEARER_TOKEN"
  ```

  ```python Python SDK
  from xdk import Client

  client = Client(bearer_token="YOUR_BEARER_TOKEN")

  # ID로 단일 포스트 가져오기
  response = client.posts.get("1234567890")
  print(response.data)
  ```

  ```javascript JavaScript SDK
  import { Client } from "@xdevplatform/xdk";

  const client = new Client({ bearerToken: "YOUR_BEARER_TOKEN" });

  const response = await client.posts.get("1234567890");
  console.log(response.data);
  ```
</CodeGroup>

<div id="user-context-authentication">
  ### User Context 인증
</div>

비공개 메트릭에 액세스하려면 포스트 작성자를 대신해 인증해야 합니다.

<Warning>
  다음 필드에는 User Context 인증이 필요합니다.

  * `tweet.fields.non_public_metrics`
  * `tweet.fields.promoted_metrics`
  * `tweet.fields.organic_metrics`
  * `media.fields.non_public_metrics`
  * `media.fields.promoted_metrics`
  * `media.fields.organic_metrics`
</Warning>

<div id="fields-and-expansions">
  ## 필드와 expansions
</div>

X API v2는 기본적으로 최소한의 data만 반환합니다. 필요한 항목만 정확히 요청하려면 `fields`와 `expansions`를 사용하세요.

<div id="default-response">
  ### 기본 응답
</div>

```json
{
  "data": {
    "id": "1234567890",
    "text": "Hello world!",
    "edit_history_tweet_ids": ["1234567890"]
  }
}
```

<div id="available-fields">
  ### 사용 가능한 필드
</div>

<Accordion title="tweet.fields">
  | 필드 | 설명 |
  |:------|:------------|
  | `created_at` | 포스트 생성 타임스탬프 |
  | `author_id` | 작성자의 사용자 id |
  | `public_metrics` | 좋아요, 리트윗, 답글, 인용 수 |
  | `entities` | 해시태그, 멘션, URL, 캐시태그 |
  | `attachments` | 미디어 키, 투표 id |
  | `conversation_id` | 스레드 식별자 |
  | `context_annotations` | 토픽/엔터티 분류 정보 |
  | `in_reply_to_user_id` | 답글 대상 사용자 |
  | `lang` | 감지된 언어 |
  | `source` | 포스트를 게시한 클라이언트 |
  | `possibly_sensitive` | 민감한 콘텐츠 여부 플래그 |
  | `reply_settings` | 누가 답글을 달 수 있는지 설정 |
</Accordion>

<Accordion title="user.fields (author_id 확장 필요)">
  | 필드 | 설명 |
  |:------|:------------|
  | `username` | @핸들 |
  | `name` | 표시 이름 |
  | `profile_image_url` | 아바타 URL |
  | `verified` | 인증 상태 |
  | `description` | 프로필 소개 |
  | `public_metrics` | 팔로워/팔로잉 수 |
  | `created_at` | 계정 생성 날짜 |
</Accordion>

<Accordion title="media.fields (attachments.media_keys 확장 필요)">
  | 필드 | 설명 |
  |:------|:------------|
  | `url` | 미디어 URL |
  | `preview_image_url` | 썸네일 URL |
  | `type` | photo, video, animated&#95;gif |
  | `duration_ms` | 동영상 길이 |
  | `height`, `width` | 크기 |
  | `alt_text` | 접근성 텍스트 |
</Accordion>

<div id="example-with-fields">
  ### 필드 사용 예제
</div>

<CodeGroup dropdown>
  ```bash cURL
  curl "https://api.x.com/2/tweets/1234567890?\
  tweet.fields=created_at,public_metrics,entities&\
  expansions=author_id,attachments.media_keys&\
  user.fields=username,verified&\
  media.fields=url,type" \
    -H "Authorization: Bearer $BEARER_TOKEN"
  ```

  ```python Python SDK
  from xdk import Client

  client = Client(bearer_token="YOUR_BEARER_TOKEN")

  # 추가 필드와 expansions를 포함한 포스트 가져오기
  response = client.posts.get(
      "1234567890",
      tweet_fields=["created_at", "public_metrics", "entities"],
      expansions=["author_id", "attachments.media_keys"],
      user_fields=["username", "verified"],
      media_fields=["url", "type"]
  )

  print(response.data)
  print(response.includes)  # 확장된 사용자 및 미디어 객체를 포함합니다
  ```

  ```javascript JavaScript SDK
  import { Client } from "@xdevplatform/xdk";

  const client = new Client({ bearerToken: "YOUR_BEARER_TOKEN" });

  const response = await client.posts.get("1234567890", {
    tweetFields: ["created_at", "public_metrics", "entities"],
    expansions: ["author_id", "attachments.media_keys"],
    userFields: ["username", "verified"],
    mediaFields: ["url", "type"],
  });

  console.log(response.data);
  console.log(response.includes); // 확장된 사용자 및 미디어 객체를 포함합니다
  ```
</CodeGroup>

<div id="post-edits">
  ## 포스트 수정
</div>

포스트는 생성된 시점으로부터 30분 이내에 최대 5회까지 수정할 수 있습니다.

<div id="how-it-works">
  ### 작동 방식
</div>

* 각 편집은 새로운 포스트 ID를 생성합니다
* `edit_history_tweet_ids`에는 모든 버전이 포함됩니다(가장 오래된 것부터)
* 해당 엔드포인트는 항상 가장 최신 버전을 반환합니다

<div id="example-response">
  ### 응답 예시
</div>

```json
{
  "data": {
    "id": "1234567893",
    "text": "Hello world! (edited twice)",
    "edit_history_tweet_ids": [
      "1234567890",
      "1234567891",
      "1234567893"
    ]
  }
}
```

<Tip>
  30분 편집 가능 시간이 지난 뒤에 조회한 포스트는 최종 버전입니다. 실시간 사용 사례에서는 최근에 게시된 포스트가 아직 편집 중일 수 있다는 점에 유의하세요.
</Tip>

<div id="error-handling">
  ## 오류 처리
</div>

<div id="common-errors">
  ### 일반적인 오류
</div>

| Status | Error | Solution |
|:-------|:------|:---------|
| 400 | 잘못된 요청 | 매개변수 형식을 확인하세요 |
| 401 | 인증되지 않음 | 인증 자격 정보를 확인하세요 |
| 403 | 권한 없음 | 앱 권한을 확인하세요 |
| 404 | 찾을 수 없음 | 포스트가 삭제되었거나 존재하지 않습니다 |
| 429 | 요청 한도 초과 | 잠시 기다린 후 다시 시도하세요 (요청 한도(rate limit) 참고) |

<div id="deleted-or-protected-posts">
  ### 삭제되었거나 보호된 포스트
</div>

포스트가 삭제되었거나, 사용자가 팔로우하지 않는 보호된 계정의 포스트인 경우:

* 단일 포스트 조회 시 `404`를 반환합니다
* 다중 포스트 조회 시 결과에서 해당 포스트를 제외하고 `errors` 배열을 포함합니다

```json
{
  "data": [
    { "id": "1234567890", "text": "Available post" }
  ],
  "errors": [
    {
      "resource_id": "1234567891",
      "resource_type": "tweet",
      "title": "Not Found Error",
      "detail": "Could not find tweet with id: [1234567891]."
    }
  ]
}
```
