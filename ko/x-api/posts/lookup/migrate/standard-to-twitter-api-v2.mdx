<div id="standard-v11-compared-to-x-api-v2">
  ## Standard v1.1과 X API v2 비교
</div>

기존에 standard v1.1에서 GET statuses/show 및 GET statuses/lookup을 사용해 왔다면, 이 가이드는 standard v1.1과 X API v2 포스트 조회 엔드포인트 간의 유사점과 차이점을 이해하는 데 도움을 줄 것입니다.

[X API v1.1 데이터 포맷](/ko/x-api/fundamentals/data-dictionary)과 [X API v2 포맷](/ko/x-api/fundamentals/data-dictionary)의 차이를 빠르게 확인하는 데 도움이 되는 [시각적 데이터 포맷 마이그레이션 도구](/ko/x-api/migrate/data-format-migration)도 참고할 수 있습니다.

* **유사점**
  * OAuth 1.0a User Context
  * 요청당 포스트 수 제한
  * 포스트 수정 이력 및 메타데이터 지원

* **차이점**
  * 엔드포인트 URL
  * 앱 및 Project 요구 사항
  * 응답 data 포맷
  * 요청 파라미터

<div id="similarities">
  ### 공통점
</div>

<div id="oauth-10a-user-context-authentication-method">
  #### OAuth 1.0a User Context 인증 방식
</div>

표준 엔드포인트는 [OAuth 1.0a User Context](/ko/resources/fundamentals/authentication)를 지원하며, 새로운 X API v2 포스트 조회 엔드포인트는 OAuth 1.0a User Context와 [OAuth 2.0 App-Only](/ko/resources/fundamentals/authentication)를 모두 지원합니다. 따라서 이전에 표준 v1.1 포스트 조회 엔드포인트 중 하나를 사용하고 있었다면, X API v2 버전으로 마이그레이션하더라도 동일한 인증 방식을 계속 사용할 수 있습니다.

App-Only 인증은 시작할 때 사용하기 가장 쉬운 방식일 가능성이 큽니다. 앱 액세스 토큰을 생성하는 방법을 알아보려면 [이 OAuth 2.0 App-Only 가이드](/ko/resources/fundamentals/authentication)를 참조하세요.

<div id="posts-per-request-limits">
  #### 요청당 포스트 수 제한
</div>

v1.1 [GET statuses/lookup](https://developer.x.com/en/docs/twitter-api/v1/tweets/post-and-engage/api-reference/get-statuses-lookup) 엔드포인트에서는 한 요청당 최대 100개의 포스트를 지정할 수 있습니다. 이는 GET /tweets 엔드포인트에도 동일하게 적용됩니다. 최대치인 100개의 포스트를 지정하려면 `ids` 매개변수를 쿼리 매개변수로 사용하고, 쉼표로 구분된 [포스트 ID](/ko/resources/fundamentals/x-ids) 목록을 전달하세요.

**포스트 편집 이력 및 메타데이터 지원**

두 버전 모두 편집 이력을 설명하는 메타데이터를 제공합니다. 자세한 내용은 포스트 조회 API 레퍼런스와 [포스트 편집 기본 사항 페이지](/ko/x-api/fundamentals/edit-posts)를 참고하세요.

<div id="differences">
  ### 차이점
</div>

<div id="endpoint-urls">
  #### 엔드포인트 URL
</div>

* **표준 v1.1 엔드포인트:**
  * `https://api.x.com/1.1/statuses/show`
  * `https://api.x.com/1.1/statuses/lookup`

* **X API v2 엔드포인트:**
  * `https://api.x.com/2/tweets`
  * `https://api.x.com/2/tweets/:id`

<div id="app-and-project-requirements">
  #### App 및 Project 요구 사항
</div>

X API v2 엔드포인트는 인증을 위해 [Project](/ko/resources/fundamentals/developer-apps)에 속한 [개발자 App](/ko/resources/fundamentals/developer-apps)의 자격 증명이 필요합니다. X API v1.1 엔드포인트는 App의 자격 증명 또는 App과 연결된 App의 자격 증명을 사용할 수 있습니다.

<div id="response-data-format">
  #### 응답 데이터 형식
</div>

표준 v1.1과 X API v2 엔드포인트 버전 간의 중요한 차이점 중 하나는 페이로드에서 필드를 선택하는 방식입니다.

표준 엔드포인트의 경우, 많은 응답 필드가 기본적으로 포함되며, 매개변수를 사용해 추가 필드를 지정할 수 있는 옵션이 제공됩니다.

반면 X API v2는 기본적으로 포스트 `id` 및 `text` 필드만 제공합니다. 추가 필드와 객체를 받으려면 [fields](/ko/x-api/fundamentals/fields) 및 [expansions](/ko/x-api/fundamentals/expansions) 매개변수를 사용해야 합니다. expansions로 확장된 항목은 응답 내의 `includes` 객체에 포함되어 반환되며, ID를 매칭하여 기본 포스트 객체와 연결할 수 있습니다.

fields 및 expansions 사용에 대한 자세한 내용은 [fields 및 expansions 사용 방법 가이드](/ko/x-api/fundamentals/data-dictionary)를 참고하세요. 또한 [데이터 형식 마이그레이션 가이드](/ko/x-api/fundamentals/fields)에서는 표준 v1.1 필드를 새로운 v2 필드에 매핑합니다.

또한 X API v2는 포스트 및 [user](/ko/x-api/fundamentals/data-dictionary#user) 객체를 포함한 여러 객체에 대해 새로운 JSON 설계를 도입합니다:

* 표준 엔드포인트는 포스트 객체를 `statuses` 배열로 반환하는 반면, X API v2는 `data` 배열을 사용합니다.
* X API v2에서는 리트윗 및 인용 트윗이 &quot;statuses&quot;라는 용어를 대체합니다.
* `like`와 같은 새로운 용어가 `favorites` 및 `favourites` 같은 용어를 대체합니다.
* 값이 없는 속성(예: `null`)은 X API v2 페이로드에 포함되지 않습니다.

X API v2의 포스트 객체에는 다음과 같은 새로운 필드가 포함됩니다:

* `conversation_id`
* 두 개의 새로운 [annotations](/ko/x-api/fundamentals/post-annotations) 필드 (`context` 및 `entities`)
* 새로운 [metrics](/ko/x-api/fundamentals/metrics) 필드
* 특정 포스트에 누가 답글을 달 수 있는지를 나타내는 `reply_setting` 필드

<div id="request-parameters">
  #### 요청 매개변수
</div>

다음 표는 표준 v1.1 요청 매개변수와 X API v2에서의 대응 매개변수를 보여줍니다.

| Standard | X API v2 |
|:----------|:----------|
| `id`     | `ids`    |

일부 표준 v1.1 매개변수는 X API v2에서 **지원되지 않습니다**:

| Standard            | Comment                                                                                                                      |
|:---------------------|:------------------------------------------------------------------------------------------------------------------------------|
| `tweet_mode`        | fields 및 expansions 기능으로 대체되었습니다.                                                                                |
| `trim_user`         | fields 및 expansions로 대체되었습니다. 사용자 데이터에는 `author_id` expansion과 `user.fields`를 사용하세요.                |
| `include_my_retweet`| 인증된 사용자가 리트윗한 포스트의 원본 포스트 ID를 제공합니다.                                                               |
| `include_entities`  | 페이로드 내 엔티티를 제어하기 위해 fields 및 expansions를 사용하세요.                                                       |
| `include_ext_alt_text` | alt 텍스트가 있는 경우 media 엔티티에 `ext_alt_text` 필드를 추가합니다.                                                  |
| `include_card_uri`  | 광고 카드가 첨부된 경우 `card_uri`를 추가합니다.                                                                            |
| `map`               | v1.1에서 필드가 null 처리되는 것과 달리, X API v2에서는 사용할 수 없는 포스트에 대해 포스트 ID와 오류 메시지를 반환합니다. |

<div id="code-examples">
  ### 코드 예제
</div>

다음 예제는 표준 v1.1 엔드포인트와 해당 v2 엔드포인트를 보여줍니다. 자격 증명은 실제 토큰으로 교체해 사용하세요. v2 엔드포인트의 경우, 토큰은 [Project](/ko/resources/fundamentals/developer-apps/overview) 내 [developer App](/ko/resources/fundamentals/developer-apps/overview)에 속해야 합니다.

v1.1의 응답 페이로드는 v2와 다릅니다. v2에서는 [fields](/ko/x-api/fundamentals/fields) 및 [expansions](/ko/x-api/fundamentals/expansions) 파라미터로 다양한 필드를 요청할 수 있습니다.

**다중 포스트 조회: v1.1 `GET statuses/lookup` → v2 `GET /tweets`**

<CodeGroup dropdown>
  ```bash cURL (v1.1)
  curl --request GET \
    --url 'https://api.x.com/1.1/statuses/lookup.json?id=1460323737035677698%2C1460323743339741184' \
    --header 'Authorization: Bearer $ACCESS_TOKEN'
  ```

  ```bash cURL (v2)
  curl --request GET \
    --url 'https://api.x.com/2/tweets?ids=1460323737035677698%2C1460323743339741184&tweet.fields=created_at&expansions=author_id&user.fields=created_at' \
    --header 'Authorization: Bearer $ACCESS_TOKEN'
  ```

  ```python Python (v2)
  import requests

  bearer_token = "YOUR_BEARER_TOKEN"
  url = "https://api.x.com/2/tweets"

  params = {
      "ids": "1460323737035677698,1460323743339741184",
      "tweet.fields": "created_at",
      "expansions": "author_id",
      "user.fields": "created_at"
  }

  headers = {"Authorization": f"Bearer {bearer_token}"}
  response = requests.get(url, headers=headers, params=params)

  print(response.json())
  ```

  ```python Python SDK
  from xdk import Client

  client = Client(bearer_token="YOUR_BEARER_TOKEN")

  # fields 및 expansions를 사용해 여러 포스트를 ID로 가져오기
  response = client.posts.get_posts(
      ids=["1460323737035677698", "1460323743339741184"],
      tweet_fields=["created_at"],
      expansions=["author_id"],
      user_fields=["created_at"]
  )

  for post in response.data:
      print(f"Post: {post.text}")
      print(f"Created at: {post.created_at}")
  ```

  ```javascript JavaScript SDK
  import { Client } from "@xdevplatform/xdk";

  const client = new Client({ bearerToken: "YOUR_BEARER_TOKEN" });

  // fields 및 expansions를 사용해 여러 포스트를 ID로 가져오기
  const response = await client.posts.getPosts({
    ids: ["1460323737035677698", "1460323743339741184"],
    tweetFields: ["created_at"],
    expansions: ["author_id"],
    userFields: ["created_at"],
  });

  response.data?.forEach((post) => {
    console.log(`Post: ${post.text}`);
    console.log(`Created at: ${post.created_at}`);
  });
  ```
</CodeGroup>
