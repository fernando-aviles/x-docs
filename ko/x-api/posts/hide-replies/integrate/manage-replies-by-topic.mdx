<div id="manage-replies-by-topic">
  ### 주제별 답글 관리
</div>

hide replies 엔드포인트를 통해 사용자와 브랜드가 대화를 주제에 맞게 유지하도록 돕는 통합을 구축할 수 있습니다. 이 페이지에서는 hide replies 엔드포인트와 [recent search](/ko/x-api/posts/recent-search) 엔드포인트를 사용해 대화를 관리하는 방법을 설명합니다.

recent search는 하나의 대화와 해당 답글을 조회할 수 있는 기능을 제공하며, 포스트 페이로드는 각 포스트의 문맥과 주제를 언어와 상관없이 이해하는 데 도움이 되는 [Post annotations](/ko/x-api/fundamentals/post-annotations) 를 반환합니다.

앱의 플로우에는 대화를 표시하고 관리하기 위한 컨트롤이 포함됩니다:

1. 사용자의 포스트를 읽고 답글을 관리할 수 있도록 사용자에게 권한을 요청합니다.

2. 포스트 URL에서 최근 대화를 가져오고, 그 대화가 현재 인증된 사용자의 것인지 확인합니다.

3. 대화 내 각 포스트를 표시하기 위해 recent search 엔드포인트를 호출합니다. 요청에는 conversation ID 검색 쿼리와 annotation 확장을 포함해, X의 해석에 따라 해당 포스트가 스포츠 관련인지 여부를 판별합니다.

4. 사용자가 선택할 때 답글을 숨기도록 hide replies를 호출합니다. 또한 사용자가 항상 제어권을 가질 수 있도록, 이 작업을 취소할 수 있는 방법도 제공합니다. 

5. 더 긴 대화의 경우, [검색 결과를 페이지네이션](/ko/x-api/posts/search/integrate/paginate)할 수 있는 컨트롤을 제공합니다.
    

<div id="optimize-for-the-user-and-for-usage">
  #### 사용자(와 사용 패턴)에 맞게 최적화하기
</div>

사용자가 수행하려는 모든 작업을 스스로 제어할 수 있도록 플로우를 설계할 수 있습니다. 이 원칙을 염두에 두면 포스트 소비를 최적화할 수 있는 통합을 구축하는 데에도 도움이 됩니다.

1. 인증된 사용자는 자신이 시작한 대화만 관리할 수 있으므로, 그렇지 않은 경우에는 플로우를 조기에 종료해야 합니다.
   * 초기 포스트 조회 요청을 보냅니다. 포스트 URL이 유효하지 않거나 대화를 인증된 사용자가 시작하지 않은 경우, 플로우를 조기에 종료합니다.
   * 이렇게 하면, 인증된 사용자가 해당 대화를 관리할 수 없는 경우 앱이 recent search 요청을 수행하지 않아도 됩니다.
2. 별도의 요청을 만들지 않도록 동일한 요청에서 [user 및 포스트 필드](/ko/x-api/fundamentals/fields)를 함께 요청합니다. 이 방식은 앱의 성능을 향상시키는 데에도 도움이 될 수 있습니다.
3. 불필요한 요청은 피하십시오. 이 앱은 답글의 숨김 상태를 사용자의 브라우저에 캐시합니다. 이는 사용자가 나중에 모더레이션 작업을 이어가고자 할 수 있는 대규모 대화에서 유용하며, 앱이 답글 숨기기/숨기기 해제 요청을 최적화하는 데에도 도움이 됩니다.
