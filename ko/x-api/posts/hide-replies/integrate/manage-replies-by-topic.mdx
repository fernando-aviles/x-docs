<div id="manage-replies-by-topic">
  ### 주제별로 답글 관리하기
</div>

hide replies 엔드포인트를 통해 사람과 브랜드가 대화를 주제에 맞게 유지하도록 돕는 통합 기능을 구축할 수 있습니다. 이 페이지에서는 hide replies와 [recent search](/ko/x-api/posts/recent-search) 엔드포인트를 사용해 대화를 관리하는 방법을 설명합니다.

recent search는 하나의 대화와 그 답글들을 조회하는 기능을 제공하며, Post 페이로드는 각 포스트의 맥락과 주제를 언어와 관계없이 이해하는 데 도움이 되는 [Post annotations](/ko/x-api/fundamentals/post-annotations)을 반환합니다.

앱의 플로우에는 대화를 표시하고 관리하기 위한 제어 기능이 포함됩니다.

1. 사용자의 포스트를 읽고 그에 대한 답글을 관리할 수 있도록 사용자에게 권한을 요청합니다.

2. 포스트 URL에서 최근 대화를 가져와, 그 대화가 인증된 사용자로부터 생성된 것인지 확인합니다.

3. recent search 엔드포인트를 호출해 대화에 포함된 각 포스트를 표시합니다. 요청에는 대화 ID 검색 쿼리와 annotation 확장이 포함되며, 이를 통해 X가 해석한 기준에 따라 포스트가 스포츠 관련인지 여부를 판별합니다.

4. 사용자가 선택할 경우 답글을 숨기기 위해 Hide replies를 호출합니다. 또한 사용자가 항상 제어권을 가질 수 있도록 이 동작을 되돌릴 수 있는 방법도 제공합니다. 

5. 더 긴 대화의 경우, [검색 결과를 페이지 단위로 탐색](/ko/x-api/posts/search/integrate/paginate)할 수 있는 제어 기능을 제공합니다.
    

<div id="optimize-for-the-user-and-for-usage">
  #### 사용자(와 사용량)을 최적화하세요
</div>

사용자가 수행하려는 모든 작업을 직접 제어할 수 있도록 플로우를 설계할 수 있습니다. 이 원칙을 염두에 두면 포스트 소비를 최적화할 수 있는 통합 기능을 구축하는 데에도 도움이 됩니다.

1. 인증된 사용자는 자신이 시작한 대화만 관리할 수 있으므로, 그렇지 않은 경우에는 플로우를 조기에 종료해야 합니다.
   * 초기 포스트 조회 요청을 수행합니다. 포스트 URL이 유효하지 않거나, 대화를 인증된 사용자가 시작하지 않은 경우 플로우를 조기에 종료합니다.
   * 이렇게 하면, 인증된 사용자가 해당 대화를 모더레이션할 수 없는 경우 앱이 최근 검색 요청을 수행하지 않아도 됩니다.
2. 별도의 요청을 보내지 않도록, 동일한 요청에서 [user 및 포스트 필드](/ko/x-api/fundamentals/fields)를 함께 요청하세요. 이 방식은 앱 성능을 향상시키는 데에도 도움이 됩니다.
3. 필요하지 않을 때는 요청을 보내지 마세요. 이 앱은 사용자의 브라우저에 답글의 숨김 상태를 캐시합니다. 이는 사용자가 나중에 모더레이션을 이어가고 싶어 할 수 있는 규모가 큰 대화에서 유용하며, 앱이 답글을 숨기거나 다시 표시하기 위한 요청을 최적화하는 데 도움이 됩니다.
