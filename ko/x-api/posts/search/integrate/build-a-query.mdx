검색 엔드포인트는 GET 요청으로 단일 쿼리를 입력받아, 해당 쿼리와 일치하는 과거 포스트들의 집합을 반환합니다. 쿼리는 다양한 포스트 속성과 일치하는 연산자들로 구성됩니다.

***

<div id="query-limitations">
  ## 쿼리 제한 사항
</div>

사용 중인 [액세스 레벨](/ko/x-api/getting-started/about-x-api)에 따라 쿼리 길이에 제한이 적용됩니다:

| 액세스 레벨 | 최근 검색 | 전체 아카이브 검색 |
| :--- | :--- | :--- |
| 셀프 서비스 | 512자 | 1,024자 |
| 엔터프라이즈 | 4,096자 | 4,096자 |

***

<div id="operator-availability">
  ## 연산자 사용 가능 여부
</div>

대부분의 연산자는 모든 개발자가 사용할 수 있지만, 일부는 특정 액세스 수준에만 제한됩니다.

* **코어 연산자:** 모든 [Project](/ko/resources/fundamentals/developer-apps)에서 사용 가능
* **고급 연산자:** 특정 액세스 수준이 부여된 Project에서 사용 가능

사용 가능 여부에 대한 자세한 내용은 전체 [연산자 목록](/ko/x-api/posts/search/integrate/operators)을 참고하세요.

***

<div id="operator-types-standalone-and-conjunction-required">
  ## 연산자 유형: 단독 사용 및 결합 필수
</div>

**단독 연산자(standalone operators)**는 단독으로 사용할 수도 있고, (결합이 필요한 연산자를 포함해) 다른 어떤 연산자와 함께 사용할 수도 있습니다.

예를 들어, 이 쿼리는 `#hashtag`가 단독 연산자이기 때문에 유효합니다.

```
#xapiv2
```

**연결자 필수 연산자**는 쿼리에서 단독으로 사용할 수 없습니다. 하나 이상의 단독 연산자가 함께 포함된 경우에만 사용할 수 있습니다. 이는 이러한 연산자만 단독으로 사용하면 매우 많은 포스트가 매칭되기 때문입니다.

예를 들어, 다음 쿼리는 연결자 필수 연산자만 포함하고 있으므로 **지원되지 않습니다**:

```
has:media
```

```
has:links OR is:retweet
```

`"X data"`와 같은 단독 연산자를 추가하면 쿼리가 정상적으로 동작합니다.

```
"X data" has:mentions (has:media OR has:links)
```

***

<div id="boolean-operators-and-grouping">
  ## 부울 연산자와 그룹화
</div>

다음 도구들을 사용해 여러 연산자를 연결할 수 있습니다:

| Operator | Description | Example |
| :--- | :--- | :--- |
| **AND** (space) | 포스트는 두 조건을 모두 만족해야 합니다 | `snow day #NoSchool`은 &quot;snow&quot; AND &quot;day&quot; AND #NoSchool이 포함된 포스트와 일치합니다 |
| **OR** | 포스트는 조건 중 하나만 만족해도 됩니다 | `grumpy OR cat OR #meme`은 &quot;grumpy&quot; OR &quot;cat&quot; OR #meme이 포함된 포스트와 일치합니다 |
| **NOT** (dash) | 이 조건과 일치하는 포스트를 제외합니다 | `cat #meme -grumpy`는 &quot;cat&quot;과 #meme은 포함하지만 &quot;grumpy&quot;는 포함하지 않는 포스트와 일치합니다 |
| **Grouping** (parentheses) | 연산자를 하나의 그룹으로 묶습니다 | `(grumpy cat) OR (#meme has:images)`는 두 그룹 중 하나와 일치합니다 |

<Note>
  **부정 연산에 대한 참고 사항**

  * 연산자 `-is:nullcast`는 항상 부정형으로 사용해야 합니다
  * 부정된 연산자는 단독으로 사용할 수 없습니다
  * 그룹화된 연산자 전체를 부정하지 마십시오. `skiing -(snow OR day OR noschool)` 대신 `skiing -snow -day -noschool`을 사용하십시오
</Note>

***

<div id="order-of-operations">
  ## 연산 순서
</div>

AND와 OR을 함께 사용할 때:

1. AND 조건으로 연결된 연산자가 먼저 평가됩니다
2. 그다음 OR 조건으로 연결된 연산자가 적용됩니다

**예시:**

| Query                    | Evaluated as               |
| :----------------------- | :------------------------- |
| `apple OR iphone ipad`   | `apple OR (iphone ipad)`   |
| `ipad iphone OR android` | `(iphone ipad) OR android` |

모호성을 없애기 위해 괄호를 사용하세요:

```
(apple OR iphone) ipad
```

```
iphone (ipad OR android)
```

***

<div id="punctuation-diacritics-and-case-sensitivity">
  ## 문장 부호, 발음 구별 부호, 대소문자 구분
</div>

**발음 구별 부호(Diacritics):** 악센트나 발음 구별 부호가 포함된 검색 쿼리는 악센트가 있는 포스트와 없는 포스트 모두와 일치합니다. 예를 들어, `Diacrítica`는 &#95;Diacrítica&#95;와 *Diacritica* 모두와 일치합니다.

**대소문자 구분:** 모든 연산자는 대소문자를 구분하지 않습니다. 쿼리 `cat`은 *cat*, *CAT*, 그리고 *Cat* 모두와 일치합니다.

<Note>
  **Filtered stream은 다르게 동작합니다**

  [Filtered stream 규칙을 구성](/ko/x-api/posts/filtered-stream/integrate/build-a-rule)할 때, 악센트가 있는 키워드는 악센트가 포함된 포스트에만 일치합니다. 예를 들어, `Diacrítica`는 &#95;Diacrítica&#95;에만 일치하고 &#95;Diacritica&#95;에는 일치하지 않습니다.
</Note>

***

<div id="quote-tweet-matching">
  ## 인용 트윗 매칭
</div>

Search Posts를 사용할 때, 연산자는 인용 트윗의 내용에는 일치하지만 인용된 원본 포스트의 내용에는 **일치하지 않습니다**.

<Note>
  [필터링된 스트림](/ko/x-api/posts/filtered-stream/introduction)은 다르게 동작하며, 인용 트윗과 원본 포스트의 내용 모두에 대해 일치 여부를 검사합니다.
</Note>

***

<div id="specificity-and-efficiency">
  ## 구체성과 효율성
</div>

<Warning>
  단일 키워드나 해시태그처럼 범위가 넓은 operator를 사용하는 것은 권장하지 않습니다. 이렇게 하면 매우 많은 포스트와 일치하여 사용 한도를 빠르게 소모하게 됩니다.
</Warning>

**효과적인 쿼리를 작성하기 위한 팁:**

1. **처음에는 구체적으로, 그다음 범위를 확장** — 관련성 높은 결과를 반환하는 타깃 쿼리부터 만드세요
2. **여러 operator를 사용** — operator를 조합해 결과를 좁히세요
3. **문자 수를 확인** — 전체 쿼리 문자열이 한도에 포함됩니다

**예시 단계:**

```
# Too broad - 200,000+ Posts per day
happy

# Better - adds language filter and exclusions
(happy OR happiness) lang:en -birthday -is:retweet

# 더욱 개선됨 - 59자, 더 구체적임
(happy OR happiness) place_country:GB -birthday -is:retweet
```

<div id="iteratively-building-a-query">
  ## 쿼리를 단계적으로 작성하기
</div>

<div id="step-1-start-with-a-basic-query">
  ### 1단계: 기본 쿼리부터 시작하기
</div>

```
happy OR happiness
```

<div id="step-2-test-and-narrow-based-on-results">
  ### 2단계: 결과를 기반으로 테스트하고 범위를 좁히기
</div>

여러 언어로 작성된 포스트가 많았습니다. 언어 필터를 추가하세요:

```
(happy OR happiness) lang:en
```

생일 축하 인사가 들어오고 있습니다. 이런 생일 축하 인사와 리트윗은 제외하세요:

```
(happy OR happiness) lang:en -birthday -is:retweet
```

<div id="step-3-broaden-for-better-coverage">
  ### 3단계: 범위를 넓혀 커버리지 향상하기
</div>

더 많은 감정을 포착하려면 관련 키워드를 추가하세요:

```
(happy OR happiness OR excited OR elated) lang:en -birthday -is:retweet
```

<div id="step-4-adjust-for-trends">
  ### 4단계: 트렌드에 맞게 조정
</div>

휴일 관련 포스트가 나타납니다. 이를 제외해 보겠습니다:

```
(happy OR happiness OR excited OR elated) lang:en -birthday -is:retweet -holidays
```

<div id="adding-a-query-to-your-request">
  ## 요청에 쿼리 추가하기
</div>

`query` 매개변수를 사용해 쿼리를 HTTP로 인코딩하세요:

```bash
curl "https://api.x.com/2/tweets/search/recent?\
query=cat%20has%3Amedia%20-grumpy&\
tweet.fields=created_at&\
max_results=100" \
  -H "Authorization: Bearer $BEARER_TOKEN"
```

<div id="query-examples">
  ## 쿼리 예제
</div>

<div id="tracking-a-natural-disaster">
  ### 자연재해 추적
</div>

허리케인 Harvey와 관련된 기상 기관의 포스트를 매칭합니다:

**쿼리:**

```
has:geo (from:NWSNHC OR from:NHC_Atlantic OR from:NWSHouston OR from:NWSSanAntonio OR from:USGS_TexasRain OR from:USGS_TexasFlood OR from:JeffLindner1) -is:retweet
```

**전체 요청 URL:**

```
https://api.x.com/2/tweets/search/recent?query=has%3Ageo%20(from%3ANWSNHC%20OR%20from%3ANHC_Atlantic%20OR%20from%3ANWSHouston%20OR%20from%3ANWSSanAntonio%20OR%20from%3AUSGS_TexasRain%20OR%20from%3AUSGS_TexasFlood%20OR%20from%3AJeffLindner1)%20-is%3Aretweet
```

<div id="sentiment-analysis-for-nowplaying">
  ### #nowplaying에 대한 감성 분석
</div>

**긍정적인 감성:**

```
#nowplaying (happy OR exciting OR excited OR favorite OR fav OR amazing OR lovely OR incredible) (place_country:US OR place_country:MX OR place_country:CA) -horrible -worst -sucks -bad -disappointing
```

**부정적 감성:**

```
#nowplaying (horrible OR worst OR sucks OR bad OR disappointing) (place_country:US OR place_country:MX OR place_country:CA) -happy -exciting -excited -favorite -fav -amazing -lovely -incredible
```

<div id="using-post-annotations">
  ### 포스트 주석 사용하기
</div>

`context:` 연산자를 사용해, 이미지가 포함된 일본어 포스트 중에서 반려동물(고양이는 제외)에 대한 것을 찾아보세요:

먼저 [포스트 조회](/ko/x-api/posts/lookup/introduction)를 사용해 `tweet.fields=context_annotations`로 domain.entity ID를 식별합니다:

* 고양이: `domain` 66, `entity` 852262932607926273
* 반려동물: `domain` 65, `entity` 852262932607926273

**쿼리:**

```
context:65.852262932607926273 -context:66.852262932607926273 -is:retweet has:images lang:ja
```
