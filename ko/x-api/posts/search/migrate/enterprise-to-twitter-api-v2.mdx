<div id="enterprise-compared-to-x-api-v2">
  ### 엔터프라이즈와 X API v2 비교
</div>

**유사점**

* 페이지네이션
* 시간대
* 포스트 편집 기록 및 메타데이터 지원

**차이점**

* 엔드포인트 URL
* 앱 및 Project 요건
* 지원되는 기간
* 응답 데이터 형식
* HTTP 메서드
* 요청 시간 형식
* 요청 매개변수
* 필터링 연산자

<div id="similarities">
  #### 유사점
</div>

**페이지네이션**

v2에는 `since_id` 및 `until_id`로 포스트 ID를 사용해 탐색할 수 있게 해 주는 새로운 페이지네이션 매개변수 등 추가 페이지네이션 기능이 있지만, 엔터프라이즈와 v2 모두 시간(`fromDate`와 `toDate`는 엔터프라이즈, `start_time`과 `end_time`은 v2)을 사용한 페이지네이션을 지원합니다.
 

**시간대**

페이지네이션 섹션에서 언급했듯이, 엔터프라이즈와 v2 모두에서 시간을 사용해 서로 다른 페이지의 data를 탐색할 수 있습니다. 두 경우 모두 이러한 매개변수를 사용할 때는 UTC를 기준 시간대로 사용해야 합니다.

**포스트 수정 이력 및 메타데이터 지원**

두 버전 모두 수정 이력을 설명하는 메타데이터를 제공합니다. 자세한 내용은 [검색 API 레퍼런스](/ko/x-api/posts/recent-search)와 [포스트 수정 기본 사항 페이지](/ko/x-api/fundamentals/edit-posts)를 참고하세요. 

<div id="differences">
  #### 차이점
</div>

**엔드포인트 URL**

* Enterprise 엔드포인트:
  * 30일 - `http://gnip-api.x.com/search/30day/accounts/:account_name/:label.json`
  * 전체 보관(Full-archive) - `http://gnip-api.x.com/search/fullarchive/accounts/:account_name/:label.json`
* X API v2 엔드포인트
  * 최근(7일) - `https://api.x.com/2/tweets/search/recent`
  * 전체 보관(Full-archive) - `https://api.x.com/2/tweets/search/all`

**App 및 Project 요구 사항**

X API v2 엔드포인트는 요청을 인증할 때 Project에서 발급된 자격 증명을 사용해야 합니다. 모든 X API v1.1 엔드포인트는 App 또는 App에 연결된 App의 자격 증명을 사용할 수 있습니다.
 

**사용 가능한 기간**

Enterprise API와 X API v2 모두 전체 보관 포스트에 대해 필터링된 포스트 데이터를 조회할 수 있는 엔드포인트를 제공합니다.

하지만 X API v2는 Enterprise API와 같이 30일 기간 엔드포인트를 제공하지 않습니다. 대신 앞에서 언급한 전체 보관 엔드포인트 또는 7일 기간 엔드포인트를 제공하며, 이는 Native Enriched to v2 및 [Activity Streams to v2](/ko/x-api/migrate/data-format-migration#migrating-from-activity-streams-data-format-to-v2)와 일치합니다. 이를 통해 Enterprise 필드를 최신 v2 필드에 매핑하는 데 도움이 됩니다. 이 가이드는 또한 특정 필드를 반환하기 위해 v2 요청에 함께 전달해야 하는 구체적인 fields 및 expansions 파라미터도 제공합니다.
 

**응답 데이터 형식**

[Enterprise 응답 형식](https://developer.x.com/x-api/enterprise-gnip-2.0/fundamentals/data-dictionary)과 [X API v2 형식](/ko/x-api/fundamentals/data-dictionary)의 가장 큰 차이점 중 하나는 payload에 어떤 필드를 반환할지 선택하는 방식입니다.

Enterprise Search API의 경우, 많은 응답 필드를 기본적으로 제공하며, 그 후 파라미터를 사용해 payload에 어떤 필드 또는 필드 집합을 반환할지 지정할 수 있습니다.

X API v2 버전은 기본적으로 포스트 `id` 및 `text` 필드만 제공합니다. 추가 필드나 객체를 요청하려면 [fields](/ko/x-api/fundamentals/fields) 및 [expansions](/ko/x-api/fundamentals/expansions) 파라미터를 사용해야 합니다. 이 엔드포인트에서 요청한 모든 포스트 필드는 기본 포스트 객체에 포함되어 반환됩니다. 확장된 사용자, 미디어, 설문조사(poll), 장소(place) 객체 및 필드는 응답 내 `includes` 객체에 포함되어 반환됩니다. 그런 다음 포스트와 확장된 객체 양쪽에 있는 ID를 매칭하여 확장된 객체를 포스트 객체와 다시 연결할 수 있습니다.

이러한 새로운 파라미터에 대해서는 각 가이드나 [fields 및 expansions 사용 방법](/ko/x-api/fundamentals/data-dictionary#how-to-use-fields-and-expansions) 가이드를 참고해 자세히 확인할 수 있습니다.

특정 필드를 요청하는 방식의 변경뿐 아니라, X API v2는 API가 반환하는 객체에 대해 새로운 JSON 설계 방식을 도입하고 있으며, 여기에는 [Post](/ko/x-api/fundamentals/data-dictionary#tweet) 및 [user](/ko/x-api/fundamentals/data-dictionary#user) 객체가 포함됩니다.

* JSON 루트 레벨에서, 표준 엔드포인트는 포스트 객체를 `statuses` 배열로 반환하지만, X API v2는 `data` 배열로 반환합니다.
* 리트윗(Retweeted) 및 인용(Quoted) &quot;statuses&quot;를 참조하는 대신, X API v2 JSON은 리트윗된 및 인용된 트윗을 참조합니다. `contributors`, `user.translator_type`와 같은 많은 레거시 및 사용 중단 필드는 제거됩니다.
* `favorites`(Post 객체)와 `favourites`(user 객체)를 모두 사용하는 대신, X API v2는 &quot;like&quot;라는 용어를 사용합니다.
* X는 값이 없는 JSON 값(예: `null`)은 payload에 기록하지 않는 방식을 채택하고 있습니다. 포스트 및 user 속성은 null이 아닌 값을 가질 때에만 포함됩니다.
   

또한 포스트 객체에 다음과 같은 새로운 필드들도 도입했습니다.

* [conversation&#95;id](/ko/x-api/fundamentals/conversation-id) 필드
* context 및 entities를 포함하는 두 개의 새로운 [annotations](/ko/x-api/fundamentals/post-annotations) 필드
* 여러 개의 새로운 [metrics](/ko/x-api/fundamentals/metrics) 필드
* 특정 포스트에 누가 답글을 달 수 있는지 표시하는 새로운 `reply_setting` 필드

마지막으로 한 가지 더 있습니다. Premium 응답에는 루트 레벨에 `requestParameters` 객체가 포함되어 있으며, 여기에 요청에 포함한 파라미터가 들어 있습니다. v2 버전에는 대신 루트 레벨에 `meta` 객체가 포함되며, 여기에는 추가 결과 페이지가 있을 경우 `newest_id`, `oldest_id`, `result_count`, `next_token`이 포함됩니다.

**HTTP 메서드**

엔터프라이즈 버전의 API에서는 JSON 본문을 포함한 POST HTTP 메서드 또는 쿼리 문자열을 포함한 GET HTTP 메서드 중 하나로 요청을 보낼 수 있습니다.

v2에서는 쿼리 문자열을 포함한 GET HTTP 메서드만 사용할 수 있습니다.
 

**요청 시간 형식**

이 엔드포인트의 엔터프라이즈 버전은 페이지네이션 매개변수와 `timePeriod` 응답 필드 모두에서 다음과 같은 날짜/시간 형식을 사용합니다: `YYYYMMDDHHmm`

v2 엔드포인트는 페이지네이션 매개변수와 `start` 및 `end` 응답 필드 모두에서 ISO 8601/RFC 3339 날짜/시간 형식을 사용합니다: `YYYY-MM-DDTHH:mm:ssZ
 `

**요청 매개변수**

다음은 엔터프라이즈와 X API v2의 요청 매개변수를 정리한 표입니다:

| 엔터프라이즈 | Search Posts v2 |
| :--- | :--- |
| query | query |
| maxResults | max&#95;results |
| fromDate (YYMMDDHHmm) | start&#95;time (YYYY-MM-DDTHH:mm:ssZ) |
| toDate (YYMMDDHHmm) | end&#95;time (YYYY-MM-DDTHH:mm:ssZ) |
|     | since&#95;id |
|     | until&#95;id |
| next | next&#95;token or pagination&#95;token |

**필터링 연산자**

엔터프라이즈와 X API v2 간의 연산자는 대부분 동일하지만, 연산자별 지원 여부에 차이가 있으며 X API v2에만 새로 도입된 연산자도 일부 있습니다.

X API v2, 엔터프라이즈, 그리고 프리미엄 및 스탠다드에서 사용 가능한 연산자의 전체 표를 보려면 [Search Posts 마이그레이션 랜딩 페이지](/ko/x-api/posts/search/migrate/overview)를 방문하세요.
