필터링 스트림 엔드포인트는 스트림에 적용된 규칙 집합과 일치하는 포스트를 전달합니다. 규칙은 다양한 포스트 속성과 일치하는 연산자로 구성됩니다.

[POST /tweets/search/stream/rules](/ko/x-api/posts/filtered-stream#post-2-tweets-search-stream-rules) 엔드포인트를 사용해 여러 규칙을 적용할 수 있습니다. 규칙을 추가하고 [GET /tweets/search/stream](/ko/x-api/posts/filtered-stream#get-2-tweets-search-stream)을 사용해 스트림에 연결하면, 설정한 규칙과 일치하는 포스트만 전달됩니다. 규칙을 추가하거나 제거하기 위해 연결을 끊을 필요는 없습니다.

***

<div id="rule-limitations">
  ## 규칙 제한 사항
</div>

규칙 개수 제한은 사용 중인 [액세스 수준](/ko/x-api/getting-started/about-x-api)에 따라 달라집니다. 구체적인 제한값은 [필터링된 스트림 소개](/ko/x-api/posts/filtered-stream/introduction)를 참고하세요.

***

<div id="operator-types-standalone-and-conjunction-required">
  ## 연산자 유형: 단독 사용 및 결합 필수
</div>

**단독 연산자**는 단독으로 사용하거나 (결합이 필요한 연산자를 포함해) 다른 어떤 연산자와도 함께 사용할 수 있습니다.

예를 들어, 이 규칙은 `#hashtag`가 단독 연산자이기 때문에 작동합니다:

```
#xapiv2
```

**연접 전용 연산자**는 규칙에서 단독으로 사용할 수 없으며, 하나 이상의 단독 연산자가 포함된 규칙에서만 함께 사용할 수 있습니다. 이는 이러한 연산자를 단독으로 사용하면 매우 많은 수의 포스트와 일치하게 되기 때문입니다.

예를 들어, 다음 규칙들은 연접 전용 연산자만 포함하고 있으므로 **지원되지 않습니다**:

```
has:media
```

```
has:links OR is:retweet
```

`"X data"`와 같은 단독 연산자를 추가하면 규칙이 제대로 동작합니다.

```
"X data" has:mentions (has:media OR has:links)
```

<div id="boolean-operators-and-grouping">
  ## 불리언 연산자와 그룹화
</div>

다음 도구를 사용해 여러 연산자를 함께 사용할 수 있습니다:

| Operator | Description | Example |
| :--- | :--- | :--- |
| **AND** (space) | 포스트가 두 조건을 모두 만족해야 함 | `snow day #NoSchool`은 &quot;snow&quot; AND &quot;day&quot; AND #NoSchool을 포함하는 포스트와 일치합니다 |
| **OR** | 포스트가 두 조건 중 하나를 만족해야 함 | `grumpy OR cat OR #meme`은 &quot;grumpy&quot; OR &quot;cat&quot; OR #meme을 포함하는 포스트와 일치합니다 |
| **NOT** (dash) | 이 조건과 일치하는 포스트를 제외 | `cat #meme -grumpy`는 &quot;cat&quot;과 #meme은 포함하지만 &quot;grumpy&quot;는 포함하지 않는 포스트와 일치합니다 |
| **Grouping** (parentheses) | 연산자를 묶어서 그룹화 | `(grumpy cat) OR (#meme has:images)`는 두 그룹 중 하나와 일치합니다 |

<Note>
  **부정(negation)에 대한 참고 사항**

  * `sample:`를 제외한 모든 연산자는 부정할 수 있습니다
  * 연산자 `-is:nullcast`는 항상 부정 형태로만 사용해야 합니다
  * 부정된 연산자는 단독으로 사용할 수 없습니다
  * 그룹화된 연산자를 부정하지 마십시오. `skiing -(snow OR day OR noschool)` 대신 `skiing -snow -day -noschool`을 사용하십시오
</Note>

***

<div id="order-of-operations">
  ## 연산 순서
</div>

AND와 OR 연산자를 함께 사용할 때:

1. AND 논리로 연결된 연산자가 먼저 결합됩니다.
2. 이후 OR 논리로 연결된 연산자가 적용됩니다.

**예시:**

| Query                    | Evaluated as               |
| :----------------------- | :------------------------- |
| `apple OR iphone ipad`   | `apple OR (iphone ipad)`   |
| `ipad iphone OR android` | `(iphone ipad) OR android` |

모호성을 없애려면 괄호를 사용하세요:

```
(apple OR iphone) ipad
```

```
iphone (ipad OR android)
```

<div id="punctuation-diacritics-and-case-sensitivity">
  ## 문장 부호, 발음 구별 기호, 대소문자 구분
</div>

**발음 구별 기호:** 발음 구별 기호(악센트)가 포함된 Filtered stream 규칙은 악센트가 포함된 포스트에만 매치됩니다. 예를 들어, `diacrítica`는 &#95;diacrítica&#95;와는 매치되지만 &#95;diacritica&#95;와는 **매치되지 않습니다**.

**대소문자 구분:** 모든 연산자는 대소문자를 구분하지 않습니다. 규칙 `cat`은 *cat*, *CAT*, *Cat* 모두와 매치됩니다.

<Note>
  **포스트 검색은 다르게 동작합니다**

  [검색 쿼리를 구성할 때](/ko/x-api/posts/search/integrate/build-a-query), 악센트가 있는 키워드는 악센트가 있든 없든 포스트와 모두 매치됩니다. 예를 들어, `Diacrítica`는 &#95;Diacrítica&#95;와 *Diacritica* 모두와 매치됩니다.
</Note>

***

<div id="quote-tweet-matching">
  ## 인용 트윗 매칭
</div>

Filtered Stream을 사용할 때 연산자는 인용 트윗의 내용 **및** 인용된 원래 포스트의 내용 모두를 기준으로 매칭합니다.

<Note>
  [포스트 검색](/ko/x-api/posts/search/introduction)은 동작 방식이 다릅니다. 인용 트윗의 내용에만 매칭되며, 원래 포스트의 내용에는 매칭되지 않습니다.
</Note>

<div id="specificity-and-efficiency">
  ## 구체성과 효율성
</div>

<Warning>
  단일 키워드나 해시태그 같은 광범위한 연산자 하나만 사용하는 것은 권장되지 않습니다. 이렇게 하면 매우 많은 포스트와 일치하게 되어 연결 할당량이 빠르게 소진될 수 있습니다.
</Warning>

**효과적인 규칙을 만드는 팁:**

1. **처음에는 구체적으로, 이후 점차 범위를 확대** — 관련성이 높은 결과를 반환하는 대상 특화 규칙을 만드세요
2. **여러 연산자를 사용** — 연산자를 조합하여 결과 범위를 좁히세요
3. **문자 수에 유의** — 전체 규칙 문자열이 제한에 모두 포함됩니다

**단계별 예시:**

```
# Too broad - 200,000+ Posts per day
happy

# Better - adds language filter and exclusions
(happy OR happiness) lang:en -birthday -is:retweet

# 더욱 개선됨 - 59자, 더 구체적임
(happy OR happiness) place_country:GB -birthday -is:retweet
```

<div id="iteratively-building-a-rule">
  ## 규칙을 단계적으로 만들기
</div>

<div id="step-1-start-with-a-basic-rule">
  ### 1단계: 기본 규칙부터 만들기
</div>

```
happy OR happiness
```

<div id="step-2-test-and-narrow-based-on-results">
  ### 2단계: 결과를 바탕으로 테스트하고 범위를 좁히기
</div>

여러 언어로 작성된 포스트가 있음을 확인했습니다. 언어 필터를 추가하세요:

```
(happy OR happiness) lang:en
```

생일 축하 메시지도 잡히고 있습니다. 이런 메시지와 리트윗을 제외해 봅시다:

```
(happy OR happiness) lang:en -birthday -is:retweet
```

<div id="step-3-broaden-for-better-coverage">
  ### 3단계: 더 넓은 커버리지를 위해 확장하기
</div>

더 많은 반응을 포착하고자 합니다. 관련 키워드를 추가하세요:

```
(happy OR happiness OR excited OR elated) lang:en -birthday -is:retweet
```

<div id="step-4-adjust-for-trends">
  ### 4단계: 트렌드에 맞게 조정
</div>

휴일 관련 포스트가 나타납니다. 제외하세요:

```
(happy OR happiness OR excited OR elated) lang:en -birthday -is:retweet -holidays
```

<div id="adding-and-removing-rules">
  ## 규칙 추가 및 제거
</div>

규칙을 추가하거나 제거하려면 [POST /2/tweets/search/stream/rules](/ko/x-api/posts/filtered-stream#post-2-tweets-search-stream-rules)를 사용하세요.

<div id="adding-rules">
  ### 규칙 추가
</div>

`value`(규칙)와 선택적 `tag`(일치하는 포스트를 식별하기 위한 값)을 포함하는 `add` JSON 요청 본문을 전송합니다:

```bash
curl -X POST "https://api.x.com/2/tweets/search/stream/rules" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -d '{
    "add": [
      {"value": "cat has:media", "tag": "cats with media"},
      {"value": "cat has:media -grumpy", "tag": "happy cats with media"},
      {"value": "meme", "tag": "funny things"},
      {"value": "meme has:images"}
    ]
  }'
```

<div id="removing-rules">
  ### 규칙 삭제
</div>

제거할 규칙 ID를 포함한 `delete` JSON 본문을 제출합니다:

```bash
curl -X POST "https://api.x.com/2/tweets/search/stream/rules" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -d '{
    "delete": {
      "ids": [
        "1165037377523306498",
        "1165037377523306499"
      ]
    }
  }'
```

<div id="rule-examples">
  ## 규칙 예시
</div>

<div id="tracking-a-natural-disaster">
  ### 자연재해 추적
</div>

허리케인 하비에 관한 기상 기관의 포스트를 매칭합니다:

```json
{
  "value": "-is:retweet has:geo (from:NWSNHC OR from:NHC_Atlantic OR from:NWSHouston OR from:NWSSanAntonio OR from:USGS_TexasRain OR from:USGS_TexasFlood OR from:JeffLindner1)",
  "tag": "허리케인 하비 - 위치 정보 포함 기상 기관"
}
```

<div id="sentiment-analysis-for-nowplaying">
  ### #nowplaying에 대한 감성 분석
</div>

**긍정적 감성:**

```json
{
  "value": "#nowplaying (happy OR exciting OR excited OR favorite OR fav OR amazing OR lovely OR incredible) (place_country:US OR place_country:MX OR place_country:CA) -horrible -worst -sucks -bad -disappointing",
  "tag": "#nowplaying positive"
}
```

**부정 감성:**

```json
{
  "value": "#nowplaying (horrible OR worst OR sucks OR bad OR disappointing) (place_country:US OR place_country:MX OR place_country:CA) -happy -exciting -excited -favorite -fav -amazing -lovely -incredible",
  "tag": "#nowplaying negative"
}
```

<div id="using-post-annotations">
  ### 포스트 annotation 사용하기
</div>

`context:` 연산자를 사용해 이미지가 포함된 일본어 반려동물(고양이는 제외) 포스트를 찾습니다:

먼저 `tweet.fields=context_annotations`를 지정한 [Post lookup](/ko/x-api/posts/lookup/introduction)을 사용해 domain.entity ID를 식별합니다:

* Cats: `domain` 66, `entity` 852262932607926273
* Pets: `domain` 65, `entity` 852262932607926273

```json
{
  "value": "context:65.852262932607926273 -context:66.852262932607926273 -is:retweet has:images lang:ja",
  "tag": "Japanese pets with images - no cats"
}
```
