필터링된 스트림 엔드포인트는 스트림에 적용된 일련의 규칙과 일치하는 포스트를 전달합니다. 규칙은 다양한 포스트 속성과 일치하는 연산자로 구성됩니다.

여러 규칙은 [POST /tweets/search/stream/rules](/ko/x-api/posts/filtered-stream#post-2-tweets-search-stream-rules) 엔드포인트를 사용해 설정할 수 있습니다. 규칙을 추가하고 [GET /tweets/search/stream](/ko/x-api/posts/filtered-stream#get-2-tweets-search-stream)을 사용해 스트림에 연결한 이후에는, 규칙과 일치하는 포스트만 전달됩니다. 규칙을 추가하거나 제거하기 위해 연결을 끊을 필요는 없습니다.

***

<div id="rule-limitations">
  ## 규칙 제한 사항
</div>

규칙 개수 제한은 [액세스 레벨](/ko/x-api/getting-started/about-x-api)에 따라 달라집니다. 구체적인 한도는 [필터링된 스트림 소개](/ko/x-api/posts/filtered-stream/introduction)를 참고하세요.

***

<div id="operator-types-standalone-and-conjunction-required">
  ## 연산자 유형: 단독 사용 및 접속사 필수
</div>

**단독 연산자**는 단독으로 사용할 수도 있고, (접속사가 필요한 연산자를 포함해) 다른 어떤 연산자와도 함께 사용할 수 있습니다.

예를 들어, 이 규칙이 유효한 이유는 `#hashtag`가 단독 연산자이기 때문입니다:

```
#xapiv2
```

**연결-필수 연산자**는 규칙에서 단독으로 사용할 수 없으며, 하나 이상의 단독 연산자가 포함된 경우에만 사용할 수 있습니다. 이는 이러한 연산자만 사용할 경우, 일치하는 포스트의 수가 매우 방대해지기 때문입니다.

예를 들어, 다음 규칙들은 연결-필수 연산자만 포함하고 있으므로 **지원되지 않습니다**:

```
has:media
```

```
has:links OR is:retweet
```

`"X data"`와 같이 독립된 연산자를 추가하면 규칙이 정상적으로 동작합니다:

```
"X data" has:mentions (has:media OR has:links)
```

<div id="boolean-operators-and-grouping">
  ## 불리언 연산자와 그룹화
</div>

다음과 같이 여러 연산자를 함께 사용할 수 있습니다:

| Operator | Description | Example |
| :--- | :--- | :--- |
| **AND** (space) | 포스트가 두 조건을 모두 만족해야 합니다 | `snow day #NoSchool`은 &quot;snow&quot;, &quot;day&quot;, #NoSchool이 모두 포함된 포스트와 일치합니다 |
| **OR** | 포스트가 두 조건 중 하나만 만족해도 됩니다 | `grumpy OR cat OR #meme`은 &quot;grumpy&quot;, &quot;cat&quot;, #meme 중 하나 이상이 포함된 포스트와 일치합니다 |
| **NOT** (dash) | 이 조건과 일치하는 포스트를 제외합니다 | `cat #meme -grumpy`는 &quot;cat&quot;과 #meme은 포함하지만 &quot;grumpy&quot;는 포함하지 않는 포스트와 일치합니다 |
| **Grouping** (parentheses) | 연산자를 함께 그룹화합니다 | `(grumpy cat) OR (#meme has:images)`는 두 그룹 중 하나와 일치합니다 |

<Note>
  **부정 연산에 대한 참고 사항**

  * `sample:`을 제외한 모든 연산자는 부정할 수 있습니다
  * 연산자 `-is:nullcast`는 항상 부정 형태로 사용해야 합니다
  * 부정 형태의 연산자는 단독으로 사용할 수 없습니다
  * 그룹화된 연산자를 부정하지 마십시오. `skiing -(snow OR day OR noschool)` 대신 `skiing -snow -day -noschool`을 사용하십시오
</Note>

***

<div id="order-of-operations">
  ## 연산 순서
</div>

AND와 OR를 함께 사용할 때:

1. AND 논리로 연결된 연산자가 먼저 결합됩니다.
2. 그다음 OR 논리로 연결된 연산자가 적용됩니다.

**예시:**

| Query                    | Evaluated as               |
| :----------------------- | :------------------------- |
| `apple OR iphone ipad`   | `apple OR (iphone ipad)`   |
| `ipad iphone OR android` | `(iphone ipad) OR android` |

모호함을 없애려면 괄호를 사용하세요:

```
(apple OR iphone) ipad
```

```
iphone (ipad OR android)
```

<div id="punctuation-diacritics-and-case-sensitivity">
  ## 문장 부호, 발음 구별 기호, 대소문자 구분
</div>

**발음 구별 기호(diacritics):** 악센트가 포함된 Filtered stream 규칙은 악센트가 포함된 포스트에만 매칭됩니다. 예를 들어, `diacrítica`는 &#95;diacrítica&#95;와는 매칭되지만 &#95;diacritica&#95;와는 **매칭되지 않습니다**.

**대소문자 구분:** 모든 연산자는 대소문자를 구분하지 않습니다. 규칙 `cat`은 *cat*, *CAT*, *Cat* 모두에 매칭됩니다.

<Note>
  **포스트 검색은 다르게 동작합니다**

  [검색 쿼리를 빌드](/ko/x-api/posts/search/integrate/build-a-query)할 때, 악센트가 있는 키워드는 악센트가 있는 포스트와 없는 포스트 모두에 매칭됩니다. 예를 들어, `Diacrítica`는 &#95;Diacrítica&#95;와 *Diacritica* 모두에 매칭됩니다.
</Note>

***

<div id="quote-tweet-matching">
  ## 인용 트윗 매칭
</div>

Filtered stream을 사용할 때, 연산자는 인용 트윗의 콘텐츠 **와** 인용된 원본 포스트의 콘텐츠 모두에 대해 매칭합니다.

<Note>
  [포스트 검색](/ko/x-api/posts/search/introduction)은 다르게 동작합니다. 인용 트윗의 콘텐츠에만 매칭되며, 원본 포스트의 콘텐츠는 매칭에 사용되지 않습니다.
</Note>

***

<div id="specificity-and-efficiency">
  ## 구체성과 효율성
</div>

<Warning>
  단일 키워드나 해시태그와 같은 광범위한 연산자 사용은 권장되지 않습니다. 매우 많은 포스트와 일치하여 연결 한도를 빠르게 소모할 수 있습니다.
</Warning>

**효율적인 규칙을 작성하기 위한 팁:**

1. **처음에는 구체적으로, 이후에 확장** — 관련성이 높은 결과를 반환하는 정밀한 규칙을 먼저 만듭니다
2. **여러 연산자를 사용** — 연산자를 조합하여 결과를 좁힙니다
3. **문자 수에 유의** — 전체 규칙 문자열이 제한에 포함됩니다

**예시 진행 단계:**

```
# Too broad - 200,000+ Posts per day
happy

# Better - adds language filter and exclusions
(happy OR happiness) lang:en -birthday -is:retweet

# 더욱 개선됨 - 59자, 더 구체적임
(happy OR happiness) place_country:GB -birthday -is:retweet
```

<div id="iteratively-building-a-rule">
  ## 규칙을 점진적으로 구성하기
</div>

<div id="step-1-start-with-a-basic-rule">
  ### 1단계: 기본 규칙으로 시작하기
</div>

```
happy OR happiness
```

<div id="step-2-test-and-narrow-based-on-results">
  ### 2단계: 결과에 따라 테스트하고 범위를 좁히기
</div>

여러 언어로 작성된 포스트가 있다는 것을 확인했습니다. 언어 필터를 추가하세요:

```
(happy OR happiness) lang:en
```

생일 축하 메시지들이 잡히고 있습니다. 이런 것들과 리트윗은 제외해 봅시다:

```
(happy OR happiness) lang:en -birthday -is:retweet
```

<div id="step-3-broaden-for-better-coverage">
  ### 3단계: 범위를 넓혀 커버리지를 개선하기
</div>

더 다양한 감성을 포착해야 합니다. 관련 키워드를 추가하세요:

```
(happy OR happiness OR excited OR elated) lang:en -birthday -is:retweet
```

<div id="step-4-adjust-for-trends">
  ### 4단계: 트렌드에 맞게 조정
</div>

휴일 포스트가 나타납니다. 이를 제외하세요:

```
(happy OR happiness OR excited OR elated) lang:en -birthday -is:retweet -holidays
```

<div id="adding-and-removing-rules">
  ## 규칙 추가 및 제거
</div>

규칙을 추가하거나 제거하려면 [POST /2/tweets/search/stream/rules](/ko/x-api/posts/filtered-stream#post-2-tweets-search-stream-rules)를 사용하세요.

<div id="adding-rules">
  ### 규칙 추가
</div>

`value`(규칙)와 선택적인 `tag`(일치하는 포스트를 식별하기 위한 태그)를 포함한 `add` JSON 본문을 제출합니다:

```bash
curl -X POST "https://api.x.com/2/tweets/search/stream/rules" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -d '{
    "add": [
      {"value": "cat has:media", "tag": "cats with media"},
      {"value": "cat has:media -grumpy", "tag": "happy cats with media"},
      {"value": "meme", "tag": "funny things"},
      {"value": "meme has:images"}
    ]
  }'
```

<div id="removing-rules">
  ### 규칙 제거
</div>

삭제할 규칙의 ID를 포함하여 `delete` JSON 본문을 제출합니다:

```bash
curl -X POST "https://api.x.com/2/tweets/search/stream/rules" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -d '{
    "delete": {
      "ids": [
        "1165037377523306498",
        "1165037377523306499"
      ]
    }
  }'
```

<div id="rule-examples">
  ## 규칙 예제
</div>

<div id="tracking-a-natural-disaster">
  ### 자연 재해 추적
</div>

허리케인 Harvey 관련 기상 기관의 포스트를 매칭하는 규칙:

```json
{
  "value": "-is:retweet has:geo (from:NWSNHC OR from:NHC_Atlantic OR from:NWSHouston OR from:NWSSanAntonio OR from:USGS_TexasRain OR from:USGS_TexasFlood OR from:JeffLindner1)",
  "tag": "허리케인 하비 - 위치 정보 포함 기상 기관"
}
```

<div id="sentiment-analysis-for-nowplaying">
  ### #nowplaying에 대한 감성 분석
</div>

**긍정적인 감정:**

```json
{
  "value": "#nowplaying (happy OR exciting OR excited OR favorite OR fav OR amazing OR lovely OR incredible) (place_country:US OR place_country:MX OR place_country:CA) -horrible -worst -sucks -bad -disappointing",
  "tag": "#nowplaying positive"
}
```

**부정적인 감정:**

```json
{
  "value": "#nowplaying (horrible OR worst OR sucks OR bad OR disappointing) (place_country:US OR place_country:MX OR place_country:CA) -happy -exciting -excited -favorite -fav -amazing -lovely -incredible",
  "tag": "#nowplaying negative"
}
```

<div id="using-post-annotations">
  ### 포스트 주석 사용하기
</div>

`context:` 연산자를 사용하여 일본어로 작성된, 반려동물(고양이는 제외)에 관한 이미지가 포함된 포스트를 찾습니다:

먼저 `tweet.fields=context_annotations`를 사용한 [Post lookup](/ko/x-api/posts/lookup/introduction)으로 domain.entity ID를 확인합니다:

* Cats: `domain` 66, `entity` 852262932607926273
* Pets: `domain` 65, `entity` 852262932607926273

```json
{
  "value": "context:65.852262932607926273 -context:66.852262932607926273 -is:retweet has:images lang:ja",
  "tag": "Japanese pets with images - no cats"
}
```
