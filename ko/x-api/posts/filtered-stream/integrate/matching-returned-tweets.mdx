<div id="matching-returned-posts-to-their-associated-rule">
  ### 반환된 포스트를 해당 규칙과 매칭하기
</div>

filtered stream 엔드포인트를 사용하면 단일 연결을 통해 여러 규칙을 설정할 수 있습니다. 스트림에서 포스트를 수신하기 전에, 관심 있는 포스트의 유형을 지정하는 규칙을 먼저 생성해야 합니다. 

사용자 속성, 위치 정보(geo-location), 언어 등 다양한 속성을 기준으로 포스트를 매칭하는 규칙을 지정할 때, 이 규칙을 더 높은 수준에서 구분하기 위해 태그를 붙일 수 있습니다. 태그는 특히 많은 규칙을 사용 중인 경우 규칙에 맥락을 부여하는 좋은 방법입니다. 필터링 규칙은 어떤 포스트 활동이 연결을 통해 전송될지를 결정합니다.

다른 유형의 포스트를 수집하기 위해 새로운 필터링 규칙을 추가하거나 기존 규칙을 제거해야 하는 경우, 앱에서 [POST tweets/search/stream/rules](/ko/x-api/posts/filtered-stream#post-2-tweets-search-stream-rules) 엔드포인트로 요청을 보내 이를 처리할 수 있습니다. 이 요청이 전송되면 필터링 규칙은 자동으로 수정되며, 다시 연결할 필요 없이 data 스트림에 변경 사항이 바로 적용됩니다. 대부분의 규칙 추가는 약 20초 이내에 적용됩니다. 드문 경우지만, 외부 요인(예: 네트워크 연결 상태)에 따라 일치하는 포스트 수신이 시작되기까지 더 오래 걸릴 수 있습니다. 규칙 목록(list rules) 엔드포인트에서 규칙을 찾을 수 없다면, 규칙 생성 요청이 성공했는지 확인하십시오. 이는 로그에서 오류 메시지가 있었는지 확인함으로써 검증할 수 있습니다.

<div id="matching-rules">
  #### 일치하는 규칙
</div>

활동이 필터링된 스트림 연결을 통해 전달될 때, `matching_rules` 배열에는 전달된 포스트와 일치한 필터 목록이 포함됩니다.

포스트 페이로드에는 특정 포스트가 전달되도록 한 규칙 id와 태그를 포함하는 추가 문자열 메타데이터가 있습니다. 여러 규칙이 하나의 포스트와 일치하는 경우, 활동은 이 메타데이터에 각각의 일치하는 규칙이 모두 포함된 상태로 한 번만 전달됩니다. 일치하는 규칙은 특정 포스트를 특정 규칙과 쉽게 연결할 수 있게 해 주며, 특히 서로 구분되는 규칙을 많이 가지고 있는 경우에 유용합니다. data가 이러한 방식으로 단일 스트림을 통해 전달되므로, 매칭을 위해 고유한 id와 태그를 사용하는 것이 필수적입니다. 

**다음은 포스트 페이로드에서 `matching_rules` 배열이 나타나는 예시입니다.**

```"matching_rules": [
    {
      "id": "1166916266197536768",
      "tag": "test-rule-tag-00000"
    },
    {
      "id": "1166916266197536769",
      "tag": "test-rule-tag-12345"
    }
  ]
```

  #### Rule tags
</div>

규칙이 생성될 때마다 각 필터링 규칙에는 태그를 함께 지정할 수 있습니다. 규칙 태그 자체에는 특별한 의미가 없으며, 규칙과 함께 전달되는 단순한 (내용을 해석하지 않는) 문자열로만 취급됩니다. 이 태그들은 반환된 activity의 `matching_rules` 메타데이터에 포함되며, 상위 수준에서 규칙들을 더 쉽게 구분할 수 있도록 하는 데 사용됩니다. 

태그를 사용하면 필터링 규칙을 논리적으로 손쉽게 그룹화할 수 있습니다. 예를 들어, 특정 규칙에 대해 고유 ID를 생성해 그 규칙의 태그로 사용하고, 앱이 처리하는 activity 내에서 해당 ID를 참조하여 결과를 특정 고객, 캠페인, 카테고리 또는 기타 관련 그룹과 연관 지을 수 있습니다.

태그는 기존 규칙에서 수정할 수 없으며, 규칙을 생성할 때에만 포함할 수 있다는 점에 유의하십시오. 태그를 “업데이트”하거나 “이름을 변경”하려면 먼저 해당 규칙을 삭제한 뒤, 원하는 태그로 다시 추가해야 합니다. 가장 좋은 방법은 태그로 고유 식별자를 사용하는 것이며, 그러면 시스템이 앱 내의 다양한 다른 데이터 포인트와 이를 연관 지을 수 있습니다. 이렇게 하면 규칙 집합은 변경할 필요가 없습니다.
