<div id="matching-returned-posts-to-their-associated-rule">
  ### 반환된 포스트를 해당 규칙과 매칭하기
</div>

filtered stream 엔드포인트를 사용하면 단일 연결을 통해 여러 규칙을 설정할 수 있습니다. 스트림에서 포스트를 수신하기 전에 어떤 유형의 포스트에 관심이 있는지 지정하는 규칙을 먼저 생성해야 합니다. 

사용자 속성, 지리 위치, 언어 등 다양한 속성을 기준으로 포스트와 일치시키는 규칙을 지정할 때, 이 규칙을 상위 수준에서 구분하기 위해 태그를 첨부할 수 있습니다. 태그는 특히 많은 규칙을 사용 중일 때 규칙의 의미를 구체화하는 좋은 방법입니다. 필터링 규칙은 어떤 포스트 활동이 연결을 통해 전송될지를 결정합니다.

다른 유형의 포스트를 수집하기 위해 새로운 필터링 규칙을 추가하거나 기존 규칙을 제거해야 하는 경우, 앱에서 [POST tweets/search/stream/rules](/ko/x-api/posts/filtered-stream#post-2-tweets-search-stream-rules) 엔드포인트로 요청을 보내 이를 처리할 수 있습니다. 이 요청이 전송되면 필터링 규칙은 자동으로 수정되고, 다시 연결할 필요 없이 변경 사항이 데이터 스트림에 바로 반영됩니다. 대부분의 규칙 추가는 약 20초 이내에 적용됩니다. 흔하지는 않지만, 외부 요인(예: 네트워크 연결 상태)에 따라 일치하는 포스트를 받기까지 더 오래 걸릴 수 있습니다. 규칙 목록 엔드포인트에서 규칙을 찾을 수 없다면, 규칙 생성 요청이 성공했는지 확인해야 합니다. 이는 로그를 확인해 오류 메시지가 있었는지 살펴봄으로써 확인할 수 있습니다.

<div id="matching-rules">
  #### 일치하는 규칙
</div>

액티비티가 필터링된 스트림 연결을 통해 전달될 때, `matching_rules` 배열에는 전달된 포스트와 일치한 필터 목록이 포함됩니다.

포스트 페이로드에는 특정 포스트가 전달되도록 한 규칙 `id` 및 태그를 포함하는 추가 문자열 형태의 메타데이터가 있습니다. 여러 규칙이 하나의 포스트와 일치하는 경우, 해당 액티비티는 이 메타데이터에 각 일치 규칙이 모두 포함된 상태로 한 번만 전달됩니다. 일치하는 규칙은 특정 포스트를 특정 규칙과 쉽게 연결할 수 있는 방법을 제공하며, 특히 서로 다른 규칙이 많은 경우에 유용합니다. 이런 방식으로 data가 단일 스트림을 통해 전달되므로, 고유한 `id`와 태그를 사용하는 것이 매칭을 위해 필수적입니다. 

**다음은 포스트 페이로드에서 &quot;matching&#95;rules&quot; 배열이 어떻게 표시되는지에 대한 예시입니다:**

```"matching_rules": [
    {
      "id": "1166916266197536768",
      "tag": "test-rule-tag-00000"
    },
    {
      "id": "1166916266197536769",
      "tag": "test-rule-tag-12345"
    }
  ]
```

<div id="rule-tags">
  #### 규칙 태그
</div>

각 필터링 규칙은 생성할 때 태그를 함께 지정할 수 있습니다. 규칙 태그는 단순히 규칙과 함께 전달되는 불투명한 문자열로 취급되며, 그 자체로는 특별한 의미를 가지지 않습니다. 태그는 반환되는 활동의 `matching_rules` 메타데이터에 포함되며, 보다 상위 수준에서 규칙을 더 쉽게 구분할 수 있도록 하기 위한 것입니다. 

태그는 필터링 규칙들을 논리적으로 그룹화하는 간편한 방법을 제공합니다. 예를 들어, 특정 규칙에 대해 고유 ID를 생성해 그 규칙의 태그로 사용할 수 있으며, 앱이 처리하는 활동 내에서 해당 ID를 참조하여 결과를 특정 고객, 캠페인, 카테고리 또는 기타 관련 그룹과 연관시킬 수 있습니다.

태그는 기존 규칙에 대해 업데이트할 수 없으며, 규칙이 생성될 때에만 포함될 수 있다는 점에 유의하세요. 태그를 업데이트하거나 이름을 바꾸려면 먼저 해당 규칙을 삭제한 다음, 원하는 태그를 사용하여 다시 추가해야 합니다. 가장 좋은 방법은 태그로 고유 식별자를 사용하는 것이며, 이를 통해 규칙 집합을 변경하지 않고도 시스템이 앱 내의 다양한 다른 데이터 포인트와 해당 태그를 연관 지을 수 있습니다.
