<div id="manage-likes-standard-v11-compared-to-x-api-v2">
  ### 좋아요 관리: standard v1.1과 X API v2 비교
</div>

standard v1.1의 [POST favorites/create](https://developer.x.com/en/docs/twitter-api/v1/tweets/post-and-engage/api-reference/post-favorites-create) 및 [POST favorites/destroy](https://developer.x.com/en/docs/twitter-api/v1/tweets/post-and-engage/api-reference/post-favorites-destroy) 엔드포인트를 사용해 왔다면, 이 가이드는 standard v1.1과 X API v2에서 좋아요를 관리하는 엔드포인트 간 유사점과 차이점을 이해하는 데 도움이 되도록 작성되었습니다.

* **유사점**
  * OAuth 1.0a User Context
* **차이점**
  * 엔드포인트 URL 및 HTTP 메서드
  * App 및 Project 요구 사항
  * 요청 파라미터

<div id="similarities">
  #### 유사점
</div>

**OAuth 1.0a User Context 인증 방식**

두 엔드포인트 버전은 모두 [OAuth 1.0a User Context](/ko/resources/fundamentals/authentication#oauth-1-0a-2)를 지원합니다. 따라서 이전에 standard v1.1 manage favorites 엔드포인트 중 하나를 사용했다면, X API v2 버전으로 마이그레이션하더라도 동일한 인증 방식을 계속 사용할 수 있습니다.

<div id="differences">
  #### 차이점
</div>

**엔드포인트 URL 및 HTTP 메서드**

* Standard v1.1 엔드포인트:
  * POST https://api.x.com/1.1/favorites/create.json
    (포스트에 좋아요)
  * POST https://api.x.com/1.1/favorites/destroy.json
    (포스트 좋아요 취소)
* X API v2 엔드포인트:
  * POST https://api.x.com/2/tweets/:id/likes
    (포스트에 좋아요)
  * DELETE https://api.x.com/2/tweets/:id/likes/:tweet&#95;id
    (포스트 좋아요 취소) 

**App 및 Project 요구 사항**

X API v2 엔드포인트를 사용하려면 요청을 인증할 때 [개발자 App](/ko/resources/fundamentals/developer-apps)에서 발급된 자격 증명을 사용해야 하며, 이 App은 [Project](/ko/resources/fundamentals/developer-apps)에 연결되어 있어야 합니다. 모든 X API v1.1 엔드포인트는 독립적인 App이든 Project에 연결된 App이든, App의 자격 증명을 사용할 수 있습니다.

**요청 파라미터**

다음 Standard v1.1 요청 파라미터에는 X API v2에서의 대응 항목이 있습니다:

| Standard v1.1 | X API v2 |
| :--- | :--- |
| id  | id  |
| includes&#95;entities | 해당 없음 |

Standard v1.1 파라미터는 쿼리 파라미터로 전달되는 반면, X API v2 파라미터는 POST 엔드포인트의 경우 요청 본문(body) 파라미터로, DELETE 엔드포인트의 경우 경로 파라미터로 전달된다는 점에 유의하세요.

또한, Standard v1.1 엔드포인트를 사용할 때는 [OAuth 1.0a User Context](/ko/resources/fundamentals/authentication)와 함께 전달되는 [Access Tokens](/ko/resources/fundamentals/authentication#obtaining-access-tokens-using-3-legged-oauth-flow)를 통해 어떤 사용자가 좋아요/좋아요 취소 작업을 수행하는지 유추하므로, 포스트에 좋아요를 누르는 사용자의 id는 필수가 아닙니다.

<div id="like-a-post-v2">
  ### 포스트에 좋아요 표시 (v2)
</div>

<CodeGroup dropdown>
  ```bash cURL
  curl -X POST "https://api.x.com/2/users/123456789/likes" \
    -H "Authorization: OAuth ..." \
    -H "Content-Type: application/json" \
    -d '{"tweet_id": "1234567890"}'
  ```

  ```python Python
  # OAuth 1.0a User Context 인증 필요
  import requests
  from requests_oauthlib import OAuth1

  auth = OAuth1(
      "API_KEY", "API_SECRET",
      "ACCESS_TOKEN", "ACCESS_TOKEN_SECRET"
  )

  url = "https://api.x.com/2/users/123456789/likes"
  response = requests.post(url, auth=auth, json={"tweet_id": "1234567890"})
  print(response.json())
  ```

  ```python Python SDK
  from xdk import Client
  from xdk.oauth1_auth import OAuth1

  oauth1 = OAuth1(
      api_key="YOUR_API_KEY",
      api_secret="YOUR_API_SECRET",
      access_token="YOUR_ACCESS_TOKEN",
      access_token_secret="YOUR_ACCESS_TOKEN_SECRET"
  )

  client = Client(auth=oauth1)

  # 포스트에 좋아요 표시
  response = client.posts.like(user_id="123456789", tweet_id="1234567890")
  print(f"Liked: {response.data.liked}")
  ```

  ```javascript JavaScript SDK
  import { Client, OAuth1 } from "@xdevplatform/xdk";

  const oauth1 = new OAuth1({
    apiKey: "YOUR_API_KEY",
    apiSecret: "YOUR_API_SECRET",
    accessToken: "YOUR_ACCESS_TOKEN",
    accessTokenSecret: "YOUR_ACCESS_TOKEN_SECRET",
  });

  const client = new Client({ oauth1 });

  // 포스트에 좋아요 표시
  const response = await client.posts.like("123456789", { tweetId: "1234567890" });
  console.log(`Liked: ${response.data?.liked}`);
  ```
</CodeGroup>

  ### 포스트 좋아요 취소하기 (v2)
</div>

<CodeGroup dropdown>
  ```bash cURL
  curl -X DELETE "https://api.x.com/2/users/123456789/likes/1234567890" \
    -H "Authorization: OAuth ..."
  ```

  ```python Python
  # OAuth 1.0a User Context 인증이 필요합니다
  import requests
  from requests_oauthlib import OAuth1

  auth = OAuth1(
  ```

