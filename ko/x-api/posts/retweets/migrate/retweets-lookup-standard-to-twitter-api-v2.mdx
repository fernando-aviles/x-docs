<div id="retweets-lookup-standard-v11-compared-to-x-api-v2">
  ### 리트윗 조회: 표준 v1.1과 X API v2 비교
</div>

표준 v1.1 [v1.1 GET statuses/retweets/:id](https://developer.x.com/en/docs/twitter-api/v1/tweets/post-and-engage/api-reference/get-statuses-retweets-id), [v1.1 GET statuses/retweets/:ids](https://developer.x.com/en/docs/twitter-api/v1/tweets/post-and-engage/api-reference/get-statuses-retweeters-ids)를 사용해 왔다면, 이 가이드는 표준 v1.1과 X API v2 리트윗 조회 엔드포인트 간의 공통점과 차이점을 이해하는 데 도움이 되도록 작성되었습니다.

* **유사점**
  * 인증
  * 요청당 사용자 제한
* **차이점**
  * 엔드포인트 URL

  * 요청 제한 사항

  * App 및 Project 요구 사항

  * 응답 data 형식

  * 요청 매개변수

<div id="similarities">
  #### 유사점
</div>

**인증**

Standard v1.1 및 X API v2 리트윗 조회 엔드포인트([v1.1 GET statuses/retweets/:id](https://developer.x.com/en/docs/twitter-api/v1/tweets/post-and-engage/api-reference/get-statuses-retweets-id) 및 [v1.1 GET statuses/retweeters/:ids](https://developer.x.com/en/docs/twitter-api/v1/tweets/post-and-engage/api-reference/get-statuses-retweeters-ids))는 모두 [OAuth 1.0a User Context](https://developer.x.com/content/developer-twitter/resources/fundamentals/authentication) 또는 OAuth 2.0 Bearer Token을 사용합니다.

**요청당 사용자 수 제한**

v1.1 및 v2 GET 엔드포인트 모두에서 리트윗 조회 엔드포인트가 반환하는 최대 사용자 수는 100명입니다. v2 리트윗 조회 엔드포인트의 경우 기본적으로 pagination 토큰이 전달되지 않으며, 기본적으로 100명의 사용자를 반환하며 이것이 반환 가능한 최대값입니다.

<div id="differences">
  #### 차이점
</div>

**엔드포인트 URL**

* 표준 v1.1 엔드포인트:
  * https://api.x.com/1.1/statuses/retweets/:id.json
    (`id` 매개변수로 지정된 포스트를 리트윗한 가장 최근 리트윗 100개의 모음을 반환합니다)
  * `https://api.x.com/1.1/statuses/retweeters/ids.json`
    (`id` 매개변수로 지정된 포스트를 리트윗한 사용자들의 사용자 ID 최대 100개의 모음을 반환합니다)
* X API v2 엔드포인트:
  * https://api.x.com/2/tweets/:id/retweeted&#95;by
    (지정된 포스트를 리트윗한 계정 목록을 반환합니다)

**App 및 Project 요구 사항**

X API v2 엔드포인트를 사용하려면 요청을 인증할 때 [developer App](/ko/resources/fundamentals/developer-apps)과 [Project](/ko/resources/fundamentals/developer-apps)에 연결된 자격 증명을 사용해야 합니다. 모든 X API v1.1 엔드포인트는 단독 App이거나 Project에 연결된 App의 자격 증명을 사용할 수 있습니다.

**응답 data 형식**

표준 v1.1과 X API v2 엔드포인트 버전 간의 가장 큰 차이점 중 하나는 페이로드에서 어떤 필드를 반환할지 선택하는 방식입니다.

표준 엔드포인트의 경우, 기본적으로 많은 응답 필드를 받게 되며, 이후 매개변수를 사용해 페이로드에 어떤 필드 또는 필드 집합을 반환할지 선택할 수 있습니다.

X API v2에서는 기본적으로 user id, 이름, username 필드만 반환합니다. 추가 필드나 객체를 요청하려면 [fields](/ko/x-api/fundamentals/fields) 및 [expansions](/ko/x-api/fundamentals/expansions) 매개변수를 사용해야 합니다. 이 엔드포인트에서 요청한 모든 사용자 필드는 기본 user 객체에 포함됩니다. 확장된 포스트 객체와 필드는 응답 내 includes 객체에 포함되어 반환됩니다. 그런 다음 user와 확장된 포스트 객체 모두에 있는 ID를 매칭하여 확장된 객체를 user 객체와 다시 연결할 수 있습니다. 

이 새로운 매개변수에 대해서는 각 가이드 또는 [fields 및 expansions 사용 방법](/ko/x-api/fundamentals/data-dictionary#how-to-use-fields-and-expansions) 가이드를 읽어보시기를 권장합니다. 

또한 표준 v1.1 필드를 신규 v2 필드에 매핑하는 데 도움이 되는 [data 형식 마이그레이션 가이드](/ko/x-api/migrate/data-format-migration#migrating-from-standard-v1-1s-data-format-to-v2)도 준비했습니다. 이 가이드는 특정 필드를 반환하기 위해 v2 요청과 함께 전달해야 하는 expansion 및 field 매개변수를 구체적으로 안내합니다. 
 

특정 필드를 요청하는 방식의 변경 사항 외에도, X API v2는 API에서 반환되는 객체(예: [Post](/ko/x-api/fundamentals/data-dictionary#tweet) 및 [user](/ko/x-api/fundamentals/data-dictionary#user) 객체)에 대해 새로운 JSON 설계를 도입했습니다.

* JSON 루트 레벨에서 표준 엔드포인트는 포스트 객체를 statuses 배열로 반환하는 반면, X API v2는 data 배열로 반환합니다. 
* 리트윗 및 인용 &quot;statuses&quot;를 참조하는 대신, X API v2 JSON은 리트윗된 및 인용된 트윗을 참조합니다. contributors, user.translator&#95;type 등 많은 레거시 및 사용 중단 필드는 제거되고 있습니다. 
* 포스트 객체의 favorites 및 user 객체의 favourites를 모두 사용하는 대신, X API v2는 like라는 용어를 사용합니다. 
* X는 값이 없는 JSON 값(예: null)은 페이로드에 기록하지 않는 규칙을 채택하고 있습니다. 포스트 및 user 속성은 null이 아닌 값을 가질 때만 포함됩니다. 
   

또한 다음을 포함하여 [Post 객체](/ko/x-api/fundamentals/data-dictionary#tweet)에 새로운 필드 집합을 도입했습니다.

* [conversation&#95;id](/ko/x-api/fundamentals/conversation-id) 필드
* context 및 entities를 포함하는 두 개의 새로운 [annotations](/ko/x-api/fundamentals/post-annotations) 필드
* 여러 새로운 [metrics](/ko/x-api/fundamentals/metrics) 필드 
* 특정 포스트에 누가 답글을 남길 수 있는지 보여주는 새로운 reply&#95;setting 필드

**요청 매개변수**

다음 표준 v1.1 요청 매개변수는 두 개의 쿼리 매개변수(user&#95;id 또는 screen&#95;name)를 허용했습니다. X API v2는 숫자형 user ID만 허용하며, 이 값은 엔드포인트 경로의 일부로 전달되어야 합니다.

<div id="get-users-who-retweeted-a-post-v2">
  ### 포스트를 리트윗한 사용자 조회 (v2)
</div>

<CodeGroup dropdown>
  ```bash cURL
  curl "https://api.x.com/2/tweets/1234567890/retweeted_by?user.fields=username,verified" \
    -H "Authorization: Bearer $BEARER_TOKEN"
  ```

  ```python Python
  import requests

  bearer_token = "YOUR_BEARER_TOKEN"
  url = "https://api.x.com/2/tweets/1234567890/retweeted_by"

  params = {"user.fields": "username,verified"}
  headers = {"Authorization": f"Bearer {bearer_token}"}

  response = requests.get(url, headers=headers, params=params)
  print(response.json())
  ```

  ```python Python SDK
  from xdk import Client

  client = Client(bearer_token="YOUR_BEARER_TOKEN")

  # 포스트를 리트윗한 사용자 조회
  response = client.posts.get_retweeted_by(
      "1234567890",
      user_fields=["username", "verified"]
  )
  for user in response.data:
      print(f"{user.username} - Verified: {user.verified}")
  ```

  ```javascript JavaScript SDK
  import { Client } from "@xdevplatform/xdk";

  const client = new Client({ bearerToken: "YOUR_BEARER_TOKEN" });

  // 포스트를 리트윗한 사용자 조회
  const response = await client.posts.getRetweetedBy("1234567890", {
    userFields: ["username", "verified"],
  });

  response.data?.forEach((user) => {
    console.log(`${user.username} - Verified: ${user.verified}`);
  });
  ```
