<div id="comparing-x-apis-post-counts-endpoints">
  ## X API의 포스트 수 집계 엔드포인트 비교
</div>

v2 포스트 수 집계 엔드포인트는 궁극적으로 [enterprise Search API의 counts 엔드포인트](/ko/x-api/enterprise-gnip-2.0/fundamentals/search-api#counts-requests-post-count)를 대체할 예정입니다. 기존 버전의 포스트 수 집계 엔드포인트를 사용하는 코드, 앱 또는 도구가 있고 이를 최신 X API v2 엔드포인트로 마이그레이션하는 것을 검토하고 있다면, 이 가이드는 그런 경우를 위한 것입니다.

***

<div id="recent-post-counts-comparison">
  ## 최근 포스트 개수 비교
</div>

Enterprise 버전의 포스트 개수 엔드포인트를 사용하면 30일치 또는 전체 아카이브에 대한 개수를 조회할 수 있습니다. 따라서 7일 기간을 조회하는 v2 최근 포스트 개수 엔드포인트는 앞에서 언급한 어느 엔드포인트의 완전한 대체재가 아닙니다.

그러나 비교에 도움이 되도록 v2 최근 포스트 개수 엔드포인트가 Enterprise 30일 엔드포인트와 어떻게 비교되는지 살펴보겠습니다.

다음 표는 다양한 유형의 최근 포스트 개수 엔드포인트를 비교한 것입니다:

| **설명** | **Enterprise** | **X API v2** |
| :--- | :--- | :--- |
| 호스트 도메인 | https://gnip-api.x.com | https://api.x.com |
| 엔드포인트 경로 | /search/30day/accounts/:account&#95;name/:label/counts.json | /2/tweets/counts/recent |
| [인증](/ko/resources/fundamentals/authentication) | Basic 인증 | OAuth 2.0 Bearer Token |
| 타임스탬프 형식 | YYYYMMDDhhmm | YYYY-MM-DDTHH:mm:ssZ  <br />[ISO 8601 / RFC 3339](https://tools.ietf.org/html/rfc3339#section-5.6) |
| 반환되는 포스트가 생성된 후 경과한 최대 기간 | 31일 | 7일 |
| 지원되는 HTTP 메서드 | GET | GET |
| 기본 요청 속도 제한 | 검색 데이터 및 개수 요청 전체에 대해 1초당 20개의 요청  <br />분당 속도 제한은 계약서에 명시된 파트너별 한도에 따라 달라집니다. | 사용자당 15분당 180개 요청  <br />App당 15분당 450개 요청 |
| 지원되는 응답 형식 | JSON | JSON |
| [annotations](/ko/x-api/fundamentals/post-annotations)를 사용한 필터링 지원 |     | ✔   |
| [conversation&#95;id](/ko/x-api/fundamentals/conversation-id)를 사용한 필터링 지원 |     | ✔   |
| 포스트 data 배열에 대한 JSON 키 이름 | results | data |
| 시간 단위(세분도) | 일, 시간 또는 분 | 일, 시간 또는 분 |
| 타임존 | UTC | UTC |
| 기간 선택을 위한 요청 파라미터 | fromDate  <br />toDate | start&#95;time  <br />end&#95;time |
| 포스트 ID를 기준으로 탐색하기 위한 요청 파라미터 |     | since&#95;id  <br />until&#95;id |
| [Project](/ko/resources/fundamentals/developer-apps)에 연결된 [개발자 App](/ko/resources/fundamentals/developer-apps)의 자격 증명을 사용해야 함 |     | ✔   |

| 설명 | Enterprise | X API v2 |

| 호스트 도메인 | https://gnip-api.x.com | https://api.x.com |
| 엔드포인트 경로 | /search/fullarchive/accounts/:account&#95;name/:label/counts | /2/tweets/counts/all |
| [인증](/ko/resources/fundamentals/authentication) | Basic auth | OAuth 2.0 Bearer Token |
| 타임스탬프 형식 | YYYYMMDDHHMM | YYYY-MM-DDTHH:mm:ssZ  <br />[ISO 8601 / RFC 3339](https://tools.ietf.org/html/rfc3339#section-5.6) |
| 포스트 개수 반환 시 조회 가능한 최대 과거 시점 | 2006년 3월부터의 전체 아카이브 | 2006년 3월부터의 전체 아카이브 |
| 지원되는 HTTP 메서드 | GET  <br />POST | GET |
| 기본 요청 속도 제한 | 분당 요청 한도는 계약서에 명시된 대로 파트너별로 달라집니다.  <br />초당 20개 요청 | App당 15분에 300개 요청  <br />App당 1초에 1개 요청 |
| 세분성 | 일, 시간, 분 | 일, 시간, 분 |
| [annotations](/ko/x-api/fundamentals/post-annotations)를 사용한 필터링 지원 |     | ✔   |
| [conversation&#95;id](/ko/x-api/fundamentals/conversation-id)를 사용한 필터링 지원 |     | ✔   |
| 포스트 data 배열의 JSON 키 이름 | results | data |
| 기간 선택을 위한 요청 파라미터 | fromDate  <br />toDate | start&#95;time  <br />end&#95;time |
| 포스트 ID를 기준으로 탐색하기 위한 요청 파라미터 |     | since&#95;id  <br />until&#95;id |
| 페이지네이션을 위한 JSON 키 이름 | next | meta.next&#95;token |
| 페이지네이션을 위한 요청 파라미터 | next&#95;token | next&#95;token 또는 pagination&#95;token |
| 타임존 | UTC | UTC |
| [Academic Research access](/ko/x-api/getting-started/about-x-api)이 있는 [Project](/ko/resources/fundamentals/developer-apps)에 연결된 [developer App](/ko/resources/fundamentals/developer-apps)의 자격 증명을 사용해야 함 |     | ✔   |

<div id="filtering-operator-comparison">
  ### 필터링 연산자 비교
</div>

두 가지 버전(엔터프라이즈와 v2)의 포스트 개수 기능은 사용 가능한 연산자가 서로 다르며, 각 버전 내에서도 연산자 사용 가능 범위에 차이가 있습니다. 이에 대한 설명은 아래와 같습니다.

Enterprise

* 엔터프라이즈 연산자에는 하위 티어가 없습니다. 모든 엔터프라이즈 연산자는 모든 엔터프라이즈 사용자에게 제공됩니다.

X API v2

* **Core:** 이 연산자는 모든 v2 사용자에게 제공됩니다.
* **Advanced:** 이 연산자는 Academic Research 액세스 권한을 승인받은 사용자에게만 제공됩니다.

각 연산자 집합에 대한 자세한 내용은 다음 가이드를 참고하세요.

* [Enterprise operators](/ko/x-api/enterprise-gnip-2.0/fundamentals/search-api#building-search-queries)
* [X API v2 operators](/ko/x-api/posts/search/integrate/build-a-query)

이제 X API v2 내의 다양한 연산자 수준을 이해했으므로, 포스트 개수 기능에서 연산자 제공 여부를 정리한 표는 다음과 같습니다(셀을 비워 둔 경우 해당 연산자는 제공되지 않음을 의미합니다).
