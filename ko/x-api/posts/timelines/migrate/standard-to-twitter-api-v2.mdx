<div id="standard-v11-timelines-to-x-api-v2-timelines">
  ## 표준 v1.1 타임라인에서 X API v2 타임라인으로
</div>

v1.1 타임라인 엔드포인트(statuses/user&#95;timeline 및 statuses/mentions&#95;timeline)를 사용해 왔다면, 이 가이드는 표준 타임라인 엔드포인트와 X API v2 타임라인 엔드포인트 간의 유사점과 차이점을 이해하여 현재 통합을 새 버전으로 마이그레이션하는 데 도움을 주는 것을 목표로 합니다.

* **유사점:**
  * 인증:
    * OAuth 1.0a User Context (최신순 홈 타임라인, 사용자 포스트 타임라인, 사용자 멘션 타임라인)
    * OAuth 2.0 App-Only (사용자 포스트 타임라인)
  * 히스토리 접근 한도: 사용자 타임라인(사용자 포스트 타임라인)은 가장 최근 포스트 3,200개에 접근할 수 있고, 멘션 타임라인(사용자 멘션 타임라인)은 가장 최근 멘션 800개에 접근할 수 있습니다.
  * 포스트 편집 이력 및 메타데이터 지원
  * 레이트 리밋(사용자 포스트 타임라인)
  * 폴링 기반 새로 고침: since&#95;id 이후의 새 결과를 가져오는 기능
  * 포스트 ID를 통한 타임라인 탐색
  * 결과 사양:
    * 결과 순서: 결과는 최신순(가장 최근 항목이 먼저 오도록)으로 반환됨
    * 답글 제외 기능(사용자 포스트 타임라인에만 해당)
    * 리트윗 제외 기능(사용자 포스트 타임라인에만 해당)
* **차이점**
  * 새로운 인증 기능:
    * OAuth 2.0 App-Only (사용자 멘션 타임라인)
    * PKCE가 포함된 OAuth 2.0 Authorization Code Flow (최신순 홈 타임라인, 사용자 포스트 타임라인, 사용자 멘션 타임라인)
  * 액세스 요건: X API v2 App 및 Project 요건
  * 레이트 리밋(사용자 멘션 타임라인 및 최신순 홈 타임라인)
  * 추가 페이지네이션 방식
    * 응답당 서로 다른 max&#95;results(개수)
  * 응답 데이터 형식
  * 요청 매개변수
    * v2 fields 및 expansions를 포함해, 요청 매개변수에 따라 커스터마이즈된 데이터 형식
    * 추가로 사용 가능한 데이터: 메트릭, 포스트 애너테이션(annotations), 설문조사

<div id="similarities">
  ### 유사점
</div>

**인증**

v1.1 `statuses/user_timeline`과 X API v2 사용자 포스트 타임라인 엔드포인트는 모두 [OAuth 1.0a User Context](/ko/resources/fundamentals/authentication) 및 [OAuth 2.0 App-Only](/ko/resources/fundamentals/authentication#bearer-token-also-known-as-app-only)를 지원합니다. 따라서 X API v2 버전으로 마이그레이션하더라도 동일한 인증 방식과 권한 부여 토큰을 계속 사용할 수 있습니다.

**과거 데이터 액세스**

v1.1 `statuses/user_timeline`과 X API v2 사용자 포스트 타임라인 엔드포인트는 모두 최신 3,200개의 포스트(리트윗 포함)를 반환합니다.

v1.1 `statuses/mentions_timeline`과 X API v2 사용자 멘션 타임라인 엔드포인트는 최신 800개의 포스트를 반환할 수 있습니다.

**포스트 수정 이력 및 메타데이터 지원**

두 버전 모두 수정 이력을 설명하는 메타데이터를 제공합니다. 자세한 내용은 [filtered stream API 레퍼런스](/ko/x-api/posts/filtered-stream#api-reference-index)와 [포스트 수정 기본 사항 페이지](/ko/x-api/fundamentals/edit-posts)를 확인하세요.

**레이트 리밋**

|     |     |
| :--- | :--- |
| **Standard v1.1** | **X API v2** |
| user&#95;timeline:<br /><br />OAuth 1.0a User Context 사용 시 15분당 900개 요청<br /><br />OAuth 2.0 App-Only 사용 시 15분당 1500개 요청 | User Posts timeline:<br /><br />OAuth 1.0a User Context 사용 시 15분 단위 윈도우당 900개 요청<br /><br />OAuth 2.0 App-Only 사용 시 15분 단위 윈도우당 1500개 요청 |

**since&#95;id를 사용한 갱신 폴링**

두 버전 모두 since&#95;id를 사용해 최신 결과를 폴링할 수 있습니다.

**포스트 ID를 사용한 타임라인 탐색**

두 엔드포인트 모두 포스트 ID가 구성되는 방식에 기반하여 포스트 ID ‘타임스탬프’를 사용해 타임라인을 탐색할 수 있습니다. 기능은 전반적으로 동일하지만, 다음과 같은 차이가 있습니다.

|     |     |
| :--- | :--- |
| **Standard timelines v1.1** | **timelines v2** |
| since&#95;id(배타적)<br /><br />max&#95;id(포함) | since&#95;id(배타적)<br /><br />until&#95;id(역시 배타적이며, 포함이었던 max&#95;id와 대비됨) |

**응답 필터링 매개변수**

|     |     |
| :--- | :--- |
| **Standard timelines v1.1** | **timelines v2** |
| 응답 필터링 매개변수:<br /><br />* include&#95;rts<br />* exclude&#95;replies | 응답 필터링 매개변수:<br /><br />* exclude=retweets,replies |
| 예시 <br /><br />https://api.x.com/1.1/statuses/user&#95;timeline.json?user&#95;id=2244994945&amp;include&#95;rts=0&amp;&amp;exclude&#95;replies=1 | 예시:<br /><br />https://api.x.com/2/users/2244994945/tweets?max&#95;results=100&amp;exclude=retweets,replies |
| 참고:<br /><br />user&#95;timeline의 경우:<br /><br />* include&#95;rts=0을 사용해도 가능한 과거 포스트 최대 개수인 최신 3,200개는 변경되지 않습니다. | 참고:<br /><br />사용자 포스트 타임라인의 경우:<br /><br />* exclude=retweets를 사용해도 가능한 과거 포스트 최대 개수인 최신 3,200개는 변경되지 않습니다.<br />* exclude=replies를 사용하면 가능한 과거 포스트 최대 개수가 최신 800개의 답글로 줄어듭니다. |

<div id="differences">
  ### 차이점
</div>

**인증**

**v1.1 `statuses/mentions_timeline` 엔드포인트는 [OAuth 1.0a User Context](https://developer-staging.x.com/resources/fundamentals/authentication)만 지원합니다.  X API v2 사용자 멘션 타임라인 엔드포인트는 [OAuth 1.0a User Context](/ko/resources/fundamentals/authentication), [OAuth 2.0 App-Only](/ko/resources/fundamentals/authentication#bearer-token-also-known-as-app-only), 그리고 [OAuth 2.0 Authorization Code with PKCE](/ko/resources/fundamentals/authenticationoauth-2-0/authorization-code "이 방식은 인가된 앱이 사용자를 대신해, 사용자로서 동작할 수 있도록 합니다. 일반적으로 특정 사용자의 공개 정보를 조회하거나 게시할 때 사용되며, 이 엔드포인트가 반환하는 결과와 사용자 간의 관계를 앱이 인지해야 할 때 유용합니다. OAuth 2.0 Authorization Code with PKCE로 인증하는 방법을 알아보려면 클릭하세요.")를 모두 지원합니다. **

X API v2 사용자 포스트 타임라인 엔드포인트를 사용해 비공개 또는 프로모션 메트릭에 접근하려면 OAuth 1.0a User Context 또는 OAuth 2.0 Authorization Code with PKCE를 사용해야 하며, 메트릭을 조회하려는 해당 포스트를 작성한 사용자와 연관된 사용자 액세스 토큰을 전달해야 합니다.

**엔드포인트 URL**

X API v2 타임라인 엔드포인트는 사용자 ID에 해당하는 경로 매개변수 `:id`가 필요합니다.

* 표준 v1.1 엔드포인트:
  * https://api.x.com/1.1/statuses/home&#95;timeline
  * https://api.x.com/1.1/statuses/user&#95;timeline
  * https://api.x.com/1.1/statuses/mention&#95;timeline
* X API v2 엔드포인트:
  * https://api.x.com/2/users/:id/timelines/reverse&#95;chronological
  * https://api.x.com/2/users/:id/tweets
  * https://api.x.com/2/users/:id/mentions

**App 및 Project 요구사항**

X API v2 엔드포인트는 요청을 인증할 때 [Project](/ko/resources/fundamentals/developer-apps)와 연결된 [developer App](/ko/resources/fundamentals/developer-apps)에서 발급된 자격 증명을 사용해야 합니다. 모든 X API v1.1 엔드포인트는 Project와의 연결 여부와 관계없이 App 자격 증명을 사용할 수 있습니다.

**요청 한도 (Rate Limits)**

|     |     |
| :--- | :--- |
| **mentions&#95;timeline:**<br /><br />OAuth 1.0a User Context로 15분당 75개 요청 | **사용자 멘션 타임라인:**<br /><br />OAuth 1.0a User Context로 15분당 180개 요청  <br />OAuth 2.0 Bearer Token으로 15분당 450개 요청 |
| **home&#95;timelime:**<br /><br />15분당 15개 요청  <br /><br />홈 타임라인에서 최대 800개의 포스트를 가져올 수 있음 | **최신순 홈 타임라인:**<br /><br />15분당 180개 요청<br /><br />지난 7일 동안 타임라인에 생성된 모든 포스트뿐 아니라, 생성 날짜와 관계없이 가장 최근의 포스트 800개까지 반환할 수 있습니다. |

**X API v2 JSON 형식**

X API v2는 API에서 반환되는 객체(예: [Post](/ko/x-api/fundamentals/data-dictionary#tweet) 및 [user](/ko/x-api/fundamentals/data-dictionary#user) 객체)에 대해 새로운 JSON 구조를 도입하고 있습니다. X API v2 형식과 필드 및 expansions를 사용하는 방법에 대해서는 [가이드](/ko/x-api/fundamentals/data-dictionary#how-to-use-fields-and-expansions)와 보다 폭넓은 [data dictionary](/ko/x-api/fundamentals/data-dictionary)를 통해 더 알아볼 수 있습니다.

* JSON 루트 레벨에서, standard 엔드포인트는 statuses 배열 안에 Post 객체를 반환하는 반면, X API v2는 data 배열을 반환합니다.
* 리트윗 및 인용 &quot;statuses&quot;를 참조하는 대신, X API v2 JSON은 리트윗 및 인용 트윗을 참조합니다. contributors, user.translator&#95;type과 같은 많은 레거시 및 사용 중단 필드는 제거되고 있습니다.
* Post 객체의 favorites와 user 객체의 favorites를 모두 사용하는 대신, X API v2는 like라는 용어를 사용합니다.
* X는 값이 없는 JSON 값(예: null)은 페이로드에 기록하지 않는다는 관례를 채택하고 있습니다. Post 및 user 속성은 null이 아닌 값을 가진 경우에만 포함됩니다.

standard v1.1과 X API v2 엔드포인트 버전 간의 가장 큰 차이점 중 하나는 페이로드에 어떤 필드가 반환될지를 선택하는 방식입니다. standard 엔드포인트에서는 페이로드에 어떤 필드 또는 필드 집합이 반환될지를 지정하기 위해 여러 파라미터를 사용할 수 있었던 반면, X API v2 버전에서는 이러한 다양한 파라미터를 [fields](/ko/x-api/fundamentals/fields) 및 [expansions](/ko/x-api/fundamentals/expansions)로 단순화했습니다.

* 필드: X API v2 엔드포인트를 사용하면 페이로드에 어떤 필드가 포함될지 선택할 수 있습니다. 예를 들어, Post, User, Media, Place, Poll 객체 모두 반환할(또는 반환하지 않을) 필드 목록을 가지고 있습니다.

* expansions: Post JSON 페이로드에서 참조되는 관련 객체를 확장하는 데 사용됩니다. 예를 들어, 모든 리트윗과 답글은 다른 Post를 참조합니다. expansions=referenced&#95;tweets.id로 설정하면, 이러한 다른 Post 객체가 tweet.fields 설정에 따라 확장됩니다. 사용자, 투표, 미디어와 같은 다른 객체들도 확장할 수 있습니다.

* conversation&#95;id

* context 및 entities를 포함한 두 개의 새로운 [annotations](/ko/x-api/fundamentals/post-annotations) 필드

* 여러 개의 새로운 [metrics](/ko/x-api/fundamentals/metrics) 필드

표준 v1.1 필드를 최신 v2 필드에 매핑하는 데 도움이 되는 [데이터 포맷 마이그레이션 가이드](/ko/x-api/migrate/data-format-migration#migrating-from-standard-v1-1s-data-format-to-v2)를 제공하고 있습니다. 이 가이드는 특정 필드를 반환하기 위해 v2 요청과 함께 전달해야 하는 expansions 및 field 파라미터도 구체적으로 안내합니다.
