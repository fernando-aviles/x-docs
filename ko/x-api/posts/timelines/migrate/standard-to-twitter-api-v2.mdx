<div id="standard-v11-timelines-to-x-api-v2-timelines">
  ## 표준 v1.1 타임라인에서 X API v2 타임라인으로
</div>

v1.1 타임라인 엔드포인트(statuses/user&#95;timeline 및 statuses/mentions&#95;timeline)를 사용해 왔다면, 이 가이드의 목적은 표준 타임라인 엔드포인트와 X API v2 타임라인 엔드포인트 간의 유사점과 차이점을 이해하여 현재 통합을 새 버전으로 마이그레이션할 수 있도록 돕는 것입니다.

* **유사점:**
  * 인증:
    * OAuth 1.0a User Context (역순 홈 타임라인, 사용자 포스트 타임라인 및 사용자 멘션 타임라인)
    * OAuth 2.0 App-Only (사용자 포스트 타임라인)
  * 과거 데이터 액세스 한도: 사용자 타임라인(사용자 포스트 타임라인)은 가장 최근 3,200개의 포스트에 액세스할 수 있고, 멘션 타임라인(사용자 멘션 타임라인)은 가장 최근 800개의 멘션에 액세스할 수 있습니다.
  * 포스트 편집 이력 및 메타데이터 지원
  * 레이트 리밋(사용자 포스트 타임라인)
  * 새로고침 폴링: `since_id` 이후의 새 결과를 가져오는 기능
  * 포스트 ID를 통한 타임라인 탐색
  * 결과 사양:
    * 결과 순서: 결과는 역순(최신순)으로 반환됨
    * 답글 제외 기능(사용자 포스트 타임라인에만 해당)
    * 리트윗 제외 기능(사용자 포스트 타임라인에만 해당)
* **차이점**
  * 새로운 인증 기능:
    * OAuth 2.0 App-Only (사용자 멘션 타임라인)
    * OAuth 2.0 Authorization Code Flow with PKCE (역순 홈 타임라인, 사용자 포스트 타임라인 및 사용자 멘션 타임라인)
  * 액세스 요건: X API v2 앱 및 Project 요건
  * 레이트 리밋(사용자 멘션 타임라인 및 역순 홈 타임라인)
  * 추가 페이지네이션 방식
    * 응답마다 서로 다른 max&#95;results(개수)
  * 응답 데이터 형식
  * 요청 파라미터
    * v2 필드 및 expansions를 포함해, 요청 파라미터를 기반으로 한 맞춤형 데이터 형식
    * 추가로 사용 가능한 데이터: 메트릭, 포스트 주석, 투표

<div id="similarities">
  ### 유사점
</div>

**인증**

v1.1 `statuses/user_timeline`과 X API v2 사용자 포스트 타임라인 엔드포인트는 모두 [OAuth 1.0a User Context](/ko/resources/fundamentals/authentication)와 [OAuth 2.0 App-Only](/ko/resources/fundamentals/authentication#bearer-token-also-known-as-app-only)를 지원합니다. 따라서 X API v2 버전으로 마이그레이션하더라도 동일한 인증 방식과 권한 부여 토큰을 계속 사용할 수 있습니다.

**과거 데이터 액세스**

v1.1 `statuses/user_timeline`과 X API v2 사용자 포스트 타임라인 엔드포인트는 모두 리트윗을 포함하여 가장 최근의 포스트 3,200개를 반환합니다.

v1.1 `statuses/mentions_timeline`과 X API v2 사용자 멘션 타임라인 엔드포인트는 가장 최근의 포스트 800개를 반환할 수 있습니다.

**포스트 편집 내역 및 메타데이터 지원**

두 버전 모두 편집 내역을 설명하는 메타데이터를 제공합니다. 자세한 내용은 [filtered stream API 레퍼런스](/ko/x-api/posts/filtered-stream#api-reference-index)와 [포스트 편집 기본 사항 페이지](/ko/x-api/fundamentals/edit-posts)를 확인하세요.

**요청 한도(레이트 리밋)**

|     |     |
| :--- | :--- |
| **Standard v1.1** | **X API v2** |
| user&#95;timeline:<br /><br />OAuth 1.0a User Context 사용 시 15분당 900개의 요청<br /><br />OAuth 2.0 App-Only 사용 시 15분당 1500개의 요청 | User Posts timeline:<br /><br />OAuth 1.0a User Context 사용 시 15분 단위(윈도우)당 900개의 요청<br /><br />OAuth 2.0 App-Only 사용 시 15분 단위(윈도우)당 1500개의 요청 |

**since&#95;id를 사용한 폴링 기반 새로 고침**

두 버전 모두 `since_id`를 사용하여 최신 결과를 폴링할 수 있습니다.

**포스트 ID를 통한 타임라인 탐색**

두 엔드포인트 모두 포스트 ID가 구성되는 방식에 기반해 포스트 ID &#39;타임스탬프&#39;를 사용하여 타임라인을 탐색할 수 있습니다. 기능은 일반적으로 동일하지만, 다음과 같은 차이점이 있습니다.

|     |     |
| :--- | :--- |
| **Standard timelines v1.1** | **timelines v2** |
| since&#95;id (exclusive)<br /><br />max&#95;id (inclusive) | since&#95;id (exclusive)<br /><br />until&#95;id (마찬가지로 exclusive이며, inclusive였던 max&#95;id와는 다름) |

**응답 필터링 파라미터**

|     |     |
| :--- | :--- |
| **Standard timelines v1.1** | **timelines v2** |
| 응답 필터링 파라미터:<br /><br />* include&#95;rts<br />* exclude&#95;replies | 응답 필터링 파라미터:<br /><br />* exclude=retweets,replies |
| 예시 <br /><br />https://api.x.com/1.1/statuses/user&#95;timeline.json?user&#95;id=2244994945&amp;include&#95;rts=0&amp;&amp;exclude&#95;replies=1 | 예시:<br /><br />https://api.x.com/2/users/2244994945/tweets?max&#95;results=100&amp;exclude=retweets,replies |
| 참고:<br /><br />user&#95;timeline의 경우:<br /><br />* include&#95;rts=0을 사용해도, 가장 최근 3,200개의 포스트라는 과거 포스트 한도는 변경되지 않습니다. | 참고:<br /><br />사용자 포스트 타임라인의 경우:<br /><br />* exclude=retweets를 사용해도, 가장 최근 3,200개의 포스트라는 과거 포스트 한도는 변경되지 않습니다.<br />* exclude=replies를 사용하면 과거 포스트 한도가 가장 최근 800개의 답글로 줄어듭니다. |

<div id="differences">
  ### 차이점
</div>

**인증**

**v1.1 `statuses/mentions_timeline` 엔드포인트는 [OAuth 1.0a User Context](https://developer-staging.x.com/resources/fundamentals/authentication)만 지원합니다. X API v2 user mention timeline 엔드포인트는 [OAuth 1.0a User Context](/ko/resources/fundamentals/authentication), [OAuth 2.0 App-Only](/ko/resources/fundamentals/authentication#bearer-token-also-known-as-app-only), [OAuth 2.0 Authorization Code with PKCE](/ko/resources/fundamentals/authenticationoauth-2-0/authorization-code "이 방식은 권한이 부여된 앱이 사용자를 대신해, 사용자로서 동작할 수 있도록 해 줍니다. 일반적으로 특정 사용자의 공개 정보를 조회하거나 게시하는 데 사용되며, 앱이 사용자와 이 엔드포인트가 반환하는 결과 간의 관계를 인지해야 할 때 유용합니다. OAuth 2.0 Authorization Code with PKCE로 인증하는 방법을 알아보려면 클릭하세요.")를 모두 지원합니다. **

X API v2 user 포스트 timeline 엔드포인트를 사용해 비공개 또는 프로모션 메트릭에 접근하려면 OAuth 1.0a User Context 또는 OAuth 2.0 Authorization Code with PKCE를 사용해야 하며, 메트릭에 접근하려는 포스트를 작성한 사용자와 연관된 사용자 액세스 토큰을 전달해야 합니다.

**엔드포인트 URL**

X API v2 timelines 엔드포인트는 사용자 ID에 해당하는 경로 매개변수 `:id`가 필요합니다.

* 표준 v1.1 엔드포인트:
  * https://api.x.com/1.1/statuses/home&#95;timeline
  * https://api.x.com/1.1/statuses/user&#95;timeline
  * https://api.x.com/1.1/statuses/mention&#95;timeline
* X API v2 엔드포인트:
  * https://api.x.com/2/users/:id/timelines/reverse&#95;chronological
  * https://api.x.com/2/users/:id/tweets
  * https://api.x.com/2/users/:id/mentions

**App 및 Project 요구 사항**

X API v2 엔드포인트를 사용하려면, 요청을 인증할 때 [developer App](/ko/resources/fundamentals/developer-apps)에서 발급된 자격 증명을 사용해야 하며, 이 App은 [Project](/ko/resources/fundamentals/developer-apps)에 연결되어 있어야 합니다. 모든 X API v1.1 엔드포인트는 Project에 연결되지 않은 App 또는 Project에 연결된 App의 자격 증명을 모두 사용할 수 있습니다.

**Rate Limits**

|     |     |
| :--- | :--- |
| **mentions&#95;timeline:**<br /><br />OAuth 1.0a User Context 사용 시 15분당 75개 요청 | **user mention timeline:**<br /><br />OAuth 1.0a User Context 사용 시 15분당 180개 요청  <br />OAuth 2.0 Bearer Token 사용 시 15분당 450개 요청 |
| **home&#95;timelime:**<br /><br />15분당 15개 요청  <br /><br />홈 타임라인에서 최대 800개의 포스트를 조회할 수 있음 | **reverse chronological home timeline:**<br /><br />15분당 180개 요청<br /><br />마지막 7일 동안 타임라인에 생성된 모든 포스트와, 생성일과 관계없이 가장 최근 포스트 800개까지 반환할 수 있습니다. |

**X API v2 JSON 형식**

X API v2는 API가 반환하는 객체에 대해 새로운 JSON 구조를 도입합니다. 여기에는 [포스트](/ko/x-api/fundamentals/data-dictionary#tweet) 및 [사용자](/ko/x-api/fundamentals/data-dictionary#user) 객체가 포함됩니다. X API v2 형식, 그리고 필드와 expansions를 사용하는 방법에 대해서는 [가이드](/ko/x-api/fundamentals/data-dictionary#how-to-use-fields-and-expansions)를 참고하고, 보다 포괄적인 [데이터 사전](/ko/x-api/fundamentals/data-dictionary)을 읽어보십시오.

* JSON 루트 수준에서 표준 엔드포인트는 statuses 배열에 포스트 객체를 반환하는 반면, X API v2는 data 배열을 반환합니다.
* 리트윗 및 인용한 &quot;statuses&quot;를 참조하는 대신, X API v2 JSON은 리트윗 및 인용 트윗을 참조합니다. contributors 및 user.translator&#95;type과 같은 많은 레거시 및 사용 중단 예정 필드는 제거되고 있습니다.
* 포스트 객체의 favorites와 사용자 객체의 favorites를 모두 사용하는 대신, X API v2는 like라는 용어를 사용합니다.
* X는 값이 없는 JSON 값(예: null)은 페이로드에 기록하지 않는 규칙을 채택하고 있습니다. 포스트 및 사용자 속성은 null이 아닌 값을 가진 경우에만 포함됩니다.

표준 v1.1과 X API v2 엔드포인트 버전 간의 가장 큰 차이 중 하나는 페이로드에서 어떤 필드를 반환할지 선택하는 방법입니다. 표준 엔드포인트에서는 페이로드에 어떤 필드 또는 필드 집합이 반환될지를 지정하기 위해 여러 매개변수를 사용할 수 있었던 반면, X API v2 버전은 이러한 다양한 매개변수를 [fields](/ko/x-api/fundamentals/fields) 및 [expansions](/ko/x-api/fundamentals/expansions)로 단순화합니다.

* 필드: X API v2 엔드포인트를 사용하면 payload에 어떤 필드가 포함될지 선택할 수 있습니다. 예를 들어, 포스트, 사용자, Media, Place, Poll 객체는 모두 반환(또는 제외)할 수 있는 필드 목록을 가지고 있습니다.

* expansions: 포스트 JSON payload에서 참조된 관련 객체를 확장하는 데 사용됩니다. 예를 들어, 모든 리트윗과 답글은 다른 포스트를 참조합니다. expansions=referenced&#95;tweets.id로 설정하면, 이 다른 포스트 객체들이 tweet.fields 설정에 따라 확장됩니다. 사용자, Poll, Media 등의 다른 객체도 확장할 수 있습니다.

* conversation&#95;id

* context 및 entities를 포함한 두 개의 새로운 [annotations](/ko/x-api/fundamentals/post-annotations) 필드

* 여러 개의 새로운 [metrics](/ko/x-api/fundamentals/metrics) 필드

표준 v1.1 필드를 최신 v2 필드에 매핑하는 데 도움이 되는 [data format migration guide](/ko/x-api/migrate/data-format-migration#migrating-from-standard-v1-1s-data-format-to-v2)를 준비해 두었습니다. 이 가이드는 또한 특정 필드를 반환하기 위해 v2 요청에 함께 전달해야 하는 expansions 및 fields 매개변수를 구체적으로 제공합니다.
