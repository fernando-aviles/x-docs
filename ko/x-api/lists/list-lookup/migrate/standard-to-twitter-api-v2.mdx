<div id="list-lookup-standard-v11-compared-to-x-api-v2">
  ### 리스트 조회: Standard v1.1과 X API v2 비교
</div>

standard v1.1의 [GET lists/show](https://developer.x.com/en/docs/twitter-api/v1/accounts-and-users/create-manage-lists/api-reference/get-lists-show) 및 [GET lists/ownerships](https://developer.x.com/en/docs/twitter-api/v1/accounts-and-users/create-manage-lists/api-reference/get-lists-ownerships) 엔드포인트를 사용해 왔다면, 이 가이드는 standard v1.1과 X API v2 리스트 조회 엔드포인트 간의 공통점과 차이점을 이해하는 데 도움을 주기 위한 것입니다.

* **유사점**
  * 인증 방법
  * 요청 한도
* **차이점**
  * 엔드포인트 URL
  * App 및 Project 요구 사항
  * 요청당 data 객체 수 제한
  * 응답 data 형식
  * 요청 매개변수

<div id="similarities">
  #### 유사점
</div>

**인증**

두 엔드포인트 버전 모두 [OAuth 1.0a User Context](/ko/resources/fundamentals/authentication#oauth-1-0a-2)와 [앱 전용(App only)](/ko/resources/fundamentals/authentication#app-only-authentication-and-oauth-2-0-bearer-token) 인증을 지원합니다. 따라서 이전에 표준 v1.1 리스트 조회 엔드포인트 중 하나를 사용하고 있었다면, X API v2 버전으로 마이그레이션하더라도 동일한 인증 방식을 계속 사용할 수 있습니다.

선호하는 인증 라이브러리/패키지에 따라 다르지만, 앱 전용 인증이 시작하기에 가장 쉬운 방법인 경우가 많으며, 간단한 요청 헤더만 설정하면 사용할 수 있습니다. 앱 전용 액세스 토큰을 생성하는 방법을 알아보려면 [이 앱 전용 가이드](/ko/resources/fundamentals/authentication#using-and-generating-an-app-only-bearer-token)를 참고하세요.

**요청 제한(레이트 리밋)**

|     |     |
| :--- | :--- |
| **Standard v1.1** | **X API v2** |
| /1.1/lists/show.json<br /><br />OAuth 1.0a User Context일 때 15분당 75회 요청 가능<br /><br />앱 전용(App only)일 때 15분당 75회 요청 가능 | /2/lists/:id<br /><br />OAuth 1.0a User Context일 때 15분당 75회 요청 가능<br /><br />OAuth 2.0 Authorization Code with PKCE일 때 15분당 75회 요청 가능 |
| /1.1/lists/ownerships.json<br /><br />OAuth 1.0a User Context일 때 15분당 15회 요청 가능<br /><br />앱 전용(App only)일 때 15분당 15회 요청 가능 | /2/users/:id/owned&#95;lists<br /><br />OAuth 1.0a User Context일 때 15분당 15회 요청 가능<br /><br />OAuth 2.0 Authorization Code with PKCE일 때 15분당 15회 요청 가능<br /><br />앱 전용(App only)일 때 15분당 15회 요청 가능 |

<div id="differences">
  #### 차이점
</div>

**엔드포인트 URL**

* Standard v1.1 엔드포인트:
  * GET https://api.x.com/1.1/lists/show.json
    (지정된 리스트 조회)
  * GET https://api.x.com/1.1/lists/ownerships.json
    (지정된 사용자가 소유한 리스트 조회)
* X API v2 엔드포인트:
  * GET https://api.x.com/2/lists/:id
    (지정된 리스트 조회)

  * GET https://api.x.com/2/users/:id/owned&#95;lists
    (지정된 사용자가 소유한 리스트 조회)

**App 및 Project 요구 사항**

X API v2 엔드포인트를 사용하려면 요청을 인증할 때 [developer App](/ko/resources/fundamentals/developer-apps)과 [Project](/ko/resources/fundamentals/developer-apps)에 연결된 자격 증명을 사용해야 합니다. 모든 X API v1.1 엔드포인트는 App 또는 Project에 연결된 App의 자격 증명을 사용할 수 있습니다.

**요청당 데이터 객체 제한**

Standard v1.1 /lists/ownerships 엔드포인트는 요청당 최대 1000개의 리스트를 반환할 수 있습니다. 새로운 v2 엔드포인트는 요청당 최대 100개의 리스트를 반환할 수 있습니다. 기본적으로 100개의 사용자 객체가 반환되며, 결과 개수를 변경하려면 1–100 사이의 숫자와 함께 query parameter인 max&#95;results= 를 전달해야 합니다. 그런 다음 응답 페이로드에 반환된 next&#95;token을 다음 요청에서 pagination&#95;token query parameter에 전달하여 페이지네이션을 계속할 수 있습니다.

**응답 데이터 형식**

Standard v1.1과 X API v2 엔드포인트 버전 간 가장 큰 차이점 중 하나는 페이로드에서 어떤 필드를 반환할지 선택하는 방식입니다.

Standard 엔드포인트의 경우, 기본적으로 많은 응답 필드를 받은 후, 매개변수를 사용하여 페이로드에 추가로 반환할 필드 또는 필드 집합을 지정할 수 있습니다.

X API v2 버전은 기본적으로 List id와 name 필드만 제공합니다. 추가 필드나 객체를 요청하려면 [fields](/ko/x-api/fundamentals/fields) 및 [expansions](/ko/x-api/fundamentals/expansions) 매개변수를 사용해야 합니다. 이 엔드포인트에서 요청한 List 필드는 기본 List 객체에 포함됩니다. 확장된 포스트 또는 사용자 객체와 필드는 응답 내 includes 객체로 반환됩니다. 그런 다음 사용자 및 확장된 포스트 객체에 있는 id 값을 매칭하여, 확장된 객체를 List 객체와 다시 연결할 수 있습니다. 

다음은 가능한 List 필드 및 expansions의 예시입니다:

* created&#95;at

* follower&#95;count

* member&#95;count

* owner&#95;id

* description

* private

|     |     |
| :--- | :--- |
| **엔드포인트** | **Expansion** |
| /2/lists/:id | owner&#95;id |
| /2/users/:id/owned&#95;lists | owner&#95;id |

이러한 새 매개변수에 대해서는 각각의 가이드 또는 [fields 및 expansions 사용 방법](/ko/x-api/fundamentals/data-dictionary#how-to-use-fields-and-expansions)에 대한 가이드를 참고하시기를 권장합니다. 

또한 Standard v1.1 필드를 최신 v2 필드에 매핑하는 데 도움이 되는 [데이터 형식 마이그레이션 가이드](/ko/x-api/migrate/data-format-migration)도 준비해 두었습니다. 이 가이드는 특정 필드를 반환하기 위해 v2 요청에 함께 전달해야 하는 expansions 및 field 매개변수도 구체적으로 안내합니다. 

특정 필드를 요청하는 방식이 변경된 것 외에도, X API v2는 [Post](/ko/x-api/fundamentals/data-dictionary#tweet) 및 [user](/ko/x-api/fundamentals/data-dictionary#user) 객체를 포함하여 API가 반환하는 객체에 대해 새로운 JSON 설계를 도입하고 있습니다.

* JSON 루트 수준에서, Standard 엔드포인트는 statuses 배열에 Post 객체를 반환하는 반면, X API v2는 data 배열을 반환합니다. 

* 리트윗 및 인용된 &quot;statuses&quot;를 참조하는 대신, X API v2 JSON은 리트윗 및 인용된 트윗을 참조합니다. contributors 및 user.translator&#95;type과 같은 많은 레거시 및 더 이상 사용되지 않는 필드가 제거되고 있습니다. 

* Post 객체의 favorites와 user 객체의 favourites를 모두 사용하는 대신, X API v2는 like라는 용어를 사용합니다. 

* X는 값이 없는 JSON 값(예: null)을 페이로드에 기록하지 않는 규칙을 채택하고 있습니다. Post 및 user 속성은 null이 아닌 값을 가진 경우에만 포함됩니다.

**요청 매개변수**

다음 Standard v1.1 요청 매개변수는 X API v2에서 이에 해당하는 항목이 있습니다:

**ID로 리스트 조회**

|     |     |
| :--- | :--- |
| **Standard v1.1** | **X API v2** |
| list&#95;id | id  |
| slug | 해당 없음 |
| owner&#95;screen&#95;name | 해당 없음 |
| owner&#95;id | expansions/fields 매개변수로 요청됨 |

**사용자 소유 리스트 조회**

|     |     |
| :--- | :--- |
| **Standard v1.1** | **X API v2** |
| user&#95;id | id  |
| screen&#95;name | 해당 없음 |
| count | max&#95;results |
| cursor | pagination&#95;token |
