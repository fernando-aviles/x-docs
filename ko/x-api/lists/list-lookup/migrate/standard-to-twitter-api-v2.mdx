<div id="list-lookup-standard-v11-compared-to-x-api-v2">
  ### List 조회: 표준 v1.1와 X API v2 비교
</div>

표준 v1.1의 [GET lists/show](https://developer.x.com/en/docs/twitter-api/v1/accounts-and-users/create-manage-lists/api-reference/get-lists-show) 및 [GET lists/ownerships](https://developer.x.com/en/docs/twitter-api/v1/accounts-and-users/create-manage-lists/api-reference/get-lists-ownerships) 엔드포인트를 사용해 왔다면, 이 가이드는 표준 v1.1과 X API v2의 List 조회 엔드포인트 간 유사점과 차이점을 이해하는 데 도움이 되도록 작성되었습니다.

* **유사점**
  * 인증 방식
  * 레이트 리밋
* **차이점**
  * 엔드포인트 URL
  * 앱 및 Project 요구 사항
  * 요청당 데이터 객체 수 제한
  * 응답 데이터 형식
  * 요청 매개변수

<div id="similarities">
  #### 유사점
</div>

**인증**

두 엔드포인트 버전 모두 [OAuth 1.0a User Context](/ko/resources/fundamentals/authentication#oauth-1-0a-2)와 [App only](/ko/resources/fundamentals/authentication#app-only-authentication-and-oauth-2-0-bearer-token)를 지원합니다. 따라서 이전에 Standard v1.1 List lookup 엔드포인트 중 하나를 사용하고 계셨다면, X API v2 버전으로 마이그레이션하더라도 동일한 인증 방식을 계속 사용할 수 있습니다.

사용 중인 인증 라이브러리/패키지에 따라 다를 수 있지만, App only 인증이 대부분의 경우 가장 쉽게 시작할 수 있는 방법이며, 단순한 요청 헤더 설정만으로 사용할 수 있습니다. App only Access Token을 생성하는 방법은 [이 App only 가이드](/ko/resources/fundamentals/authentication#using-and-generating-an-app-only-bearer-token)를 참고하세요.

**요청 한도**

|     |     |
| :--- | :--- |
| **Standard v1.1** | **X API v2** |
| /1.1/lists/show.json<br /><br />OAuth 1.0a User Context 사용 시 15분당 75회 요청 가능<br /><br />App only 사용 시 15분당 75회 요청 가능 | /2/lists/:id<br /><br />OAuth 1.0a User Context 사용 시 15분당 75회 요청 가능<br /><br />OAuth 2.0 Authorization Code with PKCE 사용 시 15분당 75회 요청 가능 |
| /1.1/lists/ownerships.json<br /><br />OAuth 1.0a User Context 사용 시 15분당 15회 요청 가능<br /><br />App only 사용 시 15분당 15회 요청 가능 | /2/users/:id/owned&#95;lists<br /><br />OAuth 1.0a User Context 사용 시 15분당 15회 요청 가능<br /><br />OAuth 2.0 Authorization Code with PKCE 사용 시 15분당 15회 요청 가능<br /><br />App only 사용 시 15분당 15회 요청 가능 |

<div id="differences">
  #### Differences
</div>

**엔드포인트 URL**

* 표준 v1.1 엔드포인트:
  * GET https://api.x.com/1.1/lists/show.json
    (지정된 리스트 조회)
  * GET https://api.x.com/1.1/lists/ownerships.json
    (지정된 사용자가 소유한 리스트 조회)
* X API v2 엔드포인트:
  * GET https://api.x.com/2/lists/:id
    (지정된 리스트 조회)

  * GET https://api.x.com/2/users/:id/owned&#95;lists
    (지정된 사용자가 소유한 리스트 조회)

**App 및 Project 요구 사항**

X API v2 엔드포인트는 요청을 인증할 때 [developer App](/ko/resources/fundamentals/developer-apps)이 [Project](/ko/resources/fundamentals/developer-apps)에 연결되어 있는 경우, 해당 App의 자격 증명을 사용해야 합니다. 모든 X API v1.1 엔드포인트는 단일 App이든 Project에 연결된 App이든 App의 자격 증명을 사용할 수 있습니다.

**요청당 data 객체 제한**

표준 v1.1 /lists/ownerships 엔드포인트는 요청당 최대 1000개의 리스트를 반환할 수 있습니다. 새로운 v2 엔드포인트는 요청당 최대 100개의 리스트를 반환할 수 있습니다. 기본적으로 100개의 사용자 객체가 반환되며, 결과 개수를 변경하려면 1–100 사이의 숫자를 값으로 하는 쿼리 매개변수 max&#95;results= 를 전달해야 합니다. 그런 다음 응답 페이로드에 포함되어 반환되는 next&#95;token 을 다음 요청에서 pagination&#95;token 쿼리 매개변수에 전달할 수 있습니다.

**응답 데이터 형식**

표준 v1.1과 X API v2 엔드포인트 버전 간의 가장 큰 차이점 중 하나는 페이로드에 어떤 필드를 반환할지 선택하는 방식입니다.

표준 엔드포인트의 경우, 기본적으로 많은 응답 필드를 받게 되며, 이후 매개변수를 사용해 어떤 추가 필드 또는 필드 집합을 페이로드에 반환할지 선택할 수 있습니다.

X API v2 버전은 기본적으로 리스트 id 및 이름 필드만 제공합니다. 추가 필드나 객체를 요청하려면 [fields](/ko/x-api/fundamentals/fields) 및 [expansions](/ko/x-api/fundamentals/expansions) 매개변수를 사용해야 합니다. 이 엔드포인트에서 요청한 모든 리스트 필드는 기본 리스트 객체에 포함되어 반환됩니다. 확장된 Post 또는 user 객체와 필드는 응답 내의 `includes` 객체에 반환됩니다. 그런 다음 사용자와 확장된 Post 객체에 있는 ID를 리스트 객체의 ID와 매칭하여 확장된 객체를 리스트 객체에 다시 연결할 수 있습니다. 

아래는 가능한 리스트 필드 및 expansions 예시입니다:

* created&#95;at

* follower&#95;count

* member&#95;count

* owner&#95;id

* description

* private

|     |     |
| :--- | :--- |
| **엔드포인트** | **확장(Expansion)** |
| /2/lists/:id | owner&#95;id |
| /2/users/:id/owned&#95;lists | owner&#95;id |

각 매개변수에 대한 개별 가이드를 참고하거나, [fields 및 expansions 사용 방법](/ko/x-api/fundamentals/data-dictionary#how-to-use-fields-and-expansions)에 대한 가이드를 읽어 이러한 새로운 매개변수에 대해 더 자세히 알아보시기를 권장합니다. 

또한 표준 v1.1 필드를 새로운 v2 필드에 매핑하는 데 도움이 되는 [데이터 형식 마이그레이션 가이드](/ko/x-api/migrate/data-format-migration)도 준비했습니다. 이 가이드는 특정 필드를 반환하기 위해 v2 요청에 함께 전달해야 하는 expansion 및 field 매개변수를 구체적으로 제공합니다. 

특정 필드를 요청하는 방식의 변경 사항 외에도, X API v2는 API가 반환하는 객체(예: [Post](/ko/x-api/fundamentals/data-dictionary#tweet) 및 [user](/ko/x-api/fundamentals/data-dictionary#user) 객체)에 대해 새로운 JSON 설계를 도입합니다.

* JSON 루트 수준에서, 표준 엔드포인트는 Post 객체를 statuses 배열에 반환하는 반면, X API v2는 data 배열을 반환합니다. 

* Retweeted 및 Quoted &quot;statuses&quot;를 참조하는 대신, X API v2 JSON은 Retweeted 및 Quoted Tweets를 참조합니다. contributors 및 user.translator&#95;type 과 같이 레거시이거나 더 이상 사용되지 않는 많은 필드는 제거됩니다. 

* Post 객체의 favorites 와 user 객체의 favourites 를 모두 사용하는 대신, X API v2는 like 라는 용어만 사용합니다. 

* X는 값이 없는 JSON 값(예: null)은 페이로드에 기록하지 않는 규칙을 채택하고 있습니다. Post 및 user 속성은 null 이 아닌 값을 가질 때만 포함됩니다.

**요청 매개변수**

다음 표준 v1.1 요청 매개변수는 X API v2에 상응하는 항목이 있습니다:

**ID로 리스트 조회**

|     |     |
| :--- | :--- |
| **표준 v1.1** | **X API v2** |
| list&#95;id | id  |
| slug | 해당 없음 |
| owner&#95;screen&#95;name | 해당 없음 |
| owner&#95;id | expansions/fields 매개변수로 요청 |

**사용자가 소유한 리스트 조회**

|     |     |
| :--- | :--- |
| **Standard v1.1** | **X API v2** |
| user&#95;id | id  |
| screen&#95;name | 해당 없음 |
| count | max&#95;results |
| cursor | pagination&#95;token |
