</div>

<div id="postman">
  ### Postman
</div>

Postman은 엔드포인트를 시험해 보는 데 매우 유용한 도구입니다. 각 Postman 요청에는 어떤 기능을 사용할 수 있는지 빠르게 이해할 수 있도록 모든 경로 및 요청 본문 매개변수가 포함되어 있습니다. Postman 컬렉션에 대해 더 자세히 알아보려면 [&quot;Postman 사용하기&quot;](/ko/tutorials/postman-getting-started) 페이지를 방문하세요.

  ## 핵심 개념

<div id="authentication">
  ### 인증
</div>

모든 X API v2 엔드포인트는 자격 증명(키와 토큰)을 사용하여 요청을 인증해야 합니다. 이 엔드포인트에 대한 요청을 인증할 때 OAuth 1.0a User Context, App only, OAuth 2.0 Authorization Code with PKCE 중 하나를 사용할 수 있습니다.

[OAuth 1.0a User Context](/ko/resources/fundamentals/authentication#oauth-1-0a-2)를 사용하는 경우, 성공적인 요청을 위해 API Key와 사용자 Access Token 일련을 사용해야 합니다. Access Token은 요청을 대신 수행하려는 사용자와 연관되어 있어야 합니다. 다른 사용자의 Access Token 일련을 생성하려면, 해당 사용자가 [3-legged OAuth flow](/ko/resources/fundamentals/authentication#obtaining-access-tokens-using-3-legged-oauth-flow)를 통해 App을 승인해야 합니다.

OAuth 1.0a는 사용하기 까다로울 수 있다는 점에 유의하세요. 이 인증 방법에 익숙하지 않다면, [라이브러리](/ko/x-api/tools-and-libraries/overview)를 사용하거나 Postman 같은 도구를 사용하거나, OAuth 2.0 또는 App only를 사용하여 요청을 인증할 것을 권장합니다.

[OAuth 2.0 Authorization Code with PKCE](/ko/resources/fundamentals/authentication#oauth-2-0-authorization-code-flow-with-pkce-2)는 애플리케이션의 스코프 및 여러 디바이스에 걸친 인가 플로우를 보다 세밀하게 제어할 수 있게 해 줍니다. OAuth 2.0을 사용하면 사용자 대신 수행할 수 있는 권한을 부여하는, 매우 세분화된 스코프를 선택할 수 있습니다.

App에서 OAuth 2.0을 사용하려면, Developer Console의 App settings 섹션에 있는 App의 인증 설정에서 OAuth 2.0을 활성화해야 합니다.

[App only](/ko/resources/fundamentals/authentication#app-only-authentication-and-oauth-2-0-bearer-token)는 요청에 [App only Access Token](/ko/resources/fundamentals/authentication#app-only-authentication-and-oauth-2-0-bearer-token)만 전달하면 됩니다. App only Access Token은 개발자 App 내에서 직접 생성하거나, [POST oauth2/token](/ko/resources/fundamentals/authentication#post-oauth2-token) 엔드포인트를 사용해 생성할 수 있습니다.

<div id="developer-console-projects-and-developer-apps">
  ### Developer Console, Project, 그리고 개발자 App
</div>

X API v2 엔드포인트와 함께 사용할 수 있는 인증 자격 증명 세트를 발급받으려면, 먼저 [개발자 계정에 가입](https://developer.x.com/en/portal/petition/essential/basic-info)하고, 해당 계정 내에 [Project](/ko/resources/fundamentals/developer-apps)를 설정한 뒤, 그 Project 내에 [개발자 App](/ko/resources/fundamentals/developer-apps)을 생성해야 합니다. 그런 다음 개발자 App에서 키와 토큰을 확인할 수 있습니다.

<div id="rate-limits">
  ### Rate limits
</div>

매일 수천 명의 개발자가 X API에 요청을 보냅니다. 이러한 요청의 막대한 양을 관리하기 위해 각 엔드포인트에는 [rate limit](https://developer.x.com/x-api/fundamentals/rate-limits)이 설정되어 있어, 앱 또는 인증된 사용자를 대신해 보낼 수 있는 요청 수가 제한됩니다.

이 엔드포인트에는 App 레벨과 사용자 레벨, 두 가지 rate limit이 적용됩니다. App rate limit은 개발자인 여러분이 특정 기간 동안 하나의 App(API Key 및 API Secret Key 또는 Bearer Token을 사용하는 것으로 간주됨)에서 이 엔드포인트로 보낼 수 있는 요청 수에 대한 제한을 의미합니다. 사용자 rate limit은 여러분이 요청을 보내는 데 사용하는 인증된 사용자가, 모든 개발자 App을 통틀어 List 포스트 조회를 수행할 수 있는 횟수에 제한이 있음을 의미합니다.

아래 표는 각 엔드포인트에 대한 rate limit을 보여줍니다.

| Endpoint | HTTP method | Rate limit |
| :--- | :--- | :--- |
| /2/lists/:id/tweets | GET | 15분당 900회 요청 |

<div id="fields-and-expansions">
  ### 필드와 expansions
</div>

X API v2 GET 엔드포인트를 사용하면 `fields` 및 `expansions`라는 도구 집합을 통해 API에서 어떤 데이터를 반환할지 정확하게 선택할 수 있습니다. `expansions` 파라미터를 사용하면 페이로드에서 참조되는 객체를 확장해 함께 받을 수 있습니다. 예를 들어 List 포스트를 조회할 때 다음과 같은 [expansions](/ko/x-api/fundamentals/expansions)를 가져올 수 있습니다:

* `author_id`

`fields` 파라미터를 사용하면 서로 다른 데이터 객체 내에서 어떤 [필드](/ko/x-api/fundamentals/fields)를 수신할지 정확하게 선택할 수 있습니다. 이 엔드포인트는 주로 포스트(Post) 객체를 반환합니다. 기본적으로 포스트(Post) 객체는 `id` 및 `text` 필드를 반환합니다. `tweet.created_at` 또는 `tweet.lang`와 같은 추가 필드를 받으려면, `fields` 파라미터를 사용하여 해당 필드를 명시적으로 요청해야 합니다.

[X API v2 데이터 사전](/ko/x-api/fundamentals/data-dictionary)에 [fields와 expansions를 함께 사용하는 방법](/ko/x-api/fundamentals/data-dictionary#how-to-use-fields-and-expansions)에 대한 가이드를 추가했습니다.

아래 표는 조회 엔드포인트에서 사용할 수 있는 필드와 expansions를 보여줍니다:

| 엔드포인트 | 필드 | Expansions |
| :--- | :--- | :--- |
| /2/lists/:id/tweets | `tweet.fields`, `user.fields` | `author_id` |

<div id="pagination">
  ### Pagination
</div>

List 포스트를 조회하면 많은 데이터가 반환될 수 있습니다. 항상 일관되고 성능이 뛰어난 결과를 제공하기 위해 페이지네이션을 사용합니다. 페이지네이션은 단일 응답에 담을 수 있는 양보다 더 많은 결과를 반환하는 X API v2 엔드포인트에서 제공되는 기능입니다. 이때 데이터는 일련의 “페이지”로 나누어 반환됩니다. 결과를 [페이지네이션하는 방법에 대해 더 알아보세요.](/ko/x-api/fundamentals/pagination)
