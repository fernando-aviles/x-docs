<div id="key-concepts">
  ## 핵심 개념

<div id="authentication">
  ### 인증
</div>

모든 X API v2 엔드포인트는 자격 증명(키와 토큰이라고도 함)을 사용해 요청을 인증해야 합니다. 이 엔드포인트에 대한 요청을 인증할 때 OAuth 1.0a User Context, App only 또는 PKCE가 포함된 OAuth 2.0 Authorization Code 중 하나를 사용할 수 있습니다.

[OAuth 1.0a User Context](/ko/resources/fundamentals/authentication#oauth-1-0a-2)를 사용하는 경우, API Key 세트와 사용자 Access Token 세트를 사용해야 요청이 성공합니다. Access Token은 요청을 대신하여 수행하려는 해당 사용자와 연결되어 있어야 합니다. 다른 사용자를 위한 Access Token 세트를 생성하려면, 그 사용자가 [3-legged OAuth flow](/ko/resources/fundamentals/authentication#obtaining-access-tokens-using-3-legged-oauth-flow)를 사용해 귀하의 App을 승인해야 합니다.

OAuth 1.0a는 사용하기 까다로울 수 있습니다. 이 인증 방식에 익숙하지 않다면, [라이브러리](/ko/x-api/tools-and-libraries/overview)를 사용하거나 Postman과 같은 도구를 사용하거나, OAuth 2.0 또는 App only를 사용해 요청을 인증할 것을 권장합니다.

[OAuth 2.0 Authorization Code with PKCE](/ko/resources/fundamentals/authentication#oauth-2-0-authorization-code-flow-with-pkce-2)는 애플리케이션의 scope와 여러 기기에 걸친 인가 플로에 대해 더 세밀한 제어를 제공합니다. OAuth 2.0을 사용하면 특정 사용자 대신 수행할 수 있는 권한을 부여하는 세밀한 scope를 선택할 수 있습니다.

App에서 OAuth 2.0을 활성화하려면, 개발자 콘솔의 App 설정 섹션에 있는 App의 인증 설정에서 이를 활성화해야 합니다.

[App only](/ko/resources/fundamentals/authentication#app-only-authentication-and-oauth-2-0-bearer-token)는 요청에 [App only Access Token](/ko/resources/fundamentals/authentication#app-only-authentication-and-oauth-2-0-bearer-token)만 포함하면 됩니다. App only Access Token은 개발자 App 내에서 직접 생성하거나, [POST oauth2/token](/ko/resources/fundamentals/authentication#post-oauth2-token) 엔드포인트를 사용해 생성할 수 있습니다.

<div id="developer-console-projects-and-developer-apps">
  ### 개발자 콘솔, Project, 그리고 개발자 App
</div>

X API v2 엔드포인트와 함께 사용할 수 있는 인증 자격 증명을 발급받으려면 먼저 [개발자 계정에 가입](https://developer.x.com/en/portal/petition/essential/basic-info)한 뒤, 해당 계정 내에 [Project](/ko/resources/fundamentals/developer-apps)를 설정하고 그 Project 안에 [개발자 App](/ko/resources/fundamentals/developer-apps)을 생성해야 합니다. 그런 다음 개발자 App 내에서 키와 토큰을 확인할 수 있습니다.

<div id="rate-limits">
  ### 요청 한도
</div>

매일 수천 명이 넘는 개발자들이 X API에 요청을 보냅니다. 이러한 요청의 방대한 양을 관리하기 위해 각 엔드포인트에는 [요청 한도](https://developer.x.com/x-api/fundamentals/rate-limits)가 설정되어 있으며, 이는 앱 또는 인증된 사용자를 대신해 보낼 수 있는 요청 수를 제한합니다.

이 엔드포인트에는 App 수준과 사용자 수준 두 가지 요청 한도가 적용됩니다. App 요청 한도는 개발자인 여러분이 특정 기간 동안 특정 App에서( API Key와 API Secret Key 또는 Bearer Token을 사용하는 것으로 간주) 이 엔드포인트로 보낼 수 있는 요청 수에 대한 제한을 의미합니다. 사용자 요청 한도는 여러분이 요청을 대신 보내는 인증된 사용자가 모든 개발자 App 전체에서 리스트 포스트 조회를 수행할 수 있는 횟수에 대한 제한을 의미합니다.

아래 표는 각 엔드포인트의 요청 한도를 보여줍니다.

| Endpoint | HTTP method | Rate limit |
| :--- | :--- | :--- |
| /2/lists/:id/tweets | GET | 15분당 900회 요청 |

<div id="fields-and-expansions">
  ### 필드 및 expansions
</div>

X API v2 GET 엔드포인트를 사용하면 `fields` 및 `expansions`라는 도구 세트를 통해 API에서 반환받고자 하는 data를 정확하게 선택할 수 있습니다. `expansions` 매개변수는 페이로드에서 id로만 참조되는 객체를 함께(확장하여) 반환하도록 합니다. 예를 들어, List 포스트를 조회할 때 다음과 같은 [expansions](/ko/x-api/fundamentals/expansions)을(를) 요청할 수 있습니다:

* `author_id`

`fields` 매개변수는 서로 다른 data 객체에서 어떤 [필드](/ko/x-api/fundamentals/fields)를 받을지 정확하게 선택할 수 있게 해줍니다. 이 엔드포인트는 주로 Post 객체를 반환합니다. 기본적으로 Post 객체는 `id` 및 `text` 필드를 반환합니다. `tweet.created_at` 또는 `tweet.lang`과 같은 추가 필드를 받으려면, 해당 필드들을 `fields` 매개변수를 사용해 명시적으로 요청해야 합니다.

[X API v2 data dictionary](/ko/x-api/fundamentals/data-dictionary)에 [fields 및 expansions 사용 방법](/ko/x-api/fundamentals/data-dictionary#how-to-use-fields-and-expansions)을 함께 설명하는 가이드를 추가해 두었습니다.

아래 표는 조회 엔드포인트에서 사용 가능한 필드 및 expansions를 보여줍니다:

| Endpoint | Fields | Expansions |
| :--- | :--- | :--- |
| /2/lists/:id/tweets | `tweet.fields`, `user.fields` | `author_id` |

<div id="pagination">
  ### 페이지네이션
</div>

List에 속한 포스트를 조회할 때는 많은 데이터를 반환할 수 있습니다. 언제든지 일관되고 높은 성능의 결과를 제공하기 위해 페이지네이션을 사용합니다. 페이지네이션은 단일 응답에 담을 수 있는 것보다 더 많은 결과를 반환하는 X API v2 엔드포인트의 기능입니다. 이런 경우 데이터는 여러 개의 ‘페이지’로 나누어 반환됩니다. 결과를 [페이지 단위로 조회하는 방법](/ko/x-api/fundamentals/pagination)에 대해 더 알아보세요.
