<div id="list-posts-lookup-standard-v11-compared-to-x-api-v2">
  ### 리스트 포스트 조회: 스탠다드 v1.1과 X API v2 비교
</div>

스탠다드 v1.1 [GET lists/statuses](https://developer.x.com/en/docs/twitter-api/v1/accounts-and-users/create-manage-lists/api-reference/get-lists-statuses) 엔드포인트를 사용해 왔다면, 이 가이드는 스탠다드 v1.1과 X API v2 엔드포인트 간의 공통점과 차이점을 이해하는 데 도움을 주기 위한 것입니다.

* **유사점**
  * 인증 방식
  * 요청 한도(레이트 리밋)
* **차이점**
  * 엔드포인트 URL
  * 앱 및 Project 요구 사항
  * 요청당 data 객체 수 제한
  * 응답 data 형식
  * 요청 매개변수

<div id="similarities">
  #### 유사점
</div>

**인증**

두 엔드포인트 버전 모두 [OAuth 1.0a User Context](/ko/resources/fundamentals/authentication#oauth-2-0)를 지원합니다. 따라서 이전에 표준 v1.1 List 포스트 조회 엔드포인트 중 하나를 사용하고 있었다면, X API v2 버전으로 마이그레이션하더라도 동일한 인증 방식을 계속 사용할 수 있습니다.

사용 중인 인증 라이브러리나 패키지에 따라 App only 인증이 시작하는 데 가장 쉬운 방법일 수 있으며, 간단한 요청 헤더 설정만으로 사용할 수 있습니다. App only 액세스 토큰을 생성하는 방법은 [이 App only 가이드](/ko/resources/fundamentals/authentication#bearer-token-also-known-as-app-only)를 참고하세요.

**요청 한도(Rate limits)**

|     |     |
| :--- | :--- |
| **Standard v1.1** | **X API v2** |
| /1.1/lists/statuses.json<br /><br />OAuth 1.0a User Context로 15분당 900개의 요청<br /><br />App only로 15분당 900개의 요청 | /2/lists/:id/tweets<br /><br />OAuth 1.0a User Context로 15분당 900개의 요청<br /><br />OAuth 2.0 Authorization Code with PKCE로 15분당 900개의 요청<br /><br />App only로 15분당 900개의 요청 |

<div id="differences">
  #### 차이점
</div>

**엔드포인트 URL**

* 표준 v1.1 엔드포인트:
  * GET https://api.x.com/1.1/lists/statuses.json
    (지정된 리스트에서 포스트 조회)
* X API v2 엔드포인트:
  * GET https://api.x.com/2/lists/:id/tweets
    (지정된 리스트에서 포스트 조회)

**App 및 Project 요구 사항**

X API v2 엔드포인트를 사용하려면 요청을 인증할 때 [개발자 App](/ko/resources/fundamentals/developer-apps)의 자격 증명을 사용해야 하며, 이 App은 [Project](/ko/resources/fundamentals/developer-apps)에 연결되어 있어야 합니다. 모든 X API v1.1 엔드포인트는 단독 App 또는 Project에 연결된 App의 자격 증명을 사용할 수 있습니다.

**요청당 데이터 객체 한도**

표준 v1.1 /lists/statuses 엔드포인트는 요청당 최대 5000개의 포스트를 반환할 수 있습니다. 새로운 v2 엔드포인트는 요청당 최대 100개의 포스트를 반환할 수 있습니다. 기본적으로 100개의 사용자 객체가 반환되며, 결과 수를 변경하려면 1–100 사이의 숫자와 함께 max&#95;results= 쿼리 매개변수를 전달해야 합니다. 그런 다음 응답 페이로드에 포함된 next&#95;token 값을 다음 요청의 pagination&#95;token 쿼리 매개변수에 전달할 수 있습니다.

**응답 데이터 형식**

표준 v1.1과 X API v2 엔드포인트 버전 간의 가장 큰 차이점 중 하나는 페이로드에 어떤 필드를 반환할지 선택하는 방식입니다.

표준 엔드포인트에서는 기본적으로 많은 응답 필드를 제공하며, 이후에 매개변수를 사용해 어떤 추가 필드 또는 필드 집합을 페이로드에 반환할지 선택할 수 있습니다.

X API v2 버전은 기본적으로 포스트 id 및 text 필드만 제공합니다. 추가 필드나 객체를 요청하려면 [필드](/ko/x-api/fundamentals/fields) 및 [expansions](/ko/x-api/fundamentals/expansions) 매개변수를 사용해야 합니다. 이 엔드포인트에서 요청한 모든 포스트 필드는 기본 포스트 객체에 포함되어 반환됩니다. 확장된 객체 필드는 응답 내 includes 객체에 포함되어 반환됩니다. 그런 다음 기본 객체의 ID와 확장 객체의 ID를 비교하여, 확장된 모든 객체를 기본 포스트 객체와 다시 매칭할 수 있습니다.

다음은 가능한 포스트 필드 및 expansions의 예시입니다:

* attachments
* author&#95;id
* context&#95;annotations
* created&#95;at
* geo
* lang

|     |     |
| :--- | :--- |
| **엔드포인트** | **확장 항목** |
| /2/lists/:id/tweets | author&#95;id |

해당 가이드에서 이 새로운 매개변수들에 대해 더 자세히 읽어 보시거나, [필드 및 expansions 사용 방법](/ko/x-api/fundamentals/data-dictionary#how-to-use-fields-and-expansions)에 대한 가이드를 참고하시기를 권장합니다.

또한 표준 v1.1 필드를 최신 v2 필드에 매핑하는 데 도움이 되는 [데이터 형식 마이그레이션 가이드](/ko/x-api/migrate/data-format-migration)도 준비해 두었습니다. 이 가이드는 특정 필드를 반환하기 위해 v2 요청에 전달해야 하는 구체적인 expansion 및 필드 매개변수도 제공합니다.

특정 필드를 요청하는 방식의 변경사항 외에도, X API v2는 [Post](/ko/x-api/fundamentals/data-dictionary#tweet) 및 [user](/ko/x-api/fundamentals/data-dictionary#user) 객체를 포함하여 API가 반환하는 객체에 대해 새로운 JSON 설계를 도입하고 있습니다.

* JSON 루트 레벨에서, 표준 엔드포인트는 **statuses** 배열에 Post 객체를 반환하는 반면, X API v2는 **data** 배열을 반환합니다.

* 리트윗 및 인용된 &quot;statuses&quot;를 참조하는 대신, X API v2 JSON은 리트윗 및 인용 트윗을 참조합니다. **contributors**, **user.translator&#95;type**과 같은 많은 레거시 및 지원 중단 필드는 제거되고 있습니다.

* **favorites**(Post 객체)와 **favourites**(user 객체)를 모두 사용하는 대신, X API v2는 **like**라는 용어를 사용합니다.

* X는 값이 없는 JSON 필드(예: **null**)는 페이로드에 기록하지 않는 규칙을 채택하고 있습니다. Post 및 user 속성은 null이 아닌 값을 가질 때만 포함됩니다.

**요청 매개변수**

다음 표준 v1.1 요청 매개변수에는 X API v2에서 상응하는 항목이 있습니다:

|     |     |
| :--- | :--- |
| Standard v1.1 | X API v2 |
| list&#95;id | id  |
| slug | 해당 없음 |
| owner&#95;screen&#95;name | 해당 없음 |
| owner&#95;id | author&#95;id 값을 가지는 expansions 매개변수로 요청 |
| since&#95;id | 해당 없음 |
| max&#95;id | 해당 없음 |
| include&#95;entities | entities 값을 가지는 tweet.fields 매개변수로 요청 |
| include&#95;rts | 해당 없음 |
| count | max&#95;results |

<div id="get-posts-from-a-list-v2">
  ### 리스트에서 포스트 가져오기 (v2)
</div>

<CodeGroup dropdown>
  ```bash cURL
  curl "https://api.x.com/2/lists/84839422/tweets?tweet.fields=created_at,public_metrics&max_results=100" \
    -H "Authorization: Bearer $BEARER_TOKEN"
  ```

  ```python Python
  import requests

  bearer_token = "YOUR_BEARER_TOKEN"
  url = "https://api.x.com/2/lists/84839422/tweets"

  params = {
      "tweet.fields": "created_at,public_metrics",
      "max_results": 100
  }
  headers = {"Authorization": f"Bearer {bearer_token}"}

  response = requests.get(url, headers=headers, params=params)
  print(response.json())
  ```

  ```python Python SDK
  from xdk import Client

  client = Client(bearer_token="YOUR_BEARER_TOKEN")

  # 리스트에서 포스트 가져오기
  for page in client.lists.get_tweets(
      "84839422",
      tweet_fields=["created_at", "public_metrics"],
      max_results=100
  ):
      for post in page.data:
          print(f"{post.created_at}: {post.text[:50]}...")
  ```

  ```javascript JavaScript SDK
  import { Client } from "@xdevplatform/xdk";

  const client = new Client({ bearerToken: "YOUR_BEARER_TOKEN" });

  // 리스트에서 포스트 가져오기
  const paginator = client.lists.getTweets("84839422", {
    tweetFields: ["created_at", "public_metrics"],
    maxResults: 100,
  });

  for await (const page of paginator) {
    page.data?.forEach((post) => {
      console.log(`${post.created_at}: ${post.text?.slice(0, 50)}...`);
    });
  }
  ```
