  ### 리스트 포스트 조회: Standard v1.1과 X API v2 비교
</div>

standard v1.1 [GET lists/statuses](https://developer.x.com/en/docs/twitter-api/v1/accounts-and-users/create-manage-lists/api-reference/get-lists-statuses) 엔드포인트를 사용해 왔다면, 이 가이드는 standard v1.1과 X API v2 엔드포인트 간의 유사점과 차이점을 이해하는 데 도움이 되도록 작성되었습니다.

* **유사점**
  * 인증 방법
  * 요청 한도
* **차이점**
  * 엔드포인트 URL
  * 앱 및 Project 요구 사항
  * 요청당 데이터 객체 한도
  * 응답 데이터 형식
  * 요청 매개변수

<div id="similarities">
  #### 유사점
</div>

**인증**

두 엔드포인트 버전 모두 [OAuth 1.0a User Context](/ko/resources/fundamentals/authentication#oauth-2-0)를 지원합니다. 따라서 이전에 표준 v1.1 리스트 포스트 조회 엔드포인트 중 하나를 사용해 왔다면, X API v2 버전으로 마이그레이션하더라도 동일한 인증 방식을 계속 사용할 수 있습니다.

선호하는 인증 라이브러리/패키지에 따라 다를 수 있지만, 앱 전용 인증이 시작하기에 가장 간단한 방법일 가능성이 높으며, 간단한 요청 헤더 설정만으로 사용할 수 있습니다. 앱 전용 액세스 토큰을 생성하는 방법을 알아보려면 [이 앱 전용 가이드](/ko/resources/fundamentals/authentication#bearer-token-also-known-as-app-only)를 참조하세요.

**요청 한도**

|     |     |
| :--- | :--- |
| **Standard v1.1** | **X API v2** |
| /1.1/lists/statuses.json<br /><br />OAuth 1.0a User Context 사용 시 15분당 900회까지 요청 가능<br /><br />앱 전용 사용 시 15분당 900회까지 요청 가능 | /2/lists/:id/tweets<br /><br />OAuth 1.0a User Context 사용 시 15분당 900회까지 요청 가능<br /><br />OAuth 2.0 Authorization Code with PKCE 사용 시 15분당 900회까지 요청 가능<br /><br />앱 전용 사용 시 15분당 900회까지 요청 가능 |

<div id="differences">
  #### 차이점
</div>

**엔드포인트 URL**

* 표준 v1.1 엔드포인트:
  * GET https://api.x.com/1.1/lists/statuses.json
    (지정된 리스트에서 트윗 조회)
* X API v2 엔드포인트:
  * GET https://api.x.com/2/lists/:id/tweets
    (지정된 리스트에서 트윗 조회)

**App 및 Project 요구 사항**

X API v2 엔드포인트는 요청을 인증할 때 [developer App](/ko/resources/fundamentals/developer-apps) 중 [Project](/ko/resources/fundamentals/developer-apps)에 연결된 App의 자격 증명을 사용해야 합니다. X API v1.1 엔드포인트는 어떤 App이든, 또는 Project에 연결된 App의 자격 증명을 사용할 수 있습니다.

**요청당 데이터 객체 제한**

표준 v1.1 /lists/statuses 엔드포인트에서는 요청당 최대 5000개의 포스트를 반환할 수 있습니다. 새로운 v2 엔드포인트에서는 요청당 최대 100개의 포스트를 반환할 수 있습니다. 기본적으로 100개의 사용자 객체가 반환되며, 결과 수를 변경하려면 1~100 사이의 숫자와 함께 쿼리 매개변수 max&#95;results= 를 전달해야 합니다. 그런 다음 응답 페이로드에 반환된 next&#95;token 값을 다음 요청의 pagination&#95;token 쿼리 매개변수에 전달할 수 있습니다.

**응답 데이터 형식**

표준 v1.1 버전과 X API v2 엔드포인트 버전 사이의 가장 큰 차이점 중 하나는 페이로드에 어떤 필드를 반환할지 선택하는 방식입니다.

표준 엔드포인트의 경우, 기본적으로 많은 응답 필드가 제공되며, 추가로 어떤 필드 또는 필드 집합을 페이로드에 반환할지 매개변수를 사용해 지정할 수 있습니다.

X API v2 버전은 기본적으로 포스트 id와 text 필드만 제공합니다. 추가 필드나 객체를 요청하려면 [fields](/ko/x-api/fundamentals/fields) 및 [expansions](/ko/x-api/fundamentals/expansions) 매개변수를 사용해야 합니다. 이 엔드포인트에서 요청한 모든 포스트 필드는 기본 Post 객체에 포함되어 반환됩니다. 확장된 객체 필드는 응답 내의 includes 객체에 반환됩니다. 그런 다음 기본 객체와 확장된 객체의 ID를 매칭하여, 확장된 객체를 기본 포스트 객체와 다시 연결할 수 있습니다.

다음은 가능한 포스트 필드와 expansions의 예시입니다:

* attachments
* author&#95;id
* context&#95;annotations
* created&#95;at
* geo
* lang

|     |     |
| :--- | :--- |
| **엔드포인트** | **Expansion** |
| /2/lists/:id/tweets | author&#95;id |

이 새로운 매개변수에 대해서는 각 가이드를 참고하거나, [fields 및 expansions 사용 방법](/ko/x-api/fundamentals/data-dictionary#how-to-use-fields-and-expansions)에 대한 가이드를 읽어 보시기를 권장합니다.

또한 표준 v1.1 필드를 새로운 v2 필드에 매핑하는 데 도움이 되는 [데이터 형식 마이그레이션 가이드](/ko/x-api/migrate/data-format-migration)도 준비했습니다. 이 가이드는 특정 필드를 반환하기 위해 v2 요청에 전달해야 하는 expansion 및 field 매개변수를 구체적으로 안내합니다.

특정 필드를 요청하는 방식이 변경된 것 외에도, X API v2는 [Post](/ko/x-api/fundamentals/data-dictionary#tweet) 및 [user](/ko/x-api/fundamentals/data-dictionary#user) 객체를 포함해 API가 반환하는 객체에 대해 새로운 JSON 설계를 도입하고 있습니다.

* JSON 루트 레벨에서, 표준 엔드포인트는 포스트 객체를 **statuses** 배열에 반환하는 반면, X API v2는 **data** 배열에 반환합니다.

* 리트윗 및 인용된 &quot;statuses&quot;를 참조하는 대신, X API v2 JSON은 리트윗 및 인용된 트윗을 참조합니다. **contributors**, **user.translator&#95;type** 과 같은 많은 레거시 및 사용 중단 필드가 제거되고 있습니다.

* 포스트 객체의 **favorites** 와 user 객체의 **favourites** 를 모두 사용하는 대신, X API v2는 **like** 라는 용어만 사용합니다.

* 값이 없는 JSON 값(예: **null**)은 페이로드에 기록하지 않는 규칙을 X에서 채택하고 있습니다. 포스트 및 user 속성은 null이 아닌 값을 가질 때만 포함됩니다.

**요청 매개변수**

다음 표준 v1.1 요청 매개변수는 X API v2에서 이에 상응하는 항목이 있습니다:

|     |     |
| :--- | :--- |
| 표준 v1.1 | X API v2 |
| list&#95;id | id  |
| slug | 해당 없음 |
| owner&#95;screen&#95;name | 해당 없음 |
| owner&#95;id | expansions 매개변수에 author&#95;id 값을 사용하여 요청 |
| since&#95;id | 해당 없음 |
| max&#95;id | 해당 없음 |
| include&#95;entities | tweet.fields 매개변수에 entities 값을 사용하여 요청 |
| include&#95;rts | 해당 없음 |
| count | max&#95;results |

<div id="get-posts-from-a-list-v2">
  ### 리스트에서 포스트 가져오기 (v2)
</div>

<CodeGroup dropdown>
  ```bash cURL
  curl "https://api.x.com/2/lists/84839422/tweets?tweet.fields=created_at,public_metrics&max_results=100" \
    -H "Authorization: Bearer $BEARER_TOKEN"
  ```

  ```python Python
  import requests

  bearer_token = "YOUR_BEARER_TOKEN"
  url = "https://api.x.com/2/lists/84839422/tweets"

  params = {
      "tweet.fields": "created_at,public_metrics",
      "max_results": 100
  }
  headers = {"Authorization": f"Bearer {bearer_token}"}

  response = requests.get(url, headers=headers, params=params)
  print(response.json())
  ```

  ```python Python SDK
  from xdk import Client

  client = Client(bearer_token="YOUR_BEARER_TOKEN")

  # 리스트에서 포스트 가져오기
  for page in client.lists.get_tweets(
      "84839422",
      tweet_fields=["created_at", "public_metrics"],
      max_results=100
  ):
      for post in page.data:
          print(f"{post.created_at}: {post.text[:50]}...")
  ```

  ```javascript JavaScript SDK
  import { Client } from "@xdevplatform/xdk";

  const client = new Client({ bearerToken: "YOUR_BEARER_TOKEN" });

  // 리스트에서 포스트 가져오기
  const paginator = client.lists.getTweets("84839422", {
    tweetFields: ["created_at", "public_metrics"],
    maxResults: 100,
  });

  for await (const page of paginator) {
    page.data?.forEach((post) => {
      console.log(`${post.created_at}: ${post.text?.slice(0, 50)}...`);
    });
  }
  ```
