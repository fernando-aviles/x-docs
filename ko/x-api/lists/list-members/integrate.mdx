  ## 핵심 개념

<div id="authentication">
  ### 인증
</div>

모든 X API v2 엔드포인트는 자격 증명(키 및 토큰)을 사용하여 요청을 인증해야 합니다. Lists **조회(lookup)** 엔드포인트에 대한 요청을 인증할 때는 OAuth 1.0a User Context, OAuth 2.0 Authorization Code with PKCE, 또는 App 전용(App only) 중 하나를 사용할 수 있습니다. 그러나 Lists **관리(manage)** 엔드포인트를 사용할 때는 반드시 OAuth 1.0a User Context 또는 OAuth 2.0으로 인증해야 합니다.

[OAuth 1.0a User Context](/ko/resources/fundamentals/authentication)를 사용하는 경우, 성공적인 요청을 위해 API Key 세트와 사용자 Access Token 세트를 사용해야 합니다. Access Token은 요청을 대신 수행하려는 대상 사용자와 연결되어 있어야 합니다. 다른 사용자를 위한 Access Token 세트를 생성하려면, 해당 사용자가 [3-legged OAuth flow](/ko/resources/fundamentals/authentication#obtaining-access-tokens-using-3-legged-oauth-flow)를 통해 귀하의 App을 승인해야 합니다.

OAuth 1.0a는 사용하기 까다로울 수 있다는 점에 유의해야 합니다. 이 인증 방식에 익숙하지 않다면 [라이브러리](/ko/x-api/tools-and-libraries/overview)를 사용하거나, Postman과 같은 도구를 사용하거나, OAuth 2.0 또는 App 전용 방식을 사용해 요청을 인증하는 것을 권장합니다.

[OAuth 2.0 Authorization Code with PKCE](/ko/resources/fundamentals/authentication#oauth-2-0-authorization-code-flow-with-pkce-2)는 애플리케이션의 스코프와 여러 기기에서의 인증 플로우를 보다 세밀하게 제어할 수 있게 해 줍니다. OAuth 2.0을 사용하면 사용자 대신 특정 권한을 부여하는 세분화된 스코프를 선택할 수 있습니다.

App에서 OAuth 2.0을 활성화하려면, Developer Console의 App 설정 섹션에 있는 App의 인증 설정에서 이를 활성화해야 합니다.

[App 전용](/ko/resources/fundamentals/authentication#oauth-2-0) 방식은 요청에 [App 전용 Access Token](/ko/resources/fundamentals/authentication#bearer-token-also-known-as-app-only)만 전달하면 됩니다. App 전용 Access Token은 개발자 App 내에서 직접 생성하거나, [POST oauth2/token](/ko/resources/fundamentals/authentication#post-oauth2-token) 엔드포인트를 사용해 생성할 수 있습니다.

<div id="developer-console-projects-and-developer-apps">
  ### Developer Console, Project 및 개발자 App
</div>

X API v2 엔드포인트와 호환되는 인증 자격 증명 세트를 얻으려면 [개발자 계정에 가입](https://developer.x.com/en/portal/petition/essential/basic-info)하고 해당 계정 내에 [Project](/ko/resources/fundamentals/developer-apps)를 설정한 다음, 그 Project 내에 [개발자 App](/ko/resources/fundamentals/developer-apps)을 생성해야 합니다. 그런 다음 개발자 App 내에서 키와 토큰을 확인할 수 있습니다.

<div id="rate-limits">
  ### Rate limits
</div>

매일 수많은 개발자가 X API에 요청을 보냅니다. 이러한 요청량을 관리하기 위해 각 엔드포인트에는 [rate limits](/ko/x-api/fundamentals/rate-limits)가 설정되어 있으며, 이는 앱 또는 인증된 사용자를 대신해 보낼 수 있는 요청 수를 제한합니다.

조회(Lookup, GET) 엔드포인트에는 App 수준과 사용자 수준 두 가지 rate limit이 적용되며, 관리(manage, POST/DELETE) 엔드포인트에는 사용자 수준 rate limit만 적용됩니다. App rate limit은 개발자인 여러분이 특정 기간 동안 어떤 App에서든(여기서는 API Key와 API Secret Key 또는 App only Access Token을 사용하는 것으로 간주) 이 엔드포인트로 전송할 수 있는 요청 수에 제한이 있음을 의미합니다. 사용자 rate limit은 여러분이 요청을 수행하는 대상인 인증된 사용자가, 어떤 개발자 App에서든 List 조회를 수행할 수 있는 횟수에 제한이 있음을 의미합니다.

아래 표는 각 엔드포인트에 대한 rate limit을 보여줍니다.

| Endpoint | HTTP method | Rate limit |
| :--- | :--- | :--- |
| /2/lists/:id/members | GET | 15분당 900회 요청 |
| /2/users/:id/list&#95;memberships | GET | 15분당 75회 요청 |
| /2/lists/:id/members | POST | 15분당 300회 요청 |
| /2/lists/:id/members/:user&#95;id | DELETE | 15분당 300회 요청 |

<div id="fields-and-expansions">
  ### 필드와 expansions
</div>

X API v2 GET 엔드포인트를 사용하면 `fields` 및 `expansions`라고 불리는 도구 집합을 통해 API에서 반환받고자 하는 데이터를 정확하게 선택할 수 있습니다. `expansions` 파라미터를 사용하면 페이로드에서 참조되는 객체를 확장하여 가져올 수 있습니다. 예를 들어, List 멤버 조회를 수행하면 다음과 같은 [expansions](/ko/x-api/fundamentals/expansions)을 가져올 수 있습니다:

* `pinned_tweet_id`

`fields` 파라미터를 사용하면 서로 다른 데이터 객체 내에서 수신하려는 [fields](/ko/x-api/fundamentals/fields)를 정확하게 선택할 수 있습니다. List 멤버 조회는 주로 user 객체를 반환합니다. 기본적으로 user 객체는 id, 이름, username 필드를 반환합니다. `user.created_at` 또는 `user.description`과 같은 추가 필드를 받으려면, `user.fields` 파라미터를 사용하여 해당 필드를 명시적으로 요청해야 합니다.

[fields 및 expansions](/ko/x-api/fundamentals/data-dictionary#how-to-use-fields-and-expansions)를 사용하는 방법에 대한 가이드를 추가해 두었습니다.

아래 표는 각 조회 엔드포인트에서 사용할 수 있는 fields 및 expansions를 보여줍니다:

| Endpoint | Fields | Expansions |
| :--- | :--- | :--- |
| /2/lists/:id/members | `user.fields`, `tweet.fields` | `pinned_tweet_id` |
| /2/users/:id/list&#95;memberships | `list.fields`, `user.fields` | `owner_id` |

<div id="pagination">
  ### 페이지네이션
</div>

멤버십/멤버를 조회하면 매우 많은 data가 반환될 수 있습니다. 언제나 일관되고 성능이 우수한 결과를 제공하기 위해 페이지네이션을 사용합니다. 페이지네이션은 단일 응답에 담을 수 있는 양을 초과하는 더 많은 결과를 반환하는 X API v2 엔드포인트의 기능입니다. 이런 경우 data는 연속된 여러 개의 &#39;페이지&#39;로 나누어 반환됩니다. 결과를 [페이지 단위로 조회하는 방법](/ko/x-api/fundamentals/pagination)에 대해 더 알아보세요.
