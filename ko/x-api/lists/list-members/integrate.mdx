</div>

  ## 핵심 개념

<div id="authentication">
  ### 인증
</div>

모든 X API v2 엔드포인트는 자격 증명(키와 토큰)을 사용해 요청을 인증해야 합니다. Lists **lookup** 엔드포인트에 대한 요청을 인증할 때는 OAuth 1.0a User Context, OAuth 2.0 Authorization Code with PKCE 또는 App only 중 하나를 사용할 수 있습니다. 그러나 **manage** Lists 엔드포인트를 사용하려면 반드시 OAuth 1.0a User Context 또는 OAuth 2.0으로 인증해야 합니다.

[OAuth 1.0a User Context](/ko/resources/fundamentals/authentication)를 사용하는 경우, 요청을 성공적으로 수행하려면 API Key와 사용자 Access Token 세트를 사용해야 합니다. Access Token은 요청을 대신 수행하려는 해당 사용자와 연결되어 있어야 합니다. 다른 사용자를 위한 Access Token 세트를 생성하려면, 해당 사용자가 [3-legged OAuth flow](/ko/resources/fundamentals/authentication#obtaining-access-tokens-using-3-legged-oauth-flow)를 사용해 App을 승인해야 합니다.

OAuth 1.0a는 사용하기 까다로울 수 있습니다. 이 인증 방식에 익숙하지 않다면 [라이브러리](/ko/x-api/tools-and-libraries/overview)를 사용하거나, Postman과 같은 도구를 사용하거나, OAuth 2.0 또는 App only를 사용해 요청을 인증할 것을 권장합니다.

[OAuth 2.0 Authorization Code with PKCE](/ko/resources/fundamentals/authentication#oauth-2-0-authorization-code-flow-with-pkce-2)는 애플리케이션의 scope와 여러 기기에 걸쳐 실행되는 인가 플로우를 더 세밀하게 제어할 수 있게 해줍니다. OAuth 2.0을 사용하면 사용자 대신 특정 권한을 부여하는 세분화된 scope들을 선택할 수 있습니다.

App에서 OAuth 2.0을 사용하려면, 개발자 콘솔의 App 설정 섹션에 있는 App의 인증 설정에서 OAuth 2.0을 활성화해야 합니다.

[App only](/ko/resources/fundamentals/authentication#oauth-2-0)는 요청에 [App only Access Token](/ko/resources/fundamentals/authentication#bearer-token-also-known-as-app-only)만 포함하면 됩니다. App only Access Token은 개발자 App 내에서 직접 생성하거나, [POST oauth2/token](/ko/resources/fundamentals/authentication#post-oauth2-token) 엔드포인트를 사용해 생성할 수 있습니다.

<div id="developer-console-projects-and-developer-apps">
  ### 개발자 콘솔, Project, 그리고 개발자 App
</div>

X API v2 엔드포인트에서 사용할 수 있는 인증 자격 증명 세트를 발급받으려면 [개발자 계정에 가입](https://developer.x.com/en/portal/petition/essential/basic-info)하고, 해당 계정 내에 [Project](/ko/resources/fundamentals/developer-apps)를 설정한 뒤, 그 Project 안에 [개발자 App](/ko/resources/fundamentals/developer-apps)을 생성해야 합니다. 그런 다음 해당 개발자 App에서 키와 토큰을 확인할 수 있습니다.

<div id="rate-limits">
  ### Rate limits
</div>

매일 수많은 개발자들이 X API에 요청을 보냅니다. 이러한 요청의 방대한 양을 관리하기 위해 각 엔드포인트에는 [rate limits](/ko/x-api/fundamentals/rate-limits)이 적용되며, 이를 통해 App 또는 인증된 사용자를 대신해 보낼 수 있는 요청 수가 제한됩니다.

조회(Lookup, GET) 엔드포인트에는 App 수준과 사용자 수준 모두에 요청 제한이 적용되며, 관리(Manage, POST/DELETE) 엔드포인트에는 사용자 수준에만 제한이 적용됩니다. App 요청 제한은 개발자인 여러분이 특정 기간 동안 특정 App(API Key와 API Secret Key 또는 App 전용 Access Token을 사용하는 것으로 간주)에서 해당 엔드포인트로 보낼 수 있는 요청 수에 한도가 있다는 뜻입니다. 사용자 요청 제한은 여러분이 요청을 대신 보내고 있는 인증된 사용자가 모든 개발자 App 전반에 걸쳐 리스트 조회를 수행할 수 있는 횟수에 한도가 있다는 뜻입니다.

아래 표는 각 엔드포인트의 요청 제한을 보여줍니다.

| Endpoint | HTTP method | Rate limit |
| :--- | :--- | :--- |
| /2/lists/:id/members | GET | 15분당 900회 요청 |
| /2/users/:id/list&#95;memberships | GET | 15분당 75회 요청 |
| /2/lists/:id/members | POST | 15분당 300회 요청 |
| /2/lists/:id/members/:user&#95;id | DELETE | 15분당 300회 요청 |

<div id="fields-and-expansions">
  ### Fields and expansions
</div>

X API v2 GET 엔드포인트에서는 `fields` 및 `expansions`라고 불리는 매개변수 집합을 사용해 API에서 어떤 데이터가 반환될지 정확히 선택할 수 있습니다. `expansions` 매개변수는 페이로드에서 참조되는 객체를 확장해 함께 반환하도록 합니다. 예를 들어 List 멤버를 조회하면 다음과 같은 [expansions](/ko/x-api/fundamentals/expansions)을(를) 요청할 수 있습니다:

* `pinned_tweet_id`

`fields` 매개변수를 사용하면 서로 다른 데이터 객체 안에서 어떤 [fields](/ko/x-api/fundamentals/fields)를 받을지 정확히 선택할 수 있습니다. List 멤버 조회는 주로 user 객체를 반환합니다. 기본적으로 user 객체는 id, 이름(name), username 필드를 반환합니다. `user.created_at`이나 `user.description`과 같은 추가 필드를 받으려면 `user.fields` 매개변수를 사용해 해당 필드를 명시적으로 요청해야 합니다.

[fields and expansions](/ko/x-api/fundamentals/data-dictionary#how-to-use-fields-and-expansions)를 사용하는 방법에 대한 가이드를 추가해 두었습니다.

아래 표는 각 조회 엔드포인트에서 사용 가능한 필드와 expansions를 보여 줍니다:

| Endpoint | Fields | Expansions |
| :--- | :--- | :--- |
| /2/lists/:id/members | `user.fields`, `tweet.fields` | `pinned_tweet_id` |
| /2/users/:id/list&#95;memberships | `list.fields`, `user.fields` | `owner_id` |

<div id="pagination">
  ### 페이지네이션
</div>

멤버십/멤버를 조회할 때는 매우 많은 데이터를 반환할 수 있습니다. 항상 일관되고 성능이 우수한 결과를 제공하기 위해 페이지네이션을 사용합니다. 페이지네이션은 단일 응답으로 반환할 수 있는 양보다 더 많은 결과를 반환하는 X API v2 엔드포인트에서 제공하는 기능입니다. 이런 경우 데이터는 여러 개의 ‘페이지’로 나누어 반환됩니다. 결과를 [페이지 단위로 나누어 조회하는 방법](/ko/x-api/fundamentals/pagination)에 대해 더 알아보세요.
