<div id="list-members-lookup-standard-v11-compared-to-x-api-v2">
  ### 리스트 멤버 조회: 표준 v1.1과 X API v2 비교
</div>

표준 v1.1 [GET lists/members](https://developer.x.com/en/docs/twitter-api/v1/accounts-and-users/create-manage-lists/api-reference/get-lists-members) 및 [GET lists/memberships](https://developer.x.com/en/docs/twitter-api/v1/accounts-and-users/create-manage-lists/api-reference/get-lists-memberships) 엔드포인트를 사용해 왔다면, 이 가이드는 표준 v1.1과 X API v2 리스트 멤버 엔드포인트 간의 공통점과 차이점을 이해하는 데 도움을 주기 위한 것입니다.

* **공통점**
  * 인증 방식
* **차이점**
  * 엔드포인트 URL
  * 레이트 리밋(요청 한도)
  * 앱 및 Project 요구 사항
  * 요청당 data 객체 수 제한
  * 응답 data 형식
  * 요청 매개변수

<div id="similarities">
  #### 유사점
</div>

**인증**

두 엔드포인트 버전 모두 [OAuth 1.0a User Context](/ko/resources/fundamentals/authentication#oauth-1-0a-2)와 [앱 전용](/ko/resources/fundamentals/authentication#oauth-2-0) 인증을 지원합니다. 따라서 이전에 standard v1.1 List members 엔드포인트 중 하나를 사용하고 있었다면, X API v2 버전으로 마이그레이션하더라도 동일한 인증 방식을 계속 사용할 수 있습니다.

사용하는 인증 라이브러리/패키지에 따라 다를 수 있지만, 일반적으로 앱 전용 인증 방식이 시작하기에 가장 간단하며, 간단한 요청 헤더 설정만으로 사용할 수 있습니다. 앱 전용 액세스 토큰을 생성하는 방법은 [이 앱 전용 가이드](/ko/resources/fundamentals/authentication#bearer-token-also-known-as-app-only)를 참고하세요.

<div id="differences">
  #### 차이점
</div>

**엔드포인트 URL**

* Standard v1.1 엔드포인트:
  * GET https://api.x.com/1.1/lists/members.json
    (지정된 리스트의 멤버 조회)
  * GET https://api.x.com/1.1/lists/memberships.json
    (사용자가 멤버로 속해 있는 리스트 조회)
* X API v2 엔드포인트:
  * GET https://api.x.com/2/lists/:id/members
    (지정된 리스트의 멤버 조회)

  * GET https://api.x.com/2/users/:id/list&#95;memberships
    (사용자가 멤버로 속해 있는 리스트 조회)

**요청 한도(레이트 리밋)**

|     |     |
| :--- | :--- |
| **Standard v1.1** | **X API v2** |
| /1.1/lists/members.json<br /><br />OAuth 1.0a User Context 사용 시 15분당 900회 요청 가능<br /><br />App only 사용 시 15분당 15회 요청 가능 | /2/lists/:id/members<br /><br />OAuth 1.0a User Context 사용 시 15분당 900회 요청 가능<br /><br />OAuth 2.0 Authorization Code with PKCE 사용 시 15분당 900회 요청 가능<br /><br />App only 사용 시 15분당 900회 요청 가능 |
| /1.1/lists/memberships.json<br /><br />OAuth 1.0a User Context 사용 시 15분당 15회 요청 가능<br /><br />App only 사용 시 15분당 15회 요청 가능 | /2/users/:id/list&#95;memberships<br /><br />OAuth 1.0a User Context 사용 시 15분당 15회 요청 가능<br /><br />OAuth 2.0 Authorization Code with PKCE 사용 시 15분당 15회 요청 가능<br /><br />App only 사용 시 15분당 15회 요청 가능 |

**App 및 Project 요구사항**

X API v2 엔드포인트를 사용하려면, 요청을 인증할 때 [developer App](/ko/resources/fundamentals/developer-apps)에서 발급된 자격 증명 중 [Project](/ko/resources/fundamentals/developer-apps)에 연결된 것을 사용해야 합니다. 모든 X API v1.1 엔드포인트는 Project에 연결되지 않은 App 또는 Project에 연결된 App의 자격 증명을 모두 사용할 수 있습니다.

**요청당 데이터 오브젝트 한도**

Standard v1.1 /1.1/lists/members 엔드포인트는 요청당 최대 5,000명의 사용자를 반환할 수 있습니다. 새로운 v2 엔드포인트는 요청당 최대 100명의 사용자를 반환할 수 있습니다. 기본적으로 100개의 사용자 오브젝트가 반환되며, 결과 개수를 변경하려면 1~100 사이의 숫자와 함께 쿼리 파라미터 max&#95;results= 를 전달해야 합니다. 그런 다음, 응답 페이로드에 포함된 next&#95;token 값을 다음 요청에서 pagination&#95;token 쿼리 파라미터에 전달하여 페이지네이션을 진행할 수 있습니다.

또한 /1.1/lists/memberships 엔드포인트는 요청당 최대 1,000개의 리스트를 반환할 수 있습니다. v2의 대체 엔드포인트에서는 요청당 최대 100개의 리스트를 반환할 수 있습니다. 기본적으로 100개의 리스트 오브젝트가 반환되며, 결과 개수를 변경하려면 /1.1/lists/members 와 동일한 방식으로 쿼리 파라미터 max&#95;results= 및 pagination&#95;token 을 사용하면 됩니다.

**응답 데이터 형식**

Standard v1.1 엔드포인트 버전과 X API v2 엔드포인트 버전 간의 가장 큰 차이점 중 하나는 페이로드에 어떤 필드를 반환할지 선택하는 방식입니다.

Standard 엔드포인트에서는 응답 필드의 상당수를 기본적으로 제공하며, 이후 파라미터를 사용해 페이로드에 추가로 반환할 필드 또는 필드 집합을 지정할 수 있습니다.

X API v2 버전 /users/:id/list&#95;memberships 는 기본적으로 List id 및 name 필드를 제공합니다. 추가 필드나 오브젝트를 요청하려면 [fields](/ko/x-api/fundamentals/fields) 및 [expansions](/ko/x-api/fundamentals/expansions) 파라미터를 사용해야 합니다. 이 엔드포인트에서 요청한 모든 리스트 필드는 기본 List 오브젝트에 포함되어 반환됩니다. 확장된 오브젝트 및 필드는 응답 내 includes 오브젝트에 포함되어 반환됩니다. 그런 다음 기본 오브젝트와 확장된 오브젝트에 모두 포함된 ID 값을 매칭하여, 확장된 오브젝트를 기본 List 오브젝트와 다시 연결할 수 있습니다. 

다음은 가능한 리스트 필드 및 expansions 예시입니다:

* created&#95;at

* follower&#95;count

* member&#95;count

* owner&#95;id

* description

* private

|     |     |
| :--- | :--- |
| **엔드포인트** | **Expansion** |
| /2/lists/:id/members | pinned&#95;tweet&#95;id |
| /2/users/:id/list&#95;memberships | owner&#95;id |

이러한 새로운 파라미터에 대해 더 알아보려면 각각의 가이드를 참고하시거나, [fields 및 expansions 사용 방법](/ko/x-api/fundamentals/data-dictionary#how-to-use-fields-and-expansions)에 대한 가이드를 읽어 보시기를 권장합니다. 

또한 표준 v1.1 필드를 최신 v2 필드에 매핑하는 데 도움이 되는 [데이터 형식 마이그레이션 가이드](/ko/x-api/migrate/data-format-migration)를 제공하고 있습니다. 이 가이드는 특정 필드를 반환하기 위해 v2 요청에 함께 전달해야 하는 구체적인 expansion 및 field 매개변수도 안내합니다. 

특정 필드를 요청하는 방식의 변경 사항 외에도 X API v2는 API가 반환하는 객체(예: [Post](/ko/x-api/fundamentals/data-dictionary#tweet) 및 [user](/ko/x-api/fundamentals/data-dictionary#user) 객체)에 대해 새로운 JSON 설계를 도입합니다.

* JSON 루트 수준에서 표준 엔드포인트는 statuses 배열로 Post 객체를 반환하는 반면, X API v2는 data 배열을 반환합니다. 

* Retweeted 및 Quoted &quot;statuses&quot;를 참조하는 대신 X API v2 JSON은 Retweeted 및 Quoted 트윗을 참조합니다. contributors 및 user.translator&#95;type과 같은 많은 레거시 및 사용 중단 필드는 제거되고 있습니다. 

* Post 객체의 favorites와 user 객체의 favourites를 모두 사용하는 대신 X API v2는 like라는 용어를 사용합니다. 

* X는 값이 없는 JSON 값(예: null)은 페이로드에 포함하지 않는 규칙을 채택하고 있습니다. Post 및 user 속성은 null이 아닌 값을 가진 경우에만 포함됩니다.

**요청 매개변수**

다음 표준 v1.1 요청 매개변수는 X API v2에서 다음과 같이 대응됩니다:

**리스트 멤버 조회**

|     |     |
| :--- | :--- |
| **표준 v1.1** | **X API v2** |
| list&#95;id | id  |
| slug | 해당 없음 |
| owner&#95;screen&#95;name | 해당 없음 |
| owner&#95;id | 해당 없음 |
| count | max&#95;results |
| cursor | pagination&#95;token |
| include&#95;entities | 해당 없음 |
| skip&#95;status | 해당 없음 |

**리스트 멤버십 조회**

|     |     |
| :--- | :--- |
| **표준 v1.1** | **X API v2** |
| user&#95;id | id  |
| screen&#95;name | 해당 없음 |
| count | max&#95;results |
| cursor | pagination&#95;token |
