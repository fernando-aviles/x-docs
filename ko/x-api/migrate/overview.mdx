| X API v2의 새로운 점   | X API v2에 새로 추가된 엔드포인트와 기능에 대해 알아보세요.                              |

| 마이그레이션 준비되셨나요?    | 일련의 가이드와 지침을 통해 마이그레이션을 시작해 보세요.                                   |
| 데이터 형식 마이그레이션 가이드 | 기존에 표준 v1.1 및 엔터프라이즈 데이터 형식과 함께 작동하던 데이터 파서를 어떻게 재설계할 수 있는지 알아보세요. |
| X API 엔드포인트 맵     | 표준 v1.1 및 엔터프라이즈 엔드포인트가 새로운 X API v2 엔드포인트에 어떻게 매핑되는지 확인해 보세요.     |

<div id="what-is-the-x-api-v2">
  ## X API v2란 무엇인가요?
</div>

X API v2는 이제 주요 X API이며, 제품 투자와 혁신이 집중되고 있는 버전입니다. 우리는 다양한 개발자 커뮤니티를 더 잘 지원하기 위해 개발자들과 협력하여 차세대 X API를 구축했습니다. 개발자 피드백을 바탕으로 더 폭넓은 요구를 충족하고, 새로운 기능과 엔드포인트를 도입하며, 개발자 경험을 개선할 수 있도록 API를 다시 설계했습니다.

X API v2는 이제 주요 X API이며, 제품 투자와 혁신이 집중되고 있는 버전입니다. 지난 몇 년 동안 개발자들과 협력하여 더 폭넓은 요구를 충족하고, 새로운 기능과 엔드포인트를 도입하며, 개발자 경험을 개선할 수 있도록 API를 다시 설계해 왔습니다. 우리는 개방형 개발자 플랫폼을 지속적으로 발전시키는 데 전념하고 있으며, 여러분이 X API v2로 어떤 것을 구축할지 매우 기대하고 있습니다.

<div id="why-migrate">
  ## 왜 마이그레이션해야 하나요?
</div>

X API v2는 현대적이고 더 지속 가능한 기반 위에 구축되었으며, 표준 v1.1 및 엔터프라이즈 제품을 대체하는 개선된 엔드포인트뿐만 아니라 완전히 새로운 기능도 제공합니다. 당사는 레거시 API(v1.1 및 엔터프라이즈) 고객이 v2로의 마이그레이션을 시작할 것을 강력히 권장하며, 궁극적으로 이들에 대한 지원을 종료(deprecate)할 계획입니다. X API를 사용하여 공개 대화를 수집·분석하고, X에서 사용자와 소통하며, 새로운 가치를 만들어 보세요.

이 섹션에서는 엔드포인트와 기능에 대해 설명합니다.

  X API 엔드포인트 맵

X API v2의 대부분 엔드포인트는 기존 엔드포인트를 대체하지만, 일부 새로운 엔드포인트도 도입했습니다. 아래는 v2에서 새롭게 제공되는 엔드포인트의 몇 가지 예시입니다:

* 사람들이 X Spaces를 더욱 잘 활용하고, 개발자들이 오디오 대화의 미래를 함께 만들어 갈 수 있도록 돕는 [Spaces 엔드포인트](/ko/x-api/spaces/introduction).
* 악의적이거나 방해가 되거나 오해의 소지가 있는 답글의 영향을 대규모로 제한하는 도구를 구축할 수 있게 해주는 [답글 숨기기](/ko/x-api/posts/hide-replies/introduction).
* [리스트 고정 및 고정 해제](/ko/x-api/lists/pinned-lists/introduction)를 하거나, 특정 사용자의 고정된 리스트를 조회할 수 있게 해주는 새로운 Lists 엔드포인트.
* 저장된 사용자 및 트윗 data가 컴플라이언스 요구 사항을 준수하는지 확인할 수 있도록 해주는 새로운 [배치 컴플라이언스 엔드포인트](/ko/x-api/compliance/batch-compliance/introduction).

  ### 새로운 및 업데이트된 응답 객체 살펴보기

다음 여섯 가지 데이터 객체를 v2 엔드포인트에서 사용할 수 있습니다:

| Object | Description |
|:--------|:-------------|
| [Tweet](/ko/x-api/fundamentals/data-dictionary#tweet) | Tweet 객체에는 `id`, `text`, `created_at`과 같은 루트 수준 필드가 다수 포함되어 있습니다. Tweet 객체는 `user`, `media`, `poll`, `place` 등 여러 자식 객체의 상위 객체이기도 합니다. |
| [User](/ko/x-api/fundamentals/data-dictionary#user) | User 객체에는 참조된 사용자를 설명하는 X 사용자 계정 메타데이터가 포함되어 있습니다. |
| [Spaces](/ko/x-api/fundamentals/data-dictionary#space) | Space 객체는 `state`, `host_id`, `is_ticketed`, `lang` 등의 필드로 구성됩니다. |
| [Lists](/ko/x-api/fundamentals/data-dictionary#list) | List 객체에는 `description`, `member_count`, `owner_id` 등을 포함하여 요청된 리스트에 대한 기본 정보가 들어 있습니다. |

| [Poll](/ko/x-api/fundamentals/data-dictionary#poll) | 트윗에 포함된 투표는 어떤 엔드포인트에서도 주요 객체는 아니지만, Tweet 객체 안에서 찾고 확장할 수 있습니다. |
| [Place](/ko/x-api/fundamentals/data-dictionary#place) | Place 객체는 `place_id`, `geo` 객체, `country_code` 등과 같은 필드로 구성됩니다. 이 정보는 트윗을 식별하고 위치별로 트윗을 분석하는 데 사용할 수 있습니다. |

<div id="flexibility-to-choose-which-objects-and-fields-you-receive">
  ### 수신할 객체와 필드를 선택할 수 있는 유연성
</div>

GET 엔드포인트에 요청을 보내면 해당 엔드포인트와 관련된 기본 데이터 객체를 수신하게 되며, 여기에 기본 필드 집합이 포함됩니다. 예를 들어, Tweet 객체는 기본적으로 `id` 및 `text` 필드를 제공합니다.

요청과 함께 추가 필드를 가져오려면 [fields](/ko/x-api/fundamentals/fields) 및 [expansions](/ko/x-api/fundamentals/expansions) 파라미터를 사용해야 합니다. expansions 파라미터를 사용하면 사용자의 고정된 트윗이나 미디어 객체와 같은 관련 데이터 객체를 가져올 수 있고, 필드 연산자를 사용하면 기본값을 넘어 반환된 객체 내에서 특정 필드를 요청할 수 있습니다.

다음은 각 X API v2 엔드포인트에서 요청할 수 있는 expansions의 전체 목록입니다:

| Object / Resource | 사용 가능한 Expansions |
|:-------------------|:----------------------|
| Tweets            | `author_id`, `edit_history_tweet_ids`, `entities.mentions.username`, `in_reply_to_user_id`, `referenced_tweets.id`, `referenced_tweets.id.author_id`, `attachments.poll_ids`, `attachments.media_keys`, `geo.place_id` |
| Users             | `pinned_tweet_id` |
| Spaces            | `invited_user_ids`, `speaker_ids`, `creator_id`, `host_ids`, `topic_ids` |

[fields 및 expansions를 사용하는 방법](/ko/x-api/fundamentals/data-dictionary#how-to-use-fields-and-expansions)에 대해 더 알아보세요.

<div id="edit-tweets">
  ## 트윗 수정
</div>

X API v2 엔드포인트는 수정된 트윗에 대한 메타데이터를 제공합니다. *Edit Tweet* 기능은 2022년 9월 1일 X 직원들을 대상으로 한 테스트에서 처음 도입되었습니다. 이 날짜부터는 요건을 충족하는 트윗을 30분 동안 최대 5번까지 수정할 수 있습니다. [트윗 수정](/ko/x-api/fundamentals/edit-posts)에 대해 더 알아보세요.
X API v2를 사용하면 개발자는 다음을 확인할 수 있습니다:

* 트윗이 생성 시점에 수정 가능한 상태였는지 여부. 설문조사가 포함된 트윗이나 예약된 트윗과 같이 수정할 수 없는 트윗도 있습니다.
* 트윗은 30분 동안 수정 가능하며, 최대 5번까지 수정할 수 있습니다. 수정 가능한 트윗의 경우, 수정 가능한 시간이 남아 있는지와 앞으로 몇 번 더 수정할 수 있는지 확인할 수 있습니다.
* 현재 보고 있는 트윗이 수정된 버전인지 여부(대부분의 경우, 특정 과거 버전을 Tweet ID로 요청하지 않는 한 API는 트윗의 가장 최신 버전을 반환합니다).
* 해당 트윗의 전체 수정 이력.
* 트윗 각 버전에 귀속되는 참여(engagement) 지표.

<div id="track-threaded-conversations">
  ## 스레드형 대화 추적
</div>

새로운 트윗 필드는 트윗이 어떤 대화 스레드에 속하는지 식별하는 데 도움이 됩니다. 대화 ID는 대화를 시작한 트윗의 트윗 ID입니다. 자세한 내용은 [대화 추적](/ko/x-api/fundamentals/conversation-id)을 참고하세요.

<div id="ready-to-migrate">
  ## 마이그레이션 준비
</div>

v2 엔드포인트를 사용하려면 다음 항목이 필요합니다:

* [개발자 계정](https://developer.x.com/en/portal/petition/essential/basic-info)
* [Project](resources/fundamentals/projects) 내에서 생성된 [개발자 App](https://developer.x.com/en/apps)
* 해당 Project의 개발자 App에서 발급된 [키와 토큰](resources/fundamentals/authentication)

Project 내의 App에서 발급된 키와 토큰을 사용하는 것이 중요합니다. Project 외부의 App에서 발급된 키와 토큰을 사용하는 경우 v2 엔드포인트에 요청을 보낼 수 없습니다.

개발자 계정을 보유하고 있으면 [개발자 콘솔](https://developer.x.com/en/portal/petition/essential/basic-info)에서 위의 모든 항목을 설정할 수 있습니다.

<div id="authentication">
  ### 인증
</div>

새로운 Twitter API에서는 서로 다른 엔드포인트에 액세스하기 위해 OAuth 1.0a User Context와 OAuth 2.0 Bearer Token이라는 두 가지 인증 패턴을 사용합니다. 각 패턴은 엔드포인트에 요청을 보낼 때 서로 다른 용도로 사용됩니다:

Twitter 사용자를 대신해 요청을 보낼 때는 OAuth 1.0a User Context가 필수입니다\
개발자 App을 대신해 요청을 보낼 때는 OAuth 2.0 Bearer Token이 필수입니다

<div id="tools-and-code">
  ## 도구 및 코드
</div>

새로운 엔드포인트와 기능에 익숙해지고 작업을 시작하는 데 도움이 되도록, 작업을 빠르게 시작할 수 있는 몇 가지 옵션을 제공합니다.

* Postman 클라이언트를 사용해 개별 엔드포인트로 요청을 보내고 연결할 수 있도록 하는 Twitter [Postman 컬렉션](https://app.getpostman.com/run-collection/9956214-784efcda-ed4c-4491-a4c0-a26470a67400)을 제공합니다. 이는 인증을 테스트하고 엔드포인트를 실험해 볼 수 있는 간편한 방법입니다.
* 또한 Twitter에서 지원하는 라이브러리와 서드파티 라이브러리 목록을 Ruby, Python, Node, Java 등을 포함한 다양한 언어로 제공합니다. 추가적인 내용을 보려면 [도구 및 라이브러리 페이지](/ko/x-api/tools-and-libraries/overview)를 참고하세요.

<div id="migrating-to-the-new-data-format">
  ## 새로운 데이터 형식으로 마이그레이션하기
</div>

v1.1 또는 엔터프라이즈에서 v2로 이전할 때에는, 데이터가 제공되는 형식이 크게 변경되었다는 점을 이해하는 것이 중요합니다. 우리는 새로운 필드를 추가하고, 필드의 순서를 수정했으며, 일부 경우에는 요소를 완전히 제거했습니다.

이러한 변경 사항을 더 잘 이해할 수 있도록, v2 이전 데이터 형식의 필드를 새로운 필드에 매핑하는 데 도움을 주고, 이러한 새 필드를 요청하는 방법을 설명하는 일련의 가이드를 준비하고 있습니다.

이 마이그레이션 허브의 [data formats migration](/ko/x-api/migrate/data-format-migration) 섹션을 방문하거나, 아래의 개별 데이터 형식 가이드를 참고해 더 자세히 알아볼 수 있습니다.

* [Native format to X API v2 (standard v1.1)](/ko/x-api/migrate/data-format-migration#migrating-from-standard-v1-1s-data-format-to-v2)
* [Native Enriched to X API v2 (enterprise)](/ko/x-api/migrate/data-format-migration#migrating-from-native-enriched-data-format-to-v2)
* [Activity Streams to X API v2 (enterprise)](/ko/x-api/migrate/data-format-migration#migrating-from-activity-streams-data-format-to-v2)
