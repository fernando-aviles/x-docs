Enterprise용 엔드포인트가 편집된 포스트에 대한 메타데이터를 제공하도록 업데이트되었습니다. &#95;포스트 편집&#95; 기능은 2022년 9월 1일 X 직원들을 대상으로 한 테스트에서 처음 도입되었습니다. 해당 날짜부터 조건을 충족하는 포스트는 30분 동안 최대 5번까지 편집할 수 있었습니다. *2022년 9월 29일 이후에 생성된 포스트의 모든 객체*에는, 포스트가 실제로 편집되지 않았더라도 포스트 편집 메타데이터가 포함됩니다. 포스트가 편집될 때마다 새로운 포스트 ID가 생성됩니다. 포스트의 편집 내역은 원래 ID로 시작하여 이 ID들을 순서대로 연결함으로써 설명할 수 있습니다. 또한, 편집 체인에 있는 어느 하나의 포스트라도 삭제되면 해당 체인에 있는 모든 포스트가 함께 삭제됩니다. 

이 메타데이터 세부 정보는 자동으로 포함됩니다. 포스트 객체에 사용 가능한 편집 내역을 포함하기 위해 별도의 요청 매개변수는 필요하지 않습니다. 

이 새로운 메타데이터를 통해 개발자는 다음을 알 수 있습니다:

* 포스트가 생성 당시 편집 대상이었는지 여부. 설문조사가 포함된 포스트나 예약된 포스트처럼 편집할 수 없는 포스트도 있습니다.
* 포스트는 30분 동안 편집할 수 있으며, 최대 5번까지 수정할 수 있습니다. 편집 가능한 포스트의 경우, 편집 가능한 시간이 남아 있는지와 앞으로 가능한 편집 횟수를 확인할 수 있습니다.
* 현재 보고 있는 포스트가 편집된 버전인지 여부. 대부분의 경우 API는 포스트의 최신 버전을 반환하며, 특정 과거 버전은 포스트 ID로 명시적으로 요청해야 합니다.

루트 수준에 세 가지 새로운 포스트 속성이 추가되었습니다:

* **edit&#95;history**  - 포스트의 편집 내역과 관련된 모든 포스트 ID를 제공합니다. &quot;initial&#95;tweet&#95;id&quot; 속성은 원본 포스트를 나타내고, &quot;edit&#95;tweet&#95;ids&quot; 속성은 해당 편집 내역과 관련된 모든 ID를 제공하는 배열입니다. 포스트가 편집되지 않은 경우 이 배열에는 단일 ID만 포함됩니다.

```
"edit_history": {
    "initial\_tweet\_id": "1283764123"
    "edit\_tweet\_ids": \["1283764123"\]
  }
```

* **edit&#95;controls** - 30분 편집 창이 언제 종료되는지와 남은 편집 가능 횟수를 나타내는 속성을 제공합니다.

```
"edit_controls": {  
     "editable\_until\_ms": 1660155761384
     "edits_remaining": 3   
  }
```

* **editable** - 포스트가 생성될 때 편집이 가능했는지를 나타냅니다. 

&quot;editable&quot;: true

대부분의 포스트는 편집할 수 있습니다. 그러나 다음 유형의 포스트는 편집할 수 없습니다. 

* 포스트가 프로모션(광고)인 경우
* 포스트에 설문조사가 포함된 경우
* 포스트가 자신의 스레드가 아닌 다른 스레드에 대한 답글인 경우
* 포스트가 리트윗인 경우 (인용 트윗은 편집 가능함)
* 포스트가 널캐스트(nullcast)인 경우
* 커뮤니티 포스트인 경우
* 슈퍼팔로우 포스트인 경우
* 공동 작성 포스트인 경우

**편집되지 않은 포스트의 예시 속성**

아래 JSON은 포스트 편집 기능이 추가된 이후에 게시된 포스트에 포함되는 편집 메타데이터를 보여줍니다. 이 예시는 편집 이력이 없는 포스트에 대한 것입니다. 

`"edit_tweet_ids"` 배열에 단 하나의 ID만 포함되어 있다는 점에 유의하세요.

```
{
  "created_at": "Wed Aug 16 18:29:02 +0000 2022",
  "id": 1557433858676740098,
  "id_str": "1557433858676740098",
  "text": "I wonder if I will every use teh edit button",
  "edit_history": {
    "initial_tweet_id": "1557433858676740098",
    "edit_tweet_ids": ["1557433858676740098"]
  },
  "edit_controls": {
    "editable_until_ms": 1660155761384,
    "edits_remaining": 5
  },
  "editable": true
}
```

**수정된 포스트의 예시 속성**

아래 JSON은 포스트 수정 기능이 추가된 이후에 게시된 포스트에 포함되는 수정 메타데이터를 보여 줍니다. 이 예시는 한 번만 수정된 포스트에 대한 것입니다. 

`"edit_tweet_ids"` 배열에는 원본 포스트와 수정된 업데이트 각각에 해당하는 두 개의 id가 있습니다.

```
{
  "created_at": "Wed Aug 16 18:35:42 +0000 2022",
  "id": 1557445923210514432,
  "id_str": "1557445923210514432",
  "text": "I wonder if I will ever use the edit button",
  "edit_history": {
    "initial_tweet_id": "1557433858676740098",
    "edit_tweet_ids": ["1557433858676740098", "1557445923210514432"]
  },
  "edit_controls": {
    "editable_until_ms": 1660155761384,
    "edits_remaining": 4
  },
  "editable": true
}
```

**컴플라이언스 지원**

[Compliance Firehose](/ko/x-api/enterprise-gnip-2.0/fundamentals/firehouse)와 v2 [batch compliance endpoint](/ko/x-api/compliance/batch-compliance/introduction)가 모두 포스트 편집 기능을 지원하도록 업데이트되었습니다. 

Compliance Firehose에 새로운 &quot;tweet&#95;edit&quot; 이벤트 유형이 추가되었습니다.

```
{
  "tweet_edit": {
    "id": <tweetId>,
    "initial_tweet_id": <tweetId>,
    "edit_tweet_ids": [<tweetId1>, <tweetId2>, <tweetId3> ...],
    "timestamp_ms": "<timestampMsStr>"
  }
}
```
