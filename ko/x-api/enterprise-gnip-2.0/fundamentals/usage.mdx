<div id="usage-api-twitter-api">
  ## Usage API | Twitter API
</div>

<div id="overview">
  ### 개요
</div>

`Enterprise`

이는 계정에서 사용하는 여러 API 전반의 사용량을 모니터링하고 관리하는 데 있어 가장 핵심적이고 *가장 효과적인* 도구입니다.

**중요한 고지 사항:**

Usage API에서 반환되는 사용량 수치는 체험판 및 기타 청구 조정으로 인해 청구서 상의 수치와 일치하지 않을 수 있습니다. 모든 수치는 UTC 기준으로, 해당 일자 동안 소비된 활동을 중복 제거한 값을 바탕으로 산정됩니다.

<div id="features">
  #### 기능
</div>

* console.gnip.com UI에서 확인 가능한 사용량 data를 프로그램으로 가져오기
* 스트림 수준 사용량 data - 제품 수준뿐만 아니라 스트림 수준(예: dev 및 prod)에서도 사용량 data 제공
* 세분화되고 설명적인 data - 검색 &quot;요청(requests)&quot;이 Full-Archive 및 30-Day Search 제품별로 구분되어 제공됨
* Historical PowerTrack의 &quot;days&quot; 및 &quot;jobs&quot; 

<div id="supported-apis">
  ### 지원되는 API
</div>

아래는 현재 Usage API에서 지원하는 API 목록입니다:

* PowerTrack API `enterprise`
* 30-Day Search API `enterprise`
* Full-Archive Search API `enterprise`
* Historical PowerTrack `enterprise`

<div id="limitations">
  ### 제한 사항
</div>

* Usage API를 사용하면 2018년 5월 1일부터의 사용 data에 접근할 수 있습니다. 2019년 7월 1일 이후에는 Usage API를 통해 **직전 13개월**의 사용 data에 접근할 수 있습니다.

* fromDate와 toDate로 정의되는 **3개월 단위**로 사용 data에 접근할 수 있습니다.

  ### get-usage
</div>

<div id="methods">
  #### **메서드**
</div>

| 메서드 | 설명 |
| :--- | :--- |
| [GET /metrics/usage/accounts/{ACCOUNT_NAME}.json](#GETData) | 사용량 data를 조회합니다 |

다음과 같습니다.

* :account&#95;name은 console.gnip.com에 표시되는, 계정과 연결된 (대소문자를 구분하는) 이름입니다

<div id="authentication-and-rate-limit">
  #### **인증 및 레이트 리밋**
</div>

<div id="authentication">
  ##### **Authentication**
</div>

모든 Usage API 요청에는 HTTP 기본 인증(HTTP Basic Authentication)이 필요하며, console.gnip.com에 로그인하거나 Gnip 스트림에 연결할 때 사용하는 계정의 활성화된 이메일/비밀번호 자격 증명 중 하나를 사용해야 합니다.

<div id="rate-limit">
  ##### **요청 한도**
</div>

Usage API에는 분당 최대 2회의 요청 한도가 적용됩니다.

<div id="best-practices-limitations">
  #### **모범 사례 및 제한 사항**
</div>

<div id="data-availability">
  ##### **데이터 가용성**
</div>

사용량 데이터는 중복이 제거된 액티비티를 기준으로, 데이터가 처리된 마지막 전체 시간 구간(UTC)까지 집계됩니다. 일반적으로 데이터는 분 단위까지 처리 및 업데이트되지만, Gnip이 시스템을 배포하는 경우는 예외입니다.

* Usage API를 사용하면 2018년 5월 1일부터의 사용량 데이터에 접근할 수 있습니다. 2019년 7월 1일 이후에는 Usage API를 통해 **직전 13개 달력월**에 대한 사용량 데이터에 접근할 수 있습니다. 

* fromDate와 toDate로 정의되는 **3개월 단위 구간**으로 사용량 데이터에 접근할 수 있습니다.

<div id="requesting-and-receiving-data">
  #### **데이터 요청 및 수신**
</div>

Usage API는 HTTP Basic 인증 자격 증명을 사용해 계정의 API 엔드포인트로 HTTP GET 요청을 보내는 방식으로 동작합니다.

<div id="get-request">
  ##### GET Request:
</div>

다음 엔드포인트에 사용자 자격 증명과 account name(계정 이름)을 사용하여 GET 요청을 보냅니다:

https://gnip-api.x.com/metrics/usage/accounts/:account&#95;name.json

**Additional Parameters**

|     |     |
| :--- | :--- |
| bucket | 선택 사항. 사용량 데이터가 제공되는 시간 단위입니다. 사용량 데이터는 일별 또는 월별 세분성으로 반환될 수 있습니다.  <br />  <br />bucket을 지정하지 않고 요청하는 경우 월별 세분성으로 반환됩니다.  <br />  <br />옵션: &#39;month&#39; 또는 &#39;day&#39; |
| fromDate (YYYYMMDDHHMM) | 선택 사항. 사용량 데이터는 2018년 5월 1일부터만 사용할 수 있습니다. 사용량 데이터가 제공되는 가장 이른 UTC 타임스탬프입니다. 타임스탬프는 일 단위 세분성을 가지며 포함 범위입니다(예: 201805010000은 0501 날짜를 포함합니다). 시간(hour)과 분(minute) 세분성에 대해 &#39;0000&#39; 이외의 값을 포함하는 요청은 &#39;0000&#39;으로 기본값 처리됩니다.  <br />  <br />fromDate 또는 toDate 없이 이루어진 요청은 해당 월의 사용량 데이터를 월 단위로 반환하며, 직전 두 달에 대한 과거 데이터도 포함합니다.  <br />  <br />**주의:** 2019년 6월 1일부터는 과거 13개월분의 달력 기준 사용량 데이터에 접근할 수 있습니다. 예를 들어, 오늘이 10월 10일이라면, 전년도 9월 1일까지의 사용량 데이터에 접근할 수 있습니다.  <br />**예시:** 201810010000은 2018년 10월 1일부터(10월 1일을 포함하여) 시작하는 데이터를 반환합니다. |
| toDate (YYYYMMDDHHMM) | 선택 사항. 사용량 데이터가 제공될 가장 최신 UTC 타임스탬프입니다. 타임스탬프는 일 단위 세분성을 가지며 비포함 범위입니다(예: 201703020000은 0302 날짜의 데이터를 포함하지 않습니다). 현재 날짜 또는 미래 날짜에 대한 toDate가 지정된 경우, 사용량 데이터는 마지막으로 완료된 전체 일(UTC)까지 반환됩니다. 시간(hour)과 분(minute) 세분성에 대해 &#39;0000&#39; 이외의 값을 포함하는 요청은 &#39;0000&#39;으로 기본값 처리됩니다.  <br />  <br />toDate 없이 이루어진 요청은 다음 bucket을 기본값으로 사용합니다(bucket=day인 경우 내일, bucket=month인 경우 다음 달). fromDate와 toDate 없이 이루어진 요청은 기본적으로 bucket=month로 설정되며, 현재 달과 그 직전 두 달에 대한 데이터를 보여줍니다.  <br />  <br />**예시:** 201703050000은 2017년 3월 5일까지의 데이터를 반환하지만, 3월 5일의 데이터는 포함하지 않습니다. |

**Example GET Request**

이 요청은 2017년 3월 1일부터 2017년 3월 5일까지의 데이터를 월 단위 세분성으로 반환하며, 2017년 3월 5일의 데이터는 포함하지 않습니다.

curl -u &quot;https://gnip-api.x.com/metrics/usage/accounts/:account&#95;name.json?bucket=month&amp;fromdate=201403010000&amp;toDate=201403150000&quot;
