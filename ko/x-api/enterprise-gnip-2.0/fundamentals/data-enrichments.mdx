<div id="introduction">
  ## Introduction
</div>

`Enterprise`

Enterprise 엔리치먼트는 일부 데이터 API의 응답 페이로드에 포함되는 추가 메타데이터입니다. 유료 구독 플랜에서만 사용할 수 있습니다.

아래 표는 각 엔리치먼트에 대한 간단한 설명을 제공합니다:

| Enrichment: | Description: |
| :--- | :--- |
| Expanded and Enhanced URLs | 포스트 본문에 포함된 단축 URL(예: bitly)을 자동으로 확장하고, 대상 페이지의 HTML 제목 및 설명 메타데이터를 제공합니다. |
| Matching rules object | 수신된 포스트에 어떤 규칙이 일치했는지를 나타냅니다. 이 객체는 응답에서 규칙 태그와 규칙 ID를 반환합니다. |
| Poll metadata | 포스트에 투표가 존재하는지 여부를 표시하고, 투표 선택지 목록과 투표 기간 및 만료 시간을 포함합니다. |
| Profile geo | 사용자 프로필 위치에서 파생된 데이터로, 가능한 경우 [경도, 위도] 좌표와 관련 장소 메타데이터를 포함합니다. |

<div id="expanded-and-enhanced-urls">
  ### 확장 및 향상된 URL
</div>

확장 및 향상된 URL 인리치먼트는 포스트 본문에 포함된 단축 URL을 자동으로 확장하고, 그 결과 URL을 메타데이터로 페이로드 내에 포함합니다. 추가로, 이 인리치먼트는 대상 페이지의 `title` 및 `description`에서 가져온 HTML 페이지 메타데이터도 제공합니다.

**중요 세부 사항:**

* 단축 링크를 해석하기 위해, 시스템은 제공된 URL로 HTTP HEAD 요청을 보내고 최종 URL에 도달할 때까지 모든 리디렉션을 따릅니다. 그런 다음 이 최종 URL(페이지 콘텐츠 자체가 아님)만 응답 페이로드에 포함됩니다.

* URL 인리치먼트는 실시간 스트림에 5~10초의 지연 시간을 추가합니다.

* Full Archive Search API에 대한 요청의 경우, 확장 URL 인리치먼트 데이터는 게시된 지 13개월 이내인 포스트에 대해서만 제공됩니다.

* URL 인리치먼트는 포스트에 포함된 포스트 링크(인용 트윗 포함), Moments 링크, 프로필 링크에는 제공되지 않습니다. 
   

<div id="post-payload">
  #### 포스트 페이로드
</div>

Expanded 및 Enhanced URL 보강 정보는 포스트 페이로드의 `entities` 객체 안, 특히 `entitites.urls.unwound` 객체에 포함되어 있습니다. 여기에는 다음과 같은 메타데이터 필드가 제공됩니다:

* 확장된 URL - `unwound.url`
* 확장된 HTTP 상태 코드 - `unwound.status`
* 확장된 URL HTML 제목 - 300자 제한 - `unwound.title`
* 확장된 URL HTML 설명 - 1000자 제한 - `unwound.description`

**다음은 URL 보강 정보가 포함된 [entities 객체](/ko/x-api/enterprise-gnip-2.0/fundamentals/data-dictionary#x-entities)의 예시입니다.**

```
"entities": {
    "hashtags": [

    ],
    "urls": [
      {
        "url": "https:\/\/t.co\/HkTkwFq8UT",
        "expanded_url": "http:\/\/bit.ly\/2wYTb9y",
        "display_url": "bit.ly\/2wYTb9y",
        "unwound": {
          "url": "https:\/\/www.forbes.com\/sites\/laurencebradford\/2016\/12\/08\/11-websites-to-learn-to-code-for-free-in-2017\/",
          "status": 200,
          "title": "11 Websites To Learn To Code For Free In 2017",
          "description": "It\u2019s totally possible to learn to code for free...but what are the best resources to achieve that? Here are 11 websites where you can get started."
        },
        "indices": [
          10,
          33
        ]
      }
    ],
    "user_mentions": [

    ],
    "symbols": [

    ]
  },
```

**다음은 포스트 링크를 포함하지만 확장되지 않은 entities 객체의 예시입니다.
**

```
"entities": {
  "urls": [{
    "url": "https://t.co/SywNbZdDmb",
    "expanded_url": "https://x.com/XDevelopers/status/1050118621198921728",
    "display_url": "x.com/XDevelopers/s…",
     "indices": [
        142,
        165
     ]
   }
  ]
}
```

<div id="filtering-operators">
  #### 필터링 연산자
</div>

다음 연산자는 URL 메타데이터의 관련 필드에서 필터링을 수행하고 토큰화된 일치 결과를 제공합니다.

**url:**

* 예: “url:tennis”
* 단어 tennis가 포함된 모든 Expanded URL에서 토큰화된 일치 검색을 수행합니다.
* “url:npr.org”처럼 사용해 특정 웹사이트의 링크를 포함하거나 제외하는 필터로도 사용할 수 있습니다.

**url&#95;title:**

* 예: “url&#95;title:tennis”
* 단어 tennis가 포함된 모든 Expanded URL의 HTML title에서 토큰화된 일치 검색을 수행합니다.
* payload에 포함된 HTML title data에서 일치 항목을 찾으며, 이 값은 최대 300자로 제한됩니다.

**url&#95;description:**

* 예: “url&#95;description:tennis”
* 단어 tennis가 포함된 모든 Expanded URL의 HTML description에서 토큰화된 일치 검색을 수행합니다.
* payload에 포함된 HTML description에서 일치 항목을 찾으며, 이 값은 최대 1000자로 제한됩니다.
   

<div id="http-status-codes">
  #### HTTP 상태 코드
</div>

확장된 URL 보강 기능은 우리가 언와인드(풀어내기)하려는 최종 URL에 대한 HTTP 상태 코드도 제공합니다. 일반적인 경우에는 값이 200입니다. 그 밖의 400번대 값은 URL을 해석(해결)하는 데 문제가 있음을 나타냅니다.

URL을 언와인드하려고 시도할 때 여러 가지 상태 코드가 반환될 수 있습니다. URL을 언와인드하는 과정에서 리다이렉트를 받으면, 다음 중 하나가 발생할 때까지 무기한 따라갑니다.

* 200번대 코드에 도달했을 때 (성공)
* 리다이렉트가 아닌 코드에 도달했을 때 (실패)
* 최종 URL을 적절한 시간 안에 해석하지 못해 타임아웃이 발생했을 때 (408 - timeout 반환)
* 어떤 종류의 예외가 발생했을 때
   

예외가 발생한 경우, 다음과 같은 원인과 반환 상태 코드 간의 매핑을 사용합니다.

| 원인 | 반환되는 상태 코드 |
| :--- | :--- |
| SSL 예외 | 403 (Forbidden) |
| URL에서 언와인드가 허용되지 않음 | 405 |
| 소켓 타임아웃 | 408 (Timeout) |
| 알 수 없는 호스트 예외 | 404 (Not Found) |
| 지원되지 않는 연산 | 404 (Not Found) |
| 연결 예외 | 404 (Not Found) |
| 잘못된 인자 | 400 (Bad Request) |
| 그 외 모든 경우 | 400 (Bad Request) |

<div id="matching-rules">
  ### 일치 규칙
</div>

일치 규칙 보강 정보(matching rules enrichment)는 수신된 포스트와 일치한 규칙이 무엇인지(어떤 규칙들이 일치했는지)를 나타내는 메타데이터 객체입니다. 이는 주로 PowerTrack 스트림과 함께 사용됩니다.

일치는 규칙에 포함된 용어에 대한 정확 일치를 기준으로 수행되며, 활동(activity) 콘텐츠에서 문장 부호가 있는 경우와 없는 경우 모두를 스캔합니다. 대소문자는 구분하지 않습니다. 콘텐츠에 해당 규칙에 정의된 모든 용어가 포함되어 있다고 판단되면, 루트 수준에 어떤 규칙(들)이 매칭되었는지를 나타내는 `matching_rules` 객체가 존재하게 됩니다.

**PowerTrack**

PowerTrack(실시간, Replay, Historical)을 통해 전달되는 포스트에는 다음과 같이 `matching_rules` 객체가 포함됩니다:

```
"matching_rules": [{
        "tag": null,
        "id": 907728589029646336,
        "id_str": "907728589029646336"
    }]
```

PowerTrack에서 `matching_rules` 객체는 주어진 결과와 일치한 *모든* 규칙을 나타냅니다. 즉, 하나의 포스트에 둘 이상의 규칙이 일치하더라도 해당 포스트는 한 번만 전달되며, `matching_rules` 요소에는 일치한 모든 규칙이 포함됩니다.

<div id="poll-metadata">
  ### 설문조사 메타데이터
</div>

설문조사 메타데이터는 모든 제품(실시간 및 이력 API)에서 보강된 네이티브 형식 페이로드로 제공되는 무료 보강 정보입니다. 이 메타데이터는 포스트에 설문조사가 포함되어 있는지 여부를 표시하고, 설문조사 선택지 목록과 설문조사의 진행 기간 및 만료 시간을 모두 포함합니다. 이 보강 정보는 설문조사의 존재를 쉽게 식별할 수 있게 해주며, 설문조사 포스트를 올바르게 렌더링하여 표시할 수 있도록 지원합니다.

<div id="important-details">
  ##### 중요 사항:
</div>

* 모든 엔터프라이즈 API(PowerTrack, Replay, Search, Historical PowerTrack)에서 사용 가능
  * *참고:* Replay 및 Historical PowerTrack의 경우, 해당 메타데이터는 2017년 2월 22일에 처음 제공되었습니다.
* 투표 정보나 투표 결과는 포함하지 않음
* 현재는 필터/연산자 지원이 없음
* **강화된 네이티브 형식(enriched native format)** 으로만 사용 가능
  * 강화된 네이티브 형식은 사용자가 제어하는 설정으로, Console을 통해 언제든지 변경할 수 있습니다: *Select a Product (PowerTrack, Replay, Search) &gt; Settings 탭 &gt; Output Format (Leave data in its original format)*

<div id="post-payload">
  #### 포스트 페이로드
</div>

투표 포스트에는 페이로드의 “entities.polls” 객체에 다음과 같은 메타데이터가 포함됩니다.

* 위치(1-4)와 선택지 텍스트를 포함한, 최대 네 개의 선택지로 구성된 “options” 배열
* 투표 만료 일시
* 투표 기간

자세한 내용은 아래 샘플 페이로드를 참고하세요.

<div id="profile-geo">
  ### 프로필 위치 정보
</div>

#### 소개

많은 X 사용자 프로필에는 사용자가 제공한 공개 위치 정보가 포함되어 있습니다. 이 데이터는 user.location에서 일반 문자열로 반환됩니다([User object data dictionary](/ko/x-api/enterprise-gnip-2.0/fundamentals/data-dictionary#native-enriched-user-object) 참고). Profile Geo Enrichment 기능은 가능한 경우 위치 문자열을 지오코딩하고 정규화하여 user.location 값과 관련된 구조화된 지리 데이터를 추가합니다. 위도/경도 좌표와 관련 장소 메타데이터는 엔터프라이즈 API 제품에서 포스트 페이로드의 일부로 포함된 경우에만 user.derived.locations에 *추가* 됩니다. 이 데이터는 [향상된 네이티브 형식](/ko/x-api/enterprise-gnip-2.0/fundamentals/data-dictionary)을 사용할 때 제공되며, [PowerTrack rules](/ko/x-api/enterprise-gnip-2.0/fundamentals/rules-filtering#enterprise-operators)를 조합해 필터링할 수 있습니다.

<Note>
  **참고:** Profile Geo Enrichment를 생성하는 데 사용되는 일부 기초 지리 데이터는 GeoNames.org에서 제공되며, X는 이를 [Creative Commons Attribution 3.0 License](https://creativecommons.org/licenses/by/3.0/us/legalcode)에 따라 사용합니다.
</Note>

Profile Geo 데이터는 X의 PowerTrack, Replay, Volume Stream, Search 및 Historical PowerTrack API에 포함됩니다.

  #### 프로필 Geo 데이터
</div>

| :--- | :--- | :--- |
| user.derived.locations.country | United States | 포스트를 생성한 사용자가 속한 국가입니다. |
| user.derived.locations.country&#95;code | US  | 포스트를 생성한 사용자가 속한 국가에 해당하는 두 글자의 ISO-3166 국가 코드입니다. |
| user.derived.locations.locality | Birmingham | 포스트를 생성한 사용자가 속한 지역(일반적으로 도시)입니다. |
| user.derived.locations.region | Alabama | 포스트를 생성한 사용자가 속한 지역(일반적으로 주/도)입니다. |
| user.derived.locations.sub&#95;region | Jefferson County | 포스트를 생성한 사용자가 속한 하위 지역(일반적으로 카운티)입니다. |
| user.derived.locations.full&#95;name | Birmingham, Alabama, United States | 포스트를 생성한 사용자가 속한 위치의 전체 이름(하위 지역 제외)입니다. |

Historical PowerTrack, Search 및 PowerTrack API는 프로필 Geo 데이터를 기반으로 한 필터링을 지원합니다. 프로필 Geo 데이터 필터링 시 어떤 연산자를 사용할 수 있는지에 대해서는 해당 제품 설명서를 참조하세요.

#### 예시 페이로드

```

        "derived": {
            "locations": \[
                {
                    "country": "United States",
                    "country_code": "US",
                    "locality": "Birmingham",
                    "region": "Alabama",
                    "sub_region": "Jefferson County",
                    "full_name": "Birmingham, Alabama, United States",
                    "geo": {
                        "coordinates": \[
                            -86.80249,

                        \],
                        "type": "point"
                    }
                }
            \]
        }
    }
}
```

<div id="limitations">
  #### 제한 사항
</div>

* Profile Geo enrichment는 프로필 위치 문자열에 설명된 지리적 장소 중 최적의 후보를 식별하려고 시도합니다. 그러나 유사한 이름을 가진 여러 장소가 있거나 이름 자체가 모호한 등의 이유로, 모든 경우에 결과가 정확하지 않을 수 있습니다.
* 사용자의 프로필 위치 필드(actor.location)에 값이 제공되지 않은 경우, 분류를 시도하지 않습니다.
* 정밀도 수준(Precision Level): Profile Geo enrichment를 국가 또는 지역 수준에서만 신뢰도 있게 판별할 수 있는 경우, subRegion 및 locality와 같은 더 낮은 수준의 지리 정보는 페이로드에서 생략됩니다.
* Profile Geo enrichment는 enrichment 결과의 정밀도 수준에 해당하는 위도/경도 좌표(단일 지점)를 제공합니다. 이 좌표는 enrichment 위치 결과의 지리적 중심을 나타냅니다. 예를 들어, 정밀도 수준이 국가 수준인 경우 해당 좌표는 그 국가의 지리적 중심으로 설정됩니다.
* 주소 속성(locality/region/country/country code)에 대해 제공되는 PowerTrack 연산자는 다양한 규칙 조합이 가능하도록 의도적으로 세분화되어 있습니다. 동일한 이름을 공유하는 특정 위치를 타깃팅하려고 할 때는 주소 규칙을 결합하는 것을 고려하십시오. 예를 들어, 다음과 같이 하면 “San Francisco, Philippines”에 대한 매치를 피할 수 있습니다: profile&#95;locality:&quot;San Francisco&quot; profile&#95;region:California 개별 Profile Geo 필드를 타깃팅하는 규칙을 작성할 때는, 세분화 수준이 높아질수록 조회되는 결과가 제한된다는 점을 유념하십시오. 어떤 경우에는 특정 도시의 데이터를 보려 할 때, 해당 도시와 상당 부분 겹치는 지역 규칙만 사용하는 것이 더 적절할 수 있습니다. 예를 들어, 스위스의 취리히(Zurich) 도시는 주변 지역과 함께 profile&#95;region:&quot;Zurich&quot;으로 효과적으로 타깃팅할 수 있습니다.
* 네이티브 Geo 포스트와 함께 사용하기: Profile Geo enrichment는 페이로드에 포함된 기본 geo 값과는 다른, 포스트에 대한 대체 유형의 지리 정보를 제공합니다. 이 두 가지 유형의 지리 정보는 (사용 가능한 지리 데이터에 기반하여) 특정 영역과 관련된 가능한 모든 포스트를 수집하기 위해 함께 사용할 수 있지만, 개념적으로 동일한 것은 아닙니다.
